## Evidence and language semantics

SET a=b, b=a on a row (a=1,b=2) must now produce (2,2), because the second expression reads the candidate after the first assignment; the previous simultaneous result was (2,1). Keep the ordered assignment list and all preflight validation. Snapshot target indices from original rows before assigning (or retain the immutable original row source while constructing candidates, so membership is equivalent and independent). Change only the expression evaluation context from the old row to the candidate row and immediately store each result there. Do not write the original table as a shortcut. Check the complete final candidate table once in the existing order, then publish once; a late NULL/duplicate-key failure must discard all earlier candidates. Count matched rows even when their values do not change. ipairs and append preserve assignment order; target lookup rejects unknown names before duplicates, followed by per-expression type checks and WHERE. Lua tables are references, so nextrow=r alone is unsafe for writes; concat(r,{}) explicitly allocates a new table and copies cell entries. Keep that copy and use nextrow as evaluate argument for successive assignments, while t.rows remains the original predicate source. A slot assignment replaces an entry rather than mutating the shared NULL sentinel or a cell value. constraints checks all changed rows and columns before equality against every final row. error aborts before t.rows=rows; matched count and singular/plural formatting remain unchanged.
