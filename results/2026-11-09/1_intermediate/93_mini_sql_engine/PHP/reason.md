## Evidence and language semantics

SET a=b, b=a on a row (a=1,b=2) must now produce (2,2), because the second expression reads the candidate after the first assignment; the previous simultaneous result was (2,1). Keep the ordered assignment list and all preflight validation. Snapshot target indices from original rows before assigning (or retain the immutable original row source while constructing candidates, so membership is equivalent and independent). Change only the expression evaluation context from the old row to the candidate row and immediately store each result there. Do not write the original table as a shortcut. Check the complete final candidate table once in the existing order, then publish once; a late NULL/duplicate-key failure must discard all earlier candidates. Count matched rows even when their values do not change. comma, array_column and foreach preserve assignment order. targets checks each unknown name before repeats, then each check/requireType precedes condition. PHP arrays have copy-on-write value semantics, and these foreach variables use no reference marker: $next=$row followed by slot assignment does not modify $t->rows. Use $next as evaluate argument; its return type explicitly restricts cell values to int|string|null. Keep original-row matching and the separate outer $rows accumulation. constraints checks target/column order and strict primary-key equality against all final rows. fail throws before the Table object rows property is replaced; rowCount and the update match arm preserve output.
