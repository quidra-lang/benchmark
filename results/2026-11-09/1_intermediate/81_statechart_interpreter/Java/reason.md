## Evidence and language semantics

Common concrete input: 1; CHART exact; state a; on a done / log "prefix"; on a done.state.a / log "exact"; on a * / log "wild"; RUN; event done.state.a; event done; event other; dump; END (each semicolon separates an input line). Original logs are prefix, prefix, wild; after removing the prefix alternative from the descriptor predicate they are exact, prefix, wild. The first event is a valid externally supplied name, also the spelling used for completion events; generated completions still enter the same event queue but use the revised exact-name rule. The only active state remains a at time zero. No guard, target, entry/exit action, timer or variable is declared; absent guards are true and every selected transition is internal. Java initializes object fields to null/false/zero, and State/Transition inherit Object identity for HashSet and ==; string matching instead uses equals/startsWith. An absent target returns an empty Choice exit set. The labeled break search is essential: it establishes the first enabled transition wins across the source ancestor loop. The streams only test overlaps or order exits and do not reorder transition candidates. Remove only trigger.event.name.startsWith(descriptor+"."); exact/wildcard, timer identity and always-kind tests remain. Null guards and action expressions establish no evaluation dependency for the literal trace; firstReference and Action.reference prove valid registration. Queue.remove supplies FIFO internal events; stdout methods show the resulting logs and dump.

Boundary review: Internal braces end the selected log, tick and dump switch arms and their enclosing selected loops, together with the target parser, definition, action, entry and macrostep branches. The return and following dispatch operations therefore retain their original scope.

## Minimization and alternatives

A single atomic state and targetless transitions minimize state-entry/exit/history dependencies while still exercising parsing, ordered transition priority, default guards, conflict filtering, action logs and dump output. A chart with guarded arithmetic or changing targets would require expression evaluation and target/history closure without adding a fact needed to locate this matching change. Queue/completion creation and separate timer/eventless dispatch anchors are retained to delimit the modification; their scheduling algorithms are not changed. Only the successful branches and custom helpers needed for this trace are retained, plus the match alternatives that distinguish old/new behavior. Each selected complete line was reviewed for necessity; the excerpt alone was checked against the common requirements. Internal boundaries needed to establish the scope of later selected operations are retained. Independent outer declaration frames and unrelated command bodies are omitted where they provide no evidence. Whitespace-only lines outside source literals and explicit line continuations are omitted: they contribute tokens but no evidence for the answer. Literal content is preserved, and files with ambiguous quote or multiline-literal syntax are left unchanged by this step.
