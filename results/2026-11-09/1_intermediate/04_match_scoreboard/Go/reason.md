## Evidence and language semantics

Events are expanded and processed sequentially. Validation/finished checks precede acceptance of each event; an error exits the current iteration/command without removing the already accepted prefix. UNDO removes one successful event, even when it was in a multi-event command and even when it ended the match. Empty history is rejected. A full pre-event state value is appended to history before the accepted event mutates current state. Undo replaces current state with the last stored value and removes it. Scores, statistics and winner fields belong to that value; bowling completion/statistics are derived from the restored rolls/count. The interface stores concrete structs containing fixed arrays. Type assertions copy those values into s, mutation updates that local value, and assignment publishes it back. Thus old interface values in history retain the pre-event arrays. Source bytes and each selected original line were verified against the current develop checkout before inheritance; the excerpt was then independently reviewed. Additional selected error helpers establish actual nonlocal failure; selected scalar/array/frame declarations establish restoration semantics where needed.
