## Evidence and language semantics

Use [TOC], a blank line, # Parent {#foo}, a blank line, > ## Foo, then @@END@@. The TOC is recognized before either heading; the quoted line is stripped of > and recursively parsed as a level-2 heading. The explicit heading reserves foo and removes {#foo} from the display source. The nested automatic heading uses raw Foo to form foo, finds it occupied, then chooses and reserves foo-1. Ordinary inline characters are escaped and assembled into the heading HTML; tag stripping that rendered HTML supplies the TOC labels Parent and Foo. Automatic slugging receives raw heading source, before inline rendering. The same final IDs are recorded for both heading attributes and TOC links. The heading-level tree makes the level-2 Foo a child of level-1 Parent. The earlier TOC placeholder is replaced only after the heading traversal, so the leading nav links #foo and #foo-1 agree with h1 id=foo and the quoted h2 id=foo-1. Java stores level/text in Block and then copies the final level, ID and label into mutable Heading objects with child lists. Standard ArrayList iteration preserves document order. Renderer owns one HashSet of IDs and one heading list across quote recursion. document evaluates renderBlocks before tableOfContents and String.replace. The ordinary-character default branch of escapeHtml and Piece constructor/assembly are sufficient for this alphabetic witness; there is no need to infer custom inline behavior from its name. Explicit IDs enter the set when visited, not through an asserted future-ID prescan.

## Minimization and alternatives

An allocation-only excerpt loses forward references and raw-versus-rendered provenance.
