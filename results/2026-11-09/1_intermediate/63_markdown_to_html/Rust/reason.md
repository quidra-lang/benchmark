## Evidence and language semantics

Use [TOC], a blank line, # Parent {#foo}, a blank line, > ## Foo, then @@END@@. The TOC is recognized before either heading; the quoted line is stripped of > and recursively parsed as a level-2 heading. The explicit heading reserves foo and removes {#foo} from the display source. The nested automatic heading uses raw Foo to form foo, finds it occupied, then chooses and reserves foo-1. Ordinary inline characters are escaped and assembled into the heading HTML; tag stripping that rendered HTML supplies the TOC labels Parent and Foo. Automatic slugging receives raw heading source, before inline rendering. The same final IDs are recorded for both heading attributes and TOC links. The heading-level tree makes the level-2 Foo a child of level-1 Parent. The earlier TOC placeholder is replaced only after the heading traversal, so the leading nav links #foo and #foo-1 agree with h1 id=foo and the quoted h2 id=foo-1. Rust explicitly owns the ID set and heading Vec on Renderer; mutable self is passed through recursive rendering. String clones retain the same chosen value for the set, stored heading and output. The TOC uses a separate index-based child Vec and borrows the recorded headings, so constructing nesting does not rerun allocation. document evaluates self.blocks first and only then self.toc for replacement. The enum makes raw heading text and quote child blocks explicit. Physical lines containing the selected Heading/Quote match arms also contain unrelated arm headers, which cannot be split under the complete-line rule. IDs are reserved in render order, without an assumed global prescan.

## Minimization and alternatives

More elaborate emphasis, links, footnotes, tables, lists, code fences, other heading syntaxes, and error handling do not establish an additional answer requirement.
