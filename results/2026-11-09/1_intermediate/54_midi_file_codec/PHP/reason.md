## Evidence and language semantics

The requested change belongs in the event transformation, after target selection and signed pitch addition and before the payload assignment. Replace the range-failure removal path with a lower/upper bound clamp. Every selected event must reach the retained-event path exactly once; leave tick, status/channel, second data byte and track order untouched. Equal resulting pitches are separate sequence entries, including entries at the same tick; no set, grouping or note-pair operation is required. The transposed count includes those now clamped, including a zero shift; dropped becomes zero and its detail loop receives no events. DECODE already formats the stored payload in track order. ENCODE already uses each retained absolute tick minus the previous retained tick, so preserving events preserves the original delta sequence, including zero deltas; the shortest base-128 encoding and channel payload emission remain applicable. Existing running-status compression only suppresses status bytes, while NOTE_OFF ZERO changes status/velocity at encoding time and keeps the pitch. Neither operation coalesces events. PHP arrays use value semantics while event objects retain identity; each retained object remains a separate entry in the rebuilt track array, and songs[name]=song commits the rebuilt arrays. Saturate the signed integer p before writing object data[0], increment kept for every target and bypass deletion; equal note values do not merge separate entries. Status high nibbles8..10 and low-nibble channel select the affected events. eventLine/eventFields and noteName determine displayed output. encode copies the event payload to local d before optional zero-velocity rewrite, emits VLQ of absolute-tick difference and appends each payload. The known-command check precedes song existence and TRANSPOSE range check; ensure throws and the catch keeps the error prefix.
