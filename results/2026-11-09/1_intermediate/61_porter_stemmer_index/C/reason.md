The initial index contains ox at positions1,3. The first PHRASE normalizes to "? ox", matches across the line boundary starting at 1:1:2, and prints PHRASE "? ox" matches=1 1:1:2. UNSTOP a prints indexed=1 and makes the next phrase "a ox", again matches=1 1:1:2. STOP ox prints unindexed=2; the final query raises ERROR STOPWORDS ONLY before matching. Every chosen form has at most two letters, so the selected early-return/no-step stemming branch proves the actual stems without needing suffix rules. The static document-pointer array and counts start at zero by C static-storage initialization; create_document uses designated initialization to zero all fields apart from the document number. add_token copies lowercase form and stem into durable allocation and fixes its original position before incrementing the count. collect_occurrences filters pointers to raw tokens rather than rewriting positions. The selected allocation/copy helpers close ownership dependencies. Phrase counts and then prints the same numeric-document/ascending-start windows. ## Minimization and alternatives

The common scenario is fixed before language selection. Keeping all raw-token storage and the active-stopword filter, rather than selecting unrelated INDEX/SEARCH command implementations, is the smaller evidence set for why positions survive. The phrase loop and custom matching/reference/format helpers are necessary: names alone cannot prove wildcard width, cross-line matching or start-reference semantics. Only the short-word stemming branch is relevant; long-word suffix rules, KWIC, ranking, similarity, deletion and append are excluded. STOP and UNSTOP are both retained to show a changed subsequent query and the separate all-stopword error. Alternative long-word examples would require a larger Porter rule closure; an INDEX command trace would duplicate the already visible index storage/filter. Individual selected statements were reviewed for the input-to-output chain, and the final excerpt was independently checked against the common trace. Whitespace-only lines outside source literals and explicit line continuations are omitted: they contribute tokens but no evidence for the answer. Literal content is preserved, and files with ambiguous quote or multiline-literal syntax are left unchanged by this step. The short-word path retains the boundary after the long-word-only condition, so its unchanged-word return is visibly reachable when the guard is false. Necessary selected loop, match and error-handler endings separate repeated token/index contributions from later query results and input processing. Python and Quidra use the unchanged indentation for these boundaries. Outer declaration framing remains unnecessary for this source-evidence excerpt.
