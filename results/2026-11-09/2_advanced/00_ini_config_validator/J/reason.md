## J source evidence

`parse_size` returns a two-box success flag/numeric value or failure flag/empty text. width_digits uses Digits and explicit length limits; decimal performs base10 decode rather than an undocumented parser. Unit lookup uses tolower and the aligned factor vector. Exact-fit |!.0 detects a nonzero fractional remainder before division and floor, so rounding is not used to admit a size. normalize_value unboxes valid/normalized, returns the E_TYPE diagnostic tuple immediately on failure, and returns a four-box success/value/empty-code/empty-message tuple after range. It keeps normalized as measure and parse_bound unwraps the same scalar parser for size bounds, using exact-fit strict comparisons. Table key accessors and numeric diagnostic rendering helpers are retained to ground these untyped table/boxed operations.

For 1.5MB the whole part contributes 1×1048576 and the fractional part contributes (5×1048576)/10 = 524288 exactly, giving 1572864 integer bytes. For 0.05KB the fractional numerator is 5×1024 = 5120 with divisor 100; the nonzero remainder rejects the value before any range comparison. This becomes E_TYPE, not a rounded 51-byte value. A successful value is checked against any nonempty size bounds in the same byte unit; strict less-than/greater-than rejection makes equality acceptable. Without a range failure it crosses the normalization return boundary; the first failed parse or range check stops that operation.
