The retained schedule runs token refill and eligible existing queued commands first, then all traffic arrivals at that time, and then PING/timeout checks. For an established client, a message arrival increments received, records the current time as last received and clears the outstanding-PING marker before examining tokens or parsing the command. Thus a message at the old timeout boundary prevents that old outstanding PING from timing out in the later phase even when it cannot execute immediately. With no usable token (or an existing FIFO backlog), it is queued and queued accounting rises unless the queue is already at capacity; the overflow branch counts the discarded incoming line and disconnects for flood, while disconnect discards queued lines and records its reason/counters. On later ticks refill can supply a token and the FIFO head executes while the client remains active. Processing increments processed and command/empty counts then parses/dispatches; PONG has no further liveness action, because arrival already cleared the marker. A malformed or unknown command has the same arrival-time liveness effect but different later command handling. Later silence can still trigger a fresh PING and then timeout; if disconnected first, the queued message is discarded instead of processed. send records the simulation timestamp, recipient and output line and increments sent; report code exposes received/sent/tokens/queue and the queued/processed/discarded/pending, PING/error and disconnection fields. At arrival, no command response is emitted solely because liveness was refreshed; later processing or PING/disconnect can append sent lines.
