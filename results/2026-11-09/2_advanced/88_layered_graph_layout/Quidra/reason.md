## Evidence and source semantics

Quidra arrays have value semantics recursively, including nested arrays; append/concat/sorted return values, and ordinary assignment does not create writable aliases. This documented guarantee is in the approved quidra-lang/quidra README at af1f6662abf4f23f1709daee29857b857c574d9b, Arrays section. Therefore order := model.initial, run_order := order, history := [order], history.append(order) and adopted = run_order are independent observable values when later nested elements mutate. No explicit deep-copy helper is necessary. Settings is likewise a value class, so each Graph receives its own settings value. In reduce_crossings, each run starts at model.initial; later runs shuffle that fresh order with the persistent seeded random_state. Strict < updates retain the earliest sweep/run on equal counts. Saved run_order, rather than the last active order, becomes adopted, and sifting mutates only adopted after the best record has been appended. Reduction retains its saved swept/run/sweep fields while process_graph recounts final_count and brute using reduced.order. Coordinates.assign consumes this exact order, adjacency and width data and returns its independent x/extents; retained allocation, final normalization and return lines establish the output binding without requiring the numerical alignment/constraint algorithms. The draw caller consumes placement and shape. Graph edges retain original endpoints; process_graph creates separate DAG edges plus reversed flags. draw reverses route points and uses the original-target arrow at the working upper endpoint for a reversed edge; the edge output separately reverses its dummy chain and preserves graph.edges endpoint names. The actual four writer bindings consume Processed.layout, stats, csv and drawings from this same final graph. PATH has its none result guard retained, while path search/highlighting and SCC algorithms are outside this accepted no-PATH graph scenario.

The effective settings are copied per graph and amended by OPTION records; node/edge acceptance and normalized numeric-ID order supply the graph passed into layout. Cycle removal preserves original endpoints while orienting the working DAG forward in an acyclic order. Longest-path layers and per-layer dummy chains produce the actual starting layer orders; reduction/promotion and PATH-specific branches are outside the chosen scenario. A restart changes within-layer ordering, not layer membership or the original edge endpoints. The active order after the last sweep is not automatically adopted: each run saves a separate best snapshot, and global run selection adopts that run's snapshot under its source comparison/tie policy. Sifting operates afterward on the adopted order. Final gap/edge/brute counts and coordinates are computed from that resulting order, while the saved swept best/run/sweep fields are retained. Therefore final crossings can differ from the saved sweep count when post-selection sifting changes the order, and either can differ from the last attempted sweep or last CSV record. A run that finishes worse than an earlier sweep does not replace its own saved snapshot. Zero crossings, the sweep limit and repeated-order guards can stop before all allowed sweeps.

Coordinates consume the adopted order and dummy adjacency; routing consumes those coordinates and chains. A reversed working edge still represents its original source and target. The source reverses or traverses its output route/chain in the original direction and chooses the corresponding endpoint/backward arrow, rather than changing the original edge's identity. layout output uses sweep/best/sift records and final node/edge geometry; crossings.csv uses the actual recorded sweep history; stats uses the saved swept fields alongside separately recomputed final/brute fields and geometry summaries; drawings serializes the same final canvas. No PATH was supplied, so path search/highlighting is not needed to explain this graph's drawing.
