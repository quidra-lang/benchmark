Trailing token comments are joined and represented by a suffix document. fits measures ordinary text/flat breaks while ignoring that suffix, and the group chooses flat when the measured content fits unless already flat/explicitly forced. Actual layout accumulates suffix strings separately. At finalization the code trims the line, joins pending comments with single spaces, and aligns the first comment at configured column C only if C > 0, current length < C−1 and C−1 + comment length ≤ width. Otherwise it adds exactly one space and the comments, without a new fit test; pending is cleared and the complete line emitted. Thus width 10 with a 10-character flat body and a three-character suffix can emit 14 characters. This is expected delayed suffix handling, not a retroactive group break. Hardline/break_parent is the separate forcing path shown in force_broken/forced; suffix by itself is not that marker.
