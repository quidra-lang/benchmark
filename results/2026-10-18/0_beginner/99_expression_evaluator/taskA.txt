Write a program that interprets and executes, in order from top to bottom, the following 9 lines (each line is one string) written in a small calculator language.
width = 12
height = width - 5
area = width * height
(area + 6) / 4
shift = -area / 8 + 3
height = 100 / (height - 7) + bonus
volume = area * depth
width = (width+3)*-(2-4)
width * shift - height
Each line is either an assignment statement of the form "name = expression" or a line consisting only of an expression. An expression consists of integer literals >= 0 (sequences of digits), variable names (names of one or more lowercase English letters only), the binary operators + - * /, unary minus -, and parentheses ( ), with or without ASCII spaces between them. Every line is syntactically correct.
Operator precedence is the usual one: unary minus binds tightest, then * and /, and + and - bind weakest. Binary operators of the same precedence associate from left to right (for example, 8 - 3 - 2 is (8 - 3) - 2). Unary minus negates the integer literal, variable, parenthesized expression, or unary-minus term immediately following it. / is integer division that truncates the fractional part of the quotient toward 0 (for example, 7 / 2 is 3 and -7 / 2 is -3). In this data, every intermediate value and every result has an absolute value less than 2 to the 31st power.
Split each line into tokens (integer literals, variable names, operators, parentheses, =), and evaluate it while parsing with recursive descent, using a table mapping variable names to values (initially empty). Evaluate from left to right; for a binary operation, first fully evaluate the left operand, then evaluate the right operand, and then apply the operation. If during evaluation a variable that has no value is referenced (undefined variable), or the value of the right operand of / is 0 (division by zero), stop evaluating at that point and treat the line as an error. Even when a line has more than one problem, evaluate in this order and report only the first problem that occurs. A line that results in an error does not change the value of any variable (for an assignment statement, the assignment is not performed). An assignment statement that is evaluated successfully sets the variable to its value (overwriting any existing value).

Output format:
Output one line per input line, in order from the top. For an assignment statement evaluated successfully, use the format "name = value"; for an expression-only line evaluated successfully, use the format "value". name is the variable assigned to, and value is the value of the expression, written as a decimal integer without extra leading zeros (with a leading "-" when negative).
For a line that results in an error, output "error: division by zero" for division by zero, or "error: undefined variable NAME" (NAME is the variable name) for an undefined variable.
Put exactly one ASCII space before and after "=", after ":", and between words.
Output only these 9 lines; no line has trailing spaces, and every line ends with a newline. The example output below is for executing 4 different lines.

Example output (the numbers are illustrative and differ from the actual answer):
total = 15
-4
error: undefined variable rate
error: division by zero
