[Overview]
Write a program that simulates, cycle by cycle and from a dynamic instruction trace, an in-order CPU with a classic five-stage pipeline (IF: instruction fetch, ID: instruction decode, EX: execute, MEM: memory access, WB: write back). A dynamic instruction trace is a record, in execution order, of the instructions processed when a program was actually run; for each instruction it gives the address (PC), the instruction class, the register numbers, the branch outcome and target, and the memory address. The simulation does not execute the meaning of the instructions (it computes no values); from this information alone it determines the cycle in which each instruction enters each stage of the pipeline.
The hazards handled are data hazards caused by register dependences (forwarding can be turned on or off; this includes stalls caused by using the result of a load instruction immediately), structural hazards caused by a non-pipelined multiplier, and control hazards caused by branches (branch predictors, a branch target buffer (BTB), a return address stack (RAS), and flushes on misprediction). Seven kinds of branch predictor are handled: two static predictors, 1-bit and 2-bit saturating counters, gshare, tournament, and perfect prediction.
The program reads the two files (the trace and the configuration) in the input/ folder, performs the following processing, and writes five files to the output/ folder. It prints nothing to standard output.
1. Trace checking: check every line of the trace and exclude the lines that do not match the format.
2. Branch prediction: with every predictor in the configuration, predict where branch instructions and jump instructions go.
3. Timing: for every combination of a pipeline variant and a predictor in the configuration, determine the timing of all instructions and break the stalls down by cause.
4. Analysis: for the one pair specified in the configuration (the primary variant and the primary predictor), compute the pipeline diagram, the cycle count and CPI, the stall breakdown, how forwarding is used, the utilization of each stage, the instructions with the most stalls, a profile, and so on.
5. Comparison: compare the prediction results of each predictor and the cycle counts of all combinations.
All computation is done with integers; real numbers are not used (decimal output is also computed with integer arithmetic).

[Input files]
There are two input files: input/trace.txt and input/config.txt. Both files consist only of printable ASCII characters (0x20 to 0x7E) and newlines (LF), and every line (including the last line) ends with a newline. Below, "space" means the ASCII space character. In the formats below, the parts enclosed in < > denote values, and all other characters appear as they are.
An "8-digit hex" is a string of exactly 8 characters consisting only of 0 to 9 and a to f (lowercase); it denotes the value of that string read as a hexadecimal number (e.g. 0040012c). In every line of trace.txt, every field that has the form of an 8-digit hex has a value of at most 7ffffff0.

* input/trace.txt (dynamic instruction trace)
Each line is one record, and the records are in the order in which they were executed. A valid record consists of the following 8 fields in this order, separated by single spaces.
<PC> <class> <rd> <rs1> <rs2> <outcome> <target> <address>
- PC: the address of the instruction. It is an 8-digit hex and a multiple of 4.
- class: the instruction class, one of the 7 names ALU (integer arithmetic), MUL (multiplication), LOAD (read from memory), STORE (write to memory), BRANCH (conditional branch), JUMP (unconditional jump) and NOP (instruction that does nothing). This sequence is called the "class order".
- rd: the register that receives the result (destination). rs1, rs2: the registers whose values are read (sources). There are 32 registers r0 to r31, written as "r" followed by a decimal number from 0 to 31 without extra leading zeros (e.g. r0, r7, r31). An unused field is "-".
- outcome: for BRANCH, T if the branch was taken and N if it was not taken. For JUMP it is always T; for every other class it is "-".
- target: for BRANCH and JUMP, the destination address when the branch (jump) is taken, as an 8-digit hex. For BRANCH it is written even when the branch was not taken. For every other class it is "-".
- address: for LOAD and STORE, the memory address read or written, as an 8-digit hex. For every other class it is "-".
How the register fields are used for each class is as follows. "required" means that a register is written, "none" means that the field is "-", and "optional" means that either is allowed.
  class    rd        rs1       rs2
  ALU      required  required  optional
  MUL      required  required  required
  LOAD     required  required  none
  STORE    none      required  required
  BRANCH   none      required  optional
  JUMP     optional  optional  none
  NOP      none      none      none
The rs1 of LOAD and STORE is the base register of the address, and the rs2 of STORE is the register holding the data to write. BRANCH decides whether to branch by comparing the values of rs1 and rs2 (only rs1 if rs2 is "-"). The rd of JUMP is the link register that receives the return address. A JUMP whose rs1 is "-" is called a "direct jump" (its target is written in the instruction), and a JUMP whose rs1 is a register is called an "indirect jump" (its target is read from a register).
The trace may contain lines that were corrupted during recording (empty lines, lines with missing fields, lines containing wrong characters, lines mixed with the content of another instruction, and so on) and duplicated lines. Corrupted lines are checked and excluded in step 2 of [Processing].
The given trace.txt is a trace recorded by running a small program that initializes and sums an array, calls functions and recurses, sorts, multiplies matrices, executes periodic branches, traverses a linked list and interprets bytecode, with corrupted lines added (r1 holds a value before the trace starts).

* input/config.txt (configuration)
The following lines appear in this order. Each line consists of words separated by single spaces.
- BTB <entries>: the number of BTB entries (a power of 2 from 1 to 1024).
- RAS <depth>: the depth of the RAS (an integer from 0 to 16; when it is 0, the RAS is not used).
- PREDICTOR <name> <scheme> <parameters...>: a branch predictor. There are 1 to 8 such lines, and their order is called the "predictor order". The scheme and parameters are one of the following. Every table size is a power of 2 from 1 to 4096, and the number of history bits is an integer from 1 to 12.
  STATIC_NT (no parameters)
  BTFN (no parameters)
  ONEBIT <table size>
  TWOBIT <table size>
  GSHARE <table size> <history bits>
  TOURNAMENT <local table size> <global table size> <history bits> <chooser table size>
  PERFECT (no parameters)
- VARIANT <name> <forwarding> <resolution stage> <multiply latency>: a pipeline variant. There are 1 to 8 such lines, and their order is called the "variant order". forwarding is ON (enabled) or OFF (disabled), the resolution stage (the stage in which the destination of a branch is determined) is ID or EX, and the multiply latency is an integer from 1 to 12.
- PRIMARY <variant name> <predictor name>: the variant (primary variant) and predictor (primary predictor) to analyze in detail.
- WINDOW <start cycle> <end cycle>: the range of cycles drawn in the pipeline diagram.
- TOP <k>: the maximum number of rows written in ranking tables (a positive integer).
- INTERVAL <k>: the number of instructions per interval when computing the CPI of each interval (a positive integer).
A name is a string of 1 to 16 characters consisting of lowercase English letters, digits and "_". Predictor names are all distinct from each other, and variant names are all distinct from each other. The two names in PRIMARY are defined ones, and there is at least one predictor whose scheme is not PERFECT. Integers are written in decimal without extra leading zeros.

[Processing]
* 1. Notation and common rules
- a div b is the integer part of the quotient of a divided by b, and a mod b is its remainder. Wherever this statement uses div and mod, a is non-negative and b is positive. a xor b is the bitwise exclusive OR of a and b, and max(...) is the maximum.
- PC, target and address are treated as integers, and comparisons and additions on them are also done as integers.
- "decimal p/q" (p is a non-negative integer and q is a positive integer) is the string of p / q rounded to 4 decimal places. Let N = (2 * p * 10000 + q) div (2 * q); write N div 10000 in decimal, followed by "." and N mod 10000 as 4 digits (padded with leading zeros). For example, if p = 5 and q = 3, then N = 16667 and the string is 1.6667.
- "percentage p/q" is the string of p / q * 100 rounded to 2 decimal places. Let N = (2 * p * 10000 + q) div (2 * q); write N div 100 in decimal, followed by "." and N mod 100 as 2 digits (padded with leading zeros). For example, if p = 2 and q = 3, then N = 6667 and the string is 66.67. When q = 0, write -.
- Compute decimals and percentages with integers only, without floating-point numbers. The given data contains no value that lies exactly on a rounding boundary.
- "reduced fraction p/q" is the string of the two values obtained by dividing p and q by their greatest common divisor, joined by "/" (e.g. for p = 50 and q = 30, 5/3).
- Every ranking or selection rule comes with a rule for deciding between equal values. Strings such as names are compared in lexicographic order of their ASCII codes.

* 2. Trace checking
Number the lines of trace.txt 1, 2, ... from the top. Split each line into fields at spaces. Where two or more spaces are consecutive, or where there is a space at the start or end of the line, empty fields arise; an empty line consists of one empty field. For each line, check the following rules from top to bottom, and exclude the line with the reason (the English word on the left) of the first rule that applies. An excluded line is called an "invalid line". A line to which no rule applies is accepted as a valid record.
1. fields: the number of fields is not 8, or there is an empty field.
2. pc: the PC is not an 8-digit hex, or is not a multiple of 4.
3. class: the class is none of the 7 names.
4. register: one of rd, rs1, rs2 is neither "-" nor a register in the register notation (r0 to r31).
5. operands: the use of rd, rs1, rs2 does not match the per-class table in [Input files].
6. taken: the outcome is neither T nor N for BRANCH, is not T for JUMP, or is not "-" for any other class.
7. target: for BRANCH and JUMP, the target is not an 8-digit hex, is not a multiple of 4, or equals PC + 4. For any other class, the target is not "-".
8. address: for LOAD and STORE, the address is not an 8-digit hex, or is not a multiple of 4. For any other class, the address is not "-".
9. conflict: a record with the same PC has already been accepted earlier, and the line differs from the first such accepted record in any of class, rd, rs1, rs2. Or, the class is BRANCH or the line is a direct jump, and the target differs from that first record (the target of an indirect jump may change from execution to execution).
The accepted records are called "instructions" and are numbered instruction 1, instruction 2, ..., instruction n in the order in which they were accepted. This number is called the "instruction number", and this order the "instruction order". The rest of the processing uses only instructions. Since instructions with the same PC all have the same class and registers, the group of instructions for each PC value is called a "static instruction", and their class and registers are called the class and registers of the static instruction.
BRANCH and JUMP instructions are called "control instructions". The "next PC" of instruction i is the target if the outcome is T, and PC + 4 otherwise. For i = 2, ..., n, a place where the PC of instruction i differs from the next PC of instruction i - 1 is called a "gap" (a place where lines were excluded or duplicated). Gaps do not affect the simulation; they are only reported.

* 3. Register dependences
- r0 is a register whose value is always 0, and writes to r0 are discarded. An instruction whose rd is one of r1 to r31 is called an instruction that "writes" that register (ALU, MUL, LOAD, and JUMP that writes a link).
- The "sources" of an instruction are those of rs1 and rs2 that hold a register r1 to r31 (r0 and "-" are not included). The source order is rs1, then rs2; even if rs1 and rs2 are the same register, they count as 2 sources.
- When the register of a source of instruction i is r, among the instructions before i that write r, the one with the largest instruction number is called the "producer" of that source. If there is no such instruction, the source has no producer. The "distance" of a source with producer p is i - p.

* 4. Branch prediction
Among JUMPs, one whose rd is r31 is called a "call", and one whose rd is "-" and whose rs1 is r31 is called a "return".
Prediction is done independently for each predictor, in one pass over all instructions in instruction order. Each predictor starts with an empty BTB, an empty RAS and a direction predictor in its initial state. Instructions that are not control instructions are not predicted and are never mispredictions.
(1) BTB
The BTB has E entries (E is the number of BTB entries), and each entry is either empty or holds one (PC, target) pair. Initially all entries are empty. The entry corresponding to an instruction whose PC is pc is entry number (pc div 4) mod E.
- Lookup: if the corresponding entry is not empty and its PC equals pc, it is a "hit" and the target of that entry is returned. Otherwise it is a "miss".
- Insert: replace the corresponding entry with the (PC, target) of the instruction.
(2) RAS
The RAS is a stack of depth S (the depth of the RAS), initially empty.
- Push: if S = 0, do nothing. If the stack already holds S values, discard the oldest value, then push.
- Pop: remove and return the newest value.
(3) Direction predictors
A direction predictor predicts the outcome of a BRANCH (taken / not taken). A "2-bit counter" holds a value from 0 to 3 and predicts "taken" if its value is 2 or more. "Updating" a counter increases it by 1 if the branch was actually taken (3 stays 3) and decreases it by 1 if it was not taken (0 stays 0). Below, pc is the PC of the BRANCH, and b is 1 if the branch was actually taken and 0 if not. Unless stated otherwise, the table index is (pc div 4) mod (the size of that table).
- STATIC_NT: always predicts "not taken".
- BTFN: predicts "taken" if target < PC (a backward branch), and "not taken" otherwise.
- ONEBIT: uses a table holding 0 or 1 (initially all 0) and predicts "taken" if the value is 1. An update sets the value to b.
- TWOBIT: uses a table of 2-bit counters (initially all 1), predicts with the counter, and an update updates that counter.
- GSHARE: uses a table of G 2-bit counters (initially all 1) and an h-bit history g (initially 0) (G is the table size and h is the number of history bits). The table index is ((pc div 4) xor g) mod G. An update updates the counter at that index, then sets g to (2 * g + b) mod 2^h.
- TOURNAMENT: uses the equivalent of a TWOBIT with the local table size (the local predictor), the equivalent of a GSHARE with the global table size and the number of history bits (the global predictor), and a table of 2-bit counters with the chooser table size (the chooser table, initially all 1). If the chooser table counter is 2 or more, the prediction of the global predictor is used; otherwise the prediction of the local predictor is used. An update first, only when the (pre-update) predictions of the two predictors differ, increases the chooser table counter by 1 (up to 3) if the global predictor's prediction was correct, and decreases it by 1 (down to 0) otherwise. Then it updates the local predictor and the global predictor, in this order.
- PERFECT: has no direction predictor and predicts every control instruction correctly.
(4) Prediction procedure
For each control instruction i, do the following in order.
1. Look up the BTB. On a hit, the returned target is the "candidate"; on a miss, there is no candidate.
2. If i is a return and the RAS is not empty, the value popped from the RAS becomes the candidate (the BTB result is not used). This is called a "RAS prediction", and if the popped value equals the target of instruction i, it is a "correct RAS prediction".
3. If i is a call, push PC + 4 onto the RAS.
4. Determine the "predicted next PC" as follows.
  PERFECT: the next PC of instruction i.
  JUMP: the candidate if there is one, otherwise PC + 4.
  BRANCH: the candidate if the direction predictor predicts "taken" and there is a candidate, otherwise PC + 4.
5. If the predicted next PC differs from the next PC of instruction i, i is a "misprediction". The misprediction kind is direction if i is a BRANCH and the direction predictor's prediction differs from the actual outcome; otherwise it is btb_miss if there is no candidate and wrong_target if there is a candidate. This order is called the "misprediction kind order".
6. If i is a BRANCH, update the direction predictor with the actual outcome (STATIC_NT, BTFN and PERFECT do nothing).
7. If the outcome of i is T, insert i into the BTB.
Since the behavior of the BTB and the RAS does not depend on the predictor scheme, the number of BTB hits, the number of RAS predictions and the number of correct RAS predictions are the same for every predictor.

* 5. Pipeline timing
From one pipeline variant (forwarding, resolution stage, multiply latency L) and whether each instruction is a misprediction under one predictor, determine the cycles F_i, D_i, X_i, M_i, W_i in which each instruction i enters the IF, ID, EX, MEM and WB stages. Cycles are numbered from 1. Instructions advance through the pipeline in instruction order, and each stage can hold only one instruction at a time. An instruction stays at least 1 cycle in IF and in ID, e_i cycles in EX (L for MUL, 1 otherwise), and 1 cycle each in MEM and WB. Since the multiplier is not pipelined, the next instruction cannot enter EX during the L cycles in which a MUL is in EX.
(1) Resolution stage
The destination of BRANCH and indirect jumps is determined in the variant's resolution stage, and that of direct jumps is determined in ID regardless of the variant. An instruction whose destination is determined in ID is called an "ID-resolved instruction". An ID-resolved instruction needs its source values at the start of its last cycle in ID (cycle X_i - 1). Every other instruction (control instructions whose destination is determined in EX, and instructions that are not control instructions) needs its source values at the start of its first cycle in EX (cycle X_i) (the same holds for the data to write of a STORE).
(2) Ready cycle of a source
For a source with producer p, the smallest value of X_i that instruction i can take with respect to that source is called the "ready cycle" of that source, defined as follows.
- Forwarding on: W_p if p is a LOAD, otherwise M_p. However, if i is an ID-resolved instruction, add 1 to this.
- Forwarding off: W_p + 1.
(The result of an instruction other than LOAD is available at the end of its last cycle in EX, and the result of a LOAD at the end of its MEM cycle; with forwarding it can be used from the next cycle. Without forwarding, source values are read from the register file in the last cycle in ID. A value written in the first half of the WB cycle can be read in the second half of the same cycle.)
Sources without a producer do not affect timing.
(3) Refetch
When a control instruction b is a misprediction, the instructions fetched from the wrong path are cancelled, and the correct next instruction (instruction b + 1) enters IF in cycle X_b if b is an ID-resolved instruction, and in cycle X_b + 1 otherwise. This cycle is written R_b.
(4) Formulas
Compute the following in instruction order.
  F_1 = 1, D_1 = 2, X_1 = 3
  for i >= 2:
    F_i = D_(i-1) (however, if instruction i - 1 is a mispredicted control instruction, F_i = R_(i-1))
    D_i = max(F_i + 1, X_(i-1))
    X_i = max(D_i + 1, M_(i-1), the ready cycle of each source of instruction i that has a producer)
  M_i = X_i + e_i, W_i = M_i + 1
The formula for F_i expresses that, since IF can hold only one instruction, the next instruction is fetched in the cycle in which the previous instruction moves to ID. The formulas for D_i and X_i express that an instruction can advance to the next stage once it has stayed at least 1 cycle in its current stage and the previous instruction has vacated the next stage (and, for X_i, also its source values are ready). An instruction waiting because of a data hazard or a structural hazard stays in ID, and the instruction behind it stays in IF. Instructions never stall after EX.
The total cycle count C is W_n.

* 6. Causes of stalls
(1) Stall records
For i >= 2, the number of cycles g_i = X_i - X_(i-1) - 1 by which instruction i enters EX later than the ideal cycle X_(i-1) + 1 is divided among the following 4 causes. This order is called the "cause order". Each cause defines a "lower bound" on X_i.
- control (refetch after a misprediction): D_i + 1
- structural (waiting for the multiplier to become free): M_(i-1)
- load_use (waiting for the result of a LOAD): the maximum ready cycle of the sources whose producer is a LOAD. If there is no such source, X_(i-1) + 1.
- raw (waiting for a result other than a LOAD): the maximum ready cycle of the sources whose producer is not a LOAD. If there is no such source, X_(i-1) + 1.
Starting from the value c = X_(i-1) + 1, for each cause in cause order, if the lower bound of that cause is greater than c, record a stall of "lower bound - c" cycles for that cause and set c to the lower bound. When all 4 causes have been checked, c equals X_i.
Each recorded entry is called a "stall record". A stall record has a cause, a number of cycles (a positive integer), a responsible instruction and a waiting instruction.
- Waiting instruction: instruction i.
- Responsible instruction: for control and structural, instruction i - 1 (the mispredicted control instruction, or the MUL); for load_use and raw, instruction i.
- A load_use or raw stall record additionally has a "producer": the producer of the source that gave the lower bound of that cause (if 2 sources give the lower bound, the rs1 one).
Finally, if instruction n is a MUL and L >= 2, add one stall record with cause structural, L - 1 cycles, responsible instruction n and no waiting instruction (for the time instruction n itself stays in EX).
Stall records are ordered by increasing i, by cause order for the same i, with the final record, if any, placed last. This is called the "record order". If S is the sum of the cycles of all stall records, C = n + 4 + S holds.
(The lower bound of control exceeds X_(i-1) + 1 only when instruction i - 1 is a misprediction, and that stall is 1 cycle if instruction i - 1 is an ID-resolved instruction and 2 cycles otherwise. The lower bound of structural exceeds X_(i-1) + 1 only when instruction i - 1 is a MUL and L >= 2, and that stall is L - 1 cycles.)
(2) Wrong-path instructions
For a mispredicted control instruction b, 1 instruction if b is an ID-resolved instruction, and 2 instructions otherwise, are fetched from the wrong path and cancelled. These are called "wrong-path instructions". The PC of the first one is the predicted next PC of b (call it P), and the PC of the second one is P + 4. Wrong-path instructions cause no hazards and do not affect the timing of other instructions. The cycles in which they are in each stage are as follows.
- b is an ID-resolved instruction: the first one is in IF in cycles D_b to X_b - 1 and is cancelled in cycle X_b.
- b is any other instruction: the first one is in IF in cycles D_b to X_b - 1, in ID in cycle X_b, and is cancelled in cycle X_b + 1. The second one is in IF in cycle X_b and is cancelled in cycle X_b + 1.
The "refetch count" is the total number of wrong-path instructions.

* 7. Pipeline diagram
The pipeline diagram has one row per instruction and one row per wrong-path instruction, with the following characters placed in the cycles. A cycle in which no character is placed is empty.
- The row of instruction i (a "correct-path row"): F in cycle F_i, * in F_i + 1 to D_i - 1, D in D_i, * in D_i + 1 to X_i - 1, X in X_i to M_i - 1, M in M_i, and W in W_i.
- The row of a wrong-path instruction (a "wrong-path row"): for the first one of an ID-resolved instruction b, F in D_b, * in D_b + 1 to X_b - 1, and x in X_b. For the first one of any other b, F in D_b, * in D_b + 1 to X_b - 1, D in X_b, and x in X_b + 1; for the second one, F in X_b and x in X_b + 1.
(When the end of a "to" range is smaller than its start, nothing is placed.)
The rows are the correct-path rows in instruction order, with the wrong-path rows of each mispredicted control instruction placed immediately after its row, first one then second one. This is called the "row order".
In each row, F and the * following it mean being in IF, D and the * following it mean being in ID, X means being in EX, M in MEM, and W in WB. x denotes the cycle in which the instruction is cancelled, and it is in no stage. Each stage holds only one row at a time.

* 8. Analysis of the primary variant
For the pair of the primary variant and the primary predictor, compute the following values from the results of 5 to 7. In this section, C, S, the stall records and so on all belong to this pair.
(1) Basic values
- CPI is C / n, and IPC is n / C.
- The stall cycles of each cause (the sum of the cycles of the stall records of that cause) and the stall count (the number of stall records of that cause).
- The CPI stack: base (always 1.0000), fill (decimal 4/n), and each cause (decimal (stall cycles of that cause)/n).
- Stall lengths: the counts of the positive values among g_i (i = 2, ..., n), divided into the 5 groups 1, 2, 3, 4, and 5 or more.
(2) Dataflow height
In instruction order, let the start s_i of instruction i be the maximum of the finish f_p of the producers p of the sources of i (0 if no source has a producer), and let the finish be f_i = s_i + l_i. l_i is 2 for LOAD, the primary variant's L for MUL, and 1 otherwise. The dataflow height H is the maximum of f_1, ..., f_n, and ILP is n / H.
(3) What-if runs
Change exactly one thing in the primary variant and the primary predictor's mispredictions (use the unchanged parts as they are), recompute the timing of 5, and obtain the total cycle count C'. Do the following 4 runs in this order.
- perfect_prediction: treat every instruction as not mispredicted (the variant is unchanged).
- single_cycle_mul: set the multiply latency to 1.
- forwarding_off or forwarding_on: invert forwarding (the name is forwarding_off if the primary variant is ON, and forwarding_on if it is OFF).
- branch_stage_ID or branch_stage_EX: invert the resolution stage (the name is branch_stage_ID if the primary variant is EX, and branch_stage_EX if it is ID).
(4) Per class
For each class in class order, compute the number of instructions of that class and the sum of the cycles of the stall records whose responsible instruction is of that class.
(5) Forwarding paths
Count all sources of all instructions, divided into 3 groups by how the value is received. Let u = X_i - 1 if instruction i is an ID-resolved instruction, and u = X_i otherwise.
- ex_mem: forwarding is on and, for the producer p, M_p = u (received from the EX/MEM pipeline register).
- mem_wb: forwarding is on, i is not an ID-resolved instruction, and W_p = u (received from the MEM/WB pipeline register).
- regfile: everything else (no producer, forwarding off, or read from the register file).
(6) Stage occupancy
Over all rows of the pipeline diagram (regardless of the window), count the cycles spent in each stage. For each stage, compute the number of cycles a in which a correct-path row is in it, the number of cycles b in which a wrong-path row is in it, and the number of cycles C - a - b in which no row is in it.
(7) Instructions with the most stalls
Sum the cycles of the stall records by cause for each PC of the responsible instruction. Sort the PCs whose total is positive by decreasing total (ties by increasing PC), and select the first TOP of them (all of them if there are fewer).
(8) Dependency pairs
Group the load_use and raw stall records by (producer PC, waiting instruction PC, cause), and compute the sum of the cycles and the number of records for each group. Sort the groups by decreasing sum of cycles, ties by increasing producer PC, then by increasing waiting instruction PC, then by cause order (load_use, raw), and select the first TOP of them (all of them if there are fewer).
(9) Intervals
Divide the instructions into intervals of INTERVAL instructions each, starting from the smallest instruction number (the last interval may have fewer than INTERVAL instructions). The cycle count of the interval of instructions a to b is W_b - W_(a-1) (with W_0 = 0), and its CPI is that cycle count / (b - a + 1).

* 9. Profile
This section is also computed for the pair of the primary variant and the primary predictor (only best in (1) uses all predictors). An "execution" of a static instruction is an instruction with its PC, and the order of executions is instruction order.
(1) Branch behavior
For each BRANCH static instruction, compute the following.
- Direction: backward if target < PC, forward otherwise.
- The number of executions, and the number of executions whose outcome is T.
- Number of transitions: the number of times the outcomes of two consecutive executions differ.
- Longest runs: the maximum number of consecutive executions whose outcome is T, and the maximum number of consecutive executions whose outcome is N (0 if there are none).
- best: among the predictors whose scheme is not PERFECT, the one with the fewest mispredictions on this static instruction (ties broken by predictor order, earlier first), and that number of mispredictions.
(2) Loops
A BRANCH static instruction whose direction is backward is regarded as a loop from its target to its PC.
- Body instruction count: (PC - target) div 4 + 1.
- Trips: looking at the executions of the static instruction in execution order, the executions from just after the previous trip up to and including the next execution whose outcome is N form one "trip", and the number of executions in a trip is the length of that trip. If the outcome of the last execution is T, the executions after the last execution whose outcome is N (all executions if there is no execution with outcome N) also form one trip.
- Compute the number of trips, the number of executions, the average length (number of executions / number of trips), and the longest length.
(3) Segments
Divide the instructions, starting from instruction 1, into sequences split immediately after each control instruction (the last sequence ends with instruction n). One sequence is called a "segment", and the PC of its first instruction its "start PC". The cycle count of the segment of instructions a to b is W_b - W_(a-1) (W_0 = 0). For each start PC, compute the number of segments, the sum of instruction counts and the sum of cycle counts; sort by decreasing sum of cycle counts (ties by increasing start PC), and select the first TOP of them (all of them if there are fewer).
(4) Indirect jumps
For each indirect jump static instruction, compute the number of executions, the number of distinct target values, and the number of executions for each target.
(5) Static instructions
For each static instruction, compute the number of executions and the sum of the cycles of the stall records whose responsible instruction has its PC.

* 10. Comparison of predictors and variants
(1) Per-predictor totals
For each predictor in predictor order, compute the following from the predictions of 4.
- Storage (number of bits): 0 for STATIC_NT, BTFN and PERFECT; the table size for ONEBIT; 2 * (table size) for TWOBIT; 2 * (table size) + (history bits) for GSHARE; 2 * (local table size + global table size + chooser table size) + (history bits) for TOURNAMENT.
- The number of control instructions, the number of mispredictions, and the accuracy (percentage (number of control instructions - number of mispredictions)/(number of control instructions)). Compute the accuracy for BRANCH only and for JUMP only in the same way.
- The number of mispredictions of each misprediction kind.
(2) All combinations
For every combination of a variant and a predictor, compute from 5 and 6 the total cycle count and the stall cycles of each cause. Sort the combinations by increasing cycle count, ties by increasing variant name, then by increasing predictor name, and rank them 1, 2, ... from the top.

[Source files]
Split the program into the following 6 source files (file names follow the conventions of each language).
- main: holds the overall flow and most of the processing. It checks each line of the trace (the 9 rules and reasons) and detects gaps, runs the prediction procedure for each predictor (calling the BTB, the RAS and the direction predictor, and determining the misprediction kind), computes the timing and aggregates the stall records for all combinations, performs the analysis of the primary variant (basic values, stall lengths, dataflow height, what-if runs, per class, forwarding paths, stage occupancy, instructions with the most stalls, dependency pairs, intervals), assembles the rows of the pipeline diagram (including wrong-path rows and annotations) and the stage contents, computes the profile (branch behavior, loops, segments, indirect jumps, static instructions), computes the per-predictor totals and the comparison ranking, and assembles the contents of the 5 output files.
- trace_io: reads the 2 input files. It returns trace.txt as a sequence of lines, provides helpers that parse 8-digit hex and register notation, and reads config.txt and returns the configuration values (BTB, RAS, the sequences of predictors and variants, PRIMARY, WINDOW, TOP, INTERVAL).
- hazards: handles register dependences. It extracts the sources of an instruction, determines the producer of each source, decides whether an instruction is an ID-resolved instruction, computes the ready cycles of sources, and determines the forwarding path.
- pipeline: from one variant and the misprediction flags, computes F_i, D_i, X_i, M_i, W_i of each instruction with the formulas of 5, and creates the stall records with the rules of 6 (1).
- predictors: handles the BTB (lookup and insert), the RAS (push and pop), the 6 kinds of direction predictor (predict and update), and the storage calculation.
- report: handles the decimal, percentage, reduced fraction and 8-digit hex formats, assembling the strings of pipeline diagram rows (the left-hand columns, the cycle characters, and the digit sequence of line 2), and writing sequences of lines to files.

[Constraints]
- trace.txt has 1 to 20000 lines, and at least 1 line is accepted. The given trace.txt has 6896 lines, of which 6876 are accepted.
- config.txt correctly follows the format in [Input files]. There is no need to check the configuration for errors.
- 1 <= start cycle <= end cycle <= (C of the primary variant and primary predictor), end cycle - start cycle < 100, and TOP <= 50.
- In all combinations and what-if runs, the total cycle count is at most 100000. Every integer that appears in the computation (including intermediate values in the decimal and percentage computations) is less than 2^31.
- In the given data, the last instruction is not a MUL. Also, no value written as a decimal or percentage lies exactly on a rounding boundary.

Instruction 6 (a call) is a direct jump, so it is an ID-resolved instruction. Because the BTB misses, it is a misprediction (btb_miss), and 1 wrong-path instruction (PC 00001018) is fetched. Instruction 6 waits 2 cycles in ID while the MUL (instruction 5) is in EX (structural 2), and during that time the wrong-path instruction also waits in IF.
