[Overview]
Write a program that, for a Bayesian network of discrete variables, learns conditional probability tables from sample data and answers a variety of probabilistic inference and structure queries. The subject is diagnosing why a car engine does not start, but since the variables, states and parent-child relations are all given in the input, the program can be used as is for networks on other subjects.
The input is 4 files in the input/ folder (network, sample data, queries, settings), and the results are written to 5 files in the output/ folder. Nothing is printed to standard output. The only source of random numbers is the generator defined in this statement (MINSTD), so the results are uniquely determined.
The processing consists of the following 6 main parts.
1. Reading the network: read the variables and their states, the parent-child relations, and the conditional probability tables (CPTs) given by experts, and compute basic quantities such as the topological order.
2. Learning and evaluation: learn the CPTs of the variables specified in the settings from the sample data by counting with a pseudocount. Compute the log-likelihood of the samples and the BIC score under the CPTs in use, and compare the marginal distributions of the model with the frequencies in the samples.
3. Exact inference: by variable elimination, compute posterior probabilities (QUERY) and the most probable assignment of all variables given the evidence (MPE). Elimination orders are built in 2 ways, by the min-fill method and from the given order, and their costs are compared; small problems are cross-checked by full enumeration.
4. Approximate inference: estimate posterior probabilities by likelihood-weighting sampling with random numbers (SAMPLE), and compare them with the exact values.
5. Prediction: using the Markov blanket, predict the state of a variable in each sample from the remaining variables, and compute the accuracy and related values (PREDICT).
6. Structure queries: determine d-separation by the Bayes-ball method together with the conditional mutual information in the samples (DSEP), the Markov blanket (BLANKET), and whether adding, removing or reversing an edge creates a cycle, together with the change in the BIC score (EDGE).

[Input files]
The input files are the 4 files input/network.txt, input/samples.csv, input/queries.txt and input/params.txt. Every file consists of ASCII characters only, and every line (including the last line) ends with a line feed (LF). No line has leading or trailing spaces, and values within a line are separated by a single space (by a comma in samples.csv).
- Variable names and state names are strings of 1 to 16 characters consisting of English letters (uppercase and lowercase). Case is significant. All variable names are distinct, and the state names of one variable are all distinct (different variables may have the same state name).
- A decimal is a decimal number consisting of a sequence of one or more digits, ".", and a sequence of one or more digits, in this order (e.g. 0.30, 1.0, 0.05). An integer is a decimal number with no extra leading zeros.

== input/network.txt (network) ==
Empty lines and lines whose first character is "#" (comment lines) are skipped. The other lines are of the following 3 kinds, in this order: first all VARIABLE lines, then all PARENTS lines, and finally all CPT blocks.
- VARIABLE line: "VARIABLE <variable name> <state name 1> <state name 2> ...". It describes one variable and its states. The number of states is 2 to 4 inclusive.
- PARENTS line: "PARENTS <child variable name> <parent variable name 1> ...". It gives the parents (1 to 3 inclusive) of the child variable. The parents are distinct from each other and from the child. Each variable has at most one PARENTS line, and a variable without a PARENTS line has no parents. The PARENTS lines may appear in any order.
- CPT block: a line "CPT <variable name>" followed immediately by R lines. R is the number of parent combinations of that variable (defined below), and is 1 for a variable without parents. The following R lines give, in the order of parent combinations, the probability of each state under that combination, in state order (as many decimals as there are states). A CPT block contains no empty lines or comment lines. Each variable has at most one CPT block, and some variables have no CPT block. The CPT blocks may appear in any order.
Probabilities are positive decimals with 1 to 4 fractional digits. The probabilities in each line sum to exactly 1 (as decimal numbers).
The order of the VARIABLE lines is called the "variable order", and the variables are numbered variable 1, variable 2, ..., variable n in that order. For each variable, the sequence of states written on its VARIABLE line is called the "state order", and the states are numbered state 1, state 2, ... in that order. The number of states of variable v is written k_v.
The sequence of parents written on a PARENTS line is called the "parent order" (it is not necessarily the same as the variable order). For a variable v whose parent order is (p_1, p_2, ..., p_m), a "parent combination" is a tuple of states of the parents (s_1, s_2, ..., s_m), and the "order of parent combinations" is the lexicographic order in which the state of the last parent p_m changes fastest (for example, with 2 parents having 2 and 3 states, the order is (1,1), (1,2), (1,3), (2,1), (2,2), (2,3)). The combinations are counted as number 1, number 2, ... in this order, and their count is k_(p_1) * k_(p_2) * ... * k_(p_m). A variable without parents has exactly one combination.

== input/samples.csv (sample data) ==
Line 1 is the header line, which lists every variable name exactly once, in any order, separated by commas. Each line from line 2 onward is one sample, listing the state names of the variables of the header columns, in the same order, separated by commas. Each state name is a state of that variable. The number of samples is N, and the order of the lines in the file is called the "sample order".

== input/queries.txt (queries) ==
Each line holds one query, and there are no empty lines. The lines are numbered 1, 2, ... in order, and this number is called the "query number". A "|" appearing in a query line is, like any other value, a single value separated by spaces.
A value of the form "<variable name>=<state name>" is called "evidence", and means that the variable has been observed to be in that state. Within one query, the variables of the evidence are distinct from each other. There are the following 7 kinds of queries.
- QUERY: "QUERY <variable name> ..." or "QUERY <variable name> ... | <evidence> ...". The 1 to 3 variables (distinct from each other) before "|" are called the "query variables". If there is a "|", one or more evidence values follow it. The query variables are different from the evidence variables.
- MPE: "MPE" or "MPE <evidence> ...". There are zero or more evidence values.
- SAMPLE: "SAMPLE <variable name> ... COUNTS <integer> ..." or "SAMPLE <variable name> ... | <evidence> ... COUNTS <integer> ...". The rules for query variables and evidence are the same as for QUERY. The 1 to 5 integers after COUNTS are called the "sample count list". The sample count list is a sequence of positive integers in increasing order (with no equal values), and its largest value is at most 5000.
- PREDICT: "PREDICT <variable name>".
- DSEP: "DSEP <variable name> ... | <variable name> ..." or "DSEP <variable name> ... | <variable name> ... | <variable name> ...". The first, second and third sequences of variables separated by "|" are called X, Y and Z respectively. X and Y each consist of one or more variables. When there is only one "|", Z is empty. The variables of X, Y and Z are all distinct from each other.
- BLANKET: "BLANKET <variable name>".
- EDGE: one of "EDGE ADD <variable name x> <variable name y>", "EDGE REMOVE <variable name x> <variable name y>" and "EDGE REVERSE <variable name x> <variable name y>". x and y are different.

== input/params.txt (settings) ==
It consists of the following 5 lines followed by n lines, in this order.
- PSEUDOCOUNT alpha: the pseudocount for learning (a positive decimal).
- ELIMINATION MINFILL or ELIMINATION GIVEN: how the elimination order used to compute the answers is determined (called the "method in use"). MINFILL is the min-fill method, and GIVEN is the given order.
- ORDER <variable name> ...: the "given order". It lists every variable exactly once.
- ENUMERATION_LIMIT L: the upper limit on the number of assignments for which the cross-check by full enumeration is performed (a positive integer).
- SEED x0: the random seed (an integer from 1 to 2147483646 inclusive).
- The following n lines: "SOURCE <variable name> GIVEN" or "SOURCE <variable name> LEARNED", one line for each variable, in variable order. For a GIVEN variable, the values of its CPT block in network.txt are used; for a LEARNED variable, the values learned from the sample data are used. A GIVEN variable always has a CPT block.

[Processing]
== 1. Notation and computation rules ==
- ln is the natural logarithm, and |t| is the absolute value of t. Real-number computations are done in double-precision floating point (IEEE 754 64-bit).
- A sum (sum) is computed by adding the terms one at a time, starting from the first term, in the specified order. Likewise, a product is computed by multiplying one factor at a time, starting from the first, in the specified order. The order of the terms of each sum and product is specified where it appears.
- Unless stated otherwise, a set of variables is handled in variable order.
- An "assignment" of a set of variables S maps each variable of S to one of its states. When S listed in variable order is (u_1, ..., u_r), the "canonical order" of the assignments of S is the lexicographic order of the state tuples (s_1, ..., s_r) in which the state of the last variable u_r changes fastest (the same idea as the order of parent combinations). When S is the empty set, there is exactly one assignment. The number of assignments is k_(u_1) * ... * k_(u_r).
- Every rule that selects a largest or smallest item comes with a rule for choosing among items with equal values.

== 2. Basic quantities of the network ==
- The set of parents of variable v is written Pa(v) (listed in parent order). A variable that has v as a parent is called a "child" of v. A variable without parents is called a "root", and a variable without children is called a "leaf".
- The "ancestors" of v are the variables reachable by following v's parents, the parents' parents, ... (not including v itself), and the "descendants" of v are the variables reachable by following v's children, the children's children, ... (not including v itself). The "ancestral closure" An(S) of a set of variables S is the set of the variables of S together with all of their ancestors.
- The number of edges is the sum of the numbers of parents of all variables.
- Topological order: repeat n times the step of selecting, among the variables not yet selected whose parents have all been selected (or that have no parents), the variable with the smallest number; the topological order is the variables in the order they were selected.
- Depth: the depth of a root is 0, and the depth of any other variable is (the maximum depth of its parents) + 1.
- Markov blanket MB(v): the set consisting of v's parents, v's children and v's "spouses". A spouse is a variable that is a parent of some child of v and is neither v itself, nor a parent of v, nor a child of v.
- Moral graph: the undirected graph that, for each variable v, connects by an edge every pair of distinct variables contained in {v} union Pa(v). Its number of edges is the number of pairs of distinct variables that are connected (the same pair is counted only once).

== 3. CPTs and learning ==
The CPT of variable v is the table of probabilities theta_v(s | r) for each parent combination r of v (number 1, number 2, ...) and each state s of v. A "row" of the CPT corresponds to one parent combination, and the order of the rows is the order of parent combinations.
(1) Counts: N_v(r, s) is the number of samples in which the parents' states are combination r and the state of v is s.
(2) Learned CPT: for each row r, let T = sum_(s = 1, ..., k_v) (N_v(r, s) + alpha) (added in state order), and theta_v(s | r) = (N_v(r, s) + alpha) / T.
(3) CPT in use: for a variable whose SOURCE is GIVEN, the values of its CPT block (the decimal numbers converted to double precision); for a LEARNED variable, the learned CPT of (2). From here on, theta_v denotes the values of the CPT in use (only the family score of (9), and EDGE in section 13, which uses it, use the learned CPT).
(4) Log-likelihood: LL_v = sum N_v(r, s) * ln theta_v(s | r). The sum is taken in row order, and within the same row in state order; terms with N_v(r, s) = 0 are not added. The log-likelihood of the network is LL = sum_v LL_v (in variable order).
(5) Number of parameters: d_v = (k_v - 1) * (the number of parent combinations of v), and the number of parameters of the network is d = sum_v d_v.
(6) BIC score: bic_v = LL_v - d_v * ln(N) / 2, and the BIC score of the network is BIC = LL - d * ln(N) / 2 (larger is better).
(7) Difference from the expert values: for a variable whose SOURCE is LEARNED and that has a CPT block, the maximum of |(learned theta_v(s | r)) - (CPT block value)| over all rows r and states s.
(8) Comparison of marginal distributions: the model's marginal distribution of variable v is P(v = s) computed by (1) to (6) of section 7 as the query "QUERY v" without evidence. The sample frequency is (the number of samples in which the state of v is s) / N.
(9) Family score: for a variable v and a set of variables P, score(v, P) is the learned score when P is regarded as the parents of v. Using P listed in variable order as the parent order, build the parent combinations and the counts, and with the learned CPT of (2), the log-likelihood of (4), the number of parameters of (5), and the formula of (6), let score(v, P) = LL_v - d_v * ln(N) / 2. The family score is always computed with the learned CPT, regardless of SOURCE.

== 4. Factors ==
A factor consists of a set of variables (called the "factor's variables", listed in variable order) and a real value for each assignment of those variables. The values are handled in canonical order of the assignments. A factor's variables may be empty, in which case it has exactly one value.
(1) CPT factor: the variables of the CPT factor of variable v are {v} union Pa(v). Its value at assignment a is theta_v(state of v in a | r), where r is the combination formed by the parents' states in a, listed in parent order.
(2) Reduction by evidence: the reduction of a factor phi by a set of evidence (a collection of pairs of a variable and a state) is the factor whose variables are phi's variables minus the evidence variables, and whose value at its assignment b is the value of phi at the assignment formed by b plus the evidence states.
(3) Product: the variables of the product phi * psi of factors phi and psi are the union of the variables of both. For each of its assignments c (in canonical order), the value is the value of phi at the assignment c restricted to phi's variables multiplied by the value of psi at the assignment c restricted to psi's variables. The product of a sequence of factors f_1, f_2, ..., f_m is computed by multiplying in sequence order as ((f_1 * f_2) * f_3) * ... * f_m. The product of a sequence with only one factor is that factor itself, and the product of an empty sequence is the factor with empty variables and value 1.
(4) Elimination by summation: the variables of the factor obtained by summing variable v out of factor phi are phi's variables minus v. Its value at assignment b is the sum, over the states of v in the order s = 1, 2, ..., of the value of phi at the assignment formed by b plus v = s.
(5) Elimination by maximization: the same as (4), but taking the maximum instead of adding.

== 5. Elimination plan (elimination order and cost) ==
From a sequence of factors (the "initial factors"), a set of variables to eliminate (the "elimination set"), and a method (the min-fill method or the given order), the elimination order and the record of each step are determined as follows. This plan does not use the factors' values; it is determined by the variables alone.
(1) Interaction graph: the vertices are the variables contained in the variables of any initial factor. Two distinct variables contained in the variables of the same initial factor are connected by an edge.
(2) Repeat the following until the elimination set is empty.
  - For each variable v in the elimination set, the variables connected to v by an edge in the current graph are the "neighbors" of v, their number is the "degree", and the number of pairs of distinct neighbors that are not connected by an edge is the "fill number".
  - Select the variable to eliminate. With the min-fill method, select the variable with the smallest fill number (on ties, the variable with the smallest degree; if that also ties, the variable with the smallest number). With the given order, select the variable of the elimination set that comes earliest in the given order.
  - For the selected variable v, keep as the record of a "step": v, the fill number of v, the step's variables (the set of v and its neighbors), and the step's size (the product of the numbers of states of the step's variables).
  - Connect by an edge every pair of neighbors of v that is not connected, remove v and its edges from the graph, and remove v from the elimination set.
(3) The sequence of variables in the order they were selected is the "elimination order". The cost is the maximum of the step sizes (0 if there are no steps) and their total.

== 6. Variable elimination ==
From the initial factors and a plan, the final factor is computed as follows. Start the factor sequence with the sequence of initial factors.
(1) For each variable v of the elimination order in turn, take out all factors in the sequence whose variables contain v (keeping their sequence order), remove them from the sequence, and compute their product. This product is called the "step product" (the step product's variables coincide with the step's variables in the plan). In sum-product elimination, sum v out of the step product ((4) of section 4); in max-product elimination, eliminate v by maximization ((5) of section 4); then append the resulting factor to the end of the sequence.
(2) When all variables have been eliminated, the product of the factors remaining in the sequence (in sequence order) is the "final factor".
(3) Traceback (for max-product elimination): in the reverse of the elimination order, for each variable v, the state of v that maximizes the value of that step's product (on ties, the lower-numbered one) is the value of v. At this point, the variables of the step product other than v were eliminated after v, so their values are already determined.

== 7. QUERY (posterior probabilities) ==
Let Q be the set of query variables (listed in the order written in the query), and e the set of evidence.
(1) Relevant variables: R = An(Q union (the variables of e)). The variables not contained in R are called "pruned variables".
(2) Initial factors: the CPT factors of the variables of R, listed in variable order, each reduced by e.
(3) Elimination set: R minus the variables of Q and the variables of e.
(4) Plans: build both the min-fill plan and the given-order plan. Perform sum-product elimination with the plan of the method in use to obtain the final factor F. The variables of F are the variables of Q (in variable order).
(5) Posterior distribution: let Z = (the sum of all values of F, in canonical order), and the posterior probability of each assignment c of Q be p(c) = F(c) / Z. Z is the probability of the evidence P(e), and the log probability of the evidence is ln Z (without evidence, Z is approximately 1).
(6) Marginal posterior probability: for a query variable q and a state s, P(q = s | e) is the sum of p(c) over the assignments c in which the state of q is s (in canonical order).
(7) Evidence conflict: computed when e is not empty. For each evidence e_j of e, perform (1) to (5) with no query variables and with e_j as the only evidence (the variables of the final factor are empty), and let its Z be P(e_j). The conflict is sum_j ln P(e_j) - ln Z (the sum in the order the evidence is written). A positive value means that the pieces of evidence disagree with each other.
(8) Evidence influence: computed when e is not empty. For each evidence e_j of e (in the order written), perform (1) to (6) with the evidence e minus e_j, and the influence of e_j is the maximum of |P(q = s | e) - (P(q = s) when e_j is removed)| over all query variables q and states s.
(9) Order agreement: perform sum-product elimination with each of the min-fill plan and the given-order plan to obtain p(c) and Z of (5); they agree if the absolute difference between the two p(c) is at most 0.000000001 for every c and the absolute difference between the two ln Z is at most 0.000000001.
(10) Cross-check by full enumeration: let U be R minus the variables of e, and K the number of assignments of U. This is performed only when K <= L. Start a value of 0 for each assignment of Q; for each assignment of U (in canonical order), add the joint probability prod_v theta_v(state of v | combination of the states of v's parents) (the product over the variables of R in variable order) at the full assignment formed by that assignment plus the states of e, to the value corresponding to the Q part of that assignment. Let Z' be the sum of the values (in canonical order of the assignments of Q), and p'(c) the value divided by Z'. They agree if |p'(c) - p(c)| <= 0.000000001 for every c and |ln Z' - ln Z| <= 0.000000001.

== 8. MPE (most probable assignment) ==
Let e be the set of evidence (possibly empty).
(1) Initial factors: the CPT factors of all variables, listed in variable order, each reduced by e. The elimination set is all variables other than the variables of e.
(2) Build both the min-fill plan and the given-order plan, and with each perform max-product elimination and traceback. The final factor has empty variables, and its value is M. The values determined by traceback together with the states of e form the MPE assignment. The answer uses the result of the method in use.
(3) The log of the joint probability is ln M. The probability of the evidence P(e) is Z computed by (1) to (5) of section 7 with no query variables and with e as the evidence (1 if e is empty). The posterior probability of the MPE is M / P(e).
(4) Margin: for each variable v other than the variables of e (in variable order), build the plan of the method in use with the same initial factors as (1) and the elimination set consisting of "all variables other than the variables of e and v" (v is not eliminated), and perform max-product elimination. The final factor is a factor whose only variable is v, and its value is m(s). m(s) is the maximum joint probability given v = s. Among the states other than the state of v in the MPE assignment, the one with the largest m(s) (on ties, the lower-numbered one) is the "second-best state" a, and the margin is ln M - ln m(a).
(5) Order agreement: they agree if the MPE assignments of the two plans are the same and the absolute difference between the two ln M is at most 0.000000001.
(6) Cross-check by full enumeration: let U be the set of all variables other than the variables of e, and K the number of its assignments; this is performed only when K <= L. For each assignment of U (in canonical order), compute the joint probability of the full assignment formed by adding the states of e (the product of theta over all variables in variable order), and select the largest one (on ties, the one earlier in canonical order). They agree if that assignment is the same as the MPE assignment and |ln (that joint probability) - ln M| <= 0.000000001.

== 9. SAMPLE (likelihood-weighting sampling) ==
(1) Random numbers: use the MINSTD generator. Start the state x at x0 (SEED); on each generation, update x to (48271 * x) mod 2147483647 and return u = x / 2147483647 (real division). There is only one generator in the whole program; it is started with x0 once at the beginning, and only the SAMPLE queries use it, continuing in order of query number. 48271 * x is less than 2^53 but exceeds 2^31, so compute it with 64-bit integers (or with double-precision floating point, which represents integers below 2^53 exactly).
(2) One weighted sample: let the weight w = 1, and for each variable v in topological order, find the CPT row r from the states of v's parents in this sample, and do the following.
  - If v is an evidence variable, set the state of v to the evidence state, and multiply w by theta_v(evidence state | r).
  - Otherwise, generate one random number u, start with c = 0, add theta_v(s | r) to c for the states in the order s = 1, 2, ..., and the first state s for which u < c becomes the state of v. If u < c does not hold up to the last state, the state is the last state.
(3) Let B be the largest value of the sample count list, and generate B weighted samples in order. After generating the i-th sample, if i is in the sample count list, compute the following over samples 1 to i (sums in sample order).
  - Total weight W = sum w, total squared weight W2 = sum w * w, effective sample size ESS = W * W / W2
  - Estimate for query variable q and state s: (the sum of the weights of the samples in which the state of q is s) / W
  - Exact value: P(q = s | e) computed by (1) to (6) of section 7 with the same query variables and evidence (the same value regardless of the sample count)
  - Error: |estimate - exact value|. The maximum error is the maximum of the errors over all q and s.

== 10. PREDICT (prediction by the Markov blanket) ==
For variable v, compute the following for each sample (in sample order). The states of the variables other than v are their states in that sample.
- For each state s of v, let g(s) = theta_v(s | combination of v's parents' states) * prod_c theta_c(state of c | combination of c's parents' states). g(s) starts from theta_v(s | ...) and is multiplied by theta_c one at a time for the children c of v in variable order. In the states of c's parents, the state of v is taken to be s.
- Let G = sum_s g(s) (in state order) and P(s) = g(s) / G; the state with the largest P(s) (on ties, the lower-numbered one) is the prediction.
The confusion matrix C[a][b] is the number of samples in which the actual state of v is a and the prediction is b. The number correct is sum_a C[a][a], the accuracy is (number correct) / N, and the log loss is -(sum ln P(actual state)) / N (the sum in sample order).

== 11. DSEP (d-separation and conditional mutual information) ==
(1) Reachable variables (Bayes-ball method): let A = An(Z). A pair (variable, direction) is called a "position". The direction is "up" (came from the child side) or "down" (came from the parent side). Let S be the smallest set of positions that contains (x, up) for every variable x of X and is closed under the following rules. For each position (y, d) of S:
  - When d is up and y is not contained in Z: (p, up) for each parent p of y and (c, down) for each child c of y are also contained in S.
  - When d is down: if y is not contained in Z, (c, down) for each child c of y is also contained in S. If y is contained in A, (p, up) for each parent p of y is also contained in S.
The variables appearing in some position of S that are contained in neither Z nor X are the "reachable variables" (S is uniquely determined regardless of the order in which positions are followed). If the reachable variables contain no variable of Y, X and Y are d-separated given Z (separated); otherwise they are not d-separated (connected).
(2) Conditional mutual information: let W = X union Y union Z. Let n(w) be the number of samples matching an assignment w of W, and n_XZ, n_YZ and n_Z the numbers of samples matching the assignment w restricted to X union Z, Y union Z and Z respectively (n_Z = N if Z is empty).
  cmi = sum (n(w) / N) * ln((n(w) * n_Z) / (n_XZ * n_YZ))
The sum is taken over the assignments w of W in canonical order, and terms with n(w) = 0 are not added. The argument of ln is computed by converting each of the two integer products n(w) * n_Z and n_XZ * n_YZ to a real number and then dividing. Further, g2 = 2 * N * cmi, and the degrees of freedom df = (number of assignments of X - 1) * (number of assignments of Y - 1) * (number of assignments of Z) (if Z is empty, the number of assignments of Z is 1).

== 12. BLANKET (Markov blanket) ==
Compute the parents, children and spouses of variable v and its Markov blanket MB(v). Further, let the "rest" be the set of all variables other than v and MB(v), perform (1) of section 11 with X = {v}, Y = rest and Z = MB(v), and answer yes if they are d-separated and no otherwise (yes if the rest is empty).

== 13. EDGE (edge change) ==
Examine whether adding one edge to, removing one edge from, or reversing one edge of the network of network.txt creates a cycle, and the change in the BIC score. EDGE queries do not change the network (every query is answered for the network of network.txt).
(1) Path search: search for a directed path from variable a to variable b (a path following edges from parent to child) by the following breadth-first search. Mark a and start with a queue containing only a. Until the queue is empty, take out the front variable t and examine the children c of t in variable order (an edge to be ignored, if any, is not used). If c is not marked, mark it, set the predecessor of c to t, and if c is b, end the search there; otherwise append c to the end of the queue. If b is marked, a path exists; the path is obtained by following the predecessors from b back to a and listing them in reverse.
(2) ADD x y (add the edge x -> y):
  - If x is already a parent of y, the result is exists.
  - Otherwise, if there is a directed path from y to x, the result is cycle. The cycle is x followed by the path from y to x found by (1): x -> y -> ... -> x.
  - Otherwise, the result is ok. before = score(y, Pa(y)), after = score(y, Pa(y) union {x}), change = after - before.
(3) REMOVE x y (remove the edge x -> y):
  - If x is not a parent of y, the result is missing.
  - Otherwise, the result is ok. before = score(y, Pa(y)), after = score(y, the set Pa(y) minus x), change = after - before.
(4) REVERSE x y (turn the edge x -> y into y -> x):
  - If x is not a parent of y, the result is missing.
  - Otherwise, if there is a directed path from x to y when the edge x -> y is ignored, the result is cycle. The cycle is y followed by that path: y -> x -> ... -> y.
  - Otherwise, the result is ok. For y, before_y = score(y, Pa(y)) and after_y = score(y, the set Pa(y) minus x); for x, before_x = score(x, Pa(x)) and after_x = score(x, Pa(x) union {y}); change = (after_y - before_y) + (after_x - before_x).
(5) When the result is ok, it improves if the change is positive, and worsens otherwise.

== 14. Structure summary ==
With the CPT factors of all variables (not reduced) as the initial factors and all variables as the elimination set, build the min-fill plan and the given-order plan. The "width" of each plan is (the maximum number of step variables) - 1.

[Output files]
Write the 5 files output/cpts.txt, output/structure.txt, output/answers.txt, output/elimination.txt and output/sampling.csv.

== Common rules ==
- The output consists of ASCII characters only, and every line (including the last line) ends with a line feed (LF). Put no extra spaces at the beginning or end of a line, and insert no empty lines unless specified.
- In the formats below, the parts enclosed in < > are replaced by values, and all other characters are written as they are. Values are separated by a single space (by a comma in sampling.csv).
- "<sequence of variables>" means variable names separated by single spaces. The order is specified for each item (if not specified, variable order). When the sequence is empty, write only -.
- <query line> is that line of queries.txt written as is.
- Integers are written as decimal numbers with no extra leading zeros.
- Real numbers are rounded to 4 decimal places and written in fixed-point notation with exactly 4 digits after the decimal point (e.g. 12.5 is 12.5000, -0.00004 is 0.0000). Exponential notation is not used, and 0 is written when the integer part is 0. Negative numbers are prefixed with -, but a value that rounds to 0 is written without - (for example, ln Z without evidence may be a negative number very close to 0, but it is written as 0.0000). The data contain no values close to a rounding boundary.
- In a file consisting of blocks, put one empty line between consecutive blocks (none before the first block or after the last block).

[Source files]
Split the program into the following 6 source files (file names follow the conventions of each language).
- main: handles the overall flow and most of the processing: calling the input readers; the basic quantities of the network (topological order, depth, ancestors and descendants, Markov blanket, moral graph); assembling the CPTs in use and aggregating the log-likelihood, BIC score, comparison of marginal distributions and difference from the expert values; parsing and dispatching the queries; QUERY (relevant variables, posterior distribution and marginal posterior probabilities, conflict, evidence influence, order agreement, cross-check by full enumeration); MPE (probability of the evidence, margin, order agreement, cross-check by full enumeration); aggregating the estimates, effective sample size and errors of SAMPLE; PREDICT; DSEP (reachable variables by the Bayes-ball method and conditional mutual information); BLANKET; EDGE (path search and change in the family score); the structure summary; formatting real numbers (rounding and handling of -0); and assembling and writing the contents of the 5 output files.
- network_io: reads the 4 input files and returns the variable names and state names, the parent sequences, the values of the CPT blocks, the samples (sequences of state numbers of each variable), the query lines, and the setting values.
- learning: handles the numbering of parent combinations, counting, the learned CPT, the log-likelihood, the number of parameters, and the family score.
- factors: handles the factor representation (a sequence of variables and a sequence of values in canonical order), enumeration of assignments in canonical order, creation of CPT factors, reduction by evidence, product, elimination by summation, and elimination by maximization.
- elimination: handles the interaction graph, the plans by the min-fill method and by the given order (step records and costs), sum-product and max-product elimination, and traceback.
- sampling: handles the MINSTD generator, state selection by cumulative probabilities, and generation of one weighted sample along the topological order.

[Constraints]
- 2 <= n <= 15. Each variable has 2 to 4 states inclusive and at most 3 parents. 1 <= N <= 2000, there are at most 40 queries, and L <= 20000. In the given data, n = 15, N = 2000, and there are 31 queries.
- The network has no cycles (following edges from parent to child never returns to the starting variable).
- The input files follow the format above correctly. There is no need to check the input for errors.
- alpha is positive and all probabilities of the CPT blocks are positive, so all values of the CPTs in use are positive. Therefore the probability of any evidence is positive, and no logarithm of 0 or division by 0 occurs.
- In every plan that is executed (the 2 plans of QUERY and MPE, the evidence conflict and influence, the probability of the evidence and the margin of MPE, the exact values of SAMPLE, the comparison of marginal distributions, and the structure summary), the step size is at most 4096 (at most 216 in the given data). In the given data, L = 12000, and the cross-check by full enumeration is performed for 6 queries (K is at most 11664).
- In the given data, every real number output is sufficiently far from a rounding boundary. Also, the maximum selection in MPE traceback and in full enumeration, the selection of the second-best state, the PREDICT prediction, the sign of the EDGE change, the comparisons of u and c in sampling (u is more than 0.000000000001 away from every c), and the agreement checks (the actual differences are less than 0.000000000001) have enough margin not to change under differences in the order of additions, fused multiply-add, or differences in the last digit of ln results (about 1 ulp). Nevertheless, compute with the formulas and orders defined in this statement.
- All integers are less than 2^53. 48271 * x in MINSTD exceeds 2^31, so 32-bit integers are not enough.

Some notes on this example:
- The empty lines and the comment line of network.txt are skipped. The parent order of WetGrass is Rain, Sprinkler, which differs from the variable order (Sprinkler comes first). The rows of the CPT and the row lines of cpts.txt follow the order of parent combinations in parent order, and the variables of the CPT factor of WetGrass are, in variable order, WetGrass, Sprinkler, Rain. The parents line of BLANKET is also in parent order (Rain, Sprinkler).
- Rain is LEARNED, so the learned values are used instead of the values of its CPT block. For example, the Cloudy=No row is 14 / 18, 3 / 18, 1 / 18, obtained by adding alpha = 1 to the counts 13, 2, 0.
- In query 1, Slippery is an ancestor of neither Rain nor WetGrass, so it is a pruned variable. In the first step of the min-fill method, Sprinkler and Cloudy have the same fill number (0) and degree (2), so the lower-numbered Sprinkler is selected. There is only one evidence, so the conflict is 0.
- In the joint lines of query 2, the variables are written in variable order (Sprinkler, Cloudy), but the marginal lines are in the order written in the query (Cloudy, Sprinkler).
- In query 3, the number of assignments of the elimination set is K = 24 > L = 12, so the cross-check by full enumeration is not performed.
- In the first weighted sample of query 4, the random numbers u are generated in the order 0.2775..., 0.7256..., 0.6979..., 0.9412.... Following the topological order, Cloudy is No since u < 0.5, Sprinkler is On since 0.4 <= u < 1.0, Rain is None since u < 0.7778..., WetGrass is evidence so the weight becomes theta(Wet | Rain=None, Sprinkler=On) = 0.9, and Slippery is Yes since 0.5385... <= u.
