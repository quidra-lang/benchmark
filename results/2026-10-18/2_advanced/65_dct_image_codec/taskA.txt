[Overview]
Write an image codec (an encoder and a decoder) that compresses a colour image with the same mechanism as baseline JPEG and restores it. The encoder converts an RGB image into luminance Y and chrominance Cb, Cr, subsamples the chrominance if requested, applies the discrete cosine transform (DCT) to each block of 8 x 8 pixels, quantizes the result, and encodes the coefficients, arranged in zigzag order, into a JPEG-format byte sequence with run lengths and Huffman codes. The decoder parses a JPEG-format byte sequence and turns it back into an image.
The program does the following.
- It compresses the input image at several qualities and lists the number of bytes and the image quality (PSNR) for each quality.
- For the result compressed at the first quality (the reference quality), it computes the decoded image, the JPEG byte sequence, the Huffman tables, per-block statistics, a reduced image built from the DC coefficients only, the image quality when coefficients are truncated, and the distribution of errors.
- It compares the chroma subsampling modes, measures the degradation when compression and decoding are repeated, and searches for a quality that fits within a target number of bytes.
- It decodes a JPEG byte sequence in which some bytes are corrupted (given as an input file), using the restart markers as clues, and builds an image in which the corrupted intervals are filled in. From that result it then builds a repaired byte sequence with optimized Huffman tables and checks that it decodes correctly.
All computations are done with integers, except the logarithm of the PSNR. The program reads the files in the input/ folder and writes files to the output/ folder. It prints nothing to standard output.

[Input files]
Every input file consists of ASCII characters only, and every line ends with a newline (LF). The values on a line are separated by single spaces, with no whitespace at the start or end of a line. Integers are written in decimal, and negative numbers have a leading "-". There are no empty lines.

(1) input/image.ppm: the input image
A colour image in P3 format (ASCII PPM). Line 1 is P3, line 2 holds the width W and the height H, and line 3 holds the maximum value, which is always 255. Of the following H lines, line y + 1 (y = 0, 1, ..., H - 1) holds 3 * W integers: the red, green and blue values R, G, B of the pixels (0, y), (1, y), ..., (W - 1, y), in pixel order, and within each pixel in the order R, G, B. The values are integers from 0 to 255. There are no comment lines.

(2) input/params.txt: parameters
It consists of the following 7 lines in this order. Each line is a parameter name followed by one or more values.
- qualities Q_1 Q_2 ... Q_n: the list of qualities (integers) to compress at. The first one, Q_1, is called the reference quality.
- sampling S: the chroma subsampling mode, one of 444, 422, 420.
- restart_interval Ri: the restart interval (a number of MCUs). When it is 0, no restart markers are used.
- huffman M: the kind of Huffman tables to use, standard (the standard tables) or optimized (optimized tables).
- target_bytes T: the target number of bytes for the quality search.
- generations Ng: the number of repeated compressions.
- truncate K_1 K_2 ... K_m: the list of numbers of coefficients (integers) to keep in coefficient truncation.

(3) input/tables.txt: transform and coding tables
It consists of 39 lines and contains the following tables in this order.
- Line 1 is dct. Of the following 8 lines, line u + 1 (u = 0, 1, ..., 7) holds the elements C(u, 0), C(u, 1), ..., C(u, 7) of the DCT matrix. C(u, x) is the value of 8192 * c_u * cos((2x + 1)u * pi / 16) rounded to an integer, where c_0 = 1 / sqrt(8) and c_u = 1 / 2 (u >= 1). The program uses the values of this table as they are and must not compute trigonometric functions.
- Line 10 is quant 0. Of the following 8 lines, line u + 1 holds the elements B_0(u, 0), B_0(u, 1), ..., B_0(u, 7) of the basic luminance quantization table.
- Line 19 is quant 1. The following 8 lines hold the basic chrominance quantization table B_1 in the same format.
- Lines 28 to 39 are 4 Huffman tables of 3 lines each. The first line is huffman c i (c is the class of the table: 0 for DC, 1 for AC; i is the id of the table: 0 for luminance, 1 for chrominance). The second line holds 16 integers BITS(1), BITS(2), ..., BITS(16), where BITS(L) is the number of codes of length L bits. The third line is the symbol list HUFFVAL, made of BITS(1) + BITS(2) + ... + BITS(16) integers. The tables appear in the order (c, i) = (0, 0), (1, 0), (0, 1), (1, 1).
The quantization tables and the Huffman tables are the standard tables shown in Annex K of the JPEG standard (ITU-T T.81).

(4) input/stream.hex: a corrupted JPEG byte sequence
A JPEG-format byte sequence produced by another encoder, written in hexadecimal. Each line consists of an even number of characters (0-9 and a-f), at least 2 and at most 64. Concatenate all lines, split the resulting string into groups of 2 characters from the start, and read each group as a 2-digit hexadecimal number; these values are the bytes b_0, b_1, ..., b_(N-1) of the byte sequence. The byte sequence follows the format described in section 10, but the values of some bytes inside the entropy-coded data (the scan) have been changed (corrupted). See [Constraints] for details.

[Processing]
Process according to sections 1 to 17 below. Sections 1 to 11 describe the methods of encoding, decoding and evaluation, and sections 12 to 17 are the processing performed with them.

* Notation
- floor(a / b) (b a positive integer) is the largest integer not greater than a / b (for negative numbers it rounds toward -infinity; for example floor(-7 / 2) = -4). ceil(a / b) (a, b positive integers) is the smallest integer not less than a / b. a mod b (b a positive integer) is a - b * floor(a / b) (it lies between 0 and b - 1 inclusive).
- rnd(a, s) = floor((a + 2^(s-1)) / 2^s) (s is a positive integer; this is a / 2^s rounded to an integer, with an exact half rounded up to the larger value).
- clamp(a) = min(max(a, 0), 255). |a| is the absolute value of a.
- A plane is a 2-dimensional array of integers; the element of plane P at column x and row y is written P(x, y) (x counts from left to right and y from top to bottom, both starting from 0).
- Block (bx, by) of a plane P is the set of 64 elements P(8 * bx + i, 8 * by + j) with 0 <= i <= 7, 0 <= j <= 7, and P(8 * bx + i, 8 * by + j) is called the element at position (i, j) of the block.
- Byte values are also written as "0x" followed by 2 hexadecimal digits, as in 0xFF. Writing a value a in n bits means writing the n digits of the binary representation of a from the most significant digit (nothing is written if n = 0). Writing a value a in 2 bytes means writing the 2 bytes floor(a / 256), a mod 256 in this order.

* 1. Colour conversion
The conversion from RGB to YCbCr computes Y, Cb, Cr from the pixel values R, G, B with the following formulas (each result lies between 0 and 255 inclusive).
  Y = floor((19595 * R + 38470 * G + 7471 * B + 32768) / 65536)
  Cb = floor((-11059 * R - 21709 * G + 32768 * B + 8421375) / 65536)
  Cr = floor((32768 * R - 27439 * G - 5329 * B + 8421375) / 65536)
The conversion from YCbCr to RGB computes R, G, B with the following formulas.
  R = clamp(Y + floor((91881 * (Cr - 128) + 32768) / 65536))
  G = clamp(Y + floor((-22554 * (Cb - 128) - 46802 * (Cr - 128) + 32768) / 65536))
  B = clamp(Y + floor((116130 * (Cb - 128) + 32768) / 65536))
The 3 planes of width W and height H obtained by converting each pixel of an image to YCbCr are called the Y plane, Cb plane and Cr plane of that image. The Y plane, Cb plane and Cr plane of the input image are called the original Y plane, original Cb plane and original Cr plane, respectively.

* 2. Components, MCUs and block order
An image consists of 3 components k = 1 (Y), 2 (Cb), 3 (Cr), and component k has horizontal and vertical sampling factors H_k, V_k (1 or 2). For encoding, (H_1, V_1) = (1, 1) if S is 444, (2, 1) if it is 422, and (2, 2) if it is 420; components 2 and 3 always have (H_k, V_k) = (1, 1). Let Hmax = max(H_1, H_2, H_3) and Vmax = max(V_1, V_2, V_3).
- An MCU is a region 8 * Hmax pixels wide and 8 * Vmax pixels high. The image is covered by MX = ceil(W / (8 * Hmax)) MCUs horizontally and MY = ceil(H / (8 * Vmax)) MCUs vertically. The MCUs are numbered m = 0, 1, ..., MX * MY - 1 from the top row down, and from left to right within each row.
- The component plane of component k is a plane of width 8 * H_k * MX and height 8 * V_k * MY. MCU m contains the H_k * V_k blocks (H_k * (m mod MX) + h, V_k * floor(m / MX) + v) (0 <= h <= H_k - 1, 0 <= v <= V_k - 1) of the component plane of component k.
- The coding order is the order of blocks obtained by taking the MCUs in order of their numbers, within each MCU the components in the order 1, 2, 3, and within each component the blocks in increasing order of v, and for equal v in increasing order of h. Encoding and decoding process the blocks in this order. The rank of a block in the coding order, counted from the start (starting from 0), is called its block number.
- When the restart interval Ri >= 1, the groups obtained by dividing the MCUs, in order of their numbers, into runs of Ri MCUs are called intervals. Interval j (j = 0, 1, ...) consists of the MCUs j * Ri, j * Ri + 1, ..., min((j + 1) * Ri, MX * MY) - 1, and the number of intervals is N_I = ceil(MX * MY / Ri). When Ri = 0, there is only interval 0, consisting of all MCUs, and N_I = 1.

* 3. Building the component planes
The component planes to be encoded are built from an image and S as follows. Let PW = 8 * Hmax * MX and PH = 8 * Vmax * MY.
(1) From each of the Y plane, Cb plane and Cr plane A of the image, build an extended plane E of width PW and height PH with E(x, y) = A(min(x, W - 1), min(y, H - 1)) (it is widened by repeating the values of the rightmost column and the bottom row).
(2) For component k let fx = Hmax / H_k and fy = Vmax / V_k, and build the component plane P_k from the extended plane E of that component with the following formula (0 <= x <= 8 * H_k * MX - 1, 0 <= y <= 8 * V_k * MY - 1). The sum runs over all pairs (i, j) with 0 <= i <= fx - 1 and 0 <= j <= fy - 1.
  P_k(x, y) = floor((sum of E(fx * x + i, fy * y + j)) / (fx * fy))
When fx = fy = 1, P_k = E.

* 4. DCT and inverse DCT
The DCT of an 8 x 8 integer array f(y, x) (0 <= x <= 7, 0 <= y <= 7) is the 8 x 8 array F(u, v) (0 <= u <= 7, 0 <= v <= 7) computed in the following 2 stages. sum_y is the sum over y = 0, 1, ..., 7, and sum_x, sum_u, sum_v are defined in the same way.
  e(u, x) = rnd(sum_y C(u, y) * f(y, x), 11)
  F(u, v) = rnd(sum_x e(u, x) * C(v, x), 15)
The inverse DCT of an 8 x 8 integer array D(u, v) is the 8 x 8 array g(y, x) computed in the following 2 stages.
  s(y, v) = rnd(sum_u C(u, y) * D(u, v), 11)
  g(y, x) = clamp(rnd(sum_v s(y, v) * C(v, x), 15) + 128)
In encoding, with a the value of the element at position (i, j) of a block of a component plane, let f(j, i) = a - 128 and compute its DCT. In decoding, the value g(j, i) obtained by the inverse DCT becomes the value of the element at position (i, j) of the block of the component plane.

* 5. Quantization
The quantization tables for quality Q (1 to 100) are built as follows. Let sc = floor(5000 / Q) if Q < 50 and sc = 200 - 2 * Q if Q >= 50, and for t = 0, 1 let
  q_t(u, v) = min(max(floor((B_t(u, v) * sc + 50) / 100), 1), 255)
q_0 is the quantization table for luminance (component 1), and q_1 is the one for chrominance (components 2 and 3).
The value of a DCT result F(u, v) quantized with quantization table q is, with a = floor((|F(u, v)| + floor(q(u, v) / 2)) / q(u, v)), a if F(u, v) >= 0 and -a if F(u, v) < 0. The dequantized value of a quantized value L(u, v) is L(u, v) * q(u, v).

* 6. Zigzag order
Arrange the 64 positions (u, v) of an 8 x 8 array in increasing order of u + v; positions with equal u + v are arranged in increasing order of u if u + v is odd, and in decreasing order of u if it is even. The k-th position in this order (k = 0, 1, ..., 63) is denoted (u_k, v_k). The order starts (0, 0), (0, 1), (1, 0), (2, 0), (1, 1), (0, 2), (0, 3), (1, 2), ... and ends with (7, 7).
The sequence z_0, z_1, ..., z_63 obtained by arranging the quantized values L(u, v) of a block in this order as z_k = L(u_k, v_k) is called the coefficient sequence of the block. z_0 is called the DC coefficient, and z_1, ..., z_63 are called the AC coefficients.

* 7. Symbols
The size category cat(a) of an integer a is 0 if a = 0, and otherwise the smallest positive integer n with |a| < 2^n. The extra bits of a are, with n = cat(a), a written in n bits if a > 0 and a + 2^n - 1 written in n bits if a < 0 (nothing is written if a = 0).
In encoding, a symbol sequence is built from the coefficient sequence of each block as follows. Each component k has a predictor Z_k, and before processing of the first MCU of each interval starts, Z_k = 0 is set for all components. The blocks are processed in coding order, and for a block of component k the following (1) and (2) are performed.
(1) Let d = z_0 - Z_k be the DC difference, and set Z_k = z_0. Output the DC symbol cat(d) and the extra bits of d.
(2) Let r = 0, and for i = 1, 2, ..., 63 in this order: if z_i = 0, increase r by 1; if z_i != 0, do the following. First, while r >= 16, output the AC symbol 0xF0 (ZRL; it stands for 16 zeros and has no extra bits) and decrease r by 16. Next, with n = cat(z_i), output the AC symbol 16 * r + n and the extra bits of z_i, and set r = 0. If r > 0 after processing up to i = 63, output the AC symbol 0x00 (EOB; it means that all the remaining coefficients are 0, and it has no extra bits).
Each symbol is coded with one of the 4 Huffman tables according to its kind (DC or AC) and its component. The DC and AC symbols of component 1 are coded with tables (0, 0) and (1, 0) respectively, and the DC and AC symbols of components 2 and 3 with tables (0, 1) and (1, 1) respectively. For table (c, i), c is called the class and i the id, and the tables (0, 0), (1, 0), (0, 1), (1, 1) are named dc_luma, ac_luma, dc_chroma, ac_chroma respectively.

* 8. Huffman tables
A Huffman table is a pair of BITS(1), BITS(2), ..., BITS(16) and HUFFVAL.
(1) Code assignment: let code = 0, and for L = 1, 2, ..., 16 in this order, assign to the first BITS(L) symbols of HUFFVAL that have not been assigned yet, in HUFFVAL order, the code length L and the code value code, increasing code by 1 after each assignment. When the processing of that L is finished, double code. The code of a symbol is its code value written in as many bits as its code length.
(2) Standard tables: the 4 tables of input/tables.txt.
(3) Optimized tables: from the symbol sequence to be coded, each of the 4 tables is built as follows. For v = 0, 1, ..., 255, let freq(v) be the number of symbols v coded with that table; in addition, add a reserved symbol 256 with freq(256) = 1.
 (a) For v = 0, 1, ..., 256, set codesize(v) = 0 and others(v) = -1.
 (b) Let c1 be the v with freq(v) > 0 whose freq(v) is smallest (if there are several, the largest v), and let c2 be the v other than c1 with freq(v) > 0 whose freq(v) is smallest (if there are several, the largest v). If there is no c2, go to (e).
 (c) Add freq(c2) to freq(c1), and set freq(c2) = 0.
 (d) Increase codesize(c1) by 1, and while others(c1) != -1, repeat setting c1 = others(c1) and increasing codesize(c1) by 1. Then set others(c1) = c2. Next increase codesize(c2) by 1, and while others(c2) != -1, repeat setting c2 = others(c2) and increasing codesize(c2) by 1. Go back to (b).
 (e) For each positive integer L, let count(L) be the number of v (0 <= v <= 256) with codesize(v) = L.
 (f) Let Lmax be the largest L with count(L) > 0. If Lmax >= 17, then for L = Lmax, Lmax - 1, ..., 17 in this order, repeat the following while count(L) > 0. Let j = L - 2, and while count(j) = 0 decrease j by 1. Decrease count(L) by 2, increase count(L - 1) by 1, increase count(j + 1) by 2, and decrease count(j) by 1.
 (g) For the largest L not greater than 16 with count(L) > 0, decrease count(L) by 1 (this removes the reserved symbol).
 (h) Let BITS(L) = count(L) (L = 1, 2, ..., 16). HUFFVAL is the list of the v (0 <= v <= 255) with codesize(v) > 0, arranged in increasing order of codesize(v) as computed up to (d), and for equal codesize(v) in increasing order of v.
The code length of each symbol is the length determined by (1) from the BITS and HUFFVAL built in this way (it may differ from codesize(v)).

* 9. JPEG byte sequence (encoding)
Encoding an image with (Q, S, M, Ri) means building a JPEG byte sequence from that image, the quality Q, the subsampling mode S, the kind of Huffman tables M and the restart interval Ri as follows.
(1) Build the component planes by section 3, quantize the DCT (section 4) of each of their blocks (section 5) with q_0 for component 1 and with q_1 for components 2 and 3, and obtain the coefficient sequences (section 6).
(2) Build the symbol sequence by section 7. If M is standard, use the standard tables; if it is optimized, use the optimized tables built from this symbol sequence.
(3) Build the byte sequence formed by concatenating the following (a) to (h) in this order. (a) to (f) are called the header, and (g) is called the scan.
 (a) SOI: 0xFF 0xD8.
 (b) DQT: 0xFF 0xDB, 132 written in 2 bytes, 0x00, q_0(u_k, v_k) for k = 0, 1, ..., 63 in this order, one byte each (64 bytes), 0x01, then q_1(u_k, v_k) in the same way (64 bytes).
 (c) SOF0: 0xFF 0xC0, 17 written in 2 bytes, 0x08, H written in 2 bytes, W written in 2 bytes, 0x03, 0x01, 16 * H_1 + V_1, 0x00, 0x02, 0x11, 0x01, 0x03, 0x11, 0x01.
 (d) DHT: 0xFF 0xC4, 2 + 17 * 4 + (the total number of HUFFVAL entries of the 4 tables) written in 2 bytes, followed, for each table in the order dc_luma, ac_luma, dc_chroma, ac_chroma, by the 1 byte 16 * class + id, the 16 bytes BITS(1), ..., BITS(16), and each symbol of HUFFVAL as 1 byte.
 (e) DRI (only when Ri > 0): 0xFF 0xDD, 4 written in 2 bytes, Ri written in 2 bytes.
 (f) SOS: the 14 bytes 0xFF 0xDA 0x00 0x0C 0x03 0x01 0x00 0x02 0x11 0x03 0x11 0x00 0x3F 0x00.
 (g) Scan: described below.
 (h) EOI: 0xFF 0xD9.
The scan is a sequence of bytes built by writing bits one after another. The written bits are grouped from the start into bytes of 8 bits each, with the bit written first as the most significant bit, and each byte is appended to the scan. If an appended byte is 0xFF, 0x00 is appended right after it (byte stuffing). The blocks are processed in coding order, and the symbols of each block are written in order, each as the code of the symbol followed by the extra bits of that symbol. Before writing the blocks of the first MCU of interval j (j >= 1), first, if the number of bits written so far is not a multiple of 8, write 1 bits until it is a multiple of 8 (padding; byte stuffing is applied to the resulting bytes). Then append the 2 bytes 0xFF, 0xD0 + ((j - 1) mod 8) (a restart marker; no byte stuffing is applied) to the scan. After the last block has been written, padding is also performed in the same way.
The following values are defined.
- Bits of a block: the total number of bits of the codes and extra bits of the symbols of that block (padding, byte stuffing and restart markers are not included).
- The number of header bytes, the number of scan bytes, and the total number of bytes (the length of the byte sequence).
- Position and length of interval j: the data of interval j starts right after SOS if j = 0, and right after the restart marker before interval j if j >= 1. The position of its first byte, counted from the start of the byte sequence (starting from 0), is the position of interval j, and the number of bytes from there to just before the next restart marker or EOI is the length of interval j.

* 10. Decoding
A JPEG byte sequence b_0, b_1, ..., b_(N-1) is decoded as follows. The byte sequence starts with 0xFF 0xD8 and ends with 0xFF 0xD9.
(1) Segment parsing: let p = 2 and repeat the following. Let b_(p+1) be the marker type and Ls = 256 * b_(p+2) + b_(p+3) the segment length, and let the Ls - 2 bytes b_(p+4), ..., b_(p+Ls+1) be the segment contents. Record the segment (position p, name, length Ls), increase p by Ls + 2, and then process the contents according to the marker type as follows. If the marker type is 0xDA (SOS), end the repetition after processing it, and let the p at that point be the scan start position p_0.
 - 0xDB (DQT): the contents are a sequence of groups of 65 bytes. The first byte of each group is the quantization table id t (0 to 3), and the following 64 bytes are q_t(u_0, v_0), q_t(u_1, v_1), ..., q_t(u_63, v_63). If a table with the same id appears again, the later table replaces it.
 - 0xC4 (DHT): the contents are a sequence of Huffman tables. Each table consists of the 1 byte 16 * c + i (c is the class, i is the id), the 16 bytes BITS(1), ..., BITS(16), and the BITS(1) + ... + BITS(16) bytes of HUFFVAL. This is table (c, i). If a table with the same (c, i) appears again, the later table replaces it.
 - 0xC0 (SOF0): the contents are the 1 byte precision (8), the height H and the width W each written in 2 bytes, the 1 byte number of components (3), followed, for each of the components k = 1, 2, 3, by 1 byte each of the component identifier, 16 * H_k + V_k, and the quantization table id Tq_k.
 - 0xDD (DRI): the contents are the restart interval Ri written in 2 bytes. If there is no DRI, Ri = 0.
 - 0xDA (SOS): the contents are the 1 byte number of components (3), followed, for each of the components k = 1, 2, 3 (in the same order as SOF0), by 1 byte each of the component identifier and 16 * Td_k + Ta_k, and finally 3 bytes (not used). Td_k and Ta_k are the ids of the Huffman tables used for the DC and AC symbols of component k.
 - 0xE0 to 0xEF (APP0 to APP15) and 0xFE (COM): the contents are not used.
 The segment names are SOF0 for 0xC0, DHT for 0xC4, DQT for 0xDB, DRI for 0xDD, SOS for 0xDA, COM for 0xFE, and, for 0xE0 + n (0 <= n <= 15), APP followed by n written in decimal (for example APP0). The segment list is the list consisting of the segment with position 0, name SOI and length 0, the recorded segments, and the segment with position N - 2, name EOI and length 0, in this order. The number of scan bytes is N - 2 - p_0.
(2) From H_k and V_k, determine Hmax, Vmax, MX, MY, the sizes of the component planes and the coding order by the rules of section 2, and determine the intervals with the Ri of (1). The coefficient sequences of all blocks are initially all 0.
(3) Reading bits: a read position p (initially p_0) and a bit buffer (initially empty) are used. To read 1 bit, if the buffer is empty, first take in 1 byte as follows. If b_p != 0xFF, take in b_p and increase p by 1. If b_p = 0xFF and b_(p+1) = 0x00, take in 0xFF and increase p by 2. If b_p = 0xFF and b_(p+1) != 0x00, it is error marker (p is not changed). The 8 bits of the byte taken in are put into the buffer and taken out one bit at a time from the most significant bit. Reading an n-bit integer means reading 1 bit n times and regarding the bits as an n-digit binary number with the bit read first as the most significant.
(4) Reading a symbol: to read one symbol with a table, let code = 0, and for L = 1, 2, ..., 16 in this order, read 1 bit beta and set code = 2 * code + beta; if the table has a symbol whose code length is L and whose code value is code (section 8 (1)), that symbol is the result. If none is found up to L = 16, it is error code.
(5) Decoding a block: a block of component k is decoded as follows, with table (0, Td_k) for DC and table (1, Ta_k) for AC. Set the coefficient sequence to all 0, and read the DC symbol n. If n > 0, read an n-bit integer w, and let d = w if w >= 2^(n-1) and d = w - 2^n + 1 otherwise (if n = 0, d = 0). Add d to the predictor Z_k, and set z_0 = Z_k. Next let i = 1, and repeat the following while i <= 63. Read an AC symbol a; if a = 0x00, end the repetition. Otherwise let r = floor(a / 16) and n = a mod 16, add r to i, and if i > 63 it is error index. If n > 0, read an n-bit integer, convert it to a value by the same rule as for DC, and set it as z_i. Increase i by 1.
(6) Processing the intervals: let j = 0 and repeat the following while j < N_I.
 (a) Set Z_k = 0 for all components, and decode the blocks of the MCUs of interval j in coding order by (5).
 (b) Empty the buffer (remaining bits are discarded). The expected marker is 0xD0 + (j mod 8) if j < N_I - 1, and 0xD9 if j = N_I - 1. If b_p = 0xFF and b_(p+1) is the expected marker, interval j is ok. The coefficient sequences decoded in (a) become the coefficient sequences of the blocks of interval j, p is increased by 2, and j is increased by 1. Otherwise, it is error sync.
 (c) If an error occurs in (a) or (b), stop decoding interval j at that point. Interval j is damaged. The coefficient sequences of the blocks of interval j stay all 0 (the values decoded in (a) are not used). Record the kind of error, the number of the MCU being decoded when the error occurred (for sync, the number of the last MCU of interval j), and the value of p at that time (the error offset), and empty the buffer. Next, find the smallest q with q >= p and q + 1 <= N - 1 such that b_q = 0xFF and b_(q+1) is one of 0xD0 to 0xD7 or 0xD9; this is the resync position (since the byte sequence ends with 0xFF 0xD9, a resync position always exists).
  - If b_(q+1) = 0xD0 + n (0 <= n <= 7), let j' = j + 1 + ((n - j) mod 8). Intervals j + 1, ..., min(j', N_I) - 1 are lost (if j' = j + 1, no interval is lost). Set p = q + 2 and j = j'.
  - If b_(q+1) = 0xD9, intervals j + 1, ..., N_I - 1 are all lost, and the processing of the intervals ends.
 The coefficient sequences of the blocks of lost intervals stay all 0.
(7) For each block of component k, from its coefficient sequence z_0, z_1, ..., z_63 form L with L(u_0, v_0) = z_0, L(u_1, v_1) = z_1, ..., L(u_63, v_63) = z_63, dequantize L with the quantization table q_(Tq_k) (the quantization table of component k), and take its inverse DCT as the values of that block of the component plane of component k. A block whose coefficient sequence is all 0 gets the value 128 everywhere.
(8) For component k, build the plane D_k of width W and height H with D_k(x, y) = P_k(floor(x * H_k / Hmax), floor(y * V_k / Vmax)) (P_k is the component plane of component k built in (7)). D_1, D_2, D_3 are the decoded Y plane, Cb plane and Cr plane, and the image obtained by converting each pixel to RGB by section 1 is the decoded image.
When a byte sequence built by section 9 is decoded, no error occurs, all intervals are ok, and the coefficient sequence of each block equals the one at encoding time.

* 11. Evaluation
(1) The PSNR of sequences of integers a_1, ..., a_n and b_1, ..., b_n, each between 0 and 255 inclusive, is, with eps = (a_1 - b_1)^2 + ... + (a_n - b_n)^2, inf if eps = 0, and if eps > 0 the value 10 * log10(65025 * n / eps) computed in double-precision floating point, rounded to 2 decimal places and written with exactly 2 digits after the decimal point (for example 31.47, 30.50).
(2) When the byte sequence of an encoded image is decoded, psnr_y is the PSNR of the W * H values of the original Y plane and of the decoded Y plane (values at the same position are paired). psnr_cb and psnr_cr are likewise the PSNR of the original Cb plane and the decoded Cb plane, and of the original Cr plane and the decoded Cr plane. psnr_rgb is the PSNR of the 3 * W * H values R, G, B of the input image and of the decoded image (values of the same colour of the same pixel are paired). The maximum error is the maximum of the absolute differences between the values of the same colour of the same pixel of the input image and the decoded image.
(3) When the total number of bytes is b, the bits per pixel bpp is 8 * b / (W * H) expressed as an irreducible fraction, written as "a/c" with numerator a and denominator c (the "/1" is written even when c = 1).

* 12. Evaluation per quality
For each Q_i (i = 1, 2, ..., n), compute the total numbers of bytes when the input image is encoded with (Q_i, S, standard, Ri) and with (Q_i, S, optimized, Ri). Also decode the byte sequence of the input image encoded with (Q_i, S, M, Ri), and compute psnr_y, psnr_cb, psnr_cr, psnr_rgb, the maximum error, and the bpp of that byte sequence.

* 13. Details at the reference quality
For the input image encoded with (Q_1, S, M, Ri) (the reference encoding) and for the decoding of that byte sequence (the reference decoding), compute the following.
(1) Block statistics: for each block of the reference encoding, compute z_0, the DC difference, the number of nonzero AC coefficients, the largest k with z_k != 0 (0 <= k <= 63; 0 if there is no such k), the bits of the block, and the error of the block. The error of the block is the sum of the squared differences between the 64 values of that block of the component plane built by section 3 in the reference encoding and the 64 values of the same block of the component plane built by section 10 (7) in the reference decoding, pairing values at the same position.
(2) Thumbnail: an image of width TW = ceil(W / 8) and height TH = ceil(H / 8). The value of pixel (x, y) is computed as follows. For each component k = 1, 2, 3, from the z_0 of block (floor(x * H_k / Hmax), floor(y * V_k / Vmax)) of component k in the reference decoding and the (0, 0) value w = q_(Tq_k)(0, 0) of the quantization table q_(Tq_k) used for component k in the reference decoding, compute clamp(floor((z_0 * w + 4) / 8) + 128). The results for k = 1, 2, 3 are Y, Cb, Cr respectively, and they are converted to RGB by section 1.
(3) Coefficient truncation: for each K_i, build the component plane of component 1 by the same method as section 10 (7) from the coefficient sequences of the blocks of component 1 in the reference decoding, keeping only z_0, ..., z_(K_i - 1) and setting the rest to 0. Compute the PSNR of the W * H values of the part 0 <= x <= W - 1, 0 <= y <= H - 1 of that component plane and of the original Y plane.
(4) Error distribution: divide the absolute differences (3 * W * H of them) between the values of the same colour of the same pixel of the input image and of the decoded image of the reference decoding into the 8 ranges 0, 1, 2 to 3, 4 to 7, 8 to 15, 16 to 31, 32 to 63, 64 to 255, and count how many fall into each range.

* 14. Comparison of subsampling modes
For each of S' = 444, 422, 420, compute the total number of bytes when the input image is encoded with (Q_1, S', M, Ri), and psnr_cb, psnr_cr, psnr_rgb when that byte sequence is decoded.

* 15. Repeated compression
Let the input image be I_0, and for g = 1, 2, ..., Ng in this order, encode image I_(g-1) with (Q_1, S, M, Ri) and let I_g be the decoded image of that byte sequence. For each g, compute the total number of bytes, the psnr_rgb of the input image and I_g (the PSNR of the 3 * W * H values), and the number of pixels for which at least one of the R, G, B values differs between I_(g-1) and I_g (the number of changed pixels). I_1 is the same as the decoded image of the reference decoding.

* 16. Quality search
Let lo = 1 and hi = 100, and repeat the following while lo < hi. Let mid = floor((lo + hi + 1) / 2), compute the total number of bytes b when the input image is encoded with (mid, S, M, Ri), and record the pair (mid, b). If b <= T, set lo = mid; otherwise set hi = mid - 1. Let Q* be lo when the repetition ends, and compute the total number of bytes b* when the input image is encoded with (Q*, S, M, Ri), whether b* <= T, and the psnr_rgb when that byte sequence is decoded.

* 17. Decoding and repairing the corrupted byte sequence
(1) Decode the byte sequence of input/stream.hex by section 10.
(2) Repair: build a new byte sequence by the same method as sections 7 to 9, using the coefficient sequences of all blocks obtained in (1) (all 0 for the blocks of damaged and lost intervals) as they are, without DCT or quantization. Here W, H and the restart interval Ri are those of the byte sequence of (1), (H_1, V_1) is that of component 1 of the byte sequence of (1), and (H_2, V_2) = (H_3, V_3) = (1, 1). q_0 is the quantization table q_(Tq_1) of component 1 in (1), q_1 is the quantization table q_(Tq_2) of component 2 in (1), and the Huffman tables are the optimized tables.
(3) Decode the byte sequence built in (2) by section 10, and check whether its decoded image is exactly identical to the decoded image of (1) (all values of all colours of all pixels are equal).

[Source files]
There are the following 6 source files. The names are language-neutral role names; extensions and capitalization follow the conventions of each language.
- main: handles the overall flow and contains most of the processing. Reading the input and calling each module; the encoding flow (building the coefficient sequences of the blocks from the component planes, building the symbol sequence (section 7), assembling the header and the scan and inserting the restart markers (section 9)); the decoder (segment parsing, decoding symbols and blocks, processing the intervals and resynchronizing after errors, building the component planes and the decoded image (section 10)); evaluation (section 11); the processing of sections 12 to 17; building and writing the contents of all output files.
- image_io: reading and writing PPM images, reading params.txt and tables.txt, reading and writing hexadecimal files.
- color: colour conversion (section 1), building the extended planes and chroma subsampling (section 3), upsampling of the component planes in decoding (section 10 (8)).
- dct: zigzag order (section 6), building the quantization tables, quantization and dequantization (section 5), DCT and inverse DCT (section 4).
- entropy: computing size categories and extra bits, converting extra bits back to values (section 7, section 10 (5)), building optimized Huffman tables (section 8 (3)), code assignment (section 8 (1)).
- bitstream: writing bits (grouping into bytes, byte stuffing, padding, appending restart markers), reading bits (taking in bytes and detecting error marker (section 10 (3)), searching for the resync position (section 10 (6) (c))).

[Constraints]
- 8 <= W <= 64 and 8 <= H <= 64.
- 1 <= n <= 8, 1 <= Q_i <= 100, and Q_1, ..., Q_n are all distinct.
- 0 <= Ri <= 64, 1 <= T <= 100000, 1 <= Ng <= 8, 1 <= m <= 8, and 1 <= K_1 < K_2 < ... < K_m <= 64.
- |C(u, x)| <= 4096 and 1 <= B_t(u, v) <= 255. The standard Huffman tables contain every symbol that occurs in section 7.
- When optimized tables are built, every table has at least one symbol to code.
- For input/stream.hex the following holds.
  - N <= 4096, b_0 = 0xFF, b_1 = 0xD8, b_(N-2) = 0xFF, b_(N-1) = 0xD9.
  - After SOI come segments among APP0 to APP15, COM, DQT, DHT, SOF0 and DRI, followed by the SOS segment. There is exactly one SOF0 and exactly one SOS, there is one DRI, and all quantization tables and Huffman tables that are used are defined before SOS.
  - The SOF0 precision is 8, the width and height are between 8 and 64 inclusive, and the number of components is 3. H_1, V_1 of component 1 are 1 or 2; components 2 and 3 have H_k = V_k = 1 and use the same quantization table and the same Huffman tables. The order of the components in SOS is the same as in SOF0. The Ri of DRI is at least 1.
  - The values of the quantization tables are between 1 and 255 inclusive. Every Huffman table is such that, when codes are assigned by section 8 (1), all code values of length L are less than 2^L. The symbols of the DC tables are between 0 and 11 inclusive, and the symbols of the AC tables are 0x00, 0xF0, or 16 * r + n (0 <= r <= 15, 1 <= n <= 10).
  - Only bytes inside the scan are corrupted; the segments up to SOS and the last 2 bytes are not corrupted.
- For the given input, the absolute value of every integer, including intermediate values of computations, is less than 2^31.
- For the given input, every PSNR that is output has eps > 0, and the exact value of 10 * log10(65025 * n / eps) is at least 10^(-6) away from a boundary for rounding to 2 decimal places (a value whose digits from the 3rd decimal place on are exactly 5).
