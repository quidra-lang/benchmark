[Overview]
Write a program that typesets mathematical formulas written in a TeX-like notation into two-dimensional ASCII art drawn with monospaced characters. It reads the two files in the input/ folder (the list of formulas and the typesetting settings). Each formula goes through lexical analysis and parsing to build a syntax tree; if there is an error, it is reported together with its column. From each part of the syntax tree the program builds a "box" that has a width, a height and a baseline, assembles fractions, superscripts and subscripts, radicals, brackets that grow to fit their contents, large operators, matrices and so on, splits formulas that exceed the width limit into several lines, and draws them on a character grid. Equation numbers and references (\tag, \label, \eqref) are also handled.
The results are written to four files in the output/ folder (the typeset formulas, the sizes and positions of the boxes, the normalized syntax trees and linear notations, and the errors and warnings); nothing is printed to standard output. All computation is done with integers and strings only; floating-point numbers are not used.

[Input files]
There are two input files: input/params.txt and input/formulas.txt. Both consist only of printable ASCII characters (character codes 32 to 126), contain no tabs, and every line (including the last one) ends with a line feed (LF).

## input/params.txt (typesetting settings)
It consists of 7 lines, each of the form "name value" (the name, one space, and an integer >= 0). The order of the lines is not fixed. The names are the following seven, and each appears exactly once. How the values are used is defined in [Processing].
- width: the width limit of a line (in characters).
- indent: the default indentation of continuation lines.
- rel_space: the number of spaces placed on each side of a relation.
- bin_space: the number of spaces placed on each side of a binary operator.
- punct_space: the number of spaces placed after punctuation.
- col_gap: the number of spaces between matrix columns.
- row_gap: the number of empty lines between matrix rows.

## input/formulas.txt (list of formulas)
Each line holds one formula. The lines are numbered 1, 2, ... in order from the first line; this number is called the "formula number", and below it is written as "formula n" (it is different from the numbers attached by \tag or \label). Each line has at least one character, contains at least one character that is not a space, and does not end with a space.
Positions within a formula line are expressed as "columns". The first character of the line is column 1. The number of characters of the line plus 1 is called the "end-of-line column".

[Processing]
## 0. Processing flow and errors
For each formula, perform the lexical analysis of 1, the brace check of 2 and the parsing of 3, in this order. If an error is found along the way, the processing of that formula ends there, and that formula is a "formula with an error". Only one error is reported per formula: the first one found. A formula without an error is called a "valid formula".
After all formulas have been parsed, build the equation numbers and the reference table of 4. Then typeset and draw the valid formulas, in order of formula number, by the methods of 5 to 10, and compute the tree notation and linear notation of 11 and the warnings of 12.
An error is a pair of a "column" and a "message". Below, when it says 'error "<message>" (column ...)', the string between the double quotes (not including the double quotes themselves) is the message, and each <...> part is replaced by what it describes. A double quote inside a message is a double-quote character that appears literally in the message (example: unknown environment "array").

## 1. Lexical analysis
Read the formula line in order from the start and split it into a sequence of "tokens". Each token has a "kind", a "value" (a string) and a "column" (the column of the first character of the token). Below, "letter" means A to Z and a to z, and "digit" means 0 to 9. Depending on the character at the current reading position, proceed as follows.
- Space: skip it.
- Letter: the longest run of letters starting there is one "identifier" (example: "ab" is one identifier with value ab).
- Digit: read the longest run of digits starting there. If the character right after it is "." and the character after that is a digit, also include the "." and the longest run of digits that follows it. The part read is one "number" (examples: "3.14" is one number; "3." is the number "3" and the symbol "."; "1.2.3" is the number "1.2", the symbol "." and the number "3").
- One of the following 18 characters: that single character is one "symbol", whose value is that character.
  +  -  *  /  =  <  >  :  (  )  [  ]  ,  ;  .  !  |  '
- One of "{", "}", "^", "_", "&": that single character is one token whose kind and value are that character. Below, these are called the "{" token, the "}" token, the "^" token, the "_" token and the "&" token respectively.
- "\": read a command by the method described next.
- Any other character: error "invalid character <that character>" (column: the column of that character).

A command is read as follows. Let c be the column of the "\".
(1) If the character after "\" is "\", the two characters "\\" are one "newline" token. If the next character is one of "{", "}", ",", the two characters "\{", "\}", "\," respectively are one "symbol command" (its value is those two characters).
(2) Otherwise, the longest run of letters starting at the character after "\" is the "command name". If the command name is empty (when the character after "\" is not a letter, or when "\" is the last character of the line), it is error "invalid command" (column c).
(3) If the command name is one of text, begin, end, tag, label, eqref, read a "raw argument". Skip spaces starting right after the command name; if the character at that position is not "{", it is error "expected {" (column: the column of that position, or the end-of-line column if the end of the line was reached). If it is "{", search for the first "}" that appears after it. If none is found, it is error "unterminated argument" (column c). If one is found, the string between the "{" and the "}" (it may be empty, and it may contain spaces and characters that cannot be used elsewhere) is the argument, and reading continues from the character after that "}". When the command name is begin or end and the argument is none of matrix, pmatrix, bmatrix, vmatrix, cases, it is error "unknown environment "<argument>"" (column c). If there is no error, the result is one token whose kind is the command name and whose value is the argument. Below, these are called the "text token", the "begin token" and so on.
(4) If the command name is one of the "symbol commands" in the table below, it is one symbol command whose value is the string "\" followed by the command name (example: value "\alpha").
(5) If the command name is one of overline, hat, vec, dot, tilde, overbrace, underbrace, it is one "accent" token whose value is the command name.
(6) If the command name is one of frac, binom, overset, underset, sqrt, left, right, it is one token whose kind is the command name. Below, these are called the "frac token", the "left token" and so on.
(7) If none of the above applies, it is error "unknown command \<command name>" (column c).
Lexical analysis ends as soon as the first error is found.

The symbol commands are as in the following table; each has a "display string" and a "type" (the meaning of types is explained in 7).
- Greek letters (34): alpha, beta, gamma, delta, epsilon, zeta, eta, theta, iota, kappa, lambda, mu, nu, xi, pi, rho, sigma, tau, upsilon, phi, chi, psi, omega, Gamma, Delta, Theta, Lambda, Xi, Pi, Sigma, Upsilon, Phi, Psi, Omega. The display string is the command name itself (example: \alpha is "alpha"), and the type is ordinary.
- Binary operators: \cdot is "*", \times is "x", \pm is "+-", \mp is "-+". The type is binary.
- Relations: \leq is "<=", \geq is ">=", \neq is "!=", \approx is "~=", \to is "->". The type is relation.
- Other symbols: \infty is "oo", \ldots and \cdots are "...", \quad is two spaces, \, is one space. The type is ordinary. \{ is "{" with type open, and \} is "}" with type close.
- Function names (10): sin, cos, tan, log, ln, exp, det, lim, max, min. The display string is the command name itself, and the type is operator.
- Large operators (3): sum, prod, int. The type is operator (their display is defined in 6).
The "command-name table" is the set of the names of the commands in the above table except \{, \}, \, (the Greek letters, cdot, times, pm, mp, leq, geq, neq, approx, to, infty, ldots, cdots, quad, the function names and the large operators).

## 2. Brace check
Go through the token sequence obtained by lexical analysis in order from the start; each time a "{" token appears, push its column onto a stack, and each time a "}" token appears, remove the top of the stack. If a "}" token appears while the stack is empty, it is error "unmatched }" (column: the column of that "}"). If the stack is not empty after the last token has been examined, it is error "unclosed {" (column: the value at the top of the stack, that is, the column of the last one of the unclosed "{"). Characters inside raw arguments and the symbol commands "\{" and "\}" are not "{" or "}" tokens, so they are not counted.

## 3. Parsing
Build a syntax tree from the token sequence. The nodes of the syntax tree are as follows.
- Atom: there are six kinds: identifier, number, symbol, symbol command, text (the argument of a text token) and reference (the argument and column of an eqref token).
- Row: a sequence of zero or more nodes (its elements).
- Fraction (numerator, denominator), binomial (upper, lower), overset (placed part, base), underset (placed part, base): each has two nodes.
- Square root (body) and indexed root (index, body).
- Script (base, subscript, superscript): one of the subscript and the superscript may be absent (both are never absent).
- Delimited group (left delimiter, right delimiter, body): a delimiter is one of the strings "(", ")", "[", "]", "|", ".", "\{", "\}".
- Matrix (environment name, rows): the environment name is one of matrix, pmatrix, bmatrix, vmatrix, cases, and each row is a sequence of cells (nodes). Every row has the same number of cells.
- Accent (accent name, body): the accent name is one of overline, hat, vec, dot, tilde, overbrace, underbrace.
A row with no elements is called an "empty row".
In the procedures below, "the next token" is the first token not yet read; when no token remains, it is "the end of input" (its column is the end-of-line column). "Read a token" means to treat the next token as having been read. The "}", "&", newline, right and end tokens and the end of input are called "terminators".
The "collapse" of a sequence L of nodes is the element of L if L has exactly one element, and otherwise the row whose elements are those of L.

(1) Whole formula: perform "read an element list" as the top level, and call its result the "top-level element list" (no collapse is applied). Then, if the next token is not the end of input, it is an error: "unexpected \right" if the next token is right, "unexpected \end" if it is end, "misplaced &" if it is "&", and "misplaced \\" if it is a newline (column: the column of that token). Because of the check in 2, a "}" never appears here.
(2) Read an element list: start with an empty sequence and repeat the following. If the next token is a terminator (only when this is performed for the index of an indexed root, a symbol with value "]" is also a terminator; this treatment does not extend to "read an element list" performed for a "{", a left or a matrix inside the index), stop without reading that token; the sequence so far is the result. If the next token is a tag or label token: when not at the top level, it is error "misplaced \tag" or "misplaced \label" (column: the column of that token). At the top level, if the formula already has a token of the same kind (tag or label), it is error "duplicate \tag" or "duplicate \label" (column: the column of that token); otherwise record the token's value (a string) and column as the formula's "tag" or "label", read the token and continue repeating. Otherwise, perform "read an element" and append its result to the end of the sequence.
(3) Read an element: if the next token is "^" or "_", the base is an empty row (the token is not read). Otherwise, the result of "read a nucleus" is the base. Then, while the next token is "^" or "_", read that token and repeat the following. For "^", if this element already has a superscript, it is error "double superscript"; for "_", if it already has a subscript, it is error "double subscript" (column: the column of the "^" or "_" just read). Otherwise, the result of "read an argument" (with name "^" or "_") becomes the superscript or the subscript. If there is neither a superscript nor a subscript, the base is the result; otherwise the script (base, subscript, superscript) is the result.
(4) Read an argument (name N): if the next token is an identifier, number, symbol, symbol command, text, eqref, "{", frac, binom, overset, underset, sqrt or accent token, the result of "read a nucleus" is the result. Otherwise (a terminator, or a "^", "_", left, begin, tag or label token), it is error "missing argument for <N>" (column: the column of that token).
(5) Read a nucleus: read one token and, depending on its kind, do the following.
  - Identifier, number, symbol, symbol command, text: the atom of that token (for a text, its content is the argument).
  - eqref: a reference whose name is the argument and whose column is the column of that token.
  - "{": perform "read an element list"; if the next token is "}", read it, and the collapse of the resulting sequence is the result. If the next token is not "}", it is the same error as in (1) ("unexpected \right" if it is right, and so on; column: the column of that token).
  - frac, binom, overset, underset: perform "read an argument" twice (with the name "\frac", "\binom", "\overset", "\underset" respectively); the result is the fraction, binomial, overset or underset holding the first result and the second result (in the order numerator, denominator for a fraction; upper, lower for a binomial; placed part, base for an overset or underset).
  - sqrt: if the next token is a symbol with value "[", read it (let c be its column), and perform "read an element list" for the index of an indexed root; if the next token is then not a symbol with value "]", it is error "missing ]" (column c). If it is a symbol with value "]", read it, and the collapse of the resulting sequence is the index. Then the result of "read an argument" (name "\sqrt") is the body; the result is the square root (body) if there is no index, and the indexed root (index, body) if there is one.
  - Accent: the result is the accent whose body is the result of "read an argument" (the name is "\" followed by the accent name).
  - left: the result of "read a delimiter" is the left delimiter, and then perform "read an element list". If the next token is not right, it is error "missing \right" (column: the column of this left token). If it is right, read it (its column is recorded in the delimited group as the "right column"), the result of "read a delimiter" is the right delimiter, and the result is the delimited group (left delimiter, right delimiter, collapse of the resulting sequence).
  - begin: read a matrix by the method of (6), with the token's value as the environment name.
  Tokens of other kinds are never read as a nucleus.
  "Read a delimiter" reads one token; if it is a symbol with value "(", ")", "[", "]", "|" or ".", or a symbol command with value "\{" or "\}", that value is the result. Otherwise it is error "invalid delimiter" (column: the column of that token).
(6) Matrix: let c be the column of the begin token. Starting with an empty first row, repeat the following. Perform "read an element list", append the collapse of the resulting sequence to the end of the cells of the current row, and read one token. If it is "&", continue repeating; if it is a newline, start a new empty row and continue repeating. If it is an end token: if its value differs from the environment name, it is error "mismatched \end" (column: the column of that end token); if they are equal, end the repetition. Anything else ("}", right, end of input) is error "missing \end" (column c).
After the repetition ends, if there are two or more rows and the last row consists of exactly one cell and that cell is an empty row, remove the last row (this handles a matrix that ends with "\\"). Then, to match the row with the most cells, append empty-row cells to the end of the other rows. The result is the matrix (environment name, rows).
For example, "x^2_i" and "x_i^2" both become script (x, i, 2), and "{x^2}^3" becomes script (script (x, none, 2), none, 3). The top-level element list of "a{b c}" has two elements: the identifier a and the row (b, c). The base of "^2" is an empty row.

## 4. Equation numbers and references
Go through the valid formulas in order of formula number and determine the "tag string" of each as follows. For a formula that has a tag, it is the string formed by joining "(", the value of the tag and ")". For a formula that has no tag but has a label, increase a counter that starts at 0 by 1; the tag string is formed by joining "(", that counter value and ")". A formula that has neither has no tag string.
Then go through the valid formulas that have a label in order of formula number; if the value of the label (the "label name") is not yet in the "reference table", add it to the table, mapping the label name to the tag string of that formula. If it is already there, leave the table unchanged and record the warning of 12 (duplicate label). The tags and labels of formulas with an error are not used.

## 5. Boxes
Typesetting is done in units of "boxes". A box is a rectangle that has a width w (an integer >= 0; a number of characters), a height h (an integer >= 1; a number of lines) and a baseline b (an integer with 0 <= b < h). The lines of a box are numbered 0, 1, ..., h-1 from the top, and line b is called the "baseline line". b is called the "ascent" (the number of lines above) and h-1-b is called the "descent" (the number of lines below).
A box has some "child" boxes and places each of them at a position (x, y) inside itself (meaning that the top-left character of the child is at column x, line y; both columns and lines are counted from 0). A box also has some "drawn strings" and places each of them at a position (x, y) inside itself (the first character of the string is at column x, line y). No child and no drawn string extends outside the box.
Each box has a "description", which is output to output/boxes.txt, and each child has a "role" in its parent (which may be empty). Descriptions and roles are defined in the sections below.
Below, "center A in width W" means setting the left column of A to the quotient of (W - width of A) divided by 2 (rounded down) (when there is a remainder, the right side is one column wider).
Each node of the syntax tree is typeset in one of two "styles": "normal" or "script". The top-level element list is typeset in normal style. The superscript and subscript of a script, the index of an indexed root, and the "placed part" of an overset or underset are typeset in script style; all other child nodes are typeset in the same style as their parent.

## 6. Typesetting atoms
The box of an atom has a width equal to the number of characters of its display string, height 1 and baseline 0, and draws the display string at position (0, 0). The display strings are as follows.
- Identifier, number, symbol: the token value itself.
- Symbol command: the display string from the table in 1 (except large operators).
- Text: the argument string itself (including spaces).
- Reference: the corresponding tag string if the name is in the reference table, otherwise "(??)" (when it is not, record the warning of 12).
A large operator in script style is an atom box whose display string is the command name ("sum", "prod", "int"). In normal style, it is a box (height 3, baseline 1) that draws the following three-line glyph. Each line of the glyph is shown between double quotes, in order from line 0 (spaces between the double quotes are also part of the glyph).
  \sum : width 3. "\--", " > ", "/--"
  \prod: width 3. "___", "| |", "| |"
  \int : width 2. " /", " |", "/ "
The description is text "<argument>" for a text, eqref "<name>" for a reference, and atom "<token value>" for any other atom (examples: atom "x", atom "3.14", atom "+", atom "\alpha", atom "\sum", atom "\,").

## 7. Typesetting rows
This section defines how to typeset a sequence of elements e_1, e_2, ..., e_n (n >= 0) side by side in a given style. Besides row nodes, this method is also used for each line in 9 and for the slash fraction in 8 (2).

(1) Types: each element has a "left type" and a "right type". There are seven types: ordinary, operator, binary, relation, open, close and punctuation.
  - Symbol atoms: "+", "-", "*" are binary; "=", "<", ">", ":" are relation; "(", "[" are open; ")", "]", "!" are close; ",", ";" are punctuation; "/", ".", "|", "'" are ordinary.
  - Symbol command atoms: the type from the table in 1.
  - Identifier, number, text and reference atoms: ordinary.
  - Delimited group: the left type is open and the right type is close.
  - Script: the left type and right type of its base.
  - Overset and underset: the left type and right type of the base.
  - Other nodes (row, fraction, binomial, square root, indexed root, matrix, accent): ordinary.
  Since scripts, oversets and undersets inherit the left type and right type of their base, the script in "\left( x \right)^2", for example, has left type open and right type close.

(2) Type conversion: for i = 1, 2, ..., n in this order, check a and b below.
  a. If the left type of e_i is binary, and either i = 1 or the right type of e_(i-1) (the result of the conversions so far) is one of binary, operator, relation, open, punctuation, set the left and right types of e_i to ordinary.
  b. If the left type of e_i is one of relation, close, punctuation, i >= 2, and the right type of e_(i-1) is binary, set the left and right types of e_(i-1) to ordinary.
  Finally, if the right type of e_n is binary, set the left and right types of e_n to ordinary. The types used below are those after this conversion (for example, the "-" in "-x" or "a = -b" becomes ordinary, and no spaces are put around it).

(3) Alphanumeric elements and word elements: the following elements are called "word elements": atoms of Greek letters and of \infty, and scripts whose base is a word element. The following elements are called "alphanumeric elements": identifier and number atoms, word elements, scripts whose base is an alphanumeric element, and accents whose accent name is one of overline, hat, vec, dot, tilde and whose body is an alphanumeric element.

(4) Spacing: the number of spaces g_i (i = 1, ..., n-1) placed between e_i and e_(i+1) is determined as follows. If e_i and e_(i+1) are both alphanumeric elements and at least one of them is a word element, g_i = 1 (example: "2\pi r" becomes "2 pi r"). Otherwise, look it up in the following table with the right type of e_i (row) and the left type of e_(i+1) (column).
               ordinary  operator  binary  relation  open  close  punctuation
  ordinary         0         1        B        R       0     0         0
  operator         1         1        -        R       0     0         0
  binary           B         B        -        -       B     -         -
  relation         R         R        -        0       R     0         0
  open             0         0        -        0       0     0         0
  close            0         1        B        R       0     0         0
  punctuation      P         P        -        P       P     P         P
  B, R, P are the values of bin_space, rel_space, punct_space respectively in normal style, and 0 in script style. 0 and 1 are those values regardless of style. The combinations marked "-" do not occur after the conversion in (2).

(5) Assembly: place e_1 at column x_1 = 0, and e_(i+1) at column x_(i+1) = x_i + w_i + g_i (w_i is the width of the box of e_i). The width of the row box is x_n + w_n (0 if n = 0); its ascent A is the maximum of the ascents of the element boxes and its descent D is the maximum of the descents of the element boxes (both 0 if n = 0); its height is A + D + 1 and its baseline is A. Each element box is placed as a child at position (x_i, A - b_i) (b_i is the baseline of the box of e_i; the baseline lines line up). The description of the box of a row node is "row", and the roles of its children are empty.

## 8. Typesetting the constructs
Let s be the style of the node. Below, the box obtained by typesetting a child node is referred to by a capital-letter name.

(1) Script (base, subscript, superscript): let B be the box of the base typeset in style s, and S and P the boxes of the subscript and the superscript typeset in script style (an absent one is not used; where its width or height is used below, it is taken as 0). If s is normal and the base is an atom of \sum, \prod, \lim, \max or \min, or an accent whose accent name is overbrace or underbrace, use the "stacked placement"; otherwise use the "right placement".
  Right placement: taking the top line of B as line 0, the bottom line of P is -1 if the baseline of B is 0, and 0 if it is 1 or more (for a base whose baseline is 0 the superscript goes above the base; otherwise it goes to the right of the top line of the base). The top line tp of P is that value minus the height of P plus 1. The top line ts of S is the height of B if the descent of B is 0, and the height of B - 1 if it is 1 or more. The top of the box, top, is min(0, tp) if P exists and 0 otherwise; the bottom, bottom, is max(height of B - 1, ts + height of S - 1) if S exists and height of B - 1 otherwise. With T = -top, place B at (0, T), S at (width of B, ts + T) and P at (width of B, tp + T). The width is width of B + max(width of S, width of P), the height is bottom - top + 1, and the baseline is baseline of B + T. The description is "scripts".
  Stacked placement: let W = max(width of B, width of S, width of P) and U = height of P. Center P in width W with its top at line 0, center B in width W with its top at line U, and center S in width W with its top at line U + height of B. The width is W, the height is U + height of B + height of S, and the baseline is U + baseline of B. The description is "limits".
  In both placements the children are B, S, P in this order (absent ones are omitted), and their roles are "base: ", "sub: ", "sup: " respectively (a role string includes its trailing space; the same applies below).

(2) Fraction (numerator, denominator):
  When s is normal: let N and D be the boxes of the numerator and the denominator typeset in style s, and W = max(width of N, width of D) + 2. Center N in width W with its top at line 0, center D in width W with its top at line height of N + 1, and on line height of N draw, at position (0, height of N), a string of W "-" characters (the fraction bar). The width is W, the height is height of N + 1 + height of D, and the baseline is height of N (the line of the fraction bar). The description is "frac", the children are N, D in this order, and their roles are "num: ", "den: ".
  When s is script (slash fraction): for each of the numerator and the denominator, if it is a row node or a fraction node, replace it with a delimited group whose body is that node, whose left delimiter is "(" and whose right delimiter is ")" (this delimited group is not added to the syntax tree, and it is not subject to the warnings of 12). Let N and D be the boxes of the numerator and the denominator after the replacement typeset in style s, and let Q be the box of an atom whose display string is "/" (description atom "/"). Arrange the three boxes N, Q, D by the method of 7 (5) with spacings of 0. The description is "slash", the children are N, Q, D in this order, and their roles are "num: ", empty, "den: ".

(3) Binomial (upper, lower): let U and L be the boxes of the upper and the lower typeset in style s, W = max(width of U, width of L), and H = height of U + 1 + height of L. Place U at the column where U would be centered in width W plus 1, with its top at line 0, and place L at the column where L would be centered in width W plus 1, with its top at line height of U + 1 (line height of U is left empty). Draw the glyph of height H of the left delimiter "(" (defined in (6)) at column 0, and the glyph of height H of the right delimiter ")" at column W + 1. The width is W + 2, the height is H, and the baseline is height of U. The description is "binom", the children are U, L in this order, and their roles are "upper: ", "lower: ".

(4) Overset (placed part, base) and underset (placed part, base): let A be the box of the placed part typeset in script style, B the box of the base typeset in style s, and W = max(width of A, width of B).
  Overset: center A in width W with its top at line 0, and center B in width W with its top at line height of A. The width is W, the height is height of A + height of B, and the baseline is height of A + baseline of B. The description is "overset", the children are A, B in this order, and their roles are "over: ", "base: ".
  Underset: center B in width W with its top at line 0, and center A in width W with its top at line height of B. The width is W, the height is height of B + height of A, and the baseline is baseline of B. The description is "underset", the children are B, A in this order, and their roles are "base: ", "under: ".
  The type of an overset or underset is the type of its base, so, for example, "\overset{def}{=}" is treated as a relation.

(5) Square root (body) and indexed root (index, body): let C be the box of the body typeset in style s, I the box of the index typeset in script style, and k = height of C. For a square root let e = 0 and T = 0; for an indexed root let e = max(0, width of I - 1) and T = max(0, height of I - k). Place things as follows.
  - Draw a string of "_" characters, as many as the width of C (the overbar), at position (e + k + 1, T).
  - Draw "\" at position (e, k + T).
  - For each of r = 1, 2, ..., k, draw "/" at position (e + k - r + 1, r + T) (a stroke rising to the right).
  - Place C at (e + k + 1, 1 + T).
  - For an indexed root, place I at (0, k - height of I + T) (the bottom of I is on the line just above the line of the "\").
  The width is e + k + 1 + width of C, the height is k + 1 + T, and the baseline is baseline of C + 1 + T. The description is "sqrt" for a square root (its only child is C, with an empty role), and "root" for an indexed root (the children are I, C in this order, with roles "index: ", "body: ").

(6) Delimited group (left delimiter, right delimiter, body): let C be the box of the body typeset in style s; for each of the left delimiter and the right delimiter, use its glyph whose height equals the height of C (defined below). Let wl be the width of the left glyph and wr the width of the right glyph. Draw the left glyph at column 0, place C at (wl, 0), and draw the right glyph at column wl + width of C. The width is wl + width of C + wr, and the height and baseline are the same as those of C. The description is "delim <left delimiter> <right delimiter>" (examples: delim ( ), delim \{ .), the only child is C, and its role is empty.
  The glyph of height k of a delimiter has width 1 (width 0 only for ".") and is a vertical column of characters, one character drawn on each line from line 0 to line k-1. "." has width 0 and draws nothing. When k = 1, "(", ")", "[", "]", "|" are that character, "\{" is "{" and "\}" is "}". When k >= 2, they are as follows.
  - "(": line 0 is "/", line k-1 is "\", and the other lines are "|".
  - ")": line 0 is "\", line k-1 is "/", and the other lines are "|".
  - "[", "]", "|": every line is that character.
  - "\{": line 0 is "/", line k-1 is "\", and the other lines are "|". However, if k >= 3, line floor((k-1)/2) is "<".
  - "\}": line 0 is "\", line k-1 is "/", and the other lines are "|". However, if k >= 3, line floor((k-1)/2) is ">".

(7) Matrix (environment name, rows): typeset each cell in style s. Let R be the number of rows, K the number of columns (cell positions), and C_ij the box of the cell in row i, column j (counted from 1). The width cw_j of column j is the maximum of the widths of C_ij (i = 1, ..., R). The ascent A_i of row i is the maximum of the ascents of C_ij (j = 1, ..., K), its descent D_i is the maximum of their descents, and the height of the row is A_i + D_i + 1. The top y_i of each row is given by y_1 = 0, y_(i+1) = y_i + height of row i + row_gap, and the left x_j of each column by x_1 = 0, x_(j+1) = x_j + cw_j + col_gap. The body width Wb is cw_1 + ... + cw_K + col_gap * (K - 1), and the body height Hb is the sum of the heights of the rows + row_gap * (R - 1). Place C_ij at column x_j + o, line y_i + A_i - b_ij. Here b_ij is the baseline of C_ij (the baseline lines of the cells in the same row line up), and o is 0 if the environment name is cases (left-aligned), and otherwise the left column of C_ij when C_ij is centered in width cw_j.
  If the environment name is matrix, the above is the box of the matrix, and its width is Wb. For pmatrix, bmatrix and vmatrix, shift the positions of all cells 2 columns to the right, and draw the glyphs of height Hb of the delimiters "(" and ")", "[" and "]", "|" and "|" respectively at column 0 and column Wb + 3. The width is Wb + 4 (one column of space is left between each delimiter and the cells). For cases, shift the positions of all cells 2 columns to the right, and draw the glyph of height Hb of the delimiter "\{" at column 0. The width is Wb + 2, and nothing is drawn on the right side.
  In every environment, the height is Hb and the baseline is floor((Hb - 1)/2). The description is "<environment name> rows=<R> cols=<K>", the children are C_11, C_12, ..., C_1K, C_21, ... in this order (row by row), and the role of C_ij is "cell <i>,<j>: " (example: cell 2,1: ).

(8) Accent (accent name, body): let C be the box of the body typeset in style s.
  - overline: the width is the width of C; draw a string of "_" characters, as many as the width of C, at position (0, 0), and place C at (0, 1).
  - hat, dot, tilde: the width is W = max(width of C, 1); draw "^", "." or "~" respectively on line 0 at column floor((W - 1)/2), and place C at (0, 1).
  - vec: the width is W = max(width of C, 2); draw at position (0, 0) a string of W - 1 "-" characters followed by ">", and place C at (0, 1).
  For the five above, the height is height of C + 1 and the baseline is baseline of C + 1.
  - overbrace: the width is width of C + 2; draw at position (0, 0) the string formed by joining "/", "-" repeated as many times as the width of C, and "\", and place C at (1, 1). The height is height of C + 1 and the baseline is baseline of C + 1.
  - underbrace: the width is width of C + 2; place C at (1, 0), and draw at position (0, height of C) the string formed by joining "\", "-" repeated as many times as the width of C, and "/". The height is height of C + 1 and the baseline is baseline of C.
  The description is the accent name itself, the only child is C, and its role is empty. By (1), scripts attached to overbrace and underbrace use the stacked placement in normal style (example: the n in "\underbrace{a + b}_{n}" is placed centered below the brace line).

## 9. Line breaking and placement of the formula
Treat the top-level element list e_1, ..., e_n of a valid formula in normal style as in 7 (1) to (4) to obtain the types and the spacings g_1, ..., g_(n-1), and typeset each element into a box. When the elements e_p through e_q (p <= q) are put on one line, the "line width" is the sum of the widths of the boxes of e_p to e_q plus the sum of g_p to g_(q-1).
A "break" is the position immediately before an element e_i (2 <= i <= n); there are the following three kinds.
- Relation break: one where the left type of e_i is relation.
- Plus-minus break: one where e_i is a symbol atom with value "+" or "-" whose type is binary.
- Punctuation break: one where the right type of e_(i-1) is punctuation (the punctuation stays at the end of the previous line).
"Building lines" with a set Q of breaks works as follows. The first line starts at e_1. For a line starting at e_p, determine the indentation d of that line (described below); the candidates are the lines that end at a break of Q after e_p (immediately before e_i, i > p), that is, e_p to e_(i-1), and the line that ends at e_n (e_p to e_n). Among the candidates, choose the longest one (the one containing the most elements) that satisfies d + line width <= width. If none satisfies it, choose the shortest candidate. The next line starts at the element after the chosen line; finish when the line containing e_n has been built.
The indentation d is 0 for the first line. When the first line has been decided, if the first line contains an element whose left type is relation, let e_r be the first such element; the "alignment column" a is the left column of e_r within the first line (the sum of the widths of the boxes of e_1 to e_(r-1) plus the sum of g_1 to g_(r-1)), and the "relation width" is the width of the box of e_r. The indentation of the second and later lines is, if there is an alignment column, a if the left type of the first element of the line is relation, and a + relation width + rel_space otherwise (relations line up under the alignment column, and lines starting with anything else line up under the first term to the right of the relation). If there is no alignment column, it is the value of indent.
How the top-level element list is split into lines is decided in the following order.
(1) Build lines with Q as the set of relation breaks; if every line satisfies d + line width <= width, adopt them (a formula that does not overflow becomes one line this way).
(2) Otherwise, build lines with Q as the set of relation breaks and plus-minus breaks; if every line satisfies d + line width <= width, adopt them.
(3) Otherwise, build lines with Q as the set of all three kinds of breaks, and adopt them.
Among the adopted lines, a line with d + line width > width is called an "overfull line"; it is reported in output/errors.txt as described in [Output files] (it is not a warning of 12 and is not counted in warnings=).
For each line, the box obtained by arranging the boxes of the elements of that line with the spacings g_p to g_(q-1) by the method of 7 (5) is called the "line box" (its description is "line <k>", where k is the line number counted 1, 2, ... from the top). Line 1 is placed at position (0, 0), and line k+1 is placed at the column equal to its indentation and the line equal to the top of line k + the height of line k.
When the formula has a tag string tau (of m characters), let tx = width - m. Let d be the left column, w the width, Y the top line and b the baseline of the box of the last line; if tx >= d + w + 2, place tau at position (tx, Y + b) (at the right end of the baseline line of the last line). Otherwise, add one new line below all the lines and place it at column tx of that line. tau is handled as a "tag box" (width m, height 1, baseline 0, drawing tau at position (0, 0); its description is tag "<tau>").
The width of the formula's "canvas" is the maximum of the right ends (left column + width) of the line boxes and the right end of the tag box; its height is the sum of the heights of the lines (plus 1 when the tag is placed on a new line).

## 10. Drawing
For each formula, prepare a character grid of the size of the canvas width and height, filled with spaces. The position of each box within the canvas (with the top-left of the canvas as (0, 0), the parent's position plus the child's placement) is called its "absolute position". For the line boxes, the tag box and all of their descendant boxes, write each non-space character of each drawn string at the grid position given by the box's absolute position plus the string's placement plus the index of the character (different boxes never write non-space characters at the same position). The lines of the grid, each with its trailing spaces removed, are the lines of the formula's "rendered result" (a line may become empty after the removal).

## 11. Tree notation and linear notation
(1) Tree notation: the notation T(X) of a node X is defined as follows.
  - Identifier, number and symbol command atoms: the token value (examples: x, 3.14, \alpha).
  - Symbol atoms: "'", the character and "'" joined together (examples: '+', '(', ''').
  - Text: a double quote ("), the argument and a double quote (") joined together.
  - Reference: (eqref "<name>").
  - Row: "(row" followed, for each element, by one space and that element's notation, and finally ")" (an empty row is "(row)").
  - Fraction, binomial, overset, underset: (frac <T(numerator)> <T(denominator)>), (binom <T(upper)> <T(lower)>), (overset <T(placed part)> <T(base)>), (underset <T(placed part)> <T(base)>).
  - Square root: (sqrt <T(body)>); indexed root: (root <T(index)> <T(body)>).
  - Script: (sub <T(base)> <T(subscript)>) if there is only a subscript, (sup <T(base)> <T(superscript)>) if there is only a superscript, and (subsup <T(base)> <T(subscript)> <T(superscript)>) if there are both.
  - Delimited group: (delim <left> <right> <T(body)>). <left> and <right> are "'", the character and "'" joined together if the delimiter is one character, and "\{" and "\}" as they are (examples: (delim '[' ')' x), (delim \{ '.' x)).
  - Matrix: "(" and the environment name, followed, for each row, by one space, "[", the notations of the cells of that row separated by single spaces, and "]", and finally ")" (example: (pmatrix [a b] [c d])).
  - Accent: (<accent name> <T(body)>).
  The tree notation of a formula is the notations of the elements of the top-level element list, separated by single spaces. Tags and labels are not included in the notation.
(2) Linear notation: the linear notation L(X) of a node X in style s is defined as follows. Below, "parenthesizing X" means joining "(", L(X) and ")".
  - Identifier, number and symbol atoms: the token value. Text: the argument. Reference: the same as its display string in 6 (but no warning is recorded here).
  - Symbol command atoms: the display string from the table in 1. A large operator is its command name ("sum", "prod", "int") regardless of style.
  - Row: the linear notations of the elements joined in order, with g_i spaces between adjacent elements e_i and e_(i+1), where g_i is the spacing of 7 (4) (computed for this row and style s).
  - Fraction: the numerator's notation, "/" and the denominator's notation joined together. The numerator's and denominator's notations are parenthesized if they are row or fraction nodes, and are L as is otherwise.
  - Binomial: "binom(", L(upper), ", ", L(lower), ")".
  - Overset and underset: "overset(" or "underset(", L(placed part) in script style, ", ", L(base), ")".
  - Script: the base's notation, followed by "_" and the subscript's notation if there is a subscript, and then by "^" and the superscript's notation if there is a superscript. The base's notation is parenthesized if the base is a row, fraction or script node, and is L as is otherwise. The notations of the subscript and the superscript are computed in script style, and are parenthesized if they are row or fraction nodes.
  - Square root: "sqrt(", L(body), ")". Indexed root: "root(", L(index) in script style, ", ", L(body), ")".
  - Delimited group: the string of the left delimiter, L(body) and the string of the right delimiter joined together. The string of a delimiter is the character itself for "(", ")", "[", "]", "|", "{" for "\{", "}" for "\}", and empty for ".".
  - Matrix: the environment name, "[", the notations of the rows separated by "; ", and "]" joined together. The notation of a row is the L of each cell of that row, separated by ", " (example: pmatrix[a, b; c, d]).
  - Accent: the accent name, "(", L(body) and ")" joined together.
  The linear notation of a formula is the notation obtained for the top-level element list as a row in normal style, with its trailing spaces removed.
  When the notation of a child is computed in the rules above, the same style as the parent is used unless stated otherwise.

## 12. Warnings
For valid formulas, record the following warnings. A warning is a pair of a column and a message.
- Missing backslash: an identifier token whose value equals one of the names in the command-name table (example: the sin in "sin x"). The message is "<value> is a command name; write \<value>", and the column is the column of the token.
- Undefined reference: a reference atom whose name is not in the reference table (one warning for each). The message is "undefined reference "<name>"", and the column is the column of the reference.
- Duplicate label: the ones recorded in 4. The message is "duplicate label "<label name>"", and the column is the column of the label.
- Delimiter mismatch: a delimited group whose left delimiter and right delimiter are both not "." and do not form a pair ("(" and ")", "[" and "]", "|" and "|", "\{" and "\}"). The message is "\left<left delimiter> closed by \right<right delimiter>" (example: \left[ closed by \right)), and the column is the right column.
The warnings of one formula are sorted in increasing order of column (no two warnings have the same column).

[Output files]
Write the following four files to the output/ folder. Every file consists only of ASCII characters, and every line (including the last one) ends with a line feed (LF). No line has trailing spaces. Output one empty line at each position where "empty line" is written below, and output no empty lines anywhere else (a rendered result may contain empty lines). All numbers are written as decimal integers without extra leading zeros.

## output/rendered.txt (typeset formulas)
For each formula, in order of formula number, output the following block. Put one empty line between consecutive blocks (not after the last block).
- "formula <formula number>"
- For a valid formula, the lines of its rendered result from 10 (as many lines as the canvas height). For a formula with an error, the single line "(error)".

## output/boxes.txt (box sizes and positions)
For each formula, in order of formula number, output the following.
- Formula with an error: the single line "formula <formula number>: error".
- Valid formula: the header line "formula <formula number>: lines=<number of line boxes> width=<canvas width> height=<canvas height> boxes=<number of boxes> depth=<depth>", followed, for each line box (from the top line down) and then for the tag box (if any), by the "box lines" of that box and its descendant boxes in preorder (the order in which the line of a box is followed, for each of its children in child order, by the lines of that child and its descendants).
A box line is formed by joining a number of spaces equal to twice the box's "level", the box's role, its description, and " x=<X> y=<Y> w=<width> h=<height> b=<baseline>". X and Y are the column and line of the box's absolute position. The level is 0 for line boxes and the tag box, and the parent's level plus 1 for every other box (the roles of line boxes and the tag box are empty). <number of boxes> in the header line is the number of box lines of that formula, and <depth> is the maximum level of the boxes of that formula plus 1.
After all formulas, output "summary: boxes=<sum of the numbers of boxes of all formulas> max_depth=<maximum of the depths of all formulas>" (both 0 if there is no valid formula), and then, for each "kind" (the part of a description before its first space; for example atom, line, pmatrix) that appears in the box lines of all valid formulas, in lexicographic order of the ASCII character codes of the kinds, output "  <kind>: <number of boxes of that kind>" (two spaces at the start of the line).

## output/trees.txt (syntax trees and linear notations)
For each formula, in order of formula number, output the following.
- Formula with an error: the single line "formula <formula number>: error".
- Valid formula: "formula <formula number>: <tree notation>" and "  linear: <linear notation>" (two spaces at the start of the line; "  linear:" when the linear notation is empty), and in addition, for a formula that has a tag string, "  tag: <tag string>".

## output/errors.txt (errors and warnings)
For each formula, in order of formula number, output the following.
- Formula with an error: the following three lines.
  "formula <formula number>, column <column>: <message>"
  two spaces followed by the formula line
  (column + 1) spaces followed by "^" (the "^" comes directly below the character at that column of the formula line)
- Valid formula: for each warning in order of column, three lines in the same format as for an error (except that the first line is "formula <formula number>, column <column>: warning: <message>"). Then, for each overfull line in order from the top line, the single line "formula <formula number>: line <line number> is overfull (width <indentation + line width> > <value of width>)".
The last line is "formulas=<number of formulas> rendered=<number of valid formulas> errors=<number of formulas with an error> warnings=<total number of warnings> overfull=<total number of overfull lines>".

[Source files]
Split the source into the following six files (file names and extensions follow the conventions of each language).
- main: handles the overall flow and the core of the processing, and holds the most logic. It reads the input files, calls the lexical analysis and parsing of each formula and records the errors, builds the equation numbers and the reference table (4), assembles the boxes of atoms and of each construct (6 and 8: right placement and stacked placement of scripts, fractions and slash fractions, binomials, oversets and undersets, square roots and indexed roots, delimited groups, matrices, accents), performs line breaking, the alignment column and tag placement (9), computes the tree notation and linear notation (11), collects the warnings (12), counts the boxes and writes the four files.
- lexer: character classification and splitting into tokens, reading commands (including raw arguments), the symbol command table and the command-name table, and lexical errors (1).
- parser: the brace check (2), the recursive-descent parsing that reads element lists, elements, arguments, nuclei, delimiters and matrices, collapse, recording tags and labels, and parse errors (3).
- boxes: the box structure (width, height, baseline, children with roles and positions, drawn strings, description), the glyphs of large operators, creating delimiter glyphs (8 (6)), and the tables of display strings and types of atoms.
- layout: the types of elements (7 (1)) and type conversion (7 (2)), deciding alphanumeric elements and word elements and the spacing table (7 (3), (4)), and assembling row boxes (7 (5)).
- canvas: drawing a box tree onto a character grid and removing the trailing spaces of each line (10), and writing out a box tree as box lines with absolute positions.

[Constraints]
- The values in params.txt are: width from 20 to 200, indent from 0 to 20, rel_space, bin_space and punct_space from 0 to 3, col_gap from 0 to 5, and row_gap from 0 to 3.
- formulas.txt has 1 to 500 lines, and each line has at most 200 characters.
- The top-level element list of a valid formula contains at least one element. The number of characters of a tag string is at most width.
- The canvas width and height of every formula are at most 1000, and the absolute values of all integers, including intermediate values of the computation, are less than 2^31.
- Apart from the conditions written here, the input is not restricted. It may contain formulas that produce errors, warnings or overfull lines, and all of them are handled according to the rules of [Processing].
