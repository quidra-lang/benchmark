[Overview]
Write a program that analyzes a set of points with integer coordinates in the plane with DBSCAN and OPTICS, which are density-based clustering methods. The neighborhoods of points are found with an index based on a grid whose cell side equals the radius, and are cross-checked by brute-force counting. A candidate radius is obtained from the knee point of the k-distance curve, and DBSCAN is run with several given radii and with that candidate. OPTICS computes the order in which the points are processed (the cluster ordering) together with core distances and reachability distances, and from these a clustering equivalent to DBSCAN and hierarchical clusters by the xi method are extracted. For each resulting cluster, the centroid (as reduced fractions), the representative point, the bounding box, the convex hull and so on are summarized; the program also checks the results, examines the containment of clusters when the radius changes, compares clusterings with the adjusted Rand index (as a reduced fraction), and so on, and draws the cluster maps, the k-distance plot and the reachability plot with characters.
Distances are handled as integer squared distances, and all comparisons and decisions are made exactly with integer arithmetic. Square roots are used only when writing some of the output values.
The input is two files in the input/ folder (point data, parameters), and the results are written to five files in the output/ folder. Nothing is written to standard output. No random numbers are used. Since every rule is fully specified, the result is uniquely determined.

[Input files]
There are two input files: input/points.csv and input/params.txt. Both files consist of ASCII characters only, and every line (including the last line) ends with a newline (LF). There is no whitespace at the start or end of a line, and there are no empty lines. Values are separated by a comma in points.csv and by a single space in params.txt. All integers are 0 or greater and are written in base 10 without extra leading zeros.

* input/points.csv (point data)
The first line is a header line, the string id,x,y. Each line from the second line on represents one point, listing the ID, the x coordinate and the y coordinate of the point in this order, separated by commas. An ID is an integer from 1 to 99999 and differs from point to point. Coordinates are integers from 0 to 10000, and no two points have the same coordinates. The lines are not necessarily sorted by ID.
Let n be the number of points. The order of the points sorted by ID in increasing order is called the "point order". The coordinates of a point p are written (x_p, y_p).

* input/params.txt (parameters)
It consists of the following 9 lines, in this order. Each line is an uppercase keyword followed by one or more values, separated by single spaces.
- EPS e_1 e_2 ...: the list of radii for which DBSCAN is run (1 to 6 distinct positive integers, in any order).
- MIN_PTS m: the number of points used to decide core points (an integer >= 2).
- OPTICS_MAX_EPS E: the maximum radius of OPTICS (a positive integer).
- EXTRACT_EPS f_1 f_2 ...: the list of radii at which clusters are extracted from the OPTICS result (1 to 6 distinct positive integers, each <= E, in any order).
- XI u/v: the steepness ratio xi = u / v of the xi method, written as the positive integers u and v (u < v) joined by "/" (example: 3/20).
- XI_MIN_SIZE s_min: the minimum size of the clusters extracted by the xi method (an integer >= 2).
- MAP_SIZE W H: the number of columns W and the number of rows H of the cluster maps (positive integers).
- KDIST_PLOT Wk Hk: the number of columns Wk and the number of rows Hk of the k-distance plot (positive integers).
- PLOT_WIDTH Wr: the maximum length Wr of the bars of the reachability plot (a positive integer).

[Processing]
* 1. Notation and computation rules
- The "squared distance" of two points p and q is d(p, q) = (x_p - x_q) * (x_p - x_q) + (y_p - y_q) * (y_p - y_q). All distance-related values in this task, such as comparisons with a radius, core distances, reachability distances and k-distances, are handled as integer squared distances unless stated otherwise.
- floor(t) is the largest integer not greater than t. Every t to which floor is applied in this task is the quotient of an integer >= 0 divided by a positive integer, so it can be computed by integer division (truncation).
- The "root" of an integer w >= 0 is the square root of w rounded to 3 decimal places and written with exactly 3 digits after the decimal point (examples: 2.236 for 5, 2.000 for 4). Square roots are computed only to write roots and are not used for any decision.
- The "reduced fraction" of integers a >= 0 and b > 0 is a'/b', where a' and b' are a and b divided by their greatest common divisor (examples: 3/2 for 6 and 4, 2/1 for 6 and 3, 0/1 for 0 and 5). The denominator is written even when it is 1.
- A clustering result gives a label to each point. A label is either -1 (noise, meaning that the point belongs to no cluster) or a cluster number starting from 0. A point whose label is 0 or greater is called a "point belonging to a cluster", the cluster with number L is called "cluster L", and the number of points belonging to a cluster is called the "size" of the cluster.
- The "character" of a label L is . (period) if L = -1, an uppercase English letter if 0 <= L < 26 (0 is A, 1 is B, ..., 25 is Z), a lowercase English letter if 26 <= L < 52 (26 is a, ..., 51 is z), and # if L >= 52.
- "INF" (infinity) denotes that a value is undefined. INF compares greater than every integer, and two INF values are equal. The result of a max that involves INF is INF.
- Every rule that selects a maximum or a minimum always comes with how to choose among equal values.

* 2. Neighborhoods and the grid index
For a positive integer e used as the radius, the "e-neighborhood" N_e(p) of a point p is the set of all points q with d(p, q) <= e * e (including p itself). |N_e(p)| is the number of its points.
e-neighborhoods are found with an index based on a grid whose cells have side e.
- The "cell" of a point p is the pair of integers (floor(x_p / e), floor(y_p / e)), written (gx, gy). Each cell records the points that fall into it, in point order. A cell that contains one or more points is called a "used cell".
- The e-neighborhood of a point p is found as follows. Let (gx, gy) be the cell of p; examine 9 cells (column, row) in total, taking the rows gy - 1, gy, gy + 1 in this order and, within each row, the columns gx - 1, gx, gx + 1 in this order. Take the points recorded in each cell one at a time in point order as q, and if d(p, q) <= e * e, append q to the end of the neighborhood. The order of the points of the neighborhood found this way is called the "scan order", and the number of points taken (counting p itself) is called the "candidate count" of p. Every point q with d(p, q) <= e * e is always in one of these 9 cells.
- As a cross-check, for each point p, examine all points q (including p itself) by brute force and count the q with d(p, q) <= e * e. If, for every point, this count equals |N_e(p)| found with the grid, the result of the cross-check is ok; otherwise it is mismatch.
A grid is built with e set to each of the distinct values among all values of EPS, the suggested radius e* found in section 3, and E. These are called the "grid radii". From then on, every e-neighborhood used is the one found with the grid (in scan order). For each grid radius, compute the following values.
- cells: the number of used cells
- busiest: the cell with the most recorded points (ties: the smaller gy, then the smaller gx). Its gx, gy and number of points are written.
- candidates: the sum of the candidate counts of all points
- pairs: ((the sum of |N_e(p)| over all points) - n) / 2. This is the number of pairs of distinct points with d(p, q) <= e * e.
- brute_pairs: the value computed with the same formula as pairs, using the sum of the counts obtained by brute force
- occupancy: for each number c of recorded points, the number of used cells with exactly c points

* 3. k-distance and the knee point
Let k = m - 1.
- The "j-th neighbor distance" of a point p is the j-th value when the d(p, q) over the n - 1 points q other than p are sorted in increasing order (equal values are counted one by one). The "k-distance" kd(p) of a point p is its k-th neighbor distance.
- Curve of the j-th neighbor distance: sort all points by the j-th neighbor distance in decreasing order (ties by ID in increasing order) and assign the ranks 1, 2, ..., n from the start. Let y_r be the j-th neighbor distance of the point with rank r.
- Knee point: for each rank r, let c_r = |(n - 1) * (y_r - y_1) - (y_n - y_1) * (r - 1)|. c_r is a value proportional to the distance between the point (r, y_r) and the straight line through the two ends (1, y_1) and (n, y_n) of the curve. The r with the largest c_r (ties: the smaller r) is called the "knee rank".
- Suggested radius: with r* the knee rank, the smallest positive integer e with e * e >= y_r*.
The curve for j = k is called the "k-distance curve"; its knee rank is r* and its suggested radius is e*. In addition, for each of j = 1, 2, ..., 2 * m, the curve, the knee rank and the suggested radius are found in the same way. This is called the "knee table" (the row for j = k is the same as above).

* 4. DBSCAN
DBSCAN with radius e is done as follows. A point p with |N_e(p)| >= m is called a "core point".
Set the labels of all points to "undecided" and let C = 0. For each point p in point order, do one of the following (1) to (3).
(1) If the label of p is not undecided, do nothing.
(2) If the label of p is undecided and p is not a core point, set the label of p to -1.
(3) If the label of p is undecided and p is a core point, set the label of p to C and append the points of the e-neighborhood of p, in scan order, to the end of a queue. Then, until the queue is empty, remove the point q at the front and process it as follows.
  - If the label of q is -1, set it to C. The neighborhood of q is not appended.
  - If the label of q is 0 or greater, do nothing.
  - If the label of q is undecided, set it to C. Further, if q is a core point, append the points of the e-neighborhood of q, in scan order, to the end of the queue.
  When the queue becomes empty, increase C by 1.
The points whose label is -1 at the end are noise. A core point always belongs to a cluster. A point that belongs to a cluster and is not a core point is called a "border point". A border point belongs to the cluster that took it in first, that is, to the smallest of the labels of the core points in its e-neighborhood.

* 5. OPTICS
OPTICS is run with radius E and uses E-neighborhoods.
- The "core distance" core(p) of a point p is, if |N_E(p)| >= m, the m-th value when the d(p, q) over the points q of N_E(p) (including p itself) are sorted in increasing order, and INF otherwise. Since d(p, p) = 0 of p itself comes first, core(p) = kd(p) whenever core(p) is not INF.
Each point has a reachability distance reach (initially INF), a predecessor pred (initially none) and a processed mark (initially unprocessed), and an "ordering" that arranges the points in a single sequence is built as follows.
(1) For each point t in point order: if t is processed, do nothing; if it is unprocessed, let the seed set be {t} and do (2).
(2) Repeat the following until the seed set is empty.
  - Remove from the seed set the point p with the smallest reach (ties: the point with the smaller ID), mark p as processed and append it to the end of the ordering. (The first point removed is t, and the reach of t stays INF.)
  - If core(p) is not INF, then for each unprocessed point q of the E-neighborhood of p, let r = max(core(p), d(p, q)); if r < reach(q), set reach(q) to r and pred(q) to p, and add q to the seed set (if it is already in it, it stays as it is).
Assign the positions 1, 2, ..., n from the start of the ordering. The reach of the point at position i is written R_i, and in addition R_(n+1) = INF. A point whose reach is INF is called a "component start", and each part obtained by splitting the ordering just before each component start is called a "component" (the point at position 1 is always a component start).

* 6. DBSCAN-equivalent extraction from OPTICS
For a positive integer f <= E, labels are given as follows. First let C = -1, then for the positions 1, 2, ..., n in this order, do the following for the point p at that position.
- If reach(p) > f * f (including reach(p) = INF): if core(p) <= f * f, increase C by 1 and set the label of p to C. Otherwise, set the label of p to -1.
- If reach(p) <= f * f: set the label of p to C (-1 if C = -1).
In this extraction, the points with core(p) <= f * f are the core points. In theory, the division of the core points into clusters is the same as in DBSCAN with radius f, but some of the border points of DBSCAN may become noise.

* 7. Extraction by the xi method
Let alpha = (v - u) * (v - u) and beta = v * v. For values a and b (each an integer or INF), "xle(a, b)" is defined to mean that beta * a <= alpha * b holds. However, if b = INF, xle(a, b) always holds, and if a = INF and b is an integer, it does not hold. (xle(a, b) is the same as sqrt(a) <= (1 - xi) * sqrt(b) holding.)
(1) Classifying positions: a position i (1 <= i <= n) is classified by R_i and R_(i+1) as follows. If R_i and R_(i+1) are both INF, it is none of the following. Otherwise,
- if xle(R_i, R_(i+1)), it is "steep up"
- if xle(R_(i+1), R_i), it is "steep down"
- if R_i < R_(i+1), it is "up"
- if R_i > R_(i+1), it is "down"
(a steep up position is also up, and a steep down position is also down).
(2) Extending a region: the end of the down region starting at position a is found as follows. Let b = a and c = 0, and for i = a, a + 1, ..., n in this order: if i is steep down, set b = i and c = 0. If i is not steep down but is up, stop there. If neither, increase c by 1, and if c > m, stop there. The value of b when stopping (or when i = n has been examined) is the end of the region. The end of an up region is found in the same way, with "steep down" replaced by "steep up" and "up" replaced by "down" in this description.
(3) Scan: prepare a list of "down areas" (initially empty; each down area has a start a, an end b and a maximum in between h), a list of xi clusters (initially empty), an integer index = 1 and a value mib = 0, and do the following for s = 1, 2, ..., n in this order. If s < index, or if s is neither steep up nor steep down, do nothing and go on to the next s.
  [1] Set mib to the maximum of mib and R_index, R_(index+1), ..., R_s.
  [2] If mib = INF, empty the list of down areas. Otherwise, remove from the list the down areas for which xle(mib, R_a) does not hold (a is the start of that down area), and set h of each remaining down area to max(h, mib).
  [3] If s is steep down: find the end b of the down region starting at s, and append the down area (a = s, b, h = 0) to the end of the list. Then set index = b + 1 and mib = R_index.
  [4] If s is steep up (when it is not steep down): find the end w of the up region starting at s, and set index = w + 1 and mib = R_index. Then examine each down area (a, b, h), from the front of the list, as follows.
    - Let cs = a and ce = w.
    - If xle(h, R_(ce+1)) does not hold, this down area does not give a candidate.
    - Let D = R_a. If xle(R_(ce+1), D), increase cs by 1 while R_(cs+1) > R_(ce+1) and cs < b. Otherwise, if xle(D, R_(ce+1)), decrease ce by 1 while R_(ce-1) > D and ce > s. If neither, leave cs and ce unchanged.
    - If ce - cs + 1 >= s_min, cs <= b and ce >= s all hold, (cs, ce) is a candidate.
    After all down areas have been examined, append the candidates to the end of the list of xi clusters in the reverse of the order in which they were found.
The down regions found in [3] (start s, end b) and the up regions found in [4] (start s, end w) are called "steep areas" and are recorded in the order in which they were found.
(4) xi clusters: number the xi clusters 0, 1, 2, ... from the front of the list of xi clusters. The xi cluster (cs, ce) is the set of points at positions cs to ce, and its size is ce - cs + 1.
(5) Labels: first set all positions to "unlabeled", then examine the xi clusters in number order. If the positions cs to ce of an xi cluster are all unlabeled, give these positions a new label (labels are used in the order 0, 1, 2, ...), and this becomes the "label" of that xi cluster. Otherwise, that xi cluster has no label. The points at positions that are still unlabeled at the end have label -1. In the result of the xi method, the points with core(p) not INF are the core points.
(6) Parent: the parent of xi cluster j is, among the xi clusters i (i != j) that satisfy the following, the one with the smallest size (ties: the smaller number): the position range of i contains the range of j (cs_i <= cs_j and ce_j <= ce_i), and moreover the size of i is larger than that of j, or the sizes are equal and i > j. If there is no such i, there is no parent.
(7) Walls and valley: for an xi cluster (cs, ce), the left wall is R_cs, the right wall is R_(ce+1), and the valley is the minimum of those of R_(cs+1), ..., R_ce that are not INF (INF if there is no such value).

* 8. Settings
The following clustering results are called "settings", and this order is called the "setting order". Each setting has a name, a radius, labels and a way of deciding core points.
(1) For each value e of EPS (in the order of the EPS list): the result of DBSCAN with radius e. The name is db<e> (example: db14), and the core points are those of section 4.
(2) The result of DBSCAN with radius e*. The name is knee<e*> (example: knee38), and the core points are those of section 4. This is called the "knee setting".
(3) For each value f of EXTRACT_EPS (in list order): the result of the extraction of section 6. The name is op<f>, the radius is f, and the core points are those of section 6.
(4) The result of the xi method of section 7. The name is xi, the radius is E, and the core points are those of section 7 (5).
(1) and (2) are called "DBSCAN settings", and (3) are called "extraction settings". The number of clusters K of each setting is the maximum of its labels + 1 (all cluster numbers 0 to K - 1 are used).

* 9. Cluster summaries
For each cluster L of a setting, let M be the set of points belonging to it and g its size, and compute the following values. SUM below denotes the sum over the points of M.
- core: the number of points of M that are core points in that setting. border = g - core.
- Centroid: with Sx = SUM x_p and Sy = SUM y_p, it is expressed by the reduced fraction of Sx and g and the reduced fraction of Sy and g.
- Medoid (representative point): the point p of M for which (g * x_p - Sx) * (g * x_p - Sx) + (g * y_p - Sy) * (g * y_p - Sy) is smallest (ties: the smaller ID). It is the point closest to the centroid.
- Bounding box: xmin and xmax are the minimum and the maximum of the x coordinates of the points of M, and ymin and ymax are the minimum and the maximum of the y coordinates. The area is A = (xmax - xmin + 1) * (ymax - ymin + 1) (the number of lattice points contained in the rectangle), and the density is expressed by the reduced fraction of g and A.
- Convex hull: let P_1, ..., P_g be the points of M sorted in increasing lexicographic order of (x, y) (by x in increasing order, ties by y in increasing order). For three points o, a, b, let turn(o, a, b) = (x_a - x_o) * (y_b - y_o) - (y_a - y_o) * (x_b - x_o). If g <= 2, the vertex sequence is P_1, ..., P_g. If g >= 3, build the following two chains.
  Lower chain: add P_1, P_2, ..., P_g in order to an empty chain. Before adding each point p, remove the last point of the chain while the chain has 2 or more points and turn(o, a, p) <= 0 for the second-to-last point o and the last point a of the chain.
  Upper chain: do the same in the order P_g, P_(g-1), ..., P_1.
  The vertex sequence is the lower chain without its last point, followed by the upper chain without its last point (it is in counterclockwise order and does not include points in the middle of an edge; when all points lie on one straight line, it consists of the two end points).
  Let h be the number of vertices and V_1, ..., V_h the vertex sequence, let V_(h+1) = V_1, and let T = |SUM over i = 1, ..., h of (x(V_i) * y(V_(i+1)) - x(V_(i+1)) * y(V_i))| (x(V) and y(V) are the coordinates of the point V). The area of the convex hull is T / 2.
- Diameter: the maximum diameter_sq of d(p, q) over two points p, q of M (including p = q). Since the maximum is always attained between vertices of the convex hull, it may be found by examining only pairs of vertices.

* 10. Checks of DBSCAN settings
For a DBSCAN setting (radius e), compute the following.
- Checks: examine the following three conditions; each is ok if it holds and fail if it does not.
  (a) A core point p and a core point q in the e-neighborhood of p always have the same label.
  (b) The e-neighborhood of a border point p always contains a core point with the same label as p.
  (c) The e-neighborhood of a noise point p contains no core point.
- isolated: the number of noise points with |N_e(p)| = 1 (no point in the neighborhood other than itself).
- ambiguous: the border points p whose e-neighborhood contains a core point with a label different from that of p. The labels of such core points, with duplicates removed and sorted in increasing order, are called the "other clusters".

* 11. Comparisons and analysis
(1) Containment: sort the DBSCAN settings by radius in increasing order (ties in setting order), and examine each pair of adjacent settings X (the earlier one) and Y. The "destination" of a cluster c of X is the label in Y of the point with the smallest ID among the core points of c (core points in X). (With the same m, a larger radius gives more core points and keeps the connections between core points, so all core points of c belong to the same cluster of Y.) For each cluster L of Y, find the numbers of the clusters of X whose destination is L, in increasing order.
(2) OPTICS and DBSCAN: for each extraction setting X (in setting order), if there are DBSCAN settings with the same radius as X, the first of them in setting order is taken as Y and compared (if there is none, nothing is done for X).
  - Over all core points of X, form the set of pairs (label in X, label in Y). If every label of X appears in exactly one pair of this set and every label of Y appears in exactly one pair, the division of the core points is same; otherwise it is different.
  - border_as_noise: the number of points whose label in X is -1 and whose label in Y is 0 or greater.
  - moved: computed only in the same case. In that case the set of pairs gives a correspondence from the labels of X to the labels of Y, and moved is the number of points whose label in X is 0 or greater and whose label in X, mapped by the correspondence, differs from their label in Y.
(3) OPTICS summary: find the number of points with core(p) not INF, the number of components, the number of components with only one point, and the maximum number of points of a component.
(4) Radius sweep: for each of f = 1, 2, ..., E, do the extraction of section 6 and find the number of clusters K_f, the number of noise points, and the size of the largest cluster (0 if there are no clusters). Further, consider the ranges f1 to f2 of consecutive f over which K_f has the same value and which cannot be extended any further. Among those with K_f >= 2, the one with the largest length f2 - f1 + 1 (ties: the smaller f1) is called the "stable range".
(5) Outliers: for each noise point p of the knee setting, the core point q of the knee setting with the smallest d(p, q) (ties: the smaller ID) is called the "nearest core point". Sort the noise points by d(p, q) to their nearest core point in decreasing order (ties by the ID of p in increasing order).
(6) Gaps: for each pair of clusters a, b (a < b) of the knee setting, find the minimum of d(p, q) over the points p of cluster a and the points q of cluster b, and the pair (p, q) that attains it (ties: the smaller ID of p, then the smaller ID of q).
(7) Contingency table: build the contingency table T of the knee setting (rows) and the result of the xi method (columns). T[r][c] is the number of points whose label in the knee setting is r and whose label in the xi method is c. With K1 the number of clusters of the knee setting and K2 the number of clusters of the xi method, the rows are r = -1, 0, ..., K1 - 1 and the columns are c = -1, 0, ..., K2 - 1. Further, for each cluster c of the xi method (0 <= c < K2), the r with the largest T[r][c] (0 <= r < K1; ties: the smaller r) is called the "matching cluster", and the shared count T[r][c] and the Jaccard coefficient are found. The Jaccard coefficient is the reduced fraction of T[r][c] and (the size of cluster r of the knee setting) + (the size of cluster c of the xi method) - T[r][c].
(8) Adjusted Rand index (ARI): let a and b be the label sequences of two settings. The points with label -1 are also treated as one group, and with C2(t) = t * (t - 1) / 2, let
  S = (the sum of C2(t) over the numbers of points t of each combination of a label in a and a label in b)
  A = (the sum of C2(t) over the numbers of points t of each label of a)
  B = (the sum of C2(t) over the numbers of points t of each label of b)
  Z = C2(n)
  numerator = 2 * (Z * S - A * B), denominator = Z * (A + B) - 2 * A * B
If the denominator is 0, the ARI is 1/1. Otherwise, it is the numerator and the denominator divided by the greatest common divisor of the absolute value of the numerator and the denominator (the denominator is positive; the numerator may be negative, and if the numerator is 0 it is 0/1). Compute these exactly with integers.

* 12. Maps and plots
(1) Cluster map: let x0 and x1 be the minimum and the maximum of the x coordinates of all points, and y0 and y1 the minimum and the maximum of the y coordinates. A point p falls into the cell at column c = floor((x_p - x0) * W / (x1 - x0 + 1)) and row r = floor((y1 - y_p) * H / (y1 - y0 + 1)) (0 <= c < W, 0 <= r < H; row 0 is the top and column 0 is the leftmost). For each setting, each cell is represented by the following character.
  - A cell that contains no points: a space
  - A cell that contains points whose labels are all -1: .
  - A cell with exactly one kind of label other than -1: the character of that label (the cell may also contain noise points)
  - A cell with two or more kinds of labels other than -1: *
(2) Kind map: for the knee setting, with the same cell division as in (1), a cell that contains a core point is represented by #, a cell that contains no core point but contains a border point by +, a cell that contains points that are all noise by ., and a cell that contains no points by a space.
(3) k-distance plot: a plot with Wk columns and Hk rows. Column c (0 <= c < Wk) covers the ranks floor(c * n / Wk) + 1 to floor((c + 1) * n / Wk) of the k-distance curve. With y' the y value of rank floor(c * n / Wk) + 1, the height h_c of column c is the largest integer h >= 0 with h * h * y_1 <= Hk * Hk * y' (y_1 is the maximum of the curve). The column that covers the knee rank r* is called the "knee column". The cell at row t (0 <= t < Hk; row 0 is the top) and column c is # if Hk - t <= h_c, otherwise : if it is in the knee column, and a space otherwise.
(4) Reachability plot: let Rtop be the maximum of those of R_1, ..., R_n that are not INF. The "bar" of position i is Wr characters - if R_i = INF, and otherwise # repeated as many times as the largest integer b >= 0 with b * b * Rtop <= Wr * Wr * R_i.

[Output files]
Write five files: output/labels.csv, output/optics_order.csv, output/kdist.txt, output/clusters.txt and output/maps.txt.

* Common format
- The output consists of ASCII characters only, and every line (including the last line) ends with a newline (LF). Do not put whitespace at the end of a line, and do not insert empty lines unless specified. The only whitespace at the start of a line is what the formats show (an indent of two spaces, and the right alignment in the lines of the reachability plot).
- In the formats below, the parts enclosed in < > are replaced by values, and all other characters are written as they are. Values are separated by a single space. "<...> ..." means values of the same kind listed separated by single spaces.
- Integers are written in base 10 without extra leading zeros, with a leading - for negative numbers.
- Roots are written with 3 decimal places as defined in section 1. The value of an ARI is numerator / denominator as a real number, rounded to 4 decimal places and written with exactly 4 digits after the decimal point (a value that rounds to 0 is written without -).
- The absence of a value (INF or "none") is written as -.
- Maps and plots are written "framed". The framed form of a plot with w columns and h rows consists of h + 2 lines: the first and the last lines are the string of +, w characters - and +, and each of the h lines in between is the string of |, the w cell characters of that row (from the left) and |.

* output/labels.csv
The first line is id followed by the names of the settings in setting order, separated by commas (id,<name>,<name>,...). Then, for each point in point order, write the following line.
<ID>,<label of the point>,... (the label in each setting, in setting order)

* output/optics_order.csv
The first line is order,id,core_sq,reach_sq,reach,predecessor. Then, for the positions i = 1, 2, ..., n in this order, write the following line for the point p at position i.
<i>,<ID of p>,<core(p)>,<reach(p)>,<root of reach(p)>,<ID of pred(p)>
If core(p) or reach(p) is INF, write - for it (if reach(p) is INF, the root is also -). If pred(p) does not exist, write -.

... (for j = 1, 2, ..., 2 * m of the knee table, in this order)
(empty line)
core_check
eps <e> core <number of points with kd(p) at most e * e> non_core <n - that number> grid_core <number of core points of that setting> <ok or mismatch>
... (one line for each DBSCAN setting, in setting order; e is the radius of that setting)
optics max_eps <E> core <number of points with core(p) not INF> <ok or mismatch>
The last value of an eps line is ok if the values of core and grid_core are equal, and mismatch otherwise. The last value of the optics line is ok if core(p) = kd(p) for every point with core(p) not INF, and mismatch otherwise.

[Source files]
Split the program into the following six source files (file names follow each language's conventions).
- main: handles the overall flow and most of the processing: calling the input reading, computing the k-distances and the knee point (including the knee table), calling the neighborhood computation for each grid radius and collecting the summaries and cross-checks, calling DBSCAN and OPTICS, the DBSCAN-equivalent extraction from OPTICS and the radius sweep, the xi method (classifying positions, extending regions, scanning, labels, parents, walls and valleys), the cluster summaries (centroid, medoid, bounding box, convex hull, diameter), the checks of DBSCAN settings, containment, the comparison of OPTICS and DBSCAN, outliers, gaps, the contingency table, ARI, building the maps and plots, and assembling the contents of the five output files.
- dataset: reads the two input files and returns the sequence of point IDs and coordinates in point order, and the parameter values.
- grid_index: handles building the grid, computing e-neighborhoods in scan order and candidate counts, selecting the cell with the most points, and counting neighborhood points by brute force.
- dbscan: computes the DBSCAN labels by deciding core points and expanding clusters with a queue.
- optics: handles computing core distances, and computing the ordering, reachability distances and predecessors using the seed set.
- report: handles formatting reduced fractions, roots and ARI values (including the treatment of -0), framed plots, and writing sequences of lines to files.

[Constraints]
- 2 * m + 1 <= n <= 2000, 2 <= m <= 20, 1 <= e_i <= 200, 1 <= E <= 200, 1 <= u < v <= 100, 2 <= s_min <= n, 1 <= W <= 100, 1 <= H <= 60, 1 <= Wk <= 100, Wk <= n, 1 <= Hk <= 40, 1 <= Wr <= 100. The given data has n = 699 and 9 settings.
- The input files strictly follow the format above. There is no need to check for input errors.
- The knee setting has at least one cluster. At least one of R_1, ..., R_n is not INF.
- Squared distances are less than 2^31, but c_r, the value of the expression used to select the medoid, the values of the expressions used to compute the heights of the k-distance plot, and the values that appear in the ARI computation (including the written numerator and denominator of the ARI) may exceed 2^31 (all of them are less than 2^53). Compute these with 64-bit integers (or a type that can represent integers less than 2^53 without error).
- Floating-point numbers are used only for the square roots needed to write roots and for the division needed to write ARI values. In the given data, every value written as a root or as an ARI value is more than 10^-9 away from a rounding boundary. All other comparisons and decisions must be made exactly with integers (and INF).
- k-distances, outliers, gaps and so on may be computed by brute force over all pairs of points (about 500,000 pairs for the given data).

In this example, the knee rank of the k-distance curve for k = 3 is 3 (y_3 = 13), and since 3 * 3 < 13 <= 4 * 4, the suggested radius is e* = 4. In db3, point 50 is a border point, and its 3-neighborhood contains core point 22 of cluster 0 and core point 68 of cluster 2, so it belongs to cluster 0, which has the smaller number, and it appears in the ambiguous lines. Point 11 is a border point in knee4, but in the OPTICS ordering it is processed at position 1 as a component start (both reach and core are INF), and it becomes noise in op4. Therefore border_as_noise is 1 in the comparison of op4 and knee4. In the xi method, xi cluster 2 (positions 2 to 13) contains the ranges of xi clusters 0 and 1, so it has no label, and labels are given to xi clusters 0, 1 and 3. Point 50 at position 9 is not in the range of any label, so it is noise in the xi method.
