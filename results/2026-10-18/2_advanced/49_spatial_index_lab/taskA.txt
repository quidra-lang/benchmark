[Overview]
Write a program that stores integer-coordinate points and rectangles in the plane in several spatial indexes, runs searches on them, and examines how the indexes work. Points are stored in five structures: a k-d tree, a PR quadtree, R-trees (one built by successive insertion and one built in bulk by the STR method), and a uniform grid. Rectangles are stored in two R-trees (successive insertion and the STR method).
There are seven kinds of search: the points within a rectangular range (RANGE), the points inside a circle (RADIUS), the k nearest points (KNN), the number of points in a window (WINDOWCOUNT), the rectangles that contain a point (CONTAINS), the k rectangles nearest to a point (NEAREST), and all point-rectangle pairs in a containment relation (JOIN, spatial join). Each search is performed in every structure responsible for it and cross-checked against the answer found by brute force, and the number of nodes each structure examined and the number of objects whose condition was tested are recorded. Point insertions (INSERT) and deletions (DELETE) are applied to all point structures, and the program also reports where a point is located in each structure (LOCATE). After the initial build and at each DUMP command, the internal structure of each tree is written out and statistics such as height, node count, fill ratio and overlap area are computed.
All coordinates are integers, and all comparisons and calculations are done exactly in integers. Floating-point numbers are not used.
The input is four files in the input/ folder (points, rectangles, parameters, commands), and the results are written to five files in the output/ folder. Nothing is written to standard output. No random numbers are used. Since every rule is fixed, the result is uniquely determined.

[Input files]
There are four input files: input/points.csv, input/rects.csv, input/params.txt and input/queries.txt. Every file consists of ASCII characters only, and every line (including the last line) ends with a line feed (LF). There are no spaces at the beginning or end of a line, and there are no empty lines. Values are separated by commas in the two CSV files and by a single space in the other files. All integers are 0 or greater and are written in decimal without extra leading zeros.

* input/points.csv (points)
The first line is a header line, the string id,x,y. Each line from the second line on represents one point and lists the point's ID, x coordinate and y coordinate, in this order, separated by commas. IDs are distinct for each point, and no two points have the same coordinates. The lines are not necessarily in ID order. The order of the lines is used as the insertion order when building the R-tree rtree.

* input/rects.csv (rectangles)
The first line is a header line, the string id,x1,y1,x2,y2. Each line from the second line on represents one rectangle and lists the rectangle's ID and x1, y1, x2, y2 (x1 <= x2, y1 <= y2), in this order, separated by commas. The rectangle is the set of all points (x, y) satisfying x1 <= x <= x2 and y1 <= y <= y2 (the boundary is included). There are also rectangles with x1 = x2 or y1 = y2, which are line segments or single points. IDs are distinct for each rectangle (a rectangle ID may have the same value as a point ID, but it has nothing to do with point IDs). The order of the lines is used as the insertion order when building the R-tree rtree_rect. The rectangles are never changed by commands.

* input/params.txt (parameters)
Consists of the following four lines, in this order.
- WORLD W: the coordinate range. The coordinates of the points and rectangles, and the coordinates appearing in commands, are all between 0 and W - 1 inclusive. W is a power of 2.
- BUCKET c: the upper limit c on the number of points a quadtree leaf can hold.
- RTREE M m: the upper limit M and the lower limit m on the number of entries in an R-tree node (2 <= m <= M / 2).
- GRID g: the side length g of a grid cell (W is divisible by g).

* input/queries.txt (commands)
Each line is one command: an uppercase command name followed by zero or more integers, separated by single spaces. There are the following 11 commands (their meaning is explained in items 9 and 10 of [Processing]).
- RANGE x1 y1 x2 y2 (x1 <= x2, y1 <= y2)
- RADIUS x y r
- KNN x y k
- WINDOWCOUNT x1 y1 x2 y2 (x1 <= x2, y1 <= y2)
- CONTAINS x y
- NEAREST x y k
- JOIN
- LOCATE id
- INSERT id x y
- DELETE id
- DUMP
The commands are numbered 1, 2, 3, ... from the top of the file; this number is called the "command number".

[Processing]
* 1. Notation and arithmetic rules
- A point p has an ID and coordinates (x_p, y_p). All points stored at a given moment are called the "current points".
- For integers x1 <= x2, y1 <= y2, the set of all points (x, y) satisfying x1 <= x <= x2 and y1 <= y <= y2 is called a "box" and is written (x1, y1, x2, y2). A rectangle is a box. The box of a point p is (x_p, y_p, x_p, y_p). Below, the four values of a box b are written b.x1, b.y1, b.x2, b.y2.
- The "area" area(b) of a box b is (b.x2 - b.x1) * (b.y2 - b.y1) (it is 0 if the width or the height is 0; it is not the number of lattice points).
- The "bounding box" of a collection of boxes is (minimum of x1, minimum of y1, maximum of x2, maximum of y2). The bounding box of two boxes a and b is written MBR(a, b).
- The "enlargement" enl(a, b) when box b is added to box a is area(MBR(a, b)) - area(a).
- Boxes a and b "intersect" when a.x1 <= b.x2, b.x1 <= a.x2, a.y1 <= b.y2 and b.y1 <= a.y2 all hold (they intersect even if they only touch at an edge or a corner).
- Box a "contains" box b when a.x1 <= b.x1, b.x2 <= a.x2, a.y1 <= b.y1 and b.y2 <= a.y2 all hold. A point p "lies in" a box a when a contains the box of p.
- The "overlap area" ov(a, b) of boxes a and b is defined with w = min(a.x2, b.x2) - max(a.x1, b.x1) and h = min(a.y2, b.y2) - max(a.y1, b.y1): it is w * h if w > 0 and h > 0, and 0 otherwise.
- The "distance" d(q, p) between points q and p is (x_p - x_q) * (x_p - x_q) + (y_p - y_q) * (y_p - y_q) (this is the squared distance; no square roots are used).
- The "minimum distance" md(q, b) between a point q and a box b is dx * dx + dy * dy. Here dx is b.x1 - x_q if x_q < b.x1, x_q - b.x2 if x_q > b.x2, and 0 otherwise, and dy is defined in the same way for y. If q lies in b, then md(q, b) = 0.
- The "reduced fraction" of integers a >= 0, b > 0 is a'/b', where a' and b' are a and b divided by their greatest common divisor (e.g. 6 and 4 give 3/2, and 6 and 3 give 2/1). The denominator is not omitted even when it is 1.
- Tuples (a, b, ...) are compared lexicographically (compare the first values; if they are equal, compare the next values).
- floor(t) is the largest integer not greater than t. Every floor(...) used in this task is the quotient of a nonnegative integer divided by a positive integer, so it can be computed with integer division (truncation).

* 2. Structures
The following seven structures are used. Their names and this order (the "structure order") are also used in the output.
- Point structures: kdtree (k-d tree), quadtree (PR quadtree), rtree (R-tree built by successive insertion), str (R-tree built by the STR method), grid (uniform grid)
- Rectangle structures: rtree_rect (R-tree built by successive insertion), str_rect (R-tree built by the STR method)
kdtree is described in 3, quadtree in 4, rtree and rtree_rect in 5, str and str_rect in 6, and grid in 7. First, each structure is built from all the input points and all the input rectangles by the method of its section. The subsequent INSERT and DELETE commands are applied to all five point structures.

* 3. k-d tree (kdtree)
Each node holds one point and has a left child and a right child (either may be absent). The depth of the root is 0, and the depth of a child is the depth of its parent + 1. The "axis" of a node at an even depth is x, and the axis of a node at an odd depth is y.
The "key" key_a(p) of a point p for axis a is the tuple (x_p, y_p, ID of p) if a is x, and (y_p, x_p, ID of p) if a is y. Since IDs are distinct for each point, the keys of two different points always differ. For a node v with axis a, key_a of every point in the subtree rooted at v's left child (the "left subtree") is smaller than key_a of v's point, and key_a of every point in the right subtree is larger.
(1) Build: the procedure build(S, t), which builds a tree from a collection of points S and a depth t, is as follows. If S is empty, there is no tree (no node). Otherwise, let a be the axis of depth t, sort the points of S in increasing order of key_a, and make the root a node holding the point at position floor(|S| / 2) of that sequence (the first position is 0; |S| is the number of points). The tree built by build(..., t + 1) from the collection of the points before that point in the sequence becomes the left child, and the tree built from the collection of the points after it becomes the right child. kdtree is built by performing build(all points, 0) on all the input points.
(2) Insertion: to add a point p, start at the root and repeat the following, with a the axis of the current node v: go to the left child if key_a(p) < key_a(v's point), and to the right child otherwise. If the child to go to does not exist, attach a new node holding p there.
(3) Minimum point: among the points in the subtree rooted at a node v, the point with the smallest key_a is written min_a(v). min_a(v) is found as follows. If the axis of v is a, it is v's point if v has no left child, and min_a(left child) if v has one. If the axis of v is not a, it is the one with the smallest key_a among v's point, min_a(left child) and min_a(right child) (excluding those of absent children).
(4) Deletion: the procedure del(v, p), which removes a point p from the subtree rooted at a node v, returns the root of the subtree after the removal ("none" if nothing is left). Let a be the axis of v.
  - If v's point is p and v has a right child: let m = min_a(right child), replace v's point with m, and set the right child to the result of del(right child, m). The result is v.
  - If v's point is p and v has no right child but has a left child: let m = min_a(left child), replace v's point with m, set the right child to the result of del(left child, m), and set the left child to none. The result is v.
  - If v's point is p and v has no children: remove v. The result is none.
  - If v's point is not p and key_a(p) < key_a(v's point): set the left child to the result of del(left child, p). The result is v.
  - Otherwise: set the right child to the result of del(right child, p). The result is v.
  To delete a point, the result of del(root, p) becomes the new root. Even when points are replaced or subtrees are moved, the depth and the axis of each node do not change (in the second case, the left subtree moves as it is to the position of the right child, so its depth stays the same).
(5) Region: the region of the root is the box (0, 0, W - 1, W - 1). For a node with region (x1, y1, x2, y2) and axis a, let s be the axis-a coordinate of the node's point. The region of the left child is (x1, y1, s, y2) if a is x and (x1, y1, x2, s) if a is y, and the region of the right child is (s, y1, x2, y2) if a is x and (x1, s, x2, y2) if a is y. All the points of a subtree lie in the region of its root.

* 4. PR quadtree (quadtree)
Each node is responsible for a square (x0, y0, size). This is the set of all points (x, y) satisfying x0 <= x <= x0 + size - 1 and y0 <= y <= y0 + size - 1. The square of the root is (0, 0, W).
A node is either a leaf or an internal node. A leaf holds the points it is responsible for, in increasing order of ID (a leaf may hold 0 points). An internal node holds no points and has four children in the order NW, NE, SW, SE. With h = size / 2, xm = x0 + h and ym = y0 + h, the squares of the children are NW (x0, y0, h), NE (xm, y0, h), SW (x0, ym, h) and SE (xm, ym, h). The side with smaller y is north.
The "destination child" of a point p at an internal node is the child on the east side (NE or SE) if x_p >= xm and on the west side (NW or SW) otherwise, and, of those, the one on the south side (SW or SE) if y_p >= ym and on the north side (NW or NE) otherwise. Points on a split line go to the east side and the south side.
(1) Insertion: to add a point p, start at the root, go to the destination child at each internal node, and add p to the leaf reached (inserting it at its position in ID order). If the number of points in that leaf exceeds c, "split" the leaf. Splitting creates four children (leaves with no points), makes the node an internal node, and inserts the points it held one at a time, in increasing order of ID, starting from that node by the same procedure as (1). If the number of points in a child exceeds c, that child is also split in the same way. Since the coordinates of the points are distinct and c >= 1, splitting always terminates.
(2) Deletion: to delete a point p, remove p from the leaf that holds it. Then examine each internal node v from that leaf's parent up to the root, from the bottom up: if the four children of v are all leaves and the sum of their numbers of points is at most c, remove the four children and make v a leaf whose points are all of their points together, sorted in increasing order of ID ("merge"). Once a node cannot be merged, no node above it can be merged either, so you may stop there.
By these rules, the shape of the quadtree is determined only by the set of points at that moment. Exactly the nodes whose square holds more than c points are internal nodes, and all other nodes are leaves.

* 5. R-trees (rtree, rtree_rect, and insertion and deletion in str, str_rect)
Each node of an R-tree holds a sequence of "entries", and the order of that sequence is called the "entry order". Each node has a "level": a leaf has level 0, and an internal node has the level of its children + 1 (all leaves are at the same depth from the root).
- A leaf entry is (box, object ID). In the point trees (rtree, str) the object is a point and the box is the box of that point. In the rectangle trees (rtree_rect, str_rect) the object is a rectangle and the box is that rectangle.
- An internal node entry is (box, child node), and its box is always kept equal to box(child node). Here the box box(v) of a node v is the bounding box of the boxes of all entries of v.
A node other than the root normally has at least m and at most M entries (the root is exempt from this; also, str and str_rect may have nodes with fewer than m entries at the time they are built).
(1) Choosing a subtree: to put an entry with box b into a node of level e, start at the root and, while the level of the current node is greater than e, choose the entry of that node with the smallest enl(entry's box, b) (if equal, the one with the smallest area(entry's box); if that is also equal, the one earlier in entry order) and go to that entry's child. The node of level e that is reached is the node into which the entry is put.
(2) Insertion: to insert an entry E at level e, append E to the end of the entry sequence of the node chosen by (1), let N be that node, and repeat the following.
  - If N has more than M entries (it will have M + 1), split N by the split of (3) into N (group 1) and a new node NN (group 2) at the same level as N.
  - If N is not the root, set the box of the entry of N's parent P whose child is N to box(N). If N was split, also append (box(NN), NN) to the end of P's entry sequence. Then repeat with P as the new N.
  - If N is the root, stop. However, if N was split, first create a new root with level N's level + 1 whose entries are (box(N), N) and (box(NN), NN), in this order.
(3) Quadratic split: the M + 1 entries E_1, E_2, ..., E_(M+1) (in entry order) are divided into two groups as follows. Below, an entry's box is sometimes referred to simply as the entry.
  (i) Choosing the seeds: for every pair (i, j) with 1 <= i < j <= M + 1, compute w = area(MBR(E_i, E_j)) - area(E_i) - area(E_j), and choose the pair with the largest w (if equal, the pair with the smaller i; if that is also equal, the pair with the smaller j). Put E_i into group 1 and E_j into group 2, and let the remaining M - 1 entries, in their original order, be the "rest". Let the boxes B1 and B2 of the groups be the boxes of the entries put into them.
  (ii) Repeat the following until the rest is empty.
    - If the number of entries in group 1 plus the number of entries in the rest equals m, append all the entries of the rest, in order, to the end of group 1 and stop. Otherwise, if the same holds for group 2, append all the entries of the rest, in order, to the end of group 2 and stop.
    - For each entry E of the rest, let d1 = enl(B1, E) and d2 = enl(B2, E); choose the entry with the largest |d1 - d2| (if equal, the one that comes first in the rest) and remove it from the rest.
    - Append the chosen entry to the end of the group with the smaller of d1 and d2. If d1 = d2, add it to the group with the smaller of area(B1) and area(B2); if that is also equal, to the group with fewer entries; if that is also equal, to group 1. Set the box of the group it was added to to the bounding box of that box and the chosen entry.
  The entries of group 1, in the order in which they entered the group, become the entries of the original node, and the entries of group 2, ordered in the same way, become the entries of the new node.
(4) Deletion: to delete the point with ID p, do the following.
  (i) Find the leaf L that holds the entry of p. There is exactly one such leaf (it can be found, for example, by searching from the root, going into the children of the entries whose box contains the box of p).
  (ii) Remove the entry of p from L's entry sequence. The order of the other entries is not changed.
  (iii) Condense: let N be L, let the "list of removed nodes" Q be empty, and repeat the following while N is not the root. Let P be N's parent. If N has fewer than m entries, remove the entry whose child is N from P's entry sequence (without changing the order of the other entries) and append N to the end of Q. Otherwise, set the box of P's entry whose child is N to box(N). Then set N to P.
  (iv) Reinsert: take the nodes of Q in order from the front, and insert all the entries of each node, in entry order, by the insertion of (2), with level e equal to that node's level. Entries of internal nodes move together with their child subtrees as they are.
  (v) While the root is an internal node with exactly one entry, make the child of that entry the new root.
(5) Build: rtree is built by starting with a leaf with no entries as the root and inserting the entry of each point at level 0 in the order of the lines of points.csv. rtree_rect is built in the same way by inserting the entry of each rectangle in the order of the lines of rects.csv.

* 6. Bulk loading by the STR method (str, str_rect)
str is built from the entries of all points, and str_rect from the entries of all rectangles, by the following procedure. First, let the sequence E of entries to arrange be the sequence of leaf entries (box, ID), let the "number" of each entry be its ID, and let the level e be 0.
(i) Let n be the number of entries in E, P the smallest integer not less than n / M, and S the smallest positive integer satisfying S * S >= P.
(ii) Sort the entries of E in increasing order of (x1 + x2, y1 + y2, number) (x1 and so on are the values of the entry's box). Divide the sorted sequence from the front into groups of S * M entries (the last group may have fewer than S * M entries). Each group is called a "slab".
(iii) For each slab, in order from the front, sort the entries in the slab in increasing order of (y1 + y2, x1 + x2, number) and divide them from the front into groups of M entries (the last group may have fewer than M entries). Make each group a node of level e that holds those entries, in that order, as its entries. Number the created nodes 0, 1, 2, ... in the order in which they were created.
(iv) If exactly one node was created, make it the root and stop. Otherwise, let E be the entries (box(v), v) of the created nodes v in the order in which they were created, let the number of each entry be the number of its node, increase e by 1, and go back to (i).
For INSERT and DELETE after the build, str is also modified by the methods of 5 (2) to (4).

* 7. Uniform grid (grid)
Let G = W / g. The grid consists of G * G cells, and cell (i, j) (0 <= i < G is the column and 0 <= j < G is the row) is responsible for the points (x, y) satisfying i * g <= x <= i * g + g - 1 and j * g <= y <= j * g + g - 1. A point p belongs to cell (floor(x_p / g), floor(y_p / g)). Each cell holds the points that belong to it in increasing order of ID. For INSERT and DELETE, the point is added to, or removed from, the sequence of its cell.
For searching, the grid is regarded as a tree of height 2 consisting of a root called the "directory" and its children, the G * G cells.

* 8. A common view of nodes
For the searches of 9, the "region" (a box), the "held objects", the "child list" and the "count" of the nodes of each structure are defined as follows.
- kdtree: the region is the one of 3 (5). The held object is the node's single point. The child list is the left child followed by the right child (absent children are not included). The count is the number of points in the subtree rooted at the node.
- quadtree: the region of a node with square (x0, y0, size) is (x0, y0, x0 + size - 1, y0 + size - 1). The held objects are the points of the leaf (in ID order) for a leaf, and there are none for an internal node. The child list is the four children in the order NW, NE, SW, SE for an internal node, and empty for a leaf. The count is the number of current points that lie in the square.
- rtree, str, rtree_rect, str_rect: the region of a node v is box(v). The held objects are the objects of its entries (points or rectangles, in entry order) for a leaf, and there are none for an internal node. The child list is the children of its entries (in entry order) for an internal node, and empty for a leaf. The count is the sum of the numbers of entries of all leaves in the subtree rooted at the node.
- grid: the region of the directory is (0, 0, W - 1, W - 1), it holds no objects, and its child list is all the cells ordered by increasing row j and, within the same row, by increasing column i. The count of the directory is the number of current points. The region of cell (i, j) is (i * g, j * g, i * g + g - 1, j * g + g - 1), its held objects are the points of the cell (in ID order), its child list is empty, and its count is the number of points in the cell.

* 9. Searches
In a search in each structure, the "node count" (the number of nodes examined) and the "test count" (the number of objects whose condition was tested) are counted. Both start at 0.
(1) Search by conditions (RANGE, RADIUS, CONTAINS): using a "region condition" and an "object condition", perform the following procedure visit on the root. The root is always examined, regardless of the conditions.
  visit(v): increase the node count by 1, increase the test count by the number of objects v holds, and add to the answer the IDs of the objects held by v that satisfy the object condition. Then, for each child u in v's child list, in order, perform visit(u) if u's region satisfies the region condition.
  The answer is sorted in increasing order of ID. The conditions of each command are as follows.
  - RANGE x1 y1 x2 y2: let B = (x1, y1, x2, y2). The region condition is "the region intersects B", and the object condition is "the point lies in B".
  - RADIUS x y r: let q = (x, y). The region condition is "md(q, region) <= r * r", and the object condition is "d(q, point) <= r * r".
  - CONTAINS x y: let Q = (x, y, x, y). The region condition is "the region contains Q", and the object condition is "the rectangle contains Q" (the point (x, y) lies in the rectangle).
(2) Count in a window (WINDOWCOUNT x1 y1 x2 y2): let B = (x1, y1, x2, y2), let the answer (a count) be 0, and perform the following procedure count on the root.
  count(v): increase the node count by 1. If B contains v's region, add v's count to the answer and stop (v's held objects are not tested and its children are not examined). Otherwise, increase the test count by the number of objects v holds, and add to the answer the number of held objects that are points lying in B. Then, for each child u in v's child list, in order, perform count(u) if u's region intersects B.
(3) Best-first search (KNN x y k, NEAREST x y k): let q = (x, y). The "distance" of an object is d(q, p) for a point p and md(q, R) for a rectangle R. A priority queue is used, into which "node elements" and "object elements" are put. The key of the element of a node v is (md(q, v's region), 0, serial number), and the key of an object element is (object's distance, 1, object's ID). Serial numbers are assigned 0, 1, 2, ... in the order in which node elements are put in, separately for each search in each structure. Keys are compared lexicographically, and the element with the smallest key is taken out of the queue (all keys are distinct, so the order of removal is uniquely determined).
  First, put in the element of the root (serial number 0). Then repeatedly take out the smallest element and do the following.
  - If it is an object element, append (object's ID, object's distance) to the end of the answer. As soon as the answer has k items, stop.
  - If it is the element of a node v, increase the node count by 1, put in all the objects held by v (in held-object order) as object elements, and increase the test count by their number. Then put in each child in v's child list, in order, as a node element.
  Because of the second value of the key, when the distances are equal a node element is taken out before an object element. Therefore the answer is in increasing order of (distance, ID), and it matches the first k items when all objects are sorted in increasing order of (distance, ID).
(4) Spatial join (JOIN): for each of the pairs of a point tree and a rectangle tree, (rtree, rtree_rect) and (str, str_rect), perform the following procedure join(A, B) starting from the root A of the point tree and the root B of the rectangle tree (the pair of roots is always examined).
  join(A, B): increase the node count by 1 and do one of the following.
  - If A and B are both leaves: increase the test count by (number of entries of A) * (number of entries of B), and, among the pairs of the point p of an entry of A and the rectangle R of an entry of B, add the pair (ID of R, ID of p) to the answer for each pair in which p lies in R.
  - If A is a leaf and B is an internal node: examine the entries of B in order, and perform join(A, entry's child) for those whose box intersects box(A).
  - If A is an internal node and B is a leaf: examine the entries of A in order, and perform join(entry's child, B) for those whose box intersects box(B).
  - If A and B are both internal nodes: for each entry a of A in order, and for each entry b of B in order, perform join(child of a, child of b) for those in which the box of a and the box of b intersect.
  The pairs of the answer are sorted in increasing order of (ID of the rectangle, ID of the point).
(5) Cross-check: for each search, the answer is also found by brute force. The brute-force answer is: for RANGE, RADIUS and CONTAINS, the IDs of all the current points (or all the rectangles) that satisfy the object condition, in increasing order; for WINDOWCOUNT, the number of current points that lie in B; for KNN, the sequence of (ID, distance) of the first k points when all current points are sorted in increasing order of (d(q, p), ID); for NEAREST, the sequence of (ID, distance) of the first k rectangles when all rectangles are sorted in increasing order of (md(q, R), ID); and for JOIN, all pairs (ID of R, ID of p) in which p lies in R, in increasing order. The answer that is output is the brute-force answer. Compare the answer of each structure with the brute-force answer, and if any structure differs, report the name of that structure in the output (with a correct implementation they always match).

* 10. Processing the commands
First, build each structure as described in 2 and record that state as "snapshot 0" (see 11 and the description of the output files). Then process the commands one at a time in order of command number.
- RANGE, RADIUS, KNN, WINDOWCOUNT: perform the search of 9 in each of the five point structures.
- CONTAINS, NEAREST: perform the search of 9 in each of rtree_rect and str_rect.
- JOIN: perform 9 (4). In the output, the search of the pair (rtree, rtree_rect) is denoted by the structure name rtree, and the search of the pair (str, str_rect) by the structure name str.
- LOCATE id: if there is no current point with ID id, the answer is "not present". Otherwise, find the position of that point in each structure as follows.
  - kdtree: starting at the root, go to children using the same comparison as in 3 (2) until reaching the node that holds the point; the position is the string formed by writing L for each move to a left child and R for each move to a right child. If the point is at the root, it is -.
  - quadtree: starting at the root, go to destination children until reaching the leaf that holds the point; the position is the names (NW, NE, SW, SE) of the children moved to, joined with /. If the root is a leaf, it is -.
  - rtree, str: from the root down to the leaf that holds the point's entry, list the position of the entry followed at each node (in entry order, the first being 1), add at the end the position of the point's entry within the leaf, and join them with /.
  - grid: the column i and the row j of the point's cell.
- INSERT id x y: add the point with ID id and coordinates (x, y) to all five point structures (kdtree by 3 (2), quadtree by 4 (1), rtree and str by 5 (2) at level 0, and grid by 7).
- DELETE id: if there is a current point with ID id, delete it from all five point structures (kdtree by 3 (4), quadtree by 4 (2), rtree and str by 5 (4), and grid by 7). Otherwise, do nothing.
- DUMP: record the state at that moment as the snapshot with the next number (in the order 1, 2, ...).

* 11. Statistics
For each snapshot, compute the following values for each structure as it was at that moment.
(1) kdtree: the height H (the maximum depth of a node + 1), the ideal height I (the smallest integer I >= 0 satisfying 2^I - 1 >= the number of nodes), the number of nodes, the number of leaves (nodes without children), the number of nodes with exactly one child, the sum D of the depths of all nodes, and the reduced fraction of D and the number of nodes (the average depth). In addition, for each depth t = 0, 1, ..., H - 1: the number of nodes at depth t, the number of leaves among them, and the number of those with exactly one child.
(2) quadtree: the height H (the maximum depth of a node + 1, with the root at depth 0), the number of internal nodes, the number of leaves L, the number of leaves without points, the maximum number of points in a leaf, and the reduced fraction of the number of current points and L * c (the fill ratio). In addition, for each depth t = 0, 1, ..., H - 1: the number of internal nodes at depth t, the number of leaves, and the sum of the numbers of points in the leaves at depth t.
(3) rtree, str, rtree_rect, str_rect: the height H (the level of the root + 1), the number of nodes N, the number of leaves, the sum E of the numbers of entries of all nodes, and the reduced fraction of E and N * M (the fill ratio). In addition, for each level e = H - 1, H - 2, ..., 0: the number of nodes at level e, the sum of their numbers of entries, the minimum and the maximum number of entries, the number of nodes with fewer than m entries (the root included), the sum of area(box(v)) over all nodes v at level e, and the sum of ov(box(u), box(v)) over all ways of choosing two distinct nodes u, v at level e (a choice and the one with u and v swapped are the same choice and are counted only once) (the overlap area).
(4) grid: the number of cells G * G, the number of cells with points, the maximum number of points in a cell, and, for each number of points k, the number of cells with exactly k points.

[Output files]
Write five files: output/answers.txt, output/visits.csv, output/join.csv, output/structures.txt and output/stats.txt.

* Common rules
- The output consists of ASCII characters only, and every line (including the last line) ends with a line feed (LF). Do not put spaces at the end of a line, and do not insert empty lines unless specified. The only spaces at the beginning of a line are the indentation (spaces) shown in the formats.
- In the formats below, each part enclosed in < > is replaced by a value, and all other characters are written as they are. Values are separated by commas in the CSV files and by a single space in the other files. "<...> ..." means a sequence of values of the same kind separated by single spaces.
- Integers are written in decimal without extra leading zeros. Negative numbers do not appear.
- When a sequence of IDs is empty, write - in place of the sequence.

* output/answers.txt
Write one line per command, in order of command number. <q> is the command number.
- RANGE, RADIUS, CONTAINS: <q> <command name> count <number of answers> ids <ID> ... check <check result>
  The IDs are the answer (in increasing order of ID).
- KNN, NEAREST: <q> <command name> count <k> ids <ID>:<distance> ... check <check result>
  In the order of the answer, list the ID and the distance joined by a colon.
- WINDOWCOUNT: <q> WINDOWCOUNT count <answer count> check <check result>
- JOIN: <q> JOIN count <number of answer pairs> check <check result>
  The pairs themselves are written to output/join.csv.
- LOCATE: <q> LOCATE <id> kdtree <position in kdtree> quadtree <position in quadtree> rtree <position in rtree> str <position in str> grid <i> <j>
  When the point is not present, write <q> LOCATE <id> missing.
- INSERT: <q> INSERT <id> inserted points <number of current points after the insertion>
- DELETE: when the point was deleted, write <q> DELETE <id> deleted points <number of current points after the deletion>; when the point was not present, write <q> DELETE <id> missing points <number of current points>.

[Source files]
Split the program into the following seven source files (file names follow the conventions of each language).
- main: handles the overall flow and most of the processing. It reads the input and calls the building of each structure, and performs the common view of nodes of 8 (the region, held objects, child list and count for each structure), the searches of 9 (search by conditions, count in a window, best-first search, spatial join, the brute-force answers and the cross-check), the command processing of 10 (applying insertions and deletions to each structure, computing the LOCATE positions, recording snapshots), the tree dumps, the statistics of 11, aggregating and ranking the node counts and test counts, and assembling the contents of the five output files.
- dataset: reads the four input files and returns the points, the rectangles, the parameter values and the sequence of commands.
- kdtree: handles k-d tree nodes, key comparison, building, insertion, the minimum point and deletion.
- quadtree: handles quadtree nodes, choosing the destination child, insertion and splitting, and deletion and merging.
- rtree: handles R-tree nodes and entries, the computation of areas, bounding boxes, enlargement and containment, choosing a subtree, insertion, the quadratic split, deletion (finding the leaf, condensing, reinsertion, replacing the root), and bulk loading by the STR method.
- grid: handles creating the grid cells and adding and removing points.
- report: handles formatting reduced fractions and ID sequences, and writing sequences of lines to files.

[Constraints]
- The number of points is always between 1 and 2000 inclusive, even during command processing; the number of rectangles is between 1 and 1000 inclusive, and the number of commands is between 1 and 1000 inclusive.
- W is a power of 2 between 2 and 4096 inclusive, 1 <= c <= 64, 4 <= M <= 64, 2 <= m <= M / 2, 1 <= g <= W, and W / g <= 64. Point IDs and rectangle IDs are between 1 and 99999 inclusive.
- The coordinates of the current points are always distinct. The id of INSERT differs from every ID of the current points (it may be the ID of a previously deleted point), and its coordinates differ from the coordinates of every current point. The id of DELETE and LOCATE may be absent from the current points.
- r of RADIUS is between 0 and 2 * W inclusive, k of KNN is between 1 and the number of current points inclusive, and k of NEAREST is between 1 and the number of rectangles inclusive.
- The given data has 480 points, 120 rectangles and 167 commands, with W = 1024, c = 4, M = 8, m = 3 and g = 64.
- Distances and minimum distances are at most 2 * (W - 1) * (W - 1), and areas are at most (W - 1) * (W - 1). In the given data, every integer that appears in the calculations, including the sums of areas and the overlap areas, is less than 2^31.
- The input files correctly follow the formats above. There is no need to check for input errors.
- The brute-force computations (for JOIN, all pairs of the current points and all rectangles; about 60,000 pairs in the given data) may be done directly.
