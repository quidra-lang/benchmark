[Overview]
Write a program that uses the k-nearest-neighbor method to predict, for each row of tabular data, its label (class) and its target value (a real number), and that selects models systematically. A model is a combination of a value of k, a distance metric, a vote weighting and a feature scaling method. A grid search with stratified cross-validation selects the "selected classifier", which predicts labels best, and the "selected regressor", which predicts target values best. In addition, the program performs leave-one-out cross-validation, nested cross-validation, McNemar tests, feature selection by backward elimination, a learning curve and a tally per confidence bin, and predicts and evaluates the test data. Finally, it builds and evaluates prototype sets (training rows used for reference) by Wilson editing and Hart condensing, and examines rows on class borders and hubs (rows that often appear as neighbors).
The input is three files in the input/ folder (training data, test data, settings), and the results are written to five files in the output/ folder. Nothing is written to standard output. No random numbers are used. The only operations used in the computation are the four arithmetic operations, square root, absolute value, maximum and minimum; since every rule is fully specified, the result is uniquely determined.

[Input files]
There are three input files: input/train.csv, input/test.csv and input/params.txt. Every file consists of ASCII characters only, and every line (including the last line) ends with a newline (LF). There is no whitespace at the start or end of a line. Values are separated by a single comma in train.csv and test.csv, and by a single space in params.txt.
A decimal number is a base-10 number consisting of, in this order, "-" (only for negative numbers), a sequence of one or more digits (the integer part), ".", and a sequence of one or more digits (the fractional part) (examples: 107.070, 0.6, -3.25). An integer is a base-10 number without extra leading zeros.

* input/train.csv (training data)
The first line is a header line listing id, d feature names, label and target in this order, separated by commas (example: id,moisture,density,label,target). A feature name is a string of 1 to 16 characters consisting of lowercase English letters and "_"; the feature names are distinct from each other and differ from each of id, label and target. The features are called feature 1, feature 2, ..., feature d in the order they appear in the header line, and this order is called the "feature order".
Each line from the second line on is one "training row", listing the ID, the d feature values, the label and the target value in this order, separated by commas.
- An ID is a string of 1 to 8 characters consisting of uppercase English letters and digits. The IDs of all rows of train.csv and test.csv are distinct from each other.
- The feature values and the target value are decimal numbers.
- A label is a string of 1 to 16 lowercase English letters.
Let n be the number of training rows. The order of the rows in the file is called the "row order". The rows are not necessarily sorted by ID. The set of all labels that appear in the training rows is called the "label set".

* input/test.csv (test data)
The first line is a header line, exactly the same string as the header line of train.csv. Each line from the second line on is one "test row", in the same format as train.csv. However, the label and the target value may be empty (nothing between two commas, or between the last comma and the end of the line). A row whose label and target value are both empty ends with ",,". A non-empty label is always contained in the label set.
The order of the rows in the file is called the "test row order". A test row with a non-empty label is called a "labelled test row", and a test row with a non-empty target value is called a "test row with a target".

* input/params.txt (settings)
It consists of the following 9 lines, in this order. Each line is a keyword followed by one or more values.
- SCALINGS s_1 s_2 ...: the list of scaling methods (1 or 2 distinct values out of standard and minmax, in any order). The order of this list is called the "scaling order".
- K_VALUES k_1 k_2 ...: the list of values of k (distinct positive integers, in increasing order). The order of this list is called the "k order".
- METRICS m_1 m_2 ...: the list of distance metrics (1 to 4 distinct values out of squared_euclidean, manhattan, chebyshev and cosine, in any order). The order of this list is called the "metric order".
- WEIGHTINGS w_1 w_2 ...: the list of vote weightings (1 or 2 distinct values out of uniform and distance, in any order). The order of this list is called the "weighting order".
- FOLDS F: the number of folds of cross-validation (an integer >= 2).
- EDIT_K E: the number of neighbors used in Wilson editing (a positive integer).
- CURVE c_1 c_2 ...: the list of numbers of rows per label used for the learning curve (distinct positive integers, in increasing order).
- BINS b_1 b_2 ...: the list of boundaries of the confidence bins (decimal numbers greater than 0 and less than 1, with 1 or 2 digits in the fractional part; at least one value, in increasing order).
- TOP T: the number of entries in the top lists (a positive integer).

[Processing]
* 1. Notation and computation rules
- The order of strings (label order, ID order) is the lexicographic order by ASCII character code (compare one character at a time from the start; the string whose first differing character has the smaller code comes first; if one string is a prefix of the other, the shorter one comes first). The "label order" is the label set sorted in this order, and the "ID order" is the IDs sorted in this order.
- sqrt is the square root and |t| is the absolute value of t. max and min are the maximum and the minimum. t^2 means t * t, and 2^31 is 2 to the power of 31.
- SUM (written in place of the summation sign) denotes the sum obtained by adding the elements one at a time from the start, in the order of the indicated sequence. A sum for which no sequence is indicated is added in the order of the elements of the expression written here (row order for rows, neighbor order for neighbors, feature order for features). The initial value of a sum is 0.
- The "4-decimal value" of a real number v is v rounded to 4 decimal places (the same value as written to the output files). Some comparisons are made on 4-decimal values; whenever that is the case, it is stated explicitly.
- Every rule that selects a maximum or minimum and every sorting rule always comes with the treatment of equal values.
- Unless stated otherwise, a "sequence" of rows keeps the row order. A sequence obtained by removing some rows from a sequence of rows also keeps the remaining rows in row order.

* 2. Scaling (standardization and normalization of features)
There are two feature scaling methods: standard and minmax.
(1) Computing the scaling: from a sequence L of training rows (N rows), compute the center m_j and the scale s_j of each feature j according to the scaling method. x_j denotes the value of feature j in each row of L, and sums are added in the order of the sequence L.
- standard: m_j = (SUM x_j) / N, s_j = sqrt((SUM (x_j - m_j) * (x_j - m_j)) / (N - 1)) (the sample standard deviation computed in two passes). When N = 1, s_j = 0.
- minmax: m_j = (the minimum of x_j), s_j = (the maximum of x_j) - (the minimum of x_j).
(2) Transforming with the scaling: the value x_j of feature j of a row (a training row or a test row) is transformed to z_j = (x_j - m_j) / s_j if s_j > 0, and to z_j = 0 if s_j = 0.
(3) Used features: unless stated otherwise, all features are used. In the feature selection of section 12, only some of the features (the "used features") are used. In every case, only the transformed values of the used features, arranged in feature order (a vector), are used for the distance computation. Since the scaling is computed per feature, m_j and s_j of the used features do not change even if some features are not used.

* 3. Distance
For two transformed vectors a = (a_1, ..., a_p) and b = (b_1, ..., b_p) (p is the number of used features; sums are added in feature order), the distance dist(a, b) for each metric is as follows.
- squared_euclidean: SUM (a_j - b_j) * (a_j - b_j) (no square root is taken)
- manhattan: SUM |a_j - b_j|
- chebyshev: the maximum of |a_j - b_j| (j = 1, ..., p)
- cosine: let dot = SUM a_j * b_j, na = sqrt(SUM a_j * a_j), nb = sqrt(SUM b_j * b_j); the distance is 1 if na = 0 or nb = 0, and otherwise 1 - dot / (na * nb) (compute na * nb first, then divide dot by it).

* 4. Neighbors, voting, estimation
(1) Neighbor order: for a row q and a set R of training rows used for reference, compute the distance d(r) between q and each row r of R; the rows of R sorted by d(r) in increasing order (ties by ID order) are called the "neighbor order of q". For a positive integer k, the first k' = min(k, |R|) rows of the neighbor order are called the "k nearest neighbors of q" (|R| is the number of rows of R).
(2) Voting: for each row r of the k nearest neighbors, the weight is w(r) = 1 / (d(r) + 0.000000001). For each label c that appears in the k nearest neighbors, compute the following three values by going through the k nearest neighbors in neighbor order.
- cnt(c): the number of rows whose label is c
- dsum(c): the sum of d(r) over the rows whose label is c
- wsum(c): the sum of w(r) over the rows whose label is c
Also, let wtotal be the sum of w(r) over all rows of the k nearest neighbors (in neighbor order). The labels that appear in the k nearest neighbors, sorted with the following priority depending on the weighting, are called the "vote order".
- uniform: cnt(c) in decreasing order, ties by dsum(c) in increasing order, further ties by label order. The vote share of label c is cnt(c) / k'.
- distance: wsum(c) in decreasing order, ties by dsum(c) in increasing order, further ties by label order. The vote share of label c is wsum(c) / wtotal.
The first label of the vote order is called the "predicted label", and its vote share the "vote share". The second label of the vote order is called the "runner-up label", and its vote share the "runner-up vote share". When only one label appears in the k nearest neighbors, there is no runner-up label and the runner-up vote share is 0.
(3) Estimation: let t(r) be the target value of a row of the k nearest neighbors; the estimate is computed as follows (sums in neighbor order).
- uniform: (SUM t(r)) / k'
- distance: (SUM w(r) * t(r)) / (SUM w(r))
(4) Models and prediction: a "model" is a combination of four items: the value of k, the metric, the weighting and the scaling method. The "notation" of a model is k=<k> metric=<metric> weighting=<weighting> scaling=<scaling method> (example: k=13 metric=manhattan weighting=uniform scaling=standard).
"Predicting a row q (a training row not contained in L, or a test row) with a model on a sequence L of training rows" means computing the predicted label, the vote share, the runner-up label, the runner-up vote share and the estimate by the following procedure.
1. Compute the scaling from L with the model's scaling method (section 2 (1); sums in the order of the sequence L).
2. Transform each row of L and q with that scaling.
3. With the model's metric, find the k nearest neighbors of q with L as the reference set (k is the model's k).
4. From the k nearest neighbors, vote and estimate with the model's weighting.
In this prediction, the predicted label being equal to the label of q is called "correct".
The neighbor order depends only on L, q, the scaling method, the metric and the used features, and not on k or the weighting. When predicting the same row with many models that differ only in k or weighting, the neighbor order can be computed once and reused.

* 5. Stratified split
To split a sequence S of training rows into F folds, sort the rows of S by label order, and within the same label by ID order. Put the i-th row (i = 0, 1, 2, ...) of this sorted sequence into fold (i mod F) + 1 (i mod F is the remainder of i divided by F; i is not reset to 0 when the label changes).
For a fold f (f = 1, ..., F), the rows of fold f are called the "validation rows", and the sequence obtained by removing the rows of fold f from S is called the "training rows of fold f".

* 6. Cross-validation and grid search
(1) Cross-validation: performing cross-validation of a model M on a sequence S of training rows means splitting S into F folds by the rule of section 5 and, for each fold f, predicting each validation row of fold f with M on the training rows of fold f. Each row of S is predicted exactly once. This prediction is called the "cross-validation prediction" of that row.
- Correct count: the number of rows of S whose cross-validation prediction is correct
- RMSE: sqrt((SUM (estimate - target) * (estimate - target)) / |S|). The sum is added in the order of the sequence S, using the estimate of each row's cross-validation prediction and that row's target value.
(2) Grid: the models of all combinations of each k in k order, each metric in metric order, each weighting in weighting order and each scaling method in scaling order, arranged in nested order with k outermost and the scaling method innermost, are called the "grid", and this order the "grid order". The number of models is the grid size G = (number of k values) * (number of metrics) * (number of weightings) * (number of scaling methods).
(3) Grid search: on the sequence of all training rows (in row order), perform cross-validation of every model of the grid and compute the correct count and the RMSE of each model. These are called the "cross-validation results".
(4) Model selection: from a collection of models, select as follows.
- Best classifier: the model with the largest correct count (ties: the one earlier in grid order)
- Best regressor: the model with the smallest 4-decimal value of RMSE (ties: the one earlier in grid order)
The best classifier over the whole grid is called the "selected classifier", and the best regressor the "selected regressor".
(5) Top lists: the models of the grid sorted by correct count in decreasing order (ties by grid order) are called the "accuracy ranking", and sorted by the 4-decimal value of RMSE in increasing order (ties by grid order) the "RMSE ranking".
(6) Best per item: for each k in k order, find the best classifier and the best regressor among only the models whose k has that value. Do the same for the metric (metric order), the weighting (weighting order) and the scaling method (scaling order).

* 7. Classification evaluation
For a sequence of pairs (true label, predicted label), compute the following. Both the true label and the predicted label are contained in the label set.
- Confusion matrix: for each label a (row) and each label b (column) in label order, C[a][b] is the number of pairs whose true label is a and whose predicted label is b.
- For a label c, let TP = C[c][c], P = (the sum of column c; the number of pairs whose predicted label is c), A = (the sum of row c; the number of pairs whose true label is c); precision = TP / P, recall = TP / A, F1 = (2 * TP) / (P + A). A is called the "support".
- When the denominator of a metric is 0, that metric has no value.
- Macro average: for each of precision, recall and F1, the values (numerator divided by denominator, as a real number) of the labels that have a value, added in label order and divided by the number of labels that have a value. If no label has a value, the macro average has no value.

* 8. Confidence bins
From the BINS boundaries, form m + 1 bins [0, b_1), [b_1, b_2), ..., [b_(m-1), b_m), [b_m, infinity) (m is the number of boundaries). The lower bounds of the bins are 0, b_1, ..., b_m respectively.
For a sequence of pairs (prediction, true label), put each pair into the bin for which the vote share v of the prediction satisfies "lower bound <= v < upper bound". For each bin, compute the number of pairs, the number of pairs whose predicted label equals the true label (the correct count), and the mean vote share (the vote shares of the pairs in the bin, added in the order of the sequence of pairs and divided by the number of pairs).

* 9. McNemar test
For each metric m in metric order, the best classifier (section 6 (4)) among only the models whose metric is m is called the "comparison model", and it is compared with the selected classifier using the cross-validation predictions.
- b: the number of training rows for which the cross-validation prediction of the selected classifier is correct and the cross-validation prediction of the comparison model is not correct
- c: the number of training rows for which the cross-validation prediction of the comparison model is correct and the cross-validation prediction of the selected classifier is not correct
- Statistic: with numerator u = (max(0, |b - c| - 1))^2 and denominator b + c, the statistic is u / (b + c). When b + c = 0, the statistic is 0.
- Significance: significant (yes) when 1000 * u > 3841 * (b + c), otherwise not significant (no) (this decides exactly, with integers, whether the statistic exceeds 3.841).
The comparison model may be the selected classifier itself (in which case b = c = 0).

* 10. Leave-one-out cross-validation
(1) Selected classifier: for each training row r, predict r with the selected classifier on the sequence obtained by removing r from the sequence of all training rows. This prediction is called the "leave-one-out prediction" of r. The training rows whose prediction is not correct are the "leave-one-out errors".
(2) Selected regressor: similarly, for each training row r, predict r with the selected regressor on the sequence with r removed, and call its estimate the "leave-one-out estimate" of r. The residual is (leave-one-out estimate) - (target value).
- RMSE: sqrt((SUM residual * residual) / n), MAE: (SUM |residual|) / n (sums in row order)
- Largest residuals: the training rows sorted by the 4-decimal value of |residual| in decreasing order (ties by ID order).
(3) Leave-one-out per k: with the models consisting of the selected classifier's metric, weighting and scaling method and each k in k order, perform the same leave-one-out prediction as in (1), and compute the correct count and the RMSE with the same formula as in (2) (using this model's estimates).

* 11. Nested cross-validation
Split the sequence of all training rows into F folds by the rule of section 5 (these are called the "outer folds"; they are the same as the cross-validation folds of section 6). For each outer fold f (f = 1, ..., F), do the following.
1. Let L be the sequence of the training rows of fold f.
2. On L, perform cross-validation of every model of the grid (L is split again into F folds by the rule of section 5; the correct count and the RMSE are computed over the rows of L).
3. From these results, select the best classifier (the "inner classifier") and the best regressor (the "inner regressor") by the same rules as section 6 (4). The "inner accuracy" of the inner classifier is (its correct count) / |L|, and the "inner RMSE" of the inner regressor is its RMSE.
4. On L, predict each validation row of fold f with the inner classifier and compute the correct count (the "outer correct count"). Also, on L, predict each validation row of fold f with the inner regressor, and call its estimate the "nested estimate" of each validation row. The outer RMSE is sqrt((SUM (nested estimate - target)^2) / (number of validation rows)) over the validation rows of fold f (in row order).
Finally, compute the nested accuracy = (sum of the outer correct counts) / n and the nested RMSE = sqrt((SUM (nested estimate - target)^2) / n) (the sum is over all training rows in row order).

* 12. Feature selection (backward elimination)
Keep the model of the selected classifier fixed and perform cross-validation while varying the set S of used features (arranged in feature order). The cross-validation correct count for S is the correct count obtained by cross-validation of the selected classifier on the sequence of all training rows with S as the used features (section 2 (3)).
1. Let S be all features. This is called the "starting set".
2. While S has 3 or more features, repeat the following "step". For each feature j of S (in feature order), compute the cross-validation correct count for the set obtained by removing j from S (the "candidate correct count"). Remove from S the j with the largest candidate correct count (ties: the one earlier in feature order).
3. Among the starting set and the set S after removing j in each step, the one with the largest cross-validation correct count (for the starting set, the correct count of the selected classifier in the grid search; for each step, the candidate correct count of the removed j) is the "selected features". If there are ties, choose the one with fewer features (the one from the later step).
4. On the sequence of all training rows, with the selected features as the used features, predict each labelled test row with the selected classifier and compute the correct count.
When there are 2 or fewer features, no step is performed, and the starting set is the selected features.

* 13. Prediction and evaluation of the test data
On the sequence of all training rows, predict every test row with the selected classifier, and obtain its predicted label, vote share, runner-up label and runner-up vote share. Also, on the sequence of all training rows, predict every test row with the selected regressor, and obtain its estimate.
(1) Classification: for the labelled test rows (in test row order), compute the correct count and, on the sequence of pairs (true label, predicted label), the evaluation of section 7 and the tally of section 8.
(2) Prediction margin: for every test row, let margin = (vote share) - (runner-up vote share). The test rows sorted by the 4-decimal value of the margin in increasing order (ties by test row order) are called the "uncertainty order".
(3) Regression: for the pairs of estimate and target value of the test rows with a target (in test row order), let error = (estimate) - (target value), and compute RMSE = sqrt((SUM error * error) / N), MAE = (SUM |error|) / N, R^2 = 1 - (SUM error * error) / (SUM (target - mean) * (target - mean)). N is the number of test rows with a target, mean = (SUM target) / N, and all sums are in test row order. Also, for each label c in label order, compute the RMSE over only the test rows with a target whose label is c (if there is no such row, it has no value).
(4) Misclassification: for the labelled test rows whose prediction is not correct (in test row order), list the k nearest neighbors under the selected classifier (with all training rows as the reference set, transformed with the scaling computed from the sequence of all training rows) in neighbor order.

* 14. Learning curve
For each value c of CURVE, build the sequence (keeping row order) obtained by selecting, for each label, the first c rows of that label in row order (all rows of that label if it has fewer than c rows), predict each labelled test row with the selected classifier on that sequence, and compute the correct count. Also, on the same sequence, predict each test row with a target with the selected regressor, and compute the RMSE with the same formula as section 13 (3).

* 15. Prototype selection
In this section, the scaling computed from the sequence of all training rows with the selected classifier's scaling method is used fixed (even when a partial set of rows is used for reference, the scaling is not recomputed). Distances are computed with all features using the selected classifier's metric, and the selected classifier's weighting is used. This is called the "classifier space". The neighbor order of a row q within a set R of rows is determined by distances in the classifier space.
(1) Wilson editing: the "editing set" initially consists of all training rows (in ID order). Repeat the following "pass".
- For each row r of the editing set (in ID order), vote with the E' nearest neighbors of r (E' = min(E, (number of rows in the editing set) - 1)), using the editing set with r removed as the reference set; if the predicted label differs from the label of r, r is a "row to remove".
- After all rows have been examined, remove all rows to remove from the editing set at once (the editing set does not change during a pass).
- Stop after a pass in which there was no row to remove. The final editing set is called the "edited set".
(2) Hart condensing: to condense a set X of rows (arranged in ID order), let the "store set" be the set consisting only of the first row of X (the first in ID order), and repeat the following "scan".
- For each row r of X (in ID order), if r is not contained in the store set, look at the label of the first row of the neighbor order of r with the store set as the reference set; if it differs from the label of r, add r to the store set immediately (the added row is also used for the decisions on the later rows of the same scan).
- Stop after a scan that added no row. The number of scans includes this last scan. The final store set is the result of condensing.
(3) Prototype sets: handle the following four sets in this order.
- original: all training rows
- edited: the edited set
- condensed: the result of condensing all training rows
- edited_condensed: the result of condensing the edited set
For each set P, compute, over the labelled test rows, the correct count of the predicted label obtained by voting with the k' nearest neighbors with P as the reference set (k' = min(k, |P|), where k is the selected classifier's k) (knn), and the correct count of the 1-nearest-neighbor predicted label (the label of the first row of the neighbor order) (1nn).
(4) Border rows: for each label c in label order, and for each training row r whose label is c (in ID order), find the neighbor order of r with all training rows except r as the reference set; the distance of the first row in it whose label is c is the "same-class distance", and the distance of the first row in it whose label is not c is the "other-class distance". When the label of the first row of the neighbor order is not c, r is a "border row". For label c, compute the number of border rows, the mean same-class distance and the mean other-class distance (both added in ID order and divided by the number of training rows whose label is c).
(5) Hubs: for the k nearest neighbors obtained when predicting each test row (all test rows) with the selected classifier in section 13 (the scaling of section 13 is the same as the scaling of the classifier space), count for each training row the number of test rows in whose k nearest neighbors it appears (the occurrence count). The training rows sorted by occurrence count in decreasing order (ties by ID order) are called the "hub order", and the number of training rows with occurrence count 0 is called the "anti-hub count".

[Output files]
Write five files: output/cv_grid.csv, output/predictions.csv, output/metrics.txt, output/learning_curve.csv and output/prototypes.txt.

* Common rules
- The output consists of ASCII characters only, and every line (including the last line) ends with a newline (LF). Do not put extra whitespace at the start or end of a line, and do not insert blank lines that are not specified.
- In the formats below, each part enclosed in < > is replaced by a value, and all other characters are written as they are. Values are separated by a single space (a single comma in .csv files). A notation like "<...> ..." means values of the same kind listed with one separator between each pair.
- Integers are written in base 10 without extra leading zeros.
- Unless specified otherwise, a real number is rounded to 4 decimal places and written in fixed-point notation with exactly 4 digits after the decimal point (examples: 12.5 is 12.5000, 0.91153 is 0.9115). Exponential notation is not used, and 0 is written when the integer part is 0. Negative numbers are prefixed with -, but a value that becomes 0 after rounding is written without - (example: -0.00004 is 0.0000). The centers and scales of the scaling are written with 6 decimal places and the lower bounds of the confidence bins with 2 decimal places, in the same way. The data contains no values close to a rounding boundary.
- A "ratio" is written in the form <a>/<b> <v>. a and b are integers and are not reduced. v is the real number a / b (example: 237/260 0.9115).
- A "reduced-fraction metric" is written in the form <p>/<q> <v>. p / q is the irreducible fraction obtained by dividing the numerator and the denominator by their greatest common divisor (0/1 if the numerator is 0), and v is its value as a real number (example: numerator 40 and denominator 82 give 20/41 0.4878). When there is no value, write - -.
- <model> is the notation of a model (section 4 (4)).
- <label counts> is, for each label c in label order, c and its count in this order (<c> <count> ...).
- <feature names> is the feature names in feature order (<feature name> ...).

* output/cv_grid.csv
The first line is k,metric,weighting,scaling,correct,accuracy,rmse. Then, for each model of the grid (in grid order), write one line
<k>,<metric>,<weighting>,<scaling method>,<correct count>,<correct count / n>,<RMSE>
(the cross-validation results of section 6).

* output/predictions.csv
The first line is id,label,vote_share,estimate. Then, for each test row (in test row order), write one line
<ID>,<predicted label of the selected classifier>,<its vote share>,<estimate of the selected regressor>
(the predictions of section 13; test rows whose label or target value is empty are also written).

* output/metrics.txt
Write the following parts in this order. Put exactly one blank line between consecutive parts (none before the first part or after the last part).
(1) Data
data train <n> test <number of test rows> labelled <number of labelled test rows> targets <number of test rows with a target> features <d> classes <number of labels in the label set>
classes <label counts>
<label counts> is the count of training rows per label.
(2) Scaling: make one part for each scaling method s in scaling order, writing
scaling <s>
followed by, for each feature in feature order,
<feature name> center <center> scale <scale>
The center and scale are those computed with s from the sequence of all training rows (6 decimal places).
(3) Folds
folds <F>
followed by, for each fold f (f = 1, ..., F),
fold <f> size <number of rows of fold f> <label counts>
(the cross-validation folds of section 6; <label counts> is the count per label of the rows of fold f).
(4) Selection
grid <G>
best_classifier <model of the selected classifier> correct <ratio> rmse <RMSE>
best_regressor <model of the selected regressor> rmse <RMSE> correct <ratio>
The ratio is (correct count) / n, and the RMSE is that model's cross-validation result.
(5) Top by correct count
top <T> by accuracy
followed by, for the first T models of the accuracy ranking (all models if there are fewer than T),
<rank> <model> correct <ratio> rmse <RMSE>
The ranks are 1, 2, ....
(6) Top by RMSE
top <T> by rmse

[Source files]
Split the program into the following six source files (file names follow each language's conventions).
- main: handles the overall flow and most of the processing: calling the input reading, building the grid, grid search by cross-validation and model selection, the top lists and best per item, per-fold results, classification evaluation (confusion matrix, reduced-fraction metrics, macro averages), the confidence-bin tally, McNemar tests, leave-one-out cross-validation (including leave-one-out per k and the largest residuals), nested cross-validation, feature selection by backward elimination, prediction and evaluation of the test data (including uncertain rows and the neighbors of misclassified rows), the learning curve, Wilson editing, Hart condensing, evaluation of the prototype sets, border rows, hubs, and assembling the contents of the five output files.
- dataset: reads the three input files and returns the feature names, the sequences of training rows and test rows (ID, feature values, label, target value; empty labels and target values are distinguished), and the settings.
- scaling: handles the scaling computation (centers and scales for standard and minmax) and the transformation that keeps only the used features.
- neighbors: handles the four distance metrics, the neighbor order computation, voting with the two weightings (vote order and vote shares) and the estimate computation.
- validation: handles the stratified split, predicting a row with a model on a sequence of training rows (computing and applying the scaling, finding the neighbor order, voting and estimating), and the computation of RMSE, MAE and R^2.
- report: handles real-number formatting (number of decimals, rounding, treatment of -0), the formatting of ratios and reduced fractions, and writing sequences of lines to files.

[Constraints]
- 2 <= d <= 8, 2 <= n <= 300, the number of test rows is between 1 and 100 inclusive, 2 <= F <= 10, 1 <= k <= 25 (each value of K_VALUES), 1 <= E <= 9, 1 <= T <= 20. The label set has at least 2 labels, and each label has at least F training rows.
- There is at least one labelled test row, and there are at least two test rows with a target, whose target values are not all the same.
- In every pass of Wilson editing, at least two rows remain in the editing set.
- The input files correctly follow the formats above. There is no need to check for input errors.
- The given data predicts the origin (4 labels) and the cupping score (target value) from measurements of green coffee beans (7 features), with n = 260, 80 test rows (74 labelled, 74 with a target), and a grid of 128 models. The total number of distance computations, including nested cross-validation and feature selection, is about 4 million.
- In the given data, every real number output is sufficiently far from a rounding boundary. Also, the neighbor order (including the boundary of the k nearest neighbors and the neighbor lists that are output), the vote order, the comparisons by 4-decimal value and the bin assignments have enough margin not to change under differences in the order of additions, fused multiply-add, or differences in the last digit of square root or division results (about 1 ulp). There is no situation where the boundary of the k nearest neighbors or an output neighbor list is decided by ID order because of equal distances, or where the vote order is decided by label order because cnt(c) and dsum(c) are equal (there are selections decided by grid order or feature order because correct counts or 4-decimal values are equal). Nevertheless, compute with the formulas and orders defined in this statement.
- All integer values (correct counts, counts, 1000 * u and 3841 * (b + c) of the McNemar test, etc.) are less than 2^31.

Some points about this example:
- For the models with k = 1, uniform and distance give the same predicted labels and estimates (apart from rounding errors), so their correct counts and 4-decimal RMSE values are equal. In such comparisons of equal values, the model earlier in grid order (weighting=uniform) is chosen. Rank 2 of the RMSE top list and the k=1 line of best per k are examples of this.
- In step 1 of feature selection, the candidate correct counts are 11 both when body is removed and when bitterness is removed, so body, which comes earlier in feature order, is removed. The correct counts of the starting set and of the set after step 1 are both 11, so the set after step 1, which has fewer features (acidity and bitterness), is the selected features.
- Test rows T3 and T4 both have a 4-decimal margin of 0.3333, so in the uncertain test rows they are listed in test row order: T3, T4.
- Test row T5 has both its label and its target value empty, so its prediction is written to predictions.csv but it is not used in the classification and regression evaluations. Test row T3 has an empty target value, so there is no test row with a target with label liberica, and its RMSE is -.
- No prediction has a vote share below 0.6, so the first confidence bin is bin 0.00 rows 0.
- In Wilson editing, pass 1 removes only R43, and pass 2 has no row to remove, so editing stops.
