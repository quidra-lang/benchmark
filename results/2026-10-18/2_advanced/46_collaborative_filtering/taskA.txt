[Overview]
Write a program that, from movie rating data (ratings from 1 to 5 that users gave to items), predicts the ratings of items that a user has not rated yet and makes recommendations. From the training data it builds seven prediction methods: the global mean (GLOBAL), a baseline from user and item biases (BASELINE), user-based collaborative filtering with Pearson correlation (USER_KNN), item-based collaborative filtering with adjusted cosine similarity (ITEM_KNN), weighted Slope One (SLOPE_ONE), matrix factorization by stochastic gradient descent (SVD) and matrix factorization by alternating least squares (ALS). It compares them by the prediction errors on the ratings of the test data (RMSE, MAE, etc.) and by ranking metrics of the recommendation lists (precision, recall, NDCG, etc.). In addition, it writes an error analysis, recommendation lists for specified users (a list in popularity order for users who have no ratings in the training data), lists of items similar to specified items, and the progress of training.
The input is four files in the input/ folder (training data, item information, test data, settings), and the results are written to five files in the output/ folder. Nothing is written to standard output. Random numbers come only from the generator defined in this statement, and since every rule is fully specified, the result is uniquely determined.

[Input files]
There are four input files: input/ratings.csv, input/items.csv, input/test.csv and input/params.txt. Every file consists of ASCII characters only, and every line (including the last line) ends with a newline (LF). There is no whitespace at the start or end of a line. Values are separated by a single comma in the CSV files and by a single space in params.txt.
An integer is a base-10 number without extra leading zeros. A decimal number is a base-10 number consisting of, in this order, a sequence of one or more digits (the integer part), ".", and a sequence of one or more digits (the fractional part) (examples: 0.01, 10.0).

* input/ratings.csv (training data)
The first line is the header line user,item,rating,timestamp. Each line from the second line on is one "training rating", listing the user ID, the item ID, the rating and the time in this order, separated by commas.
- User IDs and item IDs are positive integers. User IDs and item IDs are separate numbering systems; the same number may be used for both a user and an item.
- A rating is an integer from 1 to 5 inclusive.
- A time is a positive integer (seconds since some reference point).
The same pair of user and item never appears twice or more. Let T be the number of training ratings; the order of the lines in the file is called the "training rating order".

* input/items.csv (item information)
The first line is the header line item,title,genres. Each line from the second line on lists the item ID, the title and the genre list in this order, separated by commas.
- A title is a string of one or more characters consisting of English letters, digits, spaces, "(" and ")"; it does not start or end with a space (it contains no comma).
- A genre list is one or more genre names separated by "|". A genre name is a string of 1 to 16 English letters; the genre names within one item are distinct from each other.
The item IDs are distinct from each other and include every item ID that appears in ratings.csv and test.csv. There may also be lines for items that do not appear in ratings.csv. The lines are not necessarily sorted by ID. The number of lines from the second line on is called the "catalog size".

* input/test.csv (test data)
The first line is the header line user,item,rating. Each line from the second line on is one "test rating", listing the user ID, the item ID and the rating in this order, separated by commas (with the same meaning as in ratings.csv). The user and the item of every test rating each appear in at least one training rating. The pair of user and item of a test rating appears neither in the training ratings nor in any other test rating. Let m be the number of test ratings; the order of the lines in the file is called the "test rating order".

* input/params.txt (settings)
The following lines appear in this order. Each line is a keyword followed by one or more values.
- NEIGHBORS k: the neighborhood size (a positive integer).
- SHRINKAGE lambda: the strength of the shrinkage of the similarities and of the Slope One deviations (an integer >= 0).
- MIN_SIMILARITY theta: the lower bound of the similarities used for neighbors (a decimal number >= 0).
- BIAS_REG lambda_I lambda_U: the regularization strengths of the item biases and of the user biases (decimal numbers >= 0).
- FACTORS F: the number of factors of the matrix factorization (a positive integer).
- LEARNING_RATE gamma: the learning rate of SVD (a positive decimal number).
- REGULARIZATION lambda_S: the regularization strength of SVD (a decimal number >= 0).
- EPOCHS E_S: the number of epochs of SVD (a positive integer).
- ALS_REG lambda_A: the regularization strength of ALS (a positive decimal number).
- ALS_ITERATIONS E_A: the number of iterations of ALS (a positive integer).
- SEED seed: the random seed (an integer from 1 to 2147483646 inclusive).
- TOP_N N: the length of the recommendation lists (an integer >= 2).
- CUTOFFS c_1 c_2 ...: the list lengths for which ranking metrics are computed (distinct positive integers, at least one, in increasing order).
- NEIGHBOR_GRID k_1 k_2 ...: the neighborhood sizes to compare (distinct positive integers, at least one, in increasing order).
- USER_GROUPS b_1 b_2 ...: the boundaries of the user groups (distinct integers >= 2, at least one, in increasing order).
- ITEM_GROUPS b_1 b_2 ...: the boundaries of the item groups (distinct integers >= 2, at least one, in increasing order).
- TIME_BUCKETS B: the number of time buckets (a positive integer).
- LIST_SIZE M: the length of the neighbor, similar-item and bias lists (a positive integer).
- RECOMMEND_USERS u_1 u_2 ...: the user IDs for which recommendation lists are made (distinct positive integers, at least one). It may contain IDs that do not appear in the training ratings. The order of this list is called the "request order".
- SIMILAR_ITEMS i_1 i_2 ...: the item IDs whose similar items are examined (distinct positive integers, at least one). Every one of them is an item that appears in the training ratings.

[Processing]
* 1. Notation and computation rules
- The order of strings is the lexicographic order by ASCII character code (compare one character at a time from the start; the string whose first differing character has the smaller code comes first; if one string is a prefix of the other, the shorter one comes first).
- sqrt is the square root, log2 is the base-2 logarithm, |t| is the absolute value of t, and floor(t) is the largest integer not greater than t. a mod b (integers a >= 0, b > 0) is the remainder of dividing a by b.
- Counts, sums of ratings, and values described as "integer" in this statement are computed exactly as integers. All other values are computed in double-precision floating point (IEEE 754 64-bit). When an integer is used in a real computation, it is used as the real number equal to that integer. Division / is real division even between integers (truncation is written with floor(...)).
- SUM (written in place of the summation sign) denotes the sum obtained by adding the elements one at a time from the start, in the order of the indicated sequence; the initial value of a sum is 0. A sum for which no sequence is indicated is added in user order if it is a sum over users, in item order if it is over items, in training rating order if it is over training ratings, and in test rating order if it is over test ratings (user order and item order are defined in 2).
- Expressions are evaluated with the contents of parentheses first, and operations of equal precedence from left to right (examples: a + b + c is (a + b) + c, and a / b * c / d is ((a / b) * c) / d).
- Every rule that selects a maximum or minimum and every sorting rule always comes with the treatment of equal values. "Equal values" means values that are equal when computed with the formulas and in the order of this statement.

* 2. Organizing the training data
- Let U be the set of users and I the set of items that appear in the training ratings. The users of U sorted by ID in increasing order are called the "user order", and the items of I sorted by ID in increasing order are called the "item order". |U| and |I| are their respective counts.
- r(u, i) denotes the rating of the training rating that user u gave to item i. Below, u and v denote users, and i and j denote items.
- For a user u in U, let R(u) be the items rated by u, in item order, cnt_u their count, and S_u the sum of the ratings (an integer); the user mean is avg_u = S_u / cnt_u.
- For an item i in I, let R(i) be the users who rated i, in user order, cnt_i their count, and S_i the sum of the ratings (an integer); the item mean is avg_i = S_i / cnt_i.
- The global mean is mu = (the sum of the ratings of all training ratings (an integer)) / T.
- The "popularity order" is the items of I sorted by cnt_i in decreasing order, ties by avg_i in decreasing order, and remaining ties by ID in increasing order. The first H = floor(|I| / 5) items of the popularity order are called "popular items".
- The "candidate items" of a user u in U are the items of I that are not contained in R(u).

* 3. Random numbers
Random numbers are produced by the following generator. The state x is initialized with the seed; each time a random number is drawn, x is updated to (48271 * x) mod 2147483647, and the updated x is the drawn value. Since 48271 * x is less than 2^53, it can be computed exactly with 64-bit integers.
A "factor initial value" is obtained by drawing one random number x and computing ((x mod 2001) - 1000) / 10000 (x mod 2001 - 1000 is computed as an integer).

* 4. Solving systems of linear equations
Indices of matrices and vectors start from 1, and the element in row a, column b of a matrix A is written A[a][b]. From a symmetric positive definite matrix A of size D and a vector w, the vector x satisfying A x = w is found by the following procedure.
(1) Cholesky decomposition: for a = 1, ..., D in this order, and for each a, for b = 1, ..., a in this order, compute
  s = A[a][b] - SUM_{t=1}^{b-1} L[a][t] * L[b][t]
(compute the sum first, then subtract it from A[a][b]; when b = 1 the sum is 0), and set L[a][a] = sqrt(s) if a = b, and L[a][b] = s / L[b][b] if a > b. For the matrices solved in this task, s is always positive.
(2) Forward substitution: for a = 1, ..., D in this order, z_a = (w_a - SUM_{t=1}^{a-1} L[a][t] * z_t) / L[a][a].
(3) Back substitution: for a = D, D - 1, ..., 1 in this order, x_a = (z_a - SUM_{t=a+1}^{D} L[t][a] * x_t) / L[a][a] (the sum is added in increasing order of t).

* 5. Training RMSE and clipping
- The "training RMSE" of a prediction formula f(u, i) is obtained by computing e = r(u, i) - f(u, i) for each training rating in training rating order and then taking sqrt((SUM e * e) / T). No clipping is done here.
- The "clipping" clip(p) of a prediction p is 1 if p < 1, 5 if p > 5, and p otherwise.

* 6. Prediction methods
There are seven prediction methods: GLOBAL, BASELINE, USER_KNN, ITEM_KNN, SLOPE_ONE, SVD and ALS; this order is called the "method order". Every method computes a prediction p for u in U and i in I (i is not contained in R(u)). The predictions in this section are values before clipping.
When USER_KNN, ITEM_KNN or SLOPE_ONE has nothing at all to use for a prediction, the baseline prediction ((2)) is used as the prediction, and such a prediction is called "no-neighbor".

(1) GLOBAL: the prediction is mu.

(2) BASELINE (baseline from biases): start with the user bias b_u = 0 for every u in U and the item bias b_i = 0 for every i in I, and perform the following "sweep" 10 times.
 1. For each i in item order, set b_i = (SUM_{u in R(i)} (r(u, i) - mu - b_u)) / (lambda_I + cnt_i).
 2. For each u in user order, set b_u = (SUM_{i in R(u)} (r(u, i) - mu - b_i)) / (lambda_U + cnt_u). Step 1 uses b_u from the previous sweep (0 in the first sweep), and step 2 uses b_i computed in step 1 of this sweep.
 3. Compute the training RMSE of the prediction formula (mu + b_u) + b_i with the biases at that point.
The b_u and b_i after the 10th sweep are the final biases. The prediction (mu + b_u) + b_i (with the final biases) is called the "baseline prediction" and is the prediction of BASELINE.

(3) USER_KNN (user-based)
User similarity: for distinct u, v in U, let n be the number of items contained in both R(u) and R(v) (the common items). If n < 2, the similarity is undefined. If n >= 2, from the integer sums over the common items Sx = SUM r(u, i), Sy = SUM r(v, i), Sxx = SUM r(u, i) * r(u, i), Syy = SUM r(v, i) * r(v, i) and Sxy = SUM r(u, i) * r(v, i), compute the integers num = n * Sxy - Sx * Sy, dx = n * Sxx - Sx * Sx and dy = n * Syy - Sy * Sy. If dx = 0 or dy = 0, the similarity is undefined. Otherwise, compute the integers A = (num * n) * (num * n) and B = dx * dy * (n + lambda) * (n + lambda), and the similarity is sim(u, v) = sg * sqrt(A / B), where sg is 1 if num > 0, -1 if num < 0, and 0 if num = 0. sim(u, v) = sim(v, u), and n is called the "common count" of these two users.
(This value is mathematically equal to the Pearson correlation coefficient over the common items multiplied by n / (n + lambda). So that mathematically equal similarities become the same floating-point number, always compute it with exactly one division of the integers A and B and one square root.)
A similarity that is defined and greater than theta is called a "usable similarity".
Prediction: for a user u and an item i, the candidates are the users v of R(i) for which sim(u, v) is a usable similarity. If there are no candidates, the prediction is no-neighbor. Sort the candidates by sim(u, v) in decreasing order (ties by ID in increasing order); the first k of them (all of them if there are fewer than k) are the "selected neighbors", and the first of these is the "top neighbor". From the two sums num' = SUM sim(u, v) * (r(v, i) - avg_v) and den' = SUM sim(u, v), added in the order of the selected neighbors, the prediction is avg_u + num' / den'.

(4) ITEM_KNN (item-based)
Item similarity: for distinct i, j in I, let n be the number of users contained in both R(i) and R(j) (the common users). If n < 2, the similarity is undefined. If n >= 2, for each common user u let d_i = r(u, i) - avg_u and d_j = r(u, j) - avg_u, and compute the sums over the common users num = SUM d_i * d_j, ni = SUM d_i * d_i and nj = SUM d_j * d_j. If ni = 0 or nj = 0, the similarity is undefined. Otherwise, the similarity is sim(i, j) = num / sqrt(ni * nj) * n / (n + lambda) (computed from left to right). sim(i, j) = sim(j, i), and n is called the "common count" of these two items. The meaning of a usable similarity is the same as in (3).
Prediction: for a user u and an item i, the candidates are the items j of R(u) for which sim(i, j) is a usable similarity. If there are no candidates, the prediction is no-neighbor. Sort the candidates by sim(i, j) in decreasing order (ties by ID in increasing order); the first k of them (all of them if there are fewer than k) are the selected neighbors, and the first of these is the top neighbor. From the two sums num' = SUM sim(i, j) * (r(u, j) - avg_j) and den' = SUM sim(i, j), added in the order of the selected neighbors, the prediction is avg_i + num' / den'.

(5) SLOPE_ONE (weighted Slope One)
For distinct i, j in I, let c(j, i) (= c(i, j)) be the number of users contained in both R(i) and R(j); when c(j, i) >= 1, compute the integer sum over those users D(j, i) = SUM (r(u, j) - r(u, i)) (D(i, j) = -D(j, i)). The shrunk deviation is dev(j, i) = D(j, i) / (c(j, i) + lambda).
Prediction: for a user u and an item j, use the items i of R(u) with c(j, i) >= 1, in item order, and compute the two sums num' = SUM (dev(j, i) + r(u, i)) * c(j, i) and den' = SUM c(j, i) (den' is an integer). If there is no item to use, the prediction is no-neighbor. Otherwise, the prediction is num' / den'.

(6) SVD (matrix factorization by stochastic gradient descent)
Initialization: initialize the generator with seed, and create, in this order, P_u[1], ..., P_u[F] for each u in user order, followed by Q_i[1], ..., Q_i[F] for each i in item order, as factor initial values. The user biases g_u and the item biases h_i are all 0. The visiting sequence O is O[t] = t (t = 0, 1, ..., T - 1), where t is the index of a training rating counted from 0 in training rating order.
The SVD prediction formula is ((mu + g_u) + h_i) + dot(u, i), where dot(u, i) = SUM_{f=1}^{F} P_u[f] * Q_i[f].
For epochs 1, ..., E_S in this order, perform the following steps 1 to 3.
 1. Shuffle: for t = T - 1, T - 2, ..., 1 in this order, draw one random number x, let y = x mod (t + 1), and swap O[t] and O[y]. O is not reinitialized for each epoch; the order left by the previous epoch is shuffled further. The generator is not reinitialized either and continues to be used.
 2. Update: for t = 0, 1, ..., T - 1 in this order, for the training rating with index O[t] (user u, item i, rating r), compute e = r - (((mu + g_u) + h_i) + dot(u, i)) and update in the following order.
  Set g_u to g_u + gamma * (e - lambda_S * g_u).
  Set h_i to h_i + gamma * (e - lambda_S * h_i).
  For f = 1, ..., F in this order, from the current values a = P_u[f] and b = Q_i[f], set P_u[f] to a + gamma * (e * b - lambda_S * a) and Q_i[f] to b + gamma * (e * a - lambda_S * b).
 3. Compute the training RMSE of the SVD prediction formula.
The value of the SVD prediction formula with the values after the E_S epochs is the SVD prediction.

(7) ALS (matrix factorization by alternating least squares)
Using the final biases of BASELINE, the residual of each training rating is z(u, i) = r(u, i) - ((mu + b_u) + b_i).
Initialization: initialize the generator anew with seed (it is separate from the SVD generator), and create Y_i[1], ..., Y_i[F] for each i in item order as factor initial values.
The ALS prediction formula is ((mu + b_u) + b_i) + SUM_{f=1}^{F} X_u[f] * Y_i[f].
For iterations 1, ..., E_A in this order, perform the following steps 1 to 3.
 1. For each u in user order, let A be the F-by-F matrix A[a][b] = SUM_{i in R(u)} Y_i[a] * Y_i[b] (a, b = 1, ..., F), and then, for each a, add lambda_A * cnt_u to A[a][a]. Let w be the vector w[a] = SUM_{i in R(u)} z(u, i) * Y_i[a], solve A x = w by the procedure of 4, and let X_u be the solution x.
 2. For each i in item order, let A[a][b] = SUM_{u in R(i)} X_u[a] * X_u[b], add lambda_A * cnt_i to A[a][a] for each a, let w[a] = SUM_{u in R(i)} z(u, i) * X_u[a], and let Y_i be the solution x of A x = w (using the X_u computed in step 1).
 3. Compute the training RMSE of the ALS prediction formula.
The value of the ALS prediction formula with the values after the E_A iterations is the ALS prediction.

* 7. Training log
The training RMSEs computed for each BASELINE sweep (1 to 10), each SVD epoch (1 to E_S) and each ALS iteration (1 to E_A) are recorded in this order.

* 8. Test predictions and errors
- In test rating order, for each test rating (user u, item i, rating r), compute the prediction p of each method in method order (with neighborhood size k). q = clip(p) is the "clipped prediction", and e = q - r is the "error" of that method.
- For a collection of test ratings (in test rating order; count L >= 1), RMSE = sqrt((SUM e * e) / L) and MAE = (SUM |e|) / L.
- For each method, compute RMSE and MAE (over all test ratings), the number of test ratings for which p < 1 or p > 5 (clipped), and the number of test ratings whose prediction was no-neighbor (fallback; 0 for GLOBAL, BASELINE, SVD and ALS).

* 9. Data summary
- users is |U|, items is |I|, catalog is the catalog size, ratings is T, and test is m. density is T / (|U| * |I|).
- histogram is the numbers of training ratings whose rating is 1, 2, 3, 4 and 5.
- Rating count summary: the minimum, median and maximum of the sequence (count L) of cnt_u of U sorted in increasing order. The median is the ((L + 1) / 2)-th value if L is odd, and (the (L / 2)-th value + the (L / 2 + 1)-th value) / 2 if L is even (the sum is computed as an integer and then divided by 2). The same values are computed for cnt_i of I.
- timestamps are the minimum t_first and the maximum t_last of the times of the training ratings. cold_items is the number of items in items.csv that are not contained in I.
- Similarity summary: user_pairs is the number of pairs u, v in U with u < v (comparing IDs) for which the user similarity is defined, and its usable is the number of those that are usable similarities. item_pairs and its usable are the same for the item similarity. slope_pairs is the number of pairs i, j in I with i < j for which c(i, j) >= 1.
- Genre summary: sort the genres contained in any item of I in string order, and for each genre g compute the number of items of I that contain g (items), the sum of cnt_i of those items (ratings), and the number of training ratings for those items whose rating is 4 or more (high).
- Time buckets: the bucket number of each training rating is floor((time - t_first) * B / (t_last - t_first + 1)) + 1 (computed as integers; 1 to B). For each bucket b = 1, ..., B, compute the number of training ratings in the bucket, the number of distinct users among them, and the mean rating (the sum of the ratings (an integer) / the count; no value if the count is 0).

* 10. Error analysis
(1) Generalization: for GLOBAL, BASELINE, SVD and ALS, compute the training value train, the test value test and the difference gap = test - train. train is the training RMSE of the prediction formula mu for GLOBAL, the training RMSE of the 10th sweep for BASELINE, the training RMSE of the last epoch for SVD, and the training RMSE of the last iteration for ALS. test is the RMSE computed in 8.
(2) Neighborhood usage: for each of USER_KNN and ITEM_KNN, compute, among the test predictions of 8, the number W of predictions that are not no-neighbor; (the sum of the numbers of selected neighbors (an integer)) / W (mean_neighbors); and (the sum, added in test rating order, of each prediction's (SUM (the similarities of the selected neighbors, added in the order of the selected neighbors)) / (the number of selected neighbors)) / W (mean_similarity). If W = 0, both means have no value.
(3) Prediction statistics: for the actual ratings r (in test rating order), compute the mean ma = (SUM r) / m and the standard deviation sa = sqrt((SUM (r - ma) * (r - ma)) / m). For each method, compute the mean of the clipped predictions q, mq = (SUM q) / m, the standard deviation sq = sqrt((SUM (q - mq) * (q - mq)) / m), and the correlation coefficient (SUM (q - mq) * (r - ma)) / sqrt((SUM (q - mq) * (q - mq)) * (SUM (r - ma) * (r - ma))) (the sums are in test rating order). If all q of that method are the same value, or all r are the same value, the correlation coefficient has no value.
(4) Error bins: divide the absolute errors |e| into the five intervals [0, 0.5), [0.5, 1.0), [1.0, 1.5), [1.5, 2.0) and [2.0, infinity) (each interval includes its lower end and excludes its upper end), and for each method compute the number of test ratings in each interval.
(5) Method comparison: take all pairs (A, B) in which A comes before B in method order, ordered by A, and for equal A by B (both in method order). For each pair, compute the number of test ratings with |error of A| < |error of B| (wins), the number with equal values (ties), and the number with a greater value (losses).
(6) Errors per group: divide the test ratings into G + 1 groups by the user's cnt_u and the USER_GROUPS boundaries b_1 < b_2 < ... < b_G. A test rating for which the number of boundaries b with cnt_u >= b is g belongs to group g + 1. Group 1 covers the range 1 to b_1 - 1, group g (2 <= g <= G) covers b_{g-1} to b_g - 1, and group G + 1 covers b_G and up with no upper limit. For each group, compute the number of test ratings and the RMSE of each method (over the test ratings of the group; no value if the count is 0). Compute the same for the item's cnt_i and the ITEM_GROUPS boundaries.
(7) Errors per rating value: for the test ratings whose actual rating is v (v = 1, ..., 5), compute their number and the MAE of each method (no value if the count is 0).
(8) Errors per genre: sort the genres contained in any of the items of the test ratings in string order, and for each genre g compute the number of test ratings whose item contains g and the RMSE of each method.

* 11. Ranking evaluation
(1) Relevance and evaluated users: a test rating whose rating is 4 or more is "relevant", and rel(u) is the set of the items of the relevant test ratings of user u. The users with a non-empty rel(u), in user order, are the "evaluated users", and E is their number.
(2) Ranked lists: there are seven ranking methods: POPULAR, BASELINE, USER_KNN, ITEM_KNN, SLOPE_ONE, SVD and ALS; this order is called the "ranking order". The ranked list of method X for a user u in U is the candidate items of u sorted as follows. If X is POPULAR, they are in popularity order. Otherwise, they are sorted by the prediction of X (the value before clipping, with neighborhood size k) in decreasing order, ties by ID in increasing order. The first c entries of the ranked list are the "list of length c"; the first entry is rank 1, the next is rank 2, and so on.
(3) Per-user metrics: for an evaluated user u and the list of length c, compute the following values.
- h_u: the number of items of the list that are contained in rel(u) (hits).
- recall_u = h_u / |rel(u)|.
- ndcg_u = DCG / IDCG. DCG is the sum of 1 / log2(t + 1) over the ranks t of the hits, added in rank order (0 if there are no hits), and IDCG = SUM_{t=1}^{min(c, |rel(u)|)} 1 / log2(t + 1).
- ap_u = (SUM (h_t / t)) / min(c, |rel(u)|). The sum is over the ranks t of the hits, added in rank order, and h_t is the number of hits from rank 1 to rank t (an integer).
- rr_u: 1 / t if the highest hit is at rank t, and 0 if there are no hits.
(4) Metrics per length: for each c of CUTOFFS and each ranking method, compute the following values over the evaluated users (sums are added in user order). precision = (SUM h_u) / (c * E) (the numerator and the denominator are integers), recall = (SUM recall_u) / E, ndcg = (SUM ndcg_u) / E, map = (SUM ap_u) / E, mrr = (SUM rr_u) / E, hit_rate = (the number of users with h_u >= 1) / E.
(5) Beyond-accuracy metrics: for each ranking method, compute the following values from the lists of length N of the evaluated users.
- coverage: the number of distinct items that appear in any of the lists / |I|.
- diversity: (SUM (the number of distinct genres contained in the items of the list)) / E.
- novelty: for each user compute nov_u = (SUM log2(|U| / cnt_i)) / N (the sum is over the items of the list, in rank order; the real division |U| / cnt_i is done first), and take (SUM nov_u) / E.
- popularity: (SUM (the sum of cnt_i of the items of the list (an integer))) / (N * E) (the numerator and the denominator are integers).
- long_tail: (the total number of items of the lists that are not popular items) / (N * E).
- similarity: for each user, compute ils_u, the sum of w over the pairs of items with ranks a < b (for a = 1, ..., N - 1 in this order, and for each a, b = a + 1, ..., N in this order) divided by N * (N - 1) / 2 (an integer), and take (SUM ils_u) / E. w is sim(i, j) (the item similarity) for the two items i, j of the pair if it is defined, and 0 if it is undefined.
(6) NDCG per group: divide the evaluated users into groups by cnt_u and the USER_GROUPS boundaries with the same rule as in 10 (6). For each group, compute the number of its users and, for each ranking method, the mean of ndcg_u on the list of length N ((SUM ndcg_u) / the count; no value if the count is 0).
(7) List agreement: take all pairs (A, B) in which A comes before B in ranking order, ordered by A, and for equal A by B (both in ranking order). For each pair, compute for each evaluated user the size of the intersection / the size of the union of the item sets of the lists of length N of A and B (the Jaccard coefficient), and take (SUM (Jaccard coefficient)) / E.

* 12. Neighborhood size comparison and bias lists
(1) Neighborhood size: for each value k' of NEIGHBOR_GRID, compute the USER_KNN and ITEM_KNN predictions with neighborhood size k', and compute the RMSE in the same way as in 8. For each method, select the k' with the smallest RMSE (the smaller k' on ties).
(2) Bias lists: for the final biases of BASELINE, compute the first M items of I sorted by b_i in decreasing order (ties by ID in increasing order) (item_high), the first M items sorted by b_i in increasing order (ties by ID in increasing order) (item_low), the first M users of U sorted by b_u in decreasing order (ties by ID in increasing order) (user_high), and the first M users sorted by b_u in increasing order (ties by ID in increasing order) (user_low).

* 13. Recommendation lists
In request order, for each user u of RECOMMEND_USERS, produce the following.
- When u is not contained in U: the first N items of the popularity order form the popularity list.
- When u is contained in U:
 (1) Liked genres: consider the items of R(u) with r(u, i) >= 4; for each genre contained in any of those items, count the number of those items that contain the genre; the liked genres are the first 3 (all if there are fewer than 3) sorted by this count in decreasing order (ties by genre name in string order). The disliked genres are computed in the same way for the items with r(u, i) <= 2.
 (2) Recent ratings: the first 3 (all if there are fewer than 3) of the training ratings of u sorted by time in decreasing order (ties by item ID in increasing order).
 (3) Similar users: the users v in U for which sim(u, v) is a usable similarity, sorted by sim(u, v) in decreasing order (ties by ID in increasing order), first M (all if there are fewer than M).
 (4) Test ratings: the test ratings of u in test rating order, with the clipped prediction of each method.
 (5) In ranking order, the list of length N of each method. The genre match count is the number of items of the list that contain any of the liked genres of (1) (at most 3) (0 if there are no liked genres).

* 14. Similar items
In the order of SIMILAR_ITEMS, for each item i, produce the following four lists. Each list consists of its first M entries (all if there are fewer than M).
(1) Similarity: the items j in I (j != i) for which sim(i, j) is defined (regardless of its sign), sorted by sim(i, j) in decreasing order (ties by ID in increasing order).
(2) Factors: using the final Q of SVD, compute cos(i, j) = (SUM_{f=1}^{F} Q_i[f] * Q_j[f]) / sqrt((SUM_{f=1}^{F} Q_i[f] * Q_i[f]) * (SUM_{f=1}^{F} Q_j[f] * Q_j[f])) for j in I (j != i), and sort by cos(i, j) in decreasing order (ties by ID in increasing order).
(3) Co-rated: the items j in I (j != i) with c(i, j) >= 1, sorted by c(i, j) in decreasing order (ties by ID in increasing order).
(4) Slope One: the items j in I (j != i) with c(j, i) >= 1, sorted by dev(j, i) in decreasing order, ties by c(j, i) in decreasing order, and remaining ties by ID in increasing order.

* Common rules
- The output consists of ASCII characters only, and every line (including the last line) ends with a newline (LF). There is no extra whitespace at the start or end of a line, and no blank lines are inserted unless specified.
- In the formats below, the parts enclosed in < > are replaced by values, and all other characters are written as they are. Values are separated by a single space (by a single comma in the CSV files).

Exponent notation is not used, and 0 is written when the integer part is 0. Negative numbers are prefixed with -, but a value that rounds to 0 is written without -. [Source files]
Split the program into the following six source files (file names follow the conventions of each language).
- main: handles the overall flow and most of the processing: reading the input and calling the training, the BASELINE sweeps, the predictions of the three neighborhood methods (selecting the candidates, the baseline prediction for no-neighbor, the top neighbor), dispatching the prediction per method, the test predictions and the contents of predictions.csv, the data summary, the error analysis (generalization, neighborhood usage, prediction statistics, error bins, method comparison, errors per group, per rating value and per genre), the ranked lists and the ranking evaluation (metrics per length, beyond-accuracy metrics, NDCG per group, list agreement), the neighborhood size comparison, the bias lists, the recommendation lists, the similar items, and assembling the contents of the five output files.
- ratings: reads the four input files and returns the training ratings (in training rating order), the test ratings, the titles and genres of the items, and the setting values. It also builds the per-user and per-item rating tables (in ID order).
- neighborhood: handles the user similarity (Pearson correlation with integers, and shrinkage), the item similarity (adjusted cosine, and shrinkage), the common count c and the difference sum D of item pairs, and the selection of the k largest by similarity.
- factorization: handles the random generator and the factor initial values, SVD training (shuffling and updating, training RMSE per epoch), solving systems of linear equations (Cholesky decomposition, forward substitution, back substitution), and ALS training.
- evaluation: handles clipping, RMSE, MAE, the rank weight 1 / log2(t + 1), and the per-user ranking metrics (hit count, recall, NDCG, AP).
- report: handles the real number format (rounding, treatment of -0), writing no value, and writing a sequence of lines to a file.

[Constraints]
- |U| <= 200, |I| <= 300, catalog size <= 300, T <= 5000, m <= 1000, k <= 50, F <= 20, E_S <= 50, E_A <= 20, N <= 20, c <= 20, M <= 10, B <= 12. NEIGHBOR_GRID, USER_GROUPS and ITEM_GROUPS each have at most 6 values, and RECOMMEND_USERS and SIMILAR_ITEMS each have at most 10 values.
- The given data have |U| = 160, |I| = 228, catalog size 240, T = 3935, m = 648, k = 20, F = 8, E_S = 25, E_A = 10, N = 10, CUTOFFS 5 10 20, and M = 5. The training and prediction of every method take about 10^7 basic operations or fewer in total (for the ranked lists, predictions of about 200 candidate items are computed for each evaluated user and each requested user).
- The input files correctly follow the formats above. There is no need to check for input errors.
- E >= 1. Every evaluated user and every requested user contained in U has more candidate items than both the maximum of CUTOFFS and N. M is smaller than both |U| and |I|, and the final Q_i of SVD is not the zero vector for any item.
- All matrices solved in ALS are positive definite, and s in the middle of the Cholesky decomposition is always positive.
- The integers that appear in A and B of the user similarity and in the computation of the time bucket number are less than 2^31 for the given data (for general input they may be 2^31 or more, so in languages that have 64-bit integers, compute them with 64-bit integers). Only 48271 * x of the random generator may be 2^31 or more.
- For the given data, every real number written is sufficiently far from a rounding boundary. The comparisons of similarities with theta, the neighbor selection and the top neighbor, the order of the ranked lists, the order of the various lists, the clipping decisions, the error bins and comparisons, and the neighborhood size selection have enough margin not to change under differences in the order of additions, fused multiply-add, or differences in the last digit of log2 results (about 1 ulp). Mathematically equal values give the same floating-point number when computed with the formulas of this statement, and their comparison is decided by the rules for equal values. However, you must compute with the formulas and in the order defined in this statement.
