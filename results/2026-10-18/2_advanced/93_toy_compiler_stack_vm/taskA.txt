[Overview]
Write a compiler for a small C-like language (hereafter called "the toy language") that has an integer type (int) and a boolean type (bool), int arrays of fixed size, global and local variables, functions that can be called recursively, if/else, while, for, break, continue, return, print and read(), together with a stack-based virtual machine (hereafter called "the VM") that executes the bytecode output by that compiler.
input/program.src contains one or more programs in the toy language. For each program, the following steps are performed in this order.
1. Lexical analysis: split the source into tokens.
2. Parsing: parse the syntax by recursive descent and build an abstract syntax tree.
3. Semantic analysis: check name scopes, types, numbers of arguments, missing returns and so on. When a lexical, syntax or semantic error is found, report the first one together with its line and column position, and abort the compilation of that program.
4. Warnings: report unused variables and parameters, unreachable statements, and functions that are never called.
5. Optimization and code generation: remove functions that are never called, perform constant folding, then generate stack bytecode using labels and backpatching, and perform peephole optimization. For the code after optimization, determine the maximum stack depth of each unit (function), and the basic blocks and control flow.
6. Execution: execute the code after optimization on the VM. The VM has call frames, detects as runtime errors an array index out of range, division by 0, an operation that goes beyond the int range, exceeding the limits on call depth and on the number of executed instructions, and running out of input, and counts the executed instructions. read() reads the integers for that program, in order, from input/input.txt. For comparison, the code before optimization is also executed.
As a result, the program writes to four files in output/ a listing that includes the disassembly (before and after optimization), the values printed by the programs, the compile-time and runtime errors and warnings, and execution statistics. The program is run in a directory that contains, besides the source files, input/ holding the input files and an empty output/, and it prints nothing to standard output. All computation is done with integers; no floating-point numbers are used.

[Input files]
There are two input files: input/program.src and input/input.txt. Both files consist only of printable ASCII characters (character codes 32 to 126) and line feeds (LF), and every line (including the last line) ends with a line feed. No tabs appear, and no line has trailing spaces. Below, "space" means one ASCII space character, and a part enclosed in < > stands for a value.

* input/program.src
A file containing one or more toy-language programs one after another. The numbers 1, 2, ... given to the lines of the file from the top are called "line numbers".
A line that starts with "#program " ("#program" and one space) is called a "header line". A header line has the form "#program <name>", where <name> is the name of that program. A name is a string of at most 16 characters that starts with a lowercase letter and consists of lowercase letters, digits and "_"; names differ between programs. The first line of the file is a header line.
The lines from the line after a header line up to the line just before the next header line (or up to the last line of the file if there is no next header line) are the "source" of that program. A source has one or more lines, and its last line is not empty. The order in which the header lines appear is called the "program order".
A place in a source is expressed as the pair of a line number (the number in the whole file) and a "column" (the position counted with the first character of that line as column 1); this is called a "position" and is written "<line number>:<column>" (e.g. 12:5). Positions are ordered by comparing line numbers, and if they are equal, by comparing columns.
A source does not necessarily follow the rules of the toy language (2 to 4 of [Processing]).

* input/input.txt
A file holding the integers read by read() of each program. A line of the form "#input <name>" ("#input", one space, a name) is called a "block header", and the file consists of a sequence of "blocks", each starting with a block header (the file may be empty, with no blocks at all). <name> is one of the program names in program.src, and no two blocks have the same name.
Each line from the line after a block header up to the line just before the next block header (or up to the last line of the file if there is none) consists of one or more integers separated by single spaces. The integers are decimal, and negative numbers are prefixed with "-". Every integer is between -2147483648 and 2147483647 inclusive.
The sequence of the integers in a block, in line order and from left to right within a line, is called the "input sequence" of that program. The input sequence of a program without a block is empty.

[Processing]
* 1. Overall flow and common rules
- The programs are processed one at a time in program order. Programs do not affect each other.
- For each program, steps 2 to 10 are performed in this order. If an error is found in 2 (lexical analysis), 3 (parsing) or 4 (semantic analysis), the first error found is recorded, and the rest of the processing for that program (including everything from 5 on: warnings, optimization, execution and so on) is not performed. Such a program is called a "program that failed to compile", and a program without errors is called a "program that compiled".
- An error has a "kind" (one of lexical, syntax and semantic; these are found in 2, 3 and 4 respectively), a position, and a "message". The English strings shown in double quotes in this statement are the messages and output strings themselves. The <...> parts in them are replaced as explained. In particular, <name> is replaced by the spelling (explained in 2) of the identifier concerned.
- The "int range" is the range of integers from -2147483648 to 2147483647 inclusive. All int values of the toy language and all values handled by the VM are in the int range. The bool values false and true are represented in the VM by 0 and 1 respectively.
- The quotient of the "truncating division" of an integer a by a nonzero integer b is the integer obtained by truncating the fractional part of a / b toward 0. That is, letting q be the integer part of the quotient of |a| divided by |b|, it is q when a and b have the same sign (including the case a = 0), and -q when they have different signs. The remainder is a - (quotient) * b, which is 0 or has the same sign as a. For example, 17 divided by -5 gives quotient -3 and remainder 2, and -17 divided by 5 gives quotient -3 and remainder -2.
- Strings are compared in lexicographic order by ASCII code.
- Numbers are written in decimal, with negative numbers prefixed with "-". To "write a sequence of numbers or names separated by spaces" means to write them separated by single spaces.

* 2. Lexical analysis
Read the whole source (including the line feed at the end of each line) from the beginning and split it into a sequence of tokens. Below, a "letter" means A to Z and a to z, and a "digit" means 0 to 9. Starting at the first character of the part not yet read, apply the first of the following rules (1) to (8) that matches, and continue from the character after the part that was read.
(1) Spaces and line feeds are skipped.
(2) "//" starts a comment. Everything up to the last character of that line (the character just before the line feed) is skipped.
(3) "/*" starts a comment. Everything up to the first "*/" that appears after these two characters (including the "*/") is skipped. A comment may span several lines. If there is no "*/", it is the error "unterminated comment" at the position of the "/" of the "/*".
(4) Read the part that starts with a letter or "_" and continues with as many letters, digits and "_" as possible. If it equals one of the following 14 words, it is a "keyword" token; otherwise it is an "identifier" token.
  int  bool  void  true  false  if  else  while  for  break  continue  return  print  read
(5) Read the part that continues with as many digits as possible. This is an "integer literal" token, whose value is the value read as a decimal number (leading zeros are allowed). If the value is greater than 2147483647, it is the error "integer literal too large" at the position of its first digit. When digits are immediately followed by a letter (for example "12ab"), it becomes two tokens: the integer literal "12" and the identifier "ab".
(6) If the next two characters are one of the following 6 two-character sequences, those two characters form one "symbol" token.
  <=  >=  ==  !=  &&  ||
(7) If the next character is one of the following 17 characters, that one character forms one symbol token.
  +  -  *  /  %  <  >  =  !  (  )  {  }  [  ]  ,  ;
(8) If there is a character c that matches none of the above, it is the error "unexpected character '<c>'" at its position. <c> is that character (for example, if there is a single "&", it is "unexpected character '&'").
The kind of a lexical error is lexical, and lexical analysis is aborted as soon as the first error is found. Since lexical analysis is performed on the whole source before parsing, no syntax or semantic error is ever reported for a program that has a lexical error.
Each token has a "spelling" (the string of that token in the source) and a position (the position of its first character). A special token, "end of program", is added once at the end of the token sequence. Its position is the line number of the last line of the source and the column equal to the number of characters of that line plus 1 (just after the last character of the last line).

* 3. Parsing
(1) Grammar
The token sequence is parsed according to the following grammar. In each line, the left side of the first "=" (the one not in double quotes) is the name of the rule and the right side is its content. "..." denotes a keyword or symbol token whose spelling is that string, IDENT denotes an identifier, INT an integer literal, and END the end-of-program token. A | B means either A or B, [ A ] means A zero times or once, { A } means zero or more repetitions of A, and ( A ) denotes grouping.
  program  = { topdecl } END
  topdecl  = type IDENT ( function | global )
  global   = ( "[" INT "]" | [ "=" expr ] ) ";"
  function = "(" [ param { "," param } ] ")" block
  param    = type IDENT
  type     = "int" | "bool" | "void"
  block    = "{" { decl | stmt } "}"
  decl     = type IDENT [ "=" expr ] ";"
  stmt     = block
            | "if" "(" expr ")" stmt [ "else" stmt ]
            | "while" "(" expr ")" stmt
            | "for" "(" [ forinit ] ";" [ expr ] ";" [ simple ] ")" stmt
            | "break" ";"
            | "continue" ";"
            | "return" [ expr ] ";"
            | "print" "(" expr { "," expr } ")" ";"
            | simple ";"
  forinit  = type IDENT "=" expr | simple
  simple   = IDENT "(" [ args ] ")" | IDENT [ "[" expr "]" ] "=" expr | "read" "(" ")"
  args     = expr { "," expr }
  expr     = andexpr { "||" andexpr }
  andexpr  = eqexpr { "&&" eqexpr }
  eqexpr   = relexpr { ( "==" | "!=" ) relexpr }
  relexpr  = addexpr { ( "<" | "<=" | ">" | ">=" ) addexpr }
  addexpr  = mulexpr { ( "+" | "-" ) mulexpr }
  mulexpr  = unary { ( "*" | "/" | "%" ) unary }
  unary    = ( "-" | "!" ) unary | primary
  primary  = INT | "true" | "false" | "read" "(" ")" | "(" expr ")"
            | IDENT "(" [ args ] ")" | IDENT "[" expr "]" | IDENT
In this grammar, looking at the next single token always determines how to proceed.
- topdecl: if the token after IDENT is "(", it is a function; otherwise it is a global. In a global, if the next token is "[", it is an array; if it is "=", there is an initializer; if it is neither, ";" follows immediately.
- block: if the next token is "}", it is the end of the block; if it is one of int, bool and void, it is a decl; otherwise it is a stmt.
- stmt: chosen by its first token. If it is an identifier or read, it is simple ";". If the token after the stmt following if is else, the else part is read (an else belongs to the nearest if).
- for: if the token after "(" is one of int, bool and void, the forinit is in declaration form; if it is ";", there is no forinit; otherwise it is in simple form. The expr before the second ";" is omitted if the next token is ";", and the simple is omitted if the next token is ")".
- return: if the next token is ";", there is no expression; otherwise an expr is read.
- simple and primary: if the token after an identifier is "(", it is a function call; if it is "[", it is an array element; otherwise it is a name (of the assignment target in simple, of a variable in primary). If the token after the "(" of a call is ")", there are no arguments.
- All binary operators are left-associative (for example, a - b - c is (a - b) - c). Operators written higher in the rules above bind more weakly, and unary operators bind most strongly.
(2) Syntax errors
Look at the token sequence from the beginning; the first token at which the sequence of tokens up to and including it is no longer a prefix of any token sequence (ending with END) derivable from this grammar is called the "error token". If the parse proceeds by the choices above and stops at a place where the next token is not allowed, that token is the error token. The position of the error is the position of the error token, and the message is "unexpected end of program" if the error token is the end of program, and "unexpected '<spelling>'" otherwise (for example "unexpected 'for'"). The kind of the error is syntax, and parsing is aborted at the first error.
Parsing does not check whether names are declared, whether types match, the values of array sizes and so on (these are checked in 4).
(3) Terms and positions
- Among topdecls, those of the function form are called "functions", those of the global form "global variable declarations", and a param is called a "parameter" declaration. The block of a function is called the "body" of the function. A decl, and a forinit of the form type IDENT "=" expr, are called "declaration statements", and a variable declared by a declaration statement is called a "local variable". The type of a declaration is called the declaration's "type", the spelling of the IDENT its "name", and the expr after "=" its "initializer". A global variable declaration with "[" INT "]" is called an "array", and the value of that INT is called the "size" of the array.
- The first and third forms of simple are called "call statements", and the second form an "assignment statement". The first IDENT of an assignment statement is called the "assignment target", the expr between "[" and "]" the "index" of the assignment, and the expr after "=" the "right-hand side". The forms of stmt are called block, if statement, while statement, for statement, break statement, continue statement, return statement and print statement, and these, together with declaration statements, call statements and assignment statements, are collectively called "statements". The stmt before "else" in an if statement is called the "then statement", the stmt after it the "else statement", and the last stmt of a while statement or for statement the "body statement". The expr between "(" and ")" of an if statement or while statement, and the expr before the second ";" of a for statement, are called the "condition"; the forinit of a for statement is called the "initialization" and the simple the "update".
- The kinds of expressions are integer literal, true, false, read (the form "read" "(" ")"), variable (the form IDENT alone), array element (the form IDENT "[" expr "]"; that expr is called the "index"), function call (the form IDENT "(" [ args ] ")"; each expr of args is called an "argument"), unary operation and binary operation. "(" expr ")" is treated as the same expression as the expr inside it (the parentheses themselves do not remain).
- The "name position" of each declaration is the position of its IDENT. The position of a statement is the position of its first token (for a declaration statement, the type keyword; for an assignment statement, the assignment target; for a block, the "{"). The position of an expression is the position of its token for an integer literal, true, false and a variable; the position of the keyword read for read; the position of the IDENT for an array element and a function call; and the position of the operator for a unary operation and a binary operation.

* 4. Semantic analysis
(1) Types and names
- There are two types of values: int and bool. The "return type" of a function is one of int, bool and void.
- The names of global variables and functions are called "global names". The global names are handled together in a single table, and they can be referenced from the body of any function, regardless of whether the reference comes before or after the position of the declaration.
- The names of parameters and local variables have a "scope". For each function, its parameters and the declaration statements directly inside the body block belong to one and the same scope (the function scope). Each block inside the body (excluding the body block itself) creates a new scope. A for statement also creates a new scope, and the declaration statement of its initialization belongs to that scope (if the body statement is a block, that block creates a further inner scope). A variable declared by a declaration statement can be used from the point where the check of that declaration statement has finished (it cannot yet be used inside its own initializer) until the end of that scope.
- To "look up" a name, search from the current scope outward through the enclosing scopes in order, and if it is not found anywhere, search the global names. An inner name hides the same name in an outer scope (including global names).
- The global variable, parameter, local variable or function found by looking up a name is called the "referent" of that name. Each time a lookup succeeds, one "reference" (the position of that name token) is recorded for the referent. A reference that is not the assignment target of an assignment statement is called a "read access" (references are used in listing.txt of [Output files], and read accesses in 5).

(2) Order of checks
Semantic analysis proceeds with the checks in the following order and reports the first error found (its kind is semantic). Below, the parentheses after a message give the position of the error.
Stage 1: the global variable declarations and functions are examined one at a time in source order.
 Global variable declaration
  a. If it is an array and its type is not int, "array '<name>' must have element type int" (name position). Next, if it is an array and its size is 0, "array '<name>' must have a positive size" (position of the INT).
  b. If it is not an array and its type is void, "variable '<name>' cannot have type void" (name position).
  c. If its name is the same as the name of an earlier global variable declaration or function, "redeclaration of '<name>'" (name position).
  d. If there is an initializer and it contains one or more variables, array elements, function calls or reads, "global initializer must be constant" at the position of the one among them that comes first in the source. Otherwise, the initializer is checked by the rules of (3), and if its type differs from the type of the declaration, "type mismatch in initialization of '<name>'" (name position).
  e. The name is added to the global names.
 Function
  a. If its name is the same as the name of an earlier global variable declaration or function, "redeclaration of '<name>'" (name position).
  b. The parameters are examined one at a time from left to right. For each parameter, first, if its type is void, "parameter '<name>' cannot have type void"; next, if its name is the same as an earlier parameter of that function, "redeclaration of '<name>'" (both at the name position of the parameter).
  c. The name is added to the global names.
Stage 2: if there is no function named main (even if there is a global variable named main), "no main function" at the position of the end-of-program token. If the return type of main is not void or main has parameters, "main must be declared as 'void main()'" at the name position of main.
Stage 3: the functions are examined one at a time in source order. For each function, its parameters are added to the function scope, and the statements directly inside the body block are checked from first to last by the rules of (4). When the check of the body has finished, if the return type is not void and the body block "can complete normally" ((5)), "missing return in function '<name>'" at the name position of the function.

(3) Checking expressions
Checking an expression determines the type of that expression if there is no error.
- Integer literal, read: the type is int. true, false: the type is bool.
- Variable: the name is "looked up as a variable" (see below). The type is the type of the referent.
- Array element: the name is "looked up as an array". Next, the index is checked, and if its type is not int, "index of '<name>' must be int" (position of the IDENT). The type is int.
- Function call (all positions are the position of the IDENT):
  a. The name is looked up; if it is not found, "undeclared function '<name>'"; if the referent is not a function, "'<name>' is not a function".
  b. If the number of arguments differs from the number of parameters of the referent function, "wrong number of arguments to '<name>' (expected <number of parameters of the function>, found <number of arguments written>)".
  c. The arguments are checked one at a time from left to right, and the type of each is examined right after it is checked. If the type of the k-th argument (counting from 1) differs from the type of the k-th parameter of the function, "argument <k> of '<name>' must be <type of the k-th parameter of the function>" (the arguments from the (k+1)-th on are not checked yet).
  d. If the call appears inside an expression rather than as a call statement and the return type of the function is void, "void function '<name>' used as a value".
  The type is the return type of the function.
- Unary operation: the operand is checked, and if its type is not int for "-" or not bool for "!", "operator '-' requires int operand" or "operator '!' requires bool operand" respectively (position of the operator). The type is the type of the operand.
- Binary operation: the left operand and then the right operand are checked, and then the following is examined depending on the operator (the position is the position of the operator).
  + - * / %: if the types are not both int, "operator '<operator>' requires int operands". The type is int.
  < <= > >=: if the types are not both int, "operator '<operator>' requires int operands". The type is bool.
  == !=: if the two types differ, "operator '<operator>' requires operands of the same type". The type is bool.
  && ||: if the types are not both bool, "operator '<operator>' requires bool operands". The type is bool.
- To "look up a name as a variable" or "as an array" means to look up the name and examine the following (the position is the position of the IDENT). If it is not found, "undeclared identifier '<name>'". If the referent is a function, "'<name>' is a function, not a variable". When looking up as a variable, if the referent is an array, "array '<name>' used without index". When looking up as an array, if the referent is not an array, "'<name>' is not an array".

(4) Checking statements
- Declaration statement: a. If its type is void, "variable '<name>' cannot have type void". b. If the name already exists in the current scope, "redeclaration of '<name>'". c. If there is an initializer, it is checked, and if its type differs from the type of the declaration, "type mismatch in initialization of '<name>'". d. The variable is added to the current scope. All positions are the name position.
- Assignment statement: a. The name of the assignment target is looked up as an array if there is an index, and as a variable otherwise. b. If there is an index, it is checked, and if its type is not int, "index of '<name>' must be int". c. The right-hand side is checked, and if its type differs from the type of the assignment target (int if there is an index), "type mismatch in assignment to '<name>'". All positions are the position of the assignment target.
- Call statement: the function call or read is checked as an expression (except that d of function calls is not examined).
- If statement, while statement: the condition is checked, and if its type is not bool, "condition of 'if' must be bool" (for a while statement, "condition of 'while' must be bool"; the position is the position of the keyword). Next, for an if statement, the then statement and (if present) the else statement are checked, and for a while statement, the body statement.
- For statement: a new scope is created; the initialization (if present; as a declaration statement, call statement or assignment statement), the condition (if present; if its type is not bool, "condition of 'for' must be bool" at the position of for), the update (if present) and the body statement are checked in this order; and the scope is closed.
- Break statement, continue statement: if it is not inside the body statement of a while statement or for statement (including inside nested constructs), "'break' outside loop" or "'continue' outside loop" respectively (position of the keyword).
- Return statement (all positions are the position of return; <function name> is the name of the function containing the statement): if the return type of the function is void and there is an expression, "function '<function name>' must not return a value". If it is not void and there is no expression, "function '<function name>' must return a value". If it is not void and there is an expression, the expression is checked, and if its type differs from the return type, "return value of '<function name>' must be <return type>".
- Print statement: the argument expressions are checked one at a time from left to right, and the type of each is examined right after it is checked; if the type of the k-th one is not int, "argument <k> of 'print' must be int" (position of print).
- Block: a new scope is created, the statements inside are checked in order, and the scope is closed.

(5) Statements that can complete normally
Whether a statement "can complete normally" is determined as follows. Return statements, break statements and continue statements cannot complete normally. A block can complete normally only when every statement inside it can complete normally (including when it contains no statements). An if statement can complete normally only when there is no else statement, or when at least one of the then statement and the else statement can complete normally. All other statements (declaration statements, assignment statements, call statements, print statements, while statements, for statements) can complete normally.

* 5. Warnings
For a program that compiled, the following three kinds of warnings are collected (they are determined from the result of 4 and are not affected by the processing from 6 on).
(1) For each global variable and local variable that has no read access at all, "unused variable '<name>'" at its name position. For each parameter that has no read access at all, "unused parameter '<name>'" at the name position of the parameter. Read accesses inside functions that are never called are also counted.
(2) If the sequence of statements in a block (including body blocks) contains a statement that cannot complete normally and another statement follows it, "unreachable statement" at the position of the statement immediately after the first such statement. At most one warning is issued per block. All nested blocks are examined, including those inside unreachable statements.
(3) When somewhere in the body of a function f there is a function call whose referent is a function g, "f calls g". main and the functions that can be reached from main by following the "calls" relation one or more times are called "reachable functions". For each function that is not reachable, "function '<name>' is never called" at its name position.
The warnings are sorted in ascending order of position (no two warnings have the same position).

* 6. Removal of unneeded functions and constant folding
- The functions that are not reachable (5 (3)) are removed. The subsequent processing (7 to 10) handles only reachable functions.
- Constant folding is performed on the initializers of the global variables (in declaration order) and on the bodies of the reachable functions (in source order). Each time a folding rule is applied once, the "fold count" is increased by 1.
- A "literal" is an expression that is an integer literal (whose value is an integer) or true or false (whose value is a boolean). The position of a literal newly created by folding is the position of the expression it replaces.
(1) Folding expressions
To fold an expression, its subexpressions are folded first (for a binary operation the left operand first, for a function call the arguments from left to right), and then the following rules are examined on the result.
- Unary operation: for "-", if the operand is an integer literal with value v and -v is in the int range, it is replaced by an integer literal with value -v. For "!", if the operand is true or false, it is replaced by the literal of its negation.
- Binary operation: only the first one of the following a to d that applies is applied. Below, e is an arbitrary expression, and 0 and 1 are integer literals with those values.
  a. If both operands are literals and the result of the operation can be determined, the operation is replaced by the literal of the result. For +, - and *, the result can be determined when it is in the int range; for / and %, when the right operand is not 0 and, in addition for /, the quotient (truncating division) is in the int range (the result of % is the remainder defined in 1). For the comparisons == != < <= > >= and for && ||, the result can always be determined (== and != may also compare two boolean values).
  b. "false && e" is replaced by the literal false, and "true || e" by the literal true.
  c. "true && e", "false || e", "0 + e" and "1 * e" are replaced by e.
  d. "e + 0", "e - 0", "e * 1", "e / 1", "e && true" and "e || false" are replaced by e.
(2) Folding statements
All expressions in a statement (initializers, the index and right-hand side of an assignment, the function call of a call statement, the arguments of a print statement, the expression of a return statement, conditions) are folded, and the statements in a block, the then statement, the else statement, the body statement, and the initialization and update of a for statement are folded in the same way. However, in the following two cases the whole statement is replaced.
- If statement: if the result of folding the condition is true, the whole if statement is replaced by the then statement; if it is false, by the else statement (or by an "empty statement" if there is no else statement) (the fold count is increased by 1). The statement used for the replacement is folded before it is used, and the statement that is not used is not folded.
- While statement: if the result of folding the condition is false, the whole while statement is replaced by an empty statement (the fold count is increased by 1). The body statement is not folded.
An "empty statement" is a statement that generates no code.

* 7. Code generation
(1) VM storage and instructions
The VM has the following storage.
- Global area: an area of integers in a row. The global variables are placed in declaration order, packed from cell number 0, and the number of the first cell of a variable is its "address". A variable that is not an array occupies 1 cell, and an array of size n occupies n cells. The total number of cells occupied by the global variables is the "size of the global area".
- Operand stack: a stack onto which integers are pushed.
- Frame stack: one frame is pushed each time a function is called. A frame has a "local area" consisting of integers in a row and a "return address". The cells of the local area are called "slots" and are numbered 0, 1, ... from the beginning.
The VM has the following 31 instructions. An instruction has an "instruction name" and zero to two integer "operands" (the letters after the instruction name in the table below are the operands). The details of their behaviour are defined in 10.
  PUSH c         Pushes the integer c.
  POP            Removes one value.
  LOADG a        Pushes the value at cell a of the global area.
  STOREG a       Pops one value and writes it to cell a of the global area.
  LOADL k        Pushes the value of slot k of the current frame.
  STOREL k       Pops one value and writes it to slot k of the current frame.
  LOADA a n      Pops an index and pushes the value of that element of the array with address a and size n.
  STOREA a n     Pops a value and then an index, one at a time, and writes the value to that element of the array with address a and size n.
  ADD SUB MUL DIV MOD    Binary arithmetic operations.
  LT LE GT GE EQ NE      Binary comparisons.
  NEG            Negates the sign.
  NOT            Logical negation.
  JUMP t         Moves to code address t.
  JUMPF t        Pops one value and moves to code address t if it is 0.
  JUMPT t        Pops one value and moves to code address t if it is not 0.
  CALL t n       Calls the function starting at code address t with n arguments.
  ENTER m        Sets the length of the local area of the current frame to m.
  RET            Returns to the caller.
  RETV           Returns a value and returns to the caller.
  READ           Pushes the next integer of the input sequence.
  PRINT n        Outputs n values on one line.
  HALT           Stops.
JUMP, JUMPF and JUMPT are called "jump instructions", and their operand the "target". JUMPF and JUMPT are called "conditional jump instructions"; the "inverse" of JUMPF is JUMPT, and the inverse of JUMPT is JUMPF. LT, LE, GT, GE, EQ and NE are called "comparison instructions"; LT and GE, LE and GT, and EQ and NE are each other's "negation". JUMP, RET, RETV and HALT are called "unconditional transfers".
Each instruction has one source position (defined in (4) to (6)).
(2) Units and code addresses
The code is a sequence of "units". The first unit is the "initialization unit", whose name is "<init>". It is followed by one unit for each reachable function, in the source order of the functions. The name of a function's unit is the name of the function. The instructions in a unit are given "indices within the unit" 0, 1, ... from the beginning. During code generation and the peephole optimization of 8, targets are expressed as indices within the unit. A jump instruction jumps only within the same unit. If the number of instructions of the unit is n, a target is between 0 and n inclusive (target n denotes the place just after the last instruction of the unit).
The instructions of the whole code are given "code addresses" 0, 1, ... from the beginning, in the order in which the units are arranged. The code address of the first instruction of a unit is called the "start address" of the unit. In the listing and in the VM, targets are expressed as the code address (start address of the unit) + (index within the unit), and the t of CALL is the start address of the unit of the called function.
(3) Notation for generation
Below, [[e]] denotes the code of an expression e (when executed, it pushes one value, the value of e), and [[S]] the code of a statement S; the code items separated by commas are generated in that order. "L:" is a "label", and stands for the index within the unit of the next instruction generated after that place (or the number of instructions of the unit if no instruction follows). For a jump instruction to a label whose place is not yet determined, the target is written in when the place of the label is determined (backpatching).
(4) Generating units
- Initialization unit: for each global variable that has an initializer, in declaration order, generate [[initializer]], STOREG (address of that variable) (the position of the STOREG is the name position of the variable). Then generate CALL (start address of main's unit) 0 and HALT (both with the name position of main as their position).
- Function unit: first, slots 0, 1, ... are assigned to the parameters from left to right, and then the declaration statements in the body (including declaration statements of for initializations, and excluding those that no longer exist after the replacements of 6, that is, those inside a statement that was replaced with an empty statement or that was not used for the replacement) are assigned one slot each, with the following numbers, in source order. Separate declaration statements get separate slots even if their names are the same, and slots are never reused after a scope ends. Let m be the number of slots. Generate ENTER m (whose position is the name position of the function), then generate the code of the statements in the body block in order, and if the return type is void, finally generate RET (whose position is the position of the "}" of the body block).
(5) Code of expressions (the position of an instruction is the position of the expression unless stated otherwise)
- Integer literal c: PUSH c. true: PUSH 1. false: PUSH 0.
- Variable x: if x is a global variable, LOADG (address of x); if it is a parameter or local variable, LOADL (slot of x).
- Array element x[e]: [[e]], LOADA (address of x) (size of x).
- read: READ.
- Function call f(e1, ..., en): [[e1]], ..., [[en]], CALL (start address of f's unit) n.
- Unary operations -e, !e: [[e]], followed by NEG and NOT respectively.
- a && b: [[a]], JUMPF L1, [[b]], JUMP L2, L1: PUSH 0, L2:.
- a || b: [[a]], JUMPT L1, [[b]], JUMP L2, L1: PUSH 1, L2:.
- Other binary operations a op b: [[a]], [[b]], followed by ADD SUB MUL DIV MOD LT LE GT GE EQ NE when op is + - * / % < <= > >= == != respectively.
(6) Code of statements (the position of an instruction is the position of the statement unless stated otherwise)
- Declaration statement (name x): if there is an initializer e, [[e]], STOREL (slot of x). Otherwise PUSH 0, STOREL (slot of x). The position of the STOREL and of the PUSH 0 (when there is no initializer) is the name position.
- Assignment statement: if there is no index, [[right-hand side]], followed by STOREG (its address) if the assignment target is a global variable, and STOREL (its slot) otherwise. If there is an index, [[index]], [[right-hand side]], STOREA (address of the assignment target) (size of the assignment target).
- Call statement: [[function call or read]], followed by POP for a call to a function whose return type is not void and for read.
- Print statement print(e1, ..., en): [[e1]], ..., [[en]], PRINT n.
- If statement if (c) S (without else): [[c]], JUMPF L1, [[S]], L1:.
- If statement if (c) S1 else S2: [[c]], JUMPF L1, [[S1]], JUMP L2, L1: [[S2]], L2:.
- While statement while (c) S: L1: [[c]], JUMPF L2, [[S]], JUMP L1, L2:. In S, a break statement for this while statement is JUMP L2, and a continue statement is JUMP L1.
- For statement for (I; C; U) S: [[I]], L1: [[C]], JUMPF L3, [[S]], L2: [[U]], JUMP L1, L3:. If there is no initialization I or update U, nothing is generated for that part. If there is no condition C, [[C]] and JUMPF L3 are not generated. In S, a break statement for this for statement is JUMP L3, and a continue statement is JUMP L2.
- A break statement or continue statement is for the innermost while statement or for statement that contains it. The position of its JUMP is the position of the break statement or continue statement.
- Return statement: if there is an expression e, [[e]], RETV. Otherwise RET.
- Block: generate the code of the statements inside in order. Empty statement: generate nothing.
The sequence of units after the initialization unit and the unit of each function have been generated is called the "code before optimization".

* 8. Peephole optimization
The following rules are applied to each unit of the code before optimization, independently for each unit.
(1) Terms
Let n be the number of instructions of the unit, and let T be the set of the targets of all jump instructions in the unit. The instruction at index i is called A and the instruction at index i+1 (when i+1 < n) is called B; when B exists and i+1 is not contained in T, "B is free". A conditional jump instruction "jumps" on a value c means c = 0 for JUMPF and c != 0 for JUMPT.
To "delete" the instruction at index p means to remove that instruction, shift the indices of the following instructions down by 1, and decrease by 1 the target of every jump instruction whose target is greater than p (a jump instruction whose target was p keeps the target p, which now points to the instruction that was after the deleted instruction). To "replace" an instruction means to make the instruction at that index a new instruction; the targets of the other instructions do not change.
(2) Rules
For an index i, the following 7 rules are examined in this order. The text in parentheses is the name of the rule.
 1 (const-jump): when A is PUSH c, B is a conditional jump instruction (target t), and B is free. If B jumps on the value c, replace A with JUMP t (with the position of B) and then delete B. If it does not jump, delete B and then delete A.
 2 (not-compare): when A is a comparison instruction, B is NOT, and B is free. Replace A with its negated comparison instruction (with the position of A) and delete B.
 3 (not-jump): when A is NOT, B is a conditional jump instruction (target t), and B is free. Replace A with the inverse conditional jump instruction of B (target t, with the position of B) and delete B.
 4 (invert-branch): when A is a conditional jump instruction with target i+2, B is JUMP (target t), and B is free. Replace A with the inverse conditional jump instruction of A (target t, with the position of A) and delete B.
 5 (thread): when A is a jump instruction (target t) and t < n. If the instruction at index t is JUMP (target u), then u is the "new target"; if the instruction at index t is PUSH c, t+1 < n, and the instruction at index t+1 is a conditional jump instruction (target u), then the "new target" is u if that instruction jumps on the value c, and t+2 if it does not. If there is a new target and it differs from t, change the target of A to the new target (rule 5 applies only in this case).
 6 (jump-next): when A is a jump instruction with target i+1. If A is JUMP, delete A; if it is a conditional jump instruction, replace A with POP (with the position of A).
 7 (unreachable): when A is an unconditional transfer and B is free. Delete B.
(3) Procedure
Repeat the following until no rule applies at any index: recompute T, find the smallest index i at which at least one rule applies, apply once the first rule that applies at that i, and increase the "application count" of that rule by 1.
The sequence of units after this procedure has been performed on all units is called the "code after optimization". For the code after optimization, the code addresses and start addresses are reassigned, and the t of each CALL is set to the new start address.

* 9. Function table and control flow
For each unit of the code after optimization, the following are determined (in terms of indices within the unit; n is the number of instructions of the unit).
(1) Basic blocks: index 0, the targets of all jump instructions that are less than n, and the indices following jump instructions and unconditional transfers that are less than n are the "leaders" of basic blocks. The leaders are sorted in increasing order and named B0, B1, .... Each basic block extends from its leader to the instruction just before the next leader (for the last basic block, to the last instruction of the unit). Letting e be the index of the last instruction of a basic block, its "successors" are as follows. If the last instruction is JUMP, the basic block of the target; if it is a conditional jump instruction, the basic block of index e+1 and the basic block of the target, in this order (only one if the two are the same); if it is RET, RETV or HALT, none; for any other instruction, the basic block of index e+1. However, index n (just after the last instruction of the unit) is not included among the successors.
(2) Stack depth: the change in the number of values on the operand stack when an instruction is executed is the "stack effect" of the instruction. PUSH, LOADG, LOADL and READ have +1; POP, STOREG, STOREL, JUMPF, JUMPT, RETV, the binary arithmetic operations (ADD SUB MUL DIV MOD) and the comparison instructions have -1; STOREA has -2; LOADA, NEG, NOT, JUMP, ENTER, RET and HALT have 0; CALL t n has -n (-n+1 if the return type of the called function is not void); and PRINT n has -n. The instructions that may be executed after the instruction at index i are, among the instruction at index i+1 (when the instruction at index i is not an unconditional transfer) and the instruction at the target (when it is a jump instruction), those whose index is less than n. The depth before the instruction at index 0 is 0, and if the depth before an instruction is d, the depth before an instruction that may be executed after it is d + (the stack effect of that instruction) (whichever path is followed, the depth before each instruction is the same). For each instruction that can be reached from the instruction at index 0 by following instructions that may be executed next, compute (the depth before that instruction) + (the stack effect of that instruction); the maximum of these (but at least 0) is the "stack depth" of the unit.
(3) Recursion: when one can return to a function f by following the "calls" relation (5 (3)) from f one or more times, f is said to be "recursive".

* 10. Execution by the virtual machine
For a program that compiled, the code after optimization is executed as follows. This is called the "main run". Next, the code before optimization is executed in the same way (with the code addresses of the code before optimization). This is called the "comparison run", and its result is used only for the "executed before peephole" and "behaviour" lines of stats.txt ([Output files]).
(1) Initial state: pc (the code address of the next instruction to execute) is 0, all values of the global area are 0, the operand stack and the frame stack are empty, the read position in the input sequence is at the beginning, the executed-instruction count is 0, and the output is empty.
(2) The following a and b are repeated until HALT is executed or a runtime error occurs.
 a. If the executed-instruction count is 100000, it is the runtime error "instruction limit exceeded" at the instruction at code address pc (this instruction is not executed and not counted).
 b. Increase by 1 the executed-instruction count and the "execution count" of the instruction at code address pc, and execute that instruction as follows. Unless stated otherwise, pc is increased by 1. Below, to "pop" means to remove the top value of the operand stack and use it. The "current frame" is the top frame of the frame stack.
 - PUSH c: push c. POP: remove one value.
 - LOADG a: push the value at cell a of the global area. STOREG a: pop a value and write it to cell a of the global area.
 - LOADL k: push the value of slot k of the current frame. STOREL k: pop a value and write it to slot k of the current frame.
 - LOADA a n: pop an index i. If i < 0 or i >= n, it is the runtime error "index <i> out of bounds for array of size <n>". Otherwise, push the value at cell a+i of the global area. STOREA a n: pop a value v, and then pop an index i. The same range check as LOADA is performed, and if there is no error, v is written to cell a+i of the global area.
 - ADD, SUB, MUL, DIV, MOD: pop a value b, and then pop a value a. For DIV and MOD, if b = 0, it is the runtime error "division by zero". ADD, SUB, MUL and DIV compute a+b, a-b, a*b and the quotient of the truncating division of a by b respectively; if it is not in the int range, it is the runtime error "integer overflow", and if it is in the range, it is pushed. MOD pushes the remainder defined in 1 (the remainder is always in the int range).
 - NEG: pop a value a; if -a is not in the int range, "integer overflow"; if it is, push -a. NOT: pop a value a; push 1 if a = 0, and 0 otherwise.
 - Comparison instructions: pop a value b, and then pop a value a; push 1 if a < b for LT, a <= b for LE, a > b for GT, a >= b for GE, a = b for EQ, a != b for NE holds, and 0 if it does not hold.
 - JUMP t: set pc to t. JUMPF t: pop a value, and if it is 0, set pc to t. JUMPT t: pop a value, and if it is not 0, set pc to t.
 - CALL t n: if the frame stack already holds 100 frames, it is the runtime error "call depth limit exceeded". Otherwise, remove the top n values from the operand stack, arrange them in the order in which they were pushed (with the value that was on top placed last) as the local area, push a frame with that local area and return address pc+1, and set pc to t. At this time, increase by 1 the "call count" of the unit starting at code address t (the called function) and the "call count" of the pair (the unit containing this CALL instruction, the called unit).
 - ENTER m: append 0s to the end of the local area of the current frame to make its length m.
 - RET, RETV: remove one frame and set pc to the return address of that frame (for RETV, the value at the top of the operand stack stays there as the return value).
 - READ: if the whole input sequence has already been read, it is the runtime error "read past end of input". Otherwise, push the next integer of the input sequence and advance the read position by one.
 - PRINT n: remove the top n values from the operand stack, and append to the end of the output one line in which they are written separated by spaces, in the order in which they were pushed.
 - HALT: finish execution (normal termination).
(3) Each time the execution of an instruction finishes without a runtime error, the number of values on the operand stack at that time is examined, and its maximum (initially 0) is the "maximum stack". Also, the maximum number of frames (initially 0) is the "maximum call depth".
(4) When a runtime error occurs, its message, the instruction that caused the error (in a, the instruction at code address pc), and the frame stack at that point are recorded, and execution finishes. An instruction that caused an error in b is also counted in the executed-instruction count and in its execution count.

[Output files]
In each of the four files, for each program in program order, write one heading line "== program <name> ==" followed by the lines defined below (in stats.txt, an overall summary is added at the end). No empty lines are written.

* output/listing.txt
For a program that failed to compile, write only the single line "not compiled" after the heading. For a program that compiled, write the following (1) to (6) in this order.
(1) Global variables: if there are no global variables, the single line "globals: none"; otherwise the line "globals:" followed, in declaration order, by "  <address> <name> <type>" for each global variable. <type> is int, bool, or, for an array, "int[<size>]".
(2) Function table: the line "functions:" followed, in the order of the units of the code after optimization, by the following one line for each unit.
  "  <unit name><signature> address=<A1>-><A2> size=<S1>-><S2> slots=<m> stack=<d> blocks=<b> calls=<callees>"
  - <signature> is, for a function unit, one space followed by "<return type>(<parameter types separated by commas>)" (e.g. " int(int,bool)", " void()"), and empty for the initialization unit.
  - <A1> and <A2> are the start addresses of the unit in the code before optimization and in the code after optimization, and <S1> and <S2> are the numbers of instructions of the unit before optimization and after optimization.
  - <m> is the number of slots (the operand of ENTER) for a function unit, and 0 for the initialization unit. <d> is the stack depth of the unit, and <b> the number of basic blocks of the unit (9).
  - <callees> is, for a function unit, the names of the functions that the function calls (5 (3)) in ascending order separated by commas ("-" if there are none), and "main" for the initialization unit.
  - If the function is recursive, " recursive" is added at the end of the line.
  For a function unit, this line is followed, in slot-number order, by "    slot <number> <name> <type>" for each slot. <name> and <type> are the name and type of the parameter or local variable to which that slot was assigned.
(3) References: the line "references:" followed by "  <name> defined <line number> used <line numbers>" for the global variables (in declaration order) and then the functions (in source order, including those removed in 6). After defined comes the line number of the name position, and after used come the line numbers of the positions of the references (4 (1)) whose referent is that global variable or function, without duplicates, in ascending order, separated by spaces ("-" if there are no references).
(4) Code before optimization: the line "before peephole: <number of instructions> instructions" followed, in unit order, by one line consisting of the unit name followed by ":" (e.g. "<init>:", "main:") and the lines of the instructions of that unit. An instruction line is the code address right-aligned in 5 characters (missing digits are filled with spaces at the front), followed by two spaces, the instruction name, and each operand preceded by one space (e.g. "   17  JUMPF 23"). Targets and the t of CALL are written as code addresses. Hereafter, the string consisting of the instruction name and the operands separated by single spaces (e.g. "JUMPF 23") is called the "spelling" of the instruction.
(5) Code after optimization: the line "after peephole: <number of instructions> instructions" followed by the code after optimization in the same form as (4).
(6) Control flow: the line "control flow:" followed, in the order of the units of the code after optimization, by one line "  <unit name>" and, for each basic block of that unit, "    B<k> <code address of the first instruction>-<code address of the last instruction>". If there are successors, this is followed by " -> " and the names of the successor basic blocks in the order of 9 (1), separated by spaces (e.g. "    B1 14-17 -> B2 B4").

* output/output.txt
For each program, after the heading, write the lines output by PRINT in the main run, in order. For a program that failed to compile, write only the heading; for a program that ended with a runtime error, write only the lines output before the error occurred.

* output/diagnostics.txt
For each program, after the heading, write the following lines.
- A program that failed to compile: the line "<kind> error <position>: <message>" (e.g. "syntax error 4:5: unexpected 'for'"), the two lines of the "position display" (see below) for the position of the error, and finally "status: compile error".
- A program that compiled: first, the warnings in order in the form "warning <position>: <message>". When the main run ended with a runtime error, this is followed by "runtime error <position>: <message> in <unit name>" (<position> is the position of the instruction that caused the error, and <unit name> is the name of the unit containing that instruction), the two lines of the position display for that position, and the "caller lines" (see below). Finally, write "status: ok" if the main run terminated normally, and "status: runtime error" if it ended with a runtime error.
- The "position display" consists of two lines: two spaces followed by the source line with the line number of that position, written as is; and two spaces followed by (column - 1) spaces and "^".
- "Caller lines": for each frame of the frame stack at the time of the error, from the top (the newest) downward, excluding the bottom one (the oldest), write "  called from <name of the unit containing that CALL instruction> at <position of that CALL instruction>" for the CALL instruction that created that frame (the instruction at the code address one less than the return address of that frame). However, only up to the first 5 lines are written; if there are more, "  ... <number of lines not written> more" is written after the 5 lines.

* output/stats.txt
For each program, after the heading, write the single line "not compiled" for a program that failed to compile, and the following lines in this order for a program that compiled.
  code: <number of instructions of the code before optimization> -> <number of instructions of the code after optimization>
  folds: <fold count>
  peephole: <total of the application counts of the peephole optimization rules>
  (7 lines "  <rule name> <application count>", one per rule, in order of rule number)
  executed: <executed-instruction count of the main run>
  executed before peephole: <executed-instruction count of the comparison run>
  behaviour: <same or different>
  max call depth: <maximum call depth of the main run>
  max stack: <maximum stack of the main run>
  opcodes:   (followed by the lines described below)
  functions:   (followed by the lines described below)
  calls:   (followed by the lines described below)
  hot lines:   (followed by the lines described below)
  coverage: <number of executed lines> of <number of lines with code> lines
  not executed: <line numbers>
  hot spots:   (followed by the lines described below)
The rule names and application counts are totals over all units of that program. Each of the following lines refers to the main run.
- behaviour: "same" if the main run and the comparison run produced the same sequence of output lines and, moreover, both terminated normally or both ended with a runtime error with the same message; "different" otherwise.
- opcodes: for each instruction name whose total execution count is 1 or more, "  <instruction name> <total execution count of the instructions with that instruction name>", in descending order of count, ties broken by ascending instruction name.
- functions: for each function unit of the code after optimization (excluding the initialization unit), "  <unit name> calls=<call count of that unit (CALL in 10 (2))> executed=<total execution count of the instructions of that unit>", in descending order of the executed value, ties broken by ascending name.
- calls: for each pair (calling unit, called unit) whose call count is 1 or more, "  <name of the calling unit> -> <name of the called unit> <call count>", in descending order of call count, ties broken by ascending name of the calling unit, and further ties by ascending name of the called unit.
- The line number of the position of an instruction of the code after optimization is the "line" of that instruction. A line number that is the line of some instruction is called a "line with code", and for each line with code, the total execution count of the instructions whose line it is, is the "line execution count". hot lines: for the first 5 (all if there are fewer than 5) of the lines with code whose line execution count is 1 or more, sorted in descending order of line execution count, ties broken by ascending line number, write "  line <line number>: <line execution count>".
- coverage: <number of lines with code> is the number of lines with code, and <number of executed lines> is the number of those whose line execution count is 1 or more. not executed: the line numbers of the lines with code whose line execution count is 0, in ascending order, separated by spaces ("none" if there are none).
- hot spots: for the first 5 (all if there are fewer than 5) of the instructions whose execution count is 1 or more, sorted in descending order of execution count, ties broken by ascending code address, write "  pc=<code address> count=<execution count> <spelling of the instruction>".
After all programs, write the following overall summary.
  == summary ==
  programs: <number of programs>
  compiled: <number of programs that compiled>
  compile errors: lexical <count> syntax <count> semantic <count>
  runtime errors: <number of programs whose main run ended with a runtime error>
  folds: <total of the fold counts>
  peephole: <total of the application counts>
  (7 lines "  <rule name> <total of the application counts over all programs>", one per rule, in order of rule number)
  executed: <total of the executed-instruction counts of the main runs>
  (followed by the table described below)
The three counts of compile errors are the numbers of programs that failed to compile, counted by kind of error. The totals from folds on are totals over the programs that compiled.
The table consists of a header line (whose 5 column values are program, status, code, executed, output) and one line for each program in program order. The 5 values of a program line are the name of the program, the status, the number of instructions of the code after optimization, the executed-instruction count of the main run, and the number of lines output in the main run. The status is "ok" (normal termination) or "runtime error" for a program that compiled, and "<kind> error" (e.g. "syntax error") for a program that failed to compile; the remaining 3 values of a program that failed to compile are "-". The width of each column is the maximum number of characters of the values in that column (including the header); the 1st and 2nd columns are left-aligned (padded with spaces on the right), and the 3rd to 5th columns are right-aligned (padded with spaces on the left); each line is written as two spaces followed by the 5 values separated by two spaces each.

[Source files]
Divide the source files into the following 6 roles (file names may follow the conventions of each language).
- main: the overall flow. Reading the input files and splitting them into programs, warnings (5), removal of unneeded functions and constant folding (6), peephole optimization (8), stack depth, basic blocks and control flow, and the recursion test (9), arranging the units and reassigning code addresses, building the function table, references and disassembly listing, invoking the main run and the comparison run, building the position displays and caller lines, aggregating the statistics and building the overall summary table, and writing the four output files. It handles the largest part of the processing.
- lexer: lexical analysis (2). Tokens and lexical errors.
- parser: parsing (3). Recursive-descent parsing according to the grammar, abstract syntax tree nodes and their positions, syntax errors.
- semantic: semantic analysis (4). The table of global names and the scopes, checking expressions and statements, the order of checks and the errors, recording references and read accesses, recording the "calls" relation, and determining whether statements can complete normally.
- codegen: code generation (7). Assignment of global-area addresses and slots, generation of the instructions for expressions and statements, labels and backpatching.
- vm: the virtual machine (10). Execution of instructions, detection of runtime errors, and recording of the executed-instruction count, execution counts, call counts, maximum stack and maximum call depth.

[Constraints]
- program.src has between 2 and 1000 lines, and each line has at most 100 characters. There are between 1 and 40 programs. No source line starts with "#program ".
- An integer literal has at most 18 digits. The size of an array is at most 1000, and the size of the global area is at most 2000.
