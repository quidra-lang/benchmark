[Overview]
Write a program that performs agglomerative hierarchical clustering on observation data, presents the result as a dendrogram and in other forms, and evaluates it. Each observation consists of an ID, a known label (for example, the site where a soil sample was collected) and several numeric features. After standardizing the features if requested, the program computes the distances between observations and computes the merges for seven linkage methods (single, complete, average, weighted, centroid, median, ward), all through the Lance-Williams update formula. It writes the merge record (in SciPy linkage format), a dendrogram drawn with characters, the tree in Newick format, and the results of cutting by height and by number of clusters, and evaluates them with the cophenetic correlation coefficient, inconsistency coefficients, silhouette coefficients, the Dunn index, the Calinski-Harabasz index, the adjusted Rand index against the labels (as an irreducible fraction), and more. It also cross-checks single linkage with a minimum spanning tree, compares distance types, and compares linkage methods with each other. Finally, it selects the linkage method and number of clusters that best reproduce the labels, and examines the cluster summaries, the feature contributions, the change when each feature is removed one at a time, a refinement by the k-means method, and the stability under subsamples.
The input is two files in the input/ folder (observation data, settings), and the results are written to six files in the output/ folder. Nothing is written to standard output. The only random numbers used are those of the MINSTD generator defined in this statement. Since every rule is fixed, the result is uniquely determined.

[Input files]
There are two input files: input/data.csv and input/params.txt. Every file consists of ASCII characters only, and every line (including the last one) ends with a newline (LF). There is no whitespace at the start or end of a line, and there are no empty lines. Values are separated by a comma in data.csv and by a single ASCII space in params.txt.
An integer is a decimal number without extra leading zeros. A decimal is a decimal number written as, in this order, "-" (only for a negative number), a sequence of one or more digits (the integer part), ".", and a sequence of one or more digits (the fractional part) (e.g. 6.25, 0.5, -1.0). Exponent notation is not used.

* input/data.csv (observation data)
Line 1 is the header line: id,label followed by the feature names, separated by commas (id,label,<feature name 1>,...,<feature name p>). A feature name is a string of 1 to 12 lowercase English letters, and the names are mutually distinct.
Each line from line 2 on is one observation: the observation's ID, its label and the values of its p features, in this order, separated by commas.
- An ID is a string of 1 to 8 uppercase English letters and digits, different for each observation.
- A label is a string of 1 to 12 lowercase English letters and represents the known classification of the observation. Labels are not used for clustering, only for evaluation.
- Feature values are decimals.
Let n be the number of observations and p the number of features. Number the observations 0, 1, ..., n - 1 in the order of the lines of the file (starting from 0). This number is called the "observation number", and this order the "observation order". The value of feature f (f = 1, ..., p, in header order) of observation i is written x_i,f, and this order is called the "feature order".
The distinct labels arranged in lexicographic order (compared by smaller character code first; if one is a prefix of the other, the shorter one comes first) are called the "classes", and their count is L. The classes are numbered 0, 1, ..., L - 1 in this order, which is called the "class order". The class number of the label of observation i is written t_i.

* input/params.txt (settings)
It consists of the following 12 lines, in this order. Each line is an uppercase keyword followed by one or more values, each separated by a single ASCII space.
- DISTANCE name: the distance type used for the main analysis (one of euclidean, manhattan, correlation).
- STANDARDIZE s: whether to standardize the features (yes or no).
- LINKAGES l_1 l_2 ...: the list of linkage methods to use (1 to 7 mutually distinct ones out of single, complete, average, weighted, centroid, median, ward, in any order). The order of this list is called the "linkage order".
- CUT_HEIGHTS theta_1 theta_2 ...: the list of cut heights (one or more positive decimals, in any order). The j-th value theta_j (j = 1, 2, ...) is called "cut height j".
- CUT_K k_1 k_2 ...: the list of numbers of clusters to create by cutting (mutually distinct integers from 2 to n, in increasing order).
- INCONSISTENCY e V: the depth e of the inconsistency coefficient (an integer >= 1) and the number V of last merges for which inconsistency coefficients are computed (an integer from 1 to n - 1).
- GAP_MAX_K kmax: the upper limit for the recommended number of clusters (an integer from 2 to n - 1).
- LIST_SIZE R: the number of late-joining observations and of observations with small silhouette values to list (an integer from 1 to n).
- DENDROGRAM_WIDTH W: the width of the dendrogram in the height direction (an integer from 10 to 100).
- COMPARE_LINKAGE lc: the linkage method used for the comparison of distance types (one of single, complete, average, weighted).
- SUBSAMPLES B P x0: the number B of subsamples (an integer >= 1), the subsample size ratio P (an integer from 50 to 99, in percent), and the random seed x0 (an integer from 1 to 2147483646).
- REFINE_ITERATIONS imax: the maximum number of iterations of the refinement by the k-means method (an integer >= 1).
centroid, median and ward are included in LINKAGES only when DISTANCE is euclidean.

[Processing]
* 1. Notation and computation rules
- All real-number computations are done in double precision (IEEE 754 64-bit floating point). Input decimals are converted to double precision before use.
- sqrt is the square root, |t| is the absolute value of t, floor(t) is the largest integer <= t, and max and min are the maximum and minimum. a mod b is the remainder of dividing an integer a >= 0 by a positive integer b.
- Unless stated otherwise, a sum written as "sum" (sum_i, sum_g and so on) is accumulated one term at a time starting from 0, in observation order for observations, in feature order for features, in order of cluster number for clusters, and in pair order for observation pairs. Multiplications and divisions in a formula are evaluated from left to right in the written order, and additions and subtractions are also evaluated from left to right in the written order.
- An "observation pair" is a pair (i, j) of observation numbers with 0 <= i < j <= n - 1; there are N = n * (n - 1) / 2 of them in total. The "pair order" is by increasing i, and for equal i by increasing j.
- The "4-digit value" of a real number v is v rounded to 4 decimal places (the same as the value written to the output files). Some comparisons use 4-digit values; such cases are always stated explicitly.
- Every rule that selects a maximum or minimum and every sorting rule always states how equal values are handled.
- Fractions a/b and c/d (b > 0, d > 0) are compared by comparing a * d and c * b. The absolute values of these products are below 2^53. The "value" of a fraction a/b is the result of the real division a / b.
- The "correlation coefficient" of two real sequences of the same length m, X = (X_1, ..., X_m) and Y = (Y_1, ..., Y_m), is Sxy / sqrt(Sxx * Syy), where mX = (sum X_k) / m, mY = (sum Y_k) / m, Sxy = sum (X_k - mX) * (Y_k - mY), Sxx = sum (X_k - mX) * (X_k - mX), Syy = sum (Y_k - mY) * (Y_k - mY) (sums in the order k = 1, ..., m).
- A list of the same number q of real numbers is called a "vector". The "squared distance" of vectors u = (u_1, ..., u_q) and w = (w_1, ..., w_q) is sum (u_f - w_f) * (u_f - w_f) (in the order f = 1, ..., q). The "centroid" of a collection of vectors is the vector whose each component is obtained by adding that component of the vectors of the collection in the order of the collection and dividing by the number of vectors.

* 2. Preprocessing and distances
(1) Feature statistics: for each feature f, compute the mean mean_f = (sum_i x_i,f) / n and the standard deviation sd_f = sqrt((sum_i (x_i,f - mean_f) * (x_i,f - mean_f)) / (n - 1)).
(2) Analysis vectors: if STANDARDIZE is yes, let z_i,f = (x_i,f - mean_f) / sd_f; if no, let z_i,f = x_i,f. v_i = (z_i,1, ..., z_i,p) is the "analysis vector" of observation i. Unless stated otherwise, centroids and squared distances are computed on analysis vectors.
(3) Distances: the distance between vectors u = (u_1, ..., u_q) and w = (w_1, ..., w_q) is defined for each type as follows.
- euclidean: sqrt(squared distance of u and w)
- manhattan: sum |u_f - w_f|
- correlation: with au = (sum u_f) / q, aw = (sum w_f) / q, du_f = u_f - au, dw_f = w_f - aw: 1 - (sum du_f * dw_f) / sqrt((sum du_f * du_f) * (sum dw_f * dw_f))
(All sums are in the order f = 1, ..., q.)
(4) Distance matrix: the distance matrix of a type has, for every observation pair (i, j), the distance of that type between v_i and v_j as its value. The value at (j, i) is the same as at (i, j), and the value at (i, i) is 0. The distance matrix of the DISTANCE type is written d, and its values d(i, j). Unless stated otherwise, "distance" means a value of d.

* 3. Data summary
(1) Distance range: find the observation pair with the smallest d(i, j) (if equal, the one earlier in pair order), the observation pair with the largest d(i, j) (if equal, the one earlier in pair order), and the mean distance (sum d(i, j)) / N (sum in pair order).
(2) Nearest neighbors: the nearest neighbor nn(i) of observation i is the observation j other than i with the smallest d(i, j) (if equal, the one with the smaller observation number). Compute the mean nearest-neighbor distance (sum_i d(i, nn(i))) / n and the number of mutual nearest-neighbor pairs (the number of observations i with i < nn(i) and nn(nn(i)) = i).
(3) Label partition: the partition that gives each observation i the cluster number t_i + 1 (cluster g corresponds to class g - 1) is called the "label partition"; perform the evaluation of section 7 on it (with distance matrix d).
(4) Feature correlations: the correlation coefficient of feature f and feature g is the correlation coefficient of the original value sequences (x_0,f, ..., x_(n-1),f) and (x_0,g, ..., x_(n-1),g) (the original values are used, not the analysis vectors).
(5) Distance histogram: let dmax be the maximum of d(i, j) over all observation pairs. The "bin" of an observation pair (i, j) is min(9, floor(10 * d(i, j) / dmax)). For each bin b = 0, 1, ..., 9, compute the lower end b * dmax / 10, the upper end (b + 1) * dmax / 10, the number cnt_b of pairs in bin b, and the bar length floor(cnt_b * 50 / cmax) (integer division; cmax is the maximum of cnt_0, ..., cnt_9).

* 4. Agglomerative hierarchical clustering
From the pairwise values delta(u, w) (a distance matrix) of m objects (numbered 0 to m - 1) and a linkage method, build a sequence of m - 1 merges by the following procedure. In the main analysis the objects are the observations and delta = d, but sections 10 and 12 use the same procedure with other distance matrices or objects.
(1) Clusters and IDs: initially, create a cluster consisting of object u alone, with ID u. The cluster created by the s-th merge (s = 1, ..., m - 1) has ID m + s - 1 (in the order m, m + 1, ...). Clusters not yet merged at a given moment are called "active clusters". The size of a cluster is the number of objects it contains.
(2) Values between clusters: keep a value D for each pair of active clusters. Initially, D(u, w) = delta(u, w) * delta(u, w) if the linkage method is centroid, median or ward, and D(u, w) = delta(u, w) otherwise.
(3) Merge: among the pairs (a, b) of active clusters (with IDs a < b), select the one with the smallest D(a, b) (if several pairs have the same value, the one with the smaller a, and if a is also equal, the one with the smaller b). Merge a and b into a new cluster c, and record the merge (a, b, height, size of c). The height is sqrt(D(a, b)) for centroid, median and ward, and D(a, b) otherwise.
(4) Update: for each active cluster k other than a and b, let
  D(k, c) = alpha_a * D(a, k) + alpha_b * D(b, k) + beta * D(a, b) + gamma * |D(a, k) - D(b, k)|
(the Lance-Williams update formula). With n_a, n_b, n_k the sizes of clusters a, b, k, the coefficients are as follows.
- single: alpha_a = 0.5, alpha_b = 0.5, beta = 0, gamma = -0.5
- complete: alpha_a = 0.5, alpha_b = 0.5, beta = 0, gamma = 0.5
- average: alpha_a = n_a / (n_a + n_b), alpha_b = n_b / (n_a + n_b), beta = 0, gamma = 0
- weighted: alpha_a = 0.5, alpha_b = 0.5, beta = 0, gamma = 0
- centroid: alpha_a = n_a / (n_a + n_b), alpha_b = n_b / (n_a + n_b), beta = -(n_a * n_b) / ((n_a + n_b) * (n_a + n_b)), gamma = 0
- median: alpha_a = 0.5, alpha_b = 0.5, beta = -0.25, gamma = 0
- ward: with t = n_a + n_b + n_k, alpha_a = (n_a + n_k) / t, alpha_b = (n_b + n_k) / t, beta = -n_k / t, gamma = 0
Mathematically, the values of the single and complete formulas equal the smaller and the larger of D(a, k) and D(b, k), respectively. Then remove a and b from the active clusters and add c.
(5) Repeat (3) and (4) until one active cluster remains (m - 1 times). The s-th merge is called "merge s", and its height is written h_s. The cluster created by merge s is called "node m + s - 1", and the cluster consisting of object u alone is called "leaf u". The two merged clusters are called the "children" of the created node. The last node created, node 2m - 2, is called the "root". The merges that created the children of a node come before the merge that created that node.

* 5. Tree structure
For the result of section 4, define the following (in the main analysis m = n and the objects are the observations).
(1) Minimum number: the minimum number of leaf u is u; the minimum number of a node is the smaller of the minimum numbers of its two children.
(2) Upper child and lower child: of the two children of a node, the one with the smaller minimum number is the "upper child" and the other is the "lower child".
(3) Leaf order: the sequence of object numbers obtained by starting from the root, where a node yields "the sequence of its upper child" followed by "the sequence of its lower child", and leaf u yields the sequence consisting of u alone. It is the top-to-bottom order of the dendrogram, and object 0 is always first.
(4) Maximum subtree height: 0 for a leaf; for the node created by merge s, the maximum of h_s and the maximum subtree heights of its two children. This is written M_s. With centroid and median, the height of a merge can be smaller than the height of a child's merge (an inversion), so M_s can differ from h_s.
(5) Joining height: the joining height of observation i is the height of the merge that has leaf i as a child.
(6) Cophenetic distance: the cophenetic distance c(i, j) of an observation pair (i, j) is the height of the merge that merged the cluster containing i and the cluster containing j (the merge at which i and j first enter the same cluster).
(7) Depth: the depth of a leaf is 0; the depth of a node is 1 plus the larger of the depths of its two children. The depth of the tree is the depth of the root.
(8) Contained objects: the objects contained in a node are the objects of all leaves below it. The size of a node is the number of objects it contains.

* 6. Flat clustering
(1) General procedure: select some of the merges. If a child of a selected merge is a node, the merge that created that node is always selected as well. Perform only the selected merges, in merge order, and the clusters remaining at the end are the resulting clusters.
(2) Numbering: number the resulting clusters 1, 2, ..., in order of the position in the leaf order of the first object appearing in each cluster, earliest first (the higher a cluster is in the dendrogram, the smaller its number). Assigning to each object the number of the cluster containing it is called a "partition", and the number of clusters is written G.
(3) Cut at height h: select all merges s with M_s <= h.
(4) Cut into k clusters: select merges 1, 2, ..., m - k. There are exactly k resulting clusters.

* 7. Evaluation of a partition
For a partition of the observations (clusters 1 to G) and a distance matrix delta, compute the following values. The set of observations belonging to cluster g is written C_g, and its count |C_g|. In what follows, "the evaluation" means (1) to (5) together with the ARI against the labels.
(1) Sizes: |C_1|, ..., |C_G|.
(2) Silhouette coefficient: when G >= 2, for each observation i, let C be the cluster containing i; if |C| = 1 then s_i = 0, otherwise
  a_i = (the sum of delta(i, j) over the observations j in C other than i) / (|C| - 1)
  b_i = (the minimum, over each cluster C_g other than C, of (the sum of delta(i, j) over the observations j in C_g) / |C_g|)
  s_i = (b_i - a_i) / max(a_i, b_i)
(sums in observation order). s_i is called the "silhouette value" of observation i, and (sum_i s_i) / n the "silhouette coefficient" of the partition. When G = 1 there is no value.
(3) Dunn index: let the diameter be (the maximum of delta over observation pairs in the same cluster; 0 if there is no such pair) and the separation be (the minimum of delta over observation pairs in different clusters); if G >= 2 and diameter > 0, the index is separation / diameter. Otherwise there is no value.
(4) WSS: compute the centroid of each cluster (the centroid of the analysis vectors of the observations in C_g, with the collection in observation order), and WSS = sum_i (squared distance between v_i and the centroid of the cluster containing i).
(5) CH (Calinski-Harabasz index): compute the overall centroid (the centroid of the analysis vectors of all observations), and BSS = sum_g |C_g| * (squared distance between the centroid of C_g and the overall centroid). If 2 <= G < n, CH = (BSS / (G - 1)) / (WSS / (n - G)); otherwise there is no value.
(6) Contingency table: the contingency table T of two partitions X and Y, which give each object the numbers X_u (0 to K1 - 1) and Y_u (0 to K2 - 1), is the table of K1 rows and K2 columns with T[a][b] = (the number of objects with X_u = a and Y_u = b). For a partition with cluster numbers g, the number g - 1 is used.
(7) Adjusted Rand index (ARI): for the contingency table T of two partitions X and Y of m objects, let C2(r) = r * (r - 1) / 2, and
  Ss = (the sum of C2(T[a][b]) over all a, b), Sr = (the sum of C2(r) over each row sum r of T), Sc = (the sum of C2(r) over each column sum r of T), Z = C2(m),
  numerator = 2 * (Z * Ss - Sr * Sc), denominator = Z * (Sr + Sc) - 2 * Sr * Sc.
If the denominator is 0, the ARI is 1/1. Otherwise it is the irreducible fraction obtained by dividing the numerator and the denominator by the greatest common divisor of the absolute value of the numerator and the denominator (the denominator becomes positive, and if the numerator is 0 it is 0/1). All of these are computed exactly with integers. "The ARI against the labels" is the ARI of the partition (X) and the partition that gives each observation i the number t_i (Y).
(8) Purity: for the contingency table T of the partition (X) and the classes (Y; observation i has number t_i), sum_g (the maximum of row g - 1 of T) is the "match count", and purity is match count / n.

* 8. Analysis per linkage method
For each linkage method in LINKAGES, perform the procedure of section 4 with d, and compute the following values.
(1) Cophenetic correlation coefficient: the correlation coefficient of the sequence of d(i, j) in pair order and the sequence of c(i, j) in pair order.
(2) Leaf path length: the sum of the distances between observations adjacent in the leaf order (added in leaf order).
(3) Inversions: the merges s (2 <= s <= n - 1) with h_s < h_(s-1).
(4) Gaps and recommended number: let U_1 <= U_2 <= ... <= U_(n-1) be M_1, ..., M_(n-1) sorted in increasing order. A cut at height h yields k clusters exactly when U_(n-k) <= h < U_(n-k+1). For k = 2, 3, ..., kmax, compute the gap gap_k = U_(n-k+1) - U_(n-k). The k whose gap_k has the largest 4-digit value (if equal, the smaller k) is the recommended number.
(5) Late-joining observations: the first R observations when the observations are sorted by decreasing joining height (if equal, by increasing observation number).
(6) Merge kinds and depth: the number of merges whose two children are both leaves, the number of merges with exactly one leaf child, the number of merges with no leaf child, and the depth of the tree.
(7) Purity at the number of labels: the purity of the partition of the cut into L clusters.
(8) Inconsistency coefficient: for a merge s and an integer q >= 0, define the sequence of heights H(s, q) as follows. If q = 0, it is the empty sequence. If q >= 1, it is h_s followed by, for the children of merge s in the order a (the smaller ID), b (the larger ID), H(s', q - 1) of the merge s' that created the child if the child is a node (nothing is appended if the child is a leaf). Let cnt be the number of values in the sequence H(s, e) and its mean mu = (the sum of the values of the sequence (in sequence order)) / cnt; if cnt = 1, the standard deviation is sigma = 0 and the coefficient = 0; if cnt >= 2, sigma = sqrt((sum (value - mu) * (value - mu)) / (cnt - 1)) (sum in sequence order) and the coefficient = (h_s - mu) / sigma. Compute this for merges s = n - V, ..., n - 1.
(9) Cuts: create the partition of the cut at each height theta_j, in order of cut height j, and the partition of the cut into each number k, in CUT_K order, and perform the evaluation of section 7 (with distance matrix d) on each of them. Also create the partition of the cut into L clusters (used in (7) and in section 11 (2)).

* 9. Cross-check with a minimum spanning tree
This is performed only when LINKAGES contains single.
(1) Prim's method: with the observations as vertices and d as edge weights, build a minimum spanning tree by the following procedure. Initially put only observation 0 into the tree, and for each observation u not in the tree let key(u) = d(0, u) and parent(u) = 0. Repeat the following n - 1 times. Select the observation v not in the tree with the smallest key (if equal, the one with the smaller observation number), put it into the tree, and record the edge connecting parent(v) and v (with weight key(v)). Next, for each observation u not in the tree, if d(v, u) < key(u), let key(u) = d(v, u) and parent(u) = v. The edges are called edge 1, 2, ..., n - 1 in the order they were recorded.
(2) Total weight: the sum of the edge weights (added in edge order).
(3) Height check: match if, for every s = 1, ..., n - 1, the absolute difference between the s-th element of the sequence of edge weights sorted in increasing order and h_s of single is <= 0.000000001; otherwise mismatch.
(4) Nearest-neighbor edges: the number of observations i such that the edge connecting i and nn(i) is an edge of the minimum spanning tree (in either direction).
(5) Partition check: for each k in CUT_K, sort the edges by increasing weight (if equal, by increasing edge number), and find the connected components when the observations are connected using only the first n - k edges. match if, for every observation pair, whether the two belong to the same connected component agrees with the partition of the cut of single into k clusters (whether the two belong to the same cluster); otherwise mismatch.

* 10. Comparison of distance types
For each type, in the order euclidean, manhattan, correlation, do the following. Let delta be the distance matrix of that type, and perform the procedure of section 4 with delta and the linkage method lc of COMPARE_LINKAGE. Compute the correlation coefficient (cophenetic correlation coefficient) of the sequence of delta(i, j) in pair order and the sequence of cophenetic distances. Also, for the partition of the cut into L clusters, compute the silhouette coefficient with delta and the ARI against the labels.

* 11. Comparison and selection of linkage methods
(1) Correlation of cophenetic distances: for each pair (l, l') of linkage methods, compute the correlation coefficient of the sequence of cophenetic distances of l and that of l' (both in pair order).
(2) Agreement: for each pair (l, l') of linkage methods, compute the ARI of the partitions of the cut into L clusters of l and of l'.
(3) Ranking by cophenetic correlation coefficient: sort the linkage methods by decreasing 4-digit value of the cophenetic correlation coefficient (if equal, in linkage order).
(4) Best linkage method per k: for each k in CUT_K, the linkage method whose partition of the cut into k clusters has the largest ARI against the labels (if equal, the one earlier in linkage order).
(5) Best k per linkage method: for each linkage method, the k in CUT_K whose partition of the cut into k clusters has the largest 4-digit value of the silhouette coefficient (if equal, the smaller k).
(6) Selection: among all combinations of a linkage method and a k in CUT_K, select the one whose partition of the cut into k clusters has the largest ARI against the labels (if equal, the one earlier in linkage order, and if that is also equal, the smaller k). The selected linkage method is called lambda, the number kappa, and the partition of the cut of lambda into kappa clusters the "selected partition".

* 12. Analysis of the selected partition
Let the clusters of the selected partition be C_1, ..., C_kappa, the silhouette value of observation i (section 7 (2), with distance matrix d) be s_i, and the number of the cluster containing observation i be g(i).
(1) Cluster details: for each cluster g, compute the following.
- The size |C_g| and the cluster's silhouette value = (the sum of s_i over the observations of C_g (in observation order)) / |C_g|.
- Majority class: in row g - 1 of the contingency table T of the selected partition and the classes, the class with the largest value (if equal, the one with the smaller class number). That value is the majority count, and purity = majority count / |C_g|.
- Means in the original units: for each feature, (sum x_i,f) / |C_g| (added over the observations of C_g in observation order).
- Medoid: the observation i of C_g with the smallest (sum of d(i, j) over all observations j of C_g, including the term 0 for j = i) (if equal, the one with the smaller observation number).
- Diameter: the observation pair (i, j) (i < j) of C_g with the largest d(i, j) (if equal, the one earlier in pair order) and its d(i, j). If |C_g| = 1, the diameter is 0 and there is no pair.
- Nearest cluster: let the separation of two clusters C_g and C_h be (the minimum of d(i, j) over all pairs with i in C_g and j in C_h); the cluster h other than g with the smallest separation (if equal, the one with the smaller number) and that separation.
(2) Centroid distances: for all g and h, compute the square root of the squared distance between the centroids (centroids of the analysis vectors) of clusters g and h.
(3) Profile: for cluster g and feature f, let zeta_g,f = (the sum of (x_i,f - mean_f) / sd_f over the observations i of C_g (in observation order)) / |C_g| (computed by this formula regardless of STANDARDIZE). The bar length is min(10, floor(|zeta_g,f| * 4)).
(4) Contingency table and purity: the contingency table T of the selected partition and the classes, the match count, and the purity (section 7 (8)).
(5) Observations differing from the majority: the observations i whose class t_i differs from the majority class of g(i) (in observation order).
(6) Observations with small silhouette values: the first R observations when the observations are sorted by increasing s_i (if equal, by increasing observation number).
(7) Feature F ratios: for each feature f, let the overall mean m_f = (sum_i z_i,f) / n, the cluster mean mu_g,f = (the sum of z_i,f over the observations i of C_g) / |C_g|, between = sum_g |C_g| * (mu_g,f - m_f) * (mu_g,f - m_f), within = sum_i (z_i,f - mu_g(i),f) * (z_i,f - mu_g(i),f), and F ratio = (between / (kappa - 1)) / (within / (n - kappa)). Sort the features by decreasing 4-digit value of the F ratio (if equal, in feature order), and assign ranks 1, 2, ....
(8) Last merges: for the merges s = n - V, ..., n - 1 of lambda, compute, for the two children a, b (in increasing ID order), their IDs, their sizes, and the number of contained observations per class (in class order).
(9) Recomputation without a feature: for each feature f, in feature order, build the distance matrix of the DISTANCE type from the vectors obtained by removing the f-th component from the analysis vectors of all observations (p - 1 components; the standardization is not redone), perform the procedure of section 4 with lambda, and create the partition of the cut into kappa clusters. Compute the ARI of that partition and the selected partition, and the ARI of that partition against the labels.
(10) Refinement by the k-means method: let the centroids of the clusters of the selected partition be the initial centers c_1, ..., c_kappa, and let A_0 be the selected partition. For t = 1, 2, ..., imax in order, do the following.
  - Let A_t be the assignment of each observation i to the number g of the center c_g with the smallest squared distance to v_i (if equal, the smaller number).
  - If A_t is the same as A_(t-1) for every observation, stop there.
  - Otherwise, for each cluster g, if some observations are assigned to g in A_t, let the centroid of their analysis vectors (in observation order) be the new c_g (otherwise c_g is not changed).
The t at which it stopped (imax if it did not stop) is the number of iterations, and the last computed A_t is the refined partition (the numbers stay the center numbers; the numbering of section 6 (2) is not applied). Compute the number of observations whose numbers differ between the refined partition and the selected partition, the WSS of the selected partition and the WSS of the refined partition, the sizes and the silhouette coefficient (with distance matrix d) of the refined partition, the ARI of the refined partition and the selected partition, and the ARI of the refined partition against the labels.
(11) Stability under subsamples: use the MINSTD generator. The state is initially x0, and each time a value is drawn, the state is updated as x = (48271 * x) mod 2147483647, and the updated x is the drawn value. The state carries over across subsamples. Let the subsample size be m = floor(n * P / 100), and for b = 1, 2, ..., B in order, do the following.
  - Prepare the array (0, 1, ..., n - 1), and for t = 0, 1, ..., m - 1 in order, draw a value x, let j = t + (x mod (n - t)), and swap the t-th and j-th elements of the array (counting from 0). The first m observation numbers of the array, sorted in increasing order as o_0 < o_1 < ... < o_(m-1), are the subsample.
  - Let object u (0 to m - 1) be observation o_u, let delta(u, w) = d(o_u, o_w), perform the procedure of section 4 with lambda, and create the partition of the cut into kappa clusters (the subsample partition).
  - ARI: compute the ARI of the subsample partition and the partition obtained by restricting the selected partition to the observations of the subsample (object u has number g(o_u)) (the number of objects is m).
  - Jaccard coefficient: for each cluster g of the selected partition, let I be the intersection of C_g and the set of observations of the subsample. If I is empty, the Jaccard coefficient is 0; otherwise it is the maximum, over each cluster S (a set of observations) of the subsample partition, of |intersection of I and S| / |union of I and S|.
From the B results, compute the mean of the ARI values = (the sum of the ARI values of the rounds (in round order)) / B, and for each cluster g the mean of the Jaccard coefficients = (the sum of the Jaccard coefficients of the rounds (in round order)) / B.
(12) Distance map: with the leaf order of lambda as o_0, ..., o_(n-1), build an n-row, n-column map whose character at row r, column w (r, w = 0, ..., n - 1) is the "shade character" for the bin min(9, floor(10 * d(o_r, o_w) / dmax)) (the same formula as in section 3 (5); d(i, i) = 0). The shade characters are the 10 characters "@%#*+=-:. " (the last character is a space), representing bins 0 to 9 in this order.

* 13. Dendrogram
For each linkage method, build a character grid of n rows and W + 1 columns. Row r (0 to n - 1) represents the r-th observation in the leaf order, and column x (0 to W) represents a position in the height direction.
(1) Column positions: let Hmax be the maximum of h_1, ..., h_(n-1), and the column of height h be col(h) = floor(h / Hmax * W) (compute h / Hmax first, then multiply by W; it is W when h = Hmax). The column of merge s is written x_s = col(h_s).
(2) Anchor rows: the anchor row of leaf i is the row representing i; the anchor row of a node is floor((anchor row of the upper child + anchor row of the lower child) / 2).
(3) Marks: put the following marks on the cells of the grid. When a cell receives several marks, the character of the mark with the highest priority becomes the character of that cell. The priorities, from highest to lowest, are + then | then - then :. A cell without a mark is a space.
- Cut heights: for each cut height theta_j, if col(theta_j) <= W, put : in column col(theta_j) of every row.
- Merges: for each merge s, put + in column x_s of the anchor row of the upper child and of the anchor row of the lower child, and | in column x_s of the rows between them (excluding both ends). Furthermore, for each of the two children, put - in columns 0 to x_s - 1 of its row if the child is a leaf, or in columns x_(s') + 1 to x_s - 1 of its anchor row if the child is the node created by merge s' (nothing is put if the range is empty).
(4) Row strings: let id_w be the maximum ID length and lab_w the maximum label length (maxima over all observations). The string of row r is the concatenation of the ID of the observation of that row padded on the right with spaces to id_w characters, one space, the label padded on the right with spaces to lab_w characters, one space, and the characters of the W + 1 cells of that row (from column 0 on), with all trailing spaces removed.
(5) Scale row: id_w + lab_w + 2 spaces followed by, for x = 0, 1, ..., W in order, + if x is a multiple of 10 and - otherwise.

[Source files]
Split the program into the following six source files (file names follow each language's conventions).
- main: handles the overall flow and most of the processing. It is responsible for interpreting the settings, the data summary (distance range, nearest neighbors, label partition, feature correlations, histogram), the analysis per linkage method (cophenetic distances and correlation coefficient, leaf path length, inversions, maximum subtree heights and gaps, recommended number, joining heights, merge kinds and depth, inconsistency coefficients), flat clustering (cuts by height and by number, numbering by leaf order) and the evaluation of partitions (mean silhouette coefficient, Dunn index, WSS, CH, purity), the cross-check with a minimum spanning tree, the comparison of distance types, the comparison and selection of linkage methods, the analysis of the selected partition (cluster details, centroid distances, profile, contingency table, F ratios, last merges, recomputation without a feature, refinement by the k-means method, subsamples by MINSTD and stability, distance map), the Newick-format trees, assembling the contents of the six output files, and the real-number format.
- dataset: handles reading the two input files (feature names, IDs, labels, feature values, settings keywords and values) and writing a sequence of lines to a file.
- distances: handles feature means and standard deviations, standardization, the three distance types, and building distance matrices.
- agglomerative: handles the Lance-Williams coefficients, agglomerative clustering that selects the minimum pair by a full scan (building the merge record), and the minimum spanning tree by Prim's method.
- dendrogram: handles the leaf order, the column positions of heights, and building the dendrogram grid (marks and priorities, anchor rows, row strings).
- validation: handles the correlation coefficient, contingency tables, the adjusted Rand index (irreducible fraction), and the silhouette values per observation.

[Constraints]
- 3 <= n <= 120, 3 <= p <= 10, 2 <= L <= 10, B <= 20, imax <= 100. The given data have n = 90, p = 6, L = 4, and seven linkage methods. The procedure of section 4 is performed 26 times in total (7 times in the main analysis, 3 times in the comparison of distance types, 6 times in the recomputation without a feature, and 10 times for the subsamples).
- The input files correctly follow the formats above. There is no need to check for input errors.
- sd_f > 0. No two observations have the same analysis vector. No vector for which a correlation distance is computed has all components equal. Therefore all distances are positive, and the value inside the square root of the correlation distance formula is also positive.
- With centroid, median and ward, D(k, c) never becomes 0 or less.
- The subsample size m is at least kappa. In the refinement by the k-means method, every cluster has observations assigned to it in every A_t.
- kappa < n, and the within part of the F ratio is positive for every feature. In the inconsistency coefficient, sigma > 0 whenever cnt >= 2.
- In the given data, every real number output is sufficiently far from a rounding boundary. Also, the results of comparisons and of selections of maxima and minima, such as the selection of the minimum pair in section 4 (3), the detection of inversions, the test M_s <= h for cut heights, the determination of columns, bins and bar lengths by floor(...), nearest neighbors, the minimum spanning tree, medoids, diameters, nearest clusters and the assignments of the k-means method, have enough margin that they do not change under a different order of additions, fused multiply-add, or differences in the last digit (about 1 ulp). Nevertheless, compute with the formulas and orders defined in this statement.
- The absolute values of the integers appearing in the ARI computation are below 2^31. The absolute values of the products appearing in fraction comparisons are below 2^53, so they can be computed exactly with 64-bit integers (or integer values in double precision). The MINSTD product 48271 * x is also below 2^53.
