[Overview]
Write a program that simulates a tower defense game tick by tick (a tick is the unit of time), computing everything with integers only.
The map is a grid of cells made of rock, ground on which towers can be built, water (ground enemies move at half speed there), enemy spawn points and exactly one exit. At given ticks the player builds towers, upgrades them, sells them, changes how they choose the enemy to aim at (the target mode), and calls the next wave. Enemies appear wave by wave at the spawn points and head for the exit. Ground enemies move from cell to cell following a distance field computed by breadth-first search (BFS) from the exit. The distance field is recomputed every time a tower is built or sold, and a build that would block the way from a spawn point to the exit is refused. Air enemies fly straight to the exit. Positions are integers in units of 1/100 of a cell.
A tower chooses one enemy within its range according to its target mode and fires a projectile at it; the projectile flies after its target and deals damage on impact. Armor, splash attacks, slowing, burning (damage over time), hit point regeneration and enemies that split when killed are also handled. Killing an enemy earns a bounty, finishing a wave earns a reward and interest, and an enemy that reaches the exit reduces the lives. The game ends in victory when the last wave is finished, and in defeat when the lives reach 0.
The program reads the 5 files in the input/ folder and writes an event log, a summary per wave, map snapshots and the final result to 4 files in the output/ folder. It prints nothing to standard output. All computation is done with integers; no floating-point numbers are used. No random numbers are used. Use only the standard library.

[Input files]
All 5 input files consist only of ASCII characters, and every line ends with a line feed (LF). Each line is one or more tokens separated by single spaces; there are no spaces at the start or end of a line, never two or more consecutive spaces, and no empty lines. Every integer is 0 or more and is written in decimal without extra leading zeros.

== input/map.txt ==
The map. The first line is "<W> <H>": the width W and the height H of the map (in cells). The following H lines are the rows of the map from top to bottom (y = 0, 1, ..., H - 1), and each row has exactly W characters. The character at position x (x = 0, 1, ..., W - 1, counted from the start of the row) gives the terrain of cell (x, y). The terrain character is one of the following.
- ".": ground. Ground enemies can pass, and towers can be built.
- "#": rock. Ground enemies cannot pass, and towers cannot be built.
- "~": water. Ground enemies can pass, but towers cannot be built. Ground enemies are slowed here (section 6).
- "1" to "9": a spawn point. Ground enemies can pass, but towers cannot be built. The digit is the number of the spawn point.
- "E": the exit. Ground enemies can pass, but towers cannot be built. The map has exactly one.

== input/towers.txt ==
The table of tower types. For each type there is a one-line header "tower <name> <symbol> <targets> <level count>", followed by <level count> level lines "level <cost> <range> <power> <interval> <shot speed> <splash> <slow rate> <slow time> <burn amount> <burn time>".
- <name> is a string of 1 to 12 lowercase English letters, and <symbol> is one uppercase English letter other than "E". Both differ between types.
- <targets> is one of ground (aims only at ground enemies), air (aims only at air enemies) and both (aims at both).
- The k-th level line after the header gives the performance at level k. <cost> is the construction cost at level 1, and at level 2 and above it is the cost of upgrading from the previous level to that level.
- <range> and <splash> are lengths in position units (section 0). If <splash> is 0, only the single target is attacked; if it is positive, the enemies around the impact point are attacked together (section 8). <power> is the base damage of one shot, and <interval> is the number of ticks from firing until the tower can fire again. <shot speed> is the length (in position units) a projectile travels per tick; if <shot speed> is 0, the projectile hits within the same tick in which it was fired.
- <slow rate> is the strength of slowing (a percentage); 0 means no slowing. <burn amount> is the burn damage dealt per tick; 0 means no burning. <slow time> and <burn time> are the numbers of ticks each effect lasts.

== input/waves.txt ==
Consists of enemy type lines and wave lines. First come one or more enemy type lines, followed by one or more waves.
- An enemy type line is "enemy <name> <symbol> <movement> <hp> <armor> <speed> <bounty> <lives> <regen> <split into> <split count>". <name> is a string of 1 to 12 lowercase English letters, <symbol> is one lowercase English letter, and both differ between types. <movement> is ground or air. <hp> is the base hit points, <armor> is a value that reduces projectile damage, <speed> is the length (in position units) moved per tick, <bounty> is the gold earned when the enemy is killed, <lives> is the number of lives lost when the enemy reaches the exit, and <regen> is the hit points regenerated every tick. <split into> is "-" or the <name> of an enemy type that appears earlier than this line in this file; when an enemy of this type is killed, <split count> enemies of the <split into> type appear (section 9). If <split into> is "-", <split count> is 0; otherwise <split count> is 1 or more.
- A wave consists of one line "wave <reward>" followed by one or more lines "group <enemy name> <spawn point> <count> <delay> <interval> <hp multiplier>". Waves are numbered 1, 2, 3, ... in file order. <reward> is the gold earned when the wave is finished. A group line describes a group of enemies: <count> enemies of type <enemy name> appear at the spawn point numbered <spawn point>, the first one <delay> ticks after the start of the wave and then one every <interval> ticks (section 5). <hp multiplier> is the hit point multiplier (a percentage) of the enemies of that group.

== input/actions.txt ==
The script of player actions. Each line is one action of the form "<tick> <command> <arguments...>". <tick> is the tick at which the action is performed, an integer of 1 or more. The lines are in increasing order of <tick> (lines with the same <tick> are performed in file order). <command> and <arguments> are one of the following.
- "BUILD <type name> <x> <y>": build a tower of type <type name> on cell (x, y).
- "UPGRADE <number>": upgrade the tower with tower number <number> by one level.
- "SELL <number>": sell the tower with tower number <number>.
- "TARGET <number> <mode>": set the target mode of the tower with tower number <number> to <mode>.
- "CALL": start the next wave immediately.
<type name> is a string of 1 to 12 lowercase English letters, and <mode> is a string of 1 to 12 uppercase English letters. <x>, <y> and <number> are integers. The script is written by a person, so it may contain nonexistent type names, cells outside the map, nonexistent tower numbers and nonexistent modes (they are refused as described in section 7). The script may also have no lines at all (the file is empty).

== input/params.txt ==
The game settings. The following 7 lines appear in this order.
- Line 1 "gold <G>": the starting gold.
- Line 2 "lives <L>": the starting lives.
- Line 3 "interest <rate> <cap>": the interest rate (a percentage) applied when a wave is finished, and the cap of one interest payment.
- Line 4 "sell <rate>": the rate (a percentage) of the amount returned when a tower is sold.
- Line 5 "schedule <start> <interval>": the tick at which wave 1 starts, and the number of ticks from finishing a wave until the next wave starts.
- Line 6 "early <amount>": the gold earned per tick of advancement when the next wave is brought forward with CALL.
- Line 7 "snapshots <t1> <t2> ...": the ticks at which snapshots are written (one or more).

[Processing]
== 0. Notation and common rules ==
- All computation is done with integers. For an integer a >= 0 and a positive integer b, a div b is the integer obtained by discarding the fractional part of a / b, and a mod b is the remainder.
- isqrt(n) (n is an integer >= 0) is the largest integer r >= 0 such that r * r <= n. Compute it exactly with integers (if you use a floating-point square root, always verify and correct the result with integers).
- dec_1(a, b) (a and b are integers >= 0): if b = 0, it is "-". Otherwise it is the decimal representation of a / b rounded to one decimal place: let z = (20 * a + b) div (2 * b); the string is the decimal representation of z div 10, ".", and the single digit z mod 10, in this order. For example, dec_1(2, 3) = 0.7, dec_1(1, 4) = 0.3, dec_1(100, 1) = 100.0.
- digit(n) (n is an integer >= 0): "." if n = 0, the single digit of n if 1 <= n <= 9, and "*" if n >= 10.
- Cells: a cell of the map is written (x, y) (0 <= x < W, 0 <= y < H). x increases from left to right, and y increases from top to bottom.
- Positions: the position of a point is a pair of integers (px, py) in units of 1/100 of a cell. The center of cell (x, y) is the point (100 * x, 100 * y). The "squared distance" between two points (ax, ay) and (bx, by) is (ax - bx)^2 + (ay - by)^2.
- Directions: the 4 directions and their offsets (dx, dy) are N (0, -1), E (1, 0), S (0, 1), W (-1, 0). This sequence is called the "direction order". The "neighbor" of cell (x, y) in direction (dx, dy) is cell (x + dx, y + dy).
- Advancing a point: the operation of advancing a point P = (px, py) toward a point Q = (qx, qy) by a length s (s >= 1) is defined as follows. Let dx = qx - px and dy = qy - py. If dx^2 + dy^2 <= s^2, the result is Q, and the point "has arrived". Otherwise, let L = isqrt(dx^2 + dy^2); the result is (px + f(dx), py + f(dy)), and the point "has not arrived". Here f(d) is (d * s) div L if d >= 0, and -(((-d) * s) div L) if d < 0 (truncation toward 0).
- Identification numbers: towers get tower numbers 1, 2, 3, ... in the order in which they were successfully built (numbers of sold towers are not reused either). Enemies get enemy numbers 1, 2, 3, ... in the order in which they appeared (including enemies that appeared by splitting). Projectiles get projectile numbers 1, 2, 3, ... in the order in which they were fired. In the output, tower number n is written "T<n>", enemy number n is written "E<n>", and projectile number n is written "P<n>".
- A "living enemy" is an enemy that has appeared and has not yet been killed or reached the exit. A "standing tower" is a tower that has been built and not yet sold.

== 1. Distance field and paths ==
- A cell c is "passable" if c is inside the map, its terrain is not rock, and there is no standing tower on it.
- Distance field: for each cell c, dist(c) is the minimum number of steps needed to reach c starting from the exit, moving one step at a time to one of the 4 neighbors and using only passable cells (computed by breadth-first search). dist(exit) = 0, and the dist of a cell that cannot be reached is "none".
- The distance field is recomputed at the start of the game (there are no towers) and right after a tower is successfully built or sold (section 7). It does not change at any other time. Recomputing the distance field does not change the "next cell" (section 2) of a living ground enemy (when the enemy reaches its next cell in section 6, a new next cell is chosen using the distance field at that moment).
- Next cell: for a cell c whose dist(c) is not "none" and which is not the exit, next(c) is the neighbor with the smallest dist among the 4 neighbors of c whose dist is not "none" (if several have the smallest dist, the one that comes first in the direction order). next(c) always exists, and dist(next(c)) = dist(c) - 1.
- Path: the path of spawn point s is the sequence of cells c0 = s, c1 = next(c0), c2 = next(c1), ..., followed until the exit is reached.

== 2. Enemies ==
- An enemy has a type, maximum hit points, hit points, a hit point multiplier, a slow effect, a burn effect, and position information.
- The position information of a ground enemy is its "current cell" c = (cx, cy), its "next cell" n = (nx, ny), and its progress q (0 <= q < 100). The position of the enemy is the point (100 * cx + (nx - cx) * q, 100 * cy + (ny - cy) * q) (the point q/100 of a cell from c toward n). The "occupied cell" of the enemy is c if q < 50, and n otherwise.
- The position information of an air enemy is the position (px, py) itself. The "occupied cell" of the enemy is ((px + 50) div 100, (py + 50) div 100).
- Remaining distance rem(e): for a ground enemy e it is 100 * dist(n) + 100 - q (dist is the value in the distance field at that moment; because of the blocked rule in section 7, the dist of n of a living ground enemy is never "none"); for an air enemy e it is isqrt(squared distance between the position of e and the center of the exit).
- Spawning: when an enemy of type K with hit point multiplier p is spawned at spawn point s, its maximum hit points and hit points are both <hp> of K * p div 100, and both effects are none. For a ground enemy, c = s, q = 0 and n = next(s); for an air enemy, the position is the center of s.
- Splitting: when an enemy of type K' appears from a killed enemy e, its hit point multiplier p is the hit point multiplier of e, its maximum hit points and hit points are both <hp> of K' * p div 100, and both effects are none. Its position information is copied as is from the values of e at the time e was killed (c, n and q for a ground enemy, (px, py) for an air enemy).
- Effects: the slow effect and the burn effect each have a "strength" and a "remaining time", and the burn effect also has a "source" (the tower that applied the burn). An effect is "none" when its strength and remaining time are both 0.
  - Receiving an effect (a, d) (a >= 1): if a is greater than the current strength, set the strength to a and the remaining time to d (for a burn, set the source to that tower). If a equals the current strength, set the remaining time to the larger of the current remaining time and d (the source does not change). If a is less than the current strength, do nothing.
  - Advancing the time of an effect: subtract 1 from the remaining time; if it becomes 0, also set the strength to 0 (for a burn, also clear the source).

== 3. Towers ==
- A tower has a type, a cell (x, y), a level (initially 1), a target mode (initially FIRST), the tick at which it can fire next (initially the tick at which it was built), an investment (initially the <cost> of level 1), the tick at which it was built, the tick at which it was sold, and statistics (shots fired, hits, fizzles, kills, total damage; all initially 0). The performance values of a tower (<range> and so on) are the values of the level line of its current level. The center of the tower is the center of cell (x, y).
- A tower "can aim at" only ground enemies if the <targets> of its type is ground, only air enemies if it is air, and all enemies if it is both.
- An enemy is "within range" if the squared distance between the center of the tower and the position of the enemy is <= <range>^2.
- Target selection: the candidates are the living enemies that the tower can aim at and that are within range; the following enemy is chosen according to the target mode. If there are no candidates, there is no target.
  - FIRST: the enemy with the smallest rem(e) (the enemy closest to the exit).
  - LAST: the enemy with the largest rem(e).
  - STRONGEST: the enemy with the most hit points.
  - WEAKEST: the enemy with the fewest hit points.
  - CLOSEST: the enemy with the smallest squared distance to the center of the tower.
  In every mode, if several enemies match the condition best, the one with the smallest enemy number is chosen.

== 4. Game progress ==
The tick t starts at 1 and increases by 1 until the game ends. When an event is recorded, the current t is recorded with it. First, compute the distance field and set the "start tick of the next wave" to <start> of the schedule line. In each tick, perform the following steps (1) to (7) in this order.
  (1) Actions: perform all actions whose <tick> equals t, in script order (section 7).
  (2) Wave start and spawning: if t equals the start tick of the next wave, start the next wave (section 5). Then, if a wave is active, examine its groups in waves.txt order, and for each group that has an enemy scheduled to appear at tick t, spawn one enemy of that group (section 2) and record "SPAWN". Finally, if a wave is active, set the peak of that wave to the larger of the peak and the number of living enemies.
  (3) Enemy movement: move the enemies that are alive at this point one at a time in increasing order of enemy number (section 6). Enemies that appear during this step (enemies that appeared by splitting) do not move in this step. If the lives reach 0, the game ends in defeat at that moment; the remaining enemies do not move, and (4) to (7) are not performed.
  (4) Firing: examine the standing towers in increasing order of tower number. If t is greater than or equal to the tick at which the tower can fire next and there is a target (section 3), fire one projectile at that target (section 8). Add 1 to the shots fired of the tower, set the tick at which it can fire next to t + <interval>, and record "SHOT".
  (5) Projectile movement and impact: process the projectiles in flight (including those fired in (4) of this tick) in increasing order of projectile number (section 8).
  (6) Wave end: if a wave is active, all enemies of all groups of that wave have already appeared, and there are no living enemies, finish that wave (section 5).
  (7) Snapshot: if t equals one of the values of the snapshots line, write a snapshot block (output/snapshots.txt).
In the case of victory in (6), perform (7) and then end the game. When the game has ended, write the final block and write the 4 output files. The value of t at the moment the game ends is called the "last tick".

== 5. Waves ==
- Starting a wave: make wave number k (initially wave 1; the number advances to the next one every time a wave is started) "active", and set its start tick to t. The tick at which the i-th enemy (i = 0, 1, ..., <count> - 1) of each group is scheduled to appear is t + <delay> + i * <interval>. Then record "WAVE_START".
- Finishing a wave: add the <reward> of the wave to the gold, then add interest = min(<cap>, gold * <rate> div 100) (values of the interest line) to the gold. The wave becomes "cleared", its end tick is set to t, and "WAVE_END" is recorded. If it is the last wave, record "VICTORY", and the game ends in victory. Otherwise, set the start tick of the next wave to t + <interval> (the value of the schedule line).
- A wave is active from its start until it is cleared or the game ends in defeat. At most one wave is active at a time. Living enemies exist only while a wave is active.

== 6. Enemy movement ==
In (3), perform the following steps 1 to 5 for one enemy, in this order.
  1. Burning: if the remaining time of the burn effect is positive, let T be its source tower (the same applies even if T has been sold), subtract damage = min(hit points, burn strength) from the hit points, credit this damage to T (section 9), and advance the time of the burn effect. If the hit points become 0, this enemy is killed by T (section 9), and steps 2 to 5 are not performed.
  2. Regeneration: set the hit points to the smaller of hit points + <regen> and the maximum hit points.
  3. Speed: let s be the <speed> of the type. If the remaining time of the slow effect is positive, set s to s * (100 - slow strength) div 100, and advance the time of the slow effect.
  4. Movement:
  - Air enemy: advance the position toward the center of the exit by s (section 0). If it has arrived, this enemy has reached the exit.
  - Ground enemy: first, if the terrain of the "occupied cell" before the movement is water, set s to s div 2. Then, while s > 0, repeat the following. Let r = 100 - q. If s < r, add s to q and set s = 0. Otherwise, subtract r from s, set c to n and q = 0; if the new c is the exit, this enemy has reached the exit and the repetition ends. If it is not the exit, set n = next(c).
  5. Enemy that reached the exit: remove the enemy, and subtract lives lost = min(lives, <lives> of the type) from the lives. Add 1 to the leaks of the active wave, add the lives lost to the lives lost of the wave, add 1 to the leaks of the type, and record "LEAK". If the lives become 0, record "DEFEAT", and the game ends in defeat (the end tick of the active wave is set to t).

== 7. Actions ==
An action either "succeeds" or is "refused". In both cases, one line is recorded for the result.
- BUILD <type name> <x> <y>: check the following conditions from top to bottom, and refuse with the reason of the first one that applies.
  1. There is no type <type name>: type
  2. Cell (x, y) is outside the map: bounds
  3. The terrain of the cell is not ground: terrain
  4. There is already a standing tower on the cell: tower
  5. The gold is less than the <cost> of level 1: gold
  6. The c or n of some living ground enemy is that cell: enemy
  7. When the distance field is computed assuming a tower is built on that cell, the dist of some spawn point, or of the n of some living ground enemy, becomes "none": blocked
  If none of these applies, the action succeeds. Create a tower with a new tower number on that cell, subtract the <cost> from the gold, record "BUILD", and recompute the distance field ("Updating the distance field" below).
- UPGRADE <number>: refuse with notower if there is no standing tower with that number (the number has not been built, or the tower has been sold), with maxlevel if the level of the tower is already <level count>, and with gold if the gold is less than the <cost> of the next level, checked in this order. Otherwise the action succeeds: subtract the <cost> of the next level from the gold, add 1 to the level, add that <cost> to the investment, and record "UPGRADE". The tick at which the tower can fire next does not change.
- SELL <number>: refuse with notower if there is no standing tower with that number. Otherwise the action succeeds. The returned amount is investment * r div 100, where r is 100 if the tick of the sale equals the tick at which the tower was built, and <rate> of the sell line otherwise. Mark the tower as sold with its sale tick set to t, add the returned amount to the gold, record "SELL", and recompute the distance field. Projectiles already fired by that tower keep flying, and their results are counted in the statistics of that tower.
- TARGET <number> <mode>: refuse with notower if there is no standing tower with that number, and with mode if <mode> is none of FIRST, LAST, STRONGEST, WEAKEST and CLOSEST, checked in this order. Otherwise the action succeeds: set the target mode to <mode> and record "TARGET".
- CALL: refuse with active if a wave is active. Otherwise the action succeeds (in this case there is always a wave that has not started yet). Add the early bonus = (start tick of the next wave - t) * <amount> (the value of the early line) to the gold, set the start tick of the next wave to t, and record "CALL". That wave starts in (2) of this tick.
- Updating the distance field: when BUILD or SELL succeeds, recompute the distance field after recording the result of that action. Examine the spawn points in increasing order of number, and record "REPATH" for each spawn point whose dist differs before and after the recomputation.

== 8. Projectiles ==
- Firing a projectile: a projectile has the tower that fired it, the target enemy, the performance values of the tower at the time of firing (<power>, <shot speed>, <splash>, <slow rate>, <slow time>, <burn amount>, <burn time>) and the <targets> of the tower type, a position, and an aim point. The position starts at the center of the tower, and the aim point starts at the position of the target enemy at the time of firing. Even if the tower is later upgraded or sold, the values of the projectile do not change.
- In (5), perform the following steps 1 to 4 for one projectile, in this order.
  1. If the target enemy is alive, set the aim point to the current position of the target enemy. If it is not alive, the aim point does not change.
  2. If <shot speed> is 0, the projectile hits. Otherwise, advance the position of the projectile toward the aim point by <shot speed> (section 0), and if it has arrived, it hits. If it has not arrived, the processing of this projectile ends (it is processed again in the next tick).
  3. Remove the projectile that hit, and determine the list of enemies that take damage. If <splash> is 0, the list is the target enemy alone if it is alive, and empty if it is not alive. If <splash> is positive, the list is the living enemies that the <targets> of the projectile can aim at and whose squared distance between their position and the aim point is <= <splash>^2, in increasing order of enemy number. The whole list is determined before any damage is dealt. If the list is empty, add 1 to the fizzles of the tower that fired.
  4. Deal damage to the enemies of the list in order. For each enemy, add 1 to the hits of the tower that fired, subtract damage = min(hit points, max(1, <power> - <armor> of the type)) from the hit points, and credit this damage to the tower that fired (section 9). If the hit points become 0, the enemy is killed by the tower that fired (section 9). Otherwise, if <slow rate> is positive, the enemy receives the slow effect (<slow rate>, <slow time>), and then, if <burn amount> is positive, it receives the burn effect (<burn amount>, <burn time>) (the source of the burn is the tower that fired).

== 9. Crediting damage, killing, splitting ==
- Crediting damage v to tower T: add v to each of the total damage of T, the total damage of the enemy type, and the damage of T in the active wave.
- Enemy e is killed by tower T: remove e, and add 1 to the kill count of the "occupied cell" of e (the kill counts per cell are all initially 0). Add 1 to each of the kills of T, the kills of the active wave and the kills of the type, add the <bounty> of the type to the gold and to the bounty of the active wave, and record "KILL". Then, if the <split count> m of the type is positive, make m enemies of the <split into> type appear by splitting, one at a time (section 2; enemy numbers continue in sequence), and record "SPAWN" for each one.
- Enemies that appeared by splitting join the living enemies. Enemies that appear during (5) can take damage from later projectiles in the same (5) (but they are not included in a list that has already been determined).
- Enemies that appeared by spawning and by splitting are both counted in the spawned count of the active wave and in the spawned count of the type.

[Output files]
Common format:
- Everything is ASCII characters, and every line ends with a line feed (LF). No trailing spaces are written, and no empty lines are written unless specified.
- Integers are written in decimal without extra leading zeros. No negative numbers appear in the output.
- In the formats below, the parts enclosed in < > are replaced by values, and all other characters are written as they are.
- All 4 files are always created. A file with no lines to write is empty (0 bytes).

== output/events.txt ==
The recorded events, one per line in the order in which they were recorded, in the form "<t> <body>". <t> is the tick at which the event was recorded. <body> is one of the following. The gold and lives are the values after the processing of that event has finished.
- "BUILD T<number> <type name> <x> <y> cost <cost> gold <gold>"
- "BUILD_REFUSED <type name> <x> <y> <reason>": <type name>, <x> and <y> are as written in the script.
- "UPGRADE T<number> level <new level> cost <cost> gold <gold>"
- "UPGRADE_REFUSED T<number> <reason>", "SELL_REFUSED T<number> <reason>", "TARGET_REFUSED T<number> <reason>": <number> is as written in the script.
- "SELL T<number> refund <returned amount> gold <gold>"
- "TARGET T<number> <mode>"
- "CALL <wave number> bonus <early bonus> gold <gold>": <wave number> is the number of the wave that was called.
- "CALL_REFUSED active"
- "REPATH <spawn point number> <dist before> <dist after>"
- "WAVE_START <wave number> enemies <count>": <count> is the sum of the <count> of all groups of the wave.
- "SPAWN E<number> <type name> <origin> hp <hit points>": <origin> is the number of the spawn point if the enemy appeared at a spawn point, and "E<number>" of the killed enemy if it appeared by splitting.
- "SHOT T<tower number> E<enemy number>"
- "KILL E<enemy number> <type name> T<tower number> bounty <bounty> gold <gold>"
- "LEAK E<enemy number> <type name> lives <lives>"
- "WAVE_END <wave number> reward <reward> interest <interest> gold <gold>"
- "VICTORY", "DEFEAT"

== output/waves.csv ==
The first line is the header line "wave,start,end,status,spawned,peak,kills,leaks,lives_lost,bounty,reward,interest,gold,lives,T1,T2,...,TN". N is the number of towers built during the whole game; if N = 0, the header ends with "...,gold,lives".
From the second line on, one line per started wave in order of wave number, with the values separated by "," in the order of the header.
- wave: the wave number. start, end: the start tick and the end tick. status: cleared if the wave was cleared, lost if it ended in defeat.
- spawned: the spawned count (including enemies that appeared by splitting). peak: the peak (initially 0). kills: the kills. leaks: the leaks. lives_lost: the lives lost. bounty: the total bounty.
- reward, interest: the reward and interest earned when the wave was finished (0 if lost).
- gold, lives: the gold and lives at the moment the processing of the wave end finished (if lost, at the moment DEFEAT was recorded).
- T1 to TN: the total damage credited to each tower while the wave was active (including sold towers).

== output/snapshots.txt ==
The snapshot blocks written in (7), in the order in which they were written, followed at the end by the final block.
- Header line: a snapshot block starts with "SNAPSHOT <t> wave <k> next <n> gold <gold> lives <lives>", and the final block with "FINAL <last tick> wave <k> next <n> gold <gold> lives <lives>". <k> is the number of waves started so far. <n> is the start tick of the next wave if no wave is active and the game has not ended yet, and "-" otherwise (it is also "-" in the block written in (7) of the tick of victory).
- Grid with rulers: a picture of W characters by H rows is written in H + 1 lines. The first line is two spaces followed by the digits x mod 10 for x = 0, 1, ..., W - 1. Each of the following H lines, for y = 0, 1, ..., H - 1 in this order, is the digit y mod 10, one space, and the W characters of that row, in this order.
- Map picture: the character of each cell starts as its terrain character and is overwritten in the following order. (a) A cell that is contained in the path of some spawn point and whose terrain is "." or "~" becomes "+". (b) The cell of a standing tower becomes the <symbol> of its type. (c) The "occupied cell" of living enemies becomes the <symbol> of the type if exactly one enemy occupies the cell, and "*" if two or more do.
- Block contents: the header line, the map as a grid with rulers, and then the following lines in this order.
  - For each spawn point in increasing order of number: "PATH <spawn point number> length <dist(spawn point)>"
  - For each standing tower in increasing order of tower number: "T<number> <type name> <x> <y> level <level> mode <mode> ready <tick at which it can fire next>"
  - For each living enemy in increasing order of enemy number: "E<number> <type name> <px> <py> hp <hit points>/<maximum hit points> slow <slow strength> <slow remaining time> burn <burn strength> <burn remaining time>": (px, py) is the position of the enemy.
  - For each projectile in flight in increasing order of projectile number: "P<number> T<number of the tower that fired> E<number of the target enemy> <px> <py>": (px, py) is the position of the projectile. The number of the target enemy is written even if that enemy is not alive.
- The final block additionally contains the following, in this order.
  - "FLOW" and the distance field as a grid with rulers: a cell whose terrain is "#" is "#", the exit is "E", the cell of a standing tower is the <symbol> of its type, any other cell whose dist is "none" is "?", and any other cell c is "^" if the direction of next(c) is N, ">" if E, "v" if S, and "<" if W.
  - "COVERAGE" and the range map as a grid with rulers: a cell whose terrain is "#" is "#", the cell of a standing tower is the <symbol> of its type, and any other cell is digit(n), where n is the number of standing towers whose squared distance between the tower center and the center of that cell is <= <range>^2.
  - "KILLS" and the kill count map as a grid with rulers: a cell with a positive kill count is digit(kill count); a cell with a kill count of 0 is "#" if its terrain is "#", and "." otherwise.

== output/summary.txt ==
Write the following lines in this order.
- "outcome <result>": victory for a victory, defeat for a defeat.
- "ticks <last tick>"
- "waves <number of cleared waves>/<total number of waves> perfect <number of waves cleared with 0 leaks>"
- "lives <lives>/<starting lives>"
- "gold <gold>"
- "enemies spawned <total enemies spawned> killed <total enemies killed> leaked <total enemies that reached the exit>": the total enemies spawned includes enemies that appeared by splitting.
- "income bounty <total bounty> reward <total reward> interest <total interest> early <total early bonus> refund <total returned amount>"
- "spent <total gold spent on building and upgrading>"
- "damage <sum of the total damage of all towers>"
- "actions total <number of script lines> done <number succeeded> refused <number refused> unused <number not performed because the game ended>"
- "score <score>": score = 10 * total enemies killed + 100 * lives + 50 * number of waves cleared with 0 leaks + gold.
- "mvp T<number> damage <total damage>": the tower with the largest total damage (if several, the one with the smallest tower number; sold towers are included). If no tower was built at all, "mvp -".
- For each enemy type in waves.txt order: "ENEMY <type name> spawned <spawned count> killed <kills> leaked <leaks> damage <total damage>"
- For each built tower in order of tower number: "TOWER T<number> <type name> <x> <y> level <level> mode <mode> <state> shots <shots fired> hits <hits> fizzles <fizzles> kills <kills> damage <total damage> per_shot <dec_1(total damage, shots fired)> share <dec_1(100 * total damage, sum of the total damage of all towers)> invested <investment>": <state> is "active" if the tower is standing, and "sold <sale tick>" if it was sold. The level and mode of a sold tower are the values at the time of the sale.

[Source files]
Split the source files into files with the following 6 roles (file names and extensions follow the conventions of each language).
- main: the overall flow and the largest share of the processing. Reading towers.txt, waves.txt, actions.txt and params.txt; the game state (gold, lives, towers, enemies, projectiles, wave records, statistics); the per-tick progress of section 4; all actions and refusal checks of section 7; wave start, spawning and end of section 5; enemy movement of section 6 (burning, regeneration, water, cell-to-cell movement, leaks); firing; impact and splash attacks of section 8; crediting damage, killing and splitting of section 9; building the map picture and the 3 analysis pictures; building and writing the lines of the 4 output files.
- grid_map: reading map.txt, terrain queries (inside the map, rock, water, buildable), and the positions of the spawn points and the exit.
- pathing: the direction table, the distance field (breadth-first search), next(c), and the paths of the spawn points.
- towers: tower types and level performance (interpreting the input lines), tower state, whether a tower can aim at an enemy, whether an enemy is within range, and the target selection of section 3.
- enemies: enemy types and groups (interpreting the input lines), enemy state, position, occupied cell, speed with slowing applied, and creating enemies that appear by splitting.
- combat: the point-advancing operation using isqrt, effects (receiving, advancing time), projectiles (position, aim point, flight), and damage taking armor into account.

[Constraints]
- map.txt: 5 <= W <= 40 and 5 <= H <= 30. The spawn point numbers are consecutive starting from 1 (at least 1 and at most 9), and no digit appears more than once. At the start of the game, the dist of every spawn point is not "none".
- towers.txt: there are 1 to 10 types, and <level count> is 1 to 5. 1 <= cost <= 10000, 1 <= range <= 1000, 1 <= power <= 1000, 1 <= interval <= 100, shot speed is 0 or between 20 and 1000 inclusive, 0 <= splash <= 500, 0 <= slow rate <= 80, 0 <= burn amount <= 100. If the slow rate is 0, the slow time is 0; if it is positive, the slow time is 1 to 100. The same holds for the burn amount and burn time.
- waves.txt: there are 1 to 20 enemy types. 1 <= hp <= 10000, 0 <= armor <= 1000, 0 <= bounty <= 1000, 1 <= lives <= 100, 0 <= regen <= 100, 0 <= split count <= 5. <speed> is between 20 and 100 inclusive for a ground enemy, and between 20 and 200 inclusive for an air enemy. The <movement> of the <split into> type is the same as the <movement> of the splitting type. There are 1 to 50 waves, each wave has 1 to 20 groups, and 1 <= count <= 200, 0 <= delay <= 1000, 1 <= interval <= 1000, 1 <= hp multiplier <= 1000, 0 <= reward <= 10000. The spawn point is a number that exists on the map. For every group, <hp> of the type * hp multiplier div 100 is 1 or more, and the same holds for enemies that appear by splitting (including when splitting continues further).
- actions.txt: there are at most 2000 lines, and <tick> is at most 100000. <x> and <y> are at most 99, and <number> is between 1 and 999 inclusive.
- params.txt: 0 <= G <= 100000, 1 <= L <= 1000, 0 <= interest rate <= 100, 0 <= interest cap <= 100000, 0 <= sell rate <= 100, 1 <= start <= 10000, 1 <= interval <= 10000, 0 <= amount <= 1000. The snapshots line has at most 20 values, forming a strictly increasing sequence of values between 1 and 100000 inclusive.
- For the given input, the game ends within 100000 ticks, and every integer that appears during the computation has an absolute value less than 2^31.
