[Overview]
Write a program that trains a multilayer perceptron (a fully connected neural network) that classifies small black-and-white images (such as 8x8-pixel images of digits) by backpropagation and mini-batch gradient descent, and analyzes the results. The structure of the network (the number and sizes of the hidden layers, the activation functions, the type of the output layer) and the initial values of the weights and biases are given in files. For each "run" (a pair of a network and an optimization method) listed in the settings file, the program trains from the same initial values, selects the weights of the best epoch by early stopping on validation data, evaluates them on test data, and compares the runs with each other. Before training, it also performs a gradient check that compares the gradients obtained by backpropagation with numerical differentiation.
The input is five files in the input/ folder (training data, test data, network definitions, initial weights, settings), and the results are written to five files in the output/ folder. Nothing is written to standard output. Random numbers come only from the MINSTD generator defined in [Processing], and all initial values are given in the input, so the result is uniquely determined.

[Input files]
There are five input files: input/train.csv, input/test.csv, input/network.txt, input/weights.txt and input/params.txt. Every file consists of ASCII characters only, and every line (including the last line) ends with a newline (LF). There is no whitespace at the start or end of a line, and values are separated by a single space (a comma in CSV files).
An integer is a base-10 number without extra leading zeros. A decimal number is a base-10 number consisting of, in this order, "-" (only for negative numbers), a sequence of one or more digits (the integer part), ".", and a sequence of one or more digits (the fractional part) (examples: 0.5, -0.1479, 0.00000001). Exponential notation is not used.

* input/train.csv (training data)
The first line is a header line, the string id,label,pixels. Each line from the second line on represents one image and lists the image ID, the label and the pixel string in this order, separated by commas.
- An image ID is a string of 1 to 8 characters consisting of uppercase English letters and digits; the IDs are distinct from each other within the file.
- A label is an integer from 0 to K - 1 inclusive representing the class of the image (K is the number of classes, the number of units of the output layer in network.txt).
- The pixel string is a string of length W * H consisting of the characters 0 and 1 (W and H are the width and height of the image given in network.txt). It lists the pixels from the top row of the image downward, and within each row from left to right; 1 is black (a pixel with ink) and 0 is white. The (r * W + c + 1)-th character counted from the start (r = 0, ..., H - 1, c = 0, ..., W - 1) is the pixel in row r + 1 from the top and column c + 1 from the left.
Let n be the number of images; in the order of the lines in the file they are called image 1, image 2, ..., image n.

* input/test.csv (test data)
Same format as train.csv. Let T be the number of images; the order of the lines in the file is called the "test data order".

* input/network.txt (network definitions)
The first line is IMAGE W H, giving the width W and height H of the images (positive integers). The second line is an empty line, and from the third line on there are one or more network blocks, separated by one empty line each. Each block consists of the following lines.
- Line 1: NETWORK name (name is the name of the network, a string of 1 to 16 characters consisting of lowercase English letters and digits; it differs between blocks)
- The following 1 or 2 lines: HIDDEN u f (a hidden layer; u is the number of units, an integer from 1 to 12 inclusive, and f is the activation function, one of TANH, SIGMOID and RELU). They are listed starting from the layer closest to the input.
- The last line: OUTPUT K g (the output layer; K is the number of classes, an integer from 2 to 10 inclusive, and g is the type of the output layer, SOFTMAX or SIGMOID)
K is the same in all blocks. The order of the blocks is called the "network order".

* input/weights.txt (initial weights)
One block for each network of network.txt, in network order, separated by one empty line each. In each block, the first line is NETWORK name (the name of the network), followed, for each layer starting from layer 1, by the following lines (for the layer numbers, see 3 of [Processing]).
- LAYER l p q: the header of layer l. p is the number of units of this layer and q is the number of inputs to this layer.
- The following p lines: the j-th line (j = 1, ..., p) is W followed by q decimal numbers, the weights w_j1, ..., w_jq of unit j of layer l (the weights from inputs 1 to q).
- The last line: B followed by p decimal numbers, the biases b_1, ..., b_p of units 1 to p.

* input/params.txt (settings)
The following lines appear in this order. Each line is a keyword followed by one or more values.
- SEED s: the random seed (an integer from 1 to 2147483646 inclusive)
- BATCH_SIZE B: the mini-batch size (a positive integer)
- MAX_EPOCHS E: the maximum number of epochs (an integer from 1 to 99 inclusive)
- PATIENCE P: the number of epochs to wait before early stopping (a positive integer)
- LR_STEP S gamma: means that the learning rate is multiplied by gamma every S epochs (S is a positive integer, gamma is a decimal number greater than 0 and at most 1).
- GRADIENT_CHECK_STRIDE D: means that the gradient check selects every D-th parameter (a positive integer).
- CALIBRATION_BINS M: the number of confidence bins (one of 1, 2, 4, 5, 10)
- PRUNE q_1 q_2 ...: the pruning fractions (in percent; 1 to 5 distinct integers from 1 to 99 inclusive, in increasing order)
- NOISE r_1 r_2 ...: the fractions of pixels to flip (in percent; 1 to 5 distinct integers from 1 to 99 inclusive, in increasing order)
- The following 1 to 6 lines: RUN name net opt eta lambda (followed by additional values). Each line defines one run.
In a RUN line, name is the name of the run (a string of 1 to 20 characters consisting of lowercase English letters, digits and _; it differs between lines), net is the name of the network to use (one that exists in network.txt), opt is the optimizer, one of SGD, MOMENTUM and ADAM, eta is the initial learning rate (a positive decimal number), and lambda is the weight decay coefficient (a decimal number >= 0). The additional values are: none for SGD; one value, the momentum coefficient mu (a decimal number >= 0 and < 1), for MOMENTUM; three values, beta1, beta2 and epsilon, for ADAM (beta1 and beta2 are decimal numbers >= 0 and < 1, and epsilon is a positive decimal number). The order of the RUN lines is called the "run order".

[Processing]
* 1. Notation and computation rules
- All real-number computations are done in double precision (IEEE 754 64-bit floating point).
- ln is the natural logarithm, exp is the exponential function, tanh is the hyperbolic tangent, sqrt is the square root, |t| is the absolute value of t, floor(t) is the largest integer not greater than t, and max and min are the maximum and the minimum. a mod b is the remainder of dividing an integer a >= 0 by a positive integer b.
- A sum written with SUM (in place of the summation sign) starts from 0 and adds one term at a time in increasing order of the index (for images or parameters, in the order of their sequence). Other sums are computed the same way unless stated otherwise. Multiplications and divisions in a formula are computed from left to right in the order written.
- When a rule that selects a maximum has ties, the one with the smaller number (for classes, the smaller label) is selected unless stated otherwise.
- The "4-decimal notation" of an integer ratio a/b (a >= 0, b > 0) is obtained by computing q = floor((20000 * a + b) / (2 * b)) with integer arithmetic and writing the quotient of q divided by 10000, ".", and the remainder in 4 digits (padded with leading zeros if needed). This is a/b rounded to 4 decimal places, with exact halves rounded up (examples: 29/32 is 0.9063, 3/4 is 0.7500, 63/3 is 21.0000). When b = 0, write "-". Accuracies and similar values are written this way.

* 2. Data split and input vectors
Let n_v = floor(n / 5) and m = n - n_v. Images 1 to m of train.csv form the "training set", and images m + 1 to n form the "validation set". Both are used in file order, and these orders are called the "training set order" and the "validation set order" respectively. The test data are all images of test.csv.
From the pixel string of each image, build an input vector x of length W * H. The i-th component of x (i = 1, ..., W * H) is 1.0 if the i-th character of the pixel string is 1, and 0.0 if it is 0.

* 3. Network and parameters
Let L_h (1 or 2) be the number of hidden layers of the network, and let L = L_h + 1. The layers are called layer 1, ..., layer L starting from the one closest to the input. Layer l (l < L) is the hidden layer of the l-th HIDDEN line, and layer L is the output layer. Let n_0 = W * H, and let n_l be the number of units of layer l (K for layer L). Layer l has n_l * n_(l-1) weights w^l_ji (j = 1, ..., n_l, i = 1, ..., n_(l-1)) and n_l biases b^l_j. Unit j of the output layer corresponds to class j - 1, so below the units of the output layer are referred to by the class number k = 0, ..., K - 1.
All weights and biases of a network are called its "parameters". The "parameter order" is: the weights of layer 1 (in the order w_11, w_12, ..., w_1n_0, w_21, ..., w_n_1n_0, which is the order written in the W lines of weights.txt), the biases of layer 1 (b_1, ..., b_n_1), the weights of layer 2, the biases of layer 2, ..., the weights of layer L, the biases of layer L; the parameters are numbered from 1 in this order. Let N_p be the total number of parameters, and N_w the number of those that are weights (not biases). All parameters together are treated as a vector theta = (theta_1, ..., theta_Np), whose initial values are the values of that network's block in weights.txt.

* 4. Forward pass and loss
For one image (input vector x, label y), let a^0 = x and compute the following for l = 1, ..., L in this order.
- Pre-activation: z^l_j = (SUM_i w^l_ji * a^(l-1)_i) + b^l_j (j = 1, ..., n_l; i = 1, ..., n_(l-1)). The weighted sum is computed first, and the bias is added last.
- Activation of a hidden layer (l < L): a^l_j = f(z^l_j). f is the activation function of that layer, as follows.
  TANH: f(z) = tanh(z)
  SIGMOID: f(z) = 1 / (1 + exp(-z))
  RELU: f(z) = z if z > 0, otherwise f(z) = 0
Let z_k (k = 0, ..., K - 1) be the pre-activations of the output layer, and let the target t_k be 1 if k = y and 0 otherwise. Depending on the type of the output layer, the "score" s_k of class k, the loss ell and the output-layer error delta_k are computed as follows.
- SOFTMAX (cross-entropy loss): zm = max(z_0, ..., z_(K-1)), e_k = exp(z_k - zm), Z = SUM_k e_k, s_k = e_k / Z, ell = ln(Z) - (z_y - zm), delta_k = s_k - t_k
- SIGMOID (mean squared error): s_k = 1 / (1 + exp(-z_k)), ell = (SUM_k (s_k - t_k) * (s_k - t_k)) / K, delta_k = 2 * (s_k - t_k) * s_k * (1 - s_k) / K
The "prediction" of an image is the class with the largest score (ties: the smaller label), and its "confidence" is the score of the predicted class. An image whose prediction matches its label is called "correct".
To "evaluate" a sequence of images means to perform the forward pass for each image and compute the mean loss (the sum of the losses added in the order of the sequence, divided by the number of images) and the number of correct images (the correct count).

* 5. Backward pass and gradients
After the forward pass for one image, let delta^L_k = delta_k (the output-layer error), and for l = L - 1, ..., 1 in this order compute
  c_j = SUM_k w^(l+1)_kj * delta^(l+1)_k (k in the order of the units of layer l + 1), delta^l_j = c_j * d_j (j = 1, ..., n_l)
where d_j is the value of the derivative of the activation function of layer l: 1 - a^l_j * a^l_j for TANH, a^l_j * (1 - a^l_j) for SIGMOID, and for RELU 1 if z^l_j > 0, otherwise 0.
The "gradient" of this image is a vector in parameter order whose component for weight w^l_ji is delta^l_j * a^(l-1)_i and whose component for bias b^l_j is delta^l_j. In addition, the "input gradient" of this image is g_i = SUM_j w^1_ji * delta^1_j (i = 1, ..., n_0; j in the order of the units of layer 1).
For a sequence of images X_1, ..., X_b, the "mean gradient" is the vector whose each component is the sum of that component of the gradients of X_1, ..., X_b added in this order, divided by b, and the "mean loss" is the sum of the losses added in this order, divided by b.

* 6. Random numbers and shuffling
Random numbers are produced by the MINSTD generator. The generator has an integer state x. To "initialize with seed s" means to set x = s. To "draw a random number" means to replace x with (48271 * x) mod 2147483647 and return the new x (the product is less than 2^53, so it can be computed exactly with 64-bit integers or with double precision).
To "shuffle" a sequence (o_1, ..., o_c) means, for i = c, c - 1, ..., 2 in this order, to draw a random number r, let j = (r mod i) + 1, and swap o_i and o_j.

* 7. Gradient check
In network order, do the following for each network.
1. Initialize the generator with seed SEED and shuffle the sequence (1, 2, ..., m). The training-set images indicated by the first min(B, m) numbers of the shuffled sequence, arranged in this order, form the "check batch" (it is the same batch for all networks).
2. With theta at its initial values, compute the mean gradient A = (A_1, ..., A_Np) of the check batch (weight decay is not included).
3. For each parameter with number p = 1, 1 + D, 1 + 2 * D, ... (up to N_p), replace theta_p with theta_p + h and compute the mean loss E+ of the check batch, replace it with theta_p - h and compute the mean loss E-, and then restore theta_p to its original value. Here h = 0.00001 (a constant separate from ADAM's epsilon). Compute the numerical derivative u = (E+ - E-) / (2 * h) and the error |A_p - u| / max(1, |A_p| + |u|).
4. The result is PASS if the error is less than 0.000001 for every checked parameter, and FAIL otherwise.

* 8. Training
In run order, train the network of each run as follows. Each run is not affected by the other runs.
(1) Preparation
Set theta to the initial values of the network. Initialize the generator with seed SEED. Let the sequence O of training-set numbers be (1, 2, ..., m). Initialize the optimizer state (the MOMENTUM velocities v_p and the ADAM values m_p and v_p are all 0, and ADAM's pi1 and pi2 are 1).
(2) Epochs
For e = 1, 2, ..., E in this order, do the following steps (a) to (f).
(a) The learning rate eta_e is eta multiplied by gamma floor((e - 1) / S) times (starting from eta and multiplying by gamma one time after another).
(b) Shuffle O (the O of the previous epoch is shuffled further, continuing with the same generator).
(c) Split O from the start into groups of B numbers each; each group is a mini-batch (the last mini-batch may have fewer than B numbers). Process the mini-batches one at a time, in order, as follows. First, with the current theta, compute the mean gradient g of the training-set images indicated by the numbers of the mini-batch (in the order of O). Next, add weight decay to the weight components only: g_p <- g_p + lambda * theta_p (the bias components are left unchanged). The value sqrt(SUM_p g_p * g_p) at this point is the "gradient magnitude" of this mini-batch. Finally, update theta by the method of (3). Processing one mini-batch counts as one "update".
(d) With the current theta, evaluate the training set and the validation set, and obtain the training loss, the training correct count, the validation loss and the validation correct count. Also, the sum of the gradient magnitudes of this epoch's mini-batches added in order, divided by the number of mini-batches, is the epoch's gradient magnitude. Also record whether each image of the training set is correct (used in 9 (3)).
(e) If e = 1, or if the validation loss is smaller than the best validation loss so far, this epoch "improved". In that case, set the best validation loss to this validation loss and the best epoch to e, save the current theta and the validation correct count, and set the wait count to 0. If it did not improve, increase the wait count by 1.
(f) If the wait count has reached P, training ends (stop reason early). Otherwise, if e = E, training ends (stop reason max_epochs).
(3) Update by the optimizer
- SGD: for each p in parameter order, theta_p <- theta_p - eta_e * g_p
- MOMENTUM: for each p in parameter order, v_p <- mu * v_p + g_p, theta_p <- theta_p - eta_e * v_p
- ADAM: first, pi1 <- pi1 * beta1 and pi2 <- pi2 * beta2 (done only once per update). Then, for each p in parameter order, m_p <- beta1 * m_p + (1 - beta1) * g_p, v_p <- beta2 * v_p + (1 - beta2) * g_p * g_p, m' = m_p / (1 - pi1), v' = v_p / (1 - pi2), theta_p <- theta_p - eta_e * m' / (sqrt(v') + epsilon).
(4) Result of training
When training ends, the saved theta of the best epoch is the "final weights". The number of epochs performed is the "number of epochs", and the total number of updates is the "number of updates". All evaluations of 9 and 10 use the final weights.

* 9. Evaluation of each run
For each run, evaluate the test data with the final weights, and obtain the test loss, the test correct count, and for each test image the scores, the prediction, the confidence and the hidden-layer activations a^l_j. In addition, compute the following values.
(1) Top-2 correct count: the number of test images for which the prediction matches the label, or the class with the largest score among the classes other than the prediction (ties: the smaller label) matches the label.
(2) Mean confidence: the mean confidence of the correct test images and the mean confidence of the test images that are not correct (added in test data order and divided by the number of images). If there is no such image, there is no value.
(3) Forgetting: uses the correct/incorrect status of each training-set image in each epoch, recorded in step (d) of 8 (2). For each training-set image, the number of e (2 <= e <= number of epochs) for which the image is correct in epoch e - 1 and not correct in epoch e is the image's forgetting count. events is the sum of the forgetting counts of all images, rows is the number of images with a forgetting count of 1 or more, and never_learned is the number of images that were not correct in any epoch.
(4) Weight norms and changes: for each layer, the square root of the sum of the squares of the weights of that layer (biases not included), added in parameter order, is the "weight norm", and the square root of the sum of the squares of (final weight - initial value), added in the same order, is the "weight change".
(5) Learning curve: let Lmax be the maximum of the training losses and validation losses of all epochs performed in that run. For each epoch, prepare a row of 40 space characters (the leftmost is column 0), put the character t at column ct = floor(39 * Ltr / Lmax + 0.5) for the training loss Ltr, and then put the character v at column cv = floor(39 * Lva / Lmax + 0.5) for the validation loss Lva. However, when cv = ct, that column becomes *.
(6) Confusion matrix and per-class values: the confusion matrix is a K-by-K table C, where C[y][p] is the number of test images with label y and prediction p. For class k, support is the sum of row k of C, predicted is the sum of column k of C, and precision, recall and f1 are the 4-decimal notations of the integer ratios C[k][k]/predicted, C[k][k]/support and (2 * C[k][k])/(support + predicted) respectively.
(7) Calibration: assign each test image to the bin beta = min(M - 1, floor(c * M)) (beta = 0, ..., M - 1) determined by its confidence c. The lower end of bin beta is beta / M and its upper end is (beta + 1) / M. For each bin, compute the number of images, the correct count, the accuracy (the 4-decimal notation of correct count/number of images) and the mean confidence (added in test data order and divided by the number of images). ECE is the sum of (number of images / T) * |correct count / number of images - mean confidence| over the bins that have one or more images, added in bin order (the divisions here are real divisions).
(8) Hidden-layer activations: for each hidden layer l and each class k, compute the mean of a^l_j (j = 1, ..., n_l) over the test images with label k (added in test data order and divided by the number of images). If there is no test image with label k, there is no value. The "preferred class" of each unit j is, among the classes that have a mean value, the class with the largest mean for unit j (ties: the smaller label). For a layer whose activation function is RELU, also count, for each unit, the number of test images for which its activation is 0.
(9) Pruning: for each value q of PRUNE, sort all weights of the network (biases not included; all layers together) by the absolute value of the final weight in increasing order (ties: smaller parameter number first), and evaluate the test data with the theta obtained by replacing the first floor(q * N_w / 100) weights with 0 (the final weights themselves are not changed). Obtain the number of replaced weights, the correct count and the mean loss.
(10) Noise: for each value r of NOISE, obtain the correct count when the test data with noise rate r (below) are evaluated with the final weights. The test data with noise rate r are built as follows. Initialize the generator with seed SEED; in test data order, for each image, for each pixel starting from the first character of the pixel string, draw one random number, and if its remainder modulo 100 is less than r, flip that pixel (swap 0 and 1). The label is the same as that of the original image. The total number of flipped pixels is the flip count of noise rate r.
(11) Misclassified: the test images that are not correct, arranged in test data order.

* 10. Comparison of runs
(1) Ranking: sort the runs by test correct count in decreasing order, ties by best validation loss in increasing order, and remaining ties by run order. This order is called the "rank order", and the run ranked 1st is called the "top run".
(2) Agreement count: the agreement count of run a and run b is the number of test images for which the predictions of a and b are the same.
(3) McNemar test: for each run o other than the top run, let b be the number of test images that the top run gets correct and o does not, and c the number of test images that the top run does not get correct and o does. Let numerator = max(|b - c| - 1, 0) * max(|b - c| - 1, 0) and denominator = b + c; the value of chi2 is the 4-decimal notation of the integer ratio numerator/denominator if the denominator is positive, and 0.0000 if the denominator is 0. The result is significant (yes) if numerator * 1000 > 3841 * denominator (compared as integers), and not significant (no) otherwise.
(4) Majority vote: for each test image, count the votes of each class (the number of runs that predicted that class). Among the classes with the maximum number of votes, select the one given by the prediction of the first run, going through the runs in rank order, that predicts a class with the maximum number of votes; this is the majority-vote prediction (if only one class has the maximum number of votes, it is that class). Obtain the correct count of the majority vote, fixed (the number of test images for which the majority-vote prediction is correct and the top run is not correct) and broken (the number of test images for which the top run is correct and the majority-vote prediction is not correct).
(5) Probability averaging: use only the runs whose network has a SOFTMAX output layer, in run order. For each test image, compute for each class the mean of those runs' scores (added in run order and divided by the number of runs), take the class with the largest mean (ties: the smaller label) as the prediction, and obtain its correct count. If there is no such run, this is not done.
(6) Confused pairs: for the table U obtained by adding the confusion matrices of all runs, the first 5 pairs (y, p) with y != p and U[y][p] > 0, sorted by U[y][p] in decreasing order, ties by y in increasing order, and remaining ties by p in increasing order (all of them if there are fewer than 5).
(7) Saliency map: with the final weights of the top run, for each class k, compute the mean V_i (i = 1, ..., W * H; added in test data order and divided by the number of images) of the absolute values |g_i| of the input gradients of the test images with label k. Let Vmax be the maximum of V_1, ..., V_(W*H); the level of pixel i is min(9, floor(10 * V_i / Vmax)). If there is no test image with label k, or Vmax = 0, the level of every pixel is 0.
(8) Hardest training examples: evaluate the training set with the final weights of the top run; the first 5 training-set images when sorted by loss in decreasing order (ties: training set order) (all of them if m < 5).
(9) Misclassified examples: for each test image misclassified by the top run (9 (11)), obtain the prediction of each run, the majority-vote prediction and the nearest image. The nearest image is, among all images of train.csv (the training set and the validation set), the image with the smallest number of positions where the pixel strings differ (the distance) (ties: the image that comes earlier in train.csv).

* 11. Data summary
For each class k, count the images with label k in each of the training set, the validation set and the test data. Let n_k be the number of training-set images with label k and I_k the total number of 1s in the pixel strings of those images; the ink amount is the 4-decimal notation of the integer ratio I_k/n_k (if n_k = 0, it is "-").
The mean image of class k is obtained by computing, for each pixel i, the level min(9, floor(10 * c_i / n_k)) with integer arithmetic, where c_i is the number of training-set images with label k whose i-th character is 1 (if n_k = 0, the level of every pixel is 0).

[Output files]
Write five files: output/gradient_check.txt, output/training_log.csv, output/final_weights.txt, output/predictions.csv and output/evaluation.txt. The output/ folder is provided empty.

* Common rules
- The output consists of ASCII characters only, and every line (including the last line) ends with a newline (LF). Do not put extra whitespace at the start or end of a line, and do not insert empty lines that are not specified.
- In the formats below, each part enclosed in < > is replaced by a value, and every other character is written as is. Values are separated by a single space (a comma in CSV files).
- Integers are written in base 10 without extra leading zeros.
- A value marked "real (d decimals)" is rounded to d decimal places and written in fixed-point notation with exactly d digits after the decimal point (example: with d = 4, 12.5 is 12.5000). Exponential notation is not used, and when the integer part is 0, 0 is written. Negative numbers are prefixed with -, but a value whose rounded result is 0 gets no - (example: with d = 4, -0.00004 is 0.0000).
- A value marked "ratio" is written in the 4-decimal notation of an integer ratio from 1 of [Processing].
- A "level map" represents the level of each pixel (an integer 0 to 9) as one digit character, arranged in H lines of W characters each (from the top row down, each row from left to right). To "place side by side" the level maps of K classes means that each of the H lines is the corresponding line (W characters) of the maps of classes 0, ..., K - 1, separated by a single space each.

* output/gradient_check.txt
Write the result of the gradient check of each network in network order, separated by one empty line each. For each network, write the following lines in this order.
- network <network name>
- parameters <N_p>
- batch <the IDs of the images of the check batch, in batch order>
- One line per layer l (l = 1, ..., L): layer <l> weights <number of checked weights> biases <number of checked biases>
- checked <total number of checked parameters>
- result <PASS or FAIL>

* output/training_log.csv
The first line is a header line, the string run,epoch,lr,grad_norm,train_loss,train_acc,val_loss,val_acc,improved. Then, in run order, for each epoch performed in each run (in epoch order), write the following line.
<run name>,<e>,<eta_e: real (6 decimals)>,<epoch gradient magnitude: real (4 decimals)>,<training loss: real (6 decimals)>,<training correct count/m: ratio>,<validation loss: real (6 decimals)>,<validation correct count/n_v: ratio>,<1 if improved, otherwise 0>

* output/final_weights.txt
Write the final weights of each run in run order, separated by one empty line each. For each run, the first line is RUN <run name> NETWORK <network name> EPOCH <best epoch>, followed by the LAYER line, W lines and B line of each layer starting from layer 1, in the same format as weights.txt. The weight and bias values are real (4 decimals).

* output/predictions.csv
The first line is a header line, the string run,id,label,predicted,confidence. Then, in run order, for each run, write the following line for each test image in test data order.

[Source files]
Split the program into the following six source files (file names follow the conventions of each language).
- main: holds the overall flow and most of the processing. It calls the input reading, splits the data, performs the gradient check (check batch, numerical differentiation, judging the errors and tallying per layer), the training of each run (shuffling and mini-batches, mean gradient and weight decay, gradient magnitude, evaluation per epoch, early stopping and saving the best weights), the evaluation of each run (top-2, confidence, forgetting, weight norms and changes, learning curve, confusion matrix, calibration, hidden-layer activations, pruning, noise), the comparison of runs (ranking, agreement counts, McNemar test, majority vote, probability averaging, confused pairs, saliency maps, hardest training examples, misclassified examples and nearest images), the data summary, and assembles and writes the five output files.
- dataset: reads the five input files and returns the images (ID, label, pixel string, input vector), the network definitions, the initial weights, the setting values and the run definitions. Also handles the MINSTD generator and shuffling.
- layers: handles the activation functions and their derivatives, the computation of a layer's pre-activations (weighted sum and bias), the sum that propagates the error back to the previous layer, and the computation of the scores, loss and error of the output layer (SOFTMAX and SIGMOID).
- network: represents the structure of a network (layer sizes, activation functions, the parameter sequence and the position of each layer in it, the distinction between weights and biases), and computes the forward pass of one image (recording pre-activations and activations), the gradient by backpropagation, and the input gradient.
- optimizers: holds and updates the state of SGD, MOMENTUM and ADAM, and handles the step decay of the learning rate.
- evaluation: handles the real-number format (number of decimals, rounding, treatment of -0), the 4-decimal notation of integer ratios, the prediction (the class with the largest score) and the selection of the second class, the confusion matrix and per-class values, level map strings, and the display of images using the characters # and .

[Constraints]
- 5 <= n <= 200, 1 <= T <= 200, 1 <= W * H <= 64, 2 <= K <= 10. There are 1 to 4 networks and 1 to 6 runs. The given data have n = 160 (m = 128, n_v = 32), T = 100, W = H = 8, K = 10, two networks (one with two hidden layers and one with one), and four runs. Training and evaluating all runs requires about 2.2 * 10^7 multiply-add pairs in total.
- The input files follow the formats above correctly. There is no need to check the input for errors.
- In the given data, the absolute value of every argument of exp is less than 700, and the training losses and validation losses are positive.
- In the given data, every error of the gradient check is less than 1e-8, and the pre-activations of the RELU layers on the check batch images are at least 1e-4 away from 0 at the initial values.
- In the given data, the validation losses of different epochs of each run differ by more than 1e-9 in relative terms, so the early stopping decisions do not change due to small differences in computation.
- In the given data, every real number written to the output is sufficiently far from a rounding boundary. Also, the results of comparisons such as the prediction and the selection of the second class, the preferred classes, the ranking, the pruning order, the order of the hardest training examples, the calibration bins, the learning curve columns, the levels and the RELU decisions do not change under differences in the order of additions, fused multiply-add, differences in the last digit of exp, ln and tanh, or even changes of about 1e-12 in the initial values and the setting values.
- In a language whose standard library has no tanh, tanh(z) may be computed from exp by a formula such as 1 - 2 / (exp(2 * z) + 1). For the given data and the [Example], this does not change the output.
- The 4-decimal notation of integer ratios and the McNemar test decision can be done with integer arithmetic only. The absolute values of the integers that appear are less than 2^31.

In this example, n = 10, so images E01 to E08 are the training set and E09 and E10 are the validation set. There are three mini-batches, of 3, 3 and 2 images, so each run performs 3 updates per epoch. Run a_sgd does not improve in epochs 3 and 4; since the wait count reaches P = 2, it ends at epoch 4 (early), and its final weights are those of epoch 2. Run a_adam trained up to the maximum number of epochs E = 5 (max_epochs). In the ranking, a_adam and a_sgd both have a test correct count of 3, so a_adam, which has the smaller best validation loss, is ranked 1st. In the gradient check of network a, D = 6, so the 8 parameters 1, 7, 13, 19, 25, 31, 37, 43 are checked. The parameters of layer 1 are 1 to 30 (weights 1 to 27, biases 28 to 30), those of layer 2 are 31 to 38 (weights 31 to 36), and those of layer 3 are 39 to 47 (weights 39 to 44).
