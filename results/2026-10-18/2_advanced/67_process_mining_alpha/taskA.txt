[Overview]
Write a program that performs process mining on an event log recording an insurance claim handling process. It reads three files from the input/ folder: an event log, a reference model (a Petri net) and parameters. First it validates the log, builds the trace (sequence of activities) of each case (one claim), and computes log statistics, variants (groups of cases with the same trace), a directly-follows graph with waiting times, and a footprint (a table of the basic relations between activities). Next it discovers workflow nets with the alpha algorithm and the alpha+ algorithm from the log without the cases that contain rare transitions, and finds a dependency graph with the heuristic miner from the full log. Then, for the reference model and the two discovered nets, it determines soundness by state-space exploration, and computes footprint fitness, precision, and fitness and waiting times by timed token replay. Finally it analyzes the performers (resources), and writes the results to 8 files in the output/ folder. All ratios and averages are computed exactly as fractions of integers; floating-point numbers are not used. Nothing is printed to standard output.

[Input files]
The common format is as follows.
- Every file consists of ASCII characters only, and every line ends with a newline (LF) (including the last line). There are no blank lines.
- Line numbers of a file are counted with the first line as line 1.
- Integers are non-negative decimal integers without extra leading zeros.
- Activity names are strings of 1 to 20 characters consisting of lowercase letters and _, whose first and last characters are lowercase letters. Case IDs are strings of 1 to 8 characters consisting of uppercase letters and digits. Resource names are strings of 1 to 12 letters in which only the first character is an uppercase letter. Place names are strings of 1 to 20 characters consisting of lowercase letters, digits and _, whose first character is a lowercase letter.
- In the descriptions below, <...> denotes a part where a value goes. The symbols < > themselves appear in neither the input nor the output.

(1) input/eventlog.csv (event log)
Line 1 is the header line "case_id,activity,timestamp,resource", and from line 2 on there is one data row per line. Each data row is a case ID, an activity name, a timestamp and a resource name separated by a single comma (,), with no quotes and no spaces around the fields. A row means that in that case, that activity was completed at that timestamp by that resource.
A timestamp is a 16-character string of the form "2026-<month>-<day>T<hour>:<minute>", where <month>, <day>, <hour> and <minute> are each exactly 2 digits (a leading 0 is added when the value has one digit). The year is always 2026. The values of <month>, <day>, <hour> and <minute> may be out of range (this is checked in Section 2).
Data rows are not necessarily in order of timestamp, and the rows of the same case are not necessarily consecutive.

(2) input/model.txt (reference model)
A Petri net that is the reference model of the business process. It consists of the following 5 kinds of lines, in the order PLACE lines, TRANSITION lines, ARC lines, INITIAL line, FINAL line. Each line is a keyword and values separated by a single space.
PLACE <place name>: defines one place. The order of the PLACE lines is the place order of this net.
TRANSITION <activity name>: defines one transition with that activity name.
ARC <name1> <name2>: an arc from name1 to name2. One of them is a place name and the other is the activity name of a transition.
INITIAL <place name>: the place that holds one token in the initial marking. There is exactly one such line.
FINAL <place name>: the place that holds one token in the final marking. There is exactly one such line.

(3) input/params.txt (parameters)
It consists of the following 8 lines in this order. Each line is a keyword and a value separated by a single space. <integer> is a positive integer, and <fraction> is two positive integers joined with / (example: 4/5; not necessarily reduced), representing the value of that fraction. The value of each line is referred to by the symbol shown on the right.
filter_min_follows <integer>: f (the lower bound of directly-follows counts used in filtering)
sla_minutes <integer>: S (the target duration of a case, in minutes)
positive_observations <integer>: sigma (the number of observations required by the heuristic miner)
dependency_threshold <fraction>: theta_D (the dependency threshold)
relative_to_best <fraction>: rho (the upper bound of the difference from the best dependency measure)
loop1_threshold <fraction>: theta_1 (the threshold for length-one loops)
loop2_threshold <fraction>: theta_2 (the threshold for length-two loops)
and_threshold <fraction>: theta_A (the threshold for treating as AND)

[Processing]
Section 1. Common rules
- String order: strings are compared in lexicographic order, comparing character codes (ASCII) from the first character (when one is a prefix of the other, the shorter one is smaller). "In ascending order of name" and "in ascending order of ID" always refer to this order.
- Sequence order: sequences of activity names are compared element by element from the start using string order, and the first position where they differ decides. When one is a prefix of the other, the shorter one is smaller.
- Name pair order: name pairs (name1, name2) are ordered by name1 ascending, then by name2 ascending if equal.
- List notation: to output a collection of names, write the names arranged in the specified order and joined with "," (with no spaces). If the collection is empty, write "-". This is called list notation.
- Fractions: all ratios and averages in this task are handled exactly as fractions of integers. Do addition, subtraction, multiplication, division and comparison of fractions exactly with integers after clearing denominators.
- Fraction notation: a fraction v >= 0 is written as "<p>/<q>=<decimal>", i.e. the reduced fraction p/q (q >= 1; 0/1 if v is 0; denominator 1 if v is an integer) and the decimal obtained by truncating v to 4 decimal places, joined with =. With t = "the quotient of 10000 * p / q", the decimal is "<quotient of t / 10000>.<remainder of t / 10000 written with 4 digits (padded with leading zeros)>". For example, 2/3 is written 2/3=0.6666, 9/4 is written 9/4=2.2500, and 5 is written 5/1=5.0000. A negative fraction -v (v > 0) is written "-<p>/<q>=-<decimal>", i.e. the notation of v with a - placed before the numerator and before the decimal. However, when the truncated decimal is 0.0000, no - is placed before the decimal (example: -1/30000=0.0000). Only dependency measures (Section 8) can be negative.
- Percentage notation: for an integer a >= 0 and a positive integer b, with t = "the quotient of 10000 * a / b", write "<quotient of t / 100>.<remainder of t / 100 written with 2 digits (a leading 0 if it has one digit)>%" (example: if a = 1 and b = 3, 33.33%).
- Mean and median: the mean of a list of integers (of length 1 or more) is the fraction sum / count. For the median, sort the list in ascending order; if the length is odd, the median is the middle value; if it is even, it is the fraction (sum of the two middle values) / 2.
- Division: every integer division in this task divides a non-negative integer by a positive integer. "The quotient of x / y" is the integer with the fractional part discarded.
- Table format: for n items numbered 1 to n, writing an n-row, n-column table "with width w" means the following. The first line is 4 spaces followed by the numbers 1, 2, ..., n, each right-aligned in width w (padded with spaces on the left). Then, for i = 1, ..., n in this order, output a line consisting of the number i right-aligned in width 4, followed by the values of the cells in row i, column j for j = 1, ..., n in this order, each right-aligned in width w.
- Logs: a list of pairs "(sequence of activity names (a trace), positive integer (a weight))" is called a log. For a log M and activities a and b, the directly-follows count |a>b|_M is the sum, over the pairs of M, of "(the number of positions i in the trace x_1, ..., x_k with x_i = a and x_(i+1) = b) * weight" (a = b is allowed). Also, for a != b, the triangle count tri_M(a, b) is likewise the sum of "(the number of positions i with x_i = a, x_(i+1) = b and x_(i+2) = a) * weight".
- Basic relations: the basic relation between activities a and b (which may be the same) according to the directly-follows counts of a log M is defined as follows, and is denoted by the symbol shown on the right.
  |a>b|_M >= 1 and |b>a|_M = 0: causality from a to b (written a -> b). Symbol ->
  |a>b|_M = 0 and |b>a|_M >= 1: causality from b to a (b -> a). Symbol <-
  |a>b|_M >= 1 and |b>a|_M >= 1: parallel (a || b). Symbol ||
  |a>b|_M = 0 and |b>a|_M = 0: unrelated (a # b). Symbol #
  When a = b, the relation is either || or #. Only the alpha+ algorithm of Section 7 uses a relation different from this.
- Footprint: for a sequence of activities a_1, ..., a_n and a relation between activities, first output "ACTIVITY <i> <a_i>" one line each for i = 1, ..., n in this order, then output, with width 4, the table whose cell in row i, column j is the symbol of the relation between a_i and a_j. This is called the footprint of that sequence.

Section 2. Input validation and cases
Examine the data rows of eventlog.csv one at a time in ascending order of line number. For each row, check the conditions below in the listed order; if some condition applies, the row is rejected for the first condition that applies, and "line <line number>: <message>" is recorded as an error. A row to which no condition applies is adopted. Adopted rows are called events.
1. The timestamp is invalid: bad timestamp <timestamp>
  The timestamp is valid when all of the following hold: <month> is between 1 and 12, <day> is between 1 and (the number of days of that month), <hour> is between 0 and 23, and <minute> is between 0 and 59 (all bounds inclusive). The numbers of days of the months of 2026 are, from January, 31, 28, 31, 30, 31, 30, 31, 31, 30, 31, 30, 31.
2. A row with the same case ID, activity name and timestamp (as a string) as this row has already been adopted: duplicate event <case ID> <activity name> <timestamp>
- The time value of an event is the number of minutes elapsed since 2026-01-01 00:00, "((sum of the numbers of days of the months from January to the month before that month + <day> - 1) * 24 + <hour>) * 60 + <minute>". From here on, all comparisons and differences of times are done with time values.
- A group of events with the same case ID is called a case. The events of a case are ordered by time value ascending, then by line number ascending if equal (from here on, the events of a case are always handled in this order). The sequence of their activity names is called the trace of that case. Let C be the number of cases.
- The duration of a case is (time value of the last event) - (time value of the first event).
- The names that appear as activity names of events (without duplicates) are simply called "activities", and the names that appear as resource names (without duplicates) are simply called "resources".
- The log made of the traces of all cases, each with weight 1, in ascending order of case ID, is called the full log L. From here on, unless stated otherwise, |a>b| and tri(a, b) are the values in the full log L.

Section 3. Log statistics
- For each activity a, compute the following values.
  Event count: the number of events whose activity name is a
  Case count: the number of cases whose trace contains a
  Start count, end count: the number of cases whose trace starts with a, and ends with a, respectively
  Rework count: the number of cases whose trace contains a two or more times
  Waiting time: the mean, over each event whose activity name is a and which is not the first event of its case, of "its time value - the time value of the previous event in the case" (if there is no such event, there is no waiting time)
  Resource count: the number of distinct resources among the events whose activity name is a
  Model: yes if the reference model has a transition with activity name a, otherwise no
- For the case length (number of events) and for the duration, compute the minimum, maximum, mean and median over all cases.
- By day count: the quotient of (duration of the case) / 1440 is the day count of that case.
- Over target: a case whose duration is greater than S is called a late case.
- Weekdays: the weekday number of a time value t is the remainder of (the quotient of t / 1440 + 3) divided by 7, and the weekdays with weekday numbers 0, 1, 2, 3, 4, 5, 6 are Mon, Tue, Wed, Thu, Fri, Sat, Sun respectively (2026-01-01 is a Thursday). For each weekday, compute the number of events on that weekday, the number of cases whose first event is on that weekday (start count), and the number of cases whose last event is on that weekday (end count).

Section 4. Variants and filtering
- A group of cases with the same trace is called a variant, and its number of cases is the count of the variant. Variants are ordered by count descending, then by trace ascending in sequence order if equal, and are numbered from 1 in this order.
- For each variant, compute its first case (the case with the smallest case ID), the mean duration, the number of late cases, and the fitness (the case fitness when replaying on the reference model in Section 11; all cases with the same trace have the same value).
- Filtering: keep the cases in which every pair of adjacent activities (x_i, x_(i+1)) of the trace satisfies |x_i>x_(i+1)| >= f, and remove the cases that do not (a case with only one event is kept). Cases with the same trace get the same decision, so each variant is decided as either KEEP (kept) or DROP (removed). The log made of the traces of the KEEP variants, each with the variant's count as weight, in variant number order, is called the filtered log W.

Section 5. Directly-follows graph
- A pair of activities (a, b) with |a>b| >= 1 in the full log is called an edge (a = b is allowed). For each edge, compute the directly-follows count |a>b|, the case count (the number of cases in whose trace b immediately follows a somewhere), and the mean, minimum and maximum of the waiting times (over all cases, for every occurrence of two adjacent events whose activity names are a and b in this order, "time value of the later event - time value of the earlier event").
- Start activities: for each activity that appears as the first activity of a trace, compute the number of such cases. End activities: for each activity that appears as the last activity of a trace, compute the number of such cases and the mean duration of those cases.

Section 6. Alpha algorithm
Find a workflow net from the filtered log W. The same procedure is also used in Section 7, so it is described here as a procedure for "a log M, a set of activities T, and a relation R between activities (one of causality ->, parallel ||, unrelated #)". In the alpha algorithm, M = W, T = T_W (the set of activities appearing in W), and R = the basic relation (Section 1) according to the directly-follows counts of W.
(1) Let T_I be the set of the first activities of the traces of M, and T_O the set of the last activities.
(2) Candidate pairs: a pair (A, B) of subsets of T is called a candidate pair when all of the following hold.
  - Neither A nor B is empty.
  - a -> b for every activity a in A and every activity b in B.
  - a1 # a2 for all activities a1, a2 in A (including an activity paired with itself). The same holds for B.
  Let X be the set of all candidate pairs.
(3) Maximal pairs: a pair (A, B) in X for which there is no pair (A', B') in X such that A is a subset of A' (equality allowed), B is a subset of B' (equality allowed) and (A, B) != (A', B') is called a maximal pair, and let Y be the set of all maximal pairs.
(4) Any method may be used to find X and Y. For example, they can be found as follows. For each pair of activities satisfying all of a -> b, a # a and b # b, put ({a}, {b}) into X; then, for each pair in X, add to X those pairs, obtained by adding one activity of T to A or to B, that are candidate pairs, and repeat this until no new pair is added. A pair obtained by replacing A and B of a candidate pair with non-empty subsets is again a candidate pair, so this finds all of X. Also, a candidate pair (A, B) is maximal if and only if no pair obtained by adding one activity to A or to B is a candidate pair.
(5) Two maximal pairs are compared first by the sequences of the activities of A sorted in ascending order of name, in sequence order, and if those are equal, by the sequences of the activities of B sorted in ascending order of name, in sequence order; the smaller one comes first. Arrange the maximal pairs in this order and name them p1, p2, p3, ....
(6) The resulting net is as follows. The places are start, p1, p2, ..., end, and this order is the place order of the net. The transitions are the activities of T. The arcs are: an arc from start to t for each activity t of T_I, an arc from t to end for each activity t of T_O, and, for each maximal pair pk = (A, B), arcs from each activity of A to pk and arcs from pk to each activity of B. The initial marking has one token in start, and the final marking has one token in end.
(7) The causality count is the number of pairs (a, b) of activities of T (ordered pairs) with a -> b.
The net found by the alpha algorithm is called the alpha net. Also, an activity a of T_W with |a>a|_W >= 1 is called a length-one loop activity (in the alpha algorithm, a length-one loop activity is not unrelated to itself, so it belongs to no maximal pair).

Section 7. Alpha+ algorithm
- Let V be the log obtained by removing all length-one loop activities from each trace of W (the weights are unchanged), and let T_V be T_W without the length-one loop activities.
- For activities a != b, write a ~ b when tri_V(a, b) >= 1 and tri_V(b, a) >= 1. The alpha+ relation between activities a and b of T_V (which may be the same) is defined as follows, with all directly-follows counts taken as values in V.
  a -> b: |a>b| >= 1 and (|b>a| = 0 or a ~ b)
  a || b: |a>b| >= 1 and |b>a| >= 1 and not a ~ b
  a # b: |a>b| = 0 and |b>a| = 0
  When a ~ b, both a -> b and b -> a hold. The symbol of a footprint cell is -> if a -> b, otherwise <- if b -> a, otherwise || if a || b, and # in all other cases.
- Perform (1) to (7) of Section 6 with M = V, T = T_V and R = the alpha+ relation.
- Next, for each length-one loop activity t, let the predecessors pre(t) be "the set of activities a of T_V with |a>t|_W >= 1" and the successors post(t) be "the set of activities b of T_V with |t>b|_W >= 1" (W is the filtered log before the removal). If there is a maximal pair pk = (A, B) with A = pre(t) and B = post(t), add an arc from pk to t and an arc from t to pk (there is at most one such maximal pair). It is called the maximal pair corresponding to t.
- The net obtained in this way, whose places are start, p1, ..., end (in this order) and whose transitions are the activities of T_W (including the length-one loop activities), is called the alpha+ net. Its initial marking and final marking are the same as those of the alpha net.

Section 8. Heuristic miner
Find a dependency graph from the full log L. All directly-follows counts and triangle counts below are values in L.
- Length-one loops: for each activity a with |a>a| >= 1, the measure is |a>a| / (|a>a| + 1). If |a>a| >= sigma and measure >= theta_1, it is accepted (ACCEPT); otherwise it is rejected (REJECT). An accepted a is called an L1 loop activity.
- Length-two loops: for each pair of activities a, b (name of a < name of b) such that neither a nor b is an L1 loop activity and n = tri(a, b) + tri(b, a) >= 1, the measure is n / (n + 1). If n >= sigma and measure >= theta_2, it is accepted; otherwise it is rejected.
- Dependency measure: for activities a != b, the dependency measure D(a, b) is (|a>b| - |b>a|) / (|a>b| + |b>a| + 1). For an activity a, let Bout(a) be the maximum of D(a, c) over the activities c != a with |a>c| >= 1, and Bin(a) the maximum of D(c, a) over the activities c != a with |c>a| >= 1.
- Verdict: for each pair of activities (a, b) (a != b) with |a>b| >= 1, check the following in order; the first one that applies is the verdict.
  1. The pair of a and b is an accepted length-two loop: LOOP2
  2. |a>b| < sigma: REJECT_COUNT
  3. D(a, b) < theta_D: REJECT_MEASURE
  4. Bout(a) - D(a, b) > rho and Bin(b) - D(a, b) > rho: REJECT_BEST
  5. Otherwise: ACCEPT
- The edges of the dependency graph are (a, a) for each L1 loop activity a, and the pairs (a, b) whose verdict is LOOP2 or ACCEPT. For an activity a, an activity x with an edge (x, a) is called an input of a, and an activity x with an edge (a, x) is called an output of a (for an L1 loop activity, this includes the activity itself).
- Splits and joins: for each two activities b, c (name of b < name of c) chosen from the outputs of activity a other than a itself, the split measure is (|b>c| + |c>b|) / (|a>b| + |a>c| + 1). Likewise, for each two activities b, c (name of b < name of c) chosen from the inputs of a other than a itself, the join measure is (|b>c| + |c>b|) / (|b>a| + |c>a| + 1). If the measure is theta_A or more, it is AND; otherwise it is XOR.

Section 9. Petri net behavior and state-space exploration
For each of the three nets, the reference model, the alpha net and the alpha+ net, do the following.
- A marking is the number of tokens in each place. The initial marking and the final marking are the markings with one token in the respective designated place and zero tokens in every other place. The input places of a transition t are the places with an arc to t, and its output places are the places with an arc from t. In a marking, a transition t is enabled when every input place of t has one or more tokens (a transition with no input place is always enabled). Firing an enabled t removes one token from each input place and then adds one token to each output place.
- A marking in which every place has at most one token is called a safe marking. Mark the initial marking as explored; for each explored marking M and each transition t enabled in M, if the marking M' after firing is safe, create an edge from M to M' and add M' to the explored markings; if M' is not safe, count it as an unsafe firing (M' is not added to the explored markings). Repeat this until no new edge or explored marking is added. The explored markings and the edges do not depend on the order of exploration.
- Compute the following values.
  Marking count: the number of explored markings
  Edge count: the number of edges (one per pair of M and t)
  Unsafe firing count: the number of pairs of M and t that were unsafe firings
  Deadlock count: the number of explored markings in which no transition is enabled and which are not the final marking
  Stuck count: the number of explored markings from which the final marking cannot be reached by following edges (the final marking itself counts as able to reach it; if the final marking is not explored, all explored markings are counted)
  Final: yes if the final marking is explored, otherwise no
  Dead transitions: the transitions that are not enabled in any explored marking
  Sound: yes if the unsafe firing count and the stuck count are both 0 and there is no dead transition, otherwise no
- Net directly-follows: when a transition t is enabled in an explored marking M, the marking M' after firing it is safe, and a transition u is enabled in M', the pair (t, u) is a directly-follows pair of the net (t = u is allowed).

Section 10. Footprint fitness and precision
- Footprint fitness: for each of the three nets, let U be the union of the activities and the activity names of the transitions of that net. For each pair of activities a, b of U (which may be the same), the log-side relation is the basic relation according to the directly-follows counts of the full log, and the model-side relation is the basic relation "taking |a>b| = 1 if (a, b) is a directly-follows pair of the net and |a>b| = 0 otherwise". Let d be the number of pairs whose two symbols differ (counted as ordered pairs); the fitness is 1 - d / (number of elements of U * number of elements of U).
- Precision: a leading part of a trace of the full log (including the empty sequence of length 0 and the whole trace) is called a prefix. For each distinct prefix pi, compute the weight w(pi) (the number of cases whose trace starts with pi) and the followers O(pi) (the set of activities that immediately follow pi in the cases whose trace starts with pi and is longer than pi). A prefix pi is said to fit the net when, firing the activities of pi in order as transitions starting from the initial marking of the net, every activity is a transition of the net and is enabled at that point. For a fitting prefix pi, let E(pi) be the set of transitions enabled in the marking after firing all of it; the transitions in E(pi) that are not in O(pi) are called the escapes of pi. The allowed count is the sum of w(pi) * (number of elements of E(pi)) over all fitting prefixes, the escaping count is the sum of w(pi) * (number of escapes), and the precision is 1 - escaping count / allowed count (if the allowed count is 0, the precision is 1). Also, for each transition, the sum of w(pi) over the fitting prefixes for which it is an escape is the escape weight of that transition.

Section 11. Token replay
For each of the three nets, replay each case of the full log as follows.
- Each place holds tokens, each together with the time value at which it was produced. At the start of the replay, put one token with the time value of the first event of the case into the place of the initial marking, set the produced count p to 1, and set the consumed count c, the missing count m and the skipped count to 0.
- Process the events of the case in order. If the net has no transition with the activity name of the event, add 1 to the skipped count and go on to the next event. If it has one, then for each input place q of that transition: add 1 to c; if q has a token, remove the earliest produced one among its tokens (any one among those with the same time value), record "time value of the event - time value of that token" as a waiting time of q, and also count this once as "a consumption from q by this transition". If q has no token, add 1 to m and count it once as a missing token of q. Then add one token with the time value of the event to each output place, and add that number of tokens to p.
- After all events have been processed, for the place q of the final marking: add 1 to c; if q has a token, remove the earliest produced one (no waiting time is recorded); otherwise add 1 to m and count it once as a missing token of q. The number of tokens left in each place after that is the remaining of that place, and the sum of the remainings is the remaining count r.
- The fitness of a case is 1/2 * (1 - m / c) + 1/2 * (1 - r / p). A case with m = 0 and r = 0 is called perfectly fitting.
- For each net, compute the totals of m, r, c, p and the skipped count over all cases, the fitness computed from those totals with the same formula, and the number of perfectly fitting cases. For each place, compute the total missing, the total remaining, the deviating case count (the number of cases in which the missing or the remaining of that place is 1 or more), the number of recorded waiting times, and their mean and maximum. Furthermore, for each place with two or more output transitions (transitions that have that place as an input place), sum over all cases, for each output transition, the number of consumptions from that place by that transition.

Section 12. Resource analysis
- For each resource, compute the event count, the case count (the number of cases containing an event of that resource), and the event count per activity.
- Handovers: for each two adjacent events (e_i, e_(i+1)) of each case, count the resource pair (resource of e_i, resource of e_(i+1)) as one handover (pairs with the same resource are also counted). For each resource pair, compute the number of handovers and the number of cases with one or more handovers of that pair.
- Subcontracting: for each three consecutive events (e_i, e_(i+1), e_(i+2)) of each case such that e_i and e_(i+2) have the same resource and the resource of e_(i+1) differs from it, count the resource pair (resource of e_i, resource of e_(i+1)) once.
- Working together: for each pair of resources a, b (name of a < name of b), compute the number of cases containing both an event of a and an event of b.

[Output files]
Write the following 8 files to the output/ folder. In every file, the separator within a line is a single space (a single comma in csv files; table lines follow the table format of Section 1), and no line has trailing spaces. Every line ends with a newline (LF), and no blank lines are output. Integers are written in decimal without extra leading zeros. Fractions and percentages are written in the fraction notation and the percentage notation of Section 1, respectively, and <list of ...> is written in the list notation of Section 1. Unless stated otherwise, the names in a list are sorted in ascending order of name.

(1) output/log_summary.txt (validation result and log statistics)
First, output the errors recorded in Section 2, in the order recorded, in the form "ERROR <recorded error>". Then output the following line.
LOG rows <number of data rows> adopted <number of events> rejected <number of rejected rows> cases <C> activities <number of activities> resources <number of resources> first <first timestamp> last <last timestamp>
<first timestamp> and <last timestamp> are the timestamps of the events with the smallest and the largest time value, written as the input strings.
Then, for each activity in ascending order of name, output one line in the following form. When there is no waiting time, write - in place of <waiting time>.

[Source files]
Organize the program into the following 7 source files (name the files following the conventions of each language).
- main: holds the overall flow and the core of the processing. It extracts the parameters, validates the event log and builds the cases, computes the log statistics (per-activity values, by day count, over target, by weekday), the variants and the filtering, the edges and waiting times of the directly-follows graph, the extension of candidate pairs, the maximality test and the net construction of the alpha algorithm (shared by the alpha and alpha+ algorithms), the removal and reinsertion of loop activities in the alpha+ algorithm, the loop and dependency verdicts and the split and join verdicts of the heuristic miner, the state-space exploration and the soundness check, the footprint fitness, the precision computation, the timed token replay and its aggregation, and the resource analysis, and builds the lines of all output files.
- eventlog: reads eventlog.csv and params.txt, validates timestamps and converts them to time values, records events, groups them into cases and sorts them, and computes medians.
- dfg: counts the directly-follows counts of a log, determines basic relations, builds footprints, and handles the table format.
- alpha_miner: tests whether a pair obtained by adding one activity to a candidate pair is a candidate pair, provides the comparison used to sort maximal pairs, counts triangle counts, and determines the alpha+ relation.
- heuristic_miner: computes the dependency measures, the length-one and length-two loop measures, and the split and join measures.
- conformance: reads model.txt, records the Petri net (place order, transitions, input places and output places, initial marking and final marking), tests enabledness and fires transitions, records the replay totals (m, r, c, p, skipped count and per-place values) and computes fitness.
- report: handles the formatting of the fraction notation, percentage notation and list notation, and writing to files.

[Constraints]
- eventlog.csv has between 1 and 3000 data rows, and there is at least one event. There are at most 300 cases, at most 12 activities and at most 20 resources, and every case has at most 50 events.
- No activity name is start or end.
- model.txt has at most 20 places and at most 12 transitions, and the activity names of the transitions are all distinct. The place names are all distinct and differ from every activity name. Every name in an ARC line is defined by a PLACE line or a TRANSITION line, and the same arc never appears twice. The places of the INITIAL line and the FINAL line are defined by PLACE lines.
- 1 <= f <= 3000, 1 <= S <= 525600, 1 <= sigma <= 3000. Each of theta_D, rho, theta_1, theta_2, theta_A, written as a/b, satisfies 1 <= a <= b <= 100.
- At least one case remains in the filtered log, and no trace of V is empty.
- In both the alpha algorithm and the alpha+ algorithm, X has at most 5000 elements. For each of the three nets, there are at most 1000 explored markings. There are at most 5000 distinct prefixes.
- The absolute value of every integer appearing in the computation is less than 2^53. However, values such as the fitness with its denominators cleared, or the value multiplied by 10000 in the fraction notation, can exceed 2^31, so compute with 64-bit integers (or a type that represents integers below 2^53 exactly). Do all divisions and comparisons exactly with integers.
