[Overview]
Write a program that analyzes nonogram (picture logic) puzzles. A nonogram is a puzzle in which each cell of a grid with h rows (vertical) and w columns (horizontal) is decided to be either "filled" or "not filled". Each row and each column is given a clue: the lengths of the runs of consecutive filled cells in that row (column), listed in order from one end. The program reads the puzzle file input/puzzles.txt and the picture file input/pictures.txt. For each puzzle it checks the format and repeats two kinds of line solve (simple and precise), each of which finds the cells that can be determined by looking at a single row or column only, back and forth between rows and columns until nothing changes any more (propagation). When the cells are still not all decided, it searches by placing guesses that assume the state of a cell, and counts the solutions up to 2. From the results it writes whether the solution is unique, the difficulty, the location of a contradiction, the search log, the grading of an answer and more to output/solutions.txt and output/stats.csv. In addition, for each picture it builds the clues and examines whether the solution of that puzzle is uniquely determined and whether it can be solved by line solves alone. When needed, it creates a puzzle with added cells whose states are known from the start (given cells), and writes it to output/generated.txt. All computation is done with integers and booleans; floating-point numbers are not used. Nothing is written to standard output.

[Input files]
There are two input files: input/puzzles.txt and input/pictures.txt. Both files consist only of printable ASCII characters (including the space) and line feeds (LF), and every line (including the last one) ends with a line feed. No line has trailing spaces.

* input/puzzles.txt (the puzzle file)
A sequence of zero or more puzzle blocks. Outside the blocks there are only empty lines and lines that start with "#" (comment lines), and these are ignored. One block consists of the following lines in this order.
1. "PUZZLE s": s is the name of the puzzle. s has 1 to 32 characters and contains no space and no ",". (Whether it is a valid name is checked in step 2 of [Processing].)
2. "SIZE w h": w is the number of cells across (the number of columns) and h is the number of cells down (the number of rows). w and h are each an integer from 0 to 999 written in decimal without extra leading zeros.
3. "ROWS"
4. Row clue lines (zero or more lines): the k-th line gives the clue of the k-th row from the top.
5. "COLUMNS"
6. Column clue lines (zero or more lines): the k-th line gives the clue of the k-th column from the left.
7. Given lines (zero or more lines): each line has the form "GIVEN r c v" and states that the cell in the r-th row from the top and the c-th column from the left is known from the start to have state v. r and c are each an integer from 0 to 999 written in decimal without extra leading zeros, and v is a single character other than a space. If v is "#" it means a filled cell, and if it is "." it means a cell that is not filled. The given lines are numbered 1, 2, 3, ... from the top (the given number).
8. The answer part (may be absent): a line "ANSWER" followed by answer lines (zero or more lines). An answer is a grid that someone has solved partway or completely. The k-th answer line is the k-th row from the top, and the j-th character of that line is the j-th cell from the left. "#" means filled, "." means not filled, and "?" means not decided yet.
9. "END"
A clue line is a line of one or more characters consisting only of digits and spaces. An answer line is a line of one or more characters that contains no space and is neither "END" nor "ANSWER". A line inside a block is not a comment line even if it starts with "#" (an answer line may start with "#").

* input/pictures.txt (the picture file)
A sequence of zero or more picture blocks. Outside the blocks there are only empty lines and lines that start with "#" (comment lines), and these are ignored. One block consists of a line "PICTURE s", picture lines (zero or more lines) and a line "END", in this order. s is the name of the picture and satisfies the same conditions as a name in puzzles.txt. A picture line is a line of one or more characters that contains no space and is not "END". The k-th picture line is the k-th row from the top, and its j-th character is the j-th cell from the left. "#" is a filled cell and "." is a cell that is not filled. A line inside a block is not a comment line even if it starts with "#".

[Processing]
* 1. Terms and common rules
- Grid: an arrangement of cells with h rows and w columns. Rows are counted from the top as row 1, row 2, ..., row h, and columns from the left as column 1, column 2, ..., column w. The cell in row r and column c is written cell (r,c).
- Cell state: one of three states, "filled", "empty" and "unknown". Filled and empty together are called "determined". The determined count of a grid is the number of determined cells. When a cell state is written as one character, filled is "#", empty is "." and unknown is "?".
- Line: rows and columns together are called lines. The line of row r is the sequence of length w of cells (r,1), (r,2), ..., (r,w) in this order. The line of column c is the sequence of length h of cells (1,c), (2,c), ..., (h,c) in this order. The label of a line is "Rr" for row r and "Cc" for column c (example: R3, C12). A cell in a line is specified by its position counted 1, 2, 3, ... from the start. The state string of a line is the string formed by concatenating, in order, the one-character forms of the states of the cells of that line.
- Clue: a sequence of zero or more positive integers. Each integer is called a block, and its value is called the length of the block. The space-separated form of a clue is the integers written in decimal and joined with one space between them. The comma-separated form joins them with "," instead of spaces. In both forms, the empty clue (a clue with zero integers) is written "0".
- Run clue: for a sequence consisting only of filled and empty cells, a maximal part of consecutive filled cells is called a filled run. The clue that lists the lengths of the filled runs in order from the start is called the run clue of that sequence (example: the run clue of ".##.#" is 2, 1, and the run clue of "..." is the empty clue).
- Placement: for a clue H and a line of length n, an assignment of filled or empty to each of the n cells whose run clue equals H is called a placement of H. In a placement, the i-th block of H corresponds to the i-th filled run, and the position of the first cell of that run is called the start position of block i. A placement in which every cell that is determined in the line has the same state is called a placement consistent with the line.
- Number list: the numbers in increasing order joined with ",". If there are no numbers at all, it is written "-".
- Valid name: a name is valid if it has 1 to 20 characters and consists only of lowercase English letters (a to z), digits (0 to 9) and "_".
- Names are compared and sorted in lexicographic order by ASCII code.
- The program first processes puzzles.txt by steps 2 to 10 and writes output/solutions.txt and output/stats.csv, and then processes pictures.txt by step 11 and writes output/generated.txt.

* 2. Reading and checking the puzzles
Read the blocks of puzzles.txt in order from the start, and for each block check the following (1) to (9) in order. If one applies, the first one that applies makes the puzzle an error (an invalid puzzle) with that reason (the string in double quotes; X, A, B, i, k and so on are replaced by their values), and no further checks are made. If none applies, the puzzle is valid.
(1) The name is not a valid name: "bad name"
(2) The name equals the name of a block that comes earlier in this file (including blocks that were errors): "duplicate name"
(3) w or h is not between 1 and 30 inclusive: "bad size"
(4) The number X of row clue lines differs from h: "row count X expected h" (h is replaced by its value)
(5) The number X of column clue lines differs from w: "column count X expected w" (w is replaced by its value)
(6) Examine the row clue lines one at a time, from the line for row 1 to the line for row h, and then the column clue lines from the line for column 1 to the line for column w. If the line being examined is the clue line of row i and it is not a valid clue line, the reason is "bad clue row i". If it is a valid clue line and the sum of the block lengths of its clue + (number of blocks - 1) is greater than w, the reason is "row i too long". Column clue lines are handled in the same way, with the reasons "bad clue column i" and "column i too long" (the length compared against is h). The first line to which one applies decides the reason.
    A valid clue line is either the line consisting of the single character "0" (meaning the empty clue), or a line of one or more tokens joined with one space between them, where every token consists of 1 or 2 digits and its first character is not "0" (that is, an integer from 1 to 99 written without extra leading zeros). A line with a leading or trailing space, a line with two or more consecutive spaces, and a line that mixes "0" with other tokens are not valid clue lines. The clue that a valid clue line represents is the values of its tokens in order.
(7) The sum A of the block lengths of the row clues differs from the sum B of the block lengths of the column clues: "total mismatch rows=A columns=B"
(8) Examine the given lines in order of given number. For the line with given number k, if r is not between 1 and h inclusive, or c is not between 1 and w inclusive, or v is neither "#" nor ".", the reason is "bad given k". Otherwise, if cell (r,c) is the same cell as that of an earlier given line, the reason is "duplicate given k". The first line to which one applies decides the reason.
(9) There is an answer part, and the number of answer lines differs from h, or some answer line does not have length w, or some answer line contains a character other than "#", "." and "?": "bad answer"
The given cells of a valid puzzle are the pairs of cell and state represented by all of its given lines.

* 3. Line solve
The process of finding, from the current state of one line and its clue, the cells that can be determined by looking at that line only is called a line solve. There are two kinds of line solve, precise and simple. In both, if there is no placement consistent with the line, the result is "contradiction" and the grid is not changed. Otherwise, some of the unknown cells are determined as follows (cells that are already determined do not change).
- Precise: among the unknown cells, those that are filled in every placement consistent with the line become filled, and those that are empty in every placement consistent with the line become empty.
- Simple: for each block i of the clue, let L_i be the minimum and R_i the maximum of the start position of block i over the placements consistent with the line, and let b_i be the length of block i (L_i equals the start position in the placement with all blocks packed as far toward the start as possible, and R_i equals the start position in the placement with all blocks packed as far toward the end as possible). For each block i, the unknown cells among the cells from position R_i to position L_i + b_i - 1 (these exist only when R_i <= L_i + b_i - 1) become filled. Also, the unknown cells among the cells that lie in no range from position L_i to position R_i + b_i - 1 for any block i become empty. All other unknown cells stay unknown.
The number of cells that change from unknown to determined in a line solve is called the gain of that line solve. Every cell determined by the simple line solve is also determined, to the same state, by the precise line solve of the same line.

* 4. Propagation
Propagation takes a grid, a kind of line solve (precise or simple) and the "recompute" marks attached to the lines, and performs the following procedure.
(a) If there are rows carrying the recompute mark, choose the one with the smallest number among them. Otherwise, choose the column with the smallest number among the columns carrying the recompute mark. If there are neither, propagation ends with "done".
(b) Remove the mark from the chosen line, and perform one line solve on that line using the grid at that moment. This counts as one line solve.
(c) If the line solve is a contradiction, propagation ends with "contradiction" at that line (the grid stays as it is).
(d) Otherwise, write the newly determined cells (the cells that changed from unknown to determined in this line solve) into the grid. For each newly determined cell, attach the recompute mark to the other line crossing at that cell (the column of the cell for a row line solve, the row of the cell for a column line solve); if it already carries the mark, it stays as it is. Then go back to (a).
The record of a propagation is the sequence of items, one for each line solve performed in (b), in the order performed. The item is "label+gain" for a line solve that was not a contradiction (example: R2+3, C5+0), and "label!" for a line solve that was a contradiction (example: C4!).

* 5. Logical solving
Given a set of given cells, writing the states of the given cells into a grid whose cells are all unknown, attaching the recompute mark to every row and every column, and running propagation is called logical solving. Logical solving with the simple line solve is called simple solving, and logical solving with the precise line solve is called precise solving. The grid after logical solving is the grid at the moment the propagation ends. The result of logical solving is as follows.
- Propagation ended with contradiction: "contradiction at=L" (L is the label of the line that had the contradiction)
- Propagation ended with done, and all cells are determined: "solved"
- Propagation ended with done, and unknown cells remain: "stuck"

* 6. Search
When the result of precise solving is stuck, a search is performed starting from the grid after precise solving. The search is performed by calling the following procedure "search(G,d)" with G as the grid after precise solving and d as 1. Throughout the whole search, a guess count (initially 0) and a solution list (initially empty) are kept.
(a) Among the unknown cells of G, choose the cell for which the number of unknown cells in its row plus the number of unknown cells in its column is smallest. On a tie, choose the one with the smaller row number, and on a further tie the one with the smaller column number. This is the guess cell (r,c). This way of choosing a cell is called "the guess cell rule".
(b) Try the values v one at a time, in the order filled, empty. For each v, do the following. Add 1 to the guess count, and use the resulting value as the guess number of this guess. In a copy of G, set cell (r,c) to v, attach the recompute mark to row r and column c only, and run propagation with the precise line solve. The grid at the moment the propagation ends is the child grid, and the result of the guess is decided as follows.
  - Propagation ended with contradiction: the result is "contradiction at=L" (L is the label of the line that had the contradiction). Go on to the next v.
  - Propagation ended with done, and all cells of the child grid are determined: append the child grid to the end of the solution list; the result is "solutionN" (N is the length of the solution list after appending). If N has become 2, end the whole search immediately. Otherwise, go on to the next v.
  - Propagation ended with done, and unknown cells remain in the child grid: the result is "open". Call search(child grid,d + 1), and if the whole search ended inside it, end here immediately as well. Otherwise, go on to the next v.
For each guess, record the guess number, the depth d, the cell (r,c), the value v, the number of line solves in its propagation, the determined count of the child grid and the result (the guess record). Even if the propagation determines all cells partway, it continues line solves until the propagation ends, and the result is decided after the propagation ends. The search statistics are the guess count, the maximum depth (the maximum of the depth d of the guesses), the backtrack count (the number of guesses whose result was contradiction), the solution count (the length of the solution list) and the search line solve count (the total number of line solves in the propagations of all guesses).

* 7. Analysis
Given clues and a set of given cells, analyze them by the following procedure.
- Perform simple solving and precise solving. Both start from a grid whose cells are all unknown, with the given cells written in.
- If the result of precise solving is contradiction, the status is "contradiction", the difficulty is "-", and there is no solution.
- If the result of precise solving is solved, the status is "unique", and the solution is the single grid after precise solving. The difficulty is "easy" if the result of simple solving is also solved, and "medium" otherwise.
- If the result of precise solving is stuck, perform the search. If the solution count is 0, the status is "none"; if 1, "unique"; if 2, "multiple". The difficulty is "hard" if the status is unique, and "-" otherwise. The solutions are the solutions in the solution list of the search (for multiple, the 2 solutions in the order found).
- The line solve count of the analysis is the sum of the line solve count of precise solving and the search line solve count (the line solve count of simple solving is not included). The guess count and the maximum depth of the analysis are those values if a search was performed, and 0 if not. The solution count of the analysis is the solution count (0, 1 or 2).
The status multiple means that there are 2 or more solutions, and none means that there is no solution. Below, the same clues are sometimes analyzed many times, changing only the set of given cells.

* 8. Processing for each puzzle
For each valid puzzle, perform the analysis with its clues and given cells. This is called the analysis of the puzzle. For the analysis of the puzzle, compute the following values (the output formats are defined in [Output files]).
(1) Clue statistics: the total number of blocks of the row clues, the total number of blocks of the column clues, the total number of filled cells (the sum of the block lengths of the row clues), the maximum block length (the maximum over the clues of all rows and columns; 0 if there are no blocks at all), and the number of fixed lines (the total number of rows and columns whose clue is empty or whose sum of block lengths + (number of blocks - 1) equals the length of the line).
(2) Line solve statistics: over the items of the record of the propagation of precise solving, excluding contradiction items: the number of items with gain 1 or more (productive), the number of items with gain 0 (idle), the maximum gain (best; 0 if there are no items), and the label of the first item whose gain is best (at; "-" if best is 0).
(3) Remaining unknowns: when the result of precise solving is stuck, for each row and each column that still has unknown cells in the grid after precise solving, the number of unknown cells in it.
(4) Contradicting line: when the result of precise solving is contradiction, the label of the line that had the contradiction, its clue, and the state string of that line in the grid after precise solving.
(5) Difference between the two solutions: when the status is multiple, the cells whose states differ between the first solution and the second solution.
(6) Picture features: when the status is unique, the picture features defined in 9 for the solution.
(7) Evaluation of the given cells: when there is at least one given cell and the status is unique, for each given number k, analyze with the given cells except given cell k only; each k for which that status is unique is a redundant given cell. When there is at least one given cell and the status is contradiction or none, likewise analyze with the given cells except given cell k only; each k for which that status is unique or multiple is a blamed given cell. When the status is multiple, no evaluation is made.
(8) Grading of the answer: when there is an answer part, grade it as defined in 10.
Whenever two or more cells are listed, they are always listed in increasing order of row number, and within the same row in increasing order of column number (row-major order).

* 9. Picture features
For a grid consisting only of filled and empty cells (a solution or a picture), compute the following values.
- The number of filled cells.
- Connected components: two filled cells are considered connected when they are adjacent up, down, left or right. A set of filled cells that can reach one another by following connections is called a connected component. Compute the number of connected components and the number of cells of the largest connected component. If there are no filled cells, both are 0.
- Bounding box: the minimum and maximum of the numbers of the rows that contain a filled cell, and the minimum and maximum of the numbers of the columns that contain a filled cell. If there are no filled cells, there is none.
- Symmetry: "lr" applies when every cell (r,c) has the same state as cell (r,w + 1 - c); "ud" applies when every cell (r,c) has the same state as cell (h + 1 - r,c); "rot180" applies when every cell (r,c) has the same state as cell (h + 1 - r,w + 1 - c).

* 10. Grading of the answer
In the answer grid, "#" is filled, "." is empty and "?" is unknown.
- Mismatching row: a row such that its line in the answer grid has no placement consistent with it for its clue (a row that cannot be made to match the clue however its unknown cells are decided). Mismatching columns are defined in the same way.
- Mismatching given cell: a given cell whose cell is determined in the answer grid and differs from the state of the given cell.
- Determined count of the answer: the determined count of the answer grid.
- Result: if the determined count of the answer is less than h*w, it is "partial". Otherwise, it is "wrong" if there is any mismatching row, mismatching column or mismatching given cell, and "correct" if there is none.
- Extendability (computed only when the result is partial): "yes" if there is no mismatching row, no mismatching column and no mismatching given cell, and in addition the status of the analysis with the puzzle's given cells plus, as additional given cells, all the cells that are determined in the answer grid and are not given cells, is unique or multiple; "no" otherwise.
- Difference count (computed only when the status of the analysis of the puzzle is unique): the number of cells that are determined in the answer grid and whose state differs from that in the solution of the puzzle.

* 11. Creating puzzles from pictures
Read the blocks of pictures.txt in order from the start, and for each block check the following (1) to (4) in order. If one applies, the first one that applies makes the picture an error with that reason, and no further checks are made.
(1) The name is not a valid name: "bad name"
(2) The name equals the name of a picture block that comes earlier in this file (including blocks that were errors): "duplicate name"
(3) The number of picture lines is not between 1 and 30 inclusive: "bad height"
(4) Examine the picture lines in order from the top; the i-th picture line has a length that is not between 1 and 30 inclusive, or differs from the length of the first picture line, or contains a character other than "#" and ".": "bad row i" (the first line to which one applies decides the reason)
For a valid picture, let h be the number of picture lines and w the length of the first picture line, and build the puzzle whose clue for each row and each column is the run clue of that row and column of the picture (the picture's puzzle). Then decide the list of given cells by the following procedure. The state of a given cell added to the list is always the state of that cell in the picture.
(a) Initial analysis: analyze with no given cells (the empty list).
(b) Hint addition: while the status of the most recent analysis is multiple, repeat the following. Among the cells whose states differ between the first and second solutions of that analysis, append the first cell in row-major order to the end of the list, and analyze again with the list.
(c) Hint removal: examine the given cells of the list as it is when (b) has finished, one at a time, in the order they were added. Analyze with the current list without only that given cell, and if that status is unique, remove that given cell from the current list.
(d) Analyze with the list after (c).
(e) Logic hint addition: while the difficulty of the most recent analysis is hard, repeat the following. For the grid after precise solving of that analysis, append the cell chosen by the guess cell rule (6 (a)) to the end of the list, and analyze again with the list.
(f) Final analysis: the analysis performed last in (e). If nothing was added in (e), it is the analysis of (d). The final list is the list after (e).
Since the picture is always one of the solutions of the picture's puzzle, the status of every analysis from (a) on is unique or multiple, and (b) and (e) always terminate.
Also, when the picture's puzzle and some valid puzzle in puzzles.txt have equal w and equal h, and their clues agree on every row and every column (given cells and answers are not compared), the name of the first such puzzle in the file is the name of the puzzle with the same clues.

[Output files]
The program writes the following three files in the output/ folder. Every file consists only of ASCII characters, every line ends with a line feed (LF), and no line has trailing spaces. No empty lines are written other than those defined as paragraph separators. All integers are 0 or more and are written in decimal without extra leading zeros. In a format, only the symbols explained (symbols such as s, W, H, K and L that appear on their own in the format) are replaced by values, and all other characters are written as they are. The name s is written exactly as the string written in the first line of the block (the same for invalid puzzles and pictures).

* output/solutions.txt
For each block of puzzles.txt, in file order, write one paragraph, and after them write the ranking paragraph and the summary paragraph. Put one empty line between consecutive paragraphs. Put no empty line at the start or at the end of the file.

The paragraph of an invalid puzzle consists of the two lines "PUZZLE s" and "error reason" (reason is replaced by the reason of the error).

The paragraph of a valid puzzle consists of the following lines in this order. A line with a condition is written only when the condition holds. All values are those of the analysis of the puzzle.
1. "PUZZLE s"
2. "size=WxH givens=G status=S difficulty=D": W is w, H is h, G is the number of given cells, S is the status, and D is the difficulty.
3. "clues row_blocks=A column_blocks=B filled=F max_block=M fixed_lines=X": the clue statistics of 8 (1), written in the order explained there.
4. "simple known=K line_solves=N result=R": K is the determined count of the grid after simple solving, N is the line solve count of simple solving, and R is the result of simple solving.
5. "logic known=K line_solves=N result=R": the same values as in 4, for precise solving.
6. "steps productive=P idle=I best=B at=L": the line solve statistics of 8 (2).
7. (when h*w <= 49) "trace T": T is the items of the record of the propagation of precise solving, joined with one space between them.
8. (when the result of precise solving is stuck) "stuck rows=X columns=Y": X is, for each row that still has unknown cells, "row number:number of unknown cells", in increasing order of row number, joined with one space between them. Y is the same for the columns.
9. (when the status is contradiction) "conflict line=L clue=C cells=Z": L is the label of the line that had the contradiction, C is the comma-separated form of its clue, and Z is the state string of 8 (4).
10. (when a search was performed) "search guesses=G max_depth=D backtracks=B solutions=N line_solves=M": the search statistics (the guess count, the maximum depth, the backtrack count, the solution count and the search line solve count). After this line, in order of guess number, write for each guess the line "guess k depth=d cell=r,c value=v solves=n known=K result=X". k is the guess number, d is the depth, (r,c) is the guess cell, v is the value tried ("#" for filled, "." for empty), n is the number of line solves in its propagation, K is the determined count of the child grid, and X is the result of the guess.
11. (when the status is multiple) "differ count=N cells=Z": N is the number of cells whose states differ between the two solutions, and Z is those cells, in row-major order, each written "r,c" and joined with one space between them.
12. Side-by-side grid display: build a list of pairs of a name and a grid as follows. If the status is contradiction, the list is the single pair (partial, the grid after precise solving). Otherwise, add to the list, in this order: (simple, the grid after simple solving) if the result of simple solving is stuck; (logic, the grid after precise solving) if the result of precise solving is stuck; and (first, the first solution) and (second, the second solution) if the status is multiple. If the list is not empty, write a line consisting of "grid " followed by the names of the list joined with one space between them, and then write h lines. The r-th of these lines is the state strings of row r of each grid of the list, joined with " | " (the three characters space, vertical bar, space).
13. (when the status is unique) Write the line "sheet", the lines of the answer sheet (defined below), and the line "picture filled=N components=C largest=L bbox=Z symmetry=Y", in this order. N, C and L are the number of filled cells of the solution, the number of connected components, and the number of cells of the largest connected component. Z is the minimum row number, the minimum column number, the maximum row number and the maximum column number of the bounding box, in this order, joined with "," ("-" if there is no bounding box). Y is those of lr, ud and rot180 that apply, in this order, joined with "," ("none" if none of them applies).
14. (when there is at least one given cell and the status is unique) "givens redundant=X": X is the number list of the given numbers of the redundant given cells. (when there is at least one given cell and the status is contradiction or none) "givens blame=X": X is the number list of the given numbers of the blamed given cells.
15. (when there is an answer part) "answer result=R known=K rows=X columns=Y givens=Z": R is the result of the grading, K is the determined count of the answer, and X, Y and Z are the number lists of the numbers of the mismatching rows, the mismatching columns and the mismatching given cells (row numbers, column numbers and given numbers). If the result is partial, append " extendable=E" (E is the extendability) to the end of this line. Also, regardless of the result, if the status of the analysis of the puzzle is unique, append " differs=N" (N is the difference count) to the end of this line (after " extendable=E" if that was appended). After this line, write the line "mismatch L expected=C got=Q" for each mismatching row in increasing order of row number, and then for each mismatching column in increasing order of column number. L is the label of that line, C is the comma-separated form of its clue, and Q is the comma-separated form of the run clue of that line in the answer grid. However, when the result is partial, write "cells=Z" (Z is the state string of that line in the answer grid) instead of "got=Q".

The answer sheet is a figure that shows the solution together with the clues, and is built as follows.
- For each column c, build the sequence T_c of strings (tokens) obtained by splitting the space-separated form of the clue of that column at the spaces (for the empty clue, it is the single token "0"). The number of tokens of T_c is written |T_c|.
- Let W be the maximum length of all the tokens of all the columns plus 1, and let D be the maximum of |T_c|. Let P be the maximum length of the space-separated forms of the clues of all the rows.
- The first D lines (the column clue part): for t = 1, 2, ..., D in order, write the line formed by P spaces followed by, for each column c from left to right, the (t - (D - |T_c|))-th token of T_c right-aligned to width W (padded with spaces on the left) if t > D - |T_c|, and W spaces otherwise, with the trailing spaces finally removed. In other words, the column clues are aligned to the bottom.
- The next h lines (the board part): for row r, write the line formed by the space-separated form of the clue of row r right-aligned to width P (padded with spaces on the left), followed by, for each cell from column 1 in order, W - 1 spaces and the one character of the state of that cell.

The ranking paragraph consists of the line "RANKING" followed by the rank lines. Sort the valid puzzles whose analysis of the puzzle has status unique by difficulty (in the order easy, medium, hard), then by score in increasing order, then by name, and for the k-th puzzle (k = 1, 2, ...) write the line "rank k s D score=P size=WxH". D is the difficulty, P is the score (the line solve count of the analysis of the puzzle + 25 * the guess count of the analysis of the puzzle), W is w, and H is h. If there is no such puzzle, the paragraph is the single line "RANKING".

The summary paragraph is the single line "SUMMARY puzzles=N invalid=I contradiction=A none=B unique=C multiple=E easy=F medium=G hard=J line_solves=L guesses=Q". N is the number of blocks of puzzles.txt, I is the number of invalid puzzles, A, B, C and E are the numbers of valid puzzles whose analysis of the puzzle has status contradiction, none, unique and multiple respectively, F, G and J are the numbers of valid puzzles whose analysis of the puzzle has difficulty easy, medium and hard respectively, and L and Q are the total line solve count and the total guess count of the analyses of the puzzles over all valid puzzles (analyses for the evaluation of the given cells, the extendability and so on are not included).

* output/stats.csv
The first line is "puzzle,status,difficulty,width,height,givens,simple_known,logic_known,line_solves,guesses,max_depth,solutions,answer". Then write one line for each block of puzzles.txt, in file order. The line of a valid puzzle is the name, the status, the difficulty, w, h, the number of given cells, the determined count of the grid after simple solving, the determined count of the grid after precise solving, the line solve count of the analysis of the puzzle, the guess count, the maximum depth, the solution count, and the result of the grading ("-" if there is no answer part), joined with "," in this order. The line of an invalid puzzle is the name followed by ",invalid" and then ",-" 11 times.

* output/generated.txt
For each block of pictures.txt, in file order, write one paragraph, and after them write the summary paragraph. Put one empty line between consecutive paragraphs. Put no empty line at the start or at the end of the file.

The paragraph of an invalid picture is the single line "# picture s error reason" (reason is replaced by the reason of the error).

The paragraph of a valid picture consists of the following lines in this order.
1. "# picture s size=WxH filled=N components=C largest=L bbox=Z symmetry=Y": W is w, H is h, and N, C, L, Z and Y are the picture features of the picture, written in the same format as the "picture" line of solutions.txt.
2. "# clues row_blocks=A column_blocks=B filled=F max_block=M fixed_lines=X duplicate_of=U": A to X are the clue statistics of the picture's puzzle (8 (1)), and U is the name of the puzzle with the same clues ("-" if there is none).
3. "# plain status=S difficulty=D line_solves=N guesses=G": the status, the difficulty, the line solve count and the guess count of the initial analysis.
4. For each given cell added by hint addition, in the order added, "# hint k cell=r,c value=v status=S": k is the length of the list after adding, (r,c) is the cell added, v is its state ("#" for filled, "." for empty), and S is the status of the analysis after adding.
5. For each given cell removed by hint removal, in the order examined, "# drop cell=r,c".
6. For each given cell added by logic hint addition, in the order added, "# logic hint k cell=r,c value=v difficulty=D": k is the number in the order of addition by logic hint addition (1, 2, ...), (r,c) and v are as in 4, and D is the difficulty of the analysis after adding.
7. "# final status=S difficulty=D hints=N line_solves=M guesses=G": the status and the difficulty of the final analysis, the length of the final list, and the line solve count and the guess count of the final analysis.
8. The lines of the picture's puzzle written in the format of puzzles.txt: "PUZZLE s", "SIZE w h" (w and h are replaced by their values), "ROWS", one line each with the space-separated form of the clue of row 1 to row h, "COLUMNS", one line each with the space-separated form of the clue of column 1 to column w, one line "GIVEN r c v" (v is "#" or ".") for each given cell of the final list in row-major order, and "END".

The summary paragraph is the single line "# SUMMARY pictures=N invalid=I unique=U line_logic=L hinted=H hints=T". N is the number of blocks of pictures.txt, I is the number of invalid pictures, U is the number of valid pictures whose initial analysis has status unique, L is the number of valid pictures whose initial analysis has difficulty easy or medium, H is the number of valid pictures whose final list has length 1 or more, and T is the total of the lengths of the final lists of all valid pictures.

[Source files]
Split the source code into files with the following six roles (file names and extensions follow the conventions of each language).
- main: the overall flow and the largest share of the processing. Reading the two input files and splitting them into blocks, checking the puzzles and pictures and deciding the error reasons, the analysis (running simple solving and precise solving, calling the search, deciding the status, the difficulty, the line solve count and so on), the clue statistics, the line solve statistics, the remaining unknowns, the contradicting line, the difference between the two solutions, the picture features (connected components, bounding box, symmetry), the evaluation of the given cells, the grading of the answer (including the extendability and the difference count), the ranking and the summary, creating puzzles from pictures (hint addition, hint removal, logic hint addition, finding the puzzle with the same clues), and building all output lines and writing the three output files.
- clues: computing run clues, the space-separated and comma-separated forms of clues, checking and interpreting the tokens of clue lines, and deciding whether a clue fits within the length of a line.
- line_solver: the definition of the cell states, and the precise and simple line solves (including deciding whether a placement consistent with the line exists and computing the range of start positions of each block).
- propagation: propagation driven by the recompute marks, the record of propagation, and the determined count of a grid.
- search: choosing a cell by the guess cell rule, and the depth-first search (the guess record, the search statistics, and counting solutions up to 2).
- render: the one-character forms of cell states and the state strings of lines, and building the lines of the side-by-side grid display and of the answer sheet.

[Constraints]
- puzzles.txt has at most 1000 lines and at most 40 blocks. pictures.txt has at most 500 lines and at most 30 blocks. In both files, each line has at most 100 characters.
- In the input of this task, in every analysis performed in 2 to 11 (including the analyses for the evaluation of the given cells, the extendability and the creation of puzzles from pictures), the guess count is at most 100 and the maximum depth is at most 30.
- Every intermediate value of the computation fits in the range of a 32-bit signed integer.

Note: In cross, the run clue of row 5 of the answer, "..#.#", is 1, 1, which does not match the clue 1, so row 5 is a mismatching row. Column 5 is the same. In knotlet, precise solving determines no cell, so a search is performed. In guess 1, all 16 cells become determined partway through the propagation after cell (1,1) is set to filled, but as the propagation continues, the line solve of column 4 has a contradiction, so the result is contradiction. Even after the first solution is found in guess 3, guess 4 is performed to look for a second solution. In twins, there are given cells, but the status is multiple, so no "givens" line is written. In bar, the clue of row 2 is empty, yet given cell 1 makes cell (2,3) filled, so the line solve of row 2 has a contradiction. Removing given cell 1 makes the status unique, so the blamed given cell is 1. odd is an error because its clue line for row 1, "1 0", mixes "0" with another token. The clues of the picture's puzzle of diag agree with the clues of twins on every row and every column (the given cells of twins are not compared). In zigzag, after hint addition adds 7 given cells, hint removal removes cell (1,1) and cell (2,1). The remaining 5 given cells make the solution unique, but the difficulty is hard, so logic hint addition adds cell (1,3).
