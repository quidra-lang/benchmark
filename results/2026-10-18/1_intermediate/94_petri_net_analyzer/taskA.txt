[Overview]
Write a program that defines Petri nets (place/transition nets), simulates their behavior and analyzes their properties. The input contains one or more nets in sequence. For each net, the program reads the definition lines and builds the net, then executes the following commands one line at a time and writes the results to standard output. A net can specify arc weights, place capacities, transition priorities and inhibitor arcs. There are 20 kinds of commands: displaying and changing the marking, listing the enabled transitions, firing and undoing firing sequences, simulation by priority or by pseudo-random numbers, conflict detection, building the reachability graph and analyzing its properties (dead markings, boundedness, safeness, home markings, reversibility, persistence, liveness levels of the transitions), building the coverability tree by the Karp-Miller method, searching for a shortest firing sequence that reaches a target marking, displaying the incidence matrix, computing the minimal P-semiflows and T-semiflows by the Farkas algorithm, enumerating the minimal siphons and traps, structural classification and checking Commoner's condition, checking soundness as a workflow net, and displaying the definition. For an erroneous definition line or command line, the program outputs one line of the form "error: reason" and proceeds to the next line.

[Input format]
The first line contains a positive integer K. It is followed by K "blocks" in sequence, and the input ends there. Each block consists of the following lines in this order.
  - one line "NET <net name>"
  - definition lines (zero or more)
  - one line "END NET"
  - one line containing only a positive integer N
  - command lines (N lines)
The definition lines are the lines from the line after the NET line up to, but not including, the first line that is exactly equal to "END NET".
Every line other than the first line and the line of N consists of one or more "words" separated by single ASCII spaces. There is no whitespace at the start or end of a line, and there are no empty lines. Words consist only of printable ASCII characters other than space (character codes 33 to 126). The first word of a definition line is called the "keyword" and the first word of a command line is called the "command name"; in both cases the remaining words are called, in order, the first argument, the second argument, ...

The parts are written as follows.
- Name: a string consisting of one letter (A-Z, a-z) followed by 0 to 9 characters, each of which is a letter, a digit (0-9) or "_". The net name in the NET line is also a string of this form.
- Integer literal: a string of 1 to 10 characters consisting only of digits, whose first character is not "0" if it has 2 or more characters. Its value is the value read as a decimal number.

Each definition line is intended to be in one of the following 6 formats.
  place <name> <tokens>
  place <name> <tokens> <capacity>
  transition <name>
  transition <name> <priority>
  arc <name> <name> <weight>
  inhibit <name> <name> <threshold>
In a line whose keyword is one of place, transition, arc and inhibit and whose number of arguments matches one of the formats above, each argument is as given in the format. That is, each name part is a name, and tokens, capacity, priority, weight and threshold are integer literals whose values are from 0 to 99, from 1 to 99, from 0 to 99, from 1 to 9 and from 1 to 99, respectively. In the other definition lines (lines whose keyword is none of the four, and lines whose number of arguments does not match), the words have no restrictions other than those stated above.

The commands have the following 20 formats.
  MARKING
  RESET
  SET <place> <tokens>
  ENABLED
  FIRE <transition> ...
  UNDO <count>
  SIMULATE <steps> <seed> <mode>
  CONFLICTS
  REACH <limit>
  GRAPH <limit>
  COVER <limit>
  PATH <limit> <target>
  INCIDENCE
  PINV
  TINV
  SIPHONS
  TRAPS
  CLASSIFY
  WORKFLOW <limit>
  SHOW
FIRE is a format in which each of one or more arguments specifies a transition. Command lines do not necessarily match these formats, and their words have no restrictions other than those stated above. The handling of unknown command names, wrong numbers of arguments, invalid argument values and so on is defined in [Processing].

[Processing]
1. Overall flow
Process the blocks one at a time in input order. In each block, first process the definition lines in order by the procedure in section 2 to build the net, and when the "END NET" line is read, output the summary line. Then process the N command lines in order by the procedure in section 4. Blocks are independent; the net and the state of an earlier block do not affect later blocks.
Below, strings shown in double quotes as things to output appear in the output exactly as written. However, each part enclosed in < and > inside them is replaced by the string described. Numbers are written in decimal notation without extra leading zeros.

2. Net definition
A net consists of the following. Before any definition line is processed, there are no places, no transitions and no arcs.
- Sequence of places: each place has a name, an initial number of tokens and a capacity. The capacity is either a positive integer or none.
- Sequence of transitions: each transition has a name and a priority.
- Arcs: there are "input arcs" from a place p to a transition t and "output arcs" from a transition t to a place p, each with a positive integer weight. The weight of an input arc is written Pre(p, t) and the weight of an output arc is written Post(t, p). If there is no such arc, the value is 0.
- Inhibitor arcs: an inhibitor arc from a place p to a transition t has a positive integer threshold. It is written I(p, t), and I(p, t) is 0 if there is no such inhibitor arc.
Places are arranged in the order in which they are defined; this order is called the "place order". Transitions are also arranged in the order in which they are defined; this order is called the "transition order".

Definition lines are processed one at a time in order. Perform the following checks in this order; when an error is found, output the one line "error: <reason>" and ignore that line (the net does not change). Here "defined" means defined without error by an earlier line.
(1) If the keyword is none of place, transition, arc and inhibit, the reason is "unknown definition <keyword>".
(2) If the number of arguments is not 2 or 3 for place, not 1 or 2 for transition, or not 3 for arc and inhibit, the reason is "wrong number of arguments".
(3) For place and transition, if the first argument is the name of a defined place or transition, the reason is "duplicate name <first argument>". Places and transitions, taken together, have mutually distinct names.
(4) For place with 3 arguments, if the value of tokens is greater than the value of capacity, the reason is "tokens exceed capacity of <first argument>".
(5) For "arc X Y w", check the following in this order: if X is not the name of a defined place or transition, "unknown node <X>"; if Y is not, "unknown node <Y>"; if X and Y are both places or both transitions, "arc must connect a place and a transition"; if an arc from X to Y is already defined, "duplicate arc <X> <Y>".
(6) For "inhibit p t k", check the following in this order: if p is not the name of a defined place, "unknown place <p>"; if t is not the name of a defined transition, "unknown transition <t>"; if an inhibitor arc from p to t is already defined, "duplicate inhibitor <p> <t>".
If there is no error, define as follows.
- "place <name> <tokens>": append to the end of the sequence of places a place with that name, initial number of tokens equal to the value of tokens, and capacity none. In a line that gives a capacity, the capacity is that value.
- "transition <name>": append to the end of the sequence of transitions a transition with that name and priority 0. In a line that gives a priority, the priority is that value.
- "arc X Y w": if X is a place, set Pre(X, Y) to the value of w; if X is a transition, set Post(X, Y) to the value of w.
- "inhibit p t k": set I(p, t) to the value of k.
When the "END NET" line is read, output the following "summary line".
  "net <net name>: places=<P> transitions=<T> arcs=<A> inhibitors=<B>"
P is the number of places, T the number of transitions, A the number of defined arcs (input arcs and output arcs), and B the number of defined inhibitor arcs. Then set the current marking (section 3) to the initial marking and make the history (section 5) empty.

3. Markings and firing
(1) A "marking" assigns a number of tokens to each place. The value of a place p in a marking M is written M(p). The marking consisting of the initial number of tokens of each place is called the "initial marking". The program holds one "current marking".
A marking is written as the concatenation, in this order, of "(", the values of the places in place order separated by ",", and ")". For example "(1,0,2)". This is called the "marking notation". Only in COVER (section 9) does omega appear as a value; omega is written "w".
(2) A transition t is "enabled" in a marking M when all of the following 3 conditions hold.
  (a) M(p) >= Pre(p, t) for every place p.
  (b) M(p) < I(p, t) for every place p with I(p, t) > 0.
  (c) M(p) - Pre(p, t) + Post(t, p) <= c for every place p that has a capacity c.
When an enabled t is "fired" in M, the marking becomes M' with M'(p) = M(p) - Pre(p, t) + Post(t, p) for every place p. This is called "the marking obtained by firing t in M". A marking in which no transition is enabled is called a "dead marking".
When t is not enabled in M, the "reason" is the first of the following that applies. If some place does not satisfy (a), "insufficient tokens in <p>" for the first such place p in place order. Otherwise, if some place does not satisfy (b), "inhibited by <p>" for the first such place p. Otherwise, "capacity of <p> exceeded" for the first place p that does not satisfy (c).
(3) When transition names are output as a list, they are listed in transition order unless stated otherwise.
(4) A part written "<yes or no>" is "yes" if the stated condition holds and "no" if it does not.

4. Command processing procedure
Command lines are processed by the following procedure. If an error is found at any point, output the one line "error: <reason>" and finish processing that command. In that case, the current marking and the history do not change.
(1) If the command name is none of the 20 in [Input format], the reason is "unknown command <command name>".
(2) If the number of arguments differs from the format, the reason is "wrong number of arguments". The number of arguments in the format is 2 for SET and PATH, 3 for SIMULATE, 1 for UNDO, REACH, GRAPH, COVER and WORKFLOW, 1 or more for FIRE, and 0 for the others.
(3) For REACH, GRAPH, COVER, PATH and WORKFLOW, if <limit> is not an integer literal or its value is not between 1 and 2000 inclusive, the reason is "invalid limit <limit>".
(4) Next, perform the command-specific checks defined in section 5 and later.
If there is no error, execute the command.

5. Marking operations
The program holds a "history". The history is a sequence of markings. Each time FIRE or SIMULATE fires a transition once, the current marking just before the firing is appended to the end of the history.
"MARKING": output "marking <current marking>".
"RESET": set the current marking to the initial marking, make the history empty, and output "marking <current marking>".
"SET <place> <tokens>": perform the following checks in this order. If the first argument is not the name of a place, "unknown place <first argument>"; if the second argument is not an integer literal or its value is greater than 999, "invalid tokens <second argument>"; if the place has a capacity c and the value of the second argument is greater than c, "tokens exceed capacity of <first argument>". If there is no error, set the value of that place in the current marking to the value of the second argument, make the history empty, and output "marking <current marking>".
"ENABLED": output one line consisting of "enabled: " followed by the names of the transitions enabled in the current marking, separated by single spaces. If no transition is enabled, the line is "enabled: none".
"FIRE t1 t2 ... tn": examine the arguments from left to right; if some argument is not the name of a transition, "unknown transition <that argument>" for the first such argument (nothing is fired). If there is no error, fire ti in the current marking for i = 1, 2, ..., n in this order. However, if ti is not enabled in the current marking, output "step <i>: <ti> not enabled (<reason>) at <current marking>" and finish this command. The transitions fired up to that point are not undone. If all of them are fired, output "fired <n> -> <current marking>". The same transition may be written any number of times.
"UNDO <count>": if the first argument is not an integer literal or its value k is not between 1 and 1000 inclusive, "invalid count <first argument>"; if k is greater than the length h of the history, "cannot undo <k>: history size <h>". If there is no error, set the current marking to the k-th marking from the end of the history, remove the last k markings of the history, and output "marking <current marking>". This corresponds to undoing the last k firings.

6. SIMULATE
"SIMULATE <steps> <seed> <mode>" repeatedly fires transitions starting from the current marking. Perform the following checks in this order. If steps is not an integer literal or its value is not between 1 and 1000 inclusive, "invalid steps <steps>"; if seed is not an integer literal or its value is not between 1 and 2147483646 inclusive, "invalid seed <seed>"; if mode is neither "PRIORITY" nor "RANDOM", "invalid mode <mode>". The seed is checked even when the mode is PRIORITY.
If there is no error, let S be the value of steps and x the value of seed, set the firing count of every transition to 0, and do (1) to (3) below for i = 1, 2, ..., S in this order.
(1) Let E be the sequence of the transitions enabled in the current marking, arranged in transition order. If E is empty, output "dead (steps=<i - 1>)" and end the repetition.
(2) If the mode is PRIORITY, choose the transition in E with the maximum priority. If several transitions have the maximum priority, choose the first of them in transition order. If the mode is RANDOM, replace x with (48271 * x) mod 2147483647 and choose the transition at position x mod |E| of E, where the first element of E is at position 0. |E| is the length of E.
(3) Fire the chosen transition t (appending to the history as in section 5), add 1 to the firing count of t, and output "step <i>: <t> -> <current marking>".
If the repetition reaches i = S without ending at (1), output "completed (steps=<S>)". Finally, output one line consisting of "counts: " followed by "<name>=<firing count>" for all transitions in transition order, separated by single spaces.

7. CONFLICTS
A pair of two distinct transitions is written "<u>/<v>", where u is the one earlier in transition order and v is the later one. When pairs are listed, they are arranged in transition order of u, and pairs with the same u in transition order of v.
- Structural conflict: a pair for which there is a place p with Pre(p, u) > 0 and Pre(p, v) > 0.
- Effective conflict: a pair such that u and v are both enabled in the current marking M, and at least one of "v is not enabled in the marking obtained by firing u in M" and "u is not enabled in the marking obtained by firing v in M" holds.
Output the two lines "structural: <structural conflict pairs>" and "effective: <effective conflict pairs>". For <... pairs>, write all such pairs separated by single spaces, or "none" if there is no such pair. The current marking does not change.

8. REACH and GRAPH
(1) Reachability graph: with the current marking as R0, build a sequence of markings R0, R1, ... and "edges" as follows. Process the markings of the sequence one at a time, starting from R0. When processing Rj, examine each transition t enabled in Rj in transition order, and compute the marking M' obtained by firing t in Rj. If M' is not equal to any marking added to the sequence so far, append M' to the end of the sequence, and set the "parent" of M' to Rj and the "transition from the parent" of M' to t. However, if the length of the sequence is equal to the value of <limit> before appending, the construction is "aborted". When M' is Rk, there is one edge of t whose start is Rj and whose end is Rk. The construction ends when the last marking of the sequence has been processed. Rk is also written "M<k>".
For REACH and GRAPH, if the construction is aborted, output only the one line "reachability graph limit <value of limit> exceeded".
(2) When B can be arrived at from a marking A by following zero or more edges in their direction, A "reaches" B. When A reaches B and B reaches A, A and B belong to the same "component" (strongly connected component). A component for which there is no edge whose start belongs to the component and whose end does not belong to the component is called a "terminal component".
"REACH <limit>", once the construction ends, outputs the following lines in this order.
  "reachable markings: <number of markings in the sequence>"
  "edges: <number of edges>"
  "components: <number of components> (terminal <number of terminal components>)"
  "dead markings: <number of dead markings contained in the sequence>"
  for each dead marking Rk of the sequence, in increasing order of k, "  M<k> <Rk> path <path>"
  "max tokens: <maximum marking>"
  "bound: <maximum of the values of the maximum marking>"
  "safe: <yes if the value of bound is 1 or less, otherwise no>"
  "home markings: <number of home markings>"
  "reversible: <yes or no>"
  "persistent: <yes or no>"
  "liveness: <level list>"
The path is the transitions from the parent met when following parents from Rk until R0 is reached, listed in order from the R0 side and separated by single spaces. If k = 0, the path is "empty". The maximum marking is the marking in which the value of each place is the maximum of the values of that place over the markings of the sequence, written in marking notation. A marking that is reached from every marking of the sequence is called a "home marking". reversible is yes if R0 is a home marking. persistent is yes if, for every marking M of the sequence and every two distinct transitions t and u enabled in M, u is enabled in the marking obtained by firing t in M. The level list is "<name of t>=<level of t>" for each transition t, separated by single spaces. The level of t is as follows.
  - "L4": every terminal component contains a marking in which t is enabled.
  - "L3": not L4, and there is an edge of t whose start and end belong to the same component.
  - "L1": neither L4 nor L3, and there is an edge of t.
  - "L0": there is no edge of t.
"GRAPH <limit>", once the construction ends, outputs for each Rk, in the order k = 0, 1, ..., the one line "M<k> <Rk>: <edge list>". The edge list is the edges whose start is Rk, each written as "<transition name>->M<index of the end>", arranged in transition order of the edges' transitions and separated by single spaces. If Rk is a dead marking, the edge list is "dead".
REACH and GRAPH do not change the current marking.

9. COVER
"COVER <limit>" builds a coverability tree by the Karp-Miller method.
(1) In this command, besides integers greater than or equal to 0, a value omega that is greater than every integer appears as a value of a marking. For any integers n and m, omega >= n, omega > n, and omega - n + m = omega; also omega = omega. The enabling conditions and the firing of section 3 (2) are used as they are (a place whose value is omega always satisfies condition (a) and never satisfies condition (b); the value of a place that has a capacity never becomes omega). For two markings A and B, when A(p) >= B(p) for every place p and A and B are not equal, A "strictly covers" B.
(2) Each node of the tree has a marking, a parent and a transition from the parent. The nodes are numbered 0, 1, 2, ... in the order in which they are created. Node 0 is the "root"; it has the current marking and has no parent. The marking of node i is written Mi. A node may be given the mark "old".
After creating the root, process the nodes one at a time in increasing order of number. Node i is processed as follows.
  - If i has the mark old, do nothing.
  - If no transition is enabled in Mi, i is "dead".
  - For each transition t enabled in Mi, in transition order, do the following. First, compute the marking M' obtained by firing t in Mi. Next, for each node a on the parent-child path from the root to i, in order from the root (ending with i itself), if M' strictly covers Ma, replace with omega the values of all places p that have no capacity and satisfy M'(p) > Ma(p). The comparisons with the subsequent nodes use M' after the replacement. Then, if the number of nodes is equal to the value of <limit>, abort the construction of the tree. Otherwise, create a node whose marking is M', whose parent is i and whose transition from the parent is t. If M' is equal to the marking of any node created before, give the created node the mark old.
The construction ends when there is no unprocessed node left.
(3) If the construction was aborted, output only the one line "coverability tree limit <value of limit> exceeded". Otherwise, first output "coverability tree nodes: <number of nodes>", then output one line for each node i in order of number. That line is "  <i> <Mi> root" if i is the root, and "  <i> <Mi> <- <number of the parent> <name of the transition from the parent>" otherwise, followed, whether or not i is the root, by " old" if i has the mark old and by " dead" if i is dead (for example, if the root is dead, the line is "  0 <M0> root dead"). Finally, output "bounds: <maximum marking>" and "unbounded: <unbounded place list>". The maximum marking is the marking in which the value of each place is the maximum of the values of that place over the markings of all nodes (omega if at least one of them is omega). The unbounded place list is the names of the places whose value is omega in the marking of some node, in place order, separated by single spaces. If there is no such place, write "none".
COVER does not change the current marking.

10. PATH
"PATH <limit> <target>" finds a shortest firing sequence that reaches a marking matching the target. Each part of <target> separated by "," is called an "entry" (<target> never starts or ends with "," and never contains two consecutive ","). If the number of entries differs from the number of places P, "target needs <P> entries". Otherwise, examine the entries from left to right; if some entry matches none of the following 3 forms, "invalid target entry <that entry>" for the first such entry.
  - "*": matches any value.
  - an integer literal followed by one "+": matches any value greater than or equal to the value of the integer literal.
  - an integer literal: matches a value equal to its value.
The i-th entry corresponds to the i-th place in place order. A marking in which the value of every place matches the corresponding entry is called a marking that "matches the target".
If there is no error, search while building the sequence by the same procedure as section 8 (1). First, if R0 matches the target, end the search without building the sequence. Otherwise, each time a marking is added to the sequence, check whether it matches the target, and if it does, end the search at that point. When a marking Rk matching the target is found, obtain the sequence t1, ..., tm of transitions from the parent leading from R0 to Rk, in the same way as the path in section 8 (2), and output "reached <Rk> length=<m>: <t1> ... <tm>". Here <t1> ... <tm> is their names separated by single spaces. When m = 0, the line is "reached <R0> length=0". If the construction is aborted, output "search limit <value of limit> exceeded"; if the construction ends without finding one, output "unreachable (markings explored: <number of markings in the sequence>)".
The firing sequence obtained this way is the shortest of the firing sequences that reach a marking matching the target, and if there are several such sequences, it is the lexicographically smallest one when compared from the beginning in transition order. PATH does not change the current marking.

11. INCIDENCE, PINV, TINV
(1) The incidence matrix C is defined by C(p, t) = Post(t, p) - Pre(p, t) for a place p and a transition t. Inhibitor arcs and capacities are not involved.
"INCIDENCE" outputs C as a table. The columns of the table are the first column and one column for each transition (in transition order). The rows of the table are the header row and one row for each place (in place order). In the header row, the cell in the first column is the empty string and the cell in the column of a transition is the name of that transition. In the row of a place p, the cell in the first column is the name of p and the cell in the column of a transition t is C(p, t) in decimal notation (with a leading "-" if it is negative). The width of each column is the maximum length of the cell strings in that column. Each row is the concatenation, separated by two spaces, of its cells, each padded with spaces to the width of its column, on the right for the first column and on the left for the other columns.
(2) A tuple y that assigns one integer greater than or equal to 0 to each place, not all 0, such that sum over p of y(p) * C(p, t) = 0 for every transition t, is called a "P-semiflow". y(p) is called the coefficient of the place p. Similarly, a tuple x that assigns one integer greater than or equal to 0 to each transition, not all 0, such that sum over t of C(p, t) * x(t) = 0 for every place p, is called a "T-semiflow". The set of the elements whose coefficients in a semiflow are positive is called the "support" of that semiflow. A semiflow such that the support of no other semiflow of the same kind is a proper subset of its own support, and whose coefficients have greatest common divisor 1, is called a "minimal semiflow". There is only one minimal semiflow with any given support.
All minimal semiflows are obtained by the following Farkas algorithm. For P-semiflows the matrix A is C (rows are places, columns are transitions); for T-semiflows A is the transpose of C (rows are transitions, columns are places). Let n be the number of rows of A and m the number of columns of A.
  - For k = 1, ..., n, make a row of length m + n consisting of the m values of row k of A followed by the n values of row k of the n x n identity matrix. The first m values of each row are called the "A part" and the last n values are called the "coefficient part".
  - For j = 1, 2, ..., m in this order, do the following. For every pair of a row r whose j-th value in the A part is positive and a row s whose j-th value in the A part is negative, let a be the j-th value of r and b the j-th value of s, make a row whose value at each position is |b| * (the value of r at that position) + a * (the value of s at that position), and divide all values of that row by the greatest common divisor of the absolute values of its values. Collect the rows whose j-th value in the A part is 0 and the rows made this way. If there are several identical rows among them (rows whose values are equal at every position), keep only one of them, and further remove every row whose set of positions with positive values in the coefficient part contains the corresponding set of some other row as a proper subset. The remaining rows are the rows used when proceeding to the next j.
  - The coefficient parts of the rows remaining after j = m is finished are all of the minimal semiflows.
The minimal semiflows are arranged in decreasing lexicographic order of their tuples of coefficients. That is, one with a larger first coefficient comes first; if the first coefficients are equal, one with a larger next coefficient comes first; and so on. The "term notation" of a semiflow is its elements with positive coefficients, in order (in place order or in transition order), each written as the name alone if the coefficient is 1 and as "<coefficient>*<name>" otherwise, separated by " + " (a space, "+", a space).
(3) "PINV" outputs the following lines in this order.
  "P-semiflows: <number of minimal P-semiflows>"
  for each minimal P-semiflow y, in the order arranged above, "  <term notation of y> = <v(y)>"
  "bounds: <bound list>"
  "conservative: <yes or no>"
v(y) is sum over p of y(p) * M(p) for the current marking M. The bound of a place p is, if there is a minimal P-semiflow y with y(p) > 0, the minimum over those y of floor(v(y) / y(p)) (floor discards the fractional part) written in decimal notation, and "-" if there is none. The bound list is the bounds of the places in place order separated by ",", with the whole enclosed in "(" and ")". conservative is yes if, for every place p, there is a minimal P-semiflow y with y(p) > 0 (different places may use different y).
(4) "TINV" outputs the following lines in this order.
  "T-semiflows: <number of minimal T-semiflows>"
  for each minimal T-semiflow x, in the order arranged above, "  <term notation of x>: <realization>"
  "consistent: <yes or no>"
x is "realizable" when, starting from the current marking, some firing sequence that contains each transition t exactly x(t) times can be fired in order according to the rules of section 3. If x is realizable, the realization is "realizable " followed by the names in the lexicographically smallest such firing sequence, compared from the beginning in transition order, separated by single spaces. If x is not realizable, the realization is "not realizable". consistent is yes if, for every transition t, there is a minimal T-semiflow x with x(t) > 0 (different transitions may use different x).
PINV and TINV do not change the current marking.

12. SIPHONS and TRAPS
For a nonempty set S of places, a transition t with Post(t, p) > 0 for some place p of S is called an "input transition of S", and a transition t with Pre(p, t) > 0 for some place p of S is called an "output transition of S". When every input transition of S is also an output transition of S, S is called a "siphon". When every output transition of S is also an input transition of S, S is called a "trap". Inhibitor arcs and capacities are not involved, and neither are the values of the arc weights. A siphon that has no subset other than itself that is a siphon is called a "minimal siphon". A minimal trap is defined likewise.
A set of places is written as the concatenation, in this order, of "{", the names of the places of the set in place order separated by ",", and "}". When sets of places are listed, a set with fewer elements comes first, and for sets with the same number of elements, the sequences of the numbers of their places (0, 1, 2, ... from the beginning in place order) arranged in increasing order are compared lexicographically and the smaller one comes first. This is called the "set order".
"SIPHONS": if the number of places is greater than 12, it is an error and the reason is "more than 12 places". Otherwise, output "minimal siphons: <number of minimal siphons>", then, for each minimal siphon S in set order, output "  <S> tokens=<sum of the values of the places of S in the current marking>".
"TRAPS": the same as SIPHONS, but it outputs the minimal traps, and the first line is "minimal traps: <number of minimal traps>".

13. CLASSIFY
For a transition t, a place p with Pre(p, t) > 0 is called an "input place" of t, and a place p with Post(t, p) > 0 is called an "output place" of t. For a place p, a transition t with Post(t, p) > 0 is called an "input transition" of p, and a transition t with Pre(p, t) > 0 is called an "output transition" of p. Inhibitor arcs and capacities are not involved.
"CLASSIFY" outputs the following 7 lines in this order.
  "ordinary: <yes or no>": yes if the weight of every arc is 1.
  "pure: <yes or no>": yes if there is no pair of a place p and a transition t with Pre(p, t) > 0 and Post(t, p) > 0.
  "state machine: <yes or no>": yes if ordinary is yes and every transition has exactly one input place and exactly one output place.
  "marked graph: <yes or no>": yes if ordinary is yes and every place has exactly one input transition and exactly one output transition.
  "free choice: <yes or no>": yes if ordinary is yes and, for every place p and every transition t with Pre(p, t) > 0, t is the only output transition of p or p is the only input place of t.
  "extended free choice: <yes or no>": yes if ordinary is yes and, for every two places that have a common output transition, their sets of output transitions are equal.
  "commoner: <verdict>"
The verdict is "not applicable" if free choice is no, and "too many places" if free choice is yes and the number of places is greater than 12. Otherwise, examine the minimal siphons of section 12 in set order; if some of them do not satisfy the following condition, the verdict is "fails at <S>" for the first such S, and if all of them satisfy it, the verdict is "holds" (if there is no minimal siphon, the verdict is "holds"). The condition is that there is a trap Q that is a subset of S such that the sum of the values of the places of Q in the current marking is 1 or more.

14. WORKFLOW
A place that has no input transition is called a "source place", and a place that has no output transition is called a "sink place" (input transitions and output transitions are in the sense of section 13). "WORKFLOW <limit>" does (1) to (4) below.
(1) If the number of source places is not 1, output "workflow: no (<number of source places> source places)" and finish. If the number of sink places is not 1, output "workflow: no (<number of sink places> sink places)" and finish. Below, let i be the source place and o the sink place.
(2) Consider the graph whose vertices are the places and the transitions, with a directed edge from p to t when Pre(p, t) > 0 and a directed edge from t to p when Post(t, p) > 0. A vertex x "is on a path from i to o" when x can be arrived at from i by following zero or more edges in their direction and o can be arrived at from x. If there is a vertex that is not on such a path, examine the places in place order and then the transitions in transition order, output "workflow: no (<x> is not on a path from <i> to <o>)" for the first such vertex x found, and finish.
(3) Output "workflow: source <i> sink <o>". Let [i] be the marking in which the value of i is 1 and the values of all other places are 0, and [o] the marking in which the value of o is 1 and the values of all other places are 0. Build the reachability graph by the procedure in section 8 (1), with [i] as R0 instead of the current marking. If the construction is aborted, output "reachability graph limit <value of limit> exceeded" and finish.
(4) Output the following 4 lines in this order. "Reaches" is in the sense of section 8 (2).
  "option to complete: <yes or no>": yes if every marking of the sequence reaches [o].
  "proper completion: <yes or no>": yes if every marking M of the sequence with M(o) >= 1 is equal to [o].
  "no dead transitions: <yes or no>": yes if, for every transition, there is an edge of that transition.
  "sound: <yes or no>": yes if all of the 3 lines above are yes.
WORKFLOW neither uses nor changes the current marking.

15. SHOW
For each place, in place order, output the line "place <name> tokens=<initial number of tokens> capacity=<capacity>". If the capacity is none, <capacity> is "none". Then, for each transition t, in transition order, output the line "transition <name> priority=<priority> pre=<input list> post=<output list> inhibit=<inhibitor list>". The input list is "<name of p>:<Pre(p, t)>" for each place p with Pre(p, t) > 0, in place order, separated by ",". The output list and the inhibitor list are, likewise, "<name of p>:<Post(t, p)>" and "<name of p>:<I(p, t)>" for the places p with Post(t, p) > 0 and with I(p, t) > 0, respectively. If there is nothing to list, write "-".

[Output format]
- Output the lines defined in [Processing] in the order of the input lines. When several lines are output for one input line, output them in the order defined in [Processing].
- A definition line without an error outputs nothing. An erroneous definition line and an erroneous command line output only one line, which starts with "error: ".
- All output consists of ASCII characters, and every line ends with LF. Lines have no trailing whitespace, and no empty lines are output.

[Constraints]
- 1 <= K <= 10. Each block has at most 100 definition lines, and 1 <= N <= 300. Each line has at most 200 characters.
- The number of places P and the number of transitions T of each net satisfy 1 <= P <= 16 and 1 <= T <= 16.
- Every value of every marking that appears during processing (except omega) is at most 10^6.
- In PINV and TINV, the absolute values that appear during the algorithm of section 11 (2) are at most 10^6, and the number of rows collected at each stage is at most 1000.
- In TINV, for every minimal T-semiflow x, the product of (x(t) + 1) over all transitions t is at most 100000.
- Because of these, every integer computation fits within the range of signed 64-bit integers.

"arc a b 1" is an error because it connects two places. In FIRE t t, the first t gives (1,1), but the second t cannot fire because firing it would make the value of b exceed its capacity 1.
