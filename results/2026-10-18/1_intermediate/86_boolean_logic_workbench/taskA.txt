[Overview]
Write a program, a "logic formula workbench", that examines formulas of propositional logic. The program reads a sequence of commands from standard input, executes them in order, and writes the results to standard output. The commands cover: parsing and printing formulas; defining named formulas; building truth tables, minterms, maxterms, canonical disjunctive normal forms and canonical conjunctive normal forms; converting to negation normal form, the dual, and algebraic normal form (a representation using exclusive or); rule-based simplification and substituting values for variables; computing minimal sums of products (including with don't-cares) and minimal products of sums by the Quine-McCluskey method and Petrick's method; printing Karnaugh maps; deciding satisfiability, tautology, the number of models, equivalence and implication; deciding properties of the function (the variables it depends on, Post's five classes, symmetry); building binary decision diagrams; and building clause forms by the distributive law and deciding satisfiability by the Davis-Putnam method.

[Input format]
The input consists of the following lines, in this order.
- Line 1 is the number of commands N.
- Then N commands follow, one per line.
A command line consists either of the command name alone, or of the command name, one space, and the argument part, concatenated in this order. The command name runs from the start of the line up to just before the first space (the whole line if there is no space), and the argument part is everything after that space. There is no whitespace at the start or end of a line, but consecutive spaces may appear inside the argument part. There are the following 29 command forms (everything after the command name shows how the argument part is written).
  DEF name f
  DEFSUM name v... ; m...
  DEL name
  LIST
  PRINT f
  TABLE f
  MINTERMS f
  MAXTERMS f
  DNF f
  CNF f
  NNF f
  DUAL f
  ANF f
  SIMPLIFY f
  RESTRICT f ; a...
  COFACTOR f ; x
  MINIMIZE f
  MINDC f ; d
  MINPOS f
  KMAP f
  SAT f
  TAUT f
  COUNT f
  EQUIV f ; g
  IMPLIES f ; g
  PROPS f
  BDD f
  CLAUSES f
  DP f
Here f, g and d are formula strings (defined in section 1), name is a name, v and x are variables, m is a minterm number, and a is an assignment of the form "variable=value". Notation such as v... means zero or more words of that form separated by spaces. The exact way the argument part is split is defined in [Processing].
Every input line satisfies [Constraints], but it does not necessarily match a command form. How lines that do not match a form are handled is also defined in [Processing].

[Processing]
Process the commands one at a time in input order, writing each command's output immediately. Below, a string enclosed in double quotes is a string that appears as is in the input or output. In descriptions of output, a part such as <n> is replaced by its value. A "position" is the number telling at which character of the command line a character is (the first character of the line is character 1).

1. Lexical structure and grammar of formulas
- A variable is one uppercase letter (A to Z). The constants are "0" (false) and "1" (true). A name is a string of 1 to 8 characters that starts with a lowercase letter (a to z) and consists only of lowercase letters and digits (0 to 9) (for example, f, maj and x9 are names; F, 1a, a_b and abcdefghi are not).
- A formula string is split into tokens from the start by the following rules. Spaces are skipped and only separate tokens.
  (a) If "<->" starts at the current position, "<->" is one token; otherwise, if "->" starts there, "->" is one token.
  (b) If it is a lowercase letter, the string formed by it and all the lowercase letters and digits that follow it is one token. This is called a name token (it may be 9 or more characters long).
  (c) An uppercase letter, "0", "1", "~", "&", "^", "|", "(" and ")" are each a token of one character.
  (d) On meeting any other character (for example "2" to "9", "-" and "<" not covered by (a), ">", ";"), with that character as c, output error: invalid character '<c>' at <position of c> and end processing of that command.
  The position of a token is the position of its first character. For example, "A<->B" becomes the 3 tokens A, <->, B; "f2&A" becomes the 3 tokens f2, &, A; "A10" becomes the 3 tokens A, 1, 0; and "A <- B" gives the error of (d) at "<".
- Operators: "~" (negation) is a prefix unary operator. There are 5 binary operators, "&" (conjunction), "^" (exclusive or), "|" (disjunction), "->" (implication) and "<->" (equivalence), binding more tightly in this order ("&" binds most tightly, "<->" most loosely). "~" binds more tightly than any binary operator. "&", "^", "|" and "<->" are left-associative, and "->" is right-associative. For example, A -> B -> C is read as A -> (B -> C), A <-> B <-> C as (A <-> B) <-> C, A | B & C ^ D as A | ((B & C) ^ D), and ~A & B as (~A) & B.
- A valid formula is a token sequence defined as follows.
  Formula: an equivalence expression.
  Equivalence expression: one implication expression, followed by zero or more pairs of "<->" and an implication expression.
  Implication expression: one disjunction expression, followed by zero or one pair of "->" and an implication expression.
  Disjunction expression: one xor expression, followed by zero or more pairs of "|" and an xor expression.
  Xor expression: one conjunction expression, followed by zero or more pairs of "^" and a conjunction expression.
  Conjunction expression: one unary expression, followed by zero or more pairs of "&" and a unary expression.
  Unary expression: "~" followed by a unary expression, or an atom.
  Atom: a variable, a constant, a name token, or "(", a formula and ")" in this order.
- Formula tree: a valid formula represents a tree made of the following nodes. Variables and constants are leaves. "~" followed by a unary expression x is a negation node whose child is x. A binary operator is a node with a left child and a right child. For a left-associative operator op, "x op y op z" becomes the tree of "(x op y) op z"; for the right-associative "->", "x -> y -> z" becomes the tree of "x -> (y -> z)". "(" formula ")" is exactly the tree of the formula inside; parentheses do not remain in the tree. A name token is replaced as is by the tree defined for that name (section 4).
  Below, "formula" by itself means a formula tree. Two formulas are equal when the shape of the trees and the kind of every pair of corresponding nodes (which variable, which constant, which operator) all match. For example, A | B and B | A are not equal. The number of nodes of a formula is the total number of leaves and operator nodes; the depth is 1 for a leaf, and for an operator node the maximum depth of its children plus 1.
- Parsing a formula: if the formula string yields a token sequence t1, t2, ..., tk without an error of (d), check the following two conditions, in this order, for i = 1, 2, ..., k in this order; output the first one that applies and end processing of that command.
  (e) There is no valid formula that has t1, ..., ti as its leading part: error: unexpected '<ti>' at <position of ti>
  (f) ti is a name token and that name is not defined: error: undefined name '<ti>' at <position of ti>
  If none applies to the end and the whole sequence t1, ..., tk is not a valid formula either (including the case k = 0), output error: unexpected end of formula at <end position> and end processing of that command. The end position is the start position of the formula string (defined below) plus the number of characters of the formula string. For <ti>, write the token's string as is.
  For example, "A &" gives unexpected end of formula, and "A & ) B" (at ")"), "A B" (at "B"), "A (B)" (at "("), "A ~B" (at "~") and "()" (at ")") give unexpected errors. (e) is the same as ordinary parsing that reads the tokens from the start according to precedence and reports the first token at which it cannot proceed. Note that for a name token ti, (e) is checked regardless of whether it is defined (for example, even if x is not defined, "A x" is unexpected at "x").
- Formula strings and start positions: the formula strings of each command are as follows. The start position of a formula string is the position where its first character would be (it is defined even if the string is empty). If the command name has L characters, the position of the first character of the argument part is L + 2.
  The 20 commands PRINT, TABLE, MINTERMS, MAXTERMS, DNF, CNF, NNF, DUAL, ANF, SIMPLIFY, MINIMIZE, MINPOS, KMAP, SAT, TAUT, COUNT, PROPS, BDD, CLAUSES, DP: the whole argument part is the string of f, with start position L + 2.
  Commands split by ";" (the 5 commands RESTRICT, COFACTOR, MINDC, EQUIV, IMPLIES): split the argument part at the first ";" into a front and a back part; the front part is the string of f (start position L + 2), and the back part (from the character after ";" to the end of the argument part; it may be empty) is the second part (start position: the position of ";" plus 1). The second part is the string of d in MINDC and the string of g in EQUIV and IMPLIES; in RESTRICT and COFACTOR it is handled as described for each command.
  DEF: defined in section 4. DEFSUM, DEL and LIST have no formula strings.
  For example, in "EQUIV ; A" the string of f is empty with start position 7, so the output is error: unexpected end of formula at 7; in "EQUIV A ;" the string of g is empty with start position 10, so the output is error: unexpected end of formula at 10.

2. Formula notation and truth values
- Formula notation: the notation of a formula is built as follows. A variable or constant is its one character. A negation node is "~" immediately followed by the notation of its child, where the child's notation is enclosed in "(" and ")" if the child is a binary operator node. A binary operator op node is the notation of the left child, a space, op, a space, and the notation of the right child, concatenated in this order. However, the left child's notation is enclosed in parentheses when the left child is a binary operator op' node and op' binds more loosely than op, or when op' and op are both "->". The right child's notation is enclosed in parentheses when the right child is a binary operator op' node and op' binds more loosely than op, or when op' is the same operator as op and that operator is not "->".
  This is the way of writing with the fewest parentheses among those that read as the same tree. For example, (A & B) & C is written A & B & C, A & (B & C) is written A & (B & C), (A -> B) -> C is written (A -> B) -> C, A -> (B -> C) is written A -> B -> C, ~(~D) is written ~~D, and ((A | B) & C) ^ (D -> E) is written (A | B) & C ^ (D -> E).
- Variable list: the variables that appear at least once in the formula handled by the command (in both formulas for a command that handles two formulas), sorted alphabetically, form the variable list v1, v2, ..., vn of that command (n >= 0). Every variable that appears is in the list, even if the formula's value does not actually depend on it (for example, the variable list of A | ~A is A).
- Rows: each integer r with 0 <= r < 2^n (2^n is 2 to the power n) is a row number; in row r, the values of v1, v2, ..., vn are the digits of r written as an n-digit binary number, from the highest digit down (v1 is the most significant digit). If n = 0, there is only the one row r = 0.
- Value of a formula: the value of a formula in row r is computed from the leaves up, with the variables set to that row's values, by the following rules (values are 0 or 1). The value of a constant is that constant. ~x is 1 if x is 0, and 0 if x is 1. x & y is 1 when x and y are both 1; x ^ y is 1 when x and y differ; x | y is 1 when at least one of x and y is 1; x -> y is 0 only when x is 1 and y is 0; x <-> y is 1 when x and y are equal; otherwise the value is 0.
  A row where formula f has value 1 is called a model of f, and a row where it has value 0 is called a false row of f. The value of f in row r is written f(r).
- Assignment notation: the assignment notation of row r is "{", then v1=<value>, v2=<value>, ..., vn=<value> separated by single spaces, then "}", concatenated in this order (example: {A=0 B=1 C=0}). If n = 0, it is {}.
- Patterns: a string of n characters, each of which is "1", "0" or "-", is called a pattern. Character i of a pattern corresponds to variable vi. The pattern of row r is r written as an n-digit binary number. Pattern p contains row r when each character of p is "-" or equals the character at the same position of the pattern of row r. The literal count of a pattern is the number of its characters that are not "-".
- Terms and clauses: the term of pattern p is the string formed by taking, for i = 1, 2, ..., n in this order, vi if character i of p is "1" and ~vi if it is "0", and joining them with " & " ("&" with a space on each side). Variables corresponding to "-" do not appear. If the literal count is 0, the term is "1". The clause of pattern p is the same sequence joined with " | "; if the literal count is 0, the clause is "0". For example, for A, B, C, the term of pattern 1-0 is A & ~C and its clause is A | ~C.
- Pattern order: of two different patterns, compare them character by character from the start; at the first differing character, the one whose character comes earlier in the order "1", "0", "-" is smaller. Sorting a collection of patterns in increasing order is called sorting in pattern order. For example, 1-- < 01- < 0-1 < -11.
- Sum of products and product of sums: the sum-of-products notation of a sequence of patterns p1, p2, ..., pk is the terms of p1, ..., pk joined in this order with " | "; if k = 0 it is "0". The product-of-sums notation is the clauses of p1, ..., pk joined in this order with " & "; if k = 0 it is "1". However, in the product-of-sums notation, when k >= 2, clauses with a literal count of 2 or more are enclosed in "(" and ")" (example: (A | ~C) & B & (~A | C)). These match the notation of the tree in which the literals of each term are combined left to right with & (those of each clause with |), and these terms (clauses) are further combined left to right with | (respectively &).

3. Command checks and errors
For each command, check the following (1) to (5) in order and handle the first one that applies. A command that outputs an error changes no state (name definitions) and outputs only the one error line.
(1) The command name is not one of the 29 forms (uppercase and lowercase letters are distinguished): error: unknown command <command name>
(2) LIST has an argument part: error: unexpected argument. A command other than LIST has no argument part: error: missing argument.
(3) A command split by ";" (RESTRICT, COFACTOR, MINDC, EQUIV, IMPLIES) has no ";" in its argument part: error: missing ';'
(4) Perform the checks and formula parsing given in each command's description (sections 4 to 8), in the order of the description. Unless the description says otherwise, parse the command's formula strings as in section 1, in the order f, then the second formula (d or g).
(5) For a command that uses the truth table (the 17 commands TABLE, MINTERMS, MAXTERMS, DNF, CNF, ANF, SAT, TAUT, COUNT, EQUIV, IMPLIES, PROPS, KMAP, BDD, MINIMIZE, MINDC, MINPOS), the length n of the variable list is 9 or more: error: too many variables: <n>. The other 12 commands do not perform this check (5).
If none applies, process the command as in sections 4 to 8 (KMAP has one more check after this).

4. Name definitions
The program keeps as its state a collection of pairs of a name and a formula tree. It is initially empty. A name that has a pair is called "defined".
- DEF name f: split the argument part at the first space into a front and a back part; the front part is name and the back part is the string of f (the start position of the string of f is the number of characters of name plus 6). If the argument part has no space, output error: missing argument; if name is not a name, output error: invalid name '<name>'. Next, parse the string of f. If there is no error, output defined <name> = <notation of f> if name is not defined, or redefined <name> = <notation of f> if it is defined, and define name as the tree of f (replacing the existing definition, if any). Name tokens inside f are replaced using the definitions before this command is processed. For example, DEF f f -> D defines f as a new tree whose left child is the previous tree of f. A defined tree does not change even if names used in the string of f are later redefined or removed.
- DEFSUM name v... ; m...: split the argument part at the first ";" into a front and a back part. Check the following in order.
  - The argument part has no ";": error: missing ';'
  - Let w1, w2, ..., ws be the words (non-empty strings) obtained by splitting the front part at spaces. s = 0: error: missing argument
  - w1 is not a name: error: invalid name '<w1>'
  - s = 1, or some word among w2, ..., ws is not a single uppercase letter, or w2, ..., ws are not strictly increasing in alphabetical order (including the case where the same letter appears twice or more): error: bad variable list
  - k = s - 1 is 9 or more: error: too many variables: <k>
  - Examine the words obtained by splitting the back part at spaces, from the front; if there is a word that is neither "0" nor a string of digits only that does not start with "0", or a word whose value is 2^k or more, or a word whose value is less than or equal to the value of the previous word, then for the first such word: error: bad minterm '<word>'
  If there is no error, let w2, ..., ws be the variable list v1, ..., vk, and let the values of the words of the back part be m1 < m2 < ... < mt. For each mj, build the tree corresponding to the term of the pattern of row mj (the tree combining the literals vi or ~vi, in the order i = 1, ..., k, left to right with &), and build the tree combining these t trees, in order of j, left to right with | (if t = 0, the tree of the constant 0). With this tree as f, output as in DEF and define name as it. For example, DEFSUM q A B ; 1 2 defines q as ~A & B | A & ~B.
- DEL name: the whole argument part is name. If name is not a name, output error: invalid name '<name>'; if name is not defined, output error: undefined name '<name>'. Otherwise, remove the definition of name and output deleted <name>.
- LIST: on the first line output names: <number of defined names>, then for each defined name output one line <name> = <notation of its tree>. Names are sorted in lexicographic order of ASCII codes (compare character by character from the start by ASCII code; when one is a leading part of the other, the shorter comes first).

5. Printing and transforming formulas
- PRINT f: output the following 3 lines.
  formula: <notation of f>
  variables: <the variable list separated by single spaces> (variables: none if n = 0)
  size <number of nodes of f> depth <depth of f>
- NNF f: output the negation normal form of f in the form nnf: <notation>. The negation normal form is N(f, positive), where the formula N(x, s) is built from a formula x and a sign s (positive or negative) as follows ("1 - c" is the constant opposite to the constant c).
  Variable X: X if positive, ~X if negative
  Constant c: c if positive, 1 - c if negative
  ~x: N(x, the sign opposite to s)
  x & y: N(x, positive) & N(y, positive) if positive, N(x, negative) | N(y, negative) if negative
  x | y: N(x, positive) | N(y, positive) if positive, N(x, negative) & N(y, negative) if negative
  x -> y: N(x, negative) | N(y, positive) if positive, N(x, positive) & N(y, negative) if negative
  x <-> y: (N(x, positive) & N(y, positive)) | (N(x, negative) & N(y, negative)) if positive, (N(x, positive) & N(y, negative)) | (N(x, negative) & N(y, positive)) if negative
  x ^ y: if positive, the same formula as the negative case of x <-> y; if negative, the same formula as the positive case of x <-> y
  Here a & b and the like denote a node with left child a and right child b; the parentheses only show the shape of the tree. Constants and identical subformulas are not simplified. The result is a formula in which "~" appears only immediately before variables and which contains no "->", "<->" or "^".
- DUAL f: output the dual of f in the form dual: <notation>. The dual D(x) is built as follows.
  Variable X: X
  Constant c: 1 - c
  ~x: ~D(x)
  x & y: D(x) | D(y)
  x | y: D(x) & D(y)
  x ^ y: D(x) <-> D(y)
  x <-> y: D(x) ^ D(y)
  x -> y: ~D(x) & D(y)
  D(f) is a formula representing the function obtained by inverting the values of all variables, computing f, and inverting the result.
- SIMPLIFY f: output the formula S(f), obtained by simplifying f with the following rules, in the form simplified: <notation>.
  First, define the negation reduction R(a) of a formula a as 1 - c if a is a constant c, z if a is a negation node ~z, and ~a (a negation node whose child is a) otherwise.
  S(x) is computed from the leaves up. For a leaf (variable or constant), it is x itself. For a negation node ~y, it is R(S(y)). For a binary operator node, with a = S(left child) and b = S(right child), check the following rules for the operator from top to bottom; the result is that of the first rule that applies. If none applies, it is a node of the same operator with left child a and right child b. Here "a and b are complementary" means that a is equal to ~b or b is equal to ~a.
  &: if a or b is 0, then 0. If a is 1, then b. If b is 1, then a. If a and b are equal, then a. If a and b are complementary, then 0.
  |: if a or b is 1, then 1. If a is 0, then b. If b is 0, then a. If a and b are equal, then a. If a and b are complementary, then 1.
  ^: if a is 0, then b. If b is 0, then a. If a is 1, then R(b). If b is 1, then R(a). If a and b are equal, then 0. If a and b are complementary, then 1.
  ->: if a is 0 or b is 1, then 1. If a is 1, then b. If b is 0, then R(a). If a and b are equal, then 1. If a and b are complementary, then b.
  <->: if a is 1, then b. If b is 1, then a. If a is 0, then R(b). If b is 0, then R(a). If a and b are equal, then 1. If a and b are complementary, then 0.
  For example, A & ~~B -> C ^ C becomes ~(A & B), and (A | B) & (B | A) stays as it is.
- RESTRICT f ; a...: after parsing f, examine the words (non-empty strings) obtained by splitting the second part at spaces, from the front. If there are no words, output error: missing assignment. For each word, if it is not a 3-character word formed by one uppercase letter, "=", and "0" or "1" concatenated in this order, output error: bad assignment '<word>'; if its variable also appears in an earlier word, output error: duplicate variable <variable> (for each word, check these two in this order). If there is no error, consider the substitution that maps each word's variable to the constant of its value (variables that do not appear in f are allowed). Simplify, by the same rules as S, the formula obtained by replacing every leaf of f that is a substituted variable with its constant, and output restricted: <notation>.
- COFACTOR f ; x: after parsing f, if the words obtained by splitting the second part at spaces are not exactly one word consisting of one uppercase letter, output error: bad variable. Otherwise, let that variable be X; let f1 be the formula obtained by replacing every X in f with 1 and simplifying by the same rules as S, and f0 the formula obtained by replacing it with 0 and simplifying; output the following 3 lines (X need not appear in f).
  cofactor X=1: <notation of f1>
  cofactor X=0: <notation of f0>
  difference: <notation of the result of applying the "^" rule of SIMPLIFY with a = f1, b = f0>
  (For X, write the actual variable letter. Example: cofactor A=1: B)

6. Commands based on the truth table
- TABLE f: on the first line, output v1, v2, ..., vn and "| F" separated by single spaces (example: A B | F). Then, for rows r = 0, 1, ..., 2^n - 1 in this order, output a line with the values of v1, ..., vn, "|" and f(r) separated by single spaces (example: 0 1 | 1). If n = 0, the first line is "| F" and it is followed by the single line "| <f(0)>".
- MINTERMS f: output minterms: <the row numbers of the models of f in increasing order, separated by single spaces>. If there are no models, it is minterms: none.
- MAXTERMS f: output maxterms: <the row numbers of the false rows of f in increasing order>. If there are no false rows, it is maxterms: none.
- DNF f: as the canonical disjunctive normal form of f, output dnf: <the sum-of-products notation of the sequence of the patterns of the model rows of f, in increasing order of row number>.
- CNF f: as the canonical conjunctive normal form of f, output cnf: <the product-of-sums notation of the sequence formed by making, for each false row of f, the pattern of that row with "0" and "1" swapped, in increasing order of row number>. For example, A -> B gives cnf: ~A | B, and A & B gives cnf: (A | B) & (A | ~B) & (~A | B).
- ANF f: output the algebraic normal form of f in the form anf: <notation>. For each row number s, the coefficient c(s) is the sum of f(r) over all rows r such that "every digit that is 1 in the binary representation of r is also 1 in s", modulo 2. For each s with c(s) = 1, make the pattern obtained by writing s in binary with the digits 1 as "1" and the digits 0 as "-". The notation is these patterns sorted by increasing literal count, and by pattern order for equal literal counts, with their terms joined by " ^ ". If there is no s with c(s) = 1, write "0". For example, A | B gives anf: A ^ B ^ A & B, and A <-> B gives anf: 1 ^ A ^ B.
- SAT f: if f has a model, output satisfiable: <assignment notation of r> for the model r with the smallest row number; otherwise output unsatisfiable.
- TAUT f: if f has no false row, output tautology; otherwise output not a tautology: <assignment notation of r> for the false row r with the smallest row number.
- COUNT f: output models: <number of models of f> of <2^n>.
- EQUIV f ; g: the variable list is built from the variables that appear in both f and g. If there is no row r where f(r) and g(r) differ, output equivalent; otherwise, for the smallest such r, output not equivalent: <assignment notation of r> f=<f(r)> g=<g(r)>.
- IMPLIES f ; g: the variable list is built from both f and g. If there is no row r with f(r) = 1 and g(r) = 0, output implies; otherwise, for the smallest such r, output does not imply: <assignment notation of r>.
- PROPS f: output the following 7 lines. For <yes/no>, write yes if the property holds and no if it does not.
  depends: <the variables f depends on, in variable-list order, separated by single spaces> (depends: none if there are none)
  zero-preserving: <yes/no>
  one-preserving: <yes/no>
  self-dual: <yes/no>
  monotone: <yes/no>
  linear: <yes/no>
  symmetric: <yes/no>
  f depends on variable vi when there are two rows that differ only in the value of vi and in which f has different values. zero-preserving means f(0) = 0, and one-preserving means f(2^n - 1) = 1 (if n = 0, both are checked at row 0). self-dual means that f(r) and f(2^n - 1 - r) differ for every row r. monotone means that for every row r and every variable whose value is 0 in row r, f(r) <= f(r') holds, where r' is the row in which only that variable's value is changed to 1. linear means that for every s with c(s) = 1 in the ANF, the binary representation of s has at most one digit 1. symmetric means that f has equal values in any two rows with the same number of variables whose value is 1.
- KMAP f: if n is less than 2 or greater than 4, output error: kmap needs 2 to 4 variables. Otherwise, let p = floor(n / 2) and q = n - p, and let v1, ..., vp be the row variables and vp+1, ..., vn the column variables. The k-digit Gray code sequence is the sequence of strings obtained, for i = 0, 1, ..., 2^k - 1 in this order, by writing the bitwise exclusive or of i and floor(i / 2) as a k-digit binary number (for 2 digits: 00, 01, 11, 10).
  The first line is the label, formed by concatenating the string of v1, ..., vp concatenated, "\", and the string of vp+1, ..., vn concatenated, in this order, followed by, for each string c of the q-digit Gray code sequence in order, one space and c. Then, for each string R of the p-digit Gray code sequence, output one line: R with spaces appended to make it the same length as the label (p + 1 + q characters), followed by, for each string C of the q-digit Gray code sequence in order, one space, q - 1 spaces, and the value of f (the value in the row whose row number is the n-digit binary number formed by concatenating R and C in this order). For example, A ^ B ^ C gives the following 3 lines.
  A\BC 00 01 11 10
  0     0  1  0  1
  1     1  0  1  0
- BDD f: build the reduced ordered binary decision diagram of f. The nodes are node 0 (constant 0), node 1 (constant 1), and internal nodes numbered 2 or more. An internal node is a triple (i, lo, hi), meaning: go to node lo if the value of variable vi is 0, and to node hi if it is 1. For 1 <= j <= n + 1 and a sequence L of 2^(n-j+1) values, compute B(j, L) as follows. If j = n + 1, it is the single value of L (0 or 1). Otherwise, let L0 be the first half of L and L1 the second half; first compute lo = B(j + 1, L0), then hi = B(j + 1, L1). If lo = hi, the result is lo. Otherwise, if an internal node with triple (j, lo, hi) already exists, the result is its number; if not, create an internal node for this triple with the next number (2, 3, 4, ..., one at a time) and the result is that number. The root is B(1, [f(0), f(1), ..., f(2^n - 1)]). Output the following lines.
  nodes: <number of internal nodes>
  for each internal node, in increasing order of number: <number> = ite(<vi>, <hi>, <lo>)
  root: <number of the root>
  paths: <number of paths from the root to node 1>
  The number of paths is P(root), computed with P(0) = 0, P(1) = 1, and P(lo) + P(hi) for an internal node (i, lo, hi).

7. Minimization
MINIMIZE, MINDC and MINPOS find a minimal cover from the row sets ON and DC as follows.
  MINIMIZE f: ON is the set of models of f, and DC is empty.
  MINDC f ; d: DC is the set of models of d (the variable list is built from both f and d), and ON is the set of models of f that are not in DC.
  MINPOS f: ON is the set of false rows of f, and DC is empty.
- Implicants: when every row contained in a pattern p is in ON or DC, p is called an implicant, and the number of "-" in p is called the stage of p. When changing any one non-"-" character of an implicant p to "-" never gives an implicant, p is called a prime implicant.
- Stage display (MINIMIZE and MINDC only): for k = 0, 1, 2, ... in this order, with a the number of implicants at stage k and b the number of prime implicants among them, output stage <k>: implicants <a> primes <b>. The line for stage 0 is always output, and if there are no implicants at stage k + 1, stop after the line for stage k. Note that all implicants at stage k + 1 are obtained by combining two implicants at stage k that differ in exactly one character, neither of which is "-" at that position (making that character "-") (the Quine-McCluskey method).
- Target prime implicants: the prime implicants that contain at least one row of ON. A target prime implicant that is the only target prime implicant containing some row of ON is called an essential prime implicant.
- Covers: a set of target prime implicants such that every row of ON is contained in at least one prime implicant in it is called a cover. Among the covers, choose the single best one by comparing the following (A) to (C) in order.
  (A) Fewer prime implicants.
  (B) A smaller total literal count of the prime implicants.
  (C) Comparing the sequences of the cover's prime implicants (for MINIMIZE and MINDC, the prime implicants sorted in pattern order; for MINPOS, the patterns obtained by swapping "0" and "1" in each prime implicant, sorted in pattern order) from the start, the first differing element is smaller in pattern order.
  Every cover contains all essential prime implicants. If ON is empty, the cover is the empty set. The candidate covers can be found, for example, by Petrick's method (after choosing the essential prime implicants, make, for each row of ON not yet contained, the condition "choose one of the target prime implicants containing that row"; expand the conjunction of all of them into a sum of products and simplify it with the absorption law; each product is then a candidate), but any method may be used. The result is determined by (A) to (C).
- MINIMIZE f and MINDC f ; d: after the stage display, output the following 4 lines.
  primes: <the target prime implicants sorted in pattern order, with their terms joined by ", " (a comma and a space)> (primes: none if there are none)
  essential: <the essential prime implicants sorted in pattern order, with their terms joined by ", "> (essential: none if there are none)
  minimal: <the sum-of-products notation of the sequence of the chosen cover's prime implicants sorted in pattern order>
  terms <number of prime implicants in the cover> literals <total literal count of the cover's prime implicants>
- MINPOS f: there is no stage display. Each prime implicant p of the chosen cover is a product term of ~f, and its negation is the clause of the pattern obtained by swapping "0" and "1" in p. Output the following 2 lines.
  minimal: <the product-of-sums notation of the sequence of the patterns obtained by swapping "0" and "1" in each prime implicant of the cover, sorted in pattern order>
  clauses <number of prime implicants in the cover> literals <total literal count of the cover's prime implicants>
  For example, if f is a tautology, the output is minimal: 1 and clauses 0 literals 0; if f is unsatisfiable (the cover is the single pattern whose characters are all "-"), the output is minimal: 0 and clauses 1 literals 0.

8. Clause forms
- Clauses: a set of literals (a variable X or ~X) is called a clause. A clause that contains both X and ~X is called a tautological clause. Clause c properly contains clause e when c contains all literals of e and c != e. A clause is represented by the pattern that has, for each vi of the variable list, "1" if it contains vi, "0" if it contains ~vi, and "-" if it contains neither (only non-tautological clauses are represented by patterns).
- Tidying a clause set: removing the tautological clauses from a clause set, and then removing every remaining clause that properly contains another clause, is called tidying it.
- CLAUSES f: for g = N(f, positive) (the negation normal form of NNF), define the clause set C(x) of each subformula x as follows.
  Variable X: the set consisting of {X} only. ~X: the set consisting of {~X} only.
  Constant 1: the empty set (no clauses at all). Constant 0: the set consisting of the empty clause only.
  x & y: the union of C(x) and C(y).
  x | y: the set of clauses that are the union of c and e, over all pairs where c is a clause of C(x) and e is a clause of C(y).
  Sort the patterns of the clauses of the tidied C(g) in pattern order and output clauses: <the product-of-sums notation of that sequence>. Computing the intermediate C(x) while tidying gives the same result.
- DP f: let S be the tidied clause set computed as in CLAUSES, and output start: clauses <number of clauses of S>. Then do the following for i = 1, 2, ..., n in this order. If S is empty or contains the empty clause, end the repetition here. Otherwise, let P be the set of clauses of S that contain vi and Q the set of clauses that contain ~vi; for every pair of a clause p of P and a clause q of Q, make the clause (resolvent) that is the union of p without vi and q without ~vi, and let R be the set of non-tautological resolvents (identical clauses count as one). Remove the clauses of P and Q from S, add the clauses of R, tidy the result to get the new S, and output eliminate <vi>: resolvents <number of clauses of R> clauses <number of clauses of the new S>. Finally, output result: unsatisfiable if S contains the empty clause, and result: satisfiable otherwise.

[Output format]
- For each command, output the lines described in [Processing] in that order. Unless specified otherwise, each command's output is one line.
- Put no whitespace at the end of any line, and end every line with a newline. Write numbers in decimal without extra leading zeros.
- Where [Processing] shows the form of a line, a period at the end of the item is sentence punctuation and is not part of the output.

[Constraints]
- 1 <= N <= 500.
- Each line has 1 to 200 characters and consists only of printable ASCII characters (from space to "~").
- Parentheses in a formula string are nested at most 20 levels deep.
- Every defined formula and every formula handled by a command (the tree after names are replaced) has at most 1000 nodes and depth at most 100.
- Each word after ";" in DEFSUM has at most 9 characters.
- When MINIMIZE, MINDC and MINPOS choose a cover, at most 12 of the target prime implicants are not essential prime implicants.
- In CLAUSES and DP, the number of clauses (counting duplicates) when C(x) is built by the definition without tidying is at most 1000 for every subformula x. At each step of DP, the number of clauses of P times the number of clauses of Q is at most 10000.
- Every output line has at most 1000 characters.
