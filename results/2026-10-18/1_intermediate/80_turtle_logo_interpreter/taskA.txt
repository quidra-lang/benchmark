[Overview]
Write an interpreter that executes a subset of the LOGO language. The program reads one or more LOGO programs from standard input, executes each of them independently, and writes the results to standard output. The turtle moves in 8 directions on an infinite grid of cells, and while the pen is down it marks the cells it passes with the pen character. The supported commands are: moving forward and backward, turning in steps of 45 degrees, raising and lowering the pen and the eraser, changing the pen character, moving to given coordinates (drawing a straight line), clearing the screen, flood fill, writing text, printing the picture at an intermediate point, repetition (REPEAT, FOR, WHILE), conditionals (IF, IFELSE, TEST), defining and calling procedures (parameters, recursion, procedures that return a value, dynamically scoped variables), assigning to variables, printing values, tracing procedure calls, and pseudo-random numbers. All values are integers; expressions may use the four arithmetic operations, remainder, comparisons, unary minus, parentheses, and prefix functions. As in LOGO, the number of inputs of commands and functions determines how far one expression extends. For each program, output the printed values, the final state of the turtle, and the drawn picture (the part inside the smallest rectangle that encloses the marked cells). If there is a syntax error or a runtime error, report it in the form "ERROR line L: reason" and stop executing that program.

[Input format]
The input consists of several lines, and the last line is #EOF. Each line is a string of 0 to 200 characters consisting only of printable ASCII characters (character codes 32 to 126).
The first line has the form "#PROGRAM name". A line of this form is called a "header". name is the program name, a string of 1 to 20 characters consisting only of letters, digits and _. There is exactly one space between #PROGRAM and name.
The input consists of one or more programs. Each program consists of one header and the zero or more lines from the line after it up to just before the next header or the #EOF line. These lines following the header are called the "source lines" of that program. The #EOF line appears exactly once, at the end of the input. No source line consists of just #EOF, and no source line begins with "#PROGRAM " (#PROGRAM followed by one space).
The input lines are numbered 1, 2, 3, ... starting from the first line. These are called "line numbers". Every line number used in error reports is a line number in this whole input.

[Processing]
Process the programs one at a time in input order. For each program, first output "PROGRAM <name>" (name exactly as written in the header, without conversion to uppercase), then perform the following three stages in order.
(A) Lexical analysis and extraction of procedure definitions (Sections 2 and 3)
(B) Parsing (Sections 4 and 5)
(C) Execution (Sections 6 to 11)
Output is produced immediately, in the order in which commands are executed. If an error occurs at any stage, stop processing that program at that point, report the error (Section 12), and go on to the next program. If an error is found in (A) or (B), nothing is executed. If there is no error, output the final state after (C) (Section 12). The state is initialized for each program; processing one program never affects another.
Below, a string enclosed in double quotes is a string that appears in the output exactly as written, except that each part enclosed in < and > inside it is replaced by the value described.

Section 1. Terms and integer arithmetic
- "Space" means only the ASCII space character (character code 32). "Letters" are the 52 characters A to Z and a to z, "uppercase letters" are the 26 characters A to Z, and "digits" are the 10 characters 0 to 9.
- A "name" is a string of one or more characters that begins with an uppercase letter and consists only of uppercase letters, digits and _.
- All values are integers. The result of the integer division a / b (b nonzero) is the mathematical quotient with its fractional part discarded (rounded toward 0). a MOD b is a - b * (a / b); the result is 0 or has the same sign as a. For example, 7 / 2 = 3, -7 / 2 = -3, 7 MOD 3 = 1, -7 MOD 2 = -1, 7 MOD -2 = 1.
- floor(r) is the largest integer less than or equal to the rational number r (negative numbers are rounded toward -infinity). For example, floor(-1/6) = -1.
- When an integer is converted to a string ("decimal notation"), it has no extra leading zeros, and a negative number is prefixed with -.

Section 2. Lexical analysis
Split each source line into a sequence of "tokens" by the following procedure.
(1) If the line contains ;, remove everything from the first ; to the end of the line (a comment).
(2) Replace every lowercase letter in the remaining part with the corresponding uppercase letter. The result is called "the line string". All the following processing works on the characters after this replacement.
(3) Read the line string from the beginning. Spaces are skipped (they only serve to separate tokens).
- Each of [ ] ( ) + * / = is a token of one character.
- For <: if the next character is =, the two characters <= form one token; if it is >, the two characters <> form one token; otherwise < alone is one token. For >: if the next character is =, the two characters >= form one token; otherwise > alone is one token.
- The character - is a token of one character. When that - satisfies both "it is the first character of the line string, or the character before it is a space, [ or (" and "there is a character after it, and that character is not a space", that - is called a "sign minus". Any other - is called an "operator minus". For example, the - in "3 -2" is a sign minus, and the - in "3 - 2" or "3-2" is an operator minus.
- From any other character, read as long as the characters are none of space and [ ] ( ) + - * / = < >, and take that longest part as one "lexeme". A lexeme is classified as follows.
  - A lexeme consisting only of digits is a "number" token. Its value is the integer obtained by reading the lexeme as a decimal number (leading zeros are ignored).
  - A lexeme consisting of : followed by a name is a "variable" token, and that name is called its "variable name".
  - A lexeme consisting of " followed by a name is a "quoted word" token, and that name is called its "word value".
  - A lexeme that is a name is a "word" token.
  - Any other lexeme is invalid: error "bad token '<that lexeme>'".
Each token is labeled with the line number of the source line containing it. The "spelling" of a token is exactly the string taken as that token (for example, the spelling of a variable token includes the :, as in :SIZE). Below, when a token is mentioned in the text, it is written by its spelling.
Among the tokens, + * / = <> < > <= >= and the operator minus are called "operators". The word MOD also acts as an operator (Section 5).

Section 3. Extracting procedure definitions
Examine the source lines one at a time from the top. For each line, first perform lexical analysis on it (if there is an error, the error occurs there), then classify the line and process it. A line with no tokens at all (such as an empty line or a line containing only a comment) is ignored.
- A line whose first token is the word TO is a "definition start line".
- A line consisting of exactly one token, the word END, is a "definition end line".
- Any other line is a "body line".
Initially there is no "procedure being defined".

A definition start line is checked in the following order.
(a) If there is a procedure being defined, error "TO inside definition of <name of the procedure being defined>".
(b) If there is no second token, or it is not a word, error "bad procedure header".
(c) Let P be the second token (a word). If P is a primitive (Section 4), error "<P> is a primitive"; if P is the name of a procedure already defined, error "<P> is already defined".
(d) Examine the third and later tokens one at a time from the front. If a token is not a variable, error "bad procedure header"; if it is a variable whose variable name is the same as that of an earlier variable on the same line, error "duplicate input <spelling of that token>".
(e) If there is no error, define a procedure named P whose "parameters" are the variable names of the third and later variables, in this order, and make P the procedure being defined. The number of parameters may be 0.
On a definition end line, if there is no procedure being defined, error "END without TO". Otherwise, set the procedure being defined to none.
On a body line, append the tokens of the line, in order, to the end of the "body" of the procedure being defined if there is one, and otherwise to the end of the "top level".
If, after the last line has been examined, a procedure being defined remains, error "missing END for <its name>", whose line number is the line number of that procedure's definition start line. The line number of any other error in (A) is the line number of the line being examined.
Thus each procedure body and the top level are each a single sequence of tokens. Line breaks are the same as spaces, and one command or command list may span several lines. Also, since the number of parameters of a procedure is determined by its definition start line alone, a procedure can be called even from lines before the line where it is defined.

Section 4. Primitives
The following words (including aliases) are called "primitives". Primitives are divided into "commands", "functions" and "others". The sequence of symbols after each word gives the kinds and order of the inputs that the word takes: E is an expression, L is a command list, Q is a quoted word, and P is a print item (a quoted word or an expression). A word without symbols takes no inputs. A word in parentheses is an "alias", and an alias works exactly like the original word. However, when a word is written in an error reason, use the spelling written in the program (the alias, if it was an alias). The effect of each word is described in Sections 7 to 11.
Commands:
  FD E (FORWARD)
  BK E (BACK)
  RT E (RIGHT)
  LT E (LEFT)
  SETH E (SETHEADING)
  PU (PENUP)
  PD (PENDOWN)
  PE (PENERASE)
  SETPEN E
  SETXY E E
  SETX E
  SETY E
  HOME
  CS (CLEARSCREEN)
  CLEAN
  FILL
  LABEL P
  SNAPSHOT
  REPEAT E L
  FOR Q E E L
  WHILE E L
  IF E L
  IFELSE E L L
  TEST E
  IFTRUE L (IFT)
  IFFALSE L (IFF)
  STOP
  OUTPUT E (OP)
  MAKE Q E
  LOCAL Q
  LOCALMAKE Q E
  TRACE Q
  UNTRACE Q
  SEED E
  PRINT P (PR)
Functions:
  XCOR
  YCOR
  HEADING
  REPCOUNT
  RANDOM E
  ABS E
  NOT E
  AND E E
  OR E E
  MAX E E
  MIN E E
Others:
  TO
  END
  MOD
A procedure defined in Section 3 is a word that takes as many E inputs as it has parameters, and it can be used both as a command and as a function. A word that is neither a primitive nor a procedure name is called an "unknown word".

Section 5. Parsing
Read each procedure body, one at a time in the order in which the procedures were defined, and finally the top level, each as a "command sequence". Read forward from the first token, report the first error found, and do not examine anything after it (if an error is found in a procedure body, the top level is not examined). Below, "the next token" means the first token that has not yet been read. Unless stated otherwise, the line number of an error in (B) is the line number of the token t or u in the description.

Command sequence: read commands one at a time until there are no tokens left. However, if the next token is ] when a command is about to be read, error "unexpected ]", whose line number is the line number of that ].

Command: read the next token t, and act according to t as follows.
(a) If t is ( and the token after it is the word PRINT or PR, read that word too. This is a "multi-item print command". Repeat the following: if the next token is ), read it and end the command. If there is no next token or it is ], error "missing )", whose line number is the line number of t. Otherwise, read one input of kind P (see "Input" below) with that word (PRINT or PR) as the owner. There may be zero print items.
(b) If t is the word TO or END, error "misplaced <t>".
(c) If t is a command primitive: first, if t is one of STOP, OUTPUT, OP, LOCAL, LOCALMAKE and the top level is being read, error "can only use <t> inside a procedure". Otherwise, read the inputs in the order of the input kinds in Section 4, with t as the owner. Furthermore, if t is TRACE or UNTRACE and the word value of the quoted word read is not a procedure name, error "I don't know how to <word value>", whose line number is the line number of that quoted word.
(d) If t is a procedure name, read as many expressions as it has parameters, with t as the owner. This is a "procedure call command".
(e) If t is an unknown word, error "I don't know how to <t>".
(f) Otherwise (a number, a variable, a quoted word, an operator, a sign minus, MOD, a function primitive, [, ), and a ( that does not match (a)), error "you don't say what to do with <t>".

Input: to read one input of an owner X (a token that is one of: a command or function word, a procedure name, an operator, a sign minus, a ( token), examine the next token u and process it in the following order.
(1) If there is no u, or u is ] or ), error "not enough inputs to <X>", whose line number is the line number of X.
(2) If u is an unknown word, error "I don't know how to <u>".
(3) Act according to the kind of input as follows. Below, "reject" means error "<X> doesn't like <u> as input" (whose line number is the line number of u).
  - L: if u is [, read a command list. Otherwise reject.
  - Q: if u is a quoted word, read it. Otherwise reject.
  - P: if u is a quoted word, read it as the print item. Otherwise, read an expression with X as the owner.
  - E: read an expression with X as the owner.

Command list: read the [, read commands one at a time until the next token is ], and read that ]. If the tokens run out without a ] appearing, error "missing ]", whose line number is the line number of that [.

Expression: an expression is read in the following three stages. At every stage, operators associate from left to right.
- Expression (comparison): read one "sum" with X as the owner; then, while the next token is one of = <> < > <= >=, read that operator, read one more "sum" with that operator as the owner, and combine the two.
- Sum: similarly, read a "product", and while the next token is + or an operator minus, read the operator and read one more "product". A sign minus is not an operator, so the sum ends there.
- Product: similarly, read a "term", and while the next token is *, / or the word MOD, read the operator and read one more "term".
At each stage, the owner of the first lower-stage item read (the sum in a comparison, the product in a sum, the term in a product) is the same as the owner of that stage. That is, the owner of the first term of an expression is X, and the owner of the first term on the right of an operator is that operator.

Term: to read a term of owner X, check (1) and (2) of "Input" for the next token u, then read u and act according to u as follows.
- A number: it denotes its value.
- A variable: it denotes the value of that variable.
- A sign minus or an operator minus: read one more term with u as the owner; this denotes its value with the sign inverted (unary minus).
- (: read one expression with u as the owner. If the next token is ), read it; this denotes the value of the expression read. Otherwise, error "missing )", whose line number is the line number of u.
- A function primitive: read as many expressions as its number of inputs, with u as the owner.
- A procedure name: read as many expressions as it has parameters, with u as the owner. This is a "procedure call expression".
- Otherwise (a quoted word, a command primitive, TO, END, MOD, [, and operators other than -): error "<X> doesn't like <u> as input".

Thus each input of a function or procedure is read as one complete expression. For example, "ABS :X - 1" means ABS (:X - 1), "2 * F 3 + 1" means 2 * F (3 + 1), and "MAX 1 2 + 3" means MAX 1 (2 + 3) (F is a procedure with one parameter). Also, in "FD :X RT 90", the expression of FD ends with just :X, and RT 90 is the next command. In "PRINT 3 -2", the expression of PRINT ends at 3, and the next command begins with a sign minus, so the result is error "you don't say what to do with -". On the other hand, "SETXY 3 -2" gives the two inputs 3 and -2 of SETXY.

Section 6. State
Each program has the following state. The value in parentheses is the value when execution of the program starts.
- The turtle's position (x, y) ((0, 0)) and heading h (0).
- The pen state: one of DOWN, UP, ERASE (DOWN).
- The pen character (*).
- The canvas: for each cell, whether it has a mark and, if it has one, the mark's character (no cell has a mark).
- The list of environments (just one environment, the top-level environment). An environment holds a mapping from variable names to values and a test result (one of "none", "true", "false"). The variables of the top-level environment are called "global variables". Each time a procedure is called, a new environment is appended to the end of the list (Section 8). The environment at the end of the list is called the "current environment". Initially the top-level environment has no variables and its test result is none.
- The list of repetition numbers (empty).
- The set of traced procedures (empty).
- The random state r (1).
A cell is identified by integer coordinates (x, y). x increases toward the east (right), and y increases toward the north (up). The heading is a multiple of 45 from 0 to 315, the angle measured clockwise with north as 0. The change of coordinates (dx, dy) for one step in each heading is as follows.
  0: (0, 1), 45: (1, 1), 90: (1, 0), 135: (1, -1), 180: (0, -1), 225: (-1, -1), 270: (-1, 0), 315: (-1, 1)
In a diagonal heading, one step changes both x and y by 1.

Section 7. Movement and drawing commands
A command first evaluates all of its input expressions from left to right, and only then takes effect. Below, to "apply the pen" to a cell means: if the pen state is DOWN, set that cell's mark to the pen character (replacing any existing mark); if it is ERASE, remove that cell's mark; if it is UP, do nothing.
- FD n: use (dx, dy) of the current heading. If n is negative, use (-dx, -dy) instead of (dx, dy), and -n instead of n. First apply the pen to the current cell, then repeat "move by (dx, dy) and apply the pen to the destination cell" n times. If n is 0, just apply the pen to the current cell.
- BK n: the same as FD -n.
- RT a: if a is not a multiple of 45 (negative multiples of 45 and 0 also count as multiples), error "<the word of this command> doesn't like <a> as input". Otherwise, set h to the remainder of h + a divided by 360 (from 0 to 359).
- LT a: the same as RT, but set h to the remainder of h - a divided by 360 (from 0 to 359).
- SETH a: check for errors under the same condition as RT, and set h to the remainder of a divided by 360 (from 0 to 359).
- PU, PD, PE: set the pen state to UP, DOWN, ERASE, respectively.
- SETPEN n: if n is not between 33 and 126 inclusive, error "SETPEN doesn't like <n> as input". Otherwise, set the pen character to the character with character code n.
- SETXY x y: move the turtle in a straight line to (x, y). Let the current position be (x0, y0), and let dx = x - x0, dy = y - y0, s = max(|dx|, |dy|). If s = 0, apply the pen to (x0, y0). If s > 0, for i = 0, 1, ..., s in this order, apply the pen to the cell (x0 + floor((2*i*dx + s) / (2*s)), y0 + floor((2*i*dy + s) / (2*s))) (this is i*dx / s and i*dy / s rounded to the nearest integer, with an exact half rounded toward the larger value). Then set the turtle's position to (x, y). The heading does not change.
- SETX x: the same as SETXY x y0 (y0 is the current y coordinate).
- SETY y: the same as SETXY x0 y (x0 is the current x coordinate).
- HOME: move in the same way as SETXY 0 0, then set the heading to 0.
- CS: remove all marks from the canvas, and set the turtle's position to (0, 0) and its heading to 0. The pen is not applied. The pen state and the pen character do not change.
- CLEAN: remove all marks from the canvas. The turtle does not change.
- FILL: if the canvas has no marks at all, or the current cell has a mark, do nothing. Otherwise, let B be the rectangle (boundary included) bounded by the minimum and maximum x coordinates and the minimum and maximum y coordinates of the cells that have marks at the moment this command starts. If the current cell is outside B, do nothing. Otherwise, mark with the pen character every unmarked cell in B that can be reached from the current cell "by repeating zero or more moves to an up, down, left or right neighboring cell, passing only through unmarked cells in B" (including the current cell). FILL works regardless of the pen state.
- LABEL item: let S be the string of the print item item (Section 11), and let m be its length. Using (dx, dy) of the current heading, for k = 0, 1, ..., m-1, set the mark of the cell (x + k*dx, y + k*dy) to the (k+1)-th character of S (replacing any existing mark). LABEL works regardless of the pen state, and the turtle does not move.
- SNAPSHOT: output the canvas at that moment in the format of "Canvas output" in Section 12.

Section 8. Variables and procedures
The value of a variable :V is its value in the first environment that has the variable name V, examining the list of environments in order from the end (the current environment) toward the front (the top-level environment). If no environment has V, error "<V> has no value" (V is the variable name without the :). In this way, inside a called procedure, the variables of the procedures that called it are also visible (dynamic scope).
- MAKE "V e: evaluate e to get the value v. Next, examine the environments other than the top level from the end toward the front; if there is a first environment that has the variable name V, set V in that environment to v. If there is none, set the global variable V to v (creating it if it does not exist).
- LOCAL "V: set V in the current environment to 0 (creating it if it does not exist).
- LOCALMAKE "V e: set V in the current environment to the value of e (creating it if it does not exist).
(By Section 5, LOCAL, LOCALMAKE, STOP and OUTPUT appear only inside procedure bodies, so when they are executed, the current environment is not the top-level environment.)

A call of a procedure P (the same for procedure call commands and procedure call expressions) is performed in the following order.
(1) Evaluate the input expressions from left to right.
(2) If there are already 100 active procedure calls (defined in (2) of Section 12), error "recursion too deep".
(3) If P is in the set of traced procedures, the call is a "traced call". For a traced call, output "<indent>( <P> <the decimal notations of the input values, separated by single spaces> )". The indent is 2d spaces, where d is the number of procedure calls that were active just before this call started. If there are no inputs, output "<indent>( <P> )".
(4) Append to the end of the list of environments a new environment whose variables are P's parameter names, each associated with the corresponding value from (1), and whose test result is none.
(5) Execute the commands of P's body in order from the beginning. If the end of the body is reached or STOP is executed, this call ends "without a value". If OUTPUT e is executed, the call ends with the value v of e. STOP and OUTPUT end this whole call at that moment, even if they are executed inside a command list of REPEAT or another command.
(6) Remove the environment appended in (4).
(7) For a traced call, after the same indent as in (3), output "<P> stops" if the call ended without a value, or "<P> outputs <v>" if it ended with the value v.
For a procedure call command, if the call ended with a value v, error "you don't say what to do with <v>". For a procedure call expression, if the call ended without a value, error "<P> did not output". The value of a procedure call expression is the value v with which the call ended.
- TRACE "P: add the procedure P to the set of traced procedures (do nothing if it is already there).
- UNTRACE "P: remove the procedure P from the set of traced procedures (do nothing if it is not there).
(Whether a call is a traced call is decided at the time of (3); executing UNTRACE or TRACE during that call does not change whether (7) is performed.)

Section 9. Control commands
- REPEAT n [L]: evaluate n, and for k = 1, 2, ..., n in this order, "append k to the end of the list of repetition numbers, execute the command list L, and remove the k at the end". If n is 0 or less, do nothing. Even when the loop is left early by STOP or OUTPUT, the appended number is removed.
- FOR "V a b [L]: evaluate a, then b. If a <= b, then for the values a, a+1, ..., b in this order, and if a > b, then for the values a, a-1, ..., b in this order, for each value v "set V to v by the same rule as MAKE "V, then execute the command list L". This sequence of values is fixed at the start; changing V inside L does not affect the repetition.
- WHILE c [L]: repeat "evaluate c, and if it is not 0, execute L" until the value of c is 0.
- IF c [L]: evaluate c, and if it is not 0, execute L.
- IFELSE c [L1] [L2]: evaluate c; if it is not 0, execute L1, and if it is 0, execute L2.
- TEST c: evaluate c, and set the test result of the current environment to true if it is not 0, and to false if it is 0.
- IFTRUE [L], IFFALSE [L]: if the test result of the current environment is none, error "<the word of this command> without TEST". Otherwise, IFTRUE executes L when the test result is true, and IFFALSE executes L when it is false.
- STOP, OUTPUT e: as described in (5) of Section 8.
As truth values, 0 is false and any nonzero value is true.

Section 10. Evaluation of expressions
- A number is its value, and a variable is its value as described in Section 8.
- A unary minus is the value of its term with the sign inverted.
- A combination by an operator evaluates the left expression, then the right expression, and then computes. + is the sum, the operator minus is the difference, * is the product, and / and MOD are as in Section 1. For / and MOD, if the right value is 0, error "<that operator> doesn't like 0 as input" (whose line number is the line number of that operator). The comparison operators = <> < > <= >= give 1 if "equal", "not equal", "less than", "greater than", "less than or equal to", "greater than or equal to", respectively, holds, and 0 if it does not.
- A function first evaluates all of its input expressions from left to right, then computes the following value (AND and OR also always evaluate both inputs).
  XCOR, YCOR: the turtle's x coordinate, y coordinate.
  HEADING: the turtle's heading.
  REPCOUNT: the value at the end of the list of repetition numbers (the k of the innermost REPEAT being executed, including REPEATs in calling procedures). If the list is empty, error "REPCOUNT outside REPEAT".
  RANDOM n: if n is not 1 or more, error "RANDOM doesn't like <n> as input". Otherwise, update r to the remainder of 48271 * r divided by 2147483647, and the value is the remainder of the updated r divided by n (r is always between 1 and 2147483646 inclusive, so 48271 * r is less than 2^47).
  ABS a: the absolute value of a.
  NOT a: 1 if a is 0, otherwise 0.
  AND a b: 1 if neither a nor b is 0, otherwise 0.
  OR a b: 1 if at least one of a and b is not 0, otherwise 0.
  MAX a b, MIN a b: the larger, the smaller of a and b.
- A procedure call expression is as described in Section 8.

Section 11. Printing and other commands
The string of a print item is the word value if it is a quoted word, or the decimal notation of its value if it is an expression.
- PRINT item: output the string of item as one line.
- Multi-item print command (( PRINT item1 item2 ... )): output as one line the strings of the print items in the written order, separated by single spaces. If there are zero print items, output an empty line. The print items are evaluated from left to right, and the line is output only after all of them have been evaluated.
- SEED n: if n is not 1 or more, error "SEED doesn't like <n> as input". Otherwise, set the random state r to n.

Section 12. Output and error reporting
Canvas output: if there are no marked cells, output the single line "CANVAS 0 0 0". Otherwise, let x1 and x2 be the minimum and maximum x coordinates of the marked cells, and y1 and y2 the minimum and maximum y coordinates; output "CANVAS <x2-x1+1> <y2-y1+1> <number of marked cells>", followed by one line each for y = y2, y2-1, ..., y1 in this order. Each line consists of the characters of the cells (x, y) for x = x1, x1+1, ..., x2 in this order (the mark's character if the cell is marked, otherwise a space), with all trailing spaces removed (a line may become empty).

If (C) finishes without an error, output "TURTLE <x> <y> <h> <pen state> <pen character>", followed by the canvas output. The pen state is one of DOWN, UP, ERASE.

If an error occurs, output the following (1) and (2), and stop processing that program.
(1) The single line "ERROR line <line number>: <reason>".
(2) If the error occurred in (C) and there are "active procedure calls" at that moment (calls whose environment was appended in (4) of Section 8 and not yet removed in (6)), list them in order from the newest to the oldest, group consecutive runs of calls of the same procedure, and output one line per group. With P the procedure name of the group and c the number of calls, the line is "  in <P>" if c = 1, and "  in <P> x<c>" if c >= 2 (it begins with two spaces).
Lines output before the error occurred (lines from PRINT, SNAPSHOT, tracing, and so on) remain as they are.

The line numbers of runtime errors are as follows.
- Errors of RT, LT, SETH, SETPEN, SEED: the line number of the command's word.
- Errors of RANDOM and REPCOUNT: the line number of the function's word.
- Errors of / and MOD: the line number of the operator.
- has no value: the line number of the variable token.
- without TEST: the line number of the command's word.
- recursion too deep, you don't say what to do with, did not output: the line number of the procedure-name token of that procedure call.

[Output format]
- For each program, output the lines described in [Processing]. Every line ends with LF.
- Words and values are separated by single spaces as described. No empty lines are output, except as canvas lines and for a multi-item print command with zero print items.
- The error reasons are the following 22 kinds (replace the parts in < > as described; ' is the character ' itself).
  bad token '<lexeme>'
  TO inside definition of <name>
  bad procedure header
  <name> is a primitive
  <name> is already defined
  duplicate input <spelling>
  END without TO
  missing END for <name>
  I don't know how to <name>
  not enough inputs to <spelling>
  <spelling> doesn't like <spelling or value> as input
  you don't say what to do with <spelling or value>
  unexpected ]
  missing ]
  missing )
  misplaced <TO or END>
  can only use <spelling> inside a procedure
  <variable name> has no value
  REPCOUNT outside REPEAT
  <spelling> without TEST
  recursion too deep
  <name> did not output
In the list above, the first 8 kinds are errors that occur in (A), the next 9 kinds occur in (B), and the rest occur in (C). However, "doesn't like" and "you don't say what to do with" occur in both (B) and (C); in (B) they contain the token's spelling, and in (C) the decimal notation of the value.

[Constraints]
- The input has at most 3000 lines and at most 100 programs.
- Each number token has at most 10 characters, and its value is at most 10^9, regardless of whether it is executed.
- Every integer that appears during execution (number token values, variable values, results of operations and functions, values of command inputs, and so on; excluding the random state r and the computation inside RANDOM) has an absolute value of at most 10^9.
- The coordinates of the turtle's position, of cells to which the pen is applied, and of cells marked by FILL or LABEL all have absolute values of at most 1000.
- In one program, the number of executed commands, the number of times the pen is applied, and the total number of cells marked by FILL are each at most 10^6. Every WHILE loop terminates.
- In every canvas output, x2-x1+1 and y2-y1+1 are both at most 100.

[Example]
Input:
#PROGRAM demo
to box :n          ; a square with n+1 cells per side
  repeat 4 [fd :n rt 90]
end
box 3
pu setxy 1 1 pd setpen 46 fill
print xcor * 10 + ycor
(print "size 3 -2)
#PROGRAM oops
TO HALF :V
  OUTPUT 10 / :V
END
REPEAT 3 [PRINT HALF 2 - REPCOUNT]
#EOF

Output:
PROGRAM demo
11
SIZE 3 -2
TURTLE 1 1 0 DOWN .
CANVAS 4 4 16
****
*..*
*..*
****
PROGRAM oops
10
ERROR line 11: / doesn't like 0 as input
  in HALF

In program demo, box 3 draws a square with 4 cells per side; then the pen is raised, the turtle moves to (1, 1), the pen is lowered, the pen character is set to ., and the inside of the square is filled. The quoted word "size is converted to uppercase and printed as SIZE, and the - in 3 -2 is a sign minus, so 3 and -2 are separate print items. In program oops, the input of HALF is the whole expression 2 - REPCOUNT. In the second repetition, computing 10 / 0 causes an error, and the HALF call that was active at that moment is reported.
