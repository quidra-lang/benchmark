[Overview]
Write a program that simulates the behavior of an IPv4 router and firewall. No actual network communication is performed. The program reads a sequence of configuration commands and packet commands from standard input. On a router equipped with interfaces, a routing table (route selection by longest match), access control lists (ACLs), static NAT, port forwarding, port address translation (PAT), connection tracking (stateful inspection) and reverse path checking (uRPF), it passes each packet through processing steps in a fixed order, and outputs the verdict of whether the packet is forwarded or dropped, together with the translated addresses. There are also commands that display state and statistics. Parse and validate address strings yourself.

[Input format]
The first line contains the number of commands N. Each of the following N lines contains one command. Each command consists of a command name and zero or more arguments, separated by single spaces; there is no whitespace at the beginning or end of a line, and there are no empty lines. The commands have the following 20 forms.

  IFACE name cidr
  UP name
  DOWN name
  ROUTE prefix VIA hop metric
  ROUTE prefix DEV name metric
  NOROUTE prefix
  ACL name dir seq action proto src sports dst dports
  ACL name dir seq action proto src sports dst dports ESTABLISHED
  NOACL name dir seq
  NAT STATIC inaddr outaddr
  NAT OUTSIDE name
  NAT PAT name count
  NAT FORWARD name proto port inaddr inport
  RPF name mode
  TIMEOUT proto sec
  TICK sec
  LOOKUP addr
  PACKET name proto flags src sport dst dport ttl
  SHOW what
  CLEAR what

The arguments are specified as follows.
- name: an interface name. It is a string of 1 to 8 characters that starts with a lowercase letter and consists only of lowercase letters and digits.
- dir is IN or OUT, action is one of PERMIT, DENY, REJECT, and mode is one of STRICT, LOOSE, OFF.
- proto: in ACL it is one of TCP, UDP, ICMP, ANY; in NAT FORWARD it is TCP or UDP; in TIMEOUT and PACKET it is one of TCP, UDP, ICMP.
- what: in SHOW it is one of IFACES, ROUTES, ACL, NAT, CONNS, COUNTERS; in CLEAR it is COUNTERS or CONNS.
- metric, seq, count, port, inport, sec, sport, dport, ttl: a decimal integer of 1 to 9 digits without extra leading zeros (zero is written "0"). The range of the value is checked in [Processing].
- cidr, prefix, hop, inaddr, outaddr, addr, and src and dst of ACL and PACKET: a string of 1 to 31 printable ASCII characters containing no whitespace. Whether it is written correctly is checked in [Processing].
- sports, dports: one of "ANY", a single decimal integer written as above, or two such integers joined by "-" (example: 1024-65535).
- flags: "-", or a string of 1 to 4 characters consisting only of uppercase letters.
The command names, the number of arguments, and the words of the arguments for which choices are listed above always follow these rules exactly. Word comparisons are case-sensitive.

[Processing]
Process the commands in order starting from the first line, and for each command output the lines described in [Output format].

1. Error reporting
For each command, perform the checks listed in 4 in the listed order, and report only the first error that applies, as one line consisting of "error: " followed by the message. A command with an error changes no state at all, except that it increases the error count by 1 (it does not advance the packet number either). NAME, SEQ, P, PORT and X in the messages are the corresponding input word written exactly as given (NAME is the interface name, SEQ is the ACL sequence number, P is the protocol, PORT is the port number, and X is any other word). The checks that appear repeatedly are the following.
- Interface check: if there is no interface with that name, "no interface NAME".
- Address check: if the word is not a valid address, "bad address X".
- Prefix check: if the word is not a valid prefix, "bad prefix X"; if it is valid but, with L its length, the address has a 1 in its lower 32-L bits, "host bits set in X".

2. Addresses and prefixes
- An address is valid when it is a string consisting of exactly 4 fields separated by ".", each field consists only of 1 to 3 digits (0 to 9), a field of 2 or more characters does not start with 0, and the value of each field is at most 255. For example, "10.0.0.1" is valid, while "10.0.0", "10.0.0.256", "10.00.0.1" and "10..0.1" are not.
- An address a.b.c.d is regarded as the 32-bit value a*2^24 + b*2^16 + c*2^8 + d. Whether an address is smaller or larger, and its upper and lower bits (digits in binary), are determined by this value. In the output, an address is always written in the form a.b.c.d without extra leading zeros.
- A prefix is valid when it is a string containing exactly one "/", the part before the "/" is a valid address, the part after it is 1 or 2 digits, not starting with 0 if it has 2 digits, and its value L (the length) is between 0 and 32 inclusive. Below, a prefix is written "A/L".
- An address B is contained in the prefix A/L when the upper L bits of A and B are equal. If L = 0, every address is contained.
- The value obtained from an address by keeping its upper L bits unchanged and setting all of its lower 32-L bits to 0 is called the "network address" of length L of that address.
- In src and dst of ACL, "ANY" may be written instead of a prefix; it means the same as 0.0.0.0/0.

3. State
- Interface: has a name, an address, a length, a status (up or down), a role (inside or outside), a PAT pool (none, or a size), an RPF mode (one of strict, loose, off), a receive count rx, a transmit count tx, and a drop count drop. The order in which the interfaces were defined is called the "definition order".
- Routing table: a sequence of routes, in the order in which they were added (this order is called the "table order"; deleting routes does not change the order of the remaining ones). Each route has a type (C for a connected route, S for a static route), a destination (a network address and a length), an output interface, a next hop (none, or an address), a metric, and a use count hits. A route whose output interface has status down is called "inactive", and any other route is called "active".
- ACL: for each pair of an interface and a direction (in or out; IN and OUT in the commands denote in and out respectively), there is a set of rules and a default-deny count. Each rule has a sequence number, an action, a protocol, src, sports, dst, dports, whether it has ESTABLISHED, and a match count hits. A pair with one or more rules is said to "have an ACL".
- NAT: holds a set of static NAT mappings (pairs of an inside address and an outside address), a set of port forwarding rules (interface, protocol, outside port, inside address, inside port), and, for each interface, a set of PAT mappings (protocol, inside address, inside port, outside port, last-used time).
- Connection table: a sequence of connections (see 8). The connections are in the order in which they were added (increasing order of connection number).
- Timeout values: 300, 60 and 30 (seconds) for TCP, UDP and ICMP respectively.
- There are also a clock, the last assigned packet number, the last assigned connection number, and statistics (the forwarded count, the local count (packets addressed to the router itself), a count for each drop reason, and the error count). All of their initial values are 0. The error count is the number of "error: " lines output since the start or since the last CLEAR COUNTERS.
In the initial state, there are no interfaces, routes, ACL rules, NAT mappings or rules, or connections.

4. Processing of each command
(1) IFACE name cidr
  Checks: an interface named name already exists: "duplicate interface NAME". cidr is not a valid prefix, or its length L is not between 8 and 30 inclusive: "bad prefix X". The lower 32-L bits of the address of cidr are all 0 or all 1: "bad host address X". If there is an existing interface whose network overlaps (with A2 and L2 the address and length of that interface, and K the smaller of L and L2, the upper K bits of the address of cidr and of A2 are equal), then, with O the name of the first such interface in definition order: "subnet overlaps O".
  On success, add an interface with the address and length of cidr (status up, role inside, no PAT pool, RPF mode off, rx, tx and drop 0). In addition, append to the end of the routing table a connected route (type C, destination the network address of length L of the address of cidr together with length L, output interface name, no next hop, metric 0, hits 0).
(2) UP name, DOWN name
  Checks: the interface check on name. For UP, the status is already up: "interface NAME already up". For DOWN, the status is already down: "interface NAME already down".
  On success, set the status to up (UP) or down (DOWN). The other configuration commands can also be used on an interface whose status is down.
(3) ROUTE prefix VIA hop metric, ROUTE prefix DEV name metric
  Checks: the prefix check on prefix. For VIA, the address check on hop; for DEV, the interface check on name. metric is not between 1 and 255 inclusive: "bad metric X". For VIA, hop is equal to the address of some interface: "nexthop X is local". For VIA, there is no interface whose network contains hop (with A2 and L2 its address and length, hop is contained in A2/L2): "nexthop X unreachable". A static route already exists whose destination network address, length, output interface and next hop (two absent next hops are considered equal) are all equal to those of the route being added: "duplicate route X" (X is prefix; metrics are not compared).
  On success, append a static route to the end of the routing table (destination the address and length of prefix, metric metric, hits 0). For VIA, the output interface is the interface whose network contains hop (it is unique because interface networks do not overlap), and the next hop is hop. For DEV, the output interface is name and there is no next hop.
(4) NOROUTE prefix
  Checks: the prefix check on prefix. There is no static route whose destination network address and length are equal to the address and length of prefix: "no static route X".
  On success, delete all such static routes. Connected routes are not deleted.
(5) LOOKUP addr
  Checks: the address check on addr.
  Perform the "route selection" of 5 for addr.
(6) ACL name dir seq action proto src sports dst dports (ESTABLISHED may also follow at the end)
  Checks: the interface check on name. seq is not between 1 and 9999 inclusive: "bad sequence X". The prefix check on src ("ANY" is considered valid; the same applies to dst). The port range check on sports. The prefix check on dst. The port range check on dports. proto is ICMP or ANY, and at least one of sports and dports is not ANY: "ports not allowed for P". The pair (name, dir) already has a rule with sequence number seq: "duplicate sequence SEQ".
  Port range check: ANY denotes all ports, a single integer a denotes only port a, and "a-b" denotes the ports from a to b inclusive. If any of the integers that appear exceeds 65535, or a > b: "bad port range X".
  On success, add the rule (hits 0) to the pair (name, dir). A rule written with ESTABLISHED at the end "has ESTABLISHED".
(7) NOACL name dir seq
  Checks: the interface check on name. The pair (name, dir) has no rule with sequence number seq: "no rule SEQ on NAME d" (d is dir in lowercase).
  On success, delete that rule. A pair left with no rules returns to the state of having no ACL (its default-deny count is kept).
(8) NAT STATIC inaddr outaddr
  Checks: the address check on inaddr. The address check on outaddr. Examine inaddr and then outaddr, and if one of them is equal to the address of some interface: "address X is local". A static NAT mapping whose inside address is equal to inaddr already exists: "duplicate static X" (X is inaddr). A mapping whose outside address is equal to outaddr already exists: "duplicate static X" (X is outaddr).
  On success, add the mapping (inside inaddr, outside outaddr).
(9) NAT OUTSIDE name
  Checks: the interface check on name. The role is already outside: "interface NAME already outside".
  On success, set the role to outside.
(10) NAT PAT name count
  Checks: the interface check on name. count is not between 1 and 1000 inclusive: "bad pool size X". The interface already has a PAT pool: "pat already on NAME".
  On success, set the size of the PAT pool to count, and set the role to outside (it may already be outside). The PAT outside ports of this interface are chosen from the numbers 20000 to 20000+count-1 inclusive.
(11) NAT FORWARD name proto port inaddr inport
  Checks: the interface check on name. port is not between 1 and 65535 inclusive: "bad port PORT". The address check on inaddr. inport is not between 1 and 65535 inclusive: "bad port PORT" (here PORT is inport). The role is not outside: "interface NAME not outside". inaddr is equal to the address of some interface: "address X is local". A port forwarding rule whose interface, protocol and outside port are equal to name, proto and port respectively already exists: "duplicate forward NAME P PORT".
  On success, add the port forwarding rule (name, proto, outside port port, inside address inaddr, inside port inport).
(12) RPF name mode
  Checks: the interface check on name.
  On success, set the RPF mode to mode in lowercase.
(13) TIMEOUT proto sec
  Checks: sec is not between 1 and 86400 inclusive: "bad timeout X".
  On success, set the timeout value of proto to sec.
(14) TICK sec
  Checks: sec is not between 1 and 86400 inclusive: "bad tick X".
  On success, add sec to the clock, then perform the "expiry" processing of 9.
(15) PACKET name proto flags src sport dst dport ttl
  Checks: the interface check on name. proto is UDP or ICMP, and flags is not "-": "flags not allowed for P". proto is TCP, flags is not "-", and it contains a character other than S, A, F, R or contains the same character two or more times: "bad flags X". The address check on src. sport is not between 0 and 65535 inclusive: "bad port PORT". The address check on dst. dport is not between 0 and 65535 inclusive: "bad port PORT". ttl is not between 1 and 255 inclusive: "bad ttl X".
  On success, increase the packet number by 1 and use it as the number of this packet (the first packet is 1), increase rx of interface name by 1, and perform the "packet processing" of 7. The flag set of the packet is empty if flags is "-", and otherwise is the set of characters contained in flags (the order of the characters does not matter).
(16) SHOW what
  Output as described in [Output format]. The state is not changed.
(17) CLEAR what
  CLEAR COUNTERS sets to 0 the statistics (the forwarded count, the local count, the count for each drop reason, the error count), rx, tx and drop of every interface, hits of every route, hits of every rule, and the default-deny count of every pair. CLEAR CONNS removes all connections and all PAT mappings. Neither of them changes the clock, the packet number or the connection number.

5. Route selection
For an address B, the candidates are the active routes whose destination (the prefix given by the network address and length) contains B. Among the candidates, choose the one with the greatest length; if there are several, the one with the smallest metric among them; if there are still several, the one earliest in table order. If there are no candidates, the result is "no route". Route selection itself does not change the hits of routes (hits are increased only in 7 (13)).

6. Evaluation by an ACL
When a packet is evaluated by the ACL of the pair (interface I, direction d), given the source address and source port and the destination address and destination port to use for the evaluation: if the pair has no ACL, the result is permit (nothing is counted). If it has an ACL, examine the rules in increasing order of sequence number, and the first rule that satisfies all of the following conditions is the "matched rule".
- The protocol of the rule is ANY or is equal to the protocol of the packet.
- The source address used for the evaluation is contained in src, and the destination address used for the evaluation is contained in dst.
- If the protocol of the rule is TCP or UDP, the source port used for the evaluation is within the range sports, and the destination port is within the range dports (rules with ICMP or ANY do not examine ports).
- If the rule has ESTABLISHED, the packet belongs to an existing connection (see 8).
If there is a matched rule, increase its hits by 1. If its action is PERMIT, the result is permit; if DENY, the verdict is "DROP acl I d SEQ"; if REJECT, the verdict is "REJECT acl I d SEQ R" (I is the interface name, d is the direction, SEQ is the sequence number of the rule, and R is "tcp-reset" if the protocol of the packet is TCP and "icmp-prohibited" otherwise). If there is no matched rule, increase the default-deny count of the pair by 1, and the verdict is "DROP acl I d default".

7. Packet processing
Let I be the receiving interface, P the protocol, F the flag set, S and SP the source address and port, D and DP the destination address and port, and T the TTL. The tuple (P, S, SP, D, DP) is called the "original tuple", and a packet whose P is TCP and whose F consists of exactly S alone is called a "pure SYN". Perform the following steps (1) to (13) in order; as soon as a verdict is determined, the steps for that packet end.
(1) If the status of I is down, the verdict is "DROP down".
(2) If at least one of S and D is contained in any of 0.0.0.0/8, 127.0.0.0/8, 224.0.0.0/3, or S is equal to the address of some interface (regardless of its status), the verdict is "DROP martian".
(3) If the RPF mode of I is strict or loose, perform route selection for S. If there is no route, the verdict is "DROP rpf". If the mode is strict and the output interface of the selected route is not I, the verdict is "DROP rpf".
(4) Look up, in the connection table, the connection that the original tuple belongs to (see 8).
(5) If P is TCP, the packet does not belong to an existing connection, and it is not a pure SYN either, the verdict is "DROP invalid".
(6) Evaluate with the ACL of the pair (I, in). The values used for the evaluation are S, SP, D, DP.
(7) If the role of I is outside, translate the destination. Let D' and DP' be the translated destination address and port, initially D' = D and DP' = DP.
  - If there is a static NAT mapping whose outside address is equal to D, set D' to its inside address.
  - Otherwise, if D is equal to the address of I and there is a port forwarding rule with interface I, protocol P and outside port DP, set D' and DP' to its inside address and inside port.
  - Otherwise, if D is equal to the address of I and among the PAT mappings of I there is one whose protocol is P and whose outside port is DP, set D' and DP' to its inside address and inside port, and call this mapping the "used mapping".
  If the role of I is inside, D' = D and DP' = DP.
(8) If D' is equal to the address of some interface (regardless of its status), then, with L the name of that interface, the verdict is "LOCAL L".
(9) If T = 1, the verdict is "DROP ttl".
(10) Perform route selection for D'. If there is no route, the verdict is "DROP noroute". Let R be the selected route and O its output interface.
(11) Evaluate with the ACL of the pair (O, out). The values used for the evaluation are S, SP, D', DP'.
(12) If the role of I is inside and the role of O is outside, translate the source. Let S' and SP' be the translated source address and port, initially S' = S and SP' = SP.
  - If there is a static NAT mapping whose inside address is equal to S, set S' to its outside address.
  - Otherwise, if there is a port forwarding rule with interface O, protocol P, inside address S and inside port SP (if there are several, the one added earliest), set S' to the address of O and SP' to the outside port of that rule.
  - Otherwise, if O has a PAT pool, look for a PAT mapping of O whose protocol, inside address and inside port are P, S and SP. If there is none, choose the smallest number of the pool of O that is neither the outside port of any mapping of O nor the outside port of any port forwarding rule of O (regardless of protocol), and add to O the mapping (protocol P, inside address S, inside port SP, outside port that number, last-used time the value of the clock). If there is no such number, the verdict is "DROP exhausted". Call the found or added mapping the "used mapping", and set S' to the address of O and SP' to the outside port of that mapping.
  For any other combination of the roles of I and O, S' = S and SP' = SP.
(13) Forward the packet.
  - If there is a used mapping, set its last-used time to the value of the clock.
  - If no connection was found in (4), increase the connection number by 1 (the first connection is 1), and append a connection with that number to the end of the connection table. The orig tuple of this connection is the original tuple, its reply tuple is (P, D', DP', S', SP'), its input interface is I, its output interface is O, its state is SYN_SENT if P is TCP and UNREPLIED otherwise, its orig and reply packet counts are 0, and FIN is unrecorded on both sides. The direction of the packet in this case is "new".
  - Increase the orig packet count of the connection (when the direction is new or orig) or its reply packet count (when the direction is reply) by 1, set the last-used time of the connection to the value of the clock, and update the state of the connection by the rules of 8.
  - Increase tx of O by 1, increase hits of R by 1, and the verdict is "FORWARD" (see [Output format] for how it is written).
Once a verdict is determined, increase the statistic corresponding to the verdict by 1: the forwarded count for FORWARD, the local count for LOCAL, and otherwise (a drop) the count of the following reason. DROP down is down, DROP martian is martian, DROP rpf is rpf, DROP invalid is invalid, DROP acl and REJECT determined in (6) are acl_in, DROP ttl is ttl, DROP noroute is noroute, DROP acl and REJECT determined in (11) are acl_out, and DROP exhausted is exhausted. For a drop, also increase drop of I by 1. For LOCAL and for a drop, connections and PAT mappings are not changed, other than by the removal described in (4).

8. Connection tracking
- Each connection has a connection number, a protocol, an orig tuple, a reply tuple, an input interface, an output interface, a state, orig and reply packet counts, a last-used time, and, for each of the orig side and the reply side, whether a FIN has been recorded.
- How to find the connection that the original tuple belongs to: examine the connections of the connection table in increasing order of connection number, comparing each connection first with its orig tuple and then with its reply tuple, and find the first one for which all 5 values are equal to the original tuple. If it is equal to the orig tuple, the direction of the packet is "orig"; if it is equal to the reply tuple, it is "reply". However, if the state of the found connection is CLOSED and the packet is a pure SYN, remove that connection from the connection table and treat it as not found (it stays removed even if the packet is dropped afterwards). When a connection is found, the packet is said to "belong to an existing connection".
- State update:
  If P is UDP or ICMP, set the state to REPLIED when the direction is reply.
  If P is TCP, set the state to CLOSED if F contains R. If F does not contain R, perform the following (i) and (ii) in order.
  (i) If the state is SYN_SENT, the direction is reply, and F contains both S and A, set the state to ESTABLISHED.
  (ii) If F contains F and the state is ESTABLISHED or FIN_WAIT, record FIN for the side of the direction of the packet (new and orig are the orig side, reply is the reply side). If both the orig side and the reply side have been recorded, set the state to CLOSED; otherwise set it to FIN_WAIT.

9. Expiry
After TICK advances the clock, for each connection in the connection table, if the value of the clock minus its last-used time is greater than or equal to the timeout of that connection, remove that connection. The timeout of a connection is, for TCP, 60 if the state is SYN_SENT, 60 if FIN_WAIT, 10 if CLOSED, and the TCP timeout value if ESTABLISHED. For UDP and ICMP, it is the timeout value of that protocol regardless of the state. Similarly, for every PAT mapping, if the value of the clock minus its last-used time is greater than or equal to the timeout value of the protocol of that mapping, remove that mapping.

[Output format]
For each command, output the following lines. For a command with an error, output only the "error: " line described in 1. NAME, SEQ, P, PORT and X in the list below are, as in 1, the input words of that command written exactly as given (the symbols in the SHOW lines are as described for each of them).
- IFACE: "ok iface NAME X network N/L" (X is cidr, N is the network address of length L of the address of cidr)
- UP: "ok up NAME", DOWN: "ok down NAME"
- ROUTE: "ok route E" (E is the notation of the added route; see below)
- NOROUTE: "ok noroute X removed=K" (K is the number of deleted routes)
- LOOKUP: "lookup X E", with E the notation of the selected route, or "lookup X none" if there is no route
- ACL: "ok acl NAME d SEQ" (d is dir in lowercase; the same applies below)
- NOACL: "ok noacl NAME d SEQ hits=H" (H is the hits of the deleted rule)
- NAT STATIC: "ok nat static X Y" (X is inaddr, Y is outaddr)
- NAT OUTSIDE: "ok nat outside NAME"
- NAT PAT: "ok nat pat NAME A 20000-Z" (A is the address of the interface, Z = 20000+count-1)
- NAT FORWARD: "ok nat forward NAME P PORT X:Y" (PORT is port, X is inaddr, Y is inport)
- RPF: "ok rpf NAME m" (m is mode in lowercase)
- TIMEOUT: "ok timeout P X" (X is sec)
- TICK: "ok tick time=T expired conns=C nat=M" (T is the value of the clock after advancing it, and C and M are the numbers of connections and PAT mappings removed in 9)
- PACKET: "#K P G S:SP > D:DP V" (K is the packet number, G is the flags word, S, SP, D, DP are the src, sport, dst, dport words, and V is the verdict)
- SHOW: the multiple lines described below
- CLEAR COUNTERS: "ok clear counters"
- CLEAR CONNS: "ok clear conns=C nat=M" (C and M are the numbers of removed connections and PAT mappings)

Route notation: "K N/L via H dev I metric M" if there is a next hop, otherwise "K N/L dev I metric M". K is the type (C or S), N/L is the destination network address and length, H is the next hop, I is the name of the output interface, and M is the metric.

The PACKET verdict V is one of "DROP down", "DROP martian", "DROP rpf", "DROP invalid", "DROP acl I d SEQ" of 6, "DROP acl I d default", "REJECT acl I d SEQ R", "LOCAL L", "DROP ttl", "DROP noroute", "DROP exhausted", or, when the packet is forwarded, the following form.
  "FORWARD O H ttl=U", followed by " dnat=D':DP'" if (D', DP') differs from (D, DP) and by " snat=S':SP'" if (S', SP') differs from (S, SP), in this order, and finally " conn=C W". O is the name of the output interface; H is "via" followed by a single space and the next hop if R has a next hop, and "direct" otherwise; U = T-1; C is the number of the connection the packet belongs to (including a newly added connection); and W is the direction (one of new, orig, reply).

The SHOW output is as follows. "Name order" means the lexicographic order of interface names compared by ASCII code.
- SHOW IFACES: the first line is "show ifaces count=N" (N is the number of interfaces). Then output one line per interface, in name order, in the form "NAME A/L ST RO rpf=MO". NAME is the interface name, A/L is the address and length, ST is up or down, RO is inside or outside, and MO is the RPF mode. For an interface with a PAT pool, append " pat=U/C" at the end of the line (U is the number of PAT mappings of that interface, C is the size of the pool).
- SHOW ROUTES: the first line is "show routes count=N" (N is the number of routes). Then output all routes, sorted in increasing order of destination network address, then, if equal, in increasing order of length, then, if equal, in increasing order of metric, then, if equal, in table order, one line each in the form "E hits=H", with E the route notation. For an inactive route, append " inactive" at the end of the line.
- SHOW ACL: the first line is "show acl count=N" (N is the total number of rules over all pairs). Then, for the interfaces in name order and, for each interface, in the order in, out, output only the pairs that have an ACL. For one pair, first output the rules in increasing order of sequence number, one line each in the form "acl NAME d SEQ AC P SRC SPORTS DST DPORTS hits=H". NAME is the interface name, d is the direction, SEQ is the sequence number of the rule, AC and P are the action and protocol of the rule written as in the input, and H is the hits of the rule. For a rule with ESTABLISHED, insert " established" between DPORTS and " hits=". At the end of the pair, output "acl NAME d default DENY hits=H" (H is the default-deny count of that pair). SRC and DST are "any" if the length is 0, and "A/L" otherwise. SPORTS and DPORTS are "any" for ANY, "a" if they denote only a single port a ("a", or "a-b" with a and b equal), and "a-b" for any other "a-b".
- SHOW NAT: the first line is "show nat static=X forward=Y pat=Z" (X, Y and Z are the numbers of static NAT mappings, port forwarding rules, and PAT mappings (the total over all interfaces)). Then output, one line each, the static NAT mappings in increasing order of inside address in the form "static A B" (A is the inside address, B is the outside address), the port forwarding rules in interface name order, then in increasing order of outside port, then in lexicographic order of protocol, in the form "forward NAME P PORT A:Q" (NAME is the interface name, P is the protocol, PORT is the outside port, A is the inside address, Q is the inside port), and the PAT mappings in interface name order, then in increasing order of outside port, in the form "pat NAME PORT P A:Q idle=T" (NAME is the interface name, PORT is the outside port, P is the protocol, A is the inside address, Q is the inside port, and T is the value of the clock minus the last-used time).
- SHOW CONNS: the first line is "show conns count=N" (N is the number of connections). Then output the connections in increasing order of connection number, one line each in the form "conn C P S:SP > D:DP reply X:XP > Y:YP in=I out=O state=ST pkts=F/R idle=T". C is the connection number, P is the protocol, S, SP, D, DP are the source address, source port, destination address and destination port of the orig tuple, X, XP, Y, YP are the same values of the reply tuple, I and O are the names of the input and output interfaces, ST is the state (one of SYN_SENT, ESTABLISHED, FIN_WAIT, CLOSED, UNREPLIED, REPLIED), F and R are the orig and reply packet counts, and T is the value of the clock minus the last-used time.
- SHOW COUNTERS: the first line is "show counters packets=A forwarded=B local=C dropped=D errors=E". B is the forwarded count, C is the local count, D is the sum of the counts of all drop reasons, A = B+C+D, and E is the error count. The second line is "drops down=... martian=... rpf=... invalid=... acl_in=... ttl=... noroute=... acl_out=... exhausted=...", with the count of each reason written after its "=". Then output one line per interface, in name order, in the form "iface NAME rx=... tx=... drop=..." (NAME is the interface name), writing the rx, tx and drop of that interface after the respective "=".

All numbers are written in decimal without extra leading zeros. All output consists of ASCII characters. Items within a line are separated by a single space, no line has trailing whitespace, and every line ends with a newline. No empty lines are output.

[Constraints]
- 1 <= N <= 1000. Each line has at most 200 characters.
- The value of the clock is always less than 2^31. An address treated as a 32-bit value can be 2^31 or more, but is less than 2^32. All other values fit in 32-bit signed integers.
