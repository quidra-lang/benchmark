[Overview]
Write a program that reads a JSON document and queries and edits it with path expressions. The program reads a JSON document and a sequence of commands on it from standard input, and writes the results to standard output. JSON is read strictly; if there is an error, the first error found is reported together with its line number, column number and reason (only integers are handled as numbers; fractions and exponent notation are errors). Path expressions support selecting a child by key, selecting by index (including negative indices), wildcards, slices, and recursive search of descendants. There are 21 commands: getting values (GET), output in compact form and in pretty form, type, length and key listing, flattening of leaves (FLATTEN), aggregation by count, sum, minimum, maximum and average, filtering of array elements (FILTER), setting values (SET), deletion (DELETE), insertion into arrays (INSERT), deep merging of objects (MERGE), stable sorting (SORT), renaming keys (RENAME), undoing changes (UNDO), and loading another document (LOAD).

[Input format]
The input consists of multiple lines, and each line is a string of 0 to 200 characters consisting only of printable ASCII characters (character codes 32 to 126). The input is arranged in the following order.
- The first "document block": the zero or more lines from line 1 up to just before the first line consisting of only %%.
- From the line after that %% line, command lines follow, one command per line. The last line is a line consisting of only END, and there are no lines after it.

Immediately after a command line consisting of only LOAD, a document block (zero or more lines up to just before a line consisting of only %%) follows, and command lines continue again from the line after that %% line. A document block and the %% line that ends it are not command lines. Any line other than a line consisting of only %% (including empty lines, lines consisting of only END, and so on) may appear in a document block.

A command line (a line outside document blocks, other than the END line) is not empty, and its first and last characters are not spaces. The part of the line before the first space (the whole line if there is no space) is called the "command name", and the part after the first space is called the "argument part" (if there is no space, there is no argument part). A line whose command name is LOAD consists of only LOAD. Also, except within the "JSON value" part of SET, MERGE, INSERT and FILTER (defined in [Processing] section 9), a command line never contains two or more consecutive spaces.

There are the following 21 command formats ([ ] marks an optional part).

  LOAD
  GET path
  COMPACT [path]
  PRETTY [path]
  TYPE path
  LENGTH path
  KEYS path
  FLATTEN [path]
  COUNT path
  SUM path
  MIN path
  MAX path
  AVG path
  FILTER path field operator [JSON value]
  SET path JSON value
  DELETE path
  INSERT path index JSON value
  MERGE path JSON value
  SORT path [field] [DESC]
  RENAME path key
  UNDO

However, the input also contains lines that do not match these formats (unknown command names, wrong numbers of arguments, malformed paths or JSON values, and so on). How they are handled is described in [Processing].

[Processing]
Process the input in order from the beginning and output the results. The program holds a "document" (one JSON value) and a "history" (a sequence of document states). At the start, the document is null and the history is empty.

1. Terms
- A "space" means the half-width space (character code 32), and "LF" means the newline character (character code 10).
- "Letters" are the 52 characters A to Z and a to z, "digits" are the 10 characters 0 to 9, and "hex digits" are the 22 characters consisting of the digits, a to f, and A to F.
- An "identifier" is a string of one or more characters that starts with a letter or _ and consists only of letters, digits and _.
- An "integer notation" is a string that is either 0, or a - (optional) followed by a sequence of at most 9 digits starting with one of 1 to 9. For example, 0, 7, -12 and 999999999 are integer notations, and -0, 007, 1234567890 and +5 are not integer notations. The integer obtained by reading an integer notation as a decimal number is its "value".
- The length of a string is its number of characters. Strings are compared in lexicographic order by character code. That is, compare one character at a time from the beginning; the string whose character code is smaller at the first differing character is the smaller one, and when one string matches the beginning of the other, the shorter one is the smaller one.

2. Values and locations
A JSON value is one of the following six kinds. The name in parentheses is the "type name" of that kind.
- Object (object): a sequence of zero or more "elements". An element is a pair of a key (a string) and a value, and one object never has two or more elements with the same key. The order of the elements is called the "element order", and an element being added is always appended at the end.
- Array (array): a sequence of zero or more values. Each value in the sequence is also called an "element", and the elements are given "indices" 0, 1, 2, ... from the beginning.
- String (string): a sequence of zero or more characters with character codes 1 to 127 (it may contain non-printable characters).
- Number (number): an integer.
- Boolean (boolean): true or false.
- Null (null): the value null.
The values of the elements of an object, and the elements of an array, are called the "children" of that value. The order of the children is the element order for an object and the index order for an array. Children, children of children, ... are collectively called "descendants". The "pre-order sequence" of a value v is v itself followed by, for each child c of v in child order, the pre-order sequence of c, all concatenated.
The value of the whole document is called the "root". The "location" of a value in the document is the sequence of "steps" followed from the root to that value. There are steps that move to an element of an object (represented by a key) and steps that move to an element of an array (represented by an index). The location of the root is the empty sequence.
- Location notation: $ followed by each step, in order, written as follows and concatenated. A key step is "." followed by the key if the key is an identifier; otherwise it is "[", the single-quote representation of the key (section 3), and "]" concatenated. An index step is "[", the decimal notation of the index, and "]" concatenated. Examples: $, $.store.books[0].title, $['a b'][2], $['it\'s'].
- Document order: each step of a location is associated with a "position". The position of an index step is its index, and the position of a key step is the ordinal number (counting from 0) of the element with that key in the element order of the object. Of two locations, compare their sequences of positions from the beginning; the one with the smaller position at the first difference comes first in document order. When one location matches the beginning of the other, the shorter one (the ancestor) comes first.
- The "value count" of a value v is the total number of v and all descendants of v (keys are not counted).
- The "depth" of the document is the maximum depth of the values in the document, where the depth of the root is 1 and the depth of a child of a value of depth d is d+1.

3. Representation of values
The representation of a string s for a quote character q (" or ') - called the double-quote representation when q is " and the single-quote representation when q is ' - is q, followed by each character of s written by the following rules, concatenated in order, followed finally by q.
- A character equal to q is written as \ followed by that character (\" or \').
- \ is written as \\.
- The characters with codes 8, 12, 10, 13 and 9 are written as \b, \f, \n, \r and \t respectively.
- Otherwise, a character whose code is less than 32 or is 127 is written as \u followed by its character code as a 4-digit hexadecimal number. The hexadecimal letters are lowercase (a to f), and the number is padded on the left with 0 (for example, code 1 is \u0001 and code 127 is \u007f).
- Any other character is written as is (the quote character that is not q, and /, are also written as is).
The "compact form" of a value is: null for null, true or false for a boolean, the decimal notation (with a leading - if negative) for a number, and the double-quote representation for a string. For an array, it is the compact forms of the elements, separated by , between [ and ]; for an object, it is, between { and }, for each element, "the double-quote representation of the key", ":" and "the compact form of the value" concatenated, listed in element order separated by ,. No spaces are inserted. Example: {"a":[1,"x\ty",null],"b":{},"c":true}.
The "pretty form" of a value is the value formatted with an indent I (a sequence of spaces), built as follows starting with I empty. J is I followed by two spaces.
- Non-empty array: "[", LF, the items (for each element e, J concatenated with "e formatted with indent J") separated by "," and LF, LF, I, "]", concatenated in this order.
- Non-empty object: "{", LF, the items (for each element, J, the double-quote representation of the key, ": " (a colon and one space), and "the value formatted with indent J" concatenated) in element order separated by "," and LF, LF, I, "}", concatenated in this order.
- Anything else (including empty arrays and empty objects): the compact form.
For example, the pretty form of {"a":[1,{"b":null}],"c":{},"d":[]} is the following 10 lines.
  {
    "a": [
      1,
      {
        "b": null
      }
    ],
    "c": {},
    "d": []
  }
(The two spaces at the start of each line are indentation for this explanation; the first line of the pretty form starts with {.)

4. Reading JSON
This section defines the procedure for reading one value from a JSON text (a sequence of characters). Reading proceeds while advancing a "current position" in the text from the beginning. The position just after the last character of the text is called the "end", and the current position being the end is described as "there is no character". "Skipping whitespace" means advancing the position one character at a time while the character at the current position is a space or LF.
If an error is found during reading, reading stops at that point, and the "reason" of the error and the "error position" are reported. Unless stated otherwise, the error position is the current position at that point.
(A) Whole text: read a value (B), then skip whitespace. If any character remains, it is the error "trailing characters".
(B) Value: skip whitespace, then act according to the character c at the current position as follows.
  - There is no character: error "unexpected end of input".
  - c is {: read an object (C).
  - c is [: read an array (D).
  - c is ": read a string (E).
  - c is - or a digit: read a number (F).
  - c is a letter: read a literal (G).
  - Otherwise: error "unexpected character '<c>'".
(C) Object: advance past the {, and skip whitespace. If the character is }, advance past it and finish reading an empty object. Otherwise, starting from an empty object, repeat the following.
  (1) Skip whitespace. If there is no character, error "unexpected end of input"; if the character is not ", error "expected key".
  (2) Read a string (E), and let it be the key k. If the object being built already has an element with key k, it is the error "duplicate key <double-quote representation of k>", and the error position is the position of the first " of k.
  (3) Skip whitespace. If there is no character, error "unexpected end of input"; if the character is not :, error "expected ':'". Advance past the :.
  (4) Read a value (B), and append the element with key k and that value at the end of the object.
  (5) Skip whitespace. If the character is }, advance past it and finish reading the object. If there is no character, error "unexpected end of input"; if the character is not ,, error "expected ',' or '}'". Advance past the , and skip whitespace; if the character is }, error "trailing comma". Otherwise go back to (1).
(D) Array: advance past the [, and skip whitespace. If the character is ], advance past it and finish reading an empty array. Otherwise, starting from an empty array, repeat the following.
  (1) Read a value (B), and append it at the end of the array.
  (2) Skip whitespace. If the character is ], advance past it and finish reading the array. If there is no character, error "unexpected end of input"; if the character is not ,, error "expected ',' or ']'". Advance past the , and skip whitespace; if the character is ], error "trailing comma". Otherwise go back to (1).
(E) String: advance past the first ", and starting from an empty string, repeat the following according to the character at the current position.
  - There is no character, or the character is LF: error "unterminated string".
  - ": advance past it and finish reading the string.
  - \: act as follows according to the character e right after it. Unless stated otherwise, the error position is the position of this \.
    - There is no character right after it, or e is LF: error "unterminated string", and the error position is the position after the \.
    - e is u: unless there are 4 characters after the u and all of them are hex digits (including when there are not 4 characters after it), error "bad unicode escape". If the value of those 4 characters read as a hexadecimal number is greater than 127, error "non-ascii escape". Otherwise, append the one character whose character code is that value to the end of the string, and advance 6 characters (\, u, and the 4 hex digits).
    - e is one of ", \, /, b, f, n, r, t: append the character ", \, /, or the character with code 8, 12, 10, 13, 9 respectively to the end of the string, and advance 2 characters.
    - Otherwise: error "invalid escape '\<e>'".
  - Any other character: append that character to the end of the string, and advance 1 character.
(F) Number: let P be the position of the first character of the number. If the character is -, advance 1 character. Let D be the longest run of digits continuing from there (it may have 0 characters), and advance to just after D. Check the following in order.
  - D has 0 characters: error "invalid number", and the error position is P.
  - D has 2 or more characters and its first character is 0: error "leading zero", and the error position is the position of the first character of D.
  - The character right after D is .: error "fraction not allowed".
  - The character right after D is e or E: error "exponent not allowed".
  - D has 10 or more characters: error "number out of range", and the error position is P.
  - Otherwise: the number read is the integer obtained by reading D as a decimal number (with its sign inverted if there was a -). -0 is 0.
(G) Literal: read the longest run W of letters, and advance to just after W. If W is true, false or null, the value read is the boolean true, the boolean false, or null respectively. Otherwise, error "invalid literal '<W>'", and the error position is the position of the first character of W.

5. Processing a document block
The first document block and the document block of LOAD are both processed as follows.
The lines of the block joined in order with one LF between consecutive lines (no LF is added after the last line; if the block has 0 lines, the text is empty) form the JSON text, which is read as in section 4.
- If there is an error, output "PARSE ERROR line <L> col <C>: <reason>". L and C are the line number and column number of the error position. The position of the j-th character (counting from 1) of the i-th line (counting from 1) of the block has line number i and column number j. The position of the LF after line i has line number i and column number (the number of characters in line i + 1). The end position has, if the block has one or more lines, the line number of the last line and column number (the number of characters in the last line + 1); if the block has 0 lines, line number 1 and column number 1. The document and the history do not change.
- If there is no error, append the current document to the end of the history (section 8), then make the value read the new document, and output "LOADED nodes=<value count of the root of the new document> depth=<depth of the new document>".

6. Paths
A path is an expression for selecting values in the document.
(1) Syntax
A path is $ followed by zero or more "segments". A segment is one of the following six kinds.
  .name    .*    [selection]    ..name    ..*    ..[selection]
A name is an identifier. A selection is one of the following four kinds.
  quoted key    integer notation    *    slice
A slice is an integer notation or the empty string, ":", and an integer notation or the empty string, concatenated in this order (examples: 1:3, -2:, :2, :).
A quoted key starts with '. Starting from the next character, read one character at a time, reading a \ as a pair together with the one character right after it; the quoted key ends where a ' that is not part of a pair appears. Between the two ', a character not paired with \ represents itself, and a pair with \ represents the following character. \', \\, \/, \b, \f, \n, \r, \t represent ', \, /, and the characters with codes 8, 12, 10, 13, 9 respectively, and \u followed by 4 hex digits (whose value must be 127 or less) represents the character whose character code is that value. Any other use of \ (including \") is an error. " can be written as is. For example, ['it\'s'] represents the key it's, and ['a b'] represents the key a b (a, space, b).
If the whole path string does not exactly match this syntax, it is a path error.
(2) Selectors
Each segment represents one "selector". .name and ..name are a "key selection" whose key is that name. If the selection is a quoted key, it is a key selection whose key is the string it represents; if it is an integer notation, it is an "index selection" by its value; if it is *, it is an "all selection"; if it is a slice, it is a "slice selection". .* and ..* are all selections. The three kinds of segments that start with .. are called "descendant segments".
(3) Computing matches
Evaluating a path against the document yields a sequence of "matches". A match is a pair of a value in the document and its location.
- The initial sequence consists of the root alone.
- Apply the segments one at a time from left to right, replacing the sequence each time. To apply a segment, for each match m in the sequence, in sequence order, concatenate all of the following results; this becomes the new sequence. If the segment is not a descendant segment, the result is the result of applying the selector to the value of m. If it is a descendant segment, the result is the concatenation of the results of applying the selector to each value in the pre-order sequence of the value of m, in pre-order sequence order.
- The sequence after applying the last segment is the result of the evaluation. If there are 0 segments (the path is just $), it is the root alone.
The result of applying a selector to a value v is as follows (the location of each result is the location of v with that step added).
- Key selection (key k): if v is an object and has an element with key k, the value of that element (1 result). Otherwise 0 results.
- All selection: if v is an array, all of its elements in index order; if v is an object, the values of all of its elements in element order. Otherwise 0 results.
- Index selection (integer i): when v is an array with n elements, let j=i if i is 0 or more, and j=n+i if i is negative; if 0 <= j < n, the element at index j (1 result). Otherwise 0 results.
- Slice selection: when v is an array with n elements, let a be the value of the part before the ":" and b the value of the part after it (a=0 if the part before is empty, b=n if the part after is empty). For each of a and b, add n if it is negative, and then make it 0 if it is less than 0 and n if it is greater than n. The result is the elements at indices a, a+1, ..., b-1 (0 results if a >= b). If v is not an array, 0 results.
For example, evaluating the path $..x on the document {"a":{"x":1,"b":{"x":2}},"c":[{"x":3},4]} gives the matches $.a.x (value 1), $.a.b.x (value 2), $.c[0].x (value 3) in this order; $.c[*] gives $.c[0] and $.c[1], $.c[-1] gives $.c[1], and $.*.x gives $.a.x.
The result of an evaluation may contain matches with the same location two or more times. Below, when a command description simply says "matches", it means the sequence resulting from the evaluation; unless stated otherwise, it is handled without removing duplicates, and "match order" refers to the order of this sequence.

7. Fields and keys
(1) Field: a field is @ followed by zero or more "simple segments". A simple segment is one of the three kinds .name, [quoted key] and [integer notation], and represents a key selection or an index selection with the same meaning as in section 6. If the whole string does not exactly match this syntax, it is a field error.
The value of a field for a value x is the result of applying the selectors of the simple segments from left to right, starting from x. If the result becomes 0 values partway, the value of the field is "no value". If there are 0 simple segments (just @), it is x itself.
(2) Key: the key of RENAME is either an identifier, or something that as a whole is exactly one quoted key (section 6). That is, for a quoted key, the ' that ends the quoted key (the ' not paired with \) must be the last character of the key (for example, 'a'b and 'a'b' are key errors). Anything else is a key error. The string a key represents is the identifier itself for an identifier, and the string the quoted key represents for a quoted key.

8. History and modifying commands
SET, DELETE, INSERT, MERGE, SORT and RENAME are called "modifying commands". When a modifying command finishes without an error, the document just before executing that command is appended to the end of the history, even if the number of changes is 0. The same applies when a document block is read without an error (section 5). A command that ends in an error, and a document block with an error, change neither the document nor the history.
Whenever a value is placed in the document or in the history, an independent copy is always placed. That is, modifying the value in one place later does not change values in other places made from the same JSON value, nor values in the history.
A modifying command determines the places to modify (the "targets") on the document before the modification, and merges targets with the same location into one (removes duplicates). Then it processes the targets one at a time from later to earlier in document order (in reverse document order). Because they are processed in this order, processing one target never changes the location of a target that has not been processed yet. The "number of targets" that is output is the number after removing duplicates.

9. Interpreting commands
If the command name is none of LOAD, GET, COMPACT, PRETTY, TYPE, LENGTH, KEYS, FLATTEN, COUNT, SUM, MIN, MAX, AVG, FILTER, SET, DELETE, INSERT, MERGE, SORT, RENAME, UNDO (uppercase and lowercase are distinguished), output "ERROR unknown command '<command name>'".
The arguments of a command are extracted as follows.
- SET and MERGE: the part of the argument part before its first space is the path, and everything after that space is the JSON value. If there is no argument part, or the argument part contains no space, it is an argument error.
- INSERT: the part of the argument part before the first space is the path, the part between the first space and the second space is the index, and everything after the second space is the JSON value. If there is no argument part, or the argument part does not contain two or more spaces, it is an argument error.
- FILTER: split the argument part, from the beginning, at up to 3 spaces into up to 4 parts (the 4th part is everything after the 3rd space). The parts are, in order, the path, the field, the operator and the JSON value. It is an argument error when there are fewer than 3 parts, when the 3rd part is EXISTS and there are 4 parts, or when the 3rd part is not EXISTS and there are 3 parts.
- Any other command: the words obtained by splitting the argument part at spaces are the arguments, in order (if there is no argument part, there are 0 arguments).
A JSON value is read as in section 4. If there is an error, output "PARSE ERROR col <C>: <reason>". C is the character number (counting from 1) of the error position within the JSON value part (if it is the end, the number of characters in the JSON value part + 1). Even if the JSON value part has spaces at its beginning or end, they are skipped by the procedure of section 4.
For each command, check the errors in the order given in its description; for the first error found, output only one line and end the processing of that command. The errors and their outputs are as follows.
- Argument error: "ERROR bad arguments".
- Path error: "ERROR bad path".
- Field error: "ERROR bad field".
- Operator error: "ERROR bad operator".
- Index error: "ERROR bad index".
- Key error: "ERROR bad key".
- JSON value error: the "PARSE ERROR col <C>: <reason>" above.
- Other errors: as given in the description of each command.
When evaluating a path (computing matches), the document at that point is used.

10. The commands
Below, "shape" denotes the check of the number and arrangement of the arguments; if it does not match, it is an argument error.

LOAD
Process the document block that immediately follows as in section 5.

GET path
Shape: 1 argument. Error checks: shape, path. For each match, in match order, output one line "<location notation> = <compact form of the value>". If there are 0 matches, output one line "no match".

COMPACT [path] / PRETTY [path]
Shape: 0 or 1 arguments. Error checks: shape, path. If the path is omitted, it is $. For each match, in match order, output the compact form (COMPACT) or the pretty form (PRETTY; it may span multiple lines) of the value. If there are 0 matches, output "no match".

TYPE path
Shape: 1 argument. Error checks: shape, path. For each match, output "<location notation> <type name>". If there are 0 matches, output "no match".

LENGTH path
Shape: 1 argument. Error checks: shape, path, matches. Examine the matches in match order; if there is a match whose value is none of an object, an array and a string, output "ERROR no length at <location notation>" for the first such match. Otherwise, for each match, output "<location notation> <length>". The length is the number of elements for an object, the number of elements for an array, and the number of characters for a string. If there are 0 matches, output "no match".

KEYS path
Shape: 1 argument. Error checks: shape, path, matches. If there is a match whose value is not an object, output "ERROR not an object at <location notation>" for the first such match. Otherwise, for each match, output "<location notation> <key array>". The key array is the compact form of the array of strings consisting of the keys of that object in element order (example: ["id","name"]; [] if empty). If there are 0 matches, output "no match".

FLATTEN [path]
Shape: 0 or 1 arguments. Error checks: shape, path. If the path is omitted, it is $. For each match, in match order, output the "leaves" contained in the pre-order sequence of its value, one per line in pre-order sequence order, in the form "<location notation of the leaf> = <compact form of the leaf>". A leaf is a value that is neither an object nor an array, an empty object, or an empty array. If there are 0 matches, output "no match".

COUNT path
Shape: 1 argument. Error checks: shape, path. Output "COUNT <number of matches>" (duplicates are counted too).

SUM path / MIN path / MAX path / AVG path
Shape: 1 argument. Error checks: shape, path. Aggregate the values of the matches that are numbers (including duplicates, in match order). Values other than numbers are ignored.
- SUM: output "SUM <sum of the numbers>". If there are 0 numbers, the sum is 0.
- MIN, MAX: output "MIN <minimum>" or "MAX <maximum>" respectively. If there are 0 numbers, the output is "MIN null" or "MAX null".
- AVG: if there are 0 numbers, output "AVG null". Otherwise, let n be the number of numbers and S their sum, and let q be the integer obtained by rounding |S|*100/n to an integer (fractions of one half or more round up) (that is, the quotient (with the fraction discarded) of |S|*200+n divided by 2n). Output "AVG <average>". The average is the following concatenated in this order: - if S is negative and q is 1 or more, the quotient of q divided by 100, ".", and the remainder of q divided by 100 as 2 digits padded on the left with 0 (examples: S=13, n=5 gives 2.60; S=-1, n=8 gives -0.13; S=-1, n=300 gives 0.00).

FILTER path field operator [JSON value]
Error checks: shape (section 9), path, field, operator, JSON value (when the operator is not EXISTS), matches. The operator is one of the 7 kinds ==, !=, <, <=, >, >=, EXISTS; anything else is an operator error. If there is a match whose value is not an array, output "ERROR not an array at <location notation>" for the first such match.
Otherwise, in match order, examine each element x of each array in index order, and if the following condition holds for the value f of the field for x and the value r represented by the JSON value, output "<location notation of x> = <compact form of x>". If not even one line was output, output "no match".
- EXISTS: f is not "no value".
- ==: f is not "no value", and f and r are equal.
- !=: the condition for == does not hold (it holds when f is "no value").
- <, <=, >, >=: if f and r are both numbers, compare them by numeric magnitude; if both are strings, compare them by string order; the condition holds if the relation holds. Otherwise (including when f is "no value"), it does not hold.
Two values are "equal" when their type names are the same and one of the following applies: both are null; both are the same boolean; both are the same number; both are the same string; both are arrays with the same number of elements whose elements at the same index are all equal; both are objects with the same set of keys whose values for the same key are all equal (the element order does not matter).

SET path JSON value
Error checks: shape (section 9), path, JSON value.
If the path has 0 segments, replace the whole document with the value represented by the JSON value, and output "SET 1".
Otherwise, let L be the last segment and P the path consisting of the remaining segments, and for each parent v in the sequence of matches of evaluating P (called "parents"), collect targets as follows.
- If L is a key-selection segment (key k) that is not a descendant segment, and v is an object, the element of v with key k is a target. If v does not have an element with key k, the element about to be added to v is the target (the position of the key step of this target is the number of elements of v).
- Otherwise, each match of the result of applying L to the sequence consisting of v alone (section 6 (3)) is a target.
Process the targets as in section 8. For each target, set the value of that element to the value represented by the JSON value. For an existing element, only the value is replaced without changing its position; for an element that does not exist yet, it is appended at the end of the object as an element with key k. Finally, output "SET <number of targets>".

DELETE path
Shape: 1 argument. Error checks: shape, path, root. If the path has 0 segments, output "ERROR cannot delete root". Otherwise, the matches are the targets, and they are processed as in section 8. For each target, remove that element. For an element of an object, remove it from the element order; for an element of an array, decrease by 1 the indices of the elements after the removed element. Finally, output "DELETE <number of targets>".

INSERT path index JSON value
Error checks: shape (section 9), path, index, JSON value, matches. If the index is not an integer notation, it is an index error; let i be the value of the index. If there is a match whose value is not an array, output "ERROR not an array at <location notation>" for the first such match. Next, examine the matches in match order, and, with n being the number of elements, if there is a match for which -n-1 <= i <= n does not hold, output "ERROR index out of range at <location notation>" for the first such match.
Otherwise, the matches are the targets, and they are processed as in section 8. For the array of each target (with n elements), let j=i if i is 0 or more, and j=n+1+i if i is negative, and insert the value represented by the JSON value at index j. That is, increase by 1 the indices of the elements at index j or more, and make that value the element at index j (when j=n, this appends it at the end). Finally, output "INSERT <number of targets>".

MERGE path JSON value
Error checks: shape (section 9), path, JSON value, kind of the JSON value, matches. If the value represented by the JSON value is not an object, output "ERROR merge value is not an object". If there is a match whose value is not an object, output "ERROR not an object at <location notation>" for the first such match.
Otherwise, the matches are the targets, and they are processed as in section 8. Into the object T of each target, "merge" the object M represented by the JSON value. Merging M into T means doing the following for each element of M (key k, value x), in element order. If T has an element with key k and its value and x are both objects, merge x into the value of key k of T. Otherwise, set the value of the element of T with key k to x (if T has an element with key k, replace the value without changing its position; if not, append it at the end). Finally, output "MERGE <number of targets>".

SORT path [field] [DESC]
Shape: 1 to 3 arguments, and the arrangement of the second and later arguments is one of: none, "F", "DESC", "F DESC" (F is a word other than DESC and is treated as a field). Error checks: shape, path, field, matches. If the field is omitted, it is @. If there is a match whose value is not an array, output "ERROR not an array at <location notation>" for the first such match.
Otherwise, the matches are the targets, and they are processed as in section 8. Sort the elements of the array of each target, using the value of the field for element x as the "sort key". Without DESC, arrange them in ascending order of the sort key; with DESC, in descending order; elements with equal sort keys keep their original order (a stable sort). The order of sort keys is as follows. First compare by kind: null is the smallest, then numbers, then strings, then "others". Others are booleans, arrays, objects and "no value". Within the same kind, numbers are compared by numeric magnitude and strings by string order, and nulls are all equal to each other and others are all equal to each other. Finally, output "SORT <number of targets>".

RENAME path key
Shape: 2 arguments. Error checks: shape, path, key, matches, duplicate key. Let K be the string the key represents. If there is a match whose location's last step is not a key step (the root, or an element of an array), output "ERROR not a member at <location notation>" for the first such match.
Otherwise, the matches are the targets, and they are processed as in section 8. For each target, let k be the key of that element. If k and K differ and the object that has that element already has an element with key K, output "ERROR key exists at <location notation of that target>", restore the document to its state before this command was executed, and end the processing (the history does not change either). Otherwise, change the key of that element to K without changing the element's position (if k and K are the same, nothing changes). After all targets have been processed, output "RENAME <number of targets>".

UNDO
Shape: 0 arguments. Error checks: shape, history. If the history is empty, output "ERROR nothing to undo". Otherwise, remove the last state of the history from the history and make it the document, and output "UNDO <number of states remaining in the history>".

[Constraints]
- The input has at most 3000 lines.
- The 6-character sequence \u0000 does not appear anywhere in the input.
