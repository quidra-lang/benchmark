[Overview]
Write a program that implements game management and a thinking engine for Othello (Reversi) as a single program. Following commands read from standard input, it plays moves with automatic passes, replays and normalizes game records, sets, displays and symmetrically transforms positions, searches and plays moves automatically with an evaluation function, solves endgames exactly, plays random games and performs Monte Carlo evaluation, undoes and redoes moves, counts positions (perft), computes statistics, and so on, and writes the results to standard output.

[Input format]
The first line is the number of commands N. Each of the following N lines contains one command. Each line consists of the command name and zero or more arguments, separated by single spaces, with no whitespace at the beginning or end of the line. The input consists of these N+1 lines only.

[Processing]
Process the commands one at a time in input order, and write the output of each command immediately. Below, a string in double quotes is a string that appears verbatim in the input or output. In output descriptions, a part such as <v> is replaced by its value.

1. Board and coordinates
- The board has 8 rows and 8 columns. Columns are denoted "a" to "h" from left to right, rows are denoted "1" to "8" from top to bottom, and a square is denoted by the 2 characters of its column letter followed by its row digit (e.g. "d3"). This is called a square name. Column letters are lowercase only.
- Each square is either empty, a black disc (B), or a white disc (W). When one of black and white is called color X, the other one is called the opponent's color.
- Let c be the column position (a is 1, b is 2, ..., h is 8) and r the row digit; the number of the square is 8*(r - 1) + (c - 1). a1 is 0, b1 is 1, ..., h1 is 7, a2 is 8, ..., h8 is 63. "Square order" means ascending order of this number.
- The board string is the 64-character string that lists the 64 squares in square order, with a black disc written as "B", a white disc as "W", and an empty square as ".".
- The 8 orientations seen from each square (up, down, left, right, up-left, up-right, down-left, down-right) are called directions.
- A position is the pair of a board and the side to move (the color that plays next).

2. Move rules
- Consider placing a disc of color X on an empty square p. For each direction, trace in that direction starting from the square next to p; if one or more discs of the opponent's color continue and the square right after them holds a disc of X, then all of those continuing opponent discs are "flipped discs". If the continuing opponent discs are followed by the outside of the board or by an empty square, there are no flipped discs in that direction.
- When placing on the empty square p gives one or more flipped discs, p is a legal move for X. A square that holds a disc is not a legal move.
- When X plays p, a disc of X is placed on p, and all flipped discs are changed to discs of X.
- The number of legal moves of a color is called the mobility of that color.
- A position in which neither black nor white has a legal move is called a terminal position (regardless of the side to move).

3. State
The program has the following state.
- The board
- The side to move ("B" or "W")
- Whether the game is over
- The history (the list of moves played) and the redo list (the list of undone moves). For one move, record the color that played, the square played, the number of discs flipped, whether a pass occurred after that move, the state before the move (board, side to move, whether the game is over), and the state after the move (the same 3 items).
In the initial state, the board is the standard initial setup (d4 and e5 are white discs, d5 and e4 are black discs, the others are empty), the side to move is black, the game is not over, and the history and the redo list are empty. The program starts in the initial state.
If the game is not over when the processing of a command has finished, the side to move always has a legal move (because of the turn adjustment in section 4).

4. Turn adjustment
Doing the following (1) to (3) is called turn adjustment.
  (1) If the side to move has a legal move, do nothing.
  (2) Otherwise, if the opponent has a legal move, output "<color of the side to move> passes" and change the side to move to the opponent. This is called a pass.
  (3) If neither has a legal move, the game is over; output the game-over line (section 6). The side to move is not changed.

5. Playing a move
When the side to move X plays a legal move p, do the following (1) to (3).
  (1) Remember the current state as the state before the move, and play p. Let k be the number of discs flipped.
  (2) Change the side to move to the opponent, then perform turn adjustment.
  (3) Append this move (color X, square p, number of discs flipped k, whether a pass occurred in (2), the state before the move, the state after the move) to the end of the history, and make the redo list empty.
For MOVE and PLAY, output "<X> <p> flips <k>" after (1), followed by the output of the turn adjustment in (2). For AI, output "<X> <p> flips <k> value <value>", followed by the output of (2). When a move is played by RECORD, AUTOPLAY or RANDOM, output nothing, including the output of the turn adjustment in (2).

6. Status line and game-over line
- The game-over line is "game over B <number of black discs> W <number of white discs> <result>". <result> is "winner B" if there are more black discs, "winner W" if there are more white discs, and "draw" if they are equal. Empty squares are counted for neither side.
- The status line is the game-over line if the game is over, and "<side to move> to move" otherwise.

7. Static evaluation
- The weight of each square is given by the following table. Each row is in order from column a to column h.
  Row 1: 100, -20, 10, 5, 5, 10, -20, 100
  Row 2: -20, -50, -2, -2, -2, -2, -50, -20
  Row 3: 10, -2, -1, -1, -1, -1, -2, 10
  Row 4: 5, -2, -1, -1, -1, -1, -2, 5
  Row 5: 5, -2, -1, -1, -1, -1, -2, 5
  Row 6: 10, -2, -1, -1, -1, -1, -2, 10
  Row 7: -20, -50, -2, -2, -2, -2, -50, -20
  Row 8: 100, -20, 10, 5, 5, 10, -20, 100
- The static evaluation value of a board from the point of view of color X is E = w + 10*(m1 - m2). w is the sum of the weights of the squares holding discs of X minus the sum of the weights of the squares holding opponent discs. m1 is the mobility of X, and m2 is the mobility of the opponent.

8. Search
For a position P whose side to move is X, the search value V(P, d) at depth d (an integer >= 0) is defined as follows. Y is the opponent's color, and the first of (1) to (4) that applies is used.
  (1) If P is a terminal position, 1000*(number of discs of X - number of discs of Y).
  (2) If d = 0, the static evaluation value of P's board from the point of view of X.
  (3) If X has a legal move, then for each legal move p, let Q be the position that is the pair of the board obtained when X plays p on P's board and side to move Y, compute -V(Q, d - 1), and take the maximum of these.
  (4) Otherwise, let Q be the position with P's board unchanged and side to move Y, and the value is -V(Q, d - 1). This corresponds to a pass by X; a pass also counts as one move and uses one level of depth.
- The evaluation value of a legal move p at depth d is the -V(Q, d - 1) of (3).
- The best move at depth d is the legal move with the largest evaluation value. If several share the largest value, take the first one in square order.
- The principal variation at depth d is the list built by the following procedure. Start with the position P and the remaining depth e = d, and repeat the following until e becomes 0 or P becomes a terminal position. If the side to move in P has no legal move, append "pass" to the list and replace P by the Q of (4). If it has a legal move, append the square name of the best move at depth e to the list and replace P by the Q of (3) for that move. In either case, then decrease e by 1.
- Any method of computation (such as alpha-beta pruning) may be used, as long as the values are the same as in the definition above.

9. Exact solve
For a position P whose side to move is X, the exact value F(P) is defined as follows. Y is the opponent's color, and the first rule that applies is used.
  (1) If P is a terminal position, number of discs of X - number of discs of Y.
  (2) If X has a legal move, then for each legal move p, compute -F(Q) with the same position Q as in section 8 (3), and take the maximum of these.
  (3) Otherwise, -F(Q) with the same position Q as in section 8 (4).
- The exact value of a legal move p is the -F(Q) of (2), and the exact best move is the legal move with the largest such value (if several, the first one in square order).
- The exact principal variation is the list built by starting from the position P and repeating the following until P becomes a terminal position. If the side to move in P has no legal move, append "pass" and replace P by the Q of (3); otherwise, append the square name of the exact best move and replace P by the Q for that move.

10. perft
For a position P whose side to move is X, perft(P, d) is defined as follows. The first rule that applies is used.
  (1) If d = 0, 1.
  (2) If P is a terminal position, 1.
  (3) If X has a legal move, the sum over each legal move p of perft(Q, d - 1) at the same position Q as in section 8 (3).
  (4) Otherwise, perft(Q, d - 1) at the same position Q as in section 8 (4).

11. Random numbers
- Random numbers are generated by the MINSTD method x <- (48271*x) mod 2147483647. The initial value of x is the seed given by the command. Each time a random number is drawn, x is updated, and the updated x is the value of the random number. Within one command, all random numbers are drawn in order from a single sequence.
- To choose a move at random, list the legal moves of the side to move in square order, draw one random number, let i be its value modulo the number of legal moves, and choose the i-th legal move counting from 0. Draw one random number even when there is only one legal move.
- A random game from a position means starting from the position P and repeating the following until P becomes a terminal position. If the side to move in P has no legal move, change the side to move to the opponent without using a random number. Otherwise, choose a move at random, play it, and change the side to move to the opponent.

12. Stable discs
Whether a disc is stable is decided by the following procedure. Initially no disc is stable. Repeat the operation of making stable every non-stable disc that satisfies the following condition, until no more discs become stable.
- Condition: for each of the 4 lines through the disc's square (horizontal, vertical, the diagonal from upper left to lower right, and the diagonal from upper right to lower left), (a) or (b) holds.
  (a) Every square on that line, from one edge of the board to the other, holds a disc.
  (b) In at least one of the 2 orientations along that line, the adjacent square is outside the board, or the adjacent square holds a stable disc of the same color as that disc.

13. Board transformations
There are the following 7 transformations. The disc on the square with column position c and row digit r (c and r are 1 to 8 as in section 1) is moved to the square at the position listed.
  "rot90": column position 9 - r, row digit c (rotate 90 degrees clockwise)
  "rot180": column position 9 - c, row digit 9 - r
  "rot270": column position r, row digit 9 - c (rotate 90 degrees counterclockwise)
  "mirror": column position 9 - c, row digit r (flip left-right)
  "flip": column position c, row digit 9 - r (flip upside down)
  "diag": column position r, row digit c (reflect across the diagonal joining a1 and h8)
  "anti": column position 9 - r, row digit 9 - c (reflect across the diagonal joining h1 and a8)
Moving a square by a transformation means finding the square to which a disc on that square would move.

14. Commands
The arguments, behavior and output of each command are as follows. The meaning of "not after game over" is given in section 15. A numeric argument is valid when it is a string consisting only of digits (0 to 9) and its value is within the range specified for that command.
A game record is a string of square names written without separators. A game record argument is well-formed when its length is even and between 2 and 120 inclusive, and every part obtained by splitting it into 2 characters at a time from the beginning is a square name.

NEW
Set the state to the initial state and output "OK".

LOAD <board> <side>
<board> is a board string and <side> is "B" or "W". The command is valid when there are exactly 2 arguments, <board> is 64 characters consisting only of "B", "W" and ".", and <side> is "B" or "W". If it is invalid, including when the number of arguments is wrong, output "ERROR bad board" and do not change the state. If it is valid, set the board as given by <board>, set the side to move to <side>, set the state to not game over, and make the history and the redo list empty. Output "OK", then perform turn adjustment.

DUMP
Output "board <board string> <side to move>".

SHOW
Output the board in 10 lines. Line 1 is "  a b c d e f g h" (2 spaces followed by a to h separated by single spaces). Lines 2 to 9 are the rows with row digit r = 1 to 8 respectively: r followed by, for each square from column a to column h, a single space and the character of that square. The character of a square is "B" for a black disc, "W" for a white disc, and for an empty square "*" if it is a legal move of the side to move and "." otherwise. If the game is over, "*" is not used. Line 10 is the status line.

SCORE
Output "score B <number of black discs> W <number of white discs> empty <number of empty squares>".

LEGAL
Let n be the number of legal moves of the side to move. Output one line consisting of "legal <n>" followed by each legal move in square order, written in the form " <square name>". If the game is over, n is 0.

FLIPS <p>
Not after game over. <p> is a square name. If p holds a disc, output "ILLEGAL occupied"; if p is not a legal move of the side to move, output "ILLEGAL no flips". Otherwise, let k be the number of discs flipped when the side to move plays p, and output one line consisting of "flips <p> <k>" followed by the square names of the flipped discs in square order, written in the form " <square name>". The state is not changed.

MOVE <p>
Not after game over. <p> is a square name. Check in the same order as FLIPS: if p holds a disc, output "ILLEGAL occupied"; if p is not a legal move, output "ILLEGAL no flips". Otherwise, the side to move plays p as described in section 5.

PLAY <t>
Not after game over. <t> is a game record. Process the moves of the game record in order k = 1, 2, ..., each as a move played by the current side to move. For the k-th square p, the reason is "game over" if the game is over, "occupied" if p holds a disc, and "no flips" if p is not a legal move; if a reason applies (the first applicable one in this order), output "ILLEGAL move <k> <p> <reason>" and finish processing PLAY. The moves played up to that point remain as they are. If no reason applies, play p in the same way as MOVE (the output is also the same as MOVE).

RECORD <t>
<t> is a game record. Starting from the position of the initial state, replay the moves of the game record in order k = 1, 2, ..., each as a move played by the side to move. For the k-th square p, check the same reasons as PLAY; if a reason applies, output "ILLEGAL move <k> <p> <reason>" and finish. In that case, the program state stays as it was before RECORD was executed (the redo list is not changed either). If no reason applies, play p as described in section 5 (with no output). If all moves have been replayed, set the program state to the state after the replay (the history is the list of replayed moves and the redo list is empty), and output the following 3 lines.
- "record <number of moves> moves <number of passes> passes". The number of passes is the number of times a pass occurred in the turn adjustments during the replay.
- "normal <normalized game record>". The first move of the game record is one of d3, c4, f5 and e6, which are black's legal moves in the initial setup. If the first move is f5, choose no transformation; if e6, choose "diag"; if d3, choose "anti"; if c4, choose "rot180". The normalized game record is the square names obtained by moving the square of each move of the game record by that transformation, written in the original order without separators.
- The status line.

UNDO <n>
n is an integer >= 1. If n is greater than the number of moves in the history, output "ERROR cannot undo". Otherwise, restore the state (board, side to move, whether the game is over) to the state before the move recorded for the n-th move from the end of the history, remove the last n moves from the history, and add them, keeping their original order, to the front of the redo list. Then output the status line.

REDO <n>
n is an integer >= 1. If n is greater than the number of moves in the redo list, output "ERROR cannot redo". Otherwise, remove the first n moves from the redo list, append them, keeping their original order, to the end of the history, and set the state to the state after the move recorded for the last of those n moves. Then output the status line.

HISTORY
Output "history <number of moves in the history>", then output each move of the history from oldest to newest, one per line, in the form "<i> <color> <square name> <number of discs flipped>" with i = 1, 2, .... If a pass occurred after that move, append " pass" to the end of the line.

SHEET
Output a game sheet in 9 lines. The reference board is the board before the first move of the history if the history is not empty, and the current board if it is empty. The display of each square is the decimal representation of i if a disc was placed on that square by the i-th move of the history, and otherwise the character of that square on the reference board ("B", "W" or "."). Line 1 is a single space followed by each of a to h written right-aligned in a field of width 3 (padded on the left with spaces). Lines 2 to 9 are the rows with row digit r = 1 to 8 respectively: r followed by the display of each square from column a to column h, written right-aligned in a field of width 3.

STATS
Output 3 lines about the history.
- Line 1: let n be the number of moves in the history and f the total number of discs flipped. If n = 0, output "moves 0"; otherwise output "moves <n> flips <f> avg <a> passes <q>". q is the number of moves after which a pass occurred.
- Lines 2 and 3: for black and then white, compute n and f in the same way over the moves of that color only. If n = 0, output "<color> moves 0"; otherwise output "<color> moves <n> flips <f> avg <a> max <m> <square name> corners <c>". m is the maximum number of discs flipped by a move of that color, <square name> is the square of the oldest move in the history among the moves that reached that maximum, and c is the number of moves of that color played on any of a1, h1, a8 and h8.
- <a> is the average f/n with the digits from the third decimal place onward truncated. Let s be the integer part of 100*f/n; write the integer part of s/100, ".", and the remainder of s divided by 100 as 2 digits (with a leading 0 if it has 1 digit), in this order. For example, if f = 68 and n = 30, it is "2.26".

TRANSFORM <op>
<op> is one of the names of the transformations in section 13. Move every disc on the board by the transformation. In addition, for every move in the history and in the redo list, replace the square played by the square obtained by moving it by the transformation, and replace the board before the move and the board after the move each by the board moved by the same transformation. The side to move, whether the game is over, the order of moves, the colors, the numbers of discs flipped, and the pass records are not changed. Output "OK".

EVAL
Output the static evaluation value E of the current board from the point of view of the side to move, the weight difference w, and the mobilities m1 and m2 (section 7) in the form "eval <E> weights <w> mobility <m1> <m2>". Compute them in the same way even if the game is over.

STABLE
Count the stable discs (section 12) of the current board and output "stable B <number of black stable discs> W <number of white stable discs>".

HINT <d>
Not after game over. d is between 1 and 4 inclusive. In the current position, compute the evaluation value at depth d of each legal move of the side to move, sort them in descending order of evaluation value, and in square order for equal evaluation values, and output one move per line in the form "<square name> <evaluation value>". The state is not changed.

PV <d>
Not after game over. d is between 1 and 4 inclusive. In the current position, let v be the evaluation value of the best move at depth d, and output one line consisting of "pv <v>" followed by each element of the principal variation at depth d, written in the form " <element>". The state is not changed.

AI <d>
Not after game over. d is between 1 and 4 inclusive. Play the best move at depth d in the current position, together with its evaluation value, as described in section 5.

ANALYZE <d>
d is between 1 and 4 inclusive. Examine each move of the history from oldest to newest with i = 1, 2, .... In the position consisting of the board before that move and the color of that move, compute the evaluation value at depth d of each legal move; let v be the evaluation value of the move played, q the square of the best move, and w its evaluation value, and output "<i> <color> <square name played> <v> best <q> <w>". Finally, sum w - v over the black moves and over the white moves separately, and output "loss B <black total> W <white total>". If the history is empty, output only the last line. The state is not changed.

SOLVE
Not after game over. If there are 9 or more empty squares, output "ERROR too many empties". Otherwise, in the current position, compute the exact value of each legal move of the side to move, sort them in descending order of value, and in square order for equal values, and output one move per line in the form "<square name> <value>". Next, output the elements of the exact principal variation separated by single spaces in the form "line <principal variation>", and finally, for the board obtained by playing from the current position according to the principal variation until the end, output "final B <number of black discs> W <number of white discs>". The state is not changed.

AUTOPLAY <d1> <d2>
Not after game over. d1 and d2 are each between 1 and 4 inclusive. Until the game is over, repeatedly play, as described in section 5, the best move at the depth of the side to move (d1 if the side to move is black, d2 if white). Let n be the number of moves played by this command and q the number of those moves after which a pass occurred, and output 3 lines: "autoplay <n> moves <q> passes", "moves <game record>" with the square names of the moves played written in order without separators, and the game-over line.

RANDOM <seed>
Not after game over. <seed> is between 1 and 2147483646 inclusive. Using <seed> as the seed, repeatedly choose a move at random and play it as described in section 5 until the game is over. The output is the same 3 lines as AUTOPLAY, with "random" written instead of "autoplay" on line 1.

MC <k> <seed>
Not after game over. k is between 1 and 100 inclusive, and <seed> is between 1 and 2147483646 inclusive. <seed> is the seed. Let X be the side to move and Y the opponent, and examine each legal move p of X in square order. For each p, let Q be the position that is the pair of the board obtained when X plays p and side to move Y, and play k random games from Q. In the terminal position of each game, it is a win if X has more discs than Y, a draw if they are equal, and a loss if X has fewer; output "<p> <number of wins> <number of draws> <number of losses>". After the output for all legal moves, with 2*number of wins + number of draws as the points, output "best <square name> <points>" for the legal move with the most points (if several, the first one in square order). The state is not changed.

PERFT <d>
d is between 1 and 8 inclusive. For the current position P, output "perft <d> <perft(P, d)>".

DIVIDE <d>
Not after game over. d is between 1 and 8 inclusive. For each legal move p of the side to move, output perft(Q, d - 1) at the same position Q as in section 8 (3), one per line in square order, in the form "<p> <value>", and finally output their sum in the form "total <sum>".

15. Errors
Each command is checked in the following order; output one line for the first check that applies, and go on to the next command without changing the state.
  (1) If the command name is none of those in section 14, "ERROR unknown command". Command names are case-sensitive.
  (2) If the number or the values of the arguments do not match the description in section 14, "ERROR bad arguments". The same applies when a command that takes no arguments has arguments. However, for LOAD, output "ERROR bad board" in this case as well. Also, for MOVE and FLIPS, when there is exactly 1 argument but it is not a square name, output "ERROR bad square", and for PLAY and RECORD, when there is exactly 1 argument but it is not a well-formed game record, output "ERROR bad record".
  (3) For a command marked "not after game over", if the game is over, "ERROR game over".
  (4) The errors and ILLEGAL outputs given in the description of each command in section 14. However, when PLAY becomes ILLEGAL partway through, the moves played up to that point and their output remain, as described for PLAY in section 14.
Commands not marked "not after game over" can be executed even when the game is over.

[Output format]
For each command, output the lines specified in [Processing] in that order. The output consists of ASCII characters only; no line has trailing whitespace, and every line ends with a newline. Do not output blank lines. All numbers except the STATS averages are written as decimal integers without extra leading zeros, with "-" for negative numbers.

[Constraints]
- 1 <= N <= 500
- Each line has between 1 and 200 characters inclusive and consists only of printable ASCII characters and spaces.
- An argument consisting only of digits has at most 9 characters, and when it has 2 or more characters, its first character is not "0".
- The value computed by PERFT and the total output by DIVIDE are at most 100000.
