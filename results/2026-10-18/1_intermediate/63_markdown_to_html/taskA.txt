[Overview]
Write a program that converts a document written in a subset of Markdown into HTML. The program reads the document from standard input, interprets blocks (headings, paragraphs, blockquotes, alerts, lists, code blocks, horizontal rules, tables, tables of contents) and inline elements (emphasis, code, links, images, autolinks, footnote references) exactly according to the rules defined below, and writes HTML of the prescribed form to standard output. The results may differ from those of common Markdown processors; follow only the rules in this document.

[Input format]
Each line of standard input is a line of the document. After the last line of the document there is a terminator line consisting only of the 7 characters @@END@@. The terminator line is not part of the document.
Each line of the document consists only of printable ASCII characters and spaces (0x20 to 0x7E). There are no tabs and no spaces at the end of a line. Therefore no line consists only of spaces, and an "empty line" is a line of length 0.

[Processing]
Section 1. Processing flow
(1) Treat the whole document as one "line sequence" and split it into a block sequence by the rules of section 3. For blockquotes, alerts and each list item, treat the content as a new line sequence and split it recursively into a block sequence by the same rules.
(2) After all splitting into blocks is finished (that is, after the link reference definitions and footnote definitions have been collected from the whole document), convert the blocks of the document to HTML in order from the first (section 5). A block that has content converts its content blocks in order from the first, at its own position. Strings are converted with the inline conversion of section 4.
(3) Heading IDs (5-2) and footnote numbers (5-10) are determined in the conversion order of (2). Within one string, processing goes from the beginning. In a table, the header row cells are converted from left to right, then each body row from top to bottom, with the cells of that row from left to right.
(4) The content of a table of contents (5-9) is built after all headings of the document have been converted. It includes headings that come after the table of contents.
(5) Finally, if there are any numbered footnotes, output the footnote list (5-11).

Section 2. Terms and common operations
- The "indentation" of a line is the number of consecutive half-width spaces at the start of the line. Below, "space" by itself means a half-width space.
- "Alphanumeric characters" are the 62 characters 0-9, A-Z, a-z. "Label characters" are the 64 characters consisting of the alphanumeric characters, - and _.
- "ASCII punctuation characters" are the following 32 characters (shown separated by spaces).
  ! " # $ % & ' ( ) * + , - . / : ; < = > ? @ [ \ ] ^ _ ` { | } ~
- "Whitespace" means a space or a newline. A string to be converted inline can contain newlines, for example when it is the lines of a paragraph joined together.
- "HTML escaping" replaces & with &amp;, < with &lt;, > with &gt; and " with &quot; in a string. All other characters (including ') stay as they are.
- "Label normalization" converts uppercase letters to lowercase, replaces each run of one or more consecutive whitespace characters with a single space, and removes leading and trailing spaces.
- An "escaped read" is an operation that extracts a string starting at some position of a string, with a given set of stop characters. Look at the characters in order starting with the character at that position. If it is a stop character, stop (without extracting it). If the character is \ and the next character is an ASCII punctuation character, extract that punctuation character alone and advance 2 characters (do not stop even if that punctuation character is a stop character). Otherwise, extract the character and advance 1 character. Also stop when the end of the string is reached. The extracted characters joined in order are the result of the read, and the position where it stopped is the end of the read.
- A "backtick run" is a part where ` characters are consecutive, taken up to where no further ` precedes or follows it. The "closer" of a backtick run (of length n) is the first backtick run after it whose length is exactly n (runs of other lengths are skipped). However, where 4-1 (b) and 4-3 say "the backtick run starting at" a position, it means the part extending rightward from that position as long as ` continues (it is counted from that position even if the preceding character is a `, for example right after a \` escape).
- In this document, HTML forms and examples are sometimes shown with 2 spaces added at the start of each line. These 2 spaces are not part of the output.

Section 3. Splitting into blocks
For the first line of the line sequence that does not yet belong to any block (the current line), examine (1) to (11) below in order, and with the first one that applies, either create a block or skip the line. Repeat this until no lines of the line sequence remain. (3) to (10) apply only to lines with indentation 0.

(1) Empty line
If the current line is an empty line, skip it.

(2) Indented code
A line with indentation 4 or more. Starting from the current line, take the lines as long as each is a line with indentation 4 or more or an empty line; those lines, excluding the empty lines at their end, belong to this block. Each line with its first 4 characters removed (an empty line stays empty) is a line of the code. There is no language name.

(3) Fenced code
A line starting with ` or ~ in which the run of that character at the start of the line (the fence) has length n of 3 or more. The part after the fence with leading and trailing spaces removed is the info string. However, if the fence character is ` and the info string contains `, this rule does not apply.
Starting from the next line, the lines up to just before a line consisting only of n or more of the fence character (the closing fence) are the lines of the code, as they are (without removing spaces or anything else). The closing fence also belongs to this block. If there is no closing fence, the lines up to the last line of the line sequence are the lines of the code. If the info string is not empty, its part up to just before its first space (the whole of it if it has no space) is the language name.

(4) ATX heading
A line that starts with 1 to 6 # characters, where that run of # is immediately followed by the end of the line or a space. The number of # characters is the level of the heading. Let T be the part after the run of #, with leading and trailing spaces removed. Let U be T with all consecutive # characters at its end removed; if U is empty or ends with a space, replace T with "U with leading and trailing spaces removed". T is the text of the heading.
Example: the text of "## Title ##" is Title, that of "## Title#" is Title#, and that of "### ###" is empty. "####### x" and "#x" are not headings.

(5) Horizontal rule
A line that, after removing all spaces, becomes 3 or more of a single kind of character among -, *, _ (examples: ***, ---, ___, * * *, - - -).

(6) Blockquote and alert
A line starting with >. Starting from the current line, the lines as long as they start with > belong to this block. Removing the leading > from each line, and also the next character if it is a space, and arranging the results in order gives the content lines.
If the first content line is exactly equal to one of [!NOTE], [!TIP], [!IMPORTANT], [!WARNING], [!CAUTION], the block is an alert. The word between ! and ] (NOTE etc.) is its type, and the content lines from the 2nd onward are the content line sequence. Otherwise it is a blockquote, and all content lines are the content line sequence. In both cases, the content line sequence is split into a block sequence.

(7) List
A "list item line" that is not a horizontal rule of (5). A list item line is one of the following.
- Bullet: a line that starts with one of -, *, + (the marker), immediately followed by a space.
- Ordered: a line that starts with a run of 1 to 9 digits, immediately followed by . or ) (the marker), which is immediately followed by a space. The value of the digit run read as a decimal number (leading zeros are ignored) is the number of the item.
Two list item lines are "of the same kind" when both are bullets with the same marker, or both are ordered with the same marker (for example, - and *, and 1. and 1), are different kinds).
A list consists of one or more items collected by the following steps.
 Step 1: The current line with the leading marker (for ordered items, the digit run and the marker) and all spaces following it removed is the first content line of the item.
 Step 2: From the next line onward, as long as the lines start with 2 or more spaces, add each such line with its first 2 characters removed to the content lines. An empty line does not qualify, so an empty line ends the item there.
 Step 3: If the line reached by skipping 0 or more empty lines after the last line of the item is a list item line that is not a horizontal rule and is of the same kind as the first item of the list, make that line the current line and go back to Step 1 to collect the next item. Otherwise the list ends (the skipped empty lines are not part of the list).
The content line sequence of each item is split into a block sequence. For the list, remember whether it is a bullet list or an ordered list, and its start number (the number of the first item; the numbers of the 2nd and later items are not used).

(8) Footnote definition
A line that starts with [^, immediately followed by one or more label characters, immediately followed by ]:, where the part after that with leading and trailing spaces removed (the body) is not empty. Record the body under the name obtained by converting this run of label characters to lowercase. If a body is already recorded under the same name, do nothing. This line creates no block and outputs nothing.

(9) Link reference definition
A line that starts with [ and satisfies all of the following 3 conditions.
- The first ] in the line is immediately followed by :, and the string between the leading [ and that ] (the label) does not contain [, contains a character other than a space, and does not start with ^.
- The result (the URL) of an escaped read with the space as the stop character, starting from the position reached by skipping spaces from just after that ]:, is not empty.
- The position reached by skipping spaces from the end of that read is the end of the line, or all of the following hold: at least one space was skipped; the character at that position is " or ' (the quote); and an escaped read starting at the next position with that quote as the stop character ends at the last character of the line (that is, the closing quote).
If a quote was read under the last condition, the result of that read is the title. Otherwise there is no title. Record the URL and the title under the name obtained by normalizing the label. If the same name is already recorded, do nothing. This line creates no block and outputs nothing.

(10) Table
A line that contains |, where a next line exists, that line is a delimiter row containing |, and the number of cells of the current line equals the number of cells of the delimiter row. The current line is the header row and the next line is the delimiter row; starting from the line after the delimiter row, the lines as long as they are not empty and contain | are the body rows. These lines belong to this block.
- How to split a line into cells: remove leading and trailing spaces from the line, and if it starts with |, remove that one character. Look at the rest from the beginning in order: a \ and the character after it (if there is a next character) form a pair that goes into the cell content as it is (except that the pair \| becomes the single character |), and a | that is not part of a pair is a cell separator. Each part separated by the separators, with leading and trailing spaces removed, is a cell (if there is no separator, the whole rest is one part; if the rest is empty, it becomes one empty cell). However, when the last character of the rest is a separator |, the empty part after it does not become a cell.
  Example: "| a | b |" gives 2 cells a and b, "a | b" also gives 2 cells a and b, and "| x \| y |" gives 1 cell x | y.
- A delimiter row is a row in which every cell has the form "zero or one :, one or more -, zero or one :" concatenated in this order. The alignment of each column is center if the delimiter row's cell in that column starts with : and ends with :, left if it only starts with :, right if it only ends with :, and unspecified otherwise.
- The number of columns of the table is the number of cells of the delimiter row. If a body row has fewer cells than the number of columns, the missing ones are filled with empty cells; if it has more, the extra cells are discarded.

(11) Paragraph and setext heading
A line that matches none of the above. Looking at the lines in order starting from the line after the current line, add lines to the paragraph lines until a line that matches one of the following is met.
 - The end of the line sequence, or an empty line.
 - A line with indentation 0 consisting only of 3 or more = characters, or only of 3 or more - characters (an underline).
 - A line with indentation 0 that matches one of: the fenced code of (3), the ATX heading of (4), the horizontal rule of (5), a line starting with > of (6), or a list item line that is not a horizontal rule of (7).
A line that matches both the underline and the third condition (such as ---) is treated as an underline. If an underline is met, the underline also belongs to this block, and the block becomes a setext heading. Its level is 1 if the underline is = and 2 if it is -. Otherwise the block is a paragraph.
The paragraph lines (including the current line), each with all leading spaces removed, joined with newlines, form the text of the paragraph or setext heading. However, if the text of the paragraph is exactly the 5 characters [TOC], the block is a table of contents instead of a paragraph.
For example, lines with indentation 1 to 3, and lines in the form of a table, a link reference definition or a footnote definition, become paragraph lines when they appear in the middle of a paragraph. Indented code also does not start in the middle of a paragraph.

Section 4. Inline conversion
This is the procedure for converting a string S (a heading, a paragraph, a table cell, a footnote body, a link text, etc.) to HTML. There is conversion "inside a link" and normal conversion. The link text of a link and the alternative text of an image are converted inside a link; everything else uses normal conversion. Conversion inside a link does not recognize links, autolinks, URL autolinks or footnote references (it does recognize images). Also, conversion of a footnote body does not recognize footnote references.
The conversion has two stages. First, 4-1 splits S into a sequence of pieces; then 4-7 matches emphasis and builds the HTML. There are two kinds of pieces: "text pieces", which represent a fixed HTML string, and "delimiter pieces", which are candidates for emphasis delimiters.

4-1 Splitting into pieces
Starting from the beginning of S, examine (a) to (g) below in order for the character at the current position; the first one that applies creates one piece and advances the position. Finish when the end of S is reached.
(a) If it is \: if the next character is an ASCII punctuation character, that character HTML-escaped is a text piece; advance 2 characters. If the next character is a newline, <br /> followed by a newline (a hard line break) is a text piece; advance 2 characters. Otherwise (including when \ is the last character of S), \ is a text piece; advance 1 character.
(b) If it is `: let n be the length of the backtick run starting here. If it has a closer, take the string between them, replace every newline in it with a space, and then, if it starts with a space, ends with a space and contains a character other than a space, remove one space from the start and one from the end. This, HTML-escaped and enclosed in <code> and </code>, is a text piece; advance to just after the closer (inside code, \ is also an ordinary character). If there is no closer, n ` characters form a text piece; advance n characters.
(c) If it is < and the conversion is not inside a link: if there is a > after the current position, the string B between them up to the first > contains neither whitespace nor <, and one of the following holds, it is an autolink.
 - B starts with http:// or https:// followed by at least 1 more character. In this case href is B.
 - B is an email address. That is, it contains exactly one @, the part before @ consists only of 1 or more characters that are alphanumeric characters, ., +, - or _, and the part after @, split at ., has 2 or more parts, each consisting only of 1 or more characters that are alphanumeric characters or -. In this case href is mailto: followed by B.
 If it is an autolink, <a href="href">B</a> (with href and B HTML-escaped) is a text piece; advance to just after that >. If not, examine (d) and onward (this ends up at (g)).
(d) If the conversion is not inside a link, http:// or https:// starts at the current position, and the current position is the start of S or the preceding character is whitespace, *, _, ~ or (: let U be the string from the current position up to just before the first whitespace or < (up to the end of S if there is neither). While the last character of U is one of the following (shown separated by spaces), remove that character from U.
  . , : ; ! ? * _ ~ )
 If the remaining U is not exactly http:// or https://, it is a URL autolink: <a href="U">U</a> (with U HTML-escaped) is a text piece; advance to just after U. If it is exactly one of them, examine (e) and onward.
(e) If it is [, or if it is ! and the next character is [: try a footnote reference, a link or an image by the rules of 4-2 to 4-5. If that succeeds, create its text piece and advance to the position given by the rule. If it does not succeed, the current character ([ or !) alone is a text piece; advance 1 character.
(f) If it is one of *, _, ~: create a piece by the rule of 4-6.
(g) Otherwise: the character HTML-escaped is a text piece; advance 1 character.

4-2 Footnote reference
If the current character is [, the conversion is neither inside a link nor of a footnote body, [^ starts at the current position, there is a ] after it, and the string between [^ and the first ] converted to lowercase is a recorded footnote name, it is a footnote reference. The string of 5-10 is a text piece; advance to just after that ]. If it is not a footnote reference, go to 4-3.

4-3 Brackets of links and images
If the current character is !, try an image; if it is [, try a link. However, in conversion inside a link, a link never succeeds (an image is still tried). For an image, the [ after the ! is the "opening bracket"; for a link, the current [ is.
Look at the characters rightward in order starting from the opening bracket, counting depth from 0, to find the matching closing bracket. On \, skip that character and the next one. On `, if the backtick run starting there has a closer, skip to just after the closer; otherwise skip to just after that run. On [, increase the depth by 1. On ], decrease the depth by 1; if it becomes 0, that is the closing bracket. If no closing bracket is found, it does not succeed.
Let T (the link text) be the string between the opening bracket and the closing bracket, and let p be the position just after the closing bracket.

4-4 Link destination
Examine (i) to (iii) below in order; the first one that applies determines the link destination (the URL and, if any, the title) and the position to advance to. If none applies, it does not succeed.
(i) Reference link: when the character at p is [, there is a ] after p, and the string L from the character after p up to just before the first ] does not contain [. If L normalized when L is not empty, or T normalized when L is empty, is the name of a recorded link reference definition, use its URL and title and advance to just after that ]. If it is not a recorded name, it does not succeed ((ii) and (iii) are not examined).
(ii) Inline link: when the character at p is ( and what follows matches the following form. Skip whitespace from the position after the (, then do an escaped read with whitespace and ) as the stop characters; its result is the URL (it may be empty). Skip whitespace from the end of the read. If at least 1 character was skipped and the character at that position is " or ' (the quote), the result of an escaped read from the next position with that quote as the stop character is the title. If this read stopped at the end of S, the form does not match. If it stopped at the quote, skip whitespace from just after that quote. Finally, if the character at that position is ), the form matches; advance to just after that ). If it is not ), the form does not match.
(iii) Shortcut reference link: if T normalized is the name of a recorded link reference definition, use its URL and title and advance to p.

4-5 Pieces for links and images
For a link, let C be T converted inside a link; the following is the text piece.
  <a href="URL" title="TITLE">C</a>
For an image, convert T inside a link, remove from the result every part that starts with < and ends at the next >, and call the result A; the following is the text piece. A is written as it is (without further escaping).
  <img src="URL" alt="A" title="TITLE" />
The URL and the title are written HTML-escaped. When there is no title, the part " title="TITLE"" (including the space before it) is not written. When the title is the empty string, write title="".

4-6 Delimiters
Let n be the length of the run of the same character (one of *, _, ~) starting at the current position, let b be the character just before it (treated as a space at the start of S), and let a be the character just after it (treated as a space at the end of S). The run "can open" if a is not whitespace, and "can close" if b is not whitespace. However, if the character is _ and a and b are both alphanumeric characters, it can neither open nor close.
If the character is * or _ and n is 3 or less, or the character is ~ and n is 2, create a delimiter piece holding the character, the length n, whether it can open, and whether it can close. Otherwise, the character repeated n times is a text piece. In both cases advance n characters.

4-7 Matching emphasis
Define the procedure that turns a range of the piece sequence into HTML as follows; the result of applying it to the whole piece sequence is the conversion result of S. Look at the pieces one at a time from the start of the range, and append the following to the output in order.
- For a delimiter piece D that can open: among the pieces after D within the range, find the first delimiter piece E that has the same character and the same length as D and can close. If E exists, append the HTML of the range of pieces between D and E (made by this procedure) enclosed in the opening tag and the closing tag, and continue with the piece after E. The tags are, for * and _, <em> and </em> for length 1, <strong> and </strong> for length 2, and <em><strong> and </strong></em> for length 3; for ~, they are <del> and </del>.
- When there is no E, and for a delimiter piece that cannot open, append its character repeated as many times as its length.
- For a text piece, append its string.
Example: *a **b** c* becomes <em>a <strong>b</strong> c</em>, *a *b* c* becomes <em>a *b</em> c*, and **a* becomes **a*.

Section 5. Conversion to HTML
5-1 Block sequence
The HTML of a block sequence is the HTML of each converted block, each followed by a newline, concatenated in order. The HTML of each block shown below is written without its final newline (the final newline is added here). Output the HTML of the block sequence of the whole document.

5-2 Heading
A heading of level N with text T has the following form.
  <hN id="ID">H</hN>
ID and H are determined as follows.
- Explicit ID: when the last character of T is }, the 3 characters " {#" (a space, {, #) appear in T, and the part between the last occurrence of them and the last } consists only of 1 or more label characters, that part is the ID. In this case, replace T with the part before that " {#" with trailing spaces removed.
- Otherwise, let Q be the result of taking the characters of T in order, converting uppercase letters to lowercase, keeping lowercase letters, digits, - and _ as they are, replacing spaces and newlines with -, removing all other characters, and concatenating. If Q is empty, Q becomes heading. If Q is not yet used, Q is the ID. If it is used, try Q followed by - and the decimal representation of k, for k = 1, 2, 3, ... in order; the first one not yet used is the ID.
- In both cases, the chosen ID becomes used at this point (an explicit ID also becomes used).
- H is the inline conversion of T after the replacement.
Example: if "## Hello World" appears twice, the IDs are hello-world and hello-world-1. For "## A & B {#ab}", the ID is ab and H is A &amp; B.

5-3 Paragraph
  <p>H</p>
H is the inline conversion of the text of the paragraph.

5-4 Horizontal rule
  <hr />

5-5 Code block
<pre><code class="language-L"> followed by each line of the code HTML-escaped and followed by a newline, concatenated in order, and finally </code></pre>. L is the language name HTML-escaped. If there is no language name, it starts with <pre><code>. If there are no lines of code, it is <pre><code></code></pre> (with the class if there is a language name).
Example: with language name py and the 2 code lines a<b and c, it is the following 3 lines.
  <pre><code class="language-py">a&lt;b
  c
  </code></pre>

5-6 Blockquote and alert
The HTML of a blockquote is <blockquote> and a newline, followed by the HTML of the content block sequence (5-1), and finally </blockquote>.
The HTML of an alert is <div class="alert alert-K"> and a newline, <p class="alert-title">W</p> and a newline, followed by the HTML of the content block sequence, and finally </div>. K is the type converted to lowercase, and W is the type with only its first character uppercase and the rest lowercase (Note, Tip, Important, Warning, Caution).

5-7 List
The HTML of a bullet list is <ul> and a newline, followed by the HTML of each item, each followed by a newline, concatenated in order, and finally </ul>. An ordered list uses <ol> and </ol> instead of <ul> and </ul>. However, if the start number is not 1, write <ol start="M"> instead of <ol> (M is the decimal representation of the start number).
Lists are always written in tight form, and paragraphs inside items get no <p>. The HTML of each item is made by the following steps.
 Step 1: Start with <li>.
 Step 2: Look at the content blocks in order. For a paragraph, append the inline conversion of its text as it is. For a block other than a paragraph, append a newline if the HTML so far does not end with a newline, then append the HTML of the block and a newline.
 Step 3: Finally append </li>.
However, if the first content block is a paragraph whose text starts with one of "[ ] ", "[x] ", "[X] " (each 4 characters including the final space) followed by at least 1 more character, the item is a task item. For that paragraph, append the inline conversion of the text with its first 4 characters removed, preceded by <input type="checkbox" disabled="" /> and one space for [ ], or by <input type="checkbox" checked="" disabled="" /> and one space for [x] or [X].
Example: a list consisting of the item one and an item whose content is the paragraph two and a second list (with the item sub) is as follows.
  <ul>
  <li>one</li>
  <li>two
  <ul>
  <li>sub</li>
  </ul>
  </li>
  </ul>

5-8 Table
The HTML of a table has the following form. Header row cells are written with th and body row cells with td, and the content of a cell is the inline conversion of the cell's text. If a column's alignment is not unspecified, the opening tag of the cells in that column is written as <th style="text-align:X"> or <td style="text-align:X"> (X is one of left, center, right). For the body rows, the part from <tr> to </tr> is repeated for each row. If there are no body rows, the lines from <tbody> to </tbody> are not written.
  <table>
  <thead>
  <tr>
  <th>header cell</th>
  <th style="text-align:right">header cell</th>
  </tr>
  </thead>
  <tbody>
  <tr>
  <td>body cell</td>
  <td style="text-align:right">body cell</td>
  </tr>
  </tbody>
  </table>

5-9 Table of contents
The table of contents is built from all headings of the document (including those inside blockquotes, alerts and list items) arranged in document order. The "parent" of each heading is the nearest of the headings before it whose level is smaller than its own. If there is no such heading, it has no parent. Every "sequence of headings" below is arranged in document order.
If there are no headings at all, the HTML of the table of contents is <nav class="toc">, a newline and </nav> concatenated. Otherwise, it is <nav class="toc"> and a newline, the "TOC list" of the sequence of headings that have no parent, a newline, and </nav> concatenated.
The TOC list of a sequence of headings is <ul> and a newline, followed by, for each heading in the sequence, the following item followed by a newline, concatenated in order, and finally </ul>.
- If no heading has that heading as its parent, the item is <li><a href="#ID">X</a></li>.
- Otherwise, it is <li><a href="#ID">X</a> and a newline, the TOC list of the sequence of headings whose parent is that heading, a newline, and </li> concatenated.
ID is the ID of the heading, and X is the H (5-2) of the heading with every part that starts with < and ends at the next > removed. However many times a table of contents appears in the document, each one produces the same HTML.
Example: with headings A of level 1, B of level 2 and C of level 1 (IDs a, b, c), it is as follows.
  <nav class="toc">
  <ul>
  <li><a href="#a">A</a>
  <ul>
  <li><a href="#b">B</a></li>
  </ul>
  </li>
  <li><a href="#c">C</a></li>
  </ul>
  </nav>

5-10 Footnote reference
A footnote reference becomes the following string.
  <sup id="R"><a href="#fn-K">K</a></sup>
K is the number of the footnote. When a footnote with a given name is referenced for the first time, it is given as its number the count of footnotes numbered so far plus 1 (the first footnote is 1). If the reference is the m-th reference to that name, R is fnref-K when m is 1, and fnref-K-m when m is 2 or more.

5-11 Footnote list
If there are 1 or more numbered footnotes, output the following after the HTML of the document's block sequence: a line <section class="footnotes">, a line <ol>, a line for each footnote in increasing order of number, a line </ol>, and a line </section>.
The line of each footnote is <li id="fn-K">B G</li>. K is the number and B is the inline conversion of the footnote body. With m the number of times the footnote was referenced, G is, for j = 1, 2, ..., m in order, <a href="#fnref-K">&#8617;</a> if j is 1 and <a href="#fnref-K-j">&#8617;</a> if j is 2 or more, joined with single spaces.
Example: if footnote number 1 (body Hi.) was referenced twice, its line is as follows.
  <li id="fn-1">Hi. <a href="#fnref-1">&#8617;</a> <a href="#fnref-1-2">&#8617;</a></li>

[Output format]
- Output the HTML determined by [Processing] as it is. Every line ends with a newline.
- Add no spaces or empty lines other than those produced by the rules of [Processing] (such as empty lines inside a code block).
- If the document has no blocks and there are no numbered footnotes, output nothing.

[Constraints]
- The document has between 1 and 1000 lines, and each line is at most 200 characters long.
- The combined nesting depth of blockquotes, alerts and lists is at most 10.

[Example]
Input:

# Shopping *List*

Buy **milk** and [eggs][shop].

- [x] bread
- fruit
  1. apple
  2. pear

> Use `a<b` here[^1].

| Pen | 2 |

In this example, the table of contents is built from the heading that comes after it. The heading ID shopping-list is made from the text Shopping *List* by converting uppercase letters to lowercase, replacing the space with - and removing the * characters. [eggs][shop] is a reference link that uses the link reference definition shop at the end of the document. The final . of https://example.com/a. is not included in the URL autolink. The content of the fruit item is the paragraph fruit and an ordered list, so a newline is output after the paragraph before the list is written.
