[Overview]
Write a program that simulates the behavior of an iterative DNS resolver (full resolver). No actual network communication is performed. From standard input, the program first reads the data of the zones held by authoritative servers, and then reads a sequence of commands. The resolver starts from the root servers, follows delegations (referrals), and queries authoritative servers repeatedly to find the answer. It handles authoritative server responses (answer, CNAME, referral, NODATA, NXDOMAIN), wildcard synthesis, resolution of nameserver names that have no glue, following CNAME chains, and a cache with TTLs based on a logical clock (including caching of negative responses), and for each query it prints a trace of the steps taken and the final answer. There are also commands for MX resolution, reverse lookup, direct queries to a server, zone listing, taking servers down and bringing them back up, setting/displaying/clearing the cache, and displaying statistics.

[Input format]
The input consists of multiple lines and is divided into a first part, the "zone section", and a second part, the "command section". The zone section ends with a line consisting only of "END ZONES", and the command section starts on the next line. The command section ends with a line consisting only of "END", and this line is the last line of the input.
Each line is a string of 1 to 200 characters consisting only of printable ASCII characters (character codes 32 to 126). Each line consists of one or more "words" separated by single spaces; there is no whitespace at the beginning or end of a line, and there are never two or more consecutive spaces.
The input lines are numbered 1, 2, 3, ... in order from the first line (the END ZONES line and the END line are also counted). This number is called the "line number".

Each line of the zone section (except the END ZONES line) is one of the following three kinds.

  ROOT addr ...
  ZONE origin server
  owner ttl type data ...

A line whose first word is ROOT is called a "ROOT line", a line whose first word is ZONE is called a "ZONE line", and any other line is called a "record line". A ROOT line has one or more addr after ROOT, and a ZONE line has exactly two words after ZONE. A record line consists of four or more words, and the one or more words after type (the third word) are collectively called data. The first word of a record line is none of ROOT, ZONE and END.

Each line of the command section (except the END line) has one of the following 14 formats.

  RESOLVE name type
  MX name
  REVERSE addr
  QUERY server name type
  DUMP server name
  DOWN server
  UP server
  SET key value
  TIME sec
  CACHE
  CACHE name
  FLUSH
  FLUSH name
  STATS

The command name (the first word of each line) and the number of arguments always follow these formats exactly. Whether the argument words are valid is checked in [Processing]. Word comparisons are case-sensitive (the only exception is the comparison of names, which are compared in canonical form as described in [Processing] 2).

[Processing]
Process the input line by line starting from the first line, and output the lines described in [Output format].

1. Error reporting
For ROOT lines, ZONE lines, record lines, and each command of the command section, perform the checks listed in the respective description, in the listed order, and report only the first error that applies, as a single line "error line L: message". L is the line number of that line. A line with an error changes no state (the only exception is a ZONE line, which sets the current zone to none as described in 5(2)). An X in a message is the corresponding input word written exactly as given. Checks that appear repeatedly are as follows.
- Name check: if the word is not a valid name under the rules of 2, "bad name X".
- Address check: if the word is not a valid IPv4 address as defined in 3, "bad address X".
- Type check: if the word is none of A, NS, CNAME, SOA, PTR, MX, TXT and AAAA, "bad type X".
The ordering of these eight types in this order is called the "type order".

2. Names
- A "label" is a string of 1 to 63 characters consisting only of letters (A-Z, a-z), digits (0-9) and hyphens (-), whose first and last characters are not hyphens.
- A "name" is a sequence of labels. A name with zero labels is called the "root". The string obtained by converting the uppercase letters of each label to lowercase, joining the labels in order from the first with ".", and appending "." at the end is called the "canonical form" of the name (example: www.example.com.). The canonical form of the root is ".". All name comparisons (equality and ordering) are done on canonical forms, and in output names are always written in canonical form.
- How to read a word as a name: if the word is ".", it is the root. Otherwise, if the word ends with ".", remove that one character, and split the rest at ".". If every part produced by the split is a label, the name is those labels in order. If even one part is not a label (for example, an empty part), the word is not a valid name. However, only in places where it is stated that wildcards are allowed, the first part may be the single character "*". A name whose first label is "*" is called a "wildcard name" ("*" is also treated as a label below).
- A word that ends with "." is called an "absolute name", and any other word a "relative name". In ZONE lines and in the command section, both denote exactly the name read. In record lines, a relative name denotes the name read followed by the labels of the origin of the current zone (see 5) (if the origin is the root, it is the name read itself). Also, only in record lines, a word that is the single character "@" denotes the origin of the current zone and is a valid name. For example, when the origin is example.com., in a record line "www" denotes www.example.com.; "ns1.example.net" denotes ns1.example.net.example.com.; and "ns1.example.net." denotes ns1.example.net.
- The number of labels of a name N is called the "length" of N. A name obtained by removing zero or more labels from the beginning of N is called an "ancestor" of N (N itself and the root are also ancestors of N). The ancestors other than N itself are called "proper ancestors". When a name M is an ancestor of N, we say "N is at or below M", and when in addition N and M differ, we say "N is below M".
- "Name order": turn each of the two names into the sequence of its labels in reverse order, from the last label to the first, and compare these sequences lexicographically. Labels are compared lexicographically by ASCII code as their canonical-form strings. If one sequence is equal to a leading part of the other, the shorter one comes first. For example, ".", "com.", "example.com.", "a.example.com.", "b.example.com.", "net." are in this order.

3. Addresses and integers
- IPv4 address: a word is a valid IPv4 address if it consists of exactly four fields separated by ".", each field consists only of 1 to 3 digits, a field of two or more characters does not begin with 0, and the value of each field is at most 255. For example, "192.0.2.1" is valid, and "192.0.2", "192.0.2.256", "192.0.02.1", "192..2.1" are not. The value of the IPv4 address a.b.c.d is a*16777216 + b*65536 + c*256 + d, and addresses are compared by this value. In output, an IPv4 address is written in the form a.b.c.d without extra leading zeros.
- IPv6 address: a part consisting of 1 to 4 hexadecimal digits (0-9, a-f, A-F) is called a "group". If the word does not contain "::", it is valid if it is exactly eight groups separated by ":". If the word contains "::", let P be the part before the first occurrence of "::" and Q the part after it; the word is valid if P and Q are each either empty or one or more groups separated by ":", and the total number of groups in P and Q is at most 7 (therefore ":::" and words that contain "::" two or more times are not valid). In this case "::" denotes as many groups of value 0 as are needed to make the total number of groups 8. The sequence of the values (16 bits each) of the eight groups obtained this way is the address. Addresses are compared by comparing the group values in order from the first group.
- Canonical form of an IPv6 address: write the value of each group in lowercase hexadecimal without extra leading zeros (the value 0 is "0"), and join them with ":". However, if there are runs of two or more consecutive groups of value 0, replace the longest such run (if there are several longest runs, the earliest one), together with the ":" on both sides of it, by "::". For example, 2001:0DB8:0:0:0:0:0:1 is written "2001:db8::1", 0:0:0:0:0:0:0:0 is written "::", 2001:db8:0:1:0:0:0:0 is written "2001:db8:0:1::", 1:0:0:2:0:0:0:3 is written "1:0:0:2::3", and 1:0:2:3:4:5:6:7 is written "1:0:2:3:4:5:6:7". In output, IPv6 addresses are always written in canonical form.
- An "integer word" is a word of 1 to 9 characters consisting only of digits, which does not begin with 0 if it has two or more characters. Its value is the value read as a decimal number.

4. TTL words
The ttl of a record line denotes a number of seconds, written in form (a) or (b) below.
(a) An integer word. Its value is the number of seconds.
(b) One or more pairs of a "number" and a "unit", concatenated with nothing in between. A number is a string of 1 to 3 characters consisting only of digits, which does not begin with 0 if it has two or more characters; a unit is one of w, d, h, m, s (uppercase W, D, H, M, S have the same meaning), denoting 604800 seconds, 86400 seconds, 3600 seconds, 60 seconds and 1 second respectively. The units must appear in the order w, d, h, m, s, and the same unit cannot be used two or more times. The number of seconds is the sum, over all pairs, of the number multiplied by the seconds of the unit. For example, "1h30m" is 5400 seconds, and "30m1h", "1h1h", "1h30", "h", "1000s", "01h" are not valid.
If the word is in neither form, or the number of seconds is not between 1 and 604800 inclusive, it is the error "bad ttl X".

5. Processing of the zone section
The state of the zone section consists of the root hints (a list of IPv4 addresses), the list of zones, and the "current zone". Initially both the root hints and the list of zones are empty, and the current zone is none.
Each zone has an origin (a name), a server (an IPv4 address), the line number of its ZONE line, and a collection of records. Each record has an owner (a name), a TTL (a number of seconds), a type, and data. The data for each type is as follows.
  A: an IPv4 address
  AAAA: an IPv6 address
  NS, CNAME, PTR: a name (called the "target")
  MX: a preference (an integer) and a name (called the "exchange host")
  TXT: a string
  SOA: seven values: name mname, name rname, and integers serial, refresh, retry, expire, minimum
Two records whose owner, type and data are all equal are called "the same record" (TTLs are not compared).
The "data order" used when arranging records with the same owner and the same type is: for A and AAAA, ascending order of address; for NS, CNAME and PTR, the name order of the targets; for MX, ascending order of preference, and for equal preferences the name order of the exchange hosts; for TXT, lexicographic order comparing the strings by ASCII code. Also, the "record order" used when arranging records is: the name order of the owners; for equal owners, the type order; if that is also equal, the data order.

(1) ROOT addr ...
  For each addr in order from the front, perform the address check, and then, if that address is already in the root hints or is equal to an earlier addr on the same line, the error is "duplicate root X". If there is no error, append all addrs in the written order to the end of the root hints. A ROOT line does not change the current zone.
(2) ZONE origin server
  First set the current zone to none (it stays none even if this line has an error). Checks: name check of origin (wildcards are not allowed). Address check of server. A zone whose origin and server are equal to origin and server respectively already exists: "duplicate zone O at X" (O is the canonical form of origin, X is server).
  On success, append a zone with origin origin, server server and no records to the end of the list of zones, and make it the current zone.
(3) Record line owner ttl type data
  Let Z be the current zone and O its origin. The checks are performed in the following order.
  [1] There is no current zone: "no current zone".
  [2] Name check of owner (wildcards are allowed; relative names and "@" are as described in 2).
  [3] owner is not at or below O: "out of zone N" (N is the canonical form of owner).
  [4] Check of ttl (see 4).
  [5] Type check of type.
  [6] The number of words of data is not 1 for A, AAAA, NS, CNAME and PTR, not 2 for MX, or not 7 for SOA: "wrong field count" (for TXT the number does not matter).
  [7] Check of data (per type, as follows).
    A: address check.
    AAAA: not a valid IPv6 address: "bad address X".
    NS, CNAME, PTR: name check (wildcards are not allowed; relative names and "@" are as described in 2. The same applies to the names of MX and SOA below).
    MX: the first word is not an integer word, or its value exceeds 65535: "bad preference X". Name check of the second word.
    TXT: let T be the string obtained by joining the words of data with single spaces (the whole part of the line after the space that follows type); if any of the following is not satisfied: T has two or more characters, T begins and ends with a double quote ("), T contains no double quote at any other position: "bad text T". The data is T itself (including the double quotes at both ends).
    SOA: name check of the first and the second word, in order. For the third through the sixth word, in order, not an integer word: "bad number X". The seventh word is not an integer word or its value is not between 1 and 86400 inclusive: "bad minimum X".
  [8] type is NS and owner is a wildcard name: "ns at wildcard".
  [9] type is SOA and owner is not equal to O: "soa not at origin".
  [10] type is SOA and Z already has an SOA record: "duplicate soa".
  [11] Z already has the same record: "duplicate record".
  [12] type is CNAME and Z already has one or more records with an equal owner, or type is not CNAME and Z already has a CNAME record with an equal owner: "cname conflict N" (N is the canonical form of owner).
  On success, add to Z the record consisting of owner, the number of seconds of ttl, type and data.
(4) END ZONES
  Examine the list of zones in order from the front. For a zone that has no SOA record, output "error line L: zone O at S has no soa" (L is the line number of that zone's ZONE line, O is the origin, S is the server) and discard that zone; for a zone that has an SOA record, output "zone O at S records=K" (K is the number of records of that zone). Finally, output "loaded roots=R zones=Z records=K" (R is the number of addresses in the root hints, Z is the number of zones that were not discarded, K is the total number of their records).
  From here on, "zone" refers only to zones that were not discarded. A zone whose server is address A is called a "zone held by A", and an address that holds one or more zones is called a "known server".
  For a zone Z, the following terms are used. When the owner of some record of Z is at or below a name X, X is said to "exist" in Z (the origin of Z always exists, since there is an SOA record). A name D below the origin of Z such that Z has an NS record whose owner is D is called a "delegation point" of Z.

6. Authoritative server responses
The response when the server at address A is asked for a name N and a type T is determined by (1) to (6) below, using a name C called the "current cut" (C is determined in 8; for QUERY it is the root). There are seven kinds of responses: ANSWER, CNAME, REFERRAL, NODATA, NXDOMAIN, LAME, TIMEOUT.
(1) If A is down by DOWN (see 9(6)) or is not a known server, the response is TIMEOUT.
(2) The zones held by A whose origin is an ancestor of N are the candidates. If there is no candidate, or if the length of the origin of the candidate with the longest origin (it is unique) is less than the length of C, the response is LAME.
(3) From here on, let Z be the zone chosen in (2) and O its origin. Examine the ancestors of N that are below O in ascending order of length, and let D be the first one that is a delegation point of Z; the response is REFERRAL. This response has, in its "authority section", the NS records of Z whose owner is D (in data order), and, in its "additional section", for the targets of those NS records in order, the A records of Z whose owner is that target (in data order). The A records in the additional section are called "glue". If there is no such ancestor, go to (4).
(4) If Z has one or more records whose owner is N, take them as "the records of N" and go to (6).
(5) If N exists in Z (that is, if there is a record whose owner is below N), the response is NODATA. Otherwise, let E be the longest proper ancestor of N that exists in Z; if Z has records whose owner is the name W obtained by adding the label "*" to the front of E, take them as "the records of N" and go to (6). If not, the response is NXDOMAIN.
(6) If the records of N include records of type T, the response is ANSWER, with them in its "answer section". Otherwise, if T is not CNAME and the records of N include a CNAME record, the response is CNAME, with that CNAME record in its answer section. If neither, the response is NODATA. The records of the answer section are those records with their owner replaced by N (this matters in the wildcard case of (5)), arranged in data order.
NODATA and NXDOMAIN responses have the SOA record of Z in their authority section. The TTLs of the records in a response are the values written in the zone. LAME and TIMEOUT responses have no records.

7. Cache and settings
- The resolver has a clock (an integer). Its initial value is 0, and only TIME advances the clock. Below, t denotes the value of the clock.
- The cache has at most one "entry" per "key" (a pair of a name and a type). An entry has a kind (one of POS, NODATA, NXDOMAIN), a list of records if the kind is POS, and an expiry (an integer). The expiry minus t is called the "remaining TTL" of the entry. Initially the cache is empty.
- The resolver has the settings MINTTL, MAXTTL and NEGTTL. Their initial values are 1, 86400 and 3600 respectively.
- Storing as POS: when storing a list R of one or more records whose owners and types are all equal, let m be the minimum TTL in R; the "cache TTL" is the smaller of (the larger of m and MINTTL) and MAXTTL. Then make the entry for the key (owner of R, type of R) an entry of kind POS, with record list R (in data order) and expiry t + cache TTL (if an entry for that key already exists, it is replaced).
- Negative storing: when storing a NODATA or NXDOMAIN response for a name M and a type T, the cache TTL is the minimum of three values: the TTL of the SOA record in the authority section, its minimum, and NEGTTL; make the entry for the key (M, T) an entry whose kind is the kind of the response, with expiry t + cache TTL (if one already exists, it is replaced).
- An entry is removed when its expiry has become less than or equal to t during the processing of TIME. Entries never expire for any other reason (the clock does not advance during the processing of a single command).

8. Resolution
A "resolution" is the procedure that obtains the records of type T for a name N; it is performed with a "depth" d and a "list of pairs being resolved" S. A resolution performed directly by a command has depth 0 and S an empty list. The result of a resolution consists of a "status" and an "answer" (a list of records); the status is one of NOERROR, NODATA, NXDOMAIN and "SERVFAIL reason".
A resolution outputs "trace" lines. Each trace line output by a resolution of depth d is prefixed with 2*(d+1) spaces (in the descriptions below, this indentation is omitted and only the content of the line is written).
(1) Overall resolution
  Append the pair (N, T) to the end of S. Set the list L of CNAME records to empty, the "seen names" to the set consisting only of the name N, and the current name M to N, and repeat the following.
  [1] Perform the "lookup" of (2) for (M, T).
  [2] If the result of the lookup is a CNAME record, append it to the end of L. If its target M2 is contained in the seen names, set the status to "SERVFAIL cname loop" and end the repetition. Otherwise, if L now contains 9 records, set the status to "SERVFAIL cname chain too long" and end the repetition. If neither, add M2 to the seen names, set M to M2, and return to [1].
  [3] If the result of the lookup is ANSWER, the status is NOERROR, and the answer is L followed by the list of records of the result.
  [4] If the result of the lookup is NODATA or NXDOMAIN, the status is that same value, and the answer is L.
  [5] If the result of the lookup is "SERVFAIL reason", the status is that same value.
  When the status is SERVFAIL (including the cases of [2]), the answer is empty. Finally, remove the last pair of S.
(2) Lookup
  In the lookup for a name M and a type T, examine (a) to (d) below in order; if any of (a) to (c) applies, output the trace line "CACHE HIT M T -> R" and return the result (R is the string described below).
  (a) There is an entry for the key (M, T): if its kind is POS, the result is ANSWER with its list of records (the TTL of each record is the remaining TTL of that entry). R is "ANSWER". If its kind is NODATA or NXDOMAIN, the result and R are that kind.
  (b) There is an entry of kind NXDOMAIN whose name is one of the ancestors of M (regardless of its type): the result and R are NXDOMAIN.
  (c) T is not CNAME and there is an entry of kind POS for the key (M, CNAME): the result is that CNAME record (its TTL is the remaining TTL of that entry), and R is "CNAME target".
  (d) Among the ancestors X of M for which there is an entry of kind POS for the key (X, NS), let Z be the longest one. If Z exists, output the trace line "CACHE HIT M T -> REFERRAL Z", and set the current cut C to Z and the list of nameservers to the list of targets of the records of that entry. If Z does not exist, set C to the root, and use the root hints in (3).
  Then repeat the following.
  - Query servers by the procedure of (3). If no response was obtained, the result is "SERVFAIL no server for C" (C in canonical form).
  - If the response is REFERRAL, store the list of NS records of the authority section as POS, and store the glue of the additional section, grouped by owner, as POS (one store per owner). Then set C to the REFERRAL name D and the list of nameservers to the list of targets of the NS records of the authority section, and continue the repetition.
  - If the response is ANSWER, store the answer section as POS; the result is ANSWER with the list of records of the answer section (the TTL of each record is the cache TTL of that store).
  - If the response is CNAME, store the CNAME record of the answer section as POS; the result is that CNAME record (its TTL is the cache TTL of that store).
  - If the response is NODATA or NXDOMAIN, perform negative storing of that response for M and T; the result is that kind.
  Each time a result is returned in (a) to (c), and each time the trace line is output in (d), increase the "cache hit count" by 1.
(3) Querying servers
  A query to an address A means asking the server at A for the name M and the type T, using the current cut C, by the procedure of 6. For each query, output the trace line "ASK A M T -> R". R is "REFERRAL D" if the response is REFERRAL (D is the REFERRAL name), "CNAME target" if it is CNAME, and otherwise the kind of the response. If the response is LAME or TIMEOUT, the query is a "failure", and processing proceeds to the next query destination. As soon as a response that is not a failure is returned, querying stops, and that response is the "obtained response". If the query destinations run out, no response was obtained.
  - When the root hints are used, query the addresses of the root hints in the order of the root hints.
  - When a list of nameservers is used, take the nameserver names one at a time in name order. For each name H, determine a set of addresses as follows at the time H is taken, and query them in ascending order of address.
    - If there is an entry of kind POS for the key (H, A), the addresses of its records.
    - Otherwise, if the pair (H, A) is contained in S, output the trace line "GLUELESS H -> LOOP"; there are no addresses.
    - If neither, output the trace line "GLUELESS H", and perform a resolution of the name H with type A at depth d+1 with the same list S (its trace is output with the indentation of depth d+1). If its status is NOERROR, the addresses of the records of type A in its answer. Otherwise, there are no addresses.

9. Processing of the command section
The checks and processing of each command are as follows. See [Output format] for how the output is written.
(1) RESOLVE name type
  Checks: name check of name (wildcards are allowed). Type check of type.
  Output "resolve N T" (N is the canonical form of name, T is type), perform the resolution for N and T, and output its answer and status.
(2) REVERSE addr
  Check: if addr contains ":", it is checked as an IPv6 address, and otherwise as an IPv4 address; if it is not valid, "bad address X".
  Build the reverse name N as follows. For an IPv4 address a.b.c.d it is "d.c.b.a.in-addr.arpa." (each field is a decimal number without extra leading zeros). For an IPv6 address, write the value of each of the eight groups as 4 lowercase hexadecimal digits and concatenate them in order from the first, giving 32 hexadecimal digits; N is these digits arranged in reverse order, from the last character to the first, separated by ".", followed by ".ip6.arpa.".
  Output "reverse A N" (A is the address in its output form), perform the resolution for N and type PTR, and output its answer and status.
(3) MX name
  Check: name check of name (wildcards are allowed).
  Output "mx N" (N is the canonical form of name), perform the resolution for N and type MX, and output its answer and status. Then:
  - If the status is NOERROR, take the MX records of the answer one at a time in answer order; if the exchange host is the root, output "exchange P . -> null" (P is the preference), and otherwise perform "address resolution" for the exchange host.
  - If the status is NODATA, perform address resolution for the target host, which is the target of the last CNAME record if the answer contains a CNAME record, and N otherwise.
  - For any other status, do nothing.
  Address resolution of a host H performs the resolution of H with type A, and then the resolution of H with type AAAA, each at depth 0 with an empty list S (the trace of each is output). Then output "exchange P H -> V" for an exchange host, or "implicit H -> V" in the NODATA case. V is the following addresses separated by single spaces: if the status of the type A resolution is NOERROR, the addresses of the A records of its answer in answer order, followed, if the status of the type AAAA resolution is NOERROR, by the addresses of the AAAA records of its answer in answer order. If there are no addresses at all, V is "no address".
(4) QUERY server name type
  Checks: address check of server. Name check of name (wildcards are allowed). Type check of type.
  Ask the server server for name and type by the procedure of 6, with the root as the current cut (the cache is neither used nor changed). This counts as one query in the statistics. Output "query S N T -> R" (S is server, N is the canonical form of name, T is type, R is the same string as in 8(3)), and then output the records of the response: for ANSWER and CNAME, each record of the answer section prefixed by "answer "; for REFERRAL, each record of the authority section prefixed by "authority ", followed by each record of the additional section prefixed by "additional "; for NODATA and NXDOMAIN, the SOA record of the authority section prefixed by "authority "; each in the record format ([Output format]), one per line. The TTLs are the values written in the zone. For LAME and TIMEOUT there are no record lines.
(5) DUMP server name
  Checks: address check of server. Name check of name (wildcards are not allowed).
  If server is down by DOWN or is not a known server, output "dump S N -> TIMEOUT"; otherwise, if no zone held by server has an origin equal to name, output "dump S N -> REFUSED" (S is server, N is the canonical form of name). If there is such a zone, output "dump S N records=K" (K is the number of records of that zone), and then output all records of that zone in record order, one per line, each as two spaces followed by the record format (the TTLs are the values written in the zone). DUMP is not counted in the statistics.
(6) DOWN server, UP server
  Checks: address check of server. For DOWN, server is already down: "server X already down". For UP, server is not down: "server X not down".
  DOWN makes server down, and UP makes it no longer down. Addresses that are not known servers can also be made down. Initially no address is down.
(7) SET key value
  Checks: key is none of MINTTL, MAXTTL and NEGTTL: "bad setting X". value is not an integer word, or its value is not between 1 and 604800 inclusive: "bad value X". If changing the setting key to the value of value would make MINTTL greater than MAXTTL: "minttl above maxttl".
  On success, set the setting key to the value of value. Entries already in the cache do not change.
(8) TIME sec
  Check: sec is not an integer word, or its value is not between 1 and 1000000 inclusive: "bad time X".
  Add the value of sec to the clock, and remove all entries whose expiry is less than or equal to the clock value.
(9) CACHE, CACHE name
  Check: if name is present, name check of name (wildcards are not allowed).
  If name is absent, all entries, and if it is present, the entries whose name is at or below name, are the "selected entries", and they are output. The state does not change.
(10) FLUSH, FLUSH name
  Check: if name is present, name check of name (wildcards are not allowed).
  Remove from the cache all entries selected in the same way as in (9).
(11) STATS
  Output the statistics. The state does not change. The statistics consist of the following values, all of which are initially 0.
  - The number of queries per address and per response kind: for each query of 8(3) and each QUERY, increase the count for that address and that response kind by 1.
  - The cache hit count (see 8(2)).
  - The number of resolutions per status: each time a resolution finishes (of any depth, all of them), increase the count for its status (SERVFAIL regardless of the reason) by 1.

[Output format]
In the zone section, output only the error lines and the lines of the END ZONES processing (5(4)). In the command section, output the following lines for each command. For a command with an error, output only the "error line L: message" line described in 1.

Record format: "OWNER TTL TYPE DATA". OWNER is the owner, TTL is the TTL (the value specified in the description), TYPE is the type, and DATA is the data; DATA is the address for A and AAAA, the target for NS, CNAME and PTR, "preference exchange-host" for MX, the string for TXT, and "mname rname serial refresh retry expire minimum" for SOA.

- RESOLVE: output, in this order, the "resolve N T" line, the trace lines of the resolution, for each record of the answer a line consisting of "answer " followed by the record format (in answer order), and finally the line "status ST" (ST is the status; for SERVFAIL, "SERVFAIL reason").
- REVERSE: the "reverse A N" line, followed, as for RESOLVE, by the trace, the "answer " lines and the "status ST" line.
- MX: the "mx N" line, followed, as for RESOLVE, by the trace, the "answer " lines and the "status ST" line; then, as described in 9(3), in the order taken, the line "exchange P . -> null" for an MX record whose exchange host is the root, and, for any other exchange host and for the target host, the traces of the address resolution (type A, then type AAAA) and the line "exchange P H -> V" or "implicit H -> V".
- QUERY: the "query S N T -> R" line and the record lines of 9(4).
- DUMP: the lines of 9(5).
- DOWN: "down S"; UP: "up S" (S is server).
- SET: "set KEY=V" (KEY is key, V is the new value).
- TIME: "time now=T expired=E" (T is the clock value after the addition, E is the number of removed entries).
- CACHE: the first line is "cache entries=E" (E is the number of selected entries). Then output the selected entries sorted by the entry's name in name order, and for equal names by the entry's type in type order. For an entry of kind POS, output each record of its list of records, one per line, as two spaces followed by the record format (the TTL is the remaining TTL of the entry). For an entry of kind NODATA or NXDOMAIN, output one line "  NAME R TYPE KIND" (two leading spaces; NAME is the entry's name, R is the remaining TTL, TYPE is the entry's type, KIND is NODATA or NXDOMAIN).
- FLUSH: "flush removed=E" (E is the number of removed entries).
- STATS: the first line is "stats queries=Q hits=H" (Q is the total number of queries, H is the cache hit count). Then, for the addresses with one or more queries, in ascending order of address, output one line each in the form "  A sent=N answer=... cname=... referral=... nodata=... nxdomain=... lame=... timeout=..." (two leading spaces; A is the address, N is the total number of queries to that address, and the value after each "=" is the number of queries to that address whose response was of that kind). Finally, output "resolutions noerror=... nodata=... nxdomain=... servfail=..." (the value after each "=" is the number of resolutions with that status).

All numbers are written in decimal without extra leading zeros. All output consists of ASCII characters. Within a line, items are separated by a single space (except inside the contents of TXT strings and in the leading indentation); no line has trailing whitespace, and every line ends with a newline. No empty lines are output.

[Constraints]
- The number of input lines is between 2 and 2000 inclusive.
- The number of records added in the zone section is at most 1000, and the number of zones is at most 100.
- The clock value is always at most 10^9. IPv4 address values are less than 2^32 but can be 2^31 or more. All other values fit in 32-bit signed integers (IPv6 addresses can be handled as eight 16-bit values).
- The nesting depth of resolutions is at most 10, and a single command outputs at most 1000 lines.
