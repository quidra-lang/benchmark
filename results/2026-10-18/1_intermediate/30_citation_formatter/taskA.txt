[Overview]
Write a program that reads, from standard input, a bibliographic database written in a subset of the BibTeX format, and formats references according to commands. It handles string macros and concatenation, nested braces, removal of LaTeX accent commands, and parsing of personal names by the BibTeX rules. For four styles, APA, IEEE, CHICAGO (author-date) and MLA, it formats individual references, builds reference lists, and replaces citation commands in body text; in addition, it generates citation keys, checks entries for defects, searches, writes normalized BibTeX, and prints statistics. All output consists of ASCII characters.

[Input format]
The input consists of a "database part", a "separator line" and a "command part".

The database part starts at the first line of the input and ends just before the first line that consists of exactly the two characters "%%" (the separator line). Each line of the database part is one of the following six kinds.
- Empty line: a line of 0 characters.
- Comment line: a line that starts with "%".
- Macro definition line: a line consisting of "@string{", a macro name, " = " (space, =, space), an expression and "}", in this order.
- Entry start line: a line consisting of "@", a type, "{", a key and ",", in this order.
- Field line: a line consisting of two spaces, a field name, " = " and an expression, in this order, or such a line with a single "," appended at its end.
- Entry end line: a line consisting of the single character "}".
A run of consecutive lines consisting of an entry start line, zero or more field lines and an entry end line, in this order, is called an "entry". Field lines appear only inside entries, and no other kind of line appears inside an entry.

The elements are as follows.
- A type and a field name are each a sequence of one or more lowercase letters. A type may be something other than the seven types in the table in [Processing] 1.4, but it is never "string".
- A key is a sequence of 1 to 20 characters consisting of letters, digits, "_", "-" and ":".
- A macro name is a sequence of at most 20 characters that starts with a lowercase letter and consists of lowercase letters and digits.
- An expression is one or more "terms" separated by " # " (space, #, space). A term is one of the following four kinds.
  Brace term: a sequence of two or more characters that starts with "{" and ends with "}".
  Quote term: a sequence of two or more characters that starts and ends with the double-quote character ("), and contains no double-quote character other than the first and the last character.
  Number term: a sequence of one or more digits.
  Macro term: a sequence that has the form of a macro name.
The character "#" appears only as part of a term separator. The braces in an expression are not necessarily balanced ([Processing] 1.1). In an expression whose braces are balanced, the first "{" and the last "}" of each brace term match each other (so the braces in the part between them are also balanced), and the braces inside each quote term are also balanced.

The line after the separator line contains an integer N, the number of commands. It is followed by N command lines, the last of which is the last line of the input. The format of a command line is described in [Processing] 5.

Every line of the input consists only of printable ASCII characters (character codes 32 to 126), and its last character is not a space. It is guaranteed that every line follows this format and [Constraints]. However, the contents of the database and of the commands are not necessarily correct (how to handle them is described in [Processing]).

[Processing]
First read the database part (1.), and then process the command lines one at a time in input order (5.).

1. Reading the database part
Process the lines of the database part in order from the top. Skip empty lines and comment lines. The "line number" used in error reports is counted with the first line of the input as 1 (empty lines and comment lines are counted too).

1.1 Evaluating an expression
Evaluating an expression yields one string. First, scan the expression from the beginning one character at a time, keeping a count that is increased by 1 at "{" and decreased by 1 at "}" (it starts at 0). If the count becomes negative at some point, or is not 0 at the end, the evaluation fails with the error "unbalanced braces".
Otherwise, split the expression into terms at " # ", replace each term, from left to right, with the following string, and concatenate them; the result is the result of the evaluation.
- Brace term and quote term: the contents, with the first and the last character removed.
- Number term: the digit sequence itself.
- Macro term: the string of the macro with that name (1.3).
However, if there is a macro term whose macro name is not defined at that point, the evaluation fails with the error "unknown macro 'MACRO'", where MACRO is that macro name. If there are several such terms, report the leftmost one.

1.2 Normalization
The value of a field is the string obtained by "normalizing" the result of evaluating its expression with the following steps.
(1) Removing accent commands. A string of one of the following forms is called an "accent command", and each one has a "result character".
  a. Three characters: "\", a symbol and a letter, in this order. The symbol is one of the seven characters ' " ` ^ ~ = . (apostrophe, double quote, backquote, caret, tilde, equals sign, period). The result character is the letter. Examples: \"u, \'e
  b. Five characters: "\", a command character, "{", a letter and "}", in this order. The command character is one of the seven symbols above or one of the letters "c", "u", "v" and "H". The result character is the letter. Examples: \"{u}, \c{c}
  c. The two characters "\&". The result character is "&".
Scan the string from the beginning, and at the current position do the first of the following that applies.
  - If the character at the current position is "{", an accent command starts at the next position, and the character immediately after that accent command is "}": replace everything from that "{" to that "}" with the single result character, and move to the position after the "}". Examples: {\"u}, {\'{E}}
  - If an accent command starts at the current position: replace that accent command with the single result character, and move to the position after the accent command.
  - Otherwise: keep that character as it is, and move to the next position.
(2) Replace every "~" in the result of (1) with a space.
(3) Replace each run of consecutive spaces with a single space, and remove leading and trailing spaces.
Examples: "M{\"u}ller" becomes "Muller", "Fran\c{c}ois~Lef\`evre" becomes "Francois Lefevre", and "Jan van~der  Berg" becomes "Jan van der Berg". Braces other than those that enclosed an accent command remain in the normalized value as they are.

1.3 Macro definition lines
A macro is a pair of a macro name and a string. Initially, the following 12 "month macros" are defined.
jan: January, feb: February, mar: March, apr: April, may: May, jun: June, jul: July, aug: August, sep: September, oct: October, nov: November, dec: December
A macro definition line is checked in the following order; if there is an error, report only the first one found, and define nothing.
(1) An error in evaluating the expression (1.1).
(2) A macro with that macro name is already defined (including the month macros): "duplicate macro".
If there is no error, define the macro with that macro name as the result of evaluating the expression (the string before normalization). A defined macro can be used in the expressions of later lines.

1.4 Entries
There are the following seven entry types, and each one has its required fields.
  article: author, title, journal, year
  book: author, title, publisher, year
  inproceedings: author, title, booktitle, year
  incollection: author, title, booktitle, publisher, year
  techreport: author, title, institution, year
  phdthesis: author, title, school, year
  misc: author, title, year
An entry is checked in the following order; if there is an error, report only the first one found, and do not register the entry. Even after an error is found, the lines up to the entry end line are skipped as part of that entry.
(1) The type is none of the seven types above: "unknown type 'TYPE'", where TYPE is the type. The line number is that of the entry start line.
(2) The key is the same as the key of an already registered entry (case-sensitive): "duplicate key". The line number is that of the entry start line.
(3) Process the field lines from top to bottom as follows. The line number is that of the field line.
  - If evaluating the expression (not including the trailing ",") fails, report that error.
  - Otherwise, if the field name is the same as that of an earlier field line of the same entry: "duplicate field 'FIELD'", where FIELD is the field name.
  - Otherwise, record the normalized result of the evaluation as the value of that field.
(4) A required field is missing: "missing field 'FIELD'". Report the first missing one in the order of the table above. However, for book, author is not regarded as missing if author is absent but editor is present. The line number is that of the entry end line.
If there is no error, register the entry. A registered entry has its key, its type and all of its recorded fields (including fields that are not required and fields other than the known fields below).
Known fields (this sequence is called "the known-field order"): author, editor, title, journal, booktitle, edition, volume, number, pages, publisher, institution, school, address, howpublished, month, year, doi, note
Fields other than the known fields are called "unknown fields".

An error of a macro definition line or of an entry is reported as one line of the following form, where LINE is the line number, NAME is the macro name for a macro definition line and the key for an entry, and REASON is the error text given above.
ERROR line LINE: NAME: REASON

1.5 Result of reading
After the whole database part has been processed, output the following line.
LOADED entries=E macros=M errors=R
E is the number of registered entries, M is the number of macros successfully defined by macro definition lines (the month macros are not included), and R is the number of errors reported in 1.
Hereafter, the collection of registered entries is called "the database", and the order in which the entry start lines appear in the input is called "registration order". The database never changes after reading.

2. Personal names
The values of author and editor are parsed as a sequence of personal names (a name list). Hereafter, the "depth" of a position in a string is the number of "{" before that position minus the number of "}" before that position.
(1) Split the value at " and " (space, and, space) at depth 0, finding the occurrences from left to right without overlap, and treat each resulting part as the name of one person. However, a part that is "others" is not a name; it indicates that the name list has an "et al. mark". Hereafter, the "names" of a name list do not include others.
(2) Split each name at "," at depth 0, and remove leading and trailing spaces from each resulting part. The number of parts is 1, 2 or 3.
(3) Divide each name into four parts: First (given name), von (particle), Last (family name) and Jr (generation). Some parts may be empty. Here a "word" is each part obtained by splitting at spaces at depth 0, and a word whose first character is a lowercase letter is called a "lowercase word".
  - One part (the "First von Last" form): let the words be w1, w2, ..., wn. If there is no lowercase word among w1 to w(n-1), First is w1 to w(n-1), Last is wn, and von is empty. If there are lowercase words among them, let wi be the first and wj the last of those lowercase words; then First is w1 to w(i-1), von is wi to wj, and Last is w(j+1) to wn. Jr is empty.
  - Two parts (the "von Last, First" form): let the words of the first part be w1, w2, ..., wn. If there is no lowercase word among w1 to w(n-1), von is empty and Last is w1 to wn. If there are lowercase words among them, let wj be the last of those lowercase words; then von is w1 to wj, and Last is w(j+1) to wn. First is the second part, and Jr is empty.
  - Three parts (the "von Last, Jr, First" form): von and Last are determined from the first part in the same way as for two parts. Jr is the second part, and First is the third part.
  A part made of several words is those words joined with single spaces.
  Examples: "Jan van der Berg" has First "Jan", von "van der" and Last "Berg". "de la Cruz, juan" has von "de la", Last "Cruz" and First "juan". "Smith, Jr., John" has Last "Smith", Jr "Jr." and First "John". "{Barnes and Noble}" has only Last, which is "{Barnes and Noble}", and the other parts are empty.
(4) The string obtained by removing every "{" and "}" from a string is called the "plain form" of that string. The notations of a name are defined as follows.
  - Surname: the plain form of the following: Last if von is empty; otherwise von, a space and Last joined together. Example: van der Berg
  - Initials: split the plain form of First into words at spaces, and split each word further at "-" into pieces; for each piece, take the first letter that appears in it, uppercased, followed by "."; join these with "-" within each word, and join the words, in order, with single spaces. Examples: "John R." gives "J. R.", "Jean-Pierre" gives "J.-P.", and "juan" gives "J.".
  - Inverted form: the surname, followed by ", " and the given name if First is not empty, and then followed by ", " and the plain form of Jr if Jr is not empty.
  - Direct form: the surname, preceded by the given name and a space if First is not empty, and then followed by ", " and the plain form of Jr if Jr is not empty.
  Here the "given name" is the initials in the "initials" notation, and the plain form of First in the "full" notation. Examples: for "Smith, Jr., John", the inverted form (initials) is "Smith, J., Jr.", the inverted form (full) is "Smith, John, Jr.", the direct form (initials) is "J. Smith, Jr.", and the direct form (full) is "John Smith, Jr.". "{Barnes and Noble}" is "Barnes and Noble" in every notation.
(5) The "primary list" of an entry is the name list of author if author is present, and otherwise the name list of editor (only a book that has editor can lack author). The first name of the primary list is called the "lead name".
Two name lists are "equal" when they have the same number of names, the First, von, Last and Jr of the names at the same position are each equal as strings (as they are, before taking the plain form), and either both or neither of them has the et al. mark.

3. String rules
3.1 Comparison
Strings are compared in lexicographic order of ASCII codes (when one is a prefix of the other, the shorter one is smaller). "Ascending" means from smallest to largest in this order. To "lowercase" a string means to change every uppercase letter to the corresponding lowercase letter, and to "uppercase" means the reverse. Neither changes characters other than letters.

3.2 Title capitalization
The case of the letters of the title value (the title) is converted according to the style as follows. Characters at depth 1 or more (characters inside braces) are not changed by any conversion.
- Sentence case (used in APA): among the letters at depth 0, uppercase those that are the first character of the title or the character immediately after ": " (colon and space), and lowercase all the others. Only a letter located exactly at such a position is uppercased: if, for example, the title starts with "{" or "(", no letter at its start is uppercased, so "(re)reading" stays "(re)reading".
- Title case (used in CHICAGO and MLA): split the title into words at spaces at depth 0, convert each word by the first of the following rules that applies, and join the words with single spaces.
  a. A word that starts with "{" is not changed.
  b. If the letters of the word, extracted and lowercased, form one of the "small words" below, the word is neither the first nor the last word, and the preceding word does not end with ":": lowercase all letters of the word at depth 0.
  c. Otherwise: if the first letter that appears in the word is at depth 0, uppercase it. The other characters are not changed.
  Small words: a, an, and, as, at, but, by, for, from, in, into, nor, of, on, or, over, per, so, the, to, up, via, with, yet
- Original case (used in IEEE): nothing is changed.
Example: "Deep {L}earning for the {NLP} community: a survey?" becomes "Deep {L}earning for the {NLP} community: A survey?" in sentence case and "Deep {L}earning for the {NLP} Community: A Survey?" in title case.

3.3 Values used for sorting
- The "sort title" of an entry is the plain form of the title value, lowercased, with the leading part removed once if it starts with "a ", "an " or "the ".
- "Bibliography order" is the ascending order that compares entries by (1) the plain form of the Last of the lead name, lowercased, (2) the plain form of the year value, (3) the sort title, and (4) the key. If (1) is equal, compare by (2); if (2) is also equal, compare by (3); and so on.

3.4 Year suffixes and year labels
Collect all entries whose primary lists are equal and whose year values are also equal (as they are, before taking the plain form) into one group. For each group of two or more entries, sort the entries of the group in ascending order of (sort title, key), and assign "a", "b", "c", ... in that order as the "year suffix" of those entries. The year suffix of every other entry is empty.
The "year label" of an entry is, in APA and CHICAGO, the plain form of the year value followed by the year suffix, and in IEEE and MLA, the plain form of the year value.

4. Formatting a single reference
The reference of an entry is a one-line string built by filling values into the template determined by the style and the type (4.5).

4.1 Values
The value of a template placeholder is the plain form of the value of the entry's field with the same name (the value of a field that the entry does not have is empty). However, the following are as defined below.
- author: the primary list arranged by the rules of 4.2. When the primary list is the name list of editor, it is followed by the following style-specific string (the first one when there is one name and no et al. mark, and the second one otherwise).
  APA: " (Ed.)", " (Eds.)"; IEEE: ", Ed.", ", Eds."; CHICAGO: ", ed.", ", eds."; MLA: ", editor", ", editors"
- editor: when editor is present, its name list arranged by the rules of 4.3.
- eds: when editor is present, "Ed." if its name list has one name and no et al. mark, and "Eds." otherwise.
- title: the plain form of the title converted by 3.2.
- year: the year label.
- pages: the plain form of the pages value with every "--" replaced by "-" (the occurrences are found from left to right without overlap, so "1---2" becomes "1--2").
- pp: when pages is present, the pages above preceded by "pp. " if it contains "-", and by "p. " if it does not.
- edition: if the plain form of the edition value consists only of digits, the ordinal of that number followed by " ed.". The ordinal is the number followed by "th" if its last two digits are 11, 12 or 13; otherwise it is the number followed by "st" if its last digit is 1, "nd" if 2, "rd" if 3, and "th" otherwise (examples: 1st, 2nd, 3rd, 4th, 11th, 12th, 13th, 21st, 22nd, 113th). If it does not consist only of digits, the plain form followed by " ed." (example: Revised ed.).
- mon: if the plain form of the month value is on the left side of the following table, the abbreviation on the right side; otherwise, the plain form itself.
  January: Jan., February: Feb., March: Mar., April: Apr., May: May, June: June, July: July, August: Aug., September: Sep., October: Oct., November: Nov., December: Dec.

4.2 Author list (the author value)
Let n be the number of names in the primary list. The following two ways of listing names are used.
- List A (conjunction c): if there is one name, that name; if there are two or more, the names before the last one joined with ", ", followed by ", ", c, a space and the last name. Examples: "A, B, c C", "A, c B"
- List B (conjunction c): if there are two names, "A c B" (one space on each side of c); otherwise, the same as list A.
The rules for each style are as follows.
- APA: put each name in inverted form (initials). If there is an et al. mark, join all the names with ", " and append ", et al.". Otherwise, if n is 20 or less, list them with list A (conjunction "&"). If n is 21 or more, join the first 19 names with ", " and append ", . . . " and the last name.
- IEEE: put each name in direct form (initials). If there is an et al. mark or n is 7 or more, the first name followed by " et al.". Otherwise, list them with list B (conjunction "and").
- CHICAGO: put the first name in inverted form (full) and the other names in direct form (full). If there is an et al. mark or n is 11 or more, join the first 7 names (all of them if there are fewer than 7) with ", " and append ", et al.". Otherwise, list them with list A (conjunction "and").
- MLA: put the first name in inverted form (full) and the second name in direct form (full). If there is an et al. mark or n is 3 or more, the first name followed by ", et al.". Otherwise, list them with list A (conjunction "and").
Example: "Smith, John R. and Lee, Kate and Park, Ann" becomes "Smith, J. R., Lee, K., & Park, A." in APA, "J. R. Smith, K. Lee, and A. Park" in IEEE, "Smith, John R., Kate Lee, and Ann Park" in CHICAGO, and "Smith, John R., et al." in MLA.

4.3 Editor list (the editor value)
Put each name in direct form (initials) in APA and IEEE, and in direct form (full) in CHICAGO and MLA. If there is an et al. mark, the first name followed by " et al.". Otherwise, list them with list B (conjunction "&") in APA, and with list B (conjunction "and") in the other styles.

4.4 Template syntax
A template is a sequence of elements of the following three kinds, and the output string is built from them from left to right.
- Placeholder "{name}": outputs the value of that name (4.1).
- Optional part "<" ... ">": contains a template inside and may be nested. If the value of at least one of the placeholders directly contained in the optional part (excluding those contained in optional parts inside it) is empty, the optional part as a whole outputs nothing. Otherwise, it outputs the template inside it.
- Any other character: outputs that character. However, the character "." is not output when the string output up to just before it ends with ".", "?" or "!".
The characters "{", "}", "<" and ">" in a template are symbols that denote elements, and are not output themselves.
Example: with the template "{author}. ({year})< {note}>.", author "Smith, J. R.", year "2020" and an empty note, the result is "Smith, J. R. (2020).".

4.6 IEEE numbers
The "citation record" is a sequence of keys, initially empty. It is updated by the CITE command (5.3).
The "IEEE order" is the keys of the citation record in their order, followed by the keys of the database entries that are not in the citation record, in ascending order. The "IEEE number" of an entry is the position of that entry (counting from 1) in the IEEE order at that time.
An IEEE reference is the result of the template preceded by "[", the IEEE number and "] ".

5. Commands
A command line is a sequence of words separated by single spaces; the first word is the command name and the remaining words are the arguments. However, when the command name is CITE or SEARCH, the line is split at its first two spaces into the command name, the first argument and the second argument (the whole rest of the line, which may contain spaces). If there are fewer than two spaces, split at the spaces that there are. Command names and styles are case-sensitive.
A command line is checked in the following order; if there is an error, output one line for the first one found, and finish processing that command line.
(1) The command name is none of FORMAT, BIBLIOGRAPHY, CITE, KEYGEN, CHECK, SEARCH, EXPORT and STATS below: ERROR unknown command 'COMMAND', where COMMAND is the command name
(2) The number of arguments differs from the number specified for the command: ERROR wrong number of arguments
(3) For FORMAT, BIBLIOGRAPHY and CITE, the first argument (the style) is none of APA, IEEE, CHICAGO and MLA: ERROR unknown style 'STYLE', where STYLE is the style

5.1 FORMAT style key1 key2 ... keyk (k+1 arguments, where k is 1 or more)
Process the keys in order. For each key, if the database has an entry with that key, output its reference (4.) as one line; otherwise output "ERROR unknown key 'KEY'", where KEY is the key. If the same key appears more than once, output for each occurrence.

5.2 BIBLIOGRAPHY style (1 argument)
Output a heading line ("References" for APA, IEEE and CHICAGO, "Works Cited" for MLA), and then output the references of all entries in the database, one per line. The order is the IEEE order for IEEE and bibliography order for the other styles.
In CHICAGO and MLA, when the primary list of an entry is equal to the primary list of the entry output immediately before it, replace the part of the author value that lists the names with "---" (the string appended in 4.1 to denote editors is still appended as it is). FORMAT does not do this replacement.

5.3 CITE style text (2 arguments)
Replace the "citation commands" in the text with "citation texts". A citation command is a part that starts with one of "\cite{", "\citep{", "\citet{", "\citeauthor{" and "\citeyear{" and ends at the first "}" after it. The part between "{" and "}" is a key list (one or more keys separated by ",", containing no spaces). \cite and \citep are called "parenthetical citations", and \citet is called a "narrative citation". When the same key appears more than once in the key list of a citation command, remove all occurrences but the first.
If any citation command in the text has a key that is not in the database, output "ERROR unknown key 'KEY'" (if there are several such keys, the leftmost one in the text) and do nothing else.
Otherwise, first go through the citation commands of the text from left to right, and through the keys of each key list in order, appending every key that is not in the citation record to the end of the citation record. The citation record is updated regardless of the style. Then output, as one line, the text with each citation command replaced by the citation text below. The parts other than citation commands are not changed.

The "short name" of an entry is defined as follows, using the surnames of the names of the primary list.
- If there is an et al. mark or there are m or more names (m is 4 in CHICAGO and 3 in the other styles): the surname of the first name followed by " et al.".
- Otherwise, if there are three names: the form "A, B, and C".
- If there are two names: the form "A and B". However, in APA parenthetical citations, the form "A & B".
- If there is one name: that surname.
Here A, B and C denote the surnames of the first, second and third names.
The citation texts are as follows.
- \citeauthor: the short names of the entries joined with "; " in key-list order.
- \citeyear: the year labels of the entries joined with ", " in key-list order.
- Parenthetical citations
  APA and CHICAGO: sort the entries in bibliography order, and combine each run of consecutive entries with equal short names into one "group". Each group becomes, in APA, the short name, ", " and the year labels of the group's entries in order joined with ", "; in CHICAGO, the short name, a space and the year labels in order joined with ", ". The groups joined in order with "; " and enclosed in "(" and ")" form the citation text.
  IEEE: sort the IEEE numbers of the entries (after updating the citation record) in ascending order, and divide them into maximal runs of consecutive integers. A run of three or more numbers is written as "[first number]-[last number]", and any other run as "[number]" for each of its numbers; all of these joined in order with ", " form the citation text. Example: the numbers 1, 2, 3, 5, 7, 8 give "[1]-[3], [5], [7], [8]".
  MLA: the short names of the entries joined with "; " in key-list order, enclosed in "(" and ")".
- Narrative citations
  APA and CHICAGO: arrange the entries in key-list order, and combine each run of consecutive entries with equal short names into a group. Each group becomes the short name, " (", the year labels of the group's entries in order joined with ", ", and ")"; the groups joined in order with "; " form the citation text.
  IEEE: each entry written as the short name, " [", its IEEE number and "]", joined with "; " in key-list order.
  MLA: the short names of the entries joined with "; " in key-list order.

5.4 KEYGEN (no arguments)
Make a "generated key" for each entry in the database, and output, in registration order, one line per entry consisting of the key, " -> " and the generated key.
The "base key" of each entry is the following three strings joined in this order.
(1) The letters extracted from the plain form of the Last of the lead name, lowercased.
(2) The digits contained in the year value, in order.
(3) Split the plain form of the title value into words at spaces, and extract the letters of each word, lowercased; the first of these that is non-empty and not a small word (3.2). Empty if there is none.
For an entry whose base key differs from the base keys of all other entries, the generated key is the base key. When two or more entries have equal base keys, the generated keys of those entries are the base key followed by "a", "b", "c", ... in registration order.

5.5 CHECK (no arguments)
Examine the entries of the database in registration order. For each entry, in the following order, output one line "WARN KEY: MESSAGE" (KEY is the key of the entry) for each item that applies, where MESSAGE is the text after the colon below.
(1) pages is present, and its plain form contains "-" and does not contain "--": pages use a single hyphen
(2) pages is present, exactly two of the parts obtained by splitting its plain form at "-" are non-empty (empty parts are ignored, so "99--88" qualifies), both of them consist only of digits, and the first number is greater than the second: pages are reversed
(3) The plain form of the year value is not a sequence of exactly 4 digits: year is not 4 digits
(4) The plain form of the title value contains no lowercase letter and two or more uppercase letters: title is all caps
(5) The type is article and doi is absent: article has no doi
(6) The plain form of the title value, lowercased, is equal to that of an entry earlier in registration order: same title as K, where K is the key of the earliest such entry in registration order
(7) For each unknown field, in ascending order of field name: unknown field 'FIELD', where FIELD is the field name
Finally, output "CHECK warnings=W". W is the number of WARN lines output by this command.

5.6 SEARCH field-name string (2 arguments)
Find the database entries that have a field with that field name and whose value, in plain form and lowercased, contains the string, lowercased, as a contiguous substring. Let c be the number of entries found. If c is 1 or more, output a line consisting of "MATCHES c: " followed by the keys of the found entries in registration order separated by single spaces; if c is 0, output "MATCHES 0".

5.7 EXPORT key (1 argument)
If the database has no entry with that key, output "ERROR unknown key 'KEY'". Otherwise, output the entry in the following form.
- First line: a line consisting of "@", the type, "{", the key and ",", in this order.
- Then one line per field of the entry: a line consisting of two spaces, the field name, " = {", the value and "}", in this order, with "," appended at the end of every field line except the last one. The fields are the known fields in the known-field order, followed by the unknown fields in ascending order of field name. The value is the normalized value (not the plain form; braces are kept).
- Last line: "}"

5.8 STATS (no arguments)
Output the following lines in order.
- "ENTRIES E": E is the number of entries in the database.
- For each type that appears in the database, in ascending order of type: "TYPE t n", where t is the type and n is the number of entries of that type.
- For each plain form of a year value that appears in the database, in ascending order: "YEAR v n", where v is that value and n is the number of entries with that value.
- "AUTHORS A": A is the number of distinct direct forms (full) among the names that appear in the author name lists of all entries. Names in editor are not counted.
- The PAIR line: for each entry that has author, form every pair (a, b) (a < b) of two names from the distinct direct forms (full) of the names that appear in its author name list. For each pair, count the number of entries that formed it, and choose the pair with the largest count. If several pairs have the same count, choose the one with the smallest a, and if still tied, the one with the smallest b, and output "PAIR a & b n", where n is that number of entries. If no pair exists at all, output "PAIR none".

[Output format]
- First output the error lines of the database part in the order they were reported, followed by the LOADED line. After that, output the output of each command line in order.
- Every number is written as a decimal integer without extra leading zeros.
- The output consists only of ASCII characters. No line has trailing spaces, and no empty line is output. Every line ends with a newline.
- The error lines are of the following 11 kinds (LINE, NAME, MACRO, TYPE, FIELD, COMMAND, STYLE and KEY are replaced by the actual line number, name, macro name, type, field name, command name, style and key).
  ERROR line LINE: NAME: unbalanced braces
  ERROR line LINE: NAME: unknown macro 'MACRO'
  ERROR line LINE: NAME: duplicate macro
  ERROR line LINE: NAME: unknown type 'TYPE'
  ERROR line LINE: NAME: duplicate key
  ERROR line LINE: NAME: duplicate field 'FIELD'
  ERROR line LINE: NAME: missing field 'FIELD'
  ERROR unknown command 'COMMAND'
  ERROR wrong number of arguments
  ERROR unknown style 'STYLE'
  ERROR unknown key 'KEY'

[Constraints]
- The database part has at least 1 and at most 400 lines, and N is at least 1 and at most 200.
- Each line of the input has at most 600 characters.
- Every "\" in the result of evaluating the expression of a field line is the first character of an accent command ([Processing] 1.2).
- The plain form of every normalized field value contains at least one letter or digit.
- In author and editor values, each part obtained by splitting at " and " at depth 0 is non-empty, and "others" appears only as the last part and is never the first part. Each name contains at most two "," at depth 0, and each part obtained by splitting at "," is non-empty. When the plain form of First is split into words at spaces and each word is split into pieces at "-", every piece contains at least one letter.
- Each group to which year suffixes are assigned has at most 26 entries.
- Among the parts obtained by splitting the plain form of the pages value at "-", those consisting only of digits have at most 9 characters.
- When the plain form of the edition value consists only of digits, it does not start with 0 and is at most 9999.
- A command line has at least one character, does not start with a space, and contains no consecutive spaces except inside the second argument of CITE and SEARCH.
- Every "\" in the text of CITE is the first character of a citation command. The "{" of a citation command is always followed by a "}", and what lies between them is a key list in the format of [Processing] 5.3.

In this example, the macro jcs is defined as "Journal of Computing", and the entry bad is not registered because the braces in its title are unbalanced. In the second name of lee2019, "~" becomes a space, giving "Jan van der Berg", which is parsed with von "van der" and Last "Berg". The APA title is in sentence case, so the "a" immediately after ": " is uppercased, and the braced "GPU" is not changed. The first CITE adds the keys mul2015 and lee2019 of its parenthetical citation to the citation record in this order, so the IEEE number of mul2015 is 1 and that of lee2019 is 2. The APA parenthetical citation sorts the entries in bibliography order (Lee before Muller), and joins the two names of the short name with "&".
