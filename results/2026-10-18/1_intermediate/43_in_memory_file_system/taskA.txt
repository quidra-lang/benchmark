[Overview]
Write a program that simulates a Unix-like shell. The program holds a file system in memory (a tree structure made of directories, regular files and symbolic links), executes the command lines read from standard input one at a time, starting from the first, and writes the results to standard output. The features covered are: path resolution (absolute and relative paths, "." and "..", symbolic links and the detection of their cycles), changing the current directory (including moving to the previous directory), creating, deleting, moving and copying files and directories, creating and reading symbolic links, pipelines and output redirection, listing and information display (ls, stat, find, du, tree), and text processing (cat, wc, head, tail, grep, sort, uniq). Invalid operations are reported with error messages in fixed formats.

[Input format]
The input consists of several lines, each of which is one "command line". The last line consists of exactly the 4 characters "exit" and marks the end of the input (this line is not treated as a command line). Each line consists of 1 to 200 printable ASCII characters (character codes 32 to 126), has no space at its beginning or end, and there are no empty lines.
A command line consists of a "pipeline", which is one or more "commands" separated by " | " (the 3 characters space, vertical bar, space), followed by an optional "redirect". The redirect is " > path" or " >> path" (a space, ">" or ">>", a space, path) and is placed at the end of the command line. The characters "|" and ">" appear only as these separators.
Each command is a command name followed by zero or more arguments, separated by single spaces (echo is the only exception, explained below). The command formats are as follows ([ ] marks an optional part, and ... means the preceding part repeated one or more times).

  pwd
  cd [path]
  cd -
  mkdir [-p] path...
  touch path...
  echo text
  cat [path...]
  ls [option...] [path...]
  stat path...
  rm [option...] path...
  rmdir path...
  mv src... dest
  cp [-r] src... dest
  ln -s target path
  readlink path
  realpath path
  find [path] [test...]
  du [option...] [path...]
  tree [-a] [path]
  wc [option...] [path...]
  head [-n count] [path]
  tail [-n count] [path]
  grep [option...] pattern [path...]
  sort [option...] [path...]
  uniq [-c] [path]

The arguments are as follows.
- A "name" is a string of 1 to 16 characters consisting of lowercase English letters (a to z), digits (0 to 9), ".", "_" and "-", whose first character is not "-", and which is neither "." nor "..".
- A path is one of the following: a string of one or more "components" joined by "/", such a string with a single "/" prepended, or the single-character string "/". Each component is ".", "..", or a name. A path is 1 to 100 characters long (therefore a path never contains two or more consecutive "/", and a path other than "/" never ends with "/"). src, dest and target (the link target) are also strings of the same form as path.
- An option is an argument consisting of "-" followed by one or more lowercase English letters. Each letter represents one option; for example, "-la" means the same as "-l -a". A letter appearing two or more times means the same as appearing once. The allowed letters are l, a, t, r for ls; r, f for rm; s, a for du; l, w, c for wc; i, v, c, n, r for grep; and r, n for sort. The "-p" of mkdir, the "-r" of cp, the "-a" of tree and the "-c" of uniq are also options of the same form. Options are placed before the other arguments of the command.
- A test is one of "-name glob", "-type c" and "-maxdepth k". glob is a string of 1 to 16 characters consisting of the characters allowed in names plus "*" and "?"; c is one of "f", "d" and "l"; k is an integer from 0 to 99. No single find contains two or more tests of the same kind, but the tests may appear in any order. The first argument of find is the path if and only if it does not start with "-".
- count (the line count) is either an integer k from 0 to 999 by itself, or, for head, "-" followed by k, and, for tail, "+" followed by k.
- text (the string of echo) is a string of 1 to 40 printable ASCII characters containing neither "|" nor ">", whose first and last characters are not spaces. It may contain consecutive spaces in the middle, and its first character may be "-". An echo command is "echo", one space, then text, where text is the entire part up to the end of that command (just before the next " | ", just before the redirect, or the end of the line).
- pattern (the search string of grep) is a string of 1 to 20 printable ASCII characters containing no space, "|" or ">", whose first character is not "-".
- Integers are written without extra leading zeros.
Commands whose command name is none of the above may also appear. Such a command consists of one or more strings, each of one or more characters containing no space, "|" or ">", separated by single spaces.
It is guaranteed that every line follows these formats and the [Constraints]. However, the file or directory that a path refers to does not necessarily exist (how this is handled is explained in [Processing]).

[Processing]
Process the command lines one at a time in input order. When the exit line is read, terminate the program without printing anything.

== File system ==
The file system is a collection of "nodes". There are 3 kinds of nodes, "directory", "file" (regular file) and "link" (symbolic link), and every node has an "inode number" (a positive integer) and a "modification time" (an integer >= 0).
- A directory has zero or more "entries". An entry is a pair of a name and a node, and no directory has two or more entries with the same name.
- A file has "content". The content is a sequence of zero or more "lines" (strings of printable ASCII characters).
- A link has a "target" (a string of the same form as path).
The file system has one directory called the "root". Every node other than the root is an entry of exactly one directory. That directory is called the node's "parent", and the name of that entry is called the node's "name". The parent of the root is the root itself. When node X can be reached from node Y by moving to the parent zero or more times, Y is said to be a "descendant" of X (X itself is a descendant of X).
The following values are defined for nodes.
- "Byte count": for a file, the sum, over the lines of its content, of the length of the line plus 1 (for the newline character).
- "Size": the byte count for a file, the number of characters of the target for a link, and the number of entries for a directory.
- "Link count": for a directory, 2 plus the number of its entries whose node is a directory. 1 for files and links.
- "Absolute path": "/" for the root. For any other node, the concatenation, in order, of the names of the nodes met when following the parent-child relation from the node after the root down to that node, each preceded by "/" (example: /home/user).
The "ascending order" of strings is lexicographic order comparing character codes (if one is a prefix of the other, the shorter one comes first). Whenever names are sorted, this ascending order is used.

== State ==
The program holds the file system, the "current directory" (one directory), the "previous directory" (a string, or "none"), the "clock" (an integer) and the "next inode number" (an integer). In the initial state, the file system consists only of the root with no entries (inode number 1, modification time 0), the current directory is the root, the previous directory is none, the clock is 0 and the next inode number is 2.
- To "create a node" means to create a new node whose inode number is the next inode number and whose modification time is the clock, and then add 1 to the next inode number.
- To "add node X to directory D under name n" means to add the entry (n, X) to D. At this time, set the modification time of D to the clock.
- To "detach node X" means to remove the entry of X from the parent of X. At this time, set the modification time of the parent of X to the clock. To "remove node X" means to detach X and never use it again (if X is a directory, all descendants of X also disappear from the file system).
- When the content of a file is changed (replaced, lines appended, or emptied), set the modification time of that file to the clock. This counts as changing the content even when the content after replacement is the same as before, and when a file with 0 lines of content is emptied.
Modification times change only in the cases described here and when explicitly set by touch. For example, moving a node to another directory does not change the modification time of the node itself.

== Path resolution ==
This defines the procedure for "resolving" a path p to obtain the node that p refers to. A resolution is specified either to "follow the final link" or to "not follow the final link". Below, plain "resolve" means following the final link, and "resolve without following" means not following the final link.
1. If p starts with "/", let X be the root; otherwise, let X be the base directory. The base directory is the current directory, except inside the link expansion below.
2. Process the non-empty components obtained by splitting p at "/", one at a time from the first, as follows (if p is "/", there are no components).
  a. If X is not a directory, fail with reason "Not a directory".
  b. If the component is ".", do nothing. If the component is "..", set X to the parent of X.
  c. If the component is a name: if X has no entry with that name, fail with reason "No such file or directory". If there is such an entry, let Y be its node. If Y is a link and either this component is not the last component of p or the resolution follows the final link, replace Y with the result of the "link expansion" below. Then set X to Y.
3. X after all components have been processed is the result of the resolution.
Expansion of link Y: count the number of link expansions within one resolution (including expansions performed inside the resolution of link targets). If this expansion would make the count 9, fail with reason "Too many levels of symbolic links" (that is, at most 8 expansions can be performed in one resolution). Otherwise, resolve the target of Y by this procedure, following the final link, with the base directory being the X at that moment (the directory that has Y as an entry), and use its result as the result of the expansion. If this resolution of the target fails, the original resolution also fails with the same reason. When a command performs several resolutions, the expansion count starts from 0 for each resolution.
When the resolution of a path p requested by a command fails at step 2c because there is no entry for the last component of p itself (failures that occur inside the resolution of a link target are not included), this failure is specifically called "absent"; the X at that time is called the "creation directory", and the name of that component is called the "creation name". Commands that create nodes, when the resolution is absent, add a node to the creation directory under the creation name. Wherever this is not described, absent is treated as a failure with reason "No such file or directory".
Below, <reason> denotes the reason of a resolution failure (one of "No such file or directory", "Not a directory" and "Too many levels of symbolic links").

== Auxiliary definitions ==
- The "last component" of a path is the part after the last "/" in the path (the whole path if it contains no "/"). The last component of the path "/" is the empty string.
- The "join" of a string s and a name n is "/<n>" if s is "/", and "<s>/<n>" otherwise.
- Node X "contains the current directory" if the current directory is a descendant of X. The root always contains the current directory.
- "Read the inputs" (used by cat, wc, head, tail, grep, sort, uniq): if no path is given, there is exactly one input, the standard input (a sequence of lines), and it has no name. If paths are given, resolve each path in the given order; if the resolution fails, print the error "<command name>: <path>: <reason>", and if the result is a directory, print the error "<command name>: <path>: Is a directory". If the result is a file, its content becomes one input, whose name is the path string itself. The command interleaves the reading, the printing of errors and the per-input processing in path order. That is, the error for a path is printed after the lines output by processing the inputs of earlier paths, and before the lines output by processing the inputs of later paths (only sort reads all inputs before producing its output).

== Processing a command line ==
Each command receives a sequence of lines as its "standard input" and writes zero or more lines to its "standard output". Error messages (below simply "errors") are not written to standard output; they are printed to the terminal immediately when they occur. Here, "print to the terminal" means writing one line to the standard output of this program.
A command line is processed by the following steps.
1. Add 1 to the clock. Every modification time changed within this command line is set to this value.
2. Print the line "<absolute path of the current directory>$ <command line>" (below, the "prompt line") to the terminal. <command line> is the input line itself.
3. If there is a redirect, resolve its path.
  - If absent, create a file (with 0 lines of content) and add it to the creation directory under the creation name.
  - If the result is a file: when the redirect is ">", empty its content; when it is ">>", do nothing.
  - If the result is a directory, print the error "sh: <path>: Is a directory"; if the resolution fails, print the error "sh: <path>: <reason>"; in either case, finish processing this command line (no command is executed).
  The file obtained is called the "redirect file".
4. Execute the commands of the pipeline one at a time from left to right. The standard input of the first command is empty (0 lines), and the standard input of each subsequent command is the standard output of the preceding command. If there is no redirect, the standard output of the last command is printed to the terminal as is, each time a line is written (so the errors and the standard-output lines of the last command are interleaved in the order they occur). If there is a redirect, it is not printed to the terminal.
5. If there is a redirect and the standard output of the last command has one or more lines, append all of those lines in order to the end of the content of the redirect file. The redirect file is the very node obtained in step 3; even if it was moved or removed by a command in between, append to that node (if it was removed, the appended content is not visible from anywhere).
Commands ignore their standard input, except those whose description below says they use it. If the command name is none of the following, print the error "<command name>: command not found" (the standard output is empty).

== Commands ==
Below, "output" means writing one line to standard output, and "print the error" means printing an error. <path>, <src> and <dest> in messages are the strings written in the arguments themselves. Unless stated otherwise, a command that takes several paths processes each path in the given order, and if an error occurs for one path, it continues processing the remaining paths.

pwd
Output the absolute path of the current directory.

cd [path]
If path is omitted, "/" is assumed to be given. If path is "-": if the previous directory is none, print the error "cd: OLDPWD not set" and finish; otherwise, use the string of the previous directory as path and do the following (the <path> in the errors below is also this string).
Resolve path; if the resolution fails, print the error "cd: <path>: <reason>", and if the result is not a directory, print the error "cd: <path>: Not a directory". Otherwise, set the previous directory to the absolute path of the current directory before the change, and set the current directory to the resulting directory (the previous directory is updated even when moving to "."). If the argument was "-", additionally output the absolute path of the new current directory.

mkdir [-p] path...
Do the following for each path. Every error has the form "mkdir: cannot create directory '<path>': <reason>".
Without -p: resolve path without following. If absent, create a directory and add it to the creation directory under the creation name. If a node is obtained (even a link), it is an error with reason "File exists". If the resolution fails, it is an error with that reason.
With -p: resolve path without following, but during the resolution, when X has no entry with the name of a component of path itself that is not its last component (except when this happens inside the resolution of a link target), do not fail; instead, create a directory, add it to X under that name, and continue the rest of step 2c with the created directory as Y. If absent, likewise create a directory and add it to the creation directory under the creation name. If a node is obtained, resolve path once more (following the final link); if the result is a directory, do nothing. If the result is not a directory or this resolution fails, it is an error with reason "File exists". If the first resolution fails, it is an error with that reason (the directories created up to that point remain as they are).

touch path...
Resolve each path. If absent, create a file (with 0 lines of content) and add it to the creation directory under the creation name. If a node is obtained (it may be a directory), set its modification time to the clock. If the resolution fails, print the error "touch: cannot touch '<path>': <reason>".

echo text
Output text (output it as is even if text starts with "-").

cat [path...]
Read the inputs, and output all lines of each input in order.

ls [option...] [path...]
If no path is given, it is as if the single path "." were given. Do the following for each path.
1. If -l is given, resolve path without following; otherwise, resolve it. If the resolution fails, print the error "ls: cannot access '<path>': <reason>".
2. If the result is not a directory, "display" the list consisting of that one node, with the path string itself as its name.
3. If the result is a directory D: if two or more paths are given, first output "<path>:". Next, build a list of the entries of D (pairs of a name and a node). However, without -a, entries whose name starts with "." are excluded. With -a, the pair of the name "." and D itself and the pair of the name ".." and the parent of D are also added to the list. The list is ordered as ".", "..", then the remaining entries (in ascending order of name). With -t, re-sort it in descending order of modification time (entries with equal modification times keep their previous order). With -r, finally reverse the whole list. Then display this list (if the list is empty, nothing is output).
To "display" a list: without -l, output the name of each pair, one per line, in list order. With -l, output "<type> <link count> <size> <modification time> <name>" for each pair, one per line, in list order. <type> is "d" if the node is a directory, "-" if it is a file, and "l" if it is a link. If the node is a link, append " -> <target>" to the end of the line. <link count>, <size> and <modification time> are each right-aligned by padding them with spaces on the left to the maximum number of digits of that value within the displayed list.

stat path...
Resolve each path without following; if the resolution fails, print the error "stat: cannot stat '<path>': <reason>". If it succeeds, output "<path>: <type name>, size <size>, inode <inode number>, links <link count>, modified <modification time>". <type name> is "directory" for a directory, "regular file" for a file with one or more lines of content, "regular empty file" for a file with 0 lines of content, and "symbolic link" for a link.

rm [option...] path...
For each path, check the following in order.
1. If the last component of path is "." or "..", print the error "rm: refusing to remove '.' or '..' directory: skipping '<path>'".
2. Resolve path without following. If the resolution fails: if -f is given and the reason is "No such file or directory", do nothing. Otherwise, print the error "rm: cannot remove '<path>': <reason>".
3. If the result is a directory and -r is not given, print the error "rm: cannot remove '<path>': Is a directory".
4. If the result contains the current directory, print the error "rm: cannot remove '<path>': Device or resource busy".
5. Remove the resulting node (if it is a link, remove the link itself).

rmdir path...
For each path, check the following in order. Every error has the form "rmdir: failed to remove '<path>': <reason>".
1. If the last component of path is "." or "..", the reason is "Invalid argument".
2. Resolve path without following; if the resolution fails, it is an error with that reason.
3. If the result is not a directory, the reason is "Not a directory".
4. If the result contains the current directory, the reason is "Device or resource busy".
5. If the result has entries, the reason is "Directory not empty".
6. Remove the resulting node.

mv src... dest
If there are two or more srcs and the result of resolving dest is not a directory (including when the resolution fails), print the error "mv: target '<dest>' is not a directory" and finish. Otherwise, perform the following "move" for each src in order.
1. If the last component of src is ".", "..", or the empty string, print the error "mv: cannot move '<src>' to '<dest>': Invalid argument".
2. Resolve src without following; if the resolution fails, print the error "mv: cannot stat '<src>': <reason>". Let S be the resulting node.
3. Determine the destination. If the result of resolving dest is a directory D, let n be the last component of src, let the destination be the pair of D and the name n, and let T be the join of dest and n. Otherwise (including when this resolution fails), resolve dest without following: if absent, the destination is the pair of the creation directory and the creation name; if a node N is obtained, the destination is the pair of the parent of N and the name of N; in either case, let T be dest. If this resolution without following fails, print the error "mv: cannot move '<src>' to '<dest>': <reason>".
4. Let the destination be the pair of directory P and name n; if P has an entry with the name n, let E be its node. Check the following in order.
  a. If S is a directory and P is a descendant of S, print the error "mv: cannot move '<src>' to a subdirectory of itself, '<T>'".
  b. If E is S, print the error "mv: '<src>' and '<T>' are the same file".
  c. If E exists, S is a directory and E is not a directory, print the error "mv: cannot overwrite non-directory '<T>' with directory '<src>'".
  d. If E exists, S is not a directory and E is a directory, print the error "mv: cannot overwrite directory '<T>' with non-directory '<src>'".
  e. If E is a directory that has entries, print the error "mv: cannot move '<src>' to '<T>': Directory not empty".
  f. If E is the current directory, print the error "mv: cannot move '<src>' to '<T>': Device or resource busy".
5. If E exists, remove E. Next, detach S and add S to P under the name n. S keeps its inode number, modification time, content, target and entries (descendants) unchanged. Even if the current directory is a descendant of S, the current directory remains the same node (so its absolute path changes).

cp [-r] src... dest
If there are two or more srcs and the result of resolving dest is not a directory (including when the resolution fails), print the error "cp: target '<dest>' is not a directory" and finish. Otherwise, perform the following "copy" for each src in order.
1. If the last component of src is ".", "..", or the empty string, print the error "cp: cannot copy '<src>' to '<dest>': Invalid argument".
2. Resolve src; if the resolution fails, print the error "cp: cannot stat '<src>': <reason>". Let S be the resulting node.
3. If S is a directory and -r is not given, print the error "cp: -r not specified; omitting directory '<src>'".
4. Resolve dest. If the result is a directory, let T be the join of dest and the last component of src. If absent, or if the result is not a directory, let T be dest. If the resolution fails for a reason other than absent, print the error "cp: cannot copy '<src>' to '<dest>': <reason>".
5. When S is a directory: resolve T without following (this resolution never fails for a reason other than absent). If a node is obtained, print the error "cp: cannot copy '<src>' to '<T>': File exists". If absent and the creation directory is a descendant of S, print the error "cp: cannot copy a directory, '<src>', into itself, '<T>'". Otherwise, "clone" S into the creation directory under the creation name.
6. When S is a file: resolve T. If absent, create a file with the same content as S and add it to the creation directory under the creation name. If the result is S, print the error "cp: '<src>' and '<T>' are the same file". If the result is a directory, print the error "cp: cannot overwrite directory '<T>' with non-directory '<src>'". If the result is a file F other than S, replace the content of F with the same content as S (the inode number of F does not change). If the resolution fails for a reason other than absent, print the error "cp: cannot copy '<src>' to '<T>': <reason>".
To "clone" node X into directory P under name n means to create a node of the same kind as X (with the same content as X for a file, or the same target as X for a link), add it to P under the name n, and, if X is a directory, for each entry of X in ascending order of name, clone the node of that entry into the new directory under the name of the entry. Hence the new nodes receive inode numbers in the order of a directory first and its contents after. No link is expanded during cloning (links are cloned as links).

ln -s target path
Resolve path without following. If absent, create a link whose target is target and add it to the creation directory under the creation name (whether target refers to anything is not checked). If a node is obtained, print the error "ln: failed to create symbolic link '<path>': File exists"; if the resolution fails, print the error "ln: failed to create symbolic link '<path>': <reason>".

readlink path
Resolve path without following; if the resolution fails, print the error "readlink: <path>: <reason>", and if the result is not a link, print the error "readlink: <path>: Invalid argument". If it is a link, output its target.

realpath path
Resolve path; if the resolution fails, print the error "realpath: <path>: <reason>". If it succeeds, output the absolute path of the resulting node.

find [path] [test...]
If path is omitted, it is ".". Resolve path; if the resolution fails, print the error "find: '<path>': <reason>". If it succeeds, "visit" the resulting node with path as its display path, the last component of path ("/" if path is "/") as its match name, and 0 as its depth.
Visiting node X: if X passes all the tests, output the display path of X. Next, if X is a directory and either there is no "-maxdepth k" test or the depth of X is less than k, then for each entry of X in ascending order of name, visit the node of that entry with the join of the display path of X and the name of the entry as its display path, the name of the entry as its match name, and the depth of X plus 1 as its depth. Links are not expanded (a link is also visited as a node, but it has no entries).
The condition for passing each test is as follows. "-name glob" passes when the match name matches glob. In glob, "*" matches any string of zero or more characters, "?" matches any single character, and every other character matches that character itself; "matches" means that the whole glob matches the whole match name. "-type c" passes when the node is a file if c is "f", a directory if c is "d", and a link if c is "l". "-maxdepth k" always passes (it only limits the range that is visited).

du [option...] [path...]
If no path is given, it is as if the single path "." were given. The "usage" of a node is its byte count for a file, its size (the number of characters of the target) for a link, and the sum of the usages of the nodes of its entries for a directory. Resolve each path; if the resolution fails, print the error "du: cannot access '<path>': <reason>". If it succeeds, "report" the resulting node with path as its display path.
Reporting node X: without -s, for each entry of X in ascending order of name, if the node of the entry is a directory or -a is given, report that node with the join of the display path of X and the name of the entry as its display path. Then output "<usage of X> <display path of X>". With -s, -a has no effect. Links are not expanded.

tree [-a] [path]
If path is omitted, it is ".". Resolve path; if the resolution fails, print the error "tree: <path>: <reason>", and if the result is not a directory, print the error "tree: <path>: Not a directory". If it succeeds, first output path, then "draw" the resulting directory with the empty string as the prefix, and finally output "<D> directories, <F> files". D is the number of lines output by the drawing whose node is a directory, and F is the number of the other lines (files and links). However, if D is 1, "directories" is replaced by "directory", and if F is 1, "files" is replaced by "file".
Drawing directory X (prefix s): arrange the entries of X, excluding those whose name starts with "." when -a is not given, in ascending order of name. For each entry in order, output "<s>`-- <name>" if it is the last of the list, and "<s>|-- <name>" otherwise. However, if the node of the entry is a link, append " -> <target>" to the end of the line. If the node of the entry is a directory, immediately after that line, draw that directory with the prefix being s followed by 4 spaces if the entry is the last of the list, and s followed by "|" and 3 spaces otherwise. Links are not expanded.

wc [option...] [path...]
Read the inputs, and for each input compute the line count L, the word count W and the byte count B. W is the total, over all lines, of the number of maximal runs of consecutive non-space characters in each line. B is the sum of the length of each line plus 1. -l, -w and -c select L, W and B respectively; if none of them is given, all three are selected. For each input, output one line consisting of the selected numbers in the order L, W, B separated by single spaces, followed, if the input has a name, by one space and the name. If two or more paths were given, finally output one line consisting of the totals over all inputs that could be read, in the same form, followed by one space and "total".

head [-n count] [path]
tail [-n count] [path]
Read the inputs (there are 0 or 1 paths), and output part of the lines of that input in the original order. If count is omitted, it is "10". Let k be an integer. For head, if count is "k", output the first k lines (all lines if there are fewer than k lines), and if it is "-k", output the lines except the last k lines (nothing if there are k or fewer lines). For tail, if count is "k", output the last k lines (all lines if there are fewer than k lines), and if it is "+k", output from the k-th line counted from the first up to the last line (k = 0 is the same as 1; nothing if there are fewer than k lines).

grep [option...] pattern [path...]
Without -r, read the inputs. With -r: if no path is given, it is as if the single path "." were given; resolve each path in order, and if the resolution fails, print the error "grep: <path>: <reason>". If it succeeds, visit the resulting node in the same order as find (with no -maxdepth test), and take the visited nodes that are files, in order, as the inputs. The name of an input is the display path built by the same rules as find. Links are not expanded and are not used as inputs.
For each line of each input, the line "matches" when pattern appears in the line as a contiguous substring. With -i, replace the uppercase English letters (A to Z) with lowercase letters in both pattern and the line before comparing. Without -v the matching lines, and with -v the non-matching lines, are the "selected lines". If two or more paths are given or -r is given, the prefix is "<input name>:"; otherwise, the prefix is the empty string. With -c, output "<prefix><number of selected lines>" for each input. Without -c, for each selected line of each input in the original order, output "<prefix><line number>:<line>" with -n, or "<prefix><line>" without -n. Line numbers count the first line of that input as 1.

sort [option...] [path...]
Read the inputs, form the sequence of the lines of all inputs concatenated in input order, sort it and output it (errors from reading are all printed before any sorted line is output). Without -n, sort the lines in ascending order. With -n, sort them in increasing order of "numeric value", and sort lines with equal numeric values in ascending order of the line. The numeric value of a line is: if the line starts with a digit, the value of the longest run of digits from the start read as a decimal integer; if the line starts with "-" immediately followed by a digit, the negation of the value of the longest run of digits following that "-" read as a decimal integer; otherwise, 0 (examples: "42 apples" is 42, "-7 below" is -7, "007" is 7, "- dash" and "x10" are 0). With -r, finally reverse the whole list.

uniq [-c] [path]
Read the inputs (there are 0 or 1 paths), group consecutive identical lines into one group, and for each group in the original order, output the line without -c, or "<number of lines in the group> <line>" with -c.

[Constraints]
- The number of input lines (including the exit line) is between 2 and 1000 inclusive.
- The number of nodes in the file system is at most 1000 at all times.
- The content of every file has at most 200 lines at all times.
- A pipeline has at most 5 commands.
- When -n is given to sort, the run of digits read to obtain the numeric value of each line being sorted has at most 9 digits.

[Example]
Input:
mkdir -p docs/notes
echo hello world > docs/a.txt
echo second line >> docs/a.txt
ln -s docs/a.txt link
cd docs
ls -l
cat ../link | wc
cd -
mv docs/a.txt docs/notes
cat link
tree
find . -name *.txt
exit

Output:
/$ mkdir -p docs/notes
/$ echo hello world > docs/a.txt
/$ echo second line >> docs/a.txt
/$ ln -s docs/a.txt link
/$ cd docs
/docs$ ls -l
- 1 24 3 a.txt
d 2  0 1 notes
/docs$ cat ../link | wc
2 4 24
/docs$ cd -
/
/$ mv docs/a.txt docs/notes
/$ cat link
cat: link: No such file or directory

.
|-- docs
|   `-- notes
|       `-- a.txt
`-- link -> docs/a.txt
2 directories, 2 files
/$ find . -name *.txt
./docs/notes/a.txt

In this example, the clock advances 1, 2, ... with each command line. Each line of ls -l shows the type, link count, size, modification time and name in this order; content was appended to a.txt at time 3 (2 lines, 24 bytes), and notes was created at time 1 and has no entries. The size column is right-aligned to its maximum number of digits, 2. cat ../link expands the link and reads docs/a.txt, and its lines become the standard input of wc. After a.txt is moved into notes, the target "docs/a.txt" of link no longer refers to anything, so cat gives an error. tree does not expand links and counts the link as a file.
