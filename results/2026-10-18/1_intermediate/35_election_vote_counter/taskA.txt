[Overview]
Write an election tallying system that counts ranked ballots (ballots on which each voter ranks candidates 1st, 2nd, ...). The program reads commands from standard input and handles registering candidates, recording and undoing ballots, generating ballots with a pseudo-random number generator, withdrawing and restoring candidates, and setting the priority order used for ties. As tallying methods it supports plurality, two-round runoff, instant-runoff (IRV), Coombs, Bucklin, Borda, Baldwin, Nanson, Black, veto, Condorcet, Copeland, minimax, Schulze, ranked pairs, Kemeny, approval, and single transferable vote (STV), and it writes to standard output the round-by-round tallies and winners, pairwise tables, the progression of exhausted ballots, the full order of all candidates, spoiler analyses, comparisons between methods, and so on.

[Input format]
The first line contains the number of commands N (1 <= N <= 1000), and each of the following N lines contains one command. Each line consists of several tokens separated by single spaces, with no whitespace at the beginning or end of the line. Each command has one of the following forms (<...> marks a position where a value goes, and <name>... denotes one or more <name>s separated by single spaces).

CANDIDATES <name>...
BALLOT <votes> <ranking>
RANDOM <count> <seed>
UNDO
WITHDRAW <name>
RESTORE <name>
TIEBREAK <name>...
STATUS
BALLOTS
PROFILE
PAIRWISE
EXHAUSTED
SUMMARY
COMPARE <name> <name>
RANKING <method>
SPOILERS <method>
<method>

<method> has one of the following 18 forms and consists of one or two tokens.

PLURALITY
RUNOFF
IRV
COOMBS
BUCKLIN
BORDA
BALDWIN
NANSON
BLACK
VETO
CONDORCET
COPELAND
MINIMAX <kind>
SCHULZE
RANKEDPAIRS
KEMENY
APPROVAL <k>
STV <seats>

The format of each value is as follows.
- <name>: a candidate name, a string of 1 to 12 characters consisting of one uppercase English letter followed by 0 to 11 lowercase English letters (e.g. Alice, Bo, X).
- <votes>: an integer from 1 to 999.
- <ranking>: 1 to 10 <name>s joined with ">" (e.g. Alice>Carol>Bob), or the single character "-" (ASCII hyphen).
- <count>: an integer from 1 to 100.
- <seed>: an integer from 1 to 2147483646.
- <kind>: one of WINNING, MARGIN, OPPOSITION.
- <k>, <seats>: integers from 1 to 9.
CANDIDATES has 1 to 7 <name>s, and TIEBREAK has 1 to 10 <name>s. All integers are written in decimal without extra leading zeros.

[Processing]
Process the commands one at a time in input order.

* Terms
- "Name order": the order of names by increasing character code (ASCII). Names are compared character by character starting from the first character; if one name is a prefix of the other, the shorter one comes first (e.g. "Bo" comes before "Bob", and "Bob" comes before "Carol").
- Election: the program holds at most one "current election". Initially there is no election. An election consists of the following information.
  (1) Candidate list: the names given by CANDIDATES, in the order written. This order is called the "registration order".
  (2) Withdrawn candidates: initially there are none. Candidates that are not withdrawn are called "active candidates".
  (3) Tiebreak order: an ordering of all candidates, including withdrawn ones; initially it is name order.
  (4) Entry list: a list of "entries", to the end of which each BALLOT and each RANDOM appends one entry; initially it is empty. An entry consists of one or more "ballot groups". A ballot group is a pair of a vote count (an integer >= 1) and a ranking (a list of candidates, possibly empty); a ballot group with vote count w represents the ballots of w voters who gave the same ranking. The first candidate in the ranking is ranked 1st, the second is ranked 2nd, and so on; candidates not contained in the ranking are not ranked.
- Total votes: the sum of the vote counts of all ballot groups in all entries of the current election.

* Common rules for output and errors
On success, CANDIDATES outputs one line. On success, BALLOT, RANDOM, UNDO, WITHDRAW, RESTORE and TIEBREAK output nothing. All other commands are called "tally commands". On success, a tally command first outputs one heading line formed by concatenating "[", the entire command line, and "]" (e.g. [APPROVAL 2], [RANKING MINIMAX MARGIN]), followed by the lines given in [Output format]. Tally commands do not change the election.
When a command cannot be executed, output only one line formed by concatenating "ERROR", one space, and one of the following strings giving the reason (no heading line is output), and change nothing. The <name> part is the name that caused the error.
- no election: there is no election.
- too few candidates: there are too few candidates.
- duplicate candidate <name>: the same name appeared two or more times.
- unknown candidate <name>: the name is not a candidate of the current election.
- nothing to undo: there is no entry to undo.
- already withdrawn <name>: the candidate has already withdrawn.
- not withdrawn <name>: the candidate has not withdrawn.
- withdrawn candidate <name>: the candidate is a withdrawn candidate.
- incomplete tiebreak: TIEBREAK does not give enough names.
- no ballots: there are no entries.
- not rankable: the method cannot be used with RANKING and SPOILERS.
- too many seats: the number of STV seats is too large.
- same candidate: COMPARE specified the same candidate twice.
Each command performs its checks in the order written in the descriptions below and outputs the first error that applies.
The "name-list check" examines a list of names one at a time from the beginning: if the name is not a candidate of the current election, the error is "ERROR unknown candidate <that name>"; if the same name appears earlier in the list, the error is "ERROR duplicate candidate <that name>"; the first error found is output. Withdrawn candidates are also candidates of the current election.

* CANDIDATES
If there is only one name, the error is "ERROR too few candidates". If the same name appears two or more times, the error is "ERROR duplicate candidate <name>" for the first name, scanning from the beginning, that has the same name earlier. If there is no error, discard the current election (if any) and start a new election whose candidate list is the given names. The new election has no withdrawn candidates, its tiebreak order is name order, and its entry list is empty. On error, the current election remains as it is.

* BALLOT
If there is no election, the error is "ERROR no election". If <ranking> is "-", the ranking is empty; otherwise the ranking is the names separated by ">" in the order written, and the name-list check is applied to it. If there is no error, append to the end of the entry list an entry consisting of exactly one ballot group whose vote count is <votes> and whose ranking is that ranking. The ranking may contain withdrawn candidates.

* RANDOM
If there is no election, the error is "ERROR no election". Otherwise, create <count> ballot groups with vote count 1 by the following procedure, and append them, in the order created, as one entry to the end of the entry list.
Let the random state x be <seed>. "Drawing a random number" means replacing x with "the remainder of 48271*x divided by 2147483647" and taking the new value of x (48271*x may not fit in a 32-bit integer). Each ballot group is created as follows. Let a[0], a[1], ..., a[m-1] be the active candidates in registration order (m is the number of active candidates; each ballot group starts again from this registration-order list). For i decreasing by 1 from m-1 down to 1, draw a random number, let j be the remainder of that value divided by i+1, and swap a[i] and a[j]. Then draw one more random number, let L be the remainder of that value divided by m, plus 1, and use a[0], a[1], ..., a[L-1] as the ranking. Within one RANDOM, x carries over to the next ballot group; each RANDOM starts again from <seed>.

* UNDO
If there is no election, the error is "ERROR no election"; if the entry list is empty, the error is "ERROR nothing to undo". Otherwise, remove the last entry from the entry list. An entry added by RANDOM is removed as a whole.

* WITHDRAW, RESTORE
If there is no election, the error is "ERROR no election"; if <name> is not a candidate, the error is "ERROR unknown candidate <name>".
For WITHDRAW, next, if the candidate has already withdrawn, the error is "ERROR already withdrawn <name>"; if there are 2 or fewer active candidates, the error is "ERROR too few candidates". If there is no error, the candidate withdraws.
For RESTORE, next, if the candidate has not withdrawn, the error is "ERROR not withdrawn <name>". If there is no error, the candidate becomes an active candidate again.
Withdrawal and restoration do not change the entries. Withdrawn candidates in the entries are treated as removed from the rankings when tallying (see "* Tallying basics").

* TIEBREAK
If there is no election, the error is "ERROR no election". Next, apply the name-list check to the list of <name>s; after that, if the number of <name>s differs from the number of candidates (including withdrawn candidates), the error is "ERROR incomplete tiebreak". If there is no error, set the tiebreak order to the order of the <name>s.

* Common checks for tally commands
If there is no election, the error is "ERROR no election". For tally commands other than STATUS, next, if the entry list is empty, the error is "ERROR no ballots". Any further checks are as described for each command.

* Tallying basics
Each method tallies over a set of candidates called the "field". The field is the set of all active candidates (except that SPOILERS also performs tallies whose field is the active candidates minus one candidate). Let m be the number of candidates in the field. When candidates are listed in output, they are listed in registration order unless stated otherwise.
- Effective ranking: the ranking of a ballot group with the candidates not in the field removed, the remaining candidates kept in their original order. Below, "k-th place", "ranks", "ranked lower" and the like all refer to the effective ranking. A ballot group whose effective ranking is empty is called a "blank group".
- Preference: a ballot group "prefers X to Y" when it ranks candidate X and either does not rank Y or ranks Y lower than X. A ballot group that ranks neither X nor Y prefers neither.
- Pairwise contest: for distinct candidates X and Y, d(X,Y) denotes the sum of the vote counts of the ballot groups that prefer X to Y. When d(X,Y) > d(Y,X), "X beats Y" (Y loses to X); when d(X,Y) = d(Y,X), "X and Y tie".
- First-preference votes: for a subset S of the field, the candidate of S that appears first when a ballot group's effective ranking is scanned from the beginning is called that ballot group's "first choice in S". A ballot group in which no candidate of S appears is "exhausted with respect to S". The "first-preference votes in S" of each candidate of S is the sum of the vote counts of the ballot groups whose first choice in S is that candidate.
- Last-place votes: the "last-place votes in S" of each candidate of S are counted as follows. For each ballot group, if there are one or more candidates of S that the ballot group does not rank, add the ballot group's vote count to every one of them; otherwise (if it ranks every candidate of S), add it to the lowest-ranked candidate among them. A blank group thus adds its vote count to every candidate of S.
- Borda score: let s be the number of candidates in S. The "Borda score in S" of each candidate of S is obtained by adding, for each ballot group, "vote count * (s-j)" to the j-th candidate (j = 1, 2, ...) of the list obtained by removing from the effective ranking the candidates not in S. Candidates that are not ranked receive nothing.
- Majority: given a value for each candidate and the total T of those values, a candidate whose value v satisfies 2*v > T "has a majority".
- Condorcet winner: a candidate that beats every other candidate in the field (if one exists, there is exactly one). Condorcet loser: a candidate that loses to every other candidate in the field (if one exists, there is exactly one).
- Standings and winner: every method other than CONDORCET and STV defines the "standings", an ordering of all candidates in the field in a single line. The method's "winner" is the first candidate in the standings. In the cases that a method's description calls a "tie", " (tie)" is appended to the winner line (see [Output format]).

* Tiebreaks
- Ordering "earlier in tiebreak order first" means placing the candidate that comes earlier in the tiebreak order first.
- The "look-back rule" is the rule for choosing one candidate to eliminate in methods that repeat rounds. Let P be the set of candidates with the minimum value in the current round. Going back one round at a time from the previous round to round 1, in each round narrow P down to only those candidates whose value in that round is the minimum within P. When the look-back is finished, if exactly one candidate remains in P, choose that candidate; if two or more remain, choose the one among them that comes latest in the tiebreak order. In round 1, this means choosing, among the candidates with the minimum value, the one latest in the tiebreak order. The candidates in P remained in all earlier rounds, so their values in every round are defined.

* PLURALITY (plurality)
Count the first-preference votes in the whole field. The standings are in decreasing order of first-preference votes (equal counts: earlier in tiebreak order first). If two or more candidates have the maximum first-preference votes, it is a tie.

* RUNOFF (two-round runoff)
As round 1, count the first-preference votes in the whole field. If some candidate has a majority of the round-1 first-preference votes, finish at round 1. In that case, the standings are in decreasing order of round-1 first-preference votes (equal counts: earlier in tiebreak order first).
Otherwise, the first two candidates when ordered by decreasing round-1 first-preference votes (equal counts: earlier in tiebreak order first) are the "finalists". The case where the field has 3 or more candidates and the second and third candidates in this ordering have equal first-preference votes is called an "advancement tie". As round 2, count the first-preference votes in the set consisting of the two finalists; the one with more first-preference votes is the winner. If they are equal, it is a tie, and the winner is the one with more round-1 first-preference votes, or, if those are also equal, the one earlier in tiebreak order. The standings are the winner, the other finalist, and then the remaining candidates in decreasing order of round-1 first-preference votes (equal counts: earlier in tiebreak order first).

* IRV (instant-runoff voting)
Let S, the "set of remaining candidates", be the whole field, and repeat the following starting from round 1.
1. Count the first-preference votes in S.
2. If S has only one candidate, or some candidate has a majority of the first-preference votes in S (relative to the total of the first-preference votes in S of all candidates of S), finish with that round as the final round.
3. Otherwise, choose one candidate with the fewest first-preference votes by the look-back rule (with each round's first-preference votes as the values), eliminate it (remove it from S), and go to the next round. The case where two or more candidates have the minimum first-preference votes is called an "elimination tie".
The standings are the candidates of S in the final round in decreasing order of final-round first-preference votes (equal counts: earlier in tiebreak order first), followed by the eliminated candidates, the most recently eliminated first. The winner is the candidate that has a majority, or the only remaining candidate. The IRV winner is never a tie.

* EXHAUSTED (exhausted ballots)
Perform the same tally as IRV, and for each IRV round compute the total of the first-preference votes in S (the active votes) and the total votes minus that (the sum of the vote counts of the ballot groups exhausted with respect to S).

* COOMBS (Coombs)
Let S be the whole field, and repeat the following starting from round 1.
1. Count the first-preference votes in S.
2. If S has only one candidate, or some candidate has a majority of the first-preference votes in S, finish with that round as the final round.
3. Otherwise, count the last-place votes in S and eliminate the candidate with the most last-place votes. If two or more candidates have the maximum last-place votes (an elimination tie), eliminate, among them, the candidate with the fewest first-preference votes in this round, and if there are still two or more, the one among those latest in the tiebreak order. Go to the next round.
The standings and the winner are determined in the same way as IRV (never a tie).

* BUCKLIN (Bucklin)
Let Q be the sum of the vote counts of the ballot groups that are not blank groups, and let M, the "majority line", be the quotient of Q divided by 2, plus 1. Perform round k for k = 1, 2, ... in order. In round k, for each candidate, count the sum of the vote counts of the ballot groups that rank that candidate at any place from 1st to k-th (the round-k votes). If some candidate has M or more votes, or k = m, finish with that round as the final round.
The standings are in decreasing order of final-round votes. Among candidates with equal final-round votes, the one with more votes in the immediately preceding round comes first; if those are also equal, compare the votes of the round before that, and so on back to round 1; if all are equal, the one earlier in tiebreak order comes first. If two or more candidates have the maximum final-round votes, it is a tie.

* BORDA (Borda)
Compute the Borda scores in the whole field. The standings are in decreasing order of Borda score (equal scores: earlier in tiebreak order first). If two or more candidates have the maximum Borda score, it is a tie.

* BALDWIN (Baldwin)
Let S be the whole field, and while S has two or more candidates, repeat the following round. Compute the Borda scores in S, choose one candidate with the lowest Borda score by the look-back rule (with each round's Borda scores in S as the values), and eliminate it. The case where two or more candidates have the minimum Borda score is called an "elimination tie".
The standings are the last remaining candidate, followed by the eliminated candidates, the most recently eliminated first. It is never a tie.

* NANSON (Nanson)
Let S be the whole field, and while S has two or more candidates, repeat the following round. Let s be the number of candidates in S and T the total of the Borda scores in S, and find the candidates whose Borda score in S * s < T (whose Borda score is below the average). If there are any such candidates, eliminate all of them simultaneously and go to the next round. If there are none (if all candidates of S have equal Borda scores), finish with this round.
The standings are the candidates of the last remaining S ordered earlier in tiebreak order first, followed by the eliminated candidates, those eliminated in later rounds first. Candidates eliminated in the same round are ordered by decreasing Borda score in that round (equal scores: earlier in tiebreak order first). If the last remaining S has two or more candidates, it is a tie.

* BLACK (Black)
If there is a Condorcet winner, the standings are the Condorcet winner first, followed by the remaining candidates in decreasing order of Borda score in the whole field (equal scores: earlier in tiebreak order first). In this case it is never a tie. If there is no Condorcet winner, the standings and the tie decision are the same as BORDA.

* VETO (veto)
The last-place votes in the whole field are the "veto counts". The standings are in increasing order of veto count (equal counts: earlier in tiebreak order first). If two or more candidates have the minimum veto count, it is a tie.

* CONDORCET (Condorcet)
Find the Condorcet winner, the Condorcet loser, the Smith set and the Schwartz set.
- Smith set: a "weak path" from candidate X to candidate Y is a list of candidates starting with X and ending with Y in which, for every two adjacent candidates, the earlier one beats or ties the later one (if X and Y are the same, the list consisting of X alone is also a weak path). The Smith set is the set of candidates that have a weak path to every candidate in the field.
- Schwartz set: a "strong path" from candidate X to candidate Y is a list of two or more candidates starting with X and ending with Y in which, for every two adjacent candidates, the earlier one beats the later one (the same candidate may appear two or more times). The Schwartz set is the set of candidates X for which "if there is a strong path from Y to X, then there is also a strong path from X to Y" holds for every candidate Y in the field.
CONDORCET does not define standings.

* COPELAND (Copeland)
For each candidate, count the number W of other candidates it beats, the number D it ties, and the number L it loses to, and let its score be W + D/2. The standings are in decreasing order of score (equal scores: earlier in tiebreak order first). If two or more candidates have the maximum score, it is a tie.

* MINIMAX (minimax)
The score of each candidate X is defined according to <kind> as follows.
- WINNING: the maximum of d(Y,X) over the candidates Y that beat X. It is 0 if no candidate beats X.
- MARGIN: the maximum of d(Y,X)-d(X,Y) over the candidates Y that beat X. It is 0 if no candidate beats X.
- OPPOSITION: the maximum of d(Y,X) over all candidates Y other than X.
The standings are in increasing order of score (equal scores: earlier in tiebreak order first). If two or more candidates have the minimum score, it is a tie.

* SCHULZE (Schulze)
For distinct candidates X and Y, let q(X,Y) = d(X,Y) if X beats Y, and q(X,Y) = 0 otherwise. A "path" from X to Y is a list of two or more mutually distinct candidates starting with X and ending with Y, and its "strength" is the minimum, over every two adjacent candidates, of the value q(earlier candidate,later candidate). Let p(X,Y) be the maximum strength over all paths from X to Y. p(X,Y) can be computed, for example, by the following procedure. First set every p(X,Y) to q(X,Y); then, for each candidate I, for every pair of a candidate J other than I and a candidate K other than I and J, replace p(J,K) with the larger of p(J,K) and "the smaller of p(J,I) and p(I,K)".
The standings are built as follows. Let R be the set of candidates not yet placed in the standings; until R is empty, repeat the following: among the candidates X such that "p(Y,X) > p(X,Y) does not hold for any other candidate Y in R" (there is always at least one), take the one earliest in the tiebreak order, append it to the end of the standings, and remove it from R. If two or more candidates satisfy the condition when the first candidate is chosen, it is a tie.

* RANKEDPAIRS (ranked pairs)
A pair of candidates (X,Y) such that X beats Y is called a "majority pair". Sort all majority pairs by decreasing d(X,Y); if equal, by increasing d(Y,X); if also equal, with X earlier in tiebreak order first; if also equal, with Y earlier in tiebreak order first. Starting with no edges, process each majority pair (X,Y) in this order. If X cannot be reached from Y by following only the edges (directed edges) locked so far, lock the edge from X to Y (lock); if it can be reached, do not lock it (skip).
The standings are built by the same procedure as SCHULZE, except that the condition on a candidate X that may be chosen is "there is no locked edge to X from any other candidate Y in R". If two or more candidates satisfy the condition when the first candidate is chosen, it is a tie.

* KEMENY (Kemeny)
For each permutation of all candidates in the field (m! permutations), its score is the sum of d(X,Y) over all pairs of a candidate X that comes earlier and a candidate Y that comes later in the permutation. The permutations with the maximum score are called "optimal permutations". The standings are the one optimal permutation chosen as follows: the one whose first candidate is earliest in the tiebreak order; if there are two or more such permutations, among them the one whose second candidate is earliest in the tiebreak order; and so on. If the optimal permutations have two or more different first candidates, it is a tie.

* APPROVAL (approval)
The approval count of each candidate is the sum of the vote counts of the ballot groups that rank that candidate at any place from 1st to <k>-th. The standings are in decreasing order of approval count (equal counts: earlier in tiebreak order first). If two or more candidates have the maximum approval count, it is a tie.

* STV (single transferable vote)
Let s be <seats>. After the common checks, if s >= m, the error is "ERROR too many seats".
In STV, amounts of votes are represented as integers in which 0.01 vote is 1 (called "values" below). Blank groups are not used. Each ballot group that is not a blank group carries a "value per vote" v, initially 100 for all of them. The "quota" q is the quotient of (the sum of the vote counts of the ballot groups that are not blank groups, multiplied by 100) divided by (s+1), plus 1.
Let the set of "continuing candidates" be the whole field and the list of elected candidates be empty, and repeat the following starting from round 1.
1. For each ballot group that is not a blank group, the first continuing candidate appearing in its effective ranking is that ballot group's "current candidate". Each continuing candidate's tally is the sum of "vote count * v" over the ballot groups whose current candidate is that candidate. The sum of "vote count * v" over the ballot groups that have no current candidate is the "exhausted value".
2. If the number of continuing candidates equals the number of remaining seats (s minus the number of elected candidates), append all continuing candidates to the end of the list of elected candidates in decreasing order of tally (equal values: earlier in tiebreak order first) and finish.
3. Otherwise, if there are continuing candidates whose tally is q or more, append the one among them with the largest tally (equal values: the one earliest in the tiebreak order), E, to the end of the list of elected candidates and remove it from the continuing candidates. Let T be E's tally, and call T-q the "surplus". For each ballot group whose current candidate in step 1 of this round was E, replace its v with "the quotient of v*(T-q) divided by T". If there are now s elected candidates, finish.
4. If neither applies, choose one continuing candidate with the smallest tally by the look-back rule (with each round's tallies as the values), exclude it (it is defeated), and remove it from the continuing candidates. The case where two or more candidates have the minimum tally is called an "exclusion tie".
STV does not define standings.

* STATUS, BALLOTS, PROFILE, PAIRWISE
Output the state of the current election, a summary of the entries, the distribution of ranks, and the pairwise table, respectively (see [Output format]).

* RANKING
After the common checks, if <method> is CONDORCET or STV, the error is "ERROR not rankable". Otherwise, compute the standings of <method>.

* SPOILERS
After the common checks, if <method> is CONDORCET or STV, the error is "ERROR not rankable"; if there are fewer than 3 active candidates, the error is "ERROR too few candidates". Otherwise, compute the winner W of <method>, and further, for each active candidate Y other than W, compute the winner of <method> with the field being "the active candidates excluding Y" (Y is not actually withdrawn).

* SUMMARY
Compute the winners of the following 15 methods, in this order.
PLURALITY, RUNOFF, IRV, COOMBS, BUCKLIN, BORDA, BALDWIN, NANSON, BLACK, VETO, COPELAND, MINIMAX WINNING, SCHULZE, RANKEDPAIRS, KEMENY
Also, for each active candidate, count the number of these 15 methods in which that candidate is the winner.

* COMPARE
After the common checks, check the first <name> and then the second <name>: if it is not a candidate, the error is "ERROR unknown candidate <name>"; if it has withdrawn, the error is "ERROR withdrawn candidate <name>" (both of these are checked for the first <name> before the second <name> is checked). Next, if the two <name>s are the same, the error is "ERROR same candidate". If there is no error, let X be the first candidate and Y the second candidate, compute d(X,Y), d(Y,X), and total votes - d(X,Y) - d(Y,X) (the number of votes preferring neither), and for each of the same 15 methods as SUMMARY, determine which of X and Y comes earlier in the standings.

[Output format]
Do not put whitespace at the end of any line, and end every line with a newline. Numbers are written as decimal integers without extra leading zeros unless stated otherwise. The following notations are used below.
- "Value list": given a list of candidates and a value for each candidate, the items formed by concatenating the name, one space, and the value, separated by ", " (a comma and a space) (e.g. Alice 12, Bob 9, Carol 0). Candidates are listed in registration order unless stated otherwise.
- "Name list": names separated by ", ".
- "Rank list": names separated by " > " (a space, ">", and a space) (e.g. Bob > Alice > Carol).
- "Winner line": one line formed by concatenating "winner: " and the winner's name, followed by " (tie)" in case of a tie (e.g. winner: Bob, winner: Alice (tie)).
- An STV value x (an integer >= 0) is written as the quotient of x divided by 100, ".", and the remainder of x divided by 100 in two digits (with a leading 0 if it has one digit) (e.g. 1501 is 15.01, 7 is 0.07, 0 is 0.00).

* CANDIDATES
One line "election <k>: <m> candidates". k is the number of successful CANDIDATES commands so far (including this one), and m is the number of candidates.

* Tally commands
After the heading line, output the following lines.

STATUS: the following five lines.
election <k> (k is the same value as the k in the line output by the CANDIDATES that started the current election)
active: <name list of the active candidates>
withdrawn: <name list of the withdrawn candidates> ("withdrawn: none" if there are no withdrawn candidates)
tiebreak: <name list of all candidates in tiebreak order>
ballots: <total votes> in <number of entries> entries

BALLOTS: the first line is "total <total votes>, blank <sum of the vote counts of the blank groups>, distinct <number of distinct effective rankings>". Then, grouping together the ballot groups with the same effective ranking, output one line "<total vote count> <effective ranking notation>" for each distinct effective ranking. The effective ranking notation is the names joined with ">", or "-" for a blank group. The lines are sorted by decreasing total vote count, and when equal, by the effective ranking notation as a string in increasing character code (ASCII) order (compared the same way as name order).

PROFILE: for each active candidate, one line "<name>: <c1> <c2> ... <cm> unranked <u>". ci (i = 1, 2, ..., m) is the sum of the vote counts of the ballot groups that rank that candidate in i-th place, and u is the sum of the vote counts of the ballot groups that do not rank that candidate (including blank groups).

PAIRWISE: for each pair of two distinct candidates in the field, one line "<X> vs <Y>: <d(X,Y)>-<d(Y,X)> (<result>)". X is the one of the two that comes earlier in registration order and Y is the later one, and the result is the name of the one that wins, or "tie" if they tie. The lines are ordered by X's registration order, and by Y's registration order when X is the same.

PLURALITY: two lines, "votes: <value list of the first-preference votes>" and the winner line.

RUNOFF: after "round 1: <value list of the round-1 first-preference votes>", if the tally finished at round 1, output only the winner line. Otherwise, output "finalists: <name list of the two finalists>" (with " (tie)" at the end of this line in case of an advancement tie), "round 2: <value list of the round-2 first-preference votes of the two finalists>", and the winner line.

IRV: for each round, output one line "round <r>: <value list of the first-preference votes in S of the candidates of S>" (r is the round number). In a round in which a candidate is eliminated, append "; eliminated <eliminated candidate>" to the end of that line, and further " (tie)" in case of an elimination tie. Finally output the winner line.

EXHAUSTED: for each IRV round, one line "round <r>: active <active votes>, exhausted <total votes - active votes>".

COOMBS: for each round, output one line "round <r>: <value list of the first-preference votes in S of the candidates of S>". In a round in which a candidate is eliminated, append "; last <value list of the last-place votes in S of the candidates of S>; eliminated <eliminated candidate>" to the end of that line, and further " (tie)" in case of an elimination tie. Finally output the winner line.

BUCKLIN: "majority: <M>", then for each round from round 1 to the final round, "round <k>: <value list of the round-k votes of all candidates in the field>", then the winner line.

BORDA: two lines, "scores: <value list of the Borda scores>" and the winner line.

BALDWIN: for each round, output one line "round <r>: <value list of the Borda scores in S of the candidates of S>; eliminated <eliminated candidate>" (with " (tie)" at the end in case of an elimination tie), and finally output the winner line.

NANSON: for each round, output one line "round <r>: <value list of the Borda scores in S of the candidates of S>", and in a round in which candidates are eliminated, append "; eliminated <name list of the eliminated candidates>" to the end of that line. Finally output the winner line.

BLACK: three lines, "condorcet: <name of the Condorcet winner>" ("condorcet: NONE" if there is none), "scores: <value list of the Borda scores in the whole field>", and the winner line.

VETO: two lines, "vetoes: <value list of the veto counts>" and the winner line.

CONDORCET: four lines, "winner: <name of the Condorcet winner>", "loser: <name of the Condorcet loser>" ("winner: NONE" and "loser: NONE", respectively, if there is none), "smith: <name list of the Smith set>", and "schwartz: <name list of the Schwartz set>".

COPELAND: two lines: one line consisting of "scores: " followed by "<name> <score> (<W>-<D>-<L>)" for each candidate, separated by ", ", and the winner line. The score is written with exactly one decimal place (e.g. 2.0, 1.5, 0.0).

MINIMAX: two lines, "scores: <value list of the scores>" and the winner line.

SCHULZE: output lines of the same form as PAIRWISE, using p(X,Y) and p(Y,X) instead of d(X,Y) and d(Y,X) (with the result also decided by comparing p), followed by "ranking: <rank list of the standings>" and the winner line.

RANKEDPAIRS: in the order in which the majority pairs were processed, output one line "lock <X>><Y> <d(X,Y)>-<d(Y,X)>" for a pair that was locked, or "skip <X>><Y> <d(X,Y)>-<d(Y,X)>" for a pair that was not locked (e.g. lock Bob>Alice 7-3), and finally output the winner line. If there are no majority pairs, output only the winner line.

KEMENY: four lines, "score: <score of the optimal permutations>", "optimal: <number of optimal permutations>", "ranking: <rank list of the standings>", and the winner line.

APPROVAL: two lines, "approvals: <value list of the approval counts>" and the winner line.

STV: after "quota: <q>", for each round output one line formed by "round <r>: <value list of the tallies of the continuing candidates>; exhausted <exhausted value>" followed by one of the following. All values are written in the STV value format.
- A round that finished in step 2: "; elected <name list of the added candidates (in the order added)>"
- A round of step 3: "; elected <E> (surplus <surplus>)"
- A round of step 4: "; excluded <excluded candidate>" (followed by " (tie)" in case of an exclusion tie)
Finally output "elected: <name list of the list of elected candidates>".

RANKING: one line, the rank list of the standings.

SPOILERS: after "winner: <W>", for each active candidate Y other than W, in registration order, output one line "without <Y>: <winner when Y is excluded>", and if that winner differs from W, append " (changed)" to the end of the line.

SUMMARY: for the 15 methods, in SUMMARY order, one line "<method>: <winner>" each (a method is written like "MINIMAX WINNING"), and finally output "wins: <value list of the number of methods in which each active candidate is the winner>".

COMPARE: the following three lines.
<X> <d(X,Y)>, <Y> <d(Y,X)>, neither <number of votes preferring neither>
<X> ahead: <name list of the methods in which X comes before Y in the standings>
<Y> ahead: <name list of the methods in which Y comes before X in the standings>
The methods are listed in SUMMARY order, written the same way as in SUMMARY. If there is no such method, write, for example, "<X> ahead: none".

* Errors
One line "ERROR <reason>" (see [Processing]).

[Constraints]
- 1 <= N <= 1000.
- The number of tokens of each command and the format of each token are guaranteed to be as described in [Input format].
- Each line is at most 200 characters long.
- At any point in time, the total votes of the current election are at most 10000.
- Except for the random number computation of RANDOM, every value appearing in the computation is an integer and fits in the range of a 32-bit signed integer. 48271*x in RANDOM is less than 2^53.
