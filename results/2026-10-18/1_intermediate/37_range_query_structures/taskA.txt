[Overview]
Write a program for a "laboratory of range-query data structures" that runs representative data structures for range queries over an integer array, with every detail of each procedure fixed. The program reads an array and a sequence of commands from standard input and handles a recursive segment tree (sum, minimum, maximum, greatest common divisor), a segment tree with lazy propagation of assignment and addition, a Fenwick tree (Binary Indexed Tree) and its binary search, range addition with two Fenwick trees, a sparse table, square-root decomposition, a persistent segment tree and the k-th smallest value in a range, the number of distinct values in a range by Mo's algorithm, and a two-dimensional Fenwick tree. For each structure it performs building, updating, querying, printing of the internal state, measurements such as the number of visited nodes, and comparison against a direct scan of the array, and writes the results to standard output. Because every procedure is fixed, the output is uniquely determined.

[Input format]
Line 1 contains the number of elements n of the array. Line 2 contains the n elements of the array, separated by single spaces. Line 3 contains the number of commands N, and each of the following N lines contains one command. Each command consists of two or more words separated by single spaces (except RESET, which is a single word); there are no spaces at the beginning or end of a line, and there are no empty lines. The commands have the following 40 forms ([b] means that b may or may not be present).

  ARRAY l r
  LOAD v1 v2 ... vk
  RESET
  CHECK l r
  MO l1 r1 l2 r2 ... lk rk
  SEG BUILD op
  SEG QUERY l r
  SEG UPDATE i x
  SEG DUMP
  LAZY BUILD
  LAZY ADD l r x
  LAZY ASSIGN l r x
  LAZY QUERY l r
  LAZY DUMP
  FEN BUILD
  FEN ADD i x
  FEN PREFIX i
  FEN RANGE l r
  FEN LOWER k
  FEN DUMP
  RFEN BUILD
  RFEN ADD l r x
  RFEN SUM l r
  RFEN DUMP
  SPARSE BUILD
  SPARSE QUERY l r
  SPARSE DUMP
  SQRT BUILD [b]
  SQRT ADD l r x
  SQRT SUM l r
  SQRT DUMP
  PERSIST BUILD
  PERSIST SET ver i x
  PERSIST QUERY ver l r
  PERSIST KTH l r k
  PERSIST NODES
  GRID BUILD h w v1 v2 ... vk
  GRID ADD i j x
  GRID SUM i1 j1 i2 j2
  GRID DUMP

The arguments mean the following.
- op is a word of 1 to 8 uppercase English letters (A to Z).
- All arguments other than op (l, r, i, j, x, k, b, h, w, ver, v1 to vk, l1 to lk, r1 to rk, i1, j1, i2, j2) are integers written in decimal without extra leading zeros. A negative number is written with a leading ASCII "-", and "-0" does not appear.
- The k of LOAD, MO and GRID BUILD is a symbol for the number of values or pairs on that line and is not written in the input. The k of LOAD and MO is at least 1; the k of GRID BUILD may be 0 (in that case the line ends with w).
- Line 2 of the input contains exactly n values.
It is guaranteed that every line follows this format and the ranges in [Constraints].

[Processing]
Process the commands in order starting from the first one, and print the result of each command according to [Output format]. For each command, examine the errors listed under "Checks" in its description in the order written, print only the line of the first error that applies, and do nothing else for that command (neither the array nor any structure is changed). If no error applies, perform the "Action".

== Array ==
- The program holds an integer array A. Let n be the number of elements of A, and write its elements in index order as A[0], A[1], ..., A[n-1] (indices count from 0). Initially, A is the array given on lines 1 and 2 of the input.
- Separately from A, the program holds the "original array". Initially, the original array is the array on line 2 of the input. LOAD replaces both A and the original array, and RESET restores A to the same contents as the original array. No other command changes the original array.
- When l<=r, "range [l, r]" means the indices l, l+1, ..., r, and A[l..r] means A[l], A[l+1], ..., A[r].
- In this problem, "the quotient of a divided by b" is used only when a>=0 and b>=1, and means the integer obtained by discarding the fractional part.
- For an integer m>=1, isqrt(m) is the largest integer s satisfying s*s<=m.
- The greatest common divisor gcd(a, b) of two integers a and b is the largest integer that divides both |a| and |b|, with gcd(a, 0)=|a| and gcd(0, 0)=0. The greatest common divisor of a sequence of integers is the final g obtained by starting from g=0 and, for each element e of the sequence from front to back, replacing g with gcd(g, e) (the result is always 0 or greater).
- The "lowest bit" lowbit(p) of a positive integer p is the largest power of 2 that divides p (e.g. lowbit(12)=4, lowbit(7)=1).

== Structures ==
- There are 8 kinds of structures, SEG, LAZY, FEN, RFEN, SPARSE, SQRT, PERSIST and GRID, and the program holds at most one structure of each kind. Initially no structure exists. A structure is created by the BUILD command of its kind. If a structure of the same kind already exists, it is discarded and a new one is created. Apart from this, the only command that discards structures is LOAD.
- The 7 kinds other than GRID are called "array structures". An array structure holds a copy of A as it was when the structure was created, as the "contents" of that structure. The contents of an array structure are written C[0], C[1], ..., C[n-1] (whenever an array structure exists, n always equals the number of elements of A at the time that structure was created).
- The commands that update an array structure (SEG UPDATE, LAZY ADD, LAZY ASSIGN, FEN ADD, RFEN ADD, SQRT ADD) apply the same change to both the contents of that structure and A, and do not change the contents of any other structure. Therefore, once A is changed through one structure, the contents of other structures may disagree with A. A query on an array structure answers about the contents of that structure, not about A.
- SPARSE has no update command. PERSIST holds contents per "version" (defined in "== PERSIST =="), and PERSIST commands do not change A. GRID handles a two-dimensional array unrelated to A.
- The internal state of the 8 kinds of structures is maintained exactly as defined in the following subsections. Output such as DUMP writes this state as it is.

== Bisection tree ==
SEG, LAZY and PERSIST use trees of the following shape.
- Each "node" of the tree is "responsible for" some range [nl, nr]. The root is responsible for [0, n-1]. A node with nl=nr is called a "leaf", and a leaf has no children. A node with nl<nr has, with m being the quotient of nl+nr divided by 2, a "left child" responsible for [nl, m] and a "right child" responsible for [m+1, nr]. The "length" of a node is nr-nl+1.
- In SEG and LAZY, the nodes are numbered. The root has number 1, and the left child of the node with number v has number 2v and its right child has number 2v+1.
- "Descending to range [l, r]" is the procedure that starts at the root and does the following at each node. If the range that the reached node is responsible for is contained in [l, r] (l<=nl and nr<=r), that node is a "covered node", and the procedure does not go further down from it. Otherwise, it proceeds to those children of the node that share an index with [l, r] (the left child when l<=m, the right child when r>m). When it proceeds to both, it finishes the whole procedure below the left child before proceeding to the right child. The number of nodes reached in this procedure (including the root and the covered nodes) is called the "visit count".
- The "path to index i" is the sequence of nodes (including the root and the leaf) passed when starting at the root and repeatedly proceeding to the child responsible for a range containing i until reaching the leaf responsible for [i, i].

== SEG ==
- SEG has one operation op (one of SUM, MIN, MAX, GCD). The result of the operation on two values a and b is a+b for SUM, the smaller of a and b for MIN, the larger of a and b for MAX, and gcd(a, b) for GCD.
- Each node has one "value". The value of the leaf responsible for [i, i] is |C[i]| for GCD and C[i] otherwise. The value of a node with children is the result of the operation on (the value of the left child) and (the value of the right child).
- "Querying range [l, r]" performs a descent to range [l, r] and determines the "result" of each node as follows. The result of a covered node is its value. The result of a node that is not covered is, if the procedure proceeded to one child, the result of that child, and, if it proceeded to two, the result of the operation on (the result of the left child) and (the result of the right child). The result of the root is the answer.

== LAZY ==
- Each node has three values: "sum", "min" and "max". A node with children additionally has an "assign tag" and an "add tag". The assign tag is either "none" or an integer, and the add tag is an integer. Leaves have no tags.
- "Pulling up" a node means setting its sum to the total of the sums of its two children, its min to the smaller of the mins of its two children, and its max to the larger of the maxes of its two children.
- "Applying assignment x" to a node means setting its sum to x*(length) and its min and max to x, and, if the node has children, setting its assign tag to x and its add tag to 0.
- "Applying addition x" to a node means adding x*(length) to its sum and x to its min and max, and, if the node has children, adding x to its add tag (the assign tag is not changed).
- "Pushing down" a node means the following. If the node's assign tag is none and its add tag is 0, do nothing. Otherwise, for each child in the order left child, right child: first, if the assign tag is an integer s, apply assignment s to the child; then, whether or not the assign tag is an integer, if the add tag d is not 0, apply addition d to the child. After that, set the node's assign tag to none and its add tag to 0. The number of push-downs, excluding those that did nothing, is called the "push count".
- At creation, the sum, min and max of the leaf responsible for [i, i] are all C[i], and each node with children holds the pull-up of its children's values. All assign tags are none and all add tags are 0.
- "Updating range [l, r]" (with addition x or assignment x) performs a descent to range [l, r] as follows. Apply that addition or assignment to each covered node. At a node that is not covered, push down that node before proceeding to its children, and pull up that node after finishing the whole procedure below the children proceeded to. The number of covered nodes is called the "cover count".
- "Querying range [l, r]" performs a descent to range [l, r], pushing down each node that is not covered before proceeding to its children, and determines the "result" (a triple of sum, min and max) of each node as follows. The result of a covered node is its sum, min and max. The result of a node that is not covered is, if the procedure proceeded to one child, the result of that child, and, if it proceeded to two, the total of the sums, the smaller of the mins and the larger of the maxes of the two children's results. The result of the root is the answer, and it equals the sum, minimum and maximum of C[l..r]. A query does no pull-ups.

== FEN ==
- FEN has an array T[1], T[2], ..., T[n]. T[p] is the sum of C[q-1] over all q satisfying p-lowbit(p)<q<=p (this relation always holds).
- "Adding to a Fenwick tree": adding x at position p of an array F means repeating, while p<=n, adding x to F[p] and replacing p with p+lowbit(p). The number of times x was added to F[p] is the "visit count" of this addition (0 if p>n).
- "Fenwick prefix sum": the prefix sum of an array F up to position p is the final s obtained by starting from s=0 and repeating, while p>=1, adding F[p] to s and replacing p with p-lowbit(p). The number of times F[p] was read is the "visit count" of this prefix sum (0 if p=0). The prefix sum of T up to position p equals C[0]+C[1]+...+C[p-1].
- The "binary search" of FEN LOWER is as follows. Let s be the largest power of 2 not exceeding n, pos=0 and rest=k. While s>=1, repeat the following. If pos+s<=n, read T[pos+s], and if the value read is less than rest, subtract that value from rest and add s to pos. Then replace s with the quotient of s divided by 2. The number of times T[pos+s] was read (the number of times pos+s<=n held) is the "visit count". If pos<n at the end, the answer is index pos; if pos=n, there is no answer. When all values of C are 0 or greater, the answer is the smallest index i satisfying C[0]+C[1]+...+C[i]>=k (no answer if no such i exists).

== RFEN ==
- RFEN has arrays B1[1], ..., B1[n] and B2[1], ..., B2[n]. For p=1, 2, ..., n, let D1[p]=C[p-1]-C[p-2] (except that D1[1]=C[0] when p=1) and D2[p]=(p-1)*D1[p]. B1[p] is the sum of D1[q] over all q satisfying p-lowbit(p)<q<=p, and B2[p] is the sum of D2[q] over the same q (these relations always hold).
- The "prefix value at position p", S(p), is p*P1-P2, where P1 is the prefix sum of B1 up to position p and P2 is the prefix sum of B2 up to position p. S(p) equals C[0]+C[1]+...+C[p-1] (S(0)=0).

== SPARSE ==
- SPARSE keeps the contents C as they were at creation and has two tables Pmin and Pmax. Let K be the largest integer satisfying 2^K<=n, and call each j from 0 to K a "level". The table of level j has indices Pmin[j][i] and Pmax[j][i] for each position i=0, 1, ..., n-2^j.
- Pmin[0][i] and Pmax[0][i] are both i. For j>=1, with h=2^(j-1), for a=Pmin[j-1][i] and b=Pmin[j-1][i+h], Pmin[j][i]=a if C[a]<=C[b], and Pmin[j][i]=b otherwise. Similarly, for a=Pmax[j-1][i] and b=Pmax[j-1][i+h], Pmax[j][i]=a if C[a]>=C[b], and Pmax[j][i]=b otherwise. Pmin[j][i] is the leftmost position of the minimum of C[i..i+2^j-1], and Pmax[j][i] is the leftmost position of the maximum.
- "Querying range [l, r]" means the following: let t be the largest integer satisfying 2^t<=r-l+1 and e=r-2^t+1; for a=Pmin[t][l] and b=Pmin[t][e], the minimum position is a if C[a]<=C[b] and b otherwise; for a=Pmax[t][l] and b=Pmax[t][e], the maximum position is a if C[a]>=C[b] and b otherwise. t is called the "level". The minimum position is the leftmost position of the minimum of C[l..r], and the maximum position is the leftmost position of the maximum.

== SQRT ==
- SQRT has a "block size" b (1<=b<=n). The number of blocks c is the quotient of (n+b-1) divided by b, and block t (t=0, 1, ..., c-1) is responsible for the indices from t*b up to the index obtained by subtracting 1 from the smaller of (t+1)*b and n. The block responsible for index i is the block whose number is the quotient of i divided by b.
- SQRT has a "raw value" val[i] for each index i, and a "tag" tag[t] and a "block sum" bsum[t] for each block t. At creation, val[i]=C[i], tag[t]=0, and bsum[t] is the sum of the values of C that block t is responsible for. At all times, C[i] equals val[i]+tag[(the block responsible for i)], and bsum[t] equals the sum of the values of C that block t is responsible for.
- The "split" of range [l, r] is as follows. Let tl be the quotient of l divided by b, and tr the quotient of r divided by b. If tl=tr, the indices from l to r are the "individual indices", and there are no "whole blocks". If tl<tr, the indices from l to (tl+1)*b-1 and the indices from tr*b to r are the individual indices, and the blocks from tl+1 to tr-1 are the whole blocks (if tl+1=tr, there are no whole blocks). When tl<tr, the two end blocks are treated as individual indices even if all of their indices are contained in the range.

== PERSIST ==
- PERSIST has "versions" numbered from 0. Each version has contents (an array of length n) and a tree representing those contents. The tree has the same shape as the bisection tree, and each node holds the sum of the values of the contents in the range it is responsible for.
- At creation, only version 0 exists, and its contents are a copy of A at the time of creation. The tree of version 0 consists entirely of newly created nodes (the number of nodes is 2n-1).
- When PERSIST SET creates a new version, new nodes are created only for the nodes on the path to index i in the tree of the source version, and the other nodes are shared with the tree of the source version. The number of newly created nodes equals the number of nodes on the path. Older versions do not change.
- "Querying range [l, r]" performs a descent to range [l, r] in the tree of that version and determines the result by the same rules as SEG with SUM (the answer is the sum of the contents from l to r).
- PERSIST KTH uses the following "value trees" for the contents E[0], ..., E[n-1] of version 0. Let V[0], V[1], ..., V[m-1] be the distinct values appearing in E in increasing order, and call the q with E[i]=V[q] the "rank" of E[i]. A value tree has the same shape as the bisection tree for range [0, m-1], and each node has a "count".
- At creation, the value trees R0, R1, ..., Rn are built as follows. R0 consists entirely of newly created nodes, with all counts 0 (the number of nodes is 2m-1). For i=0, 1, ..., n-1 in this order, with q being the rank of E[i], R(i+1) is made by creating, for each node on the path to index q in R(i) (the sequence of nodes down to the leaf responsible for [q, q]), a new node whose count is 1 greater, and sharing the other nodes with R(i). The count of the node responsible for range [p, q] in R(j) is the number of elements among E[0], ..., E[j-1] whose rank is at least p and at most q.
- "The k-th of range [l, r]" is found as follows. Let u be the root of R(r+1), w the root of R(l), p=0, q=m-1, and the visit count 1. While p<q, repeat the following: let mid be the quotient of p+q divided by 2 and d be (the count of the left child of u)-(the count of the left child of w); if k<=d, replace u and w with their respective left children and q with mid; otherwise subtract d from k, and replace u and w with their respective right children and p with mid+1. In both cases, add 1 to the visit count afterwards (once per repetition). The answer is V[p], which equals the k-th value when E[l..r] is sorted in increasing order (equal values are counted separately).

== MO ==
- MO uses no structure; it processes the given pairs (queries) for the current A in the order of Mo's algorithm. The queries are numbered from 1 in the order written, and query number j represents range [lj, rj].
- Let B=isqrt(n), and let the "block" of query j be the quotient of lj divided by B. Sort the queries in increasing order of block; queries with the same block in increasing order of rj if the block is even and in decreasing order of rj if it is odd; and, if those are also equal, in increasing order of number. This is called the "processing order".
- Starting from L=0, R=-1 and moves=0, for each query j in processing order, add |lj-L|+|rj-R| to moves, and replace L with lj and R with rj. The final value of moves is called the "total moves".
- The answer to query j is the number of distinct values appearing in A[lj..rj].

== GRID ==
- GRID has an integer table G with h rows and w columns, and an array U[1..h][1..w]. The value in row i, column j of G (0<=i<h, 0<=j<w) is written G[i][j]. U[p][q] is the sum of G[y-1][z-1] over all y, z satisfying p-lowbit(p)<y<=p and q-lowbit(q)<z<=q (this relation always holds).
- The "two-dimensional prefix sum up to position (p, q)" is the final s obtained by starting from s=0 and, for each y traced as y=p, p-lowbit(p), ... while y>=1, and for each z traced as z=q, q-lowbit(q), ... while z>=1, adding U[y][z] to s. The number of times U was read is the visit count of this prefix sum (0 if p=0 or q=0). This prefix sum equals the sum of all G[i][j] satisfying i<p and j<q.

== Common checks ==
- "Check structure S" means: if no structure of kind S exists, print "ERROR NOT BUILT <S>" (<S> is the name of the kind, such as SEG or LAZY).
- "Check index i" means: if i<0 or i>=n, print "ERROR BAD INDEX <i>".
- "Check range l r" means: check index l, check index r, and then, if l>r, print "ERROR BAD RANGE <l> <r>".
- "Check GRID cell i j" means: if any of i<0, i>=h, j<0, j>=w holds, print "ERROR BAD CELL <i> <j>" (h and w are the current numbers of rows and columns of GRID).

== Commands ==
ARRAY l r
- Checks: check range l r.
- Action: print "ARRAY <l> <r> <A[l]> <A[l+1]> ... <A[r]>".

LOAD v1 v2 ... vk
- Checks: none.
- Action: replace both A and the original array with the array consisting of v1, v2, ..., vk in this order (k elements). Then discard all array structures (GRID is kept as it is). Print "LOAD n=<k> removed=<number of array structures discarded>".

RESET
- Checks: none.
- Action: restore A to the same contents as the original array. Then rebuild each existing array structure from the restored A by the same procedure as the BUILD of its kind. SEG is rebuilt with the same operation op, SQRT is rebuilt with the same block size b, and PERSIST returns to the state with only version 0. Rebuilding prints no BUILD lines. GRID is not changed. Print "RESET rebuilt=<number of array structures rebuilt>".

CHECK l r
- Checks: check range l r.
- Action: first, compute directly the sum s, minimum a, maximum z and greatest common divisor g of A[l..r], and print "CHECK <l> <r> sum=<s> min=<a> max=<z> gcd=<g>". Then, in the order SEG, LAZY, FEN, RFEN, SPARSE, SQRT, PERSIST, for each existing array structure, perform the following query by exactly the same procedure as that command (LAZY push-downs are also performed).
  SEG: SEG QUERY l r
  LAZY: LAZY QUERY l r
  FEN: FEN RANGE l r
  RFEN: RFEN SUM l r
  SPARSE: SPARSE QUERY l r
  SQRT: SQRT SUM l r
  PERSIST: PERSIST QUERY ver l r, where ver is the version with the largest number
  For each structure, print "<kind> <verdict> <items>". <items> is what remains of the line that the query command would print if it were executed alone, after removing the leading "<the 2 words of the command> <l> <r> " (for PERSIST, "PERSIST QUERY <ver> <l> <r> "). For PERSIST, however, "version=<ver> " is put in front of it. <verdict> is OK if the two values of every one of the following pairs are equal, and DIFF otherwise: for SEG, the one pair of the answer and s, a, z or g (when op is SUM, MIN, MAX or GCD, respectively); for LAZY, the three pairs of the sum and s, the minimum and a, and the maximum and z; for SPARSE, the two pairs of C[minimum position] and a, and C[maximum position] and z (C is the contents of SPARSE); for the other structures, the one pair of the answer and s.
  Finally, print "RESULT ok=<number of OKs> diff=<number of DIFFs>". If there is no array structure at all, print only the "CHECK" line and "RESULT ok=0 diff=0".

MO l1 r1 l2 r2 ... lk rk
- Checks: for j=1, 2, ..., k in this order, check range lj rj (print only the first error found).
- Action: print "MO queries=<k> block=<B> moves=<total moves>" and "ORDER <the query numbers in processing order, separated by single spaces>", then, for j=1, 2, ..., k in this order, print "ANSWER <j> <lj> <rj> distinct=<answer to query j>".

SEG BUILD op
- Checks: if op is none of SUM, MIN, MAX, GCD, print "ERROR BAD OP <op>".
- Action: build a SEG with operation op from A. Print "SEG BUILD <op> nodes=<number of nodes> maxnode=<largest node number> root=<value of the root>".

SEG QUERY l r
- Checks: check structure SEG, then check range l r.
- Action: query range [l, r], and print "SEG QUERY <l> <r> <name>=<answer> visited=<visit count>". <name> is sum, min, max or gcd when op is SUM, MIN, MAX or GCD, respectively.

SEG UPDATE i x
- Checks: check structure SEG, then check index i.
- Action: set C[i] and A[i] to x. Change the value of the leaf responsible for [i, i] as defined, and then recompute, as defined, the values of the nodes with children on the path to index i, in order starting from the one nearest the leaf. Print "SEG UPDATE <i> <x> root=<value of the root> visited=<number of nodes on the path to index i>".

SEG DUMP
- Checks: check structure SEG.
- Action: print "SEG DUMP <op> nodes=<number of nodes>", then, for each node in increasing order of number, print "NODE <number> <nl> <nr> <value>".

LAZY BUILD
- Checks: none.
- Action: build a LAZY from A. Print "LAZY BUILD nodes=<number of nodes> sum=<sum of the root> min=<min of the root> max=<max of the root>".

LAZY ADD l r x
- Checks: check structure LAZY, then check range l r.
- Action: update range [l, r] with addition x. For each q with l<=q<=r, add x to C[q] and A[q]. Print "LAZY ADD <l> <r> <x> visited=<visit count> covered=<cover count> pushes=<push count>".

LAZY ASSIGN l r x
- Checks: check structure LAZY, then check range l r.
- Action: update range [l, r] with assignment x. For each q with l<=q<=r, set C[q] and A[q] to x. Print "LAZY ASSIGN <l> <r> <x> visited=<visit count> covered=<cover count> pushes=<push count>".

LAZY QUERY l r
- Checks: check structure LAZY, then check range l r.
- Action: query range [l, r], and print "LAZY QUERY <l> <r> sum=<sum> min=<minimum> max=<maximum> visited=<visit count> pushes=<push count>".

LAZY DUMP
- Checks: check structure LAZY.
- Action: print "LAZY DUMP nodes=<number of nodes>", then, for each node in increasing order of number, print "NODE <number> <nl> <nr> sum=<sum> min=<min> max=<max> assign=<assign tag> add=<add tag>". When the assign tag is none, and for a leaf, write assign=-; for a leaf, write the add tag as 0.

FEN BUILD
- Checks: none.
- Action: build a FEN from A. Print "FEN BUILD n=<n> total=<sum of all values of C>".

FEN ADD i x
- Checks: check structure FEN, then check index i.
- Action: add x to C[i] and A[i], and add x at position i+1 of T. Print "FEN ADD <i> <x> visited=<visit count of that addition>".

FEN PREFIX i
- Checks: check structure FEN, then check index i.
- Action: compute the prefix sum s of T up to position i+1 (C[0]+...+C[i]), and print "FEN PREFIX <i> sum=<s> visited=<visit count of that prefix sum>".

FEN RANGE l r
- Checks: check structure FEN, then check range l r.
- Action: compute the prefix sum s1 of T up to position r+1, then the prefix sum s2 up to position l, and print "FEN RANGE <l> <r> sum=<s1-s2> visited=<total of the visit counts of the 2 prefix sums>".

FEN LOWER k
- Checks: check structure FEN. Then, if C has a negative value, print "ERROR NEGATIVE <i>" for the one among them with the smallest index i.
- Action: perform the binary search, and print "FEN LOWER <k> index=<i> visited=<visit count>" if there is an answer index i, or "FEN LOWER <k> index=none visited=<visit count>" if there is none.

FEN DUMP
- Checks: check structure FEN.
- Action: print "FEN DUMP n=<n>" and "T <T[1]> <T[2]> ... <T[n]>".

RFEN BUILD
- Checks: none.
- Action: build an RFEN from A. Print "RFEN BUILD n=<n> total=<sum of all values of C>".

RFEN ADD l r x
- Checks: check structure RFEN, then check range l r.
- Action: for each q with l<=q<=r, add x to C[q] and A[q]. Add x at position l+1 of B1, -x at position r+2 of B1, x*l at position l+1 of B2, and -x*(r+1) at position r+2 of B2, in this order (if r+2>n, that addition changes nothing and its visit count is 0). Print "RFEN ADD <l> <r> <x> visited=<total of the visit counts of the 4 additions>".

RFEN SUM l r
- Checks: check structure RFEN, then check range l r.
- Action: take S(r+1)-S(l) as the answer, and print "RFEN SUM <l> <r> sum=<answer> visited=<visit count>". The visit count is the total of the visit counts of the 4 prefix sums used to compute S(r+1) and S(l) (B1 and B2 up to position r+1, and B1 and B2 up to position l).

RFEN DUMP
- Checks: check structure RFEN.
- Action: print "RFEN DUMP n=<n>", "B1 <B1[1]> ... <B1[n]>" and "B2 <B2[1]> ... <B2[n]>" in this order.

SPARSE BUILD
- Checks: none.
- Action: build a SPARSE from A. Print "SPARSE BUILD levels=<K+1> entries=<E>". E is the total of n-2^j+1 over j=0, 1, ..., K (the number of entries of one table).

SPARSE QUERY l r
- Checks: check structure SPARSE, then check range l r.
- Action: query range [l, r], and, with a the minimum position, z the maximum position and t the level, print "SPARSE QUERY <l> <r> min=<C[a]> minpos=<a> max=<C[z]> maxpos=<z> level=<t>".

SPARSE DUMP
- Checks: check structure SPARSE.
- Action: print "SPARSE DUMP levels=<K+1>", then, for j=0, 1, ..., K in this order, print "MIN <j> <Pmin[j][0]> <Pmin[j][1]> ... <Pmin[j][n-2^j]>" and "MAX <j> <Pmax[j][0]> ... <Pmax[j][n-2^j]>" in this order.

SQRT BUILD [b]
- Checks: if b is present and b>n, print "ERROR BAD BLOCK <b>".
- Action: if b is absent, let b=isqrt(n); build a SQRT with block size b from A. Print "SQRT BUILD block=<b> blocks=<c>".

SQRT ADD l r x
- Checks: check structure SQRT, then check range l r.
- Action: for each q with l<=q<=r, add x to C[q] and A[q]. Split range [l, r]; for each individual index i, add x to val[i] and to bsum[t] (of the block t responsible for i). For each whole block t, add x to tag[t] and x*b to bsum[t]. Print "SQRT ADD <l> <r> <x> whole=<number of whole blocks> cells=<number of individual indices>".

SQRT SUM l r
- Checks: check structure SQRT, then check range l r.
- Action: split range [l, r]; the answer is the total of val[i]+tag[(the block responsible for i)] over all individual indices i and bsum[t] over all whole blocks t. Print "SQRT SUM <l> <r> sum=<answer> whole=<number of whole blocks> cells=<number of individual indices>".

SQRT DUMP
- Checks: check structure SQRT.
- Action: print "SQRT DUMP block=<b> blocks=<c>", then, for t=0, 1, ..., c-1 in this order, with f the first index and e the last index that block t is responsible for, print "BLOCK <t> <f> <e> add=<tag[t]> sum=<bsum[t]> <val[f]> <val[f+1]> ... <val[e]>".

PERSIST BUILD
- Checks: none.
- Action: build a PERSIST from A (build version 0 and the value trees R0 to Rn). Print "PERSIST BUILD nodes=<number of nodes of the tree of version 0> distinct=<m> valuenodes=<total number of nodes created for the value trees>".

PERSIST SET ver i x
- Checks: check structure PERSIST. Then, if ver<0 or ver>=(number of versions), print "ERROR BAD VERSION <ver>". Then check index i.
- Action: create a new version whose contents are the contents of version ver with the value at index i set to x; its number is the number of versions that existed before it. Print "PERSIST SET <ver> <i> <x> version=<number of the new version> created=<number of newly created nodes>".

PERSIST QUERY ver l r
- Checks: check structure PERSIST. Then, if ver<0 or ver>=(number of versions), print "ERROR BAD VERSION <ver>". Then check range l r.
- Action: query range [l, r] in version ver, and print "PERSIST QUERY <ver> <l> <r> sum=<answer> visited=<visit count>".

PERSIST KTH l r k
- Checks: check structure PERSIST, then check range l r. Then, if k<1 or k>r-l+1, print "ERROR BAD K <k>".
- Action: find the k-th of range [l, r], and print "PERSIST KTH <l> <r> <k> value=<answer> visited=<visit count>".

PERSIST NODES
- Checks: check structure PERSIST.
- Action: print "PERSIST NODES versions=<number of versions> position=<P> value=<Q>". P is the total of the number of nodes of the tree of version 0 and the numbers of nodes newly created by each PERSIST SET, and Q is the total number of nodes created for the value trees (both are counted since PERSIST was last built by PERSIST BUILD or RESET).

GRID BUILD h w v1 v2 ... vk
- Checks: if k differs from h*w, print "ERROR BAD COUNT <k> <value of h*w>".
- Action: build a GRID with h rows and w columns where G[i][j]=v(i*w+j+1) (0<=i<h, 0<=j<w; the values are laid out from the first row onward, and from left to right within each row). Print "GRID BUILD rows=<h> cols=<w> total=<sum of v1 to vk>".

GRID ADD i j x
- Checks: check structure GRID, then check GRID cell i j.
- Action: add x to G[i][j], and, for each y traced as y=i+1, y+lowbit(y), ... while y<=h, and for each z traced as z=j+1, z+lowbit(z), ... while z<=w, add x to U[y][z]. Print "GRID ADD <i> <j> <x> visited=<number of additions to U>".

GRID SUM i1 j1 i2 j2
- Checks: check structure GRID, check GRID cell i1 j1, then check GRID cell i2 j2. Then, if i1>i2 or j1>j2, print "ERROR BAD RECT <i1> <j1> <i2> <j2>".
- Action: let s1, s2, s3 and s4 be the two-dimensional prefix sums up to positions (i2+1, j2+1), (i1, j2+1), (i2+1, j1) and (i1, j1), respectively, and print "GRID SUM <i1> <j1> <i2> <j2> sum=<s1-s2-s3+s4> visited=<total of the visit counts of the 4 prefix sums>". The answer is the sum of all G[i][j] satisfying i1<=i<=i2 and j1<=j<=j2.

GRID DUMP
- Checks: check structure GRID.
- Action: print "GRID DUMP rows=<h> cols=<w>", then, for p=1, 2, ..., h in this order, print "ROW <p> <U[p][1]> <U[p][2]> ... <U[p][w]>".

[Output format]
- For each command, print only the lines described in [Processing]. Every command prints one or more lines.
- Words and values within a line are separated by single spaces, as described. Put no spaces at the beginning or end of a line, and print no empty lines. End every line with a newline.
- Integers are written in decimal without extra leading zeros, with a leading "-" for negative numbers ("-0" is never written). op is written exactly as it appears in the input.
- The error lines are of the following 11 kinds (the parts in < > are replaced with the corresponding name or integer).
  ERROR NOT BUILT <S>
  ERROR BAD OP <op>
  ERROR BAD INDEX <i>
  ERROR BAD RANGE <l> <r>
  ERROR NEGATIVE <i>
  ERROR BAD BLOCK <b>
  ERROR BAD VERSION <ver>
  ERROR BAD K <k>
  ERROR BAD COUNT <k> <value of h*w>
  ERROR BAD CELL <i> <j>
  ERROR BAD RECT <i1> <j1> <i2> <j2>

[Constraints]
- 1 <= n <= 2000, and the k of LOAD is also at least 1 and at most 2000.
- 1 <= N <= 1000
- Each line is at most 30000 characters long.
- The values on line 2 of the input, v1 to vk of LOAD, x of each command, and v1 to vk of GRID BUILD all have absolute value at most 10^9.
- l, r, i, j, ver, i1, j1, i2, j2, lj, rj and the k of PERSIST KTH are integers with absolute value at most 10^6 (they may be out of range, in which case an error results as described in [Processing]).
- The k of FEN LOWER satisfies 1 <= k <= 10^12, and the b of SQRT BUILD satisfies 1 <= b <= 10^6.
- The number k of pairs of MO is at least 1 and at most 100.
- GRID BUILD: 1 <= h <= 20, 1 <= w <= 20, and the number of values k is at least 0 and at most 400.
- The input is constructed so that, when the procedures of [Processing] are performed exactly as written, every integer that appears along the way (values such as the contents, node values, tags, T, B1, B2 and U, as well as intermediate products and sums of computations) has absolute value less than 2^53.
