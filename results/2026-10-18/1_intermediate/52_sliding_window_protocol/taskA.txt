[Overview]
Write a program that simulates sliding window protocols, which reliably deliver frames over a channel where frames can be lost or corrupted, using integer time steps (called "ticks" below) as the unit of time. No real network communication is performed. Three protocols are handled: Stop-and-Wait (SW), Go-Back-N (GBN) and Selective Repeat (SR). The program reads several scenarios from standard input, checks the settings of each scenario, and, if they are valid, outputs a timeline that describes the actions of the sender and the receiver in time order, one per line, followed by per-frame records and statistics. Finally, it outputs a ranking of the completed scenarios and a per-protocol summary.

[Input format]
The first line is the number of scenarios Q. Q scenario blocks follow, each of the following form.

SCENARIO name
key value ...
...
END

The first line of a block is "SCENARIO" and a name, the last line is a line consisting only of "END", and the zero or more lines between them are setting lines. A setting line consists of a key word followed by zero or more values. Keys and values are specified as follows (setting lines whose number of values or ranges do not match this specification may also appear in the input; they are treated as errors in 1 of [Processing]).

Required keys (each takes exactly 1 value):
- PROTOCOL p: the protocol. One of SW, GBN, SR.
- FRAMES n: the number of frames to send. Between 1 and 60 inclusive.
- WINDOW w: the size of the send window. Between 1 and 32 inclusive.
- SEQBITS k: the number of bits of the sequence number. Between 1 and 6 inclusive. Below, M = 2^k.
- TIMEOUT T: the length of the retransmission timer (in ticks). Between 1 and 50 inclusive.
- DELAY d: the one-way propagation delay (in ticks). Between 1 and 10 inclusive.

Optional keys (the treatment when omitted is given in parentheses):
- INTERVAL g (0): 1 value, between 0 and 10 inclusive. Frame f cannot be sent for the first time before tick f*g.
- MAXTICKS L (1000): 1 value, between 1 and 2000 inclusive. The tick at which the simulation is cut off.
- DUPACK m (not used): 1 value, between 1 and 10 inclusive. The number of duplicate ACKs that triggers a fast retransmission.
- NAK x (OFF): 1 value, ON or OFF. Whether negative acknowledgements (NAKs) are used.
- BACKOFF x (OFF): 1 value, ON or OFF. Whether the timer length is doubled at every timeout.
- CONGESTION x (OFF): 1 value, ON or OFF. Whether a congestion window is used.
- UNSAFE x (OFF): 1 value, ON or OFF. Whether the check of the upper limit of the window size is skipped.
- TRACE x (ALL): 1 value, one of ALL, SENDER, RECEIVER, NONE. Which lines are written to the timeline.
- RANDOM s p c (not used): 3 values. Random loss and corruption. s is the seed, between 1 and 2147483646 inclusive; p is the probability of loss (in percent) and c is the probability of corruption (in percent), with p >= 0, c >= 0 and p+c <= 100.
- LOSEDATA i ... (none): the numbers of the data transmissions that are lost on the channel.
- LOSECTRL j ... (none): the numbers of the control frames that are lost on the channel.
- CORRUPTDATA i ... (none): the numbers of the data transmissions that are corrupted.
- CORRUPTCTRL j ... (none): the numbers of the control frames that are corrupted.
- DELAYDATA i:e ... (none): delays the arrival of data transmission number i by e extra ticks.
- DELAYCTRL j:e ... (none): delays the arrival of control frame number j by e extra ticks.
- SNAPSHOT t ... (none): the ticks at which a state summary is output.
The seven keys from LOSEDATA to SNAPSHOT take one or more values. Each value of LOSEDATA, LOSECTRL, CORRUPTDATA and CORRUPTCTRL, and the number before ":" in each value of DELAYDATA and DELAYCTRL, is between 1 and 9999 inclusive; the extra delay e after ":" is between 1 and 50 inclusive; each value of SNAPSHOT is between 0 and 2000 inclusive. In addition, within the same key, the same number (for DELAYDATA and DELAYCTRL the number before ":", for SNAPSHOT the tick) must not appear two or more times.

The following is guaranteed about the input.
- Words are separated by a single ASCII space, there is no whitespace at the beginning or end of a line, and there are no empty lines.
- A scenario name is a string of 1 to 16 characters consisting of English letters, digits, "_" and "-", and names differ between scenarios.
- The first word (the key) of a setting line consists of uppercase English letters, digits and "_", and is not SCENARIO or END. It may be a word that is not in the list above.
- A value is a sequence of printable ASCII characters without spaces. The values of FRAMES, WINDOW, SEQBITS, TIMEOUT, DELAY, INTERVAL, MAXTICKS, DUPACK, RANDOM, LOSEDATA, LOSECTRL, CORRUPTDATA, CORRUPTCTRL and SNAPSHOT are decimal integers of 1 to 9 digits, possibly preceded by "-" (there are no numbers of two or more digits starting with 0, and no "-0"). The values of DELAYDATA and DELAYCTRL are two such integers joined by ":". The values of PROTOCOL, NAK, BACKOFF, CONGESTION, UNSAFE and TRACE, and the values of keys not in the list, have no further restrictions.
- Word comparisons are case-sensitive.

[Processing]
1. Checking the settings
For each scenario, perform the checks (1) to (6) below in this order, and report only the first error found. A scenario with an error is not simulated. Below, K is a key, W, U, I and J are integers in decimal notation, and P is the value of PROTOCOL.
(1) Examine the setting lines from top to bottom, and for each line test (a) to (c) in this order.
  (a) The key is not in the list above: "unknown key K"
  (b) The same key already appears on an earlier line: "duplicate key K"
  (c) The number of values does not match the specification (3 for RANDOM, one or more for the seven keys from LOSEDATA to SNAPSHOT, 1 for all others): "wrong number of values for K"
(2) Examine the required keys in the order PROTOCOL, FRAMES, WINDOW, SEQBITS, TIMEOUT, DELAY, and if one is missing: "missing key K"
(3) Examine the specified keys in the order PROTOCOL, FRAMES, WINDOW, SEQBITS, TIMEOUT, DELAY, INTERVAL, MAXTICKS, DUPACK, NAK, BACKOFF, CONGESTION, UNSAFE, TRACE, RANDOM, LOSEDATA, LOSECTRL, CORRUPTDATA, CORRUPTCTRL, DELAYDATA, DELAYCTRL, SNAPSHOT, and if a value does not satisfy the specification above (allowed words, ranges, prohibition of duplicates): "bad value for K"
(4) PROTOCOL is SR and DUPACK is specified: "DUPACK not supported for SR"
(5) Let the upper limit U of the window size be 1 for SW, 2^k - 1 for GBN and 2^(k-1) for SR. If w > U: "window W exceeds limit U for P" (W is the value of w). However, when UNSAFE is ON and PROTOCOL is GBN or SR, this check is not performed.
(6) If some number appears in both LOSEDATA and CORRUPTDATA, then for the smallest such number I: "data #I both lost and corrupted". Otherwise, if some number appears in both LOSECTRL and CORRUPTCTRL, then for the smallest such number J: "control #J both lost and corrupted"

2. Terms and state
- In this task, "a mod b" denotes the remainder of a divided by b, expressed as a value at least 0 and less than b (the same applies when a is negative).
- Frames have frame numbers from 0 to n-1, and the sequence number of frame f is f mod M. Besides its sequence number, a data frame carries the frame number itself as its payload. The receiver acts only on the sequence number; the payload is used only to judge whether a delivery is correct.
- Each time the sender sends a data frame, the transmission is given a "data transmission number", counting from 1 within the scenario (a retransmission is also one transmission). Each time the receiver sends a control frame (ACK or NAK), it is given, separately, a "control frame number", counting from 1. The numbers in keys such as LOSEDATA refer to these numbers.
- The sender has the following state. base: the smallest frame number not yet acknowledged. H: the number of frames that have been sent at least once so far (frames 0 to H-1 have been sent). C: the current timer length (initially T). In addition, for GBN the sender has the frame number to send next, next, one timer, and a count D of duplicate ACKs. For SR it has, for each frame, an acknowledged mark and a timer, and a retransmission queue (first in, first out).
- The effective window size E is w when CONGESTION is OFF, and the smaller of w and the congestion window cwnd (see 7 (2)) when it is ON.
- The receiver has the next position to deliver, r (initially 0), and a NAK-sent mark. For SR it additionally has a buffer that holds pairs of a position and a payload.
- A timer is either stopped or holds one expiry tick. Initially, base = H = next = D = 0, all timers are stopped, no mark is set, and the retransmission queue and the buffer are empty.
- SW behaves by exactly the same rules as GBN (for SW, w is always 1). The rules written below for GBN also apply to SW.
- When a frame is obtained from a number a, use f = base + ((a-base) mod M). This is the smallest frame number at least base whose sequence number is a.

3. Channel
- A transmission made at tick t arrives at the other side at tick t+d (for a transmission for which an extra delay e is specified by DELAYDATA or DELAYCTRL, at tick t+d+e).
- The outcome of each transmission (normal, lost, corrupted) is determined at the moment it is sent, as follows. When RANDOM is specified, the random number generator is advanced once per transmission, in the order in which the transmissions occur, regardless of whether it is a data frame or a control frame. The generator starts from x0 = s, and each advance sets x = (48271*x) mod 2147483647. For x after advancing, let v = x mod 100; if v < p the transmission is lost, if p <= v < p+c it is corrupted, and otherwise it is normal. On top of that, if the number of the transmission is in LOSEDATA (LOSECTRL for a control frame) it is lost, and if it is in CORRUPTDATA (CORRUPTCTRL for a control frame) it is corrupted; this takes precedence over the random result (the generator is still advanced once in this case). If the number is in no list and RANDOM is not specified, the transmission is normal.
- Even if lists such as LOSEDATA, or DELAYDATA and DELAYCTRL, contain the number of a transmission that never actually occurred, that number has no effect.
- For a lost transmission, only a LOST line is output at the tick at which it would have arrived; nothing happens at the other side. For a corrupted transmission, a CORRUPT line is output at the tick at which it arrives, and the receiving side discards it and does nothing else.

4. Processing at each tick
For ticks t = 0, 1, 2, ... in this order, perform the following steps 1 to 6 at each tick.
Step 1: The receiver processes the data frames arriving at tick t in increasing order of data transmission number (see 5). The LOST and CORRUPT lines of lost or corrupted transmissions are also output within this order, at the tick at which they arrive (or would have arrived) (see 3).
Step 2: The sender processes the control frames arriving at tick t in increasing order of control frame number (see 6). LOST and CORRUPT lines are handled as in step 1.
Step 3: If base = n at this point, t is the completion tick; skip steps 4 and 5 and go to step 6.
Step 4: Process timeouts (see 6 (5)).
Step 5: Send at most one data frame (see 6 (6)).
Step 6: If t is equal to one of the SNAPSHOT values, output the state summary line. Then, if the scenario completed in step 3, output "t DONE" and end the simulation of this scenario. If it has not completed and t = L, output "t ABORT" and end the simulation (aborted). Otherwise, go to the next tick.
Transmissions that are still in transit on the channel when the simulation ends are not processed, and SNAPSHOT values that refer to ticks after the end of the simulation produce no output.

5. Receiver rules
When an uncorrupted data frame (sequence number s, data transmission number i) arrives, first output "t RECV seq=s #i", then process it according to (1) or (2) below. Here, to "deliver" means to pass the frame to the upper layer as the frame for position r and output a DELIVER line, increase r by 1, and clear the NAK-sent mark. If the payload of the delivered frame is equal to r (before the increase), the delivery is a correct delivery; otherwise it is a wrong delivery. To "discard" means to output "t DISCARD seq=s".
(1) GBN
  - If s = r mod M, deliver the arriving frame and send ACK s.
  - Otherwise, discard it. Then, if NAK is ON and the NAK-sent mark is not set, send NAK (r mod M) and set the mark. Otherwise, if r > 0 send ACK ((r-1) mod M), and if r = 0 send nothing.
(2) SR: let o = (s-r) mod M.
  - If o < w, the arriving frame is regarded as the frame for position r+o.
    * If a pair for position r+o is already in the buffer, discard it and send ACK s.
    * Otherwise, if o = 0, deliver the arriving frame, and then, as long as a pair for position r is in the buffer, repeatedly remove it from the buffer and deliver its payload. After that, send ACK s.
    * Otherwise, put the pair of position r+o and the payload into the buffer, output "t BUFFER f=F" (F = r+o), and send ACK s. Then, if NAK is ON and the NAK-sent mark is not set, send NAK (r mod M) and set the mark.
  - If o >= w, discard it. In addition, if (r-s) mod M is at most w (the frame is regarded as a retransmission of an already delivered frame), send ACK s.
When sending a control frame, output "t ACK a=A #j" or "t NAK a=A #j" (A is the number it carries, j is the control frame number).

6. Sender rules
When an uncorrupted control frame arrives, (1) or (2) below decides whether it is accepted. If it is accepted, output "t GOTACK a=A #j base=B" or "t GOTNAK a=A #j base=B" (A is the carried number, j is the control frame number, B is base after processing); if it is not accepted, output "t OLDACK a=A #j" or "t OLDNAK a=A #j".
(1) On receiving ACK a: obtain f by the method in 2.
  - GBN: if f < H, accept it and set base to f+1 (frames base to f are acknowledged). If next < base, set next = base. Then, if base = next, stop the timer; otherwise, set the expiry tick of the timer to t+C.
  - SR: accept it if f < H and frame f does not have the acknowledged mark. Set the mark on f, stop the timer of f, and remove f from the retransmission queue if it is there. Then, while base < H and frame base has the mark, increase base by 1.
(2) On receiving NAK a: obtain f by the method in 2.
  - GBN: if f <= H, accept it, set base to f (frames base to f-1 are acknowledged), and perform a "go-back".
  - SR: accept it if f < H and frame f does not have the mark. Stop the timer of f, and append f to the end of the retransmission queue if it is not in it.
(3) "Go-back" (GBN only): set next to base, stop the timer, and set D to 0.
(4) Whenever base increases, by whichever rule, set C = T, and for GBN set D = 0 (the C used when setting the timer in the GBN case of (1) is the value after this). Also, for each frame, record the first tick at which it was acknowledged at the sender (for GBN, the tick at which base became greater than that frame number; for SR, the tick at which the mark was set on that frame).
(5) Timeouts (step 4)
  - GBN: if the expiry tick of the timer is t, output "t TIMEOUT f=F" (F = base) and perform a "go-back".
  - SR: examine the frames numbered at least base and less than H in increasing order of number, and for each one whose timer's expiry tick is t, stop the timer, append the frame to the end of the retransmission queue, and output "t TIMEOUT f=F" (F is that frame number).
  Each time one timeout occurs, if BACKOFF is ON, set C = min(2C, 8T).
(6) Sending (step 5)
  - GBN: if next < n and next < base+E, and furthermore next < H or next*g <= t, send frame next, set H = max(H, next+1), and increase next by 1. At this time, if the timer is stopped, set its expiry tick to t+C.
  - SR: if the retransmission queue is not empty, remove the frame at its front and send it. If it is empty, send frame H and increase H by 1 when H < n, H < base+E and H*g <= t all hold. In either case, set the expiry tick of the timer of the sent frame to t+C.
  The sending line is "t SEND f=F seq=S #i" for the first transmission of the frame, and "t RESEND f=F seq=S #i" for the second and later transmissions (F is the frame number, S is its sequence number, i is the data transmission number).

7. Additional features
(1) DUPACK (GBN only): for an ACK a that was not accepted, after outputting the OLDACK line, if base >= 1 and a = (base-1) mod M, increase D by 1. When D reaches m, output "t FASTRETX f=F" (F = base) and perform a "go-back".
(2) CONGESTION: when it is ON, the sender has a congestion window cwnd (initially 1), a threshold ssthresh (initially w) and a counter A (initially 0).
  - For each newly acknowledged frame (f-base+1 frames for a GBN ACK, f-base frames for a GBN NAK, where base is the value before processing; 1 frame for an SR ACK), only if cwnd < w: if cwnd < ssthresh, increase cwnd by 1; otherwise, increase A by 1, and when A = cwnd, increase cwnd by 1 and set A = 0.
  - Each time one timeout occurs: set ssthresh = max(floor(cwnd/2), 1), cwnd = 1 and A = 0.
  - When a NAK is accepted, and on FASTRETX: set ssthresh = max(floor(cwnd/2), 1), cwnd = ssthresh and A = 0. For a GBN NAK, the increase above is performed first, and then this decrease.
  - When the pair (cwnd, ssthresh) differs between before and after the processing of one control frame or the processing of one timeout, output "t CWND c ssthresh=s" (c and s are the values after processing) after the last line output by that processing.
(3) When a window exceeding the upper limit is used with UNSAFE, or when the arrival order of frames is changed by extra delays, the sender or the receiver may mistake an old frame or an old acknowledgement for a new one, and wrong deliveries can also occur. These cases are also processed exactly by the rules above. The receiver position r or a position put into the buffer may become n or more; these cases are also processed by the same rules (since the payload is always less than n, a delivery to a position n or more is a wrong delivery).

[Output format]
For each scenario, in input order, output the following.
- The first line is "== name ==".
- If the settings contain an error, output on the second line "error: " followed by the message from 1, and end the output of that scenario.
- If there is no error, output the following two lines.
  "config: P n=N w=W k=K T=X d=Y" (N, W, K, X and Y are the values of n, w, k, T and d respectively)
  "options: interval=G limit=L dupack=U nak=V backoff=V congestion=V unsafe=V trace=Z random=R"
  G is the value of g, L is the value of MAXTICKS, U is the value of m ("off" if DUPACK is not specified), each V is "on" or "off", Z is the value of TRACE in lowercase, and R has the form "s/p/c" ("off" if RANDOM is not specified). Omitted keys are shown with their treatment when omitted.
- Then output the timeline. Each line begins with the tick t, and the lines are in the order in which they arise under the rules of [Processing]. The kinds of lines are as follows.
  Receiver lines: "t LOST data #i", "t CORRUPT data #i", "t RECV seq=S #i", "t DELIVER f=F" (correct delivery), "t DELIVER f=F wrong=G" (wrong delivery; F is the position, G is the frame number in the payload), "t BUFFER f=F", "t DISCARD seq=S", "t ACK a=A #j", "t NAK a=A #j"
  Sender lines: "t SEND f=F seq=S #i", "t RESEND f=F seq=S #i", "t LOST ack #j", "t LOST nak #j", "t CORRUPT ack #j", "t CORRUPT nak #j", "t GOTACK a=A #j base=B", "t OLDACK a=A #j", "t GOTNAK a=A #j base=B", "t OLDNAK a=A #j", "t TIMEOUT f=F", "t FASTRETX f=F", "t CWND c ssthresh=s"
  Lines that are always output: "t SNAPSHOT sender=X receiver=Y", "t DONE", "t ABORT"
  The "data", "ack" and "nak" in LOST and CORRUPT lines are the kind of the transmission that would have arrived. If TRACE is ALL, output all lines; if SENDER, output the sender lines and the lines that are always output; if RECEIVER, output the receiver lines and the lines that are always output; if NONE, output only the lines that are always output. Lines that are not output are still counted in the statistics below.
- X and Y of the state summary line are strings of n characters each. The (f+1)-th character from the left of X (f = 0, 1, ..., n-1) is, for frame f, the first of the following that applies: "A" if it is acknowledged (for GBN f < base, for SR it has the mark), "R" if it is waiting for retransmission (for GBN next <= f < H, for SR it is in the retransmission queue), "O" if it has been sent (for GBN f < next, for SR f < H), "W" if f < base+E, and "." otherwise. The (f+1)-th character from the left of Y is, for position f, "D" if f < r, "B" if SR and a pair for position f is in the buffer, "W" if SR and f < r+w, or GBN and f = r, and "." otherwise.
- After the timeline, output one line per frame in the order f = 0 to n-1.
  "frame F: seq=S tx=X first=A delivered=B acked=C"
  F is the frame number, S is its sequence number, X is the number of times the frame was sent, A is the tick at which it was first sent, B is the tick at which it was correctly delivered to position F, and C is the first tick at which it was acknowledged at the sender. If there is no such tick, the value is "-".
- Then output the following four lines. After each "=", write the value described below.
  "totals: data=... resent=... control=... nak=... timeouts=... fastretx=..."
  "channel: lost_data=... lost_ctrl=... corrupt_data=... corrupt_ctrl=..."
  "receiver: delivered=... errors=... discarded=... max_buffer=..."
  "result: completion=... goodput=... efficiency=...% utilization=...% latency=..."
  data: the total number of SEND and RESEND lines (the total number of data transmissions; written X below). resent: the number of RESEND lines. control: the number of control frames sent. nak: the number of NAKs among them. timeouts: the number of TIMEOUT lines. fastretx: the number of FASTRETX lines.
  lost_data: the number of "LOST data" lines. lost_ctrl: the total number of "LOST ack" and "LOST nak" lines. corrupt_data: the number of "CORRUPT data" lines. corrupt_ctrl: the total number of "CORRUPT ack" and "CORRUPT nak" lines.
  delivered: the number of correct deliveries (written D below). errors: the number of wrong deliveries. discarded: the number of DISCARD lines. max_buffer: the maximum number of pairs held in the SR buffer at the same time (0 for GBN).
  completion: the completion tick ("-" if aborted). goodput: D / completion tick ("-" if aborted). efficiency: D / X * 100. utilization: X / (t_end+1) * 100 (t_end is the tick at which DONE or ABORT was output). latency: the average, over the correctly delivered frames, of (tick of delivery - tick of first transmission) ("-" if D = 0).
  goodput and latency are truncated (the third and later decimal places are discarded) to 2 decimal places, and efficiency and utilization are truncated (the second and later decimal places are discarded) to 1 decimal place; they are written without omitting any decimal digits (e.g. 0.30, 60.0, 5.00).

After all scenarios, output the following.
- One line "== ranking ==".
- Sort the completed scenarios in decreasing order of D / completion tick, ties broken by decreasing order of D / X, and remaining ties by input order, and output one line each, numbered from 1: "rank. name P goodput=G efficiency=V%". P is the protocol, and G and V are the same values, written in the same way, as goodput and efficiency in the result line of that scenario. Comparisons use the exact values before truncation.
- Then, for the scenarios that did not complete, in input order, output "- name invalid" for those whose settings contained an error, and "- name aborted" for those that were aborted.
- One line "== protocols ==".
- In the order SW, GBN, SR, for each protocol with at least one completed scenario, output "P: runs=N goodput=G efficiency=V%". N is the number of completed scenarios, G is (sum of D) / (sum of completion ticks) over those scenarios, and V is (sum of D) / (sum of X) * 100, written in the same way as above.

All output consists of ASCII characters. Items within a line are separated by a single ASCII space, no line has trailing whitespace, and every line ends with a newline. No empty lines are output.

[Constraints]
- 1 <= Q <= 60. The input has at most 1000 lines, and each line has at most 200 characters.
- Intermediate values of the random number computation are at most 48271*2147483646 (less than 2^47), so they can be computed exactly with 64-bit integers. All other values fit in 32-bit signed integers.
- The simulation always ends by tick L, so one scenario has at most 2001 data transmissions.
