[Overview]
Write a bill-splitting program that records expenses shared during a group trip or in a shared house and works out who owes whom among the members. It reads commands from standard input one line at a time and writes, for each command, a result in a fixed format to standard output.
All money is handled as integers counted in units of 1/100 of the base currency (called "cents" below); floating-point numbers are not used. Each expense is divided among its participants by one of 5 split modes (equal, exact amounts, percentages, units, and equal with extras), and an expense in a foreign currency is converted into the base currency at a fixed rate. The program also handles expenses paid by several people, editing and deleting expenses, recurring expenses that repeat as the date advances, recording settlements (repayments), budgets per category, various summary tables, and computing the set of transfers needed to settle up (by a greedy method and by a method that minimizes the number of transfers).

[Input format]
The first line contains N, the number of command lines that follow. Lines 2 through N+1 each contain one command. Each line is a sequence of tokens separated by single ASCII spaces, with no whitespace at the start or end of the line. The program ends after processing all N command lines.

The token formats are as follows.
- Name: 1 to 10 lowercase English letters (example: alice).
- Expense ID: 1 to 10 characters consisting of lowercase English letters and digits (examples: dinner, x3). It is given to a new expense by EXPENSE.
- Expense reference: a string that designates an expense; it has the form of an expense ID or the form of the ID of a recurring-expense copy described later (examples: gym#2, gym#2#2).
- Category: 1 to 12 lowercase English letters.
- Currency code: 3 uppercase English letters (example: EUR).
- Amount: an integer part and a fractional part joined by ".". The integer part is a decimal number from 0 to 99999 inclusive with no extra leading zeros. The fractional part has exactly 2 digits (examples: 0.07, 45.50, 900.00). The amount "a.bc" represents the integer a*100+bc counted in units of 1/100.
- Amount spec: either an amount alone (an amount in the base currency), or an amount immediately followed by "@" and a currency code (an amount in that foreign currency; example: 45.50@EUR).
- Day, number of days, rate, basis points, units: non-negative decimal integers with no extra leading zeros.

There are the following 23 kinds of commands. Each <...> part holds a token in the format above, and "..." means that the preceding element appears one or more times.
DAY <day>
MEMBER <name>
LEAVE <name>
CURRENCY <currency code> <rate>
EXPENSE <expense ID> <payer name> <amount spec> <category> <split mode> <participant spec>...
EDIT <expense reference> <payer name> <amount spec> <category> <split mode> <participant spec>...
PAYERS <expense reference> <name>:<amount>...
DELETE <expense reference>
RECURRING <expense reference> <number of days>
SETTLE <name of the sender> <name of the receiver> <amount spec>
BUDGET <category> <amount>
BALANCES
OWES <name>
HISTORY <name>
MATRIX
CATEGORY
BUDGETS
TOTALS
MEMBERS
One of EXPENSES ALL, EXPENSES CATEGORY <category>, EXPENSES MEMBER <name>, EXPENSES DAYS <day1> <day2>
PERIODS <number of days>
SHOW <expense reference>
One of SIMPLIFY GREEDY, SIMPLIFY OPTIMAL

The split mode is one of EQUAL, EXACT, PERCENT, SHARES, ADJUST, and the format of the participant specs depends on the split mode as follows.
- EQUAL: one or more <name>, or the single token "ALL" alone.
- EXACT: one or more <name>:<amount>.
- PERCENT: one or more <name>:<basis points>. Basis points are an integer from 0 to 10000 inclusive, where 10000 represents 100%.
- SHARES: one or more <name>:<units>. Units are an integer from 0 to 1000 inclusive.
- ADJUST: one or more items, each either <name> or <name>:<amount> (the amount is the extra amount).
The amounts in EXACT and ADJUST, and the amounts in PAYERS, never carry "@". They are amounts written in the currency of the expense (the foreign currency for a foreign-currency expense, the base currency for a base-currency expense).

[Processing]
== State and initial state ==
- Current day: initially 1.
- Members: initially there are none. A name registered by MEMBER has one of two statuses, "active" or "left", and it stays a "registered" name even after leaving. Each member has a "status day" (the day of the most recent join, rejoin or leave).
- Currencies: initially only the base currency exists. The base currency has no code; an amount spec without "@" is an amount in the base currency. Foreign currencies are defined by CURRENCY.
- Expenses, settlements, budgets: initially there are none.
- Record number: expenses added by EXPENSE, recurring-expense copies created by DAY, and settlements recorded by SETTLE receive a common serial number (the record number) 1, 2, 3, ... in the order they are created. EDIT and PAYERS do not change the record number.
- Used IDs: an ID that has ever been given to an expense (including IDs of deleted expenses and of copies) becomes used and can never be used again. An ID written in a command that resulted in an error does not become used.
A command that results in an error does not change the state at all; it only outputs one error line.

== Ordering rules ==
"Ascending order" of names, categories and currency codes is lexicographic order by character code (ASCII) (when one is a prefix of the other, the shorter one comes first). "Chronological order" of expenses and settlements is ascending order of day, and for the same day, ascending order of record number.

== Currency conversion ==
A foreign amount (an integer a counted in units of 1/100) is converted, using that currency's rate r, by computing a*r/10000 and rounding the fractional part half up (exactly 0.5 rounds up) to an integer number of cents. That is, the converted amount is floor((a*r+5000)/10000). The rate r is the integer equal to 100 times "how many cents one unit of that foreign currency is worth"; for example, CURRENCY EUR 10850 means that 1 EUR is 108.50 cents (1.0850 units of the base currency). Conversion always uses the rate at that moment; changing a rate does not change the amounts of expenses or settlements that were already computed.

== Two distribution methods ==
Equal distribution: to distribute an integer T equally among k people in a fixed order, let q = floor(T/k) and m = T mod k, and assign q+1 to the first m people in that order and q to the rest.
Largest-remainder distribution: to distribute an integer T among k people in a fixed order with non-negative integer weights w1, ..., wk (whose sum W is at least 1), first assign floor(T*wi/W) to each person i and record the remainder (T*wi) mod W. Let L be the amount by which the sum of the assignments falls short of T (L is less than k); add 1 to each of L people in descending order of remainder (when remainders are equal, the person earlier in the order has priority).

== Computing an expense ==
An expense has a day, a record number, a list of payers (names, and payments in the expense's currency), an amount A (an integer counted in units of 1/100 of the expense's currency), a currency, a category, a split mode, and a list of participants (names and specified values). An expense created by EXPENSE or EDIT has one payer, whose payment is A (PAYERS can change this to several people). The following three things are computed from an expense.
1. Total T: the converted amount of A (for a base-currency expense, T = A).
2. Share of each participant: first, as stage 1, divide A among the participants according to the split mode and obtain each person's portion s1, ..., sk in the expense's currency (their sum is A).
  - EQUAL: distribute A equally among the participants.
  - EXACT: each person's specified amount is taken as the portion as it is. The condition is that the specified amounts add up to exactly A.
  - PERCENT: distribute A by largest remainder with the basis points as weights. The condition is that the basis points add up to exactly 10000.
  - SHARES: distribute A by largest remainder with the units as weights. The condition is that the units add up to at least 1.
  - ADJUST: a participant written without an amount has an extra amount of 0. The condition is that the sum E of the extra amounts is at most A. Each person's portion is that person's part of the equal distribution of A-E among the participants plus that person's extra amount.
  Next, as stage 2, distribute T by largest remainder with s1, ..., sk as weights, and take the result as the participants' shares (in cents). For a base-currency expense, the shares equal the portions.
3. Contribution of each payer: T distributed by largest remainder with each payer's payment (in units of 1/100 of the expense's currency) as weights. For a base-currency expense, the contributions equal the payments.
The order used for distribution is the order in which the participants or payers are written. When ALL is given with EQUAL, the participant list is all members active at the time that command is processed, in ascending order of name, and that list is recorded in the expense. The same name may appear both as a payer and as a participant.

== Balances ==
A member's balance is (the sum of that member's contributions) - (the sum of that member's shares) over all existing expenses, plus the amounts that member paid and minus the amounts that member received over all settlements. A member with a positive balance is on the receiving side, and a member with a negative balance is on the paying side. Because of rules such as "frozen expenses" described later, the balance of a member who has left is always 0.

== Debts between members (used by OWES and MATRIX) ==
For each existing expense, compute the net amount (contribution - share in that expense) of each member who appears in that expense. List the members with a negative net amount (borrowers) in ascending order of name, and the members with a positive net amount (lenders) in ascending order of name. Between the first borrower and the first lender, take the smaller of the borrower's remaining deficit and the lender's remaining surplus, regard "the borrower owes the lender" that amount, and subtract it from both remainders. A borrower whose remainder becomes 0 is replaced by the next borrower, and a lender whose remainder becomes 0 is replaced by the next lender (if both become 0, both advance); when either list is exhausted, that expense is done. The amounts obtained this way are summed for each pair of members. A settlement "x paid y v cents" is treated as subtracting v from the amount x owes y. Finally, the net debt of the pair x and y is (the total amount x owes y) - (the total amount y owes x); if it is positive, x owes y that amount; if negative, y owes x its absolute value; if 0, neither owes the other.

== Frozen expenses ==
An expense whose payers or participants include a member who has left is "frozen" and cannot be changed by EDIT, PAYERS or DELETE.

== Processing of each command ==
Error checks are made in the order written, and only the first error that applies is output. The text of the error lines is given in [Output format].
1. DAY d: if d is less than or equal to the current day, the error is invalid day. Otherwise, create copies of recurring expenses by the following procedure, and then set the current day to d. As long as there are recurring expenses (existing expenses for which RECURRING has set an interval of 1 or more and that setting has not been cleared yet) whose next day is <= d, select the one among them with the earliest next day (if next days are equal, the one with the smaller record number) and do one of the following.
  - If all payers and participants of that expense are active and its total converted at the current rate is 1 or more, create one copy and add the interval to that expense's next day.
  - Otherwise, create no copy and clear that expense's recurring setting (cancel).
  A copy is a new expense that has exactly the contents of the original expense (the template) at that moment (payers and payments, amount, currency, category, split mode, participants and specified values); its day is the template's next day, and its record number is a newly assigned number. Its ID is the template's ID, "#", and n joined in this order, where n is "the number of copies already made from that template + 2": the first copy gets 2, the next 3, and so on (the count continues even if the recurring setting is cleared and set again). The total, shares and contributions of a copy are computed at the rates at that moment. The ID of a copy becomes used. A copy itself is not a recurring expense, but it can be made one with RECURRING, in which case its copies get IDs such as gym#2#2.
2. MEMBER name: if name is active, the error is duplicate member. If it is not registered, register it as an active member; if it has left, make it active again (rejoin). In both cases, set that member's status day to the current day.
3. LEAVE name: if name is not registered, the error is unknown member; if it has left, inactive member; if its balance is not 0, member has a balance. Otherwise, mark it as left and set its status day to the current day.
4. CURRENCY code rate: set the rate of foreign currency code to rate (if it is already defined, replace it). There are no errors.
5. EXPENSE id payer spec category mode parts...: check in the following order.
  (a) id is used: duplicate id
  (b) payer is not registered: unknown member; has left: inactive member
  (c) the currency code of the amount spec is not defined: unknown currency
  (d) the amount A is 0, or the converted total T is 0: invalid amount
  (e) check the participants one by one in the order written: not registered: unknown member; has left: inactive member; the same name already appeared earlier: duplicate member (with ALL, nothing in this check applies)
  (f) the condition of the split mode (described above for EXACT, PERCENT, SHARES, ADJUST) is not met: splits do not add up
  If there is no error, add it as an expense of the current day, assign a record number, and mark id as used.
6. EDIT ref payer spec category mode parts...: if the expense ref does not exist, the error is unknown expense; if that expense is frozen, the error is inactive member (the name is the first member who has left found by looking through the payer list and then the participant list, in order). Then the same checks as (b) to (f) of EXPENSE are made. If there is no error, replace the contents of the expense (the payers become the single payer payer, plus the amount, currency, category, split mode and participants) and recompute it at the current rates. The day, record number, recurring setting (interval and next day) and number of copies made do not change.
7. PAYERS ref name:amount...: if the expense ref does not exist, the error is unknown expense; if it is frozen, inactive member (same as EDIT). Then check the names in the order written: not registered: unknown member; has left: inactive member; already appeared earlier: duplicate member. Finally, if the sum of the amounts differs from the expense's amount A, the error is payers do not add up. If there is no error, replace the payer list with the one written, and obtain the contributions by distributing the recorded total T again by largest remainder with the new payments as weights. No reconversion at the current rate is done here; the total and the shares do not change.
8. DELETE ref: if the expense ref does not exist, the error is unknown expense; if it is frozen, inactive member (same as EDIT). If there is no error, delete that expense. If it was a recurring expense, its recurring setting also disappears.
9. RECURRING ref k: if the expense ref does not exist, the error is unknown expense. If k is 1 or more, set that expense's interval to k and its next day to (current day + k) (if it is already a recurring expense, overwrite this). If k is 0, clear the recurring setting (it is not an error even if it was not a recurring expense).
10. SETTLE from to spec: if from is not registered, the error is unknown member; if it has left, inactive member; then the same checks for to; if from and to are the same, same member; if the currency code is not defined, unknown currency; if the amount is 0 or the converted amount is 0, invalid amount. If there is no error, record the settlement "from paid to the converted amount" with the current day and a new record number. Settlements cannot be undone.
11. BUDGET category amount: if amount is 0.00, delete the budget of that category (it is not an error if there is no budget); otherwise, set the budget of that category to amount (in cents) (replacing it if it already exists).
12. BALANCES, MATRIX, CATEGORY, BUDGETS, TOTALS, MEMBERS, EXPENSES ALL, EXPENSES CATEGORY, EXPENSES DAYS, PERIODS, SIMPLIFY GREEDY: output the summary without changing the state. There are no errors.
13. OWES name, HISTORY name, EXPENSES MEMBER name: if name is not registered, the error is unknown member (a member who has left may be specified). The state is not changed.
14. SHOW ref: if the expense ref does not exist, the error is unknown expense. The state is not changed.
15. SIMPLIFY OPTIMAL: if 13 or more members have a non-zero balance, the error is too many members. The state is not changed.

== Budget warnings ==
After a successful EXPENSE or EDIT, and each time DAY creates one copy, if the category of that expense (for EDIT, the category after the change) has a budget and the sum of the totals of all existing expenses in that category (called the "spent amount" below) exceeds the budget, output one warning line.

== Simplifying transfers (the state is not changed) ==
SIMPLIFY GREEDY: copy the balances of the members with a non-zero balance, and repeat the following transfer until all of them are 0. The member with the smallest (most negative) balance (if tied, the one first in ascending order of name) is the sender, and the member with the largest balance (if tied, the one first in ascending order of name) is the receiver; the transfer amount is the smaller of the absolute value of the sender's balance and the receiver's balance, which is added to the sender's balance and subtracted from the receiver's balance.
SIMPLIFY OPTIMAL: consider dividing all members with a non-zero balance into non-empty groups, each of whose balances sum to 0. A division with the maximum number of groups is optimal, and then the minimum number of transfers is (number of members) - (number of groups). When there are several optimal divisions, a single one is fixed by deciding the groups one at a time as follows. Among the members not yet in a group, let p be the first one in ascending order of name. The candidates are the sets of members that contain p, whose balances sum to 0, and such that, even if it is chosen as the next group, the overall number of groups can still reach the maximum depending on how the remaining members are divided; among the candidates, the one whose "list of member names in ascending order" is lexicographically smallest becomes the next group. This is repeated until every member is in a group. Lists are compared name by name from the beginning, and when one is a prefix of the other, the shorter one is smaller. Within each group, the transfers are decided by the same method as SIMPLIFY GREEDY using only the balances of that group's members (the number of transfers then is the group's number of members - 1). Since there are at most 12 members, this can be found by dynamic programming over subsets of the members (at most 4096 of them).

[Output format]
For each command, output one or more lines in the formats below. Text inside double quotes is written exactly as shown, in ASCII characters, and each <...> part is replaced by a value. Except for indentation and the column alignment of MATRIX, every space between tokens is a single ASCII space. "(indent 2)" means that the line starts with 2 ASCII spaces, and "(indent 4)" means that the line starts with 4 ASCII spaces. The output consists of ASCII characters only; no line has trailing spaces, and every line ends with a newline (LF). No empty lines are output.

== Number notation ==
- Amount notation: a number of cents c >= 0 is written as the integer part of c/100 (a decimal number with no extra leading zeros), ".", and c mod 100 as 2 digits (with a leading 0 when it has one digit), in this order (examples: 0.07, 16.50, 1200.00). A foreign amount A is written the same way.
- Signed amount notation: if c > 0, "+" followed by the amount notation of c; if c < 0, "-" followed by the amount notation of -c; if c = 0, "0.00" (examples: +60.41, -4.50).
- Percentage notation: for a part p and a whole w (w > 0), compute x = floor(p*10000/w) and write the integer part of x/100, ".", x mod 100 as 2 digits, and "%", in this order. Digits from the third decimal place on are truncated (examples: 42.85%, 100.00%, 118.56%).
- Rate notation: for a rate r, the integer part of r/10000, ".", and r mod 10000 as 4 digits (missing digits are padded with leading zeros), in this order (examples: 1.0850, 0.0068).
Below, every amount not otherwise specified is written in amount notation. Integers such as days, numbers of days and counts are written as decimal numbers with no extra leading zeros.

== Currency note ==
At each position marked {currency note} in the formats below, write " [<amount A> <currency code>]" (including the one leading ASCII space; for example, after a total it looks like "49.60 [45.50 EUR]") if the expense or settlement concerned is in a foreign currency, and write nothing if it is in the base currency. Lines not marked {currency note} never get it.

== Output of each command (on success) ==
- DAY: the first line is "DAY <d>". Then, for each copy-processing step, in the order processed, output (indent 2) "RECUR <ID of the copy> <total of the copy>" if a copy was made, or (indent 2) "CANCEL <ID of the template>" if it was cancelled. A RECUR line is followed by a warning line when needed.
- Warning line: (indent 2) "WARNING <category> over budget by <spent amount - budget>"
- MEMBER: "MEMBER <name> joined" for a new registration, "MEMBER <name> rejoined" for a rejoin.
- LEAVE: "LEAVE <name>"
- CURRENCY: "CURRENCY <currency code> <rate notation of the new rate>". If the rate of an already defined currency was replaced, append " was <rate notation of the old rate>".
- EXPENSE: "EXPENSE <expense ID> <total>{currency note} = <name of participant 1> <share of participant 1> + <name of participant 2> <share of participant 2> + ...". All participants are listed in the order of the participant list (including those whose share is 0), and the name-share pairs are separated by " + ". With a single participant, " + " does not appear. After that, a warning line follows when needed.
- EDIT: the same as EXPENSE (including the warning line), except that the first word is "EDIT" and the expense reference is written in place of the expense ID.
- PAYERS: "PAYERS <expense reference> <total>{currency note} = <name of payer 1> <contribution of payer 1> + ...". The payers are listed in the new payer order.
- DELETE: "DELETE <expense reference>"
- RECURRING: if k is 1 or more, "RECURRING <expense reference> interval <k> next <next day>"; if k is 0, "RECURRING <expense reference> stopped".
- SETTLE: "SETTLE <sender> -> <receiver> <converted amount>{currency note}"
- BUDGET: "BUDGET <category> <budget>" when a budget was set, "BUDGET <category> removed" when it was deleted.
- BALANCES: the first line is "BALANCES". Then, for each active member in ascending order of name, one line (indent 2) "<name> <signed amount notation of the balance>".
- OWES name: the first line is "OWES <name>". Then examine the registered members y other than name (including members who have left) in ascending order of name, and output one line if the net debt of the pair name and y is not 0: (indent 2) "<name> owes <y> <amount>" if name owes y, or (indent 2) "<y> owes <name> <amount>" if y owes name.
- HISTORY name: the first line is "HISTORY <name>". Then output, in chronological order, one line per item for the existing expenses in which name appears as a payer or participant and for the settlements that name paid or received: (indent 2) "day <day> <label> <change> balance <running total>". The label is the expense reference (ID) for an expense, and for a settlement it is the sender's name, "->", and the receiver's name joined without spaces (example: bob->carol). The change is name's (contribution - share) in that expense for an expense; for a settlement it is +(settlement amount) if name paid and -(settlement amount) if name received. The running total starts at 0 and adds the changes in order. The change and the running total are written in signed amount notation.
- MATRIX: the first line is "MATRIX". If there are no active members, then output only one line (indent 2) "(none)". If there are active members, use the active members in ascending order of name for both the rows and the columns; the cell at row r, column c is "-" if r and c are the same, and otherwise the amount notation of the net debt that r owes c (0 if r does not owe c). Let L be the maximum length of the names, and W the maximum length of the strings of all names and all cells. The second line is L ASCII spaces followed, for each column name, by "2 ASCII spaces + the name right-aligned to width W by padding on the left with ASCII spaces". The third and following lines are, for each row, the row's name left-aligned to width L by padding on the right with ASCII spaces, followed, for each cell, by "2 ASCII spaces + the cell right-aligned to width W by padding on the left with ASCII spaces".
- CATEGORY: the first line is "CATEGORY". List the categories of the existing expenses in descending order of category total (the sum of the totals of the expenses in that category) (if tied, ascending order of category), and for each category output (indent 2) "<category> <total> <percentage>". The percentage is the percentage notation of the category total relative to the sum of the totals of all existing expenses. Immediately after it, output the members whose sum of shares in that category is not 0, in descending order of the sum of shares (if tied, ascending order of name), one line each: (indent 4) "<name> <sum of shares> <percentage>". This percentage is the percentage notation of the sum of shares relative to the category total.
- BUDGETS: the first line is "BUDGETS". Output one line for each category that has a budget, in ascending order of category. With S the spent amount (0 if there are no expenses in that category) and B the budget, output (indent 2) "<category> spent <S> budget <B> used <percentage> left <B-S>" if S is at most B, or (indent 2) "<category> spent <S> budget <B> used <percentage> over <S-B>" if S exceeds B. The percentage is the percentage notation of S relative to B (it may exceed 100%).
- TOTALS: the first line is "TOTALS". Then, for every registered member (including members who have left) in ascending order of name, one line (indent 2) "<name> paid <sum of contributions> share <sum of shares> sent <sum paid in settlements> received <sum received in settlements>". Next, for each foreign currency used by at least one existing expense, in ascending order of currency code, one line (indent 2) "currency <currency code> expenses <number of expenses in that currency> amount <sum of their amounts A> base <sum of their totals>" (settlements are not counted). Finally, output (indent 2) "expenses <number of existing expenses> total <sum of their totals> settlements <number of settlements> total <sum of settlement amounts>".
- MEMBERS: the first line is "MEMBERS". Then, for every registered member in ascending order of name, one line: (indent 2) "<name> active day <status day> expenses <count>" if active, or (indent 2) "<name> left day <status day> expenses <count>" if the member has left. The count is the number of existing expenses in which that member appears as a payer or participant.
- EXPENSES: the first line is the input command line itself (example: "EXPENSES DAYS 5 12"). Then output the existing expenses matching the condition in chronological order, one line each: (indent 2) "day <day> <expense reference> <category> <total> by <list of payer names>". The list of payer names is the names joined by "," (no spaces) in the order of the payer list. Finally, output (indent 2) "count <count> total <sum of totals>" (if nothing matches, "count 0 total 0.00"). The conditions are: ALL, all expenses; CATEGORY c, expenses whose category is c; MEMBER n, expenses in which n appears as a payer or participant; DAYS d1 d2, expenses whose day is at least d1 and at most d2.
- PERIODS k: the first line is "PERIODS <k>". Group the existing expenses that have the same i = floor((day-1)/k), and for each i that has at least one expense, in ascending order of i, output (indent 2) "days <i*k+1>-<i*k+k> expenses <count> total <sum of totals>".
- SHOW: the first line is "SHOW <expense reference>". The second line is (indent 2) "day <day> category <category> mode <split mode> total <total>{currency note}". Then output, in the order of the payer list, one line per payer (indent 2) "paid <name> <contribution>", and then, in the order of the participant list, one line per participant (indent 2) "share <name> <share>"; at the end of each share line, append the following depending on the split mode. EQUAL: nothing. EXACT: " <amount notation of the specified amount>". PERCENT: " <basis points expressed as a percentage>" (for basis points b: the integer part of b/100, ".", b mod 100 as 2 digits, and "%"; examples: 33.34%, 0.00%). SHARES: " <units>/<sum of units>". ADJUST: " +<amount notation of the extra amount>" (" +0.00" if the extra amount is 0). Finally, if it is a recurring expense, output (indent 2) "recurring interval <interval> next <next day>".
- SIMPLIFY GREEDY: the first line is "SIMPLIFY GREEDY transfers <number of transfers>". Then, in the order the transfers were decided, one line per transfer: (indent 2) "<sender> -> <receiver> <transfer amount>".
- SIMPLIFY OPTIMAL: the first line is "SIMPLIFY OPTIMAL transfers <total number of transfers> groups <number of groups>". Then, in the order the groups were decided, output the line (indent 2) "group <member names in ascending order separated by single ASCII spaces>" followed by that group's transfers in the order they were decided, one line per transfer: (indent 4) "<sender> -> <receiver> <transfer amount>".
For BALANCES, OWES, HISTORY, CATEGORY, BUDGETS, MEMBERS and PERIODS, if there is no line to output after the first line, output one line (indent 2) "(none)" instead. For SIMPLIFY GREEDY and SIMPLIFY OPTIMAL, if there are no transfers, output only the first line ("transfers 0", and for OPTIMAL "groups 0").

== Error lines ==
On an error, output exactly one of the following lines. Each <...> holds the token that caused the check to fail (a name, expense ID, expense reference, currency code or day), as it was written. However, for inactive member on a frozen expense, it holds the name of the member who has left as determined in the EDIT item of [Processing].
"ERROR unknown member <name>"
"ERROR inactive member <name>"
"ERROR duplicate member <name>"

[Constraints]
- 1 <= N <= 1000.
- The input correctly follows the formats in [Input format] (there are no unknown commands, wrong numbers of tokens, or tokens that do not match their format). The only errors to detect are those listed in [Processing].
- The day of DAY, and day1 and day2 of EXPENSES DAYS, are from 1 to 10000 inclusive, and day1 <= day2. The number of days of PERIODS is from 1 to 10000 inclusive, the number of days of RECURRING is from 0 to 365 inclusive, and rates are from 1 to 100000 inclusive.
- At most 30 members are registered. A single command contains at most 30 participant specs or payers.
- DAY creates at most 500 copies in total.
- When computed by the rules above, the absolute value of every integer, including intermediate values, is less than 2 to the 53rd power (computing with 64-bit signed integers does not overflow).
