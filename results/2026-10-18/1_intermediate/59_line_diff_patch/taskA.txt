[Overview]
Write a program that computes text differences (diff), applies patches (patch) and performs three-way merges (merge). It reads a sequence of commands from standard input and, while managing texts written directly in the input as named "files", handles line-level differences in eight formats, word-level and character-level differences, difference statistics, application of unified-format patches (including searching for position offsets, fuzz, reverse application and detection of already-applied patches), execution of ed-style edit scripts, three-way merges and conflict resolution, and undoing changes, and writes the results to standard output.

[Input format]
The input is read from standard input. The first line contains the number of commands N, followed by N commands. Each command is one line consisting of the command name and zero or more arguments, separated by single spaces (there are no spaces at the beginning or end of the line). However, the command line of FILE, PATCH and EDIT is immediately followed by k "data lines", where k is given by the argument k. Data lines are not counted in the number of commands N. There are the following 15 command forms ([ ] marks an optional part, and ... means zero or more repetitions).

  FILE name k
  COPY src dst
  PRINT name
  FILES
  DIFF a b format [compare-option]...
  WORDDIFF a b
  CHARDIFF a b
  STAT a b [compare-option]...
  PATCH name k [patch-option]...
  EDIT name k
  DIFF3 base a b
  MERGE base a b out [mode]
  CONFLICTS name
  RESOLVE name i side
  UNDO name

- name, src, dst, a, b, base and out are file names: strings of 1 to 8 characters consisting of lowercase letters (a to z) and digits (0 to 9).
- format is one of BRIEF, NORMAL, ED, RCS, IFDEF m, UNIFIED n, CONTEXT n, SIDE w. IFDEF, UNIFIED, CONTEXT and SIDE are paired with the one argument that follows. m is a string of 1 to 12 characters consisting of uppercase letters, digits and "_".
- compare-option is one of the three options ICASE, IWHITE, ISPACE; each is written at most once, in any order.
- patch-option is one of the three options REVERSE, DRYRUN, FUZZ f (a pair of two words, "FUZZ" and an integer f); each is written at most once, in any order.
- mode is one of MARKERS, DIFF3, OURS, THEIRS, UNION. When omitted, it is MARKERS.
- side is one of OURS, THEIRS, BASE, BOTH.
- k, n, w, f and i are integers in decimal notation without extra leading zeros.

The data lines of FILE and EDIT are called "text lines". A text line consists of 1 to 60 printable ASCII characters (character codes 32 to 126), and its first and last characters are not spaces. The data lines of PATCH are called "patch lines". A patch line consists of 1 to 61 printable ASCII characters, and its last character is not a space. Also, in a patch line that has 2 or more characters and whose first character is a space, "-" or "+", the second character is not a space.
It is guaranteed that every line follows this format and the [Constraints]. However, the contents of patches and edit scripts are not necessarily well-formed (how they are handled is explained in [Processing]).

[Processing]
Process the commands one at a time in input order and output the results.

* Files and history
- The program manages files by name. The content of a file is a sequence of zero or more lines. Initially there are no files. Below, "line count" means the number of lines of a file or similar, and "line x" means the position counted with the first line as line 1.
- From the input constraints, it is guaranteed that every line of every file has at least 1 character and that its first and last characters are not spaces.
- "Saving content C to file X" means pushing the current content of X (or, if X does not exist, the state "does not exist") onto the end of the "history" of X, and then setting the content of X to C (creating X if it does not exist). Each file name has its own history, which is initially empty. The content of a file changes only when it is saved and on UNDO.

* Common error
If any of the following files referenced by a command does not exist, output the single line "ERROR no such file <filename>" and do nothing else for that command (its data lines are skipped). If more than one of them does not exist, report only the first one in the order written below.
  COPY: src. PRINT, PATCH, EDIT, CONFLICTS, RESOLVE: name. DIFF, WORDDIFF, CHARDIFF, STAT: a, then b. DIFF3, MERGE: base, a, then b (out of MERGE need not exist).
FILE, FILES and UNDO never produce this error.

* Line difference
Many commands compute the difference between a sequence of lines A (n lines) and a sequence of lines B (m lines) by the following procedure. Whether two lines are equal is decided by whether their "comparison keys" are equal as strings. For DIFF and STAT, the comparison key is the line with the following transformations, as specified by the compare options, applied; for all other commands it is the line itself. The transformed string is used only for comparison; the output always uses the original lines.
  ICASE: change each uppercase letter (A to Z) to the corresponding lowercase letter.
  IWHITE: remove all spaces.
  ISPACE: replace each run of 2 or more consecutive spaces with a single space.
(1) For 0 <= i <= n and 0 <= j <= m, let L(i,j) be "the length of the longest common subsequence of the first i lines of A and the first j lines of B". That is, L(i,0) = L(0,j) = 0, and when i and j are both at least 1, L(i,j) = L(i-1,j-1)+1 if line i of A and line j of B are equal, and otherwise L(i,j) is the larger of L(i-1,j) and L(i,j-1).
(2) Starting from i = n, j = m, repeat the following while i and j are both at least 1. If line i of A and line j of B are equal, make these two lines a pair of "matched lines" and decrease i and j by 1 each. Otherwise, if L(i-1,j) >= L(i,j-1), decrease i by 1; otherwise decrease j by 1.
(3) Also treat line 0 of A with line 0 of B, and line n+1 of A with line m+1 of B, as pairs of matched lines, and arrange all pairs in order of the line numbers of A (the line numbers of B are then also in increasing order). For two adjacent pairs (i,j) and (i',j'), if at least one of lines i+1 to i'-1 of A and lines j+1 to j'-1 of B consists of 1 or more lines, those lines form one "change block". Change blocks are arranged in order of the line numbers of A.
The lines of A contained in a change block are called "deleted lines", and the lines of B are called "inserted lines". For a change block, let p = i (the number of lines of A before the block), q = j (the number of lines of B before the block), x = the number of deleted lines, and y = the number of inserted lines (x >= 0, y >= 0, x+y >= 1). A change block is treated as located immediately after line p of A and line q of B (the same applies when there are no deleted lines or no inserted lines). The matched lines, excluding the pair of line 0 of A and line 0 of B and the pair of line n+1 of A and line m+1 of B, are called "common lines".

* Range notation
With s the number of lines before a range and c the number of lines in the range, the following three notations are used.
  R(s,c): "<s+1>,<s+c>" if c >= 2, "<s+1>" if c = 1, "<s>" if c = 0.
  U(s,c): "<s+1>,<c>" if c >= 2, "<s+1>" if c = 1, "<s>,0" if c = 0.
  M(s,c): always "<s+1>,<c>".
For example, when s = 4: if c = 3, R is "5,7", U is "5,3" and M is "5,3"; if c = 0, R is "4", U is "4,0" and M is "5,0".

* FILE name k
Save the following k text lines as the content of file name (if name already exists, its content is replaced), and output "FILE <name> lines=<k>".

* COPY src dst
Save the same content as the content of src to dst (src and dst may be the same), and output "COPY <src> <dst> lines=<line count>".

* PRINT name
Output "PRINT <name> lines=<line count>", then output each line of name, from the first in order, in the form "<line number>| <line content>". If the line number is shorter than 3 characters, pad it on the left with spaces to 3 characters (example: "  7| text").

* FILES
Output "FILES count=<number of existing files>", then list the existing files in lexicographic order of their names (compared by ASCII character codes; if one is a prefix of the other, the shorter one comes first), one per line, as "<name> lines=<line count> undo=<number of states stored in the history>".

* UNDO name
If the history of name is empty, output "ERROR nothing to undo <name>". Otherwise, remove the last state from the history and restore name to that state. If that state is "does not exist", delete name and output "UNDO <name> removed"; otherwise set the content of name to that state and output "UNDO <name> lines=<line count>". UNDO pushes nothing onto the history.

* DIFF a b format [compare-option]...
Compute the line difference with A = the content of a and B = the content of b. If there are no change blocks, output only "Files <a> and <b> are identical", regardless of the format. If there are change blocks, output according to the format as follows.

BRIEF: Output "Files <a> and <b> differ".

NORMAL: For each change block in order, output the following. First output "<R(p,x)><letter><R(q,y)>". The letter is c if x and y are both at least 1, d if y = 0, and a if x = 0. Then output each deleted line preceded by "< " ("<" and a space); if the letter is c, output "---"; then output each inserted line preceded by "> ".

ED: Process the change blocks from the back (from the last block to the first block). For each block, output "<R(p,x)><letter>" (the letter is the same as in NORMAL); if the letter is c or a, then output the inserted lines as they are, followed by a line consisting only of "." (for the letter d, nothing follows the "<R(p,x)>d" line).

RCS: For each change block in order, if x >= 1, output "d<p+1> <x>", and if y >= 1, output "a<p+x> <y>" followed by the inserted lines (as they are).

IFDEF m: Output the content of A and B combined into one. From the beginning in order, output each common line as the line of A as it is, and output each change block at its position as follows.
  x and y both at least 1: "#ifndef <m>", the deleted lines, "#else /* <m> */", the inserted lines, "#endif /* <m> */".
  y = 0: "#ifndef <m>", the deleted lines, "#endif /* ! <m> */".
  x = 0: "#ifdef <m>", the inserted lines, "#endif /* <m> */".

For UNIFIED n and CONTEXT n, the change blocks are grouped into "hunks". Look at the change blocks from the first in order; if the number of common lines between a block and the block just before it (the p of the block minus the p+x of the previous block) is at most 2n, put the block in the same hunk as the previous block; otherwise start a new hunk. Let F be the first change block of a hunk and G the last change block, and let c1 = min(n, p of F) and c2 = min(n, (line count of A) - (p of G) - (x of G)). The range of the hunk is, on the A side, from line (p of F) - c1 + 1 to line (p of G) + (x of G) + c2 of A, and on the B side, from line (q of F) - c1 + 1 to line (q of G) + (y of G) + c2 of B (the c1 lines before F and the c2 lines after G are common lines that show the surrounding context). Let sA be the number of lines before the A-side range and cA the number of lines in the A-side range, and similarly sB and cB for the B side.

UNIFIED n: First output "--- <a>" and "+++ <b>". Then, for each hunk, output "@@ -<U(sA,cA)> +<U(sB,cB)> @@" followed by the body of the hunk. The body is produced by walking through the A-side range from the beginning: for a common line, output " " (one space) followed by the line of A; on reaching a change block, output each deleted line of that block preceded by "-", and then each inserted line preceded by "+".

CONTEXT n: First output "*** <a>" and "--- <b>". Then, for each hunk, output the following in order.
  - "***************" (15 "*")
  - "*** <R(sA,cA)> ****"
  - Only when the hunk has 1 or more deleted lines, output each line of the A-side range in order. A common line is output preceded by "  " (two spaces). A deleted line is output preceded by "! " if the y of its change block is at least 1, or by "- " if y = 0.
  - "--- <R(sB,cB)> ----"
  - Only when the hunk has 1 or more inserted lines, output each line of the B-side range in order. A common line is output as the line of B preceded by "  ". An inserted line is output preceded by "! " if the x of its change block is at least 1, or by "+ " if x = 0.

SIDE w: Output the whole of A and B side by side. Walk through A and B simultaneously from the beginning, outputting one line for each pair of common lines and max(x,y) lines for each change block. Row t (t = 1, 2, ...) of a change block represents the pair of the t-th deleted line and the t-th inserted line if t <= x and t <= y, only the t-th deleted line if only t <= x holds, and only the t-th inserted line if only t <= y holds. Each output line is formed by concatenating, in this order: the first w characters of the "left string" (the whole string if it is shorter than w characters) padded on the right with spaces to exactly w characters, a space, the "symbol", a space, and the first w characters of the "right string" (the whole string if it is shorter than w characters); then all trailing spaces are removed. For a pair of common lines, the left is the line of A, the symbol is a space, and the right is the line of B. For a pair of a deleted line and an inserted line, the left is the deleted line, the symbol is "|", and the right is the inserted line. For a deleted line alone, the left is the deleted line, the symbol is "<", and the right is the empty string. For an inserted line alone, the left is the empty string, the symbol is ">", and the right is the inserted line.

* WORDDIFF a b / CHARDIFF a b
Compute the line difference with A = the content of a and B = the content of b. If there are no change blocks, output only "Files <a> and <b> are identical". If there are change blocks, then for each change block output one line for each t = 1, 2, ..., max(x,y) in order, and finally output one summary line.
Here each line is regarded as a sequence of "tokens". In WORDDIFF, a token is a maximal sequence of characters containing no space (a word). In CHARDIFF, each single character (including a space) is one token. "Joining" several strings means concatenating them in order, with one space between consecutive strings in WORDDIFF and with nothing between them in CHARDIFF.
- When t <= x and t <= y: take the token sequence of the t-th deleted line (line p+t of A) as the first sequence (A in the "line difference" procedure) and the token sequence of the t-th inserted line (line q+t of B) as the second sequence (likewise B), and compute their difference by the same procedure as the line difference (treating tokens as lines and using each token itself as the comparison key). The matched tokens here are called "common tokens". From the beginning in order, arrange as one part each: for a common token, the token itself; for a change block of tokens, "[-" + the deleted tokens joined + "-]" if there are deleted tokens, and "{+" + the inserted tokens joined + "+}" if there are inserted tokens (if both, the deletion comes first). Let S be the string obtained by joining all the parts. Output "a<p+t> b<q+t>: <S>".
- When only t <= x holds: output "a<p+t>: [-<the tokens of that deleted line joined>-]".
- When only t <= y holds: output "b<q+t>: {+<the tokens of that inserted line joined>+}".
The summary line is "WORDS deleted=<D> inserted=<I> common=<C>" for WORDDIFF and "CHARS deleted=<D> inserted=<I> common=<C>" for CHARDIFF. D is the total number of tokens output between "[-" and "-]", I is the total number of tokens output between "{+" and "+}", and C is the total number of common tokens.
For example, the pair "the old cat" and "the new cat" gives "the [-old-] {+new+} cat" in WORDDIFF and "the [-old-]{+new+} cat" in CHARDIFF, and the pair "cat" and "cut" gives "c[-a-]{+u+}t" in CHARDIFF.

* STAT a b [compare-option]...
Compute the line difference with A = the content of a and B = the content of b. Let D be the total number of deleted lines, I the total number of inserted lines, T = D+I, and S the number of common lines ((line count of A) - D). Output the following two lines.
  <a> -> <b> | <T> <graph>
  changes=<number of change blocks> insertions=<I> deletions=<D> unchanged=<S> similarity=<similarity>%
The graph is P "+" characters followed by Q "-" characters. If T <= 20, P = I and Q = D. If T > 20, P is the quotient of 20*I divided by T (fractional part truncated) and Q is the quotient of 20*D divided by T, and furthermore P = 1 if I >= 1 and P = 0, and Q = 1 if D >= 1 and Q = 0. When T = 0, the space after "<T>" in the first line and the graph are not output (the first line becomes "<a> -> <b> | 0"). The similarity is the quotient of 200*S divided by the sum of the line counts of A and B (fractional part truncated), and it is 100 if A and B both have 0 lines.

* PATCH name k [patch-option]...
Read the following k patch lines as a "patch" and apply it to file name. Patch lines are numbered in order starting from line 1.

(1) Parsing the patch
All lines before the first patch line that starts with "@@" are ignored. If no line starts with "@@", output "PATCH ERROR no hunks" and finish. Otherwise, starting from the first line that starts with "@@", repeat (a) to (d) below to read one or more "hunks".
 (a) The current line (call it line t) must be a "hunk header". A hunk header is a line consisting of exactly 4 parts separated by single spaces: "@@", "-<range>", "+<range>", "@@". A range has the form "X" or "X,Y", where X and Y are each a sequence of 1 to 4 digits (0 to 9) (the values are read as decimal numbers, ignoring leading zeros). When Y is omitted, Y = 1. Furthermore, if X is 0, Y must also be 0. If the line is not a hunk header, output "PATCH ERROR line <t>: bad hunk header" and finish. Let X and Y of the first range be the "old start line" and the "old line count", and X and Y of the second range be the "new start line" and the "new line count".
 (b) Read the following lines in order as "body lines". The first character of a body line is called its "kind", and the part from the second character on is called its "text". The body of the hunk ends as soon as the number of body lines whose kind is a space or "-" has reached the old line count and the number of body lines whose kind is a space or "+" has reached the new line count (if the old line count and the new line count are both 0, the body has 0 lines). If the patch lines run out before the body ends, output "PATCH ERROR line <t>: truncated hunk" (t is the line number of the hunk header) and finish. If the line about to be read (call it line u) has fewer than 2 characters, if its kind is none of a space, "-" and "+", if its kind is a space or "-" although the hunk has already read as many body lines of kind space or "-" as the old line count, or if its kind is a space or "+" although the hunk has already read as many body lines of kind space or "+" as the new line count, output "PATCH ERROR line <u>: bad hunk line" and finish.
 (c) If the body has no line whose kind is "-" or "+", output "PATCH ERROR line <t>: no changes" and finish.
 (d) If patch lines remain, take the next line as the current line and return to (a). If none remain, parsing is finished.
When parsing finishes with an error, output nothing other than that error line, and do not change the file.

(2) Preparing the application
Apply the patch in the "forward direction" if REVERSE is absent, and in the "reverse direction" if it is present. For each hunk, define the following.
- Old sequence: the sequence of the texts of the body lines whose kind is a space or "-" in the forward direction, or whose kind is a space or "+" in the reverse direction, in body order.
- New sequence: the sequence of the texts of the body lines whose kind is a space or "+" in the forward direction, or whose kind is a space or "-" in the reverse direction, in body order.
- Start line s: the old start line in the forward direction, and the new start line in the reverse direction.
- Leading context count pre: the number of consecutive lines of kind space from the start of the body. Trailing context count suf: the number of consecutive lines of kind space from the end of the body.
Let F = f if FUZZ f is present, and F = 0 otherwise.

(3) Searching for a hunk
A hunk is "searched for", given a sequence of lines W, an integer adj and a direction, as follows. The old sequence, the new sequence and the start line s are those defined in (2) for the given direction. First, let e = s-1+adj if the old sequence has 1 or more lines, and e = s+adj if the old sequence has 0 lines. Then, for f = 0, 1, ..., F in order, and for each f, for the offset delta = 0, 1, -1, 2, -2, 3, -3 in order, check the following condition; the search succeeds at the first point where the condition holds.
  Let cp = min(f, pre) and cs = min(f, suf); let O' be the old sequence with its first cp lines and last cs lines removed, and N' the new sequence with its first cp lines and last cs lines removed. Let the position P = e+cp+delta. The condition is that P >= 0 and P+(line count of O') <= (line count of W), and furthermore that lines P+1 to P+(line count of O') of W are all equal, in order, to O' (if O' has 0 lines, the only condition is 0 <= P <= (line count of W)).
On success, the "result" consists of f, delta and P at that time, together with the sequence of lines obtained by replacing lines P+1 to P+(line count of O') of W with N' (if O' has 0 lines, the sequence of lines obtained by inserting N' immediately after line P of W (at the beginning if P = 0)). If the condition does not hold for any combination, the search fails.

(4) Application
First, output "patching file <name>" if DRYRUN is absent, or "checking file <name>" if it is present. Let W be the content of name.
If searching for the first hunk with W and adj = 0 in the specified direction fails, and searching for it in the opposite direction (with the same W, adj = 0 and F) succeeds, output "Reversed (or previously applied) patch detected! Skipping patch." and "RESULT applied=0 failed=0 ignored=<number of hunks> lines=<line count of W>" and finish (the file is not changed).
Otherwise, let adj = 0, and search for the hunks from the first one in order, in the specified direction, with W and adj as they are at that time. For the i-th hunk:
- If the search succeeds, set W to the sequence of lines of the result, add delta+(line count of the new sequence)-(line count of the old sequence) to adj, and output "Hunk #<i> succeeded at <P+1>". However, if f >= 1, append " with fuzz <f>" to the end of the line. Then, regardless of f, if delta != 0, append to the end of the line " (offset <delta> line)" when delta is 1 or -1, and " (offset <delta> lines)" otherwise. A negative delta is written as a decimal number with a leading "-".
- If the search fails, output "Hunk #<i> FAILED at <s>" without changing W or adj.
After processing all hunks, output "RESULT applied=<number of successful hunks> failed=<number of failed hunks> ignored=0 lines=<line count of W>". If DRYRUN is absent and 1 or more hunks succeeded, save W to name.

* EDIT name k
Treat the following k text lines as an "edit script" and execute it from the beginning on a copy W of the content of name. The lines of the edit script are numbered in order starting from line 1. An edit script consists of instruction lines, each followed, depending on the instruction, by text. The last character of an instruction line is called the "instruction", and the part before it the "address". For each instruction line (call it line t), perform (1) to (4) below in order.
(1) If the instruction is none of a, c and d, or the address is not well-formed, the error is "EDIT ERROR line <t>: bad command". Well-formed means a "number" when the instruction is a, and a "number" or "number,number" (two numbers joined by a single ",") when the instruction is c or d. Here a number is a sequence of 1 to 4 digits, and its value is read as a decimal number. When the address has one number (value X), let Y = X; when it has two numbers, let them be X and Y in order.
(2) If the instruction is a and X is greater than the line count of W, or the instruction is c or d and 1 <= X <= Y <= (line count of W) does not hold, the error is "EDIT ERROR line <t>: bad range".
(3) When the instruction is a or c, the "text" is the lines from the line after the instruction line up to just before the first line consisting only of the single character "." (it may be 0 lines). If there is no line consisting only of ".", the error is "EDIT ERROR line <t>: missing terminator".
(4) Execute the instruction. For a, insert the lines of the text immediately after line X of W (at the beginning if X = 0). For c, replace lines X to Y of W with the lines of the text. For d, delete lines X to Y of W. The next instruction line is the line after the "." line for a and c, and the line after the instruction line for d.
When an error occurs, output only that error line, stop the execution, and do not change name (the instructions executed so far are discarded as well). If the execution reaches the end, output "EDIT <name> commands=<number of instructions executed> lines=<line count of W>" and save W to name.

* Three-way comparison (common to DIFF3 and MERGE)
Let O be the content of base, A the content of a, and B the content of b. With O as the first sequence (A in the "line difference" procedure) and A or B as the second sequence (likewise B), compute the line differences of O and A and of O and B (the comparison key is the line itself), and determine which line of A and which line of B each line of O is matched with. Next, starting from x = y = z = 0 (the numbers of lines already processed in O, A and B respectively), repeat the following while at least one of x < (line count of O), y < (line count of A) and z < (line count of B) holds, dividing the contents into "chunks".
(1) If line x+1 of O exists and it is matched with both line y+1 of A and line z+1 of B, make that line a "stable line" and increase x, y and z by 1 each.
(2) Otherwise, search, from line x+1 of O onward, for the first line of O that is matched with some line of A and also with some line of B. If one is found, let it be line i of O and let the matched lines of A and B be lines ja and jb respectively; make lines x+1 to i-1 of O, lines y+1 to ja-1 of A and lines z+1 to jb-1 of B one "change chunk" (any of these parts may have 0 lines), and set x = i-1, y = ja-1, z = jb-1. If none is found, make all remaining lines of O, A and B one change chunk, and set x, y and z to the line counts of O, A and B respectively.
Let Oc, Ac and Bc be the O, A and B parts of a change chunk. If Ac equals Oc (the same number of lines, and each line equal in order), the kind is b; otherwise, if Bc equals Oc, the kind is a; otherwise, if Ac equals Bc, the kind is both; if none of these, the kind is conflict. The "location" of a change chunk is the string "base <M(x, line count of Oc)> a <M(y, line count of Ac)> b <M(z, line count of Bc)>", written using the values of x, y and z just before the chunk is made.

* DIFF3 base a b
For each change chunk in order, output "==== <kind> <location>", then output each line of Oc preceded by "O ", each line of Ac preceded by "A " if the kind is not b, and each line of Bc preceded by "B " if the kind is b or conflict. Finally, output "DIFF3 chunks=<number of change chunks> a=<number of kind a> b=<number of kind b> both=<number of kind both> conflicts=<number of kind conflict>".

* MERGE base a b out [mode]
Process the chunks in order to build the "merge result", a sequence of lines. For a stable line, append that line; for a change chunk of kind b, append Bc; for a change chunk of kind a or both, append Ac. For a change chunk of kind conflict, append the following lines according to the mode.
  OURS: Ac.
  THEIRS: Bc.
  DIFF3: "<<<<<<< <a>", Ac, "||||||| <base>", Oc, "=======", Bc, ">>>>>>> <b>".
  MARKERS and UNION: First, let K be the maximum number of equal lines continuing from the beginning of Ac and Bc, and, for the remainders after removing the first K lines from each of Ac and Bc, let J be the maximum number of equal lines continuing from the end. Let Am be Ac with its first K lines and last J lines removed, and Bm be Bc with its first K lines and last J lines removed. Append the first K lines of Ac, the middle part, and the last J lines of Ac, in this order. The middle part is "<<<<<<< <a>", Am, "=======", Bm, ">>>>>>> <b>" for MARKERS, and Am, Bm for UNION.
Here <a>, <b> and <base> are the file names given in the command. First output "MERGE <out> lines=<line count of the merge result> a=<number of kind a> b=<number of kind b> both=<number of kind both> conflicts=<number of kind conflict>", then, for each change chunk of kind conflict in order, output "CONFLICT <number> <location>" (numbers count from 1). Finally, save the merge result to out (even if out is the same as base, a or b, the merge result is computed before saving).

* CONFLICTS name / RESOLVE name i side
The following 4 kinds of lines are called "marker lines".
  Start marker: a line whose first 7 characters are "<<<<<<<" and whose length is exactly 7 characters or whose 8th character is a space.
  Base marker: a line whose first 7 characters are "|||||||" and whose length is exactly 7 characters or whose 8th character is a space.
  Separator marker: a line consisting only of "=======" (7 "=").
  End marker: a line whose first 7 characters are ">>>>>>>" and whose length is exactly 7 characters or whose 8th character is a space.
The "conflict regions" in a file are found as follows. Examine the lines in order starting from line 1. If the line being examined (call it line g) is a start marker, let line h be the first marker line after line g. If line h is a base marker, let line h instead be the first marker line after line h. Then, if line h is a separator marker and the first marker line after line h (call it line r) is an end marker, lines g to r form one conflict region, and examination continues from line r+1. In all other cases (including when line g is not a start marker and when a required marker line does not exist along the way), examination continues from line g+1. Conflict regions are numbered 1, 2, ... in the order they are found. The "ours part" of a conflict region is from the line after the start marker up to just before the first marker line after it. The "base part" is, if there is a base marker, from the line after it up to just before the separator marker; if there is no base marker, there is no base part. The "theirs part" is from the line after the separator marker up to just before the end marker. Any of these parts may have 0 lines.

CONFLICTS name: Output "CONFLICTS <name> count=<number of conflict regions>", then, for each conflict region in order, output "<number>: lines <line number of the start marker>-<line number of the end marker> ours=<line count of the ours part> base=<line count of the base part> theirs=<line count of the theirs part>". When there is no base part, write "none" after base=.

RESOLVE name i side: If the number of conflict regions is less than i, output "ERROR no conflict <i> in <name>". If side is BASE and the i-th conflict region has no base part, output "ERROR no base section in conflict <i>". Otherwise, compute the content obtained by replacing the whole i-th conflict region (including its marker lines) with the ours part if side is OURS, the theirs part if THEIRS, the base part if BASE, or the ours part followed by the theirs part if BOTH. Output "RESOLVE <name> <i> <side> lines=<line count of that content> remaining=<number of conflict regions in that content>", and save that content to name.

[Output format]
- For each command, output only the lines described in [Processing]. Every command outputs 1 or more lines.
- All numbers are written as decimal integers without extra leading zeros (apart from the spaces padded before the line numbers of PRINT).
- Spaces appear at the beginning of a line only as the spaces padded before the line numbers of PRINT, as the spaces placed at the start of body lines of UNIFIED and CONTEXT, and in lines of SIDE whose left string is empty. There are no spaces at the end of a line (if you output as described in [Processing], no trailing spaces appear). No empty lines are output. Every line ends with a newline.
- The error lines are of the following 12 kinds (the parts in < > are replaced by the corresponding values).
  ERROR no such file <filename>
  ERROR nothing to undo <name>
  ERROR no conflict <i> in <name>
  ERROR no base section in conflict <i>
  PATCH ERROR no hunks
  PATCH ERROR line <t>: bad hunk header
  PATCH ERROR line <t>: truncated hunk
  PATCH ERROR line <u>: bad hunk line
  PATCH ERROR line <t>: no changes
  EDIT ERROR line <t>: bad command
  EDIT ERROR line <t>: bad range
  EDIT ERROR line <t>: missing terminator

[Constraints]
- 1 <= N <= 300
- k of FILE: 0 <= k <= 60. k of PATCH and EDIT: 1 <= k <= 60.
- n of UNIFIED and CONTEXT: 0 <= n <= 10. w of SIDE: 4 <= w <= 40. f of FUZZ: 0 <= f <= 3. i of RESOLVE: 1 <= i <= 99.
- The whole input has at most 2000 lines. Every file always has at most 500 lines.
