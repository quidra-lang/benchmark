[Overview]
Write a program that serves as a laboratory for bin packing problems and cutting problems with integer sizes. It reads a sequence of commands from standard input and performs: running ten heuristics (online and offline methods) for one-dimensional bin packing while counting bin inspections, computing lower bounds, searching for an optimal solution by branch and bound, local improvement that reduces the number of bins, verifying an assignment, bin covering (the dual problem), machine scheduling by the MULTIFIT method, the cutting-stock problem using cutting patterns, two-dimensional strip packing, and bin packing of rectangles with guillotine cuts. It writes the results to standard output.

[Input format]
The first line contains the number of commands N. Each of the following N lines contains one command. Each command consists of the command name and zero or more arguments, separated by single spaces, with no spaces at the beginning or end of the line. The commands have the following 23 formats.

  ITEMS C s1 s2 ... sk
  RANDOM n C seed
  NEXTFIT
  FIRSTFIT
  BESTFIT
  WORSTFIT
  ALMOSTWORST
  HARMONIC k
  KBOUNDED k
  FFD
  BFD
  WFD
  TRACE H
  REDUCE H
  BOUNDS
  COMPARE k
  EXACT limit
  CHECK b1 b2 ... bk
  COVER
  MULTIFIT m
  CUTSTOCK L p1 p2 ... pm
  SHELF W r1 r2 ... rn
  GUILLOTINE W H M R r1 r2 ... rn

H is a "method specification": either one word, one of NEXTFIT, FIRSTFIT, BESTFIT, WORSTFIT, ALMOSTWORST, FFD, BFD, WFD, or the two words "HARMONIC k" or "KBOUNDED k". M is FIXED or ROTATE, and R is FIRST or BEST. p1 through pm have the form "<length>:<demand>" (e.g. 45:3), and r1 through rn have the form "<width>x<height>" (e.g. 4x3; the separator is the lowercase English letter x); both are two integers >= 0 joined by the separator. All other arguments are integers >= 0. All integers are written in decimal without extra leading zeros. The k of ITEMS and CHECK, the m of CUTSTOCK, and the n of SHELF and GUILLOTINE are symbols denoting the number of values on that line; they are not written in the input. It is guaranteed that every line follows this format and the ranges in [Constraints].

[Processing]
Process the commands in order starting from the first command line, and output the result of each command according to [Output format]. Error checks are performed in the order given in each command's description; output only the line of the first error that applies, and do nothing else for that command (the state does not change either).
Below, for positive integers a and b, ceil(a/b) is the smallest integer greater than or equal to a divided by b, and floor(a/b) is the largest integer less than or equal to a divided by b.

== Item list ==
- The laboratory holds exactly one "current item list". An item list consists of a capacity C (an integer >= 1) and k items numbered 1, 2, ..., k, each of which has an integer size between 1 and C inclusive. Initially there is no item list. ITEMS and RANDOM replace the current item list with a new one only when they succeed.
- The commands other than ITEMS, RANDOM, CUTSTOCK, SHELF and GUILLOTINE are called "1D commands". A 1D command uses the current item list; if there is no item list, it outputs "ERROR NO ITEMS" before any other check. CUTSTOCK, SHELF and GUILLOTINE neither use nor change the item list.
- An item with number i and size s is written "i:s"; this is called the "item notation" (e.g. 3:7).
- "Sorting items in descending order" means sorting them by size from largest to smallest, and in increasing order of number when the sizes are equal.
- The "total size" is the sum of the sizes of all items in the current item list.

== Bins ==
- The sum of the sizes of the items in a bin is called the "load" of that bin. An item of size s "fits" in a bin with capacity V and load l if l+s<=V. The bin capacity V is the capacity C of the item list, except where MULTIFIT and CUTSTOCK define it separately.
- Bins are numbered from 1 in the order they are opened (created). The items in a bin are kept in the order they were put in.
- The "bin line" of a bin is "BIN <bin number> load=<load>/<C> items=<item notation> <item notation> ...". The item notations are listed in the order of the items in the bin, separated by single spaces.

== Heuristics ==
The ten methods take the items one at a time in the "processing order" and put each one either into one existing bin or into a newly opened bin. The processing order is increasing order of number for NEXTFIT, FIRSTFIT, BESTFIT, WORSTFIT, ALMOSTWORST, HARMONIC and KBOUNDED, and the items sorted in descending order for FFD, BFD and WFD. Each method increases the inspection count by 1 whenever the description below says "inspect" (it starts at 0). Opening or closing a bin does not count as an inspection.
  NEXTFIT: If there is at least one bin, inspect the most recently opened bin, and if the item fits, put it in that bin. If there is no bin or the item does not fit, open a new bin.
  FIRSTFIT and FFD: Inspect the existing bins one at a time in increasing order of number; as soon as a bin in which the item fits is found, stop inspecting and put the item in that bin. If the item fits in no bin, open a new bin.
  BESTFIT and BFD: Inspect all existing bins (the inspection count increases by the number of bins), and put the item in the bin with the largest load among the bins in which it fits (if tied, the one with the smallest number). If it fits in no bin, open a new bin.
  WORSTFIT and WFD: The same as BESTFIT, but put the item in the bin with the smallest load among the bins in which it fits (if tied, the one with the smallest number).
  ALMOSTWORST: Inspect all existing bins, sort the bins in which the item fits in increasing order of load (if tied, in increasing order of number), and put the item in the second bin if there are two or more, or in that bin if there is only one. If it fits in no bin, open a new bin.
  HARMONIC k: The "class" of an item of size s is the smaller of floor(C/s) and k (it is between 1 and k inclusive). Each class has at most one "current bin"; initially no class has one. Let c be the class of the item; if class c has a current bin, inspect it, and if the item fits, put it in that bin. If there is no current bin or the item does not fit, open a new bin, put the item in it, and make that bin the current bin of class c. The class of each bin is the class of the item that opened the bin.
  KBOUNDED k: The method keeps a collection of "active" bins (initially empty). Inspect the active bins one at a time in increasing order of number; as soon as a bin in which the item fits is found, stop inspecting and put the item in that bin. If it fits in none of them, first, if there are exactly k active bins, "close" the one among them with the largest load (if tied, the one with the smallest number) and remove it from the active bins. Then open a new bin, put the item in it, and add that bin to the active bins. A closed bin is never used again.

== Details of the 1D commands ==
ITEMS C s1 s2 ... sk
Checks: If C=0, "ERROR BAD CAPACITY". If some si is 0 or greater than C, "ERROR BAD ITEM <i>" for the one with the smallest i among them.
Processing: Make the item list with capacity C and size si for item i (i=1, ..., k) the current item list, and output "ITEMS count=<k> capacity=<C> total=<total size>".

RANDOM n C seed
Checks: If n=0 or n>40, "ERROR BAD COUNT". If C=0, "ERROR BAD CAPACITY". If seed=0 or seed>=2147483647, "ERROR BAD SEED".
Processing: Let x=seed, and for i=1, 2, ..., n in this order, replace x with (the remainder of 48271*x divided by 2147483647) and then set the size of item i to (the remainder of x divided by C)+1. Make the item list consisting of these n items and capacity C the current item list, and output the two lines "RANDOM count=<n> capacity=<C> total=<total size>" and "SIZES <size of item 1> <size of item 2> ... <size of item n>".

NEXTFIT, FIRSTFIT, BESTFIT, WORSTFIT, ALMOSTWORST, HARMONIC k, KBOUNDED k, FFD, BFD, WFD
Checks: For HARMONIC and KBOUNDED, if k=0, "ERROR BAD PARAMETER".
Processing: Pack all items of the current item list into bins with that method. First output the "header line", then the bin lines of all bins in number order. The header line is "<method name> bins=<number of bins> inspections=<inspection count> waste=<number of bins*C-total size>". However, for HARMONIC and KBOUNDED, insert " k=<k>" right after the method name (e.g. HARMONIC k=3 bins=4 ...), and for KBOUNDED, append " closes=<number of times a bin was closed>" at the end of the line. For HARMONIC, append " class=<class of the bin>" at the end of each bin line.

TRACE H
Checks: If H is HARMONIC k or KBOUNDED k and k=0, "ERROR BAD PARAMETER".
Processing: Pack the items in the same way as the command H, and output the header line of the command H prefixed with "TRACE ". Then, instead of the bin lines, output one line for each item, the t-th item in processing order (t=1, 2, ...): "STEP <t> item=<item notation> bin=<number of the bin the item was put in> inspected=<increase of the inspection count while processing that item>". When the item was put in a newly opened bin, append " new" at the end of the line, and when KBOUNDED closed a bin, further append " closed=<number of the closed bin>" after that. For HARMONIC, append " class=<class of the item>" at the end of the line (after " new" if present).

REDUCE H
Checks: The same as TRACE.
Processing: Starting from the result of packing with H, perform the following steps (1) to (4).
(1) Sort all bins in increasing order of load (if tied, in increasing order of number), and in that order select each bin b one at a time and perform the "removal attempt" of (2).
(2) Sort the items of bin b in descending order, and in that order, one at a time, determine the item's "destination" as the bin with the largest load (if tied, the one with the smallest number) among the bins other than b in which the item fits. Here the load of each bin is treated as including the items whose destinations have already been determined in this attempt. If an item fits in no bin, this attempt fails; change nothing and make the attempt with the next bin b.
(3) When the destinations of all items of b have been determined, the attempt succeeds. In the order the destinations were determined, take each item out of b and put it at the end of its destination bin, remove the now empty bin b, and decrease by 1 the number of each bin whose number is greater than b. Then return to (1).
(4) When the attempts for all bins sorted in (1) have failed, finish.
First output "REDUCE <method name> before=<initial number of bins> after=<final number of bins> eliminated=<number of bins removed>" (for HARMONIC and KBOUNDED, insert " k=<k>" right after the method name). Then output one line for each successful attempt, in order: "ELIMINATE bin=<b> load=<load of b before the attempt> moves=<move> <move> ...". A move has the form "<item notation>-><destination number>" (e.g. 4:4->1), and the moves are listed in the order the destinations were determined. The bin numbers in this line are the numbers at the time of that attempt (before b is removed). Finally, output the bin lines of all remaining bins in number order. For HARMONIC, the bin lines also carry class (the class of a bin does not change by the moves).

BOUNDS
Processing: Let T be the total size; the lower bound L1 is ceil(T/C). The lower bound L2 is computed as follows. The "thresholds" are 0 and the size s of every item satisfying 2s<=C (equal values are merged into one). For each threshold alpha, form the groups of items
  J1: items satisfying s>C-alpha
  J2: items satisfying 2s>C and s<=C-alpha
  J3: items satisfying 2s<=C and s>=alpha
(s is the size of the item), let E=(total size of J3)-(number of items in J2*C-total size of J2), and let L(alpha)=(number of items in J1)+(number of items in J2)+(ceil(E/C) if E>0, otherwise 0). L2 is the maximum of L(alpha) over all thresholds.
First output "BOUNDS total=<T> L1=<L1> L2=<L2>", then one line per threshold in increasing order of threshold: "ALPHA <alpha> j1=<number of items in J1> j2=<number of items in J2> j3=<number of items in J3> bound=<L(alpha)>".

COMPARE k
Checks: If k=0, "ERROR BAD PARAMETER".
Processing: Run each of the ten methods (HARMONIC and KBOUNDED with the parameter k). First output "COMPARE k=<k> L1=<L1> L2=<L2>" (L1 and L2 are the same values as in BOUNDS), then one line per method, "<method name> bins=<number of bins> gap=<number of bins-L2> waste=<the same value as in the header line> inspections=<inspection count>", in increasing order of the number of bins, and if tied, in lexicographic order of the method names by ASCII character codes. The method name does not include k.

EXACT limit
Checks: If limit=0, "ERROR BAD PARAMETER". If there are 21 or more items, "ERROR TOO MANY ITEMS".
Processing: Search for the minimum number of bins by branch and bound. Let t1, t2, ..., tk be the items sorted in descending order, and for i=1, ..., k+1 let ri be the total size of ti through tk (r(k+1)=0). L2 is the same value as in BOUNDS. The result of FFD is the initial "best solution", and B is the number of bins of the best solution. The "node count" is initially 0. First output "EXACT ffd=<number of bins of FFD> L2=<L2>".
If B=L2, do not search, and the status is bound. Otherwise, perform visit(1) starting from a state with no bins. visit(i) is performed in the state where t1 through t(i-1) have been packed into bins, as follows. Let m be the current number of bins and u the sum of their loads.
(1) If the node count equals limit, set the status to limit and abort the whole search immediately. Otherwise increase the node count by 1.
(2) Let F=m*C-u, and let D=m+(ceil((ri-F)/C) if ri-F>0, otherwise 0). If D>=B, end this visit.
(3) If i=k+1, record the current state of the bins (bins numbered in the order they were opened, the items in each bin in the order they were put in) as the new best solution, set B=m, and output "IMPROVE bins=<m> nodes=<node count at that time>". If B=L2, set the status to bound and end the whole search. Otherwise end this visit.
(4) Examine the bins in increasing order of number, and for each bin in which ti fits and such that no bin with a smaller number has the same load, in order, put ti in that bin, perform visit(i+1), and take ti out after it returns.
(5) If m+1<B, open a new bin, put ti in it, perform visit(i+1), and remove that bin after it returns.
If visit(1) returns without the search having been aborted or ended, the status is complete.
After the search (also when no search was performed), output "RESULT bins=<number of bins of the best solution> nodes=<node count> status=<status>", followed by the bin lines of all bins of the best solution in number order.

CHECK b1 b2 ... bk
Checks: If the number of values differs from the number of items, or some bi is 0, "ERROR BAD ASSIGNMENT".
Processing: Examine the assignment that puts item i into the bin with "label" bi. The number of bins is the number of distinct labels used, and a bin whose load is greater than C is "overfull". First output "CHECK bins=<number of bins> over=<number of overfull bins> L2=<L2 (the same value as in BOUNDS)> status=<valid if there is no overfull bin, invalid if there is one>", then, in increasing order of label, the bin lines with the label used as the bin number (the items in a bin in increasing order of number). Append " OVER" at the end of the bin line of an overfull bin.

COVER
Processing: A bin whose load has become C or more is called a "covered bin"; solve the problem of making as many covered bins as possible (the bin covering problem) with two methods. First output "COVER total=<total size> upper=<floor(total size/C)>".
  DNF: Put the items in increasing order of number into the "current bin". The first item is put in a new bin. If, as a result of putting an item, the load of the current bin becomes C or more, that bin is finished as a covered bin, and the next item is put in a new bin.
  BIGSMALL: Make a list of the items sorted in descending order. While the list is not empty, take out the head of the list (the largest item) and put it in a new bin; then, while the load of that bin is less than C and the list is not empty, repeatedly take out the tail of the list (the smallest item) and put it in that bin.
In both methods, the items of a bin that ended with its load still less than C (if there is one, it is only the last bin) are the "rest". For each method in order, output "<method name> covered=<number of covered bins> rest=<total size of the rest>", then the bin lines of the covered bins numbered from 1 in the order they were made, and finally, if there is a rest, "REST items=<item notation> <item notation> ..." (in the order the items were put in). In the bin line of a covered bin, the load may be greater than C.

MULTIFIT m
Checks: If m=0, "ERROR BAD PARAMETER".
Processing: Assign the items to m machines so as to make the maximum (the "makespan") of the per-machine total sizes (the "loads") small. Let T be the total size and P the largest size; lo is the larger of ceil(T/m) and P, and hi is the larger of ceil(2T/m) and P. First output "MULTIFIT m=<m> lower=<lo> upper=<hi>".
While lo<hi, let mid=floor((lo+hi)/2), pack all items of the current item list into bins with FFD using bin capacity mid, and let b be the number of bins. If b<=m, output "TRY cap=<mid> bins=<b> ok" and set hi=mid; otherwise output "TRY cap=<mid> bins=<b> fail" and set lo=mid+1.
When this finishes, assign bin j of the result of FFD with bin capacity hi to machine j (if there are fewer than m bins, nothing is assigned to the remaining machines; the number of bins of this FFD is always at most m). Output "RESULT cap=<hi> makespan=<makespan>" and one line for each machine, from machine 1 to m in order: "MACHINE <j> load=<load> items=<item notation> <item notation> ..." (the items in the order in the bin; items=- if there is nothing).
Then, as the LPT method, assign the items, in descending order, each to the machine with the smallest load at that time (if tied, the machine with the smallest number). Output "LPT makespan=<makespan>" and MACHINE lines of the same form for machines 1 to m (the items in the order they were assigned).

== CUTSTOCK L p1 p2 ... pm ==
Checks: If L=0, "ERROR BAD CAPACITY". Then examine p1, p2, ... in order: if the length is 0 or greater than L, or the demand is 0, output "ERROR BAD PIECE <j>"; if the length equals the length of some p before it, output "ERROR DUPLICATE PIECE <j>" (j is the number of that p).
Processing: Cut pieces of length lambda, as many as their demand, from bars of length L. Arrange the piece types in decreasing order of length as lambda_1>lambda_2>...>lambda_m, and let d1, ..., dm be their respective demands. A tuple of integers >= 0 (a1, ..., am) satisfying a1*lambda_1+...+am*lambda_m<=L is called a "pattern", L-(a1*lambda_1+...+am*lambda_m) is called its "trim", and a pattern whose trim is less than lambda_m is called a "maximal pattern". Sort all maximal patterns in decreasing lexicographic order of (a1, a2, ..., am) (larger a1 first, if equal larger a2 first, ...), and number them from 1.
Greedy method: Start the remaining demand ei of each type at di. While there is a type with positive ei, compute the "useful count" of each maximal pattern (the sum of min(ai, ei) over all i), cut one bar with the pattern with the largest useful count (if tied, the one with the smallest number), and replace each ei with max(0, ei-ai).
The output is as follows. Let Q=d1*lambda_1+...+dm*lambda_m.
  "CUTSTOCK L=<L> pieces=<m> patterns=<number of maximal patterns>"
  For each maximal pattern in number order, "PATTERN <number> <breakdown> rest=<trim>". The breakdown is "<ai>x<lambda_i>" for each type with ai>0, joined with + in decreasing order of length (e.g. 1x45+2x20).
  For each maximal pattern used, in number order, "USE <number> bars=<number of bars cut with that pattern>".
  For each type in decreasing order of length, "PIECE <lambda_i> demand=<di> cut=<number of pieces cut>".
  "TOTAL bars=<number of bars cut> trim=<sum of the trims of the bars cut> surplus=<total number of pieces cut-total demand> waste=<number of bars*L-Q>"
  For comparison, let b be the number of bins when the sequence of items consisting of d1 pieces of lambda_1, d2 pieces of lambda_2, ... arranged in this order is packed into bins of capacity L by the FIRSTFIT rule, and output "FFD bars=<b> waste=<b*L-Q>".
  Finally, "LOWER bars=<ceil(Q/L)>".

== Common rules for two dimensions ==
- The rectangles of SHELF and GUILLOTINE are numbered 1, 2, ... in argument order, and the rectangle with number j is represented by the j-th uppercase English letter (A for 1, B for 2, ...). The area of a rectangle is width*height.
- Coordinates are integer coordinates with the x axis pointing right and the y axis pointing up. A rectangle of width w and height h placed at position (x, y) occupies the unit cells from column x to column x+w-1 and from row y to row y+h-1.
- The "drawing" of a region of width W and height Ht consists of Ht lines. From top to bottom, they represent the rows y=Ht-1, Ht-2, ..., 0, one row per line, and each line lists the cells from x=0 to W-1, one character per cell: the letter of the rectangle occupying the cell if there is one, otherwise . (period).

== SHELF W r1 r2 ... rn ==
Checks: If W=0, "ERROR BAD CAPACITY". Examine r1, r2, ... in order, and if there is a rectangle whose width or height is 0 or whose width is greater than W, output "ERROR BAD RECT <j>" with the number j of the first such rectangle.
Processing: Place the rectangles, without rotation, into a strip of width W that extends upward without limit. The "processing order" is the order of the rectangles sorted in decreasing order of height, if equal in decreasing order of width, if equal in increasing order of number. First output "SHELF W=<W> rects=<n> area=<total area>", then run the following four methods in the order NFDH, FFDH, BFDH, SKYLINE, each starting from an empty strip. The util of each method is floor(total area*100/(W*Ht)) (Ht is the overall height of that method).
NFDH, FFDH and BFDH are methods that stack "shelves" from the bottom. A shelf has a bottom y coordinate, a height, and a used width (initially 0), and shelves are numbered from 1 in the order they are created. For each rectangle (width w, height h) in processing order, select one shelf, place the rectangle at position (used width, bottom y) of that shelf, and add w to the used width of the shelf. A shelf with used width+w<=W is a "fitting shelf".
  NFDH: If the most recently created shelf is a fitting shelf, select that shelf.
  FFDH: Select the fitting shelf with the smallest number.
  BFDH: Select the fitting shelf with the largest used width (if tied, the shelf with the smallest number).
If no shelf can be selected, create a new shelf and select it. The bottom y of a new shelf is 0 for the first shelf, otherwise the y+height of the shelf created just before it, and its height is h (because of the processing order, the height of a placed rectangle is always at most the height of the shelf). The overall height Ht is the y+height of the last created shelf. The output is "<method name> height=<Ht> shelves=<number of shelves> util=<util>", then for each shelf in number order "LEVEL <shelf number> y=<bottom y> h=<shelf height> used=<used width> items=<letter>@<x> <letter>@<x> ..." (in placement order), and finally the drawing of width W and height Ht.
SKYLINE starts the "height" of each column x (0<=x<W) at 0, and for each rectangle (width w, height h) in processing order, computes, for every x satisfying 0<=x<=W-w, the maximum y(x) of the heights of columns x through x+w-1, selects the x with the smallest y(x) (if tied, the smallest x), places the rectangle at position (x, y(x)), and sets the heights of columns x through x+w-1 all to y(x)+h. The overall height Ht is the maximum of the column heights at the end. The output is "SKYLINE height=<Ht> util=<util>", one line per rectangle in placement order "PLACE <letter> x=<x> y=<y> w=<w> h=<h>", and finally the drawing of width W and height Ht.

== GUILLOTINE W H M R r1 r2 ... rn ==
Checks: If W=0 or H=0, "ERROR BAD CAPACITY". Examine r1, r2, ... in order, and if there is a rectangle whose width or height is 0, or that cannot be placed in an empty region of width W and height H (when M is FIXED: w<=W and h<=H does not hold; when ROTATE: neither w<=W and h<=H nor h<=W and w<=H holds), output "ERROR BAD RECT <j>" with the number j of the first such rectangle.
Processing: Place the rectangles on "sheets" of width W and height H. When M is ROTATE, a rectangle may also be placed rotated by 90 degrees (with its width and height swapped). Sheets are numbered from 1 in the order they are opened. The rectangles are processed in decreasing order of area, if equal in increasing order of number.
- Each sheet has an ordered list of "free rectangles". A free rectangle has a position (x, y), a width and a height, and is written "<x>,<y>,<width>x<height>". When a sheet is opened, its list contains only the one free rectangle "0,0,<W>x<H>".
- A rectangle of width w and height h "can be placed" in a free rectangle of width fw and height fh if w<=fw and h<=fh, or if M is ROTATE and h<=fw and w<=fh.
- If R is FIRST, examine the sheets in increasing order of number, and each sheet's list from its head, and select the first free rectangle found in which the rectangle can be placed. If R is BEST, select, among the free rectangles of all sheets in which the rectangle can be placed, the one with the smallest area (fw*fh) (if tied, the one on the sheet with the smaller number; if still tied, the one earlier in the list). In both cases, if no sheet has a free rectangle in which the rectangle can be placed, open a new sheet and select its free rectangle.
- Place the rectangle at position (fx, fy) of the selected free rectangle (position (fx, fy), width fw, height fh). If w<=fw and h<=fh, place it without rotation (placed width pw=w, placed height ph=h); otherwise place it rotated (pw=h, ph=w).
- After placing, remove the selected free rectangle from the list, and let rw=fw-pw and rh=fh-ph. If rw<=rh, append the "top rectangle" (fx, fy+ph, width fw, height rh) and the "right rectangle" (fx+pw, fy, width rw, height ph); if rw>rh, append the top rectangle (fx, fy+ph, width pw, height rh) and the right rectangle (fx+pw, fy, width rw, height fh); in either case they are appended to the end of the list in the order top rectangle, right rectangle. However, a rectangle whose width or height is 0 is not appended.
The output is first "GUILLOTINE W=<W> H=<H> mode=<M> rule=<R> rects=<n> sheets=<number of sheets> rotated=<number of rectangles placed rotated> util=<floor(total area*100/(number of sheets*W*H))>". Then, for each sheet in number order, output "SHEET <sheet number> placed=<number of rectangles placed> area=<total area of the placed rectangles>", one line per rectangle in placement order "PLACE <letter> x=<x> y=<y> w=<pw> h=<ph>" (append " rotated" at the end of the line for a rectangle placed rotated), "FREE <free rectangle> <free rectangle> ..." listing the free rectangles of the list at the end in list order separated by single spaces ("FREE none" if the list is empty), and the drawing of width W and height H.

[Output format]
- For each command, output only the lines described in [Processing]. Every command outputs at least one line.
- The words and values in a line are separated by single spaces as described. Do not put spaces at the beginning or end of a line, and do not output blank lines. Every line ends with a newline.
- All numbers are written as decimal integers without extra leading zeros (negative numbers do not appear).
- The error lines are the following 11 kinds (the < > parts are replaced with the corresponding number).
  ERROR NO ITEMS
  ERROR BAD CAPACITY
  ERROR BAD ITEM <i>
  ERROR BAD COUNT
  ERROR BAD SEED
  ERROR BAD PARAMETER
  ERROR TOO MANY ITEMS
  ERROR BAD ASSIGNMENT
  ERROR BAD PIECE <j>
  ERROR DUPLICATE PIECE <j>
  ERROR BAD RECT <j>

[Constraints]
