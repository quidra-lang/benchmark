[Overview]
Write a Mustache-style template engine. The program reads commands such as data definitions, partial template definitions and templates from standard input in order, renders templates by inserting the data into them, and writes the results to standard output. Templates support variable insertion (with and without HTML escaping), name resolution through dot-separated names and a context stack, repetition over lists and conditional display based on the truthiness of a value (sections), inverted sections, comments, inclusion of partial templates (with indentation), the name "." that denotes the current value, loop variables, filter chains, and delimiter changes. Lines that consist of a tag only are removed entirely, as in the Mustache specification. Data is defined by lines of the form "key = value", where a key may contain dot-separated names and list indices. When a template contains an error or an error occurs during rendering, the error is reported in the form "ERROR line N: reason" instead of the rendered result.

[Input format]
The input consists of several lines, and the last line is END. Each line is a string of 0 to 200 characters consisting only of printable ASCII characters (character codes 32 to 126).
The input is a sequence of the following 9 kinds of commands. The 3 kinds DATA, PARTIAL and TEMPLATE are "blocks" made of several lines.

  DATA (followed by a body, ending with an ENDDATA line)
  PARTIAL name (followed by a body, ending with an ENDPARTIAL line)
  TEMPLATE name (followed by a body, ending with an ENDTEMPLATE line)
  RENDER name
  DUMP
  STRICT ON
  STRICT OFF
  RESET
  END

A block begins with a start line (one of DATA, PARTIAL name, TEMPLATE name) and ends with the first end line that appears after it (a line consisting only of ENDDATA, ENDPARTIAL or ENDTEMPLATE, respectively). The 0 or more lines between the start line and the end line are called the "body" of the block. A line identical to the block's end line never appears in the body, but any other line (including lines consisting only of END or DATA, empty lines, and so on) may appear.
Every line outside blocks matches one of the 9 formats above exactly. name is an "identifier" ([Processing] Section 1) of at most 20 characters. There is exactly one ASCII space between the command name and name. END appears exactly once outside blocks as the last line, and no line follows it.
The input lines are numbered 1, 2, 3, ... starting from the first line. This number is called the "line number". Every line number used in error reports is a line number within this whole input.

[Processing]
Process the commands in order from the beginning. The program has the following state.
- Data: one map that stores values (Section 2), called the "root". Initially it is an empty map.
- Collection of partial templates: holds one body (a sequence of lines) per name. Initially empty.
- Collection of templates: holds one body (a sequence of lines) per name. Initially empty. Names of partial templates and names of templates are handled separately.
- Strict mode: ON or OFF. Initially OFF.

Section 1. Terms
- "Space" means only the ASCII space (character code 32). To "strip the surrounding spaces" of a string means to remove all spaces at its beginning and at its end.
- "Letters" are the 52 characters A to Z and a to z; "digits" are the 10 characters 0 to 9.
- An "identifier" is a string of 1 or more characters that starts with a letter or _ and consists only of letters, digits and _.
- A "subscript" is a string that is either 0 or starts with one of 1 to 9 and consists only of digits (decimal notation without extra leading zeros). The integer that a subscript denotes is the value of that subscript.
- The length of a string is counted in characters. Strings are compared in lexicographic order by ASCII character code. That is, compare one character at a time from the beginning; at the first differing character, the string whose character has the smaller code is smaller; when one string is a prefix of the other, the shorter one is smaller.
- LF denotes the newline character (character code 10). It never appears in input lines, but it may appear in string values and in rendered results.

Section 2. Values
A value is one of the following 6 kinds.
- String: a sequence of 0 or more characters. It may contain LF.
- Integer
- Boolean: true or false.
- List: a sequence of 0 or more values. The elements are numbered 0, 1, 2, ... from the beginning.
- Map: a collection of 0 or more key-value pairs. Keys are identifiers, and the same key never appears more than once in one map.
- Absent: represents the absence of a value. It is never stored in the data, but it appears when name resolution fails or as the result of a filter, and it may also become an element of a list that a filter creates.
A value X "has" a part p when p is an identifier and X is a map that has the key p, or when p is an index (an integer) and X is a list that has an element with index p. In that case, the value of key p of X, or the element with index p of X, is written "the p of X".

Section 3. Data block (DATA)
Process each line of the body from top to bottom as follows.
(1) Empty lines and lines starting with # are ignored (they are not counted in any of the counts below).
(2) A line starting with "UNSET " (UNSET followed by one ASCII space) is a "delete line", and the whole part after those 6 characters is the key k.
(3) Every other line is an "assignment line". The part before the first occurrence of " = " (the 3 characters: ASCII space, =, ASCII space) in the line is the key k, and the part after it is the value notation v.

Key format: an identifier followed by 0 or more items, each of which is either "." followed by an identifier, or "[" followed by a subscript followed by "]" (examples: title, user.name, items[0].price, grid[1][2]). A key is divided into the leading identifier and each following item. These are called "parts"; an identifier part denotes the identifier itself, and a [ ] part denotes the value of the subscript (an index). The substring from the beginning of the key to the end of a part is called the "prefix" of that part. For example, the prefixes of the 3 parts items, 0, price of items[0].price are items, items[0] and items[0].price, respectively.

A value notation is one of the following. Anything else is an error.
- String notation: starts with ", is read character by character from the next character, and ends at the next ". Each character in between denotes itself, except that \ is paired with the character right after it: \" denotes ", \\ denotes \, and \n denotes LF. It is an error when the character right after \ is anything other than these 3 or there is no character after it, when there is no closing ", or when there are characters after the closing ".
- Integer notation: 0, or an optional - followed by a sequence of digits starting with one of 1 to 9. It is read as a decimal number (-0 and 007 are errors).
- Boolean notation: true or false.
- The empty list notation [] and the empty map notation {}.
- List notation: 1 or more string, integer or boolean notations, separated by ", " (a comma and one ASCII space), between [ and ]. For example, ["red", "a, b", 3, true] is a list of 4 elements: the string red, the string a, b (comma, space included), the integer 3, and the boolean true.

An assignment line is processed as follows. Only the first error that applies is recorded, and that line does not change the data.
(a) If the line contains no " = ", error "bad line".
(b) If k does not match the key format, error "bad key '<k>'".
(c) If v is not a valid value notation, error "bad value '<v>'".
(d) Otherwise, with the root as the "current container" X, process the parts p of the key in order from the beginning as follows.
  - If p is an index and is greater than the number of elements of X, error "index gap at '<prefix of p>'".
  - If p is the last part, make the value denoted by v the p of X. If X has p, replace it (regardless of the kind of its value); otherwise add it (for an index part whose index equals the number of elements, append it at the end). This finishes processing the line.
  - If p is not the last part, the required kind is "map" if the next part is an identifier, or "list" if it is an index. If X has p and the p of X is of the required kind, it becomes the new X. If X has p but the p of X is not of the required kind, error "type conflict at '<prefix of p>'". If X does not have p, add an empty value of the required kind as the p of X (by the same addition rule as above), and it becomes the new X.
  (Because the first part is always an identifier and the root is a map, X is always a map when an identifier part is processed, and X is always a list when an index part is processed.)
  When an error occurs during (d), the data also remains exactly as it was before the line was processed (no empty value added up to that point remains either).

A delete line is processed as follows. If k does not match the key format, error "bad key '<k>'". Otherwise, with the root as X, go through the parts from the beginning: if X has the part, the part of X becomes the new X and processing continues. If X has every part up to the last one, remove the value of the last part (for a map, remove that key-value pair; for a list, remove that element and decrease the indices of the following elements by 1). If some part is not present on the way, error "no value at '<k>'", and the data does not change.

After processing the whole body, output "DATA set=<number of assignment lines without error> unset=<number of delete lines without error> errors=<number of lines with an error>", followed by "ERROR line <line number of that line>: <reason>" for each line with an error, in increasing order of line number.

Section 4. Lexical analysis of templates
When a template or a partial template is rendered, its "source" (a sequence of lines: the body for a template, the lines built in Section 8 for a partial template) is analyzed into a sequence of texts and tags.
The analysis uses a pair of an opening delimiter O and a closing delimiter C (the delimiters). When analysis of a source begins, O is {{ and C is }}.
Read each line of the source, from the top line down, as follows. Start with the beginning of the line as the "read position".
(1) Find the first occurrence of O at or after the read position. If it is not found, the part from the read position to the end of the line is text, and the line is finished.
(2) If it is found, the part from the read position to just before it is text, and a tag starts at that O. If the character right after O is {, the tag is a "triple tag": find the first occurrence of the string "}" followed by C at or after the character right after that {, and the part from right after the { to just before that } is the "content" of the tag. Otherwise, find the first occurrence of C at or after the character right after O, and the part from right after O to just before C is the content. If the string searched for is not found within the same line, it is the error "unclosed tag". If it is found, the position right after that string becomes the new read position, and go back to (1).
Let E be the content of the tag with the surrounding spaces stripped. The kind of the tag is determined as follows.
- A triple tag is a "raw variable tag", and E is its "expression".
- Otherwise, if the first character of E is one of # ^ / ! > & =, the tag is a "section start tag", an "inverted section start tag", a "closing tag", a "comment tag", a "partial tag", a "raw variable tag", or a "delimiter change tag", respectively. The part of E from the second character on, with the surrounding spaces stripped, is the "argument part" of the tag. For a raw variable tag, the argument part is the expression.
- Anything else is a "variable tag", and E is the expression (it is also a variable tag when E is empty).
A delimiter change tag is processed at the moment it is read, as follows. When E has 2 or more characters, its last character is also =, and splitting the part of E without its first and last = by spaces (consecutive spaces count as one separator, and leading and trailing spaces are ignored) gives exactly 2 items, neither of which contains =, the first item becomes the new O and the second the new C. The new delimiters are used from right after this tag (including the rest of the same line) and stay in effect until the end of that source or until they are changed again. Otherwise, it is the error "invalid delimiters".

Section 5. Checking tags
Check the tags in the order in which they appear in the source. When an error is found, stop analyzing the source at that point and report that error; nothing after it is examined. The line number of the error is the line number of the line containing that tag. Within the same line, tags are checked from left to right. unclosed tag and invalid delimiters are also errors found at the position of that tag and follow this order.
The format of a "name" is one of: ".", one of the 4 loop variable names "@index", "@number", "@first", "@last", or 1 or more identifiers or subscripts separated by "." (examples: name, user.address.city, items.0.price, 0).
An expression is checked as follows. Split the expression into parts at each | that is outside quotes. Here, "outside quotes" means being outside when the expression is read from the beginning and the state toggles between inside and outside at each ' (starting outside).
- The first part, with the surrounding spaces stripped, is the name of the expression. If it does not match the name format, error "invalid name '<name>'".
- Each of the second and later parts, in order, has its surrounding spaces stripped and is then split at each : that is outside quotes. The first item is the filter name and the second and later items are the arguments. Spaces are not stripped from the filter name or the arguments after splitting (for example, the filter name of "pad :3" is "pad " (pad followed by one ASCII space), and the argument of "pad: 3" is " 3" (one ASCII space followed by 3)). If the filter name is not one of the 29 filters in Section 10, error "unknown filter '<filter name>'"; if the number or notation of the arguments does not follow that filter's rule, error "bad arguments for '<filter name>'".
An argument notation is either a string of 2 or more characters that starts with ' and ends with ' and contains no ' in between (a string argument; its value is the string without the ' at both ends, and it may be empty), or an optional - followed by 1 to 9 digits (an integer argument; read as a decimal number, ignoring leading zeros). Anything that is neither does not follow the rule of any filter.
Each tag is checked as follows.
- Variable tag and raw variable tag: check the expression.
- Section start tag and inverted section start tag: check the argument part as an expression, and if it passes, "open" a section named by the name of that expression.
- Closing tag: let A be the argument part. If A does not match the name format, error "invalid name '<A>'" (filters cannot be written). If no section is open, error "unexpected closing '<A>'". Let B be the name of the innermost (most recently opened) open section; if A and B differ, error "mismatched closing '<A>', expected '<B>'". If they are the same, close that section.
- Partial tag: if the argument part is not an identifier, error "invalid name '<argument part>'".
- Comment tag: no check; do nothing.
- Delimiter change tag: only the processing of Section 4.
If, after examining up to the end of the source, some sections remain open without being closed, it is the error "unclosed section '<its name>'" for the innermost one of them, and the line number is the line number of that section start tag.

Section 6. Standalone lines
A line of the source that has exactly one tag, where that tag is a section start tag, an inverted section start tag, a closing tag, a comment tag, a partial tag or a delimiter change tag, and where all the text of that line consists only of spaces (it may be empty), is called a "standalone line".
- On a standalone line, the text is discarded and the LF at the end of the line is not output either. Only the effect of the tag remains.
- On a line that is not standalone, the texts and tags are arranged in the order in which they appeared, and then one LF is added.
- When a partial tag is on a standalone line, the text before that tag (0 or more spaces) is the "indentation" of that partial template. The indentation of a partial tag that is not on a standalone line is empty.
By the above, the source becomes a sequence of texts (including the added LFs) and tags. The part of the sequence between a section start tag or inverted section start tag and the closing tag that closed it is called the "content" of that section.
For example, in a source consisting of the 3 lines "{{#items}}", "  - {{name}}", "{{/items}}", lines 1 and 3 are standalone lines and are removed, and the content of section items consists of the 3 items: the text "  - " (2 spaces, -, 1 space), the variable tag name, and LF. On the other hand, the line "{{#a}}x{{/a}}" is not a standalone line; that line becomes a section with content x, followed by the LF at the end of the line.

Section 7. Rendering and name resolution
Rendering uses a "context stack" and a "loop stack". When rendering of a template begins, the context stack contains only the root and the loop stack is empty. Process the sequence of texts and tags from the beginning; the concatenation of all output strings is the rendered result.
- Text: output it as is.
- Variable tag: evaluate the expression, convert the result to a string (Section 9), HTML-escape it, and output it. HTML escaping means replacing, among the characters of the string, & with &amp;, < with &lt;, > with &gt;, " with &quot;, and ' with &#39; (replaced results are not replaced again).
- Raw variable tag: evaluate the expression, convert the result to a string, and output it as is.
- Section start tag: let v be the result of evaluating the expression.
  - If v is a list, for each element in order from the beginning, push that element onto the context stack and push the pair (index i of the element, number of elements n) onto the loop stack, render the content, and then pop both stacks. If v is an empty list, nothing is output. An element is rendered even if it is a falsy value (Section 9).
  - If v is not a list and is a truthy value, push v onto the context stack, render the content once, and then pop it. The loop stack is not changed.
  - If v is a falsy value, nothing is output.
- Inverted section start tag: if the result of evaluating the expression is a falsy value, render the content once without changing either stack. If it is a truthy value, nothing is output.
- Comment tag and delimiter change tag: nothing is output.
- Partial tag: as described in Section 8.
Evaluating an expression: resolve the name of the expression by the rules below, and apply the filters to the obtained value from left to right (Section 10); the result is the result of the evaluation. However, when strict mode is ON, for variable tags and raw variable tags only, a failed name resolution is the runtime error "missing '<name>'" (no filter is applied). For section start tags and inverted section start tags, a failed resolution is not an error even in strict mode.
Name resolution:
- "." resolves to the top value of the context stack (the resolution counts as successful even if that value is absent).
- A loop variable name fails to resolve if the loop stack is empty. Otherwise, for the top pair (i, n) of the loop stack, @index resolves to the integer i, @number to the integer i+1, @first to true if i=0 and false otherwise, and @last to true if i=n-1 and false otherwise.
- Any other name is split into parts at "." (an identifier as is; a subscript is a part denoting the index given by its value). Examine the values of the context stack from the top down and find the first value that has the first part. If none is found, the resolution fails. If one is found, starting from that value, follow the parts in order from the beginning to "the part of that value". If some part is not present on the way, the resolution fails (it does not go back to search lower values of the context stack again). The name resolves to the value reached after following the last part.
When resolution fails, the value is absent.

Section 8. Partial templates
When processing a partial tag, check the following in order.
(1) If there is no partial template with that name, runtime error "unknown partial '<name>'".
(2) The depth of the template's source is 0, and the depth of the source of a partial template rendered by a partial tag in a source of depth d is d+1. If the depth of the source containing this tag is 8, runtime error "partial depth exceeded at '<name>'".
(3) The source of the partial template is made from the lines of its body, where each non-empty line gets the tag's indentation prepended (empty lines stay as they are). The line numbers remain the line numbers of the body lines. Analyze this source as described in Sections 4 to 6 (the delimiters start as {{ and }}), render it using the context stack and loop stack as they are at that moment, and output the result at this position.
Since partial templates are checked when they are defined (Section 11), the analysis in (3) never produces an error. Note that the indentation is added to the lines of the partial template's body; it is not added after an LF contained in the value of a variable.

Section 9. String conversion, truthiness, numeric conversion
The string conversion S(v) of a value v is as follows.
- Absent is the empty string, a string is itself, an integer is its decimal notation (with a leading - if negative), and a boolean is true or false.
- A list is the string conversions of its elements joined in order from the beginning by ", " (a comma and one ASCII space). An empty list is the empty string.
- A map cannot be converted to a string; it is the runtime error "cannot render map" (the same applies when a list has a map as an element).
A value is a "falsy value" when it is absent, false, the integer 0, the empty string, an empty list or an empty map. Every other value (including the strings 0 and false) is a "truthy value".
The numeric conversion N(v) of a value v inside a filter f is as follows. Absent is 0, an integer is itself, and a string that is an optional - followed by 1 to 9 digits is the integer obtained by reading it as a decimal number (ignoring leading zeros). Anything else (booleans, lists, maps, strings not of the above form) is the runtime error "not a number for '<f>'".

Section 10. Filters
Each filter receives a value v (the value of the expression at that point) and returns a new value. The way each filter is written, its argument rule and its result are as follows. n denotes an integer argument, s, t, c, p denote string arguments, and x denotes a string argument or an integer argument. The rule is to give the number and kinds of arguments shown in the written form, satisfying the conditions stated there; any other way of giving arguments does not follow the rule. For filters whose result description involves S(v) or N(v), the runtime errors of Section 9 may occur in that computation. Below, returning the received value unchanged is written "v unchanged".
- upper: the string S(v) with lowercase letters changed to the corresponding uppercase letters.
- lower: the string S(v) with uppercase letters changed to the corresponding lowercase letters.
- title: the string S(v) in which the first character and every character whose preceding character is a space are changed to uppercase letters, and all other letters are changed to lowercase letters (non-letters are unchanged). For example, "hELLO  wORLD 3d" becomes "Hello  World 3d".
- trim: the string S(v) with the surrounding spaces stripped.
- length: the number of elements if v is a list, the number of keys if it is a map, and otherwise the length of S(v) (0 if absent). The result is an integer.
- first, last: if v is a list, its first element (first) or last element (last), or absent if the list is empty. If it is not a list, v unchanged.
- reverse: if v is a list, the list with its elements in reverse order; if it is a string, the string with its characters in reverse order. Otherwise v unchanged.
- items: if v is a map, sort all its keys in increasing order, and for each key K create a map with exactly two keys, key (whose value is the string K) and value (whose value is the K of v); the result is the list of these maps in that order. If it is not a map, v unchanged.
- comma: the string made from the decimal notation of the absolute value of N(v) by inserting "," every 3 digits from the right, with a leading - if N(v) is negative. For example, 1234567 becomes 1,234,567, -1000 becomes -1,000, and 999 becomes 999.
- sum, min, max: if v is a list, convert each element to a number in order from the beginning (if an error occurs on the way, it is a runtime error at that point), and the result is their total (sum), minimum (min) or maximum (max). For an empty list, sum is 0 and min and max are absent. If it is not a list, N(v).
- default:x: if v is a falsy value, the value of the argument x; if it is a truthy value, v unchanged.
- eq:x: true if S(v) and S(value of x) are equal, false if they differ.
- pad:n, pad:n:c: n is 0 or more and c has length 1. If the length of S(v) is less than n, the string made by appending c (a space if c is not given) at the end until the length becomes n. Otherwise S(v).
- lpad:n, lpad:n:c: the same as pad, but the characters are added at the beginning instead of the end.
- truncate:n: n is 0 or more. If the length of S(v) is greater than n, the first n characters followed by "..." (3 periods). Otherwise S(v).
- replace:s:t: s is a non-empty string. The string obtained by scanning S(v) from the beginning, replacing each occurrence of s with t, and continuing the scan right after the replaced part (the replacement result itself is not scanned). For example, if S(v) is aaaa, s is aa and t is b, the result is bb.
- join:s: if v is a list, the string conversions of its elements joined in order from the beginning by s. If it is not a list, S(v).
- sort, sort:p: if v is a list, the list with its elements sorted in increasing order of their "sort key". Elements with equal sort keys keep their original order (stable sort). Without an argument, the element itself is the sort key; with the argument p, the sort key is the value of key p if the element is a map that has the key p, and absent otherwise. Sort keys are ordered by kind as absent, integer, string, boolean, and list or map, from smallest; within the same kind, integers are compared by numeric value, strings by the order of Section 1, booleans with false smaller, and all lists and maps are equal. If it is not a list, v unchanged.
- pluck:p: if v is a list, the list in which each element is replaced by the value of key p if the element is a map that has the key p, and by absent otherwise. If it is not a list, v unchanged.
- add:n, sub:n, mul:n: N(v)+n, N(v)-n, N(v)*n.
- div:n, mod:n: n is not 0. div is the largest integer not greater than N(v)/n (rounding toward negative infinity), and mod is N(v) - n*(result of div). For example, for -7, div:2 is -4 and mod:2 is 1; for 7, div:-2 is -4 and mod:-2 is -1.
- gt:n, lt:n: true if N(v) is greater than n (gt), or less than n (lt); otherwise false.
(Giving arguments to the filters without arguments, upper, lower, title, trim, length, first, last, reverse, items, comma, sum, min, max, does not follow the rule. For example, "upper:1" is bad arguments for 'upper'.)

Section 11. Commands
DATA
Process as described in Section 3 and output.

PARTIAL name
Analyze the body as a source as described in Sections 4 and 5 (there is no indentation, and the delimiters start as {{ and }}). If there is an error, output "PARTIAL <name> ERROR line <line number>: <reason>" and do not change the collection of partial templates (if a partial template with the same name already exists, it remains). If there is no error, make this body the body of partial template name, and output "PARTIAL <name> DEFINED lines=<number of lines of the body>" if no partial template with the same name existed, or "PARTIAL <name> REPLACED lines=<number of lines of the body>" if one existed (it was replaced).

TEMPLATE name
Make this body the body of template name (if a template with the same name exists, replace it; it is stored even if analysis or rendering produces an error). Then render template name.

RENDER name
If template name exists, render it with the current state. Otherwise, output "TEMPLATE <name> ERROR line <line number of this RENDER line>: unknown template '<name>'".

Template name is rendered as follows. Analyze the body as a source (depth 0) as described in Sections 4 to 6, and if there is no error, render it as described in Section 7. When the analysis finds an error, or when a runtime error occurs during rendering, stop rendering at that point and output only the single line "TEMPLATE <name> ERROR line <line number>: <reason>" (the result rendered up to that point is not output). The line number of a runtime error is the line number of the line containing the tag that caused the error. For a tag inside a partial template, it is the line number of the line of that partial template's body. Within the processing of one tag, the order is name resolution (including the strict mode check), application of the filters from left to right, then string conversion, and only the first runtime error that occurs is reported.
If there is no error, for the rendered result R, output "TEMPLATE <name> OK lines=<L> chars=<length of R>", followed by R line by line. The "lines" of R are the pieces of R split at LF. However, when R ends with LF, the last empty piece is excluded, and when R is empty there are 0 lines. L is the number of these lines. Each line is output as is, followed by LF (even when R does not end with LF, the last line is output followed by LF).

DUMP
List and output all "leaves" of the data. A leaf is a value reachable from the root that is a string, an integer, a boolean, an empty list or an empty map (the root itself is not a leaf). Traverse depth-first from the root, maps in increasing order of key and lists in increasing order of index, and list the leaves in the order they are encountered.
First output "DUMP leaves=<number of leaves>", followed by one line "<path> = <notation>" for each leaf. The path starts from the root key and is written by appending "." and the key for a map key (no "." before the first key), and "[", the index and "]" for a list index (example: items[0].price). The notation is, for a string, the string with \ replaced by \\, " by \", and LF by \n, enclosed in " at both ends; for an integer, its decimal notation; for a boolean, true or false; for an empty list, []; for an empty map, {}.

STRICT ON, STRICT OFF
Set strict mode to ON or OFF, respectively, and output the command line as is ("STRICT ON" or "STRICT OFF").

RESET
Make the data an empty map, empty the collection of partial templates and the collection of templates, and output "RESET". Strict mode is not changed.

END
Finish processing. Output nothing.

[Output format]
- For each command, output only the lines described in [Processing]. Every line ends with LF.
- The rendered result lines following a TEMPLATE OK line are output exactly as in the rendered result (empty lines are output as they are). In all other lines, words and values are separated by one ASCII space as described.
- Integers are written in decimal notation without extra leading zeros, with a leading - for negative numbers.
- The error reasons are the following 20 kinds (the < > parts are replaced as described in [Processing]; ' is the character ' itself).
  bad line
  bad key '<k>'
  bad value '<v>'
  index gap at '<prefix>'
  type conflict at '<prefix>'
  no value at '<k>'
  unclosed tag
  invalid delimiters
  invalid name '<name>'

In the list above, the first 6 kinds are errors in data blocks, the next 8 are analysis errors, the next 5 are errors during rendering (runtime errors), and the last 1 is an error that occurs in RENDER.

[Constraints]
- The input has at most 3000 lines.
- The absolute values of the integers in the data, of integer arguments, of filter results and of every integer that appears along the way are at most 10^9.
- The values of subscripts in keys are at most 1000. The nesting depth of values in the data (the number of parts followed from the root to that value) is at most 10.
- When rendering of a template succeeds, the length of the rendered result is at most 10000, and no line of the rendered result ends with a space.

[Example]
Input:
DATA
user.name = "Ann <Admin>"
items[0].name = "Pen"
items[0].price = 1200
items[1].name = "Ink"
items[1].price = 80
tags = ["new", "sale"]
x[3] = 1
ENDDATA
PARTIAL row
{{@number}}. {{name|pad:6:'.'}}{{price|comma|lpad:6}}
ENDPARTIAL
TEMPLATE receipt
Hello, {{user.name}}! / {{{user.name|upper}}}
{{#items}}
  {{>row}}
{{/items}}
{{! this line is removed }}
Tags: {{tags|join:' / '}} ({{tags|length}})
{{^coupon}}
Total: {{items|pluck:'price'|sum|comma}}
{{/coupon}}
ENDTEMPLATE
TEMPLATE broken
{{#items}}{{name}}
ENDTEMPLATE
END

Output:
DATA set=6 unset=0 errors=1
ERROR line 8: index gap at 'x[3]'
PARTIAL row DEFINED lines=1
TEMPLATE receipt OK lines=5 chars=110
Hello, Ann &lt;Admin&gt;! / ANN <ADMIN>
  1. Pen... 1,200
  2. Ink...    80
Tags: new / sale (2)
Total: 1,280
TEMPLATE broken ERROR line 25: unclosed section 'items'

In this example, the x[3] line is an error because, after the empty list of x (0 elements) is created, the index 3 is greater than the number of elements, so x is not created. In template receipt, the lines {{#items}}, {{>row}}, {{/items}}, the comment, {{^coupon}} and {{/coupon}} are standalone lines and are removed, and each line of partial template row gets the indentation (2 spaces) at its beginning. {{user.name}} is HTML-escaped, and the triple tag {{{user.name|upper}}} is not escaped. coupon fails to resolve and is a falsy value, so the content of the inverted section is rendered. In template broken, the section items opened on line 25 is not closed.
