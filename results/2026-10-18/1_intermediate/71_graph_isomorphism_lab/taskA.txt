[Overview]
Write a program that studies isomorphism and symmetry of small simple undirected graphs (at most 16 vertices). The program reads a sequence of commands from standard input, executes the commands in order, and writes the results to standard output. The commands define and generate named graphs (well-known graph families, complements, line graphs, Cartesian products, vertex relabelling and so on), compute invariants, perform colour refinement, search for canonical forms by individualisation and refinement, test isomorphism, compute the order and the orbits of the automorphism group, count subgraph isomorphisms, and enumerate the isomorphism classes of graphs with few vertices.

[Input format]
The input consists of the following lines, in this order.
- Line 1 is the number of commands N.
- Then N commands follow, one per line.
A command line consists of one or more words separated by single spaces, with no whitespace at the beginning or end of the line. The first word is the command name and the remaining words are the arguments. The formats of the commands are as follows (everything other than the command name is the name of an argument).
GRAPH name n e...
CYCLE name n
PATH name n
COMPLETE name n
BIPARTITE name a b
STAR name k
WHEEL name k
PETERSEN name
HYPERCUBE name d
CIRCULANT name n j...
GRID name r c
COMPLEMENT name g
LINE name g
PRODUCT name g1 g2
UNION name g1 g2
RELABEL name g p...
INDUCED name g v...
CANONIZE name g
DELETE g
LIST
SHOW g
INVARIANTS g
REFINE g v...
CANON g
ISO g1 g2
AUT g
SUBISO g1 g2
CLASSIFY n
In the formats, x... means zero or more arguments of the form x. However, j... of CIRCULANT and v... of INDUCED are one or more. For example, GRAPH has two or more arguments, and the third and all later ones are of the form e.
Arguments are written as follows.
- name, g, g1 and g2 are graph names. A graph name is a string of 1 to 8 characters that starts with a lowercase English letter (a to z) and consists only of lowercase English letters and digits (0 to 9). For example, g, k5 and pet2 are graph names, and K5, 5k, a_b and abcdefghi are not graph names.
- n, a, b, k, d, j, r, c, p and v are number words. A number word is a string of 1 to 3 characters consisting only of digits, whose first character is not 0 when it has 2 or more characters. Its value is the value read as a decimal number. For example, 0, 7 and 120 are number words, and 07, -1, +3, 1000 and x are not number words.
- e is an edge word. An edge word is a string formed by concatenating a number word, one "-" (an ASCII hyphen) and a number word, in this order (examples: 0-1, 12-3). With u the value of the first number word and v the value of the second, it is called the edge word u-v. For example, 0--1, 0-, 0-1-2 and 0-01 are not edge words.

[Processing]
Process the commands one at a time in input order, and write the output of each command immediately. Below, a string in double quotes is a string that appears literally in the input or output. In the descriptions of output, a part such as <n> is replaced by its value.

1. Graphs and terminology
- A graph consists of a number of vertices n (1 <= n <= 16) and a set of edges. The vertices are the n vertices 0, 1, ..., n - 1. An edge is a pair {u, v} of two distinct vertices u, v, and has no direction. There is at most one edge joining the same two vertices, and no edge joins a vertex to itself. The number of edges of a graph is written m.
- When there is an edge {u, v}, u and v are said to be adjacent, and v is called a neighbour of u. The degree of a vertex is the number of its neighbours.
- When an edge is written in output, it is written as u-v with u < v (for example, {3, 1} is 1-3). The edge order is the order that sorts edges by increasing u, and for equal u by increasing v.
- When two sequences of numbers of the same length are compared lexicographically, they are compared from the beginning, and the one whose first differing element is smaller is the smaller one. Two strings of the same length consisting of 0 and 1 are compared in the same way from the beginning, and the one whose first differing character is "0" is the smaller one.
- An automorphism of a graph G is a permutation sigma of the vertices of G (a one-to-one correspondence from vertices to vertices) such that, for any two vertices u, v, {u, v} is an edge if and only if {sigma(u), sigma(v)} is an edge. Two graphs G1, G2 are isomorphic if they have the same number of vertices and there exists a one-to-one correspondence f from the vertices of G1 to the vertices of G2 such that, for any two vertices u, v of G1, {u, v} is an edge of G1 if and only if {f(u), f(v)} is an edge of G2.
- The program keeps as its state a collection of pairs of a graph name and a graph (below, the registry). Initially the registry is empty. A name in the registry is called defined, and the graph with that name is referred to simply by that name (for example, "graph g").

2. Command checks and errors
For each command, check (1) to (5) below in order, and handle the first one that applies. A command that outputs an error changes nothing in the state and outputs only the single error line.
(1) The command name is not one of the formats (uppercase and lowercase letters are distinguished): error: unknown command <command name>
(2) The number of arguments differs from the format, or an argument does not follow the rules in [Input format]: error: bad arguments
(3) An argument that refers to an existing graph (g, g1, g2 in the formats) has a name that is not defined: with <name> the name of the first such argument, error: no graph <name>. Note that for the first argument name of a graph-defining command (section 3.), it does not matter whether it is defined.
(4) Perform the value checks given in the description of each command in sections 3. to 10., in the order of the description, and output the first error that applies.
(5) Process the command as described in sections 3. to 10.
Of the error lines used in value checks, the following two are shared by several commands. The other error lines are given in the description of each command.
- error: bad value: an argument value is outside the allowed range, for example too small.
- error: too large: the number of vertices of the graph to be built exceeds 16 (for CLASSIFY, n exceeds 5).

3. Graph-defining commands
The 18 commands from GRAPH to CANONIZE each build one graph from the arguments and put it into the registry under the name name. If name is already defined, the program replaces that graph with the new graph and outputs redefined <name> n <n> m <m>; otherwise it outputs defined <name> n <n> m <m> (<n> and <m> are the number of vertices and the number of edges of the new graph). The new graph is built from the graphs as they are before the registry is changed (for example, COMPLEMENT g g replaces graph g with its complement).
The graph built by each command and the value checks are as follows. "Join vertex x and vertex y" means adding the edge {x, y}. Even if the same two vertices are joined two or more times, there is only one edge.
- GRAPH name n e...: if n is 0, output error: bad value; if n is 17 or more, output error: too large. Next, examine the edge words of e... from the front, and for u-v, output error: bad edge <the edge word> if u >= n or v >= n or u = v, and output error: duplicate edge <the edge word> if it joins the same two vertices as an earlier edge word (for example, 0-1 after 1-0). Output an error only for the first edge word to which one applies, and write <the edge word> exactly as the edge word is written in the input. If there is no error, build the graph with n vertices in which vertex u and vertex v are joined for each edge word u-v (if e... has zero words, it is the graph with no edges).
- CYCLE name n: if n is 2 or less, error: bad value; if 17 or more, error: too large. The graph has n vertices, and for i = 0, 1, ..., n - 1, vertex i and vertex (i + 1) mod n are joined.
- PATH name n: if n is 0, error: bad value; if 17 or more, error: too large. The graph has n vertices, and for i = 0, 1, ..., n - 2, vertex i and vertex i + 1 are joined.
- COMPLETE name n: if n is 0, error: bad value; if 17 or more, error: too large. The graph has n vertices, and every two distinct vertices are joined.
- BIPARTITE name a b: if at least one of a and b is 0, error: bad value; if a + b is 17 or more, error: too large. The graph has a + b vertices, and for all i, j with 0 <= i < a, 0 <= j < b, vertex i and vertex a + j are joined.
- STAR name k: if k is 0, error: bad value; if 16 or more, error: too large. The graph has k + 1 vertices, and for i = 1, 2, ..., k, vertex 0 and vertex i are joined.
- WHEEL name k: if k is 2 or less, error: bad value; if 16 or more, error: too large. The graph has k + 1 vertices; for i = 1, 2, ..., k, vertex 0 and vertex i are joined, for i = 1, 2, ..., k - 1, vertex i and vertex i + 1 are joined, and in addition vertex k and vertex 1 are joined.
- PETERSEN name: the graph has 10 vertices, and for i = 0, 1, 2, 3, 4, vertex i and vertex (i + 1) mod 5, vertex i and vertex i + 5, and vertex 5 + i and vertex 5 + ((i + 2) mod 5) are joined.
- HYPERCUBE name d: if d is 0, error: bad value; if 5 or more, error: too large. The graph has 2^d (2 to the power d) vertices, and every two vertices whose vertex numbers, written as d-digit binary numbers, differ in exactly one digit are joined.
- CIRCULANT name n j...: if n is 2 or less, error: bad value; if 17 or more, error: too large. Next, with the values of j... from the front being j(1), j(2), ..., j(t), if some j(s) is 0, or some j(s) has 2 * j(s) > n, or j(1) < j(2) < ... < j(t) does not hold, error: bad value. The graph has n vertices, and for every pair of i = 0, 1, ..., n - 1 and s = 1, 2, ..., t, vertex i and vertex (i + j(s)) mod n are joined.
- GRID name r c: if at least one of r and c is 0, error: bad value; if r * c is 17 or more, error: too large. The graph has r * c vertices; vertex x * c + y is placed at position (x, y) for 0 <= x < r, 0 <= y < c, and if y + 1 < c the vertices at (x, y) and (x, y + 1) are joined, and if x + 1 < r the vertices at (x, y) and (x + 1, y) are joined.
- COMPLEMENT name g: builds the complement of graph g. The number of vertices is the same as g, and every two distinct vertices that are not adjacent in g are joined.
- LINE name g: builds the line graph of graph g. Let the edges of g in edge order be e(0), e(1), ..., e(m-1). If m is 0, output error: no edges; if m is 17 or more, output error: too large. Otherwise, the graph has m vertices, and for 0 <= i < j < m, if e(i) and e(j) share a vertex, vertex i and vertex j are joined.
- PRODUCT name g1 g2: builds the Cartesian product of graphs g1 and g2. With n1, n2 the numbers of vertices of g1, g2, if n1 * n2 is 17 or more, error: too large. The graph has n1 * n2 vertices, and the pair (x, y) of vertex x of g1 and vertex y of g2 corresponds to vertex x * n2 + y. For each edge {y, y'} of g2 and every x, the vertices of (x, y) and (x, y') are joined, and for each edge {x, x'} of g1 and every y, the vertices of (x, y) and (x', y) are joined.
- UNION name g1 g2: builds the graph that places graphs g1 and g2 side by side (the disjoint union). With n1, n2 the numbers of vertices of g1, g2, if n1 + n2 is 17 or more, error: too large. The graph has n1 + n2 vertices; for each edge {u, v} of g1, vertex u and vertex v are joined, and for each edge {u, v} of g2, vertex u + n1 and vertex v + n1 are joined.
- RELABEL name g p...: renumbers the vertices of graph g. Let n be the number of vertices of g, and let the values of p... from the front be p(0), p(1), ..., p(t-1). If t != n, or p(0), ..., p(t-1) is not an arrangement of 0, 1, ..., n - 1 with each appearing once, output error: bad permutation. Otherwise, the graph has n vertices, and for each edge {u, v} of g, vertex p(u) and vertex p(v) are joined (vertex i of g becomes vertex p(i) of the new graph).
- INDUCED name g v...: builds an induced subgraph of graph g. Let the values of v... from the front be v(0), v(1), ..., v(t-1). If some value is greater than or equal to the number of vertices of g, or the same value appears two or more times, output error: bad vertices. Otherwise, the graph has t vertices, and for 0 <= i < j < t, if v(i) and v(j) are adjacent in g, vertex i and vertex j are joined (vertex i of the new graph corresponds to vertex v(i) of g).
- CANONIZE name g: finds the canonical labelling lambda (section 6.) of graph g, and builds the graph with the same number of vertices as g in which, for each edge {u, v} of g, vertex lambda(u) and vertex lambda(v) are joined.

4. Registry operations, graph display and invariants
- DELETE g: removes graph g from the registry and outputs deleted <g>.
- LIST: outputs graphs <number of defined names> on the first line, and then, for each defined name, one line <name> n <number of vertices> m <number of edges>. Names are sorted in lexicographic order of ASCII codes (compare character by character from the beginning by ASCII code; when one is a prefix of the other, the shorter one comes first).
- SHOW g: outputs graph <g> n <number of vertices> m <number of edges> on the first line, and then, for vertices v = 0, 1, ..., n - 1 in this order, a line consisting of <v>: followed by the neighbours of v in increasing order, each preceded by a single space (example: 2: 0 1 5). If v has no neighbours, the line is just <v>:.
- INVARIANTS g: outputs the invariants of graph g in the following 8 lines.
  invariants <g>
  degrees <degree sequence>
  edges <number of edges> triangles <number of triangles>
  components <number of connected components> sizes <sequence of connected component sizes>
  girth <girth> diameter <diameter> radius <radius>
  bipartite <yes or no>
  the clique line
  the chromatic line
  Here, the degree sequence is the sequence of the degrees of all vertices in decreasing order, the number of triangles is the number of sets of 3 vertices in which every two vertices are adjacent, and the sequence of connected component sizes is the sequence of the numbers of vertices of the connected components in decreasing order (the elements of a sequence are separated by single spaces). A connected component is a group of vertices that can reach one another by repeatedly moving to an adjacent vertex.
  The girth is the length of the shortest cycle (a cycle is 3 or more distinct vertices x1, x2, ..., xs such that x1 and x2, x2 and x3, ..., xs and x1 are each adjacent, and its length is s); if there is no cycle, it is written none.
  The distance between two vertices is the minimum number of moves needed to get from one to the other by repeatedly moving to an adjacent vertex. The eccentricity of a vertex v is the maximum of the distances between v and each vertex (including v itself). If the number of connected components is 1, the diameter is the maximum eccentricity and the radius is the minimum eccentricity. If the number of connected components is 2 or more, both the diameter and the radius are written INF.
  bipartite is yes if all vertices can be split into two groups so that every edge joins two vertices of different groups, and no otherwise.
  If the number of vertices is 13 or more, the clique line and the chromatic line are clique - and chromatic - respectively. If the number of vertices is 12 or less, they are as follows.
  - The clique line is clique <omega> <vertex sequence>. A clique is a set of vertices in which every two vertices are adjacent (including sets of a single vertex), and omega is the maximum number of vertices of a clique. In <vertex sequence>, write, among the cliques with omega vertices, the one whose vertices listed in increasing order form the lexicographically smallest sequence, in that order.
  - The chromatic line is chromatic <chi> <colour sequence>. A colouring assigns one colour (an integer >= 0) to each vertex so that no two adjacent vertices get the same colour. chi is the smallest integer such that a colouring using only colours 0, 1, ..., chi - 1 exists (the chromatic number). In <colour sequence>, write, among the colourings using only colours 0, ..., chi - 1, the one whose sequence of the colours of vertices 0, 1, ..., n - 1 in order is lexicographically smallest, in that order.

5. Colour refinement
- A colour partition assigns one colour (an integer >= 0) to each vertex such that the colours used are exactly 0, 1, ..., k - 1. k is called the number of colours. The set of vertices assigned colour x is called the cell of colour x (or simply a cell). The colour assigned to vertex v in colour partition c is written c(v).
- The degree colour partition is the colour partition that assigns to each vertex v, as its colour, the number of distinct values, among the values occurring as degrees of the vertices, that are smaller than the degree of v. For example, for 4 vertices with degrees 3, 1, 1, 2, the colours are 2, 0, 0, 1.
- Round: a new colour partition c' is made from colour partition c as follows. For each vertex v, let L(v) be the sequence of the colours of the neighbours of v in increasing order (equal colours are listed repeatedly; if there are no neighbours it is the empty sequence), and let the pair (c(v), L(v)) be the signature of v. Two signatures are compared first by their first elements, the colours, and if those are equal, by comparing their second elements, the sequences, from the beginning, where the one whose first differing element is smaller is the smaller one (when one sequence is a prefix of the other, the shorter one is the smaller one). c'(v) is the number of distinct signatures, among those occurring as signatures of the vertices, that are smaller than the signature of v.
- Refinement: starting from colour partition c, repeatedly make c' by a round. If the number of colours of c' equals the number of colours of c, finish with c as the result (this round is not counted). Otherwise replace c by c', add 1 to the round count, and repeat. The number of rounds of a refinement is the total number of rounds added until it finishes.
- Individualisation: individualising vertex v in colour partition c means, with x = c(v), making the colour partition c' in which the colour of each vertex w is the following c'(w). If c(w) < x, c'(w) = c(w); if w = v, c'(w) = x; otherwise (c(w) > x, or c(w) = x and w != v), c'(w) = c(w) + 1.
- The stable colour partition of a graph is the result of refining the degree colour partition.
- REFINE g v...: let the values of v... from the front be v(0), v(1), ..., v(t-1). If some value is greater than or equal to the number of vertices of graph g, output error: bad vertices. Otherwise, let c be the stable colour partition of g and r the number of rounds of that refinement, and for i = 0, 1, ..., t - 1 in order do the following. If the cell of v(i) in c consists of v(i) alone, output error: singleton <v(i)> and finish processing this command (nothing else is output). Otherwise, let the new c be the result of refining the colour partition obtained by individualising v(i) in c, and add the number of rounds of that refinement to r. When all have been done, with k the number of colours of c, output refine <g> rounds <r> cells <k> on the first line, and then, for colours x = 0, 1, ..., k - 1 in this order, a line consisting of <x>: followed by the vertices of the cell of colour x in increasing order, each preceded by a single space (example: 1: 2 3).

6. Canonical form search
The canonical form of a graph G (with n vertices) is found by traversing the following search tree depth-first. Each node of the search tree is a colour partition.
(1) The root is the stable colour partition of G.
(2) When a node is visited, add 1 to the number of visited nodes. If the number of colours of its colour partition c is n (that is, if every cell has only one vertex), the node is a leaf and has no children.
(3) At a node that is not a leaf, choose, among the cells containing 2 or more vertices, the one with the fewest vertices (if there are several such cells, the one with the smallest colour). Take the vertices v of the chosen cell one at a time in increasing order; the child is the result of refining the colour partition obtained by individualising v in c, and after that child and all its descendants have been visited, move on to the next v.
Since the colour partition lambda of a leaf assigns to each vertex exactly one of 0, 1, ..., n - 1, it is also called a labelling. The string of a leaf lambda is the string of 0s and 1s of length n(n - 1)/2 obtained from the n-by-n matrix B whose element in row lambda(u) and column lambda(v) is 1 if {u, v} is an edge of G and 0 otherwise (rows and columns are counted from 0, and the diagonal elements are 0), by writing the elements of B in row i and column j for i = 0, 1, ..., n - 2 in order, and for each i, for j = i + 1, ..., n - 1 in order (if n = 1, it is the empty string).
The largest of the strings of all leaves (by the comparison in section 1.) is called the canonical string. The lambda of the first visited leaf among the leaves having the canonical string is called the canonical labelling. The canonical strings of two graphs are equal if and only if they are isomorphic. Also, the number of leaves having the canonical string equals the number of automorphisms of G.
- CANON g: search for the canonical form of graph g, and with <nodes> the number of visited nodes (including the root and the leaves), <leaves> the number of leaves, lambda the canonical labelling and s the canonical string, output the following 3 lines.
  canon <g> nodes <nodes> leaves <leaves>
  labels <lambda(0)> <lambda(1)> ... <lambda(n-1)>
  string <s>
  If s is the empty string, output string -.

7. Isomorphism test
- ISO g1 g2: compare graphs g1 and g2 (they may have the same name) in the order of items (a) to (j) below, and output one line for the first item in which a difference is found. The values of (a) to (h) are the same as in INVARIANTS, and <value1> and <value2> are the values of g1 and g2.
  (a) The numbers of vertices differ: not isomorphic vertices <value1> <value2>
  (b) The numbers of edges differ: not isomorphic edges <value1> <value2>
  (c) The degree sequences differ: not isomorphic degrees
  (d) The numbers of triangles differ: not isomorphic triangles <value1> <value2>
  (e) The numbers of connected components differ: not isomorphic components <value1> <value2>
  (f) The girths differ: not isomorphic girth <value1> <value2>
  (g) The diameters differ: not isomorphic diameter <value1> <value2>
  (h) The bipartite values differ: not isomorphic bipartite <value1> <value2>
  (i) In the results of REFINE (with zero words in v...), the numbers of rounds differ, or the sequences of the numbers of vertices of the cells of colours 0, 1, ... in order differ: not isomorphic refinement
  (j) The canonical strings (section 6.) differ: not isomorphic canonical
  If no item has a difference, output isomorphic on the first line and mapping <f(0)> <f(1)> ... <f(n-1)> on the second line. With lambda1, lambda2 the canonical labellings of g1, g2, f(v) is the vertex w of g2 with lambda2(w) = lambda1(v) (f is an isomorphism correspondence from g1 to g2).

8. Automorphisms
- The order of the automorphism group of a graph G is the number of automorphisms of G. The orbit of a vertex v is the set of sigma(v) over all automorphisms sigma, and the orbit of an edge {u, v} is the set of edges {sigma(u), sigma(v)} over all automorphisms sigma. The set of all automorphisms equals the set of all sigma defined, with lambda0 the canonical labelling of G, for each leaf lambda having the canonical string by: sigma(v) is the vertex w with lambda0(w) = lambda(v).
- AUT g: output the following lines for graph g.
  aut <g> order <order of the automorphism group>
  vertex orbits <number of vertex orbits>
  For each vertex orbit, orbit <vertex sequence> (the vertices in the orbit in increasing order). The orbits are sorted by increasing smallest vertex they contain.
  edge orbits <number of edge orbits> (0 if there are no edges)
  For each edge orbit, orbit <edge sequence> (the edges in the orbit in edge order, in the form u-v). The orbits are sorted by the edge order of the first edge they contain.
  transitive vertex <yes or no> edge <yes or no>
  On the last line, vertex is yes if there is exactly one vertex orbit, edge is yes if there is exactly one edge orbit, and otherwise each is no.

9. Subgraph isomorphism
- SUBISO g1 g2: let graph g1 be the pattern P (with k vertices) and graph g2 the target T (with n vertices) (they may have the same name). An embedding is a map f from the vertices of P to the vertices of T that maps distinct vertices to distinct vertices and such that, for every edge {u, v} of P, {f(u), f(v)} is an edge of T. An induced embedding is an embedding such that, in addition, for any two distinct vertices u, v that are not adjacent in P, {f(u), f(v)} is not an edge of T. If k > n, there is no embedding.
  With E the number of embeddings, I the number of induced embeddings and A the order of the automorphism group of P, output subiso <g1> <g2> embeddings <E> induced <I> on the first line and copies <E / A> induced <I / A> on the second line (the divisions are always exact). Then, for the first 5 embeddings (all of them if there are fewer than 5) when the embeddings are sorted in lexicographic order of the sequence f(0), f(1), ..., f(k - 1), output embedding <f(0)> <f(1)> ... <f(k-1)> one per embedding, and if that embedding is an induced embedding, append a single space and induced at the end of the line.

10. Enumeration of isomorphism classes
- CLASSIFY n: if n is 0, error: bad value; if 6 or more, error: too large. For m = 0, 1, ..., n(n - 1)/2, let S(m) be the set of the canonical strings (section 6.) of all graphs with n vertices and m edges (the number of elements of S(m) is the number of isomorphism classes of graphs with n vertices and m edges). Output classify <n> total <total number of elements of S(0), S(1), ...> on the first line, and then, in increasing order of m, a line consisting of edges <m> count <number of elements of S(m)> followed by the strings of S(m) in increasing order, each preceded by a single space. The empty string for n = 1 is written -.
  Note that S(0) consists only of the canonical string of the graph with no edges, and S(m+1) is obtained from S(m) as follows. For each string s in S(m), consider the matrix B from which the string s is obtained by the construction in section 6., and build the graph with n vertices in which vertex i and vertex j are joined for every i < j such that the element of B in row i and column j is 1. Build, for every s and every choice of two vertices, the graph obtained by adding one edge joining two non-adjacent vertices of this graph; the set of their canonical strings is S(m+1).

[Output format]
- For each command, output the lines described in [Processing], in that order. Unless otherwise specified, the output of each command is one line.
- Words within a line are separated by single spaces, no line has whitespace at its beginning or end, and every line ends with a newline (lines shown indented in [Processing] are also output without leading whitespace).
- Numbers are written in decimal without extra leading zeros.
- In the descriptions in [Processing], the period at the end of each item is sentence punctuation and is not part of the output.

[Constraints]
- 1 <= N <= 500.
- Each word of a command line is a string of 1 to 20 printable ASCII characters other than whitespace (from ! to ~), and each line has at most 1000 characters.
- In the search of section 6. (including, besides CANON, the searches performed internally by CANONIZE, ISO, AUT, SUBISO and CLASSIFY), the number of visited nodes is at most 2 * 10^4 for every search in the input.
- For SUBISO, the sum over i = 1, 2, ..., k of the number of maps from vertices 0, 1, ..., i - 1 of P to vertices of T that map distinct vertices to distinct vertices and map every edge of P among vertices 0, ..., i - 1 to an edge of T is at most 10^5.
