[Overview]
Write an event-driven logic simulator for digital logic circuits assembled from hierarchical modules. The program reads, line by line from standard input up to the line "END", module definitions (a module is a circuit component that lists logic gates and instances of other modules) and commands, processes them in the order read, and writes the results to standard output. Signals take three values, 0, 1 and X (unknown), and there are 10 gate types: AND, OR, NAND, NOR, XOR, XNOR, NOT, BUF, the 2-input multiplexer MUX2, and the D flip-flop DFF, which acts on the rising edge of its clock. A module is checked for structural errors (undefined modules, undriven signals, multiple drivers, etc.) when it is defined, and when it is used it is converted into a flat circuit with its instances expanded. The commands that inspect modules provide a listing, netlist and hierarchy display, statistics, truth tables, an equivalence check of two modules, stuck-at fault detection, the longest and shortest delay paths, and clock period analysis. For simulation, one circuit is built, stimuli (value changes, vectors, pulses, clocks) are applied to its inputs, events with propagation delays (transport delays) are processed in time order, and changes of watched signals, waveforms, change histories, signal values, etc. are output. If more than 1000 events occur at the same time, the simulation halts as an oscillation.

[Input format]
The input consists of one or more lines, and the last line consists of only the three characters "END". A line consisting only of "END" appears only as the last line.
Each line consists of one or more words separated by single spaces. There are no spaces at the beginning or end of a line, and there are no empty lines. A word consists of one or more ASCII characters with codes 33 to 126 (printable characters other than the space).
The lines from a line whose first word is "MODULE" through the first subsequent line consisting only of "ENDMODULE" are called a module definition. The first line of a module definition is called the header line, the last line the end line, and the lines between them (zero or more) the body lines. A module definition has the following format.
  MODULE <module name> IN <input port>... OUT <output port>...
  <body line>
  ...
  ENDMODULE
A body line is one of the following: a gate line or an instance line.
  <gate type> <gate name> <input signal>... -> <output signal> <delay>
  INST <instance name> <module name> <port name>=<signal name>...
Here, <input port>... and the like denote zero or more words of that form. The gate types are the 10 types AND, OR, NAND, NOR, XOR, XNOR, NOT, BUF, MUX2, DFF.
A line not contained in any module definition (except the last "END" line) is a command line. The first word of a command line is called the command name, and the remaining words the arguments. There are the following 25 command formats.
  BUILD M
  RESET
  SET t s v
  APPLY t bits
  PULSE s t w
  CLOCK s start half count
  RUN t
  WATCH s...
  UNWATCH s...
  SHOW s...
  CHECK s v
  PROBE s
  WAVE t0 t1
  HISTORY s
  ACTIVITY k
  STATUS
  MODULES
  NETLIST M
  HIERARCHY M
  STATS M
  TRUTHTABLE M
  EQUIV M1 M2
  FAULTS M
  CRITICAL M
  PERIOD M
Here M, M1, M2 are module names, s is a signal name, v is a value, t, t0, t1, w, start, half, count, k are numbers, and bits is a word listing values. WATCH and UNWATCH take one or more s, and SHOW takes zero or more s.
Every input line satisfies [Constraints], but does not necessarily match the formats shown here. The handling of lines that do not match a format and of invalid words is defined in [Processing].

[Processing]
1. Overall flow
Number the input lines with line numbers starting from 1 (the lines of module definitions are counted too). Process the input from the beginning in order, and stop when the "END" line is reached (nothing is output for the "END" line). A module definition, from its header line through its end line, is processed together as one unit (section 3), and command lines are processed one line at a time (section 7 onward).
Below, strings in double quotes are strings that appear literally in the input or output. In descriptions of output, each part enclosed in < and > is replaced by its value.
An error is output as the single line "error: line <n>: <message>". <n> is the line number of the line specified in each item. Below, an error is shown only by its <message> part. The order of checks for one unit is specified in each item, and only the first error found is output. A module definition that results in an error does not define a module, and a command that results in an error does not change any state. In both cases nothing is output other than the single error line.

2. Names, numbers, values
- Name: a word of 1 to 16 characters that starts with a lowercase letter (a-z) and consists only of lowercase letters, digits (0-9) and "_". Names are used for ports, signals, gates and instances.
- Module name: a word of 1 to 16 characters that starts with an uppercase letter (A-Z) and consists only of uppercase letters, digits and "_".
- Number: a word of 1 to 9 characters consisting only of digits, whose first character is not "0" if it has 2 or more characters. It is read as a decimal number. For example, 0, 7, 1000 are numbers, and 007, -1, 1.5, 1x are not numbers.
- Value: a signal value is one of the three values 0, 1, X, written "0", "1", "X" respectively. A word representing a value is a one-character word that is one of these three.
- Name order: compare two strings character by character from the beginning by ASCII code; the one whose first differing character has the smaller code comes first. If one string is a prefix of the other, the shorter one comes first.

3. Module definitions
A defined module consists of a module name, a list of input ports, a list of output ports and a list of body lines, and it remains until the end of the input. The input port list and the output port list are each ordered as written in the header line; this order is called the port order. Initially no module is defined.
Check a module definition in the order (A) to (C) below.
(A) Check the header line in the following order. The error line number is the line number of the header line.
  (1) If the line does not satisfy all of the following conditions: it has 5 or more words, the third word is "IN", exactly one of the fourth and later words is "OUT", and the last word is not "OUT": bad module header
  (2) If the second word is not a module name: bad module name <second word>
  (3) If a module with that name is already defined: duplicate module <second word>
  (4) The words between "IN" and "OUT" are the input ports, and the words after "OUT" are the output ports (there may be zero input ports). Examine the input ports and then the output ports one word at a time: if the word is not a name, bad name <word>; if it is the same as an earlier port, duplicate port <word> (for each word, check these two in this order).
(B) Check the body lines one line at a time from top to bottom. The error line number is the line number of that body line. A signal name is called "driven" if, at the time of the check, it is one of the following: an input port; the output signal of a gate line in an earlier body line; a signal name connected to an output port in an instance line in an earlier body line; the signal name of a connection already examined in (7) of the same instance line. Also, the gate names and instance names of earlier body lines are called "used names".
  - If the first word is a gate type, check the line as a gate line in the following order.
    (1) The line matches the format if it has 5 or more words, the third word from the end is "->", and no other word is "->". If it does not match the format: bad gate syntax
    In what follows, the second word is the gate name, the words from the third word up to the word just before "->" are the input signals (m - 5 of them if the line has m words), the second word from the end is the output signal, and the last word is the delay word.
    (2) If the gate name is not a name: bad name <gate name>
    (3) If the number c of input signals is not within the range defined for the type (2 to 8 inclusive for AND, OR, NAND, NOR, XOR, XNOR; 1 for NOT and BUF; 3 for MUX2; 2 for DFF): bad input count <c> for <type>
    (4) Examine the input signals in order, followed by the output signal; if some word is not a name, for the first such word: bad name <word>
    (5) If the delay word is not a number or its value is greater than 1000: bad delay <delay word>
    (6) If the gate name is a used name: duplicate name <gate name>
    (7) If the output signal is driven: multiple drivers for <output signal>
  - If the first word is "INST", check the line as an instance line in the following order.
    (1) If the line has fewer than 3 words: bad instance syntax
    In what follows, the second word is the instance name, the third word is N, and the fourth and later words (zero or more) are the connections.
    (2) If the instance name is not a name: bad name <instance name>
    (3) If no module named N is defined: unknown module <N> (the module currently being defined, and a module whose definition resulted in an error, are not defined either)
    (4) Examine the connections one word at a time from the front, checking (a) to (d) below in this order.
      (a) If the word does not satisfy the condition that it contains exactly one "=" and has at least one character both before and after the "=": bad connection <word>
      In what follows, the part before "=" is the port name and the part after it is the signal name.
      (b) If the port name is neither an input port nor an output port of N: unknown port <port name>
      (c) If the port name is the same as the port name of an earlier connection on this line: duplicate connection <port name>
      (d) If the signal name is not a name: bad name <signal name>
    (5) If some input port of N has no connection, for the first such port in the port order of N: unconnected input <port name> (output ports may be left unconnected)
    (6) If the instance name is a used name: duplicate name <instance name>
    (7) Examine the connections to output ports of N one at a time in the order written; if the signal name is driven: multiple drivers for <signal name>
  - If the first word is anything else: unknown statement <first word>
(C) If (A) and (B) found no error, examine the following "reads" in order. First, going through the body lines from top to bottom, the reads are: for a gate line, its input signals in order; for an instance line, the signal names of the connections to input ports of N in the order written (the line number is the line number of that body line). After that, the output ports in port order are reads (the line number is the line number of the header line). If there is a read of a signal name that is not driven once all body lines have been checked, for the first such read: undriven signal <signal name>
If there is no error, define the module and output "defined <module name> inputs <number of input ports> outputs <number of output ports> gates <number of gate lines> instances <number of instance lines>".
Signal names, gate names and instance names have meaning only within their own module definition. Signal names are treated separately from gate names and instance names, so the same word may be used both as a signal name and as a gate name. The output signal of a gate may also be one of that gate's own input signals.

4. Flattening
Commands that use a module operate on the flat circuit (the flattened circuit) obtained by expanding all instances. The gate list obtained by expanding module N with prefix P (a string) and port mapping pi (which maps some of the port names of N to signal names) is defined as follows. The actual name of a signal name x appearing in the body of N is the name that pi maps x to if pi gives a mapping for x, and otherwise the string P followed by x.
- Going through the body lines from top to bottom: for a gate line, append to the end of the list one gate whose name is the string P followed by the gate name, whose type and delay are those of the line, and whose input signals and output signal are their respective actual names.
- For an instance line, let i be its instance name and N' its module name; append, as is, to the end of the list the gate list obtained by expanding N' with the prefix formed by concatenating P, i and "." in this order, and with the port mapping that maps port name p to the actual name of y for each connection p=y. An unconnected output port has no mapping, so its actual name is the new prefix followed by the port name.
The flattened circuit of module M consists of the gate list obtained by expanding M with the empty string as the prefix and an empty port mapping, together with the input ports and output ports of M. The order of the gate list is called the gate order. In what follows, G is the number of gates and n is the number of input ports of M. The signals of the flattened circuit are the input ports of M and the output signals of the gates. These are all distinct, and there are n + G of them. Each input signal of each gate, and each output port of M, is one of the signals. The signal order is the input ports of M in port order, followed by the output signals of the gates in gate order.
For example, the flattened circuit of FULL in the [Example] has the gates h1.x1 (XOR, inputs a, b, output t), h1.a1 (AND, inputs a, b, output c1), h2.x1 (XOR, inputs t, cin, output s), h2.a1 (AND, inputs t, cin, output c2), o1 (OR, inputs c1, c2, output cout) in this order, and its signal order is a, b, cin, t, c1, s, c2, cout. In a module that uses FULL twice, expanding "INST f0 FULL a=x b=y cin=z s=w" makes the output signal of f0.h1.x1 be f0.t and the output signal of f0.o1 be f0.cout.
A gate g "reads" a signal s if s is one of the input signals of g. Even if a gate has the same signal among its input signals several times, it is counted as one reading gate. The fanout of a signal s is the number of gates that read s.
Combinational loop: the flattened circuit has a combinational loop if there is a sequence of non-DFF gates g1, g2, ..., gm (m >= 1) such that g(i+1) reads the output signal of gi for i = 1, ..., m - 1, and g1 reads the output signal of gm (a cycle through a DFF is not a combinational loop).

5. Gate values
The output value of a non-DFF gate is determined from the values of its input signals as follows. If the same signal appears several times among the input signals, each occurrence is treated as one input.
- AND: 0 if some input is 0; otherwise 1 if all inputs are 1; otherwise X.
- OR: 1 if some input is 1; otherwise 0 if all inputs are 0; otherwise X.
- XOR: X if some input is X; otherwise 1 if the number of inputs with value 1 is odd, and 0 if it is even.
- NAND, NOR, XNOR: the inversion of the value of AND, OR, XOR respectively. Inverting a value turns 0 into 1 and 1 into 0, and leaves X as X.
- BUF: the value of the input itself. NOT: the inversion of the value of the input.
- MUX2: let the input signals be sel, a, b in order. If sel is 0, the value of a; if sel is 1, the value of b. If sel is X: the common value if the values of a and b are equal, and X if they differ (if a and b are both X, the result is X).
The input signals of a DFF are, in order, the clock clk and the data d, and its output signal is q. As defined in section 10, a DFF acts only when the value of clk changes from 0 to 1.

6. Evaluation as a combinational circuit
TRUTHTABLE, EQUIV and FAULTS evaluate a module M as a combinational circuit. Check M in the following order; if a condition holds, it is an error.
  (1) M is not defined: unknown module <M>
  (2) The flattened circuit contains a DFF: <M> is not combinational
  (3) The flattened circuit has a combinational loop: <M> has a combinational loop
  (4) n is greater than 8: too many inputs <n>
If there is no error, compute row r for each integer r = 0, 1, ..., 2^n - 1 (2^n is 2 to the power n), with r as the row number. The bit string of row r is the string of r written as an n-digit binary number (the most significant digit first). In row r, the value of the i-th input port is the i-th character of the bit string, and the value of the output signal of each gate is determined from the values of that gate's input signals as in section 5 (since there is no combinational loop, the values of all signals are uniquely determined and each is 0 or 1). The output values of row r are the values of the output ports listed in port order.

7. Common checks for commands
For a command line, check (1) to (4) below in order; if one holds, it is an error. The error line number of a command is the line number of that command line.
(1) The command name is none of the 25 commands (uppercase and lowercase letters are distinguished): unknown command <command name>
(2) The number of arguments differs from the format: wrong argument count
(3) For a simulation command (the 15 commands RESET, SET, APPLY, PULSE, CLOCK, RUN, WATCH, UNWATCH, SHOW, CHECK, PROBE, WAVE, HISTORY, ACTIVITY, STATUS), no circuit has been built (section 9): no circuit
(4) For the 5 commands SET, APPLY, PULSE, CLOCK, RUN, the simulation is halted (section 11): simulation halted
If none of these holds, perform the command-specific checks in the order given in the descriptions from section 8 onward, and if there is no error, execute the command. If an argument described as a "number" in a command description is not a number: bad number <word>; if an argument described as a "positive number" is not a number or its value is 0: bad number <word>.

8. Commands that inspect modules
These commands do not change the simulation state.
- MODULES: output "modules <number of defined modules>" on the first line, then, for each module in the order of definition, "<module name> inputs <number of input ports> outputs <number of output ports> gates <number of gates of the flattened circuit>".
- NETLIST M: if M is not defined: unknown module <M>. Output "netlist <M> gates <G> signals <n + G>" on the first line, then, for each gate in gate order, "<gate name> <type> <input signals in order, separated by single spaces> -> <output signal> <delay>".
- HIERARCHY M: if M is not defined: unknown module <M>. Output the instance hierarchy of M. The first line is M. Following the line of a module, for each instance line of that module's body, one at a time from top to bottom, output the line "<instance name> <module name of that instance>", followed by the lines produced by the same rule for the module of that instance. Each line starts with a number of spaces equal to twice its depth (0 for the line of M, 1 for the lines of the instances in the body of M, 2 for the lines of the instances inside those, ...). For example, the hierarchy of a module ADD that uses FULL twice is as follows.
  ADD
    f0 FULL
      h1 HALF
      h2 HALF
    f1 FULL
      h1 HALF
      h2 HALF
- STATS M: if M is not defined: unknown module <M>. Output the following 3 lines.
  stats <M> gates <G> signals <n + G> depth <depth>
  types <type> <count> <type> <count> ...
  max fanout <signal> <fanout>
  The depth is the maximum of the levels of all signals. The level of an input port and of a DFF output signal is 0, and the level of the output signal of a non-DFF gate is the maximum of the levels of that gate's input signals plus 1. If the flattened circuit has a combinational loop, write "-" as the depth. The types line lists, in the order AND, OR, NAND, NOR, XOR, XNOR, NOT, BUF, MUX2, DFF, only the types that occur at least once in the flattened circuit, each with its count. The max fanout line gives the signal with the largest fanout (if several signals share the maximum, the first in signal order) and its fanout.
- TRUTHTABLE M: after the checks of section 6, output on the first line the input ports in port order, then "|", then the output ports in port order, separated by single spaces (example: a b | s c). Then, for r = 0, 1, ..., 2^n - 1 in order, output a line of each character of the bit string of row r, "|", and each value of the output values of row r, separated by single spaces (example: 0 1 | 1 0).
- EQUIV M1 M2: if M1 is not defined: unknown module <M1>; if M2 is not defined: unknown module <M2>. Next, check (2) to (4) of section 6 for M1, and then (2) to (4) for M2. Next, if M1 and M2 differ in the number of input ports or in the number of output ports: port mismatch. If there is no error, compare the output values of row r of M1 and M2 for r = 0, 1, ... in order (port names are not compared); if some row differs, output for the first such row "not equivalent at <bit string>: <output values of M1> vs <output values of M2>", and otherwise output "equivalent". Here the output values are written by concatenating the values without separators (example: not equivalent at 11: 0 vs 1).
- FAULTS M: after the checks of section 6, examine stuck-at faults. A fault is a pair of a signal s and a value v (0 or 1), written "s/v". The circuit with fault s/v is the circuit in which the value of s is always v. That is, if s is an input port, the value of s is v regardless of the bit string of the row; if s is the output signal of a gate, the value of s is v regardless of that gate's computation; and the values of the other signals are computed as in section 5. A fault is detected in row r if the output values of row r differ from those of the fault-free circuit. A fault that is detected in at least one row is a detectable fault, and the first such row is the detecting row of that fault. Examine the faults for each signal s in signal order, s/0 then s/1, and output the following lines.
  First line: "faults <number of faults 2 * (n + G)> detected <number of detectable faults>"
  Then, for each fault that is not detectable, in the order examined: "undetected <s>/<v>"
  Last: a line consisting of "tests" followed by, for the row numbers of the detecting rows of the detectable faults (duplicates removed) in increasing order, the bit string of each such row written after a single space (for a signal s that is an output port, at least one of s/0 and s/1 is always detectable, so there is at least one bit string)
- CRITICAL M: if M is not defined: unknown module <M>; if the flattened circuit has a combinational loop: <M> has a combinational loop. Examine the delays from input ports to output ports, excluding paths through DFFs. For each signal, determine whether its latest arrival time L and earliest arrival time E are "defined" or "undefined", and their values when defined, as follows. For an input port they are defined, with L = E = 0. For the output signal of a DFF they are undefined. For the output signal of a non-DFF gate g: if none of the input signals of g has defined arrival times, they are undefined; if one or more do, L is the maximum of their L plus the delay of g, and E is the minimum of their E plus the delay of g. In the latter case, among the input signals with defined arrival times, the one with the largest L (if several, the first in the order of the input signals of g) is the "previous signal" of the output signal of g.
  For each output port in port order, output "<port> min <E> max <L>" if its arrival times are defined, and "<port> unreachable" if they are undefined. Then, if no output port has defined arrival times, output "critical none". Otherwise, taking as the endpoint the output port with the largest L (if several, the first in port order), output "critical <L of the endpoint>: <path>". The path is obtained by following previous signals from the endpoint one after another until a signal that has no previous signal is reached, and joining all the signals visited with " -> " (a space, "->", a space), in order from the end opposite to the endpoint to the endpoint. For example: a -> t -> s.
- PERIOD M: if M is not defined: unknown module <M>; if the flattened circuit has no DFF: <M> has no flip-flops; if the flattened circuit has a combinational loop: <M> has a combinational loop. Determine L and the previous signal of each signal by the same method as CRITICAL, changing only the starting points. That is, for an input port they are undefined, and for the output signal of each DFF they are defined, with L equal to the delay of that DFF (the output signal of a DFF has no previous signal). Let F be the number of DFFs. If none of the signals of the data inputs d of the DFFs has a defined L, output "flip-flops <F> period none". Otherwise, taking as the endpoint the one with the largest L (if several, the one whose DFF comes first in gate order), output "flip-flops <F> period <L of the endpoint>: <path>". The path is built in the same way as for CRITICAL.

9. Building the circuit
The simulation state consists of the circuit (the flattened circuit of one module), the value of each signal, the current time, the event queue, the watch list, the change record of each signal, the number of processed events, and whether the simulation is halted. Initially no circuit has been built.
- BUILD M: if M is not defined: unknown module <M>. Make the flattened circuit of M the new circuit, and set the values of all signals to X, the current time to 0, the event queue, the watch list and the change records of all signals to empty, the number of processed events to 0, and the state to not halted (the previous circuit and state are discarded). Output "built <M> signals <n + G> gates <G>".
- RESET: keep the circuit and the watch list, set the rest of the state to the same as just after BUILD, and output "reset".
Hereafter, the input ports of the module of the circuit are simply called inputs. Also, "signal" refers to a signal of the circuit and "gate" refers to a gate of the circuit.

10. Events
An event is a triple of a time, a signal and a value. To "schedule" an event means to add the event to the event queue. Within the event queue, an event with a smaller time comes first, and among events with equal times, the one scheduled earlier comes first.
Processing an event at time t (signal s, value v) means the following.
- If the value of s equals v, do nothing.
- Otherwise, letting u be the previous value of s, change the value of s to v. Then handle the gates that read s one at a time in gate order, as follows.
  Non-DFF gate: compute the output value y from the current values of its input signals as in section 5, and schedule the event with time t + delay, the output signal of the gate, and value y. Schedule it even if y is the same as the current value of the output signal.
  DFF: only when s is the clk of that DFF, u is 0 and v is 1, schedule the event with time t + delay, output signal q, and as its value the current value of d. Otherwise do nothing.
An event scheduled by a gate with delay 0 is an event at time t, and it is processed after the events at time t that are in the queue at that point.

11. Running the simulation
- RUN t: t is a number. Letting T be the current time, if t <= T: time <t> is not after <T>. While the event queue is not empty and the time of its first event is less than t, let tau be the time of the first event and repeat the following "step at time tau".
  (1) Remember the current values of all signals as the values at the start of the step.
  (2) While the time of the first event in the event queue is tau, repeatedly remove the first event from the queue and process it. However, if 1000 events have already been processed in this step before removing an event, halt due to oscillation (defined below). Every processed event, including events that did not change a value, is counted in the number of processed events.
  (3) For each signal whose value differs from its value at the start of the step, append the pair (tau, its value) to the end of the change record of that signal.
  (4) In watch list order, for each signal s whose value differs from its value at the start of the step, output "<tau> <s> <value of s>".
  The number of glitches of this step is the number of signals whose value changed at least once during the processing of (2) and whose value at the end of (2) equals its value at the start of the step (signals that immediately returned to their original value).
  When the repetition ends, set the current time to t and output "run <t> events <number of events processed by this command> glitches <total of the numbers of glitches of the steps of this command> pending <number of events remaining in the event queue>". If the event queue is empty from the start, or the time of its first event is t or more, output this line without performing any step.
  Halting due to oscillation: when halting in (2), output "halted: oscillation at time <tau>", empty the event queue, set the current time to tau, set the state to halted, and end this command. Steps (3) and (4) of this step are not performed, and the run line is not output. The 1000 events processed in this step are included in the number of processed events, and the signal values stay as they were at the moment of halting. The halted state continues until the next BUILD or RESET.

12. Stimuli
These commands schedule events that give values to inputs. The time argument of each command (t of SET, APPLY and PULSE, and start of CLOCK): if it is not a number, bad number <word>; if it is less than the current time, time <its value> is in the past.
- SET t s v: check t, s, v in this order. If s is not an input: not an input <s>; if v is not a word representing a value: bad value <v>. Schedule the event with time t, signal s and value v, and output "set <s> <v> at <t>".
- APPLY t bits: after checking t, if the number of characters of bits differs from the number of inputs, or bits contains a character other than "0", "1", "X": bad vector <bits>. For the inputs one at a time in port order, schedule an event at time t that gives the i-th input the value of the i-th character of bits, and output "apply <bits> at <t>".
- PULSE s t w: if s is not an input: not an input <s>. Next, check t and then w (a positive number). Schedule, in this order, an event at time t that gives s the value 1 and an event at time t + w that gives s the value 0, and output "pulse <s> <t> <t + w>".
- CLOCK s start half count: if s is not an input: not an input <s>. Next, check start, half (a positive number) and count (a positive number) in this order. For i = 0, 1, ..., count - 1 in order, schedule an event at time start + i * half that gives s the value 0 if i is even and the value 1 if i is odd, and output "clock <s> events <count> last <start + (count - 1) * half>".

13. Observation
- WATCH s...: examine the arguments in order from the front: if an argument is not a signal, unknown signal <s>; if it is already in the watch list or is the same as an earlier argument of this command, already watched <s> (for each argument, check these two in this order). If there is no error, append the arguments in this order to the end of the watch list, and output "watching <signals of the watch list in order, separated by single spaces>".
- UNWATCH s...: examine the arguments in order from the front: if an argument is not a signal, unknown signal <s>; if it is not in the watch list or is the same as an earlier argument of this command, not watched <s> (for each argument, check these two in this order). If there is no error, remove them from the watch list (the order of the remaining signals is unchanged), and output a line of the same form as WATCH. However, if the watch list has become empty, output "watching nothing".
- SHOW s...: if there are arguments, examine them in order from the front: if an argument is not a signal, unknown signal <s>. If there is no error, output one line consisting of "<s>=<value of s>" for each argument, separated by single spaces (if the same signal appears several times, write it each time). If there are no arguments, output one line consisting of the input ports of the module of the circuit in port order, then "|", then the output ports in port order, with each port written as "<port>=<its value>", separated by single spaces (example: a=1 b=0 | s=1 c=0. If there are no input ports, the line starts with "|").
- CHECK s v: if s is not a signal: unknown signal <s>; if v is not a word representing a value: bad value <v>. If the value of s is v, output "check <s>=<v> ok", and otherwise output "check <s>=<v> failed (<value of s>)".
- PROBE s: if s is not a signal: unknown signal <s>. Output the following 2 lines.
  First line: if s is an input, "<s>=<value of s> driven by input". Otherwise, letting g be the gate whose output signal is s, "<s>=<value of s> driven by <name of g> <type of g> <x>=<value of x> ... delay <delay of g>". The <x>=<value of x> part lists the input signals x of g in order (if the same signal appears several times, each time), separated by single spaces.
  Second line: "fanout <fanout of s>" followed by the names of the gates that read s, in gate order, each written after a single space.
- WAVE t0 t1: check t0 and then t1 for being numbers. If t0 < t1 <= current time does not hold: bad range <t0> <t1>; if the watch list is empty: nothing watched. In watch list order, for each signal s output "<s> <waveform>". The waveform is the string of the values of s at the end of time tau, one character each, for tau = t0, t0 + 1, ..., t1 - 1 in order. The value at the end of time tau is the value of the last pair, among the pairs of the change record of s, whose time is tau or less, and X if there is no such pair.
- HISTORY s: if s is not a signal: unknown signal <s>. Output one line consisting of "history <s> changes <number of pairs in the change record of s>" followed by each pair (tau, value) of the change record of s, in record order, as " <tau>:<value>" (starting with a space).
- ACTIVITY k: k is a positive number. Sort all signals in decreasing order of the number of pairs in their change records, ties broken by name order, and for the first k signals (all signals if there are fewer than k) output "<signal> <number of pairs in the change record>", one per line.
- STATUS: output the following 2 lines.
  circuit <module name of the circuit> time <current time> pending <number of events in the event queue> events <number of processed events> halted <yes if halted, otherwise no>
  values 0:<number of signals with value 0> 1:<number of signals with value 1> X:<number of signals with value X>

[Output format]
- For each module definition and each command line, output the lines defined in [Processing], in input order. When one unit outputs several lines, output them in the order described in [Processing]. Each module definition and command line that does not result in an error outputs one or more lines.
- The output consists only of ASCII characters, and each line ends with a newline (LF). Do not put spaces at the end of a line, and do not output empty lines. Within a line, the separator is a single space, except for the leading spaces of HIERARCHY lines.
- Numbers are written in decimal notation without extra leading zeros.
- Where [Processing] shows the form of a line, a period at the end of an item is sentence punctuation and is not included in the output.

[Constraints]
- The number of input lines (including the "END" line) is between 1 and 1000 inclusive, and each line is at most 100 characters long.
- A line whose first word is "MODULE" is always followed later by a line consisting only of "ENDMODULE", and between them there is no line whose first word is "MODULE" and no line consisting only of "END". A line consisting only of "ENDMODULE" appears only as the end line of a module definition.
- The flattened circuit of every defined module has at most 500 gates. The flattened circuit of a module that is the target of FAULTS has at most 100 gates.
- The value of every word that is a number is at most 1000000. When CLOCK does not result in an error, count is at most 1000 and start + (count - 1) * half is at most 1000000.
- A single RUN processes at most 100000 events.
- Every output line is at most 2000 characters long.
