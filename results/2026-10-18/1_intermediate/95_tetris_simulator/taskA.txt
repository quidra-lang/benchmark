[Overview]
Write a simulator of the falling-block puzzle "Tetris". The program reads a sequence of commands and operations from standard input and, in a well 10 columns wide and 22 rows high (the top 2 rows are hidden rows), handles the appearance of the 7 kinds of pieces (a 7-bag randomizer), movement and rotation (rotation states and wall kicks), soft drops and hard drops, hold, gravity and lock delay, line clears, scoring (level multiplier, Back-to-Back, T-spins, combos, perfect clears), level progression, cancelling and rising of garbage lines, game-over detection, board display and analysis, determination of the shortest operation sequence, automatic play by evaluating placements, searching for T-spin candidates, undoing moves, and saving and restoring states, and writes the results to standard output.

[Input format]
The first line is the number of lines N. Each of the following N lines contains one command line or operation line. The input consists of exactly these N + 1 lines.
Each line consists of one or more words separated by single spaces, with no whitespace at the beginning or end of the line. A line whose first word is one of the following 16 command names is called a command line; any other line is called an operation line. The formats of the command lines are as follows (the parts other than the command name are argument names).
NEW seed level
PRINT
NEXT
PREVIEW n
STATUS
ANALYZE
ROW r pattern
GARBAGE n h
ATTACK n
TICK n
UNDO
SAVE name
LOAD name
SPINS
HINT n
AUTO n
An operation line is a line listing names of operations (section 7) "L", "R", "LL", "RR", "SD", "DD", "CW", "CCW", "HD", "LOCK", "HOLD" (example: "CW RR SD HD"). However, as an error, it may contain words that are not operation names.

[Processing]
Process the lines one at a time in input order, writing the output for each line immediately. Below, a string enclosed in double quotes is a string that appears literally in the input or output. In the output descriptions, a part such as <v> is replaced by its value. The quotient of a / b is the integer obtained by discarding the fractional part (in the divisions of this problem, the dividend is 0 or more and the divisor is 1 or more).

1. The well
- The well consists of cells, 10 columns wide and 22 rows high. Columns are numbered 1 to 10 from left to right, rows are numbered 1 to 22 from bottom to top, and the cell in column c and row r is written (c, r). Rows 1 to 20 are the visible part, and rows 21 and 22 are hidden rows.
- Each cell is either empty or filled (contains a block). A position whose column number is less than 1 or greater than 10, or whose row number is less than 1 or greater than 22, is called "outside the well". There are no cells outside the well.
- When all 10 cells of a row are filled, the row is said to be "complete".

2. Pieces
- There are 7 kinds of pieces: "I", "O", "T", "S", "Z", "J", "L". Each piece consists of 4 blocks inside an n x n square frame (n = 4 for I, n = 2 for O, n = 3 for the others).
- A position inside the frame is written as the pair (i, j) of a column position i, counted 0, 1, ..., n - 1 from the left, and a row position j, counted 0, 1, ..., n - 1 from the top.
- Each piece has 4 rotation states, denoted by the state names "0", "R", "2", "L". In this order, their state numbers are 0, 1, 2, 3.
- The positions that contain blocks in state 0 are shown in the following figures. Each figure lists the rows of the frame from the top row down; "#" is a position with a block and "." is a position without one.
  I: "...." "####" "...." "...."
  O: "##" "##"
  T: ".#." "###" "..."
  S: ".##" "##." "..."
  Z: "##." ".##" "..."
  J: "#.." "###" "..."
  L: "..#" "###" "..."
- The positions that contain blocks in state number k + 1 (k = 0, 1, 2) are obtained by moving each position (i, j) that contains a block in state number k to (n - 1 - j, i) (that is, by rotating 90 degrees clockwise within the frame). For example, the states of T are as follows.
  0: ".#." "###" "..."
  R: ".#." ".##" ".#."
  2: "..." "###" ".#."
  L: ".#." "##." ".#."
- The position of a piece is represented by the triple (s, x, y) of the state number s, the column number x of the left edge of the frame, and the row number y of the top edge of the frame. For a piece at position (s, x, y), the block at frame position (i, j) in state s occupies the cell (c, r) = (x + i, y - j). x and y may take values for which part of the frame lies outside the well (x can also be 0 or less).
- When a piece of kind k is placed at position p and all positions occupied by its 4 blocks are not outside the well and are empty cells, we say "k can be placed at p".
- The spawn position is (0, 5, 22) for O and (0, 4, 22) for the other pieces. For example, T at its spawn position occupies (5, 22), (4, 21), (5, 21), (6, 21).
- The "lowest block row" is the minimum of the row numbers of the positions occupied by the 4 blocks.

3. Movement operations
The following 8 operations, each of which computes a new position from the position p = (s, x, y) of a piece of kind k, are called movement operations. A movement operation is evaluated on the well at that time and succeeds only when k can be placed at the resulting position. When it cannot be placed, the operation fails and the position does not change.
- "L": change the position to (s, x - 1, y).
- "R": change the position to (s, x + 1, y).
- "LL": repeat "L" as long as it succeeds. If it does not succeed even once, it fails.
- "RR": repeat "R" as long as it succeeds. If it does not succeed even once, it fails.
- "SD": change the position to (s, x, y - 1).
- "DD": repeat "SD" as long as it succeeds. If it does not succeed even once, it fails.
- "CW": right (clockwise) rotation. The state number b after the rotation is the remainder of s + 1 divided by 4.
- "CCW": left (counterclockwise) rotation. The state number b after the rotation is the remainder of s + 3 divided by 4.
For a rotation, try in order the 5 offsets (dx, dy) in the row of the table below that goes from the name of the state before the rotation to the name of the state after the rotation, use the first offset for which k can be placed at (b, x + dx, y + dy), and take that position as the result. The ordinal of the offset used among the 5 (1 to 5) is called the test number of that rotation. If k cannot be placed for any of the 5, the rotation fails. A positive dy points upward (the direction in which the row number increases). For rotations of O, instead of the table, only the single offset (0, 0) is tried.
  Table for J, L, S, T, Z:
  0->R: (0, 0), (-1, 0), (-1, 1), (0, -2), (-1, -2)
  R->0: (0, 0), (1, 0), (1, -1), (0, 2), (1, 2)
  R->2: (0, 0), (1, 0), (1, -1), (0, 2), (1, 2)
  2->R: (0, 0), (-1, 0), (-1, 1), (0, -2), (-1, -2)
  2->L: (0, 0), (1, 0), (1, 1), (0, -2), (1, -2)
  L->2: (0, 0), (-1, 0), (-1, -1), (0, 2), (-1, 2)
  L->0: (0, 0), (-1, 0), (-1, -1), (0, 2), (-1, 2)
  0->L: (0, 0), (1, 0), (1, 1), (0, -2), (1, -2)
  Table for I:
  0->R: (0, 0), (-2, 0), (1, 0), (-2, -1), (1, 2)
  R->0: (0, 0), (2, 0), (-1, 0), (2, 1), (-1, -2)
  R->2: (0, 0), (-1, 0), (2, 0), (-1, 2), (2, -1)
  2->R: (0, 0), (1, 0), (-2, 0), (1, -2), (-2, 1)
  2->L: (0, 0), (2, 0), (-1, 0), (2, 1), (-1, -2)
  L->2: (0, 0), (-2, 0), (1, 0), (-2, -1), (1, 2)
  L->0: (0, 0), (1, 0), (-2, 0), (1, -2), (-2, 1)
  0->L: (0, 0), (-1, 0), (2, 0), (-1, 2), (2, -1)
- When "SD" fails from position p, the piece is said to be grounded at p.
- The landing position of position p is the position reached by repeating "SD" from p as long as it succeeds (p itself if the piece is grounded at p).

4. Random numbers and the queue
- Each game uses one random number sequence. Random numbers are generated by the MINSTD method x <- (48271 * x) mod 2147483647. The initial value of x is the seed given by NEW. Each time a random number is drawn, x is updated, and the updated x is the value of the random number.
- The queue is the sequence of the kinds of the pieces that will come next.
- To add a bag, prepare the sequence of the 7 kinds "I", "O", "T", "S", "Z", "J", "L" (in this order, the first one being element 0), and for i = 6, 5, 4, 3, 2, 1 in this order, draw one random number, let j be its remainder divided by i + 1, and swap element i and element j (do nothing if i = j). Append the resulting sequence of 7 kinds to the end of the queue.
- To take the next piece from the queue, remove the kind at the front of the queue and use it. After that, if the length of the queue is less than 5, add a bag. Therefore the length of the queue is always 5 or more.
- The hole columns of garbage lines (section 9) are also drawn from the same random number sequence.

5. Game state
- A game has the following state.
  each cell of the well, the random number value, the queue, the hold (one piece kind, or empty), whether hold has been used
  the kind and position of the current piece, the last motion (one of "none", "move", "rotation"; for "rotation" it also holds its test number)
  values for the current piece: operation count, drop points, fall counter, ground counter, reset count, lowest record
  starting level, level, score, number of cleared lines, piece count (the number of locked pieces), consecutive clear count S, consecutive difficult clear count B, pending list (a list of positive integers, each being a number of rows of garbage lines)
  the statistics values (section 10), whether the game has ended
  history, piece start state, saves (section 11)
- A game becomes "in progress" when it is started with NEW, and becomes "ended" when the game is over.
- When a new game is started with NEW, set the random number value to the seed, the starting level and the level to the specified level, all cells of the well to empty, the queue to empty, the hold to empty, the hold to not used, the score, number of cleared lines, piece count, S, B and all statistics values to 0, and the pending list, history and saves to empty. Then add a bag, take the next piece from the queue and spawn it (section 6), and record the piece start state (section 11).

6. Spawning, position updates, game over
- To spawn a piece of kind k, set the current piece to kind k, its position to the spawn position and the last motion to "none", set the operation count, drop points, fall counter, ground counter and reset count to 0, and set the lowest record to the lowest block row at the spawn position. If k cannot be placed at the spawn position, the game is over (block out).
- To "update the position" of the piece to position p, set the position of the piece to p and the last motion to the specified one. Further, if the lowest block row at p is smaller than the lowest record, set the lowest record to that value and set the reset count to 0.
- When the game is over, output "game over block out" for a block out, "game over lock out" for a lock out, or "game over top out" for a top out, then output the summary (section 10), and set the game to ended. The processing in which the game became over is aborted at that point (for example, if it happened in the middle of a lock, the remaining steps of the lock are not performed).

7. Operations
An operation line is processed as follows.
- If there is a word that is not an operation name, let w be the first such word and output "ERROR unknown <w>". Otherwise, if no game has been started yet, output "ERROR no game", and if the game has ended, output "ERROR game over".
- If none of these applies, perform each operation in word order. If the game becomes over midway, the remaining operations are not performed.
- When an operation fails, output "fail <operation name>" and do nothing more for that operation (the remaining operations of the line are still performed).
Each operation does the following.
- Movement operations "L", "R", "LL", "RR", "SD", "DD", "CW", "CCW": first, increase the operation count by 1 (even if the operation fails). Next, perform the movement operation of section 3 with the kind and position of the current piece; if it fails, the operation fails. When it succeeds, let q be the resulting position and do the following.
  "SD", "DD": let m be the number of rows moved; add m to each of the score, the drop points and the statistics drop total, update the position to q (last motion "move"), and set the fall counter and the ground counter to 0.
  "L", "R", "LL", "RR": update the position to q (last motion "move").
  "CW", "CCW": update the position to q (last motion "rotation", whose test number is the test number of that rotation).
  For "L", "R", "LL", "RR", "CW", "CCW", after the position update, if the ground counter is greater than 0 and the reset count is less than 15, set the ground counter to 0 and increase the reset count by 1.
- "HD" (hard drop): let m be the number of rows from the current position to the landing position (it may be 0); add 2 * m to each of the score, the drop points and the statistics drop total. If m >= 1, update the position to the landing position (last motion "move"). Then lock (section 9). "HD" never fails.
- "LOCK": if the piece is grounded, lock it. If it is not grounded, the operation fails.
- "HOLD": if hold has been used, the operation fails. Otherwise, mark hold as used and increase the statistics hold count by 1. If the hold is empty, put the kind of the current piece into the hold, take the next piece from the queue and spawn it. If it is not empty, let k be the kind in the hold, set the hold to the kind of the current piece, and spawn a piece of kind k. In either case, the spawn may result in a block out.
- "HD", "LOCK" and "HOLD" do not increase the operation count, whether they succeed or fail (the reset to 0 by a spawn follows section 6).

8. Gravity and lock delay
The fall interval G(v) at level v is 60, 48, 37, 28, 21, 16, 11, 8, 6, 4, 3, 2 for v = 1, 2, ..., 12 respectively, and 1 for v >= 13. The processing of one tick is as follows.
- If the piece is not grounded at its current position, set the ground counter to 0 and increase the fall counter by 1. If the fall counter becomes G at the current level or more, update the position to the position one row lower (last motion "move") and set the fall counter to 0.
- If it is grounded, increase the ground counter by 1. If the ground counter becomes 30 or more, lock (section 9).

9. Locking
To lock the current piece, perform the following steps (1) to (15) in order. Let k be the kind of the current piece and p = (s, x, y) its position. When locking, the piece is always grounded at p.
(1) Shortest sequence: if k can be placed at the spawn position, consider the operation sequences that start from the spawn position and, by performing zero or more movement operations, reach a position whose landing position is p. Movement operations are evaluated as in section 3 on the well at this point (the state is not changed). Among such operation sequences, choose the ones with the fewest operations; if there are several, the shortest sequence is the lexicographically smallest one, compared from the first operation, regarding the operations as increasing in the order "L", "R", "LL", "RR", "SD", "DD", "CW", "CCW". When k cannot be placed at the spawn position, or there is no such operation sequence, there is no shortest sequence.
(2) T-spin check: perform the check only when k is "T" and the last motion is "rotation"; otherwise the result is "no T-spin". If, among the 4 corner positions of the frame (x, y), (x + 2, y), (x + 2, y - 2), (x, y - 2), the number of those that are outside the well or are filled cells is 3 or more, it is a T-spin. Further, if the 2 front corners of state s ((x, y) and (x + 2, y) in state 0, (x + 2, y) and (x + 2, y - 2) in R, (x + 2, y - 2) and (x, y - 2) in 2, (x, y - 2) and (x, y) in L) are both outside the well or filled cells, or the test number of the last rotation is 5, the result is "full"; otherwise it is "mini". If the number is 2 or less, the result is "no T-spin".
(3) Fill the cells occupied by the 4 blocks of the piece. Then remove all complete rows, move the remaining rows down while keeping their order, and make the rows freed at the top empty rows. Let n be the number of removed rows.
(4) Append the piece start state to the end of the history (section 11). Increase the piece count by 1, increase the statistics count of pieces of that kind by 1, and add the operation count to the statistics operation total.
(5) Clear type: from n and the result of (2), determine the type name, the base points and the lines to send by the following table. When n = 0 and there is no T-spin, there is no clear type, and the base points and the lines to send are 0. Other combinations not in the table do not occur.
  no T-spin, n = 1: "SINGLE", 100, 0
  no T-spin, n = 2: "DOUBLE", 300, 1
  no T-spin, n = 3: "TRIPLE", 500, 2
  no T-spin, n = 4: "TETRIS", 800, 4
  mini, n = 0: "TSPIN_MINI", 100, 0
  mini, n = 1: "TSPIN_MINI_SINGLE", 200, 0
  mini, n = 2: "TSPIN_MINI_DOUBLE", 400, 1
  full, n = 0: "TSPIN", 400, 0
  full, n = 1: "TSPIN_SINGLE", 800, 2
  full, n = 2: "TSPIN_DOUBLE", 1200, 4
  full, n = 3: "TSPIN_TRIPLE", 1600, 6
  Let V be the level at this point; the clear points P are base points * V, and the send count Q is the lines to send.
(6) Streak: if n >= 1, increase S by 1 and further do the following. If n = 4 or it is a T-spin (mini or full), increase B by 1, and if as a result B >= 2, it is Back-to-Back. If it is neither n = 4 nor a T-spin, set B to 0. If n = 0, regardless of whether it is a T-spin, set S to 0 and leave B unchanged (it is not Back-to-Back). In the Back-to-Back case, set P to the quotient of P * 3 / 2 and add 1 to Q.
(7) Combo: let C = S - 1. If C >= 1, the combo points are 50 * C * V; otherwise the combo points are 0. If C >= 0, add the following number to Q: 0, 1, 1, 2, 2, 3, 3, 4, 4, 4, 5 for C = 0, 1, 2, ..., 10 respectively, and 5 for C > 10.
(8) Perfect clear: if n >= 1 and the well after (3) has no filled cell at all, it is a perfect clear. In this case, the perfect points are 800 * V, 1200 * V, 1800 * V, 2000 * V for n = 1, 2, 3, 4 respectively (but 3200 * V when n = 4 and Back-to-Back), add 10 to Q, and increase the statistics perfect count by 1. If it is not a perfect clear, the perfect points are 0.
(9) Let the gained points A be P + combo points + perfect points. Add A to the score, n to the number of cleared lines, and Q to the statistics sent total. Set the statistics max combo to the larger of itself and C, and the statistics max chain to the larger of itself and B.
(10) Output "lock <piece count> <k> <name of state s> <x> <y> keys <operation count> <number of operations of the shortest sequence> drop <drop points> lines <n> sent <Q> +<A> total <score>". If there is no shortest sequence, write "-" in place of <number of operations of the shortest sequence>.
  Then, if there is a shortest sequence and the operation count is greater than its number of operations, increase the statistics finesse fault count by 1 and output "finesse <sequence>". <sequence> is the names of the operations of the shortest sequence separated by single spaces, or "none" if the number of operations is 0.
  Then, if there is a clear type, increase the statistics count of that type by 1 and output "clear <type name> <P>". At the end of this line, append " b2b" if it is Back-to-Back, then " combo <C> <combo points>" if C >= 1, then " perfect <perfect points>" if it is a perfect clear.
(11) Level: if starting level + the quotient of number of cleared lines / 10 is greater than V, set the level to that value and output "level <level>".
(12) Lock out: if all 4 cells filled in (3) are in row 21 or row 22, the game is over (lock out).
(13) Cancelling: let T be the sum of the numbers in the pending list, and let c = the smaller of Q and T. If c >= 1, reduce the pending list by c rows in total from the front (reduce the first number, and when it becomes 0, remove it and reduce the next number, continuing until the total reduction is c). Add c to the statistics cancelled total and output "cancel <c> pending <sum of the numbers in the pending list>".
(14) Rising: if n = 0, let the number of risen rows be r = 0, and repeat the following while the pending list is not empty and r < 8. Let e be the first number of the pending list, and let m = the smaller of e and 8 - r. Draw one random number, let h be its remainder divided by 10 plus 1, and insert m rows of garbage lines with hole h (see below). If they cannot be inserted and the game becomes over, stop here. If they are inserted, add m to each of the statistics received total and r, subtract m from the first number of the pending list and remove it if it becomes 0, and output "rise <m> hole <h> pending <sum of the numbers in the pending list>".
(15) Set the hold to not used, take the next piece from the queue and spawn it. If it is not a block out, record the piece start state (section 11).
Inserting garbage lines: to insert m rows of garbage lines with hole h, first, if any cell in the m rows from row 23 - m to row 22 is filled, the game is over (top out) without changing the well. Otherwise, shift every row of the well up by m rows (the contents of row r move to row r + m), and make each row from row 1 to row m a row in which only the cell in column h is empty and the other 9 cells are filled. The position of the current piece is not changed by this.

10. Summary
- The statistics values are the drop total, hold count, operation total, finesse fault count, perfect count, sent total, cancelled total, received total, max combo, max chain, the number of pieces of each kind (7 values), and the count of each clear type (11 values).
- The summary consists of the following 7 lines. <g> is the serial number of the game (NEW in section 15).
  summary game <g> score <score> level <level> lines <number of cleared lines> pieces <piece count>
  clears single <count of SINGLE> double <count of DOUBLE> triple <count of TRIPLE> tetris <count of TETRIS> perfect <perfect count>
  tspins mini <count of TSPIN_MINI> mini_single <count of TSPIN_MINI_SINGLE> mini_double <count of TSPIN_MINI_DOUBLE> zero <count of TSPIN> single <count of TSPIN_SINGLE> double <count of TSPIN_DOUBLE> triple <count of TSPIN_TRIPLE>
  pieces I <number of I> O <number of O> T <number of T> S <number of S> Z <number of Z> J <number of J> L <number of L>
  best combo <max combo> chain <max chain> holds <hold count> drops <drop total> faults <finesse fault count>
  garbage sent <sent total> cancelled <cancelled total> received <received total>
  rates app <ratio of sent total to piece count> apl <ratio of sent total to number of cleared lines> kpp <ratio of operation total to piece count>
- The ratio of a to b is "0.00" if b = 0. Otherwise, let q be the quotient of 100 * a / b; the ratio is the quotient of q / 100, ".", and the remainder of q / 100 in 2 digits (with a "0" in front if it has 1 digit), written consecutively. For example, for a = 38 and b = 18 it is "2.11".

11. Piece start state, undo, saves
- The piece start state is a copy of everything in the game state except the history, the piece start state and the saves (including the well, the random number value, the queue, the hold, the current piece and the last motion, the values for the current piece, the score, the pending list, the statistics values, and so on). "Record the piece start state" means making a copy of the state at that point the piece start state. In other words, the piece start state is the state immediately after the game was last started or a piece last spawned (excluding spawns caused by hold).
- UNDO removes the last copy from the history, restores the game state (except the history, the piece start state and the saves) to the contents of that copy, and makes that copy the piece start state. This returns to the state immediately after the last locked piece spawned.
- SAVE stores, under a name, a copy of everything in the game state except the saves (including the history and the piece start state). LOAD sets the game state (except the saves) to the contents of the stored copy. Saves exist per game and become empty when a new game is started.

12. Well evaluation
For a well and a number n, the height h(c) of column c = 1, 2, ..., 10 is the maximum row number of the filled cells in column c (0 if there are none). The number of holes is the sum, over all columns c, of "the number of empty cells in column c in rows below h(c)". The bumpiness is |h(1) - h(2)| + |h(2) - h(3)| + ... + |h(9) - h(10)|. The evaluation value is 76 * n - 51 * (h(1) + h(2) + ... + h(10)) - 36 * number of holes - 18 * bumpiness.

13. Placement candidates
- The candidate list for kind k, starting position p and prefix operation sequence H is built as follows. All operations are evaluated as in section 3 on the well at that time (the state is not changed).
  Examine the rotation sequences in the order "none", "CW", "CW CW", "CCW" ("none" is the sequence containing no operations; the same holds for the movement sequences below). Perform the rotations of the rotation sequence in order from p; if any of them fails, skip that rotation sequence. Let q be the position after performing the rotation sequence.
  For each rotation sequence, examine the movement sequences in the order "none", "L", "L L", "L L L", ..., "R", "R R", "R R R", .... The movement sequences consisting of "L" are examined from shortest to longest, only up to the number of times "L" succeeded when performed one at a time from q. The same applies to "R". Let t be the landing position of the position reached by performing the movement sequence from q.
  If the set of the 4 cells occupied by the blocks at t is the same as one that has already appeared while building this candidate list, skip it. Otherwise, append the candidate (evaluation value, kind k, operation sequence) to the end of the candidate list. The evaluation value is the evaluation value of section 12 for the well obtained by placing k at t and removing the complete rows in the same way as in section 9 (3), and for the number of removed rows. The operation sequence is the concatenation of H, the rotation sequence, the movement sequence and "HD", in this order.
- The ranked candidates are obtained by concatenating the following 2 lists in this order and sorting the result by evaluation value in descending order. Candidates with equal evaluation values keep their order in the concatenated list. They are counted as rank 1, rank 2, ... from the front.
  the candidate list built with the kind of the current piece, the current position and an empty prefix
  only when hold has not been used and kind k2 (the kind in the hold if the hold is not empty, or the kind at the front of the queue if it is empty) can be placed at the spawn position: the candidate list built with k2, the spawn position and the prefix "HOLD"

14. T-spin candidates
When the current piece is "T", for every position u that can be reached from the current position by performing zero or more movement operations, consider "CW" and "CCW" from u. If the rotation succeeds, the piece is grounded at the resulting position q, and the check of section 9 (2) (performed on the well at that time), assuming that the last motion at q was that rotation (with its test number), gives mini or full, then q is a T-spin candidate. When the same position q becomes a candidate several times, it is full if it was judged full at least once, and mini otherwise.

15. Commands
The arguments, behavior and output of each command are as follows. Commands marked "allowed after end" can be executed even when the game has ended (section 16).

NEW seed level
seed is between 1 and 2147483646 inclusive, and level is between 1 and 15 inclusive. If a game is in progress, first output "game stopped" and the summary. Next, output the serial number g of the game (the number of successful NEWs; 1 for the first NEW) in the form "game <g> seed <seed> level <level>", and start a new game as in section 5. The state and the saves of the previous game are discarded.

PRINT
Allowed after end. Output the well in 22 lines. For r = 22, 21, ..., 1 in this order, each line consists of the row number r right-aligned in width 2 (preceded by one space if it has 1 digit), followed by one space and then the characters of the cells of columns 1 to 10 written without separators. The character of a cell is "#" if it is filled, "@" if a block of the current piece occupies it, "+" if it is a cell that the blocks of the piece would occupy at the landing position of the current position, and "." if none of these applies (the first one that applies, in this order). If the game has ended, "@" and "+" are not used.

NEXT
Allowed after end. Output "hold <hold> next <first 5 of the queue>". <hold> is the kind in the hold, or "-" if it is empty. <first 5 of the queue> is the 5 kinds from the front of the queue written without separators.

PREVIEW n
Allowed after end. n is between 1 and 14 inclusive. Make copies of the queue and the random number value, add bags using the copied random number value until the length of the copied queue is n or more, and output "preview <listing>", where <listing> is the first n kinds of the copied queue written without separators. The game state is not changed.

STATUS
Allowed after end. Output the 2 lines "score <score> level <level> lines <number of cleared lines> pieces <piece count>" and "piece <piece> streak <S> chain <B> pending <sum of the numbers in the pending list>". <piece> is "-" if the game has ended, and otherwise "<kind of the current piece> <state name> <x> <y>".

ANALYZE
Allowed after end. Compute the values of section 12 for the current well (not including the current piece) and n = 0, and output the 2 lines "heights <h(1)> <h(2)> ... <h(10)>" (the 10 heights separated by single spaces) and "holes <number of holes> bumpiness <bumpiness> value <evaluation value>".

ROW r pattern
r is between 1 and 22 inclusive. pattern is a 10-character string consisting only of "#" and ".", containing at least one ".". If, among the columns i for which the i-th character from the left of pattern is "#", there is a column in which a block of the current piece occupies row r, output "ERROR overlap". Otherwise, make each column i of row r a filled cell if the i-th character of pattern is "#", or an empty cell if it is ".", and output "OK". The current piece and its values are not changed.

GARBAGE n h
n and h are between 1 and 10 inclusive. Insert n rows of garbage lines with hole h (section 9). If the game is not over, let (s, x, y) be the position of the current piece, and for j = 0, 1, ..., n in this order, find the first j such that the piece can be placed at (s, x, y + j). If one is found, set the position of the piece to (s, x, y + j) (this is not a position update, so the last motion, the lowest record, the reset count, etc. do not change) and output "OK". If none is found, the game is over (top out).

ATTACK n
n is between 1 and 20 inclusive. Append n to the end of the pending list and output "pending <sum of the numbers in the pending list>".

TICK n
n is between 1 and 1000 inclusive. Perform the processing of one tick (section 8) n times. If the game becomes over midway, stop there.

UNDO
If the history is empty, output "ERROR nothing to undo". Otherwise, perform the undo as in section 11 and output "undo <piece count> <kind of the current piece>".

SAVE name
name is a string of 1 to 8 characters consisting only of lowercase English letters (a to z). As in section 11, store a copy of the state under the name name (replacing any save with the same name), and output "OK".

LOAD name
Allowed after end. name has the same form as for SAVE. If there is no save with the name name, output "ERROR unknown save". If there is, set the state to the contents of that save as in section 11 (the save remains), and output "load <piece count> <kind of the current piece>". Even if the game has ended, the state returns to the one at the time of saving, so the game becomes in progress.

SPINS
If the current piece is not "T", output only "spins 0". If it is "T", sort the T-spin candidates of section 14 by the y of the position (s, x, y) in ascending order, by x in ascending order when y is equal, and further by s in ascending order when those are also equal, output "spin <name of state s> <x> <y> <type name>" for each one, and finally output "spins <number of candidates>". <type name> is the type name determined by the table of section 9 (5) from the number of rows that would be removed in the same way as in section 9 (3) when the piece is placed at that position, and from the check result for that position (mini or full). The state is not changed.

HINT n
n is between 1 and 10 inclusive. For the top n of the ranked candidates (section 13) (all of them if there are fewer than n candidates), output one line "hint <rank> <kind> <operation sequence> value <evaluation value>" for each, in rank order. <operation sequence> is the names of the operations separated by single spaces. The state is not changed.

AUTO n
n is between 1 and 50 inclusive. Repeat the following n times. If the game becomes over midway, stop there. Output "auto <kind> <operation sequence>" (<operation sequence> has the same form as in HINT) for the rank-1 ranked candidate, and perform each operation of that operation sequence in order as in section 7.

16. Order of checks and end of input
- A command line is checked in the following order; output the first one that applies and finish processing that command.
  (1) If the number or the form of the arguments does not match the description in section 15, "ERROR bad arguments". The same applies when a command that takes no arguments has arguments. A numeric argument has the correct form when it consists only of digits (0 to 9), does not start with "0" if it has 2 or more characters, and its value is within the range given in the description.
  (2) For a command other than NEW, if no game has been started yet, "ERROR no game".
  (3) For a command other than NEW and the "allowed after end" commands, if the game has ended, "ERROR game over".
  (4) The errors given in the description of each command in section 15.
- After all lines have been processed, if a game is in progress, output "game stopped" and the summary.

[Output format]
For each line, output the lines specified in [Processing] in that order. The output consists only of ASCII characters; no line has trailing whitespace, and every line ends with a newline. No empty lines are output. Except for the ratios in the summary, all numbers are written as decimal integers without extra leading "0"s, and negative numbers are prefixed with "-".

[Constraints]
- 1 <= N <= 500
- Each line is between 1 and 100 characters long and consists only of alphanumeric characters, "#", ".", "-" and spaces.
- A word consisting only of digits is at most 10 characters long.
