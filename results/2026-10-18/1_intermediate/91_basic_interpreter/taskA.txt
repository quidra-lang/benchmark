[Overview]
Write an interpreter that executes BASIC programs with line numbers. The input contains one or more programs, and each program consists of, in this order, the program lines, a RUN line, the data lines read by INPUT statements, and an END line. The interpreter handles adding, replacing and deleting program lines, a syntax check before execution, integer and string variables, one- and two-dimensional arrays, expressions with precedence, output by PRINT (the separators semicolon and comma, zones of 10 characters, TAB and SPC), IF ... THEN ... ELSE, GOTO, GOSUB and RETURN, branching by ON, FOR ... NEXT, WHILE ... WEND, READ, DATA and RESTORE, INPUT, pseudo-random numbers, string and numeric functions, and error handling by ON ERROR and RESUME. A runtime error that is not trapped is reported in the form "ERROR IN LINE n: message" and execution ends. Each time the execution of a program ends, a READY line is output.

[Input format]
The first line contains an integer T, the number of programs.
Then T programs follow in order. One program consists of the following (1) to (4) in this order.
(1) Program lines: zero or more lines. Each line has one of the following forms.
  - A line consisting only of a line number
  - A line consisting of a line number, one or more spaces, and the line content, in this order (the line content begins with a character other than a space)
  A line number is an integer from 1 to 9999 written in decimal, with no extra leading zeros.
(2) One line consisting only of the three uppercase letters RUN.
(3) Data lines: zero or more lines. Each line is a string of zero or more characters and is read by INPUT statements (section 14). A data line never consists only of the three characters END.
(4) One line consisting only of the three uppercase letters END.
Every line of the input consists only of ASCII printable characters (character codes 32 to 126) and never ends with a space.

[Processing]
1. Overall flow
Process the programs one at a time in order, as follows. The programs are independent of each other: the stored lines, variables, random state and so on are not carried over to the next program.
Step 1. Read the program lines in order and store the program (section 3).
Step 2. When the RUN line is read, check the syntax of all stored lines (section 7). If there is an error, report the error and go to step 4.
Step 3. If there is no error, execute the program (sections 8 to 16).
Step 4. Perform the end-of-execution processing (section 17). The single READY line is output exactly once, at the end of this processing.
The data lines and the END line are input read by INPUT statements during the execution of that program. They may all be read before execution. Data lines left unused are discarded, and the next program is read from the line after the END line.

2. Terms and notation
- "Space" means only the space character (character code 32). "Uppercase letter" means A to Z, and "digit" means 0 to 9. LF is the newline character (character code 10).
- For integers a and b (b nonzero), the "truncated quotient" is the integer obtained by discarding the fractional part of a / b, rounding toward zero. For example, it is 3 for 7 and 2, -3 for -7 and 2, -3 for 7 and -2, and 3 for -7 and -2.
- The "decimal representation" of an integer n is the string obtained by writing the absolute value of n in decimal without extra zeros (0 is written as 0), prefixed with - if n is negative. For example, 42 gives 42 and -7 gives -7.
- In the grammar descriptions, [ X ] means that X may be omitted, { X } means X repeated zero or more times, and X | Y means X or Y. All other uppercase words and symbols are tokens written exactly as shown (section 4).

3. Storing the program
- Initially, no lines are stored.
- When a line of the form "line number, spaces, line content" is read, what remains after removing all spaces following the line number is stored as the content of the line with that line number. If a line with the same line number is already stored, its content is replaced with the new content.
- When a line consisting only of a line number is read, the line with that line number is deleted from storage. If no line with that line number is stored, nothing happens.
- The stored lines are treated as arranged in increasing order of line number, regardless of the order in which they were entered.
- Whether a line content is correct is not checked at this stage. An error in a line that disappeared through replacement or deletion causes no problem.

4. Tokens
Read the line content from left to right and split it into a sequence of "tokens" by the following rules.
(1) Spaces are skipped. A space only serves to separate tokens.
(2) If the character is ", create one "string constant" whose value is the characters from the next character up to just before the next occurrence of " (the value may be empty, and spaces are included in the value as they are). If there is no next ", it is a syntax error.
(3) If the character is a digit, create one "numeric constant" whose value is the maximal run of digits starting there, read in decimal. Leading zeros are allowed (007 is 7). If the value is greater than 32767, it is a syntax error.
(4) If the character is an uppercase letter:
  - If the three characters starting at that position are REM, create one token REM, and skip all characters after it up to the end of the line as a comment (the tokens of the line content end there).
  - Otherwise, take the maximal run of uppercase letters and digits starting there, include the immediately following character if it is $, and make that one "word".
(5) If the next two characters are one of <>, <=, >=, make those two characters one symbol.
(6) Otherwise, if the character is one of + - * / ^ = < > ( ) , ; :, make that one character one symbol.
(7) If the character is anything else (a lowercase letter, $, #, ., etc.), it is a syntax error.
A word is one of the following.
- Variable name: one uppercase letter, or one uppercase letter followed by one digit, either with or without a trailing $. A variable name with $ is called a "string variable name", and one without $ is called an "integer variable name". Examples: A, Z9, B$, C1$.
- Reserved word: REM LET PRINT INPUT READ DATA IF THEN ELSE GOTO GOSUB RETURN ON ERROR RESUME FOR TO STEP NEXT WHILE WEND DIM RESTORE RANDOMIZE END STOP TAB SPC AND OR NOT MOD ERR ERL
- Function name: ABS SGN INT SQR RND LEN ASC VAL CHR$ STR$ LEFT$ RIGHT$ MID$ INSTR
Any other word (AB, A12, FORI, etc.) fits nowhere in the grammar, so it is a syntax error if it appears. For example, FOR I=1 TO 10 is split into the 6 tokens FOR, I, =, 1, TO, 10, but FORI=1 TO 10 contains the word FORI and is therefore a syntax error.

5. Expression grammar and types
The grammar of expressions is as follows. Operations listed higher bind more weakly (have lower precedence).
  expression    ::= logical-or
  logical-or    ::= logical-and { OR logical-and }
  logical-and   ::= negation { AND negation }
  negation      ::= NOT negation | comparison
  comparison    ::= sum { comparison-operator sum }
  sum           ::= product { additive-operator product }
  product       ::= unary { multiplicative-operator unary }
  unary         ::= - unary | power
  power         ::= primary [ ^ unary ]
  primary       ::= numeric-constant | string-constant | variable-name | array-element | function-call | ERR | ERL | ( expression )
  array-element ::= variable-name ( integer-expression [ , integer-expression ] )
  function-call ::= function-name ( expression { , expression } )
A comparison operator is one of = <> < > <= >=, an additive operator is + or -, and a multiplicative operator is one of * / MOD.
- From this grammar, OR, AND, the comparison operators, the additive operators and the multiplicative operators are all left-associative (A - B - C is (A - B) - C, and A < B < C is (A < B) < C). ^ is right-associative: 2 ^ 3 ^ 2 is 2 ^ (3 ^ 2). Unary - binds more weakly than ^ and more strongly than the multiplicative operators, so - 2 ^ 2 is -(2 ^ 2), 2 ^ - 1 is 2 ^ (-1), and 2 * - 3 is 2 * (-3). NOT binds more weakly than comparisons and more strongly than AND, so NOT A = B is NOT (A = B), and NOT A AND B is (NOT A) AND B. There is no unary +.
- When a variable name is immediately followed by (, it is always an array element. Since spaces only separate tokens, A (1) is also an array element.
- An expression is read as far as possible while it still fits the grammar. For example, the expression in PRINT 1 -1 is 1 - 1.
Each expression has one of two types, "integer" or "string". An expression of type integer is called an "integer expression", and an expression of type string is called a "string expression".
- Numeric constants, integer variable names, array elements with an integer variable name, ERR and ERL are integer expressions. String constants, string variable names and array elements with a string variable name are string expressions. The type of ( expression ) is the type of the expression inside. The type of a function call is as given in the table of section 11.
- + is addition with an integer expression as the result if both operands are integer expressions, and concatenation with a string expression as the result if both operands are string expressions.
- Both operands of a comparison operator must have the same type, and the result is an integer expression.
- The operands of the other operators (- * / MOD ^ AND OR NOT and unary -) and the subscripts of array elements must be integer expressions. The result is an integer expression.
- The number and types of the arguments of a function must be as given in the table of section 11.
An expression that violates these rules is a syntax error. For example, "A" + 1, -"A", A$ < 1, LEN(5) and MID$("ABC") are syntax errors.

6. Statement grammar
A line content is a "statement list": one or more statements separated by :.
  statement-list ::= statement { : statement }
The statements are as follows. Below, "line-number" is a numeric constant, and "target" is a variable name or an array element.
  (1)  REM
  (2)  [ LET ] target = expression            (the target and the expression have the same type)
  (3)  PRINT { print-item }
  (4)  INPUT target { , target }
  (5)  READ target { , target }
  (6)  DATA data-item { , data-item }
  (7)  IF integer-expression THEN clause [ ELSE clause ]
  (8)  GOTO line-number
  (9)  GOSUB line-number
  (10) RETURN
  (11) ON integer-expression GOTO line-number { , line-number }
  (12) ON integer-expression GOSUB line-number { , line-number }
  (13) ON ERROR GOTO line-number
  (14) RESUME [ NEXT | line-number ]
  (15) FOR integer-variable-name = integer-expression TO integer-expression [ STEP integer-expression ]
  (16) NEXT [ integer-variable-name ]
  (17) WHILE integer-expression
  (18) WEND
  (19) DIM array-declaration { , array-declaration }
  (20) RESTORE [ line-number ]
  (21) RANDOMIZE integer-expression
  (22) END
  (23) STOP
Notes:
- (1) REM statement: by section 4, everything after REM up to the end of the line is skipped, so a REM statement is always the last statement on its line.
- (2) Assignment statement: the form without LET begins with the target. Everything after the = that immediately follows the target is the expression, so A = B = C is a statement that assigns the value of B = C to A.
- (3) PRINT statement: print-item ::= expression | TAB ( integer-expression ) | SPC ( integer-expression ) | ; | ,
  An expression cannot be followed directly by another expression with nothing in between (PRINT "A" "B" is a syntax error). TAB and SPC can be used only in this position and cannot be written inside an expression.
- (6) DATA statement: data-item ::= [ - ] numeric-constant | string-constant
- (7) IF statement: clause ::= line-number | clause-statement { : clause-statement }
  A "clause-statement" is a statement that is none of IF, FOR, NEXT, WHILE, WEND and DATA. The clause after THEN continues up to just before the token ELSE or up to the end of the line, and the clause after ELSE continues up to the end of the line. Therefore an IF statement is always the last statement on its line. A clause consisting only of a line-number can be followed only by ELSE or the end of the line if it is the clause after THEN, and only by the end of the line if it is the clause after ELSE (IF A THEN 100 : PRINT 1 is a syntax error).
- (11) to (13): if ON is immediately followed by the reserved word ERROR, the statement is (13); otherwise it is (11) or (12).
- (19) DIM statement: array-declaration ::= variable-name ( integer-expression [ , integer-expression ] )
- Each statement consists of exactly the tokens of its form, with nothing missing and nothing extra. A statement followed by extra tokens (PRINT 1 ELSE 2, GOTO 10 20, etc.) and an empty statement (after the : in PRINT 1 :) are syntax errors.

7. Syntax check
When the RUN line is read, check for every stored line whether its line content follows the rules of sections 4 to 6. If one or more lines do not, let n be the smallest line number among those lines, output the single line "ERROR IN LINE n: SYNTAX ERROR", and do not execute the program.
Whether the line that a line number refers to exists, whether a value is within range, and the like are not checked by the syntax check; they are checked during execution (section 16).

8. Execution state
At the start of execution, prepare the following state.
- Variables: the 286 integer variables denoted by integer variable names all have the value 0, and the 286 string variables denoted by string variable names all have the empty string as their value.
- Arrays: initially there are none (section 12).
- Control stack: initially empty (section 15).
- Data item sequence and read position (READ statement in section 14): the read position is initially at the start of the sequence.
- Next data line to read: initially the first data line of the program.
- Random state x: initially 1.
- Error handler line: initially 0. Whether "handling an error": initially not handling an error. Values of ERR and ERL: initially both 0 (section 16).
- Current output line: initially empty (section 13).

9. Statement order and flow of execution
- The "statement sequence" of a program is formed by arranging all stored lines in increasing order of line number and listing the statements of each line's statement list from left to right. Statements inside the clauses of an IF statement are not included in the statement sequence; they are regarded as part of that IF statement.
- The "next statement" of each statement is defined as follows.
  - The next statement of a statement in the statement sequence is the statement immediately after it in the statement sequence. The last statement of the statement sequence has no next statement.
  - The next statement of a statement in a clause is the statement immediately after it in the same clause. If it is the last statement of the clause, its next statement is the next statement of the IF statement containing that clause.
  For example, when line 10 is IF X THEN PRINT 1 : GOSUB 100 : PRINT 2 ELSE PRINT 3 and line 20 is PRINT 4, the next statement of GOSUB 100 is PRINT 2, and the next statement of both PRINT 2 and PRINT 3 is PRINT 4. The next statement of the IF statement itself is also PRINT 4.
- Execution starts with the first statement of the statement sequence. If the statement sequence is empty, execution ends without doing anything.
- After a statement is executed, its next statement is executed, unless sections 14 to 16 specify otherwise. If there is no next statement, execution ends.
- "Go to line n" means to execute the first statement of the line with line number n next. If there is no line with line number n, it is runtime error UNDEFINED LINE NUMBER.
- Below, a "position" is either one statement in the statement sequence or in a clause, or a marker meaning "there is no next statement". "Go to position p" means to execute the statement at p next (or, if p means "there is no next statement", to end execution).

10. Values and operations
- Integers take values from -32768 to 32767. When the result of an operation is outside this range, it is runtime error OVERFLOW.
- Strings are strings of ASCII printable characters with a length from 0 to 255. When the length of the result of a concatenation exceeds 255, it is runtime error STRING TOO LONG.
- Order of evaluation: for a binary operator, both operands are evaluated, the left operand first and then the right operand, before the operation is performed (the right operand is not skipped even for AND and OR). Function arguments, array element subscripts and the upper bounds in a DIM statement are also evaluated from left to right. If a runtime error occurs during evaluation, the execution of the statement is aborted at that point (section 16).
The operations are defined as follows.
- A + B, A - B, A * B: the mathematical sum, difference and product.
- A / B: if B is 0, DIVISION BY ZERO. Otherwise the truncated quotient of A and B (-32768 / -1 is OVERFLOW).
- A MOD B: if B is 0, DIVISION BY ZERO. Otherwise A - B * (the truncated quotient of A and B); the result is 0 or has the same sign as A. For example, 7 MOD 3 is 1, -7 MOD 3 is -1, and 7 MOD -3 is 1. It is not OVERFLOW even if the intermediate truncated quotient is out of range (-32768 MOD -1 is 0).
- A ^ B: if B is negative, ILLEGAL FUNCTION CALL. Otherwise A raised to the power B (0 ^ 0 is 1).
- - A (unary): the value of A with its sign inverted (-(-32767 - 1) is OVERFLOW).
- Comparison: -1 if the comparison holds, 0 if it does not. Integers are compared by numeric value. Strings are compared in lexicographic order: the character codes are compared one character at a time from the start, the string with the smaller character code at the first differing character is the smaller one, and when one string matches the beginning of the other, the shorter one is the smaller one.
- AND, OR, NOT: bitwise AND, OR and NOT on the 16-bit two's complement representation. The result is always within range, and NOT A equals -1 - A. For example, 12 AND 10 is 8, 12 OR 10 is 14, NOT 0 is -1, -1 AND 5 is 5, and -8 OR 3 is -5.
- Conditions: in IF and WHILE statements, a condition is true if the value of its expression is nonzero and false if it is 0.

11. Functions
A function call evaluates all its arguments from left to right and then computes its value as in the following table. "integer" and "string" in the table are the types of the arguments and of the result.
- ABS(integer a) -> integer: the absolute value of a (ABS(-32767 - 1) is OVERFLOW).
- SGN(integer a) -> integer: 1 if a is positive, 0 if a is 0, -1 if a is negative.
- INT(integer a) -> integer: a itself (since every value is an integer, INT does not change the value).
- SQR(integer a) -> integer: ILLEGAL FUNCTION CALL if a is negative. Otherwise, the largest integer >= 0 whose square is <= a (SQR(10) is 3).
- RND(integer n) -> integer: ILLEGAL FUNCTION CALL if n is less than 1. Otherwise, update the random state x to (48271 * x) mod 2147483647; the value is the remainder of the updated x divided by n, plus 1 (from 1 to n).
- LEN(string s) -> integer: the length of s.
- ASC(string s) -> integer: ILLEGAL FUNCTION CALL if s is empty. Otherwise the character code of the first character of s.
- VAL(string s) -> integer: remove all spaces at the start of s; if the next character is + or -, remove it as the sign; then read the maximal run of digits that follows in decimal; the value is that number with the sign applied (the sign is inverted for -). If there are no digits at all, the value is 0. If the value after applying the sign is outside the integer range, OVERFLOW (VAL("-32768") is -32768, VAL("32768") is OVERFLOW). For example, VAL("  -12AB") is -12, VAL("+7") is 7, and VAL("X1"), VAL("- 5") and VAL("") are 0.
- CHR$(integer n) -> string: ILLEGAL FUNCTION CALL unless n is from 32 to 126. Otherwise the single character with character code n.
- STR$(integer n) -> string: the decimal representation of n.
- LEFT$(string s, integer n) -> string: ILLEGAL FUNCTION CALL if n is negative. Otherwise the first n characters of s (all of s if n is greater than or equal to the length of s).
- RIGHT$(string s, integer n) -> string: ILLEGAL FUNCTION CALL if n is negative. Otherwise the last n characters of s (all of s if n is greater than or equal to the length of s).
- MID$(string s, integer p [, integer n]) -> string: ILLEGAL FUNCTION CALL if p is less than 1, or if n is given and is negative. Otherwise, counting the first character of s as character 1, the part from character p to the end (the empty string if p is greater than the length of s). If n is given, the first n characters of that part (the whole part if its length is n or less).
- INSTR(string s, string t) -> integer: the first of the positions at which t occurs in s as a contiguous part (the first character of s is position 1). 0 if it does not occur. 1 if t is empty.

12. Variables and arrays
- A variable name written in an expression denotes the value of that variable; a variable name written as a target assigns to that variable.
- An array has a name (of the same form as a variable name) and one or two "upper bounds", and has one element for every combination of subscripts in which each subscript is from 0 to its upper bound. The number of elements is u + 1 if the only upper bound is u, and (u + 1) * (v + 1) if the upper bounds are u and v. If the name has the form of an integer variable name, the elements are integers and are initially all 0; if it has the form of a string variable name, the elements are strings and are initially all the empty string. An array is unrelated to the variable with the same name (A and A(1) are different things).
- When an array element is referenced (both when its value is read and when it is used as a target), the following is done in order.
  (1) Evaluate the subscripts from left to right.
  (2) If there is no array with that name, create an array with as many upper bounds as there are subscripts, all equal to 10 (automatic declaration).
  (3) If the number of subscripts differs from the number of upper bounds of the array, or if any subscript is less than 0 or greater than the corresponding upper bound, it is runtime error SUBSCRIPT OUT OF RANGE.
  (4) Reference the element with those subscripts.
  An array created in (2) remains even if (3) results in an error.

13. Output
- The current output line is the string of one line that has not been output yet. "Write" means to append a string to the end of the current output line.
- "End the line" means to output the current output line with all spaces at its end removed, followed by LF, and to make the current output line empty.
- "Output the message M" means: if the current output line is not empty (including the case where it consists only of spaces), first end the line; then output M followed by LF.
- A PRINT statement processes its print items from left to right as follows. Below, L is the length of the current output line at that moment.
  - Expression: evaluate the expression, and write its decimal representation if it is an integer, or the string itself if it is a string.
  - ;: do nothing.
  - ,: write spaces until the length becomes "the smallest multiple of 10 that is greater than L" (10 spaces if L is 0, 7 spaces if L is 13).
  - TAB(e): evaluate e. If e is negative, ILLEGAL FUNCTION CALL. If L is less than e, write spaces until the length becomes e. Otherwise do nothing.
  - SPC(e): evaluate e. If e is negative, ILLEGAL FUNCTION CALL. Write e spaces.
  After all print items have been processed, if the last print item is neither ; nor , (including the case where there are no print items), end the line. If a runtime error occurs partway through, the strings written up to that point remain in the current output line.

14. Behavior of each statement
The statements that use the control stack (GOSUB, RETURN, ON ... GOSUB, FOR, NEXT, WHILE, WEND) are described in section 15, and ON ERROR and RESUME in section 16.
- REM statement, DATA statement: do nothing.
- Assignment statement: (1) If the target is an array element, perform its reference (section 12). (2) Evaluate the expression. (3) Assign to the target.
- PRINT statement: as described in section 13.
- INPUT statement: process the targets one at a time from left to right as follows.
  (1) If the target is an array element, perform its reference.
  (2) If no data line remains to be read, it is runtime error INPUT PAST END. Otherwise, read one line, the next data line to read, and advance the next data line to read to the line after it.
  (3) If the target is a string, assign the whole line read (including spaces) and finish processing this target.
  (4) If the target is an integer: if the line read consists only of "zero or one -, followed by one or more digits" (containing no other characters) and its value is from -32768 to 32767, assign that value and finish processing this target. Otherwise, output the message ?REDO FROM START (section 13) and return to (2).
- READ statement: the "data item sequence" is formed by taking the DATA statements in the statement sequence in order and listing the data items of each from left to right. The value of an item that is a numeric constant with - is the integer obtained by inverting the sign of the value of the numeric constant; the value of a numeric constant item is that integer; the value of a string constant item is that string. Process the targets one at a time from left to right as follows.
  (1) If the target is an array element, perform its reference.
  (2) If the read position is at the end of the sequence (after the last item), it is runtime error OUT OF DATA.
  (3) Take the item at the read position and advance the read position by one.
  (4) If the type of the item (integer or string) differs from the type of the target, it is runtime error TYPE MISMATCH (the read position stays advanced).
  (5) Assign the value of the item to the target.
- RESTORE statement: if there is no line number, set the read position to the start of the sequence. If there is a line number n: if there is no line with line number n, it is runtime error UNDEFINED LINE NUMBER; otherwise, set the read position to the position of "the first item in the sequence among the items of DATA statements on lines whose line number is n or greater" (the end of the sequence if there is no such item).
- IF statement: evaluate the condition expression. If it is true, execute the clause after THEN; if it is false and there is an ELSE clause, execute the clause after ELSE. If it is false and there is no ELSE clause, do nothing (proceed to the next statement). Executing a clause means: if the clause is a line-number n, go to line n; if it is a statement list, execute its first statement next. The statements in a clause are executed in order following the "next statement" rules of section 9.
- GOTO n: go to line n.
- ON e GOTO n1, n2, ..., nk: (1) Evaluate e. (2) If e is negative, ILLEGAL FUNCTION CALL. (3) If e is from 1 to k, go to line ne. (4) If e is 0 or greater than k, do nothing.
- RANDOMIZE e: evaluate e; if e is less than 1, ILLEGAL FUNCTION CALL. Otherwise set the random state x to e.
- DIM statement: process the array declarations one at a time from left to right as follows. (1) Evaluate the upper bound expressions from left to right. (2) If an array with that name already exists (including one created by automatic declaration), it is runtime error DUPLICATE DEFINITION. (3) If any upper bound is negative, ILLEGAL FUNCTION CALL. (4) If the number of elements is more than 10000, it is runtime error OUT OF MEMORY. (5) Create an array with that name and those upper bounds.
- END statement: end execution.
- STOP statement: output the message BREAK IN LINE n (n is the line number of the line containing this STOP statement) and end execution.

15. Statements that use the control stack
- The control stack is a stack onto which elements are pushed, and there are the following three kinds of elements.
  GOSUB element: holds a return position.
  FOR element: holds a variable name, a final value, an increment, and the position of the loop start.
  WHILE element: holds the position of a WHILE statement.
- When an element is "pushed", if the control stack already holds 100 elements, it is runtime error OUT OF MEMORY (nothing is pushed).
- The "search range" is the elements from the top of the control stack toward the bottom, up to just before the first GOSUB element (the GOSUB element itself is not included; if there is no GOSUB element, it is the whole stack).
- GOSUB n: (1) If there is no line with line number n, UNDEFINED LINE NUMBER. (2) Push a GOSUB element whose return position is the position of the next statement of this GOSUB statement. (3) Go to line n.
- ON e GOSUB n1, n2, ..., nk: (1) Evaluate e. (2) If e is negative, ILLEGAL FUNCTION CALL. (3) If e is from 1 to k, perform (1) to (3) of the GOSUB statement for ne (the return position is the position of the next statement of this ON statement). (4) If e is 0 or greater than k, do nothing.
- RETURN: find the GOSUB element closest to the top in the whole control stack. If there is none, it is runtime error RETURN WITHOUT GOSUB (the control stack does not change). If there is one, remove that element and all elements above it, and go to the return position of that element.
- FOR v = a TO b STEP s (s is 1 if there is no STEP):
  (1) Evaluate a, b and s in this order.
  (2) If s is 0, ILLEGAL FUNCTION CALL.
  (3) If the search range contains FOR elements for the variable v, remove the one closest to the top among them and all elements above it.
  (4) Assign a to the variable v.
  (5) If s is positive and a > b, or if s is negative and a < b, the loop body is not executed even once. In this case, find the matching NEXT statement (see below); if there is none, it is runtime error FOR WITHOUT NEXT. If there is one, go to the position of the next statement of that NEXT statement (no FOR element is pushed).
  (6) Otherwise, push a FOR element with variable name v, final value b, increment s, and loop start (the position of the next statement of this FOR statement).
  The "matching NEXT statement" is found as follows. Examine the statements after the FOR statement in the statement sequence in order, while keeping a count d that starts from 0. For a FOR statement, add 1 to d; for a NEXT statement, if d is 0, that NEXT statement is the matching NEXT statement, and otherwise subtract 1 from d. The variable name written in a NEXT statement is not examined. If none is found by the end of the statement sequence, there is no matching NEXT statement.
- NEXT [v]:
  (1) Find, among the FOR elements in the search range (the FOR elements for the variable v when v is given), the one closest to the top. If there is none, it is runtime error NEXT WITHOUT FOR.
  (2) Remove all elements above the element found.
  (3) Add the element's increment to the current value of the element's variable. If the result is outside the integer range, OVERFLOW (the variable does not change).
  (4) Assign the result to the variable.
  (5) If the increment is positive and the result is greater than the final value, or if the increment is negative and the result is less than the final value, remove the element and proceed to the next statement. Otherwise, go to the element's loop start position.
  The final value and the increment of a loop are the values at the time the FOR statement was executed; they do not change even if variables in the expressions change afterwards.
- WHILE e: evaluate e. If it is true, push a WHILE element holding the position of this WHILE statement and proceed to the next statement. If it is false, find the matching WEND statement; if there is none, it is runtime error WHILE WITHOUT WEND. If there is one, go to the position of the next statement of that WEND statement. The matching WEND statement is found by the same method as the matching NEXT statement, reading FOR as WHILE and NEXT as WEND.
- WEND: find the WHILE element closest to the top in the search range. If there is none, it is runtime error WEND WITHOUT WHILE. If there is one, remove that element and all elements above it, and go to the position of that element's WHILE statement (the WHILE statement is executed again and its condition is evaluated again).

16. Runtime errors and error handling
- When a runtime error occurs during the execution of a statement, the execution of that statement is aborted at that point. The changes made up to then, such as assignments, output, automatic declarations, and changes to the control stack and the read position, remain as they are. The statement in which the error occurred is called the "error statement". For an error that occurs while the condition of an IF statement is evaluated, or while going to a line for a line-number clause of an IF statement, the error statement is that IF statement. For an error that occurs in a statement in a clause, the error statement is that statement in the clause.
- When the error handler line is not 0 and an error is not being handled, the error is "trapped". In that case, set the value of ERR to the error code (table below) and the value of ERL to the line number of the line containing the error statement, remember the error statement, enter the "handling an error" state, and, with n the value of the error handler line, go to line n.
- When the error is not trapped, output the message ERROR IN LINE n: M (n is the line number of the line containing the error statement, M is the message in the table below) and end execution.
- The messages and error codes of runtime errors are the following 17.
  NEXT WITHOUT FOR          1
  RETURN WITHOUT GOSUB      3
  OUT OF DATA               4
  ILLEGAL FUNCTION CALL     5
  OVERFLOW                  6
  OUT OF MEMORY             7
  UNDEFINED LINE NUMBER     8
  SUBSCRIPT OUT OF RANGE    9
  DUPLICATE DEFINITION      10
  DIVISION BY ZERO          11
  TYPE MISMATCH             13
  STRING TOO LONG           15
  RESUME WITHOUT ERROR      20
  FOR WITHOUT NEXT          26
  WHILE WITHOUT WEND        29
  WEND WITHOUT WHILE        30
  INPUT PAST END            62
- ON ERROR GOTO n: if n is 0, set the error handler line to 0. If n is not 0: if there is no line with line number n, UNDEFINED LINE NUMBER; otherwise, set the error handler line to n. In either case, whether an error is being handled is not changed.
- RESUME statements: if an error is not being handled, it is runtime error RESUME WITHOUT ERROR. If an error is being handled, do the following.
  RESUME: leave the "handling an error" state and go to the position of the remembered error statement (that statement is executed again from the beginning).
  RESUME NEXT: leave the "handling an error" state and go to the position of the next statement of the remembered error statement. If the error statement is an IF statement, this is the next statement of that IF statement (the clause is not entered).
  RESUME n: if there is no line with line number n, UNDEFINED LINE NUMBER (an error is still being handled at this point, so this error is not trapped). Otherwise, leave the "handling an error" state and go to line n.
- The values of ERR and ERL are those of the last trapped error. They do not change when the "handling an error" state is left.
- If another runtime error occurs while an error is being handled, that error is not trapped, so the message is output and execution ends.

17. End of execution
When execution ends (whether by an END statement, a STOP statement, there being no next statement, or a runtime error that is not trapped), and when the program was not executed because of a syntax error, end the line if the current output line is not empty. Then output the single line READY.

[Output format]
- For each program, output the syntax error line or the output produced during execution (the lines from PRINT statements, and the messages ?REDO FROM START, BREAK IN LINE n and ERROR IN LINE n: M), and finally output the single line READY.
- Every line ends with LF and has no trailing spaces.

[Constraints]
- 1 <= T <= 100
- For each program, the program lines and the data lines are each at most 200 lines.
- Every line of the input is at most 200 characters long.
- A run of 10 or more consecutive digits never appears in the part of a program line's content outside string constants, in a data line, or in the string argument of VAL.
- The length of the current output line is always at most 500.
- The execution of each program always terminates, and the total number of statements executed (a statement in a clause and an IF statement each count as one) is at most 100000.

[Example]
Input:
3
30 PRINT "TOTAL"; T
10 FOR I = 1 TO 3 : INPUT A : T = T + A : NEXT I
20 PRINT "ITEMS", 3, "AVG"; T / 3
30 PRINT "TOTAL ="; T : IF T > 10 THEN GOSUB 100 ELSE PRINT "SMALL"
40 END
100 PRINT "BIG"; : RETURN
RUN
4
five
5
3
END
10 DIM A(2)
20 FOR I = 0 TO 3 : A(I) = I * 10 : PRINT A(I); " "; : NEXT I
RUN
END
10 PRINT "HELLO"
20 PRINT "A" + 1
RUN
END

Output:
?REDO FROM START
ITEMS     3         AVG4
TOTAL =12
BIG
READY
0 10 20
ERROR IN LINE 20: SUBSCRIPT OUT OF RANGE
READY
ERROR IN LINE 20: SYNTAX ERROR
READY

In the first program, line 30 is replaced by the content entered later. The second data line, five, is not an integer, so ?REDO FROM START is output and the next line is read; A is read as 4, 5 and 3 in this order. When execution ends at the END after returning from GOSUB 100, the BIG in the current output line is output by ending the line. In the second program, A(3) for I equal to 3 exceeds the upper bound 2, so the trailing space of "0 10 20 " in the current output line is removed and the line is ended before the error message is output. The third program is not executed because the type of the expression on line 20 is incorrect.
