[Overview]
Write a processor (query engine) for Datalog, a logic database language. The program reads statements from standard input, written one per line, registers facts and rules, and answers queries. Rules may be recursive, and negation (not) may be used to the extent that the program can be stratified. Rule bodies may also contain comparisons involving integer arithmetic (addition, subtraction, multiplication and division). Queries are answered by computing the set of all tuples derivable from the registered facts and rules (the model), bottom-up to a fixpoint, stratum by stratum. In addition, the program performs aggregation such as the number or the sum of the answers, deletion of facts (retract), explanation of derivations (why), deletion of rules (forget), undoing of changes (undo), checking of constraints (check), and display of the registered contents and statistics. A statement with an error, such as an arity mismatch, an unsafe variable or negation that cannot be stratified, is rejected with an error report.

[Input format]
The input consists of several lines, and the last line is halt. . Each line is a string of 0 to 200 characters consisting only of ASCII printable characters (character codes 32 to 126).
Each line contains zero or one statement. A statement never spans several lines. The halt. on the last line is a statement that marks the end of the input; no earlier line contains a correctly formed halt statement.
The lines of the input are numbered 1, 2, 3, ... in order starting from the first line (empty lines and lines with only a comment are counted too). This number is called the line number.

[Processing]
Process the input lines one at a time in order, starting with the first line. For each line, first perform lexical analysis (Section 2); if there are no tokens, do nothing and go on to the next line. If there are tokens, perform syntax analysis (Section 3) and process the resulting statement (Sections 10 to 13). When the halt. line is reached, finish processing without outputting anything.
If an error is found anywhere in lexical analysis, syntax analysis or the processing of the statement, output the single line "ERROR line <line number>: <reason>" and stop processing that line. In that case the statement has no effect at all (neither the registered contents nor the undo history change). For each line, only one error is reported: the first one found in the order of the descriptions.
Below, a string enclosed in double quotes is a string that appears in the output exactly as is. However, each part inside it enclosed in < and > (written in descriptive words) is replaced by the value described.

Section 1. Terms and values
- A space means only the half-width space (character code 32). The lowercase letters are the 26 characters a to z, the uppercase letters are the 26 characters A to Z, the digits are the 10 characters 0 to 9, and the word characters are the 63 characters consisting of the lowercase letters, the uppercase letters, the digits and _.
- The reserved words are the following 17 words.
  not mod count sum min max retract dump why forget listing strata stats check predicates undo halt
- A Datalog value is of one of two kinds: an integer or a symbol. A symbol is a string of 0 or more characters, each of which is a printable character (character codes 32 to 126) other than ". Integers and symbols are values of different kinds; for example, the integer 7 and the symbol consisting of the one-character string 7 are different values.
- Value order: every integer comes before every symbol. Between integers, the numerically smaller one comes first. Between symbols, compare the character codes one character at a time from the beginning; the one whose character code is smaller at the first differing character comes first. If one is a prefix of the other, the shorter one comes first. For example, the integer -3, the integer 10, the empty symbol, the symbol Zoe, the symbol ab and the symbol abc are in this order.
- Tuple order: between sequences of values of the same length, compare the values in order starting from the first; the sequence whose value at the first differing position comes first in value order comes first.
- Notation of a value: an integer is written in decimal (with no extra leading zeros, and with a leading - for a negative number). A symbol that starts with a lowercase letter, consists only of word characters and is not a reserved word is written as the string itself. Any other symbol (the empty symbol, a symbol that starts with a character other than a lowercase letter, a symbol that contains a character other than a word character, or a symbol equal to a reserved word) is written as the string with a " added on both sides. For example, the notation of the symbol bob is bob, that of the symbol New York is "New York", that of the symbol Dee is "Dee", that of the empty symbol is "", that of the symbol max is "max", and that of the symbol consisting of the one character 7 is "7".
- A predicate is denoted by a name (Section 2). Each predicate has a fixed arity (number of arguments), which is an integer of 0 or more. A tuple of a predicate P is a sequence of values whose length equals the arity of P. A predicate of arity 0 has only one kind of tuple, the empty sequence.
- Notation of a tuple: for a predicate P and a tuple (v1, ..., vk), if k is 1 or more, it is the string consisting of P followed by (, the notations of v1 to vk separated by ", " (a comma and one space), and ). If k is 0, it is just P. Examples are parent(ann, "New York") and raining.

Section 2. Lexical analysis
Read the line from the beginning and divide it into a sequence of tokens by the following rules.
(1) Skip spaces (they serve only to separate tokens).
(2) On reading %, ignore everything from there to the end of the line (a comment). However, a % inside a string of (3) does not start a comment.
(3) On reading ", everything up to the next " forms one string token. The string of 0 or more characters between the two " (it may contain spaces and %) is called the content of the string. If there is no next " on the line, the error is "unterminated string".
(4) If the two characters starting at the current position are one of :- ?- != <= >=, those two characters form one token.
(5) Otherwise, if the current character is one of ( ) , . : = < > + - * /, that one character forms one token.
(6) Otherwise, if the current character is a word character, read as long as word characters continue, and cut out that longest part as one word. Words are classified as follows.
  - A word that starts with a lowercase letter is a reserved word token if it is a reserved word, and a name token otherwise.
  - A word that starts with an uppercase letter is a variable token. This word is called the variable name.
  - A word consisting only of the single character _ is an anonymous variable token.
  - A word consisting only of digits is an integer token. Its value is the integer obtained by reading the word as a decimal number (leading zeros are ignored). If the value is greater than 1000000000, the error is "integer out of range '<the word>'".
  - Any other word (a word of 2 or more characters starting with _, or a word that starts with a digit and contains a non-digit character) is an error, and the error is "bad token '<the word>'".
(7) Any other character (such as ! ? # ; [) is an error, and the error is "bad character '<the character>'".
The error reported is the first one found when reading the line from the beginning. For example, if ! is immediately followed by =, it is the != of (4); otherwise ! is an error of (7). A - is always a token of one character by itself; negative integers are expressed by the syntax (Section 3).
The notation of a token is exactly the input string cut out as that token. The notation of a string token includes the " on both sides.

Section 3. Syntax
A line with one or more tokens must form, as a whole, exactly one statement. The syntax of a statement is shown below. { X } means zero or more repetitions of X, [ X ] means that X may be omitted, and | means "or"; ::= separates a grammar symbol from its definition. These five symbols ::= { } [ ] | are notation of the grammar, not tokens. Every other ASCII symbol and every reserved word in the grammar stands for that token, and NAME, STRING, INTEGER, VARIABLE and ANONYMOUS stand for a token of the kind name, string, integer, variable and anonymous variable, respectively.

  Statement ::= Clause | Query | Command
  Clause ::= Atom . | Atom :- Body . | :- Body .
  Query ::= ?- [ Aggregate ] Body .
  Aggregate ::= count | sum VARIABLE : | min VARIABLE : | max VARIABLE :
  Command ::= retract Atom . | why Atom . | dump NAME . | forget INTEGER . | listing [ NAME ] . | strata . | stats . | check . | predicates . | undo . | halt .
  Body ::= Literal { , Literal }
  Literal ::= Atom | not Atom | Expression ComparisonOperator Expression
  ComparisonOperator ::= = | != | < | <= | > | >=
  Atom ::= NAME | NAME ( Term { , Term } )
  Term ::= NAME | STRING | INTEGER | - INTEGER | VARIABLE | ANONYMOUS
  Expression ::= Product { AdditiveOperator Product }
  AdditiveOperator ::= + | -
  Product ::= Factor { MultiplicativeOperator Factor }
  MultiplicativeOperator ::= * | / | mod
  Factor ::= Term | ( Expression )

Notes and terms:
- When a literal starts with a name token, read it as "Expression ComparisonOperator Expression" if the next token is a comparison operator or one of + - * / mod, and as an atom otherwise.
- The term "- INTEGER" denotes a negative integer (or 0). There may be spaces between - and the integer. Within an expression, a - immediately after a term or ) is the subtraction operator. For example, X - 3 and X -3 are both expressions that subtract 3 from X, and X - -3 is an expression that subtracts -3 from X.
- A clause of the form "Atom ." is called a fact clause, one of the form "Atom :- Body ." a rule, and one of the form ":- Body ." a constraint. The atom of a fact clause or of a rule is called the head. The body of a fact clause is empty.
- Among the literals of a body, an atom without not is called a positive atom, an atom with not a negated atom, and "Expression ComparisonOperator Expression" a comparison.
- A variable token is called a named variable, and named variables with the same variable name are the same variable. Each occurrence of an anonymous variable is a different one, and it is never bound to a value. The word "variable" alone means a named variable.
- Terms of the forms NAME, STRING, INTEGER and "- INTEGER" are called constants. The value of a name is the symbol whose string is the same as the name, the value of a string is the symbol of its content, the value of an integer is that integer, and the value of "- INTEGER" is that integer with its sign reversed (- 0 is 0). Therefore the name bob and the string "bob" are the same value, and 007 and 7 are also the same value.

Syntax errors: looking at the token sequence in order from the beginning, let T be the first token such that the sequence from the beginning up to and including that token is not a prefix of any statement. In that case the error is "syntax error at '<notation of T>'". If there is no such token and the whole token sequence is not a complete statement, the error is "syntax error at end of line". For example, in p(a). q(b). the q of the second atom is T, and the error is "syntax error at 'q'". p(a) gives "syntax error at end of line". In p(max). the reserved word max cannot be a term, so the error is "syntax error at 'max'".

Section 4. Program state
The processor has the following state. Initially all of it is empty, and the next rule number is 1.
- The registered predicates, each with its arity.
- The registered facts: for each registered predicate, a set of tuples (each tuple is contained only once).
- The registered rules and constraints: each has a number. Below, "rule N" means the rule or constraint whose number is N.
- The next rule number: each time a rule or constraint is registered, it is given this value as its number, and the value is increased by 1. A number once used is never used again, even after forget or undo.
- The undo history: a sequence of entries. A statement that changes the state (registering a fact, registering a rule, registering a constraint, retract, forget) adds, immediately before changing the state, one entry to the end of the history consisting of the registered predicates (including their arities), the registered facts and the contents of the registered rules and constraints at that time, together with the line number of the statement. A statement that changes nothing and a statement that results in an error add no entry to the history.

Section 5. Predicate checks
Predicate check for clauses: starting from the head atom (if any), examine the positive atoms and negated atoms of the body from left to right. Let P be the predicate of the atom and k the number of its terms. If P is registered and its arity a differs from k, or if P is not registered and has appeared earlier in this clause with a number of terms a, and a differs from k, the error is "arity mismatch for <P>: expected <a>, got <k>".
Predicate check for queries, retract and why: examine the atoms from left to right; if the predicate P is not registered, the error is "unknown predicate <P>", and if it is registered and its arity a differs from the number of terms k, the error is "arity mismatch for <P>: expected <a>, got <k>". A query or the like never registers a predicate.

Section 6. Safety checks
For clauses (including fact clauses) and queries, check the following in this order.
(1) If the head contains an anonymous variable, the error is "anonymous variable in head".
(2) If any comparison of the body (in either the left or the right expression) contains an anonymous variable, the error is "anonymous variable in comparison".
(3) The variables that appear in positive atoms of the body are called bound variables. First take the variables in the terms of the head from left to right (in a query with an aggregate sum, min or max, take the variable of the aggregate instead), then take the negated atoms and comparisons of the body from left to right, examining the variables in them from left to right. If a variable that is not a bound variable is found, then for the first such variable V found, the error is "unsafe variable <V>".
A fact clause, whose body is empty, has no bound variables, so if the head contains a variable, the first one is an unsafe variable.

Section 7. Dependencies and strata
For a registered rule (constraints are not included), with H the predicate of the head and Q the predicate of an atom of the body, we say that "H depends on Q". If that atom is a negated atom, it is a negative dependency; if it is a positive atom, it is a positive dependency.
Assign an integer s(P) of 0 or more to each registered predicate P. s is the assignment, among those that satisfy s(H) >= s(Q) for every positive dependency and s(H) >= s(Q) + 1 for every negative dependency, in which the value of each predicate is minimal. s(P) is called the stratum of P. s(P) equals the maximum, over all paths that follow dependencies one or more times starting from P, of the number of negative dependencies contained in the path (0 if there are no dependencies). If there is a cycle (a path that follows dependencies and returns to the starting predicate) that contains a negative dependency, no such assignment exists.
When a rule is about to be registered, if no assignment would exist after adding that rule and registering the unregistered predicates in it (with their arities), the error is "negative cycle through <H>", where H is the predicate of the head of that rule. For the registered rules, an assignment always exists.
When it is possible to return to P by following dependencies one or more times starting from a predicate P, P is said to be recursive.

Section 8. Solutions and values of expressions
Given a body and a set D of tuples for each predicate, a solution of the body is an assignment of values to all variables that appear in the body that satisfies all of the following.
- Each positive atom matches some tuple of its predicate in D.
- Each negated atom matches no tuple of its predicate in D.
- Each comparison holds.
An atom matches a tuple when, for each position, if the term is a constant its value equals the value of the tuple, and if it is a variable the assigned value equals the value of the tuple. A position with an anonymous variable matches any value. When the body has no variables, there is 1 solution if the empty assignment satisfies the above conditions, and 0 solutions otherwise. Two solutions are considered the same when they assign the same value to every variable. (Because of the safety checks, every variable of the body appears in a positive atom, so the number of solutions is finite.)

Value of an expression: the value of an expression consisting of a term only is the value of the term (for a variable, the assigned value). The value of an expression enclosed in parentheses is the value of the expression inside. The operators * / mod bind more tightly than + -, and operators of the same precedence associate from left to right (for example, 7 - 2 - 1 is (7 - 2) - 1, and 1 + 2 * 3 is 1 + (2 * 3)). When the values a and b on the left and right of an operator are both integers, a + b, a - b and a * b are the integer sum, difference and product, a / b is the largest integer less than or equal to the exact quotient of a divided by b (rounding toward negative infinity), and a mod b is a - b * (a / b). For example, 7 / 2 = 3, -7 / 2 = -4, 7 / -2 = -4, 7 mod 3 = 1, -7 mod 2 = 1, and 7 mod -2 = -1. However, when at least one of a and b is not an integer, or when b is 0 for / and mod, the result of the operation is "no value". The result of an operation with no value on either its left or its right side is also no value.
A comparison holds as follows. If at least one of the left and right expressions has no value, the comparison does not hold, whatever the comparison operator is (!= does not hold either). Otherwise, = holds when the left and right sides are the same value (values of the same kind that are equal), and != holds when they are not the same value. < <= > >= hold only when the left and right sides are both integers and are in that numerical relation (they do not hold if at least one side is a symbol).

Section 9. Computing the model
Queries and some commands use the model. The model is the set of tuples of each registered predicate determined by the following procedure from the registered facts and rules (constraints are not included) at that time. The implementation method is free, but the model, the derivation numbers, the deriving rules, the numbers of rounds and the numbers of new tuples must agree with those determined by this procedure.
(1) Let the set of tuples of each predicate be the set of registered facts of that predicate. The derivation number of these tuples is 0. Let the round serial number n be 0.
(2) For k = 0, 1, 2, ..., (the maximum stratum of the registered predicates), in this order, perform the processing of stratum k. A rule whose head predicate has stratum k is called a rule of stratum k. In the processing of stratum k, repeat the following round.
  - In one round, for each rule of stratum k, with D being the sets of tuples at the start of the round, find all solutions of the body, and for each solution make the tuple (a tuple of the head predicate) consisting of the values of the terms of the head. Among the tuples made in this way, those not contained in the set of their predicate at the start of the round are the new tuples.
  - If there are no new tuples, finish the processing of stratum k.
  - If there are new tuples, increase n by 1 and add all new tuples to the sets of their predicates. The derivation number of the added tuples is n. Also, for each new tuple, the rule with the smallest number among the rules that made that tuple in this round is the deriving rule of that tuple. Then go on to the next round.
(3) The sets of tuples when the processing of all strata has finished are the model.
The number of rounds of stratum k is the number of rounds in the processing of stratum k that added new tuples (the final round, which had no new tuples, is not counted). The number of new tuples of stratum k is the total number of tuples added in the processing of stratum k. Since the stratum of the predicate of a negated atom is smaller than the stratum of the head predicate of its rule, its set of tuples is already fixed before the processing of stratum k starts.

Section 10. Registering clauses
For a fact clause, perform the check of Section 5 and then the check of Section 6. If there is no error, and the tuple consisting of the values of the terms of the head is not contained in the registered facts of its predicate, add an entry to the history and then add that tuple to the registered facts (if the predicate is not registered, also register the predicate with that arity). If it is already contained, do nothing. In either case there is no output.
For a rule, perform the check of Section 5, the check of Section 6, the duplicate check and the stratification check of Section 7, in this order. For a constraint, perform the check of Section 5, the check of Section 6 and the duplicate check, in this order. In the duplicate check, if among the registered rules and constraints there is one whose notation (Section 11) is the same as the notation of this rule or constraint, then with N being its number, the error is "duplicate of rule <N>". If there is no error, add an entry to the history, then register it with the next rule number, and register the unregistered predicates in it with the numbers of terms they have there.
After registering a rule or constraint, for each variable that appears exactly once in it (counting all occurrences in the head and the body; anonymous variables are not counted), in the order of their first occurrence, output "WARNING line <line number>: singleton variable <variable name>". There is no other output.

Section 11. Notation of rules
The notation of rules and constraints is defined as follows.
- Notation of a term: a constant term is the notation of its value (Section 1). A variable is its variable name, and an anonymous variable is _.
- Notation of an atom: the name of the predicate, followed by nothing if there are no terms, or, if there are terms, by (, the notations of the terms separated by ", ", and ). A negated atom is "not " (not and one space) followed by the notation of the atom.
- Notation of an expression: an expression consisting of a term only is the notation of that term. An expression enclosed in parentheses is (, the notation of the expression inside, and ) (parentheses are kept exactly as written in the input; none are added or removed). An operation is the notation of the left expression, one space, the operator (+ - * / mod), one space, and the notation of the right expression. A comparison is the notation of the left expression, one space, the comparison operator, one space, and the notation of the right expression.
- The notation of a rule is the notation of the head, " :- ", the notations of the literals of the body separated by ", ", and ".", in this order. The notation of a constraint is ":- ", the notations of the literals of the body separated by ", ", and ".", in this order.
For example, the notation of the rule given by the input p(X):-q( X ,007,"bob"),not r(X,_),X+(1)*2>=- 3. is p(X) :- q(X, 7, bob), not r(X, _), X + (1) * 2 >= -3.

Section 12. Queries
For a query, perform the check of Section 5 (the check for queries) and then the check of Section 6. If there is no error, find all solutions of the body with respect to the model. The variables that appear in the body, arranged in the order of their first occurrence in the body (from left to right, including occurrences in negated atoms and comparisons), are called the answer variables, and for each solution, the sequence of the values assigned to the answer variables, in that order, is called an answer. Identical answers are treated as one, and the answers are arranged in tuple order.
- Query without an aggregate: if there are answer variables, output for each answer one line consisting of "<variable name> = <notation of the value>" for the answer variables, in their order, separated by ", ", and finally output "<number of answers> answers". However, when the number of answers is 1, output "1 answer". When there are no answer variables, output "true." if there is at least one solution, and "false." otherwise.
- count: output the number of answers in decimal (if there are no answer variables, it is 1 if there is a solution, and 0 otherwise).
- sum V: output in decimal the total obtained by adding up the value of V for each answer, adding it once per answer even when the values are equal. If there are no answers, it is 0. If even one value of V is a symbol, the error is "non-integer value in sum".
- min V, max V: output the notation of the value of V among the answers that comes first in value order (min), or last in value order (max). If there are no answers, output "no answers".
For example, ?- sum A : age(P, A). adds up A for each of the answers with distinct combinations of the values of P and A.

Section 13. Commands
(a) retract <atom>.
The terms of the atom may be constants, variables and anonymous variables. After the check of Section 5 (the check for queries), delete all tuples among the registered facts of that predicate that match the atom. Here, the atom matches a tuple when it matches in the sense of Section 8 under some assignment of values to the variables of the atom (if the same variable is at several positions, the values of the tuple at those positions must all be equal). If no tuple matches, the error is "no matching facts". Otherwise, add an entry to the history, then delete them, and output "<number of deleted tuples> facts retracted". However, when it is 1, output "1 fact retracted". A tuple that is only derived by rules is not a registered fact, so it is not a target of retract.
(b) dump <name>.
If the predicate with that name is not registered, the error is "unknown predicate <name>". If it is registered, arrange the tuples of that predicate in the model in tuple order, output one line "<notation of the tuple>." for each of them, and finally output "<number of tuples> tuples". However, when it is 1, output "1 tuple".
(c) why <atom>.
After the check of Section 5 (the check for queries), if the atom contains a variable or an anonymous variable, the error is "why needs a ground atom". Let t be the tuple consisting of the values of the terms of the atom. If t is not contained in the set of that predicate in the model, output "false."; if it is contained, output the proof of t at depth 0.
The procedure for outputting the proof of a tuple t at depth d is as follows. The indent is 2*d spaces.
- If the derivation number of t is 0, output "<indent><notation of the tuple t> [fact]".
- Otherwise, let m be the derivation number of t. Examine the rules whose head predicate is the predicate of t (constraints are not included) in increasing order of number, and select the first rule R for which there exists a solution theta of the body satisfying the following conditions. The conditions are that theta is a solution of the body of R with respect to the model, except that the tuples matched by positive atoms are restricted to those whose derivation number is smaller than m (negated atoms and comparisons are checked against the model as is), and that the tuple consisting of the values of the terms of the head of R under theta equals t. Such an R always exists and coincides with the deriving rule of t. When several theta satisfy the conditions, arrange the variables of R in the order of their first occurrence in R (head, then body, from left to right), and select the theta whose sequence of values assigned to them comes first in tuple order.
  Then output "<indent><notation of the tuple t> [rule <number of R>]", and process the literals of the body of R from left to right. For a positive atom, output at depth d+1 the proof of the tuple consisting of the values of its terms under theta. However, when that atom contains an anonymous variable, output the proof of the tuple that, among the tuples of the model that match the atom under theta and whose derivation number is smaller than m, comes first in tuple order. For a negated atom or a comparison, output one line consisting of the indent and two spaces, followed by the notation of that literal (Section 11) with its variables replaced by the notations of the values assigned by theta (anonymous variables stay as _, constants, operators and parentheses also stay as in the notation, and expressions are not evaluated).
However many times the same tuple appears in a proof, its proof is output each time.
(d) forget <integer>.
Let N be the value of the integer. If rule N (a rule or a constraint) is not registered, the error is "no rule <N>". If it is registered, add an entry to the history and then delete rule N. There is no output. The registrations of predicates remain as they are.
(e) undo.
If the history is empty, the error is "nothing to undo". Otherwise, remove the last entry of the history, restore the registered predicates, the registered facts and the registered rules and constraints to the contents of that entry (the state immediately before processing the statement that added that entry), and output "undid line <line number of that entry>". The next rule number is not restored. undo itself adds no entry to the history.
(f) listing. and listing <name>.
listing. outputs the registered rules and constraints in increasing order of number, each as one line "<number>: <notation>". For listing <name>., if the predicate with that name is not registered, the error is "unknown predicate <name>"; if it is registered, output in the same form only the rules (constraints are not included) whose head predicate is that predicate. In both cases, if there is no rule to output, output "no rules".
(g) strata.
If there are no registered predicates, output "no predicates". Otherwise, for each k = 0, 1, ..., (the maximum stratum), output "stratum <k>: <list of predicates>". The list of predicates consists of the names of all registered predicates whose stratum is k, arranged in value order (order by character codes), with a * added immediately after the name of each recursive predicate, separated by ", ".
(h) stats.
Output "facts <F>, rules <R>, constraints <C>, tuples <T>". F is the total number of registered facts, R is the number of registered rules (excluding constraints), C is the number of registered constraints, and T is the total number of tuples of the model. Next, if there are registered predicates, then for each k = 0, 1, ..., (the maximum stratum), output "stratum <k>: rounds <number of rounds of stratum k>, new <number of new tuples of stratum k>". Finally, for each registered rule (excluding constraints), in increasing order of number, output "rule <number>: new <number of tuples of the model whose deriving rule is that rule>".
(i) predicates.
If there are no registered predicates, output "no predicates". Otherwise, arrange the names of the predicates in value order (order by character codes), and for each of them output "<name>/<arity>: facts <F>, rules <R>, tuples <T>". F is the number of registered facts of that predicate, R is the number of rules (constraints are not included) whose head predicate is that predicate, and T is the number of tuples of that predicate in the model.
(j) check.
If there are no registered constraints, output "no constraints". Otherwise, for each constraint in increasing order of number, find the answers of the body of the constraint with respect to the model in the same way as for a query (Section 12). If there are no answers, output "constraint <number>: ok". If there are answers, output "constraint <number>: <number of answers> violations" ("constraint <number>: 1 violation" when there is 1), and, if there are answer variables, then output the answers one at a time in tuple order, each on one line consisting of two spaces followed by the same form as for a query ("<variable name> = <notation of the value>" separated by ", ").

[Output format]
- Output the lines described in [Processing] in the order of the input lines. Every line ends with LF. No empty lines are output.
- There are the following 18 kinds of error reasons (the < > parts are replaced as described; ' is the character ' itself).
  unterminated string
  bad character '<character>'
  bad token '<word>'
  integer out of range '<word>'
  syntax error at '<notation of the token>'
  syntax error at end of line
  unknown predicate <predicate>
  arity mismatch for <predicate>: expected <count>, got <count>
  anonymous variable in head
  anonymous variable in comparison
  unsafe variable <variable name>
  duplicate of rule <number>
  negative cycle through <predicate>
  non-integer value in sum
  no matching facts
  why needs a ground atom
  no rule <number>
  nothing to undo
- There is only one kind of warning, "WARNING line <line number>: singleton variable <variable name>".

[Constraints]
- The number of input lines is at most 1000.
- A word consisting only of digits has at most 10 characters.
- At all times there are at most 50 registered predicates, the arity of a predicate is at most 8, there are at most 1000 registered facts, and there are at most 100 registered rules and constraints.
- The total number of tuples of the model is always at most 5000. The number of answers of one query, the number of answers of one constraint, and the number of solutions of one rule in one round are each at most 10000.
- The absolute value of every integer that appears during the evaluation of a comparison expression is always at most 10^15. That is, whatever value is assigned to each variable of the comparison expression, chosen from the values that appear at its position in the model at that time for any one of the positive atoms of the body in which the variable appears (chosen independently for each variable), the evaluation never exceeds this range.
- The number of lines output by one why is at most 500.

[Example]
Input:
% family tree
parent(ann, bob).
parent(bob, cid).
parent(bob, "Dee").   % "Dee" starts with an uppercase letter
anc(X, Y) :- parent(X, Y).
anc(X, Y) :- parent(X, Z), anc(Z, Y).
?- anc(ann, Who).
?- count anc(X, _).
why anc(ann, cid).
leaf(X) :- anc(Root, X), not parent(X, _).
bad(X) :- leaf(X), not bad(X).
age(ann, 61). age(bob, 35).
age(bob, 35).
?- sum A : age(P, A), A > 40 - 10.
strata.
halt.

Output:
Who = "Dee"
Who = bob
Who = cid
3 answers
2
anc(ann, cid) [rule 2]
  parent(ann, bob) [fact]
  anc(bob, cid) [rule 1]
    parent(bob, cid) [fact]
WARNING line 10: singleton variable Root
ERROR line 11: negative cycle through bad
ERROR line 12: syntax error at 'age'
35
stratum 0: age, anc*, parent
stratum 1: leaf

The symbol Dee starts with an uppercase letter, so its notation is "Dee", and it comes before bob in value order. The only answer variable of ?- count anc(X, _). is X, so there are 2 answers, ann and bob. anc(ann, cid) is derived by rule 2 in the second round, and the anc(bob, cid) in it is derived by rule 1 in the first round. The variable Root of the leaf rule appears only once, so a warning is output, but the rule is registered as rule 3. The bad rule creates a cycle of dependencies containing a negative dependency, so it is not registered. Line 12 contains two statements, so it is a syntax error, and age(ann, 61) is not registered. Therefore the answer of sum is only the 35 of bob. The strata are 0 for parent, anc and age, and 1 for leaf, and anc is recursive because it depends on itself.
