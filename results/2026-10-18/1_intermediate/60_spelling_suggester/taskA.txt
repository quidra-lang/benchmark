[Overview]
Write a spell checker for English words. The program reads from standard input a dictionary of words with their frequencies, followed by a sequence of commands. It then detects words in a text that are not in the dictionary and suggests corrections, corrects automatically, checks capitalization and repeated words, computes edit distances and their operation sequences, encodes pronunciation with Soundex, segments words, completes words by prefix match and fuzzy prefix match, edits the dictionary, the ignore list and the replacement rules (with undo), learns frequencies from text, and so on, and writes the results to standard output. Correction candidates are searched with an edit distance that also counts a swap of two adjacent characters as a single operation (the restricted Damerau-Levenshtein distance). When the keyboard mode is turned ON, a weighted distance is used that counts a typo on a key adjacent on the keyboard as cheaper.

[Input format]
The 1st line contains the number of dictionary words M, and each of the following M lines contains one dictionary word and its frequency, separated by a single space. A word is a sequence of 1 to 30 lowercase letters (a to z), and no word appears twice or more. A frequency is an integer from 1 to 1000000, written in decimal without extra leading zeros.
The next line contains the number of commands N, and each of the following N lines contains one command. There are the following 27 command formats.

  CHECK text
  CORRECT text
  FIX text
  PROFILE text
  LEARN text
  SUGGEST w
  DIST w1 w2
  SOUNDEX w
  SOUNDS w
  SPLIT w
  PREFIX w k
  COMPLETE w k
  LIST w k
  WORD w
  ADD w f
  REMOVE w
  IGNORE w
  UNIGNORE w
  RULE w1 w2
  UNRULE w
  RULES
  KEYBOARD mode
  SET option value
  UNDO
  REPORT
  HISTORY
  STATS

text stands for a "text", and the other lowercase names (w, w1, w2, k, f, mode, option, value) stand for "arguments". The command name and the arguments, and the arguments among themselves, are separated by a single space. In the 5 commands that take a text (CHECK, CORRECT, FIX, PROFILE, LEARN), the command name is followed by a single space, and the whole rest of the line after it is the text. A text is at least 1 character long, and its first and last characters are not spaces.
Each command line is 1 to 160 characters long, consists only of printable ASCII characters (character codes 32 to 126), and its first and last characters are not spaces. Two or more consecutive spaces can occur only inside a text. However, the input may contain lines whose command name is none of the 27 commands, lines with the wrong number of arguments, and lines with invalid argument values; their handling is defined in [Processing].

[Processing]
Process the commands in order from the first line, and output the result of each command.

1. Terms and state
- A "letter" is one of the 52 characters: the uppercase letters A to Z and the lowercase letters a to z. "Converting to lowercase" means changing each uppercase letter to the corresponding lowercase letter.
- Words are compared in lexicographic order by ASCII character code. That is, compare character by character from the beginning; at the first differing character, the one with the smaller character code is smaller, and if one word is equal to the beginning of the other, the shorter one is smaller.
- The program has the following state.
  Dictionary: a collection of pairs of a word (a sequence of 1 to 30 lowercase letters) and its frequency (an integer >= 1). Initially it holds the M words of the input.
  Ignore list: a collection of words. Initially empty. Words in the ignore list are not in the dictionary but are treated as correct words. The same word is never in both the dictionary and the ignore list.
  Replacement rules: a collection of rules of the form "correct word u to word v", at most one per u. u is called the rule's "source word" and v its "target". Initially empty.
  Keyboard mode: ON or OFF. Initially OFF.
  Base limit: initially 2.
  Suggestion count: initially 5.
  Undo history: a sequence of records. Initially empty.
  Unknown-word log: a count per word. Initially empty.
  Correction log: a count per "pair of an original word form and a correction". Initially empty.
  Counters: 6 integers checked, unknown, case, capital, repeats, corrected. Initially all 0.
- A word is "known" if it is in the dictionary or in the ignore list.
- "Frequency order" means decreasing frequency, and for equal frequencies, increasing word.
- The "limit" L is the base limit if the keyboard mode is OFF, and twice the base limit if it is ON.

2. Tokens
In a text, a run of consecutive letters that is neither preceded nor followed by a letter (a maximal run of letters) is called a "token". Every character other than a letter (digits, symbols, spaces) is treated as a separator. Tokens are numbered 1, 2, 3, ... from left to right. The token converted to lowercase is called the token's "word form".
Example: the tokens of the text "Don't stop2go!" are the 4 tokens Don, t, stop, go, whose word forms are don, t, stop, go respectively.
The properties of a token are defined as follows. Here, the "gap" of a token is the sequence of characters between that token and the immediately preceding token.
- Sentence start: the token is the 1st token, or its gap contains at least one of . ! ?.
- Repeat: the token is the 2nd or a later token, its word form equals the word form of the immediately preceding token, and every character of its gap is a space.
- Mixed case: the token contains an uppercase letter at the 2nd or a later position, and moreover does not consist only of uppercase letters. For example, tHe, HEllo, McKay are mixed case, and NASA, Hello, I, hello are not mixed case.

3. Edit distance
For a word a (length p) and a word b (length q), build a table d (d[i][j], 0 <= i <= p, 0 <= j <= q) as follows. The i-th character of a is written a_i and the j-th character of b is written b_j (both counted from 1).
First, define the cost g of a deletion and of an insertion, and the cost s(x, y) of a substitution that turns character x into character y, as follows.
  When the keyboard mode is OFF: g=1. s(x, y) is 0 if x=y, and 1 otherwise.
  When the keyboard mode is ON: g=2. s(x, y) is 0 if x=y, 1 if x and y are adjacent in the adjacency table below, and 2 otherwise.
The cost of swapping two adjacent characters is 1 in both modes.
- Let d[0][0]=0, d[i][0]=i*g, d[0][j]=j*g.
- For i=1, 2, ..., p in this order, and for each i, for j=1, 2, ..., q in this order, let d[i][j] be the minimum of the following values.
  d[i-1][j]+g (deletion of a_i)
  d[i][j-1]+g (insertion of b_j)
  d[i-1][j-1]+s(a_i, b_j) (substitution of a_i by b_j; a match when a_i=b_j)
  d[i-2][j-2]+1 (swap; considered only when i >= 2, j >= 2, a_i=b_(j-1) and a_(i-1)=b_j all hold)
d[p][q] is called the "edit distance" from a to b, written D(a, b).
The adjacency table is as follows. It represents keys that are adjacent on a QWERTY keyboard; "x: ..." is the list of letters adjacent to x. The adjacency relation is symmetric.
  a: q s w z
  b: g h n v
  c: d f v x
  d: c e f r s x
  e: d r s w
  f: c d g r t v
  g: b f h t v y
  h: b g j n u y
  i: j k o u
  j: h i k m n u
  k: i j l m o
  l: k o p
  m: j k n
  n: b h j m
  o: i k l p
  p: l o
  q: a w
  r: d e f t
  s: a d e w x z
  t: f g r y
  u: h i j y
  v: b c f g
  w: a e q s
  x: c d s z
  y: g h t u
  z: a s x

4. Candidates and corrections
- The "candidates" of a word x are the dictionary words y such that y differs from x and D(x, y) <= L (words in the ignore list are never candidates).
- Candidates are sorted by increasing D(x, y), ties by decreasing frequency, and further ties by increasing word. This is called "candidate order".
- The "correction" of a word x that is not known is defined as follows. If there is a replacement rule with source word x, it is that rule's target. Otherwise, it is the first candidate in candidate order. If there are no candidates either, there is no correction. A known word has no correction.

5. Case pattern
When a token T is replaced by a lowercase word y, use y changed to match T as follows.
- If T is 2 or more characters long and consists only of uppercase letters: make every character of y uppercase.
- Otherwise, if the 1st character of T is an uppercase letter: make only the 1st character of y uppercase.
- Otherwise: y as it is.
For example, with y=hello, the result is HELLO if T is HELO, Hello if T is Helo or HEllo, and hello if T is helo or hELO. Also, replacing T=U with you gives You.

6. Soundex code
The "digit" of a letter is defined as follows (an uppercase letter is the same as the corresponding lowercase letter).
  b f p v: 1
  c g j k q s x z: 2
  d t: 3
  l: 4
  m n: 5
  r: 6
  a e i o u y: 0
  h w: no digit
The Soundex code of a word x is a 4-character string built by the following steps.
(1) The 1st character of x converted to uppercase is the 1st character of the code. Also, set the "previous digit" to the digit of the 1st character of x. However, if the 1st character is h or w, set the previous digit to 0.
(2) Examine the characters of x from the 2nd to the last in order. If the character is h or w, do nothing. For any other character, let c be its digit; if c is not 0 and also differs from the previous digit, append c to the end of the code. Then, whether or not it was appended, set the previous digit to c.
(3) If the code is longer than 4 characters, keep only its first 4 characters; if it is shorter than 4 characters, append 0s to the end until it is 4 characters long.
Example: robert and rupert give R163, ashcraft gives A261, tymczak gives T522, pfister gives P236, and lee gives L000.

7. Segmentation
A "segmentation" of a word x is a way of expressing x as a concatenation of one or more dictionary words (words in the ignore list are not used). For example, if the dictionary contains the, cat, he and does not contain t, thecat has exactly one segmentation, the cat. If x itself is a dictionary word, the segmentation consisting of x alone also exists.
Among the segmentations, choose those with the fewest words; if there are several, the one whose word sequence is lexicographically smallest (compare word by word from the first word; the one whose word at the first differing position is smaller) is the "best segmentation". For example, between i sit and is it, the 1st word i is smaller than is, so i sit is smaller.

8. Parsing command lines and checking arguments
For each command line, examine the following in this order.
(1) The part of the line before the first space (the whole line if there is no space) is the command name. If the command name matches none of the 27 commands (uppercase and lowercase letters are distinguished), output "ERROR UNKNOWN COMMAND <command name>".
(2) For a command that takes a text, if the line consists of the command name only, output "ERROR BAD ARGUMENTS <command name>". For any other command, if the number of arguments obtained by splitting the part after the command name at spaces (0 for a line consisting of the command name only) differs from its format, also output "ERROR BAD ARGUMENTS <command name>".
(3) If none of the above applies, process the command as described in section 9. Test the error conditions listed under "Checks" in section 9 in the order they are written; for the first one that holds, output exactly one error line and do nothing else for that command (the state does not change at all). If none of them holds, perform the processing described after them.
There are the following 2 kinds of argument checks, written in section 9 like "word check of w" and "number check of k (1 to 20)".
- Word check: the argument passes if it consists only of letters and its length is at most 30; the argument converted to lowercase is then the value used in the subsequent processing and output. If it fails: "ERROR BAD WORD <argument>".
- Number check (lower bound to upper bound): the argument passes if it is 1 to 7 characters long, consists only of digits (0 to 9), and its value read as a decimal number (leading zeros are ignored) is at least the lower bound and at most the upper bound; that value is then used. If it fails: "ERROR BAD NUMBER <argument>".
In an error line, <argument> is the argument exactly as written in the input.

9. Commands
In the output descriptions below, <w> and the like denote the values obtained by the checks (the word converted to lowercase, or the decimal number without leading zeros). A description of the form "A followed by the items, each in the form " X"" denotes a line consisting of A followed, on the same line, by each item written in the form X, with a single space placed before each item (if there are 0 items, the line is just A). S denotes the suggestion count.

CHECK text
Examine the tokens of the text in order of their numbers. For each token, each of the following (a) to (d) that applies becomes one "finding" line, in this order. <i> is the token number and <T> is the token itself (with its original case).
(a) When the word form x is not known: if there is a replacement rule with source word x, "UNKNOWN <i> <T> RULE <target>". Otherwise, if x has candidates, "UNKNOWN <i> <T> SUGGEST" followed by the first S candidates in candidate order (all of them if there are fewer than S), each in the form " <candidate>". If there are no candidates either, "UNKNOWN <i> <T> NONE". In addition, increase the count of x in the unknown-word log by 1.
(b) When the token is mixed case: "CASE <i> <T>".
(c) When the token is a sentence start and its 1st character is a lowercase letter: "CAPITAL <i> <T>".
(d) When the token is a repeat: "REPEAT <i> <T>".
First output "CHECK words=<number of tokens> unknown=<number of (a)> case=<number of (b)> capital=<number of (c)> repeats=<number of (d)>", then output the findings in order. Also, add the number of tokens to the counter checked, and add the numbers of (a), (b), (c), (d) to unknown, case, capital, repeats respectively.

CORRECT text
In the text, replace each token whose word form has a correction with that correction changed according to the case pattern of section 5. Other tokens and the characters that are not part of tokens are kept as they are. For each replaced token, increase by 1 the count of the pair (word form, correction) in the correction log and the counter corrected. Output "CORRECT changed=<number of replaced tokens>: <text after replacement>".

FIX text
Fix the text by processing its tokens in order of their numbers as follows.
- A repeat token is removed together with its gap (spaces). Whether a token is a repeat is decided on the original text. For example, in the the the, the 2nd and 3rd tokens are both repeats and are removed, so only the remains.
- A token T that is not a repeat is replaced by R, which is y if its word form x has a correction y, or x otherwise, changed according to the case pattern of section 5. Furthermore, if T is a sentence start and the 1st character of R is a lowercase letter, make the 1st character of R uppercase.
The characters that are not part of tokens are kept as they are, except for the spaces before removed tokens. For each token replaced by a correction, update the correction log and the counter corrected in the same way as CORRECT. Output "FIX removed=<number of removed tokens> replaced=<number of tokens replaced by a correction> recased=<number of tokens that have no correction and whose R differs from T>: <text after fixing>".
(Among tokens without a correction, only mixed-case tokens and sentence-start tokens can change. For example, tHe becomes the (The at a sentence start), HEllo becomes Hello, and McKay becomes Mckay.)

PROFILE text
Output "PROFILE words=<number of tokens> distinct=<number of distinct word forms> unknown=<number of tokens whose word form is not known> rate=<unknown/words*100> avglen=<average number of characters of the tokens> longest=<word form of the longest token> sentences=<number of sentence-start tokens>". rate is written rounded half up to 1 decimal place, and avglen rounded half up to 2 decimal places. If there are several longest tokens, choose the one with the smallest number. If there are no tokens at all, use rate=0.0 avglen=0.00 longest=-. The state is not changed.

LEARN text
First, record to the undo history (see the description of UNDO). Next, process the tokens in order of their numbers. If the word form x has 31 or more characters, do nothing (count this as skipped). If x is in the dictionary, increase its frequency by 1 (updated). If it is not in the dictionary, add x to the dictionary with frequency 1, and if x is in the ignore list, remove it from the ignore list (added). When the same word form appears twice or more, from the 2nd occurrence on it is in the dictionary, so it is counted as updated. Output "LEARN updated=<number of updated> added=<number of added> skipped=<number of skipped>".

SUGGEST w
Checks: word check of w.
If w is known, output "SUGGEST <w> KNOWN". If it is not known and there is a replacement rule with source word w, output "SUGGEST <w> RULE <target>". If neither, output "SUGGEST <w> found=<number of candidates of w>" followed by the first S candidates in candidate order (all of them if fewer), each in the form " <candidate>:<edit distance from w to that candidate>".

DIST w1 w2
Checks: word check of w1. Word check of w2.
Build the table d of section 3 with a=w1 and b=w2, and obtain a sequence of operations by the following procedure. Starting from (i, j)=(p, q), repeat the first applicable one of (A) to (D) below until (i, j)=(0, 0).
(A) If i >= 1, j >= 1 and d[i][j]=d[i-1][j-1]+s(a_i, b_j): if a_i and b_j differ, obtain the operation "sub:<a_i>><b_j>" (if they are equal, obtain nothing). Set (i, j) to (i-1, j-1).
(B) If i >= 2, j >= 2, a_i=b_(j-1), a_(i-1)=b_j and d[i][j]=d[i-2][j-2]+1: obtain the operation "swap:<a_(i-1)><a_i>" and set (i, j) to (i-2, j-2).
(C) If i >= 1 and d[i][j]=d[i-1][j]+g: obtain the operation "del:<a_i>" and set (i, j) to (i-1, j).
(D) Otherwise: obtain the operation "ins:<b_j>" and set (i, j) to (i, j-1).
Output "DIST <w1> <w2> <D(w1, w2)>" followed by the obtained operations in the reverse of the order in which they were obtained (that is, starting from the operation nearest to the beginning of the words), each in the form " <operation>". For example, when the keyboard mode is OFF, the output of DIST kitten sitting is "DIST kitten sitting 3 sub:k>s sub:e>i ins:g".

SOUNDEX w
Checks: word check of w.
Output "SOUNDEX <w> <Soundex code of w>".

SOUNDS w
Checks: word check of w.
Collect the dictionary words, other than w, whose Soundex code equals the code of w. Output "SOUNDS <w> <code of w> count=<number of collected words>" followed by up to the first 10 collected words in frequency order (all of them if fewer), each in the form " <word>".

SPLIT w
Checks: word check of w.
If w has a segmentation, output "SPLIT <w> ways=<total number of segmentations> ->" followed by the words of the best segmentation in order, each in the form " <word>". If there is no segmentation, output "SPLIT <w> ways=0 -> NONE". The total number of segmentations is the number of segmentations that are distinct as word sequences.

PREFIX w k
Checks: word check of w. Number check of k (1 to 20).
Collect the dictionary words that start with w (including w itself). Output "PREFIX <w> count=<number of collected words>" followed by up to the first k collected words in frequency order (all of them if fewer), each in the form " <word>:<frequency>".

COMPLETE w k
Checks: word check of w. Number check of k (1 to 20).
For each dictionary word y, build the table d of section 3 with a=w and b=y, and let the "prefix distance" E(y) of y be the minimum of d[p][0], d[p][1], ..., d[p][q] (p is the length of w and q is the length of y; E(y) is the smallest of the edit distances from w to "the first 0 to q characters of y"). Collect the words y for which E(y) is at most the quotient of L divided by 2 (fractional part truncated). Output "COMPLETE <w> count=<number of collected words>" followed by up to the first k collected words in increasing order of E(y), ties by decreasing frequency, further ties by increasing word (all of them if fewer), each in the form " <word>:<E(y)>".

LIST w k
Checks: word check of w. Number check of k (1 to 20).
Collect the dictionary words that are greater than or equal to w (including w itself). Output "LIST <w> count=<number of collected words>" followed by up to the first k collected words in increasing order (all of them if fewer), each in the form " <word>:<frequency>".

WORD w
Checks: word check of w. If w is not in the dictionary, "ERROR NOT FOUND <w>".
Output "WORD <w> freq=<frequency> rank=<rank of w when the dictionary words are sorted in frequency order> soundex=<Soundex code of w> neighbors=<number of candidates of w>". Ranks are counted from 1.

ADD w f
Checks: word check of w. Number check of f (1 to 1000000). If w is in the dictionary, "ERROR DUPLICATE <w>".
After recording to the undo history, add w to the dictionary with frequency f, and if w is in the ignore list, remove it from the ignore list. Output "ADD <w> <f>".

REMOVE w
Checks: word check of w. If w is not in the dictionary, "ERROR NOT FOUND <w>".
After recording to the undo history, remove w from the dictionary. Output "REMOVE <w> <frequency of w before removal>".

IGNORE w
Checks: word check of w. If w is in the dictionary, "ERROR IN DICTIONARY <w>". If w is in the ignore list, "ERROR ALREADY IGNORED <w>".
After recording to the undo history, add w to the ignore list and output "IGNORE <w>".

UNIGNORE w
Checks: word check of w. If w is not in the ignore list, "ERROR NOT IGNORED <w>".
After recording to the undo history, remove w from the ignore list and output "UNIGNORE <w>".

RULE w1 w2
Checks: word check of w1. Word check of w2. If w1 is in the dictionary, "ERROR IN DICTIONARY <w1>". If w2 is not in the dictionary, "ERROR NOT FOUND <w2>".
After recording to the undo history, make the replacement rule with source word w1 "correct w1 to w2". If there was originally no rule with source word w1, output "RULE <w1> <w2>". If there was one (including when its target is the same as w2), replace that rule and output "RULE <w1> <w2> REPLACED <target before the replacement>".
A replacement rule stays as it is even if its source word later enters the dictionary or the ignore list, or its target is removed from the dictionary. However, it is not used while its source word is known (as stated in section 4, a known word has no correction).

UNRULE w
Checks: word check of w. If there is no replacement rule with source word w, "ERROR NO RULE <w>".
After recording to the undo history, remove that rule and output "UNRULE <w> <target>".

RULES
Output "RULES count=<number of replacement rules>" followed by all replacement rules in increasing order of source word, each in the form " <source word>><target>".

KEYBOARD mode
Checks: if mode is neither ON nor OFF (uppercase and lowercase letters are distinguished), "ERROR BAD MODE <mode>".
Set the keyboard mode to mode and output "KEYBOARD <mode>".

SET option value
Checks: if option is neither LIMIT nor SUGGESTIONS (uppercase and lowercase letters are distinguished), "ERROR BAD OPTION <option>". Number check of value (1 to 3 if option is LIMIT, 1 to 10 if it is SUGGESTIONS).
If option is LIMIT, set the base limit to value; if it is SUGGESTIONS, set the suggestion count to value. Output "SET <option> <value>".

UNDO
Checks: if the undo history is empty, "ERROR NOTHING TO UNDO".
Remove the last record from the undo history, and restore the three items, the dictionary (words and frequencies), the ignore list and the replacement rules, to the contents of that record. Output "UNDO <command name of that record>".
"Recording to the undo history" means appending to the end of the undo history a copy of the contents of the dictionary, the ignore list and the replacement rules at that moment, together with the command name. A record is made for ADD, REMOVE, IGNORE, UNIGNORE, RULE and UNRULE only when no error occurs, and for LEARN always (even when there are no tokens). UNDO itself is not recorded. The keyboard mode, base limit, suggestion count, unknown-word log, correction log and counters are not restored by UNDO.

REPORT
Sort the words in the unknown-word log by decreasing count, ties by increasing word. Output "REPORT distinct=<number of words>" followed by the first 10 of them (all of them if fewer), each in the form " <word>:<count>".

HISTORY
Sort the pairs in the correction log by decreasing count, ties by increasing original word form, further ties by increasing correction. Output "HISTORY distinct=<number of pairs>" followed by the first 10 of them (all of them if fewer), each in the form " <original word form>><correction>:<count>".

STATS
Output the following 2 lines. avglen is written rounded half up to 2 decimal places.
"STATS words=<number of dictionary words> total=<sum of the dictionary frequencies> avglen=<average number of characters of the dictionary words> top=<first word in frequency order>:<its frequency> ignored=<number of words in the ignore list> rules=<number of replacement rules> keyboard=<keyboard mode> limit=<limit L> suggestions=<suggestion count> undo=<number of records in the undo history>"
"SESSION checked=<checked> unknown=<unknown> case=<case> capital=<capital> repeats=<repeats> corrected=<corrected>"

[Output format]
- For each command, output only the lines described in [Processing]. Every command outputs at least one line.
- Words and values within a line are separated by a single space, as described. However, in CORRECT and FIX lines, the part after ": " is the processed text itself, and the spaces in it are exactly as in the text. Do not put spaces at the end of a line, and do not output blank lines. Every line ends with a newline.
- Integers are written in decimal without extra leading zeros. Decimals (rate and avglen of PROFILE, avglen of STATS) are rounded half up to the specified number of digits and written as the integer part (written as 0 when it is 0) and the fractional part with the specified number of digits, joined by . (examples: 0.0, 87.5, 4.00, 3.83).
- There are the following 13 kinds of error lines (the < > parts are replaced as described in [Processing]).
  ERROR UNKNOWN COMMAND <command name>
  ERROR BAD ARGUMENTS <command name>
  ERROR BAD WORD <argument>
  ERROR BAD NUMBER <argument>
  ERROR BAD MODE <mode>
  ERROR BAD OPTION <option>
  ERROR DUPLICATE <w>
  ERROR NOT FOUND <word>
  ERROR IN DICTIONARY <word>
  ERROR ALREADY IGNORED <w>
  ERROR NOT IGNORED <w>
  ERROR NO RULE <w>
  ERROR NOTHING TO UNDO

[Constraints]
- 1 <= M <= 300, 1 <= N <= 500.
- The number of dictionary words is always at least 1 and at most 500 (no command that would make the dictionary empty is given).
- The sum of the frequencies is always less than 2^31.
- The exact values (computed as fractions) of rate and avglen of PROFILE and avglen of STATS never lie exactly on a rounding boundary (where the part below the last written digit is exactly one half; for example, a value such as 3.125 for a value written to 2 decimal places).
