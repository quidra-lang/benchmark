[Overview]
Write a toolkit (working environment) for finite automata. The program reads commands from standard input one line at a time, executes them in order, and writes the results to standard output. Deterministic finite automata (DFA) and nondeterministic finite automata (NFA), which may contain epsilon transitions, can be defined under a name, and an NFA can also be built from a regular expression by Thompson's construction. For the defined automata, the program performs: deciding whether a string is accepted and showing the sequence of states, epsilon-closure, conversion to a DFA by the subset construction, removal of epsilon transitions, DFA minimization by removing unreachable states and by Moore's method (partition refinement), equivalence testing (showing the shortest distinguishing string), union, intersection and difference by the product construction, construction of the complement, reversal, concatenation and Kleene star, enumerating and counting accepted strings, deciding whether a language is empty and whether it is finite, a summary of properties, printing the transition table and the definition, searching for a synchronizing word, and listing and deleting automata. There are 26 kinds of commands. For a command with an error, the program prints one line of the form "error: reason" and proceeds to the next command.

[Input format]
The first line contains a positive integer N, followed by N lines. The input consists of exactly these N + 1 lines.
Each line from the second line on consists of one or more "words" separated by single spaces. There is no whitespace at the beginning or end of a line, and there are no empty lines. Words consist only of printable ASCII characters other than the space (character codes 33 to 126).
Among the lines from the second line on, a line whose first character is # is a "comment line". Every other line is called a "command line" and contains one command. The first word of a command line is called the "command name", and the remaining words are called, in order, the 1st argument, the 2nd argument, ...

The commands have the following 26 forms.

  DFA X state-list alphabet start-state accepting-state-list transitions...
  NFA X state-list alphabet start-state accepting-state-list transitions...
  REGEX X alphabet regular-expression
  ACCEPT X string
  CLOSURE X state-list
  TODFA X Y
  EPSFREE X Y
  MINIMIZE X Y
  EQUIV X Z
  UNION X Z Y
  INTERSECT X Z Y
  DIFF X Z Y
  COMPLEMENT X Y
  REVERSE X Y
  CONCAT X Z Y
  STAR X Y
  ENUM X k
  COUNT X n
  EMPTY X
  FINITE X
  INFO X
  TABLE X
  SHOW X
  SYNC X
  LIST
  DELETE X

X, Y and Z are automaton names. The "transitions..." of a DFA or NFA line is a sequence of zero or more words, each representing a transition. Each part is written as follows.
- Automaton name: one uppercase letter (A-Z) followed by 0 to 7 (inclusive) characters, each an uppercase letter or a digit (0-9).
- State name: a string of 1 to 8 (inclusive) characters consisting only of letters (A-Z, a-z) and digits.
- Symbol: one lowercase letter (a-z) other than e, or one digit. The lowercase letter e is not a symbol; it is used to denote epsilon (the empty string).
- Alphabet: a string of 1 to 10 (inclusive) mutually distinct symbols, in any order.
- State list: a string of one or more state names separated by ",".
- Accepting state list: either the single character "-", or a string of one or more state names separated by ",". "-" means that there are no accepting states.
- Transition: a string of the form "p:c:q", consisting of a state name p, one character c and a state name q in this order, separated by ":". c is a lowercase letter or a digit.
- String (the 2nd argument of ACCEPT): either the single character "e", or a string of 1 to 30 (inclusive) characters consisting only of lowercase letters and digits. The single character "e" denotes the empty string.
- Regular expression: a string of 1 to 40 (inclusive) characters consisting only of lowercase letters, digits, "|", "*", "+", "?", "(" and ")".
- k and n: a non-negative integer written in decimal without extra leading zeros.
The input also contains erroneous lines, such as unknown command names, wrong numbers of arguments, and references to nonexistent names, states or symbols. How they are handled is defined in [Processing]. However, on a line whose number of arguments matches the form (for DFA and NFA lines, a line with 5 or more arguments), every argument follows the rules above. Nothing beyond what is stated above is guaranteed (for example, that state names are not duplicated, or that the symbol of a transition is contained in the alphabet).

[Processing]
1. Overall flow
Process the N lines in order, starting from the 2nd line of the input. For a comment line, do nothing and print nothing. Process a command line by the procedure in section 3.
The program keeps an "automaton table". It is a list of (name, automaton) pairs in the order they were registered, and it is empty at the start. The table never contains the same name twice.
Below, a string enclosed in double quotes is a string that appears in the output exactly as written. However, a part enclosed in < and > inside it is replaced by the string described. <X>, <Y> and <Z> are the names of the respective automata.

2. Automata, strings and notation
(1) An automaton consists of the following.
- Kind: DFA or NFA.
- State sequence: a sequence of mutually distinct state names. Below, the states are considered to be ordered as in this sequence, and this order is called the "state order". The position of a state in the state sequence, counted 0, 1, 2, ... from the front, is called the "index" of that state.
- Alphabet Sigma: a set of symbols. The symbols are considered to be ordered by increasing character code, and this order is called the "symbol order" (digits come before lowercase letters).
- Start state: one of the states.
- Set of accepting states: a set of states. It may be empty.
- Set of transitions: a set of triples (p, c, q), where p is a state, c is a symbol of Sigma or e, and q is a state. It never contains the same triple twice. A transition whose c is e is called an "epsilon transition".
An automaton of kind DFA has no epsilon transitions and has exactly one transition of the form (p, c, q) for every state p and every symbol c of Sigma. This q is written delta(p, c).
(2) A "string" is a sequence of zero or more symbols of Sigma. When a string is printed, the empty string is written "e", and any other string is written as its symbols in sequence. The "shortlex order" of strings is the order in which the shorter string comes first, and, for strings of the same length, the symbols are compared from the front and the string whose first differing symbol comes earlier in the symbol order comes first. The first string of a set of strings in shortlex order is called the "smallest string" of that set.
(3) The "epsilon-closure" of a set of states S is the set of all states that belong to S or can be reached from them by following epsilon transitions one or more times. For a set of states S and a symbol c, the epsilon-closure of the set of all states q such that there is a transition (p, c, q) from some state p in S is called the "destination of S on c". The epsilon-closure of the set consisting only of the start state is called the "initial set".
For a string w = c1 c2 ... cm, let S0 be the initial set, and for i = 1, 2, ..., m in this order let Si be the destination of S(i-1) on ci. The automaton "accepts" w when Sm contains at least one accepting state. For the empty string, m = 0 and the decision is made by S0. The set of all strings accepted by an automaton is called the "language" of that automaton. If the kind is DFA, every Si consists of exactly one state.
(4) A set of states is written as the concatenation, in this order, of "{", the names of the states of the set in state order separated by ",", and "}". The empty set is "{}". This is called "set notation". Also, when a "list" of states is printed, the names of the states are written in state order separated by ","; if there are no states at all, "none" is written.
(5) The "summary line" of an automaton X is the following line.
  "<kind> <X>: alphabet=<a> states=<s> accepting=<f> transitions=<t>"
a is the string of the symbols of Sigma in symbol order, s is the number of states, f is the number of accepting states, and t is the number of transitions.
(6) A command that creates a new automaton (DFA, NFA, REGEX, TODFA, EPSFREE, MINIMIZE, UNION, INTERSECT, DIFF, COMPLEMENT, REVERSE, CONCAT, STAR) registers the created automaton under the given name at the end of the automaton table and prints its summary line. Depending on the command, "detail lines" follow. Every detail line begins with two spaces.
(7) A state sequence with "N-series names" is a sequence in which the states are named, in index order, N0, N1, N2, ... ("N" followed by the decimal representation of the index). Similarly, state sequences with D-series, M-series and P-series names are D0, D1, ..., M0, M1, ..., and P0, P1, ..., respectively.

3. Procedure for processing a command
A command line is processed by the following procedure. If an error is found at any point (including errors found by the checks defined in sections 4, 5 and 6), print the single line "error: <reason>" and finish processing that command. In that case the automaton table does not change. The error strings shown in double quotes in sections 4 to 6 are this <reason> part.
(1) If the command name is none of the 26 kinds in [Input format], the reason is "unknown command <command name>".
(2) If the command name is DFA or NFA, process it by the procedure in section 4; if it is REGEX, by the procedure in section 5. Steps (3) to (8) below are the procedure for the other 23 kinds of commands.
(3) The roles of the arguments of each command are defined as follows. A "reference" is the name of an automaton in the table, a "DFA reference" is the name of an automaton of kind DFA in the table, a "new name" is the name of an automaton about to be created, and "other" is any other argument.
  ACCEPT, CLOSURE, ENUM, COUNT: reference, other
  TODFA, EPSFREE, REVERSE, STAR: reference, new name
  MINIMIZE, COMPLEMENT: DFA reference, new name
  EQUIV: reference, reference
  UNION, INTERSECT, DIFF: DFA reference, DFA reference, new name
  CONCAT: reference, reference, new name
  EMPTY, FINITE, INFO, TABLE, SHOW, DELETE: reference
  SYNC: DFA reference
  LIST: none (0 arguments)
If the number of arguments differs from the number of these roles, the reason is "wrong number of arguments".
(4) Examine the arguments that are references or DFA references from left to right; if a name is not in the table, the reason is "unknown automaton <that name>".
(5) If the argument that is a new name is in the table, the reason is "<that name> already exists".
(6) Examine the arguments that are DFA references from left to right; if a name is that of an automaton of kind NFA, the reason is "<that name> is not a DFA".
(7) For a command with two arguments that are references or DFA references (EQUIV, UNION, INTERSECT, DIFF, CONCAT), if the alphabets of the two automata differ as sets, the reason is "alphabets differ".
(8) For ACCEPT and CLOSURE, perform the checks defined in section 6.
If there is no error, execute the command. In the descriptions below, the automaton of the 1st argument is X, the automaton of the 2nd argument of EQUIV, UNION, INTERSECT, DIFF and CONCAT is Z, and the new name is Y.

4. DFA and NFA
"DFA X ..." defines an automaton of kind DFA, and "NFA X ..." defines an automaton of kind NFA. Perform the following checks in this order and report the first error found.
(1) If there are fewer than 5 arguments: "wrong number of arguments".
(2) If X is in the table: "<X> already exists".
(3) Examine the state names of the state list from left to right; if a state name has the same state name to its left: "duplicate state <that state name>".
(4) If the start state is not in the state list: "unknown state <start state>".
(5) If the accepting state list is not "-", examine its state names one by one from left to right: if a state name is not in the state list, "unknown state <that state name>"; if the same state name appears to its left, "duplicate state <that state name>".
(6) Examine the transition words one by one from left to right. Writing a word as p:c:q, check the following in this order.
  - If p is not in the state list: "unknown state <p>".
  - If c is e and the kind is DFA: "epsilon transition in DFA".
  - If c is not e and is not contained in the alphabet: "unknown symbol <c>".
  - If q is not in the state list: "unknown state <q>".
  - If the same word (with p, c and q all the same) appears to its left: "duplicate transition <p:c:q>".
  - If the kind is DFA and a word with the same p and c appears to its left: "conflicting transition <p:c:q>".
  Here <p:c:q> is the word written as it is.
(7) If the kind is DFA, examine each state p of the state list in the order of the state list, and for each of them each symbol c of Sigma in symbol order; for the first pair for which there is no transition word with that p and c: "missing transition <p>:<c>".
If there is no error, create the automaton whose state sequence is in the order of the state list, whose Sigma is the set of the symbols of the alphabet, whose start state and set of accepting states are as specified, and whose set of transitions is the set of triples represented by the transition words; register it as X and print its summary line.

5. REGEX
"REGEX X alphabet regular-expression" builds an NFA from a regular expression. Perform the following checks in this order and report the first error found.
(1) If the number of arguments is not 3: "wrong number of arguments".
(2) If X is in the table: "<X> already exists".
(3) Examine the characters of the regular expression from left to right; if there is a character that is a lowercase letter or a digit, is not e, and is not contained in the alphabet: "unknown symbol <that character>".
(4) If the following parsing finds an error: "syntax error at <i>".

Parsing: number the characters of the regular expression 1, 2, 3, ... from the front; this number is called the "position". The parser advances through the regular expression one character at a time from the front. The first character not yet consumed is called the "next character". After all characters have been consumed, the next character is the "end", and its position is the number of characters of the regular expression plus 1. Parsing is done by reading one "alternation"; if, after reading it, the next character is not the end, it is an error. Each element is read as follows.
- Alternation: read one concatenation. Then, while the next character is "|", consume it and read another concatenation, repeatedly. If the concatenations read are T1, ..., Tk in order, the result is T1 if k = 1, and the alternation T1 | ... | Tk if k >= 2.
- Concatenation: read one factor. Then, while the next character is a lowercase letter, a digit or "(", read another factor, repeatedly. If the factors read are F1, ..., Fk in order, the result is F1 if k = 1, and the concatenation F1 ... Fk if k >= 2.
- Factor: read one atom and call it A. Then, while the next character is "*", "+" or "?", consume it and replace A by A*, A+ or A?, respectively, repeatedly. The final A is the result. For example, "a*?" is (a*)?.
- Atom: if the next character is a lowercase letter or a digit, consume it. That character is the result (e denotes the empty string). If the next character is "(", consume it and read one alternation. Then, if the next character is ")", consume it, and the alternation read inside the parentheses is the result. If it is not ")", it is an error. If the next character is anything else (one of "|", ")", "*", "+", "?" or the end), it is an error.
When an error is found, i is the position of the next character at that moment. Only the first error found is reported. For example, "a|" is an error at position 3 (the end), "()" at position 2, "(ab" at position 4, "ab)a" at position 3, "*a" at position 1, and "a||b" at position 3.

Construction: if there is no error, build an NFA from the parse result as follows. Each time a state is created, it is given the next index 0, 1, 2, ... in order of creation. For each element t of the parse result, build a part with two states, the entry s(t) and the exit f(t). A transition whose c is e is an epsilon transition.
- A symbol or the empty string c (c = e for the empty string): create states s and f in this order, and add the transition (s, c, f).
- Concatenation F1 ... Fk: build the parts of F1, ..., Fk in this order, and for i = 1, ..., k-1 add the transition (f(Fi), e, s(F(i+1))). The entry is s(F1) and the exit is f(Fk). No new states are created.
- Alternation T1 | ... | Tk: create a state s, build the parts of T1, ..., Tk in this order, and create a state f. For each i, add the transitions (s, e, s(Ti)) and (f(Ti), e, f).
- A*: create a state s, build the part of A, and create a state f. Add the transitions (s, e, s(A)), (f(A), e, f), (f(A), e, s(A)) and (s, e, f).
- A+: the same as A*, but the transition (s, e, f) is not added.
- A?: the same as A*, but the transition (f(A), e, s(A)) is not added.
The entry and exit of a symbol, an alternation, A*, A+ and A? are the states s and f created there. Build the part of the whole parse result, and register as X the automaton whose kind is NFA, whose state sequence has N-series names (indices in order of creation), whose Sigma is the set of the symbols of the alphabet, whose start state is the entry of the whole, whose only accepting state is the exit of the whole, and whose set of transitions is all the added transitions; then print its summary line. The entry of the whole is always N0.
For example, "a*b" is the concatenation (a*) b; N0 is created as s of a*, N1 and N2 as s and f of a, N3 as f of a*, and N4 and N5 as s and f of b. The transitions are the 7 transitions (N1, a, N2), (N0, e, N1), (N2, e, N3), (N2, e, N1), (N0, e, N3), (N4, b, N5), (N3, e, N4); the start state is N0 and the accepting state is N5.

6. ACCEPT and CLOSURE
"ACCEPT X string": let w be the empty string if the 2nd argument is "e", and otherwise the string of the 2nd argument. As the check of section 3 (8), examine the characters of w from left to right; if a character is not contained in Sigma, the error is "unknown symbol <that character>". If there is no error, for w = c1 ... cm compute S0, S1, ..., Sm of section 2 (3), and print the following line.
  "<verdict> <S0> -<c1>-> <S1> -<c2>-> <S2> ... -<cm>-> <Sm>"
The verdict is "ACCEPT" if X accepts w, and "REJECT" if it does not. <Si> is the name of the single state of Si if X is a DFA, and Si written in set notation if X is an NFA. The parts are separated by single spaces. If w is the empty string, the line is "<verdict> <S0>". For example, the output for a DFA looks like "REJECT q0 -a-> q1 -b-> q1", and the output for an NFA looks like "ACCEPT {p} -a-> {p,q}".
"CLOSURE X state-list": as the check of section 3 (8), examine the state names of the state list from left to right; if a state name is not a state of X, the error is "unknown state <that state name>". If there is no error, print on one line, in set notation, the epsilon-closure of the set of the states of the list (the same state name may appear two or more times).

7. TODFA and EPSFREE
"TODFA X Y" builds a DFA with the same language as X by the subset construction. Build a sequence T0, T1, ... of sets of states of X as follows. T0 is the initial set of X. For i = 0, 1, 2, ... in this order, examine each symbol c of Sigma in symbol order for Ti, and compute the destination U of Ti on c. If U is not equal to any set added to the sequence so far, append U to the end of the sequence. Finish when the last set of the sequence has been processed. The empty set is also treated as a set in the same way (if a destination is the empty set, the empty set is added to the sequence).
When the sequence is T0, ..., T(k-1), the DFA created has the state sequence with D-series names D0, ..., D(k-1) (Di corresponds to Ti), the same Sigma as X, the start state D0, as accepting states the Di corresponding to the Ti that contain an accepting state of X, and the transitions (Di, c, Dj) where the destination of Ti on c is Tj. After the summary line, print the detail lines "  D<i> = <Ti>" for i = 0, ..., k-1 in this order. <Ti> is Ti written in set notation for the states of X.
"EPSFREE X Y" builds an NFA without epsilon transitions that has the same language as X. The state sequence, Sigma and start state are the same as those of X. The accepting states are the states whose singleton set has an epsilon-closure containing an accepting state of X. The transitions are, for each state p of X and each symbol c of Sigma, (p, c, q) for each state q contained in the destination on c of the epsilon-closure of {p}. The kind is NFA, and only the summary line is printed.

8. MINIMIZE
"MINIMIZE X Y" builds a DFA with the minimum number of states that has the same language as the DFA X.
(1) A state that can be reached from the start state of X by following transitions zero or more times is called "reachable". After the summary line, print the detail line "  unreachable: <list of the states that are not reachable>".
(2) A division of the set of all reachable states into some nonempty "blocks" is called a "partition". When a partition is printed, each block is written in set notation, and the blocks are listed separated by single spaces, in order of their first state (the first state in state order), earliest first.
The first partition P0 consists of two blocks: the block of the reachable states that are accepting states and the block of the reachable states that are not accepting states. However, a block that would be empty is omitted. Print the detail line "  round 0: <P0>".
For r = 1, 2, ... in this order, build the next partition Pr from P(r-1). Two reachable states p and q belong to the same block in Pr if and only if they belong to the same block in P(r-1) and, for every symbol c of Sigma, delta(p, c) and delta(q, c) belong to the same block in P(r-1). If the number of blocks of Pr equals the number of blocks of P(r-1), finish the refinement without printing Pr. Otherwise, print the detail line "  round <r>: <Pr>" and continue.
(3) Let P be P(r-1) at the moment the refinement finishes (the last partition printed). Name the blocks of P B0, B1, ... in the following order. The block containing the start state is B0. For i = 0, 1, 2, ... in this order, examine each symbol c of Sigma in symbol order for Bi; if the block containing delta(p, c) for a state p of Bi (it is the same block whichever state p of Bi is chosen) has no name yet, give it the name with the next number. Finish when the last named block has been processed (every block of P gets a name).
The DFA created has the state sequence with M-series names (Mi corresponds to Bi), the same Sigma as X, the start state M0, as accepting states the Mi corresponding to blocks consisting of accepting states, and the transitions (Mi, c, Mj) (where Bj is the block containing delta(p, c) for a state p of Bi). After the round lines, print the detail lines "  M<i> = <Bi>" in order of i. <Bi> is Bi written in set notation.

9. EQUIV, UNION, INTERSECT, DIFF, COMPLEMENT
"EQUIV X Z": if the language of X and the language of Z are equal, print "EQUIVALENT". Otherwise, let w be the smallest string of the set of strings accepted by exactly one of X and Z, and print "NOT EQUIVALENT: <w> is accepted only by <W>". W is the name of whichever of X and Z accepts w. X and Z may be the same name.
"UNION X Z Y", "INTERSECT X Z Y", "DIFF X Z Y": build a DFA by the product construction. Build a sequence R0, R1, ... of pairs of a state of X and a state of Z as follows. R0 is (start state of X, start state of Z). For i = 0, 1, 2, ... in this order, examine each symbol c of Sigma in symbol order for Ri = (p, q); if the pair (deltaX(p, c), deltaZ(q, c)) is not equal to any pair added to the sequence so far, append it to the end of the sequence (deltaX and deltaZ are delta of X and of Z, respectively). Finish when the last pair of the sequence has been processed.
The DFA created has the state sequence with P-series names (Pi corresponds to Ri), the same Sigma as X, the start state P0, and, for Ri = (p, q) and a symbol c, the transition (Pi, c, Pj) (where Rj = (deltaX(p, c), deltaZ(q, c))). The Pi corresponding to Ri = (p, q) is an accepting state: for UNION, when at least one of p and q is an accepting state; for INTERSECT, when both p and q are accepting states; for DIFF, when p is an accepting state and q is not an accepting state. After the summary line, print the detail lines "  P<i> = (<p>,<q>)" in order of i. <p> and <q> are the names of the two states of Ri.
"COMPLEMENT X Y": build the DFA whose state sequence, Sigma, start state and set of transitions are the same as those of X, and whose accepting states are all the states that are not accepting states of X. Only the summary line is printed.

10. REVERSE, CONCAT, STAR
These commands create an automaton of kind NFA and print only the summary line. Sigma is the same as that of X. Each state sequence has N-series names, and the states of X and Z are mapped to states determined as follows. Below, the state to which a state p is mapped is written p', and the mapped version of a transition (p, c, q) means (p', c, q').
"REVERSE X Y": let m be the number of states of X; the state sequence is N0, ..., Nm, and the state of X with index i is mapped to N(i+1). N0 is a new state. The transitions are (q', c, p'), the reversed direction of each transition (p, c, q) of X, and (N0, e, p') for each accepting state p of X. The start state is N0, and the only accepting state is s', which corresponds to the start state s of X.
"CONCAT X Z Y": let m be the number of states of X and n the number of states of Z; the state sequence is N0, ..., N(m+n-1), the state of X with index i is mapped to Ni, and the state of Z with index j is mapped to N(m+j). The transitions are the mapped versions of each transition of X and each transition of Z, and (p', e, s') for each accepting state p of X (s is the start state of Z). The start state is the state corresponding to the start state of X, and the accepting states are all the states corresponding to the accepting states of Z.
"STAR X Y": let m be the number of states of X; the state sequence is N0, ..., Nm, and the state of X with index i is mapped to N(i+1). N0 is a new state. The transitions are the mapped versions of each transition of X, (N0, e, s'), and (p', e, s') for each accepting state p of X (s is the start state of X). However, a transition whose triple is already present is not added again. The start state is N0, and the accepting states are N0 and all the states corresponding to the accepting states of X.

11. ENUM, COUNT, EMPTY, FINITE, SYNC
"ENUM X k": let t be the number of strings of length k or less accepted by X. Print one line consisting of "<t>", followed by the first min(t, 50) of those strings in shortlex order, each preceded by a single space, and, if t is greater than 50, finally followed by " ..." (one space and three periods). If t = 0, the line is just "0".
"COUNT X n": print on one line the number of strings of length exactly n accepted by X.
"EMPTY X": print "EMPTY" if the language of X is the empty set, and otherwise "NOT EMPTY <w>". w is the smallest string of the set of strings accepted by X.
"FINITE X": print "INFINITE" if the language of X is an infinite set, and "FINITE <t>" if it is a finite set. t is the number of strings in the language (0 if the language is the empty set).
"SYNC X": for a state p of the DFA X and a string w = c1 ... cm, write p.w for the state obtained by starting from p and applying delta with c1, ..., cm in this order (if w is the empty string, p.w = p). When p.w is the same single state q for every state p of X (including states that are not reachable), w is called a "synchronizing word". If a synchronizing word exists, print "SYNCHRONIZING <w> -> <q>" for the smallest string w of the set of synchronizing words and the corresponding q; if no synchronizing word exists, print "NOT SYNCHRONIZING". For a DFA with one state, the empty string is a synchronizing word.

12. INFO, TABLE, SHOW, LIST, DELETE
"INFO X": print the following 8 lines in this order.
  the summary line of X
  "  epsilon transitions: <number of epsilon transitions>"
  "  reachable: <list of the states that can be reached from the start state by following transitions (including epsilon transitions) zero or more times>"
  "  live: <list of the states from which an accepting state can be reached by following transitions (including epsilon transitions) zero or more times>"
  "  deterministic: <yes or no>"
  "  complete: <yes or no>"
  "  language: <one of empty, finite, infinite>"
  "  minimal DFA states: <m>"
deterministic is yes if there are no epsilon transitions and, for every state p and every symbol c of Sigma, there is at most one transition of the form (p, c, q); otherwise it is no. complete is yes if, for every state p and every symbol c of Sigma, there is at least one transition of the form (p, c, q); otherwise it is no. language is empty if the language is the empty set, finite if it is a nonempty finite set, and infinite if it is an infinite set. m is the number of states of the DFA obtained by applying MINIMIZE to the DFA obtained by applying TODFA to X (it equals the minimum number of states of a DFA that accepts the language of X).
"TABLE X": print the transition table. The columns of the table are the first column and one column per symbol of Sigma in symbol order; if X is an NFA with at least one epsilon transition, an e column is added at the end. The rows of the table are the header row and one row per state of X in state order. The string of each cell is as follows.
- Header row: the first column is the empty string, a symbol column is that symbol, and the e column is "e".
- Row of state p: the first column is the concatenation, in this order, of "->" if p is the start state and otherwise two spaces, then "*" if p is an accepting state and otherwise one space, then the name of p. The column of c, where c is a symbol or e, is the name of delta(p, c) if X is a DFA. If X is an NFA, it is the set of states q for which there is a transition (p, c, q), written in set notation, or "-" if there is no such q.
The width of each column is the maximum length of the cell strings in that column. Each row is formed by padding each cell string on the right with spaces to the width of its column, joining them with two spaces as separators, and removing all trailing spaces.
"SHOW X": print X on one line in the form of a DFA or NFA command line that would redefine X under the same name. That is, list the following words separated by single spaces: the kind ("DFA" or "NFA"), the name of X, the names of the states in state order separated by ",", the symbols of Sigma in symbol order, the name of the start state, the names of the accepting states in state order separated by "," ("-" if there are no accepting states), and then a word "<p>:<c>:<q>" (p and q are state names) for each transition (p, c, q). The transition words are ordered by p in state order; those with the same p by c (in the order of the symbols of Sigma in symbol order, followed by e); and those with the same c as well by q in state order. If there are no transitions, the line ends with the accepting-states word.
"LIST": print the summary lines of all automata registered in the table, in the order of registration. If the table is empty, print "(none)".
"DELETE X": remove X from the table and print "deleted <X>". A removed name can later be used as the name of a new automaton (that automaton is registered at the end of the table).

[Output format]
- Print the lines defined in [Processing] in the order of the input lines. When one command line prints several lines, print them in the order defined in [Processing].
- A comment line prints nothing. A command line with an error prints only one line beginning with "error: ", and a command line without an error prints one or more lines.
- All output consists of ASCII characters, and every line ends with LF. No line has trailing whitespace, and no empty lines are printed.

[Constraints]
- 1 <= N <= 500. Each line has at most 1000 characters.
- The state list of a DFA or NFA line contains at most 30 state names.
- Every automaton registered in the automaton table has at most 200 states.
- For every automaton referenced by a command line without an error, the DFA obtained by applying TODFA to it has at most 200 states.
- For ENUM X k, k <= 30 and |Sigma|^k <= 10000; for COUNT X n, n <= 60 and |Sigma|^n <= 10^15. Here |Sigma| is the number of symbols of the alphabet of X.
- For FINITE X, |Sigma|^m <= 10^15, where m is the number of states of X.
- For SYNC X, X has at most 10 states.
- By these, every integer printed is at most 10^15. Also, since the number of strings of length L is at most |Sigma|^L, the intermediate counts that appear when counting, length by length, the strings of length n or less for COUNT and the strings of length less than m for FINITE are also at most 10^15.

[Example]
Input:
10
# strings over a and b that end with ab
NFA N p,q,r ab p r p:a:p p:b:p p:a:q q:b:r
ACCEPT N aab
TODFA N D
MINIMIZE D M
TABLE M
ENUM M 3
REGEX R ab a*b
SHOW R
SYNC N

Output:
NFA N: alphabet=ab states=3 accepting=1 transitions=4
ACCEPT {p} -a-> {p,q} -a-> {p,q} -b-> {p,r}
DFA D: alphabet=ab states=3 accepting=1 transitions=6
  D0 = {p}
  D1 = {p,q}
  D2 = {p,r}
DFA M: alphabet=ab states=3 accepting=1 transitions=6
  unreachable: none
  round 0: {D0,D1} {D2}
  round 1: {D0} {D1} {D2}
  M0 = {D0}
  M1 = {D1}
  M2 = {D2}
       a   b
-> M0  M1  M0
   M1  M1  M2
  *M2  M1  M0
3 ab aab bab
NFA R: alphabet=ab states=6 accepting=1 transitions=7
NFA R N0,N1,N2,N3,N4,N5 ab N0 N5 N0:e:N1 N0:e:N3 N1:a:N2 N2:e:N1 N2:e:N3 N3:e:N4 N4:b:N5
error: N is not a DFA

N is an NFA that accepts the strings over a and b that end with ab. In TODFA, the destinations are computed from the initial set {p} on a and then on b, and {p,q} and {p,r} are added to the sequence. In MINIMIZE, after P0 = {D0,D1} {D2}, D0 and D1 are split because their destinations on b (D0 and D2) belong to different blocks in P0, and P1 has 3 blocks. P2 also has 3 blocks, so the refinement finishes without printing P2. REGEX a*b yields exactly the NFA of the example in section 5. SYNC can only be used on a DFA, so it is an error for N.
