[Overview]
Write a program that implements an arithmetic unit for floating-point formats with a small number of bits (small floating-point formats) that follow the same rules as IEEE 754 binary floating-point numbers. The program reads a sequence of commands from standard input; it defines formats, encodes numbers and decodes bit strings, performs the four arithmetic operations, square root and fused multiply-add (FMA) with a specified rounding mode, converts between formats, compares, computes neighboring values and the ULP, converts to integers, prints a table of values, and analyzes the error of sequential summation, compensated summation (Kahan's method) and dot products, and writes the results to standard output.
Every operation first determines the exact (real) value of the result and then rounds it only once with the specified rounding mode. Since the values of a format can be represented exactly with integers (a sign, an integer significand and a power-of-two exponent), the program must not use floating-point numbers; process everything with integer arithmetic only.

[Input format]
The first line contains the number of commands N. Each of the following N lines contains one command. The input consists of exactly these N+1 lines. Each command consists of a command name and zero or more arguments, separated by single spaces; there are no spaces at the beginning or end of a line, and there are no empty lines. There are 19 command formats, as follows ([mode] is an optional argument).

  FORMAT name e m
  ENCODE f v [mode]
  DECODE f a
  ADD f a b [mode]
  SUB f a b [mode]
  MUL f a b [mode]
  DIV f a b [mode]
  SQRT f a [mode]
  FMA f a b c [mode]
  CONVERT f g a [mode]
  COMPARE f a b
  NEXTUP f a
  NEXTDOWN f a
  ULP f a
  TOINT f a type [mode]
  TABLE f
  SUM f mode a1 a2 ... ak
  KAHAN f mode a1 a2 ... ak
  DOT f mode a1 a2 ... ak | b1 b2 ... bj

The arguments mean the following.
- name, f and g are format names. A format name is one uppercase letter (A to Z) followed by zero or more uppercase letters or digits (0 to 9).
- e and m are non-negative integers written in decimal notation without extra leading zeros.
- mode is a string of three uppercase letters representing a rounding mode, and type is a string of uppercase letters and digits representing an integer type. Their valid values are defined in [Processing].
- v, a, b, c, a1 to ak and b1 to bj are "operands". Each operand is written in one of the following five forms.
  Bit form: "0b" followed by one or more of the digits 0 and 1 (example: 0b0011110000000000).
  Hex form: "0x" followed by one or more digits and uppercase letters A to F (example: 0x3C00).
  Special value: one of inf, -inf, nan.
  Fraction: of the form p/q, or the same preceded by a single "-" (examples: 1/3, -2047/2048). p and q are non-negative integers written in decimal notation without extra leading zeros.
  Decimal: an integer part alone, or an integer part, "." and a fractional part in this order, or either of these preceded by a single "-" (examples: 7, 0.1, -0.0, 3.1415927). The integer part is a non-negative integer written in decimal notation without extra leading zeros, and the fractional part is a sequence of one or more digits.
  The form of an operand is determined as follows: if it starts with "0b" it is the bit form, if it starts with "0x" it is the hex form, if it is one of inf, -inf, nan it is a special value, if it contains "/" it is a fraction, and otherwise it is a decimal.
- The "|" of DOT is an argument consisting of a single ASCII vertical bar character. A DOT line contains exactly one such argument, with one or more operands both before it and after it.
- k and j are symbols denoting the numbers of listed operands; they are not written in the input.
The number of arguments always matches the formats above, and every line is guaranteed to follow these formats and [Constraints] (whether the argument values are valid is checked as described in [Processing]).

[Processing]
Process the commands in order starting from the first one, and output the result of each command according to [Output format]. A format added by FORMAT can be used in the subsequent commands. Apart from this, no command affects any later command.

== Formats ==
A format is determined by the pair of the number of exponent bits e and the number of fraction bits m, and formats are distinguished by their names. For a format, define w=1+e+m (the number of bits of a pattern), bias=2^(e-1)-1, emin=1-bias and emax=bias.
The following three formats (built-in formats) exist from the start, and formats can be added with the FORMAT command.
  HALF: e=5, m=10
  E5M2: e=5, m=2
  E4M3: e=4, m=3
Every format follows the rules of this statement (E4M3 also has infinities and NaNs exactly according to the rules below, and its largest finite value is 240).

== Patterns and values ==
A value of a format is represented by a w-bit "pattern". A pattern is identified with an integer that is at least 0 and less than 2^w; its w-digit binary representation is split, starting from the most significant digit, into the sign bit s (1 bit), the exponent field E (e bits) and the fraction field F (m bits). That is, for a pattern p, s=floor(p/2^(e+m)), E=floor(p/2^m) mod 2^e and F=p mod 2^m. A pattern represents the following.
- E=2^e-1 and F=0: an infinity. It is +infinity if s=0 and -infinity if s=1.
- E=2^e-1 and F!=0: a NaN (not a number). If F>=2^(m-1) (the most significant bit of F is 1), it is a "quiet NaN"; otherwise it is a "signaling NaN".
- E=0 and F=0: a zero. It is +0 if s=0 and -0 if s=1.
- E=0 and F!=0: a subnormal number.
- Otherwise: a normal number.
Zeros, subnormal numbers and normal numbers are called "finite values". For a finite value, define the "integer significand" M and the "exponent" Q as M=2^m+F and Q=E-bias-m for a normal number, and M=F and Q=emin-m for a zero or a subnormal number. The number represented by a finite value is (-1)^s*M*2^Q (+0 and -0 are both the number 0).
The following terms are used.
- "Standard NaN": the pattern with s=0, E=2^e-1 and F=2^(m-1). Whenever a result is a NaN, this pattern is always used.
- "Largest finite value": the pattern with s=0, E=2^e-2 and F=2^m-1 (it is 65504 in HALF).
- "Zero of sign s", "infinity of sign s": the zero pattern and the infinity pattern, respectively, whose sign bit is s.
- To "flip the sign" of a pattern means to change its sign bit s to 1-s (this is done in the same way for a NaN).

== Operands ==
Each operand represents one pattern of a certain format. That format is f for CONVERT, and the command's f for every other command. The meaning and the validity condition of each form are as follows.
- Bit form: the pattern whose value is the digit sequence after "0b" read as a binary number. It is invalid if the number of digits is not w.
- Hex form: the pattern whose value is the sequence after "0x" read as a hexadecimal number. It is invalid if the number of digits is not ceil(w/4) (w divided by 4, rounded up), or if the value is 2^w or more.
- Special value: inf is the pattern of +infinity, -inf the pattern of -infinity, and nan the pattern of the standard NaN.
- Fraction: the pattern obtained by rounding the exact value of p/q, multiplied by -1 if there is a "-", with rounding mode RNE by the method of the "Rounding" section. It is invalid if q=0.
- Decimal: the pattern obtained by rounding the exact value of the written decimal number, multiplied by -1 if there is a "-", with rounding mode RNE by the method of the "Rounding" section.
When the value of a fraction or a decimal is exactly 0, it is not rounded; it is -0 if there is a "-" and +0 otherwise (examples: -0, -0.0 and -0/7 are -0). Even if the command specifies a rounding mode, operands are always rounded with RNE, and the flags raised by this rounding are discarded (they are not included in the flags of the command's result).
However, for v of ENCODE, the bit form and the hex form are invalid, and the value of v is rounded as described for ENCODE.
Except for v of ENCODE, the operands (a, b, c, a1, and so on) in the descriptions below refer not to the values of the written strings but to the patterns obtained in this way (and to the numbers those patterns represent).

== Flags ==
For the result of an operation, it is determined, for each of the following five "flags", whether the flag is raised or not. In every command, only the flags that this statement says to raise are raised.
  invalid (invalid operation), divbyzero (division by zero), overflow (overflow), underflow (underflow), inexact (inexact result)
To "combine" the flags of several operations means to form the set of flags in which every flag raised by any of those operations is raised.

== Rounding ==
There are five rounding modes:
  RNE: round to the nearest value. If exactly halfway, choose the one whose integer significand is even.
  RNA: round to the nearest value. If exactly halfway, choose the one farther from 0.
  RTZ: round toward 0.
  RUP: round toward +infinity.
  RDN: round toward -infinity.
When the optional mode is omitted, rounding mode RNE is used, and RNE is written for <mode> in the output.
The result (pattern and flags) of rounding a nonzero real number x to a format is obtained by the following procedure. Let s=0 if x is positive and s=1 if x is negative, and let a be the absolute value of x.
(1) Find the integer t satisfying 2^t<=a<2^(t+1). If t>emax, it is an "overflow"; go to (6).
(2) Let q=max(t,emin)-m, and let N be the integer part and r (0<=r<1) the fractional part of a/2^q.
(3) If the following condition for the rounding mode holds, add 1 to N.
  RNE: r>1/2, or r=1/2 and N is odd.
  RNA: r>=1/2.
  RTZ: this condition never holds.
  RUP: r>0 and s=0.
  RDN: r>0 and s=1.
(4) If N has become 2^(m+1), change N to 2^m and add 1 to q. If as a result q>emax-m, it is an "overflow"; go to (6).
(5) The result is the pattern whose sign bit is s and which has E=q+m+bias and F=N-2^m if N>=2^m, or E=0 and F=N if N<2^m (if N=0, it is the zero of sign s). The number this pattern represents is (-1)^s*N*2^q. The flags are raised as follows.
  - If r>0, raise inexact.
  - If r>0, a<2^emin, and moreover the value of the "rounding with an unbounded exponent range" is also less than 2^emin, raise underflow. The value of the "rounding with an unbounded exponent range" is N*2^(t-m), where N is obtained by performing (2) and (3) with q in (2) replaced by q=t-m. If t<emin-1, this value is always less than 2^emin.
(6) In the case of an overflow, raise overflow and inexact, and the result pattern is as follows.
  RNE and RNA: the infinity of sign s.
  RTZ: the largest finite value if s=0, and the largest finite value with its sign flipped if s=1.
  RUP: +infinity if s=0, and the largest finite value with its sign flipped if s=1.
  RDN: the largest finite value if s=0, and -infinity if s=1.
For example, in HALF, x=2049 becomes 2048 (N=1024) with RNE and 2050 with RNA and RUP, and inexact is raised. x=65520 overflows in (4) with RNE and becomes +infinity, and becomes 65504 with RTZ (with RTZ it is not an overflow).

== When a sum is exactly 0 ==
In the operations ADD, SUB and FMA, and in ROUNDED of SUM and KAHAN and FUSED of DOT, the exact sum of several "terms" is rounded. When that sum is exactly 0, the rounding procedure is not used and no flags are raised; the result is the following zero.
- If all terms are zeros of the same sign (all +0, or all -0), the zero of that sign.
- Otherwise, -0 if the rounding mode is RDN, and +0 for any other rounding mode.
The sign of a term that is zero is its sign bit for an operand, and the exclusive OR of the sign bits of a and b (1 if they differ, 0 if they are equal) for a product a*b (when at least one of a and b is zero).

== NaN rule ==
"Apply the NaN rule" in the description of a command means the following. If any of the operands is a NaN, the result is the standard NaN, invalid is raised if any of the operands is a signaling NaN, and the other rules of that command are not used. If no operand is a NaN, proceed to the next rule.

== Notations ==
- Bit notation: the s, E and F of the pattern written as binary numbers of 1, e and m digits respectively (padded with leading zeros), placed in this order and separated by "|". For example, 1 in HALF is 0|01111|0000000000.
- Hex notation: "0x" followed by the pattern written as a hexadecimal number of ceil(w/4) digits (uppercase letters A to F, padded with leading zeros). For example, 1 in HALF is 0x3C00, and pattern 9 of a format with w=4 is 0x9.
- Decimal notation: an exact representation of a rational number v whose denominator is a power of 2, written as follows. If v is negative, write "-" first; then write the integer part of |v| as a decimal number without extra leading zeros (0 if |v| is less than 1); and if the fractional part of |v| is not 0, write "." followed by the digits of the fractional part without trailing zeros. Since the denominator is a power of 2, the fractional part ends after a finite number of digits (examples: 1.5, -0.000000059604644775390625, 65504, 0).
- Value notation: inf if the pattern is +infinity, -inf if it is -infinity, and nan if it is a NaN. For a finite value, write "-" first if s=1 (-0 is written as -0), followed by the decimal notation of the absolute value of the number, M*2^Q.
- Fraction notation: the absolute value of a rational number expressed as an irreducible fraction p/q (p>=0, q>=1), written as p if q=1 and as p/q otherwise. A negative number is preceded by "-", and 0 is written as 0.
- Flag notation: "flags=" followed by the names of the raised flags in the order invalid, divbyzero, overflow, underflow, inexact, separated by "," (an ASCII comma). If no flag is raised, it is flags=none.
- Pattern notation: "<bit notation> <hex notation> <value notation>".
- Result notation: for the pattern and the flags of a result, "<pattern notation> <flag notation>".

== Error checks ==
For each command, first examine the arguments from left to right; if one of the following errors is found, output only the error line of the first error found and do nothing else for that command (no format is added either).
- A format name f or g is not the name of any format that exists at that point: "ERROR UNKNOWN FORMAT <format name>" (the name of FORMAT is not checked here).
- mode is not one of RNE, RNA, RTZ, RUP, RDN: "ERROR BAD MODE <mode>".
- type is not one of I8, U8, I16, U16, I32, U32: "ERROR BAD TYPE <type>".
- An operand is invalid under the conditions of the "Operands" section: "ERROR BAD OPERAND <operand>".
If the arguments contain no error, perform the "Check" items in the description of each command in the order written, and if one of them applies, likewise output only its error line. In the < > parts of an error line, put the string exactly as written in the input.

== Commands ==

FORMAT name e m
Check: if a format named name already exists (including the built-in formats), "ERROR FORMAT EXISTS <name>". If e is not between 2 and 5 inclusive, or m is not between 1 and 10 inclusive, "ERROR BAD FORMAT".
Processing: add a format with e exponent bits and m fraction bits under the name name, and output "FORMAT <name> e=<e> m=<m> bits=<w> bias=<bias> emin=<emin> emax=<emax>".

ENCODE f v [mode]
Processing: if v is nan, the result is the standard NaN; if it is inf, +infinity; if it is -inf, -infinity; if v is a fraction or a decimal whose value is 0, the signed zero determined as in the "Operands" section; in these cases no flags are raised. Otherwise, the result is the exact value of v rounded with mode. Output "ENCODE <f> <mode> <value of v> <result notation>". <value of v> is the string itself (nan, inf, -inf) if v is a special value, and the fraction notation of the exact value of v if v is a fraction or a decimal.

DECODE f a
Processing: the class of the pattern p of a is zero for a zero, subnormal for a subnormal number, normal for a normal number, infinity for an infinity, qnan for a quiet NaN and snan for a signaling NaN. First output "DECODE <f> <bit notation of p> <hex notation of p> <class> sign=<s>", and then output the following lines.
- If p is a finite value, the two lines "FIELDS exponent=<E> fraction=<F> unbiased=<Q+m> significand=<binary significand>" and "VALUE <fraction notation of the number represented by p> <value notation of p>". The binary significand is "1" for a normal number, or "0" for a zero or a subnormal number, followed by "." and F written as an m-digit binary number (padded with leading zeros).
- If p is an infinity, the one line "FIELDS exponent=<E> fraction=<F>".
- If p is a NaN, the one line "FIELDS exponent=<E> fraction=<F> payload=<F mod 2^(m-1)>".
E, F and Q+m are integers in decimal notation (negative numbers have a "-").

== Arithmetic commands (ADD, SUB, MUL, DIV, SQRT, FMA) ==
Determine the result (pattern and flags) by the following rules, and output "<command name> <f> <mode> <result notation>". Below, sigma is the exclusive OR of the sign bits of a and b.

ADD f a b [mode]
Apply the NaN rule. If a and b are infinities of different signs, the result is the standard NaN, with invalid raised. Otherwise, if a is an infinity the result is a, and if b is an infinity the result is b (no flags). If both a and b are finite values, round the exact sum a+b, with a and b as the terms.

SUB f a b [mode]
Let b' be b with its sign flipped, and determine the result by the same rules as ADD f a b'.

MUL f a b [mode]
Apply the NaN rule. When at least one of a and b is an infinity: if at least one of a and b is zero, the result is the standard NaN, with invalid raised; otherwise the result is the infinity of sign sigma. If both a and b are finite values and at least one of them is zero, the result is the zero of sign sigma. Otherwise, round the exact product a*b.

DIV f a b [mode]
Apply the NaN rule. Then determine the result by the first of the following cases that applies.
- a is an infinity: if b is also an infinity, the standard NaN with invalid; otherwise the infinity of sign sigma.
- b is an infinity: the zero of sign sigma.
- b is zero: if a is also zero, the standard NaN with invalid; otherwise the infinity of sign sigma, with divbyzero raised.
- a is zero: the zero of sign sigma.
- Otherwise: round the exact quotient a/b.

SQRT f a [mode]
Apply the NaN rule. If a is zero, the result is a (+0 for +0, -0 for -0). Otherwise, if the sign bit of a is 1 (a negative number or -infinity), the result is the standard NaN, with invalid raised. If a is +infinity, the result is +infinity. Otherwise, round the exact square root sqrt(a) (sqrt(a) may be irrational, but the procedure of the "Rounding" section can still be used as it is).

FMA f a b c [mode]
Apply the NaN rule to a, b and c. When at least one of a and b is an infinity: if at least one of a and b is zero, or c is an infinity whose sign bit differs from sigma, the result is the standard NaN, with invalid raised; otherwise the result is the infinity of sign sigma. Otherwise, if c is an infinity, the result is c. Otherwise, round the exact value a*b+c only once, with the product a*b (its exact value, not rounded in between) and c as the terms.

== Other commands ==

CONVERT f g a [mode]
a is a pattern of format f. If a is a NaN, the result is the standard NaN of format g, and invalid is raised if a is a signaling NaN. If a is an infinity, the result is the infinity of format g with the same sign, and if a is a zero, the zero of format g with the same sign (no flags). Otherwise, round the number represented by a to format g. Output "CONVERT <f> <g> <mode> <result notation>" (the result notation is that of format g).

COMPARE f a b
If at least one of a and b is a signaling NaN, raise invalid. The relation R is UN if at least one of a and b is a NaN; otherwise compare a and b as numbers (+0 and -0 are equal, -infinity is less than every other number, and +infinity is greater than every other number), and R is LT if a is smaller, EQ if they are equal, and GT if a is greater. Also, define the "order key" of a pattern p as p if the sign bit of p is 0, and -(p-2^(w-1))-1 if it is 1; compare the key of a with the key of b, and let T be LT if the key of a is smaller, EQ if they are equal, and GT if it is greater. Output "COMPARE <f> <hex notation of a> <hex notation of b> <R> total=<T> <flag notation>".

NEXTUP f a
Apply the NaN rule. If a is +infinity, the result is +infinity, and if a is zero (+0 or -0), the result is pattern 1 (the smallest positive subnormal number). Otherwise, the result is a+1 (as a pattern integer) if the sign bit of a is 0, and a-1 if it is 1. Output "NEXTUP <f> <result notation>".

NEXTDOWN f a
Apply the NaN rule. Otherwise, apply the same rules as NEXTUP to a with its sign flipped, and the result is the obtained pattern with its sign flipped. Output "NEXTDOWN <f> <result notation>".

ULP f a
Apply the NaN rule. If a is an infinity, the result is +infinity. If a is a finite value, the result is the pattern with sign bit 0 that represents the number 2^Q, where Q is the exponent of a (such a pattern always exists). Output "ULP <f> <result notation>".
In NEXTUP, NEXTDOWN and ULP, no flags are raised other than those raised by the NaN rule.

TOINT f a type [mode]
The range of each type is: I8 from -128 to 127, U8 from 0 to 255, I16 from -32768 to 32767, U16 from 0 to 65535, I32 from -2147483648 to 2147483647, and U32 from 0 to 4294967295 (all inclusive).
If a is a NaN or an infinity, the conversion is "invalid". If a is a finite value, let K be the integer part and r the fractional part of the absolute value of the number represented by a; if the condition of step (3) of the "Rounding" section holds (reading N as K and s as the sign bit of a), add 1 to K; then let z=(-1)^s*K. If z is not within the range of type, the conversion is "invalid".
If it is invalid, output "TOINT <f> <type> <mode> invalid flags=invalid". Otherwise output "TOINT <f> <type> <mode> <z> <flag notation>". z is an integer in decimal notation (0 is written as 0, and negative numbers have a "-"), and the only flag raised is inexact, which is raised if r>0.

TABLE f
Check: if w>8, "ERROR TABLE TOO LARGE".
Processing: let c=(2^e-1)*2^m. The patterns 0, 1, ..., c-1 are all of the non-negative finite values, and the numbers they represent increase in this order. Output "TABLE <f> count=<c>", and then, for i=0, 1, ..., c-1 in this order, output "ENTRY <i> <pattern notation of pattern i> gap=<difference>". The difference is the decimal notation of the number represented by pattern i+1 minus the number represented by pattern i if i<c-1, and "-" (an ASCII hyphen) if i=c-1. Then output the following five lines.
  "MAX <pattern notation of the largest finite value>"
  "MINNORMAL <pattern notation of pattern 2^m>"
  "MINSUBNORMAL <pattern notation of pattern 1>"
  "EPSILON <decimal notation of 2^(-m)>"
  "PATTERNS finite=<2c> infinite=2 nan=<2*(2^m-1)> total=<2^w>"

== Summation analysis (SUM, KAHAN, DOT) ==
These three commands use the rounding mode mode for all operations. Below, ADD(x,y), SUB(x,y), MUL(x,y) and FMA(x,y,z) denote the result (pattern and flags) obtained by the same rules as the respective commands, with format f and rounding mode mode.
At the end of the output of SUM and KAHAN, output the following four lines (called the "summary"). Here P is the pattern of the computed result and U is the combined flags.
  "RESULT <pattern notation of P> <flag notation of U>"
  "EXACT <decimal notation of the exact value of a1+a2+...+ak>"
  "ROUNDED <result notation>": the result of rounding the exact sum a1+a2+...+ak, with a1, ..., ak as the terms, only once with mode (if the sum is 0, follow the "When a sum is exactly 0" section).
  "DIFF <error>": nan if P is a NaN, inf if P is +infinity, -inf if P is -infinity, and otherwise the fraction notation of "the number represented by P minus the exact sum".

SUM f mode a1 a2 ... ak
Check: if any of the operands is a NaN or an infinity, "ERROR NOT FINITE".
Processing: let S1=a1, and compute Si=ADD(S(i-1),ai) for i=2, ..., k in this order. Output "SUM <f> <mode> count=<k>", and then, for i=2, ..., k in this order, output "PARTIAL <i> <result notation of Si>" (the flags are those of that ADD). Then output the summary with P=Sk and U=(the combined flags of all ADDs). If k=1, there are no PARTIAL lines, and U has no flags raised.

KAHAN f mode a1 a2 ... ak
Check: if any of the operands is a NaN or an infinity, "ERROR NOT FINITE".
Processing: let S=a1 and C=+0, and for i=2, ..., k in this order, perform the following four operations in this order and then set S=T.
  Y=SUB(ai,C), T=ADD(S,Y), D=SUB(T,S), C=SUB(D,Y)
Output "KAHAN <f> <mode> count=<k>", and for each i=2, ..., k, after setting S=T, output "KSTEP <i> sum=<value notation of S> comp=<value notation of C> <flag notation>". The flags are the combined flags of the four operations for that i. Then output the summary with P=S and U=(the combined flags of all operations). If k=1, there are no KSTEP lines, and U has no flags raised.

DOT f mode a1 a2 ... ak | b1 b2 ... bj
Check: if k!=j, "ERROR LENGTH MISMATCH". If any of the operands is a NaN or an infinity, "ERROR NOT FINITE".
Processing: compute the dot product a1*b1+a2*b2+...+ak*bk in the following three ways.
  Sequential (NAIVE): let X1=MUL(a1,b1), and for i=2, ..., k in this order let Xi=ADD(X(i-1),MUL(ai,bi)). The result is Xk, and its flags are the combined flags of all MULs and ADDs.
  Chained (CHAINED): let Y1=MUL(a1,b1), and for i=2, ..., k in this order let Yi=FMA(ai,bi,Y(i-1)). The result is Yk, and its flags are the combined flags of the first MUL and all FMAs.
  Fused (FUSED): round the exact sum with a1*b1, ..., ak*bk (each an exact product) as the terms only once with mode (if the sum is 0, follow the "When a sum is exactly 0" section).
Output the following six lines. Each error is computed from the respective result and the exact sum in the same way as DIFF of the summary.
  "DOT <f> <mode> n=<k>"
  "NAIVE <result notation of the sequential result>"
  "CHAINED <result notation of the chained result>"
  "EXACT <decimal notation of the exact sum>"
  "FUSED <result notation of the fused result>"
  "DIFF naive=<error of the sequential result> chained=<error of the chained result>"

[Output format]
- For each command, output only the lines described in [Processing]. Every command outputs at least one line.
- Words and values within a line are separated by single spaces, as described. Do not put spaces at the beginning or end of a line, and do not output empty lines. Every line ends with a newline.
- Integers (including emin of FORMAT and the like) are written in decimal notation without extra leading zeros, and negative numbers are preceded by "-".
- There are the following nine kinds of error lines (the < > parts are replaced by the corresponding strings).
  ERROR UNKNOWN FORMAT <format name>
  ERROR BAD MODE <mode>
  ERROR BAD TYPE <type>
  ERROR BAD OPERAND <operand>
  ERROR FORMAT EXISTS <name>
  ERROR BAD FORMAT
  ERROR TABLE TOO LARGE
  ERROR LENGTH MISMATCH
  ERROR NOT FINITE

[Constraints]
- 1 <= N <= 500
- The length of a format name is between 1 and 8. At most 10 formats are added by FORMAT.
- e and m are between 0 and 99 inclusive.
- mode consists of three uppercase letters, and type is a string of 1 to 4 characters consisting of uppercase letters and digits.
- In the bit form there are 1 to 20 digits after "0b", and in the hex form there are 1 to 6 digits after "0x".
- p and q of a fraction are between 0 and 10^8 inclusive.
- A decimal has at most 8 significant digits (the length of the digit sequence obtained by concatenating the digits of the integer part and the fractional part and removing all leading zeros), and its fractional part has at most 10 digits.
- k of SUM and KAHAN is between 1 and 20, and k and j of DOT are between 1 and 10.
- Write each term whose exact sum is computed in FMA, SUM, KAHAN and DOT as (-1)^s*M*2^Q (for a product term x*y, M is the product of the M of x and the M of y, and Q is the sum of the Q of x and the Q of y), and let L be the minimum Q among the terms with M!=0. In the test data, the total of M*2^(Q-L) over all terms is less than 2^50.
- The test data is constructed so that every integer appearing in the computation has an absolute value less than 2^53 when exact values are handled in the form n*2^E/d (n and d positive integers, E an integer), step (2) of rounding is performed by integer division, the difference of two numbers (the DIFF error and the TABLE difference) is computed as the difference of integers aligned to the smaller of the two exponents, and the fractional part of a decimal notation is computed by digit-by-digit division (repeatedly multiplying the remainder by 10 and dividing by the denominator).

[Example]
Input:
10
FORMAT T4 2 1
ENCODE HALF 0.1
DECODE T4 0x9
ADD HALF 2048 1
ADD HALF 2048 1 RUP
DIV HALF 1 0
SQRT HALF -1
TOINT HALF -2.5 I8 RNA
SUM T4 RNE 0.5 0.5 1.5
ENCODE HALF 1 RXX

Output:
FORMAT T4 e=2 m=1 bits=4 bias=1 emin=0 emax=1
ENCODE HALF RNE 1/10 0|01011|1001100110 0x2E66 0.0999755859375 flags=inexact
DECODE T4 1|00|1 0x9 subnormal sign=1
FIELDS exponent=0 fraction=1 unbiased=0 significand=0.1
VALUE -1/2 -0.5
ADD HALF RNE 0|11010|0000000000 0x6800 2048 flags=inexact
ADD HALF RUP 0|11010|0000000001 0x6801 2050 flags=inexact
DIV HALF RNE 0|11111|0000000000 0x7C00 inf flags=divbyzero
SQRT HALF RNE 0|11111|1000000000 0x7E00 nan flags=invalid
TOINT HALF I8 RNA -3 flags=inexact
SUM T4 RNE count=3
PARTIAL 2 0|01|0 0x2 1 flags=none
PARTIAL 3 0|10|0 0x4 2 flags=inexact
RESULT 0|10|0 0x4 2 flags=inexact
EXACT 2.5
ROUNDED 0|10|0 0x4 2 flags=inexact

ERROR BAD MODE RXX

In the ENCODE of this example, 1/10 lies between the two adjacent HALF values 0.0999755859375 and 0.10003662109375, and since the former is closer, it is rounded to the former. The non-negative finite values of T4 (e=2, m=1) are the six values 0, 0.5, 1, 1.5, 2 and 3. In S3=ADD(S2,1.5) (S2=1) of SUM, the exact sum 2.5 lies exactly halfway between 2 and 3, so RNE rounds it to 2 (N=2), whose integer significand is even.
