[Overview]
Write a simulator of CPU scheduling for processes that include I/O. The program reads a sequence of commands from standard input, registers and modifies processes, simulates the execution of the processes tick by tick under nine scheduling algorithms (FCFS, SJF, SRTF, RR, PRIORITY, HRRN, EDF, LOTTERY, MLFQ), and writes Gantt charts, per-process metrics, averages, CPU utilization, event logs, the state at a given time, comparisons between algorithms and so on to standard output. Switching between processes (a context switch) takes time, and any number of I/O operations can run at the same time.

[Input format]
The first line contains the number of command lines N. Each of the following N lines contains one command. Each command consists of a command name and zero or more arguments, separated by single spaces, with no spaces at the beginning or end of the line. There are 18 command formats, as follows ("burst ..." means that one or more bursts follow, and "[param ...]" means that zero or more params follow).

  PROC id arrival priority burst ...
  GEN prefix count seed
  SETPRIO id p
  DEADLINE id d
  DROP id
  CLEAR
  LIST
  RUN algo [param ...]
  TRACE algo [param ...]
  TIMELINE algo [param ...]
  SNAPSHOT algo t [param ...]
  BURSTS algo [param ...]
  WINDOW algo w [param ...]
  STATS algo [param ...]
  SWEEP algo key lo hi [param ...]
  DIFF algo algo2 [param ...]
  COMPARE [param ...]
  RANK metric [param ...]

The arguments have the following forms.
- id is a string of 1 to 8 characters that starts with an uppercase letter and consists only of uppercase letters (A to Z) and digits (0 to 9).
- prefix is a string of 1 to 4 characters consisting only of uppercase letters.
- burst is the letter C or I immediately followed by an integer (e.g. C5, I12). C denotes a CPU burst and I denotes an I/O burst, and the integer is its length (in ticks).
- algo and algo2 are strings of 1 to 12 characters consisting only of uppercase letters (not necessarily valid algorithm names).
- key and metric are strings of 1 to 12 characters consisting only of lowercase letters.
- param is a word of the form "key=value", where the key is a string of 1 to 12 characters consisting only of lowercase letters and the value is an integer.
- The other arguments (arrival, priority, count, seed, p, d, t, w, lo, hi) are integers.
- Every integer is between 0 and 2147483647 inclusive and is written in decimal without extra leading zeros.
It is guaranteed that every line follows this format and the [Constraints].

[Processing]
Process the commands in order starting from the first command line, and output the result of each command according to the [Output format].

== Notation ==
- "Ascending order of ID" means the lexicographic order of IDs by ASCII character code. If one ID is a prefix of the other, the shorter one comes first (e.g. the order B, B1, B10, B2, C).
- For an integer u >= 0 and an integer v >= 1, "the truncated notation of u/v" is the following string: let c be the quotient of 100*u divided by v (with the fractional part discarded); the string consists of the quotient of c divided by 100, ".", and the remainder of c divided by 100 written with 2 digits (with a leading 0 if it has 1 digit), in this order (e.g. 3.66 for u=11, v=3; 5.00 for u=5, v=1; 0.06 for u=1, v=16).
- "Update x" means replacing the integer x with the remainder of 48271*x divided by 2147483647.

== The process registry ==
The program has one "registry", which is initially empty. Up to 10 processes can be registered in the registry, and each process has the following information.
- ID. It is unique within the registry.
- Arrival time. An integer from 0 to 200.
- Priority. An integer from 0 to 9; a smaller value means a higher priority.
- Deadline. Either an integer from 1 to 1000 (relative to the arrival time) or "none".
- Burst sequence. CPU bursts and I/O bursts in alternation, starting with a CPU burst and ending with a CPU burst. Each burst has a length from 1 to 30.
The following 7 commands operate on the registry. Errors are checked in the order written; only the line of the first error that applies is output, and the command does nothing else.

PROC id arrival priority burst ...
Check: if id is already registered, "ERROR duplicate process <id>". If 10 processes are already registered, "ERROR too many processes". If arrival is greater than 200, "ERROR invalid arrival <id>". If priority is greater than 9, "ERROR invalid priority <id>". If the sequence of bursts is not valid, "ERROR invalid bursts <id>". The sequence of bursts is valid when the number of bursts is odd, the 1st, 3rd, 5th, ... bursts all start with C, the 2nd, 4th, ... bursts all start with I, and every burst has a length from 1 to 30.
Action: register a process that has the burst sequence in the order written and the deadline "none", and output "PROC <id> cpu=<sum of the CPU burst lengths> io=<sum of the I/O burst lengths>".

GEN prefix count seed
The IDs of the processes to generate are the count strings formed by writing each integer from 1 to count in decimal directly after prefix (prefix1, prefix2, ...), in this order.
Check: if any of the IDs to generate is already registered, "ERROR duplicate process <that ID>" for the one among them that comes earliest in generation order. If the number of registered processes plus count is greater than 10, "ERROR too many processes".
Action: first output "GEN count=<count>". Then, with the random state x set to seed, for each ID in order, create and register a process by the following procedure (with the deadline "none") and output one line in the same format as LIST. Update x and set the arrival time to the remainder of x divided by 21. Update x and set the priority to the remainder of x divided by 10. Update x and set m to 1+(the remainder of x divided by 3). Then, for j=1, 2, ..., m in order: if j is 2 or more, update x and append an I/O burst of length 1+(the remainder of x divided by 8) to the end of the sequence; after that, regardless of the value of j, update x and append a CPU burst of length 1+(the remainder of x divided by 9) to the end of the sequence.

SETPRIO id p
Check: if id is not registered, "ERROR unknown process <id>". If p is greater than 9, "ERROR invalid priority <id>".
Action: set the priority of id to p and output "SETPRIO <id> priority=<p>".

DEADLINE id d
Check: if id is not registered, "ERROR unknown process <id>". If d is greater than 1000, "ERROR invalid deadline <id>".
Action: if d is 0, set the deadline of id to "none" and output "DEADLINE <id> none". If d is 1 or more, set the deadline of id to d and output "DEADLINE <id> <d>".

DROP id
Check: if id is not registered, "ERROR unknown process <id>".
Action: remove id from the registry and output "DROP <id>".

CLEAR
Empty the registry and output "CLEAR count=<number of removed processes>".

LIST
First output "LIST count=<number of registered processes>". Then output one line per registered process in ascending order of ID: "<id> arrival=<arrival time> priority=<priority> deadline=<deadline> bursts=<burst sequence>". If the deadline is "none", write none. The burst sequence is written by writing each burst in the same form as an input burst (C for a CPU burst or I for an I/O burst, immediately followed by its length) and joining them in sequence order, separated by commas "," (e.g. bursts=C5,I3,C2).

== Algorithms and parameters ==
The algorithm names are the 9 names FCFS, SJF, SRTF, RR, PRIORITY, HRRN, EDF, LOTTERY, MLFQ, and this order is called the "algorithm order". A simulation uses the following 5 parameters.

  Key    Meaning                Valid values          Default      Used by
  cs     switch time            0 to 5                0            all algorithms
  q      time quantum           1 to 20               4            RR, LOTTERY
  k      aging interval         1 to 50               5            PRIORITY
  s      boost interval         0 to 500              0            MLFQ (0 means no boost)
  seed   initial random value   1 to 2147483646       1            LOTTERY

The params of a command are examined from left to right, and for the first error found, the following one line is output.
- The key is none of the 5 keys above: "ERROR unknown key <key>"
- The key cannot be used in that command: "ERROR key <key> not allowed for <algo>". In the commands that have exactly one algo (RUN, TRACE, TIMELINE, SNAPSHOT, BURSTS, WINDOW, STATS, SWEEP), only the keys used by the algorithm algo can be used. In DIFF, COMPARE and RANK, all 5 keys can be used.
- The key has already been specified in the same command: "ERROR duplicate key <key>"
- The value is not a valid value given above: "ERROR invalid <key>"
If there is no error, the default value is used for each key that was not specified.
The "parameter notation" of an algorithm M is the string "cs=<value of cs>" followed by, for each key used by M in the order q, k, s, seed, " <key>=<value>" (with one leading space) (e.g. "cs=0" for FCFS, "cs=1 q=3" for RR, "cs=0 q=4 seed=1" for LOTTERY). The "full parameter notation" is the string of all 5 keys in the order cs, q, k, s, seed, each in the form "<key>=<value>", separated by single spaces (e.g. "cs=0 q=4 k=5 s=0 seed=1").

== Simulation ==
A simulation is performed on all processes currently in the registry, with one algorithm and the values of the 5 parameters. A simulation does not change the registry and always starts from the initial state below. A single command may perform several simulations.

-- Terms --
- Time is an integer >= 0. The interval from time t to time t+1 is called "tick t".
- Each process is in one of the following 6 states: not arrived, ready, switching, running, in I/O, finished.
- Each process has a "current burst" and its "remaining time".
- A queue is a sequence of ready processes in order. MLFQ uses 3 queues, queue 0, queue 1 and queue 2; the other algorithms use only one queue. "Adding a process to the queue" means making the process ready, appending it to the end of the queue (in MLFQ, to the end of the queue whose number equals the level of the process), and setting the "enqueue time" of the process to the current time.
- The CPU is "idle", "switching" or "running". A switching CPU holds one process and a "remaining switch time"; a running CPU holds one process and a "consecutive run time".
- The "previous process" is the process that was last run on the CPU.
- In PRIORITY each process has an "effective priority" and a "wait counter"; in MLFQ each process has a "level" (0, 1 or 2) and a "level usage". The allotment of level 0 is 4 and the allotment of level 1 is 8.

-- Initial state --
The time is 0, every process is not arrived, its current burst is its first CPU burst, and its remaining time is the length of that burst. The effective priority equals the priority, and the wait counter, the level, the level usage and the selection count are all 0. The queue is empty, the CPU is idle, there is no previous process, and the switch count is 0. The random state x of LOTTERY is the value of seed.

-- Steps for each time --
For each time t (t=0, 1, 2, ...), perform steps 1 to 7 below in order. "Record <event>" means appending the line "<t> <event>" to the end of the event log (e.g. recording "ARRIVE A" at time 3 appends "3 ARRIVE A").

Step 1 (PRIORITY only) Aging: for the processes in the queue, one at a time from the front, increase the wait counter by 1, and when it becomes equal to k, reset the wait counter to 0. When it is reset to 0, if the effective priority is 1 or more, decrease the effective priority by 1 and record "AGE <id> <new effective priority>".
(The processes in the queue at this point are those that were ready throughout tick t-1. At t=0 the queue is empty.)

Step 2 I/O completion: for the processes in I/O whose remaining time is 0, one at a time in ascending order of ID, advance the current burst to the next CPU burst (setting the remaining time to its length), add the process to the queue, and record "IODONE <id>".

Step 3 Arrival: for the not-arrived processes whose arrival time is t, one at a time in ascending order of ID, add the process to the queue and record "ARRIVE <id>".

Step 4 CPU check:
(a) If the CPU is switching and the remaining switch time is 0, "start running" its process (see below) and record "START <id>".
(b) Otherwise, if the CPU is running, let P be its process (P was run during tick t-1), and do one of (b1) and (b2) below.
  (b1) If the remaining time of P is 0 and the current burst is the last burst of P, make P finished, set the finish time of P to t, record "DONE <id>", and make the CPU idle.
  (b2) Otherwise, first, if the algorithm is MLFQ, the level of P is less than 2, and the level usage of P equals the allotment of that level, "demote" P. Demoting means increasing the level of P by 1, setting its level usage to 0, and recording "DEMOTE <id> <new level>". Then do exactly one of the following: the first one that applies.
  - If the remaining time of P is 0, advance the current burst of P to the next I/O burst (setting the remaining time to its length d), make P in I/O, record "IO <id> <d>", and make the CPU idle.
  - If P was demoted in this step, add P to the queue and make the CPU idle.
  - If the algorithm is RR or LOTTERY and the consecutive run time equals q, add P to the queue, record "EXPIRE <id>", and make the CPU idle.
  - If the "preemption condition" of the algorithm (described later) holds, add P to the queue, record "PREEMPT <id>", and make the CPU idle.
  - If none of these applies, do nothing (P stays running).
(c) If the CPU is idle, or the remaining switch time is 1 or more, do nothing.
If all processes are finished at this point, end the simulation (steps 5 and later are not performed). The t at this point is called the "end time" and is written T.

Step 5 (MLFQ only) Boost: if s is 1 or more, t is 1 or more, and t is a multiple of s, make the concatenation of queue 0, queue 1 and queue 2 in this order (keeping the order within each queue) the new queue 0, and empty queue 1 and queue 2. Furthermore, set the level and the level usage of every process to 0, and record "BOOST".

Step 6 Selection: if the CPU is idle and the queue (in MLFQ, any of the 3 queues) is not empty, select one process P by the "selection rule" of the algorithm (described later), remove it from the queue, reset the effective priority of P to the priority of P and its wait counter to 0, and increase the selection count of P by 1. If P differs from the previous process (including when there is no previous process yet), a "switch" occurs, and the switch count is increased by 1. If a switch occurs and cs is 1 or more, make the CPU switching with P and the remaining switch time cs, make P switching, and record "SWITCH <id>". Otherwise (no switch occurs, or cs is 0), start running P immediately and record "DISPATCH <id>".
  To "start running" a process P means making the CPU running with P and the consecutive run time 0, and making P running. When P starts running for the first time, that time becomes the "start time" of P.

Step 7 Executing the tick: do the following for tick t, then increase t by 1 and return to step 1.
- If the CPU is running, decrease the remaining time of its process by 1, increase the consecutive run time and the level usage by 1 each, and make that process the previous process. The "label" of this tick is the ID of that process.
- If the CPU is switching, decrease the remaining switch time by 1. The label of this tick is CS.
- If the CPU is idle, the label of this tick is IDLE.
- Every process in I/O decreases its own remaining time by 1.
- The state of each process at the end of step 6 is the state of that process during tick t, and the number of ready processes at the end of step 6 (in MLFQ, the total over the 3 queues) is the "queue length" of tick t.

-- Selection rules and preemption conditions --
When a selection rule has several "smallest" or "largest" candidates, choose the one among them closest to the front of the queue. The preemption condition is checked for the P of step 4, and "the queue" there refers to the queue at the time of step 4 (in MLFQ, all 3 queues). For an algorithm with no preemption condition stated, preemption does not occur.
- FCFS: select the process at the front of the queue.
- SJF: select the process with the smallest remaining time.
- SRTF: the selection is the same as SJF. The preemption condition is that the queue contains a process whose remaining time is smaller than the remaining time of P.
- RR: select the process at the front of the queue (EXPIRE in step 4 applies).
- PRIORITY: select the process with the smallest effective priority. The preemption condition is that the queue contains a process whose effective priority is smaller than the effective priority of P.
- HRRN: select the process with the largest response ratio. The response ratio of a process at time t is (W+S)/S, where W is t minus the enqueue time of the process and S is its remaining time. Whether the response ratio of process X is larger than the response ratio of process Y is determined by whether (W_X+S_X)*S_Y is larger than (W_Y+S_Y)*S_X.
- EDF: the "absolute deadline" of a process that has a deadline is the sum of its arrival time and its deadline. If the queue contains processes that have a deadline, select the one among them with the smallest absolute deadline; otherwise select the process at the front of the queue. The preemption condition is that P has no deadline and the queue contains a process that has a deadline, or that P has a deadline and the queue contains a process whose absolute deadline is smaller than the absolute deadline of P.
- LOTTERY: the number of tickets of each process is 10 minus the priority of that process. Let Z be the total number of tickets of the processes in the queue; update x, and let r be the remainder of x divided by Z (this update is performed even when the queue contains only one process). Add up the numbers of tickets in order from the front of the queue, and select the process at which the sum first becomes greater than r (EXPIRE in step 4 applies).
- MLFQ: select the process at the front of the non-empty queue with the smallest number. The preemption condition is that any of the queues whose number is smaller than the level of P is non-empty.

-- Metrics --
From the result of a simulation, compute the following values.
- For each process: the turnaround time is the finish time minus the arrival time, the waiting time is the turnaround time minus the total length of all bursts of that process (both CPU and I/O), and the response time is the start time minus the arrival time. A process that has a deadline "met its deadline" if its finish time is less than or equal to its absolute deadline, and otherwise "missed its deadline".
- The "average" of each of the turnaround time, the waiting time and the response time is the truncated notation of S/n, where S is the total over all processes and n is the number of processes. Averages are compared by comparing their totals S.
- The "busy time" is the number of ticks whose label is a process ID (it equals the total length of all CPU bursts), the "total switch time" is the number of ticks whose label is CS, and the "idle time" is the number of ticks whose label is IDLE. The "CPU utilization" is the truncated notation of busy time*100/T.
- The "missed count" is the number of processes that missed their deadline.

== Commands that perform simulations ==
There are 11 of them: RUN, TRACE, TIMELINE, SNAPSHOT, BURSTS, WINDOW, STATS, SWEEP, DIFF, COMPARE, RANK. Errors are checked in the following order; only the line of the first error that applies is output, and the command does nothing else.
1. If algo is none of the 9 algorithm names, "ERROR unknown algorithm <algo>". For DIFF, the same check is then also performed for algo2 ("ERROR unknown algorithm <algo2>"). For RANK, if metric is none of turnaround, waiting, response, end, switches, missed, "ERROR unknown metric <metric>".
2. The checks that only WINDOW and SWEEP have, as written in their descriptions.
3. The param check (see "Algorithms and parameters").
4. If the registry is empty, "ERROR no processes".
Below, "parameter notation" in the description of each command means the parameter notation of the algorithm algo.

RUN algo [param ...]
Perform one simulation with the algorithm algo, and output the following lines in order.
(1) "RUN <algo> <parameter notation>"
(2) Gantt chart: group each run of consecutive ticks with the same label into one "segment", and write each segment as "[<number of its first tick>-<number of its last tick+1> <label>]" (e.g. if ticks 0 to 4 all have the label A, [0-5 A]). Split the segments, in time order, into groups of 8, and for each group output one line consisting of "GANTT " (GANTT and one space) immediately followed by the segments of that group concatenated without separators (the last line may have fewer than 8 segments).
(3) One line per process in ascending order of ID: "<id> arrival=<arrival time> done=<finish time> turnaround=<turnaround time> waiting=<waiting time> response=<response time> slices=<selection count>". For a process that has a deadline, append " deadline=<absolute deadline> late=<lateness>" (with one leading space) to the end of this line. The lateness is the finish time minus the absolute deadline if that value is positive, and 0 otherwise.
(4) "AVERAGE turnaround=<average turnaround time> waiting=<average waiting time> response=<average response time>"
(5) "CPU end=<T> busy=<busy time> switch=<total switch time> idle=<idle time> switches=<switch count> util=<CPU utilization>"
(6) "QUEUE max=<maximum queue length> avg=<truncated notation of sum of queue lengths/T>" (the maximum and the sum are over ticks 0 to T-1)
(7) "EVENTS preempt=<number of PREEMPT> expire=<number of EXPIRE> demote=<number of DEMOTE> boost=<number of BOOST> age=<number of AGE>" (each is the number of such events in the event log)
(8) "DEADLINE met=<number of processes that met their deadline> missed=<missed count>"

TRACE algo [param ...]
Perform one simulation with the algorithm algo, output "TRACE <algo> <parameter notation>", then output each line of the event log in the order recorded, and finally output "END <T>".

TIMELINE algo [param ...]
Perform one simulation with the algorithm algo. If T is greater than 100, output only "ERROR too long <T>". Otherwise, output "TIMELINE <algo> <parameter notation> end=<T>", then output one line per process in ascending order of ID. Each line consists of the ID padded with trailing spaces to 8 characters (no padding if the ID has 8 characters), one space, and T characters representing the state of that process from tick 0 to tick T-1, one character per tick, in this order. The characters are # for running, s for switching, . (period) for ready, i for in I/O, and - (hyphen) for not arrived and finished.

SNAPSHOT algo t [param ...]
Perform one simulation with the algorithm algo, and output the state at the end of step 6 at time t. If t is T or more, output instead the state at the end of step 4 at time T (when the simulation ended). The output is as follows.
(1) "SNAPSHOT <algo> <parameter notation> t=<t>"
(2) "CPU RUN <ID of its process>" if the CPU is running, "CPU SWITCH <ID of its process>" if it is switching, and "CPU IDLE" if it is idle.
(3) For algorithms other than MLFQ, the one line "QUEUE <queue>"; for MLFQ, the 3 lines "QUEUE0 <queue 0>", "QUEUE1 <queue 1>", "QUEUE2 <queue 2>". <queue> is the IDs of the processes in that queue in order from the front, separated by single spaces, or none if the queue is empty.
(4) One line per process in ascending order of ID. If the process is not arrived, "<id> FUTURE at=<arrival time>"; if it is finished, "<id> DONE at=<finish time>". Otherwise, "<id> <state name> burst=<index> left=<remaining time>", where the state name is READY for ready, SWITCH for switching, RUN for running, and IO for in I/O, and the index is the position of the current burst in the burst sequence (counting from 1 through both CPU bursts and I/O bursts). Furthermore, to each line of this form (a line other than FUTURE and DONE), append " prio=<effective priority>" at the end if the algorithm is PRIORITY, or " level=<level> used=<level usage>" at the end if it is MLFQ (both with one leading space).

BURSTS algo [param ...]
Perform one simulation with the algorithm algo, and output "BURSTS <algo> <parameter notation>". Then, for each process in ascending order of ID, output one line for each CPU burst of that process in sequence order: "<id> #<j> len=<L> ready=<R> start=<B> end=<E> wait=<E-R-L> slices=<c>". j is the position of that burst among the CPU bursts (counting from 1), L is its length, R is the time at which the process was added to the queue for that burst (the arrival time for the first CPU burst, otherwise the time at which the immediately preceding I/O burst completed), B is the time at which the process first started running in that burst, E is the time at which the remaining time of that burst became 0 (the number of the last tick of that burst+1), and c is the number of times the process was selected during that burst (from R to E).

WINDOW algo w [param ...]
Check 2: if w is not between 1 and 1000 inclusive, "ERROR invalid window".
Action: perform one simulation with the algorithm algo, and output "WINDOW <algo> <parameter notation> width=<w>". Then, for a=0, w, 2w, ... in order (while a is less than T), treat ticks a to b-1 (where b is the smaller of a+w and T) as one window, and output one line per window: "<a>-<b> busy=<busy> switch=<switch> idle=<idle> util=<truncated notation of busy*100/(b-a)> top=<top>". busy, switch and idle are the numbers of ticks in that window whose label is a process ID, CS, and IDLE, respectively. top is the ID of the process that is the label of the largest number of ticks in that window; if there are several such processes, the first one in ascending order of ID; if no tick has a process ID as its label, none.

STATS algo [param ...]
Perform one simulation with the algorithm algo, and output "STATS <algo> <parameter notation>". Then output one line for each of the turnaround time, the waiting time and the response time, in this order: "<name> min=<minimum> (<ID of minimum>) max=<maximum> (<ID of maximum>) median=<median> total=<total>". The names are turnaround, waiting and response, respectively. The ID of the minimum and the ID of the maximum are the ID of a process that has that value; if there are several, the first one in ascending order of ID. The median is, when the values of all processes are arranged in increasing order, the middle value if the count is odd, or the average of the two middle values if the count is even; it is written as the integer part, ".", and the first decimal digit (0 or 5), in this order (e.g. 7.0, 7.5).

SWEEP algo key lo hi [param ...]
Check 2: if key is none of the 5 keys, "ERROR unknown key <key>". If key is a key that cannot be used with the algorithm algo, "ERROR key <key> not allowed for <algo>". If lo is greater than hi, or either lo or hi is not a valid value of key, or hi-lo is greater than 20, "ERROR invalid range".
In check 3, key is treated as an already specified key (if param contains key, the error is "ERROR duplicate key <key>").
Action: first output "SWEEP <algo> <key> <lo> <hi>". Then, for v=lo, lo+1, ..., hi in order, set the value of key to v, take the other parameters from param and the default values, perform a simulation with the algorithm algo, and output one line per simulation: "<parameter notation> turnaround=<average turnaround time> waiting=<average waiting time> response=<average response time> util=<CPU utilization> end=<T> switches=<switch count>" (the value of key in the parameter notation is v). Finally, output "BEST <key>=<v>" for the v with the smallest average waiting time (the smallest v if there are several).

DIFF algo algo2 [param ...]
Perform one simulation each with the algorithm algo and the algorithm algo2, and output "DIFF <algo> <algo2> <full parameter notation>". Then output one line per process in ascending order of ID: "<id> turnaround=<t1>/<t2> waiting=<w1>/<w2> response=<r1>/<r2>". t1, w1, r1 are the turnaround time, waiting time and response time of that process under the algorithm algo, and t2, w2, r2 those under the algorithm algo2. Finally output "WINS <algo>=<a> <algo2>=<b> ties=<c>". a is the number of processes with t1 smaller than t2, b is the number of processes with t1 greater than t2, and c is the number of processes with t1 equal to t2 (algo and algo2 may be the same algorithm name).

COMPARE [param ...]
Perform one simulation with each of the 9 algorithms, and first output "COMPARE <full parameter notation>". Then output a table. Each row of the table consists of the string of the first column padded with trailing spaces to 8 characters, followed, for each of the remaining 7 columns, by "one space and the string of that column padded with leading spaces to 8 characters". The first row is the header, whose columns are, in order, ALGO, TURN, WAIT, RESP, UTIL, END, SWITCH, MISS. Then follows one row per algorithm in algorithm order, whose columns are, in order, the algorithm name, the average turnaround time, the average waiting time, the average response time, the CPU utilization, T, the switch count, and the missed count. Finally output "BEST turnaround=<algorithm name> waiting=<algorithm name> response=<algorithm name>". Each is the algorithm with the smallest such average; if there are several, the first one in algorithm order.

RANK metric [param ...]
Perform one simulation with each of the 9 algorithms, and first output "RANK <metric> <full parameter notation>". The "value" of each algorithm is the corresponding average if metric is turnaround, waiting or response (compared by the totals), T if it is end, the switch count if it is switches, and the missed count if it is missed. Arrange the algorithms in increasing order of value (in algorithm order for equal values), and output one line per algorithm: "<rank> <algorithm name> <value>". The rank is the number of algorithms whose value is smaller than the value of that algorithm, plus 1. The value is written in its truncated notation if it is an average, and as an integer otherwise.

[Output format]
- For each command, output only the lines described in [Processing]. Every command outputs at least one line.
- Words and values within a line are separated by single spaces as described. However, after the ID in TIMELINE and in the COMPARE table, spaces are lined up as described. Do not put spaces at the end of a line, and do not output blank lines. Every line ends with a newline.
- Numbers, except truncated notations and the STATS median, are written as decimal integers without extra leading zeros.
- There are the following 17 kinds of error lines (each part in < > is replaced with the value as described).
  ERROR duplicate process <id>
  ERROR too many processes
  ERROR invalid arrival <id>
  ERROR invalid priority <id>
  ERROR invalid bursts <id>
  ERROR invalid deadline <id>
  ERROR unknown process <id>
  ERROR unknown algorithm <algo>
  ERROR unknown metric <metric>
  ERROR unknown key <key>
  ERROR key <key> not allowed for <algo>
  ERROR duplicate key <key>
  ERROR invalid <key>
  ERROR invalid window
  ERROR invalid range
  ERROR no processes
  ERROR too long <T>

[Constraints]
- 1 <= N <= 500
- The number of bursts in PROC is from 1 to 15.
- GEN: 1 <= count <= 99, 1 <= seed <= 2147483646
- The whole input contains at most 200 commands that perform simulations.
- When processed according to the rules, the end time T is less than 20000. The absolute values of all integers needed for the processing are less than 2^47 (the largest is 48271*x used to update x).
