[Overview]
Write a workbench (a working environment) for terms of the untyped lambda calculus. The program reads commands from standard input one line at a time, executes them in order, and writes the results to standard output. Terms consist of variables, abstractions (\x. M) and applications (M N), and can be written with parentheses, abstractions that group several bound variables together, a shorthand for Church numerals (#n), and macros whose names are written in uppercase letters. The program handles the following 20 commands: defining (let), deleting (unlet) and listing (macros) macros, switching the display of steps (steps), switching eta-reduction (eta), setting the upper limit on the number of steps (limit), expanding a term (expand), substituting for a variable (subst), reducing with 4 strategies (leftmost-outermost, leftmost-innermost, call-by-name, call-by-value) (reduce), deciding equality by reduction (equal), deciding alpha-equivalence (alpha), printing the de Bruijn form (debruijn), free variables (fv), size (size), depth (depth), inferring the principal simple type (type), reading a result back as a Church numeral, boolean or pair (church), converting to combinations of S, K and I (SKI terms) (ski) and reducing them (skireduce), and running on the Krivine abstract machine (kam). In substitution, bound variables are renamed by fixed rules to avoid the capture of variables by bound variables. Result terms are printed in a unique form that uses minimal parentheses and renames the bound variables to a, b, c, .... For an erroneous command, the program outputs one line of the form "error: reason" (for a syntax error it also shows the column number) and moves on to the next command.

[Input format]
The input consists of several lines, and the last line is a line consisting only of quit. Each line is a string of 0 to 200 characters consisting only of printable ASCII characters (character codes 32 to 126), and the first and the last character of a non-empty line are not spaces.
Each line is one of the following.
- An empty line.
- A line starting with -- (a "comment line").
- A line consisting only of quit. It appears exactly once, as the last line of the input.
- Any other line (a "command line").
In a command line, the part before the first space (the whole line if there is no space) is called the "command name", and the part after the first space is called the "argument part" (if there is no space, the argument part is the empty string). There is no command line whose command name is quit.

The commands have the following 20 forms. [ ] denotes an optional part, and on|off denotes either on or off. A "name" (written <name>) and a "variable name" (written <variable name>) are defined in section 1 of [Processing], and how to write a "term" (written <term>) is defined in sections 3 and 4.

  let <name> = <term>
  unlet <name>
  macros
  steps on|off
  eta on|off
  limit n
  expand <term>
  subst <variable name> = <term> ; <term>
  reduce [<strategy>] <term>
  equal <term> ; <term>
  alpha <term> ; <term>
  debruijn <term>
  fv <term>
  size <term>
  depth <term>
  type <term>
  church <term>
  ski <term>
  skireduce <term>
  kam <term>

A <strategy> is one of NORMAL, APPLICATIVE, CBN and CBV. However, the input also contains lines with unknown command names, format errors, syntax errors and so on. How they are handled is explained in [Processing].

[Processing]
Process the input lines in order from the first. Ignore empty lines and comment lines and output nothing for them. When the quit line is reached, stop processing (nothing is output for the quit line). Process the command lines one line at a time by the procedure of section 11.
The program has the following "state", and the state carries over from one command line to the next. The value in parentheses is the initial value.
- Macro table: a mapping from names to terms (it contains only the 3 predefined macros of section 6, and no user-defined macros).
- Display mode: on or off (off).
- Eta mode: on or off (off).
- Limit L: an integer from 1 to 10000 (10000).
Below, a string enclosed in double quotes is a string that appears in the output as it is. However, a part enclosed in < and > inside it is replaced by the string described. Every output line ends with LF.

1. Terminology
- A "space" is the half-width space (character code 32). "Lowercase letters" are the 26 characters a to z, "uppercase letters" are the 26 characters A to Z, and "digits" are the 10 characters 0 to 9. \ is the backslash (character code 92).
- A "variable name" is a string of one or more characters that starts with a lowercase letter and consists only of lowercase letters and digits (examples: x, y1, abc2).
- A "name" is a string of one or more characters that starts with an uppercase letter and consists only of uppercase letters, digits and _ (examples: TRUE, B1, C_1). Names are used for macros.
- The "character code order" of strings is the order that compares two strings one character at a time from the start, puts first the string whose character code is smaller at the first differing character, and, if one string is a prefix of the other, puts the shorter one first. For example, a10 comes before a2, and AB comes before A_B.
- The "decimal notation" of an integer is its decimal representation without extra leading zeros.
- The characters of a command line are numbered 1, 2, 3, ... in order from the first character, and this number is called the "column" (the first character of the command name is column 1).

2. Terms
A "term" is one of the following 5 kinds.
- A variable x (x is a variable name).
- A macro reference A (A is a name).
- A numeral shorthand #n (n is an integer >= 0; it denotes the Church numeral n).
- An abstraction \x. M (x is a variable name, called the "bound variable" of this abstraction; M is a term, called the "body" of this abstraction).
- An application M N (M and N are terms; M is called the "function part" and N the "argument part").
A term that contains no macro references and no numeral shorthands is called a "pure term". Most commands that take a term first "expand" the term into a pure term by the method of section 6 and then process it.
An occurrence of a variable x in a term is said to be "bound" by the innermost of the enclosing abstractions whose bound variable is x, if there is such an abstraction; otherwise it is said to be "free". The set of variable names that occur free in a term M is written FV(M) and is called the "free variables" of M. That is, FV(x) = {x}, FV(\x. M) is the set FV(M) with x removed, FV(M N) is the union of FV(M) and FV(N), and FV of a macro reference and of a numeral shorthand is the empty set.
Two pure terms are "alpha-equivalent" if their de Bruijn forms (section 8) are the same. Terms that differ only in the names of bound variables are alpha-equivalent. Free variables are distinguished by their names.

3. Lexical analysis
For the commands that take terms (section 11), the argument part is first split into a sequence of "tokens". Read the argument part in order from its first character, and cut out tokens by the following rules.
- Spaces are skipped (they only serve to separate tokens).
- Each of the 6 characters \ . ( ) = ; is a token of one character.
- From a lowercase letter, read on as long as a lowercase letter or a digit follows, and make that longest part one "variable name token".
- From an uppercase letter, read on as long as an uppercase letter, a digit or _ follows, and make that longest part one "name token".
- When the character right after # is a digit, # together with the longest sequence of digits following it is one "numeral shorthand token". Its value is the integer obtained by reading the digit sequence as a decimal number (leading zeros are ignored).
- On meeting any other character (a # not immediately followed by a digit, a digit that is not part of a variable name, name or numeral shorthand token, a symbol not listed above, and so on), it is the error "column <C>: unexpected character '<c>'". C is the column of that character and c is that character.
Each token is given the column of its first character. At the end of the token sequence, one token called the "end" is placed, and its column is the number of characters of the command line plus 1.
For example, the argument part of "expand \x.xy" becomes the 5 tokens \, x, ., xy and end (xy is a single variable name token). "IDx" is 2 tokens: the name token ID and the variable name token x.
Lexical analysis proceeds in order from the start of the argument part and reports the first (leftmost) erroneous character found. If an error occurs in lexical analysis, parsing is not performed.

4. Parsing
The token sequence is consumed in order from the start. The "next token" is the first of the tokens not yet consumed. Below, to "expect X" means: if the next token is X, consume it; otherwise it is the error "column <C>: expected <notation of X>". C is the column of the next token, and the notation of X is as follows.
  variable name token: variable
  name token: macro name
  the tokens ., ), =, ;: '.', ')', '=', ';' respectively
To "read a term" is the following procedure.
(1) While the next token is a variable name, name, numeral shorthand or ( token, repeat reading one "atom".
(2) Then, if the next token is \, read one "abstraction".
(3) The things read in (1) and (2) are called "elements". If no element was read, it is the error "column <C>: expected term". C is the column of the next token.
(4) Let E1, E2, ..., Ek be the elements in the order read. The term read is the term (...((E1 E2) E3)...) Ek obtained by applying E1 to E2, ..., Ek one after another from left to right. If k = 1, it is E1.
Atom: consume the next token. If it is a variable name token, the atom is that variable; if it is a name token, the atom is the macro reference with that name; if it is a numeral shorthand token, the atom is the numeral shorthand with that value. If it is (, read a term and expect ). In this case the atom is the term read inside the parentheses.
Abstraction: consume \ and expect a variable name token. Then, while the next token is a variable name token, consume it. Let x1, x2, ..., xm be the variable names read, in order. Next, expect . and read a term M. The abstraction read is \x1. (\x2. (... (\xm. M) ...)).
Thus application is left-associative, and the body of an abstraction extends as far to the right as possible. For example, "f x y" is (f x) y, "\x y. x y" is \x. (\y. (x y)), "a \x. x b" is a (\x. (x b)), and "(\x. x) y" is the application of the abstraction \x. x to y.
Each command reads tokens in the order determined in section 11. After everything determined has been read, if the next token is not the end, it is the error "column <C>: unexpected '<t>'". C is the column of that next token, and t is the string of that token. Parsing reports only the first error found.

5. Printing terms
The "printed form" of a term t is defined as s(t, true) using the following function s. The e in s(t, e) is a value true or false and is used to decide whether an abstraction is enclosed in parentheses (false represents a position where the printed form of t may be followed by characters that do not belong to t).
- If t is a variable or a macro reference, it is that variable name or name. If t is a numeral shorthand #n, it is "#<decimal notation of n>".
- If t is an abstraction, start from t and follow the body as long as the body is an abstraction, viewing t as t = \x1. \x2. ... \xk. M (k >= 1, and M is a term that is not an abstraction). Let S be the string obtained by concatenating, in this order, "\", the bound variables x1, x2, ..., xk separated by single spaces, ".", one space, and s(M, true). The result is S if e is true, and S enclosed in ( and ) if e is false.
- If t is an application M N, the left side is s(M, true) enclosed in ( and ) if M is an abstraction, and s(M, false) otherwise. The right side is s(N, true) enclosed in ( and ) if N is an application, and s(N, e) otherwise. s(t, e) is the concatenation of the left side, one space and the right side, in this order.
For example, \x. \y. x (y z) is printed as "\x y. x (y z)", (\x. x) (\y. y) as "(\x. x) \y. y", (x (\y. y)) z as "x (\y. y) z", (x y) z as "x y z", x (y z) as "x (y z)", and \x. \x. x as "\x x. x". Reading a printed form back by the rules of section 4 gives the original term.

6. Macros and expansion
The macro table is a mapping from names to terms. The following 3 macros are "predefined" and are always in the table (the right-hand sides are terms read by the rules of section 4).
  S = \x y z. x z (y z)
  K = \x y. x
  I = \x. x
The user can define macros with other names by let. The 7 names S, K, I, NORMAL, APPLICATIVE, CBN and CBV are called "reserved names". The user cannot define or delete a macro with a reserved name.
The "expansion" of a term t is the pure term obtained by replacing the macro references and numeral shorthands of t as follows. The parts of t are processed from left to right (in an application, the function part is processed before the argument part).
- Macro reference A: if A is not in the macro table, it is the error "unbound macro <A>". Otherwise, replace it with the expansion of the defining term of A at that time.
- Numeral shorthand #n: replace it with \f. \x. f (f (... (f x) ...)) (with n applications of f; \f. \x. x if n = 0). The names of the bound variables are f and x.
- A variable stays as it is, an abstraction \x. M becomes \x. (expansion of M), and an application M N becomes (expansion of M) (expansion of N).
The rules of let and unlet (section 11) guarantee that the defining term of a macro has no free variables and that the macro table contains neither references to undefined macros nor circular references. Hence expansion always terminates, and no variable is captured by expansion. A macro reference is replaced using the definition at the time of expansion (redefining a macro also changes the expansion of the other macros that refer to it).

7. Substitution
The term M[x := N], obtained by substituting a pure term N for the variable x in a pure term M, is defined as follows.
(1) If M is the variable x, it is N; if M is a variable other than x, it is M.
(2) If M is an application P Q, it is P[x := N] Q[x := N].
(3) When M is an abstraction \y. B:
  (a) If y is the same as x, or x is not in FV(B), it is M unchanged.
  (b) Otherwise, if y is not in FV(N), it is \y. (B[x := N]).
  (c) Otherwise (when y is in FV(N) and x is in FV(B)), the bound variable is renamed. Let b be the string obtained from y by removing all the digits at its end. For i = 1, 2, 3, ... in order, examine the variable name formed by b followed by the decimal notation of i, and let z be the first one that is in neither FV(N) nor FV(B). The result is \z. ((B[y := z])[x := N]). Here B[y := z] is the term obtained by substituting the variable z for y in B, computed by these rules (1)-(3).
For example, (\y. x y)[x := y] is \y1. y y1, (\y. x y y1)[x := y] is \y2. y y2 y1, (\y3. x y3)[x := y3] is \y1. y3 y1, (\y. z)[x := y] is \y. z, and (\x. x)[x := y] is \x. x.

8. Canonical printed form and de Bruijn form
The "name sequence" is defined as follows: for k = 0, 1, 2, ..., the k-th name is "the lowercase letter whose character code is 97 + (the remainder of k divided by 26)", followed, if k >= 26, by the decimal notation of "the quotient of k divided by 26". That is, a, b, ..., z, a1, b1, ..., z1, a2, b2, ....
The "canonical printed form" of a pure term t is the printed form (section 5) of the term obtained by renaming the bound variables of t as follows. Let F = FV(t). Take the abstractions of t one at a time in the order in which their bound variables appear from the left in the printed form (an abstraction comes before the abstractions in its body, and in an application the abstractions in the function part come before those in the argument part), and assign them names one at a time from the start of the name sequence, skipping the names contained in F. Change the bound variable of each abstraction, and the occurrences of the variables bound by that abstraction, to the assigned name. Different abstractions are assigned different names.
For example, the canonical printed form of x (\y. y) (\y. \z. z y) is "x (\a. a) \b c. c b", and the canonical printed form of \y. a y is "\b. a b". Alpha-equivalent terms have the same canonical printed form.

The "de Bruijn form" of a pure term t is obtained by replacing each bound variable occurrence in t with the number of the abstractions enclosing it that are inside the abstraction binding it (an integer >= 0, called the "index"), and removing the names of the bound variables of the abstractions. Free variable occurrences stay as variable names. The de Bruijn form is printed by the rules of section 5, except that an index is printed as its decimal notation and an abstraction is printed as "\" followed by the printed form of its body (the bound variable, "." and the space are not written). The way the bodies are followed and the way parentheses are placed are the same as in section 5.
For example, the printed de Bruijn form of \x. \y. x (\z. z y) w is "\\1 (\0 1) w", and that of (\x. x) y is "(\0) y".

9. One reduction step
An application (\x. B) N whose function part is an abstraction is called a "beta-redex", and replacing it with B[x := N] is called "beta-contraction". An abstraction of the form \x. (M x) where x is not in FV(M) is called an "eta-redex", and replacing it with M is called "eta-contraction".
For each of the 4 strategies, the "one step" of a pure term t is defined by the following recursive procedure. The result of one step is either a pair of the term after the contraction and the kind of contraction (beta or eta), or "none". "Eta is used" means that the strategy is NORMAL or APPLICATIVE and the eta mode is on. To "replace the subterm P" means that the result of the one step of t is the term obtained by replacing P in t with the result term of the one step of P (computed with the same strategy), and its kind is the kind of the one step of P.

NORMAL (leftmost-outermost):
- When t is an application M N: if M is an abstraction, beta-contract t. Otherwise, if M has a one step, replace M; if not, if N has a one step, replace N; if neither has one, none.
- When t is an abstraction \x. B: if eta is used and t is an eta-redex, eta-contract t. Otherwise, if B has a one step, replace B; if not, none.
- When t is a variable: none.
APPLICATIVE (leftmost-innermost):
- When t is an application M N: if M has a one step, replace M; if not, if N has a one step, replace N. If neither has one, beta-contract t if M is an abstraction; otherwise none.
- When t is an abstraction \x. B: if B has a one step, replace B. If not, eta-contract t if eta is used and t is an eta-redex; otherwise none.
- When t is a variable: none.
CBN (call-by-name; the inside of abstractions and argument parts are not reduced):
- When t is an application M N: if M is an abstraction, beta-contract t. Otherwise, if M has a one step, replace M; if not, none.
- When t is an abstraction or a variable: none.
CBV (call-by-value; the inside of abstractions is not reduced, and a contraction happens only after the argument part has become a "value". A value is a variable or an abstraction):
- When t is an application M N: if M has a one step, replace M; if not, if N has a one step, replace N. If neither has one, beta-contract t if M is an abstraction and N is a value; otherwise none.
- When t is an abstraction or a variable: none.

10. Running a reduction
To "reduce" a pure term t with strategy X means to repeat the following for k = 1, 2, 3, ... in order.
(1) Compute the one step of t under X. If it is none, the reduction "succeeds"; the result is t and the number of steps is k - 1.
(2) If k > L (that is, if L contractions have already been done and t can still be contracted), the reduction "fails".
(3) Replace t with the result term of the one step. If the display mode is on and the command performing the reduction is reduce, output "step <k> (<kind of contraction>): <printed form of t>" (the printed form here is the printed form of section 5, not the canonical printed form). equal and church output no steps. skireduce is as described in section 14.
reduce outputs "result: <canonical printed form of the result> (steps: <number of steps>)" on success, and "no normal form within <L> steps" on failure (the wording is the same for CBN and CBV).

11. Processing commands
Each command line is processed in the following order.
(1) If the command name is not one of the 20 kinds in [Input format], it is the error "unknown command <command name>".
(2) If the command name is one of steps, eta, limit, macros and unlet, the sequence of "words" obtained by splitting the argument part at spaces is used (a word is a part of one or more characters containing no space, preceded and followed by a space or an end of the argument part). Lexical analysis is not performed.
(3) For the other commands, lexically analyze the argument part (section 3), read tokens in the order determined below for each command (section 4), and finally check that the next token is the end. After that, expand the terms read, in order starting from the one further left in the token sequence (section 6; let does not expand).
(4) Perform the processing of each command.
If an error occurs anywhere, output the one line "error: <reason>", stop processing that command line, and move on to the next line. A command in which an error occurred does not change the state.

let <name> = <term>:
Expect a name token (let A be its string), expect =, and read a term B. Check the following in order.
(a) If A is a reserved name, it is the error "reserved name <A>".
(b) Let R1, R2, ... be the names of the macro references contained in B, from left to right. For each Ri in order: if Ri is the same as A or Ri "depends on" A, it is the error "recursive definition of <A>". Otherwise, if Ri is not in the macro table, it is the error "unbound macro <Ri>". Here, a macro R depends on A if R is a user-defined macro and its defining term contains a reference to A or a reference to a macro that depends on A.
(c) If FV(B) is not empty, it is the error "free variable <v> in definition of <A>". v is the first element of FV(B) in character code order.
If there is no error, output "redefined <A>" if A is already a user-defined macro, and "defined <A>" otherwise, and set the definition of A in the macro table to B (the term without expansion).

unlet <name>:
If there is not exactly one word, or that word is not a name, it is the error "bad argument". Let A be that word. If A is a reserved name, it is the error "reserved name <A>"; if A is not a user-defined macro, it is the error "unbound macro <A>". If there are user macros whose defining terms contain a reference to A, let U be the one among them whose name comes first in character code order; it is the error "<A> is used by <U>". Otherwise, remove A from the macro table and output "removed <A>".

macros:
If there are one or more words, it is the error "bad argument". Otherwise, output the user-defined macros one at a time in character code order of their names, each as one line "<name> = <printed form of the defining term>". The defining term is printed by the rules of section 5 without expansion (macro references appear as names and numeral shorthands in the form #n). The predefined S, K and I are not output. If there are no user-defined macros, output "(none)".

steps on|off, eta on|off:
Unless there is exactly one word and it is on or off, it is the error "bad argument". Otherwise, set the display mode (for steps) or the eta mode (for eta) to that value. Nothing is output.

limit n:
Unless there is exactly one word, it is a string of 1 to 5 characters consisting only of digits, and its value read as a decimal number is from 1 to 10000, it is the error "bad argument". Otherwise, set the limit L to that value (for example, 00100 is 100). Nothing is output.

expand <term>:
Read a term and output the printed form (section 5; not the canonical printed form) of the expanded term.

subst <variable name> = <term> ; <term>:
Expect a variable name token (let x be that variable name), expect =, read a term N, expect ;, and read a term M. Expand N and then M, and output the printed form (section 5; not the canonical printed form) of M[x := N] (section 7).

reduce [<strategy>] <term>:
If the first token is a name token whose string is one of NORMAL, APPLICATIVE, CBN and CBV, consume it and use it as the strategy. Otherwise the strategy is NORMAL. Then read a term, reduce the expanded term with that strategy (section 10), and output the result.

equal <term> ; <term>:
Read a term P, expect ;, and read a term Q. Expand P and then Q, and reduce each of them with strategy NORMAL (section 10; the eta mode uses its value at that time, and no steps are output even if the display mode is on). Output "unknown" if either reduction fails, "yes" if both succeed and the results are alpha-equivalent to each other, and "no" otherwise.

alpha <term> ; <term>:
Read and expand 2 terms in the same way as equal, and output "yes" if the expanded terms are alpha-equivalent to each other, and "no" otherwise (no reduction is performed).

debruijn <term>:
Output the printed form of the de Bruijn form (section 8) of the expanded term.

fv <term>:
Output the free variables of the expanded term in character code order, separated by single spaces, on one line. If there are no free variables, output "(none)".

size <term>, depth <term>:
Output the decimal notation of the size size(t) or the depth depth(t) of the expanded term t. size(variable) = 1, size(\x. M) = 1 + size(M), size(M N) = 1 + size(M) + size(N), depth(variable) = 1, depth(\x. M) = 1 + depth(M), and depth(M N) = 1 + max(depth(M), depth(N)) (\x y. M counts as 2 abstractions).

type <term>: as described in section 12.
church <term>: as described in section 13.
ski <term>, skireduce <term>: as described in section 14.
kam <term>: as described in section 15.
(For these commands as well, reading the term, checking the end and expanding are done as in (3).)

12. Type inference (type)
A "type" is either a type variable or a function type A -> B made of 2 types A and B. A "typing" of a pure term t is an assignment of types to all subterms of t that satisfies all of the following conditions.
- All occurrences of the same free variable are assigned the same type. All occurrences of the variables bound by the same abstraction are assigned the same type, and this type is the type of the bound variable of that abstraction.
- The type of an abstraction \x. M is A -> B, where A is the type of x and B is the type of M.
- In an application M N, where A is the type of N and B is the type of M N, the type of M is A -> B.
If t has a typing, there is a type T of t such that the type of t in every typing of t is obtained by substituting types for the type variables of T (the "principal type"), and the principal type is unique up to renaming of type variables. The principal type can be obtained, for example, as follows. Assign distinct type variables to the bound variable of each abstraction, to each free variable and to the result of each application, and for each application M N make the equation "type of M = type of N -> type of M N". Solve these equations by unification (including the occurs check); if there is no solution, there is no typing. If there is a solution, applying the most general solution to the type of t gives the principal type.
Output: if there is no typing, output "not typable". Otherwise, output one line with the principal type printed as follows. Name the type variables, in the order in which they first appear from the left when printed, with the names of the name sequence of section 8 in order from its start (no names are skipped). A type variable is printed as its name. A function type A -> B is printed as the concatenation of the printed form of A, " -> " (the 4 characters space, -, >, space), and the printed form of B, in this order. However, if A is a function type, the printed form of A is enclosed in ( and ) (B is not enclosed).
For example, the principal type of \f. \x. f (f x) is printed as "(a -> a) -> a -> a", the principal type of x y (x and y are free variables) is printed as "a", and \x. x x has no typing.

13. Reading back Church values (church)
Reduce the expanded term with strategy NORMAL (section 10). Here eta-contraction is not used regardless of the eta mode, and no steps are output regardless of the display mode. On failure, output "no normal form within <L> steps". On success, let u be the result term with its bound variables renamed in the same way as in the canonical printed form of section 8, and output r(u) on one line. r(v) is determined by checking the following (1)-(4) in order and using the first one that applies.
(1) If v has the form \f. \x. B and B is the term f (f (... (f x) ...)) obtained by applying f to x n times (n >= 0), it is the decimal notation of n (a Church numeral). Here f is the bound variable of the outer abstraction, x is the bound variable of the inner abstraction, and the f and x in B are occurrences bound by the respective abstractions.
(2) If v has the form \t. \f. t (t is the bound variable of the outer abstraction), it is "true" (the Church boolean true).
(3) If v has the form \f. (f P) Q and f is in neither FV(P) nor FV(Q), it is "(<r(P)>, <r(Q)>)" (a Church pair).
(4) Otherwise, it is the canonical printed form of v regarded as an independent term (the names of the bound variables are reassigned starting from a).
In u, all bound variable names are distinct from each other and also distinct from the free variable names, so the forms above can be decided by comparing names. The Church boolean false \t. \f. f is the same term as the Church numeral 0, so it becomes "0" by (1). For example, if the result is \a. a (\b. \c. c) (\d. d), output "(0, \a. a)".

14. SKI terms (ski, skireduce)
An "SKI term" is a term made of variables, "constants" (the 3 kinds S, K and I) and applications. SKI terms are printed by the rules of section 5, and a constant is printed as its letter (S, K, I). FV(e) of an SKI term e is the set of variable names occurring in e (constants have no free variables).
The conversion T(t) of a pure term t is defined as follows.
- If t is a variable, T(t) = t; if t is an application M N, T(t) = T(M) T(N); if t is an abstraction \x. M, T(t) = A(x, T(M)).
Here, A(x, e) for a variable name x and an SKI term e is determined by checking the following (1)-(4) in order and using the first one that applies.
(1) If x is not in FV(e), it is K e (the constant K applied to e).
(2) If e is the variable x, it is I.
(3) If e is an application P Q, Q is the variable x, and x is not in FV(P), it is P.
(4) Otherwise (e is an application P Q), it is S A(x, P) A(x, Q) (that is, (S A(x, P)) A(x, Q)).
ski: for the expanded term t, output the printed form of T(t).
skireduce: for the expanded term t, reduce e = T(t) by the same procedure as in section 10, using the one step below (the limit is L; if the display mode is on, output "step <k> (<kind>): <printed form of e>" at each step). On success, output "result: <printed form of the result> (steps: <number of steps>)", and on failure "no normal form within <L> steps".
The one step of an SKI term e is as follows. View e as the term (...((h a1) a2)...) an obtained by applying a term h that is not an application to n terms (n >= 0) a1, a2, ..., an from left to right in order.
- If h is I and n >= 1, the result is (...((a1 a2) a3)...) an, and the kind is I.
- If h is K and n >= 2, the result is (...((a1 a3) a4)...) an, and the kind is K.
- If h is S and n >= 3, the result is (...(((a1 a3) (a2 a3)) a4)...) an, and the kind is S.
- Otherwise, compute the one step of each of a1, a2, ..., an in this order; the result is obtained by replacing the first ai for which a one step was obtained with the result term of that step, and the kind is the kind of the one step of that ai. If none of the ai has a one step, none.

15. Krivine abstract machine (kam)
Run the de Bruijn form d of the expanded term on the Krivine abstract machine.
A "closure" is a pair of a term in de Bruijn form and an "environment". An environment is a sequence of closures, whose elements are numbered 0, 1, 2, ... from the front. A "state" of the machine consists of the "code" c (a term in de Bruijn form), the environment E, and the "stack" P (a sequence of closures; the one pushed last is called the "top"). Initially c = d, and E and P are empty. There are the following 3 kinds of state "transitions".
- push: if c is an application M N, push the closure (N, E) onto P and set c to M.
- grab: if c is an abstraction and P is not empty, remove the top closure from P and add it to the front of E (the element of E previously numbered i becomes number i + 1), and set c to the body of that abstraction.
- access: if c is an index i, let (c', E') be the closure numbered i in E, and set c to c' and E to E' (i is always less than the length of E).
When c is an abstraction and P is empty, and when c is a free variable, no transition is possible.
Repeat the following for k = 1, 2, 3, ... in order.
(1) If no transition is possible, the run succeeds, and the number of transitions is k - 1.
(2) If k > L, the run fails.
(3) Perform one transition. If the display mode is on, output "step <k> (<kind of transition>): <printed form of c after the transition> [env <number of elements of E>, stack <number of elements of P>]". The printed form of c is the printed de Bruijn form of section 8, and the kind of transition is one of push, grab and access.
On failure, output "no result within <L> transitions". On success, compute the term represented by the stopped state as follows. The term R(c, E) represented by a closure (c, E) is the term in de Bruijn form obtained from c by replacing every occurrence of an index i in c such that i >= j, where j is the number of abstractions in c that enclose that occurrence, with R(the closure numbered i - j in E) (the result of R contains no indices that refer to outer abstractions, so it can be embedded as it is). Let p1, p2, ..., pm be the closures of P in order from the top; the term represented by the stopped state is the term (...((R(c, E) R(p1)) R(p2))...) R(pm) obtained by applying R(c, E) to R(p1), R(p2), ..., R(pm) from left to right in order. Using the canonical printed form of the pure term whose de Bruijn form is this term (it does not depend on the names of the bound variables and is determined by the de Bruijn form alone), output "result: <canonical printed form> (transitions: <number of transitions>)".

[Output format]
- Output the lines described in [Processing] in input order. Every line ends with LF and has no trailing spaces. No empty lines are output.
- An error line has the form "error: <reason>", and the reason is one of the following 16 kinds (replace each part in < > as described; ' is the character ' itself).
  column <column>: unexpected character '<character>'
  column <column>: expected term
  column <column>: expected variable
  column <column>: expected macro name
  column <column>: expected '.'
  column <column>: expected ')'
  column <column>: expected '='
  column <column>: expected ';'
  column <column>: unexpected '<string of the token>'
  unknown command <command name>
  bad argument
  unbound macro <name>
  reserved name <name>
  recursive definition of <name>
  free variable <variable name> in definition of <name>
  <name> is used by <name>
- The lines that are not errors have the following forms.
  defined <name>, redefined <name>, removed <name> (let, unlet)
  <name> = <printed form of a term>, (none) (macros)
  step <k> (<kind>): <printed form of a term> (reduce, skireduce, when the display mode is on)
  step <k> (<kind of transition>): <printed form of the code> [env <count>, stack <count>] (kam, when the display mode is on)
  result: <printed form of a term> (steps: <number of steps>), result: <printed form of a term> (transitions: <number of transitions>)
  no normal form within <L> steps, no result within <L> transitions
  yes, no, unknown (equal, alpha)
  printed form of a term (expand, subst, debruijn, ski), list of free variables or (none) (fv), integer (size, depth), printed form of a type or not typable (type), result of reading back a Church value (church)

[Constraints]
- The number of input lines is at most 1000.
- The digit sequence of a numeral shorthand token has at most 3 characters, and its value is at most 100.
- The number of user-defined macros is always at most 100.
- Every term that appears during the processing of a command (expanded terms, intermediate and resulting terms of reduction and substitution, SKI terms, the code of the Krivine machine and the term represented by its stopped state, and so on) has size at most 10000 and depth at most 200 (in SKI terms, a constant counts as size 1 and depth 1, the same as a variable). Every type that appears during the processing of type has size (1 for a type variable; for a function type A -> B, the size of A plus the size of B plus 1) at most 10000 and depth (1 for a type variable; for a function type A -> B, the larger of the depth of A and the depth of B plus 1) at most 200.
- Over the whole input, the total of the number of contractions performed in reduce, equal, church and skireduce and the number of transitions performed in kam is at most 100000.
