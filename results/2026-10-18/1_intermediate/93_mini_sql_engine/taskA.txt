[Overview]
Write a small SQL database engine. The program reads SQL statements, each ending with ;, one after another from standard input, executes table creation (CREATE TABLE) and deletion (DROP TABLE), row insertion (INSERT), update (UPDATE), deletion (DELETE) and queries (SELECT), and writes the results to standard output. There are two column types, integer (INT) and string (TEXT), and a cell that has no value is represented by NULL. Queries support column selection and aliases, inner joins and left outer joins, filtering with WHERE, three-valued logic including NULL, IN, BETWEEN and LIKE, aggregation with GROUP BY and HAVING, sorting by multiple keys, DISTINCT, and LIMIT and OFFSET, and the result is printed as a table enclosed in ruled lines. Each statement is checked before it is executed; if there is an error such as an unknown table or column, an ambiguous column, a type mismatch or a duplicate primary key, the error is reported and the statement is not executed.

[Input format]
The input consists of multiple lines. Each line is a string of 0 to 200 characters consisting only of ASCII printable characters (character codes 32 to 126), and ends with LF.
The input is a sequence of statements delimited by the rules of Section 2. A single statement may span multiple lines, and one line may contain multiple statements.
The last line of the input is the 5 characters EXIT;, and this is the statement that marks the end of the input (the EXIT statement, Section 4). When the part before it is split into statements by the rules of Section 2, only spaces, newlines and comments remain after the ; of the last statement. Also, there is no EXIT statement before the last line.

[Processing]
Split the input into statements by the rules of Section 2, and process them one at a time, starting from the first statement. For each statement, perform lexical analysis (Section 3), parsing (Section 4), checking and execution, in this order (checking and execution are described in Sections 10 to 14). A statement whose only token is ; (an empty statement) does nothing. When the EXIT statement is reached, finish processing without printing anything.
If an error is found at any point of the processing, print the single line "ERROR: <reason>" and stop processing that statement. In that case the statement has no effect at all (the state of the database does not change), and nothing else is printed. For each statement, only one error is reported: the first one found in the order of the descriptions below.
Below, output strings shown in double quotes (such as error reasons) are strings that appear in the output exactly as written. However, a part enclosed in < and > inside them is a description in words; write the value it describes in its place. Double quotes are also used when defining terms.

Section 1. Values and types
- A "letter" is one of the 52 characters A to Z and a to z, a "digit" is one of the 10 characters 0 to 9, and a "space" is the ASCII space character (character code 32).
- A value is an integer, a string or NULL. A string is a sequence of 0 or more characters, each of which is a printable character other than '.
- There are two column types, INT and TEXT. A value of an INT column is an integer or NULL, and a value of a TEXT column is a string or NULL.
- The "written form" of a value: an integer is written in decimal notation (without extra leading zeros, and with a leading - for a negative number), a string is the string itself (not enclosed in '), and NULL is the 4 characters NULL.
- "Value order": two integers are compared by numeric magnitude. Two strings are compared character by character from the beginning by character code, and the string whose character code is smaller at the first differing character is the smaller one. If one is a prefix of the other, the shorter one is the smaller one. Uppercase and lowercase letters are distinguished, so, for example, the empty string, Apple, a%b, a_b, ab, apple are in this order from smallest to largest.
- "Truth value": a value used as a condition is regarded as "true" if it is a nonzero integer, "false" if it is 0, and "unknown" if it is NULL. The result of a comparison and the like represents true as 1, false as 0, and unknown as NULL.

Section 2. Statement delimiting and comments
Read the whole input character by character from the beginning, and split it into statements by the following rules.
- When a ' is read, read up to the next ' as a "string literal". A string literal is always closed within the same line as the ' that opened it. A ; or -- inside a string literal has no special meaning.
- When two consecutive - appear outside a string literal, everything from those two - to the end of the line (just before the LF) is a "comment" and is ignored. A ' or ; inside a comment is also ignored.
- A ; outside string literals and comments is the end of a statement. One statement runs from the character after the end of the previous statement (for the first statement, the beginning of the input) up to and including that ;.
For example, the two lines SELECT name and FROM t; together form one statement, and the single line CREATE TABLE a (x INT); DROP TABLE a; is two statements.

Section 3. Lexical analysis
Read the statement from the beginning and split it into a sequence of tokens by the following rules. The rules are applied in the order of their numbers.
(1) Spaces and newlines are skipped (their only role is to separate tokens).
(2) When two consecutive - appear, skip from there to the end of the line as a comment.
(3) A ' up to the next ' forms one "string" token. Its value is the string of 0 or more characters between the two '.
(4) If the current character is a digit, read as long as digits continue; the longest such part forms one "integer" token. Its value is the integer obtained by reading it as a decimal number (leading zeros are ignored).
(5) The longest part that starts with a letter or _ and is read as long as letters, digits and _ continue is one "word". If the word, with its lowercase letters converted to uppercase, is equal to one of the reserved words below, it is a "reserved word" token; otherwise it is a "name" token. That is, reserved words are case-insensitive; for example, select, Select and SELECT are all the reserved word SELECT. On the other hand, names are case-sensitive; for example, emp and Emp are different names.
(6) If the 2 characters starting at the current position are one of <> != <= >= ||, those 2 characters form one "symbol" token.
(7) If the current character is one of ( ) , . ; * / % + - = < >, that single character forms one symbol token.
(8) Any other character (such as " ! | # ? @ ~) is an error: "unexpected character '<that character>'".
The reserved words are the following 45.
  SELECT DISTINCT FROM AS JOIN INNER LEFT OUTER ON WHERE GROUP BY HAVING ORDER ASC DESC LIMIT OFFSET
  INSERT INTO VALUES UPDATE SET DELETE CREATE TABLE DROP PRIMARY KEY NOT NULL INT TEXT
  AND OR IS IN BETWEEN LIKE COUNT SUM MIN MAX AVG EXIT
Lexical analysis is performed on the whole statement before parsing. Therefore, if the statement contains characters of (8), the error of (8) is reported for the first such character, regardless of whether there is a syntax error.
The "written form" of a token is exactly the input string that was cut out as that token. The written form of a reserved word keeps the uppercase and lowercase letters as written in the input, and the written form of a string token includes the ' on both sides.

Section 4. Syntax
The token sequence of a statement must, as a whole, exactly match a "statement" of the following grammar. "{ X }" means zero or more repetitions of X, "[ X ]" means that X may be omitted, and a "|" standing alone means "or" (a single | is not a token of the language; the token || is always written as two adjacent bars). "::=" separates the symbol being defined from its definition. In the grammar, uppercase words denote reserved word tokens, the other ASCII symbols denote that symbol token, and name, integer and string denote a token of that kind. The other lowercase words (such as column_def) are the symbols defined in the grammar.

  statement ::= [ command ] ;
  command ::= CREATE TABLE name ( column_def { , column_def } )
       | DROP TABLE name
       | INSERT INTO name [ ( name { , name } ) ] VALUES value_tuple { , value_tuple }
       | UPDATE name SET assignment { , assignment } [ WHERE expr ]
       | DELETE FROM name [ WHERE expr ]
       | query
       | EXIT
  column_def ::= name type { PRIMARY KEY | NOT NULL }
  type ::= INT | TEXT
  value_tuple ::= ( expr { , expr } )
  assignment ::= name = expr
  query ::= SELECT [ DISTINCT ] select_list FROM table { join } [ WHERE expr ]
               [ GROUP BY column_ref { , column_ref } ] [ HAVING expr ]
               [ ORDER BY order_item { , order_item } ] [ LIMIT integer [ OFFSET integer ] ]
  select_list ::= * | select_item { , select_item }
  select_item ::= expr [ [ AS ] name ]
  table ::= name [ [ AS ] name ]
  join ::= [ INNER | LEFT [ OUTER ] ] JOIN table ON expr
  order_item ::= expr [ ASC | DESC ]
  column_ref ::= name [ . name ]
  expr ::= and_expr { OR and_expr }
  and_expr ::= not_expr { AND not_expr }
  not_expr ::= NOT not_expr | comparison
  comparison ::= additive [ comp_op additive | IS [ NOT ] NULL | [ NOT ] IN ( expr { , expr } )
              | [ NOT ] BETWEEN additive AND additive | [ NOT ] LIKE additive ]
  comp_op ::= = | <> | != | < | <= | > | >=
  additive ::= multiplicative { add_op multiplicative }
  add_op ::= + | - | ||
  multiplicative ::= unary { mul_op unary }
  mul_op ::= * | / | %
  unary ::= - unary | primary
  primary ::= integer | string | NULL | column_ref | aggregate | ( expr )
  aggregate ::= COUNT ( * ) | aggregate_name ( [ DISTINCT ] expr )
  aggregate_name ::= COUNT | SUM | MIN | MAX | AVG

Notes and terms:
- Operators bind as given by the grammar. From weakest to strongest: OR, AND, NOT, comparison, additive (+ - ||), multiplicative (* / %), unary -; binary operators of the same strength associate from left to right. For example, 7 - 2 - 1 is (7 - 2) - 1, 1 + 2 * 3 is 1 + (2 * 3), -a % 3 is (-a) % 3, NOT a = b is NOT (a = b), and p OR q AND r is p OR (q AND r). Comparisons cannot be chained, so a = b = c is a syntax error.
- The AND after BETWEEN is part of the BETWEEN. For example, x BETWEEN 1 AND 3 AND y = 2 is (x BETWEEN 1 AND 3) AND (y = 2).
- A negative number is expressed with a unary - and an integer. Since two consecutive - start a comment, 2 - -3 is an expression that subtracts -3 from 2, but 2--3 is 2 followed by a comment.
- The name of a select item is called a "column alias", and the second name of a table is called a "table alias" (AS may be omitted in both).
- JOIN and INNER JOIN are called an "inner join", and LEFT JOIN and LEFT OUTER JOIN are called a "left outer join".
- A statement whose command is EXIT is called the "EXIT statement".

Syntax errors: look at the token sequence from the beginning, and let T be the first token such that the sequence from the beginning up to and including that token is not a prefix of any statement. Then the error is "syntax error at '<written form of T>'" (since a statement always ends with ;, a statement that does not match the grammar always has such a T). For example, in SELECT * FROM; T is ;, giving "syntax error at ';'". In SELECT id name title FROM emp; name can be a column alias, but title cannot follow it, giving "syntax error at 'title'". SELECT key FROM emp; gives "syntax error at 'key'", because the reserved word KEY cannot start an expression.

Section 5. Database state
The database consists of 0 or more tables, and initially there is no table. Each table has the following.
- The table name (the names are distinct within the database).
- One or more columns. Each column has a name, a type (INT or TEXT), and whether NULL is forbidden. The columns have an order, the order in which they were written in CREATE TABLE, called the "column order".
- Zero or one "primary key" column.
- Zero or more rows. Each row has one value for each column. The rows have an order, called the "row order". A row added by INSERT is appended at the end. UPDATE does not change the row order, and DELETE keeps the order of the remaining rows.
A table always satisfies the following "constraints": the value of a column that forbids NULL is not NULL. When there is a primary key column, there are no two or more rows whose values in that column are equal.

Section 6. Scopes and resolution of column references
A column reference in an expression looks for a column in the "scope" of that expression. A scope is a sequence of pairs of a "scope name" and a table.
- SELECT statement: the table after FROM and the table of each join, in the order written (however, the scope of an ON expression contains only some of the tables, as described in Section 14). The scope name is the table alias if there is one, and the table name otherwise. A table given a table alias can be referred to only by that alias, and the original table name does not become a scope name.
- UPDATE and DELETE statements: only that table, and the scope name is the table name.
- Value expressions of an INSERT statement: the scope is empty.
Column references are resolved as follows. Scope names and column names are compared case-sensitively.
- A column reference R.c of the form name . name: if the scope name R is not in the scope, the error is "unknown table <R>"; if the table of R has no column c, the error is "unknown column <R>.<c>". Otherwise it refers to the column c of the table of R.
- A column reference c consisting of a single name: count the columns named c among the columns of all tables in the scope; if there are 0, the error is "unknown column <c>", and if there are 2 or more, the error is "ambiguous column <c>". If there is exactly 1, it refers to that column.
The column referred to by a column reference is distinguished by which column of the table of which scope name in the scope it is. For example, when the same table is used twice with the aliases a and b, a.id and b.id are different columns.
The "written form" of a column reference is the string formed by joining the written names (for R.c, with a . between them), as in c or R.c.

Section 7. Checking expressions
Before the value of an expression is computed, the expression is checked by the following procedure "check", which determines its "type". There are three types: INT, TEXT and the "NULL type". Two types are said to be "compatible" when they are equal or one of them is the NULL type.
Checking is done under a scope (Section 6) and the following two settings.
- Aggregates: aggregates may be written (aggregates allowed) or may not be written (aggregates not allowed).
- Grouping: "on" or "off". When it is on, the grouping columns (Section 14) have been determined.
check does the following for each kind of expression. "Check a subexpression" means performing check on that subexpression (recursively); an error found inside it is reported at that moment.
(a) The type of an integer is INT, the type of a string is TEXT, and the type of NULL is the NULL type.
(b) A column reference is resolved by the method of Section 6. Next, if grouping is on, this column reference is not inside the argument of an aggregate, and the column it refers to is none of the grouping columns, the error is "column <written form of the column reference> is not grouped". The type is the type of that column.
(c) ( expr ): check the inner expression. The type is the type of the inner expression.
(d) Unary -: check the subexpression; if its type is not compatible with INT, the error is "type mismatch for -". The type is INT.
(e) The binary operations + - * / %: check the left and then the right subexpression, then examine, left and then right, whether the type is compatible with INT; if it is not, the error is "type mismatch for <operator>". The type is INT. || likewise examines whether the types are compatible with TEXT (the error is "type mismatch for ||"), and the type is TEXT.
(f) Comparison operators: check the left and then the right subexpression; if the left and right types are not compatible, the error is "type mismatch for <written form of the comparison operator>" (<> and != are as written). The type is INT.
(g) IS NULL and IS NOT NULL: check the subexpression. The subexpression may have any type. The type is INT.
(h) IN and NOT IN: check the left expression and then the expressions in the parentheses (from left to right), then examine the types of the expressions in the parentheses from left to right; if one is not compatible with the type of the left expression, the error is "type mismatch for IN". The type is INT.
(i) BETWEEN and NOT BETWEEN: check the left expression, the expression after BETWEEN and the expression after AND, in this order, then examine, for the expression after BETWEEN and then the expression after AND, whether its type is compatible with the type of the left expression; if it is not, the error is "type mismatch for BETWEEN". The type is INT.
(j) LIKE and NOT LIKE: check the left and then the right subexpression, then examine, left and then right, whether the type is compatible with TEXT; if it is not, the error is "type mismatch for LIKE". The type is INT.
(k) NOT: check the subexpression; if its type is not compatible with INT, the error is "type mismatch for NOT". AND and OR: check the left and then the right subexpression, then examine, left and then right, whether the type is compatible with INT; if it is not, the error is "type mismatch for AND" or "type mismatch for OR". The type is INT in all these cases.
(l) Aggregates: first, if the setting is aggregates not allowed, or if this aggregate is inside the argument of another aggregate, the error is "misuse of aggregate <aggregate name>" (the aggregate name is written in uppercase letters). The type of COUNT(*) is INT. For the other aggregates, check the argument expression (its inside is "inside the argument of an aggregate"); for SUM and AVG, if the type of the argument is not compatible with INT, the error is "type mismatch for SUM" or "type mismatch for AVG". The type is INT for COUNT, SUM and AVG, and the type of the argument for MIN and MAX.
For example, in 'x' + nosuch, the left 'x' is checked before the right nosuch is resolved, so "unknown column nosuch" is reported. In (name + 1) + nosuch (where name is a TEXT column), "type mismatch for +" is found first, while checking the left subexpression.
Checking a "condition": for the expression after WHERE, ON or HAVING, after performing check, if its type is not compatible with INT, the error is "type mismatch for WHERE", "type mismatch for ON" or "type mismatch for HAVING", respectively.

Section 8. Values of expressions
Given the value of each column of the scope, the value of an expression is determined as follows.
- An integer, a string and NULL have that value, a column reference has the value of the column it refers to, and ( expr ) has the value of the inner expression.
- Unary -: NULL if the value is NULL; otherwise the integer with its sign reversed.
- + - *: NULL if either side is NULL; otherwise the integer sum, difference or product.
- / and %: NULL if either side is NULL, or if the right value is 0. Otherwise, a / b is the integer obtained by discarding the fractional part of a divided by b (rounding toward 0), and a % b is a - b * (a / b). For example, 7 / 2 = 3, -7 / 2 = -3, 7 / -2 = -3, 7 % 3 = 1, -7 % 3 = -1, and 7 % -3 = 1.
- ||: NULL if either side is NULL; otherwise the string formed by the left string followed by the right string.
- Comparison operators: NULL if either side is NULL. Otherwise, 1 if the left and right sides are in that relation in value order (= is equal, <> and != are not equal, and < <= > >= are the respective order relations), and 0 if they are not.
- x IS NULL is 1 if x is NULL, and 0 otherwise. x IS NOT NULL is the opposite.
- x IN (v1, ..., vk): NULL if x is NULL. Otherwise, 1 if among v1, ..., vk there is one that is not NULL and is equal to x; if there is none, NULL if there is a NULL among v1, ..., vk, and 0 otherwise.
- x BETWEEN a AND b has the same value as (x >= a) AND (x <= b) (the AND follows the rule below).
- x LIKE p: NULL if either x or p is NULL. Otherwise, 1 if the whole string x matches the pattern p, and 0 if it does not. In the pattern, % matches any string of 0 or more characters, _ matches any single character, and any other character matches only that character itself (uppercase and lowercase letters are distinguished). For example, 'banana' LIKE '%an%' and 'a%b' LIKE 'a_b' are 1, and 'Apple' LIKE 'a%' and '' LIKE '_' are 0.
- The values of NOT IN, NOT BETWEEN and NOT LIKE are the values of IN, BETWEEN and LIKE, respectively, with NOT applied.
- NOT x is NULL if x is unknown, 0 if it is true, and 1 if it is false.
- x AND y is 0 if either one is false; otherwise NULL if either one is unknown; and 1 if both are true.
- x OR y is 1 if either one is true; otherwise NULL if either one is unknown; and 0 if both are false.
- The values of aggregates are determined by Section 9.
For example, NULL = NULL, NULL <> 1 and 1 + NULL are all NULL, NULL IS NULL is 1, 0 AND NULL is 0, 1 OR NULL is 1, and 5 AND 7 is 1.

Section 9. Aggregates
The value of an aggregate is determined over the rows of a group (Section 14) as follows. COUNT(*) is the number of rows of the group. For the other aggregates, compute the value of the argument expression for each row of the group, and remove the NULLs. If DISTINCT is present, additionally, of values that are equal and occur 2 or more times, keep only one. For the remaining values:
- COUNT is the number of values (0 if there are 0 values).
- SUM is the sum of the values.
- MIN and MAX are the smallest and the largest value in value order.
- AVG is the integer obtained by dividing the sum of the values by the number of values and discarding the fractional part (rounding toward 0). For example, if the values are -1, -1, -1, -2, -2, -2, then -9 / 6 = -1.5, so it is -1.
- SUM, MIN, MAX and AVG are NULL if 0 values remain.

Section 10. CREATE TABLE and DROP TABLE
CREATE TABLE examines the following in order.
(1) If a table with the same name already exists, the error is "table <table name> already exists".
(2) Examine the column definitions from left to right. If the column name is equal to the name of an earlier column definition, the error is "duplicate column <column name>". Next, if the number of PRIMARY KEY written up to this column definition (including those inside this column definition) has reached 2 or more, the error is "multiple primary keys".
If there is no error, create a table with no rows and print "Table <table name> created.". The column with PRIMARY KEY written is the primary key column. The primary key column and the columns with NOT NULL written forbid NULL (NOT NULL may be written two or more times in the same column definition).
DROP TABLE: if there is no table with that name, the error is "unknown table <table name>". If there is, delete that table together with its rows, and print "Table <table name> dropped.".

Section 11. INSERT
INSERT is performed in the following order.
(1) If there is no table with that name, the error is "unknown table <table name>".
(2) If there is a list of column names, examine the names from left to right: if the table has no column with that name, the error is "unknown column <name>"; if it is equal to an earlier name in the list, the error is "duplicate column <name>". The columns written in the list, in the order written, are the "target columns". If there is no list, all columns of the table, in column order, are the target columns.
(3) Examine the value tuples from left to right. If the number of expressions in a value tuple differs from the number of target columns, the error is "expected <number of target columns> values, got <number of expressions>". Otherwise, check the expressions of that value tuple one at a time from left to right, with an empty scope, aggregates not allowed and grouping off (Section 7), and right after checking each expression, if its type is not compatible with the type of the corresponding target column (the i-th target column for the i-th expression), the error is "type mismatch for column <target column name>" (the next expression is checked after that).
(4) Create a new row for each value tuple. The values of the target columns are the values of the corresponding expressions, and the values of the other columns are NULL.
(5) Let the "modified table" be the table with the new rows appended at the end of its rows in the order of the value tuples, and perform the constraint check (Section 13) for the new rows.
(6) If there is no error, replace the table with the modified table, and print "<count> rows inserted.". The count is the number of rows added; when it is 1, print "1 row inserted.".

Section 12. UPDATE and DELETE
UPDATE is performed in the following order.
(1) If there is no table with that name, the error is "unknown table <table name>".
(2) Examine the column names of the SET assignments from left to right: if the table has no column with that name, the error is "unknown column <name>"; if it is equal to the column name of an earlier assignment, the error is "duplicate column <name>".
(3) Check the assignment expressions one at a time from left to right, with that table as the scope, aggregates not allowed and grouping off, and right after checking each expression, if its type is not compatible with the type of the assigned column, the error is "type mismatch for column <column name>" (the next expression is checked after that).
(4) If there is a WHERE, check its expression as a condition (Section 7) with the same settings as in (3).
(5) The rows of the table for which the value of the WHERE expression is true (all rows if there is no WHERE) are the "target rows". For each target row, compute all the assignment expressions with the values of that row before the update, and replace the value of each assigned column with the corresponding result. So, for example, SET a = b, b = a swaps the values of a and b. Let the table obtained this way be the "modified table", and perform the constraint check (Section 13) for the target rows.
(6) If there is no error, replace the table with the modified table, and print "<count> rows updated.". The count is the number of target rows (rows whose values did not change are also counted); when it is 1, print "1 row updated.".
DELETE: if there is no table with that name, the error is "unknown table <table name>". Next, if there is a WHERE, check its expression as a condition with the same settings as for UPDATE. If there is no error, delete the rows for which the value of the WHERE expression is true (all rows if there is no WHERE), and print "<count> rows deleted." ("1 row deleted." when the count is 1). The count is the number of rows deleted.

Section 13. Constraint check
For INSERT and UPDATE, in the modified table, examine the rows to be checked (the new rows for INSERT, the target rows for UPDATE) one at a time in row order, and for each row examine (1) and then (2) below.
(1) Look at each column in column order; if the value of a column that forbids NULL is NULL, the error is "NULL value in column <column name>".
(2) If there is a primary key column and the modified table has another row whose primary key value is equal to that of this row (regardless of whether that row is one of the rows to be checked, and of whether it comes before or after this row), the error is "duplicate primary key <written form of that value>".
The first error found is reported. Since duplicate primary keys are judged on the modified table, for example, in a table whose primary key id has the values 1, 2 and 3, UPDATE t SET id = id + 1; is not an error.

Section 14. SELECT
Checking is done in the following order.
(1) Examine the table after FROM and the table of each join, in the order written. If there is no table with that name, the error is "unknown table <table name>". If its scope name (Section 6) is equal to the scope name of a table examined earlier in this statement, the error is "duplicate table name <scope name>". For the table of a join, next check its ON expression as a condition, with the tables examined up to that point (including this table) as the scope, aggregates not allowed and grouping off.
(2) If there is a WHERE, check its expression as a condition, with all tables as the scope, aggregates not allowed and grouping off.
(3) If there is a GROUP BY, resolve its column references from left to right by the method of Section 6 (the scope is all tables). The columns referred to are the "grouping columns".
(4) A query to which any of the following applies is called an "aggregate query": it has a GROUP BY; it has a HAVING; an aggregate is written somewhere in a select item or an order item (including inside the argument of an aggregate). The settings for the checks in (5) to (7) below are: all tables as the scope, aggregates allowed, and grouping "on" for an aggregate query and "off" otherwise.
(5) When the select list is *, take the tables of the scope in scope order and the columns of each table in column order, and regard the select list as a sequence of select items, one for each column, whose expression is only the column reference R.c formed from the scope name R of that table and the column name c (however, the written form of this column reference is only the column name c). Check the expressions of the select items from left to right.
(6) If there is a HAVING, check its expression as a condition.
(7) Examine the order items from left to right, and determine the "key" of each.
  - When the expression consists of a single integer token, let its value be k. If k is not at least 1 and at most the number of select items, the error is "ORDER BY position <k> is out of range" (k is written in decimal notation). Otherwise, the key is the value of the k-th select item.
  - When the expression consists of a single name token and there is a select item with a column alias equal to that name, the key is the value of the leftmost such select item.
  - Otherwise, check the expression; the key is the value of that expression.
  For example, ORDER BY 2 sorts by the 2nd select item, but ORDER BY (2) and ORDER BY 1 + 1 sort by a constant.

Execution is done in the following order.
(1) Joins: the rows of the table after FROM, in row order, form the initial "row list". For each join in turn, for each row L of the row list (in list order), examine each row R of the join's table in row order, and if the value of the ON expression is true for the row combining L and R, add that combined row to a new row list. In a left outer join, if there is no R for which the value of the ON expression is true for L, add the row combining L with a row in which all columns of the join's table are NULL. The new row list built this way is used for the next join.
(2) If there is a WHERE, keep only the rows of the row list for which the value of the WHERE expression is true.
(3) In an aggregate query, divide the rows into groups. If there is a GROUP BY, rows whose values of all grouping columns are equal are gathered into one group (in this comparison, NULLs are regarded as equal to each other). The groups are ordered by the order in which the first row of each group appears in the row list. If there is no GROUP BY, the entire row list (it may have 0 rows) is one group. If there is a HAVING, keep only the groups for which the value of the HAVING expression is true. Then create one "result row" from each group. Here, the value of an aggregate is computed over the rows of that group by the method of Section 9, and the value of a column reference outside the arguments of aggregates is the value of that grouping column (which is common within the group).
  For a query that is not an aggregate query, create one result row from each row of the row list.
  A result row holds the value of each select item (the "output values") and the value of the key of each order item.
(4) Sorting: if there is an ORDER BY, sort the result rows by comparing them by the 1st key, then, if equal, by the 2nd key, and so on. With ASC (also when it is omitted) the smaller one in value order comes first, and with DESC the larger one comes first. Here NULL is regarded as smaller than any value, and NULLs are regarded as equal to each other (so NULL comes first with ASC and last with DESC). Result rows whose keys are all equal keep their order from before the sort.
(5) If there is a DISTINCT, look at the result rows from the front, and remove each one whose output values are all equal to the output values of some earlier result row (in this comparison, NULLs are regarded as equal to each other).
(6) If there is OFFSET m, remove the first m result rows (all of them if there are fewer than m). If there is LIMIT n, keep only the first n.
(7) Print the remaining result rows in the format of Section 15.
A sort key may be an expression that is not in the select list. Since DISTINCT is done after sorting, the result row that appears first after sorting is the one that remains. Column aliases can be referred to only in ORDER BY; they cannot be referred to in WHERE, GROUP BY or HAVING.

Section 15. Result table
The result table has one column for each select item (for *, the select items regarded in Section 14 (5)), and each column has the following heading and type.
- Heading: the column alias if there is one. Otherwise, when the expression consists only of a column reference (a single name token, or the three tokens name . name), the heading is the column name (the name after the . if there is one). Each column of * also has the column name. Otherwise, it is the string formed by concatenating the written forms of the tokens of the expression in order, where a single space is inserted between two adjacent tokens only when neither of them is a symbol token (that is, each is a reserved word, a name, an integer or a string). For example, the heading of the select item count ( * ) is count(*), of SUM( e.salary )*2 is SUM(e.salary)*2, of x IS NOT NULL is x IS NOT NULL, of name || '!' is name||'!', and of (id) is (id).
- Type: the type of the expression of the select item (Section 7).
The string of each cell is the written form of the value (Section 1). The "width" of each column is the maximum of the lengths of the column's heading and of all cell strings to be printed in it (result rows removed by LIMIT and OFFSET are not included). The output consists of the following lines.
(1) Separator line: + followed, for each column, by (width + 2) characters - and then a +.
(2) Heading line: | followed, for each column, by one space, the heading padded with spaces on its right to the length of the width, one space, and |.
(3) Separator line.
(4) One line for each result row: the same form as the heading line, with the cell string written instead of the heading. However, for a column of type INT, the cell string is padded with spaces on its left to the length of the width (right-aligned). For columns of type TEXT and of the NULL type, it is padded with spaces on its right, like the heading (left-aligned).
(5) Separator line.
(6) "(<number of result rows> rows)". However, when the number of result rows is 1, "(1 row)". Here the number of result rows is the number of lines printed in (4) (result rows removed by LIMIT and OFFSET are not counted).
When there are 0 result rows, the separator line of (5) immediately follows the separator line of (3). For example, if there are two columns with the headings id (INT) and name (TEXT), and the output values of the result rows are 7 and Ann, and 12 and NULL, the following 7 lines are printed.
+----+------+
| id | name |
+----+------+
|  7 | Ann  |
| 12 | NULL |
+----+------+
(2 rows)

[Output format]
- Print the lines described in [Processing], in statement order. Every line ends with LF. No empty line is printed.
- The output of each statement is as follows.
  CREATE TABLE: "Table <table name> created."
  DROP TABLE: "Table <table name> dropped."
  INSERT: "<count> rows inserted." ("1 row inserted." when the count is 1)
  UPDATE: "<count> rows updated." ("1 row updated." when the count is 1)
  DELETE: "<count> rows deleted." ("1 row deleted." when the count is 1)
  SELECT: the result table (Section 15)
  Empty statement and EXIT statement: nothing is printed.
- An error is the single line "ERROR: <reason>", where the reason is one of the following 16 kinds (replace the parts in < > as described; ' is the character ' itself).
  unexpected character '<character>'
  syntax error at '<written form of the token>'
  table <table name> already exists
  unknown table <name>
  duplicate column <column name>
  multiple primary keys
  duplicate table name <scope name>
  unknown column <written form of the column reference>
  ambiguous column <column name>
  type mismatch for <operator etc.>
  misuse of aggregate <aggregate name>
  column <written form of the column reference> is not grouped
  ORDER BY position <integer> is out of range
  expected <count> values, got <count>
  NULL value in column <column name>
  duplicate primary key <written form of the value>
- What follows "type mismatch for" is one of - + * / % || = <> != < <= > >= IN BETWEEN LIKE NOT AND OR SUM AVG WHERE ON HAVING, or "column <column name>".

[Constraints]
- The input has at most 1000 lines, and at most 500 statements (including empty statements and the EXIT statement).
- An integer token has at most 10 characters, and its value is at most 1000000000. A sequence of digits is never immediately followed by a letter or _ (for example, a sequence such as 12ab does not appear).
- A name token has at most 30 characters, and the value of a string token has at most 50 characters.
- The number of tables is always at most 20, the number of columns of one table is at most 10, and the number of rows is always at most 200.
- In the joins of a SELECT, the number of pairs of L and R examined for one join is at most 100000.
- The absolute value of every integer that appears during the computation of an expression (including the sums of aggregates) is always at most 10^15. The length of a string value is always at most 200.

[Example]
Input:
CREATE TABLE fruit (id INT PRIMARY KEY, name TEXT NOT NULL, price INT);
INSERT INTO fruit VALUES (1, 'apple', 120), (2, 'banana', NULL),
  (3, 'cherry', 300);  -- this statement spans two lines
INSERT INTO fruit VALUES (4, 'date', 80), (3, 'elder', 50);
SELECT name, price * 2 AS double, price / 7 FROM fruit ORDER BY price DESC;
UPDATE fruit SET price = price + 10 WHERE price < 200 OR name LIKE 'b%';
CREATE TABLE sale (fruit_id INT, qty INT);
INSERT INTO sale VALUES (1, 5), (3, 2), (1, 4), (9, 1);
SELECT f.name, COUNT(s.qty) AS n, SUM(s.qty) FROM fruit f LEFT JOIN sale s ON s.fruit_id = f.id GROUP BY f.name ORDER BY n DESC, 1;
SELECT name FROM fruit WHERE qty > 1;
select id from fruit where name = 1;
EXIT;

Output:
Table fruit created.
3 rows inserted.
ERROR: duplicate primary key 3
+--------+--------+---------+
| name   | double | price/7 |
+--------+--------+---------+
| cherry |    600 |      42 |
| apple  |    240 |      17 |
| banana |   NULL |    NULL |
+--------+--------+---------+
(3 rows)
2 rows updated.
Table sale created.
4 rows inserted.
+--------+---+------------+
| name   | n | SUM(s.qty) |
+--------+---+------------+
| apple  | 2 |          9 |
| cherry | 1 |          2 |
| banana | 0 |       NULL |
+--------+---+------------+
(3 rows)
ERROR: unknown column qty
ERROR: type mismatch for =

The INSERT on lines 2 to 3 is one statement spanning two lines. In the INSERT on line 4, the primary key 3 of the second value tuple duplicates an existing row, so the row with id 4 is not inserted either. When the rows are sorted in descending order of price, NULL comes last with DESC. price / 7 is the value of 300 / 7 and of 120 / 7 with the fractional part discarded. The value of the WHERE of the UPDATE is 1 OR 0, true, for apple, NULL OR 1, true, for banana, and 0 OR 0, false, for cherry, so 2 rows are updated (the price of banana is NULL + 10, so it remains NULL). In the join, there is no fruit corresponding to the sale with fruit_id 9, and there is no sale corresponding to banana, so the left outer join produces a row of banana with all columns of s NULL. COUNT(s.qty) does not count NULL, so the n of banana is 0. The 1 in ORDER BY n DESC, 1 denotes the 1st select item (f.name). The last two statements are errors because fruit has no column qty, and because the TEXT name is compared with the INT 1.
