[Overview]
Write a program that solves network flow problems on a directed graph, and related combinatorial optimization problems, with algorithms whose procedures are specified in full detail. The program reads a sequence of commands from standard input and handles: registering and modifying vertices, edges (capacity, cost, lower bound) and demands; maximum flow by the Edmonds-Karp method, Dinic's method and the capacity scaling method; augmenting along one augmenting path at a time; minimum cut; capacity sensitivity analysis; minimum-cost flow by the successive shortest path method using the Bellman-Ford method; routes that share no edge or no vertex; decomposition of a flow into paths and cycles; flow verification; feasibility testing of circulations with lower bounds and demands, and minimum-cost circulations; maximum matching and minimum vertex cover in bipartite graphs by Kuhn's method; and the assignment problem. It writes the results to standard output. Because every search order and every tie-breaking choice is specified, the output is uniquely determined, down to the flow on each edge.

[Input format]
The first line contains the number of commands N. Each of the following N lines contains one command. A command consists of a command name and zero or more arguments, separated by single ASCII spaces; there are no leading or trailing spaces and no empty lines. There are the following 22 commands (only EDGE has two forms).

  NODE x1 x2 ... xk
  EDGE u v c
  EDGE u v c w
  LOWER e l
  CAP e c
  COST e w
  DEMAND x d
  RESET
  CLEAR
  SHOW
  AUGMENT s t
  MAXFLOW s t
  DINIC s t
  SCALING s t
  MINCUT s t
  SENSITIVITY s t
  MINCOST s t k
  DISJOINT s t mode
  DECOMPOSE
  VERIFY
  CIRCULATION mode
  MATCH A B P
  ASSIGN mode n a1 a2 ... ar

The arguments mean the following.
- x1 through xk, u, v, x, s and t are vertex names. A name is a string consisting of one letter (A to Z and a to z) followed by zero or more letters or digits (0 to 9). Uppercase and lowercase letters are distinguished.
- c and l are integers >= 0, w and d are integers, and e is an integer >= 0 (specifying an edge number). Negative integers are written with a leading "-".
- k of MINCOST is either an integer >= 0 or the word MAX.
- mode is the word EDGE or VERTEX for DISJOINT, ANY or MINCOST for CIRCULATION, and MIN or MAX for ASSIGN.
- A and B of MATCH each consist of one or more names separated by "," (ASCII comma). P is either the single character "-" (ASCII hyphen) or one or more "pairs" separated by ",". A pair is two names joined by "-" (example: a1-x2).
- n of ASSIGN is an integer >= 0, and each of a1 through ar is either an integer or the single lowercase letter x.
- k of NODE and r of ASSIGN are symbols denoting the number of values on that line; they are not written in the input. r may differ from n*n.
- Every integer is written in decimal without extra leading zeros (0 is written as "0", and "-0" does not occur).
It is guaranteed that every line follows this format and the ranges in [Constraints].

[Processing]
Process the commands in order starting from the first line, and output the result of each command according to [Output format]. Test the errors listed under "Checks" in the description of each command in the listed order; output only the line of the first error that applies, and do nothing else for that command (change no state at all). If no error applies, perform the "Processing".

--- Network
- The program holds one network. The network consists of a sequence of vertices, a sequence of edges, the demand of each vertex, the flow on each edge, and the "flow owner". Initially (and after CLEAR) there are no vertices and no edges, and the flow owner is "none".
- Each vertex has a name, and the names are distinct. Vertices are numbered from 1 in the order they were added, and increasing order of these numbers is called "vertex order". Each vertex has an integer "demand"; the demand of a vertex when it is added is 0.
- Each edge has a start vertex and an end vertex (distinct vertices), a capacity (an integer >= 0), a cost (an integer), a lower bound (an integer from 0 to the capacity inclusive) and a flow (an integer from 0 to the capacity inclusive). Edges are numbered from 1 in the order they were added; this number is called the "edge number". Below, M denotes the number of edges. Several edges may have the same start vertex and end vertex.
- The flow owner is one of "none", "flow from s to t" (s and t are distinct vertices, and the direction matters) and "circulation", and represents the command that produced the current flows. When the owner is "none", the flow on every edge is 0.
- For a vertex x, out(x) denotes the sum of the flows on the edges whose start vertex is x, and in(x) the sum of the flows on the edges whose end vertex is x. When the owner is "flow from s to t", out(s)-in(s) is called its "flow value". The sum of (flow)*(cost) over all edges is called the "total cost".
- Only CIRCULATION and VERIFY use lower bounds and demands in their computation. AUGMENT, MAXFLOW, DINIC, SCALING, MINCUT, SENSITIVITY, MINCOST and DISJOINT ignore lower bounds and demands.

--- Common checks
- "Check vertex x" means: if there is no vertex named x, output "ERROR UNKNOWN NODE <x>".
- "Check edge e" means: if e is not between 1 and M inclusive, output "ERROR UNKNOWN EDGE <e>" (<e> as written in the input).
- "Check endpoints s, t" means: check vertex s and vertex t in this order, and then, if s and t are the same name, output "ERROR SAME NODE".

--- Working networks and arcs
The algorithms below run either on the network itself or on a "working network" built for each command. A working network also consists of vertices and numbered edges, and each edge has a start vertex, an end vertex, a capacity, a cost and a flow. When running on the network itself, ignore the lower bounds, use its capacities, costs and flows as they are, and overwrite its flows.
- Each edge (start vertex u, end vertex v, capacity c, cost w, flow f) creates two "arcs". The "forward arc" goes from u to v, with residual capacity c-f and cost w. The "backward arc" goes from v to u, with residual capacity f and cost -w. An arc whose residual capacity is positive is called a "usable arc".
- The "arc list" of a vertex x consists of the forward arcs of the edges whose start vertex is x, in increasing order of edge number, followed by the backward arcs of the edges whose end vertex is x, in increasing order of edge number. These are all the arcs leaving x.
- The "global arc list" consists of the forward arcs of all edges in increasing order of edge number, followed by the backward arcs of all edges in increasing order of edge number.
- A sequence of arcs a1, a2, ..., aL (L>=1) in which the start vertex of a1 is s and the end vertex of each ai is the start vertex of a(i+1) is called a "path" starting at s. To "push" an amount delta along a path means, for each arc of the path, to add delta to the flow of its edge if it is a forward arc, or to subtract delta from the flow of its edge if it is a backward arc. The minimum of the residual capacities of the arcs of a path is called the "bottleneck" of the path.
- The "path notation" of a path is the name of the start vertex of the path followed, for i=1, 2, ..., L in this order, by "<sign><edge number>" and "the name of the end vertex of ai", all separated by single spaces. The sign is "+" for a forward arc and "-" for a backward arc (example: s +1 a -3 b +5 t).

--- Breadth-first search
A "breadth-first search" from a vertex s (with a threshold Delta; Delta=1 unless stated otherwise) is as follows. Mark s as visited, set the "level" of s to 0, and create a queue containing only s. Until the queue is empty, remove a vertex x from the front, and examine the arcs a of the arc list of x in order: if the residual capacity of a is at least Delta and the end vertex y of a is not visited, mark y as visited, set the level of y to (level of x)+1, set the "parent arc" of y to a, and append y to the back of the queue. The vertices that have been marked as visited are said to be "reachable" from s. When t is reachable, the path formed by the arcs passed while following parent arcs from t until reaching s (repeatedly moving to the start vertex of the parent arc of the current vertex), arranged in reverse order, is called the "shortest augmenting path".

--- Single augmentation and the augmenting path method
- A "single augmentation" from s to t (with a threshold Delta) means: perform a breadth-first search from s (threshold Delta), and if t is reachable, push the bottleneck of the shortest augmenting path along it. If t is not reachable, do nothing.
- The "augmenting path method" (Edmonds-Karp method) from s to t means repeating single augmentations (Delta=1) until t is no longer reachable.

--- Dinic's method
Dinic's method from s to t repeats the following "phase".
At the start of a phase, perform a breadth-first search from s. If t is not reachable, Dinic's method ends. If it is reachable, use the levels computed by this search throughout this phase (vertices that are not reachable have no level). Prepare a "pointer" p(x)=1 for each vertex x, let the path P be empty and the current vertex x be s, and repeatedly perform the first applicable one of (1) to (3) below until the phase ends.
(1) If x is t, push the bottleneck of P along P, make P empty, and set x back to s.
(2) If p(x) is greater than the number of arcs in the arc list of x: if x is s, end this phase. Otherwise, remove the last arc of P from P, make the start vertex of that arc the new x, and add 1 to p(x).
(3) Let a be the p(x)-th arc of the arc list of x, and y the end vertex of a. If a is a usable arc (at that moment), y has a level, and the level of y equals (level of x)+1, append a to the end of P and set x to y. Otherwise, add 1 to p(x).

--- Capacity scaling method
In the capacity scaling method from s to t, let Delta be the largest power of two (1, 2, 4, 8, ...) that is at most the maximum capacity of the edges of the network (if there are no edges, or the maximum capacity is 1 or less, Delta=1). While Delta>=1, repeat single augmentations (threshold Delta) until t is no longer reachable, and then halve Delta (if Delta=1, it becomes 0 and the method ends). The amount pushed is the bottleneck of the shortest augmenting path, which is at least Delta.

--- Shortest path computation and the successive shortest path method
A "shortest path computation" (Bellman-Ford method) from s is as follows. First, build the sequence Q by taking, in order, only the usable arcs from the global arc list at that moment (Q does not change during this computation). Set the distance dist to 0 for s and to "undefined" for all other vertices. Repeat the following "pass" until a pass in which no update occurs at all. In a pass, examine the arcs a of Q in order; letting x be the start vertex of a, y its end vertex and kappa its cost, if dist(x) is not undefined and either dist(y) is undefined or dist(x)+kappa<dist(y), update dist(y) to dist(x)+kappa and the parent arc of y to a. A dist changed during a pass is used immediately when examining later arcs in the same pass. When the computation finishes, if dist(t) is not undefined, the path formed by the arcs passed while following parent arcs from t until reaching s, arranged in reverse order, is called the "cheapest path", and dist(t) is called its "unit cost".
The "successive shortest path method" from s to t (with a target amount K, where K is an integer >= 0 or "unlimited") starts with the total pushed amount F and the total cost C both set to 0, and, while F<K (without any limit if unlimited), repeats the following. Perform the shortest path computation, and end if dist(t) is undefined. Otherwise, let delta be the smaller of the bottleneck of the cheapest path and K-F (the bottleneck if unlimited), push delta along the cheapest path, add delta to F, and add delta*(unit cost) to C. The pushed paths are numbered from 1 in the order they were pushed.
In this program, the successive shortest path method is always started from the state in which all flows are 0, after the negative cycle check (below) has confirmed that there is no negative cycle. Therefore the passes always terminate, and following the parent arcs always reaches s.

--- Negative cycle check
A sequence of two or more edges e1, ..., eL in which the end vertex of each ei is the start vertex of e(i+1), the end vertex of eL is the start vertex of e1, and the start vertices of e1, ..., eL are pairwise distinct is called a "cycle". The "negative cycle check" determines whether, among the cycles consisting only of edges that satisfy the specified condition, there is one whose sum of costs is negative.

--- Flow decomposition
Split the flows of a (working) network into "flow paths" and "cycles" by the following procedure. First, make a copy g(i) of the flow of each edge i, and compute, for each vertex x, b(x)=(sum of g over the edges whose start vertex is x)-(sum of g over the edges whose end vertex is x). While there is an edge with positive g, repeat (1) to (3) below.
(1) If there is a vertex with positive b, let x0 be the first such vertex in vertex order. Otherwise, let x0 be the start vertex of the edge with the smallest edge number among the edges with positive g.
(2) Let the vertex sequence W be (x0) and the edge sequence E be empty.
(3) Let x be the last vertex of W, let i be the edge with the smallest edge number among the edges whose start vertex is x and whose g is positive (such an edge always exists), let y be the end vertex of i, and append i to the end of E.
  - If y is the same as the q-th vertex of W, the edges of E from the q-th through the last form a cycle that starts at y and returns to y. Let delta be the minimum g of these edges, subtract delta from g of these edges, record this cycle (starting at y) together with delta, and return to (1).
  - Otherwise, append y to the end of W. If b(y)<0, the edges of E form a flow path from x0 to y. Let delta be the smallest of the minimum g of the edges of E, b(x0) and -b(y); subtract delta from g of every edge of E, subtract delta from b(x0), add delta to b(y), record this flow path (starting at x0) together with delta, and return to (1). If b(y)>=0, repeat (3).
Arrange the recorded flow paths and cycles in the order they were recorded. The flow paths are numbered from 1 in the order they were recorded, and so are the cycles, separately. The path notation of a flow path is the path notation of the path that starts at x0 and consists of the forward arcs of the edges of the flow path (all edges of E at that time) in order. The path notation of a cycle is the path notation of the path that starts at y and consists of the forward arcs of the edges of the cycle (the edges of E from the q-th through the last at that time) in order; it starts with y and ends with y.

--- Starting a flow
The step "start a flow from s to t" performed by AUGMENT, MAXFLOW, DINIC, SCALING and MINCUT is as follows. If the flow owner is not "flow from s to t" (with the same s and the same t), set the flow on every edge to 0. Then set the flow owner to "flow from s to t", and take the flow value at that moment as the "start value". In other words, if a flow with the same s and t remains, it is inherited and continued; otherwise the flow starts from 0.

--- Flow list
To output the "flow list" means to output "FLOW <edge number> <start vertex> <end vertex> <flow>/<capacity>" for each edge in edge-number order (nothing is output if M=0).

--- Commands that edit vertices and edges

NODE x1 x2 ... xk
Checks: Examine the names from x1 onward in order; if some xi has the same name as an existing vertex or as a name written earlier in this command, "ERROR DUPLICATE NODE <xi>" for the first such xi. Next, if the number of vertices plus k is greater than 20, "ERROR TOO MANY NODES".
Processing: Add x1, x2, ..., xk as vertices in this order (with demand 0), and output "NODE added=<k> total=<number of vertices after adding>".

EDGE u v c
EDGE u v c w
Checks: Check vertex u and vertex v in this order. If u and v are the same name, "ERROR SELF LOOP". If M is 60, "ERROR TOO MANY EDGES".
Processing: Add an edge with start vertex u, end vertex v, capacity c, cost w (0 if w is not written), lower bound 0 and flow 0 as edge number M+1. The flow owner does not change. Output "EDGE <edge number> <u> <v> cap=<c> cost=<cost>".

LOWER e l
Checks: Check edge e. If l is greater than the capacity of that edge, "ERROR BAD BOUND".
Processing: Set the lower bound of edge e to l, and output "LOWER <e> low=<l> cap=<capacity>". The flow does not change.

CAP e c
Checks: Check edge e. If c is less than the lower bound of that edge, "ERROR BAD BOUND". If c is less than the flow of that edge, "ERROR BELOW FLOW".
Processing: Set the capacity of edge e to c, and output "CAP <e> low=<lower bound> cap=<c>".

COST e w
Checks: Check edge e.
Processing: Set the cost of edge e to w, and output "COST <e> cost=<w>".

DEMAND x d
Checks: Check vertex x.
Processing: Set the demand of x to d, and output "DEMAND <x> <d> total=<sum of the demands of all vertices>". The demand is the value that in(x)-out(x) should equal in the result of CIRCULATION (a negative demand represents the amount sent out of that vertex).

RESET
Processing: Let r be the number of edges whose flow is not 0; output "RESET edges=<r>", set the flow of every edge to 0, and set the flow owner to "none".

CLEAR
Processing: Output "CLEAR nodes=<number of vertices> edges=<M>", remove all vertices and edges, and return to the initial state (no vertices or edges, and the flow owner is "none").

SHOW
Processing: Output the following lines in order.
  "NETWORK nodes=<number of vertices> edges=<M>"
  "STATE none" if the flow owner is "none", "STATE circulation cost=<total cost>" if it is "circulation", or "STATE flow <s> <t> value=<flow value> cost=<total cost>" if it is "flow from s to t"
  for each vertex x in vertex order, "NODE <x> demand=<demand> out=<out(x)> in=<in(x)>"
  for each edge in edge-number order, "EDGE <edge number> <start vertex> <end vertex> cap=<capacity> cost=<cost> low=<lower bound> flow=<flow>"

--- Maximum flow and minimum cut commands

AUGMENT s t
Checks: Check endpoints s, t.
Processing: Start a flow from s to t, and perform a single augmentation (Delta=1) from s to t on the network. If an amount was pushed, output "AUGMENT <s> <t> value=<flow value after pushing> amount=<amount pushed> <path notation of the shortest augmenting path>"; if t was not reachable, output "AUGMENT <s> <t> value=<flow value> none".

MAXFLOW s t
Checks: Check endpoints s, t.
Processing: Start a flow from s to t, and perform the augmenting path method from s to t on the network. The paths pushed by single augmentations are numbered from 1 in the order they were pushed. Output "MAXFLOW <s> <t> value=<flow value at the end> start=<start value> paths=<number of paths>", then, for each path in order, "AUG <number> amount=<amount pushed> <path notation>", and finally the flow list.

DINIC s t
Checks: Check endpoints s, t.
Processing: Start a flow from s to t, and perform Dinic's method from s to t on the network. The phases in which t was reachable are numbered from 1 in order, and the paths pushed in (1) are numbered from 1 in the order they were pushed (the numbering continues across phases). Output "DINIC <s> <t> value=<flow value at the end> start=<start value> phases=<number of phases> paths=<number of paths>", then, for each path in order, "AUG <number> phase=<number of the phase in which the path was pushed> amount=<amount pushed> <path notation>", and finally the flow list.

SCALING s t
Checks: Check endpoints s, t.
Processing: Start a flow from s to t, and perform the capacity scaling method from s to t on the network. The paths pushed by single augmentations are numbered from 1 in the order they were pushed. Output "SCALING <s> <t> value=<flow value at the end> start=<start value> paths=<number of paths>", then, for each path in order, "AUG <number> delta=<Delta at that time> amount=<amount pushed> <path notation>", and finally the flow list.

MINCUT s t
Checks: Check endpoints s, t.
Processing: Start a flow from s to t, and perform the augmenting path method from s to t on the network (up to this point it is the same as MAXFLOW, but the paths are not output). Then perform a breadth-first search from s, and let S be the set of vertices reachable from s. The edges whose start vertex belongs to S and whose end vertex does not belong to S (including edges with capacity 0) are the "cut edges". Output the following lines in order.
  "MINCUT <s> <t> value=<flow value> edges=<number of cut edges>"
  "SOURCE <the vertices belonging to S, in vertex order, separated by single spaces>"
  "SINK <the vertices not belonging to S, in vertex order, separated by single spaces>"
  for each cut edge in edge-number order, "CUT <edge number> <start vertex> <end vertex> <capacity>"
S always contains s and never contains t. The sum of the capacities of the cut edges equals the flow value.

SENSITIVITY s t
Checks: Check endpoints s, t.
Processing: Using only the vertices, edges and capacities of a network (not its flows, lower bounds or costs), the flow value obtained by performing the augmenting path method from s to t on a working copy with all flows set to 0 is called the "maximum flow amount" of that network (the maximum flow amount is the same whichever method is used to find it). Let V be the maximum flow amount of the original network. For each edge i, if the maximum flow amount of the network in which only the capacity of edge i is increased by 1 is greater than V, edge i is "up-effective". If the capacity of edge i is at least 1 and the maximum flow amount of the network in which only that capacity is decreased by 1 is less than V, edge i is "down-effective". Letting U be the number of up-effective edges and D the number of down-effective edges, output "SENSITIVITY <s> <t> value=<V> up=<U> down=<D>", then, for each edge that is up-effective or down-effective (or both), in edge-number order, "CRITICAL <edge number> <start vertex> <end vertex> up=<yes if up-effective, otherwise no> down=<yes if down-effective, otherwise no>". The state of the network does not change at all.

--- Minimum-cost flow and route commands

MINCOST s t k
Checks: Check endpoints s, t. Next, perform the negative cycle check on the edges whose capacity is at least 1; if there is a cycle whose sum of costs is negative, "ERROR NEGATIVE CYCLE".
Processing: On a working network that has the same vertices and edges as the network (with the same edge numbers, start vertices, end vertices, capacities and costs) and all flows 0, perform the successive shortest path method from s to t with target amount K=k (unlimited if k is MAX).
  If k is an integer and F<k at the end, output only "MINCOST <s> <t> k=<k> infeasible max=<F>", and do not change the network.
  Otherwise, replace the flow of each edge of the network with the flow of the edge with the same number in the working network, and set the flow owner to "flow from s to t". Output "MINCOST <s> <t> k=<k> flow=<F> cost=<C>" (<k> is the integer as written in the input, or MAX), then, for each pushed path in order, "AUG <number> amount=<delta> cost=<unit cost> <path notation of the cheapest path>", and finally the flow list.

DISJOINT s t mode
Checks: Check endpoints s, t.
Processing: Build the working network described next, perform the augmenting path method from s to t with all flows set to 0, and split the resulting flows into flow paths and cycles by flow decomposition. Discard the cycles, and number only the flow paths from 1 in the order they were recorded. Output "DISJOINT <s> <t> <mode> count=<number of flow paths>", then, for each flow path in order, "PATH <number> <path notation of the flow path>". The state of the network does not change at all.
  When mode is EDGE: use a working network that has the same vertices as the network and, for each edge of the network, an edge with the same edge number, start vertex and end vertex, whose capacity is 0 if the capacity in the network is 0 and 1 if it is 1 or more. The number of flow paths equals the maximum number of routes from s to t that share no edge.
  When mode is VERTEX: split each vertex x other than s and t into two vertices, "the entrance of x" and "the exit of x". s and t are not split; each of them is itself both its entrance and its exit. As edges, first, for i=1, ..., M in order, place an edge from "the exit of the start vertex" to "the entrance of the end vertex" of network edge i, with the same edge number i (its capacity is 0 or 1, as for EDGE); then, for each vertex x other than s and t in vertex order, place an edge of capacity 1 from "the entrance of x" to "the exit of x", with edge numbers M+1, M+2, ... in this order. In this case, the path notation of a flow path is the name of s followed, only for the edges of the flow path whose edge number is at most M, in order, by "+<edge number>" and "the name of the original vertex of the end vertex of that edge" (edges with edge numbers greater than M and their end vertices are not written). The number of flow paths equals the maximum number of routes from s to t that share no vertex other than s and t.
In either mode, the only vertex whose b can be positive in the flow decomposition is s.

DECOMPOSE
Processing: Split the current flows of the network into flow paths and cycles by flow decomposition. Letting P be the number of flow paths and Q the number of cycles, output "DECOMPOSE paths=<P> cycles=<Q>", then, in the order they were recorded, "PATH <flow path number> amount=<delta> <path notation of the flow path>" for a flow path, or "CYCLE <cycle number> amount=<delta> <path notation of the cycle>" for a cycle. The state of the network does not change at all.

--- Verification and circulation commands

VERIFY
Processing: Examine the current flows and collect the following violations in order.
  First, for each edge in edge-number order, if the flow is less than the lower bound, "LOW <edge number> flow=<flow> low=<lower bound>".
  Next, for each vertex x in vertex order, if x has a required value h(x) as defined below and in(x)-out(x) differs from h(x), "BALANCE <x> net=<in(x)-out(x)> need=<h(x)>". If the flow owner is "flow from s to t", s and t have no required value, and the required value of every other vertex is 0. If the owner is "none" or "circulation", the required value of each vertex is its demand.
If there are no violations, output "VERIFY ok". Otherwise, output "VERIFY violations=<number of violations>", followed by the collected violation lines in the order they were collected.

CIRCULATION mode
Checks: If mode is MINCOST, perform the negative cycle check on the edges whose (capacity)-(lower bound) is at least 1; if there is a cycle whose sum of costs is negative, "ERROR NEGATIVE CYCLE".
Processing: If the sum Sigma of the demands of all vertices is not 0, output "CIRCULATION infeasible unbalanced=<Sigma>" and finish.
If Sigma=0, compute, for each vertex x, r(x)=(demand of x)-(sum of the lower bounds of the edges whose end vertex is x)+(sum of the lower bounds of the edges whose start vertex is x), and build the following working network. Its vertices are all vertices of the network plus two new vertices, the "super source" and the "super sink". Its edges are numbered from 1 in the following order.
  (1) the network edges i=1, ..., M, with the same edge number, start vertex, end vertex and cost, and with capacity (capacity)-(lower bound)
  (2) for each vertex x with r(x)<0, in vertex order, an edge from the super source to x with capacity -r(x) and cost 0
  (3) for each vertex x with r(x)>0, in vertex order, an edge from x to the super sink with capacity r(x) and cost 0
With all flows set to 0, perform the augmenting path method from the super source to the super sink if mode is ANY, or the successive shortest path method (unlimited) from the super source to the super sink if mode is MINCOST. Let R be the sum of r(x) over the vertices with r(x)>0, and A the sum of the flows on the edges of (3).
  If A<R, output "CIRCULATION infeasible required=<R> achieved=<A>", and then output "CUT <vertex> <vertex> ...", listing in vertex order the vertices of the network that are reachable by a breadth-first search from the super source (the super source and the super sink are not included) (there is always at least one such vertex). The network does not change.
  If A=R, replace the flow of each edge i of the network with (lower bound of edge i)+(flow of edge i of the working network), set the flow owner to "circulation", output "CIRCULATION feasible required=<R> cost=<total cost>", and then output the flow list. At this point, lower bound<=flow<=capacity holds for every edge, and in(x)-out(x)=demand holds for every vertex.

--- Commands unrelated to the network
MATCH and ASSIGN are computations that use only the values written in the command; they neither use nor change the state of the network (names may be the same as vertices of the network).

MATCH A B P
Checks: Examine the names of A from left to right; if the same name appears earlier in A, "ERROR DUPLICATE VERTEX <name>". Next, examine the names of B from left to right; if the same name appears earlier in B, or the same name is in A, "ERROR DUPLICATE VERTEX <name>". Next, examine the pairs of P from left to right; for a pair a-b, if a is not contained in A, "ERROR UNKNOWN VERTEX <a>"; if b is not contained in B, "ERROR UNKNOWN VERTEX <b>"; if the same pair (with the same a and the same b) appears earlier, "ERROR DUPLICATE PAIR <a>-<b>".
Processing: Find a maximum matching of the bipartite graph whose "left vertices" are the names of A, whose "right vertices" are the names of B, and whose "links" are the pairs a-b of P, each connecting left vertex a and right vertex b, by the following Kuhn's method. Initially no vertex has a "partner". Take the left vertices a one at a time in the order of A; each time, make the set of "examined right vertices" empty, and then perform the procedure try(a) once (even if the result is failure, simply proceed to the next left vertex).
  try(a): Go through the pairs of P from left to right; each time a pair whose left vertex is a is seen, if the right vertex b of that pair is not examined at that moment, mark b as examined, and if b has no partner, or try(a') succeeds for the partner a' of b, set the partner of b to a and the partner of a to b, and finish with success. If no success has occurred after going through the last pair, finish with failure.
Let K be the number of left vertices that have a partner, and call the left vertices without a partner "free left vertices". Next, determine the vertex set Z as follows. All free left vertices belong to Z. A right vertex b linked to a left vertex a belonging to Z belongs to Z if b is not the partner of a. If a right vertex b belonging to Z has a partner, that partner also belongs to Z. Continue until no more vertices are added to Z. The left vertices not belonging to Z in the order of A, followed by the right vertices belonging to Z in the order of B, form the "cover". Output the following lines in order.
  "MATCH size=<K> left=<number of names in A> right=<number of names in B>"
  for each left vertex a that has a partner, in the order of A, "PAIR <a> <partner of a>"
  "FREE <the free left vertices in the order of A, joined by ","> <the right vertices without a partner in the order of B, joined by ",">" (each part is "-" if there are none)
  "COVER size=<number of vertices in the cover> <the vertices of the cover separated by single spaces>" ("COVER size=0" if the number is 0)
  only when there is at least one free left vertex, "HALL <the left vertices belonging to Z in the order of A, joined by ","> <the right vertices belonging to Z in the order of B, joined by "," ("-" if there are none)>"
The cover is a minimum vertex set that contains at least one end of every link, and its size equals K. The right vertices on the HALL line are all of the right vertices linked to the left vertices on the HALL line, and their number is less than the number of those left vertices.

ASSIGN mode n a1 a2 ... ar
Checks: If n<1 or n>8, "ERROR BAD SIZE". If r differs from n*n, "ERROR BAD LENGTH".
Processing: Arrange the values in a table of n rows and n columns, where the value of the cell in row i, column j is v(i,j)=a((i-1)*n+j). A cell whose value is x is a "forbidden cell". An assignment p=(p(1),p(2),...,p(n)) that assigns one column p(i) to each row i so that no two rows are assigned the same column, and in which (i,p(i)) is not a forbidden cell for any i, is called an "admissible assignment", and v(1,p(1))+v(2,p(2))+...+v(n,p(n)) is called its "sum".
  If there is no admissible assignment, output "ASSIGN <mode> n=<n> infeasible".
  Otherwise, let T be the minimum sum if mode is MIN, or the maximum sum if mode is MAX, and let q be the number of admissible assignments whose sum is T. Among the admissible assignments whose sum is T, choose the one whose (p(1),p(2),...,p(n)) is lexicographically smallest (the one with the smallest p(1); if those are equal, the one with the smallest p(2); ...), output "ASSIGN <mode> n=<n> total=<T> optimal=<q>", and then, for i=1, ..., n in order, output "MATE <i> <p(i)> <v(i,p(i))>".

- Integers are written in decimal without extra leading zeros, and negative numbers have a leading "-" (0 is written as "0").

In MAXFLOW in this example, the second shortest augmenting path traverses edge 2 backward (-2), cancelling what the first path pushed from a to d. MINCUT inherits the flow that remains for the same s and t (no augmenting path is left) and finds the cut. In MATCH, q becomes a free left vertex because, when trying to add q, the partner p of x cannot be moved elsewhere. In ASSIGN, there are two assignments with sum 3, (2,3,1) and (3,1,2), and the lexicographically smaller one, (2,3,1), is chosen.
