[Overview]
Write a program that manages a project schedule. The program reads a sequence of commands from standard input, executes them one at a time from the first, and writes the results to standard output. It registers work items (tasks) and dependencies between tasks (of three kinds, finish-to-start, start-to-start and finish-to-finish, each with a lag in days), and performs schedule computation by the critical path method (earliest and latest start and finish days, total float, free float), enumeration of critical paths, mapping onto a calendar of working days, a character-based Gantt chart, resource leveling, aggregation of PERT three-point estimates, crashing that shortens the project one day at a time starting from the cheapest task, what-if evaluation with changed durations, comparison with a baseline, and more.

[Input format]
The first line contains the number of commands N, and each of the following N lines contains one command. Each line consists of a command name followed by zero or more arguments, separated by single spaces. There is no whitespace at the beginning or end of a line, and there are no empty lines. There are the following 29 command formats (the parts other than the command name are argument names).
TASK id duration resource units
DEP a b kind lag
UNDEP a b
REMOVE id
NOTBEFORE id day
CRASHCOST id maxdays cost
UNCRASH id
PERT id o m p
CAPACITY resource limit

The arguments are written as follows.
- id, a and b are task names. A task name is a string of 1 to 8 characters that starts with an uppercase letter (A-Z) and consists only of uppercase letters and digits (0-9).
- resource is a resource name. A resource name is a string of 1 to 8 characters consisting only of lowercase letters (a-z).
- kind is one of FS, SS and FF.
- lag is an integer. A negative number is written with a leading "-", and a number of 0 or more has no sign.
- date is a 10-character string of the form "YYYY-MM-DD". YYYY is 4 digits representing a year from 2000 to 2199. MM and DD are 2 digits each (00 to 99), and the pair of MM and DD does not necessarily represent an existing month and day.
- The other arguments (duration, units, day, maxdays, cost, o, m, p, limit, budget) are integers of 0 or more.
All integers are written in decimal, and a nonzero number has no leading zeros. It is guaranteed that every line follows these formats and the [Constraints].

[Processing]
Process the commands one at a time in input order, writing the output of each command immediately. Below, a string enclosed in double quotes is a string that appears in the output exactly as written. However, a part enclosed in < and >, such as <id> or <T>, is replaced by its value. One that encloses an argument name of that command (<id> in the description of TASK, <limit> in the description of LEVEL, and so on) stands for the string of that argument; the others stand for values defined in the description.

* Name order
Task names are compared with each other, and resource names with each other, in the following order. Compare the character codes (ASCII) one character at a time from the beginning; the name whose code is smaller at the first differing character comes first. When one name equals the beginning of the other, the shorter one comes first. Digits come before uppercase letters. For example, A1, A10, A2, AB, B are in this order. Below, "name order" means this order. A "name list" is the string obtained by arranging some names in name order and joining them with single spaces.

* State
A task has the following information.
- Name. Two or more tasks with the same name never exist at the same time.
- Base duration, resource name and units. These are the duration, resource and units given by TASK. The units are the amount of the resource that the task uses on each day it works.
- Start constraint day. Initially 0.
- Crash data. Initially none; CRASHCOST sets it to a pair of a crash limit (maximum number of days) and a cost per day.
- Crashed days. Initially 0.
- Three-point estimate. Initially none; PERT sets it to a triple of an optimistic value o, a most likely value m and a pessimistic value p.
The duration of a task is its base duration minus its crashed days. Below, the plain word "duration" refers to this value.

A dependency is a tuple of a predecessor task a, a successor task b, a kind kind and a lag lag. It is written "dependency a -> b"; a is called a predecessor of b, and b is called a successor of a. There is at most one dependency for the same ordered pair (a, b). a -> b and b -> a are different dependencies, and both may exist at the same time.

In addition, there are the start date (initially unset), the set of holidays (initially empty), the deadline (initially unset), a capacity for each resource (initially unset for every resource) and the baseline (initially none). Initially there are no tasks and no dependencies.

The commands that change the state are TASK, DEP, UNDEP, REMOVE, NOTBEFORE, CRASHCOST, UNCRASH, PERT, CAPACITY, START, HOLIDAY, DEADLINE, CRASH (changes only the crashed days) and BASELINE (changes only the baseline). The other commands do not change the state.

* Days and dates
Schedules are computed in units of days. Days are numbered with integers of 0 or more, and day 0 is the first day of the project. A task whose start day is day s and whose duration is d works for the d days from day s to day s+d-1. Then s+d is called the finish day of the task (the finish day is the number of the day after the last day worked).

The calendar is the Gregorian calendar. A year y is a leap year when y is a multiple of 4 and not a multiple of 100, or when y is a multiple of 400. February has 29 days in a leap year and 28 days otherwise. January 1, 2000 is a Saturday. A date string YYYY-MM-DD represents an existing date when MM is between 01 and 12 inclusive and DD is between 01 and the number of days in that month inclusive.

Dates are output in the form "YYYY-MM-DD Www". YYYY is the year in 4 digits, MM and DD are the month and the day in 2 digits (with a leading 0 when they have one digit), and Www is one of Mon, Tue, Wed, Thu, Fri, Sat, Sun representing the day of the week (Monday through Sunday, in this order) (example: 2026-04-06 Mon). Below, this form is called the "date notation".

A day from Monday to Friday that is not in the set of holidays is called a working day. When the start date S is set, the date of day k is the (k+1)-th day when the working days on or after S (including S) are listed in date order. For example, if S is a Saturday, day 0 is the first working day on or after S.

* Cycles
Following dependencies in the direction from predecessor to successor and returning to the original task is called a cycle. Whether a cycle exists is determined as follows. Starting from the set of all tasks, repeatedly remove "a task that has no predecessor among the remaining tasks" until no such task remains. Let R be the set of tasks that finally remains (R does not depend on the order of removal). If R is empty, there is no cycle; otherwise there is a cycle.

When there is a cycle, one cycle is chosen as follows. Every task in R has at least one predecessor in R. Let x0 be the first task in R in name order, and for i = 0, 1, 2, ... in this order, let x(i+1) be the first, in name order, of "the predecessors of x(i) that are in R". When x(i+1) equals a task x(j) (0 <= j <= i) that has already appeared, stop there. Then the sequence of tasks x(j), x(i), x(i-1), ..., x(j+1) is a cycle, with a dependency in this direction between each pair of adjacent tasks and from the last task to x(j). Rotate this sequence so that the task that comes first in name order within it is at the front, and call the result C1, C2, ..., Ck; the string obtained by joining C1, C2, ..., Ck, C1 with " -> " is called the "cycle notation".
For example, if the only dependencies are the four A -> B, B -> C, C -> B, C -> D, then A is removed and R is B, C, D; x0 = B, x1 = C, x2 = B and the procedure stops there, so the cycle notation is "B -> C -> B".

* Schedule computation
When there is no cycle, compute for each task t the earliest start ES(t), the earliest finish EF(t), the latest start LS(t), the latest finish LF(t), the total float TF(t) and the free float, and the project duration T, as follows. This is called "schedule computation", and the computed values together are called the "schedule". d(t) is the duration of task t. However, WHATIF, DRAG and CRASH sometimes perform schedule computation with the duration of some task temporarily set to another value; in that case that value is used as d(t) for that task.

A dependency a -> b (lag L) represents the following condition, according to its kind.
- FS (finish-to-start): start day of b >= finish day of a + L
- SS (start-to-start): start day of b >= start day of a + L
- FF (finish-to-finish): finish day of b >= finish day of a + L

Forward pass: proceeding through the tasks whose predecessors all have ES and EF determined, set ES(t) to the maximum of the following values, and EF(t) = ES(t) + d(t).
- the start constraint day of t
- for each dependency a -> t (lag L): EF(a)+L if the kind is FS, ES(a)+L if SS, EF(a)+L-d(t) if FF
The maximum of EF over all tasks is the project duration T.

Backward pass: proceeding through the tasks whose successors all have LS and LF determined, set LF(t) to the minimum of the following values, and LS(t) = LF(t) - d(t).
- T
- for each dependency t -> b (lag L): LS(b)-L if the kind is FS, LS(b)-L+d(t) if SS, LF(b)-L if FF

TF(t) = LS(t) - ES(t) (this value is always 0 or more). A task with TF(t) = 0 is called a "critical task".

The "margin" of a dependency a -> b (lag L) is ES(b)-EF(a)-L if the kind is FS, ES(b)-ES(a)-L if SS, and EF(b)-EF(a)-L if FF (this value is always 0 or more). The free float of task t is the minimum of T-EF(t) and the margins of the dependencies that have t as the predecessor.

* Critical paths
A dependency a -> b is called a "critical dependency" when a and b are both critical tasks and its margin is 0. A critical path is a sequence of critical tasks t1, t2, ..., tk (k >= 1) that satisfies all of the following conditions.
- There is no critical dependency that has t1 as the successor.
- There is no critical dependency that has tk as the predecessor.
- For each i with 1 <= i < k, ti -> t(i+1) is a critical dependency.
Critical paths are compared by comparing task names from the beginning; the path whose task name at the first differing position comes first in name order comes first (one is never a prefix of the other). When critical paths are listed, all critical paths are listed in this order. The string obtained by joining t1, t2, ..., tk with " -> " (just t1 when k is 1) is called the "path notation".

* Writing numbers
- Signed notation: if the integer x is 0 or more, write "+" followed by x; if it is negative, write "-" followed by the absolute value of x (examples: +0, +3, -2).
- Two-decimal notation: for a rational number x of 0 or more, let h be the largest integer not exceeding 100x; write the quotient of h divided by 100, ".", and the remainder of h divided by 100 in 2 digits (with a leading 0 when it has one digit). In other words, the digits from the third decimal place on are truncated (examples: 30.16 for x = 181/6, 7.50 for 7.5, 0.00 for 0). Compute x exactly as a fraction.

* Errors
When a command results in an error, output only the single line "error: <MESSAGE>" and do not change the state at all. In the description of each command, the error conditions are listed in the order in which they are checked, and the MESSAGE of the first condition that applies is used. The MESSAGE when no task named x exists is "unknown task <x>"; below, this condition is written simply as "unknown task".

The following 14 commands are called "analysis commands": CPM, CRITICAL, SLACK, DRAG, STATS, CALENDAR, GANTT, LEVEL, LOAD, PERTSUM, CRASH, WHATIF, BASELINE, VARIANCE. An analysis command first performs the following common checks in this order.
1. There are no tasks: MESSAGE is "no tasks".
2. There is a cycle: MESSAGE is "cycle " followed by the cycle notation (example: error: cycle A -> B -> D -> A).
If no common check applies, the command-specific error conditions given in the description of each command are checked. If none of those applies either, schedule computation is performed with the current durations, and then the processing of the command is performed. In the descriptions of the analysis commands below, ES, EF, LS, LF, TF, free float, T and critical refer to this schedule unless stated otherwise.

* Processing of each command
TASK id duration resource units
If a task named id already exists, it is an error ("task <id> already exists"). Otherwise, add a task with name id, base duration duration, resource name resource and units units (the other information takes the initial values described above), and output "task <id> added".

DEP a b kind lag
The error conditions, in order, are: no task named a exists ("unknown task <a>"), no task named b exists ("unknown task <b>"), a and b are the same ("self dependency <a>"), and a dependency a -> b already exists (even if the kind or lag differs; "dependency <a> -> <b> already exists"). If there is no error, add the dependency a -> b (kind kind, lag lag) and output "dependency <a> -> <b> <kind><L> added" (<L> is the signed notation of lag) (examples: dependency A -> B FS+0 added, dependency C -> D SS-2 added). A dependency that creates a cycle can also be added.

UNDEP a b
The error conditions, in order, are "unknown task <a>", "unknown task <b>", and no dependency a -> b exists ("no dependency <a> -> <b>"). Delete the dependency a -> b and output "dependency <a> -> <b> removed".

REMOVE id
The error condition is unknown task. Delete all dependencies that have id as the predecessor or the successor, then delete the task id, and output "task <id> removed with <k> dependencies" (<k> is the number of deleted dependencies). Write "dependencies" even when <k> is 0 or 1. The baseline does not change.

NOTBEFORE id day
The error condition is unknown task. Set the start constraint day of id to day, and output "notbefore <id> <day>".

CRASHCOST id maxdays cost
The error conditions, in order, are: unknown task, maxdays is greater than or equal to the base duration of id ("crash limit too large for <id>"), and maxdays is less than the crashed days of id ("crash limit below used days for <id>"). Set the crash data of id to crash limit maxdays and cost per day cost (replacing it if it already exists; the crashed days do not change), and output "crash <id> max <maxdays> cost <cost>".

UNCRASH id
The error condition is unknown task. Let k be the crashed days of id; output "uncrash <id> restored <k> days" and reset the crashed days to 0. Write "days" even when <k> is 0 or 1. The crash data does not change.

PERT id o m p
The error conditions, in order, are: unknown task, and o <= m <= p does not hold ("invalid estimate"). Set the three-point estimate of id to (o, m, p) (replacing it if it already exists), and output "pert <id> expected <E> variance <V>". <E> is (o+4m+p)/6 and <V> is the square of (p-o) divided by 36, each written in two-decimal notation. The three-point estimate does not change the duration of the task.

CAPACITY resource limit
Set the capacity of the resource resource to limit (replacing it if it is already set), and output "capacity <resource> <limit>". It does not matter if there is no task whose resource name is resource. This command never results in an error.

START date
HOLIDAY date
DEADLINE date
If date does not represent an existing date, it is an error ("invalid date <date>"; <date> is written as in the input). For HOLIDAY, next, if the date is already in the set of holidays, it is an error ("duplicate holiday <date>"). If there is no error, START sets the start date and DEADLINE sets the deadline to that date (replacing it if it is already set), and HOLIDAY adds the date to the set of holidays. The outputs are "start <D>", "holiday <D>" and "deadline <D>" respectively (<D> is the date notation of that date). Saturdays and Sundays can also be added to the set of holidays (this does not affect whether a day is a working day).

LIST
Output "tasks <n>, dependencies <m>, holidays <h>" (<n> is the number of tasks, <m> the number of dependencies, and <h> the number of elements in the set of holidays), then, for each task in name order, one line "<t> duration <d> resource <r> units <u> preds <P>". <t> is the task name, <d> the duration, <r> the resource name, <u> the units, and <P> the name list of the predecessors of the task; if the task has no predecessors, <P> is "none".

SHOW id
The error condition is unknown task. Output the following 6 lines.
Line 1: "task <id> duration <d> resource <r> units <u>" (<d> is the duration, <r> the resource name, <u> the units). If the start constraint day x is not 0, append " notbefore <x>".
Line 2: "preds: " followed by each dependency x -> id, in name order of x, written in the form "<x> <K><L>" (<K> is the kind, <L> the signed notation of the lag) and joined with ", " (a comma and a single space). If there is no such dependency, the line is "preds: none".
Line 3: "succs: " followed by each dependency id -> x, in name order of x, written in the form "<x> <K><L>" and joined in the same way. If there is no such dependency, the line is "succs: none".
Line 4: "crash: max <M> used <U> cost <C>" if there is crash data (<M> is the crash limit, <U> the crashed days, <C> the cost per day), otherwise "crash: none".
Line 5: "pert: <o> <m> <p>" if there is a three-point estimate (<o>, <m>, <p> are the values of the three-point estimate), otherwise "pert: none".
Line 6: "schedule: unavailable" if there is a cycle. If there is no cycle, perform schedule computation with the current durations, and the line is "schedule: ES <es> EF <ef> LS <ls> LF <lf> TF <tf> FF <ff>" (<es>, <ef>, <ls>, <lf>, <tf>, <ff> are, in order, the ES, EF, LS, LF, TF and free float of id). If id is a critical task, append " critical".

IMPACT id
The error condition is unknown task. The tasks other than id that can be reached from id by following dependencies one or more times in the direction from predecessor to successor are called "affected tasks" (even if id is on a cycle, id itself is not included). Output "impact <id>: <L>" (<L> is the name list of the affected tasks). If there are no affected tasks, output "impact <id>: none".

CPM
Output a table of the schedule. Let W be the larger of 4 and the number of characters in the longest task name.
Line 1 is "TASK" padded on the right with spaces to W characters, followed by each of "DUR", "ES", "EF", "LS", "LF", "TF", "FF" padded on the left with spaces to 5 characters, concatenated in this order.
Then, for each task in name order, output one line consisting of the task name padded on the right with spaces to W characters, followed by each of the values of the duration, ES, EF, LS, LF, TF and free float padded on the left with spaces to 5 characters, concatenated in this order, and, for a critical task, further followed by " *".
Finally output "project duration <T>".

CRITICAL
Let k be the number of critical paths; output "critical paths: <k>", then output the path notations, one per line, in the order in which the critical paths are listed.

SLACK
For each value f that appears as the TF of a task, in increasing order, output one line "float <f>: <L>" (<L> is the name list of the tasks whose TF is f).

DRAG
For each critical task t, in name order, output one line "<t> drag <v>". <v> is T minus the project duration obtained by schedule computation with only the duration of t temporarily set to 0. <v> can also be 0 or negative.

STATS
Let n be the number of tasks and c the number of critical tasks; output the following 4 lines.
Line 1: "tasks <n>, critical <c>, dependencies <m> (FS <x>, SS <y>, FF <z>)". <m> is the number of dependencies, and <x>, <y>, <z> are the numbers of dependencies whose kind is FS, SS, FF respectively.
Line 2: "work <L>". <L> is obtained by writing "<r> <w>" for each resource name r that appears as the resource name of a task, in name order (<w> is the sum of "duration * units" over the tasks whose resource name is r), joined with ", ".
Line 3: "float total <s>, average <A>". <s> is the sum of TF over all tasks, and <A> is s/n in two-decimal notation.
Line 4: "duration <T>, critical share <P>%". <P> is 100c/n in two-decimal notation.

CALENDAR
The command-specific error condition is that the start date is not set ("no start date"). If there is no error, output the following lines.
First, for each task in increasing order of ES (in name order when ES is equal), output one line "<t> <D1> - <D2>". <t> is the task name, <D1> is the date of day ES(t), and <D2> is the date of day EF(t)-1, both written in date notation.
Next, output "project <D1> - <D2>, <T> working days, <C> calendar days". <D1> is the date of day 0 and <D2> is the date of day T-1 (both in date notation), and <C> is the number of calendar days from the date of day 0 to the date of day T-1 (both ends inclusive).
If the deadline is set, output the following one line. Let E be the date of day T-1, and let <D> be the date notation of the deadline. If E is the same day as the deadline or earlier, the line is "deadline <D> met, <X> working days to spare", where <X> is the number of working days after E and on or before the deadline (including the deadline). If E is later than the deadline, the line is "deadline <D> missed by <X> working days", where <X> is the number of working days after the deadline and on or before E (including E). Write "working days" even when <X> is 0 or 1. If the deadline is not set, this line is not output.
Finally output "holidays in span: <L>". <L> is obtained by writing the dates in the set of holidays whose day of the week is one of Monday through Friday and that are on or after the date of day 0 and on or before the date of day T-1, in date order and in date notation, joined with ", ". If there is no such date, <L> is "none".

GANTT
The command-specific error condition is that T is greater than 60 ("chart too wide (<T> days)"). If there is no error, output the following lines. Let W be the number of characters in the longest task name.
Line 1 is the concatenation of W spaces, " |", one digit for each k = 0, 1, ..., T-1 in this order that is the remainder of k divided by 10, and "|".
Then, for each task in increasing order of ES (in name order when ES is equal), output one line that is the concatenation of the task name padded on the right with spaces to W characters, " |", a bar of T characters, and "|". The (k+1)-th character of the bar (k = 0, 1, ..., T-1) is, if ES <= k < EF, "=" for a critical task and "-" for a task that is not critical. It is "." if EF <= k < LF, and a space otherwise.

LEVEL limit
Evaluate a leveling that delays the starts of tasks according to the resource capacities. The capacity of resource r is the value set by CAPACITY if it is set, and limit if it is not set; it is written C(r). The command-specific error condition is that there is a task whose units are greater than C(r) for its resource name r ("capacity <C> too small for <t>"; <t> is the first such task in name order, and <C> is C(r) of its resource).
If there is no error, determine the leveled start day S(t) and finish day F(t) of each task t by the following procedure. Initially every task is undecided, and the total usage U(r, k) for each resource r and each day k is 0. While there is an undecided task, repeat the following.
1. Among the undecided tasks whose predecessors are all decided, let t be the one with the smallest LS (the first in name order if there are several).
2. Let s0 be the maximum of the start constraint day of t and the value for each dependency a -> t (lag L) (F(a)+L if the kind is FS, S(a)+L if SS, F(a)+L-d(t) if FF).
3. Let r be the resource name of t and u its units. Let S(t) be the smallest integer s >= s0 such that U(r, k)+u <= C(r) for every day k with s <= k < s+d(t), and let F(t) = S(t)+d(t). Add u to U(r, k) for each day k with S(t) <= k < F(t), and mark t as decided.
When all tasks are decided, output the following lines.
- "level capacity <limit>: duration <T> -> <L>" (<L> is the maximum of F over all tasks).
- In the order in which the tasks were decided, one line per task "<t> start <S> finish <F> shift <X>" (<t> is the task name, <S> is S(t), <F> is F(t), and <X> is S(t)-ES(t)).
- For each resource name r that appears as the resource name of a task, in name order, one line "resource <r> capacity <C> peak <P> -> <Q>". <C> is C(r). <P> is the maximum, over days, of the daily total usage of resource r when each task uses its units every day from day ES to day EF-1. <Q> is the same maximum when each task uses them from day S to day F-1.

LOAD resource
The command-specific error condition is that there is no task whose resource name is resource ("unknown resource <resource>"). If there is no error, for each day k = 0, 1, ..., T-1, let u(k) be the sum of the units of the tasks whose resource name is resource and for which ES <= k < EF. Output "load <resource>: " followed by u(0), u(1), ..., u(T-1) separated by single spaces, then output "peak <P> on day <k>" (<P> is the maximum of u(k), and <k> is the smallest k with u(k) = P). Further, if the capacity of the resource resource has been set by CAPACITY, output "capacity <C> exceeded on <X> days" (<C> is that capacity, and <X> is the number of k with u(k) > C). Write "days" even when <X> is 0 or 1.

PERTSUM
In the order in which the critical paths are listed, output one line per path "<P>: expected <E> variance <V>". <P> is the path notation. For each task on the path, use its (o, m, p) if it has a three-point estimate, and otherwise use (d, d, d), where d is the duration of the task. <E> is the sum over the whole path of (o+4m+p)/6, and <V> is the sum over the whole path of the square of (p-o) divided by 36, each written in two-decimal notation. Compute the sums exactly as fractions and truncate only once at the end.

CRASH budget
Let the remaining budget be budget, and repeat the following procedure.
1. Perform schedule computation with the current durations (including the crashing done so far in this CRASH), and let T be its project duration. "Critical" in step 2 refers to this schedule.
2. A task that satisfies all of the following conditions is a candidate: it is critical; it has crash data; its crashed days are less than its crash limit; and schedule computation with only the duration of that task temporarily decreased by 1 gives a project duration smaller than T.
3. If there are no candidates, end the repetition with the reason "no candidate".
4. Among the candidates, let t be the one with the smallest cost per day (the first in name order if there are several), and let c be that cost. If c is greater than the remaining budget, end the repetition with the reason "insufficient budget".
5. Add 1 to the crashed days of t, subtract c from the remaining budget, and output "step <i>: <t> <d1> -> <d2>, cost <c>, project <T2>". <i> is the ordinal number of this crashing within this CRASH (counting from 1), <t> is the task name, <d1> and <d2> are the durations of t before and after the crashing, and <T2> is the project duration obtained by schedule computation with the durations after the crashing. Then go back to step 1.
When the repetition ends, output "crash done: <n> days, cost <s>, project <T0> -> <T1>, budget left <r>, <REASON>". <n> is the number of crashings, <s> is the total cost spent, <T0> is the first and <T1> the last project duration, <r> is the remaining budget, and <REASON> is the reason the repetition ended. Write "days" even when <n> is 0 or 1. The changes to the crashed days remain after the CRASH.

WHATIF id duration
The command-specific error condition is unknown task. If there is no error, compute the schedule with the current durations (before) and the schedule obtained by schedule computation with only the duration of id temporarily set to duration (after). The state is not changed.
First output "whatif <id> <d0> -> <duration>: project <T0> -> <T1>" (<d0> is the duration of id, and <T0> and <T1> are the project durations before and after).
Then, for each task for which at least one of ES, EF and TF differs between before and after, in name order, output one line consisting of the task name followed, for each of ES, EF, TF whose value differs, in this order, by " <X> <p>-><q>" (<X> is one of "ES", "EF", "TF", <p> is the value before, and <q> is the value after) (example: B ES 4->6 TF 2->0).
Finally, if the set of critical tasks differs between before and after, output "critical <L0> -> <L1>" (<L0> and <L1> are the name lists of the critical tasks before and after). If it is the same, this line is not output.

BASELINE
Save T and the name, ES and EF of each task as the baseline (replacing it if it already exists), and output "baseline saved: <n> tasks, duration <T>" (<n> is the number of tasks).

VARIANCE
The command-specific error condition is that there is no baseline ("no baseline"). If there is no error, let T0 be the project duration of the baseline, and output "variance: duration <T0> -> <T> (<S>)" (<S> is the signed notation of T-T0). Then, for each name in the union of the task names in the baseline and the current task names, in name order, output the following line. If the name is only in the baseline, "<t> removed"; if it is only among the current tasks, "<t> new" (<t> is the task name). If it is in both and ES or EF differs, "<t> start <s> finish <f>", where <s> is the current ES minus the baseline ES and <f> is the current EF minus the baseline EF, both in signed notation. If it is in both and ES and EF are both the same, output nothing. If no line about a task was output, finally output "no task changes".

[Output format]
The output of each command consists of the lines defined in [Processing], and the outputs are written in command order. When one command outputs several lines, they are output in the order described in [Processing].
All output consists of ASCII characters, and each line ends with a newline (LF). Do not put whitespace at the end of a line, and do not output empty lines. The only line with leading whitespace is the first line of GANTT.
Numbers are written in decimal, with a leading "-" for a negative number. Except in the date notation and the fractional part of the two-decimal notation, numbers have no extra leading zeros.
Unless otherwise specified, whitespace within a string is a single space.

[Constraints]
- 1 <= N <= 1000
- At most 30 tasks and at most 100 dependencies exist at the same time. The set of holidays has at most 100 elements.
- For TASK, duration is between 1 and 99 inclusive, and units is between 0 and 20 inclusive.
- lag is between -30 and 30 inclusive.
- For NOTBEFORE, day is between 0 and 200 inclusive.
- For CRASHCOST, maxdays is between 0 and 98 inclusive, and cost is between 0 and 10000 inclusive.
- For PERT, o, m and p are between 1 and 99 inclusive.
- For CAPACITY and LEVEL, limit is between 1 and 20 inclusive.
- For CRASH, budget is between 0 and 1000000 inclusive.
- For WHATIF, duration is between 1 and 99 inclusive.
- All dates computed by CALENDAR are in the range from January 1, 2000 to December 31, 2199.
- Whenever CRITICAL or PERTSUM is executed, the number of critical paths is at most 100.
- Every integer that appears during the computation has an absolute value less than 2 to the 31st power.
