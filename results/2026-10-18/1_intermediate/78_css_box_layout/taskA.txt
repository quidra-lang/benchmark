[Overview]
Write a program that computes a layout based on a CSS-like box model on an integer grid where one character is one unit. From standard input it reads, in this order, the size of the viewport (the display area), a style sheet, a document tree and a list of commands. It applies the style sheet rules to each element according to selector specificity (the cascade), arranges boxes that have margins, borders and padding according to the rules of block layout, flex layout, grid layout, relative positioning and absolute positioning, and computes the position and size of every element. Then, following the commands, it outputs a list of boxes and box details, a character drawing of the screen, the element found at a given position, style changes with re-layout, viewport size changes, and a list of elements whose content overflows. All computation is done with integers.

[Input format]
The input consists of the following four parts in this order.
- Line 1: the viewport width W and height H, separated by one space.
- Style sheet: zero or more rule lines, followed by a line consisting only of "---".
- Document: one or more element lines, followed by a line consisting only of "===".
- Commands: zero or more command lines, followed by a line consisting only of "END".
The "END" line is the last line of the input. Except for the indentation of element lines, no line has leading or trailing whitespace. There are no empty lines.

* Rule lines
A rule line is the concatenation, in this order, of a selector list, one space, "{", one space, a declaration list, one space, and "}".
A selector list is one or more selectors separated by "," followed by one space. A selector is one of the following three kinds.
- Type selector: a type name itself (example: div).
- Class selector: "." immediately followed by a class name (example: .card).
- ID selector: "#" immediately followed by an ID (example: #main).
A declaration list is one or more declarations separated by ";" followed by one space. A declaration is the concatenation, in this order, of a property name, ":", one space, and a value. A property name is a string of one or more characters consisting only of lowercase letters (a to z) and hyphens (-). A value is one or more tokens separated by single spaces; a token is a string of one or more characters consisting only of printable ASCII characters that contains no space, ";", "{" or "}". The property name may be a name not defined in [Processing], and the value may be invalid for the property ([Processing] Section 2).
Example of a rule line:
  #nav, .bar { display: flex; margin: 0 1; width: 50% }

* Element lines
An element line is the concatenation, in this order, of an indentation, a head, and an optional text part.
- The indentation is 2*d spaces, where d is the depth of the element. The first element line has depth 0, and it is the only element line of depth 0. This element is called the root. Every element line from the second on has depth at least 1 and at most the depth of the immediately preceding element line plus 1. The parent of an element of depth d (d >= 1) is the element of the last element line of depth d-1 that precedes it. In that case, the element is a child of its parent. The children of an element are ordered in the order in which they appear in the input.
- The head is the concatenation, in this order and with no whitespace, of a type name, "#", an ID, and zero or more ".class-name" parts (example: div#main.card.wide).
- If there is a text part, it follows immediately after the head as one space, a double quote character ("), the text, and a double quote character (").
A type name is a string of 1 to 10 characters that starts with a lowercase letter and consists only of lowercase letters and digits (0 to 9). An ID and a class name are strings of 1 to 12 characters that start with a lowercase letter and consist only of lowercase letters, digits and hyphens. All elements have distinct IDs, and no element has the same class name twice or more.
The text is a string of 1 to 60 characters consisting only of printable ASCII characters other than the double quote ("), and it is one or more words (strings of one or more characters containing no space) separated by single spaces. An element that has text is called a text element. A text element has no children.
The order of all elements in the order in which their element lines appear in the input is called document order.

* Command lines
A command line is a command name followed by zero or more arguments, separated by single spaces. There are the following seven commands (the parts other than the command name are argument names).
  LAYOUT
  BOX id
  RENDER
  HIT x y
  SET id property value
  VIEWPORT w h
  OVERFLOW
id is a string written by the same rules as an ID, but an element with that ID does not necessarily exist. property is a string of one or more characters consisting only of lowercase letters and hyphens. value is a sequence of one or more tokens written by the same rules as the value of a rule line (on a SET line, the whole part after the one space following property is value). x, y, w and h are integers from 0 to 999, and nonzero numbers have no leading zeros.
There may also be lines whose command name (a string of one or more uppercase letters) is none of these seven. The number and content of the arguments of such lines are unspecified.

[Processing]
First, read line 1, the style sheet and the document, and perform the layout (Section 5) once. Nothing is output at this time. Then execute the commands one by one in input order, writing each command's output immediately.
Below, strings in double quotes are strings that appear in the output as they are. However, a part enclosed in < and >, such as <id>, is replaced by the string defined in the description. All numbers are written in decimal, and negative numbers have a leading "-".

* Section 1. Properties and values
The kinds of tokens that appear in values are named as follows.
- Non-negative integer: a token of 1 to 3 characters consisting only of digits (0 to 9). It represents an integer from 0 to 999.
- Positive integer: a non-negative integer that is not 0.
- Signed integer: a non-negative integer, or a token consisting of "-" immediately followed by a non-negative integer.
- Percentage: a token consisting of a non-negative integer immediately followed by "%" (example: 50%).
- fr value: a token consisting of a positive integer immediately followed by "fr" (example: 2fr). That positive integer is called the fr factor.

Each element has one value for each of the following properties (longhand properties). In each item, what follows the colon is the valid values, and the part in parentheses at the end is the initial value.
- display: one of block, flex, grid, none (block).
- position: one of static, relative, absolute (static).
- box-sizing: one of content-box, border-box (content-box).
- width, height: one of auto, a non-negative integer, a percentage (auto).
- min-width, min-height: either a non-negative integer or a percentage (0).
- max-width, max-height: one of none, a non-negative integer, a percentage (none).
- margin-top, margin-right, margin-bottom, margin-left: a non-negative integer (0).
- padding-top, padding-right, padding-bottom, padding-left: a non-negative integer (0).
- border-top, border-right, border-bottom, border-left: either 0 or 1 (0).
- top, right, bottom, left: either auto or a signed integer (auto).
- flex-direction: one of row, row-reverse, column, column-reverse (row).
- flex-wrap: either nowrap or wrap (nowrap).
- justify-content: one of start, end, center, space-between, space-around, space-evenly (start).
- align-items: one of stretch, start, end, center (stretch).
- align-self: one of auto, stretch, start, end, center (auto).
- row-gap, column-gap: a non-negative integer (0).
- order: a signed integer (0).
- flex-grow: a non-negative integer (0).
- flex-shrink: a non-negative integer (1).
- flex-basis: one of auto, a non-negative integer, a percentage (auto).
- grid-template-columns, grid-template-rows: either none alone, or a sequence of one or more track specifications (each one of a non-negative integer, an fr value, auto) (none).
- grid-column, grid-row: one of the following five forms (auto). a, b and n are positive integers, and in the form a / b, a < b.
    auto
    a
    a / b
    a / span n
    span n
For longhand properties other than grid-template-columns, grid-template-rows, grid-column and grid-row, the value must be exactly one token. A value is valid only when its token sequence matches one of the forms written here. For example, 1234, -5, 5px and 50 % are not valid values for width, and 3 / 2 and span 0 are not valid values for grid-column.

There are also the following four shorthand properties.
- margin, padding, border: 1 to 4 tokens, each of which is valid as a value of margin-top, padding-top or border-top, respectively. With 1 token it applies to top, bottom, left and right; with 2 tokens, the first applies to top and bottom and the second to right and left; with 3 tokens, the first applies to top, the second to right and left, and the third to bottom; with 4 tokens, they apply to top, right, bottom and left in this order.
- gap: 1 or 2 non-negative integers. With 1, it applies to both row-gap and column-gap; with 2, the first applies to row-gap and the second to column-gap.
A shorthand declaration is treated as the declarations of the corresponding longhand properties (in the order -top, -right, -bottom, -left for margin, padding and border, and in the order row-gap, column-gap for gap) placed in order at its position. For example, "margin: 1 2 3" is the same as margin-top: 1, margin-right: 2, margin-bottom: 3, margin-left: 2 placed in this order. If the number of tokens is out of range, or if even one token is invalid, the whole value of that shorthand is invalid.
Longhand properties and shorthand properties together are called known properties.

* Section 2. Cascade
Among the declarations in rule lines, those whose property name is not a known property and those whose value is not valid for the property are invalid and are treated as if they did not exist.
A rule matches an element when one or more selectors in the rule's selector list match the element. A type selector matches elements whose type name is equal, a class selector matches elements that have that class name, and an ID selector matches the element whose ID is equal. The specificity of a selector is 2 for an ID selector, 1 for a class selector and 0 for a type selector. The specificity, for an element, of a rule that matches the element is the maximum specificity among the rule's selectors that match the element.
The value of each longhand property of an element is determined as follows.
(1) If a SET that specifies the value of that property for that element has ever succeeded (a SET of a shorthand property specifies the value of each corresponding longhand property), the value specified by the last such SET.
(2) Otherwise, if the rules that match the element contain valid declarations of that property (with shorthands replaced by longhand declarations), the value of the one whose rule has the largest specificity. If several have the largest specificity, the value of the one among them that is latest in the style sheet (a declaration in a rule on a later line is later, and within the same rule, one further to the right is later).
(3) Otherwise, the initial value.
There is no inheritance of values (a child does not take over its parent's values).

* Section 3. Boxes and coordinates
A coordinate is a pair of integers (x, y), where x increases to the right and y increases downward. A cell of the grid (the place of one character) is denoted by its coordinate. A rectangle whose top-left coordinate is (x, y), whose width is w and whose height is h is written "rectangle (x, y, w, h)". This rectangle contains every cell (X, Y) satisfying x <= X < x+w and y <= Y < y+h. The viewport is rectangle (0, 0, W, H).
An element is said to be displayed when its display is not none and it is either the root or its parent is displayed. A displayed element has the following four boxes (rectangles). An element that is not displayed has no boxes.
- Content box: its width is the content width cw and its height is the content height ch.
- Padding box: the content box extended upward, downward, left and right by the values of padding-top, padding-bottom, padding-left and padding-right, respectively.
- Border box: the padding box extended upward, downward, left and right by the values of border-*.
- Margin box: the border box extended upward, downward, left and right by the values of margin-*.
Hereafter, the values of an element's margin-top, margin-right, margin-bottom and margin-left are written mt, mr, mb and ml, the values of padding-* are written pt, pr, pb, pl, and the values of border-* are written bt, br, bb, bl. Also, pl+pr+bl+br is called the horizontal frame width, pt+pb+bt+bb the vertical frame width, ml+mr the horizontal margin, and mt+mb the vertical margin. The width of the border box is cw + horizontal frame width, and its height is ch + vertical frame width.
The in-flow children of an element are those of its children that are displayed and whose position is not absolute, in child order.

* Section 4. Resolving and constraining lengths
The values of width, height, min-width, min-height, max-width, max-height and flex-basis are resolved, per element, against a reference (a non-negative integer, or "indefinite") as follows. The result of resolving is an integer or "no value".
- auto and none resolve to no value.
- A non-negative integer n resolves to n.
- A percentage p% resolves to no value if the reference is indefinite, and otherwise to the quotient of (reference * p) divided by 100 (rounded down).
- Furthermore, if the result is an integer and the element's box-sizing is border-box, the frame width is subtracted from that integer, and if the result is negative it becomes 0. The frame width is the horizontal frame width for width, min-width, max-width, and for flex-basis when the main axis (Section 10) is horizontal; it is the vertical frame width otherwise.
Therefore, a resolved integer always represents a size of the content box.
The horizontal constraint for a reference X has as its lower bound min-width resolved against X (0 if no value), and as its upper bound max-width resolved against X (no upper bound if no value). The vertical constraint is defined in the same way with min-height and max-height. To clamp a value v by a constraint means: if there is an upper bound and v is greater than the upper bound, replace v with the upper bound; then, if v is less than the lower bound, replace v with the lower bound (when the lower bound is greater than the upper bound, the result is the lower bound).

* Section 5. Overall layout procedure
The layout is performed once at the start and each time a SET or VIEWPORT succeeds, and it recomputes the boxes of all displayed elements. The procedure is as follows.
(1) For every element, determine the value of each longhand property by the cascade (Section 2).
(2) If the root is displayed and the root's position is not absolute, lay out the root with width reference W and height reference H (Section 6). The root's relative position is (ml, mt) (the root's margins).
(3) Lay out the displayed elements whose position is absolute by absolute positioning (Section 12), one by one in document order.
(4) In document order, determine the final position of each displayed element (below).
Laying out an element determines that element's content width cw, its content height ch, and the relative position of each in-flow child. A relative position expresses the top-left coordinate of the element's border box as a difference from a reference point. The reference point is the top-left of the parent's border box for an element whose position is not absolute (for the root, the top-left (0, 0) of the viewport), and the top-left of the containing block (Section 12) for an absolute element. The same element may be laid out several times; its cw, ch, text lines and the relative positions of its children are those from the last time it was laid out.
The final top-left coordinate (x, y) of an element's border box is the final coordinate of the reference point plus the relative position, plus, if position is relative, the following shift (dx, dy).
- dx: the value of left if left is not auto; otherwise, if right is not auto, the value of right with its sign inverted; 0 if both are auto.
- dy: the value of top if top is not auto; otherwise, if bottom is not auto, the value of bottom with its sign inverted; 0 if both are auto.
The shift does not affect the placement of other elements (descendants move with it through the reference point). Hereafter, the "border box" and the like of a displayed element refer to those at these final coordinates.

* Section 6. Laying out an element
The procedure to lay out an element E with width reference CW (a non-negative integer) and height reference CH (a non-negative integer or indefinite) is as follows. When laying out, a content width FW or a content height FH may be given.
(1) If FW is given, cw = FW. Otherwise, cw is the value of E's width resolved against CW (or, if that is no value, max(0, CW - horizontal margin - horizontal frame width)), clamped by the horizontal constraint for CW.
(2) If FH is not given and E's height resolved against CH is not no value, FH is treated as given, with that value clamped by the vertical constraint for CH.
(3) Compute the height A of E's content. If E is a text element (even if its display is flex or grid), wrap the text at width cw (Section 7) and let A be the number of lines. If it is not a text element, lay out E's in-flow children by flex layout (Section 10) if display is flex, by grid layout (Section 11) if grid, or by block layout (Section 8) if block, and let A be the value obtained there. In these layouts, E's content-height reference K is FH if FH is given, and indefinite if not.
(4) If FH is given, ch = FH; otherwise ch is A clamped by the vertical constraint for CH.
Hereafter, E's vertical constraint for CH is called E's height constraint. Also, in each layout, the positions of children are given as distances from the top-left of E's content box. Since the top-left of E's content box is bl+pl to the right of and bt+pt below the top-left of E's border box, a child's relative position is that distance with these added.

* Section 7. Text wrapping
To wrap text at width w means to pack the words into lines in order from the first. The first word starts line 1. Each subsequent word is added to the current line with one space in between if (number of characters in the current line + 1 + number of characters in the word) is at most w; otherwise, that word starts a new line. A word longer than w is still placed on a line by itself as it is (that line is longer than w).

* Section 8. Block layout
Let cw be E's content width and K its content-height reference. Lay out E's in-flow children one at a time in order, each with width reference cw and height reference K, and stack them from top to bottom.
- The top edge of the first child's border box is that child's mt below the top edge of E's content box.
- The top edge of the border box of the second and each later child is below the bottom edge of the previous child's border box by the larger of (the previous child's mb) and (that child's mt) (collapsing of adjacent sibling margins).
- The left edge of each child's border box is that child's ml to the right of the left edge of E's content box.
A is 0 if there are no children; otherwise it is the distance from the top edge of E's content box to the bottom edge of the last child's border box, plus the last child's mb. Parent and child margins never collapse.
Here, the bottom edge of a border box is the position of its top edge plus the border box height.

* Section 9. Max-content width and distribution
For a displayed element E, the max-content width M(E) and the width contribution P(E) are defined as follows.
- P(E): E's width resolved against an indefinite reference (M(E) if no value), clamped by the horizontal constraint for an indefinite reference, plus the horizontal frame width and the horizontal margin. Since the reference is indefinite, percentages give no value.
- M(E): if E is a text element, the number of characters of the text. Otherwise, if display is flex and flex-direction is row or row-reverse, the sum of P of the in-flow children plus column-gap * (number of children - 1) (0 if there are no children). If display is grid, determine the placement of E's items and the number of columns NC by Section 11 (1), compute the column sizes by the method of Section 11 (2) with the available length U indefinite, the gap d equal to column-gap, and each item's contribution equal to that item's P; then M(E) is the sum of the column sizes plus column-gap * (NC - 1). Otherwise, the maximum of P over the in-flow children (0 if there are no children).
To distribute a non-negative integer T according to a sequence of non-negative integer weights w1, ..., wk (whose sum S is positive) means to assign to each i the quotient of (T * wi) divided by S (rounded down), and then to assign the amount by which the total of the assignments falls short of T (the remainder) one unit at a time to the entries with positive weight, in order from the first. Since the remainder is less than the number of entries with positive weight, each receives at most 1 from the remainder.

* Section 10. Flex layout
Let cw be the content width and K the content-height reference of an element E whose display is flex (a flex container). If flex-direction is row or row-reverse, the main axis is horizontal and the cross axis is vertical; if column or column-reverse, the main axis is vertical and the cross axis is horizontal. The main gap g is column-gap if the main axis is horizontal and row-gap if it is vertical. The gap between lines g' is row-gap (used only when the main axis is horizontal). The main reference is cw if the main axis is horizontal and K if it is vertical.
The items of E are E's in-flow children sorted in ascending order of their order values. Items with equal order are arranged in document order. This order is called item order. For each item I, align is E's align-items if I's align-self is auto, and I's align-self otherwise. Also, the sum of the frame width and margin along the main axis (horizontal frame width + horizontal margin if the main axis is horizontal, vertical frame width + vertical margin if vertical) is called I's outer amount o. The "cross frame width" and "cross margin" are defined in the same way for the direction of the cross axis.
I's "main-axis constraint" is the horizontal constraint for the main reference if the main axis is horizontal, and the vertical constraint for the main reference if vertical.

(1) Per-item values
For each item I, in item order, compute the following values.
(a) Only when the main axis is vertical, I's cross size c is determined first. Let r = max(0, cw - horizontal margin - horizontal frame width). c is the following value clamped by the horizontal constraint for cw: if I's width is not auto, width resolved against cw; if it is auto and align is stretch, r; if it is auto and align is anything else, the smaller of M(I) and r.
(b) Base size B: I's flex-basis resolved against the main reference. If that is no value, the main-axis size (width if the main axis is horizontal, height if vertical) resolved against the main reference. If that is also no value, M(I) if the main axis is horizontal; if vertical, the A of Section 6 (3) obtained when laying out I with width reference cw, height reference K and FW = c.
(c) Hypothetical size H: B clamped by the main-axis constraint.

(2) Main length
The main length L is cw if the main axis is horizontal, and K if the main axis is vertical and K is not indefinite. If the main axis is vertical and K is indefinite, it is the sum of H + o over all items plus g * (number of items - 1) (0 if there are no items), clamped by E's height constraint.

(3) Splitting into lines
If the main axis is horizontal and flex-wrap is wrap, put the items into lines in item order. The first item starts the first line, and each subsequent item is added to the current line if (sum of H + o of the items in the current line + g * number of items in the current line + that item's H + o) is at most L; otherwise, that item starts a new line. In all other cases, all items go into one line. If there are no items, there are no lines.
Steps (4) to (7) below are performed for each line, in order from the first line. Let k be the number of items in the line, and G = g * (k - 1).

(4) Main size (growing and shrinking)
If the sum of H + o over the line's items plus G is less than L, grow; otherwise, shrink. Each item's weight is its flex-grow value when growing, and (flex-shrink value * B) when shrinking. Items with weight 0, and, when growing, items with B > H, and, when shrinking, items with B < H, are frozen from the start with target size H. The other items start unfrozen. Repeat the following until no unfrozen items remain.
 (i) Free space F = L - G - (sum of (target size + o) over the frozen items and (B + o) over the unfrozen items).
 (ii) Distribute (Section 9) max(0, F) when growing, or max(0, -F) when shrinking, to the unfrozen items according to their weights taken in item order. Each item's tentative target is B + assignment when growing, and B - assignment when shrinking.
 (iii) The target size of each unfrozen item is its tentative target clamped by the main-axis constraint, and its violation is (target size - tentative target). Let V be the sum of the violations.
 (iv) If V = 0, freeze all items. If V > 0, freeze the items with positive violation; if V < 0, freeze the items with negative violation.
The final target size is the item's main size s.

(5) Cross size
If the main axis is horizontal, lay out each item of the line with width reference cw, height reference K and FW = s, and let its ch be the item's cross size c. If the main axis is vertical, c is the value from (a). The item's outer cross size is c + cross frame width + cross margin.
The line's cross size LC is as follows.
- If the main axis is vertical, cw.
- If the main axis is horizontal and there is only one line: K if K is not indefinite; if indefinite, the maximum outer cross size of the line's items, clamped by E's height constraint.
- If the main axis is horizontal and there are two or more lines, the maximum outer cross size of the line's items.

(6) Main-axis positions
Let the remaining space R = L - (sum of s + o over the line's items) - G. The space placed before each item (for the first item, between it and the main start; for each later item, the length placed between it and the previous item in addition to g) is determined by justify-content as follows. When R <= 0, all of them are 0 regardless of justify-content.
- start: all 0.
- end: R before the first item, 0 elsewhere.
- center: the quotient of R divided by 2 before the first item, 0 elsewhere.
- space-between, space-around, space-evenly: distribute (Section 9) R over k + 1 places in total, namely before the first item, the k - 1 places between items, and after the last item, according to weights, and use the k values excluding the one after the last item. The weights, in the order of these k + 1 places, are: for space-between, 0 at both ends and 1 for every place in between; for space-around, 1 at both ends and 2 for every place in between; for space-evenly, all 1. However, for space-between with k = 1, the sum of the weights is 0, so the space is 0.
The items are arranged in item order starting from the main start: space, the item's margin box (length s + o along the main axis), gap g, the next item's space, the next item's margin box, and so on. The main start and the direction of arrangement are: for row, from the left edge of the content box going right; for row-reverse, from the right edge going left; for column, from the top edge going down; for column-reverse, from the position L below the top edge going up. The margin on the start side of the margin box is ml for row, mr for row-reverse, mt for column and mb for column-reverse.

(7) Cross-axis positions and final layout
The cross start of the first line is the top edge of the content box (the left edge if the main axis is vertical), and the cross start of each later line is LC + g' below the cross start of the previous line. Each item of the line is laid out, in item order, as follows.
- If the main axis is horizontal, align is stretch and the item's height is auto: replace c with max(0, LC - vertical margin - vertical frame width) clamped by the item's vertical constraint for K, and then lay out the item with width reference cw, height reference K, FW = s and FH = c.
- Otherwise, if the main axis is horizontal, lay out the item with width reference cw, height reference K and FW = s.
- If the main axis is vertical, lay out the item with width reference cw, height reference K, FW = c and FH = s.
Let Q = LC - (c + cross frame width + cross margin). The offset is Q if Q > 0 and align is end, the quotient of Q divided by 2 if Q > 0 and align is center, and 0 otherwise (align is start or stretch, or Q <= 0). The edge of the item's border box on the cross-start side (the top edge; the left edge if the main axis is vertical) is at (offset + the item's mt (ml if the main axis is vertical)) from the line's cross start.
The height A of E's content is, if the main axis is horizontal, the sum of LC over all lines plus g' * (number of lines - 1) (0 if there are no lines), and L if the main axis is vertical.

* Section 11. Grid layout
Let cw be the content width and K the content-height reference of an element E whose display is grid (a grid container). E's items, item order and each item's align are the same as in flex layout. The explicit columns are the track specifications of grid-template-columns (one auto if none), and the explicit rows are the track specifications of grid-template-rows (zero if none). Columns and rows are each numbered in order starting from 1.

(1) Placement
From each item's grid-column value, obtain the column start (determined or undetermined) and the number of columns the item spans (the column span) as follows: auto gives undetermined and 1; a gives a and 1; a / b gives a and b - a; a / span n gives a and n; span n gives undetermined and n. From the grid-row value, obtain the row start and the number of rows spanned (the row span) in the same way. An item placed at start position (r, c) occupies all squares (pairs of a row and a column) in rows r to r+(row span)-1 and columns c to c+(column span)-1.
The number of columns NC is the maximum of: the number of explicit columns, (column start + column span - 1) for each item whose column start is determined, and the column span of each item whose column start is undetermined.
First, place the items whose row start and column start are both determined at those positions, in item order (they may overlap other items). Next, with the cursor (row cr, column cc) set to (1, 1), place the remaining items in item order as follows. Below, "overlaps" means that placing at a position would occupy at least one square occupied by an already placed item.
- If only the row start r is determined: place it at the smallest column c with 1 <= c <= NC - column span + 1 such that placing at (r, c) does not overlap. If there is no such c, place it at (r, 1). The cursor is not changed.
- If only the column start c is determined: if c < cc, increase cr by 1. Place it at the smallest row r >= cr such that placing at (r, c) does not overlap, and set the cursor to (r, c + column span).
- If both are undetermined: start from (r, c) = (cr, cc) and repeat the following. If c + column span - 1 > NC, increase r by 1 and set c = 1; otherwise, if placing at (r, c) would overlap, increase c by 1; otherwise, place it at (r, c) and stop. After that, set the cursor to (r, c + column span).
The number of rows NR is the maximum of the number of explicit rows and (row start + row span - 1) for each item (0 if there are no items and no explicit rows).

(2) Track sizes
The sizes of a sequence of tracks (columns or rows) are computed from an available length U (an integer or indefinite), a gap d and each item's contribution, as follows. The sequence is the explicit tracks followed by auto tracks added until the count reaches NC (NR for rows).
 (i) The size of a non-negative integer track is its value.
 (ii) The size of an auto track, and of an fr value track when U is indefinite, is the maximum contribution among the items that start at that track and whose span in that direction (column span for columns, row span for rows) is 1 (0 if there is no such item).
 (iii) The size of an fr value track when U is not indefinite is 0 for now.
 (iv) If U is not indefinite, compute the leftover U - (sum of the sizes from (i) to (iii)) - d * (number of tracks - 1). If the leftover is positive, distribute it (Section 9) in track order, over the fr value tracks with their fr factors as weights if there are any fr value tracks, or otherwise over the auto tracks with weight 1 each, and add the results to the track sizes. If there are no tracks of either kind, do nothing.

(3) Column sizes and item widths
Compute the column sizes with U = cw, d = column-gap and item contributions P(I). For each item, compute the area width aw (sum of the sizes of the columns it occupies + column-gap * (column span - 1)) and the area left edge ax (sum of the sizes of the columns to the left of it + column-gap * number of columns to the left of it). The item's content width gw is width resolved against aw (if no value, max(0, aw - horizontal margin - horizontal frame width)), clamped by the horizontal constraint for aw. Lay out each item, in item order, with width reference aw, an indefinite height reference and FW = gw, and let the border box height + vertical margin be that item's row contribution.

(4) Row sizes and final layout
Compute the row sizes with U = K, d = row-gap and item contributions equal to the row contributions from (3). For each item, compute the area height ah and top edge ay in the same way as for columns (using row-gap), and lay out the items in item order as follows.
- If align is stretch and the item's height is auto, let FH be max(0, ah - vertical margin - vertical frame width) clamped by the vertical constraint for ah, and lay out the item with width reference aw, height reference ah, FW = gw and FH.
- Otherwise, lay out the item with width reference aw, height reference ah and FW = gw.
Let Q = ah - (the item's border box height + vertical margin), and determine the offset in the same way as in (7) of flex layout. The left edge of the item's border box is ax + ml from the left edge of the content box, and its top edge is ay + offset + mt from the top edge of the content box. justify-content is not used in grid layout.
The height A of E's content is the sum of the row sizes plus row-gap * (NR - 1) (0 if NR = 0).

* Section 12. Absolute positioning
The containing block of an element E whose position is absolute is the padding box of the nearest ancestor of E (parent, parent's parent, ...) whose position is relative or absolute. If there is no such ancestor, it is the viewport. Let CBW and CBH be the width and height of the containing block. Those of E's top, right, bottom and left that are not auto are denoted by their values.
(1) If E's width is not auto, let w be width resolved against CBW. If it is auto, let r = max(0, CBW - left - right - horizontal margin - horizontal frame width) (left and right that are auto are counted as 0); if neither left nor right is auto, w = r; otherwise w is the smaller of M(E) and r. Let FW be w clamped by the horizontal constraint for CBW.
(2) If E's height is auto and neither top nor bottom is auto, let FH be max(0, CBH - top - bottom - vertical margin - vertical frame width) clamped by the vertical constraint for CBH. In other cases, FH is not given.
(3) Lay out E with width reference CBW, height reference CBH, FW (and FH).
(4) Determine E's relative position (x, y) as follows. The reference point is the top-left of the containing block.
- x: left + ml if left is not auto; otherwise, if right is not auto, CBW - right - mr - (width of E's border box); ml if both are auto.
- y: top + mt if top is not auto; otherwise, if bottom is not auto, CBH - bottom - mb - (height of E's border box); mt if both are auto.
An absolutely positioned element is not an in-flow child of its parent, so it does not affect its parent's layout, M or P.

* Section 13. Commands
- LAYOUT
Output "layout <W>x<H>" (<W> and <H> are the current viewport width and height), followed by one line per element in document order: "<indent><id> <x> <y> <w> <h>". <indent> is 2*d spaces for the element's depth d, <id> is the element's ID, and <x> <y> <w> <h> are the top-left coordinates, width and height of the border box. For an element that is not displayed, output "<indent><id> none".
- BOX id
If there is no element with id, output "error: unknown element <id>"; if it exists but is not displayed, output "box <id>: none". If it is displayed, output "box <id>" followed by the following four lines. The four numbers on each line are the x coordinate and y coordinate of the top-left, the width and the height of that box.
  margin <x> <y> <w> <h>
  border <x> <y> <w> <h>
  padding <x> <y> <w> <h>
  content <x> <y> <w> <h>
- RENDER
Create a screen of width W and height H with every cell set to ".". Draw the displayed elements on the screen one by one in document order, each by the following steps (1) to (3) in order (what is drawn later overwrites what was drawn earlier). Nothing is drawn in cells outside the screen.
(1) Set every cell of the border box to a space.
(2) Redraw the cells of the border box that lie on the following top, bottom, left and right sides. The top side is the topmost row when bt = 1, the bottom side is the bottommost row when bb = 1, the left side is the leftmost column when bl = 1, and the right side is the rightmost column when br = 1. A cell that lies on the top or bottom side and also on the left or right side becomes "+", a cell that lies only on the top or bottom side becomes "-", and a cell that lies only on the left or right side becomes "|".
(3) If it is a text element, draw each line of the wrapped text: line i (i = 0, 1, ...) is drawn one character at a time going right, starting from the cell i below the top-left of the content box (spaces within the line are drawn too). Characters that extend outside the content box are drawn too.
When drawing is finished, output "render <W>x<H>", followed by a line of W+2 "#" characters, each row of the screen from top to bottom enclosed with "#" on the left and right (H lines), and a line of W+2 "#" characters.
- HIT x y
Unless x < W and y < H, output "error: point <x> <y> outside viewport". Otherwise, find the displayed element E that is latest in document order among those whose border box contains cell (x, y). If there is no such element, output "hit <x> <y>: none"; otherwise, output "hit <x> <y>: <path>", where <path> is the IDs of the elements from the root to E (the root, its child, ..., E) in order, separated by " > " (a > with a space before and after it).
- SET id property value
If there is no element with id, output "error: unknown element <id>"; if property is not a known property, output "error: unknown property <property>"; if value is not valid as a value of property, output "error: invalid value for <property>: <value>" (check in this order and output only the first one that applies). If none of these applies, the SET succeeds. For that element, record the values of the longhand properties specified by the declaration "property: value" (for a shorthand, the values assigned to each corresponding longhand property by the rules of Section 1) (Section 2 (1)), perform the layout, and output "set <id> <property> <value>: <changed>". <changed> is the IDs of the elements whose border box (including whether the element is displayed) differs between before and after the layout, in document order, separated by single spaces. If there are no such elements, <changed> is "no change". A border box differs when whether the element is displayed has changed, or, if displayed, any of its top-left coordinates, width or height has changed.
- VIEWPORT w h
Unless 1 <= w <= 80 and 1 <= h <= 40, output "error: invalid viewport <w> <h>". Otherwise, change the viewport width to w and height to h, perform the layout, and output "viewport <w> <h>: <changed>". <changed> is the same as for SET.
- OVERFLOW
Output "overflow: <list>", where <list> is the IDs of the displayed elements whose content overflows, in document order, separated by single spaces. If there are no such elements, output "overflow: none". The content of a text element overflows when the number of characters of the longest of the lines obtained by wrapping its text at width cw is greater than cw, or when the number of lines is greater than ch. The content of an element that is not a text element overflows when at least one of its in-flow children has a margin box that is not contained in the element's content box. A margin box is not contained in the content box when any of the following holds: the left edge of the margin box is to the left of the left edge of the content box, its top edge is above the top edge of the content box, its right edge (left edge + width) is to the right of the right edge of the content box, or its bottom edge (top edge + height) is below the bottom edge of the content box.
- Any other command
Output "error: unknown command <name>" (<name> is the command name).

[Output format]
The output of each command consists of the lines defined in [Processing], output in command order.
The output consists only of ASCII characters, and each line ends with a newline (LF). Lines have no trailing whitespace, and no empty lines are output. Only the indentation of LAYOUT has leading whitespace. Numbers have no extra leading zeros.

[Constraints]
- 1 <= W <= 80, 1 <= H <= 40
- There are at most 60 rule lines; one rule line has at most 10 selectors and at most 20 declarations.
- There are 1 to 60 elements, and the depth is at most 10.
- There are at most 300 command lines.
- The digit-only parts of tokens (including the part after "-" and the part before "%" or "fr") do not start with 0 unless they are 0 itself.
- A valid grid-template-columns or grid-template-rows value has at most 10 track specifications, and a, b and n in a valid grid-column or grid-row value are at most 20.
- Every integer that appears during the computation has absolute value less than 10^9.
