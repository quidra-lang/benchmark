[Overview]
Write a program that computes golf handicaps and results. The handicap calculation is modelled on the World Handicap System (WHS), and everything is computed with integers and exact fractions. The program reads commands from standard input, processes the registration of courses, tees and players, the recording and removal of round scores, handicap index calculation and history, course handicaps, scorecards, statistics, the results of events (stroke play, Stableford, par competition, match play, Nassau, four-ball, better-ball, skins), and an annual points ranking, and writes the results to standard output.

[Input format]
The first line contains the number of commands N (1 <= N <= 1000), and each of the following N lines contains one command. Each line consists of several tokens separated by single spaces, with no whitespace at the beginning or end of the line. A command has one of the following forms (<...> marks a position where a value goes, [...] marks an optional part, and [...]... denotes zero or more repetitions).

COURSE <course> <par1> ... <par18> <SI1> ... <SI18>
TEE <course> <tee> <rating> <slope>
PLAYER <player> <name> [<index>]
ROUND <player> <course> <tee> <day> <score1> ... <score18>
REMOVE <player>
INDEX <player>
HISTORY <player>
LOWINDEX <player> <day>
COURSEHCP <player> <course> <tee>
HCPTABLE <course> <tee> <index1> <index2>
CARD <player> <number>
STATS <player>
HOLESTATS <course>
PLAYERS
EVENT <event> <format> <course> <tee> <day> <allowance> <player> [<player>]...
RESULTS <event>
MERIT

The format of each value is as follows.
- <course>, <tee>, <player>, <event>: IDs identifying a course, a tee, a player and an event respectively; each is a string of 1 to 8 characters consisting of lowercase letters and digits.
- <name>: the player's name, a string of 1 to 12 letters (uppercase and lowercase).
- <par1> to <par18>: the pars of holes 1 to 18, integers from 1 to 99.
- <SI1> to <SI18>: the stroke indexes of holes 1 to 18 (SI: the difficulty rank of a hole, which gives the order in which handicap strokes are allocated), integers from 1 to 99.
- <rating>: the course rating multiplied by 10, an integer from 1 to 9999 (example: 721 represents a course rating of 72.1).
- <slope>: the slope rating, an integer from 1 to 999.
- <index>, <index1>, <index2>: a handicap index multiplied by 10, an integer from -999 to 9999 (example: 184 represents an index of 18.4, and -23 represents an index of -2.3). A negative index is what is called a plus handicap.
- <day>: an integer from 1 to 9999 representing a date. The day after day d is day d + 1.
- <score1> to <score18>: the scores (numbers of strokes taken) on holes 1 to 18; each is an integer from 1 to 19, "X" (pick-up: a hole abandoned partway without holing out), or "-" (the hole was not played).
- <number>: an integer from 1 to 999.
- <format>: one of STROKE, STABLEFORD, PAR, MATCH, NASSAU, FOURBALL, BETTERBALL and SKINS.
- <allowance>: a percentage giving the rate at which the handicap is applied, an integer from 1 to 999.
All integers are written in decimal without extra leading zeros, and a negative number is written with a single leading "-" ("-0" does not appear). EVENT has 1 to 10 <player> tokens.

[Processing]
Process the commands one by one in input order.

== Common rules for output and errors ==
A successful COURSE, TEE, PLAYER or EVENT prints nothing. Every other command, when successful, prints the lines shown in [Output format].
When a command cannot be executed, print only one line consisting of "ERROR", a single space, and one of the following strings giving the reason. The checks are made in the order written in the description of each command, and the first one that applies is printed. A command that results in an error changes nothing.
- unknown course, unknown tee, unknown player, unknown event, unknown round: the specified course, tee, player, event or round does not exist.
- duplicate course, duplicate tee, duplicate player, duplicate event: one with the same ID already exists.
- invalid course, invalid tee, invalid index, invalid day, invalid allowance, invalid players: a value is invalid.
- too few holes: too many holes were not played.
- no rounds: the player has no rounds.
- no index: there is no index.
- missing round: a round for the event is missing.
Below, "ID order" means the order obtained by comparing IDs character by character from the first character by character code (ASCII), where, if one is equal to the beginning of the other, the shorter one comes first (example: "a1" comes before "ab", and "ab" comes before "abc").

== Number representation and rounding ==
Values with one decimal place, such as indexes, course ratings and differentials (defined later), are all handled as integers multiplied by 10 (example: 18.4 is 184). All calculations are done with exact values. Two kinds of rounding are used, as described below. Every value for which "rounding down" is specified is 0 or more.
- Round half away from zero: the integer nearest to x. If x is exactly halfway between two integers, the one with the larger absolute value (example: 2.5 becomes 3, -2.5 becomes -3).
- Round half up: the integer nearest to x. If x is exactly halfway between two integers, the larger one (example: 2.5 becomes 3, -2.5 becomes -2).
Both can be obtained with integer arithmetic only, but take care with the handling of division of negative numbers.

== COURSE ==
1. If a course with the same ID already exists, the result is "ERROR duplicate course".
2. If any par is a value other than 3, 4 and 5, or <SI1> to <SI18> do not contain each integer from 1 to 18 exactly once, the result is "ERROR invalid course".
3. If there is no error, register the course with no tees. The par and SI of hole h are <parh> and <SIh> respectively. The sum of the pars of the 18 holes is called the "course par" P of that course.

== TEE ==
1. If there is no course <course>, the result is "ERROR unknown course".
2. If that course already has a tee with the same ID, the result is "ERROR duplicate tee". A tee of a different course may have the same ID.
3. If <rating> is not between 500 and 900 inclusive, or <slope> is not between 55 and 155 inclusive, the result is "ERROR invalid tee".
4. If there is no error, register the tee on that course. The rating R (the value multiplied by 10) and the slope S of the tee are <rating> and <slope> respectively.
The "tee check" performed by other commands that specify a course and a tee is the check that gives "ERROR unknown course" if there is no course <course>, and "ERROR unknown tee" if that course has no tee <tee>.

== PLAYER ==
1. If a player with the same ID already exists, the result is "ERROR duplicate player".
2. If <index> is given and it is not between -100 and 540 inclusive, the result is "ERROR invalid index".
3. If there is no error, register the player. If <index> is given, it becomes the player's current index; otherwise the player is in the "no index" state.
Each player has a current index (or the no-index state), a list of rounds, a list of index records, and a last calculation. Right after registration, the rounds and the index records are empty and there is no last calculation. Rounds are kept in the order in which they were registered and are numbered 1, 2, 3, ... from the oldest.

== Allocation of handicap strokes ==
For an integer handicap H, the number of "strokes" on each hole is determined as follows. This is called "the allocation of H".
- When H is 0 or more: let q be the quotient and r the remainder of H divided by 18. Each hole gets q strokes, except that only the holes whose SI is r or less get q + 1.
- When H is negative: let q be the quotient and r the remainder of -H divided by 18. Each hole gets -q strokes, except that only the holes whose SI is 19 - r or more get -q - 1.
The strokes of the 18 holes sum to H. For example, for H = 20 the holes with SI 1 and 2 get 2 and all other holes get 1, and for H = -3 the holes with SI 16, 17 and 18 get -1 and all other holes get 0.

== Course handicap ==
The "course handicap" on a tee of a player with index I (the value multiplied by 10) is I / 10 * S / 113 + (R / 10 - P) rounded half up to an integer. This is equal to (I * S + 113 * (R - 10 * P)) / 1130. Here R and S are the rating and the slope of that tee, and P is the course par of that course.

== ROUND ==
Check in the following order.
1. If there is no player <player>, the result is "ERROR unknown player".
2. Perform the tee check.
3. If the player has rounds and <day> is smaller than the day of the player's latest round (the round with the largest number), the result is "ERROR invalid day".
4. If 5 or more of <score1> to <score18> are "-", the result is "ERROR too few holes".
If there is no error, process in the following order. <scoreh> is called the score of hole h, and a hole whose score is an integer is called a "hole with a score".
(1) Let I0 be the player's index at that time. If I0 exists, the course handicap with I0 on that tee is the "handicap" of this round, and let s_h be the strokes on hole h in its allocation. If I0 does not exist, the handicap of this round is "none" and every s_h is 0.
(2) The "limit" of hole h is par + 2 + s_h (net double bogey) if I0 exists, and par + 5 otherwise.
(3) The "adjusted score" of hole h is the smaller of the score and the limit if the score is an integer, the limit if it is "X", and par + s_h (net par) if it is "-".
(4) The sum of the adjusted scores of the 18 holes is the "AGS" (adjusted gross score).
(5) The "differential" D of this round is 113 * (10 * AGS - R) / S rounded half away from zero to an integer (this corresponds to 113 / S * (AGS - R / 10) multiplied by 10).
(6) The "exceptional score reduction" E of this round is defined as follows: if I0 exists and I0 - D is 70 or more, E is 10 when I0 - D is less than 100 and 20 when it is 100 or more. In all other cases E is 0.
(7) Append this round to the end of the player's list of rounds. A round stores the day, the course, the tee, the score of each hole, the handicap, the adjusted score of each hole, AGS, D and E.
(8) Perform the "index update" below with day d = <day>.
(9) After that, if the player has an index, append one pair of <day> and the index at that time to the end of the index records.

== Index update (for day d) ==
The player's rounds taken from the newest (largest number), at most 20 of them, are the "eligible rounds", and let n be their count.
If n is less than 3, the index (including the no-index state) is not changed, and the last calculation becomes "none".
If n is 3 or more, compute the new index as follows.
(1) The "adjusted differential" of each eligible round r is the D of r minus the sum of E over r itself and all eligible rounds newer than r.
(2) Depending on n, determine the number k of rounds to count and the adjustment a as follows.
  n = 3: k = 1, a = -20
  n = 4: k = 1, a = -10
  n = 5: k = 1, a = 0
  n = 6: k = 2, a = -10
  n = 7, 8: k = 2, a = 0
  n = 9 to 11: k = 3, a = 0
  n = 12 to 14: k = 4, a = 0
  n = 15, 16: k = 5, a = 0
  n = 17, 18: k = 6, a = 0
  n = 19: k = 7, a = 0
  n = 20: k = 8, a = 0
(3) Sort the eligible rounds in increasing order of adjusted differential (if the adjusted differentials are equal, the newer round comes first); the first k of them are the "counting rounds".
(4) The sum of the adjusted differentials of the counting rounds divided by k, rounded half away from zero to an integer, is the "average" A, and let C = A + a.
(5) If the low index for day d (defined below) exists, let L be its value; if C - L exceeds 30, set C = L + 30 + (C - L - 30) / 2 (rounded down, discarding the fractional part) (soft cap). After that, if C - L exceeds 50, set C = L + 50 (hard cap). If there is no low index, neither of these is applied.
(6) If C exceeds 540, set C = 540 (maximum).
(7) C becomes the player's new index. As the last calculation, store k, A, a, L ("none" if there is no low index), whether the hard cap changed the value, whether the soft cap changed the value, and whether the maximum changed the value.

== Low index ==
A player's "low index for day d" is the smallest index among those of the player's index records whose day is between d - 365 and d - 1 inclusive. If there is no such record, there is no low index. If several records have the smallest index, the one among them with the smallest day is the "low index record".

== REMOVE ==
1. If there is no player <player>, the result is "ERROR unknown player".
2. If the player has no rounds, the result is "ERROR no rounds".
3. If there is no error, remove the latest round, and restore the player's current index, index records and last calculation to the state immediately before that round was registered. In other words, the state becomes the same as if that round had never been registered.

== INDEX, HISTORY, STATS, LOWINDEX ==
If there is no player <player>, the result is "ERROR unknown player". Otherwise, print the lines given in [Output format]. The eligible rounds, adjusted differentials and counting rounds for HISTORY are obtained from the rounds at that time in the same way as in the index update. Even when the number n of eligible rounds is less than 3, the adjusted differentials are obtained in the same way as in step (1) of the index update (there are no counting rounds).

== COURSEHCP ==
1. If there is no player <player>, the result is "ERROR unknown player".
2. Perform the tee check.
3. If the player does not have an index, the result is "ERROR no index".
4. If there is no error, print the course handicap on that tee with the current index, and the strokes in its allocation.

== HCPTABLE ==
1. Perform the tee check.
2. Unless -100 <= <index1> <= <index2> <= 540, the result is "ERROR invalid index".
3. If there is no error, compute the course handicap on that tee for each index from <index1> to <index2> in steps of 1 (corresponding to steps of 0.1 in the index), and print one entry for each run of consecutive indexes with the same course handicap, in order starting from the run with the smallest indexes.

== CARD ==
1. If there is no player <player>, the result is "ERROR unknown player".
2. If <number> is greater than the number of the player's rounds, the result is "ERROR unknown round".
3. If there is no error, print the scorecard of the round with that number. The strokes on each hole of the scorecard are those of the allocation of that round's handicap (0 if the handicap is none). The "net" of a hole with a score is score - strokes, and a hole without a score has no net.

== Stableford points ==
The points of a hole with a score are par + 2 - n, where n is the net (0 if this is negative) (this gives 0 for net double bogey or worse, 1 for net bogey, 2 for net par, 3 for net birdie, ...). The points of a hole without a score are 0.

== STATS ==
Over all of the player's current rounds, compute the following values.
- Count the holes with a score, classified by the value score - par: -2 or less as eagles, -1 as birdies, 0 as pars, 1 as bogeys, 2 as doubles, and 3 or more as others. Also, the number of holes whose score is "X" is pickups. Holes whose score is "-" are not counted in any of these.
- For each of the holes with par 3, 4 and 5, compute the average of the scores over the holes with a score.
- A round in which all 18 holes have a score is called a "complete round"; compute the minimum (best) and the average (average) of the score totals of the complete rounds.

== HOLESTATS ==
1. If there is no course <course>, the result is "ERROR unknown course".
2. If there is no error, consider those current rounds of all players that are on that course (regardless of the tee). For each hole, compute the number of considered rounds that have a score on that hole (scores) and the average of those scores.
3. Give each hole a difficulty rank. Arrange the holes whose scores is 1 or more in decreasing order of (sum of scores - par * scores) / scores (the average relative to par), with equal values in increasing order of hole number. After them, arrange the holes whose scores is 0 in increasing order of hole number, and assign ranks 1 to 18 in this order. Compare with exact values (after clearing the denominators, the comparison can be done with integers).

== PLAYERS ==
Arrange all players as follows: the players with an index in increasing order of index (plus handicaps first), followed by the players with no index. Players that fall in the same position are in ID order.

== EVENT ==
1. If an event with the same ID already exists, the result is "ERROR duplicate event".
2. Perform the tee check.
3. If <allowance> is not between 1 and 100 inclusive, the result is "ERROR invalid allowance".
4. If even one of the <player>s is not a registered player, the result is "ERROR unknown player".
5. If the same ID appears two or more times among the <player>s, or the number of <player>s does not fit the format, the result is "ERROR invalid players". The number must be 2 for MATCH and NASSAU, 4 for FOURBALL, one of 4, 6 and 8 for BETTERBALL, and between 2 and 8 inclusive for the other formats.
6. If there is no error, register the event. An event stores the format, the course, the tee, the day, the allowance and the list of players (in input order).

== RESULTS ==
1. If there is no event <event>, the result is "ERROR unknown event".
2. Examine the players of the event one at a time in list order. If none of the player's current rounds has the same course, tee and day as the event, the result is "ERROR missing round". If there are such rounds, the one with the smallest number among them is that player's "event round", and if its handicap is none, the result is "ERROR no index". Print only the error of the first player that causes an error.
3. If there is no error, the "playing handicap" PH of each player is (handicap of the event round) * allowance / 100 rounded half up to an integer.
4. The strokes on each hole of each player are those of the allocation of "that player's PH - the minimum PH over all players of the event" for MATCH, NASSAU and FOURBALL, and those of the allocation of PH for the other formats. The net of a hole with a score in the event round is score - strokes, and a hole without a score has no net. Stableford points are also computed with these strokes.
5. Compute and print the results according to the rules for each format below.

== Ranking by countback ==
When players (or teams) are ranked by a sequence of per-hole values (18 values), compare, in this order, the total over the 18 holes, the total over holes 10 to 18, the total over holes 13 to 18, the total over holes 16 to 18, and the value of hole 18, and decide the ranking by the first one that differs. Whether the smaller value or the larger value ranks higher is defined for each format. If all of these are equal, players are in ID order, and teams are in ID order of their first player. Ranks are 1, 2, 3, ... from the top.

== STROKE (stroke play) ==
A player with even one hole without a score is "NR" (no return). Rank the players who are not NR by the sequence of nets, with the smaller value ranking higher. Further, if there is at least one player who is not NR, the player ranked first when the players who are not NR are ranked by the sequence of scores, with the smaller value ranking higher, is the "gross winner".

== STABLEFORD (Stableford) ==
Rank all players by the sequence of points, with the larger value ranking higher.

== PAR (par competition) ==
The value of each hole is 1 if the net is less than par, 0 if it is equal to par, and -1 if it is greater than par or there is no net. Rank all players by this sequence of values, with the larger value ranking higher. The sum of the values is the player's "record".

== Match play (MATCH, NASSAU, FOURBALL) ==
This is a contest between two "sides". In MATCH and NASSAU the first player is side 1 and the second player is side 2; in FOURBALL the first and second players are side 1 and the third and fourth players are side 2. The name of a side is the player's ID in MATCH and NASSAU, and in FOURBALL the two IDs in list order joined with "+" (example: amy+jon).
The score of a side on each hole is the minimum of the nets of those players of the side who have a net; if no player of the side has a net, the side has no score. If both sides have a score, the side with the smaller one wins the hole, and if they are equal the hole is tied. If only one side has a score, that side wins; if neither side has one, the hole is tied.
A "match" over holes a to b is played as follows. Set the lead to 0 and, starting from hole a in order, add 1 to the lead if side 1 wins and subtract 1 if side 2 wins, and record the "status" after that hole. The status is "<lead> UP" if the lead is positive, "<-lead> DN" if it is negative, and "AS" if it is 0 (example: 2 UP, 1 DN). If, after that hole, the absolute value of the lead has become greater than the number of remaining holes (b - the number of that hole), the match ends there. The match also ends when it has been played through hole b.
The "result" of a match is "AS" if the lead when it ends is 0. Otherwise it is the concatenation of the name of side 1 if the lead is positive or of side 2 if it is negative, a single space, and then "<absolute value of the lead>&<number of remaining holes>" (example: 3&2) if the number of remaining holes is 1 or more, or "<absolute value of the lead> UP" (example: 1 UP) if it is 0.
- MATCH (match play) and FOURBALL (four-ball): play one match over holes 1 to 18.
- NASSAU (Nassau): using the same hole results, play three matches independently of each other: holes 1 to 9 (front), holes 10 to 18 (back) and holes 1 to 18 (total).

== BETTERBALL (better-ball) ==
The first and second players of the list, the third and fourth players, ... each form one "team". The value of a team on each hole is the larger of the two players' Stableford points. Rank the teams by this sequence of values, with the larger value ranking higher.

== SKINS (skins) ==
Set the carry-over count c to 0 and process holes 1 to 18 in order. On each hole, first add 1 to c. If, among the players who have a net on that hole, exactly one player has the minimum net, that player wins c skins and c is set to 0. Otherwise (including the case where no player has a net), c is carried over unchanged to the next hole.
If c is 1 or more after hole 18 has been processed, the c skins are divided equally among all players who had the minimum net on hole 18 (all players of the event if no player had a net on hole 18). Each player's share is c / (number of players) rounded down to two decimal places (the third and later decimal places are discarded).
Each player's total is the sum of the number of skins won and the share (a value with at most two decimal places).

== MERIT (annual points ranking) ==
Examine all events in registration order; those whose format is STROKE, STABLEFORD or PAR and for which RESULTS does not give an error at that point are the "counted events". For each counted event, add 1 to the appearances of every player of that event, give 10, 8, 6, 5, 4, 3, 2 and 1 points to the players in RESULTS rank order starting from rank 1, and add 1 to the wins of the player ranked 1. NR players are given no points.
Arrange the players with 1 or more appearances in decreasing order of points, then, if points are equal, in decreasing order of wins, and, if these are also equal, in ID order, and assign ranks 1, 2, 3, ... from the top.

[Output format]
Do not put whitespace at the end of any line, and end every line with a newline. Items are separated by a single space. Integers are written in decimal without extra leading zeros, and negative numbers are written with a leading "-". The following formats are used to display values.
- Index display: if the value v (multiplied by 10) is 0 or more, the concatenation of the quotient of v divided by 10, ".", and the remainder (one digit) (example: 184 is 18.4, 5 is 0.5, 0 is 0.0); if v is negative, "+" followed by -v written in the same way (example: -23 is +2.3). If there is no index, "none".
- Signed decimal display: if the value v (multiplied by 10) is 0 or more, the same as the index display; if v is negative, "-" followed by -v written in the same way (example: -57 is -5.7, -20 is -2.0).
- Handicap display: an integer h is written as it is if it is 0 or more, and as "+" followed by -h if it is negative (example: -7 is +7).
- Two-decimal display: a value of 0 or more, rounded down to two decimal places (the third and later decimal places are discarded), written as the integer part, ".", and a two-digit fractional part (example: 4.1666... is 4.16, 87 is 87.00).
Below, <rounds> is the number of the player's current rounds (not the number of eligible rounds).

== ROUND ==
One line: "round <player> <number>: ags <AGS> diff <D>", followed by " exceptional " and the signed decimal display of -E if E is not 0, and finally " index " and the index display of the index after processing. <number> is the number of the registered round. D is in signed decimal display.
Example: round ann 8: ags 80 diff 5.9 exceptional -2.0 index 9.5

== REMOVE ==
One line: "removed <player> <number>: index <index>". <number> is the number of the removed round, and <index> is the index display of the index after processing.

== INDEX ==
One line: "index <player>: <index> rounds <rounds>". If there is a last calculation, append " lowest <k> average <A> adjustment <a>" (A and a in signed decimal display) to that line, and further append, in this order, " low <L>" (index display) if L exists, " hard cap" if the hard cap changed the value, " soft cap" if it did not but the soft cap changed the value, and " maximum" if the maximum changed the value.
Example: index ann: 13.5 rounds 3 lowest 1 average 30.2 adjustment -2.0 low 8.5 hard cap

== HISTORY ==
The first line is "history <player>: rounds <rounds>". Then print the eligible rounds one per line from the oldest, in the form "<number> day <day> <course> <tee> ags <AGS> diff <D>". Append, in this order, " adjusted <adjusted differential>" if the adjusted differential differs from D, and " *" if n is 3 or more and the round is a counting round. D and the adjusted differential are in signed decimal display. If there are no rounds, print only the first line.

== LOWINDEX ==
One line: "lowindex <player> <day>: <index> day <record day>" if the low index for <day> exists, and otherwise "lowindex <player> <day>: none". <index> is the index display of the low index, and <record day> is the day of the low index record.

== COURSEHCP ==
One line: "coursehcp <player> <course> <tee>: <course handicap> strokes <s1> ... <s18>". The course handicap is in handicap display, and s1 to s18 are the strokes (integers) on holes 1 to 18.

== HCPTABLE ==
The first line is "hcptable <course> <tee>: <index1> to <index2>". Then, for each run, print one line "<min> to <max>: <course handicap>". <index1>, <index2>, <min> and <max> (the smallest and largest index of the run; they may be equal) are in index display, and the course handicap is in handicap display.

== CARD ==
The first line is "card <player> <number>: <course> <tee> day <day> handicap <handicap>". The handicap is in handicap display, or "none" if it is none.
Then, for holes 1 to 18, print one line each: "<hole number> <par> <SI> <score> <adjusted score> <strokes> <net> <points>". <score> is as given in the input (an integer, "X" or "-"), and <net> is "-" if there is no net. Right after the line of hole 9 print an "OUT" line, and right after the line of hole 18 print an "IN" line and a "TOTAL" line, in this order. These have the form "<label> <par> <score> <adjusted score> <strokes> <net> <points>" and give the totals over holes 1 to 9, holes 10 to 18 and holes 1 to 18 respectively. However, if the range contains even one hole without a score, <score> and <net> are "-".
The last line is "ags <AGS> diff <D>" (D in signed decimal display).

== STATS ==
One line: "stats <player>: rounds <rounds> best <minimum> average <average> eagles <count> birdies <count> pars <count> bogeys <count> doubles <count> others <count> pickups <count> par3 <average> par4 <average> par5 <average>". All averages are in two-decimal display. If there is no complete round, the values of best and average are "-", and the average for a par that has no holes with a score is also "-".

== HOLESTATS ==
The first line is "holestats <course>: rounds <number of considered rounds>". Then, for holes 1 to 18 in order, print one line each: "<hole number> par <par> si <SI> scores <scores> avg <average> rank <rank>". The average is in two-decimal display, and it is "-" if scores is 0.

== PLAYERS ==
The first line is "players <number of players>". Then, in the PLAYERS order, print one line for each player: "<player> <name> <index> rounds <rounds>". <index> is in index display.

== RESULTS ==
The first line is "results <event>: <format> <course> <tee> day <day> allowance <allowance>". The following lines depend on the format. PH below is in handicap display.
- STROKE: in rank order, "<rank> <player> net <net total> gross <score total> hcp <PH>"; then, for the NR players in ID order, "NR <player> hcp <PH>"; and finally, if there is a gross winner, "gross <player> <score total>".
- STABLEFORD: in rank order, "<rank> <player> points <points total> hcp <PH>".
- PAR: in rank order, "<rank> <player> <record> hcp <PH>". The record is "<record> UP" if it is positive, "<-record> DN" if it is negative, and "AS" if it is 0.
- MATCH, FOURBALL: one line consisting of "strokes" followed by " <player> <strokes>" for each player in list order (<strokes> is that player's PH - the minimum PH over all players), one line consisting of "status " followed by the statuses of the match in order, separated by ", " (a comma and a space), and one line "result <result>".
- NASSAU: the same "strokes" line as MATCH, followed by the three lines "front <result>", "back <result>" and "total <result>".
- BETTERBALL: in rank order, "<rank> <player1>+<player2> points <points total> hcp <PH of player1> <PH of player2>".
- SKINS: for each hole where skins were won, in hole order, "hole <hole number> <player> <number of skins won>". If an equal division was made, next print one line consisting of "carry <c>" followed by " <player>" for each player sharing in the division, in ID order. Finally, print all players in decreasing order of total (in ID order if equal), in the form "<player> <total>". The total is in two-decimal display.

== MERIT ==
The first line is "merit: events <number of counted events>". Then, in rank order, print one line each: "<rank> <player> <points> wins <wins> played <appearances>".

== Errors ==
One line "ERROR <reason>" (see [Processing]).

[Constraints]
- 1 <= N <= 1000.
- The number of tokens of each command and the format of each token are guaranteed to be as in [Input format].
- Each line is at most 200 characters long.
- All integers appearing in the calculations fit in the range of signed 32-bit integers.
