[Overview]
Write a program that is a small full-text search engine for English documents. The program reads from standard input a list of stopwords (words that are not indexed), several documents, and a sequence of commands. It splits the body of each document into words, turns each word into its stem with Porter stemming, and builds an inverted index that records, for each stem, the positions where it occurs. Porter stemming is an algorithm published by M. F. Porter in 1980; it removes the endings (suffixes) of English words according to rules, so that connect, connected, connection, etc. are reduced to the same stem connect. On top of this, the program shows the steps of stemming, lists the index, performs boolean searches, phrase searches and proximity searches, counts occurrences, shows KWIC (the context before and after a keyword, with the keyword positions aligned), computes the similarity between documents, adds and removes stopwords and documents, and so on, and writes the results to standard output.

[Input format]
The input consists of the stopword line, the document part, and the command part, in this order.
Line 1 is "STOPWORDS" followed by the stopwords, each preceded by one space (if there are 0 stopwords, the line is just "STOPWORDS"). Each stopword is a sequence of 1 to 30 lowercase letters (a to z), and no word appears twice or more.
The document part starts at line 2. Each document consists of a line "DOC <document number>", the body lines (0 or more lines), and a line consisting only of "ENDDOC", in this order. A document number is an integer from 1 to 999, written in decimal without extra leading zeros, and no document number appears twice or more. The documents are not necessarily in order of document number. Each body line has 0 to 100 characters, consists only of printable ASCII characters (character codes 32 to 126), and its last character is not a space. A body line is never "ENDDOC".
If the line following an "ENDDOC" line starts with "DOC " (D, O, C and one space), it is the "DOC" line of the next document. Otherwise the command part starts at that line.
The command part consists of command lines, one command per line, followed by a line consisting only of "END" (the last line of the input). There are the following 21 command names, with the following formats (INDEX and TOP each have two formats).

  STEM w1 w2 ... wn
  STEPS w
  MEASURE w
  INDEX
  INDEX p
  SEARCH expr
  PHRASE w1 w2 ... wn
  NEAR w1 w2 k
  TOP k
  TOP k d
  KWIC w
  TF d w
  DF w
  VARIANTS w
  SIMILAR d k
  RANK k w1 w2 ... wn
  INFO d
  LINE d i
  STATS
  STOP w
  UNSTOP w
  APPEND d text
  DELETE d

expr denotes the "expression", text denotes the "text", and the other lowercase names (w, w1, w2, wn, p, k, d, i) denote "arguments". The number of words n is 1 to 10 for STEM, 2 to 10 for PHRASE, and 1 to 10 for RANK. The command name and the arguments, and the arguments among themselves, are separated by one space. For SEARCH, the whole part after the one space following the command name, up to the end of the line, is the expression. For APPEND, the whole part after the one space following d, up to the end of the line, is the text.
Each command line has 1 to 200 characters, consists only of printable ASCII characters, does not start or end with a space, and does not start with "DOC ". Two or more consecutive spaces can occur only inside the text of APPEND. However, the input may contain lines whose command name is none of the 21 kinds, lines with the wrong number of arguments, and lines with invalid argument values; how to handle them is defined in [Processing].

[Processing]
Process the commands from top to bottom and output the result of each command.

1. Terms and state
- "Letters" are the 52 characters: the uppercase letters A to Z and the lowercase letters a to z. "Lowercasing" means changing each uppercase letter to the corresponding lowercase letter.
- Words (strings) are compared in lexicographic order by ASCII character code. That is, compare them character by character from the beginning; the one whose character code is smaller at the first differing character is smaller, and when one is a prefix of the other, the shorter one is smaller.
- Document numbers are compared as integers.
- The program holds the following state.
  The stopword set: a collection of words. Initially it is the stopwords on line 1.
  The document collection: each document has a document number and a sequence of body lines. Initially it is the documents of the document part. The body lines are given "line numbers" 1, 2, 3, ... from top to bottom.

2. Tokens, indexed tokens, stems
- Within each body line, a run of consecutive letters that is not preceded or followed by a letter (a maximal run of letters) is called a "token". All characters other than letters (digits, symbols, spaces) are treated as separators. A token never spans lines. For example, the tokens of the line "Don't stop2go!" are the 4 tokens Don, t, stop, go.
- The lowercased token is called the "form" of the token.
- Each token has the line number of the line that contains it, and a "position". Positions are numbered per document: the tokens are numbered 1, 2, 3, ... starting from line 1, and from left to right within the same line. A line that contains no tokens (including an empty line) consumes no positions.
- A token whose form is in the stopword set is called a "stopword token", and any other token is called an "indexed token". Stopword tokens also get positions. When the stopword set changes, which tokens are indexed tokens also changes, but the line numbers and positions of the tokens do not change.
- The "stem" of an indexed token is the result of applying the stemming of section 3 to its form.
- For a document d and a word s, the number of indexed tokens of d whose stem is s is written tf(d, s), and the number of documents with tf(d, s) >= 1 is written df(s). The sum of tf(d, s) over all documents is called the "total frequency" of s, and a word whose total frequency is 1 or more is called an "index stem".
- An indexed token whose stem is s is called an "occurrence" of s. When occurrences are listed, "occurrence order" means ascending order of document number and, within the same document, ascending order of position.
- The set of the stems of all indexed tokens of document d (duplicates counted once) is called the "stem set" of d.
- The "reference" of a token is the string "<document number>:<line number>:<position>" (example: 12:3:25).

3. Stemming (Porter's algorithm)
The stem of a word w consisting only of lowercase letters is obtained as follows.
- If w has 2 or fewer characters, w itself is the stem.
- If w has 3 or more characters, apply steps 1a, 1b, 1c, 2, 3, 4, 5a, 5b to w once each, in this order, and the word finally obtained is the stem. Each step is applied to the word resulting from the previous step.

(1) Consonants and vowels
Each letter of a word is either a consonant or a vowel. a, e, i, o, u are vowels. y is a consonant if it is the first letter of the word; from the second letter on, it is a vowel when the preceding letter is a consonant, and a consonant when the preceding letter is a vowel. All other letters are consonants.
The string obtained by writing each letter of a word as C if it is a consonant and V if it is a vowel, in order, is called the "pattern" of the word. For example, the pattern of tree is CCVV, the pattern of toy is CVC, and the pattern of syzygy is CVCVCV.

(2) The m value and conditions
The "m value" of a word is the number of places in its pattern where a V is immediately followed by a C. For example, the m value of tr, ee, tree, by is 0, the m value of trouble, oats, ivy is 1, and the m value of troubles, private, orrery is 2.
The following three conditions on a word are used.
  *v*: the word contains at least one vowel.
  *d: the word has 2 or more characters, and its last 2 characters are the same letter and both are consonants.
  *o: the word has 3 or more characters, the last 3 characters of its pattern are CVC, and the last letter of the word is none of w, x, y.
For example, *d holds for fizz, and *o holds for hop. how and toy have the pattern CVC, but *o does not hold for them because their last letter is w or y.

(3) Applying the rules
Steps 1a, 1b, 1c, 2, 3, 4, 5a are given by tables of rules of the form "suffix -> replacement (condition)". "(empty)" denotes the empty string, and "no condition" denotes a condition that always holds. Each step is processed as follows.
- Among the rules of that step whose suffix the word ends with, select exactly one rule, the one with the longest suffix. If there is no such rule, the word does not change in that step.
- The part left after removing the selected rule's suffix from the word is called the "remainder". Check the rule's condition on the remainder; if it holds, the new word is the remainder followed by the replacement. If it does not hold, the word does not change. In this case, other rules with shorter suffixes are not tried.
- The m value, *v*, *d, *o that appear in conditions are checked by regarding the remainder as a word.
For example, in step 4, if the word is replacement, the rule with the longest suffix ement is selected among the rules with suffixes ement, ment, ent; the m value of the remainder replac is 2, so the word becomes replac. If the word is agreement, the ement rule is selected likewise, but the m value of the remainder agre is 1, so the condition does not hold; the ment and ent rules are not tried, and the word stays agreement.

Step 1a (all conditions are "no condition"):
  sses -> ss, ies -> i, ss -> ss, s -> (empty)
Examples: caresses -> caress, ponies -> poni, caress -> caress, cats -> cat

Step 1b:
  eed -> ee (m value > 0), ed -> (empty) (*v*), ing -> (empty) (*v*)
When the word was changed by the ed or ing rule, then check the following (i) to (v) in order on the whole new word, and perform only the first one that applies (if none applies, do nothing).
  (i) The word ends with at: append e to the end of the word.
  (ii) The word ends with bl: append e to the end of the word.
  (iii) The word ends with iz: append e to the end of the word.
  (iv) *d holds and the last letter of the word is none of l, s, z: remove the last character of the word.
  (v) The m value is 1 and *o holds: append e to the end of the word.
Examples: feed -> feed, agreed -> agree, bled -> bled, motoring -> motor, conflated -> conflate, troubled -> trouble, sized -> size, hopping -> hop, falling -> fall, hissing -> hiss, filing -> file, failing -> fail

Step 1c:
  y -> i (*v*)
Examples: happy -> happi, sky -> sky

Step 2 (all conditions are "m value > 0"):
  ational -> ate, tional -> tion, enci -> ence, anci -> ance, izer -> ize,
  abli -> able, alli -> al, entli -> ent, eli -> e, ousli -> ous,
  ization -> ize, ation -> ate, ator -> ate, alism -> al, iveness -> ive,
  fulness -> ful, ousness -> ous, aliti -> al, iviti -> ive, biliti -> ble
Examples: relational -> relate, conditional -> condition, rational -> rational, radicalli -> radical

Step 3 (all conditions are "m value > 0"):
  icate -> ic, ative -> (empty), alize -> al, iciti -> ic, ical -> ic, ful -> (empty), ness -> (empty)
Examples: triplicate -> triplic, formative -> form, electriciti -> electric, hopeful -> hope, goodness -> good

Step 4 (all replacements are "(empty)" and all conditions are "m value > 1", except that the condition of the ion rule alone is "m value > 1 and the remainder ends with s or t"):
  al, ance, ence, er, ic, able, ible, ant, ement, ment, ent, ion, ou, ism, ate, iti, ous, ive, ize
Examples: revival -> reviv, allowance -> allow, replacement -> replac, adoption -> adopt, opinion -> opinion, activate -> activ, effective -> effect

Step 5a:
  e -> (empty) (m value > 1, or "m value = 1 and *o does not hold")
Examples: probate -> probat, rate -> rate, cease -> ceas

Step 5b:
If the m value of the whole word is greater than 1, *d holds, and the word ends with l, remove the last character of the word.
Examples: controll -> control, roll -> roll

Overall example: generalizations becomes generalization in step 1a, generalize in step 2, general in step 3, and gener in step 4 (it does not change in the other steps), so its stem is gener. Likewise, the stem of oscillators is oscil, the stem of connections is connect, the stem of running is run, the stem of happiness is happi, and the stem of agreed is agre.
These rule tables are exactly those of the 1980 paper, and do not include changes such as bli -> ble or logi -> log found in later published implementations. For example, the stem of possibly is possibli.

4. Interpreting command lines and checking arguments
For each command line, check the following in order.
(1) The part of the line before its first space (the whole line if there is no space) is the command name. If the command name matches none of the 21 commands (uppercase and lowercase are distinguished), output "ERROR UNKNOWN COMMAND <command name>".
(2) Extract the arguments as follows. If the line is only the command name, there are 0 arguments for every command. Otherwise, let X be the part after the one space following the command name;
  - for SEARCH, the whole of X is the expression, and there is 1 argument.
  - for APPEND, if X contains a space, the part of X before its first space is d and the whole part after it is the text, and there are 2 arguments. If X contains no space, there is 1 argument, X alone.
  - for any other command, the arguments are the parts of X separated by spaces.
(3) If the number of arguments is not in the following range, output "ERROR BAD ARGUMENTS <command name>". STEM: 1 to 10, PHRASE: 2 to 10, RANK: 2 to 11, INDEX: 0 or 1, TOP: 1 or 2, STATS: 0, NEAR: 3, TF, SIMILAR, LINE, APPEND: 2, all other commands (STEPS, MEASURE, SEARCH, KWIC, DF, VARIANTS, INFO, STOP, UNSTOP, DELETE): 1.
(4) If none of the above applies, process the command as described in section 5. Check the conditions listed as "Checks" in section 5 in the order written; for the first one that applies, output exactly one error line and do nothing else for that command (the state does not change at all). If none applies, perform the processing described after them.
There are the following 4 kinds of argument checks, written in section 5 as "word check of w", "term check of w", "number check of k (1 to 100)", "document check of d", and so on.
- Word check: the argument passes if it has 1 to 30 characters and consists only of letters; its lowercased value is the value used in the subsequent processing and output. If it fails: "ERROR BAD WORD <argument>".
- Term check: first perform the word check; if it fails: "ERROR BAD WORD <argument>". If it passes and the lowercased value v is in the stopword set: "ERROR STOPWORD <v>". Otherwise it passes, and the stem of v is the value used in the subsequent processing and output.
- Number check (lower bound to upper bound): the argument passes if it has 1 to 7 characters, consists only of digits (0 to 9), and its value read as a decimal number (leading zeros ignored) is at least the lower bound and at most the upper bound; that value is used. If it fails: "ERROR BAD NUMBER <argument>".
- Document check: first perform the number check (1 to 999); if it fails: "ERROR BAD NUMBER <argument>". If it passes and there is no document whose document number is that value v: "ERROR NO DOC <v>". If there is, it passes, and that document is used.
<argument> in an error line is the argument exactly as written in the input. <v>, and <w>, <d>, <k> etc. in the output descriptions of section 5, are the values obtained by the checks (the lowercased word, the stem, or the decimal number without leading zeros).

5. Commands
In the output descriptions below, "... followed by the items, each in the form " X"" means the items are placed on the same line, each preceded by one space (if there are 0 items, nothing is written for that part).

STEM w1 w2 ... wn
Checks: word check of w1, w2, ..., wn (performed in this order).
Output "STEM" followed by, for each wi in order, " <wi>:<stem of wi>". wi may be a stopword.

STEPS w
Checks: word check of w.
When the stem of w is computed as in section 3, collect, in order, the steps among 1a, 1b, 1c, 2, 3, 4, 5a, 5b in which the word changed between before and after the step. Output "STEPS <w>" followed by, for each collected step, " <step name>:<word after applying that step>". The step names are 1a, 1b, 1c, 2, 3, 4, 5a, 5b. If no step was collected (including when w has 2 or fewer characters), output "STEPS <w> NONE".

MEASURE w
Checks: word check of w.
Regarding the whole of w as one word, output "MEASURE <w> <pattern of w> m=<m value of w> vowel=<a> double=<b> cvc=<c>". a, b, c are YES if *v*, *d, *o, respectively, hold for w, and NO if they do not.

INDEX
INDEX p
Checks: if p is given, word check of p.
If p is not given, the targets are all index stems; if p is given, the targets are the index stems that start with p (including p itself). p is not turned into a stem; its lowercased value is used as is. First output "INDEX stems=<number of target stems>". Then output the target stems in ascending order, one per line, each as "<stem> df=<df(stem)>" followed by the references of all occurrences of that stem in occurrence order, each in the form " <reference>".

SEARCH expr
Read the expression and search as follows.
(a) Lexemes: read the expression from the left, skipping spaces as separators. "(" and ")" are each a lexeme of 1 character. A run of other characters (characters other than space, "(" and ")") is, as a whole, one lexeme. For example, "(bread)OR(network)" becomes the 7 lexemes (, bread, ), OR, (, network, ).
(b) Kinds of lexemes: AND, OR, NOT (written only in uppercase letters and matching exactly) are called "operators", and ( and ) are called "parentheses". Among the other lexemes, a sequence of 1 to 30 letters is called a "plain term", and such a sequence followed by one "*" is called a "prefix term"; both together are called "terms". The letter part of a term, lowercased, is called the "spelling" of the term. For example, and and Not are not operators but plain terms.
(c) Checks:
  - If there is a lexeme that is none of an operator, a parenthesis, or a term, let T be the leftmost such lexeme: "ERROR BAD TERM <T>".
  - If the whole sequence of lexemes does not form exactly one "expression" of the grammar below: "ERROR SYNTAX".
  - If there is a plain term whose spelling is a stopword, let v be the spelling of the leftmost such term: "ERROR STOPWORD <v>". The spelling of a prefix term may be a stopword.
(d) Grammar:
  expression = conjunction { OR conjunction }
  conjunction = negation { [ AND ] negation }
  negation = NOT negation | element
  element = term | ( expression )
Here, { X } means X repeated 0 or more times, [ X ] means X may or may not be present, and | means one of the two. That is, negations placed next to each other without AND are also regarded as joined by AND (implicit AND). Binding strength is in the order NOT, AND, OR (strongest first), and AND and OR are left-associative. For example, "a b OR NOT c d" is interpreted as "((a AND b) OR ((NOT c) AND d))".
(e) Evaluation: the set of documents denoted by each part of the expression is defined as follows.
  Plain term: with s the stem of the spelling, the set of documents d with tf(d, s) >= 1.
  Prefix term: with q the spelling, the set of documents whose stem set contains at least one stem that starts with q (including q itself). q is not turned into a stem.
  NOT X: the set of all documents that are not in the set of X.
  X AND Y: the set of documents that are in both the set of X and the set of Y.
  X OR Y: the set of documents that are in at least one of the set of X and the set of Y.
(f) Canonical form: build the string representing the interpretation (the canonical form) as follows. The canonical form of a plain term is the stem of its spelling, the canonical form of a prefix term is its spelling followed by "*", the canonical form of NOT X is "(NOT <canonical form of X>)", the canonical form of X AND Y is "(<canonical form of X> AND <canonical form of Y>)", and the canonical form of X OR Y is "(<canonical form of X> OR <canonical form of Y>)". The parenthesis lexemes in the expression do not appear directly in the canonical form.
Output "SEARCH <canonical form of the whole expression> count=<number of documents in the set of the whole expression>" followed by the document numbers of that set in ascending order, each in the form " <document number>".

PHRASE w1 w2 ... wn
Checks: word check of w1, w2, ..., wn (performed in this order). If every wi is a stopword: "ERROR STOPWORDS ONLY".
For each i, if wi is not a stopword, let ti be the stem of wi; if it is a stopword, let ti be "?". "?" means that it matches any token. A pair of a document d and an integer s such that 1 <= s and s + n - 1 <= (the number of tokens in d), and such that for every i = 1, 2, ..., n "ti is ?, or the token at position s + i - 1 of d is an indexed token and its stem equals ti" holds, is called a "match". A match may span lines. Let P be the string formed by joining t1, t2, ..., tn in order, separated by one space. Output "PHRASE "<P>" matches=<number of matches>" followed by all matches, in ascending order of document number and, within the same document, in ascending order of s, each in the form " <d>:<line number of the token at position s of d>:<s>".

NEAR w1 w2 k
Checks: term check of w1. Term check of w2. Number check of k (1 to 100).
Let s1 and s2 be the stems of w1 and w2. For each document, consider all pairs of a position p of an occurrence of s1 and a position q of an occurrence of s2 with p and q different, and find the minimum of |p - q| (when s1 and s2 are equal, this means considering pairs of two different occurrences). Collect the documents that have at least one such pair and whose minimum is k or less. Output "NEAR <s1> <s2> <k> count=<number of collected documents>" followed by the collected documents in ascending order of document number, each in the form " <document number>:<minimum>".

TOP k
TOP k d
Checks: number check of k (1 to 100). If d is given, document check of d.
If d is not given, the "count" of each index stem is its total frequency; if d is given, the "count" of each stem s in the stem set of d is tf(d, s). Sort the stems in descending order of count, and stems with equal counts in ascending order of stem, and select the first k (all of them if there are fewer than k). Output "TOP <k>" if d is not given, or "TOP <k> doc=<d>" if d is given, followed by the selected stems, each in the form " <stem>:<count>".

KWIC w
Checks: term check of w.
Let s be the stem of w. First output "KWIC <s> count=<number of occurrences of s>". Then output all occurrences of s in occurrence order, one per line, each in the form "|<L>[<T>]<R>| <reference>". T is the token as written in the body (with its original uppercase and lowercase). L is the up to 30 characters immediately before the token within the body line containing the token. If there are fewer than 30 characters before the token, take all the characters there are and pad them on the left with spaces to 30 characters. R is the up to 30 characters immediately after the token. If there are fewer than 30 characters after the token, take all the characters there are and pad them on the right with spaces to 30 characters. L and R use the characters of the body as is (including spaces, digits, symbols and other tokens).

TF d w
Checks: document check of d. Term check of w.
With s the stem of w, output "TF <d> <s> <tf(d, s)>".

DF w
Checks: term check of w.
With s the stem of w, output "DF <s> <df(s)>".

VARIANTS w
Checks: term check of w.
Let s be the stem of w, and over all occurrences of s, count the number for each form. Output "VARIANTS <s> count=<number of distinct forms>" followed by the forms in ascending order, each in the form " <form>:<number>".

SIMILAR d k
Checks: document check of d. Number check of k (1 to 100).
For each document e other than d, with A the stem set of d and B the stem set of e, compute the Jaccard coefficient J = |A intersection B| / |A union B| (|X| is the number of elements of the set X). However, when |A union B| = 0, J = 0. Express J as an irreducible fraction p/q (q >= 1). When J = 0, it is 0/1. Sort the documents e in descending order of J, and documents with equal J in ascending order of document number, and output "SIMILAR <d>" followed by the first k (all of them if there are fewer than k), each in the form " <e>:<p>/<q>".

RANK k w1 w2 ... wn
Checks: number check of k (1 to 100). Term check of w1, w2, ..., wn (performed in this order).
Let Q be the set of the stems of w1, w2, ..., wn (duplicates counted once). For each document d, let matched be the number of stems s in Q with tf(d, s) >= 1, and let total be the sum of tf(d, s) over all stems s in Q. Sort the documents with matched >= 1 in descending order of matched, those with equal matched in descending order of total, and those with equal total as well in ascending order of document number. Output "RANK count=<number of documents with matched >= 1>" followed by the first k (all of them if there are fewer than k), each in the form " <document number>:<matched>:<total>".

INFO d
Checks: document check of d.
Output "INFO <d> lines=<number of lines of d> tokens=<number of tokens of d> indexed=<number of indexed tokens of d> stems=<number of elements of the stem set of d> top=<X>". X is "<s>:<tf(d, s)>" for the stem s in the stem set of d with the largest tf(d, s) (if there are several, the smallest stem among them). If d has no indexed tokens at all, X is "-".

LINE d i
Checks: document check of d. Number check of i (1 to 999). If i is greater than the number of lines of d: "ERROR NO LINE <d>:<i>".
Output "LINE <d>:<i> tokens=<number of tokens on line i of d>" followed by the tokens on line i of d from left to right, each in the form " <form>/<stem>" if it is an indexed token, or " <form>/-" if it is a stopword token.

STATS
Output "STATS docs=<number of documents> lines=<total number of lines of all documents> tokens=<total number of tokens of all documents> indexed=<total number of indexed tokens of all documents> stems=<number of index stems> stopwords=<number of stopwords>".

STOP w
Checks: word check of w. If w is in the stopword set: "ERROR ALREADY STOPWORD <w>".
Add w to the stopword set, and output "STOP <w> unindexed=<number of tokens of all documents whose form is w>".

UNSTOP w
Checks: word check of w. If w is not in the stopword set: "ERROR NOT STOPWORD <w>".
Remove w from the stopword set, and output "UNSTOP <w> indexed=<number of tokens of all documents whose form is w>".

APPEND d text
Checks: number check of d (1 to 999).
If there is no document with document number d, create a new document with document number d that has no body lines. Then add the text (as is, including spaces) to document d as the last line of its body. The line number of the added line is the number of lines of d before the addition plus 1. The tokens of the added line get positions numbered from the number of tokens of d before the addition plus 1, in order. Output "APPEND <d> line=<line number of the added line> tokens=<number of tokens of the added line> indexed=<number of indexed tokens among them> new=<N>". N is YES if the document was newly created, and NO otherwise.

DELETE d
Checks: document check of d.
Remove document d from the document collection, and output "DELETE <d> lines=<number of lines of the removed document> tokens=<number of tokens of the removed document>". A new document may later be created by APPEND with the document number of the removed document.

[Output format]
- For each command, output only the lines described in [Processing]. Every command outputs at least one line.
- Words and values within a line are separated by one space as described. However, the characters inside L and R of the occurrence lines of KWIC are as described. Do not put spaces at the end of lines, and do not output empty lines. End every line with a newline.
- Integers are written in decimal without extra leading zeros.
- There are the following 12 kinds of error lines (the parts in < > are replaced as described in [Processing]).
  ERROR UNKNOWN COMMAND <command name>
  ERROR BAD ARGUMENTS <command name>
  ERROR BAD WORD <argument>
  ERROR BAD NUMBER <argument>
  ERROR NO DOC <v>
  ERROR NO LINE <d>:<i>
  ERROR STOPWORD <v>
  ERROR STOPWORDS ONLY
  ERROR BAD TERM <T>
  ERROR SYNTAX
  ERROR ALREADY STOPWORD <w>
  ERROR NOT STOPWORD <w>

[Constraints]
- The initial stopwords number 0 to 50.
- The initial documents number 1 to 20, and the body of each document has 0 to 30 lines.
- There are 1 to 500 command lines (the "END" line is not counted).
- The number of documents is always 50 or less, and the total number of lines of all documents is always 1000 or less.
- There is no upper limit on the length of a body token (tokens longer than 30 characters may occur).

[Example]
Input:

In this example, the first SEARCH is interpreted as (connect OR (runner AND (NOT ran))); document 2 matches because it contains connect, and document 1 contains runner but also contains ran, so it does not match. In PHRASE, the stopword of matches any token, so connection (position 2), of (position 3), networks (position 4) of document 2 match. In NEAR, the distance 1 between connecting (position 6) and people (position 7) in document 2 is the minimum. In TOP, connect and peopl, with total frequency 3, come first in ascending order of stem, and of run and runner, with total frequency 2, the smaller run is third. In SIMILAR, the stem set of document 1 {run, runner, ran, past, peopl} and the stem set of document 2 {connect, network, peopl, node, hope} have an intersection of 1 element and a union of 9 elements, so the result is 1/9. The The in the APPEND line is a stopword, so indexed is 2, and in the following TF there are 3 occurrences of runner in document 1.
