[Overview]
Write a program that operates a B-tree index, which holds pairs of an integer key and a string value, exactly following the procedures of the textbook "Introduction to Algorithms" (by Cormen et al., commonly called CLRS). The program reads a sequence of commands from standard input, performs insertion (splitting full nodes in advance on the way down), deletion (CLRS cases 1, 2a, 2b, 2c, 3a and 3b), lookup with the search path, range scans and range counts, minimum and maximum, floor and ceiling, rank, movement with a cursor, level-order printing, a listing of pages (nodes), dumping and loading a tree, invariant checking, rebuilding and compacting, saving and restoring, and step-by-step trace output, and writes the results to standard output. Every procedure is fully specified, so the output is uniquely determined.

[Input format]
The first line contains N, the number of commands, and each of the following N lines contains one command. Each command consists of one or more words separated by single ASCII spaces; there is no whitespace at the start or end of a line, and there are no empty lines. The commands have the following 29 formats.

  CREATE t
  LOAD t s1 s2 ... sm
  INSERT k v
  BULKLOAD k1 v1 k2 v2 ... kp vp
  DELETE k
  DELRANGE a b
  GET k
  RANGE a b
  COUNT a b
  MIN
  MAX
  FLOOR k
  CEIL k
  RANK k
  SELECT i
  SEEK k
  NEXT
  PREV
  PRINT
  PAGES
  DUMP
  HEIGHT
  STATS
  VERIFY
  REBUILD
  COMPACT
  SAVE
  RESTORE
  TRACE f

The arguments mean the following.
- t, k, a, b, i, and k1 through kp are integers written in decimal notation without extra leading zeros. A negative number is written with an ASCII "-" in front, and "-0" does not appear.
- v, and v1 through vp are "values": words of 1 to 12 characters consisting of uppercase English letters (A to Z), lowercase English letters (a to z) and digits (0 to 9).
- f is ON or OFF.
- p in BULKLOAD is a symbol for the number of pairs and is not written in the input. p is at least 1.
- s1 through sm in LOAD are "tokens" that describe a tree, and m is a symbol for their number (it is not written in the input). m may be 0, in which case the line ends with t. Each token is one of "(", ")", or an "entry token". An entry token is an integer k in the same notation as above and a value v joined by an ASCII "=" (example: -15=apple), and it represents the entry with key k and value v. The token sequence is not necessarily a valid tree notation (see LOAD in [Processing]).
It is guaranteed that every line follows these formats and the ranges in [Constraints].

[Processing]
Process the commands in order from the first line, and output the result of each command according to [Output format]. For each command, first check the errors defined in "== Error checks ==" in the specified order, output only the line of the first error that applies, and do nothing else for that command (change no state at all). If no error applies, perform the processing in "== Commands ==".

== Shape of the B-tree ==
- The index is a B-tree with "minimum degree" t (an integer from 2 to 5 inclusive). A B-tree is a rooted tree made of "nodes", and the topmost node is called the "root".
- Each node holds a sequence of zero or more "entries". An entry is a pair of a key (an integer) and a value. Let m be the number of entries of a node; the entries, in sequence order, are written entry 0, entry 1, ..., entry m-1, and their keys key[0], key[1], ..., key[m-1].
- A node with no children is called a "leaf", and a node with children is called an "internal node". An internal node has exactly m+1 children, written in order c[0], c[1], ..., c[m]. The "left sibling" of c[j] is c[j-1] (when j>=1), and the "right sibling" is c[j+1] (when j<m).
- The depth of the root is 0, and the depth of a child of a node is the depth of that node plus 1.
- A node with 2t-1 entries is called "full".
- Each node has one "page number" (a non-negative integer). Two nodes that exist at the same time have different page numbers. How they are assigned is defined in "== Page numbers ==".
- "Preorder" is the order consisting of the node itself, followed by the preorder of the subtree rooted at c[0], the preorder of the subtree rooted at c[1], ..., the preorder of the subtree rooted at c[m]. "Inorder" is the order consisting of the inorder of the subtree rooted at c[0], entry 0, the inorder of the subtree rooted at c[1], entry 1, ..., entry m-1, the inorder of the subtree rooted at c[m] (in a leaf, it is the order from entry 0 to entry m-1).
- The "notation" of a node is the string formed by concatenating "[", the keys in sequence order separated by single ASCII spaces, and "]" (example: [10 20]; if there are no entries, it is []).
- The "tree notation" is a sequence of tokens separated by single ASCII spaces, defined for each node as follows. The notation of a leaf is "(", zero or more entry tokens, and ")" in this order. The notation of an internal node is "(", the notation of c[0], then for j=0, 1, ..., m-1 in this order the entry token of entry j and the notation of c[j+1], and finally ")" (the notation of an internal node with m=0 is "(", the notation of c[0], ")"). An entry token is "<key>=<value>". The tree notation is the notation of the root. For example, the tree notation of a tree whose root is [20] and whose children are the leaves [10] and [30 40] looks like "( ( 10=a ) 20=b ( 30=c 40=d ) )".

== Valid B-trees ==
- "Checking" a tree means searching for the first violation by the following procedure. Each node is given a "location", a depth, a "lower bound" lo and an "upper bound" hi as follows. The location of the root is root, its lower bound is -infinity and its upper bound is +infinity. For a node x with location L, lower bound lo and upper bound hi, its child c[j] has the location "L.j" (L followed by an ASCII "." and j; example: root.1.0), the lower bound key[j-1] of x if j>=1 or lo if j=0, and the upper bound key[j] of x if j<m or hi if j=m.
- Visit all nodes in preorder, and for each node examine (1) through (4) below in order. The check ends at the first violation found. If there is no violation, the result of the check is "no violation".
  (1) Count: it is a violation if the number of entries m is outside the allowed range. The allowed range is 0 to 2t-1 inclusive if the root is a leaf, 1 to 2t-1 inclusive if the root is an internal node, and t-1 to 2t-1 inclusive for a node other than the root.
  (2) Order: for j=0, 1, ..., m-2 in this order, it is a violation if key[j]>=key[j+1].
  (3) Range: for j=0, 1, ..., m-1 in this order, it is a violation if lo is not -infinity and key[j]<=lo, or if hi is not +infinity and key[j]>=hi.
  (4) Depth: when the node is a leaf, if it is the first leaf visited in preorder, remember its depth as the "reference depth". Otherwise, it is a violation if its depth differs from the reference depth.
- A tree in which the check finds no violation is called a "valid B-tree". In a valid B-tree, the keys of the entries listed in inorder are in strictly ascending order (no two keys are equal), and all leaves have the same depth. The "height" of a valid B-tree is the depth of its leaves (the height of a tree consisting of the root only is 0).
- When the tree of the index is not a valid B-tree, the index is said to be "damaged". A damaged index arises only through LOAD and RESTORE. INSERT, BULKLOAD, DELETE and DELRANGE on a valid B-tree keep the tree a valid B-tree.

== State ==
- The program holds the index (a B-tree and its minimum degree t), 3 "counters" (the split count splits, the merge count merges, the borrow count borrows), the cursor, the saved copy, and the trace mode.
- Initially, there is no index, the cursor is "unset", there is no saved copy, and the trace mode is OFF.
- The saved copy is replaced only by SAVE, and the trace mode changes only by TRACE (even when CREATE, LOAD, etc. replace the index, the saved copy and the trace mode stay as they are).
- The counters become 0 at CREATE, LOAD and COMPACT, and at the beginning of the processing of REBUILD. The split count increases by 1 at every child split, the merge count at every merge, and the borrow count at every case 3a.

== Page numbers ==
- The page number of the root made by CREATE is 0.
- In a tree made by LOAD or COMPACT, the nodes are numbered 0, 1, 2, ... in the order in which they appear in preorder.
- When a new node is created during an insertion, it gets the smallest non-negative integer that no node of the tree uses at that moment. In a root split, the new root is created first and given its page number, and after that the new node of the child split is created.
- In a merge, the right one of the two merged nodes disappears. When the root shrinks, the old root disappears. The page number of a node that disappears becomes a number that no node uses.
- Apart from these, the page number of a node does not change (it keeps the same number even when its entries or children change).

== Write count and free count ==
- The "content" of a node is the pair of its sequence of entries (the key and value of each entry) and its sequence of child page numbers.
- The "write count" of INSERT, BULKLOAD, DELETE or DELRANGE is the number of page numbers used by nodes of the tree after the processing that were not used before the processing, or for which the content of the node with that page number differs before and after the processing. The "free count" is the number of page numbers that were used before the processing and are not used after the processing. Changes in the middle of the processing are not counted; only the states before and after the processing are compared.

== Position and search ==
- For a node x and a key k, the "position" pos(x, k) is the smallest j (0<=j<m) that satisfies k<=key[j], or m if there is no such j. This definition is used as is even in a damaged tree whose entry keys are not in ascending order.
- The "search" for a key k is the following procedure. Let the "path" be an empty sequence and let x be the root. Append x to the end of the path and let j=pos(x, k). If j<m and key[j]=k, entry j of x is found and the search ends. Otherwise, if x is a leaf, the search ends without finding it. If neither, replace x with c[j] and repeat.

== Insertion ==
- "Splitting child j" of a node x means dividing the full child y=c[j] (which has entries 0 through 2t-2) into two. Create a new node z; the entries of z are entries t through 2t-2 of y (t-1 entries), and if y is an internal node, the children of z are c[t] through c[2t-1] of y (t children). y keeps entries 0 through t-2 and (if it is an internal node) c[0] through c[t-1]. Insert entry t-1 of y (the middle entry) at position j of the entry sequence of x, and insert z at position j+1 of the child sequence of x (z becomes c[j+1] of x). Add 1 to the split count.
- "Inserting" an entry with key k, which is not in the index, and value v is the following procedure.
  1. If the root is full, create a new node s that has no entries and has only the previous root as its child c[0], make s the root, and split child 0 of s.
  2. Let x be the root. While x is an internal node, repeat the following. Let j=pos(x, k); if c[j] of x is full, split child j of x, and if k>key[j], add 1 to j. Then replace x with c[j].
  3. Insert the entry (k, v) at position pos(x, k) of the entry sequence of the leaf x.

== Deletion ==
- "Merging child j" of a node x means combining the left node y=c[j] and the right node z=c[j+1] into one. The entry sequence of y becomes the concatenation of "the entries of y, entry j of x, the entries of z" in this order, and the child sequence of y becomes the concatenation of "the children of y, the children of z" in this order. Remove entry j and child c[j+1] from x; z disappears. Add 1 to the merge count. After this, if x is the root and x now has 0 entries, y becomes the new root and x disappears (this is called "the root shrinks").
- "Deleting" a key k that is in the index means performing the following procedure DEL(x, k) with x being the root. DEL(x, k) is called only when k is in the subtree rooted at x. In DEL(x, k), let j=pos(x, k) and do one of the following.
  (A) If j<m and key[j]=k (k is in x):
    - If x is a leaf, it is case 1. Remove entry j from x.
    - If x is an internal node, let y=c[j] and z=c[j+1].
      Case 2a: if y has t or more entries, find the entry p with the largest key in the subtree rooted at y (the last entry of the leaf reached from y by following the last child), perform DEL(y, key of p), and then replace entry j of x with p (key and value).
      Case 2b: if it is not case 2a and z has t or more entries, find the entry s with the smallest key in the subtree rooted at z (the first entry of the leaf reached from z by following the first child), perform DEL(z, key of s), and then replace entry j of x with s.
      Case 2c: if neither, merge child j of x, and perform DEL(y, k) on the merged node y.
  (B) Otherwise (k is not in x; in this case x is an internal node): let c=c[j]. If c has exactly t-1 entries, let L be the left sibling of c and R the right sibling of c (they may not exist), and do the first of the following that applies. If c has t or more entries, do nothing.
      Case 3a-left: if L exists and L has t or more entries, insert entry j-1 of x at the beginning of the entry sequence of c, and remove the last entry of L from L and make it entry j-1 of x. If L is an internal node, remove the last child of L from L and insert it at the beginning of the child sequence of c. Add 1 to the borrow count.
      Case 3a-right: if R exists and R has t or more entries, append entry j of x to the end of the entry sequence of c, and remove the first entry of R from R and make it entry j of x. If R is an internal node, remove the first child of R from R and append it to the end of the child sequence of c. Add 1 to the borrow count.
      Case 3b-left: if L exists, merge child j-1 of x (L and c are combined), and replace c with that merged node.
      Case 3b-right: otherwise, merge child j of x (c and R are combined), and replace c with that merged node.
    Then perform DEL(c, k).
- The "case sequence" of a deletion is the list of the cases 1, 2a, 2b, 2c, 3a-left, 3a-right, 3b-left and 3b-right performed during the deletion, in the order they were performed. Their names are 1, 2a, 2b, 2c, 3a-left, 3a-right, 3b-left and 3b-right, respectively. When nothing was done in (B), nothing is added. In cases 2a and 2b, the name of the case is added first, and then the cases inside DEL(y, ...) or DEL(z, ...) are added.

== Trace ==
- When the trace mode is ON, and only when INSERT inserts a new entry or DELETE deletes a key, output the following lines, which represent each stage of the procedure, in the order they occur, before the result line. They are not output when INSERT updates a value, when DELETE does not find the key, or for BULKLOAD, DELRANGE or REBUILD. Below, <x>, <y>, etc. are page numbers of nodes, and <notation> is the notation of a node.
  STEP grow page=<s>
    When step 1 of insertion creates the new root s (the line for the split of its child follows).
  STEP split page=<y> keys=<notation of y before the split> up=<key of the middle entry> new=<z>
    When a child split is performed.
  STEP place page=<x> keys=<notation of x after the insertion>
    When step 3 of insertion inserts the entry into the leaf x.
  STEP 1 page=<x> keys=<notation of x after the removal>
    When case 1 is performed.
  STEP 2a page=<x> pred=<key of p>
    When it is decided to perform case 2a (output before the lines of DEL(y, ...)).
  STEP 2b page=<x> succ=<key of s>
    When it is decided to perform case 2b (output before the lines of DEL(z, ...)).
  STEP 2c page=<x> merge=<y>+<z> keys=<notation of the merged node>
    When the merge of case 2c is performed.
  STEP 3a-left page=<x> child=<c> from=<L> keys=<notation of c after borrowing>
  STEP 3a-right page=<x> child=<c> from=<R> keys=<notation of c after borrowing>
    When case 3a-left or 3a-right is performed.
  STEP 3b-left page=<x> merge=<L>+<c> keys=<notation of the merged node>
  STEP 3b-right page=<x> merge=<c>+<R> keys=<notation of the merged node>
    When the merge of case 3b-left or 3b-right is performed.
  STEP shrink page=<y>
    When the root shrinks (output immediately after the line of the merge that caused it). y is the new root.
- The page of STEP 2c, 3b-left and 3b-right is the node x that performed the merge (the parent of the two merged nodes).

== Cursor ==
- The cursor takes one of the states "unset", a key (an integer), BEGIN, or END. The key the cursor points to is not necessarily in the index (even after that key is deleted, the cursor keeps pointing to that key).
- CREATE and LOAD make the cursor unset, and SEEK, NEXT and PREV move the cursor. No other command changes the cursor (a command that results in an error does not change it either).

== Error checks ==
- TRACE: there are no errors to check.
- CREATE: if t is not between 2 and 5 inclusive, output "ERROR BAD DEGREE <t>".
- LOAD: if t is not between 2 and 5 inclusive, output "ERROR BAD DEGREE <t>". Next, if the token sequence s1, ..., sm is not exactly the notation of one tree, output "ERROR SYNTAX <q>". q is the smallest q such that the sequence s1 through sq is not a prefix (the whole notation included) of any tree notation. If there is no such q (the whole sequence is an unfinished beginning of some tree notation), q=m+1.
- Any other command: first, if there is no index, output "ERROR NO INDEX". Next, if the command is one of INSERT, BULKLOAD, DELETE, DELRANGE, RANGE, COUNT, MIN, MAX, FLOOR, CEIL, RANK, SELECT, SEEK, NEXT, PREV, HEIGHT, COMPACT and the index is damaged, output "ERROR DAMAGED" (GET, PRINT, PAGES, DUMP, STATS, VERIFY, REBUILD, SAVE and RESTORE can be executed even when the index is damaged). Next, check the following for each command.
  DELRANGE, RANGE, COUNT: if a>b, output "ERROR BAD RANGE <a> <b>".
  SELECT: if i<1 or i is greater than the number of entries of the index, output "ERROR BAD POSITION <i>".
  NEXT, PREV: if the cursor is unset, output "ERROR NO CURSOR".
  RESTORE: if there is no saved copy, output "ERROR NO SAVE".

== Commands ==
Below, "<n>" denotes the number of nodes of the tree, "<keys>" the number of entries of the tree, "<h>" the height of the tree after the processing, "<w>" the write count, and "<f>" the free count. Writing an entry in the form "<key>=<value>" is called the "entry display".

CREATE t
- Create an index with minimum degree t consisting of only one leaf with no entries (page number 0), and replace the previous index with it. Set the counters to 0 and make the cursor unset. Output "CREATE t=<t>".

LOAD t s1 s2 ... sm
- Build the tree represented by the token sequence, and replace the previous index with it as an index with minimum degree t. Page numbers are assigned in preorder starting from 0. Set the counters to 0 and make the cursor unset. The tree does not have to be a valid B-tree. Output "LOAD t=<t> nodes=<n> keys=<keys> <status>". <status> is OK if the index is not damaged, and DAMAGED if it is damaged.

INSERT k v
- Search for the key k. If it is found, replace the value of that entry with v (the shape of the tree does not change), and output "INSERT <k> UPDATED old=<value before the replacement> writes=<w>". If it is not found, insert the entry (k, v), and output "INSERT <k> NEW splits=<number of splits performed in this insertion> height=<h> writes=<w>".

BULKLOAD k1 v1 k2 v2 ... kp vp
- For j=1, 2, ..., p in this order, perform the same processing as INSERT kj vj (no lines are output). Then output "BULKLOAD pairs=<p> new=<number of entries inserted> updated=<number of times a value was replaced> splits=<number of splits performed in this command> height=<h> writes=<w>". The write count compares the states before and after the whole command.

DELETE k
- Search for the key k. If it is not found, output "DELETE <k> NOT FOUND" (the tree does not change). If it is found, delete k and output "DELETE <k> REMOVED value=<value of the deleted entry> cases=<case sequence> height=<h> writes=<w> frees=<f>". <case sequence> is the names of the cases separated by ASCII "," (example: 3b-left,2a,1).

DELRANGE a b
- At the beginning of the processing, list the keys in the index that are at least a and at most b in increasing order, and delete them one by one in that order. Then output "DELRANGE <a> <b> removed=<number of keys deleted> merges=<number of merges performed in this command> borrows=<number of borrows performed in this command> height=<h> writes=<w> frees=<f>". The write count and the free count compare the states before and after the whole command.

GET k
- Search for the key k. If it is found, output "GET <k> FOUND value=<value> path=<path>"; if it is not found, output "GET <k> NOT FOUND path=<path>". <path> is the notations of the nodes of the search path, in order, separated by " -> " (an ASCII space, -, >, an ASCII space) (example: [10 20] -> [12 15]).

RANGE a b
COUNT a b
- Perform the following procedure SCAN(root). SCAN(x) adds 1 to the visit count and then, for j=0, 1, ..., m in this order, does the following. If x is an internal node and "j=0 or key[j-1]<b" and "j=m or key[j]>a", perform SCAN(c[j]). Then, if j<m and a<=key[j]<=b, add entry j of x to the result. The visit count starts from 0, and the entries of the result are in increasing order of key.
- RANGE outputs one line consisting of "RANGE <a> <b> count=<number of entries in the result> visited=<visit count>" followed, for each entry of the result in result order, by one ASCII space and the entry display. COUNT outputs "COUNT <a> <b> count=<number of entries in the result> visited=<visit count>".

MIN
MAX
- If the index is empty (has 0 entries), output "MIN EMPTY" ("MAX EMPTY" for MAX). Otherwise, output "MIN <entry display>" for the entry with the smallest key ("MAX <entry display>" for the entry with the largest key for MAX).

FLOOR k
CEIL k
- FLOOR outputs "FLOOR <k> <entry display>" for the entry with the largest key among the entries whose key is at most k if there is one, and "FLOOR <k> NONE" otherwise. CEIL outputs "CEIL <k> <entry display>" for the entry with the smallest key among the entries whose key is at least k if there is one, and "CEIL <k> NONE" otherwise.

RANK k
- Let r be the number of entries whose key is less than k, and output "RANK <k> <r>".

SELECT i
- For the i-th entry counted from the smallest key (counting from 1), output "SELECT <i> <entry display>".

SEEK k
- If there is an entry whose key is at least k, set the cursor to the smallest such key and output "SEEK <k> <entry display>" for that entry. Otherwise, set the cursor to END and output "SEEK <k> END".

NEXT
PREV
- NEXT moves the cursor as follows. If the cursor is a key c, move it to the smallest key greater than c, or to END if there is none. If it is BEGIN, move it to the smallest key, or to END if the index is empty. If it is END, it stays END.
- PREV moves the cursor as follows. If the cursor is a key c, move it to the largest key less than c, or to BEGIN if there is none. If it is END, move it to the largest key, or to BEGIN if the index is empty. If it is BEGIN, it stays BEGIN.
- If the cursor after the move is a key, output "NEXT <entry display>" ("PREV <entry display>" for PREV) for that entry. If it is END, output "NEXT END"; if it is BEGIN, output "PREV BEGIN".

PRINT
- Output the nodes of the tree by depth. The sequence for depth 0 consists of the root only, and the sequence for depth d+1 lists the children of the nodes of the sequence for depth d, in node order, and within each node from c[0] onward. For d=0, 1, ... in this order, until the sequence is empty, output one line consisting of "LEVEL <d>" followed, for each node of the sequence, by one ASCII space and the notation of the node.

PAGES
- Output all nodes of the tree in increasing order of page number, one line per node, as "PAGE <page number> <notation of the node> kids=<children>". <children> is, for an internal node, the page numbers of its children from c[0] onward separated by ASCII ","; for a leaf, it is "-".

DUMP
- Output "DUMP <t> <tree notation>".

HEIGHT
- Output "HEIGHT <height of the tree>".

STATS
- Let l be the number of leaves and F be (2t-1)*<n>; the "fill rate" u is the quotient of 100*<keys> divided by F (fractional part truncated). Output "STATS t=<t> nodes=<n> leaves=<l> keys=<keys> fill=<u>% splits=<split count> merges=<merge count> borrows=<borrow count>" (the % is the ASCII character).

VERIFY
- Check the tree; if there is no violation, output "VERIFY OK". If there is a violation, let <location> be the location of the node where the violation was found and <notation> its notation, and output the following line.
  (1) Count: "VERIFY FAIL COUNT at=<location> node=<notation> keys=<m> allowed=<smallest allowed count>..<largest allowed count>"
  (2) Order: "VERIFY FAIL ORDER at=<location> node=<notation> <comparison>". <comparison> is key[j], an ASCII ">=", and key[j+1] concatenated without spaces (example: 30>=20).
  (3) Range: "VERIFY FAIL RANGE at=<location> node=<notation> key=<key[j]> low=<lower bound> high=<upper bound>". A lower bound of -infinity is written "-inf", and an upper bound of +infinity is written "+inf".
  (4) Depth: "VERIFY FAIL DEPTH at=<location> node=<notation> depth=<depth of that node> expected=<reference depth>"

REBUILD
- Make the sequence of all entries of the tree in inorder, and let e be its length. Then create an empty index with the same minimum degree t, the same as CREATE, and set the counters to 0 (the cursor does not change), and process each entry of the sequence in order by the same procedure as INSERT (when the same key appears again, its value is replaced). The rebuilt index is not damaged. Output "REBUILD entries=<e> keys=<keys> nodes=<n> splits=<split count> height=<h>".

COMPACT
- From the sequence E of all entries of the tree in increasing order of key, build a new tree from the bottom level upward by the following procedure, and replace the previous tree with it.
  1. Let the entry sequence S be E, and let the sequence of child candidates C be empty.
  2. Let M be the number of entries in S, and let g be the quotient of (M+2t) divided by 2t (fractional part truncated). Let K=M-(g-1); let d be the quotient and r the remainder of K divided by g; among the g nodes to be built, the 1st through r-th nodes have d+1 entries each, and the remaining nodes have d entries each.
  3. Divide S, from the front, into the entries of the 1st node, one "separator" entry, the entries of the 2nd node, one separator entry, ..., the entries of the g-th node (there are g-1 separators). If C is empty, all the nodes built are leaves. If C is not empty, assign C from the front, to the nodes in order starting from the 1st node, (number of entries of that node + 1) at a time, as their children in the same order.
  4. If g=1, make the built node the root and finish. Otherwise, replace S with the sequence of separator entries and C with the sequence of the g nodes built, and go back to 2.
- The page numbers of the new tree are assigned in preorder starting from 0, and the counters are set to 0. Output "COMPACT nodes=<number of nodes before the replacement>-><number of nodes after the replacement> height=<h>".

SAVE
- Make a copy of the index (the minimum degree, the shape of the tree, the entries and page number of each node, and the counters) the saved copy, replacing the previous saved copy. Output "SAVE nodes=<n> keys=<keys> <status>". <status> is the same as for LOAD.

RESTORE
- Replace the index (the minimum degree, the shape of the tree, the entries and page number of each node) and the counters with a copy of the saved copy (the saved copy itself remains). The cursor and the trace mode do not change. Output "RESTORE nodes=<n> keys=<keys> <status>". <status> is the same as for LOAD.

TRACE f
- Set the trace mode to f and output "TRACE <f>". It can be executed even when there is no index.

[Output format]
- For each command, output only the lines described in [Processing].
- Words and values in a line are separated by single ASCII spaces as described. Do not put whitespace at the start or end of a line, and do not output empty lines. Every line ends with a newline.
- Integers are written in decimal notation without extra leading zeros, and negative numbers have a "-" in front ("-0" is never written). Values are written exactly as given in the input.
- There are the following 8 kinds of error lines (each < > part is replaced with the corresponding integer).
  ERROR NO INDEX
  ERROR DAMAGED
  ERROR BAD DEGREE <t>
  ERROR SYNTAX <q>
  ERROR BAD RANGE <a> <b>
  ERROR BAD POSITION <i>
  ERROR NO CURSOR
  ERROR NO SAVE

[Constraints]
- 1 <= N <= 1000
- Each line is at most 4000 characters long.
- t is an integer whose absolute value is at most 100 (it may be outside 2 to 5, in which case it is an error as described in [Processing]).
- k, a, b, i, k1 through kp, and the keys of entry tokens are all integers whose absolute values are at most 10^6.
- The number of pairs p of BULKLOAD is from 1 to 200, and the number of tokens m of LOAD is from 0 to 1500.
- When the token sequence of LOAD is a tree notation, every node of that tree has depth at most 10. Also, in every token sequence of LOAD, the number of "(" minus the number of ")" counted from the beginning is at most 11 at every position.
- The number of entries of the index is at most 500 at any time.

[Example]
Input:
15
CREATE 2
BULKLOAD 10 ant 20 bee 30 cat 40 dog
GET 40
INSERT 20 bat
TRACE ON
INSERT 50 elk
DELETE 10
TRACE OFF
RANGE 15 45
PRINT
PAGES
STATS
LOAD 2 ( ( 5=fox ) 3=gnu ( 7=hen ) )
VERIFY
MIN

Output:
CREATE t=2
BULKLOAD pairs=4 new=4 updated=0 splits=1 height=1 writes=3
GET 40 FOUND value=dog path=[20] -> [30 40]
INSERT 20 UPDATED old=bee writes=1
TRACE ON
STEP place page=2 keys=[30 40 50]
INSERT 50 NEW splits=0 height=1 writes=1
STEP 3a-right page=1 child=0 from=2 keys=[10 20]
STEP 1 page=0 keys=[20]
DELETE 10 REMOVED value=ant cases=3a-right,1 height=1 writes=3 frees=0
TRACE OFF
RANGE 15 45 count=3 visited=3 20=bat 30=cat 40=dog
LEVEL 0 [30]
LEVEL 1 [20] [40 50]
PAGE 0 [20] kids=-
PAGE 1 [30] kids=0,2
PAGE 2 [40 50] kids=-
STATS t=2 nodes=3 leaves=2 keys=4 fill=44% splits=1 merges=0 borrows=1
LOAD t=2 nodes=3 keys=3 DAMAGED
VERIFY FAIL RANGE at=root.0 node=[5] key=5 low=-inf high=3
ERROR DAMAGED

In BULKLOAD, when 40 is inserted, the root [10 20 30] (page 0) is full, so a new root (page 1) is created and then [10 20 30] is split. [10] remains in page 0, 20 moves up into the new root, and [30] becomes a new node (page 2). After that, 40 goes into page 2, so the 3 pages 0, 1 and 2 are written. In DELETE 10, the child [10] of the root [20] has t-1=1 entry, there is no left sibling, and the right sibling [30 40 50] has 2 or more entries, so it is case 3a-right; after 20 moves down into the child and 30 moves up into the root, 10 is removed from the leaf (case 1). The tree of LOAD is damaged because the key 5 of the root's left child is greater than or equal to the upper bound 3, so MIN cannot be executed.
