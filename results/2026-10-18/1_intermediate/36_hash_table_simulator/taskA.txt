[Overview]
Write a program that simulates a hash table. It handles six collision resolution modes: separate chaining (CHAIN), linear probing (LINEAR), quadratic probing (QUADRATIC), double hashing (DOUBLE), Robin Hood hashing (ROBINHOOD), and cuckoo hashing (CUCKOO). The program reads a sequence of commands from standard input, performs insertion of keys and values, lookup, deletion, deletion with tombstones, probe counting, automatic growing and shrinking based on the load factor, capacity changes and mode conversion, display of the table contents, statistics, histograms of clusters and costs, and key generation with a specified random number generator and comparison between modes, and writes the results to standard output. It can also display search paths and item movements, so that it is visible how collisions were resolved.

[Input format]
The first line contains the number of commands N. Each of the following N lines contains one command. Each line consists of a command name and zero or more arguments, separated by single spaces, with no spaces at the beginning or end of the line. A command name consists of 1 to 10 uppercase letters. There are the following 25 command formats.

  CREATE mode m
  MAXLOAD p
  MINLOAD p
  TRACE flag
  HASH key m
  PUT key v
  ADD key v
  GET key
  DEL key
  PROBE key
  GEN count len seed
  GENDEL count len seed
  RESIZE m
  CONVERT mode
  CLEAR
  DUMP
  MAP
  STATS
  KEYS
  TOP k
  SCAN c k
  CLUSTERS
  DIST
  COMPARE m
  BENCH m count len seed

The arguments are as follows.
- key is a "key": a string of 1 to 10 characters consisting only of lowercase letters (a to z) and digits (0 to 9).
- mode and flag are words of 1 to 10 characters consisting only of uppercase letters.
- v is an integer from -1000000 to 1000000 inclusive. A negative number is written with a leading "-", and a number of 0 or more is written without a sign.
- All other arguments (m, p, count, len, seed, k, c) are integers from 0 to 2147483647 inclusive.
All numbers are written in decimal without extra leading zeros (0 is written as "0"). A line of any of the 25 commands above always has exactly the number of arguments shown above, and each argument has the form described here. In addition, there may be lines whose command name is none of the 25 above. On such a line, the command name is followed by zero or more words of printable ASCII characters containing no spaces. It is guaranteed that every line follows this format and the [Constraints].

[Processing]
Process the commands one at a time in order from the first line, writing each command's output immediately. In the description below, strings enclosed in double quotes are strings that appear verbatim in the input or output. In output descriptions, a part such as <key> is replaced by its value.

1. Overall state
The program has the following state.
- Table: zero or one table. Initially there is no table.
- Maximum load factor MAXLOAD: an integer, initially 75.
- Minimum load factor MINLOAD: an integer, initially 0.
- Tracing: either ON or OFF, initially OFF.
The maximum load factor, the minimum load factor and tracing are settings separate from the table; they do not change when the table is recreated by CREATE.

2. Hash function, primes, two-decimal representation
- For a string s, an integer B of 0 or more, and a positive integer M, H(s, B, M) is computed as follows. Starting with h=0, for each character of s in order from the first, replace h with the remainder of "h * B + (the character code of that character)" divided by M. The value of h after all characters have been processed is H(s, B, M). Character codes are ASCII codes: "0" to "9" are 48 to 57, and "a" to "z" are 97 to 122. For example, H(ab, 31, 11) is 3, because the remainder of 97 divided by 11 is 9, and the remainder of 9*31+98=377 divided by 11 is 3.
- For a positive integer n, P(n) denotes the smallest prime that is n or more (primes are 2, 3, 5, 7, 11, ...). For example, P(1)=2, P(4)=5, P(11)=11, P(16)=17.
- For integers a and b of 0 or more, the "two-decimal representation of a / b" is "0.00" if b=0. Otherwise, let q be the quotient of 100*a divided by b (fractional part discarded); the representation is the concatenation, in this order, of the quotient of q divided by 100, ".", and the remainder of q divided by 100 written with two digits (prefixed with 0 if it has one digit). For example, 2 / 3 is "0.66", 7 / 2 is "3.50", and 5 / 1 is "5.00".

3. Table structure
A table has a mode, a capacity cap (an integer of at least 2), a number of items size, a number of tombstones tomb, and the following mode-specific structure. An "item" is a pair of a key and a value (an integer). A table never contains two or more items with the same key.
- CHAIN: cap "buckets" numbered 0 to cap-1. Each bucket has one "chain", which is an ordered sequence of zero or more items.
- LINEAR, QUADRATIC, DOUBLE, ROBINHOOD: cap "slots" numbered 0 to cap-1. Each slot is in one of the states empty, item, or tombstone. Tombstones appear only in LINEAR, QUADRATIC and DOUBLE; a ROBINHOOD slot is either empty or an item.
- CUCKOO: two parts, "table 1" and "table 2", each with cap slots numbered 0 to cap-1. Each slot is either empty or an item.
The value 2*cap if the mode is CUCKOO, and cap otherwise, is called the table's "number of slots" and is written S. tomb is always 0 in modes other than LINEAR, QUADRATIC and DOUBLE.
For a key s, let h1(s)=H(s, 31, cap), h2(s)=H(s, 37, cap), and step(s)=1+H(s, 37, cap-1), where cap is the capacity the table has at that time.

4. Writing positions and contents
<position>, which shows the place of an item in the output, is written as follows.
- CHAIN: the bucket index.
- LINEAR, QUADRATIC, DOUBLE, ROBINHOOD: the slot index.
- CUCKOO: "T1.<p>" for slot p of table 1, and "T2.<p>" for slot p of table 2 (example: T2.5).
The "content" of a slot is written as the key if it holds an item, "D" if it is a tombstone, and "-" if it is empty.

5. Search
A "search" for a key s "examines" places of the table one at a time in a fixed order, and ends when the item with key s is found or when it is determined that it is not found. The number of examinations is called the "probe count". The sequence obtained by appending "<position>:<content>" (for CHAIN, "<bucket index>:<key of the examined item>") each time a place is examined is called the "path". When the same place is examined two or more times, it is counted each time and appended to the path each time.
- CHAIN: Examine the items of the chain of bucket h1(s) one at a time from the head; if an item has key s, the search ends as found. If it is not found after examining all of them, the search ends as not found. If the chain is empty, the probe count is 0 and the path is empty.
- LINEAR, QUADRATIC, DOUBLE: For i = 0, 1, 2, ..., cap-1 in order, examine the following slot p.
    LINEAR: p is the remainder of h1(s)+i divided by cap
    QUADRATIC: p is the remainder of h1(s)+i*i divided by cap
    DOUBLE: p is the remainder of h1(s)+i*step(s) divided by cap
  If the examined slot is empty, the search ends as not found. If it holds an item with key s, the search ends as found. If it is a tombstone or an item whose key is not s, proceed to the next i. If the search has not ended after examining the slot for i=cap-1, it ends as not found (the probe count is then cap).
- ROBINHOOD: For i = 0, 1, 2, ... in order, examine the slot whose index is the remainder of h1(s)+i divided by cap. If the slot is empty, the search ends as not found. If it holds an item with key s, the search ends as found. If it holds another item and that item's distance is less than i, the search ends as not found. Otherwise, proceed to the next i. The "distance" of an item with key t in slot q is the remainder of q-h1(t)+cap divided by cap. Since the table always has an empty slot, the search ends within cap examinations.
- CUCKOO: First examine slot h1(s) of table 1; if it holds an item with key s, the search ends as found. Otherwise, examine slot h2(s) of table 2; if it holds an item with key s, the search ends as found, otherwise as not found. The probe count when not found is always 2.
For an item in the table, the probe count of a search for its key is called the item's "cost". For example, in CHAIN it is the item's position counted 1, 2, ... from the head of the chain; in ROBINHOOD it is the distance plus 1; in CUCKOO it is 1 if the item is in table 1 and 2 if it is in table 2.

6. Placement procedure
The "placement procedure" that places an item X with key s into the table is as follows for each mode. The placement procedure either succeeds or fails; when it succeeds, the <position> where X was placed is determined.
- CHAIN: Append X to the end of the chain of bucket h1(s). <position> is that bucket's index. It always succeeds.
- LINEAR, QUADRATIC, DOUBLE: Search for s (it is guaranteed not to be found). Place X in the first tombstone slot examined during that search if there is one; otherwise, in the empty slot where the search ended. When X is placed in a tombstone slot, tomb is decreased by 1; this is called "tombstone reuse". If the examined slots contained neither a tombstone nor an empty slot (this happens only in QUADRATIC after cap examinations), the procedure fails. For PUT and ADD, the result of the search performed at the beginning of the command is used as is.
- ROBINHOOD: With position q=h1(s) and distance d=0, repeat the following (a) to (c).
  (a) If slot q is empty, place X there and finish.
  (b) If the item Y in slot q has a distance less than d, take Y out, place X in slot q, let Y be the new X, and set d to Y's distance (before it was taken out). This is called a "displacement".
  (c) Set q to the remainder of q+1 divided by cap, increase d by 1, and return to (a).
  It always succeeds. <position> is the slot where the first item X was placed (the place where it was first placed by (a) or (b)). The number of displacements is called the "displacement count". For each displaced item Y, its move from the slot it was taken out of to the slot where it is next placed is recorded, in order of displacement, as "SHIFT <key of Y> <index of the slot it was taken out of> -> <index of the slot it was placed in>".
- CUCKOO: With table number t=1 and kick count k=0, repeat the following (a) to (c).
  (a) Let p=h1(key of X) if t=1, or p=h2(key of X) if t=2. If slot p of table t is empty, place X there and finish (success).
  (b) If k=cap, the procedure fails. The X at this point is called the "homeless" item.
  (c) Take out the item Y in slot p of table t, place X there, increase k by 1, and record "KICK <key of Y> T<t>.<p>". Let Y be the new X, switch t to the other table (1 to 2, 2 to 1), and return to (a).
  On success, <position> is the place where the item with key s is located when the procedure finishes. The final k is called the "kick count". Even on failure, the items moved by kicks remain in the table as they are.

7. Deletion
Deleting the item with key s found by a search is done as follows for each mode. In every mode, size is decreased by 1.
- CHAIN: Remove the item from the chain (the order of the following items does not change).
- LINEAR, QUADRATIC, DOUBLE: Make that slot a tombstone and increase tomb by 1.
- ROBINHOOD: After making that slot q empty, perform a "backward shift". Let j be the remainder of q+1 divided by cap, and while slot j holds an item whose distance is 1 or more, repeat the following: move that item to the slot whose index is the remainder of j-1+cap divided by cap (slot j becomes empty), record "SHIFT <key of that item> <j> -> <index of the destination>", and set j to the remainder of j+1 divided by cap. The number of items moved is called the "shift count".
- CUCKOO: Make that slot empty.

8. Rebuild
- The "old slot order" of a table's items is the order in which the items are listed as follows. In CHAIN, buckets 0 to cap-1 in order, each chain from head to tail. In LINEAR, QUADRATIC, DOUBLE, ROBINHOOD, slots 0 to cap-1 in order (tombstones are not included). In CUCKOO, slots 0 to cap-1 of table 1, followed by slots 0 to cap-1 of table 2.
- "Rebuilding" a list of items L into mode M and capacity c means creating a new empty table of mode M and capacity c, and placing the items of L in order from the first with the placement procedure of section 6. If even one placement procedure fails, the rebuild fails. Placement procedures inside a rebuild do not record SHIFT and KICK and do not change the statistics counters (section 11). When the rebuild succeeds, the contents of the current table (mode, capacity, items, tombstones) are replaced by those of the new table. The new table's tomb is 0 and its size is the number of items in L. The statistics counters are carried over unchanged.
- An "automatic rebuild" is performed with a given reason <reason> and initial capacity c as follows. List the current table's items in old slot order and, if there is a "pending item", append it at the end; call this list L. Rebuild L into capacity c without changing the mode; if it fails, replace c with P(2*c) and redo the rebuild from the beginning of L, repeating until it succeeds. When it succeeds, increase the rebuild count by 1 and output "REHASH <reason> <old capacity> -> <new capacity>".

9. Load check and shrink check
- The "load check" is performed exactly once, at the end of processing a PUT or ADD, when that PUT or ADD added a new item to the table (including PUTs performed inside GEN). If (size+tomb)*100 is greater than MAXLOAD*S, then: if size*200 is greater than MAXLOAD*S, an automatic rebuild is performed with reason load and initial capacity P(2*cap); otherwise, an automatic rebuild is performed with reason tomb and initial capacity cap (the same capacity). In either case, the check is not repeated afterwards.
- The "shrink check" is performed exactly once, at the end of processing a DEL, when that DEL deleted an item (including DELs performed inside GENDEL). Let c=P(cap / 2) (here / is division that discards the fractional part), and let S'=2*c if the mode is CUCKOO, and S'=c otherwise. When size*100 is less than MINLOAD*S, c is less than cap, and size*100 is less than or equal to MAXLOAD*S', the list of the current table's items in old slot order is rebuilt into capacity c without changing the mode. If this succeeds, increase the rebuild count by 1 and output "REHASH shrink <old capacity> -> <c>". If it fails, do nothing (output nothing).

10. Tracing
When tracing is ON, each of the commands PUT, ADD, GET and DEL outputs, immediately after its result line (the first line output in that command's description in section 13), the path of the search performed at the beginning of that command. That line consists of "PATH" followed by the elements of the path, separated by single spaces (if the path is empty, it is "PATH none"). Then the SHIFT and KICK lines recorded by that command's placement procedure or deletion are output in the order they were recorded. REHASH lines are output after these lines. When tracing is OFF, PATH, SHIFT and KICK lines are not output. Also, for processing performed inside GEN, GENDEL, COMPARE and BENCH, these lines are not output even if tracing is ON.

11. Statistics counters
A table has the following counters. All of them become 0 when the table is created by CREATE and are never reset to 0 by any other command (they remain unchanged after RESIZE, CONVERT and CLEAR).
- Total probe count: the sum of the probe counts of the searches that PUT, ADD, GET and DEL (including those performed inside GEN and GENDEL) perform at the beginning of the command. Searches by PROBE and searches inside rebuilds, COMPARE and BENCH are not included.
- Rebuild count: the number of automatic rebuilds and successful shrinks.
- inserts: the number of times a new item was added (including the case where the placement procedure failed and the item was added by an automatic rebuild); updates: the number of times a key was found and the value of an existing item was overwritten (including the case where the value did not change) (by PUT, ADD and GEN).
- hits: the number of times GET found an item; misses: the number of times GET did not find it.
- deletes: the number of times DEL and GENDEL deleted an item; absent: the number of times DEL and GENDEL did not find the key.

12. Key generation
GEN, GENDEL and BENCH generate keys from the arguments count, len and seed as follows. Start with x=seed. Each key is made by concatenating, in the order obtained, the len characters obtained by repeating the following operation len times: replace x with the remainder of 48271*x divided by 2147483647, and obtain one lowercase letter whose character code is 97+(the remainder of x divided by 26). For the second and later keys, the value of x left by the previous key continues to be used.

13. Commands
When there is no table, every command except CREATE, MAXLOAD, MINLOAD, TRACE, HASH, BENCH, and the commands that are not among the 25 above does nothing and outputs "ERROR NO TABLE". The following describes the processing when there is a table (for the commands just listed, regardless of whether there is a table). Error checks are performed in the order written; only the line of the first error that applies is output, and the command does nothing else.

CREATE mode m
Checks: if mode is none of CHAIN, LINEAR, QUADRATIC, DOUBLE, ROBINHOOD, CUCKOO (hereafter "the six mode names"), "ERROR BAD MODE <mode>". If m is not between 2 and 10000 inclusive, "ERROR BAD CAPACITY".
Processing: discard the previous table and create an empty table with mode mode and capacity P(m) (all statistics counters are 0). Output "CREATE <mode> cap=<P(m)>".

MAXLOAD p
Checks: if p is not between 10 and 95 inclusive, "ERROR BAD LOAD".
Processing: set the maximum load factor to p and output "MAXLOAD <p>". This command does not perform a rebuild.

MINLOAD p
Checks: if p is not between 0 and 40 inclusive, "ERROR BAD LOAD".
Processing: set the minimum load factor to p and output "MINLOAD <p>". This command does not perform a rebuild.

TRACE flag
Checks: if flag is neither ON nor OFF, "ERROR BAD ARGUMENT".
Processing: set tracing to flag and output "TRACE <flag>".

HASH key m
Checks: if m is not between 2 and 10000 inclusive, "ERROR BAD CAPACITY".
Processing: output "HASH <key> m=<m> h31=<H(key, 31, m)> h37=<H(key, 37, m)> step=<1+H(key, 37, m-1)>". This is computed independently of the table.

PUT key v
Search for key. Below, its probe count is written <probe count>.
- If found: change the item's value to v and output "PUT <key>=<v> UPDATED old=<old value> at=<position> probes=<probe count>".
- If not found: place the item (key, v) with the placement procedure and increase size by 1.
  On success, output the line "PUT <key>=<v> NEW at=<position> probes=<probe count>" with the following appended at the end depending on the mode. For LINEAR, QUADRATIC, DOUBLE, " reused" only when a tombstone was reused. For ROBINHOOD, " shifted=<displacement count>". For CUCKOO, " kicks=<kick count>". For CHAIN, nothing is appended (each appended part begins with a single space).
  If it fails in QUADRATIC, output "PUT <key>=<v> NEW probes=<probe count> full", and perform an automatic rebuild with the item (key, v) as the pending item, reason full, and initial capacity P(2*cap).
  If it fails in CUCKOO, output "PUT <key>=<v> NEW probes=<probe count> kicks=<kick count> failed", and perform an automatic rebuild with the homeless item as the pending item, reason kicks, and initial capacity P(2*cap).
  Finally, perform the load check.
The tracing lines (section 10) are output immediately after the line above that begins with "PUT".

ADD key v
Performs the same processing and output as PUT, except that when the key is found, the value is changed to "old value + v". The first word of the output line is ADD, and in the <v> part, write the new value when the key was found, or the value of the placed item (v) when it was not found.

GET key
Search for key; if found, output "GET <key>=<value> at=<position> probes=<probe count>"; if not found, output "GET <key> NOT FOUND probes=<probe count>".

DEL key
Search for key; if not found, output "DEL <key> NOT FOUND probes=<probe count>". If found, delete the item as in section 7 and output "DEL <key> OK at=<position> probes=<probe count>". For ROBINHOOD, " shifted=<shift count>" is appended at the end of this line. When an item was deleted, the shrink check is performed after the tracing lines.

PROBE key
Search for key and output a line consisting of "PROBE <key>", followed by the elements of the path in order, followed by "FOUND probes=<probe count>" if found or "MISS probes=<probe count>" if not found, each separated by a single space (example: "PROBE kiwi 3:pear 4:D 5:- MISS probes=3"; if the path is empty, "PROBE kiwi MISS probes=0"). PROBE changes neither the table nor the statistics counters, and outputs no tracing lines.

GEN count len seed
Checks: if any one of the following is not satisfied: count is between 1 and 500 inclusive, len is between 1 and 10 inclusive, seed is between 1 and 2147483646 inclusive, "ERROR BAD ARGUMENT".
Processing: generate count keys by the method of section 12 and, in the order generated, for the i-th key (counting from 1), perform the same processing as "PUT <that key> <i>". However, the PUT lines and tracing lines are not output; only the REHASH lines are output, in the order they occur. Finally, output "GEN <count> new=<number of new items added> updated=<number of times an existing item's value was overwritten>".

GENDEL count len seed
Checks: same as GEN.
Processing: generate count keys by the same method as GEN (with the same arguments, the key sequence is the same as GEN's) and, in the order generated, for each key perform the same processing as "DEL <that key>" (including the shrink check). However, the DEL lines and tracing lines are not output; only the REHASH lines are output, in the order they occur. Finally, output "GENDEL <count> deleted=<number of items deleted> missing=<number of times the key was not found>".

RESIZE m
Checks: if m is not between 2 and 10000 inclusive, "ERROR BAD CAPACITY". Let c=P(m), and let S'=2*c if the mode is CUCKOO, and S'=c otherwise; if size*100 is greater than MAXLOAD*S', "ERROR TOO SMALL". Rebuild the list of the current table's items in old slot order into capacity c without changing the mode; if it fails, "ERROR REBUILD FAILED" (the table does not change).
Processing: if the rebuild succeeds, output "RESIZE <old capacity> -> <c>". c may be the same as the old capacity (the tombstones disappear and the items are placed again). The rebuild count is not increased.

CONVERT mode
Checks: if mode is none of the six mode names, "ERROR BAD MODE <mode>". Let c be the current capacity, and let S'=2*c if mode is CUCKOO, and S'=c otherwise; if size*100 is greater than MAXLOAD*S', "ERROR TOO SMALL". Rebuild the list of the current table's items in old slot order into mode mode and capacity c; if it fails, "ERROR REBUILD FAILED" (the table does not change).
Processing: if the rebuild succeeds (the table's mode becomes mode), output "CONVERT <old mode> -> <mode> cap=<c>". mode may be the same as the old mode. The rebuild count is not increased.

CLEAR
Output "CLEAR <size>", then remove all items and tombstones and set size and tomb to 0. The mode, capacity and statistics counters do not change.

DUMP
First output "DUMP <mode> cap=<cap> size=<size> tomb=<tomb>", then output the following lines.
- CHAIN: one line per bucket starting from bucket 0: "<index> -" if the chain is empty; otherwise, a line consisting of "<index>" followed by the items of the chain from the head in the form "<key>=<value>", separated by single spaces (example: "4 fig=21 guava=60").
- LINEAR, QUADRATIC, DOUBLE: one line per slot starting from slot 0: "<index> -" if empty, "<index> D" if a tombstone, "<index> <key>=<value>" if an item.
- ROBINHOOD: one line per slot starting from slot 0: "<index> -" if empty, "<index> <key>=<value> d=<distance>" if an item.
- CUCKOO: one line per slot, in the order slots 0 to cap-1 of table 1, then slots 0 to cap-1 of table 2: "T<table number> <index> -" if empty, "T<table number> <index> <key>=<value>" if an item.

MAP
First output "MAP <mode> cap=<cap>". Then represent each bucket or slot by one character, and split them in order from index 0 into lines of 40 characters each (the last line may have fewer than 40 characters). Each line consists of the index represented by the first character of that line written with 5 digits (padded with leading zeros if it has fewer than 5 digits), a single space, and the characters in index order. The characters are as follows. Here, the "gauge" of an integer n of 0 or more is the one-digit numeral representing n if n is 9 or less, and "+" if n is 10 or more.
- CHAIN: "." if the chain is empty; otherwise, the gauge of the number of items in the chain.
- LINEAR, QUADRATIC, DOUBLE: "." if empty, "D" if a tombstone, and the gauge of "the item's cost - 1" if an item.
- ROBINHOOD: "." if empty, and the gauge of the distance if an item.
- CUCKOO: "." if empty, "#" if an item. Table 1 and table 2 are each split separately into lines of 40 characters starting from slot 0 (the index at the start of a line is the slot index within that table); all lines of table 1 are output before the lines of table 2, and each line is prefixed with "T1 " or "T2 " (the table number and a single space) (example: "T1 00000 #..#.").

STATS
Output the following 2 lines.
  STATS <mode> size=<size> cap=<cap> slots=<S> tomb=<tomb> load=<load factor>% longest=<max cost> avg=<average cost> probes=<total probe count> rehashes=<rebuild count>
  OPS inserts=<inserts> updates=<updates> hits=<hits> misses=<misses> deletes=<deletes> absent=<absent>
The load factor is the two-decimal representation of "100*size" / S, the max cost is the maximum of the costs of all items in the table (0 if there are no items), and the average cost is the two-decimal representation of "sum of costs" / size.

KEYS
Sort all keys in the table in ascending order, and output a line consisting of "KEYS <size>" followed by the keys in order, separated by single spaces (example: "KEYS 2 9lives fig"; if there are no items, "KEYS 0"). Ascending order of keys is lexicographic order by ASCII character code (digits come before lowercase letters, and if one key is a prefix of the other, the shorter one comes first).

TOP k
Checks: if k is not between 1 and 100 inclusive, "ERROR BAD ARGUMENT".
Processing: sort the table's items in descending order of cost, and for equal cost in ascending order of key, and select up to k items from the beginning. Let n be the number of selected items; first output "TOP <n>", then output one line per selected item in order: "<key> cost=<cost> at=<position>".

SCAN c k
Checks: if k is not between 1 and 100 inclusive, "ERROR BAD ARGUMENT". If c is S or more, "ERROR BAD CURSOR".
Processing: assign each bucket or slot of the table a "cursor number" from 0 to S-1: in CHAIN the bucket index; in LINEAR, QUADRATIC, DOUBLE, ROBINHOOD the slot index; in CUCKOO, slot p of table 1 is p and slot p of table 2 is cap+p. Starting with e=c, while e is less than S and fewer than k keys have been collected, collect the keys of the items at the place with cursor number e (in CHAIN, the keys of all items of the chain in order from the head; nothing is collected from tombstones and empty slots) and increase e by 1. When this ends, if e=S, set e=0. Output a line consisting of "SCAN next=<e>" followed by the collected keys in the order collected, separated by single spaces (if nothing was collected, just "SCAN next=<e>").

CLUSTERS
First, compute the sequence of "run" lengths as follows.
- CHAIN: for each non-empty chain, the number of its items.
- LINEAR, QUADRATIC, DOUBLE, ROBINHOOD: a "run" is a part where non-empty slots (holding an item or a tombstone) are consecutive in index order and that cannot be extended further on either side; take its length (number of slots). Slot cap-1 and slot 0 are treated as adjacent (circular). If there is no empty slot at all, there is considered to be one run of length cap.
- CUCKOO: all the run lengths computed in the same way as above for table 1 and for table 2, combined.
Output "CLUSTERS runs=<number of runs> longest=<length of the longest run>" (longest=0 if there are no runs), then output the histogram (below) of the sequence of run lengths.

DIST
Output "DIST keys=<size> longest=<max cost>", then output the histogram (below) of the sequence of costs of all items in the table. The max cost is the same as in STATS.

Histogram
The "histogram" of CLUSTERS and DIST outputs, for each distinct value x appearing in the sequence of values, one line in ascending order of x: "<x> <f> <bar>". f is the number of occurrences of x in the sequence, and the bar is f "#" characters if f is 50 or less, or 50 "#" characters followed by one "+" if f is greater than 50. If the sequence is empty, there are no histogram lines.

COMPARE m
Checks: if m is not between 2 and 10000 inclusive, "ERROR BAD CAPACITY".
Processing: let L be the list of the current table's items in ascending order of key, and c=P(m). First output "COMPARE keys=<number of items in L> cap=<c>". Then perform the following experiment for the modes CHAIN, LINEAR, QUADRATIC, DOUBLE, ROBINHOOD, CUCKOO in this order, outputting one line per mode. In the experiment, separately create an empty table of that mode with capacity c (all statistics counters 0), and for each item (key and value) of L in order from the first, perform the same processing as PUT on that table (including automatic rebuilds and the load check; the current value of the maximum load factor is used). Nothing is output during this. Then output "<mode> cap=<capacity of the experiment table> longest=<max cost> avg=<average cost> probes=<total probe count of the experiment table> rehashes=<rebuild count of the experiment table>". The max cost and average cost are computed for the experiment table by the same method as STATS. The current table and its statistics counters do not change.

BENCH m count len seed
Checks: if m is not between 2 and 10000 inclusive, "ERROR BAD CAPACITY". If count, len or seed is not in the same range as for GEN, "ERROR BAD ARGUMENT".
Processing: generate 2*count keys by the method of section 12; the first count keys generated are the "insertion keys" and the last count keys generated are the "query keys". Let c=P(m); first output "BENCH cap=<c> count=<count> len=<len> seed=<seed>". Then, for the modes CHAIN, LINEAR, QUADRATIC, DOUBLE, ROBINHOOD, CUCKOO in this order, as in COMPARE, separately create an empty table of that mode with capacity c, and for the i-th insertion key (counting from 1) perform, in order, the same processing as "PUT <that key> <i>" (nothing is output). Then search that table for the query keys one at a time in order; let u be the number of searches that did not find the key, and w the sum of the probe counts of those searches (when the same key appears two or more times, it is searched and counted each time). Output "<mode> cap=<capacity of the experiment table> keys=<size of the experiment table> hit=<average cost> misses=<u> miss=<two-decimal representation of w / u> rehashes=<rebuild count of the experiment table>". The average cost is computed for the experiment table by the same method as STATS. BENCH does not change the current table or its statistics counters.

Commands other than the 25 above
Output "ERROR UNKNOWN COMMAND <command name>".

[Output format]
- For each command, output only the lines described in [Processing]. Every command outputs at least one line.
- Words in a line are separated by single spaces as described. No spaces at the beginning or end of a line, and no blank lines are output. Every line ends with a newline.
- All numbers are written as decimal integers (negative numbers with a leading "-") without extra leading zeros. However, the index at the start of each MAP line is padded to 5 digits, and two-decimal representations are written as described in section 2.
- The error lines are the following 9 kinds (the parts in < > are replaced by the corresponding word).
  ERROR NO TABLE
  ERROR UNKNOWN COMMAND <command name>
  ERROR BAD MODE <mode>
  ERROR BAD CAPACITY
  ERROR BAD LOAD
  ERROR BAD ARGUMENT
  ERROR BAD CURSOR
  ERROR TOO SMALL
  ERROR REBUILD FAILED

[Constraints]
- 1 <= N <= 1000
- Throughout processing, the absolute value of every item's value is at most 1000000000.
- Throughout processing, the table capacity is always at most 20000 (including the experiment tables of COMPARE and BENCH).
- The lines of GEN, GENDEL, COMPARE and BENCH number at most 40 in total over the whole input.
- The absolute value of every integer needed in processing is less than 2^47 (the largest is 48271*x used in key generation).

In this example, the capacity is P(6)=7. The h1 values of apple, bean, corn and cod are all 1, so LINEAR looks for a free slot starting from slot 1. Slot 2, from which bean was deleted, becomes a tombstone, and cod reuses that tombstone. The final PUT kiwi makes 4 items; (4+0)*100=400 is greater than 50*7=350, and 4*200=800 is also greater than 350, so an automatic rebuild to a table of capacity P(14)=17 is performed.
