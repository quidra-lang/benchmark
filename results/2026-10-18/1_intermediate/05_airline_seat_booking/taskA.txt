[Overview]
Write a program that manages the seat maps and bookings of scheduled flights. It defines the seat layouts of aircraft, creates flights operated with those aircraft, and then handles accepting bookings and assigning seats automatically, changing and swapping seats, cancellations, check-in, upgrades to a higher class, closing a flight (denied boarding and calculation of compensation), determining the boarding order, and displays such as the seat map and the passenger manifest. The program reads commands from standard input, processes them one at a time in the order given, and writes the results to standard output.

[Input format]
The first line contains N, the number of command lines that follow. Each of the following N lines is one command. Each line consists of one or more tokens separated by a single space, with no spaces at the beginning or end of the line.
In the descriptions below, <...> marks a part where a value goes, and [...] marks a part that may be omitted. The symbols < > [ ] themselves never appear in the input. In the output, the only one of them that appears is the > contained in the "->" (an ASCII hyphen followed by a greater-than sign) of lines such as MOVED.

The commands are as follows.

Aircraft definition:
AIRCRAFT <model> <base_row> <limit>
CABIN <class> <from_row> <to_row> <block1> <block2> ...
EXIT <row1> <row2> ...
BLOCKED <seat1> <seat2> ...
END

Flight and booking operations:
FLIGHT <flight> <model> <overbook>
BOOK <PNR> <flight> <class> <passenger1> <passenger2> ...
SEAT <PNR> <name> <seat>
SWAP <PNR1> <name1> <PNR2> <name2>
CANCEL <PNR> [<name>]
STATUS <name> <tier>
CHECKIN <PNR>
VOLUNTEER <PNR> <name>
UPGRADE <flight>
CLOSE <flight>
BLOCK <flight> <seat>
UNBLOCK <flight> <seat>

Display:
MAP <flight>
MANIFEST <flight>
LOADFACTOR <flight>
BALANCE <flight>
BOARDING <flight>
AVAIL <flight> <class>
INFO <PNR>
FIND <name>

The values mean the following.
- <class> is one of F (first), J (business) and Y (economy). F is the highest and Y the lowest; from highest to lowest the order is F, J, Y.
- <seat> is a row number (a decimal integer without leading zeros) immediately followed by a seat letter (one uppercase English letter); for example, 12C is seat C in row 12.
- <passenger> has the form <name>:<type> or <name>:<type>:<pref>. <type> is one of ADULT (adult), CHILD (child) and INFANT (infant), and <pref> is a preference for the kind of seat, one of W (window), M (middle) and A (aisle).
- <tier> is a membership tier, one of PLATINUM, GOLD, SILVER and NONE (no tier).
- <PNR> is a booking number, <flight> is the name of a flight, and <model> is the name of an aircraft.
- <base_row>, <limit>, <overbook>, <from_row>, <to_row> and <row> are decimal integers.

[Processing]
1. Initial state
Initially there are no aircraft, no flights and no bookings, and everyone's membership tier is NONE.

2. Errors
Check the error conditions listed in the description of each command, in the order listed. For the first condition that holds, output only one line consisting of ERROR followed by a single space and the message (e.g. ERROR unknown flight QD999), and the command ends without changing anything. If none of the conditions holds, process the command as described and output the lines as described.

3. Aircraft definition
A new aircraft definition starts with the line AIRCRAFT <model> <base_row> <limit> and ends with the line END. Only CABIN, EXIT and BLOCKED lines appear between them. The base row and the limit are used by BALANCE.
- CABIN <class> <from_row> <to_row> <block1> <block2> ...: every row from from_row to to_row (inclusive) belongs to that class. In each row, the seats with the seat letters of block1, block2, ... are arranged from left to right in this order, and there is an aisle between adjacent blocks. For example, "CABIN Y 6 17 ABC DEF" means that rows 6 through 17 are economy, and each row has the three seats A, B, C and the three seats D, E, F on either side of an aisle.
- EXIT <row1> ...: the listed rows are exit rows.
- BLOCKED <seat1> ...: the listed seats are blocked seats of this aircraft.
- END: registers the aircraft and outputs one line "AIRCRAFT <model> <class> <seats> <class> <seats> ...". The pairs of class and seat count are listed in the order F, J, Y for the classes the aircraft has. The seat count is the number of seats of that class that are not blocked seats.
- The lines AIRCRAFT, CABIN, EXIT and BLOCKED output nothing.

4. Seat terminology
- Seat kind: in each row, the leftmost seat of the first (leftmost) block and the rightmost seat of the last (rightmost) block are window seats (W). Of the other seats, those at the left end or right end of a block are aisle seats (A), and the rest are middle seats (M). For example, in a row with layout ABC DEFG HJK, A and K are W; C, D, G and H are A; and B, E, F and J are M. In a row with layout A CD, A and D are W and C is A.
- Row block: the set of seats of one row that belong to one block is called a row block.
- Left to right: seat letters increase alphabetically from left to right (see [Constraints]), so the "left to right" order within one row is the same as ascending order of seat letters.
- Scan order: the order in which the seats of a class are sorted by ascending row number and, within the same row, from left to right is called the scan order.
- Free seat: a seat that is not a blocked seat on that flight and in which nobody sits is called a free seat.

5. Flights, bookings and passengers
- Flights are created with FLIGHT. A flight has a set of blocked seats (at creation the same as the aircraft's blocked seats; it changes with BLOCK and UNBLOCK), a booking limit for each class, a state that is either open or closed (open at creation), and a volunteer list (empty at creation). The booking limit is floor(S * (100 + overbook) / 100), where S is the aircraft's seat count of that class, the value output by END. The booking limit never changes afterwards.
- Bookings are created with BOOK. A booking has a PNR, a flight, a sequence of passengers (in the order written in BOOK), and whether it is checked in (not checked in at creation).
- ADULT and CHILD are passengers who need a seat. An INFANT has no seat and sits on the lap of an adult of the same booking. The k-th INFANT in listed order in BOOK sits on the lap of the k-th ADULT in listed order. An adult who has an infant on their lap is called an "adult with an infant".
- Each passenger has a current class. Initially it is the class given in BOOK, and it may change by UPGRADE. A passenger who needs a seat either has one seat or is in the "unassigned" state, without a seat.
- The passengers on a flight are the passengers who are included in the bookings of that flight and have not yet been removed.
- Passenger order: the order in which the passengers of a flight are sorted by the order in which their bookings were accepted (the order in which BOOK succeeded) and, within the same booking, by listed order is called the passenger order.
- Booked count of a class: the number of passengers on the flight who need a seat and whose current class is that class (those with a seat plus those unassigned).
- Removal: to remove a passenger from a flight means to free that passenger's seat, take the passenger out of the booking, and delete the passenger from the volunteer list if listed there. When an adult with an infant is removed, the infant is removed at the same time. When only an infant is removed, the adult who had that infant on their lap is no longer an adult with an infant.
- The PNR of a booking that has no passengers left is treated as a nonexistent PNR by all subsequent commands. However, a PNR once accepted by BOOK can never be used by BOOK again.

6. Seating conditions
A passenger p who needs a seat can sit in a seat s of p's current class when all three of the following hold.
(1) s is a free seat.
(2) If p is a CHILD or an adult with an infant, the row of s is not an exit row.
(3) If p is an adult with an infant, no adult with an infant other than p sits in the same row block as s.

7. Individual seat selection
This is the procedure for choosing one seat of class c for a passenger p. The candidates are the seats of c for which p satisfies the seating conditions, in scan order. If p has a preference and the candidates include seats of the preferred kind, choose the first of those in scan order. Otherwise, choose the first candidate. If there are no candidates, no seat is found.

8. Reassignment
Examine the unassigned passengers of the flight one at a time in passenger order, and perform individual seat selection in that passenger's current class. If a seat is found, seat the passenger there and output "REASSIGNED <PNR> <name> <seat>". The reassignment ends after every passenger has been examined once (no passenger is examined twice).

9. Seat assignment at booking
Let P1, P2, ..., Pk be the passengers who need a seat in a booking accepted by BOOK, in listed order.
- When k is 1: the method is SINGLE. Perform individual seat selection for P1 in the booked class and seat P1 in the seat found. If none is found, P1 becomes unassigned.
- When k is 2 or more: examine "candidates" in order as follows. A candidate is a sequence S1, ..., Sk of k seats of the booked class and means that Pi sits in Si. A candidate "fits" when, assuming P1, ..., Pk are seated in their respective seats at the same time, Pi satisfies the seating conditions for Si for every i (for condition (3), the other adults with an infant who sit in the same candidate are counted in addition to the passengers already seated). Examine the candidates of stage 1, stage 2 and stage 3 in this order, and within each stage in the order described below; adopt the first candidate that fits and seat everyone in its seats. The method is the name of the stage in which that candidate was found. Stages 1 to 3 do not use preferences. Also, when seats in a sequence are counted in each stage, as in "k consecutive seats" or "the x-th seat from the left", blocked seats and occupied seats also count as one seat each (a candidate that contains such a seat does not fit, by condition (1)).
  Stage 1 (BLOCK): the candidates are k consecutive seats from left to right within one row block, with S1, ..., Sk being those k seats ordered from left to right. Examine the rows in ascending order, within the same row the blocks from left to right, and within the same block the starting positions from left to right. Blocks with fewer than k seats produce no candidates.
  Stage 2 (ROW): the candidates are k consecutive seats when the seats of one row are lined up in a single line from left to right, ignoring the aisles, with S1, ..., Sk being those k seats ordered from left to right. Examine the rows in ascending order, and within the same row the starting positions from left to right.
  Stage 3 (STACK): for h = 2, 3, ..., k in this order, let w = ceil(k / h) and examine the following candidates. A candidate is determined by a starting row r, a block b, and a starting position x (1 or more) counted from the left within block b; for j = 0, 1, ..., k - 1, S(j+1) is "the seat in row r + floor(j / w) that is the (x + (j mod w))-th from the left of block b", where j mod w is the remainder of j divided by w. In other words, using the same w columns, seats are assigned one row at a time starting from row r, w seats from the left in each row (in the last row, only as many seats from the left as the number of remaining people). A candidate is not considered if x + w - 1 exceeds the number of seats of block b, or if any of the rows used (from row r to row r + ceil(k / w) - 1) does not belong to the booked class. Within the same h, examine r in ascending order, within the same r the blocks from left to right, and within the same block x in ascending order.
  Stage 4 (SPLIT): if no candidate of stages 1 to 3 fits, the method is SPLIT. Perform individual seat selection in the booked class for P1, ..., Pk one at a time in this order, and seat each in the seat found (the seat of a passenger seated earlier is not a free seat for later passengers). Passengers for whom no seat is found become unassigned.

10. Commands
* AIRCRAFT, CABIN, EXIT, BLOCKED, END
As described in section 3. There are no errors.

* FLIGHT <flight> <model> <overbook>
Errors:
1. A flight with the same flight name already exists: duplicate flight <flight>
2. No aircraft of that model has been defined: unknown aircraft <model>
Creates the flight and outputs one line "FLIGHT <flight> <model> <class> <seats>/<booking_limit> ...". The pairs are listed in the order F, J, Y for the classes the aircraft has, and the seat count is the value output by END.

* BOOK <PNR> <flight> <class> <passenger1> ...
Errors:
1. The PNR has already been accepted by an earlier BOOK (including when that booking has no passengers left): duplicate PNR <PNR>
2. The flight does not exist: unknown flight <flight>
3. The flight is closed: flight <flight> is closed
4. The flight's aircraft does not have that class: no cabin <class> on <flight>
5. Two or more passengers in this BOOK have the same name: duplicate name <name> in <PNR> (<name> is the name of the first passenger, examining the passengers in listed order, who has a passenger with the same name before them)
6. A passenger (including an infant) with the same name as a passenger of this BOOK is already on the flight: <name> already on <flight> (<name> is the name of the first such person in listed order)
7. There is no ADULT: no adult in <PNR>
8. The number of INFANTs is greater than the number of ADULTs: too many infants in <PNR>
9. The booked count of the class plus the number of passengers in this booking who need a seat exceeds the booking limit: limit exceeded for <flight> <class>
Accepts the booking, sets everyone's current class to the given class, and assigns seats as described in section 9. Then outputs one line "BOOKED <PNR> <flight> <class> <method> <name>:<result> <name>:<result> ...". The items <name>:<result> are listed for all passengers including infants, in listed order; <result> is the seat, UNASSIGNED if unassigned, or LAP for an infant.

* SEAT <PNR> <name> <seat>
Errors:
1. The PNR does not exist: unknown PNR <PNR>
2. The booking's flight is closed: flight <flight> is closed
3. The booking has no passenger with that name: no passenger <name> in <PNR>
4. The passenger is an INFANT: infant <name> has no seat
5. The seat is not a seat of the passenger's current class on the flight's aircraft (including a seat that does not exist on the aircraft): no seat <seat> in cabin <class> (<class> is the passenger's current class)
6. The seat is a blocked seat on that flight: seat <seat> is blocked
7. Someone sits in the seat (including the passenger themself): seat <seat> is occupied
8. Seating condition (2) is not satisfied: exit row <row> not allowed for <name>
9. Seating condition (3) is not satisfied: infant limit reached at <seat>
Moves the passenger to the seat (the seat the passenger sat in until then becomes free) and outputs "MOVED <PNR> <name> <old_seat> -> <seat>". Then performs reassignment.
Note that when the processing of any command has finished, no seat remains in which an unassigned passenger could sit while satisfying the seating conditions (see sections 8 and 9), so a SEAT that names an unassigned passenger always results in one of errors 5 to 9. Therefore the passenger of a successful SEAT always has an old seat.

* SWAP <PNR1> <name1> <PNR2> <name2>
Errors:
1. For PNR1 and name1, check the same conditions with the same messages as SEAT errors 1 to 3 (PNR1 does not exist: unknown PNR <PNR1>; the flight is closed: flight <flight> is closed; the booking has no passenger named name1: no passenger <name1> in <PNR1>), in this order.
2. Then, for PNR2 and name2, check the same three conditions with the same messages, in this order.
3. The two are the same passenger: cannot swap <name1> with itself
4. Checking the passenger name1 and then the passenger name2, the passenger is an INFANT: infant <name> has no seat
5. The flights of the two bookings differ: <PNR1> and <PNR2> are on different flights
6. The current classes of the two passengers differ: <name1> and <name2> are in different cabins
7. Checking the passenger name1 and then the passenger name2, the passenger is unassigned: <name> has no seat
8. Assuming that both passengers first vacate their seats and then the passenger name1 sits in the seat of the passenger name2 and the passenger name2 sits in the seat of the passenger name1 at the same time, either of the two does not satisfy the seating conditions for the new seat (for condition (3), the other passenger is also counted as sitting in their new seat): swap of <name1> and <name2> breaks seating rules
Swaps the seats of the two passengers and outputs "SWAPPED <PNR1> <name1> <new seat of name1> <PNR2> <name2> <new seat of name2>". Then performs reassignment.

* CANCEL <PNR> [<name>]
Errors:
1. The PNR does not exist: unknown PNR <PNR>
2. The booking's flight is closed: flight <flight> is closed
3. A name is given and the booking has no passenger with that name: no passenger <name> in <PNR>
4. A name is given, and one or more passengers remain after excluding the cancellation targets, and none of them is an ADULT: <PNR> would have no adult
Without a name, all passengers of the booking are the cancellation targets; with a name, that passenger is the target (together with the infant, if the passenger is an adult with an infant). Removes all targets from the flight and outputs "CANCELLED <PNR> <name> <name> ...". The names are the target passengers in listed order. Then performs reassignment.

* STATUS <name> <tier>
There are no errors. Sets the membership tier of the person with that name and outputs "STATUS <name> <tier>". There is one membership tier per name, common to all flights. It applies both to passengers who have already booked and to passengers who book later.

* CHECKIN <PNR>
Errors:
1. The PNR does not exist: unknown PNR <PNR>
2. The booking's flight is closed: flight <flight> is closed
3. The booking is already checked in: <PNR> already checked in
Marks the booking as checked in and outputs "CHECKIN <PNR> <count>". The count is the number of passengers remaining in the booking (including infants).

* VOLUNTEER <PNR> <name>
Accepts a volunteer to give up their seat and not board.
Errors:
1. The PNR does not exist: unknown PNR <PNR>
2. The booking's flight is closed: flight <flight> is closed
3. The booking has no passenger with that name: no passenger <name> in <PNR>
4. The passenger is not an ADULT, or is an adult with an infant: <name> cannot volunteer
5. The passenger is unassigned: <name> has no seat
6. The passenger is already on the volunteer list: <name> already volunteered
Appends the passenger to the end of the flight's volunteer list and outputs "VOLUNTEER <PNR> <name> <seat>".

* UPGRADE <flight>
Errors:
1. The flight does not exist: unknown flight <flight>
2. The flight is closed: flight <flight> is closed
List the classes of the flight's aircraft from highest to lowest, and make each two adjacent classes a pair (higher class, lower class). For example, with F, J, Y there are the two pairs (F, J) and (J, Y); with only F and Y there is the one pair (F, Y). Process the pairs from the highest one down, as follows.
- First, among the passengers whose current class at that point is the lower class, the targets are those who are ADULT, are not adults with an infant, and whose membership tier is not NONE (including both those with a seat and those unassigned). Sort them by membership tier (in the order PLATINUM, GOLD, SILVER) and, within the same tier, by passenger order.
- Process the targets one at a time in order. If the booked count of the higher class is greater than or equal to the booking limit of the higher class, finish processing this pair. Otherwise, perform individual seat selection in the higher class for that passenger, and if no seat is found, finish processing this pair. If one is found, free the old seat, change the current class to the higher class, seat the passenger in that seat, and output "UPGRADED <PNR> <name> <lower_class> <old_seat> -> <higher_class> <new_seat>". If the passenger was unassigned, the old seat is UNASSIGNED.
After all pairs have been processed, perform reassignment, and finally output "UPGRADE <flight> <count>". The count is the number of passengers upgraded by this command.

* CLOSE <flight>
Errors:
1. The flight does not exist: unknown flight <flight>
2. The flight is closed: flight <flight> is closed
Closes boarding by the following steps.
(1) Process the bookings that have one or more passengers left and are not checked in, one at a time in the order the bookings were accepted. Output "NOSHOW <PNR> <count>" (the count is the number of passengers of the booking, including infants) and remove all passengers of the booking from the flight.
(2) Perform reassignment.
(3) Process the classes of the aircraft one at a time in the order F, J, Y. For each class, examine one at a time, in the order of the volunteer list, the volunteers who, at the moment processing of that class begins, have a seat and whose current class is that class. If, assuming that volunteer's seat became free, one or more of the unassigned passengers of the same class would satisfy the seating conditions for that seat, the volunteer is denied boarding voluntarily. That is, output "DENIED VOLUNTARY <PNR> <name> <class> <compensation>", remove the volunteer from the flight, and then perform reassignment. If there is no such unassigned passenger, the volunteer stays in their seat.
(4) Deny boarding involuntarily to all passengers who are still unassigned, one at a time in passenger order. That is, output "DENIED INVOLUNTARY <PNR> <name> <class> <compensation>" and remove the passenger from the flight (if the passenger is an adult with an infant, the infant is removed too).
(5) Mark the flight as closed and output "CLOSED <flight> denied <count> compensation <total>". The count is the number of passengers for whom a DENIED line was output in (3) and (4) (infants removed together with them are not counted), and the total is the sum of the compensation amounts of those lines.
The compensation depends on the passenger's class at the time boarding is denied, as follows. A CHILD gets half the amount in this table. Infants get no denied-boarding line and no compensation.
F: voluntary 500, involuntary 1000
J: voluntary 300, involuntary 600
Y: voluntary 150, involuntary 300

* BLOCK <flight> <seat>
Errors:
1. The flight does not exist: unknown flight <flight>
2. The flight is closed: flight <flight> is closed
3. The seat does not exist on the flight's aircraft (it is in no class): no seat <seat> on <flight>
4. The seat is already a blocked seat on that flight: seat <seat> is blocked
Makes the seat a blocked seat of this flight and outputs "BLOCK <flight> <seat>". If someone was sitting in the seat, that passenger is taken out of the seat and made unassigned, then individual seat selection is performed in the passenger's current class, and if a seat is found, the passenger is seated there. Then outputs "DISPLACED <PNR> <name> <old_seat> -> <new_seat>". If no new seat was found, <new_seat> is UNASSIGNED (the passenger stays unassigned). Finally performs reassignment.

* UNBLOCK <flight> <seat>
Errors:
1. The flight does not exist: unknown flight <flight>
2. The flight is closed: flight <flight> is closed
3. The seat does not exist on the flight's aircraft: no seat <seat> on <flight>
4. The seat is not a blocked seat on that flight: seat <seat> is not blocked
Removes the seat from the blocked seats of this flight (seats that were blocked in the aircraft definition can also be removed), outputs "UNBLOCK <flight> <seat>", and then performs reassignment.

* MAP <flight>
Errors:
1. The flight does not exist: unknown flight <flight>
Can also be used for closed flights. First outputs "MAP <flight>". Then, for the classes the aircraft has, in the order F, J, Y, outputs the following lines.
- "CABIN <class>"
- A header line: three spaces followed by the blocks of that class in definition order, separated by a single space (e.g. "   ABC DEF").
- For each row of that class, one line per row in ascending row order: the row number right-aligned in width 2 (preceded by one space if it has one digit), a single space, and then, for each block, the characters representing its seats from left to right without spaces, with a single space between blocks (e.g. " 8 ..X X.."). The character representing a seat is # if it is a blocked seat on that flight, X if someone sits in it, E if it is a free seat in an exit row, and . for any other free seat.

* MANIFEST <flight>
Errors:
1. The flight does not exist: unknown flight <flight>
Can also be used for closed flights. First outputs "MANIFEST <flight> seated <seated_count> unassigned <unassigned_count> infants <infant_count>", where <seated_count> is the number of passengers with a seat, <unassigned_count> is the number of unassigned passengers, and <infant_count> is the number of infants on the flight. Then outputs the passengers with a seat, one per line, by ascending row of the seat and, within the same row, from left to right, followed by the unassigned passengers, one per line, in passenger order. Each line is "<seat> <class> <PNR> <name> <type>", where <seat> is --- if unassigned and <class> is the current class. After that, the following items are appended, only those that apply, in this order, each preceded by a single space.
- "+<infant_name>" for an adult with an infant
- the tier, if the membership tier is not NONE
- CHECKED, if the booking is checked in
- VOL, if the passenger is on the volunteer list

* LOADFACTOR <flight>
Errors:
1. The flight does not exist: unknown flight <flight>
Can also be used for closed flights. First outputs "LOADFACTOR <flight>". Then, for the classes the aircraft has, in the order F, J, Y, outputs one line each "<class> <seated>/<seats> <load_factor> booked <booked>/<booking_limit>", and finally outputs "ALL <total_seated>/<total_seats> <load_factor>". The seated count is the number of passengers whose current class is that class and who have a seat, and the seat count is the number of seats of that class that are currently not blocked seats on that flight. The load factor consists of, with q = floor(seated * 1000 / seats), the quotient of q divided by 10, a decimal point ".", the remainder of q divided by 10, and "%", in this order (e.g. 27.1% if q is 271, 0.5% if q is 5, 100.0% if q is 1000). The load factor of the ALL line is calculated the same way from the totals.

* BALANCE <flight>
Errors:
1. The flight does not exist: unknown flight <flight>
Can also be used for closed flights. For each passenger with a seat, the weight is 80 for an ADULT and 40 for a CHILD, and 10 more is added for an adult with an infant (the infant's weight). Let W be the sum of the weights, and let the moment M be the sum over these passengers of weight * (row number of the seat - base row of the aircraft). Unassigned passengers and their infants are not counted. With L the limit of the aircraft, the verdict is OK if -L <= M <= L, NOSE-HEAVY if M < -L, and TAIL-HEAVY if M > L; outputs "BALANCE <flight> weight <W> moment <M> limit <L> <verdict>".

* BOARDING <flight>
Errors:
1. The flight does not exist: unknown flight <flight>
Can also be used for closed flights. Determines the boarding order of the passengers with a seat (unassigned passengers and infants are not included). Each passenger is put into one of the following groups; a group higher in this list takes precedence.
- PRE: the passenger's booking still has one or more infants (this applies even if the passenger is not themself an adult with an infant).
- CABIN: the current class is F or J.
- TIER: the membership tier is PLATINUM or GOLD.
- ZONE<z>: everyone else (economy passengers). z = floor((row number of the seat - start row of class Y) / 5) + 1.
The boarding order is PRE, CABIN, TIER in this order, each group sorted by ascending row and, within the same row, from left to right. After them come the ZONE passengers, sorted by descending z, within the same z by seat kind in the order W, M, A, within the same kind by descending row, and within the same row from left to right.
First outputs "BOARDING <flight> <count>", then one line per passenger in boarding order: "<number> <group> <seat> <PNR> <name>". The number is the position in the boarding order starting from 1, and the group is one of PRE, CABIN, TIER and ZONE<z> (e.g. ZONE2).

* AVAIL <flight> <class>
Errors:
1. The flight does not exist: unknown flight <flight>
2. The flight's aircraft does not have that class: no cabin <class> on <flight>
Can also be used for closed flights. For the free seats of that class, outputs "AVAIL <flight> <class> free <free_count> W <window_count> M <middle_count> A <aisle_count> EXIT <exit_count>", where <free_count> is the number of free seats, <window_count>, <middle_count> and <aisle_count> are the numbers of free window, middle and aisle seats, and <exit_count> is the number of free seats in exit rows.

* INFO <PNR>
Errors:
1. The PNR does not exist: unknown PNR <PNR>
Can also be used for bookings of closed flights. First outputs "INFO <PNR> <flight> <count> <state>". The count is the number of passengers remaining in the booking (including infants), and the state is CHECKED if the booking is checked in and NOT-CHECKED otherwise. Then outputs the remaining passengers in listed order, one per line, as "<name> <type> <class> <result>". <class> is the current class, and <result> is the seat, UNASSIGNED if unassigned, or LAP for an infant.

* FIND <name>
There are no errors. First outputs "FIND <name> <tier> <count>", where <tier> is the membership tier. Then examines the flights on which a passenger (including an infant) with that name is aboard, in the order the flights were created, and outputs one line "<flight> <PNR> <class> <result> <state>" for each. <class> and <result> are the same as in INFO, and <state> is OPEN if the flight is open and CLOSED if it is closed. The count is the number of such lines output (if it is 0, only the first line is output).

[Output format]
- For each command, output the lines specified in [Processing], in the specified order. On an error, output only one line starting with ERROR.
- Every separator within a line is a single space. Only the MAP header line and the MAP lines with a one-digit row number start with a space, and no line ends with a space.
- Every number is written as a decimal integer without extra leading zeros (except the one fractional digit of a load factor and the right alignment of MAP row numbers). A negative number is prefixed with -.
- The output consists of ASCII characters only, every line ends with a newline (LF), and no empty lines are output.

[Constraints]
- 1 <= N <= 1000. Command names, the number of arguments and the format of each token are always correct, but a command may refer to a model, flight, PNR, name or seat that does not exist.
- <model> is 1 to 8 characters consisting of uppercase English letters and digits, <flight> is 2 uppercase English letters followed by 1 to 4 digits, <PNR> is 6 characters consisting of uppercase English letters and digits, and <name> is 1 to 12 uppercase English letters.
- Aircraft definitions are always written correctly. Only CABIN, EXIT and BLOCKED lines appear between AIRCRAFT and END, and these lines never appear outside a definition. The same model is never defined twice.
- Every aircraft always has a CABIN line for Y, there is at most one CABIN line per class, and the CABIN lines appear in the order F, J, Y. 1 <= from_row <= to_row <= 99, the start row of a later class is greater than the end row of the earlier class, and row numbers may skip between classes.
- Each CABIN line has two or more blocks, each block has 1 to 4 letters, and a row has at most 10 seats. All seat letters of the same class are uppercase English letters and strictly increase alphabetically from left to right.
- Each aircraft definition has, after all CABIN lines, exactly one EXIT line and one BLOCKED line, in this order. The row numbers listed in EXIT and the seats listed in BLOCKED exist on that aircraft and have no duplicates within each line. Each class has at least one seat that is not a blocked seat.
- 1 <= base_row <= 99, 0 <= limit <= 100000, 0 <= overbook <= 50.
- The row number of a <seat> is between 1 and 99 inclusive.
- A BOOK has 1 to 9 passengers, and <pref> is given only for ADULT and CHILD, never for INFANT. The <class> of BOOK and AVAIL is one of F, J and Y (the flight's aircraft does not necessarily have it).
- At every point in time, every class of every flight has at least one seat that is not a blocked seat on that flight.
- The absolute value of every integer that appears in the calculations is less than 2^31.
