[Overview]
Write an analysis tool for DNA base sequences. It registers sequences under names and performs tasks such as building complementary strands, translation into amino acids, searching for ORFs (reading frames from a start codon to a stop codon), base composition analysis, searching for motifs and restriction enzyme sites, comparison and alignment of sequences, calculation of melting temperature and molecular mass, primer evaluation, prediction of RNA secondary structure, and assembly of overlapping fragments. Read a sequence of commands from standard input, execute them one at a time from the first, and write the results to standard output.

[Input format]
The first line contains the number of commands N, and each of the following N lines contains one command. The input consists of exactly these N + 1 lines.
A command line consists of a command name followed by zero or more arguments, with the command name and the arguments separated by single spaces. The valid commands are the following 31, and their argument lists are as follows. <...> marks a position where one argument goes, and "..." means that more arguments of the same kind as the preceding one follow (their number is specified in [Processing]).

SEQ <newname> <sequence>
SLICE <name> <start> <end> <newname>
JOIN <newname> <name> <name> ...
MUTATE <name> <pos> <base>
DEL <name>
LIST
REVCOMP <name>
COMPLEMENT <name>
REVERSE <name>
TRANSCRIBE <name>
TRANSLATE <name> <frame>
CODONS <name> <frame>
PROTEIN <name> <frame>
ORFS <name> <minlen>
GC <name>
GCWINDOW <name> <width> <step>
SKEW <name>
KMERS <name> <k> <t>
FIND <name> <motif>
RESTRICT <name> <enzyme> ...
PALINDROMES <name> <min> <max>
REPEATS <name> <minunit> <maxunit> <mincount>
HAMMING <name> <name>
ALIGN <name> <name> <mode> <match> <mismatch> <gap>
CONSENSUS <name> <name> ...
TM <name>
MASS <name>
PRIMER <name>
FOLD <name> <loop>
ASSEMBLE <newname> <minoverlap> <name> <name> ...
PACK <name>
UNPACK <newname> <length> <hex>

However, input lines do not necessarily follow these forms. Some lines have a wrong command name, or a wrong number of arguments or wrong argument values; how to handle them is specified in [Processing].

[Processing]
== State ==
The program keeps a "registry" as its state. The registry is a collection of pairs of a name and a sequence, and no two pairs have the same name. Initially the registry is empty.
A sequence is a string of one or more uppercase letters (bases) of the four kinds A, C, G, T. The length of every sequence in the registry is always between 1 and 500 inclusive.
In the description of each command below, s denotes the sequence referred to by the first <name> argument, and n denotes its length. The i-th base from the start of a sequence t is written t[i], and the part from the i-th to the j-th base (i <= j) is written t[i..j]. All positions are counted from 1.
Commands are executed one at a time from the first, and each command outputs one or more lines as specified in [Output format].

== Argument kinds ==
Each argument is checked as one of the following kinds, according to its position in the command's form. In the error strings below, X stands for the string of the checked argument itself.
- <name>: must be a name in the registry. Otherwise the error is "unknown sequence X".
- <newname>: must be a string of 1 to 10 characters whose first character is a lowercase letter (a to z) and whose second and later characters are each a lowercase letter or a digit (0 to 9). Otherwise the error is "invalid name X". It may or may not be a name already in the registry.
- Integer arguments (<start>, <end>, <pos>, <frame>, <minlen>, <width>, <step>, <k>, <t>, <min>, <max>, <minunit>, <maxunit>, <mincount>, <match>, <mismatch>, <gap>, <loop>, <minoverlap>, <length>): must be a string of 1 to 6 digits (0 to 9), or such a string preceded by exactly one "-", and its value read as a decimal number is used. Leading zeros are allowed (007 is 7, -0 is 0). Strings with a "+", a "-" alone, strings containing a decimal point, strings with 7 or more digits, and so on, are invalid. The value must be within the range specified by each command. If the argument is invalid or out of range, the error is "invalid number X".
- <sequence>, <base>, <motif>, <enzyme>, <mode>, <hex>: their conditions and errors are specified in the description of each command. Like the other kinds, these conditions are also checked in step 3 of "Error handling" below, in the order of argument positions.

== Error handling ==
A command is checked in the following order, and only the first error found is reported.
1. The command name matches none of the 31 command names (uppercase and lowercase are distinguished): error "unknown command X" (X is the command name).
2. The number of arguments differs from what the command specifies: error "wrong argument count".
3. Check the arguments one at a time from left to right against the conditions of their kinds.
4. Check the other conditions specified in the description of each command, in the order in which they are written in the description.
A command that results in an error outputs only one line formed by concatenating "ERROR", one space, and the error string in this order (example: ERROR unknown sequence foo), and does not change the registry at all.

== Registration ==
"Register sequence t under new name x" means the following processing, which is done at the end of each command. If the length of t exceeds 500, the error is "too long". Otherwise, if x is not in the registry, the pair (x, t) is added to the registry; if it is, the sequence of that pair is replaced with t. When the registration results in an error, that command also outputs only the one error line.

== Basic definitions ==
- Complementary bases: A and T are each other's complementary bases, and so are C and G.
- complement(t): the sequence obtained by replacing each base of sequence t with its complementary base.
- revcomp(t): the sequence complement(t) in reverse order (the reverse complement strand). The base at position j of the reverse complement strand of s is the complementary base of s[n + 1 - j], and position j of the reverse complement strand corresponds to position n + 1 - j of s (the forward strand).
- Reverse-complement palindrome: a sequence t such that revcomp(t) = t (example: GAATTC). Its length is always even.
- gc(t): the total number of G and C contained in sequence t.
- Transition and transversion: a pair of two different bases is a transition if it is {A, G} or {C, T}, and a transversion otherwise.
- Lexicographic order: the order on base strings of equal length that compares them one character at a time from the start and puts first the one whose first differing character is smaller in the order A < C < G < T.
- pct(a, b) (integers a >= 0 and b >= 1): with q = floor(10000 * a / b), the string formed by concatenating the quotient of q divided by 100, ".", and the remainder of q divided by 100 written with 2 digits (prefixed with 0 if it has 1 digit). This is the percentage 100 * a / b with the digits from the third decimal place onward truncated (examples: pct(2, 3) is 66.66, pct(1, 1) is 100.00, pct(0, 7) is 0.00).
- milli(w) (integer w >= 0): the string formed by concatenating the quotient of w divided by 1000, ".", and the remainder written with 3 digits (leading zeros included) (examples: milli(433570) is 433.570, milli(1005) is 1.005).
- Repeat count: for the part w = t[i..i+u-1] of length u starting at position i of sequence t, check for q = 1, 2, 3, ... in this order whether "t[i + (q - 1) * u..i + q * u - 1] fits inside t and equals w"; the first q for which this does not hold, minus 1, is called the repeat count of length u at position i (it is always at least 1).

== IUPAC symbols ==
Motifs and the recognition sequences of restriction enzymes use the following 15 symbols. Each symbol stands for a set of bases.
A: {A}, C: {C}, G: {G}, T: {T}, R: {A, G}, Y: {C, T}, W: {A, T}, S: {C, G}, K: {G, T}, M: {A, C}, B: {C, G, T}, D: {A, G, T}, H: {A, C, T}, V: {A, C, G}, N: {A, C, G, T}
A symbol p matches a base x if x is contained in the set that p stands for. The complement of a symbol is the symbol that stands for the set obtained by replacing each base of the set it stands for with its complementary base. A and T, C and G, R and Y, K and M, B and V, D and H are each other's complements, and W, S, N are their own complements. The reverse complement revcomp(u) of a symbol string u is the string obtained by replacing each symbol of u with its complement and arranging them in reverse order.
A symbol string u of length m occurs at position i of a sequence t if 1 <= i <= (length of t) - m + 1 and, for every j = 1, ..., m, the j-th character of u matches t[i + j - 1].
Also, for a nonempty set of bases, the symbol that stands for that set is called the IUPAC symbol of the set (example: the IUPAC symbol of {A, G} is R).

== Genetic code and reading frames ==
A string of 3 bases is called a codon. Codons are translated into one-letter symbols representing amino acids according to the following table (the standard genetic code). The symbol "*" stands for a stop codon.
A: GCT GCC GCA GCG, C: TGT TGC, D: GAT GAC, E: GAA GAG, F: TTT TTC,
G: GGT GGC GGA GGG, H: CAT CAC, I: ATT ATC ATA, K: AAA AAG,
L: TTA TTG CTT CTC CTA CTG, M: ATG, N: AAT AAC, P: CCT CCC CCA CCG, Q: CAA CAG,
R: CGT CGC CGA CGG AGA AGG, S: TCT TCC TCA TCG AGT AGC, T: ACT ACC ACA ACG,
V: GTT GTC GTA GTG, W: TGG, Y: TAT TAC, *: TAA TAG TGA
A frame f, which designates a reading frame, is one of 1, 2, 3, -1, -2, -3. The reading-frame string of frame f of s is the part of s from the f-th base onward if f > 0, and the part of revcomp(s) from the |f|-th base onward if f < 0 (it is the empty string if n < |f|). The sequence of codons obtained by splitting the reading-frame string into groups of 3 bases from the start is called the codon list of frame f. The 1 or 2 bases left over at the end are not used. The string formed by arranging in order the symbols obtained by translating each codon of the codon list is called the translation of frame f. Translation does not stop at a stop codon; a "*" is placed at that position and translation continues.

== Processing of each command ==
(1) Registration and editing
- SEQ <newname> <sequence>: 2 arguments. Examine the characters of <sequence> in order from the start; when a character other than A, C, G, T (lowercase letters included) appears for the first time, with c that character and p its position, the error is "invalid base c at p" (example: ERROR invalid base N at 4). If all characters are valid, register <sequence> under the new name.
- SLICE <name> <start> <end> <newname>: 4 arguments; <start> a and <end> b are between 1 and n inclusive. If a <= b, register s[a..b] under the new name; if a > b, register revcomp(s[b..a]) under the new name.
- JOIN <newname> <name> <name> ...: 3 to 9 arguments, and the second and later arguments are all <name> (2 to 8 of them). Register under the new name the sequence obtained by concatenating the sequences of the second and later names in the order written. The same name may be written any number of times. The new name may be the same as one of the second and later names; the concatenation uses the sequences as they were before this command is executed.
- MUTATE <name> <pos> <base>: 3 arguments; <pos> p is between 1 and n inclusive. <base> must be a single character that is one of A, C, G, T; otherwise the error is "invalid base X". If s[p] is the same as <base>, the error is "no change". Otherwise, replace the p-th base of s in the registry with <base>.
- DEL <name>: 1 argument. Remove the pair with that name from the registry.
- LIST: no arguments. Display the contents of the registry.

(2) Conversion (each takes 1 argument)
- REVCOMP <name>: compute revcomp(s).
- COMPLEMENT <name>: compute complement(s).
- REVERSE <name>: compute the sequence s in reverse order.
- TRANSCRIBE <name>: compute the string (RNA sequence) obtained by replacing every T in s with U.

(3) Translation
TRANSLATE, CODONS and PROTEIN take 2 arguments, and <frame> is a nonzero integer between -3 and 3 inclusive (0 is out of range, so it gives the error "invalid number X").
- TRANSLATE <name> <frame>: compute the translation of the frame.
- CODONS <name> <frame>: for each codon that appears in the codon list of the frame, count the number of times it appears.
- PROTEIN <name> <frame>: the protein is the part of the frame's translation before the first "*" (the whole translation if there is no "*"). If the protein is empty, the error is "empty protein". Compute the length L of the protein, its molecular mass, its charge and its amino acid composition. The molecular mass is represented by the integer W obtained by summing, for each character of the protein, the residue mass in the following table (in units of 0.001) and adding 18015 for one water molecule. The charge is the integer obtained by subtracting the total number of D and E contained in the protein from the total number of K and R contained in it.
  A 71079, C 103139, D 115089, E 129116, F 147177, G 57052, H 137141, I 113160, K 128174, L 113160,
  M 131193, N 114104, P 97117, Q 128131, R 156188, S 87078, T 101105, V 99133, W 186213, Y 163176
- ORFS <name> <minlen>: 2 arguments; <minlen> m is between 1 and 200 inclusive. For each of the 6 frames, examine the codon list one codon at a time from the start, and find ORFs by the following rules. Initially you are outside an ORF.
  - When ATG appears outside an ORF, an ORF starts at that codon.
  - When a stop codon (TAA, TAG, TGA) appears inside an ORF, the ORF ends at that codon and you return to outside an ORF.
  - For any other codon, do nothing (an ATG that appears inside an ORF does not start a new ORF).
  An ORF that has not ended by the end of the codon list is discarded. The protein of an ORF is the translation from its starting ATG up to the codon just before the stop codon, and only the ORFs whose protein length (number of codons) is m or more are results. The range of an ORF is from the first base of its starting ATG to the third base of its stop codon. This is a range on s if f > 0 and a range on revcomp(s) if f < 0, so in the case f < 0, convert each of the two end positions j of the range to position n + 1 - j of s. Of the two positions on s obtained in this way, the smaller one is the left end l and the larger one is the right end r. Sort the results in increasing order of left end l (two or more ORFs never have equal l).

(4) Composition
- GC <name>: 1 argument. Compute the number of each of A, C, G, T contained in s, and pct(gc(s), n).
- GCWINDOW <name> <width> <step>: 3 arguments; <width> w and <step> d are between 1 and 500 inclusive. If w > n, the error is "window too large". For every i among i = 1, 1 + d, 1 + 2 * d, ... that satisfies i + w - 1 <= n, in increasing order of i, compute pct(gc(window), w) of the window s[i..i+w-1].
- SKEW <name>: 1 argument. For k = 0, 1, ..., n, let skew(k) be the number of G minus the number of C contained in s[1..k] (skew(0) = 0). Compute the minimum of skew(k), all k at which the minimum is attained, the maximum, and all k at which the maximum is attained.
- KMERS <name> <k> <t>: 3 arguments; k is between 1 and 12 inclusive, and t is between 1 and 100 inclusive. If k > n, the error is "k too large". The n - k + 1 parts s[i..i+k-1] for i = 1, ..., n - k + 1 are called k-mers; count the number of times each k-mer appears. Compute the number of windows n - k + 1 and the number of distinct k-mers. In addition, sort the k-mers in decreasing order of count, ties in lexicographic order, and take the first t of them (all of them if there are fewer than t distinct k-mers).

(5) Search
- FIND <name> <motif>: 2 arguments. <motif> must be a string of 1 to 30 characters consisting only of the 15 uppercase letters that are IUPAC symbols; otherwise the error is "invalid motif X". With u the motif, find all positions at which u occurs in s (forward-strand occurrences) and all positions at which revcomp(u) occurs in s (reverse-strand occurrences). A reverse-strand occurrence represents the position, in s, of the left end of the range where u can be read on the complementary strand.
- RESTRICT <name> <enzyme> ...: 2 to 7 arguments, and the second and later arguments are all <enzyme> (1 to 6 of them). Each <enzyme> must exactly match one of the enzyme names in the table below (uppercase and lowercase are distinguished); otherwise the error is "unknown enzyme X". Even if it matches, if it is the same as an <enzyme> written before it in the same command, the error is "duplicate enzyme X". These two checks are done for each <enzyme> in order from left to right (for example, the error of RESTRICT s EcoRI EcoRI Foo is duplicate enzyme EcoRI).
  Enzyme table (enzyme name, recognition sequence, cut offset, in this order):
  EcoRI GAATTC 1, BamHI GGATCC 1, HindIII AAGCTT 1, PstI CTGCAG 5, SmaI CCCGGG 3,
  KpnI GGTACC 5, XbaI TCTAGA 1, NotI GCGGCCGC 2, EcoRV GATATC 3, HaeIII GGCC 2,
  AluI AGCT 2, TaqI TCGA 1, Sau3AI GATC 0, HincII GTYRAC 3, AvaI CYCGRG 1
  A recognition sequence is a string of IUPAC symbols. Every recognition sequence is equal to its own reverse complement, so examining s alone amounts to examining both strands. When a recognition sequence occurs at position p of s, with e the cut offset of that enzyme, c = p + e - 1 is the cut point of that occurrence. A cut point c means cutting between s[c] and s[c + 1], and only those with 1 <= c <= n - 1 are valid (the others are ignored).
  For each enzyme, find all its valid cut points. Next, combine the valid cut points of all enzymes (equal values are merged into one) and sort them in increasing order as c1 < c2 < ... < ck. With c0 = 0 and c(k+1) = n, the k + 1 parts s[c(i-1) + 1..c(i)] (i = 1, ..., k + 1) are the fragments.
- PALINDROMES <name> <min> <max>: 3 arguments; <min> a and <max> b are between 2 and 20 inclusive. If a > b, the error is "invalid range". Find all parts s[i..i+L-1] whose length L is between a and b inclusive and that are reverse-complement palindromes.
- REPEATS <name> <minunit> <maxunit> <mincount>: 4 arguments; <minunit> a and <maxunit> b are between 1 and 6 inclusive, and <mincount> c is between 2 and 50 inclusive. If a > b, the error is "invalid range". Find tandem repeats as follows. For each unit length u = a, a + 1, ..., b, start from i = 1 and repeat the following while i + u - 1 <= n. Compute the unit w = s[i..i+u-1] and the repeat count r of length u at position i. If w is primitive and r >= c, add s[i..i+r*u-1] to the results as a tandem repeat (unit w, count r) and add r * u to i. Otherwise add 1 to i.
  Here a unit w is primitive if, for none of the divisors d of u (1 <= d < u), w is equal to its first d characters repeated u / d times. If u = 1, it is always primitive (for example, AT and CAG are primitive, and AA and ATAT are not primitive).
  Sort the results in increasing order of start position, ties in increasing order of unit length.

(6) Comparison
- HAMMING <name> <name>: 2 arguments. Let a be the sequence of the first name and b the sequence of the second name. If a and b have different lengths, the error is "length mismatch". Compute the number of positions i with a[i] != b[i] (the Hamming distance), and, among them, the number of positions where the pair of the two bases is a transition and the number of positions where it is a transversion.
- ALIGN <name> <name> <mode> <match> <mismatch> <gap>: 6 arguments. <mode> must be GLOBAL or LOCAL; otherwise the error is "invalid mode X". <match> alpha is between 1 and 20 inclusive, <mismatch> beta is between -20 and 0 inclusive, and <gap> gamma is between -20 and -1 inclusive.
  Let a be the sequence of the first name and b the sequence of the second name, and, in this description only, let m be the length of a and n the length of b. For 1 <= i <= m and 1 <= j <= n, let sigma(i, j) be alpha if a[i] = b[j], and beta otherwise. For 0 <= i <= m and 0 <= j <= n, define the score table H(i, j) as follows.
  - GLOBAL (Needleman-Wunsch method): H(i, 0) = i * gamma and H(0, j) = j * gamma, and for i >= 1 and j >= 1, H(i, j) = max(H(i - 1, j - 1) + sigma(i, j), H(i - 1, j) + gamma, H(i, j - 1) + gamma).
  - LOCAL (Smith-Waterman method): H(i, 0) = H(0, j) = 0, and for i >= 1 and j >= 1, H(i, j) = max(0, H(i - 1, j - 1) + sigma(i, j), H(i - 1, j) + gamma, H(i, j - 1) + gamma).
  For GLOBAL, the score is S = H(m, n), and (m, n) is the starting point. For LOCAL, the maximum of H(i, j) is the score S, and the starting point is, among the (i, j) with H(i, j) = S, the one with the smallest i, and among those the one with the smallest j. For LOCAL, if S = 0 there is no alignment, and processing ends here.
  With the starting point as (i, j), repeat the following steps to build the columns of the alignment one at a time (traceback). For GLOBAL, stop when i = 0 and j = 0; for LOCAL, stop when H(i, j) = 0.
  1. If i >= 1 and j >= 1 and H(i, j) = H(i - 1, j - 1) + sigma(i, j), build a column pairing a[i] with b[j], and decrease each of i and j by 1.
  2. If step 1 does not apply, and i >= 1 and H(i, j) = H(i - 1, j) + gamma, build a column pairing a[i] with a gap, and decrease i by 1.
  3. If neither step 1 nor step 2 applies, build a column pairing a gap with b[j], and decrease j by 1.
  The alignment is the built columns arranged in the reverse of the order in which they were built, and the number of columns is the alignment length L. The a-side row is the string of length L formed by arranging the base of a in each column ("-" for a gap), and the b-side row is likewise the string formed by arranging the base of b in each column. The middle row is the string formed by arranging, for each column, "-" if either side is a gap, "|" if the two bases are equal, and "*" if they differ. Let the number of "|" in the middle row be the identity count I, and the number of "-" be the gap count Q. With (i1, j1) the starting point and (i0, j0) the (i, j) at the end of the traceback, the range covered by the alignment is from the (i0 + 1)-th to the i1-th position of a, and from the (j0 + 1)-th to the j1-th position of b (for GLOBAL, always the whole of a and the whole of b).
- CONSENSUS <name> <name> ...: 2 to 10 arguments, all <name>. If the same name is written more than once, each occurrence counts as one sequence. If the sequences do not all have equal lengths, the error is "length mismatch". Let L be the common length. For each position i (1 <= i <= L) and each base x, count the number of sequences whose i-th base is x (the profile). The consensus sequence is the sequence formed by arranging, at each position, the base with the largest count (on a tie, the earliest in the order A, C, G, T), and the IUPAC consensus is the string formed by arranging, at each position, the IUPAC symbol of the set of all bases with the largest count.

(7) Physical properties and evaluation (each takes 1 argument)
- TM <name>: compute the integer T representing 10 times the melting temperature (in degrees Celsius). If n < 14, T = 10 * (2 * (n - gc(s)) + 4 * gc(s)) (Wallace rule). If n >= 14, T = floor((649 * n + 410 * gc(s) - 6724) / n). This is 10 times the value of 64.9 + 41 * (gc(s) - 16.4) / n with the digits from the second decimal place onward truncated, and the numerator is always positive.
- MASS <name>: the base masses (in units of 0.001) are A 331222, C 307197, G 347221, T 322208. The single-strand mass w(t) of a sequence t is the integer obtained by subtracting (length of t - 1) * 18015 from the sum of the masses of the bases of t (one water molecule is subtracted for each bond between adjacent bases). Compute the single-strand mass w(s) and the double-strand mass w(s) + w(revcomp(s)).
- PRIMER <name>: treating s as a PCR primer, evaluate the following 7 items in order, and for each item determine its value and whether it passes or fails.
  1. length: the value is n. It passes if 18 <= n <= 25.
  2. gc: the value is pct(gc(s), n). It passes if 40 * n <= 100 * gc(s) <= 60 * n.
  3. tm: the value is T as computed by TM. It passes if 520 <= T <= 620.
  4. clamp: the value is the number of G and C contained in the last 5 bases of s (the whole of s if n < 5). It passes if it is between 1 and 3 inclusive.
  5. run: the value is the maximum length of a run of consecutive identical bases. It passes if it is 4 or less.
  6. repeat: the value is the maximum, over the positions i (1 <= i <= n - 1) with s[i] != s[i + 1], of the repeat count of length 2 at position i (0 if there is no such i). It passes if it is 4 or less.
  7. selfcomp: the value is the maximum length of a part that is a reverse-complement palindrome (0 if there is none). It passes if it is 6 or less.

(8) RNA secondary structure
- FOLD <name> <loop>: 2 arguments; <loop> h is between 0 and 10 inclusive. If n > 100, the error is "too long". Regarding s as RNA (reading T as U), find the secondary structure with the maximum number of base pairs by the Nussinov method. s[k] and s[j] can form a pair when the pair of the two bases is one of {A, T}, {C, G}, {G, T}. For integers i and j, let F(i, j) be 0 if i > j, and, if 1 <= i <= j <= n, the largest of the following values.
  - F(i, j - 1)
  - F(i, k - 1) + 1 + F(k + 1, j - 1) for each k such that i <= k <= j - h - 1 and s[k] and s[j] can form a pair
  F(1, n) is the number of base pairs (every pair encloses h or more bases between its two positions). The pairs are determined by the following procedure. Start with a collection of intervals containing only [1, n], and, until the collection is empty, take out one interval and do the following (the order in which intervals are taken out does not affect the result). Let [i, j] be the interval taken out.
  1. If F(i, j) = 0, do nothing.
  2. Otherwise, if F(i, j) = F(i, j - 1), add the interval [i, j - 1] to the collection.
  3. Otherwise, choose the smallest k (i <= k <= j - h - 1) such that s[k] and s[j] can form a pair and F(i, k - 1) + 1 + F(k + 1, j - 1) = F(i, j), pair k with j, and add the intervals [i, k - 1] and [k + 1, j - 1] to the collection.
  Represent the determined pairs as a string of length n with "(" at the smaller position of each pair, ")" at the larger position, and "." at the positions contained in no pair (dot-bracket notation).

(9) Assembly
- ASSEMBLE <newname> <minoverlap> <name> <name> ...: 4 to 10 arguments, and the third and later arguments are all <name> (2 to 8 of them). <minoverlap> v is between 1 and 100 inclusive. Using the sequences of the third and later names as fragments, join them with the following greedy method. The fragments are treated as an ordered list.
  1. Arrange the sequences of the third and later names in the order written to form the list of fragments. If two or more sequences are equal, keep only the first of them. Next, remove every fragment that is a substring of another fragment in the list.
  2. While there are two or more fragments, repeat the following. For each ordered pair (x, y) of two different fragments in the list, the overlap ov(x, y) is the largest o (1 <= o < min(length of x, length of y)) such that the last o characters of x are equal to the first o characters of y (0 if there is no such o). Choose the pair with the largest ov(x, y); if several pairs have the same value, choose the one whose x is earlier in the list, and if still tied, the one whose y is earlier in the list. If the overlap o of the chosen pair is less than v, stop repeating. Otherwise, replace x with the new fragment formed by x followed by the rest of y with its first o characters removed (its position in the list stays the position of x), remove y from the list, and then remove from the list every other fragment that is a substring of the new fragment.
  3. The remaining fragments are called contigs. Register the longest contig (on a tie in length, the one earlier in the list) under the new name.

(10) 2-bit encoding
- PACK <name>: 1 argument. Represent A, C, G, T by the codes 0, 1, 2, 3 respectively, and pad the end of the sequence of codes of s with 0s so that their count is a multiple of 4. Split this sequence into groups of 4 from the start, and turn each group (c1, c2, c3, c4) into the integer 64 * c1 + 16 * c2 + 4 * c3 + c4 (between 0 and 255 inclusive). Compute the string formed by writing each of these integers as 2 uppercase hexadecimal digits (leading zeros included) and concatenating them in order.
- UNPACK <newname> <length> <hex>: 3 arguments; <length> L is between 1 and 500 inclusive. <hex> must consist only of digits (0 to 9) and uppercase letters A to F and have length exactly 2 * ceil(L / 4); otherwise the error is "invalid hex". Split <hex> into groups of 2 characters from the start, turn each integer x read as hexadecimal back into the 4 codes floor(x / 64), floor(x / 16) mod 4, floor(x / 4) mod 4, x mod 4, and arrange them in order. If any of the codes from the (L + 1)-th onward is nonzero, the error is "invalid padding". Otherwise, register under the new name the sequence obtained by turning the first L codes back into bases.

[Output format]
For each command, output one or more lines as specified below. Each line ends with a newline and has no trailing spaces. Integers are written in decimal without extra leading zeros, and negative numbers are written with a "-". When several items are placed on one line, they are separated by single spaces. In the formats below, a word in angle brackets <...> stands for the value it describes, and everything else is written literally. Wherever a format below says "list of ...", if there is not a single number to place there, write none instead. The values in the examples only show how things are written.
- Error: one line "ERROR <error string>".
- Registration line (the output of SEQ, SLICE, JOIN, UNPACK, and the last line of ASSEMBLE): "stored <newname> <length> nt" if the new name was not in the registry before the registration, and "replaced <newname> <length> nt" if it was. The length is the length of the registered sequence. Example: stored gene1 120 nt
- MUTATE: one line "<name> <mutation> <type>". The mutation is the original base, the position p and the new base concatenated without spaces. The type is transition if the pair of the original base and the new base is a transition, and transversion if it is a transversion. Example: gene1 C12T transition
- DEL: one line "deleted <name>".
- LIST: output the pairs of the registry in lexicographic order of names, one pair per line, in the form "<name> <length> nt". The lexicographic order of names compares them one character at a time from the start in character-code order (0 < 1 < ... < 9 < a < b < ... < z), and when one is equal to a leading part of the other, the shorter one comes first. If the registry is empty, output one line no sequences.
- REVCOMP, COMPLEMENT, REVERSE, TRANSCRIBE: one line with the computed string.
- TRANSLATE: one line with the translation. If the codon list is empty, none. Example: MAIVMGR*KGAR*
- CODONS: in decreasing order of count, ties in lexicographic order of codons, output one line per distinct codon: "<codon> <amino acid symbol> <count>". If the codon list is empty, output one line none. Example: ATG M 2
- PROTEIN: 3 lines. Line 1 is the protein, line 2 is "length <L> mass <molecular mass> charge <charge>", and line 3 is the amino acid composition. The molecular mass is written as milli(W). The charge is written with a "+" if positive (example: +2), as 0 if zero, and with a "-" if negative. The amino acid composition is the amino acid symbols contained in the protein, in decreasing order of count, ties in alphabetical order of the symbol, arranged in the form "<symbol>=<count>". Example:
  MKR
  length 3 mass 433.570 charge +2
  K=1 M=1 R=1
- ORFS: for each result ORF, in the sorted order, output one line "<frame> <l> <r> <length> <protein>". The frame is written with a sign, such as +1, +2, +3, -1, -2, -3, and the length is the length of the protein. If there are no results, output one line none. Example: -1 61 81 6 MPGKFD
- GC: one line "A=<number of A> C=<number of C> G=<number of G> T=<number of T> GC=<percentage>%". The percentage is pct(gc(s), n), followed by "%". Example: A=3 C=5 G=4 T=2 GC=64.28%
- GCWINDOW: for each window, in increasing order of i, output one line "<start position>-<end position> <percentage>%". The start position is i, the end position is i + w - 1, and the percentage is pct(gc(window), w). Example: 11-30 50.00%
- SKEW: 2 lines, "min <minimum> at <list of k>" and "max <maximum> at <list of k>". The values of k are arranged in increasing order. Example: min -1 at 74 75
- KMERS: line 1 is "<number of windows> windows <number of distinct k-mers> distinct", and from line 2 onward, for each k-mer taken, in the sorted order, one line "<k-mer> <count>". Example: 98 windows 16 distinct
- FIND: 2 lines, "forward <list of positions of forward-strand occurrences>" and "reverse <list of positions of reverse-strand occurrences>". The positions are arranged in increasing order. Example: line 1 is forward 18 28 44 and line 2 is reverse none
- RESTRICT: first, for each enzyme, in argument order, output one line "<enzyme name> <list of valid cut points>" (in increasing order). Then output 2 lines, "fragments <list of fragments>" (each fragment in the form "<start position>-<end position>", in their order within s) and "sizes <list of lengths>" (the lengths of the fragments in decreasing order). Example:
  EcoRI 1
  BamHI none
  fragments 1-1 2-99
  sizes 98 1
- PALINDROMES: output the result parts in increasing order of start position, ties in increasing order of length, one per line, in the form "<start position> <length> <sequence of the part>". If there are no results, output one line none. Example: 88 8 GCGGCCGC
- REPEATS: for each result tandem repeat, in the sorted order, output one line "<start position>-<end position> <unit>x<count>". The unit sequence, the lowercase letter x and the count are concatenated without spaces. If there are no results, output one line none. Example: 4-18 CAGx5
- HAMMING: one line "distance <Hamming distance> transitions <number of transitions> transversions <number of transversions>".
- ALIGN: 4 lines if there is an alignment. Line 1 is "score <S> a <start>-<end> b <start>-<end> identity <I>/<L> gaps <Q>", where the start and end after a are i0 + 1 and i1, and the start and end after b are j0 + 1 and j1. Line 2 is the a-side row, line 3 is the middle row, and line 4 is the b-side row. If there is no alignment (LOCAL with S = 0), one line "score 0". Example:
  score 11 a 4-14 b 4-12 identity 8/11 gaps 2
  TACAGATTACA
  |*|-||||-||
  TGC-GATT-CA
- CONSENSUS: 6 lines. Lines 1 to 4 are, for the bases A, C, G, T in this order, "<base> <count at position 1> <count at position 2> ... <count at position L>"; line 5 is "consensus <consensus sequence>", and line 6 is "iupac <IUPAC consensus>".
- TM: one line "Tm <temperature> <method>". The temperature is the quotient of T divided by 10, ".", and the remainder (1 digit) concatenated, and the method is wallace if n < 14, and gc otherwise. Example: Tm 53.8 gc
- MASS: one line "ss <single-strand mass> ds <double-strand mass>". Both masses are written with milli. Example: ss 322.208 ds 653.430
- PRIMER: 8 lines. Lines 1 to 7 are "<item name> <value> <verdict>" in item order; the value is the pct string for gc, written in the same way as the temperature of TM for tm, and an integer otherwise. The verdict is OK if the item passes and FAIL if it fails. Line 8 is PASS if all items pass, and otherwise FAIL followed by the names of the failed items in item order. Example: FAIL tm clamp
- FOLD: 2 lines. Line 1 is the dot-bracket notation, and line 2 is "pairs <number of base pairs>".
- ASSEMBLE: line 1 is "contigs <number of contigs>", followed by one line "<length> <sequence>" for each contig in list order, and finally the registration line.
- PACK: one line "<n> <string of hexadecimal digits>". Example: 6 3260

[Constraints]
- 1 <= N <= 400. The first line is a decimal integer without extra leading zeros.
- Each line from the second line onward is a string of 1 to 600 characters consisting only of ASCII printable characters and spaces, and ends with a newline (LF).
- A command line contains one or more words, separated by single spaces. There are no leading or trailing spaces, no consecutive spaces, and no empty lines.
- The command name, the number of arguments and the argument values are not guaranteed to be correct. Incorrect ones are errors according to the rules in [Processing].
- The absolute value of every integer that appears during computation is less than 2^31.
