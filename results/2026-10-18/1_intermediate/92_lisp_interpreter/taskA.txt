[Overview]
Write an interpreter for a small Lisp language similar to Scheme. The program reads a Lisp program from standard input and repeatedly reads one top-level expression, evaluates it, and writes its value to standard output (a REPL). An expression may span any number of lines. The interpreter handles a reader for integers, booleans, strings, symbols, quote ('), lists and dotted pairs; a printer that writes values in their external representation; an environment model with lexical scope; 14 special forms (define, lambda, if, cond, let (including named let), let*, letrec, begin, set!, quote, and, or, when, unless); closures and variable numbers of arguments; and 42 built-in procedures (arithmetic, comparison, predicates, pair and list operations, higher-order procedures, strings, output, errors). When an error occurs during reading or evaluation, the program outputs a single line of the form "Error: reason" and moves on to the next expression.

[Input format]
The input consists of multiple lines, and the last line is a line consisting of exactly the 6 characters (exit). No line before it consists of exactly the 6 characters (exit).
Each line is a string of 0 to 200 characters consisting only of ASCII printable characters (character codes 32 to 126). All lines before the last line, concatenated in this order (without the newline character at the end of each line), are called the "program". The last line is not part of the program and is neither read nor evaluated.

[Processing]
Section 1. Terms and notation
- "Space" means only the half-width space (character code 32). LF denotes the newline character (character code 10).
- Below, Lisp expressions and values are shown in the form in which they are written in a program, such as (define x 1).
- When a value is tested as a condition, only #f is false, and every other value (including 0, the empty list and the unspecified value) is regarded as true.
- A "list" is either the empty list or a pair whose cdr is a list. The empty list has 0 elements, and the elements of a list that is a pair are its car followed by the elements of its cdr, in order. The number of elements is called the "length" of the list. A pair for which following the cdrs in turn ends in a value other than the empty list is not a list.
- A "new list" is a list all of whose pairs holding the elements are newly created (if it has 0 elements, it is the empty list).

Section 2. Values
There are the following 8 kinds of values.
- Integer: a signed integer.
- Boolean: the two values #t, which represents true, and #f, which represents false.
- String: a sequence of 0 or more characters. Each character is either an ASCII printable character or LF.
- Symbol: a value that has a name; the name is a sequence of 1 or more characters. Uppercase and lowercase letters in names are distinguished (abc and ABC are different symbols). Symbols with the same name are the same value.
- Empty list: the single value written ().
- Pair: a combination of two values called the car and the cdr. A new, distinct pair results every time a pair is created; two separately created pairs are not identical even if their cars and cdrs are the same (see eq? in Section 10). There is no way to change the car or cdr of a pair once it has been created.
- Procedure: a value that can be called. There are two kinds: built-in procedures (Section 10) and compound procedures created by lambda and the like (Sections 8 and 9). Likewise, a new, distinct procedure results every time a procedure is created. A procedure either has one "name" (a symbol) or has no name. The name of a built-in procedure is the name shown in Section 10. A compound procedure has no name when it is created, and gets a name only in the cases described in Section 8. Once given, a name never changes.
- Unspecified value: the single value used as the value of expressions that have no meaningful value (define, set!, display, etc.).

Section 3. Reading
The program is read as a sequence of "tokens". A token never spans lines.

(1) Tokens
Within each line, starting from the beginning of the line, tokens are extracted one at a time as follows, according to the character at the read position.
- A space is skipped.
- For the character ;, the rest of the line is skipped entirely (a comment).
- The characters (, ) and ' are each a token of 1 character.
- The character " starts a "string token". Starting with the next character, the characters are examined one at a time, in order, and the contents of the string are built by the following rules.
  - The character " ends the string token there (the token extends up to and including that ").
  - The character \ forms a pair with the next character and represents 1 character. \" represents ", \\ represents \, and \n represents LF. If the character after \ is none of these three (", \, n), it is the token error bad escape.
  - Any other character represents itself.
  If the end of the line is reached before the closing " (including the case where \ is the last character of the line), it is the token error unterminated string.
- From any other character, the longest sequence of characters up to just before a "delimiter" (the 6 kinds: space, (, ), ', ", ;) or the end of the line is extracted as one token, called an "atom". Atoms are classified as follows.
  - An atom consisting only of the single character . is a "dot".
  - An atom consisting only of zero or one leading + or -, followed by one or more digits (0 to 9), is an integer token. Its value is the value of the digit sequence read in decimal (negated if there is a -). For example, 42, -7, +5 (value 5), 007 (value 7) and -0 (value 0) are integer tokens.
  - #t and #f are the tokens of the booleans #t and #f, respectively.
  - Otherwise, an atom whose first character is # is the token error bad token: <atom>. <atom> is the atom written exactly as it appears. For example, #true gives bad token: #true.
  - Any other atom is the token of the symbol whose name is that atom. For example, x, +, -, list?, 1+, a.b and ... (three . characters) are all symbols.

(2) datum
"Reading one datum" means reading one token and then doing the following according to that token.
- An integer, boolean, string or symbol token: its value is the datum.
- (: a list is read by the procedure below.
- ': read one datum d. The new list (quote d), whose elements are the symbol quote and d in this order, is the datum.
- ): the read error "unexpected )".
- A dot: the read error "unexpected .".
A list is read by starting with an empty sequence of elements and following these steps.
  a. Read one token.
  b. If that token is ), the new list whose elements are the elements read so far, in order (the empty list if there are none), is the datum.
  c. If that token is a dot and at least one element has been read so far, read one datum t, then read one token. If that token is not ), it is the read error expected ). If it is ), the elements read so far, e1, ..., en, are put in order into the cars of new pairs; the cdr of the 1st pair is the 2nd pair, ..., the cdr of the (n - 1)-th pair is the n-th pair, and the cdr of the n-th pair is t; the result (the 1st pair) is the datum. For example, (1 2 . 3) is the pair whose car is 1 and whose cdr is (2 . 3). When t is a list, the result is also a list: (1 . (2 3)) has the same form as (1 2 3), and (1 . ()) the same form as (1).
  d. Otherwise, read one datum starting with that token (if that token is a dot, this is unexpected . as described above), append it to the end of the sequence of elements, and go back to a.
All pairs created by reading are new pairs. Therefore, even data written the same way consist of different pairs when they are read separately.

(3) Read errors
- When a token is about to be read and the remaining part of the program (after the read position) contains no characters other than spaces and comments, it is the read error unexpected end of input.
- Token errors (bad escape, unterminated string, bad token) are read errors that occur when an attempt is made to read that token. The part before the erroneous token is read normally.
- When a read error occurs, the partially read datum is discarded and a single line "Error: read: <reason>" is output (Section 5). <reason> is one of the 7 kinds above. After that, for unexpected end of input, reading of the program ends. Otherwise, the rest of the line containing the token that caused the error (for "unexpected )" and "unexpected .", that ) or dot; for "expected )", the token read in place of ); for a token error, the erroneous token) is skipped entirely, and reading continues from the beginning of the next line.

Section 4. External representation and display form
The "external representation" of a value v is the string built as follows, according to the kind of v.
- Integer: decimal notation. A negative number is prefixed with - (e.g. -15). 0 is 0.
- Boolean: #t or #f.
- String: the character ", followed by each character in order, with " replaced by the 2 characters \", \ by \\, and LF by \n, and all other characters as they are, followed finally by the character ". For example, the external representation of the 3-character string a"b is "a\"b".
- Symbol: its name.
- Empty list: ().
- Pair: starting from v and following the cdrs in turn, as long as the value reached is a pair, list the external representation of its car. If the non-pair value finally reached is not the empty list, append . and the external representation of that value after them. Separate the items listed this way by single spaces, and put ( in front and ) at the end; the result is the external representation. Examples: (1 (2 "x") . a) and (1 2 3).
- Procedure: "#<procedure name>" for a procedure that has a name, and "#<procedure>" for a procedure without a name. For example, #<procedure car>.
- Unspecified value: #<void>.
The "display form" of a value differs from the external representation only in how strings are rendered: a string (including strings contained inside pairs) is not enclosed in " and has no replacements; its characters are written as they are. For example, for the list whose elements are the string "a b" and the symbol c, the external representation is ("a b" c) and the display form is (a b c).

Section 5. REPL and output
- Starting from the beginning of the program, reading one datum and evaluating it is repeated by the following steps.
  (1) If the remaining part of the program contains no characters other than spaces and comments, terminate.
  (2) Read one datum. If a read error occurs, handle it as in Section 3(3) and go back to (1).
  (3) Evaluate (Section 7) the datum read, as an expression, in the global environment (Section 6).
  (4) If evaluation finishes and the value is not the unspecified value, output one line containing the external representation of the value. If the value is the unspecified value, output nothing. If an error occurs during evaluation, output a single line "Error: <reason>" (Section 11).
  (5) Go back to (1) to read the next datum, starting just after the datum that was read.
- All output is written to standard output in order. The only things output are the characters written by display and newline (Section 10), value lines, and error lines (including read errors).
- The state after something has been written, in which the last character written is not LF, is called "mid-line". When outputting a value line or an error line, if the output is mid-line, first write one LF. Then write the string of that line followed by LF.
- When reading of the program ends (both when terminating at (1) and when ending because of unexpected end of input), if the output is mid-line, write one final LF.

Section 6. Environments
- A "frame" is a table mapping variables (symbols) to values. A variable in a frame may also be in the "uninitialized" state (letrec in Section 8).
- An "environment" is a sequence of frames ordered from innermost to outermost. The environment obtained by adding a new empty frame as the innermost frame of an environment E is called "the extension of E".
- The "global environment" is an environment consisting of a single frame, which initially holds the 42 built-in procedures (Section 10), each as the value of the variable with its name. There is only one global environment for the whole program, and changes to its frame carry over to later expressions.
- To "look up" a variable x in an environment E means to examine the frames of E from the innermost outward and obtain the value of x in the first frame that contains x. If no frame contains x, it is the error unbound variable: <x>; if x is uninitialized in that frame, it is the error uninitialized variable: <x>. <x> is the name of the variable.
- To "bind" a variable x to a value v in a frame F means: if F does not contain x, add x with value v; if it does, replace the value of x with v.
- Variables named after built-in procedures are ordinary variables too, so they can be given other values by define or set!. After that, the new value is used when the variable is looked up.

Section 7. Evaluating expressions
To "evaluate" an expression x in an environment E means to obtain a value as follows, according to the kind of x.
1. Integer, boolean, string: x itself is the value.
2. Symbol: the value of looking up x in E.
3. Empty list: the error bad syntax: ().
4. A pair that is not a list: the error bad syntax: <external representation of x>.
5. A list whose first element is one of the 14 keywords of Section 8: it is evaluated as a special form as described in Section 8. Whether it is a keyword is determined only by the name of the symbol that is the first element, and does not depend on variable bindings. For example, even if a variable named if is defined, (if ...) remains a special form.
6. Any other list (a procedure call): first evaluate the first element (the operator) in E, then evaluate the remaining elements (the arguments) in E from left to right. After that, if the value of the operator is not a procedure, it is the error not a procedure: <external representation of the operator's value>. If it is a procedure, call that procedure (Section 9) with the argument values, in order, as its arguments; the result is the value.
- To "evaluate a body" in an environment E means to evaluate a sequence of 1 or more expressions in E from first to last and take the value of the last expression as its value.
- When an error occurs during evaluation, evaluation of that top-level expression stops there. Bindings added or changed and characters written up to that point are not undone.

Section 8. Special forms
There are 14 keywords: quote, if, define, set!, lambda, begin, let, let*, letrec, cond, and, or, when, unless.
When evaluating a special-form expression x in an environment E, first check whether x matches the "shape" given in each item. If it does not, it is the error bad syntax: <external representation of x>, without evaluating any part of x. The shape check is performed every time the expression is evaluated, and expressions that are not evaluated (such as those inside the body of a procedure that has not been called) are not checked. Below, n is the number of elements of x (including the keyword itself). Also, unless stated otherwise, expressions are evaluated in E.
The following two terms are used.
- A "parameter list" is one of the following 3. All symbols appearing in it must be distinct from one another.
  (a) The empty list, or a list whose elements are all symbols, (p1 ... pk): the ordinary parameters are p1, ..., pk and there is no rest parameter.
  (b) A symbol r: there are no ordinary parameters and the rest parameter is r.
  (c) A pair that is not a list, in which the cars encountered while following the cdrs in turn are all symbols p1, ..., pk (k is 1 or more) and the value finally reached is a symbol r, (p1 ... pk . r): the ordinary parameters are p1, ..., pk and the rest parameter is r.
- A "binding list" is a list (possibly the empty list) each of whose elements is "a list (name expr) of 2 elements, a symbol name and an expression expr". name is called the name of that binding, and expr the expression of that binding.
The special forms are as follows.
1. (quote d): the shape is n = 2. d itself is the value. The pairs contained in d are not re-created, so however many times the same quote expression is evaluated, the value is the identical pair.
2. (if c a) and (if c a b): the shape is n = 3 or n = 4. Evaluate c; if its value is true, the value is the value of evaluating a; if false, the value is the value of evaluating b (the unspecified value when n = 3).
3. define: when the 2nd element is a symbol, it is treated as the form (define name expr); when the 2nd element is a pair, it is treated as the form (define (name . formals) body ...). Otherwise it is bad syntax.
  (define name expr): the shape is n = 3. Evaluate expr in E to obtain the value v. If v is a compound procedure without a name, set its name to name. Then bind name to v in the innermost frame of E. The value is the unspecified value.
  (define (name . formals) body ...): the shape is n >= 3, the car of the 2nd element is a symbol name, and its cdr is a parameter list formals. Create the same compound procedure as evaluating (lambda formals body ...) in E would, set its name to name, and bind name to that procedure in the innermost frame of E. The value is the unspecified value. For example, (define (f x . r) ...) defines a procedure f with the ordinary parameter x and the rest parameter r.
4. (set! name expr): the shape is n = 3 and name is a symbol. Evaluate expr in E to obtain the value v. Then examine the frames of E from the innermost outward, and in the first frame that contains name, replace the value of name with v (it may be uninitialized). If no frame contains name, it is the error unbound variable: <name>. The value is the unspecified value.
5. (lambda formals body ...): the shape is n >= 3 and the 2nd element is a parameter list. The value is a new compound procedure without a name, holding the ordinary parameters and rest parameter of formals, the sequence of the 3rd and later elements (the "body"), and the environment E.
6. (begin e ...): the shape is n >= 1 (there may be 0 expressions). Evaluate the expressions in E from first to last; the value of the last expression is the value. If there are 0 expressions, the value is the unspecified value.
7. let: when the 2nd element is a symbol, it is treated as the form (let name bindings body ...) (named let); otherwise it is treated as the form (let bindings body ...).
  (let bindings body ...): the shape is n >= 3, the 2nd element is a binding list, and the names of the bindings are all distinct from one another. After evaluating the expressions of the bindings in E from first to last, create the extension E' of E, and in its new frame bind the name of each binding to the value of the corresponding expression. The value is the value of evaluating the 3rd and later elements as a body in E'.
  (let name bindings body ...): the shape is n >= 4, the 3rd element is a binding list, and the names of the bindings are all distinct from one another. After evaluating the expressions of the bindings in E from first to last, create the extension E' of E. Create a new compound procedure p whose ordinary parameters are the names of the bindings, in order (with no rest parameter), whose body is the sequence of the 4th and later elements, and whose environment is E'; set the name of p to name, and bind name to p in the new frame of E'. Then the value is the result of calling p (Section 9) with the values of the evaluated binding expressions, in order, as its arguments.
8. (let* bindings body ...): the shape is the same as for let (the non-named one), except that the names of the bindings may repeat. With k bindings, let E0 = E, and for i = 1, 2, ..., k in this order, evaluate the expression of the i-th binding in the environment E(i-1), and bind the name of the i-th binding to that value in the new frame of the environment E(i), the extension of E(i-1). The value is the value of evaluating the 3rd and later elements as a body in E(k). When there are 0 bindings, the body is evaluated in the extension of E.
9. (letrec bindings body ...): the shape is the same as for let (the non-named one) (the names of the bindings are all distinct from one another). Create the extension E' of E, and add all the names of the bindings to its new frame in the uninitialized state. Next, for the bindings one at a time from first to last, evaluate its expression in E' and immediately bind its name to that value. After all bindings are done, the value is the value of evaluating the 3rd and later elements as a body in E'.
10. (cond clause ...): the shape is that each of the 2nd and later elements (the "clauses") is a list of 1 or more elements, and a clause whose first element is the symbol else (an "else clause") has 2 or more elements and is the last clause. There may be 0 clauses. The clauses are examined from first to last as follows.
  - If it is an else clause, the value is the value of evaluating its 2nd and later elements as a body in E.
  - Otherwise, evaluate the first element of the clause (the condition) in E. If it is false, go on to the next clause. If it is true, the value is the value of the condition when the clause consists of the condition only, and otherwise the value of evaluating the 2nd and later elements of the clause as a body in E.
  If no clause determines a value, the value is the unspecified value. The symbol else has a special meaning only at the head of a cond clause; anywhere else it is an ordinary symbol.
11. (and e ...): the shape is n >= 1. Evaluate the expressions from first to last; as soon as a false value appears, the value is #f (the remaining expressions are not evaluated). If all are true, the value is the value of the last expression; if there are 0 expressions, the value is #t.
12. (or e ...): the shape is n >= 1. Evaluate the expressions from first to last; as soon as a true value appears, that value is the value (the remaining expressions are not evaluated). If all are false, or there are 0 expressions, the value is #f.
13. (when c body ...): the shape is n >= 3. Evaluate c; if true, the value is the value of evaluating the 3rd and later elements as a body in E; if false, the value is the unspecified value.
14. (unless c body ...): the shape is n >= 3. Evaluate c; if false, the value is the value of evaluating the 3rd and later elements as a body in E; if true, the value is the unspecified value.

Section 9. Calling procedures
- The "display name" of a procedure is its name if it has a name, and lambda if it has no name.
- When calling a procedure p with m arguments, the number of arguments is checked first. For a compound procedure, with k the number of ordinary parameters, m = k must hold if there is no rest parameter, and m >= k if there is one. For a built-in procedure, the number must be as given in Section 10. If this is not satisfied, the error is "<display name of p>: wrong number of arguments (expected <k>, got <m>)" when the number is fixed at exactly k, and "<display name of p>: wrong number of arguments (expected at least <k>, got <m>)" when it is k or more. For example, f: wrong number of arguments (expected 2, got 3).
- A built-in procedure works as described in Section 10, and its result is the result of the call.
- When calling a compound procedure p, create the extension E' of p's environment, and in its new frame bind the ordinary parameters, in order, to the argument values. If there is a rest parameter, bind it to the new list of the remaining argument values that did not correspond to ordinary parameters, in order (the empty list if there are none). Then the value of evaluating the body of p in E' is the result of the call.

Section 10. Built-in procedures
There are the following 42 built-in procedures. The parentheses after a name give the number of arguments accepted: "k" means exactly k, and "k or more" means k or more (Section 9).
After checking the number of arguments, a built-in procedure checks the kinds of its arguments in the order given in each procedure's description. "Check v as T" means: T is one of the following 5 kinds, and if v is not a value of that kind, it is the error "<procedure name>: expected <T>, got <external representation of v>". <procedure name> is the name of that built-in procedure, regardless of which variable it was called through.
  integer: an integer
  pair: a pair
  list: a list (Section 1)
  procedure: a procedure
  string: a string
For example, (car 5) is the error car: expected pair, got 5. Only after all kind checks are done are the other errors given in the description checked.

<Arithmetic>
The following procedures first check all arguments as integer, from left to right.
- + (0 or more): the sum of the arguments. 0 if there are no arguments.
- * (0 or more): the product of the arguments. 1 if there are no arguments.
- - (1 or more): with 1 argument, its negation. With 2 or more, the first argument minus the 2nd and later arguments, subtracted from left to right.
- quotient, remainder, modulo (2): let the arguments be a and b, in order. If b is 0, it is the error "<procedure name>: division by zero". quotient is the integer q obtained by discarding the fractional part of a / b (rounding toward 0), remainder is a - b * q, and modulo is a - b * f (f is the largest integer <= a / b). For example, (quotient -7 2) is -3, (remainder -7 2) is -1, (modulo -7 2) is 1, and (modulo 7 -2) is -1.
- abs (1): the absolute value of the argument.
- min, max (1 or more): the smallest and largest value among the arguments, respectively.
- gcd (0 or more): the greatest common divisor of the absolute values of the arguments. 0 when there are no arguments or all arguments are 0. For example, (gcd -12 18) is 6 and (gcd 0 5) is 5.

<Comparison>
- =, <, >, <=, >= (1 or more): first check all arguments as integer, from left to right (all arguments are checked regardless of the outcome of the comparisons). The result is #t if a = b, a < b, a > b, a <= b, a >= b, respectively, holds for every pair of adjacent arguments a, b (a on the left), and #f if it fails for even one pair. With 1 argument, the result is #t.

<Predicates>
The following procedures do not check the kinds of their arguments.
- not (1): #t if the argument is #f, otherwise #f.
- eq? (2): #t if the two arguments a, b satisfy any of the following, otherwise #f.
  - a and b are both integers with equal values.
  - a and b are both booleans and are equal.
  - a and b are both strings with the same length and the same character at every position.
  - a and b are both symbols with equal names.
  - a and b are both the empty list, or both the unspecified value.
  - a and b are the identical pair, or the identical procedure.
  For example, (eq? '(1) '(1)) is #f, but (let ((x '(1))) (eq? x x)) is #t.
- equal? (2): if a and b are both pairs, #t when their cars are equal and their cdrs are equal in the sense of equal?, and #f otherwise. In all other cases it is the same as eq?.
- null?, pair?, list?, number?, symbol?, procedure? (1): #t if the argument is, respectively, the empty list, a pair, a list, an integer, a symbol, a procedure; otherwise #f.

<Pairs and lists>
- cons (2): a new pair whose car is the 1st argument and whose cdr is the 2nd argument.
- car, cdr (1): check the argument as pair; its car or cdr, respectively.
- cadr (1): check the argument x as pair, then check the cdr of x as pair; the result is the car of the cdr of x. For example, (cadr '(1)) is the error cadr: expected pair, got () for the cdr of x, which is ().
- list (0 or more): a new list whose elements are the arguments, in order.
- length (1): check the argument as list; its length.
- append (0 or more): with no arguments, the empty list. Otherwise, check all arguments except the last one as list, from left to right. The result consists of the elements of each argument except the last, in argument order and, within each argument, in element order, and the cdr of its last pair is the last argument. The elements of the arguments other than the last are all put into new pairs, and the last argument is used as it is without being re-created. If the arguments other than the last have no elements at all, the result is the last argument itself. For example, (append '(1) '(2 3) 4) is (1 2 3 . 4) and (append '() 5) is 5.
- reverse (1): check the argument as list; a new list of its elements in reverse order.
- list-ref (2): check the 1st argument as list and the 2nd argument k as integer. If k is negative or not less than the length of the list, it is the error "list-ref: index out of range: <k>" (<k> is the external representation of k). Otherwise, the k-th element, counting the first element as the 0th.

<Higher-order procedures>
When the following procedures call a procedure given as an argument, the call is also made as in Section 9 (a wrong number of arguments and the like is an error of that call).
- map (2 or more): check the 1st argument f as procedure, then check the 2nd and later arguments as list, from left to right. Let L be the minimum of the lengths of those lists; for i = 0, 1, ..., L - 1 in this order, call f with the i-th elements (counting the first as the 0th) of the lists, in list order, as its arguments. The value is a new list whose elements are the results of the calls, in order.
- filter (2): check the 1st argument f as procedure and the 2nd argument as list. For the elements of the list from first to last, call f with that element as its single argument; the value is a new list of the elements for which the result was true, in their original order.
- fold-left (3 or more): check the 1st argument f as procedure, then check the 3rd and later arguments as list, from left to right (the 2nd argument is not checked). Let a be the 2nd argument and L the minimum of the lengths of the 3rd and later lists; for i = 0, 1, ..., L - 1 in this order, call f with a followed by the i-th elements of the lists, in list order, as its arguments, and let the result be the new a. The final a is the value. For example, (fold-left cons '() '(1 2)) is ((() . 1) . 2).
- apply (2 or more): check the 1st argument f as procedure and the last argument as list, in this order. The value is the result of calling f with the 2nd through second-to-last arguments followed by the elements of the last argument, in order, as its arguments. For example, (apply + 1 2 '(3 4)) is 10.

<Strings and output>
- string-append (0 or more): check all arguments as string, from left to right; the string formed by concatenating them in order. With no arguments, the empty string.
- number->string (1): check the argument as integer; a string whose contents are its external representation.
- display (1): write the display form of the argument. The value is the unspecified value.
- newline (0): write one LF. The value is the unspecified value.

<Errors>
- error (1 or more): check the 1st argument as string and raise a user error. Its <reason> is the characters of the string of the 1st argument as they are, followed, for each of the 2nd and later arguments in order, by one space and the external representation of that argument. For example, evaluating (error "bad value:" 42 "x" 'y) outputs the line Error: bad value: 42 "x" y.

Section 11. Summary of errors
- A read error outputs a single line "Error: read: <reason>", and reading continues as in Section 3(3). <reason> is one of the following 7 kinds.
  unexpected )
  unexpected .
  expected )
  unterminated string
  bad escape
  bad token: <atom>
  unexpected end of input
- An evaluation error outputs a single line "Error: <reason>", stops evaluation of that top-level expression, and the next datum is read starting just after that datum (the rest of the line is not skipped). <reason> is one of the following.
  bad syntax: <external representation of the expression>
  unbound variable: <name of the variable>
  uninitialized variable: <name of the variable>
  not a procedure: <external representation of the value>
  <display name>: wrong number of arguments (expected <k>, got <m>)
  <display name>: wrong number of arguments (expected at least <k>, got <m>)
  <procedure name>: expected <kind>, got <external representation of the value>
  <procedure name>: division by zero
  list-ref: index out of range: <k>
  and the <reason> of a user error raised by the error procedure (Section 10)
- An error line is Error: and one space, followed, for a read error, by read:, one space and <reason>, and, for an evaluation error, by <reason>. The spaces inside <reason> are single spaces, exactly as written above.

[Output format]
- The output consists only of the characters written by display and newline, value lines (the external representation of a value), and error lines ("Error: read: <reason>" or "Error: <reason>"), and is divided into lines by the rules of Section 5.
- The last character of the output is LF (unless nothing is output).

[Constraints]
- The number of input lines is at most 3000.
- An integer token has at most 15 digits.
- Every integer that appears during evaluation (including token values, arguments and results of built-in procedures, and intermediate values of computations) has absolute value less than 2^53.
- The nesting depth of compound procedure calls (the number of compound procedure calls that have started and whose results are not yet determined, including those called from built-in procedures such as map) is always at most 200.
- The nesting depth of parentheses within one datum is at most 50.
- Starting from any pair contained in a datum read or created during evaluation, and following car or cdr repeatedly in any order, the number of pairs passed through (including the first pair) is at most 1000.
- Every output line has at most 1000 characters and does not end with a space.

[Example]
Input:
(define (square x) (* x x))
(square 12)
(define (sum-list lst)
  (if (null? lst) 0 (+ (car lst) (sum-list (cdr lst)))))
(sum-list (map square '(1 2 3))) ; 1 + 4 + 9
'(1 . (2 . (3 . 4)))
(display "hello") (newline)
(display "x =") (+ 1 2)
square
(lambda (n) n)
(car '())
(square 1 2)
(let ((x 1)) (set! x (+ x 41)) x)
(error "oops:" 'bad "x")
) (display "skipped")
(list "a\qb")
(exit)

Output:
144
14
(1 2 3 . 4)
hello
x =
3
#<procedure square>
#<procedure>
Error: car: expected pair, got ()
Error: square: wrong number of arguments (expected 1, got 2)
42
Error: oops: bad "x"
Error: read: unexpected )
Error: read: bad escape

In this example, the define on lines 3-4 spans 2 lines. The value of define is the unspecified value, so nothing is output. After display on line 7 writes hello, newline writes LF. On line 8, display writes x = and the output is still mid-line when the line for the value 3 is output, so an LF is written first. On line 15, the first ) is the error unexpected ), and the rest of that line ((display "skipped")) is skipped. On line 16, \q inside the string is the error bad escape.
