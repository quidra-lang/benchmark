[Overview]
Write a Minesweeper game engine. Minesweeper is a game in which you reveal every cell without a mine while avoiding the mines hidden on the board. A revealed cell shows the number of mines in the 8 cells around it. The program reads a sequence of commands from standard input, executes them in order, and writes the results to standard output. The commands cover creating a board (placing mines with random numbers, or using a fixed layout), revealing cells, marking cells with flags and question marks, revealing the surrounding cells at once (chord), undoing operations, displaying the board and the state, recording and replaying moves, hints and automatic play by logical deduction, computing the probability that a cell is a mine, automatic play that also makes guesses, computing a board difficulty measure (3BV), and collecting statistics. Random numbers come only from the specified generator, so the results are fully determined.

[Input format]
The input consists of the following lines in this order.
- The first line is the number of commands N.
- Then N commands follow, one per line. However, the line of a LAYOUT command is immediately followed by h lines that describe the board (these lines are not counted in N).
A command line consists of one or more words separated by single ASCII spaces, with no whitespace at the start or end of the line. The first word is the command name and the remaining words are the arguments. There are the following 24 command formats (the parts other than the command name are argument names).
NEW w h mines seed
PRESET name seed
LAYOUT w h
SAFETY mode
RESTART
REVEAL x y
FLAG x y
UNFLAG x y
QUESTION x y
CHORD x y
UNDO
SHOW
STATUS
CELL x y
HISTORY n
REPLAY k
HINT
AUTO
ANALYZE
PROB x y
FRONTIER
SOLVE
BOARDINFO
STATS
The arguments are written as follows.
- w, h, mines, seed, x, y, n and k are number words. A number word is a string of 1 to 10 characters consisting only of digits (0 to 9) that does not start with 0 when it has 2 or more characters. Its value is the value read as a decimal number. For example, 0, 7 and 120 are number words, while 07, -1, +3, 12345678901 and x are not.
- name is one of beginner, intermediate and expert (lowercase letters).
- mode is one of block, cell and none (lowercase letters).
A LAYOUT line and the h lines that follow it always have the form described in [Constraints].

[Processing]
Process the commands one by one in input order, writing the output of each immediately. Below, a string enclosed in double quotes is a string that appears exactly as is in the input or output. A part such as <n> in an output description is replaced by its value.

1. Board and terms
- The board consists of w cells horizontally and h cells vertically. The cell that is x-th from the left and y-th from the top is written (x, y). Both x and y are counted from 0 (0 <= x <= w - 1, 0 <= y <= h - 1). In the input, a cell is given as x then y. In the output, a <cell> part is written as x and y joined by an ASCII comma "," (for example, (3, 5) is written 3,5).
- Each cell is either a mine or a safe cell.
- The neighbors of cell (x, y) are the cells (x + dx, y + dy) (dx and dy are each one of -1, 0 and 1, not both 0) that lie inside the board. When neighbors are examined in sequence, always examine them in the order (x - 1, y - 1), (x, y - 1), (x + 1, y - 1), (x - 1, y), (x + 1, y), (x - 1, y + 1), (x, y + 1), (x + 1, y + 1), skipping those outside the board. This order is called neighbor order.
- The number of a safe cell is the number of its neighbors that are mines (0 to 8).
- Row-major order is the order of cells by increasing y, and for equal y by increasing x.
- Each cell is either revealed or hidden. A hidden cell may carry one mark, either a flag or a question mark. A revealed cell has no mark.
- An unknown cell is a cell that is hidden and not flagged (a cell with a question mark is also an unknown cell).
- A numbered cell is a revealed safe cell whose number is 1 or more.
- For a numbered cell c, let F(c) be the number of flagged neighbors of c, U(c) the set of neighbors of c that are unknown cells, and rem(c) be (the number of c) - F(c).
- The flag count is the number of flagged cells on the whole board. The number of remaining mines is (the total number of mines) - (the flag count) (it can be negative).

2. State
The program has the following state. Initially there is no game, the SAFETY setting is block, and all statistics are 0 (the minimum move count of a won game is none).
- Game: when there is a game, it has the following.
  the board size w, h and the total number of mines m
  the mine placement (which may not be determined yet) and the seed used to determine the placement
  whether each cell is revealed, and the mark of each cell
  the game state: one of ready, playing, won and lost. ready means the mine placement is not determined yet, playing means the game is in progress, won means the game was won and lost means the game was lost. A game whose state is won or lost is said to be finished.
  the exploded cell: the mine cell that the player tried to reveal when the game was lost. It exists only when the game state is lost.
  the move record: the sequence of successful operations, oldest first. Each operation is a pair of a kind and a cell. The kind is one of reveal, flag, unflag, question, chord, auto-reveal, auto-flag and guess. The length of the move record is called the move count.
  the undo record: a sequence of records used by UNDO to restore the state (explained under UNDO in section 9).
- The SAFETY setting: one of block, cell and none.
- Statistics: the number of finished games, the number of wins, the number of losses, the current win streak, the longest win streak, and the minimum move count of a won game (none if no game has been won yet).
Creating a game (NEW, PRESET, LAYOUT) discards the previous game. In a new game every cell is hidden and unmarked, and the move record and the undo record are empty. A game created by NEW or PRESET starts with the mine placement not determined (ready), and a game created by LAYOUT starts with the mine placement determined (playing).

3. Mine placement
In a game whose mine placement is not determined, when a reveal operation (section 4) is performed for the first time, mines are placed as follows, based on the cell to be revealed s = (sx, sy).
(1) The candidate list is the list, in row-major order, of the board cells that satisfy the following condition.
  If the SAFETY setting (at the time of placement) is block: cells with |x - sx| >= 2 or |y - sy| >= 2 (cells outside the 3x3 area centered on s).
  If it is cell: cells other than s.
  If it is none: all cells.
(2) Let the random state r be seed.
(3) Repeat the following m times. Update r to (48271 * r) mod 2147483647. With L the length of the candidate list, make the cell at index (r mod L) of the candidate list (the first cell being index 0) a mine, and remove that cell from the candidate list (the order of the remaining cells does not change).
(4) Every cell that did not become a mine is a safe cell. Set the game state to playing.
48271 * r is less than 2^47, so it can be computed exactly with 64-bit integers. Once determined, the mine placement does not change for the rest of that game (also after RESTART or UNDO).

4. Reveal operation
The operation of revealing an unknown cell s is as follows.
- If the mine placement is not determined, place the mines as in section 3.
- If s is a mine, perform the loss processing (section 5). In this case the opened count is 0.
- If s is a safe cell, reveal cells in a chain by the following procedure. First reveal s (removing its mark, if any) and create a queue containing only s. Until the queue is empty, repeatedly take the cell q at the front of the queue, and if the number of q is 0, examine the neighbors of q in neighbor order, reveal each one that is an unknown cell (removing a question mark), and append it to the end of the queue. Flagged cells are not revealed. The number of cells newly revealed this way (including s) is the opened count of this operation. Every cell revealed in this chain is a safe cell.

5. Loss, win and board display
- Loss processing: set the game state to lost and make the mine cell that the player tried to reveal the exploded cell (the exploded cell does not become a revealed cell). The output in this case (the loss output) is one line boom <exploded cell> followed by the h lines of the board display.
- Win check: if the game state is playing and every safe cell is revealed, set the game state to won and set the mark of every mine cell to a flag (question marks also become flags). The output in this case (the win output) is one line win moves <moves>. When the win check is performed is specified in the description of each command.
- Where the loss output and the win output are written is as described for each command.
- Statistics update: when the game state becomes won or lost as a result of processing a command (REVEAL, CHORD, AUTO, SOLVE), update the statistics as follows. Add 1 to the number of finished games. On a win, add 1 to the number of wins and to the current win streak, set the longest win streak to the larger of itself and the current win streak, and set the minimum move count of a won game to the smaller of itself and the move count of this game (if it is none, set it to the move count of this game). On a loss, add 1 to the number of losses and set the current win streak to 0.
- The board display consists of h lines. Line y from the top (counted from 0) is the w characters of the cells (x, y) for x = 0, 1, ..., w - 1, concatenated in this order. The character of each cell is as follows.
  When the game state is lost, a mine cell is "!" if it is the exploded cell, "F" if it is flagged, and "*" otherwise (including when it has a question mark). A flagged safe cell is "X". All other cells follow the normal rule below.
  Normal rule: a revealed cell is "." if its number is 0, and otherwise the single digit of its number. A hidden cell is "F" if it is flagged, "?" if it has a question mark, and "#" if it is unmarked.
  When the game state is not lost, every cell follows the normal rule.

6. Deduction
HINT, AUTO, ANALYZE and SOLVE use the following deduction. The deduction trusts the flags (treats flagged cells as mines) and does not change any state. The result of the deduction is a pair of the set of cells found to be safe (the safe set) and the set of cells found to be mines (the mine set), and each cell has a reason. Try rules 1 to 4 below in order; the result of the deduction is the result of the first rule whose result is not empty. If the results of all rules are empty, the result of the deduction is empty (both the safe set and the mine set are empty).
- Rule 1: consider every numbered cell c with rem(c) = 0 and U(c) not empty. All cells of U(c) of such c are safe. The safe set is the union of those U(c), and the mine set is empty. The reason of each cell t in the safe set is single <cell>, where <cell> is the first, in row-major order, of such cells c whose U(c) contains t.
- Rule 2: consider every numbered cell c such that rem(c) equals the number of cells of U(c) and U(c) is not empty. All cells of U(c) of such c are mines. The mine set is the union of those U(c), and the safe set is empty. The reasons are determined in the same way as in rule 1 (of the form single <cell>).
- Rule 3: consider every pair (a, b) of two different numbered cells such that U(a) is not empty and U(a) is a proper subset of U(b) (every cell of U(a) is contained in U(b), and U(b) has more cells). For each pair, let D be U(b) with the cells of U(a) removed, and let d = rem(b) - rem(a). If d = 0, all cells of D are safe, and if d equals the number of cells of D, all cells of D are mines. The safe set and the mine set are the combined results of all pairs (if flags are wrong, the same cell can be in both). The reason of each cell t is subset <a> <b> (<a> and <b> have the form of <cell>), where the pair (a, b) is the first pair that put t on the safe set side (for a reason in the mine set, on the mine set side) when the pairs are sorted by a in row-major order, and for equal a by b in row-major order.
- Rule 4: if the game state is playing, the number of remaining mines is 0, and there is at least one unknown cell, all unknown cells are safe. The safe set is the set of all unknown cells, and the mine set is empty. The reason of each cell is count.

7. Frontier and components
PROB, FRONTIER and SOLVE use the following computations.
- A constraint cell is a numbered cell c whose U(c) is not empty. A constraint cell c represents the constraint that exactly rem(c) of the cells of U(c) are mines.
- A frontier cell is a cell contained in U(c) of some constraint cell c.
- Two frontier cells are connected if there is a constraint cell c whose U(c) contains both of them. A maximal set of frontier cells that can all reach one another by repeatedly moving between connected cells is called a component. Every frontier cell is contained in exactly one component. The first cell of a component in row-major order is the representative cell of that component.
- A configuration of a component K is an assignment of mine or safe to each cell of K (if K has n cells, there are 2^n of them). A configuration of K is consistent if the constraint holds for every constraint cell c whose U(c) is contained in K (U(c) of every constraint cell c is contained entirely in one component). The number of consistent configurations of K is called the configuration count of K. The minimum and maximum numbers of cells assigned mine in a consistent configuration of K are called the minimum mine count and the maximum mine count of K.
- The probability of a cell t contained in a component K, when the configuration count of K is 1 or more, is the number of consistent configurations of K that make t a mine divided by the configuration count of K.
- Configuration counts and the like can be computed fast enough within [Constraints] by a search that assigns mine or safe to the cells of K one at a time and backtracks as soon as it is known that the constraints cannot be satisfied.

8. Command checks and errors
For each command, check (1) to (10) below in order and handle the first one that applies. A command that outputs an error does not change any state.
(1) If it is LAYOUT, process it as in section 9.
(2) The command name is not one of the formats (uppercase and lowercase letters are distinguished): error: unknown command <command name>
(3) The number of arguments differs from the format, or an argument does not follow the rules in [Input format]: error: bad arguments
(4) For NEW or PRESET, a value is out of range, or for HISTORY, n is 0: error: bad value. The ranges for NEW and PRESET are that all of 1 <= w <= 30, 1 <= h <= 30, 1 <= mines <= w * h - 9 and 1 <= seed <= 2147483646 hold (for PRESET, the w, h and mines determined by name are used).
(5) If it is NEW, PRESET, SAFETY or STATS, process it as in section 9.
(6) There is no game: error: no game
(7) For a command that specifies a cell (x, y) by its arguments (REVEAL, FLAG, UNFLAG, QUESTION, CHORD, CELL, PROB), x >= w or y >= h: error: out of range
(8) For any of REVEAL, FLAG, UNFLAG, QUESTION, CHORD, UNDO, HINT, AUTO, ANALYZE, PROB, FRONTIER and SOLVE, the game is finished: error: game over
(9) For ANALYZE or BOARDINFO, the mine placement is not determined: error: not started
(10) Process it as in section 9 (which also defines some errors).

9. Processing of each command
- NEW w h mines seed: create a new game with board size w, h, total number of mines mines, seed seed, and the mine placement not determined, and output new <w>x<h> mines <mines>. The x between <w> and <h> is a single lowercase letter x, with no spaces around it (the same applies to the <w>x<h> form below).
- PRESET name seed: with w = 9, h = 9, mines = 10 if name is beginner, w = 16, h = 16, mines = 40 if it is intermediate, and w = 30, h = 16, mines = 99 if it is expert, do the same processing as NEW w h mines seed (the output is also the same).
- LAYOUT w h: read the next h lines as the rows of the board. Whether or not there is an error, proceed to the next command only after reading the h lines. If there is a line whose length is not w or that contains a character other than "*" and ".", let the topmost such line be line i (1 <= i <= h), and output error: bad row <i>. Otherwise, if the number k of "*" is 0 or w * h, output error: bad mine count <k>. With either error, the current game remains as it is. Otherwise, create a new game (with game state playing) with the placement in which a cell (x, y) is a mine if the x-th character from the left (counted from 0) of line y from the top (counted from 0) is "*" and every other cell is safe, and with total number of mines k, and output layout <w>x<h> mines <k>.
- SAFETY mode: set the SAFETY setting to mode and output safety <mode>. This setting is used for mine placements (section 3) performed from now on (if the mine placement of the current game is not determined yet, it is also used for that placement).
- RESTART: keeping the size, the total number of mines, the seed and the mine placement of the current game (if not determined, it stays not determined), hide every cell and remove its mark, empty the move record and the undo record, remove the exploded cell, and set the game state to playing if the mine placement is determined, or to ready if not. Output restart <w>x<h> mines <m>. It can be done even if the game is finished.
- REVEAL x y: if (x, y) is revealed, output error: already revealed, and if it is flagged, output error: flagged. Otherwise, append (reveal, (x, y)) to the end of the move record, then perform the reveal operation (section 4) on (x, y). If the game is lost, write the loss output. If not, output revealed <opened count>, then perform the win check, and on a win write the win output.
- FLAG x y: if (x, y) is revealed, output error: already revealed, and if it is flagged, output error: already flagged. Otherwise, set the mark of (x, y) to a flag (a question mark becomes a flag), append (flag, (x, y)) to the end of the move record, and output flagged <cell> left <remaining mines>.
- UNFLAG x y: if (x, y) is revealed, output error: already revealed, and if it is not flagged (including when it has a question mark), output error: not flagged. Otherwise, remove the flag to leave it unmarked, append (unflag, (x, y)) to the end of the move record, and output unflagged <cell> left <remaining mines>.
- QUESTION x y: if (x, y) is revealed, output error: already revealed. Otherwise, append (question, (x, y)) to the end of the move record. If (x, y) has a question mark, remove it to leave it unmarked and output unmarked <cell> left <remaining mines>. Otherwise (when it is unmarked or flagged), set its mark to a question mark and output questioned <cell> left <remaining mines>.
- CHORD x y: let c = (x, y). Check the following in this order. If c is hidden, output error: not revealed; if the number of c is 0, output error: no number; if F(c) differs from the number of c, output error: flags <F(c)> of <number of c>; if U(c) is empty, output error: nothing to reveal. Otherwise, append (chord, c) to the end of the move record, examine the neighbors of c in neighbor order, and perform the reveal operation (section 4) on each one that is an unknown cell at that moment (skipping cells already revealed by the chain from a cell revealed earlier). If the game is lost, stop at that point (the remaining neighbors are not examined) and write the loss output. If not, output chorded <k> with k the total opened count, then perform the win check, and on a win write the win output.
- UNDO: if the undo record is empty, output error: nothing to undo. Otherwise, remove the last element of the undo record, restore whether each cell is revealed, the mark of each cell, and the move record to those saved in that element, and output undo <name> moves <moves after undo>. <name> is the command name of that element in lowercase letters (one of reveal, flag, unflag, question, chord, auto and solve). The mine placement, the game state and the statistics are not restored (for example, even if a REVEAL that placed the mines is undone, the placement remains and the game state stays playing).
  The undo record is built as follows. When processing any of REVEAL, FLAG, UNFLAG, QUESTION, CHORD, AUTO and SOLVE increases the move count, append to the end of the undo record that command name together with the triple (whether each cell is revealed, the mark of each cell, the move record) as it was just before processing the command. When the move count does not increase (on an error, or when AUTO or SOLVE did nothing), nothing is appended.
- SHOW: output the h lines of the board display (section 5).
- STATUS: output status <game state> left <remaining mines> moves <moves> revealed <revealed cells>/<safe cells>. The number of safe cells is w * h - m (the same even if the mine placement is not determined).
- CELL x y: if (x, y) is revealed, output cell <cell> number <number> flags <f> unknown <u>. f and u are the number of flagged cells and the number of unknown cells among the neighbors of (x, y) (also for a cell whose number is 0). If (x, y) is hidden, output cell <cell> hidden mark <mark> open <o>. <mark> is flag for a flag, question for a question mark, and none if unmarked. o is the number of revealed cells among the neighbors of (x, y). CELL outputs by this rule regardless of the game state (it does not show whether the cell is a mine).
- HISTORY n: output history <moves> on the first line, then output the last min(n, move count) operations of the move record, oldest first, one per line in the form <index> <kind> <cell>. <index> is the position of that operation in the move record counted from the start (starting from 1).
- REPLAY k: if k is greater than the move count, output error: no move <k>. Otherwise, output replay <k>/<moves>, then output, as the h lines of the board display (section 5), the board obtained by redoing the first k operations of the move record of the current game in order from the first. The redo starts from a copy of the current game in which every cell is hidden and its mark removed, the exploded cell is removed, and the game state is playing if the mine placement is determined, or ready if not. The mine placement of the current game is used as is, and each operation is performed as follows. reveal, auto-reveal and guess are the reveal operation (section 4) on that cell. chord is the cell-revealing part of CHORD (examine the neighbors of that cell in neighbor order, reveal each one that is an unknown cell at that moment, and stop if the game is lost). flag and auto-flag set the mark of that cell to a flag. unflag removes the flag. question removes the question mark if there is one, and otherwise sets the mark to a question mark. The win check is performed after each operation. The redo outputs nothing (the loss output and the win output are not written either), and if the board to display is after a loss, it is displayed by the rule for a loss. REPLAY does not change any state.
- HINT: perform the deduction (section 6). If the safe set is not empty, output hint safe <t> by <reason of t> for the first cell t of it in row-major order. If the safe set is empty and the mine set is not empty, output hint mine <t> by <reason of t> for the first cell t of it in row-major order. If both are empty, output hint none.
- AUTO: set the round count, the flagged count and the total opened count to 0 each, and repeat the following while the game state is playing.
  Perform the deduction (section 6), and stop if the result is empty. Otherwise, add 1 to the round count and do (a) and (b) below in this order.
  (a) Take the cells of the safe set one at a time in row-major order. If the cell is hidden at that moment, append (auto-reveal, that cell) to the end of the move record, then perform the reveal operation (section 4) on that cell, add the opened count to the total, and perform the win check. If the game is lost or won, stop AUTO at that point ((b) is not done either).
  (b) Take the cells of the mine set one at a time in row-major order. If the cell is an unknown cell at that moment, set its mark to a flag (a question mark becomes a flag), add 1 to the flagged count, and append (auto-flag, that cell) to the end of the move record.
  After stopping, output auto rounds <rounds> flagged <flagged count> revealed <total opened>, and if the game was lost or won during AUTO, then write that loss output or win output.
- ANALYZE: perform the same processing as AUTO on a copy of the current game (outputting nothing), and output its result. If the copy is lost, output analyze boom <exploded cell of the copy> rounds <rounds>; if it is won, output analyze clear rounds <rounds>; otherwise output analyze stuck rounds <rounds> revealed <revealed cells of the copy>/<safe cells>. The current game and the statistics do not change at all.
- PROB x y: let t = (x, y). If t is revealed, output error: already revealed, and if it is flagged, output error: flagged. Otherwise, compute the frontier cells and the components (section 7), and if t is not a frontier cell, output prob <t> unconstrained. If the configuration count of the component K containing t is 0, output prob <t> inconsistent. Otherwise, output prob <t> <a>/<b> size <cells in K> configs <configuration count of K>. a/b is the probability of t as an irreducible fraction (0/1 if the probability is 0, and 1/1 if it is 1).
- FRONTIER: compute the frontier cells and the components (section 7), and output frontier <frontier cells> components <components> on the first line. Then output one line per component, in row-major order of the representative cells: component <representative cell> size <cell count> configs <configuration count> min <minimum mine count> max <maximum mine count> if the configuration count is 1 or more, or component <representative cell> size <cell count> inconsistent if the configuration count is 0.
- SOLVE: play automatically, including guesses, until the game ends. Set the round count, the flagged count, the total opened count and the guess count to 0 each, and repeat (1) to (3) below.
  (1) Perform the same processing as AUTO (with no output; the loss output and the win output are kept to be written later), and add its round count, flagged count and total opened count to the corresponding values of SOLVE. If the game is finished, stop.
  (2) Choose the cell to guess. The candidates are the frontier cells contained in components whose configuration count is 1 or more (the value is the probability of the cell), and the unknown cells that are not frontier cells (the value is max(remaining mines, 0) / (the number of unknown cells on the whole board, including frontier cells)). The frontier cells and the components are computed on the board at this moment. If there are no candidates, stop. Choose the candidate with the smallest value (values are compared exactly as fractions), and if there are several such cells, choose the first of them in row-major order.
  (3) Add 1 to the guess count, append (guess, the chosen cell) to the end of the move record, then perform the reveal operation (section 4) on that cell, add the opened count to the total, and perform the win check. If the game is finished, stop.
  After stopping, output solve guesses <guesses> rounds <rounds> flagged <flagged count> revealed <total opened>, and if the game was lost or won during SOLVE, then write that loss output or win output.
- BOARDINFO: compute the following values for the mine placement and output 3bv <3BV> openings <openings> largest <largest opening size> mines <m> safe <safe cells>. These values depend only on the mine placement and are unrelated to whether cells are revealed, to marks, and to the game state.
  A blank cell is a safe cell whose number is 0.
  An opening is a maximal set of blank cells that can all reach one another by repeatedly moving between neighboring cells.
  The size of an opening is the number of cells (without duplicates) consisting of the blank cells of that opening together with the cells that are neighbors of any of those blank cells (this equals the number of cells revealed by the chain when one blank cell of that opening is revealed). If there is no opening, the largest opening size is 0.
  3BV is the sum of the number of openings and the number of safe cells whose number is 1 or more and that have no blank cell among their neighbors.
- STATS: output stats played <finished games> won <wins> lost <losses> rate <win rate> streak <current win streak> best <longest win streak> fastest <minimum moves of a won game>. <win rate> is - if the number of finished games is 0, and otherwise the integer floor((wins * 100) / (finished games)) followed by "%". <minimum moves of a won game> is - if it is none.

[Output format]
- For each command, output the lines described in [Processing] in that order. Unless otherwise specified, the output of each command is one line.
- Words in a line are separated by a single ASCII space, no line has trailing whitespace, and every line ends with a newline.
- Numbers are written in decimal without extra leading zeros. A negative number is prefixed with "-".
- A <cell> part is <x>,<y>, that is, x and y joined by an ASCII comma, with no spaces.
- In the [Processing] description, the period at the end of a sentence (including one right after an output template) is a sentence delimiter and is not part of the output.

[Constraints]
- 1 <= N <= 1000, and the whole input has at most 3000 lines.
- Each word of a command line is a string of 1 to 20 printable ASCII characters other than space (from ! to ~).
- A LAYOUT line is always LAYOUT, w and h separated by single ASCII spaces, where w and h are decimal numbers from 1 to 30 without leading zeros. Each of the h lines that follow it is a string of 1 to 40 printable ASCII characters other than space.
- Every component whose configurations are counted in PROB, FRONTIER and SOLVE has at most 30 cells and a configuration count of at most 100.
