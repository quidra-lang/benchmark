## Evidence and language semantics

The same compact valid scenario is used in every language: IFACE wan 9.0.0.1/24; IFACE lan 10.0.0.1/24; ROUTE 0.0.0.0/0 DEV wan 1; NAT PAT wan 2; NAT FORWARD wan UDP 8080 10.0.0.2 80; ACL wan IN 10 PERMIT UDP ANY ANY 9.0.0.1/32 8080; ACL wan OUT 10 PERMIT UDP 10.0.0.2/32 80 ANY ANY; ACL wan OUT 20 REJECT UDP ANY ANY ANY ANY. Then PACKET wan UDP - 8.0.0.2 5000 9.0.0.1 8080 64 forwards to lan with dnat=10.0.0.2:80 and a new connection. PACKET lan UDP - 10.0.0.2 80 8.0.0.2 5000 64 matches that connection reply, forwards to wan and reverses the port-forward using snat=9.0.0.1:8080. PACKET lan UDP - 10.0.0.3 1234 8.0.0.2 53 64 is a PAT candidate rejected by wan out 20 (icmp-prohibited). Inbound ACL observes the original public destination; outbound ACL observes the translated destination and original private source, before source translation. Outbound ACL return precedes source translation/allocation and the common last-used refresh, connection creation/record, tx and route-hit updates; therefore neither a new nor an existing PAT mapping can be allocated/refreshed by a rejected packet. rx/packet/drop counters and the matching ACL hit still change. Final forwarded=2, dropped=1, acl_out=1; wan rx/tx/drop=1/1/0, lan=2/1/1. The connection has original/reply packet counters 1/1 and UDP state REPLIED; connected-lan and default-route hits are each 1; wan in10/out10/out20 hits are each 1. Empty ACLs allow without a default hit; an unmatched nonempty ACL increments its default hit and drops. PAT remains empty.

Ruby Hash and Array elements are references: connection and selected route hashes returned by find/min_by remain the stored objects, so their updates persist. Array equality compares complete tuple contents. ACL sort_by followed by find is first-match sequence ordering and increments rule hits before action. Separate translated_* scalars form the post-DNAT/pre-SNAT out-ACL tuple; the early return is before PAT lookup/creation and timestamp update.

## Minimization and alternatives

The common witness deliberately uses UDP with flag -, TTL 64, default-up interfaces, RPF off, a direct DEV route, empty static-NAT collection and one port-forward. It exercises both destination and source translation and a rejected PAT candidate with three packets. TCP state/flag branches, VIA recursion, RPF modes, STATIC configuration, timers/expiration, clearing, and unrelated SHOW views cannot affect these outcomes. Keep the executed configuration/parser/value checks, ACL matching/order/default behavior, route/connection lookup, translated tuples, the ACL-to-NAT control boundary, packet output and counter updates. A pipeline-only alternative was rejected because custom parsers, ACL match/evaluation and route/connection/NAT helpers determine the meaning of the supplied input and side effects. A whole-command-dispatch or whole-program alternative contains unrelated features. PAT port-choice internals are unnecessary: rejection prevents the translation call itself, and the successful reply returns through the port-forward branch before PAT allocation. Blank lines and unrelated branch bodies are excluded. The final excerpt is independently re-read alone with language/library semantics and the valid-input assumption; it supports every shared requirement without Task A-only evidence.

Only the initial reset counter assignments are needed: interfaces/routes are empty during initialize, so reset loops then have no effect. Port-choice body is skipped by the witness and rejection gate; creation/insertion/refresh sites suffice to establish the forbidden effects.
