## Evidence and language semantics

The same bare-token scenario is used across languages: SET k v EX 5; BEGIN; BEGIN; SET keep inner; COMMIT; SNAPSHOT s; RESTORE s; TICK 6; ROLLBACK; GET k; RESTORE s; GET keep; GET k. It distinguishes an outer transaction copy, an inner commit, and a retained named snapshot. The clock starts at zero; the TTL deadline is five; at clock six restoring either saved database removes k. The outer rollback removes keep from the current database but the named snapshot s still supplies it. PHP arrays have value/copy-on-write semantics, whereas objects are handles. Consequently the selected readonly Value/Entry declarations and scalar string payload matter: saved array entries cannot be mutated through a shared object. put creates a new Entry. transactions array_pop discards only the newest saved array, and named snapshots remain in their separate array after restore. Both restoration paths assign database only and purge using the independent time field. Prefixing keys with a colon avoids numeric key coercion; entry/put evidence supplies the mapping used by GET. Output arrays are printed one row each with the selected exact status and value formatting.
