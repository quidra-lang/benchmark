## Evidence and language semantics

The same bare-token scenario is used across languages: SET k v EX 5; BEGIN; BEGIN; SET keep inner; COMMIT; SNAPSHOT s; RESTORE s; TICK 6; ROLLBACK; GET k; RESTORE s; GET keep; GET k. It distinguishes an outer transaction copy, an inner commit, and a retained named snapshot. The clock starts at zero; the TTL deadline is five; at clock six restoring either saved database removes k. The outer rollback removes keep from the current database but the named snapshot s still supplies it. Swift structs, enums, String, Array and Dictionary have value semantics, so copying the Database value into transactions or snapshots preserves its records even with copy-on-write storage. The selected declarations establish that all payloads here are values; no explicit deep-copy routine is required. popLast removes only one transaction; snapshots subscripting does not remove the named save. Restoring database leaves the separate time and snapshots fields intact, then purge removes deadline <= time. Standard optional/map semantics explain nil and optional expiry, while explicit quote and reply functions establish visible formatting.
