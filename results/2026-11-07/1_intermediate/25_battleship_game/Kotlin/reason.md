## Evidence and language semantics

Normalize only the parsed command name SHOT to FIRE (or bind SHOT to exactly the existing FIRE handler), before all name-based routing, leaving argument positions and the ordered batch intact. Do not loop by dispatching separate FIRE commands: that would repeat validation/allowance and finish turns independently. The excerpt separates batch validation from action and retains the original per-shot and completion calls. An error in a later command does not undo already accepted state; an invalid later cell in the current batch is discovered during its preflight before any shot. Exceptions/early returns bypass completion. Repeated cells reach the unchanged shot operation in order, so its existing ALREADY behavior remains; victory still stops remaining shots. AI and TORPEDO keep their own operands, handlers, output and action rules. Kotlin execute and turn both read the original List token w[0]. Construct/pass one canonical FIRE token list before routing, or pass the canonical command explicitly; merely changing the outer local val does not update the callee. The remaining list is unchanged, preflight scans every target before setting BATTLE, and the FIRE loop emits each shot and accumulates hit before one finishTurn. shoot calls stats.record. AI retains Strategy.valueOf and its own turn path; TORPEDO keeps its row/side scan and single-shot handling. A persistent Game object is shared across repeat iterations, and a GameError skips action/automatic control without undoing preceding accepted shots.
