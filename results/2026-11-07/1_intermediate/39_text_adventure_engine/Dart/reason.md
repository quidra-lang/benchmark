## Evidence and language semantics

Dart record equality makes Place pairs comparable; sorted Item IDs assign the list indexes used by the fuel sweep. Nullable treasure distinguishes a declared treasure from an ordinary item. Set construction and cascade addAll retain the nearby snapshot before the lit flags change. USE filters ordered records, executes the MoveEffect, and only then does run call turn for action verbs; case clauses do not fall through in Dart. fail throws CommandFailure with Never return and process catches it outside run, explaining bypass on failure. SCORE has an information branch and no entry in the action set. Enum declaration and the parallel alias list are both retained because Verb.values uses their indexes. Independent excerpt review checks the world-to-USE dispatch, resolution and validation, stored-treasure effect, lighting/fuel transition, death-before-win guard, SCORE non-action evidence and outer output/error path as one dependency chain. Full action membership lists are retained where absence of SCORE is material; the declaration and alias order are both retained where ordinal lookup is used. The common trace is `Use the wand on the bell`, with unambiguous wand/bell items, the wand carried, and `RULE wand bell ADD gem trophy`. The final unstored gem is a treasure; ADD moves it to the trophy-room floor. The pre-turn state has a lit torch with exactly one fuel unit, reachable in the current DARK room, and no previous terminal status. Rules run first and produce Done. when no MESSAGE runs; the move count advances once, every lit light loses one integer fuel unit, and the torch becomes unlit while remaining a zero-fuel light. Its proximity is sampled before the fuel sweep, so its outage message is emitted, then the lit-to-dark notice. Darkness advances and the final treasure makes victory possible only if no death has already occurred. Score is current stored treasure points plus bonus, not a separately accumulated treasure counter. For the fatal contrast, begin with darkness count two and the final-fuel light lit elsewhere, while both USE operands are carried and thus resolvable in darkness. The light still burns out, without a nearby outage notice, darkness reaches three, death suppresses victory although the gem effect and score remain. This is a reachable state comparison, not an assumption that a previously lit room can already have darkness count two. Failed resolution, an uncarried first operand, or no applicable rule escapes before turn passage; SCORE is an information command and similarly does not consume fuel or increment moves. The selected input/output path preserves the original echoed command and prints terminal and final scores. 

## Minimization and alternatives

The selection chooses USE consistently in all twenty languages, as permitted by “USE or movement”; movement, exits, inventory mutation, saving/restoring, and unused rule effects are not a second required trace. Rule ADD, operand resolution, exact light-property/fuel separation, and end-turn ordering are individually necessary. A turn-only excerpt cannot establish the action effects or failure bypass; a USE-only excerpt cannot establish death priority, fuel or victory. Information SCORE is used as the representative non-action. Built-in collection traversal/equality, integer operations, exception/result propagation and output formatting supply standard language semantics; custom helpers on the trace are included. Whole routines are not selected automatically, and blank/closing-only lines and unrelated branches are excluded when separable. No gameplay source is modified, compiled or run.

The excerpt contains 5750 tokens under `metric/tokenizer.py`. Only complete source lines are counted; the question and this rationale are excluded. Task B uses the README assumption that the Task A program satisfies its contract; this selection does not claim compilation or runtime verification.
