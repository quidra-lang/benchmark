## Evidence and language semantics

Ordered std::map keys provide identifier traversal without a separate sort; references in endTurn mutate the actual ItemState. The decrementation is guarded by lit and uses --fuel before equality, then clears lit independently of Item.light. Place equality and ordering are explicit; reachable builds a parent-to-children map and traverses open containers, while scoring follows parent places to the trophy floor. Variant visitation applies AddItem, and the ordered Rule vector supplies trigger/condition checks and message rows. Failure exceptions unwind before endTurn and are returned as rows by command; SCORE has rows but no membership in actions. Input preserves the original echo and QUIT final-score formatting. The common trace is `Use the wand on the bell`, with unambiguous wand/bell items, the wand carried, and `RULE wand bell ADD gem trophy`. The final unstored gem is a treasure; ADD moves it to the trophy-room floor. The pre-turn state has a lit torch with exactly one fuel unit, reachable in the current DARK room, and no previous terminal status. Rules run first and produce Done. when no MESSAGE runs; the move count advances once, every lit light loses one integer fuel unit, and the torch becomes unlit while remaining a zero-fuel light. Its proximity is sampled before the fuel sweep, so its outage message is emitted, then the lit-to-dark notice. Darkness advances and the final treasure makes victory possible only if no death has already occurred. Score is current stored treasure points plus bonus, not a separately accumulated treasure counter. For the fatal contrast, begin with darkness count two and the final-fuel light lit elsewhere, while both USE operands are carried and thus resolvable in darkness. The light still burns out, without a nearby outage notice, darkness reaches three, death suppresses victory although the gem effect and score remain. This is a reachable state comparison, not an assumption that a previously lit room can already have darkness count two. Failed resolution, an uncarried first operand, or no applicable rule escapes before turn passage; SCORE is an information command and similarly does not consume fuel or increment moves. The selected input/output path preserves the original echoed command and prints terminal and final scores.

## Minimization and alternatives

The selection chooses USE consistently in all twenty languages, as permitted by “USE or movement”; movement, exits, inventory mutation, saving/restoring, and unused rule effects are not a second required trace. Rule ADD, operand resolution, exact light-property/fuel separation, and end-turn ordering are individually necessary. A turn-only excerpt cannot establish the action effects or failure bypass; a USE-only excerpt cannot establish death priority, fuel or victory. Information SCORE is used as the representative non-action. Built-in collection traversal/equality, integer operations, exception/result propagation and output formatting supply standard language semantics; custom helpers on the trace are included. Whole routines are not selected automatically, and blank/closing-only lines and unrelated branches are excluded when separable. No gameplay source is modified, compiled or run. The torch is already lit with one fuel unit in the question's pre-turn state. Separate LIGHT/EXTINGUISH command bodies and their dedicated dispatches supply no fact about the selected USE turn and are omitted. Light capability, lit/fuel state, world parsing, USE effects, fuel and death/victory ordering remain selected.
