## Evidence and language semantics

PHP objects preserve reference identity for GameState and Item, while the nearby membership array is copied before the burn sweep. Place.key/equals define exact placement comparisons; sorted associative item keys control fuel and ambiguity order. USE resolves both operands and applies MoveEffect before returning Done. CommandFailure stores response rows; throwing it unwinds past endTurn and the outer catch returns only those rows. Verb.action explicitly excludes Score. Score is calculated from current places and bonus after rule effects, with EndStatus::Dead set before the only None-to-Won transition. Independent excerpt review checks the world-to-USE dispatch, resolution and validation, stored-treasure effect, lighting/fuel transition, death-before-win guard, SCORE non-action evidence and outer output/error path as one dependency chain. Full action membership lists are retained where absence of SCORE is material; the declaration and alias order are both retained where ordinal lookup is used. The common trace is `Use the wand on the bell`, with unambiguous wand/bell items, the wand carried, and `RULE wand bell ADD gem trophy`. The final unstored gem is a treasure; ADD moves it to the trophy-room floor. The pre-turn state has a lit torch with exactly one fuel unit, reachable in the current DARK room, and no previous terminal status. Rules run first and produce Done. when no MESSAGE runs; the move count advances once, every lit light loses one integer fuel unit, and the torch becomes unlit while remaining a zero-fuel light. Its proximity is sampled before the fuel sweep, so its outage message is emitted, then the lit-to-dark notice. Darkness advances and the final treasure makes victory possible only if no death has already occurred. Score is current stored treasure points plus bonus, not a separately accumulated treasure counter. For the fatal contrast, begin with darkness count two and the final-fuel light lit elsewhere, while both USE operands are carried and thus resolvable in darkness. The light still burns out, without a nearby outage notice, darkness reaches three, death suppresses victory although the gem effect and score remain. This is a reachable state comparison, not an assumption that a previously lit room can already have darkness count two. Failed resolution, an uncarried first operand, or no applicable rule escapes before turn passage; SCORE is an information command and similarly does not consume fuel or increment moves. The selected input/output path preserves the original echoed command and prints terminal and final scores. 

Concurrent a24a review: Remove only the fallback into the unrelated item-action switch and its LIGHT arm. USE and SCORE retain their earlier return paths. The concurrent candidate was reviewed against the same three answer requirements and the same USE/fatal-darkness scenario. The lit torch with one fuel unit is part of the question's pre-turn state; executing a separate LIGHT or EXTINGUISH command is not required. The original excerpt review remains applicable to the unchanged world parsing, resolution, rule ADD, fuel/proximity, score and death-before-victory chain. ## Minimization and alternatives

The selection chooses USE consistently in all twenty languages, as permitted by “USE or movement”; movement, exits, inventory mutation, saving/restoring, and unused rule effects are not a second required trace. Rule ADD, operand resolution, exact light-property/fuel separation, and end-turn ordering are individually necessary. A turn-only excerpt cannot establish the action effects or failure bypass; a USE-only excerpt cannot establish death priority, fuel or victory. Information SCORE is used as the representative non-action. Built-in collection traversal/equality, integer operations, exception/result propagation and output formatting supply standard language semantics; custom helpers on the trace are included. Whole routines are not selected automatically, and blank/closing-only lines and unrelated branches are excluded when separable. No gameplay source is modified, compiled or run. A smaller alternative omits the separate LIGHT/EXTINGUISH command implementation while retaining light capability, lit/fuel state and the burn transition. That reduction is adopted. Classification lists are retained in full where a required fact is non-membership. Only necessary source declarations and control boundaries from the concurrent review are added; no source program was edited or executed.

The excerpt contains 6621 tokens under `metric/tokenizer.py`. Only complete source lines are counted; the question and this rationale are excluded. Task B uses the README assumption that the Task A program satisfies its contract; this selection does not claim compilation or runtime verification.
