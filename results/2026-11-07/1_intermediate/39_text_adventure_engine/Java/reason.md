## Evidence and language semantics

Adventure sorts item identifiers into array positions; the ascending fuel loop therefore gives identifier order. Place records use value equality; reachable climbs parent places but requires open containers, whereas stored climbs parents independently of their visibility. The parsed ADD effect is a MoveItem record with a floor Place, and the USE switch performs its state write before turn. Java exceptions escape failed resolve or validation to the process catch, so they never reach the bottom turn call. Verb.action excludes SCORE; the selected terminal enum and guarded victory condition establish death priority. The main loop recognizes BEGIN and QUIT, echoes original input and then flushes the accumulated response. The common trace is `Use the wand on the bell`, with unambiguous wand/bell items, the wand carried, and `RULE wand bell ADD gem trophy`. The final unstored gem is a treasure; ADD moves it to the trophy-room floor. The pre-turn state has a lit torch with exactly one fuel unit, reachable in the current DARK room, and no previous terminal status. Rules run first and produce Done. when no MESSAGE runs; the move count advances once, every lit light loses one integer fuel unit, and the torch becomes unlit while remaining a zero-fuel light. Its proximity is sampled before the fuel sweep, so its outage message is emitted, then the lit-to-dark notice. Darkness advances and the final treasure makes victory possible only if no death has already occurred. Score is current stored treasure points plus bonus, not a separately accumulated treasure counter. For the fatal contrast, begin with darkness count two and the final-fuel light lit elsewhere, while both USE operands are carried and thus resolvable in darkness. The light still burns out, without a nearby outage notice, darkness reaches three, death suppresses victory although the gem effect and score remain. This is a reachable state comparison, not an assumption that a previously lit room can already have darkness count two. Failed resolution, an uncarried first operand, or no applicable rule escapes before turn passage; SCORE is an information command and similarly does not consume fuel or increment moves. The selected input/output path preserves the original echoed command and prints terminal and final scores.  The switch selector binds the alias cases to the input word, and the selected else edges distinguish no-argument validation, required operands, GO and USE preposition handling.

## Minimization and alternatives

The selection chooses USE consistently in all twenty languages, as permitted by “USE or movement”; movement, exits, inventory mutation, saving/restoring, and unused rule effects are not a second required trace. Rule ADD, operand resolution, exact light-property/fuel separation, and end-turn ordering are individually necessary. A turn-only excerpt cannot establish the action effects or failure bypass; a USE-only excerpt cannot establish death priority, fuel or victory. Information SCORE is used as the representative non-action. Built-in collection traversal/equality, integer operations, exception/result propagation and output formatting supply standard language semantics; custom helpers on the trace are included. Whole routines are not selected automatically, and blank/closing-only lines and unrelated branches are excluded when separable. No gameplay source is modified, compiled or run. The torch is already lit with one fuel unit in the question's pre-turn state. Separate LIGHT/EXTINGUISH command bodies and their dedicated dispatches supply no fact about the selected USE turn and are omitted. Light capability, lit/fuel state, world parsing, USE effects, fuel and death/victory ordering remain selected.
