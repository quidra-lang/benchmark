## Evidence and language semantics

Static objects are zero-initialized: NONE, ALWAYS, false lit, and zero counters are the initial values. Ordered indexes are populated and qsort compares item IDs with strcmp, so pass_turn decrements all lit items in identifier order. The pointer-based world parser preserves names using offsets into stored definition lines. ADD_ITEM writes a floor Place; explicit same_place supplies value comparison and parent traversal establishes reachability/storage. Successful execute returns true, whereas fail prints a message and longjmp resumes the command setjmp, bypassing pass_turn. SCORE returns successfully but action(SCORE) is false. The actual echo and final score use stdout directly, without a hidden output buffer. Independent excerpt review checks the world-to-USE dispatch, resolution and validation, stored-treasure effect, lighting/fuel transition, death-before-win guard, SCORE non-action evidence and outer output/error path as one dependency chain. Full action membership lists are retained where absence of SCORE is material; the declaration and alias order are both retained where ordinal lookup is used. The common trace is `Use the wand on the bell`, with unambiguous wand/bell items, the wand carried, and `RULE wand bell ADD gem trophy`. The final unstored gem is a treasure; ADD moves it to the trophy-room floor. The pre-turn state has a lit torch with exactly one fuel unit, reachable in the current DARK room, and no previous terminal status. Rules run first and produce Done. when no MESSAGE runs; the move count advances once, every lit light loses one integer fuel unit, and the torch becomes unlit while remaining a zero-fuel light. Its proximity is sampled before the fuel sweep, so its outage message is emitted, then the lit-to-dark notice. Darkness advances and the final treasure makes victory possible only if no death has already occurred. Score is current stored treasure points plus bonus, not a separately accumulated treasure counter. For the fatal contrast, begin with darkness count two and the final-fuel light lit elsewhere, while both USE operands are carried and thus resolvable in darkness. The light still burns out, without a nearby outage notice, darkness reaches three, death suppresses victory although the gem effect and score remain. This is a reachable state comparison, not an assumption that a previously lit room can already have darkness count two. Failed resolution, an uncarried first operand, or no applicable rule escapes before turn passage; SCORE is an information command and similarly does not consume fuel or increment moves. The selected input/output path preserves the original echoed command and prints terminal and final scores. 

Concurrent a24a review: Remove only the LIGHT switch arm. The USE arm, its validation, and the action classification and pass_turn call remain. The concurrent candidate was reviewed against the same three answer requirements and the same USE/fatal-darkness scenario. The lit torch with one fuel unit is part of the question's pre-turn state; executing a separate LIGHT or EXTINGUISH command is not required. The original excerpt review remains applicable to the unchanged world parsing, resolution, rule ADD, fuel/proximity, score and death-before-victory chain. The final excerpt was checked for retained USE/SCORE classification and for every changed caller or control boundary; no omitted LIGHT implementation is used as evidence.

## Minimization and alternatives

The selection chooses USE consistently in all twenty languages, as permitted by “USE or movement”; movement, exits, inventory mutation, saving/restoring, and unused rule effects are not a second required trace. Rule ADD, operand resolution, exact light-property/fuel separation, and end-turn ordering are individually necessary. A turn-only excerpt cannot establish the action effects or failure bypass; a USE-only excerpt cannot establish death priority, fuel or victory. Information SCORE is used as the representative non-action. Built-in collection traversal/equality, integer operations, exception/result propagation and output formatting supply standard language semantics; custom helpers on the trace are included. Whole routines are not selected automatically, and blank/closing-only lines and unrelated branches are excluded when separable. No gameplay source is modified, compiled or run. A smaller alternative omits the separate LIGHT/EXTINGUISH command implementation while retaining light capability, lit/fuel state and the burn transition. That reduction is adopted. Classification lists are retained in full where a required fact is non-membership. Only necessary source declarations and control boundaries from the concurrent review are added; no source program was edited or executed.

The excerpt contains 7363 tokens under `metric/tokenizer.py`. Only complete source lines are counted; the question and this rationale are excluded. Task B uses the README assumption that the Task A program satisfies its contract; this selection does not claim compilation or runtime verification.
