## Evidence and language semantics

Tree stores a flat array of Value records and child indices; object keys and children remain in document order. Quidra class/array values have value semantics, so the typed Tree next := document creates a value whose nested key-slot assignments do not mutate document or saved history. Dot mutation authority applies to next, and only .commit(next) installs it. This language guarantee makes a separate hand-written deep-copy helper unnecessary for RENAME. targets uses ordinal comparisons both for deduplication and insertion in reverse order. try propagates an error before commit, and the top-level match formats it; location retains original Step keys. Self and no-match still commit. Selected types, local candidate, nested assignment and commit authority establish isolation without importing a reference-object model from another language. The final independent excerpt-only pass also removed individually checked unused locals/fields or uncalled non-null compact branches; these lines supply no input, state or output fact for the fixed trace. Independent excerpt-only review followed the fixed input from block collection to JSON construction, path composition, reverse target traversal, error-before-commit (or restoration), PRETTY and UNDO. The success/no-match paths reach the same commit even when no content changes. Provenance and token count were then checked separately; no target program was executed. The fixed valid fixture starts with an initial `null` block and then LOADs `[{"old":null,"new":null},{"old":null}]`. Keys are unescaped ASCII identifiers and values are null, so number/escape parsing and other path selectors are not needed for this trace. The initial block prints LOADED nodes=1 depth=1 and the second prints LOADED nodes=6 depth=3; both successful loads add the preceding document to history. RENAME $[*].old new selects the two old members, deduplicates locations, and processes reverse document order: $[1].old is considered before $[0].old. The second object has no new key, but the first already does. The failure is ERROR key exists at $[0].old; it does not commit a changed document or push history. Whether this is implemented by editing a private copy or restoring a saved tree is explained by the selected copy/transaction code. Root PRETTY therefore still displays the loaded array in original member order. UNDO then restores null and prints UNDO 1. In separate comparisons from the loaded state, rename-to-self reports RENAME 2, and no-match reports RENAME 0; both succeed and add a snapshot, so their first UNDO prints UNDO 2 and restores an identical-looking loaded document. No-match is an empty selected-location list, not a JSON null value. 

## Minimization and alternatives

The fixture deliberately exercises JSON arrays, ordered objects, plain key strings and null literals, and only root/wildcard/key path segments. Full unrelated numeric/escape readers, recursive/index/slice query selectors and the other editing commands do not contribute facts for this question. Physical lines that mix relevant and irrelevant branches are retained whole. A RENAME-only excerpt cannot prove atomicity/history or the output after failure; a LOAD/PRETTY-only excerpt cannot prove deduplication, collision order or no-op history. Deep-copy construction or immutable value semantics is retained wherever it establishes isolation. Each chosen branch/helper is reviewed individually; no target program is compiled, run or edited.
