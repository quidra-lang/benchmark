## Evidence and language semantics

JsonValue keeps explicit kind, ordered keys and child lists, so JSON null is distinct from no matches. copy duplicates both keys and every child recursively; commit stores the existing document only after all edits on the duplicate finish. Match.positions supplies positional identities and Python lexicographic list sorting with reverse=True establishes reverse document order; adjacent equal positions are then deduplicated. Key mutation writes one list slot and preserves order. CommandError unwinds before commit, so earlier edits affect only the private duplicate. pretty recursively renders the original document after failure. Every successful rename calls commit even for equal keys or zero targets; undo pops exactly one state. Standard list slicing, comprehensions, exception propagation and string joining supply the remaining semantics. Independent excerpt-only review followed the fixed input from block collection to JSON construction, path composition, reverse target traversal, error-before-commit (or restoration), PRETTY and UNDO. The success/no-match paths reach the same commit even when no content changes. Provenance and token count were then checked separately; no target program was executed. The fixed valid fixture starts with an initial `null` block and then LOADs `[{"old":null,"new":null},{"old":null}]`. Keys are unescaped ASCII identifiers and values are null, so number/escape parsing and other path selectors are not needed for this trace. The initial block prints LOADED nodes=1 depth=1 and the second prints LOADED nodes=6 depth=3; both successful loads add the preceding document to history. RENAME $[*].old new selects the two old members, deduplicates locations, and processes reverse document order: $[1].old is considered before $[0].old. The second object has no new key, but the first already does. The failure is ERROR key exists at $[0].old; it does not commit a changed document or push history. Whether this is implemented by editing a private copy or restoring a saved tree is explained by the selected copy/transaction code. Root PRETTY therefore still displays the loaded array in original member order. UNDO then restores null and prints UNDO 1. In separate comparisons from the loaded state, rename-to-self reports RENAME 2, and no-match reports RENAME 0; both succeed and add a snapshot, so their first UNDO prints UNDO 2 and restores an identical-looking loaded document. No-match is an empty selected-location list, not a JSON null value.
