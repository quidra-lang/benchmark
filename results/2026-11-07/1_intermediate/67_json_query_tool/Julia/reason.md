## Evidence and language semantics

Value stores ordered key and item vectors; Julia one-based child positions are converted to zero-based array notation by location. targets sorts tuples of these positions in reverse lexicographic order, then removes duplicate tuples with Set. deepcopy recursively duplicates the mutable tree before any rename, while resolve follows preserved ordinal positions. CommandError leaves the private copy uninstalled; commit! pushes history only after every target succeeds. Equal-key and empty selections reach the same commit. PRETTY recursively joins the unchanged original vectors and UNDO pops one tree. Standard deepcopy, tuple sorting, Set membership and exception propagation supply the language/library guarantees; no shallow-copy assumption is made. Independent excerpt-only review followed the fixed input from block collection to JSON construction, path composition, reverse target traversal, error-before-commit (or restoration), PRETTY and UNDO. The success/no-match paths reach the same commit even when no content changes. Provenance and token count were then checked separately; no target program was executed. The fixed valid fixture starts with an initial `null` block and then LOADs `[{"old":null,"new":null},{"old":null}]`. Keys are unescaped ASCII identifiers and values are null, so number/escape parsing and other path selectors are not needed for this trace. The initial block prints LOADED nodes=1 depth=1 and the second prints LOADED nodes=6 depth=3; both successful loads add the preceding document to history. RENAME $[*].old new selects the two old members, deduplicates locations, and processes reverse document order: $[1].old is considered before $[0].old. The second object has no new key, but the first already does. The failure is ERROR key exists at $[0].old; it does not commit a changed document or push history. Whether this is implemented by editing a private copy or restoring a saved tree is explained by the selected copy/transaction code. Root PRETTY therefore still displays the loaded array in original member order. UNDO then restores null and prints UNDO 1. In separate comparisons from the loaded state, rename-to-self reports RENAME 2, and no-match reports RENAME 0; both succeed and add a snapshot, so their first UNDO prints UNDO 2 and restores an identical-looking loaded document. No-match is an empty selected-location list, not a JSON null value. 

## Minimization and alternatives

The fixture deliberately exercises JSON arrays, ordered objects, plain key strings and null literals, and only root/wildcard/key path segments. Full unrelated numeric/escape readers, recursive/index/slice query selectors and the other editing commands do not contribute facts for this question. Physical lines that mix relevant and irrelevant branches are retained whole. A RENAME-only excerpt cannot prove atomicity/history or the output after failure; a LOAD/PRETTY-only excerpt cannot prove deduplication, collision order or no-op history. Deep-copy construction or immutable value semantics is retained wherever it establishes isolation. Each chosen branch/helper is reviewed individually; no target program is compiled, run or edited.
