## Evidence and language semantics

Value derives Clone recursively over Vec and String, so the changed tree and saved history own independent nested values. Objects use a Vec of key/value pairs and key mutation changes a slot in place. Vec<usize> locations derive lexicographic Ord from standard-library types; collecting into BTreeSet removes duplicate positions and iter().rev() yields reverse document order. A collision returns Err before the history push/root assignment, discarding the local changed value. RENAME equal keys and zero target counts still reach that assignment. The Result output branch prints the exact pre-edit notation and leaves root/history untouched on error. Independent excerpt-only review followed the fixed input from block collection to JSON construction, path composition, reverse target traversal, error-before-commit (or restoration), PRETTY and UNDO. The success/no-match paths reach the same commit even when no content changes. Provenance and token count were then checked separately; no target program was executed. The fixed valid fixture starts with an initial `null` block and then LOADs `[{"old":null,"new":null},{"old":null}]`. Keys are unescaped ASCII identifiers and values are null, so number/escape parsing and other path selectors are not needed for this trace. The initial block prints LOADED nodes=1 depth=1 and the second prints LOADED nodes=6 depth=3; both successful loads add the preceding document to history. RENAME $[*].old new selects the two old members, deduplicates locations, and processes reverse document order: $[1].old is considered before $[0].old. The second object has no new key, but the first already does. The failure is ERROR key exists at $[0].old; it does not commit a changed document or push history. Whether this is implemented by editing a private copy or restoring a saved tree is explained by the selected copy/transaction code. No-match is an empty selected-location list, not a JSON null value. 

## Minimization and alternatives

The fixture deliberately exercises JSON arrays, ordered objects, plain key strings and null literals, and only root/wildcard/key path segments. Full unrelated numeric/escape readers, recursive/index/slice query selectors and the other editing commands do not contribute facts for this question. Physical lines that mix relevant and irrelevant branches are retained whole. A RENAME-only excerpt cannot prove atomicity/history or the output after failure; a LOAD/PRETTY-only excerpt cannot prove deduplication, collision order or no-op history. Deep-copy construction or immutable value semantics is retained wherever it establishes isolation. Each chosen branch/helper is reviewed individually; no target program is compiled, run or edited.
