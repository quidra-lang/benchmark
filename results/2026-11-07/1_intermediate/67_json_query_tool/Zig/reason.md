## Evidence and language semantics

Value.copy allocates a new Value, a fresh key ArrayList buffer and recursively copied child nodes. Key byte slices are const and rename replaces a slot rather than mutating bytes, so sharing immutable text does not share mutable tree state. targets duplicates the Match slice, sorts descending by the explicit ordinal comparator, and removes equal position vectors. resolve walks the copied nodes. Returning error.Invalid from the collision propagates through try before commit; run catches it and emits failure.reason. The old document/history pointers therefore stay unchanged. Equal names and empty target slices still commit and report their count. Arena lifetime keeps prior snapshots valid through UNDO; standard ArrayList iteration preserves object order. Independent excerpt-only review followed the fixed input from block collection to JSON construction, path composition, reverse target traversal, error-before-commit (or restoration), PRETTY and UNDO. The success/no-match paths reach the same commit even when no content changes. Provenance and token count were then checked separately; no target program was executed. The fixed valid fixture starts with an initial `null` block and then LOADs `[{"old":null,"new":null},{"old":null}]`. Keys are unescaped ASCII identifiers and values are null, so number/escape parsing and other path selectors are not needed for this trace. The initial block prints LOADED nodes=1 depth=1 and the second prints LOADED nodes=6 depth=3; both successful loads add the preceding document to history. RENAME $[*].old new selects the two old members, deduplicates locations, and processes reverse document order: $[1].old is considered before $[0].old. The second object has no new key, but the first already does. The failure is ERROR key exists at $[0].old; it does not commit a changed document or push history. Whether this is implemented by editing a private copy or restoring a saved tree is explained by the selected copy/transaction code. Root PRETTY therefore still displays the loaded array in original member order. UNDO then restores null and prints UNDO 1. In separate comparisons from the loaded state, rename-to-self reports RENAME 2, and no-match reports RENAME 0; both succeed and add a snapshot, so their first UNDO prints UNDO 2 and restores an identical-looking loaded document. No-match is an empty selected-location list, not a JSON null value. 

## Minimization and alternatives

The fixture deliberately exercises JSON arrays, ordered objects, plain key strings and null literals, and only root/wildcard/key path segments. Full unrelated numeric/escape readers, recursive/index/slice query selectors and the other editing commands do not contribute facts for this question. Physical lines that mix relevant and irrelevant branches are retained whole. A RENAME-only excerpt cannot prove atomicity/history or the output after failure; a LOAD/PRETTY-only excerpt cannot prove deduplication, collision order or no-op history. Deep-copy construction or immutable value semantics is retained wherever it establishes isolation. Each chosen branch/helper is reviewed individually; no target program is compiled, run or edited.

The excerpt contains 9051 tokens under `metric/tokenizer.py`. Only complete source lines are counted; the question and this rationale are excluded. Task B uses the README assumption that the Task A program satisfies its contract; this selection does not claim compilation or runtime verification.
