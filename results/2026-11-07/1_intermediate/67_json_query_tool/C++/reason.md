## Evidence and language semantics

Value owns vectors of strings and nested Value objects; compiler-generated value copy recursively copies their owned elements. Thus Value updated = document creates an isolated tree, not a pointer alias. Match pointers refer to the original tree, while resolution on updated uses stored ordinal positions. std::vector relational comparison is lexicographic, so sorting positions descending and adjacent unique yields reverse document order with duplicate locations removed. A runtime_error bypasses commit and destroys the private updated tree; the catch prints ERROR plus the original Match location. commit moves the preceding tree into history and installs the candidate even for no-op or zero-target success. PRETTY traverses the ordered vectors and UNDO moves/pops the last saved value. The final independent excerpt-only pass also removed individually checked unused locals/fields or uncalled non-null compact branches; these lines supply no input, state or output fact for the fixed trace. Independent excerpt-only review followed the fixed input from block collection to JSON construction, path composition, reverse target traversal, error-before-commit (or restoration), PRETTY and UNDO. The success/no-match paths reach the same commit even when no content changes. Provenance and token count were then checked separately; no target program was executed. The fixed valid fixture starts with an initial `null` block and then LOADs `[{"old":null,"new":null},{"old":null}]`. Keys are unescaped ASCII identifiers and values are null, so number/escape parsing and other path selectors are not needed for this trace. The initial block prints LOADED nodes=1 depth=1 and the second prints LOADED nodes=6 depth=3; both successful loads add the preceding document to history. RENAME $[*].old new selects the two old members, deduplicates locations, and processes reverse document order: $[1].old is considered before $[0].old. The second object has no new key, but the first already does. The failure is ERROR key exists at $[0].old; it does not commit a changed document or push history. Whether this is implemented by editing a private copy or restoring a saved tree is explained by the selected copy/transaction code. Root PRETTY therefore still displays the loaded array in original member order. UNDO then restores null and prints UNDO 1. In separate comparisons from the loaded state, rename-to-self reports RENAME 2, and no-match reports RENAME 0; both succeed and add a snapshot, so their first UNDO prints UNDO 2 and restores an identical-looking loaded document. No-match is an empty selected-location list, not a JSON null value.
