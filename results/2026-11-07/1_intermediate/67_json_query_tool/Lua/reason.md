## Evidence and language semantics

JSON null is a node table, so it is not confused with Lua nil or an absent target. Object keys and child nodes occupy parallel dense arrays traversed by ipairs. copy recursively allocates both arrays and each child table. targets sorts copied match references by explicit ordinal comparison and removes adjacent equal paths. resolve indexes only the new copied tree. A fail raises a table error through pcall before commit; the outer error handler emits its reason, and the original document/history are untouched. Falling through find returns nil for absent keys. Self-rename and an empty selected table still reach commit, whose multiple assignment saves the old document and installs the new one; UNDO table.remove reports the remaining stack size. The final independent excerpt-only pass also removed individually checked unused locals/fields or uncalled non-null compact branches; these lines supply no input, state or output fact for the fixed trace. Independent excerpt-only review followed the fixed input from block collection to JSON construction, path composition, reverse target traversal, error-before-commit (or restoration), PRETTY and UNDO. The success/no-match paths reach the same commit even when no content changes. Provenance and token count were then checked separately; no target program was executed. The fixed valid fixture starts with an initial `null` block and then LOADs `[{"old":null,"new":null},{"old":null}]`. Keys are unescaped ASCII identifiers and values are null, so number/escape parsing and other path selectors are not needed for this trace. The initial block prints LOADED nodes=1 depth=1 and the second prints LOADED nodes=6 depth=3; both successful loads add the preceding document to history. RENAME $[*].old new selects the two old members, deduplicates locations, and processes reverse document order: $[1].old is considered before $[0].old. The second object has no new key, but the first already does. The failure is ERROR key exists at $[0].old; it does not commit a changed document or push history. Whether this is implemented by editing a private copy or restoring a saved tree is explained by the selected copy/transaction code. Root PRETTY therefore still displays the loaded array in original member order. UNDO then restores null and prints UNDO 1. In separate comparisons from the loaded state, rename-to-self reports RENAME 2, and no-match reports RENAME 0; both succeed and add a snapshot, so their first UNDO prints UNDO 2 and restores an identical-looking loaded document. No-match is an empty selected-location list, not a JSON null value.
