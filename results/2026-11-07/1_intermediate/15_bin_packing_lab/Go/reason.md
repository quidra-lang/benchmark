## Evidence and language semantics

The common witness is three commands: `ITEMS 10 6 6 5 5 4`, `KBOUNDED 2`, `KBOUNDED 2`. All sizes are nonzero and at most 10, k is nonzero, and ITEMS establishes readiness. The ITEMS line is `ITEMS count=5 capacity=10 total=26`. Each run processes the five original numbered items, inspecting respectively 0, 1, 2, 2, 1 active bins (six total). Item 3 cannot fit either load-6 bin, so the existing full-active closure chooses bin 1 (greatest load, smallest number on a tie); it opens bin 3, which takes items 3 and 4, while item 5 goes to bin 2. Current output is `KBOUNDED k=2 bins=3 inspections=6 waste=4 closes=1`, with BIN 1 load=6/10 items=1:6; BIN 2 load=10/10 items=2:6 5:4; BIN 3 load=10/10 items=3:5 4:5. The proposed comparator chooses the smallest load, then largest bin number: in this tie it closes bin 2 instead, leaving BIN 1 load=10/10 items=1:6 5:4, BIN 2 load=6/10 items=2:6, BIN 3 unchanged. Only the closure winner calculation changes. Removing its active entry preserves the relative order of survivors, and the new bin is appended; comparisons for closure do not increment packing inspections. Closure count, creation, placement, numbering, waste and output paths remain unchanged. The second KBOUNDED starts a new local packing using the same five items and capacity; it repeats the applicable result rather than retaining active-bin state. Go zero values initialize packing counters, nil bin slices and bin loads; item is a struct with scalar fields copied by range and by put. The input slice shares storage, but the selected pack path does not write to it or to item fields. Strict greater-load scanning retains the earliest ascending active id; add equality with greater id and lower-load selection. Slice removal retains survivor order and append introduces the new greatest id. The persistent lab items are unchanged by this route.

## Minimization and alternatives

The direct KBOUNDED witness avoids TRACE records and formatting. Every retained group supplies parsing/validation, first-fit inspections, closure and placement, counters/output, or the persistent-state boundary. Full routines would add other packing methods, random generation, bounds, reductions and 2D packing. A closure-only excerpt cannot establish inspections, assignment output or input preservation. An input-copy declaration alone is insufficient in reference-based languages, so the selected executed writes and scalar item representation are retained. Class/implementation and branch headers remain where needed to associate the selected calls with their definitions. The final excerpt was reviewed independently against all three common requirements; no target program was executed. Whitespace-only lines outside source literals and explicit line continuations are omitted: they contribute tokens but no evidence for the answer. Literal content is preserved, and files with ambiguous quote or multiline-literal syntax are left unchanged by this step.
