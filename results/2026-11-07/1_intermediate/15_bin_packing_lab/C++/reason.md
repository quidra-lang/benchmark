## Evidence and language semantics

The common witness is three commands: `ITEMS 10 6 6 5 5 4`, `KBOUNDED 2`, `KBOUNDED 2`. All sizes are nonzero and at most 10, k is nonzero, and ITEMS establishes readiness. The ITEMS line is `ITEMS count=5 capacity=10 total=26`. Each run processes the five original numbered items, inspecting respectively 0, 1, 2, 2, 1 active bins (six total). Item 3 cannot fit either load-6 bin, so the existing full-active closure chooses bin 1 (greatest load, smallest number on a tie); it opens bin 3, which takes items 3 and 4, while item 5 goes to bin 2. Current output is `KBOUNDED k=2 bins=3 inspections=6 waste=4 closes=1`, with BIN 1 load=6/10 items=1:6; BIN 2 load=10/10 items=2:6 5:4; BIN 3 load=10/10 items=3:5 4:5. The proposed comparator chooses the smallest load, then largest bin number: in this tie it closes bin 2 instead, leaving BIN 1 load=10/10 items=1:6 5:4, BIN 2 load=6/10 items=2:6, BIN 3 unchanged. Only the closure winner calculation changes. Removing its active entry preserves the relative order of survivors, and the new bin is appended; comparisons for closure do not increment packing inspections. Closure count, creation, placement, numbering, waste and output paths remain unchanged. The second KBOUNDED starts a new local packing using the same five items and capacity; it repeats the applicable result rather than retaining active-bin state. C++ const vector<Item>& input and scalar Item fields establish read-only current items in pack; the local ordered vector is a value copy. Bins own copied Item values. Strict greater-load scanning over ascending active indices retains the smallest tied bin. The new test must accept lower load and, on equality, larger index. erase preserves surviving vector order; push_back appends. No returned packing is stored into PackingLab.items.

## Minimization and alternatives
