## Evidence and language semantics

Common concrete input: 1; CHART exact; state a; on a done / log "prefix"; on a done.state.a / log "exact"; on a * / log "wild"; RUN; event done.state.a; event done; event other; dump; END (each semicolon separates an input line). Original logs are prefix, prefix, wild; after removing the prefix alternative from the descriptor predicate they are exact, prefix, wild. The first event is a valid externally supplied name, also the spelling used for completion events; generated completions still enter the same event queue but use the revised exact-name rule. The only active state remains a at time zero. No guard, target, entry/exit action, timer or variable is declared; absent guards are true and every selected transition is internal. Rust Option makes absence explicit: target? returns None from scope, None guards map to Ok(true), and None action expressions map to Ok(0). Vec registration/document order survives cloning; BTreeSet IDs are only membership/conflict sets, not a replacement ordering of candidate priority. is_disjoint accepts empty exits, and no scope yields no entry seed. Remove starts_with(&(d.clone()+".")) from the event any predicate only; timer indices and eventless kind routing remain separate. VecDeque pop_front and Trigger::event retain internal/completion event names. Literal text is owned String; its clone is an unchanged value, and output formatting is explicit.

Boundary review: The log, tick and dump match arms close separately from their containing match/loop scopes. Internal target-parsing, definition, action, entry, microstep and input boundaries keep following operations outside those branches; independent fn/impl frames are omitted.

## Minimization and alternatives

A single atomic state and targetless transitions minimize state-entry/exit/history dependencies while still exercising parsing, ordered transition priority, default guards, conflict filtering, action logs and dump output. A chart with guarded arithmetic or changing targets would require expression evaluation and target/history closure without adding a fact needed to locate this matching change. Queue/completion creation and separate timer/eventless dispatch anchors are retained to delimit the modification; their scheduling algorithms are not changed. Only the successful branches and custom helpers needed for this trace are retained, plus the match alternatives that distinguish old/new behavior. Each selected complete line was reviewed for necessity; the excerpt alone was checked against the common requirements. Internal boundaries needed to establish the scope of later selected operations are retained. Independent outer declaration frames and unrelated command bodies are omitted where they provide no evidence.
