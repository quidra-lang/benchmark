## Evidence and language semantics

Common concrete input: 1; CHART exact; state a; on a done / log "prefix"; on a done.state.a / log "exact"; on a * / log "wild"; RUN; event done.state.a; event done; event other; dump; END (each semicolon separates an input line). Original logs are prefix, prefix, wild; after removing the prefix alternative from the descriptor predicate they are exact, prefix, wild. The first event is a valid externally supplied name, also the spelling used for completion events; generated completions still enter the same event queue but use the revised exact-name rule. The only active state remains a at time zero. No guard, target, entry/exit action, timer or variable is declared; absent guards are true and every selected transition is internal. State and Transition are classes without value equality overrides, so HashSet and == use identity. Defaults initialize guards/targets to null, state.Active/trace to false and clocks to zero; the selected field declarations suffice without fabricated constructor assignments. Null conditional Reference/Evaluate avoids expression work for the literal-only trace. List order plus first matching guard and HashSet dedup/Overlaps determine priority/conflicts. Removing only StartsWith(d+".",Ordinal) preserves exact ordinal equality, wildcard, timer identity and eventless kind matching. Internal events retain the Event wrapper and ordinary event dispatch; the first root child enters once and target-null transitions have no exit/entry changes. Console.WriteLine establishes logs/dump.

## Minimization and alternatives

A single atomic state and targetless transitions minimize state-entry/exit/history dependencies while still exercising parsing, ordered transition priority, default guards, conflict filtering, action logs and dump output. A chart with guarded arithmetic or changing targets would require expression evaluation and target/history closure without adding a fact needed to locate this matching change. Queue/completion creation and separate timer/eventless dispatch anchors are retained to delimit the modification; their scheduling algorithms are not changed. Only the successful branches and custom helpers needed for this trace are retained, plus the match alternatives that distinguish old/new behavior. Each selected complete line was reviewed for necessity; the excerpt alone was checked against the common requirements. Standalone closing delimiters and unrelated commands are omitted where they provide no evidence.
