## Evidence and language semantics

Common concrete input: 1; CHART exact; state a; on a done / log "prefix"; on a done.state.a / log "exact"; on a * / log "wild"; RUN; event done.state.a; event done; event other; dump; END (each semicolon separates an input line). Original logs are prefix, prefix, wild; after removing the prefix alternative from the descriptor predicate they are exact, prefix, wild. The first event is a valid externally supplied name, also the spelling used for completion events; generated completions still enter the same event queue but use the revised exact-name rule. The only active state remains a at time zero. No guard, target, entry/exit action, timer or variable is declared; absent guards are true and every selected transition is internal. The source allocator uses calloc for zeroed chart/transition/action storage, establishing zero counters, inactive states and absent pointers on the stipulated bug-free target; source also explicitly sets target=-1 and root parent=-1. An absent target returns Choice {scope=-1, exits=0}, so bitwise conflict checks retain the first ordered candidate without state changes. Pointer equality identifies timers and duplicate transitions; strcmp/strncmp helpers define event-name semantics. Remove only the final starts-and-dot disjunct, retaining exact/wildcard and kind dispatch. Null guards default to 1 and null action expressions to 0; literal output uses fputs and a newline. Input copies remain owned until chart completion. The custom word/read_line, bitset, initialization and active-state print paths close the concrete trace; expression arithmetic and target/history internals are not evaluated here.

## Minimization and alternatives

A single atomic state and targetless transitions minimize state-entry/exit/history dependencies while still exercising parsing, ordered transition priority, default guards, conflict filtering, action logs and dump output. A chart with guarded arithmetic or changing targets would require expression evaluation and target/history closure without adding a fact needed to locate this matching change. Queue/completion creation and separate timer/eventless dispatch anchors are retained to delimit the modification; their scheduling algorithms are not changed. Only the successful branches and custom helpers needed for this trace are retained, plus the match alternatives that distinguish old/new behavior. Each selected complete line was reviewed for necessity; the excerpt alone was checked against the common requirements. Standalone closing delimiters and unrelated commands are omitted where they provide no evidence.
