## Evidence and language semantics

Replace the existing delete-or-keep decision only for selected NOTE_ON, NOTE_OFF and POLY_PRESSURE events with note=max(0,min(127,old+n)), retaining the event in its original track slot and preserving tick, kind, channel and other fields. Keep the current optional-channel predicate and validation before mutation. Distinct events remain distinct even if they clamp to the same note; neither transformation nor later traversal should deduplicate them. All affected events count as transposed (including n=0 or a note already at the endpoint); retain the result format transposed K dropped 0, with no dropped-event detail lines. DECODE must render the new note at the retained tick/track/position. ENCODE must visit every retained event, emit its updated channel-message payload and derive each delta from the unchanged absolute ticks, including zero deltas for equal-time events. Existing running-status and NOTE_OFF ZERO handling remain in force and must operate on the preserved event sequence. Enum declaration order makes the first three Kind values precisely the note families; channelEvent includes channel messages through PitchBend. Song stores ordered vector values, and transpose copies an Event (including vector fields), changes fields[0], moves it to the replacement track and then replaces the original track. Retaining all copies thus preserves ticks and positions and never keys events by pitch. DECODE displays fields[0] through pitchName. ENCODE copies the fields only for optional NOTE_OFF ZERO rewriting, emits every field in order, updates running status and converts int64 tick differences to shortest VLQ. Command tokens come from whitespace extraction, map lookup precedes bounded stoll argument conversion, and fail throws before mutation. The standard vector and move semantics preserve owned values.
