## Evidence and language semantics

Replace the existing delete-or-keep decision only for selected NOTE_ON, NOTE_OFF and POLY_PRESSURE events with note=max(0,min(127,old+n)), retaining the event in its original track slot and preserving tick, kind, channel and other fields. Keep the current optional-channel predicate and validation before mutation. Distinct events remain distinct even if they clamp to the same note; neither transformation nor later traversal should deduplicate them. All affected events count as transposed (including n=0 or a note already at the endpoint); retain the result format transposed K dropped 0, with no dropped-event detail lines. DECODE must render the new note at the retained tick/track/position. ENCODE must visit every retained event, emit its updated channel-message payload and derive each delta from the unchanged absolute ticks, including zero deltas for equal-time events. Existing running-status and NOTE_OFF ZERO handling remain in force and must operate on the preserved event sequence. Events are objects holding integer tick/status and an array payload, while songs/tracks are ordered PHP arrays. foreach obtains the same event objects, updates only d[0], appends each retained event to a new array and explicitly stores the song back. Keeping the target after clamping preserves array order and does not merge equal notes. ensure throws; song existence is checked before the TRANSPOSE range checks. eventType/eventFields/eventLine establish decoded family/channel/pitch. ENCODE obtains a value copy of the PHP payload array, so its NOTE_OFF ZERO adjustment does not change the stored event; ordered array merges and VLQ encoding preserve all events and tick differences. Integer arithmetic is exact within the task limits.
