## Evidence and language semantics

Replace the existing delete-or-keep decision only for selected NOTE_ON, NOTE_OFF and POLY_PRESSURE events with note=max(0,min(127,old+n)), retaining the event in its original track slot and preserving tick, kind, channel and other fields. Keep the current optional-channel predicate and validation before mutation. Distinct events remain distinct even if they clamp to the same note; neither transformation nor later traversal should deduplicate them. All affected events count as transposed (including n=0 or a note already at the endpoint); retain the result format transposed K dropped 0, with no dropped-event detail lines. DECODE must render the new note at the retained tick/track/position. ENCODE must visit every retained event, emit its updated channel-message payload and derive each delta from the unchanged absolute ticks, including zero deltas for equal-time events. Existing running-status and NOTE_OFF ZERO handling remain in force and must operate on the preserved event sequence. Event instances carry Long ticks and mutable Int payload lists; Song owns ordered mutable lists of those instances. The existing iterator.remove is the deletion point; replacing that decision with clamped data[0] assignment and retained-event counting leaves traversal slots and all scalar fields intact. The three channel status nibbles and channel number are established by channel/kind/ch. DECODE uses ordered nested iteration and eventText/noteName. ENCODE iterates the same sequence, emits exact Long tick differences as VLQ, and keeps running status and optional NOTE_OFF ZERO payload rewriting. Failure throws after unknown-command and missing-song checks, and Long ranges enforce semitone/channel limits before mutation.
