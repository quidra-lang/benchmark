## Evidence and language semantics

The requested change belongs in the event transformation, after target selection and signed pitch addition and before the payload assignment. Replace the range-failure removal path with a lower/upper bound clamp. Every selected event must reach the retained-event path exactly once; leave tick, status/channel, second data byte and track order untouched. Equal resulting pitches are separate sequence entries, including entries at the same tick; no set, grouping or note-pair operation is required. The transposed count includes those now clamped, including a zero shift; dropped becomes zero and its detail loop receives no events. DECODE already formats the stored payload in track order. ENCODE already uses each retained absolute tick minus the previous retained tick, so preserving events preserves the original delta sequence, including zero deltas; the shortest base-128 encoding and channel payload emission remain applicable. Existing running-status compression only suppresses status bytes, while NOTE_OFF ZERO changes status/velocity at encoding time and keeps the pitch. Neither operation coalesces events. Kotlin iterates each MutableList with its iterator; the current iterator.remove is the deletion point. Clamp the Long sum, write it via data[0], count the target and do not remove it. Leaving all original list entries intact automatically preserves tick, order and distinct equal-pitch events. val code prevents reassigning the event code and the selected Event/list types distinguish that from mutable tick/data. Song is obtained by reference from songs, so mutation of its lists persists without replacement in the map. Inclusive Long ranges and &&/|| establish bounds and shift-before-channel evaluation after command/song checks. fail returns Nothing by throwing Failure and the catch keeps error: formatting. The channelKinds/kind relation resolves the names; eventText and noteName resolve display. The encoder emits one payload after vlq(e.tick-last), and its local List<Int> replacement for zero-off does not overwrite stored pitch.
