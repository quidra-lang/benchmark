## Evidence and language semantics

The requested change belongs in the event transformation, after target selection and signed pitch addition and before the payload assignment. Replace the range-failure removal path with a lower/upper bound clamp. Every selected event must reach the retained-event path exactly once; leave tick, status/channel, second data byte and track order untouched. Equal resulting pitches are separate sequence entries, including entries at the same tick; no set, grouping or note-pair operation is required. The transposed count includes those now clamped, including a zero shift; dropped becomes zero and its detail loop receives no events. DECODE already formats the stored payload in track order. ENCODE already uses each retained absolute tick minus the previous retained tick, so preserving events preserves the original delta sequence, including zero deltas; the shortest base-128 encoding and channel payload emission remain applicable. Existing running-status compression only suppresses status bytes, while NOTE_OFF ZERO changes status/velocity at encoding time and keeps the pitch. Neither operation coalesces events. Song.Tracks is a slice of slices of *Event; each row append keeps the original pointers in their original order and permits equal payloads. Mutating e.Data[0] updates that held event, and song.Tracks[t]=row preserves its track position. Status<176 identifies the first three valid channel message families, with the channelNames/kind relation making their NOTE_OFF/NOTE_ON/POLY_PRESSURE identities explicit. The pitch addition explicitly widens Data[0] to int64 before applying the signed amount, and must clamp before byte conversion. Command validation precedes song-map lookup and the between predicate; error lines are emitted directly in those branches. The output helper and decimal conversion complete the textual dependency. eventLine maps the stored first data byte through noteName, while encode appends one data body per entry after vlq(Tick-last); it never uses a pitch-keyed map. The local NOTE_OFF ZERO body is separate from e.Data and keeps Data[0].
