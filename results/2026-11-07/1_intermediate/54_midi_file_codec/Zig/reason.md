## Evidence and language semantics

Replace the existing delete-or-keep decision only for selected NOTE_ON, NOTE_OFF and POLY_PRESSURE events with note=max(0,min(127,old+n)), retaining the event in its original track slot and preserving tick, kind, channel and other fields. Keep the current optional-channel predicate and validation before mutation. Distinct events remain distinct even if they clamp to the same note; neither transformation nor later traversal should deduplicate them. All affected events count as transposed (including n=0 or a note already at the endpoint); retain the result format transposed K dropped 0, with no dropped-event detail lines. DECODE must render the new note at the retained tick/track/position. ENCODE must visit every retained event, emit its updated channel-message payload and derive each delta from the unchanged absolute ticks, including zero deltas for equal-time events. Existing running-status and NOTE_OFF ZERO handling remain in force and must operate on the preserved event sequence. The source declares i64 arithmetic and mutable byte slices in Event, with ordered ArrayList tracks. clone duplicates every payload and nested track, so command mutation affects the selected song copy, which is explicitly committed to songs[at]. Keeping each copied event and clamping before byte(@intCast) prevents out-of-range conversion and retains sequence identity. lookup and early error returns establish validation precedence. Event fields/textLine and noteName show DECODE output; encodeSong traverses tracks and events and uses putVlq on absolute-tick differences, then emits the retained note payload with running-status and NOTE_OFF ZERO rewriting. Host text/line helpers only format and append a newline; ordered ArrayList operations preserve collisions as separate events.
